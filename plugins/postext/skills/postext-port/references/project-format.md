# Postext project format (preset bundle)

A Postext **project is a book**: one config, one font set, one resource set and
an ordered list of chapters (per language). On disk it is a folder, or the same
folder zipped as a `.postext` file.

```
my-book/
  preset.json                 manifest (required) — generated by build_preset.py
  chapters/<lang>/NN-slug.md  one Markdown file per chapter (name order = book order)
  resources/                  figures: .svg .png .jpg .jpeg .webp .gif (+ .pdf print masters)
  fonts/                      .ttf .otf .woff2 single faces (.woff and .ttc do not load)
  thumbnail.jpg               optional cover for the project picker
  fingerprint.json            optional {"fingerprint": "<sha1>"}: lets the sandbox notice edits
  layouts.json                engine-written pagination cache — never write it by hand
  build_preset.py, source/, resources.json, CREDITS.md …   yours; ignored by the loader
```

## 1. `preset.json` (manifest v2)

```jsonc
{
  "version": 2,                        // 2 = book with chapters (1 = single "markdown" file, legacy)
  "id": "my-book",                     // [a-z0-9-], stable
  "name": "My Book",
  "description": "…", "locale": "es", "locales": ["es", "en"],
  "thumbnail": "thumbnail.jpg", "license": "CC BY 4.0", "credits": "…", "tags": ["book"],
  "view": { "canvasScope": "book" },   // "book": the canvas lays out the whole book; default "chapter"

  "chapters": {                        // or a plain array when there is one language
    "es": [ { "title": "Luz", "file": "chapters/es/01-luz.md" }, { "title": "Color", "file": "chapters/es/02-color.md" } ],
    "en": [ { "title": "Light", "file": "chapters/en/01-light.md" }, { "title": "Colour", "file": "chapters/en/02-colour.md" } ]
  },

  "config": { /* PostextConfig — see configuration.md. NEVER customFonts. */ },

  "resources": [ /* §3 */ ],
  "fonts": [ /* §4 */ ],

  "localized": {                       // per-language overrides (§2)
    "en": {
      "config": { "locale": "en-us", "resourceTypes": [ … ], "headings": { …whole object… } },
      "resources": [ { "id": "sky", "caption": "A clear evening sky.", "altText": "…" } ]
    }
  }
}
```

What the loader checks: version, id, name, the chapters shape, resource `id` +
`typeId`, font `name` + `variants[{weight: number, file}]`, and that every file
exists (a missing chapter/resource/font file aborts the load; a missing `pdfFile`
only drops the print master). It does **not** check `kind`, `typeId` against
`resourceTypes`, or anything inside `config` — `lint_project.py` does.

### Chapters

- Order = array order. The `title` is only for the UI (Projects panel, TOC in
  the sandbox); it is never injected into the text. Take it from the chapter's H1.
- The sandbox joins chapters with a blank line; **nothing forces a page break
  between chapters**: a chapter opens a page through its H1's
  `headings.levels[0].breakBefore` (or a heading style's).
- **Only the first chapter's YAML front matter** (`title`, `subtitle`, `author`,
  `publishDate`) counts: it feeds `{title}`/`{subtitle}`/`{author}` in designs.
  Front matter in later chapters is ignored (with a warning).
- Split a single source at every H1 (anything before the first H1 stays in
  chapter 1; a `:::part` fence right above an H1 travels with it).
- Book layout: cover (`00-cover.md`), front matter, contents (a chapter holding
  `:::toc`), parts (`:::part` at the top of each part's first chapter),
  chapters, back matter / credits.

## 2. Languages (`localized`)

- `chapters` may map each locale to its own chapter list. The sandbox picks the
  exact tag, then the base language (`es` for `es-ES`), then `locale`, then the
  first key.
- `localized.<lang>.config` is **shallow**: each top-level key it names
  replaces the shared one wholesale (merge order: built-in defaults ← `config`
  ← `localized.<lang>.config`). A localized `headings` must carry the whole
  `headings` object. Typically restate per language: `locale`, `bodyText`
  (hyphenation locale), `headings` (labels such as "Capítulo {1}"),
  `headingStyles`, `parts`, `toc`, `resourceTypes` (Figura/Figure), `header`
  (literal running-head text).
- `localized.<lang>.resources[]`: `{id, caption?, note?, altText?, table?, file?, pdfFile?, width?, height?}`
  merged into the resource with the same id. `table` replaces the whole table
  (model and styleId). `file` swaps the artwork (a diagram with translated
  labels in `resources/en/…`).
- Two *different* books per language (not a translation): give resources
  language-prefixed ids, keep them all in the shared list, and leave
  `localized.resources` empty.
- Always put `config.locale` (`es`, `en-us`, `fr`, `de`, `it`, `pt`, `ca`, `nl`):
  hyphenation, table continuation strings ("(cont.)") and the PDF `/Lang`.

## 3. Resources

Figures, photos, diagrams and tables are **resources**, never Markdown. The
chapter cites them with `:ref{id="…"}` (floats, numbered by first mention) or
embeds them with `::resource{id="…"}` (placement `here`).

```jsonc
// bitmap — ALWAYS declare width/height in pixels (Node renderers cannot decode images)
{ "id": "neptune-spot", "typeId": "figure", "kind": "bitmap", "file": "resources/neptune-spot.jpg",
  "width": 3200, "height": 1800,
  "caption": "Dark spot on *Neptune*.",          // inline markup allowed; the label/number is added
  "note": "Credit: ESO/P. Irwin et al.",         // credit line under the caption
  "altText": "A blue planet with a dark oval",   // always write it (tagged PDF)
  "placement": { "position": "top", "span": "page" } }

// svg — size read from width/height/viewBox if omitted; optional vector print master
{ "id": "cell-diagram", "typeId": "figure", "kind": "svg", "file": "resources/cell-diagram.svg",
  "pdfFile": "resources/cell-diagram.pdf",       // single-page PDF embedded verbatim in the PDF export
  "caption": "…", "placement": { "position": "auto", "span": "column" } }

// table — a TableModel, no file
{ "id": "spectrum", "typeId": "table", "kind": "table", "caption": "Visible spectrum bands.",
  "note": "Source: …",
  "placement": { "position": "here", "span": "column", "width": 0.8, "align": "center" },
  "table": { "styleId": "compact",               // optional tableStyles entry
    "model": { "headerRowCount": 1, "columnWidths": [2, 1],
      "rows": [
        [ {"content": "Colour", "isHeader": true}, {"content": "nm", "isHeader": true, "align": "right"} ],
        [ {"content": "**Red** :swatch{color=\"band\"}", "background": {"hex": "#fde2e4", "model": "hex"}}, {"content": "620–750", "align": "right"} ],
        [ {"content": "Blue", "image": {"resourceId": "shapes", "width": 0.5}, "verticalAlign": "middle"}, {"content": "450–495"} ],
        [ {"content": "Visible range", "colSpan": 2, "align": "center"}, {"content": "", "hiddenBy": {"row": 3, "col": 0}} ]
      ] } } }
```

- **Tables**: every row holds one entry per grid column; a merged cell gets
  `colSpan`/`rowSpan` and every slot it covers stays as
  `{"content": "", "hiddenBy": {"row": r, "col": c}}`. `columnWidths` are relative
  weights. Cell `content` is an inline snippet: `**bold**`, `*italic*`,
  `^sup^`, `~sub~`, `:ref`, `:swatch`, `:chip`; `\n` separates paragraphs; a
  paragraph starting with `• `, `– `, `1. ` is a hanging list item (two leading
  spaces per nesting level). **No `$math$` in cells, captions or notes.**
  `image` draws a bitmap/SVG resource in the cell (width = fraction of the cell).
  `background` fills the cell (link it to a palette id to re-theme).
- **placement**: `position` `auto` (float to the first free slot after the first
  `:ref`) | `top` | `bottom` | `here` (inline at the `::resource` line);
  `span` `column` | `page` | `side` (the float column of a `oneAndHalf` layout);
  `width` 0–1 + `align`; `captionSide: true` (caption in the side column beside
  a main-column figure); `rotate: "ccw"|"cw"` (landscape table/figure on its own
  page, spine-flush; split between rows when too long). Missing fields fall
  back to the resource type's `defaultPlacement`, then `auto`/`column`.
- A `here` resource that is only `:ref`'d and never `::resource`'d is numbered
  but never placed.
- **Resource types** (`config.resourceTypes`): `figure` and `table` exist by
  default *in English* — a non-English book must declare them. Custom types
  for plates, ornaments, artwork, sub-tables… An empty `numberingTemplate` (or
  caption prefix) makes an unnumbered type (ornaments, decorative artwork,
  credit-line photos). Numbering: `{n}`, `{h1}.{n}`, `{h1}-{n}` with `resetOn`
  and `counterFormat` (decimal, roman-upper…).
- Ids: descriptive slugs from the caption (`fig-cohort-study`), never numbers —
  numbers are computed from the first mention, so chapters can move.
- Words drawn inside an SVG only render with the page fonts when they are
  outlines, or `@font-face` subsets embedded in the SVG's `<defs>` (an `<img>`
  cannot see the page's fonts). The PDF backend draws SVG `<text>` with the
  document's embedded faces.
- The PDF backend draws an SVG vector subset (paths, groups, `use`, clipPath,
  solid paints, opacity, text, data-URI images); filters, masks and gradients
  fall back to a raster. A `pdfFile` master is embedded as-is (best fidelity
  for print: keep the original vector artwork). Chrome paints nothing past ~20
  nested SVG filters: flatten such figures.

## 4. Fonts

```json
{ "name": "Adobe Garamond Pro", "redistributable": false,
  "variants": [ { "weight": 400, "style": "normal", "file": "fonts/AGaramondPro-Regular.woff2" },
                { "weight": 400, "style": "italic", "file": "fonts/AGaramondPro-Italic.woff2" },
                { "weight": 700, "style": "normal", "file": "fonts/AGaramondPro-Bold.woff2" } ] }
```

- `name` is what every `fontFamily` in the config references. Bundle **every**
  family the config uses (body, headings, callouts, captions, tables, lists,
  design text, running heads): the browser can fetch Google Fonts for missing
  names, but the PDF export and headless renders cannot.
- Provide 400/700 normal + italic where the text uses them; semibold bold →
  add 600 and `bodyText.boldFontWeight: 600`.
- `redistributable: false`: rendering and PDF embedding work, but a `.postext`
  export leaves the files out (licensed faces). Subset them (`fonts.py subset`).
- Variable fonts → static instances (`fonts.py instance`); collections →
  single faces (`fonts.py split`); horizontal scaling of the source layout →
  scaled derived face (`fonts.py scale`).
- Never write `config.customFonts`: it is built from this array.

## 5. Opening the project

- **Import**: zip the folder (`preset_kit.py pack my-book`, or
  `cd my-book && zip -r ../my-book.postext . -x '.*'`) and use Sandbox →
  Projects → *Import .postext…* at https://postext.dev/en/sandbox. The import
  takes the chapters and wording of the sandbox UI language.
- **Serve a folder of presets** (self-hosted/dev sandbox): put bundles under a
  root with an `index.json` (`preset_kit.py index <root>`):
  `{"version": 1, "presets": [{"id": "my-book", "dir": "my-book", "name": "My Book", "locale": "es"}]}`.
  In a Postext checkout set `POSTEXT_PRIVATE_PRESETS_DIR=/abs/root` in
  `apps/web/.env.local` and restart `pnpm dev`; the presets appear in the
  Projects panel (dev only). Allowed file extensions: json md svg png jpg jpeg
  webp gif pdf otf ttf woff2.
- **Permalink**: `/<ui-locale>/sandbox#preset=<id>&lang=<content locale>&view=canvas|html|pdf&chapter=<1-based>&page=<printed page number>`.

## 6. Rendering headlessly

`scripts/render.mjs` lays the project out in Node with the real engine and the
bundle's own fonts, prints warnings and writes a PDF (+ page PNGs):

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y >/dev/null && npm i postext postext-pdf react @pdf-lib/fontkit
node render.mjs my-book --lang es --out /tmp/my-book.pdf --png /tmp/my-book-pages --dpi 60
```

It mirrors the sandbox loader (defaults ← config ← localized config; chapters
joined like the book view) and reports `PARSE` issues (unclosed math/fences),
`WARN calloutOverflow`, unknown resource ids, and font families that are not
bundled. Line breaks can differ very slightly from the browser (fontkit vs
canvas metrics); the sandbox's PDF tab is the reference.

## 7. Bundles from code

The `postext` npm package reads and writes `.postext` files (exported from
`postext` and from the `postext/bundle` subpath; docs:
https://postext.dev/en/docs/configuration#bundles-postext-files).

```js
import { openBundle, loadBundleFonts, registerBundleImages, buildBundle, renderPage,
  bundleResourceBytes, bundleFontProvider, createBundle } from 'postext';
import { renderToPdf, decompressWoff2 } from 'postext-pdf';

// Open: chapters, config (customFonts wired to the bundle's files), resources.
const bundle = await openBundle(bytes, { locale: 'es' }); // Uint8Array | ArrayBuffer | Blob
await loadBundleFonts(bundle);        // browser: FontFace for every bundled face
await registerBundleImages(bundle);   // canvas backend; bundleImageUrl(bundle) for renderToHtml
const docs = buildBundle(bundle);     // one VDTDocument per chapter, chained like the Sandbox
const pdf = await renderToPdf(docs, {
  fontProvider: bundleFontProvider(bundle, { decodeWoff2: decompressWoff2, fallback }),
  resourceBytes: bundleResourceBytes(bundle),
});

// Write: payloads are looked up by fileId in `files`.
const { bytes: out, warnings } = await createBundle({
  name: 'My Book', locale: 'es',
  chapters: [{ markdown: '# Uno\n\n…' }],
  config,                                   // customFonts variants name their fileId
  resources,                                // svg.fileId / bitmap.fileId
  files: { 'fig.svg': svgText, 'serif-regular': fontBytes },
});
```

- A loaded payload's `fileId` is its path inside the bundle
  (`bundle.files.get('resources/fig.svg')`).
- `openBundle` uses the Sandbox's base config (default palette + localised
  resource types) under the manifest's `config`, and applies `localized`
  for the chosen locale, so code and Sandbox lay the book out alike.
- `createBundle` strips config defaults, writes fonts as `fonts[]` (never
  `config.customFonts`), and warns about missing payloads, `.woff` faces and
  `redistributable: false` families (left out).
- `buildBundle` lays each chapter out with the previous one's counters,
  page parity and numbering, and gives `:::toc` chapters the book outline —
  so every chapter starts on a new page, as in the Sandbox (the headless
  `render.mjs` joins the chapters into one flow instead).
- Under plain Node the dists need the extension-retrying resolve hook that
  `render.mjs` registers.
