# Postext project format (preset bundle)

A Postext **project is a book**: one config, one font set, one resource set and
an ordered list of chapters (per language). On disk it is a folder, or the same
folder zipped as a `.postext` file.

```
my-book/
  preset.json                 manifest (required) — generated by build_preset.py
  chapters/<lang>/NN-slug.md  one Markdown file per chapter (name order = book order)
  resources/                  figures: .svg .png .jpg .jpeg .webp .gif (+ .pdf print masters), videos: .mp4 .webm (+ .poster.jpg); a video at a web address (MP4 or HLS .m3u8) needs only its poster
  fonts/                      .ttf .otf .woff2 single faces (.woff and .ttc do not load)
  thumbnail.jpg               optional cover for the project picker
  fingerprint.json            optional {"fingerprint": "<sha1>"}: lets the sandbox notice edits
  layouts.json                engine-written pagination cache — never write it by hand
  layouts.<lang>.json         the same, one per edition of a multilingual book (read before layouts.json;
                              postext ≥ 1.9.1): saved from the sandbox, valid for one engine version.
                              From 1.42 the Sandbox's export writes one for every edition that has a
                              current pagination (layouts.json is the primary edition's); a stale one
                              is ignored
  build_preset.py, source/, resources.json, CREDITS.md …   yours; ignored by the loader
```

## 1. `preset.json` (manifest v2)

```jsonc
{
  "version": 2,                        // 2 = book with chapters (1 = single "markdown" file, legacy)
  "configVersion": 22,                 // the config rules `config` is written for (postext ≥ 1.5). Below 21 each
                                       // localized config replaces the shared top-level keys it names (§2). Without it the
                                       // bundle reads as 1.4: H1 breaks pinned, maths × 1.1312 when a chapter has `$`,
                                       // layout.inlineResourceGap 'above' when a chapter embeds a ::resource,
                                       // layout.inlineResourceGapInBoxes false when one sits inside a :::callout,
                                       // headings.inlineMarks false when a heading carries marks, drop caps at 1.4 size,
                                       // bodyText.colonListRoom 'line' when a list follows a line ending in ':',
                                       // layout.boxChildSplitMinLines 1 when a chapter opens a :::callout,
                                       // bodyText.breakAfterDashes false when a chapter sets a closed dash (say—that's),
                                       // bodyText.optimalRagged false when the config sets running text ragged,
                                       // bodyText.breakAfterHyphens false when a chapter sets a compound (well-known)
                                       // headings.keepWithNextSplit 'fill' when a chapter has a heading
                                       // bodyText.paragraphContainerSpacing 'add' when a paragraph style meets a :::paragraphs
  "id": "my-book",                     // [a-z0-9-], stable
  "name": "My Book",
  "description": "…", "locale": "es", "locales": ["es", "en"],
  "openLocale": "es",                  // optional: the edition opened when no language is asked for (a zh-Hant
                                       // original on a Spanish or English site); must be one of `locales`
  "binding": "right",                  // optional: the edge a shelf draws the spine on (index.json;
                                       // `preset_kit.py index` copies it there). The layout's binding is page.binding
  "thumbnail": "thumbnail.jpg", "license": "CC BY 4.0", "credits": "…", "tags": ["book"],
  "view": { "canvasScope": "book" },   // "book": the canvas lays out the whole book; default "chapter".
                                       // Books over 200 chapters open a chapter at a time whatever they ask
  "start": { "pageIndexOffset": 57, "pageNumbering": { "startAt": 58 }, "headings": { "h1": 3 } },
                                       // optional (postext after 1.26.3): where the book starts when the bundle
                                       // holds part of a longer one (page 58, an even page, in chapter 4); §2

  "chapters": {                        // or a plain array when there is one language
    "es": [ { "title": "Luz", "file": "chapters/es/01-luz.md" }, { "title": "Color", "file": "chapters/es/02-color.md" } ],
    "en": [ { "title": "Light", "file": "chapters/en/01-light.md" }, { "title": "Colour", "file": "chapters/en/02-colour.md" } ]
  },

  "config": { /* PostextConfig — see configuration.md. NEVER customFonts. */ },

  "resources": [ /* §3 */ ],
  "fonts": [ /* §4 */ ],

  "localized": {                       // per-language overrides (§2)
    "en": {
      // Only what this language sets differently, merged over `config` field by field (§2)
      "config": { "locale": "en-us", "headings": { "levels": [{ "level": 1, "numberingTemplate": "Chapter {1}" }] } },
      "resources": [ { "id": "sky", "caption": "A clear evening sky.", "altText": "…" } ],
      "view": { "canvasScope": "chapter" },  // optional: how this edition opens, over the shared `view`
      "start": { "pageIndexOffset": 58 }     // optional: where this edition starts, in place of the shared `start`
    }
  }
}
```

What the loader checks: version, id, name, the chapters shape, resource `id` +
`typeId`, font `name` + `variants[{weight: number, file}]`, and that every file
exists (a missing chapter or resource file aborts the load; a missing font file only drops that face with a
warning from postext 1.39, and a family with a `fallback` is set in it; a missing `pdfFile`
only drops the print master). It does **not** check `kind`, `typeId` against
`resourceTypes`, or anything inside `config` — `lint_project.py` does.

### Chapters

- Order = array order. The `title` is only for the UI (Books panel, TOC in
  the sandbox); it is never injected into the text. Take it from the chapter's H1.
- The sandbox joins chapters with a blank line; **nothing forces a page break
  between chapters**: a chapter opens a page through its H1's
  `headings.levels[0].breakBefore` (or a heading style's).
- **Only the first chapter's YAML front matter** (`title`, `subtitle`, `author`,
  `publishDate`) counts: it feeds `{title}`/`{subtitle}`/`{author}` in designs.
  Front matter in later chapters is ignored (with a warning).
- Split a single source at every H1 (anything before the first H1 stays in
  chapter 1; a `:::part` fence right above an H1 travels with it).
- Book layout: cover (`00-cover.md`), front matter, contents (a chapter holding
  `:::toc`), parts (`:::part` at the top of each part's first chapter),
  chapters, back matter / credits.

## 2. Languages (`localized`)

- `chapters` may map each locale to its own chapter list. The sandbox picks the
  exact tag, then the base language (`es` for `es-ES`), then `locale`, then the
  first key. Chinese keys name the script: `zh-Hans` and `zh-Hant` are two
  editions, never the same one; a reader asking for `zh-TW` or `zh-HK` gets
  `zh-Hant`, one asking for `zh` or `zh-CN` gets `zh-Hans` (postext ≥ 1.9).
  Permalinks take the same tags (`#preset=my-book&lang=zh-Hant`).
- **General settings and overrides** (`configVersion` 21, postext after
  1.57). `config` holds the general settings every edition reads;
  `localized.<lang>.config` is that language's override, with only the
  fields it sets differently, merged over `config` field by field (merge
  order: built-in defaults ← `config` ← the override):
  - objects key by key, down to single fields:
    `{ "bodyText": { "fontFamily": "Amiri" } }` changes the face and keeps
    the general size, leading and alignment;
  - a colour (`hex`) or a length (`value` + `unit`) is one value, replaced
    whole;
  - lists of entries with an `id` (`calloutStyles`, `headingStyles`,
    `chipStyles`, `colorPalette`, `resourceTypes`, a template's frames,
    `comics.cast`) entry by entry on `id`; `levels` lists (headings, lists,
    `toc`) on `level`; `customFonts` on `name`. An entry the general list
    lacks is added after its entries.
    `[{ "id": "note", "stripe": { "side": "right" } }]` moves one box's
    stripe and keeps its background;
  - `{ "id": "note", "$remove": true }` takes a general entry out for that
    language; a list in another order is written as the removal of every
    general entry, then the language's list;
  - any other list (a fallback stack, tab stops) is replaced whole;
  - `null` takes the general value out: the field reads the language's
    default.
- **General or override.** General: everything every edition should follow
  when it changes: page, margins, grid, columns, colours and palette, box,
  heading, chip and table styles, spacing, the layout of running heads,
  composed-page templates. Override: what belongs to the language:
  `locale`, the faces of its script and their size, hyphenation and
  line-breaking rules, the words of labels (`numberingTemplate`
  "Capítulo {1}", a running-head label such as "Capítulo"/"Chapter"; the
  titles come from placeholders), a side or alignment written as left or
  right. Write sides and alignments relative to the text direction in the
  general settings (`stripe.side: 'start'`, `textAlign: 'start'`) and leave
  `direction`, `page.binding` and `numerals` at auto: an Arabic edition then
  needs no override for them. The built-in resource types (Figura/Figure)
  follow each edition's `locale` without an override; give `resourceTypes`
  entries by `id` only to change their wording. A localized config
  translates labels, never the book's text: that is in `chapters.<lang>`
  and `localized.<lang>.resources` (SKILL.md, "Content in the Markdown").
  Every edition lives in this one manifest; never ship a preset per
  language.
- **Writing the overrides.** Build each edition's whole config in
  `build_preset.py` and write the difference:
  `"config": config(primary)` and `localized[lang]["config"] =
  preset_kit.diff_config_layers(config(primary), config(lang))` (the
  scaffold does this). `preset_kit.merge_config_layers(general, override)`
  shows what an edition reads. From code, the `postext` package has
  `mergeConfigLayers`, `diffConfigLayers`, `commonConfig` (what several
  whole configs agree on: the general settings of editions that each kept
  their own) and `overridePaths`.
- **Older rules.** Under `configVersion` 20 or less, and in postext 1.57 or
  earlier whatever the stamp, each top-level key of
  `localized.<lang>.config` replaces the shared one whole, so a localized
  `headings` had to carry the whole object and `lint_project.py` warns
  about keys that drop shared fields. Moving such a bundle to 21 keeps it
  correct (a restated whole object merges to itself), but rewrite the
  overrides as differences so a general change reaches every edition.
- `localized.<lang>.resources[]`: `{id, caption?, note?, altText?, table?, file?, pdfFile?, width?, height?, poster?, video?, resolution?, fileResolution?}`
  merged into the resource with the same id, field by field. `table` replaces the whole table
  (model and styleId) and `video` the whole video object; `poster` + `video` (≥ 1.17) give a language its own
  cut of a video (its own address, start, player). When `file` or `poster` differs from the shared one, the shared
  `width`, `height`, `pdfFile` and `fileResolution` are dropped and read from the new file unless restated. `file` swaps the artwork (a diagram with translated
  labels in `resources/en/…`).
- `localized.<lang>.view` (postext ≥ 1.9.2): how that edition opens, over the
  manifest's `view` (`{ "canvasScope": "chapter" }` for a translation that
  paints whole too slowly while the original opens on the whole book).
  `pickBundleView(manifest, locale)` resolves it; `openBundle` returns it as
  `canvasScope`.
- `localized.<lang>.name` and `.description` (postext ≥ 1.34.1, #891): the
  title the Sandbox's library, its import and `postext check --locale` give
  that edition; the primary edition keeps the manifest's `name`. Before
  1.34.1 every edition is named after the manifest `name`. The title the
  book prints is its first chapter's front matter `title` (what `{title}`
  prints). From 1.42 the Sandbox shows an imported book's edition titles
  (Books row, window title) as the edition on screen changes, until the reader
  renames the project: that name then stands in every language, and an export
  writes each edition's own title back as `localized.<lang>.name` only when
  the project was not renamed.
- `start` (postext after 1.26.3): where the book starts, for a bundle that
  holds part of a longer publication (an article that runs on pages 58 to 61
  of an issue, one chapter of a textbook ported on its own). It is the
  `continuation` of the first chapter, as `buildDocument` takes it:
  `pageIndexOffset` (the pages before the first: an odd count opens the book
  on an even page, with the mirrored margins and running heads of that side),
  `pageNumbering: { startAt, format }` (the folio of the first page),
  `headings: { h1, … }` (`{ "h1": 3 }` makes the first `#` chapter 4, in the
  opener and in every "Fig. 4.1"), `part: { number, title, palette? }` (the
  part left open before it) and the counters `resourceCounters`,
  `resourceNumbers`, `statementCounters`, `footnoteNumber`, `lineNumber`,
  `afterPartPage`. Not `bookPageCount`: the reader counts the pages.
  `buildBundle`, the CLI (`postext info` prints it) and the Sandbox lay the
  book out from there and chain the chapters after the first from it; the
  Sandbox keeps it with the book and writes it back on export. Leave it out
  for a book that starts at its beginning, and prefer it to faking the start
  in the content (a `:::numbering{startAt=58}` moves the folio but not the
  page side). `localized.<lang>.start` gives
  one edition its own (a right-bound edition that opens on the other side),
  `{}` an edition that starts at its beginning; `pickBundleStart(manifest,
  locale)` resolves it and `openBundle` returns it as `start`. An older
  reader ignores the field.
- Two *different* books per language (not a translation): give resources
  language-prefixed ids, keep them all in the shared list, and leave
  `localized.resources` empty.
- Always put `config.locale` (`es`, `en-us`, `fr`, `de`, `it`, `pt`, `ca`, `nl`, `zh-Hans`, `zh-Hant`…):
  hyphenation, built-in resource types, table continuation strings ("(cont.)") and the PDF `/Lang`.
  A Chinese edition next to a Latin one restates in its `localized.<lang>.config` at least `locale`,
  `bodyText` (a Chinese face, 2 em indent), `headings` (Chinese face, `第{1:一}章`), `captionStyle`,
  `orderedLists` and, when it is set vertically, `layout` (`writingMode`) and `page`
  (the Chinese folios); `cjk` only where it differs from the region's defaults.

## 3. Resources

Figures, photos, diagrams and tables are **resources**, never Markdown. The
chapter cites them with `:ref{id="…"}` (floats, numbered by first mention) or
embeds them with `::resource{id="…"}` (placement `here`).

```jsonc
// bitmap — ALWAYS declare width/height in pixels (Node renderers cannot decode images)
{ "id": "neptune-spot", "typeId": "figure", "kind": "bitmap", "file": "resources/neptune-spot.jpg",
  "width": 3200, "height": 1800,                 // the file's pixels, never print-size arithmetic
  "resolution": 300,                             // ≥ 1.24, optional: ppi at its natural print size (3200 px = 271 mm)
                                                 // on a page of any dpi; or layout.bitmapResolution for every bitmap
  "caption": "Dark spot on *Neptune*.",          // inline markup allowed; the label/number is added
  "note": "Credit: ESO/P. Irwin et al.",         // credit line under the caption; `\\` (or `\` at a line end) starts a new line, in captions too
  "altText": "A blue planet with a dark oval",   // always write it (tagged PDF)
  "safeArea": { "x": 0.3, "y": 0.2, "width": 0.4, "height": 0.6 }, // optional: the part always shown (fractions); lets the engine crop the rest to fit or balance a column
  "placement": { "position": "top", "span": "page" } }

// svg — size read from width/height/viewBox if omitted; optional vector print master
{ "id": "cell-diagram", "typeId": "figure", "kind": "svg", "file": "resources/cell-diagram.svg",
  "pdfFile": "resources/cell-diagram.pdf",       // single-page PDF embedded verbatim in the PDF export
  "inlineFonts": false,                          // optional (≥ 1.25): keep the markup as stored, no fonts embedded
  "caption": "…", "placement": { "position": "auto", "span": "column" } }

// table — a TableModel, no file
{ "id": "spectrum", "typeId": "table", "kind": "table", "caption": "Visible spectrum bands.",
  "note": "Source: …",
  "placement": { "position": "here", "span": "column", "width": 0.8, "align": "center" },
  "table": { "styleId": "compact",               // optional tableStyles entry
    "model": { "headerRowCount": 1, "columnWidths": [2, 1],
      "rows": [
        [ {"content": "Colour", "isHeader": true}, {"content": "nm", "isHeader": true, "align": "right"} ],
        [ {"content": "**Red** :swatch{color=\"band\"}", "background": {"hex": "#fde2e4", "model": "hex"}}, {"content": "620–750", "align": "right"} ],
        [ {"content": "Blue", "image": {"resourceId": "shapes", "width": 0.5}, "verticalAlign": "middle"}, {"content": "450–495"} ],
        [ {"content": "Visible range", "colSpan": 2, "align": "center"}, {"content": "", "hiddenBy": {"row": 3, "col": 0}} ]
      ] } } }

// video — YouTube / Vimeo (no file) or an own file; printed as its poster with a
// play mark and a QR code (config.videoStyle), played in HTML and EPUB
{ "id": "keeper-talk", "typeId": "video", "kind": "video",
  "poster": "resources/keeper-talk.poster.jpg", "width": 1280, "height": 720, // poster size: ALWAYS declare it
  "caption": "The keeper explains the lamp.", "altText": "A keeper beside the lamp",
  "video": { "source": "youtube", "url": "https://youtu.be/aqz-KE-bpKQ", "start": 30 } }
{ "id": "lamp-turning", "typeId": "video", "kind": "video",
  "file": "resources/lamp-turning.mp4",          // own file, carried by the bundle
  "poster": "resources/lamp-turning.poster.jpg", "width": 1920, "height": 1080,
  "video": { "source": "file", "format": "mp4",
    "url": "https://media.example.org/lamp-turning.mp4", // production address: QR code, PDF link, EPUB fallback
    "player": { "download": false } } }
{ "id": "reel", "typeId": "video", "kind": "video",  // a video at an address only: no "file"
  "poster": "resources/reel.poster.jpg", "width": 1280, "height": 720,
  "video": { "source": "file", "format": "hls",       // "hls" for an .m3u8 stream (inferred from the extension)
    "url": "https://media.example.org/reel/master.m3u8" } } // plays in HTML and on Folio's pages; EPUB links the poster
```

- **Tables**: every row holds one entry per grid column; a merged cell gets
  `colSpan`/`rowSpan` and every slot it covers stays as
  `{"content": "", "hiddenBy": {"row": r, "col": c}}`. `columnWidths` are relative
  weights. Cell `content` is an inline snippet: `**bold**`, `*italic*`,
  `^sup^`, `~sub~`, `:ref`, `:swatch`, `:chip`; `\n` separates paragraphs; a
  paragraph starting with `• `, `– `, `1. ` is a hanging list item (two leading
  spaces per nesting level). Inline `$math$` works in cells, captions and notes from postext 1.19 (Pandoc's rule; `\$` for a dollar).
  `image` draws a bitmap/SVG resource in the cell (width = fraction of the cell).
  `background` fills the cell (link it to a palette id to re-theme).
- **placement**: `position` `auto` (float to the first free slot after the first
  `:ref`) | `top` | `bottom` | `here` (inline at the `::resource` line);
  `span` `column` | `page` | `side` (the float column of a `oneAndHalf` layout);
  `width` 0–1 + `align` (`align` also places a bitmap/SVG narrower than its slot,
  e.g. a small bitmap or one `fitFiguresToPage` shrank); `captionSide: true` (caption in the side column beside
  a main-column figure, floated or, ≥ 1.28, set `here`); `rotate: "ccw"|"cw"` (landscape table/figure on its own
  page, spine-flush; split between rows when too long). Missing fields fall
  back to the resource type's `defaultPlacement`, then `auto`/`column`. More fields (`wrap` beside or round the
  picture, `shrink`, `minScale`, `captionMeasure`, `citingPage`, `columns`): configuration.md §15. A picture the
  text runs round (postext ≥ 1.36; PNG with transparency, or `contour.points` for any picture):
  ```jsonc
  { "id": "pear", "typeId": "figure", "kind": "bitmap", "file": "resources/pear.png", "width": 600, "height": 800,
    "placement": { "position": "here", "wrap": "contour", "align": "right", "width": 0.42 },
    "contour": { "threshold": 0.5, "margin": { "value": 2, "unit": "mm" } } }
  ```
- A `here` resource that is only `:ref`'d and never `::resource`'d is numbered
  but never placed.
- **Comic panel pictures** are bitmap or SVG resources placed by
  `::panel{art=id}` (never cited). Besides `safeArea` they carry `anchors`
  (speaker mouths, heads, faces), `avoid` zones and `faces` (the faces of
  people who do not speak, postext ≥ 1.28), all in fractions of the
  picture and shared by every language; `preset_kit.bitmap(…, safe_area=,
  anchors=, avoid=, faces=)` writes them. See comics.md §9.
- **Videos**: numbered in their own sequence by the built-in `video` type
  (Video 1.1), added on its own to a `resourceTypes` list that lacks it. Without
  a poster they print a dark 16:9 box; an own file without `video.url` gets no
  QR code or PDF link. Poster overlays and player options live in
  `config.videoStyle` (`playMark`, `qr`, `linkPoster`, `html`, `player`).
- `video` fields besides `source`/`url`/`format`/`player`: `start` / `end` (seconds; it plays that part, and the QR
  code and PDF link start at `start`), `width` / `height` (the frame size in px: its ratio when there is no poster;
  the manifest's top-level `width`/`height` are the poster's), `duration` (seconds, informative) and `posterTime`
  (second of a file's frame used as the poster, informative). `url` accepts any YouTube form (watch, youtu.be,
  Shorts, embed, youtube-nocookie) or Vimeo page (unlisted with its hash).
- The poster is set at its slot's measure (or `placement.width`) in its own ratio, enlarged if small; it takes a
  `safeArea` and `placement.align` like a bitmap.
- Video warnings: `videoWithoutPoster` (dark box in the video's ratio, 16:9 when unknown), `videoWithoutUrl` (a file
  with no production `url`: no QR code, no link; HTML/EPUB without the file show the poster), `videoUrlInvalid` (a
  YouTube/Vimeo address that names no video: poster instead of a player).
- **Resource types** (`config.resourceTypes`): `figure`, `table` and `video`
  exist by default in the document's language (`locale`; English for a language
  without strings); declare them to rename or restyle. Custom types
  for plates, ornaments, artwork, sub-tables… An empty `numberingTemplate` (or
  caption prefix) makes an unnumbered type (ornaments, decorative artwork,
  credit-line photos). Numbering: `{n}`, `{h1}.{n}`, `{h1}-{n}` with `resetOn`
  and `counterFormat` (decimal, roman-upper…). From postext 1.38 a type may
  leave fields out: `{ "id": "foto", "numberingTemplate": "" }` is a whole
  unnumbered type (the built-in type of the same id, else the id and `{h1}.{n}`,
  fill the rest); older engines need every field.
- Ids: descriptive slugs from the caption (`fig-cohort-study`), never numbers —
  numbers are computed from the first mention, so chapters can move.
- Words drawn inside an SVG: keep them as `<text>` and name the family in
  `font-family` (postext ≥ 1.25). An `<img>` cannot see the page's fonts, so
  the engine embeds the faces the text names as `@font-face` data URIs when
  the picture is shown (canvas, HTML, EPUB): the bundle's own fonts first,
  then registered families and those of Google Fonts or Fontsource. The PDF sets SVG `<text>` with the
  document's embedded faces. No outlining, no hand-made `@font-face`; set
  `"inlineFonts": false` on an SVG resource that carries its own faces or
  must stay byte-identical. Checks: `svgFontUnavailable` (a family with no
  face), `svgFontsTooLarge` (over 2 MB).
- The PDF backend draws an SVG vector subset (paths, groups, `use`, clipPath,
  solid paints, opacity, text, data-URI images); filters, masks, gradients and
  style sheets fall back to a raster, except a `<style>` holding only
  `@font-face` rules (≥ 1.25), which stays vector. A `pdfFile` master is embedded as-is (best fidelity
  for print: keep the original vector artwork). Chrome paints nothing past ~20
  nested SVG filters: flatten such figures.

## 4. Fonts

```json
{ "name": "Adobe Garamond Pro", "redistributable": false,
  "variants": [ { "weight": 400, "style": "normal", "file": "fonts/AGaramondPro-Regular.woff2" },
                { "weight": 400, "style": "italic", "file": "fonts/AGaramondPro-Italic.woff2" },
                { "weight": 700, "style": "normal", "file": "fonts/AGaramondPro-Bold.woff2" } ] }
```

- `name` is what every `fontFamily` in the config references. Bundle **every**
  family the config uses (body, headings, callouts, captions, tables, lists,
  design text, running heads). The Sandbox and the `postext` command line
  fetch a missing family from Google Fonts, or from Fontsource when Google
  Fonts does not have it; `render.mjs` downloads nothing, measures a missing
  family with a stand-in face and embeds only bundled faces in its PDF.
- Provide 400/700 normal + italic where the text uses them; semibold bold →
  add 600 and `bodyText.boldFontWeight: 600`.
- `fallback` (postext ≥ 1.42): `"fallback": "<open family>"` on a `fonts` entry
  names the family that stands in for a licensed one the pack leaves out. Write
  such a family as `{ "name": "Adobe Garamond Pro", "redistributable": false,
  "variants": [], "fallback": "EB Garamond" }`: it stays in the manifest with
  no file, and every host (the Sandbox, `postext`, `postext-pdf`'s bundle font
  provider, `loadBundleFonts`) sets the faces it has no file of in the
  fallback's cuts of the same weight and slant, under the licensed name. A
  family that keeps files keeps them and takes only a slant it has none of
  (an italic) from the fallback. Why: the plain bundle used to lay out in the
  generic fallback face, wider than the real one, so about every twentieth
  frame of a composed book reported `frameOverflow` and `missingFont` /
  `bundle` warnings filled the report; with a stand-in of about the same
  width the plain bundle checks near the real one, and `composed_check.py` and
  the Checks panel can be run on it. The final PDF is still made from the
  bundle that carries the faces (the PDF of the plain one embeds the open
  face). The import prints one line per family (`none of its font files are in
  the bundle, those faces are set in <fallback>`) in place of a `missingFont`
  per face; a family with no `fallback` behaves as before. `render.mjs` does not read `fallback` (verification.md §2).
- Pick the stand-in by measurement, not by name: `fonts.py width LICENSED.ttf
  CANDIDATE.ttf… --text-from chapters/<lang>/` sets a paragraph of the book in
  each face at the body size and prints the candidate's width as a ratio of the
  licensed face's (serif candidates: Source Serif 4, Noto Serif, PT Serif, EB
  Garamond, Libre Baskerville, Lora; sans: Source Sans 3, Open Sans, Noto Sans,
  Lato). Run it for regular, bold and italic and keep the candidate within
  about 2 % in all three. If none is within 5 %, say so in the port notes and
  deliver both bundles with the warning that only the one with its faces is
  checked. `preset_kit.py pack --fallback "Adobe Garamond Pro=EB Garamond"`
  writes the entry; record the choice and the measured ratio in the port notes.
- The stand-in travels in exports (postext ≥ 1.43). A family with
  `"redistributable": false` and a `fallback` is no longer left to the reading
  system in an EPUB or HTML export: the Sandbox and `postext epub` /
  `postext html` embed the fallback's faces (the weights and slants the book
  uses) under the licensed family's name, and so do the SVG pictures whose text
  is set in that family. The family's own files never leave the book. A
  family without a `fallback`, or whose fallback has no file, is named without
  files as before. A fallback that is itself a family the bundle carries is
  used from the bundle's own files first; one that only Google's style sheet
  serves (not Fontsource) works in the Sandbox PDF and in SVG pictures too.
  Because the fallback now travels, it must be open (OFL, Apache or similar):
  `lint_project.py` errors when it names a family of the same manifest marked
  `redistributable: false`, and `pack` should offer one by measured width
  (above), never by name. EPUBCheck sees the stand-in faces as ordinary font
  items named after the licensed family.
- `redistributable: false`: rendering and PDF embedding work, but a `.postext`
  export leaves the files out (licensed faces). Subset them (`fonts.py subset`). A bundle that names
  font files it does not carry imports into the Sandbox with the family reported as unknown (postext
  ≥ 1.39, #904): the `fonts` entries need not be dropped from the manifest.
- Variable fonts → static instances (`fonts.py instance`); collections →
  single faces (`fonts.py split`); horizontal scaling of the source layout →
  scaled derived face (`fonts.py scale`).
- Never write `config.customFonts`: it is built from this array.

## 5. Opening the project

- **Import**: zip the folder (`preset_kit.py pack my-book --manifest-only`
  packs `preset.json` and only the files it names; without the flag, or with
  `zip -r`, every file of the folder but `source/`, scripts and caches goes
  in, so keep work folders and tool outputs outside the project or add
  `--exclude GLOB`) and use Sandbox → Books → New → *Open a .postext file…*
  at https://postext.dev/en/sandbox. A bundle with several languages is kept
  whole as one book from postext 1.39 (editions beside the one open, switched from
  the Books row or the edition bar; before, the import asked which one to keep and
  held that edition only: import each edition to check it). The Sandbox
  keeps the working book in about 5 MB of browser storage: keep the config
  under 1 MB (`preset_kit.py lint` prints its size and warns from 3 MB; a
  config of several MB can break the import and the saves).
- **Serve a folder of presets** (self-hosted/dev sandbox): put bundles under a
  root with an `index.json` (`preset_kit.py index <root>`):
  `{"version": 1, "presets": [{"id": "my-book", "dir": "my-book", "name": "My Book", "locale": "es"}]}`.
  In a Postext checkout set `POSTEXT_PRIVATE_PRESETS_DIR=/abs/root` in
  `apps/web/.env.local` and restart `pnpm dev`; the presets appear under
  *Sample books* in the Books panel (dev only). Allowed file extensions: json md svg png jpg jpeg
  webp gif pdf otf ttf woff2.
- **Permalink**: `/<ui-locale>/sandbox#preset=<id>&lang=<content locale>&view=canvas|pdf|folio|html|epub&chapter=<1-based>&page=<printed page number>`.

## 6. Rendering headlessly

While working, keep the project unpacked and let the `postext` executable lay
it out on every save (verification.md §2):

```bash
postext build my-book --locale es --images /tmp/pages --pages 12-15 -f jpeg --watch > /tmp/watch.log 2>&1 &
```

It reads only the files the manifest names (the generator, `source/` and the
other project files are ignored, and so are their changes), and
`postext pack my-book` zips the folder without `source/`, dot files, `*.py`,
`resources.json`, `chapters.json`, `report.md`, `roles.json` and `layouts*.json`,
but **with every font file**, those of `redistributable: false` families
included, and with the manifest as written. To ship, use `preset_kit.py pack`
(it leaves licensed faces out and writes their `fallback` entries), with
`--manifest-only` to ship only what the manifest names.

`scripts/render.mjs` lays the project out in Node with the real engine and the
bundle's own fonts, prints warnings, and writes chosen pages as JPEGs
(painted by the engine's canvas renderer) and/or a PDF:

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y >/dev/null && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
node render.mjs my-book --lang es --jpeg /tmp/pages --pages 12-15     # the pages that print 12–15 → /tmp/pages/page-NNN.jpg
node render.mjs book.postext --jpeg /tmp/pages --pages '#1'            # a packed bundle works too; '#n' = n-th page of the layout
node render.mjs my-book --lang es --out /tmp/my-book.pdf               # the PDF, for print checks
```

One-shot JPEGs from `render.mjs` are the fallback for the loop, and with
`--repo <checkout>` its `SANDBOX-WARN` lines a milestone check (verification.md §2);
`--png` rasterises the PDF instead and needs poppler.

It mirrors the sandbox loader (defaults ← config ← localized config, merged field by field from configVersion 21; chapters
joined like the book view). A manifest without `configVersion` is read as the
Sandbox reads it, with the 1.4 rules pinned (§1), and a `NOTE` line names the
rules it kept. It reports `PARSE` issues (unclosed math/fences),
`WARN calloutOverflow`, unknown resource ids, and font families that are not
bundled. Line breaks can differ very slightly from the browser (fontkit vs
canvas metrics); the sandbox's PDF tab is the reference. A config that names
no language (`locale` or `bodyText.hyphenation.locale`) hyphenates in en-us
here, while the Sandbox falls back to the language of its interface: set
`config.locale` (the linter notes a missing one).

## 7. Bundles from code

The `postext` npm package reads and writes `.postext` files (exported from
`postext` and from the `postext/bundle` subpath; docs:
https://postext.dev/en/docs/configuration-bundles#bundles-postext-files).

```js
import { openBundle, loadBundleFonts, registerBundleImages, buildBundle, renderPage,
  bundleResourceBytes, bundleFontProvider, createBundle } from 'postext';
import { renderToPdf, decompressWoff2 } from 'postext-pdf';

// Open: chapters, config (customFonts wired to the bundle's files), resources.
const bundle = await openBundle(bytes, { locale: 'es' }); // Uint8Array | ArrayBuffer | Blob
await loadBundleFonts(bundle);        // browser: FontFace for every bundled face (drops stale widths)
// Families the bundle names but does not carry (Google Fonts, or Fontsource): prepareFonts(chapters, bundle.config, { resolve })
await registerBundleImages(bundle);   // canvas backend; bundleImageUrl(bundle) for renderToHtml
const docs = buildBundle(bundle);     // one VDTDocument per chapter, chained like the Sandbox
const pdf = await renderToPdf(docs, {
  fontProvider: bundleFontProvider(bundle, { decodeWoff2: decompressWoff2, fallback }),
  resourceBytes: bundleResourceBytes(bundle),
});

// Write: payloads are looked up by fileId in `files`.
const { bytes: out, warnings } = await createBundle({
  name: 'My Book', locale: 'es',
  chapters: [{ markdown: '# Uno\n\n…' }],
  config,                                   // customFonts variants name their fileId
  resources,                                // svg.fileId / bitmap.fileId
  files: { 'fig.svg': svgText, 'serif-regular': fontBytes },
});
```

- A loaded payload's `fileId` is its path inside the bundle
  (`bundle.files.get('resources/fig.svg')`).
- `openBundle` uses the Sandbox's base config (default palette + localised
  resource types) under the manifest's `config`, and applies `localized`
  for the chosen locale, so code and Sandbox lay the book out alike. The
  resource types are in the language the bundle serves (`bundle.locale`):
  a one-language bundle keeps its own whatever locale is asked for. A
  manifest with no `locale` takes the language its `config` sets
  (`locale`, then the hyphenation locale).
- `createBundle` strips config defaults, writes fonts as `fonts[]` (never
  `config.customFonts`), and warns about missing payloads, `.woff` faces and
  `redistributable: false` families (left out). Pass `mtime: new Date(1980, 0, 1)`
  for byte-identical output (otherwise every file is dated now). Build the
  date from local fields: a zip stores local time, so a timestamp or a
  `…Z` string gives different bytes in each time zone.
- `createBundle` also takes `id`, `description`, `markdown` (a one-chapter book), `thumbnail: { data, mime }`,
  `canvasScope: 'book'`, `start` (§2), and `localized: { en: { name?, description?, chapters?, config?, resources?,
  start? } }` for more editions: `chapters`, `config` and `resources` above are then the `locale` edition
  (required). Each top-level key of a localized `config` you pass replaces the shared one for that language, and
  the manifest stores the difference as an override (configVersion 21, §2); `planBundle` (`postext/bundle`) takes
  `sharedConfig` to write general settings apart from the primary edition. `resources` carry the wording
  (`caption`, `note`, `altText`, `table`) and the artwork with words (`bitmap.fileId` / `svg.fileId`) by `id`.
- `buildBundle(bundle, { config, metadata, onChapter, layoutCache })`: `config` lays out with another config,
  `metadata` fills `{title}`/`{author}` (front matter wins), `layoutCache: createBundleLayoutCache()` reused across
  builds lays out again only the chapters whose inputs changed (`stats` says which).
- `buildBundle` lays each chapter out with the previous one's counters,
  page parity and numbering, and gives `:::toc` chapters the book outline —
  so every chapter starts on a new page, as in the Sandbox (the headless
  `render.mjs` joins the chapters into one flow instead).
- Under plain Node the dists need the extension-retrying resolve hook that
  `render.mjs` registers.


### Design files (≥ 1.79)

A design file is a `.postext` with no chapters: a book's design without its text. The manifest says
`design: { parts: [...] }` and `chapters: []`; `config` holds only the settings of those parts, with the
font files (`fonts/`) and the colour profile (`profiles/`) they name. The parts are the Sandbox Design
panel's groups (`DESIGN_PARTS`: page, writing, colors, text, composition, headings, lists, figures, callouts,
exercises, comics, running, parts, output, folio, advanced; `DESIGN_PART_KEYS` maps each to its settings). The book's
own settings (`BOOK_OWN_KEYS`: locale, direction, numerals, resourceTypes, checks, debug) never go in one.
≥ 1.80 `composition` holds the composition rules inside `bodyText` (hyphenation minWordLength, leftMin, rightMin,
capitalized, fewerHyphens, ladders, maxConsecutive, ladderPenalty, lastWord, lastWordPenalty; hyphenateAcrossColumns,
stacks, stackMinCharacters, stackPenalty, citationBreaks, citationBreakPenalty, operatorBreaks, operatorBreakPenalty);
`text` keeps the rest of `bodyText`, so a design's type and its rules apply apart. A 1.79 design whose `text` holds
some of those rules reads with `composition` too.

```js
import { extractDesign, applyDesign } from 'postext';
import { createDesignBundle, openDesignBundle } from 'postext/bundle';
const design = extractDesign(book.config, ['page', 'text', 'headings']);
const { bytes } = await createDesignBundle({ name: 'House style', locale: 'es', design, files });
const opened = await openDesignBundle(bytes);           // or a whole book's .postext: fromBook: true
const config = applyDesign(other.config, opened.design); // named styles merge by id, fonts by family
```

- From the command line: `postext design my-book -o house.postext [--parts page,text,headings]`, and any
  command takes `--design house.postext [--design-parts …]` to set the book in it before `--config`/`--set`,
  and (≥ 1.80) `--composition es|en-US|en-GB|fr|de|auto` to set a language's composition convention after it.
- Composition conventions (≥ 1.80): `COMPOSITION_CONVENTIONS`, `compositionConventionFor(tag)`,
  `compositionConventionDesign(c)` (a design for `applyDesign`), `followsCompositionConvention(config, c)`. Spanish:
  ladders 'avoid' + maxConsecutive 1, lastWord 'avoid', stacks 'avoid', hyphenateAcrossColumns false; en-US and fr:
  ladders 'avoid' + 3, lastWord 'avoid'; en-GB: ladders 'avoid' + 2, lastWord 'avoid'; de: ladders 'avoid' + 3.
  A port keeps the original's breaks: leave the rules off (or 'warn' for proofs) unless the publisher asks for its
  house rules on new titles; then ship them as a composition-only design file.
- When a publisher's titles share a house design, port it once as a design file and give each title only
  what it changes; the Sandbox's Design panel imports the same file (Designs).
