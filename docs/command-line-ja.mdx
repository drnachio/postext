# コマンドライン

**`postext`は、ターミナル、スクリプト、エージェントから本を組みます。**

[Sandbox](/ja/sandbox)は、目で確かめながら本を書き、デザインする場所です。コマンドラインは同じ本を受け取り、ブラウザーなしでそのファイルを作ります。印刷用のPDF、HTMLのページ、EPUB、1ページまたは全ページの画像、Wordの文書です。ほかに、`.postext`バンドルをまとめたり展開したり、Wordの文書を読み込んだり、本の内容を示したり、本に問題がないかを検査したりもします。

システムごとに**自己完結した1つの実行ファイル**です。postextのエンジン、PDF、EPUB、HTML、Wordの書き出し、ページを描くペインター（Skia）、アラビア語などの複雑な文字のためのHarfBuzz、印刷用のICCプロファイル、既定のフォント（EB GaramondとOpen Sans）がすべて入っています。インストールするランタイム、パッケージ、ライブラリーはありません。レイアウトはSandboxと同じなので、同じ本は同じページに分かれます。

## 入手する

macOSまたはLinuxでは[Homebrew](https://brew.sh)を使います。

```bash
brew install drnachio/postext/postext
```

Windowsでは[Scoop](https://scoop.sh)を使います。

```powershell
scoop bucket add postext https://github.com/drnachio/scoop-postext
scoop install postext
```

どちらも最新リリースの実行ファイルをチェックサムで確かめてから`postext`コマンドとしてインストールし、`brew upgrade postext`や`scoop update postext`で次のリリースに更新します。パッケージマネージャーを使わない場合は、ファイルを自分でダウンロードします。

Postextのリリースごとに、実行ファイルが[GitHub Release](https://github.com/drnachio/postext/releases/latest)で公開されます。チェックサム（`SHA256SUMS`）と`readme.txt`も付いています。

各ファイルの大きさは115〜140 MBです。`https://github.com/drnachio/postext/releases/latest/download/<file>`のリンクは、つねに最新のものを指します。

LinuxまたはmacOSでは次のとおりです。

```bash
curl -fL -o postext https://github.com/drnachio/postext/releases/latest/download/postext-linux-x64
chmod +x postext
./postext
```

`PATH`の通ったフォルダー（`/usr/local/bin`、`~/.local/bin`）に移すと、どこからでも`postext`として実行できます。macOSは、ブラウザーでダウンロードしたファイルを隔離します。一度だけ、そのフラグを外します。

```bash
xattr -d com.apple.quarantine postext-macos-arm64
```

Windowsでは、PowerShellで次のようにします。

```powershell
Invoke-WebRequest https://github.com/drnachio/postext/releases/latest/download/postext-windows-x64.exe -OutFile postext.exe
.\postext.exe
```

Node.jsがあれば、`npx postext-cli`が自分のシステム用の実行ファイルをnpmからダウンロードして実行します。`npm install -g postext-cli`なら、`postext`コマンドとして残ります。

引数なしで実行すると、`postext`はヘルプを表示します。`postext help <command>`は1つのコマンドのオプションを一覧にします。

## 最初の本

フォルダーに入れた3つのMarkdownファイルは、それだけで1冊の本です。ファイルごとに1章になり、名前の順に並びます。

```bash
postext pdf chapters/ --name "Field notes" -o field-notes.pdf
```

最初の章のフロントマターが本のタイトルと著者を決め、残りはエンジンの既定値が受け持ちます。2段組み、ベースライングリッド、両端そろえとハイフネーション、柱です。必要になったら、設定と画像を加えます。

```bash
postext pdf chapters/ --config design.json --resources pictures/ -o field-notes.pdf
```

Sandboxで作った本（**本**パネルの<strong>ダウンロード（.postext）</strong>）は、そのまま使えます。

```bash
postext pdf my-book.postext -o my-book.pdf
postext image my-book.postext --page 1 -o cover.png
```

## 本として読めるもの

本を読むコマンドは、どれも次のいずれかを受け付けます。

- **`.postext`ファイル**：Sandboxが書き出し、開くバンドルです（[バンドル](/ja/docs/configuration-bundles#バンドルpostextファイル)を参照）。
- **本のフォルダー**：バンドルを展開したもので、`preset.json`、章、リソース、フォントが入っています。エージェントスキルが納品するのはこの形で、`postext unpack`もこれを書き出します。
- **ばらのMarkdown**：1つ以上の`.md`ファイルで、指定した順に1ファイル1章になります。フォルダーを渡すと、その中の`.md`ファイルを名前の順に読みます（`01-intro.md`、`02-method.md`…）。あわせて次のものを指定できます。
  - `--config design.json`：設定です。設定のオブジェクトだけでも、`preset.json`全体でもかまいません。
  - `--resources pictures/`：画像です。それぞれ、拡張子を除いたファイル名を名前とする図になります（`map.png`は`::resource{id="map"}`）。フォルダーに`resources.json`があれば、代わりにそれが画像を記述します（id、種類、キャプション、代替テキスト）。形式は`preset.json`の`resources`と同じです。
  - `--fonts fonts/`：本に含めるフォントファイル（TTF、OTF、WOFF2）です。フォントのテーブルが示すファミリー名で識別されます。
  - `--name "Title"`：本の名前です。

`--config`はバンドルやフォルダーにも使え、本自身の設定の上に統合されます。多言語のバンドルは、`--locale`で別の言語を求めない限り（`--locale en`）、バンドル自身の言語で読まれます。

どのコマンドも、`-o`でパスを指定しない限り、実行した場所に入力の名前で書き出します（`images`は`pages/`に書き出します）。`-o -`は、1つの出力を標準出力に書き出します。

### pdf

```bash
postext pdf book.postext -o book.pdf
postext pdf book/ --pdfx x4 --profile fogra51 -o book-print.pdf
postext pdf book/ --color-space grayscale --no-outlines
```

PDFは本自身の設定に従います（[PDF生成](/ja/docs/configuration-fonts-colors-viewers#pdf生成設定)と[印刷出力](/ja/docs/configuration-fonts-colors-viewers#印刷出力設定)を参照）。次のオプションは、1回の実行に限ってそれを変えます。

- `--pdfx none|x1a|x4`：印刷所向けのPDF/X規格。
- `--profile NAME|FILE`：出力ICCプロファイル。名前（`fogra39`、`fogra51`、`fogra52`、`swop5`、`gracol2006`、`snap2007`、`ifra26`など、印刷設定のプロファイル）か、`.icc`ファイルで指定します。
- `--color-space rgb|cmyk|grayscale`。
- `--accessible` / `--no-accessible`：スクリーンリーダーのためのタグ構造。
- `--no-outlines`：しおりを入れません。
- `--page-negative`：一部の印刷ワークフロー向けのネガのページ。

### html

```bash
postext html book.postext -o book.html
postext html book.postext -o site/ --mode single
```

`.html`で終わるパスには、画像とフォントを中に収めた1つのファイルを書き出します。送るのに便利です。それ以外のパスはフォルダーになり、`index.html`の横に`assets/`を置きます。`assets/`には画像、フォント、自前でホストする動画が入ります。`--assets embed|folder`を使うと、どのパスでもどちらかを選べます。ページは印刷用のレイアウトを画面の大きさで表示したもので、横に並べるか（`--mode multi`、既定）、縦に重ねるか（`--mode single`）を選べます。`redistributable: false`と指定したフォントは、名前は記されますがコピーはされません。フォントが`fallback`を指定している場合は、代わりにそのオープンフォントの書体が、元のフォントの名前で書き出されます（postext 1.43以降）。

### epub

```bash
postext epub book.postext -o book.epub
postext epub book.postext --layout reflowable --cover cover.jpg
```

`--layout fixed`（既定）は、すべてのページを印刷したとおりに保ち、テキストは選択できます。`--layout reflowable`は、読書システムがその画面に合わせてテキストを組み直せるようにします（[EPUBの本](/ja/docs/configuration-html-folio-epub#epubの本postext-epub)を参照）。表紙は、`--cover`で画像を指定しない限り本のサムネイルです。パッケージのメタデータ（タイトル、著者、言語、識別子）は、Sandboxと同じく最初の章のフロントマターから取ります。`redistributable: false`のフォントはコピーされません。`fallback`を指定したフォントは、そのオープンフォントの書体が元のフォントの名前で埋め込まれます（postext 1.43以降）。

### imageとimages

```bash
postext image book.postext --page 12 -o page-12.png
postext image book.postext --page "#1" --dpi 300 -f jpeg -o cover.jpg
postext images book.postext -o pages/ --dpi 100
postext images book.postext --pages 1-10,iv -f webp --pattern "{chapter}-{label}"
```

ページは、**印刷された番号**（`12`、`iv`、範囲の`7-9`）か、`#`を付けた**本の中の位置**（`#1`は何が印刷されていても最初のページ、`#10-#20`、終わりまでの`#30-`）で指定します。`--pages`はコンマ区切りのリストを受け付けます。描画するのはSandboxのCanvasビューと同じペインターなので、画像はPDFを経ずに、レイアウトしたとおりのページを示します。

- `--format png|jpeg|webp`（または`-o`の拡張子）。JPEGとWebPには`--quality 1-100`。
- `--dpi`：解像度。既定は150です。ページを読むには72〜100で足り、印刷用には300です。
- `--pattern`：`images`が書き出すファイルの名前。`{n}`（位置。`{n:03}`は3桁にゼロで埋めます）、`{label}`（印刷された番号）、`{chapter}`から作ります。既定は`page-{n:03}`です。
- `--print-preview`：出力プロファイルを通して、印刷所が再現するとおりのページを、仕上がり線と塗り足しを描いて示します。
- `--jobs N`：同時にエンコードする画像の数（既定では、コンピューターのプロセッサーの数）。

### docxとimport-docx

```bash
postext docx book.postext -o book.docx
postext docx book/ --variant semantic -o words.docx
postext docx book/ --variant facsimile -o pages.docx
postext import-docx book.docx book/ --dry-run
postext import-docx book.docx book/
postext import-docx manuscript.docx -o manuscript/ --locale es --report
```

`docx`は、Sandboxが書き出すWord文書（[Sandbox › Word文書](/ja/docs/sandbox-books-saving#word文書)を参照）と、もう1種類を書き出します。既定の`--variant formatted`は、Markdownから編集できる文書を組み立て、Word自身の見出し、リスト、脚注、表、数式、セクションを使い、Wordでできる範囲で本のデザインどおりに組んで、本のフォントを埋め込みます（`--no-embed-fonts`なら名前だけを指定します）。Wordに対応する構造がないものは、*Postext Source*のコンテンツコントロールにソースのまま入ります。`--variant semantic`は、同じテキストを内容だけの文書として書き出します。A4、1段組、Arialの簡素な文書で、各部分が何であるかを示すWordのスタイルを使い、ページのデザインもフォントの埋め込みもありません。どちらも組版は必要なく、WordでもGoogleドキュメントでも開け、`import-docx`で戻せます。`--variant facsimile`は`pdf`と同じように本を組み、各ページをWordのセクションとして、各行を固定のテキストボックスに入れ、フォントを埋め込んで書き出します。デスクトップ版のWordでレイアウトを見るためのファイルで、編集やGoogleドキュメントには向きません。本が配布できないファミリー（`customFonts`の`redistributable: false`）は外し、EPUBと同じく、そのオープンな代替フォントを入れます。ライセンスが埋め込みを禁じるフォント、PostScriptのアウトラインを持つフォント、可変フォントは、報告したうえで名前だけを指定します。`build`では、`--docx FILE`が同じファイルを書き出し、`--docx-variant`と`--no-docx-fonts`を使えます（postext 1.68以降）。`--template`は`docx`と`build`には効かなくなりました。

ファイルのあとに本を指定すると、`import-docx`は、その本から`docx`で書き出した文書に加えた校正を本に戻します。ファイルが持つ対応表を読み、テキストを書き出し時の章のコピーと比べ、校正をひとつずつ今の本に統合します。対象は、フォルダー、`.postext`、単独のMarkdownの章ファイルと、`preset.json`（単独のMarkdownなら`--resources DIR`の`resources.json`）にあるリソースの文言（キャプション、注、代替テキスト、表のセル）です。複数の言語を持つ本では、`--locale`でファイルを書き出したときの版を指定します。リソースの文言への校正は、その版の`localized`ブロックに入ります。校正は1件ずつ1行で報告されます。

- `applied`：入った先のファイルと行を示します。
- `conflict`：書き出しのあとに本の側でもテキストが変わった、章やリソースがもうない、または2つの校正が重なっている。
- `rejected`：本が自動で付ける文字（番号、キャプションのラベル、引用スタイルが参考文献から書く文字）、またはPostextのマークアップをまたぐ書式。

引用の中の校正は、著者が書いた部分、つまりロケーターか文献の前後の語句に入るとき、その引用に戻ります。`[see also @simmons1991, 346–47]`のページ範囲をWordで`346–48`に直すと、`[see also @simmons1991, 346–48]`になります。報告の行は引用を名指しします（`citation simmons1991: locator "7" → "8"`）。著者名、タイトル、*Ibid.*への変更は`rejected`になります。書いたとおりに印刷されない部分（`346--47`が`346–47`と印刷される場合）も`rejected`になり、本の中の位置が示されるので、そこで直します。

変更履歴は承諾したものとして扱い、コメントは作成者と位置を一覧にしますが、書き込みません。適用されなかった校正があると、終了コードは3になります。`--dry-run`（`-n`）は、報告と、変わるファイルそれぞれのunified diffを出力し、何も書き込みません。各ファイルは書き込み先の隣に書いてから上書きの名前に変えるので、途中で止まっても章が半分だけ残ることはありません。読み込みの最中に変わった章ファイルは、`docx.fileChanged`の警告を出してそのままにします。本を指定したときは`-o`を使えません。`--json`の答えには、`variant`（ファイルがどの書き出しか。`formatted`、`semantic`、`facsimile`のどれか）、`writer`（ファイルのプロパティが示す書き出し機能）、`exportId`、`edits`（それぞれ`status`、`reason`、`kind`、`before`、`after`、`at`を持ち、引用の中では`citation`と`citationPart`も持つ）、`comments`、`files`、ドライランなら`diff`が入ります。

Googleドキュメントで編集して`.docx`でダウンロードしたファイルも戻せます。Googleドキュメントは対応表と章のコピーを残しません。読み込みのときに本から対応表を書き直し、報告にそう出ます。このファイルは書き出したテキストのコピーを持たないので、今の本と比べます。書き出しのあとに本が変わっていると報告が警告し、その間に本の側で加えた変更が、それを元に戻す編集として出ることがあります。Googleドキュメントのファイルは、書き出した元の本に、その本を変える前に読み込んでください。Wordで保存したファイルは対応表を持ったままなので、あとから本に加えた変更と統合されます。Googleドキュメントは、まるごと置き換えたテキスト（見出し、表のセル、キャプション、囲みのタイトル、脚注）の隠しブックマークも消します。読み込みは、そのテキストを前後のテキストとの位置関係から見つけるので、見出しは見出しのまま残り、キャプションはそのリソースに入ります。決められないとき（たとえば、隣に段落も入力されていて区別がつかないとき）は、報告には代わりに削除と追加が出ます。同じファイルをもう一度読み込んでも、何も入りません。

本を指定しないと、`import-docx`は任意のWord文書を新しい本にします。レベル1の見出しごとに章を分け（`--no-split`なら1章のまま）、画像と表はリソースになります。`--report`は、Sandboxが表示する品質レポート（使われているスタイル、直接の書式、手入力の番号…）を出力します。`--template`は読み込み用のテンプレート（Sandboxから保存した`.json`、またはテンプレートを含む`.docx`）を受け付けます。

字間はテキストではなくスタイルの性質なので、Markdownには入りません。`docx`は、段落スタイル、見出しスタイル、見出しのレベルの`letterSpacing`を、Wordのスタイルの字間として書き出します。`import-docx`はそれをスタイルの文字サイズに対するemとして読み戻し、`letterSpacing`が設定されていないスタイル（Wordのスタイルに対応する`--config`ファイルの段落スタイルと見出しスタイル、および見出しのレベル）に設定します。本がすでに指定している字間はそのままです。`--json`を付けると、`styleTracking`に、設定したもの（`applied`）と見送ったもの（`skipped`）が並びます（postext 1.39以降）。

### idml

```bash
postext idml book/ -o book.idml
postext idml book.postext -o book.idml --images link
postext idml book/ -o out/book.idml --lines reflow --fonts
```

`idml`は`pdf`と同じように本を組み、ページをInDesign Markupのパッケージとして書き出します。InDesignで仕上げるためのものです。見開きの余白を持つ本では、ページを背をはさんだ見開きに置き（それ以外の本では見開きごとに1ページ）、罫線、ボックス、パス、画像はページアイテムに、表はInDesignの表に、テンプレートページの各枠のテキストは固有のストーリーを持つテキストフレームになります（`next`でつないだ枠は1つのストーリーを共有します）。囲みスタイルは段落スタイルに、作者が指定したCMYKの色はスウォッチになります。フォームフィールドを持つチップは、InDesignのフォームフィールドになります。`--lines keep`（既定）は各行をPostextが終えた位置で終えるので、InDesignにはPDFと同じ行が表示されます。`--lines reflow`は段落をInDesignのコンポーザーに任せるので、改行位置は変わることがあります。`--spreads facing`または`--spreads single`を付けると、余白の設定にかかわらず、ページを見開きに組むか組まないかを決められます。`--images link`を付けると、画像はファイルの中ではなく、隣の`Links/`に置かれます。`--fonts`は、使われている書体のフォントファイルをパッケージの隣の`Document fonts/`に書き出します。InDesignはそこからその文書のフォントを見つけます。`-o`でファイルを指定する必要があり、本が再配布できないファミリーは書き出さずに警告を出します。パッケージが本のとおりには扱えないもの（縦組みのテキストの圏点、表の角丸の枠）は、`idml.*`の警告で報告します。書き出しを行うのは`postext-idml`パッケージです。[プログラムからの利用 › InDesignパッケージ](/ja/docs/configuration-programmatic-usage#indesignパッケージpostext-idml)を参照してください。`build`では、`--idml FILE`が同じパッケージを書き出し、`--idml-images`、`--idml-lines`、`--idml-spreads`、`--idml-fonts`を併せて使えます。postext 1.71以降。`--lines`と`--fonts`は1.76以降、`--spreads`は1.78以降。

### import-idml

```bash
postext import-idml book.idml -o book/
postext import-idml book.idml -o book.postext --layout flow --links pictures/
postext import-idml book.idml --report --json
postext import-idml package.zip -o book.postext
postext import-idml package.zip --document Book/Book.idml -o book/
```

`import-idml`はInDesign Markupのパッケージを読み込み、新しい本をフォルダーまたは`.postext`として書き出します。章はMarkdownに、設定は文書のスタイルとページから得られるものに、画像と表はリソースになります。`.indd`は読み込めません。先にInDesignでInDesign Markupとして保存してください。`--layout pages`は、テンプレートページを使って文書を1ページずつそのままたどり、各枠を元の位置に置きます。`--layout flow`は、テキストを読む順に並べ、文書のスタイルを付けた流し込みの本を書き出し、Postextが組み直します。`auto`（既定）はどちらかを選び、その理由を示します。ファイルは、zipにしたInDesignパッケージでもかまいません。<strong>ファイル › パッケージ</strong>で<strong>IDML を含める</strong>にチェックを入れて作ったフォルダーを、1つの`.zip`にしたものです。この場合、コマンドはそのIDMLを`Links/`フォルダーの画像とともに読み込み、`Document fonts/`フォルダーのフォントファイルを本に入れます。zipに複数のIDML文書が入っているときは、読み込む文書を`--document`でzip内のパスによって指定します（`--document Book/Book.idml`）。指定がなければ、コマンドは文書を一覧にします。`.indd`しか入っていないパッケージは受け付けず、IDMLを得る方法を示します。リンク画像はまず`--links`から、次にパッケージから、最後にファイルのあるフォルダーとその`Links/`から読み込みます。見つからなかったものは一覧に出します。文書が指定しているフォントも一覧に出します。単体の`.idml`にフォントファイルは入っていないので、本を作るときに`--font-dir`で渡してください。パッケージの場合は、`--font-dir`にあるフォントがパッケージのファイルの代わりに本に入ります。フォントコレクション（`.ttc`、`.otc`）は、パッケージにあっても`--font-dir`にあっても単独のスタイルに分けられ、本が使うスタイルだけが入ります（postext 1.83以降）。

Postextから書き出した本は、同じ行のまま戻ります。InDesignで作った文書の読み込みには欠落があります。コマンドは判定（`faithful`、`approximate`、`lossy`のいずれか）、件数、失われたものと近似したものを出力します。`--report`を付けると、注記と、各段落スタイルをどう読んだかも加わり、`--json`はそのすべてをデータとして出力します。`--hidden`、`--pasteboard`、`--non-printing`を付けると、非表示のレイヤーとオブジェクト、ペーストボード上のもの、印刷しないオブジェクトも読み込みます。`--conditions all`は条件テキストをすべて読み込み、`--changes reject`は変更履歴を却下したものとして読み、`--no-masters`はマスターページのアイテムを除きます。`--name`と`--locale`は書名と言語を指定します。読み込みを行うのは`postext-idml`パッケージの`idmlToPostext`です。[プログラムからの利用 › InDesignパッケージ](/ja/docs/configuration-programmatic-usage#indesignパッケージpostext-idml)を参照してください。読み込みは文書をそのまま写します。手元に残す本を、レイアウトの規則を割り出して移植するなら、代わりにエージェントスキルを使ってください（[InDesign：読み込み、書き出し、移植](/ja/docs/indesign)を参照）。

### design

```bash
postext design book.postext -o novel.postext
postext design book/ --parts page,text,headings -o type.postext
postext pdf other/ --design novel.postext -o other.pdf
```

デザインファイルは本のデザインだけを持ち、本文は持ちません。指定したパーツ（デザインパネルのグループ。[デザインファイル](/ja/docs/configuration-bundles#デザインファイル)を参照）の設定と、それが参照するフォントファイルとカラープロファイルを含みます。再配布できないフォントは含みません。`--parts`でカンマ区切りの一部のパーツだけを取り、`--design-name`、`--id`、`--description`でデザインに名前を付けます。同じ本からは常に同じバイト列ができます。

`--design FILE`は本を読むすべてのコマンドのオプションで、`--config`と`--set`の前に、デザインファイルまたは別の本のデザインを本に適用します。パーツの設定が本のものを置き換え、名前付きスタイルはidで統合され、デザインのフォントが本のフォントに加わります。`--design-parts`で一部のパーツだけを使います。Sandboxのデザインパネルも同じファイルを読み込み・書き出しします。

`--composition TAG`も本を読むすべてのコマンドのオプションで、`--design`の後に、ある言語の伝統の組版規則を設定します（postext 1.80以降）。`es`、`en-US`（または`en`）、`en-GB`、`fr`、`de`のいずれか、または本の言語を使う`auto`を指定します。慣習の規則が本の規則を置き換え、ほかの規則は既定値に戻ります。文字組みはそのままです。[組版の慣習](/ja/docs/configuration-text#組版の慣習)を参照してください。

```bash
postext pdf book/ --composition auto -o book.pdf
postext design book/ --composition es --parts composition -o house-rules.postext
```

### packとunpack

```bash
postext pack my-book/ -o my-book.postext
postext pack 01.md 02.md --name "Notes" --config design.json --resources img/ -o notes.postext
postext unpack my-book.postext -o my-book/
```

`pack`は本のフォルダーをそのままzipにするか、ばらのMarkdownからバンドルを作ります。同じ入力からはつねに同じバイト列ができるので、バンドルを比べたり、ハッシュを取ったりできます。ばらのMarkdownでは、`--id`、`--description`、`--thumbnail FILE`（表紙の画像）でバンドルのid、説明、サムネイルを設定します。idは既定で名前のスラッグです。フォルダーでは、その`preset.json`の内容がそのまま使われます。表紙を指定していない本には、最初のページが表紙として入ります（`thumbnail.jpg`、長辺1024 px）。ファイルマネージャーがファイルのアイコンとして表示できる画像です。`--no-auto-thumbnail`で省けます。`unpack`は、`--force`を付けない限り、空でないフォルダーには書き込みません。

### infoとcheck

```bash
postext info book.postext --pages
postext check book.postext
postext check chapters/ --strict --json
```

`info`は、章（タイトル、語数、ファイル。`--pages`を付けるとページも）、リソース、そしてすべてのフォントファミリーとその出どころ（本、フォルダー、実行ファイル、ダウンロードのキャッシュ、代替フォント）を一覧にします。本が始まりの位置を示している場合（`preset.json`の`start`。58ページ、第4章から始まる抜粋など）は、それも表示します。どのコマンドも本をそこからレイアウトします。

`check`は本をレイアウトし、Sandboxの**検査**パネルが示すものを報告します。閉じていないMarkdown、不明なリソース・ディレクティブ・スタイル、レイアウトが無理に収めた囲み、見つからないフォント、エンジンが置き換えた設定です。印刷用に設定した本（または`--preflight`を付けた場合）では、プリフライトも報告します。解像度不足の画像、細すぎる罫、複数インキの小さな文字、上限を超えるインキ量、仕上がり線に近い文字です。地の色とのコントラストが足りない文字（`contrast`）も、色の組み合わせごとに1回、画面での比と、印刷では出力プロファイルの用紙での比を添えて報告します。どの問題も、章のファイル、行、ページを示します。エラーが見つかると終了コードは3になります。`--strict`を付けると、警告が1つでもあれば3になります。

また、設定のデザインのうち、プレースホルダーではなく本の文章そのものが書き込まれているテキスト（`contentInConfig`）も、見出しスタイル、柱、部扉のデザインごとに1回、各テキストのパスを添えて報告します。その文章をMarkdownに移すか、書名や出版社名を`checks.contentInConfig.allow`に加えてください。

ページテンプレートのある本では、`check`は次も報告します。枠に収まらないテキスト（`frameOverflow`。再配置で試した手順と、収めるための修正案を添えます）、枠が追加できるページ数を超えて続く文章（`frameContinuationLimit`）、後ろにないページへのジャンプ（`continueTargetMissing`）、描けない図のラベルや重なり合う図のラベル（`labelAnchorUnknown`、`anchorUnlabelled`、`labelOverflow`、`labelOverlap`）、ほかの枠の下に隠れた枠や端からはみ出した枠（`frameCovered`、`frameOutsideArea`）、グリッドに収まる数を超えたカード（`repeatOverflow`）、ページに配置できないモジュール（`moduleUnknown`、`moduleAsPage`、`moduleNested`、`moduleNameRejected`）です。警告のあと、再配置の記録があるテンプレートページごとに`reflow`の行を1行出力します。`--json`では、手順、修正案、再配置の記録がデータとして付きます。[テンプレートページ › 警告](/ja/docs/composed-pages#警告)と[再配置の記録](/ja/docs/composed-pages#再配置の記録)を参照してください。

### buildと--watch

```bash
postext build book/ --pdf out/book.pdf --html out/book.html --images out/pages --pages 1-4
postext build chapters/ --pdf book.pdf --watch
```

`build`は本を一度だけレイアウトし、指定したすべての出力（`--pdf`、`--html`、`--epub`、`--images`、`--docx`、`--idml`）を、各コマンドのオプションとともに書き出します。`--watch`を付けると動き続けます。章、設定、画像が変わると、フォントとエンジンを読み込んだまま本をレイアウトし直し（1章ならたいてい1秒もかかりません）、出力を書き直します。保存した内容で本が壊れたときは、エラーを出力し、最後に正しく作れたファイルを残します。

## フォント

フォントを含む本（バンドル、または`--fonts`を付けたばらのMarkdown）は、そのフォントだけで組まれます。設定が指定するファミリーのうち本に含まれないものは、`postext`が次の順に探します。

1. `--font-dir`で指定したフォルダー。
2. 実行ファイルに組み込まれた書体。エンジンの既定であるEB GaramondとOpen Sansです。
3. ダウンロードのキャッシュ。
4. [Google Fonts](https://fonts.google.com)。静的なTrueTypeファイルを丸ごと取得します。Google Fontsにないファミリー（Commit Mono、FiraGO）は[Fontsource](https://fontsource.org)から取得します。取得したファイルはキャッシュに残るので、1つのファミリーのダウンロードは1回で済みます。

ファミリーにないウェイトは、ブラウザーが選ぶのと同じフォントで組みます（CSSのフォントマッチングです。500より上ではより太いフォントを先に、400より下ではより細いフォントを先に試すので、400と700だけのファミリーでは600も550も700になります）。ファミリーにないイタリックは正体で組みます。どちらもフォントはそのまま使い、ページ画像でもPDFでも同じです。ウェイトが1つだけの見出し用書体は太字でも自分の字形のまま、イタリックのないファミリーは正体のままです。

取得するのは、設定に書かれたウェイトです。どのファミリーもレギュラー、ボールドとそれぞれのイタリックを取得し、設定で指定したほかのウェイトも取得します。太字に使うウェイトも含まれます（`bodyText.boldFontWeight: 600`なら600のフォントを取得します）。ファミリーにあるウェイトを読み込めなかった場合（オフラインでキャッシュにファイルがない、ダウンロードに失敗した、フォントフォルダーにそのファイルがない）は、同じファミリーのうち同じ規則で選ばれるフォントで組み、`postext check`が`fontFallback`の警告として報告します。行の折り返しがSandboxと変わることがあります。

フェイスにグリフのない文字は、別のフォントで描かれます。`postext check`は読み込んだ各フェイスの`cmap`表を読み、そうした文字を本全体でフェイスごとに1件の`glyphFallback`警告として示します。`--json`では、その`data`に文字と数が入ります。

キャッシュは`~/.cache/postext`（Windowsでは`%LOCALAPPDATA%\postext\cache`）です。`POSTEXT_CACHE_DIR`か`--cache-dir`で場所を変えられます。`--offline`はダウンロードを行いません。どこにも見つからないファミリーは、その名前のままEB Garamondで組まれるので、レイアウトとPDFは食い違いません。`missingFont`の警告がそのファミリーの名前を示します。各ファミリーの出どころは`postext info`で確かめられます。

ライセンス付きファミリーのファイルを含めないバンドルでは、代わりに幅の近いオープンなファミリーを指定できます（マニフェストの`fonts`にある`fallback`。postext 1.42以降）。`postext`は上の手順でそのファミリーを探し、本に入っていない書体を、ライセンス付きファミリーの名前のまま、同じウェイト・同じ傾きの書体で組みます。そのため、レイアウトはファイルがあるときに近くなり、`postext check`もそのファミリーについて`missingFont`を報告しません。本に一部しか入っていないファミリーは、ファイルが1つもない傾きだけを`fallback`から取ります。PDFにはオープンな書体が埋め込まれます。

## スクリプトとエージェントから使う

コマンドラインは、コーディングエージェントを含むほかのプログラムから動かせるように作られています。

- **`--json`**：コマンドが終わったときに、1つのJSONオブジェクトを標準出力に出力します。メッセージはすべて標準エラーに出ます。レポートには、書き出したもの、ページ、出どころ付きのすべての警告、各段階にかかった時間（ミリ秒）が並びます。

```json
{
  "ok": true,
  "command": "pdf",
  "version": "1.22.1",
  "book": { "name": "notes", "id": "notes", "locale": "en", "chapters": 2 },
  "pages": 3,
  "outputs": [{ "kind": "pdf", "path": "notes.pdf", "bytes": 29746, "pages": 3 }],
  "warnings": [
    {
      "kind": "unknownResourceId",
      "severity": "warning",
      "message": "Unknown resource id \"map\" in ::resource — nothing is embedded (offset 26)",
      "at": "notes/02-more.md:5"
    }
  ],
  "timings": { "read": 13, "fonts": 8.4, "math": 28.2, "layout": 51.6, "pdf": 132.1, "total": 1638 },
  "exitCode": 0
}
```

- **終了コード**：`0`は完了、`1`は失敗、`2`は使い方の誤り（不明なオプション、入力の指定漏れ）、`3`は`check`がエラー（`--strict`では警告）を見つけたこと、または`import-docx`がWordの校正を取り込めなかったことを示します。
- **質問しません**。入力を待つことはありません。空でないフォルダーは、確認を求めずに拒否します。
- **標準出力**：`-o -`は、PDF、画像、バンドルを標準出力に書き出し、パイプで先に渡せるようにします。
- **速度**。実行ファイルは数百分の1秒で起動します。短い本なら、PDFやページ画像は1秒を大きく下回る時間でできます。長い本では、レイアウトにかかる分だけ時間がかかります（140ページの挿絵入りの小説で約10秒）。長い本の数ページを見るには、`--chapters`を`image`か`images --pages`と組み合わせます。多くの変更を重ねながら本に取り組むときは、`postext build --watch`を動かしたままにして、その出力を読みます。

[エージェントスキル](/ja/docs/skill)は、作業中のページを描画したり、移植を検査したりするのにコマンドラインを使います。

## Python

`pip install postext`で、コマンドラインをPythonのライブラリとして使えます。パッケージは依存関係のない純粋なPythonで、バージョンはpostextと同じです。最初にコマンドを実行するとき、そのバージョンのGitHub Releaseからお使いのシステム用の実行ファイルをダウンロードし、`SHA256SUMS`で検証して、上で説明したキャッシュの`bin/<バージョン>/`に保存します。`POSTEXT_BIN`に手元の実行ファイル（Homebrew、Scoop、自分でビルドしたもの）を指定すれば、何もダウンロードしません。

```python
import postext

report = postext.pdf("book.postext", out="book.pdf", set={"page.dpi": 300}, locale="es")
print(report.output.pages)
for warning in report.warnings:
    print(warning.kind, warning.at, warning.message)

pdf = postext.pdf_bytes(open("book.postext", "rb").read())
```

- **コマンドごとに1つの関数**：`pdf`、`html`、`epub`、`image`、`images`、`docx`、`idml`、`import_docx`、`import_idml`、`design`、`pack`、`unpack`、`info`、`check`、`build`。オプションは同じ名前をアンダースコアで書きます（`color_space`、`font_dirs`、`dry_run`）。`set`は辞書、`config`はファイルか辞書、`chapters`は数値、リスト、`range`、`"1,3-5"`のいずれかを受け取ります。本を読む関数はすべて、デザインファイルをパスかバイト列で渡す`design=`と、リストか`"page,text"`で渡す`design_parts=`、言語タグか`"auto"`で渡す`composition=`を受け取ります。
- **レポートはオブジェクト**。各関数はコマンドを`--json`付きで実行し、レポートを返します。`outputs`、`pages`、`timings`、そして`warnings`で、警告はそれぞれ`kind`、`severity`、`message`、`at`、`page`を持つ`Diagnostic`です。`info`は`chapters`、`resources`、`fonts`を、`check`は`passed`、`error_count`、`warning_count`を、`design`は`name`と`parts`を、`import_idml`は`layout`、`reason`、`chapters`、`quality`、`fonts`、`missing_links`、`package`を加えます。
- **エラーは例外**。失敗すると`PostextError`、オプションの誤りは`UsageError`になります。`check`がエラーを見つけると`ProblemsFound`を送出し、その`report`に一覧があります。`raise_on_problems=False`を渡すとレポートを返します。
- **バイト列**。本は`.postext`バンドルのバイト列でも渡せます。`out="-"`ではファイルが`report.content`に入って戻り、`pdf_bytes`、`html_bytes`、`epub_bytes`、`image_bytes`、`docx_bytes`、`idml_bytes`、`pack_bytes`、`design_bytes`はそれを直接返します。
- `postext.Postext(binary, cwd=…, timeout=…)`は指定した実行ファイルを使い、`python -m postext …`はコマンドラインそのものです。

呼び出しのたびに実行ファイルを起動し直します。すべてのオプションはパッケージの[README](https://github.com/drnachio/postext/tree/main/packages/postext-python)にあります。

## しくみ

コマンドラインは、[リポジトリ](https://github.com/drnachio/postext/tree/main/packages/postext-cli)の`postext-cli`パッケージです。[Bun](https://bun.sh)がそれをエンジンと書き出し機能とともに、システムごとに1つの実行ファイルにコンパイルします。テキストの計測と描画は、Sandboxでブラウザーのcanvasが行うのと同じように、[Skia](https://skia.org)（`@napi-rs/canvas`経由）が行います。ビットマップを含むSVG画像（data URIとして埋め込まれたPNGやJPEG。PDFから切り出した図版を`pdftocairo -svg`で書き出すとこの形になります）は、SkiaのSVGレンダラーがそうした画像を描かないため、代わりに[resvg](https://github.com/linebender/resvg)が描画します。リリースのたびに実行ファイルがビルドされ、Linux、Alpine、macOS、Windowsで実行されてから、GitHub Releaseに添付されます。npmには`postext-cli`と、実行ファイルごとに1つの`postext-cli-<system>`パッケージが公開されます。

リポジトリのコピーから実行するには次のようにします。

```bash
pnpm install
pnpm --filter postext-cli start pdf book.postext
pnpm --filter postext-cli build:bin --current
```

1つ目はソースから実行します。2つ目は、このコンピューター用の実行ファイルを`packages/postext-cli/bin/`に書き出します。

## Sandboxとの違い

- **HTML**は、印刷用のレイアウトを画面の大きさで表示したものです。SandboxのHTMLタブは、ウィンドウに合わせてテキストを組み直します。
- **`--chapters`**：指定した章だけを単独でレイアウトします。そのページ番号は振り直されますが、Sandboxは本全体の番号を続けます。
- **フォント**は、本、指定したフォルダー、実行ファイル、Google Fonts、またはFontsource（Google Fontsにないファミリーの場合）から取り、コンピューターにインストールされたフォントは使いません。そのため、本はどの環境でも同じように仕上がります。
- **テキストの言語**は、ブラウザーでは文書自身の言語です（`bodyText.shapingLanguage: 'document'`。postext 1.30以降の既定値です）。Skiaのcanvasは言語を受け取りますが、シェーピングには使いません。そのためコマンドラインは、各フォントの既定の言語の字形で計測し、設定の内容にかかわらず、常に`shapingLanguage: 'host'`で本をレイアウトします。PDFとページ画像も同じ字形で描きます。ある言語用の字形を備えたフォントを使う本（カタルーニャ語の`l·l`、トルコ語の`fi`、英語の本で使う中国語フォントの数字）は、コマンドラインでは既定の字形で組まれます。`'document'`で計測のしかたが変わるもの（行末で分割された語の各部分、右から左の語、デザインのテキスト）も、コマンドラインでは`'host'`と同じに計測するので、行の切れる位置がSandboxと違うことがあります。
