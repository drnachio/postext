# 模板页

**模板决定页面的形式；Markdown提供内容，并说明每一部分进哪个框。**

模板页是按模板排出的页面。模板里有命名的框（标题色带、一段课文、一个配有照片的方框）、一起移动的组和装饰，全部定义在配置的`pageTemplates`下。在Markdown里，这一页写成一个页面块，写明所用的模板，并按名称把内容分到各个框。Markdown里从不写位置和尺寸，配置里也从不写正文文字，所以译本就是同一个模板配上另一种语言的文字。

本页讲的是Markdown，以及页面如何据此排出。模板本身（框、尺寸、样式和装饰）见[配置 › 模板页](/zh/docs/configuration-composed-pages)。没有模板页的文档，排版结果与以前完全相同。

## 页面块

```md
::::page{template="tema-cajas" fondo="banda-retos"}
# La actividad económica y el dinero

Las personas utilizan :chip[recursos]{style="clave"} que se obtienen de la naturaleza…
::::
```

模板页写成一个*页面块*：以一行**四个冒号**开头，后接`page`和它的属性，以单独一行**同样数目的冒号**结束。页面内部，三个冒号的容器（`:::frame`、`:::callout`、`:::figure`、`:::columns`、`:::paper`）照常开启和关闭，所以单独的`:::`关闭的是其中最内层的那个，不会关闭页面。用五个冒号开头的页面（`:::::page`）用五个冒号结束，这时页面里一行四个冒号只是普通文字。

模板页总是从新的一页（或跨页）开始，结束行之后的文字从下一页开始。

三个冒号的`:::page{split=…}`是漫画页（见[漫画](/zh/docs/comics)），仍是这个含义。只用三个冒号、却带`template=`的`:::page`仍按漫画页读取，同时`pageFenceLength`警告会提示模板页需要四个冒号。

缺少开始行或结束行时，解析器会自行恢复，不丢文字：

- 没有结束的页面一直延续到章末，并在开始行报告为未闭合的容器；
- 页面尚未结束时又遇到一行`::::page`，会先在那里结束前一页（以同样的方式报告）；
- 结束行会关闭页面内仍未关闭的框或标注框，并逐一报告；
- 冒号数目不同的结束行不会结束这一页：它留在文字中，一眼就能看到。

## 框与槽位

```md
:::frame{slot="dinero" label="El dinero"}
Es el instrumento utilizado como medio de pago…

Hasta hace pocos años, lo más normal era pagar con dinero en **efectivo**…
:::
```

**槽位**指明一段内容进哪个框：它与模板中某个框的名称对应。`:::frame{slot="…"}`把其中的全部内容送进那个框。框里可以写任何Markdown：段落、列表、标题、行内标签、`::resource`嵌入、`:ref`引用、脚注、`:::columns`和嵌套的标注框。`label`和`title`为框的页签或标题提供文字，与`:::callout`相同；框的外观来自模板给它指定的标注框样式，一段内容也可以指定自己的外观（见[框的外观](#框的外观)）。

内容按以下规则分配：

- 槽位相同的几段内容按Markdown中的顺序合在一起；重复的网格除外，在那里每段内容各是一张卡片（见[重复的槽位](#重复的槽位)）。
- 没有槽位的内容进入模板的**流文框**（标为`flow`的框）。
- 没有槽位的标题，如果模板里有接收其级别的框（`takes: "h1"`），就先进入那个框；所以课本里一课的标题只需在页首写`# 标题`。
- 没有槽位的`:::toc`交给设置了`takes: "toc"`的框，前提是模板里有这样的框（见下文“目录排在框里”）。
- 如果内容写的槽位在模板里没有，它会进入流文框，并给出报告（`slotUnknown`）。

写在模板页之外的`slot`照样会读取，但不起作用。

### 重复的槽位

模板把一张卡片画一次，再按页面的需要在网格中排出任意多次（带`repeat`的组，见[配置 › 重复一组框的网格](/zh/docs/configuration-composed-pages#重复一组框的网格)）时，每个指明卡片主槽位的`:::frame`就是一张卡片，按书写顺序排列：

```md
::::page{template="fotos"}
# 河边的动物

:::frame{slot="foto"}
::resource{id="garza"}

:::frame{slot="pie"}
苍鹭
:::
:::

:::frame{slot="foto"}
::resource{id="nutria"}

:::frame{slot="pie"}
水獭
:::
:::
::::
```

- **卡片的成员。** 在卡片这段内容里，指明这组框中另一个框（这里是`pie`，即题注小签）的块或`:::frame`，进入同一张卡片的那个框。其余内容进入卡片的主框。
- **一个块，一张卡片。** 单独写、不在任何容器里的`::resource{id="…" slot="foto"}`也是一张卡片。
- **名称。** 卡片从1开始编号：第二张卡片的框是`foto[2]`和`pie[2]`，警告、重排记录和沙盒里都用这些名称。
- **数量。** 页面上有几段内容，就有几张卡片。有五种动物的西班牙语版和有四种的英语版用同一个模板。设了`repeat.max`的网格最多容纳这么多张；每多出一段就给出`repeatOverflow`，这段内容进入流文框。

这组框中的某个框，只有在本页没有任何卡片填它时，才报告为`slotEmpty`。重复的框从不接收标题，也从不是流文框。

### 框的外观

一段内容可以采用一种有名称的外观：一组颜色，由配置在`frameLooks`中定义（见[配置 › 框的外观](/zh/docs/configuration-composed-pages#框的外观)）。Markdown指明用哪种外观，配置说明这种外观是什么样子。在网格中，这样每张卡片可以有自己的颜色，而所有卡片仍用同一个模板和同一种样式：

```md
::::page{template="fotos"}
# 河边的动物

:::frame{slot="foto"}
::resource{id="garza"}

:::frame{slot="pie" look="rojo"}
苍鹭
:::
:::

:::frame{slot="foto" look="marino"}
::resource{id="nutria"}

:::frame{slot="pie" look="verde"}
水獭
:::
:::
::::
```

- **写在哪里。** `look`写在任何`:::frame{slot="…"}`的开始行上。卡片的主内容（这里是第二张照片的框）和嵌在其中的成员（每个题注小签）各自指定自己的外观。
- **改变什么。** 外观叠加在框的样式和模板自身的颜色之上，只作用于这一段内容：其他卡片保持各自的颜色。接续到另一个框里的文字（串接框、追加页）仍保持这种外观。
- **未知的id。** `frameLooks`中没有的id会在该属性处给出`lookUnknown`，并附上最接近的id，框保持原来的颜色。

### 页面中的模块

带模块组（`modules: true`，见[配置 › 模块](/zh/docs/configuration-composed-pages#模块)）的页面模板，从`:::module`容器中取得它的各块，按书写顺序上下叠放。块由模块的模板画出，容器里放的是它的文字：

```md
::::page{template="tema"}
# 河流

:::module{template="caja"}
:::frame{slot="texto" label="你知道吗？"}
河流发源于山中，雨水和雪水在那里汇成溪流。
:::
::resource{id="rio" slot="foto"}
:::

:::module{template="arbol" name="ramas"}
:::frame{slot="raiz"}
河流
:::
:::frame{slot="izq"}
它带来的水
:::
:::frame{slot="der"}
两岸的生命
:::
:::
::::
```

- `template`指定一个`role: 'module'`的模板。`name`可以不写：它给这个模块实例命名，于是它的框是`ramas.raiz`、`ramas.izq`。不写时，实例名是`<template>[n]`，即这个模块在本页同一模板的模块中的序号：`arbol[1].raiz`。本页已被占用的名称，或含有空格、`.`、`#`、`[`或`]`的名称，换成这个默认名称（`moduleNameRejected`）。
- **槽位**：`:::module`里的槽位属于这个模块自己：`slot="raiz"`指向本模块的`raiz`框，所以一页上同一模板的两个模块，文字互不混淆。没有指明槽位的内容进入模块的流文框，标题进入模块中接收其级别（`takes`）的框；两者都没有时，进入页面的流文框。
- **顺序。** 模块按Markdown的顺序叠放，所以另一页可以把同样的块换个顺序排，或者多放一棵树，而不需要新的模板。
- **并排。** 模块组是行或网格，或者内部有自己的组（`within`）时，同样的块会并排：两个`:::module{template="aviso"}`后接四个`:::module{template="tarjeta"}`，排成一行两个方框，下面是2 × 2的卡片网格。Markdown仍然只说明有哪些模块、按什么顺序（见[配置 › 模块](/zh/docs/configuration-composed-pages#模块)）。 自 postext 1.51 起，组也可以位于行内，于是方框可以放在一列卡片旁边，行中的模块按 `grow` 和 `shrink` 分享行的空间。
- 写在页面块之外的`:::module`是一个装着其内容的普通方框。模块里面再套模块是不支持的（`moduleNested`）。

## 示例

课本中的一页，有标题色带、一段带列表的课文，以及三个彩色方框，每个方框旁边配一张照片：

```md
::::page{template="tema-cajas" fondo="banda-retos"}
# La actividad económica y el dinero

## La actividad económica

Las personas utilizan :chip[recursos]{style="clave"} que se obtienen de la naturaleza…

- Las :chip[empresas.]{style="clave"} Ofrecen bienes y servicios a cambio de un beneficio.
- Las :chip[personas y familias.]{style="clave"} Adquieren lo que ofrecen las empresas…

:::frame{slot="dinero" label="El dinero"}
Es el instrumento utilizado como medio de pago, ya que su valor es conocido…
:::

::resource{id="dinero-pago" slot="dinero-fotos"}

:::frame{slot="gasto" label="El gasto"}
- **Fijo:** es el que se produce todos los meses…
- **Variable:** puede cambiar según las necesidades…
:::

::resource{id="gasto-compras" slot="gasto-fotos"}

:::frame{slot="ahorro" label="Préstamos y ahorro"}
Si necesitas o quieres comprar algo muy caro…
:::

::resource{id="ahorro-balanza" slot="ahorro-fotos"}
::::
```

标题进入接收`h1`的框；小标题、段落和列表进入流文框；每个方框和每张照片进入各自槽位对应的框。加泰罗尼亚语版就是同样的这些行换上另一种语言的文字：模板、槽位和照片都不变。

## 页面如何排出

模板页单独占一页（对设计元素的`pages`筛选而言，页面角色是`composed`）。模板按页面落在哪一侧来取，所以会套用它的`variants.recto`或`variants.verso`。然后逐个放置并填充各个框，用的是全书其余部分的排版设置：段落样式和标题样式、列表、行内标签、脚注标记，以及框自己的标注框样式。

### 放置框

框放在它的网格单元格里，或者放在`placement`指定的位置（锚点、边和偏移，与设计元素相同）；两者都没有时，放在模板区域的左上角，宽度与区域相同。锚定到另一个框的框（`"to": "#dinero"`）在那个框之后放置，并随它移动：`below`把它挂在那个框下面，`right-of`放在旁边，`top-right`这样的角则把它钉在那个框外框的对应角上。

框的高度可以是固定值（长度或百分比）、`fill`（一直到区域边缘），或默认的`auto`：取它所接收内容的高度，介于`minHeight`和`maxHeight`之间，且不超出区域底边。框比内容高时，内容的位置由`verticalAlign`决定（`top`、`middle`、`bottom`，或用`justify`把空间分到各块之间）。框的标注框样式按框的完整尺寸画出底色、边框、圆角、色条和图标；`:::frame`的`label`印在样式的页签里。

### 流文框与标题

没有写槽位的内容进入标为`flow`的框；某一级的第一个标题进入用`takes`接收这一级的框。一页中的各个框按其内容在Markdown中首次出现的顺序读取，每个框整体读完：屏幕阅读器、带标签的PDF和流式版式的输出，都会先读完页面开头的正文，再读方框，而不会在正文中间插进去。

排在框里的标题保留其级别或标题样式的设计（页签、色带、由设计排出的`{titleText}`），按框的宽度排出，和在页面的栏里一样，框会为设计留出空间；框里的文字缩小时，设计随之缩小，框旋转时，设计也随之旋转。见[标注框与框中的标题](/zh/docs/configuration-headings#标注框与框中的标题)。postext 1.36及以前，这样的标题不带设计。

### 目录排在框里

框可以排目录（自postext 1.42起）。给模板一个设置了`takes: "toc"`的框，并在页面块里写`:::toc`；也可以把它写在指定槽位的`:::frame`里：

```md
::::page{template="contents"}
# 本单元内容 {toc="false"}

:::toc{keep="part" levels="1-2"}
::::
```

框按目录自己的规则排各行，和正文里的目录一样。每一篇有自己的一行，由`toc.parts.design`绘制；条目保留自己的编号、点状前导符和页码标签，并链接到它所列的页面；框不会在条目之间加段间距。`keep`在框里同样有效：设置`overflow.continueIn: "next-page"`时，一个整框放得下的目录块会整块移到新增的页面，比框还高的目录块则在它的块首和`toc.groups.minEntriesAfterHead`个条目之后截断，新增的页面以重复的块首开头（`toc.groups.continuation`）。截断处的标记（`overflow.mark`）和新增页面开头的文字（`overflow.fromMark`），用法与其他框相同。

列表上方的标题是普通标题，目录会把它列进去，除非它的标题样式写了`toc: false`，或标题带有`{toc="false"}`，与正文里的做法相同。页面的底色，即整张纸之下的一种颜色或一幅图，属于模板的装饰：它画在各框之下，并在目录新增的每一页上重复。篇与篇之间的分页（`toc.parts.breakBefore`）在能接续的框里起作用（`overflow.continueIn: "next-page"`，或带`next`的框）：即使内容全放得下，框也在除第一篇以外的每一篇之前截断，每一篇都从新增的一页或下一个框开始。不能接续的框会忽略这个分页。自postext 1.43起。

### 串接框

`next`把一个框装不下的内容送到同一页的另一个框，那个框再送往下一个，就像排版软件里串接的文本框：

```json
{ "name": "columna-1", "flow": true, "next": "columna-2", "height": { "value": 120, "unit": "mm" } },
{ "name": "columna-2", "placement": { "anchor": { "to": "#columna-1", "edge": "right-of" } } }
```

文字在两行之间断开，在下一个框中接着排，按那个框的宽度重新断行，不丢也不重复。`overflow.continueIn: "#frame"`的意思相同。

框的断开方式与正文相同。标题绝不排在片段的末尾：它跟着它引出的那几行走。在列表的项与项之间断开时，两边各至少留两项（`bodyText.avoidOrphansInLists`或`bodyText.avoidWidowsInLists`关闭时为一项）；在`bodyText.shortListSplit: 'avoid'`下，不超过`bodyText.shortListMaxItems`项的列表不在项与项之间断开。没有哪个断点满足这些条件时，片段在标题或列表之前结束，或者在列表的某一项中间结束。要在这一页之后追加的页上接着排，见[文字接续时](#文字接续时)。

### 推开文字的框

设了`exclude: "push"`的框不让其他框的文字进入自己的矩形：其他框中碰到它的行，在矩形遮住的那一侧缩短，就像正文中文字绕排图片一样。锚定在方框一角并标为`push`的照片，会让方框的文字从它旁边排过。如果方框要为图片留出一条固定的空栏，可以改用`padding`。

再加上`"wrap": "contour"`，框就按其中图片的形状推开文字，而不是按它的矩形：抠图插画的Alpha通道，或资源`contour`中的多边形。另一个框的每一行，按形状在它旁边的宽度缩短，所以方框的文字会沿着压在上面的图画的轮廓排，不必逐行手工换行或缩进。推开文字的框里的题注和其他文字仍按各自的外框推开，旋转的框按它的外框推开，形状未知的图片也按它的外框推开，并给出`textWrap`警告（原因为`noContour`）。形状、阈值和间距见[文档格式 › 沿轮廓绕排](/zh/docs/document-format-resources#沿轮廓绕排)。

```json
{ "name": "drawing", "exclude": "push", "wrap": "contour", "layer": 2,
  "placement": { "anchor": { "to": "#box", "edge": "top-right" } }, "width": { "value": 150, "unit": "mm" } }
```

### 装饰、书眉与层

模板的装饰（`decoration`：图片、线条、方框和短文字）在各框的外框确定之后才排放，所以元素可以锚定到某个框（`"to": "#gasto"`）并跟着它走，[连接线](/zh/docs/configuration-composed-pages#连接线)也可以用一条线连起两个框，不管它们的文字把它们推到哪里，线都连在框上。装饰中的文字读取本页自己的属性：页面块上的`fondo="banda-retos"`给出`{attr.fondo}`，例如用`"resourceId": "{attr.fondo}"`逐页选择背景图。书眉和页脚也读取这些属性。模板的`header`或`footer`取代所在章节的设置，`false`把它隐藏，两者都没设时印出所在章节的书眉和页脚。在从右到左或竖排的页面上，框随镜像或旋转后的行文方向排布，装饰则留在纸面上：用起始边或结束边定位的元素（`top-start`，见[元素定位](/zh/docs/configuration-headers-footers#元素定位)）在每个版本里都会留在它的框旁边。

各框按`layer`的顺序绘制：装饰在第0层，框默认在第1层，层号高的画在层号低的上面，负数层画在装饰下面。`rotate`让框连同其内容绕框的中心旋转任意角度，在画布、PDF、HTML阅读器和固定版式EPUB中都是如此。

### 放不下的内容

框的内容比框高、既没有可以接续的下一个框、也没有可以接续的页（`overflow.continueIn`）时，全部内容仍保留在文档中，但只显示放得下的部分：其余部分在分页输出中于框底被裁掉，警告[`frameOverflow`](#frameoverflow)会说明裁掉了多少。没有任何框接收的内容（没有流文框，或这一侧缺少某个框）排进正文，放在模板页之后的那一页。

## 印刷之外：HTML、EPUB与带标签的PDF

所有输出都按Markdown的顺序读模板页，而不是按模板列出框的顺序，也不是按图层绘制的顺序。

- **流式EPUB**：整页变成一个节（`<section class="pt-composed pt-composed-tema-cajas">`），节的开头是该页的分页标记。每个框是节里的一个块（`<div class="pt-frame pt-frame-dinero">`），放在其内容在Markdown中首次出现的位置；一个框和它的`next`链接续的各框合成一个块，内容接续到追加页上的框也是如此：各个片段拼接起来，在两页之间断开的段落仍是一个段落，追加页的分页标记就放在这个段落里、那一页文字开始的地方。用标注框样式绘制的框保留该样式的方框：底色、边框、内边距、正文文字，`label`作为方框的标题。没有样式的框就是普通的块。装饰（背景图、卡片、设计文字）属于印刷页面，不予输出。
- **插图的标注**：HTML阅读器和固定版式EPUB把每个画出的标注作为文字写在图片之后，按书写顺序排列（`<div class="pt-figure-label">`，用CSS矩阵旋转），所以读屏软件先读图片的替代文字，再读标注的文字。EPUB中的图片不含这些文字。流式版式的书把其中的简单标注画在图片上，作为叠在图片之上的一个SVG（`pt-label-layer`，采用图片自身的坐标，文字随图片缩放；自postext 1.40起）：粗体或斜体的文字，带所属样式的光晕和底板，并按`rotate`旋转。竖排标注，以及含公式、行内标签或标记的标注，不画进SVG。从右向左书籍中的标注按它们在纸面上的样子来画（自postext 1.42起）：每个词都在印刷版量出的x位置，从右向左文字的词则单独成为一段从右向左的文字，锚定在它的右边缘，浏览器因此能连接它的字母。所有标注都列在图片之后、插图之内：这是一个视觉上隐藏的列表（`pt-figure-labels pt-hidden`），读屏软件只读一遍。没有画出的标注（其锚点不存在）则跟在图片的替代文字之后，如`欧洲地图（马德里）`；中文和日文标注用`（…、…）`，阿拉伯文标注用阿拉伯逗号（،）。
- **HTML阅读器与固定版式EPUB**：两者都按印刷效果显示套用了模板的页面：每个框在自己的方框里，按`rotate`旋转，内容放不下时裁掉多出的部分，画在较低图层的框之上，装饰位于第0层。标记按阅读顺序列出各框，并用`z-index`按图层顺序绘制，所以辅助技术沿Markdown的顺序朗读，页面外观仍与印刷一致。装饰性图片对辅助技术隐藏（`alt=""`）。装饰所用的字体也在沙盒嵌入EPUB的字体之列；固定版式EPUB缺少其中某个字体时，会给出`missingFont`警告。
- **带标签的PDF**：结构树按同样的顺序读各框。每个框（或一条框链）是一个`Div`，包含其标题、段落和列表，接续到追加页上的框，各个片段也同属这一个`Div`（在两页之间断开的段落是一个`P`，接续标记是版面工件）；其中每张图片是一个`Figure`，后面跟着一个`Div`，按书写顺序为每个画出的标注放一个`P`。标注的光晕和底板是版面工件（artifact），所以标注的文字只读一遍；装饰同样是版面工件。

在代码中，插图的标注位于其块的`resourceBlock.labels`：文字、锚点或坐标点、样式和源码范围，另有`layout`（画出的标注的各行、方框、旋转和样式）和`rect`（标注画在哪里，`sourceAt`据此作答）。`composedReadingOrder(composedPaintOrder(page))`按阅读顺序给出一页的装饰和各框。

### frameOverflow

这条警告来自排版，而不是上面那些读源码的检查：页面排好之后，它才出现在检查面板、`postext check`和文档的`contentWarnings`中。

**原因**：灌入某个框的内容（通过它的槽位，或进入流文框的内容）比框高，这个框已没有可以接续的`next`框，而[逐级重排](#仍然放不下时)的各个步骤也都没能让它放下。最常见的情况是文字比框能容纳的多：译文比原文长，或者框被固定的`height`或`maxHeight`限住了。放不下的部分在分页输出中于框底被裁掉；它仍留在文档、源码映射和流式EPUB中。警告会给出模板、框、页码、文档的`locale`、被裁掉的高度（`overflowMm`）、`configPath`（该框在配置中的JSON指针，`/pageTemplates/0/frames/2`）、尝试过的步骤（`stepsTried`）、文字和图片最后停留的缩放比例（`scale`、`imageScale`），以及`proposals`，即能让内容放下的修改。

**解决**：采用其中一条建议，每条都附有在这一页上算出的取值（见[警告及其建议](#警告及其建议)）。否则就给框更多空间，用`next`把它接到另一个框，缩短文字，或者换一个模板来排这一页。

空框也会报告。在框都已无可再让的纵向组里，被压到`minHeight`或固定高度以下的框（答题区、图片位）即使完全没有内容，也按被截去的高度算作放不下。给它的修改建议是降低它自己的`minHeight`，或降低同组中内容少于此值的框的`minHeight`；不会去占另一个空框的位置。

### frameContinuationLimit

**原因**：`overflow.continueIn`为`'next-page'`或`'template:<id>'`的框把容纳不下的内容送到追加页，那一页上的框又把剩下的继续往后送，一页接一页，直到这个模板页追加的页数达到上限，即16页（见[文字接续时](#文字接续时)）。剩下的部分在最后一个追加页上于框底被裁掉；它仍留在文档、源码映射和流式EPUB中。警告给出那一页的模板和框、追加的页数（`pages`）、被裁掉的高度（`overflowMm`）、框的`configPath`以及页码。最常见的情况是追加页上接收内容的框比文字小得多。

**解决**：给那个框更多空间（加大它的高度，或者用带有更大框的`overflowTemplate`），或者缩短文字。要跨好几页才排得下的方框，通常应该放进正文。

### continueTargetMissing

**原因**：框的`overflow.continueIn`为`'page:<id>'`（见[跳转到后面的页面](#跳转到后面的页面)），而文章所在的页之后没有页面块`::::page{id="<id>"}`：可能是id拼错了，页面块上没有写这个id，规则读取的页面块属性（`'page:{attr.sigue}'`）缺失，或者那个页面块在前面（`before: true`）。其余部分与`'next-page'`一样，排在紧接着追加的一页上。警告给出模板、框、`target`（要找的id）、框的`configPath`以及页码。这个id也可以属于书中靠后章节的某个页面块；只用`buildDocument`单独排版、又没有`laterPageIds`的章节，只认得自己的页面。

**解决**：给后面那个页面块加上这个id，或者改正`continueIn`中的名称或它读取的页面块属性。文章之前的页不能接续文章：把那个页面块移到文章之后，或者指定后面的一页。

### frameCovered

**原因**：框的一部分被画在它上面的另一个框盖住（层号更高，或同一层而在模板中排得更后），而那个框在这里是不透明的：照片下面压着的题注，镂空图片下面的页签，被一条色带盖住的方框最后几行。这项检查在页面排好之后、按内容给各框定下的外框进行，所以一页在西班牙语里不被遮挡，在文字更长的版本里可能就被盖住了。框用它的底色（样式的背景或`look.background`、页签、色条）、图片和文字行遮挡别的框；轮廓线什么也不遮挡，让文字沿图片形状绕排的框（`wrap: 'contour'`）也不会用自己的外框遮住文字行。可能被遮住的有：框的文字行、页签和标题、图片和表格。压在图片上的文字不报告：它能不能看清，由对比度检查负责。宽度不到0.3毫米的交叠算作相碰，面积不到1平方毫米的一对框不计。

警告写明模板、框、盖住它的框（`coveredBy`、`coveredByPath`）、被遮住的面积（`overlapMm2`）、最先被盖住的文字（`text`）或图片（`picture`）、语言和页码，并指向被盖住的框的内容。每对框一条警告。

**解决**：每条建议都是数据，与`frameOverflow`的建议相同：

- `layer`：把盖住它的框的`layer`设到被盖住的框之下，只在这样不会转而遮住别的东西时提出；
- `exclude`：在盖住它的框上设`'push'`，让被盖住的文字绕开它（只在正文的行被压住时提出）；
- `move`：`frame`、`dxMm`、`dyMm`，即让这对框分开所需的、盖住它的框的最小位移，会在页上试排：只有当移动后的框以及锚定在它上面的框都不碰到其他任何框、也都留在容纳它们的范围之内时才提出。没有哪个方向能分开，或者被盖住的框挂在盖住它的框上时，不提出移动。

交叠是有意为之时（一幅有意伸到文字上方的图画），在任一个框上设`overlap: 'allow'`。自postext 1.48起。

### frameOutsideArea

**原因**：框超出了容纳它的范围：它的文字超出裁切线，会被裁掉，或者它的底色和图片超出出血线（没有出血时，两者都是裁切线）；或者它的任何部分超出了它锚定在其内部的框或组，例如锚定在卡片内部的一条说明（锚定到`'#card'`的`top-left`，偏移伸进卡片里），被自己的文字推出了卡片的底边。锚定在另一个方框外侧某条边上（`below`、`right-of`）的框从不算在它内部。超出不到0.3毫米的不计。

警告给出`past`（`'trim'`、`'bleed'`、`'frame'`或`'group'`）、`target`（那个框或组的名称）、`excessMm`（最大的超出量）、`sides`（每一侧的超出量）、语言和页码。

**解决**：建议有：`maxHeight`，即这个框能占的空间（对于底边固定的框不提出，因为降低高度并不能让它回到范围内）；文字框同时还有`continueNextPage`，让放不下的部分接着排；它锚定在其内部的那个框的`minHeight`，加上超出的量；`move`，在它只超出一侧时让它回到范围内的位移，只有移动后不碰到其他框时才提出。有意挂在卡片外面的徽章设`overlap: 'allow'`。自postext 1.48起。

## 文字变长时

模板页在模板声明的限度之内自行调整。如果一页上的各个框组成一个纵向组，在第一个框里写更长的文字，这个框就会变高来容纳它，下面的框以及锚定在它们上面的照片和装饰随之下移；模板一行也不用改。文字变短，框就回到声明的高度。标了`pin`的框或装饰元素留在模板放置它的地方，用于必须压在画面上的方框。纵向组和横向组怎样分配空间、哪个框先让步，都在模板中设定：见[配置 › 组如何分配空间](/zh/docs/configuration-composed-pages#组如何分配空间)。

方框排到区域底边、组里再没有框能让出空间时，放不下的那个框按下文的步骤逐级重排；组本身不带来别的警告。

## 仍然放不下时

内容放不下的框会依次尝试模板允许的各种腾出空间的办法，到第一个奏效的为止。每一步都叠加在前面各步之上，顺序如下：

能接续到另一页的框会提前走这一步：在`redistribute`之后、`scaleImages`和`shrinkText`之前。跨几页排的文章保持同一个字号，最后一页也不会排得比前面几页小。只有在无法再接续时，它的图片和文字才会缩小：在接续所能追加的最后一页上，或者应该接收其余部分的框一点也接不下时。`fit.preferContinue: false`保持表中的顺序，适用于宁可缩小几个点也不愿多加一页的方框。

没有哪一步能让内容放下时，框在底边截断，保留逐级重排达到的缩放比例，排版报告`frameOverflow`。追加页上的框如果收到的内容一点也接不下，就不再往后送（否则会无休止地追加页面）：它同样报告`frameOverflow`，尝试过的步骤中包括`continue`。每一步都把整页重排一遍，所以结果只取决于这一页：同样的输入得到同样的页面，放不下的框按模板中的顺序处理，修改一个模板页不会改变其他任何页面。相关设置见[配置 › 内容放不下时](/zh/docs/configuration-composed-pages#内容放不下时)。

## 文字接续时

框可以把容纳不下的内容送到模板页之后追加的一页上，或者送到书中后面的某一页。规则由框的`overflow.continueIn`决定：

<table>
  <thead>
    <tr>
      <th style={{ width: '200px' }}>取值</th>
      <th>内容在哪里接着排</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>'#frame'</code></td>
      <td>同一页上的另一个框，与<code>next</code>相同（见<a href="#串接框">串接框</a>）。</td>
    </tr>
    <tr>
      <td><code>'next-page'</code></td>
      <td>这一页之后追加的一页上的同一个框，追加页按模板的<code>overflowTemplate</code>来排。没有设置时，追加页是把同一个模板再排一遍，只填这一个框：其他框不占空间（它们的高度随空内容而定，并退出所在的组），所以这个框从靠近页面顶端的地方开始，装饰和书眉沿用这个模板的。</td>
    </tr>
    <tr>
      <td><code>'template:&lt;id&gt;'</code></td>
      <td>那个模板的一页。</td>
    </tr>
    <tr>

    </tr>
  </tbody>
</table>

```json
{ "id": "tema-cajas", "overflowTemplate": "tema-sigue",
  "frames": [
    { "name": "dinero", "style": "caja-azul", "maxHeight": { "value": 40, "unit": "mm" },
      "overflow": { "continueIn": "next-page" } } ] },
{ "id": "tema-sigue",
  "frames": [ { "name": "dinero", "style": "caja-azul" } ] }
```

接续是[逐级重排](#仍然放不下时)中的一步：框先变高，在组中腾出空间，这些不够时就在底边截断，而不先把图片或文字缩小（除非它的`fit.preferContinue`为`false`）。它的文字和图片保持原来的大小，这一片段以接续标记结束，其余部分从截断的那一行起接着排，按接收它的框的宽度重新断行。内容不丢也不重复，也不发出警告。

- **哪个框接收。** 在追加页上，内容进入同名的框；模板中没有同名的框时，进入它的流文框；再没有，就进入它第一个还没被占用的框。用`next`串接的文章从串的开头接着排：三个串接的栏中第三栏剩下的内容，进入追加页的第一栏（与串首同名的框，没有则进入流文框），所以接续到自身的正文模板会填满每一页的每一栏。一页上有几个框接续到同一个模板时，如果那个模板为每个框都备有一个框，它们共用一个追加页；否则后面那个框单独占一页。追加页上什么也没收到的框留空。
- **一次又一次。** 仍然放不下的片段再接着排到下一个追加页：框在那一页上有自己的`overflow.continueIn`时按它来，否则沿用把内容带来的那条规则。一个模板页最多连续追加16页；最后一页上仍放不下的部分被裁掉，并报告为[`frameContinuationLimit`](#framecontinuationlimit)。追加页上的框如果小到一点内容也接不下，就报告`frameOverflow`，而不再追加页面。
- **在哪里截断。** 与页面上相同：标题跟着它的头几行，列表两边各留两项（见[串接框](#串接框)）。方框一点也放不进这一页时，整个方框连同页签一起接着排：页面上不会留下一个页签和一个接续标记，下面却是空的片段。此时方框在原页面上不占位置；如果它下面的答题区在那里保持不了原有大小，方框就连同答题区一起整体转到后面。
- **各页保留什么。** 被截断的框先让出它在组中的空间，所以它后面的框保持原来的大小。其余部分在再排一遍的同一个模板上接着排时，纵向组里紧跟在它后面的空框（活动方框下面留给作答的空白：不接收内容的框）随它一起走。它们在本页上不占空间；在追加页上，它们在方框剩下的部分下方保持原来的大小，锚定在它们上面的装饰也一样。那个追加页上的其他框不占空间，它们的装饰也不画出；纵向组保持它的第一个框在模板中的位置，所以方框剩下的部分从纵向组开始的地方排起，避开该页的引题和书眉。
- **普通的页。** 追加页是书中的页：它们有页码，带有所用模板（或所在章节）的书眉，采用所在一侧的`variants`，页面块的`{attr.x}`也照样传到它们的装饰。设了`spread: true`的追加页模板从下一个偶数页开始，需要时先插一个为奇偶而留的空白页，并占用紧接着的奇数页；`overflowTemplate`为单页模板的跨页，接续到单页上。页面块之后的文字从最后一个追加页的下一页开始。
- **id。** 第n个追加页上的框是`cp0:<name>~<n>`；接收内容的框，以页面块本身那一页上最先把内容送出的框来命名（`cp0:dinero~1`、`cp0:dinero~2`），所以不论由哪个框接收，选区都保持原来的元素。每个框记下它从哪个框接续而来、又接续到哪个框（`continuedFrom`、`continuesTo`），该页的`VDTPage.composed.continuationOf`是页面块本身那一页的索引，各片段的块带有方框的id加上`-cont-<n>`，与拆分的标注框相同。
- **重新排版。** 内容接续到别页的模板页，每次构建都连同追加页一起重新排：页面缓存只保留内容不越出本页的页面。

### 跳转到后面的页面

杂志文章在自己的页上排不完时，会跳过别的文章，转到后面的某一页：“转第47页”。`overflow.continueIn: 'page:<id>'`把其余部分送到带有那个`id`的页面块，不论它在本章后面的什么地方：

```markdown
::::page{template="articulo" sigue="p47"}
…
::::

::::page{template="otra"}
…
::::

::::page{template="saltos" id="p47"}
…
::::
```

```json
{ "name": "cuerpo", "flow": true,
  "overflow": { "continueIn": "page:{attr.sigue}",
    "mark": "转第 {page} 页", "fromMark": "接第 {page} 页" } }
```

- **哪一页。** `<id>`可以是`{attr.name}`，从文章所在的页面块读取，这样一个文章模板就能用于每一篇文章，每篇转到哪里由Markdown来写。
- **哪个框。** 由`'page:<id>#<frame>'`指定的框；没有指定时，进入与送出内容的串首同名的框，没有则进入那一页自身内容留空的第一个框。那一页在其他框中照样排自己的内容。
- **跳转之后。** 那个框容纳不下的部分，排在跳转页之后追加的页上，从那里起与`'next-page'`相同；在跳转页上找不到空框的文章也到那里接着排。
- **id与链接。** 跳转页上的框保留自己的id（`cp2:resto`）。送出内容的框的`continuesTo`和接收内容的框的`continuedFrom`把各片段连起来，送出页的重排记录写着“cuerpo continued on page 47”。流式EPUB和带标签的PDF把文章当作一个整体来读。
- **不在后面的页。** 后面没有哪个页面块带有这个id时，报告[`continueTargetMissing`](#continuetargetmissing)，其余部分排在下一页上。
- **跳到后面的章节文件。** 每篇文章一个章节文件的杂志，也这样跳转：带有`id`的页面可以在书中靠后的章节里（自postext 1.41起）。送出内容的章节把剩余部分交出，有该页的章节把它排进那一页留空的框里，和处理同一文件内的跳转一样。剩余部分里的脚注、标题和图的编号以及引用，保留各自章节给它们的编号；标记印出的是全书的页码：“转第47页”写的是有该页的章节所印出的页码，中间的章节增减多少页都不受影响。点击从别的章节带来的文字，光标落在这些文字原先所在章节的Markdown里。几篇文章跳到同一页时，按章节的先后占用该页的空框。修改文章，有该页的章节会重新排版；修改中间的章节则不会。带标签的PDF把剩余部分读在它所在的页上，排在该页自身内容之后；流式EPUB则把它读在有该页的章节里。剩余部分按全书正文的排版设置，不按有该页的章节里带样式的小节来排；其中写下的索引标记、锚点或标题，列在有该页的章节排下这些文字的那一页上（索引、目录和引用里都是如此，PDF里作为跳转目标也是），而不是文章开始的那一页（自postext 1.42起）。在沙盒画布上，送出内容的章节的编辑器里的选区和光标，会画在带过去的文字上。

标记里可以写`{page}`：其余部分所在那一页印出的页码，杂志常这样写（`mark: "转第 {page} 页"`）。它适用于新增的页（`'next-page'`、`'template:<id>'`），也适用于文章跳到的后面某个页面块（`'page:<id>'`）。页码在各页编号之后填入。

接续标记排在片段最后一行的下方，用方框的正文字体，对齐和倾斜按样式的`continuesMarkerAlign`和`continuesMarkerItalic`（默认右对齐、斜体）。它属于分页用的附属内容：流式EPUB不输出它，带标签的PDF把它标为版面工件。同一页上用`next`串接的框不带标记。

另一页上的片段开头不带框的页签和标题，与拆分的标注框后面的各部分一样。`overflow.fromMark`设定片段开头的文字，`{page}`是内容来自的那一页的页码：`"接第 {page} 页"`。接收内容的框自己的`fromMark`优先于送出内容的框的；两者都不设置，片段开头就不加文字。设了`repeatTitle: true`的样式在那里重复标题，并加上`continuedSuffix`（“(cont.)”）。两种标记都用方框的正文字体，对齐和倾斜与末尾的标记相同，也都属于分页用的附属内容。

## 重排记录

每个模板页都留有一份记录，写明排版相对于模板本身的画法改动了什么：哪个框变高、让出了空间或移动了位置，变化了多少，又是哪个框引起的。文字放得进模板的页面不留任何记录。高度为`auto`且没有`minHeight`的框不声明自己的高度：无论文字多长，记录里它都不会“变高”，锚定在它上面的框也不会“移动”（例如杂志的导语和挂在它下面的各栏）。把它在版面上画出的高度设为`minHeight`，两者就都会记录下来。排版食谱的压力测试（C38）则把这样的框与按原文排出的结果相比较。

## 跨页

设了`spread: true`的模板是左右相对的两页合成的一整张版面：一条横跨书脊的色带，一条从一侧外边缘延伸到另一侧外边缘的插图带，两边各有几张卡片。页面块用`spread`写明这一点：

```md
::::page{template="linea-tiempo" spread}
# Cómo medimos el tiempo

Para saber cuándo comer, trabajar o descansar, las personas siempre han necesitado medir el tiempo…

:::frame{slot="banda-2"}
Con relojes de máquina
:::

::resource{id="tira-tiempo" slot="tira"}
::::
```

- **从哪里开始。** 跨页总是从偶数页开始（从左往右读的书是左页，从右往左读的书是右页），并占用紧接着的奇数页。前面的文字若在偶数页结束，下一页留空（与漫画跨页之前一样，是为奇偶而留的空白页），让两半正好相对。结束行之后的文字从这个奇数页的下一页开始。
- **一整张版面。** 框排在一张与两页同宽的版面上。`content`区域从一页的外侧页边一直到另一页的外侧页边，两个内侧页边都包含在内；`trim`是并排的两张裁切后的页面；`bleed`在天头、地脚和两侧外边缘加上出血，书脊处从不加。`grid`划分整个宽度：六栏就是每页三栏。从右往左读的书里，这张版面像它的页面一样左右镜像，所以第一栏落在右页上。
- **订口。** `gutter`是以书脊为中心、宽度为该值的一条带。没有`crossGutter: true`的框要避开它：横跨整条带的框在它中心所在的一侧被截到带的边缘；内侧边缘落进带里的框则整个移出去。`auto`高度按变窄后的宽度来量，页面的重排记录会记下这次改动（`resized`或`moved`，原因为`gutter`）。不设`gutter`时，这条带就是书脊本身，只有明确要求的框才会越过折缝。
- **跨过书脊。** 设了`crossGutter: true`的框可以跨过书脊。框里的文字只读一次，在框的中心所在的那一页；对面那一页画出框属于自己的一半，在自己的版面边缘截断，这样色带或插图在打开的书上看起来是一整块。带标签的PDF把这一半标为工件（artifact），HTML对辅助技术隐藏它，选择或搜索文字时也只会找到一次。
- **装饰**在整张版面上排一次，再以同样的方式在书脊处切开：底色、从一页延伸到另一页的卡片、右页上的书眉。锚定在`#框名`上的元素会跟着那个框到它所在的页面。跨页本身就包含奇偶两页，所以不接受`variants`；`header`和`footer`在它的每一页上都和普通页面一样起作用。

在画布上、在沙盒的跨页视图里和在Folio中，两页并排显示。PDF有两页，各自在出血处截断。固定版式EPUB给这两页加上`page-spread-left`和`page-spread-right`以及`rendition:spread-both`，让阅读器在横竖两种方向上都把它们放在一起显示。流式EPUB像读其他模板页一样，按Markdown的顺序读这些框。

### spreadMismatch

**原因**：页面块与模板不一致：页面块写了`spread`而模板只占一页，或者模板是跨页模板（自己设了`spread: true`，或通过`extends`继承）而页面块没写。以模板为准：跨页模板排在左右相对的两页上，其他模板排在一页上。警告给出模板、页面块的标记（`fence`）和模板的标记（`templateSpread`），并指向`spread`属性；页面块没有这个属性时，指向模板名。

**解决**：让页面块与模板一致：跨页模板就在页面块上写`spread`，单页模板就去掉它，或者换一个模板。

## 迁移文字放在样式里的书

在模板页出现之前做的书，可能把各页的文字放在标题样式里：每页一个隐藏标题，它的书眉把每段文字放到印刷页上原来的位置。*配置中存放的正文*检查会指出这一点。在沙盒中，检查面板里的**把文字移到Markdown**会把每个页面设计变成一个页面模板，框放在文字原来的位置，并把每一页变成一个页面块，文字放进`:::frame`槽位；它会显示每一页的前后对比，并且可以撤销。参见[把文字移到Markdown](/zh/docs/sandbox-composed-pages#把文字移到markdown)。在代码中，`moveTextToMarkdown({ config, chapters, metadata }, options)`做同样的事，返回新的配置、章节和一份报告。

设置`labelsOnPictures: true`（自postext 1.38起）后，设计放在图片上的文字不再变成框，而是成为这张图片的标注：只有一行、不超过四个词、字号不大于正文四分之三（`labelsOnPictures: { maxFontSize }`可设定别的上限），且文字框落在同一设计的某张图片之内。图片离开装饰，变成位于原绘制位置的一个框，框里是一个`:::figure`，每段文字一行`::label`；每段文字成为图片资源的一个锚点，位于设计原来放它的地方（首行基线、对齐方式所指的一侧、文字框的宽度），并按它的样子生成一个标注样式。请在输入中传入书的`resources`：结果会带着锚点把它们返回（`result.resources`）；如果某张位图比设计拉伸覆盖的框小，会给它设置相应的`resolution`，使它排到那个宽度。出现在多页上的图片共用锚点。报告中的`labels`统计图片、标注、锚点和标注样式的数量。书中有可变成标注的文字时，沙盒的对话框会把它作为一个选项提供，默认关闭，需要时再打开。如果设计在图片上方画了装饰（横过地图的标签），而图片下方没有装饰，图片的框就放到层`-1`，位于装饰之下，标签仍在地图之上（自postext 1.40起）。图片下方也有装饰，或装饰盖住图片的某个标注时，框只能占一个层位，无法同时满足两种上下顺序：框留在层0，该页会被标为可能看起来不同的页（`overPicture`）。

## 在代码中使用

`composedPages(blocks)`读取一章解析后的块（`parseMarkdownWithIssues(markdown).blocks`），按顺序为每个页面块返回一个节点，包括：`template`、`spread`、带有每个值源码范围（`attrSources`）的`attrs`、`fenceIndex`（该页面块在章中的序号，各语言相同）、`slots`（每个槽位的块索引，按Markdown中的顺序）、`unassigned`（没有槽位的块），以及整页的源码范围。块在`ContentBlock.slot`中记录它指定的槽位及该值的源码范围；插图是一个`resourceBlock`，其`figure`含有插图的属性和标注，每个标注带有文字、行内片段和指回Markdown的源码映射。`checkComposedSlots(pages, config)`为这些页面返回三种槽位警告。

排版之后，模板页的`VDTPage.composed`记录它的模板、所套用的变体、页面块的属性，以及每个框的这些信息：id（`cp0:dinero`，即页面块的序号加框名，各语言相同）、外框、层、旋转、放不下的内容高度（`overflowPx`）、从哪个框接续而来或接续到哪个框、它在配置中的路径（`/pageTemplates/0/frames/2`）以及它的块的id。这些块是`page.floats`和`doc.blocks`中普通的标注框块，带有各自的源码范围，所以在沙盒预览中点击一个未旋转的框，就会跳到它的Markdown。`composedPaintOrder(page)`给出渲染器绘制各框和装饰的顺序，`frameMatrix(frame)`给出框的旋转。

## 来源映射

模板页上画出的每样东西都知道自己写在哪里：编辑器可以从页面上的一点回到Markdown或配置，也可以从Markdown的一段找到它在页面上排成了什么。

`sourceAt(doc, pageIndex, x, y)`接收排好的页面上的一个点（页面像素，从纸张左上角算起），返回那里的内容，由内向外：每个元素后面跟着包含它的元素。标注框里的一个字会带上它所在的行、段落、框、框所属的组和模板；装饰里的一个词会带上它的设计元素、装饰和模板。每个元素都有`level`、稳定的`id`、`source`，大多还有它在页面上的`rect`（转正的，即旋转框的`rotate`之前的位置）。

在从右到左或竖排的页面上，框排在页面的行文坐标系里，纸面上看是镜像的或转了四分之一圈；装饰和书眉留在纸面坐标里。`sourceAt`仍然接收纸面上的点，并为框做换算。`rect`位于行文坐标系的元素会带上`flow: true`，`sourceAt`、`elementsForSource`和`findElement`都是如此；`flowRectToPage(page, rect)`给出它在纸面上的框，`flowToPage(page, x, y)`换算其中一点。postext 1.38及以前，在这类页面的框上取纸面点，只能找到模板。

层级由内向外为：`text`、`attr`、`label`、`resource`、`line`、`block`、`box`、`frame`、`group`、`design`、`slot`、`template`。框和模板还带有`content`，即它们包含的Markdown范围：框的槽位内容、整个页面块。`file`是宿主在选项中传入的名称（`{ file: 'tema-1.md' }`，或者对由多章拼接而成的文档，传一个以页码索引为参数的函数）。

```ts
import { buildDocument, sourceAt, elementsForSource, findElement } from 'postext';

const doc = buildDocument({ markdown, resources }, config);
const chain = sourceAt(doc, 0, 640, 1180, { file: 'tema-1.md' });
// [ { level: 'text', id: 'cp0:dinero-c0@12', source: { kind: 'markdown', start: 677, end: 678, file: 'tema-1.md' } },
//   { level: 'line', … }, { level: 'block', id: 'cp0:dinero-c0', … },
//   { level: 'frame', id: 'cp0:dinero', source: { kind: 'config', path: '/pageTemplates/0/frames/2' }, content: { start: 665, end: 942 } },
//   { level: 'template', id: 'cp0', source: { kind: 'config', path: '/pageTemplates/0' } } ]

elementsForSource(doc, 677, 690); // 这段文字涉及的行、块、框、页面和设计文字
findElement(doc, 'cp0:dinero');   // 重新排版后的同一个框，带有它的rect
```

`elementsForSource(doc, start, end)`反过来查，对这段Markdown涉及的每一行、每个块、框、模板页和设计文字，返回`{ pageIndex, element }`。排到框底之下的行带有`clipped: true`：在页面上被裁掉，在来源映射中仍然保留。在跨页上，跨过书脊、在对页上阅读的那半个框，在`sourceAt`和`elementsForSource`中都以它所显示的块的id作答，并带有`facing: true`。此时`elementsForSource`给每一页返回的框，其`rect`是该页实际画出的那部分，所以从书脊附近开始的色带在两页上都有可以点中的位置。插图的标注在`label`层级作答，带有它的id和锚点，无论它画在图片的什么位置。

**稳定的id。** 模板页是`cp<n>`，`n`是它的页面块在本章中的序号；框是`cp<n>:<框名>`（在后面页面上接续的第k段内容加`~<k>`），框中的块是`cp<n>:<框名>-c0`、`-c1`……，组是`cp<n>:group:<组名>`，装饰或页眉页脚中的元素是`cp<n>:decoration:<id>`、`cp<n>:header:<id>`、`cp<n>:footer:<id>`，插图的标注是`cp<n>:<槽位>:label:<锚点>`。这些id都不依赖位置，也不依赖文字，所以无论怎样重新排版，在本章的任何语言版本中都相同：编辑之后选区依然有效，在译本中也能找到同一个框。`findElement(doc, id)`可以重新找到该元素。

**目录条目。** `:::toc`的每一行在`tocEntry.headingSource`中记录它所列标题在本章Markdown正文中的位置（不计前置元数据，与大纲的计法相同）；`sourceAt`在该行的块上以`heading`给出。

**只重排一页。** 每个模板页的排版结果按它所读取的内容保存：模板、该页的Markdown、样式和字体、语言、页面落在奇数页还是偶数页，以及纸张的几何尺寸。之后的排版再次遇到同一页时（下一轮排版、本章别处的一次编辑、同一worker中再次分页），会直接沿用。在某一页内编辑，或修改它的页面块上的属性，只重排这一页；修改模板则重排所有使用该模板的页面。含有脚注、交叉引用、文献引用或目录的页面每次都重新排版，因为它印出的内容取决于书的其余部分。跨页也每次都重新排版：它的两页是同一张纸。`VDTComposedPage.layoutKey`是一页中各个框的键；`composedPagePaintKey(page)`再加上框周围的内容（页眉页脚、装饰、页码），宿主只要键不变，就可以保留已经画好的像素。沙盒的画布正是这样做的：在某一页上编辑，只重画这一页。

## 漫画页

漫画页（`:::page{split}`）是一种模板页，它的框由分割生成：每个分格一个，带有稳定标识`cm<n>:<名称>`，斜切格子有多边形轮廓，可通过`box`使用标注框样式，文字格中可以灌入Markdown。见[漫画 › 漫画页与模板页](/zh/docs/comics#漫画页与模板页)。
