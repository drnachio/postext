# Konfiguration: Kästen


## Kastenstile

Die Eigenschaft `calloutStyles` legt die benannten Kastenstile fest, die ein Dokument mit einem Container `:::callout{type="…"}` anwendet – Anmerkungen, Tipps, Warnungen, Lernziele, jeder Inhalt, der in einem getönten oder umrandeten Kasten vom Fließtext abgesetzt wird. Ein neutraler Stil, `note`, ist standardmäßig dabei (hellgrauer Hintergrund, keine Kontur, kein Streifen, kein Symbol, kein Titel), sodass `:::callout` ohne jede Konfiguration funktioniert; wer `calloutStyles` angibt, ersetzt diese Standardliste.

```ts
const config: PostextConfig = {
  calloutStyles: [
    { id: 'note', name: 'Note' },
    {
      id: 'objectives',
      name: 'Learning objectives',
      title: 'Objectives',
      stripe: { enabled: true, side: 'left' },
      icon: { kind: 'glyph', glyph: '✓' },
      titleStyle: { textTransform: 'uppercase' },
      lists: { bulletChar: '–' },
    },
    {
      id: 'warning',
      title: 'Warning',
      backgroundEnabled: false,
      border: { enabled: true, color: { hex: '#AA0000', model: 'hex' }, width: { value: 1, unit: 'pt' } },
      borderRadius: { value: 1, unit: 'mm' },
      titleStyle: { color: { hex: '#AA0000', model: 'hex' } },
    },
  ],
};
```

```md
:::callout{type="objectives"}
- Describe the parts of the lantern.
- Trim the wick at dusk.
:::

:::callout{type="warning" title="Do not touch the lens"}
The glass stays hot for an hour after the flame is out.
:::
```

### Ecken, Seiten und verbundene Etiketten

Ein Kasten muss kein Rechteck mit vier gleichen Ecken und einer einzigen Kontur sein. Seit postext 1.48 kann ein Stil manche Ecken abrunden und andere nicht, seine Kontur nur an einigen Seiten zeichnen und sein Etikett als eine einzige Form aus dem Kasten wachsen lassen: die Karte eines Schulbuchs, deren Titeletikett und Körper ein einziger Umriss sind, gezeichnet vom Stil statt in ein Bild hinter der Seite gemalt.

```ts
calloutStyles: [
  // Rounded at the top only, a rule over the box and a heavier foot.
  { id: 'ficha', background: { model: 'hex', hex: '#fff4d6' },
    borderRadius: { topLeft: { value: 3, unit: 'mm' }, topRight: { value: 3, unit: 'mm' } },
    border: { enabled: false, color: { model: 'hex', hex: '#c58b00' }, width: { value: 0.75, unit: 'pt' },
      sides: { top: { enabled: true }, bottom: { enabled: true, width: { value: 2, unit: 'pt' } } } } },
  // A card whose tab grows out of its top edge.
  { id: 'tarjeta', background: { model: 'hex', hex: '#ffffff' }, borderRadius: { value: 3, unit: 'mm' },
    border: { enabled: true, color: { model: 'hex', hex: '#2a6f97' }, width: { value: 1, unit: 'pt' } },
    label: { position: 'top-left', inset: { value: 4, unit: 'mm' }, joined: true, fillet: { value: 2, unit: 'mm' },
      color: { model: 'hex', hex: '#2a6f97' } } },
]
```

- **Ecken.** `borderRadius` ist eine Länge für alle vier Ecken oder `{ topLeft, topRight, bottomRight, bottomLeft }`. Eine Ecke, die im Objekt fehlt, ist eckig. Die Ecken sind die des Blatts. Zwei Ecken nehmen nie mehr als die Seite zwischen ihnen; jede gibt anteilig nach.
- **Seiten.** `border.sides.top`, `right`, `bottom` und `left` nehmen `enabled`, `color` und `width` an, und jedes fehlende Feld kommt von der ganzen Kontur. Ein Kasten mit einer Kontur nur oben ist `border: { enabled: false, sides: { top: { enabled: true } } }`, oder `enabled: true` mit den drei anderen Seiten ausgeschaltet. Die Innenkante einer Seite folgt ihrer Breite, sodass eine abgerundete Ecke zwischen einer dünnen und einer dicken Seite so geschwungen ist, wie CSS sie zeichnet.
- **Verbundenes Etikett.** Mit `label.joined: true` sind Etikett und Kasten ein Umriss, eine Füllung (der `background` des Kastens; der eigene `background` des Etiketts wird nicht gezeichnet) und eine Kontur, die um das Etikett herumläuft. Das Etikett steht auf der Kante, um seine Höhe außerhalb des Kastens: Sein `offset` muss `0` sein (ein anderer Wert wird als `unknownConfigValue` gemeldet und als `0` gelesen). Seine äußeren Ecken übernehmen den Radius der Kastenecke, an die es sich schmiegt, und die inneren Ecken, an denen es auf den Kasten trifft, rundet `fillet` ab (Standard: dieser Radius). Ein Etikett, das bündig mit der Seite des Kastens steht (ein `inset` unter einem halben Pixel), steigt gerade aus dieser Seite auf. Geben Sie den Wörtern eine Farbe, die auf der Füllung des Kastens lesbar ist (`label.color`), da das Etikett keine eigene Füllung mehr hat. Mit `label.ownBackground: true` wird ein verbundener Reiter im eigenen `background` des Etiketts gemalt, über der Füllung des Kastens und unter dem Rahmen; so kann ein weißer Reiter auf einem getönten Kasten stehen oder ein farbiger auf einem Kasten ohne Füllung.
- **Ecken des Reiters.** `label.borderRadius` gibt dem Reiter eigene Ecken: eine Länge oder `{ topLeft, topRight, bottomRight, bottomLeft }` auf den Ecken des Blatts, wie das `borderRadius` des Kastens. Ein Reiter abseits des Kastens bleibt eckig, solange er keine setzt. Ein verbundener Reiter rundet damit seine beiden äußeren Ecken (`topLeft` und `topRight` oben, `bottomLeft` und `bottomRight` unten); ohne Wert übernehmen sie den Radius der Kastenecke. Die Hohlkehlen behalten in beiden Fällen `fillet`.
- **Etiketten am Fuß.** `position: 'bottom-right'`, `'bottom-left'`, `'bottom-start'` oder `'bottom-end'` hängt das Etikett an den Fuß des Kastens, einfach oder verbunden: Es ist das umgedrehte obere Etikett, `offset` unter dem Fuß, die `rule` entlang des Fußes. Seitliche Etiketten gibt es nicht: Die Wörter eines Etiketts laufen quer.

Jedes Ausgabeformat zeichnet diese Formen: Canvas und PDF als Vektorumrisse, der HTML-Betrachter und das EPUB mit festem Layout mit CSS je Ecke und je Seite. Das umfließende EPUB schreibt die Ecken und Seiten in sein CSS und setzt ein verbundenes Etikett als einfaches Etikett. Das `look.border.color` eines Rahmens färbt jede Seite um, und eine Teilpalette färbt jede einzeln um. Ein Stil, dessen Ecken und Seiten alle gleich sind, wird wie bisher gesetzt.

### Ein Zeichen auf dem Etikett

Das Zeichen ist Dekoration: ein Layout-Artefakt in einem getaggten PDF, im HTML vor assistiven Technologien verborgen und im umfließenden EPUB aus dem Titel des Kastens weggelassen, sodass das Etikett nur über seine Wörter gelesen wird.

### Stile, die auf einem anderen basieren

`extends` nennt einen anderen Stil aus `calloutStyles`, und jedes Feld, das der Stil offenlässt, kommt von diesem. Objekte wie `padding`, `border`, `titleStyle` oder `fixed` werden Schlüssel für Schlüssel zusammengeführt, sodass ein Stil nur eine Seite des Innenabstands oder nur `fixed.offset` ändern kann; eine Farbe oder eine Länge wird ganz übernommen; `id` und `name` werden nie geerbt. Ein Elternstil kann seinerseits auf einem anderen basieren. Ein Buch mit Kästen an vielen Stellen behält einen Stil für ihr Aussehen und je Stelle einen schlanken Stil:

```ts
calloutStyles: [
  {
    id: 'caja',
    background: { model: 'hex', hex: '#dff0fa' },
    padding: { top: { value: 3, unit: 'mm' }, right: { value: 4, unit: 'mm' }, bottom: { value: 3, unit: 'mm' }, left: { value: 4, unit: 'mm' } },
  },
  { id: 'caja-p5', extends: 'caja', placement: 'fixed', fixed: { offset: { x: { value: 12, unit: 'mm' }, y: { value: -40, unit: 'mm' } } } },
  { id: 'caja-p9', extends: 'caja', placement: 'fixed', fixed: { anchor: { to: 'container', edge: 'top-right' } } },
]
```

Ändern Sie das Aussehen von `caja`, und alle Kästen folgen, jeder an seinem Platz. Ein `extends`, das auf keinen vorhandenen Stil verweist, löst `calloutStyleExtendsUnknown` aus (die Warnung schlägt die nächstliegende ID vor, und der Stil steht für sich, mit den eingebauten Werten), und Stile, die im Kreis aufeinander basieren, lösen `calloutStyleExtendsCycle` aus (sie stehen für sich, bis einer auf einem Stil außerhalb des Kreises basiert). In der Sandbox legt das Feld **Basiert auf** eines Kastenstils es fest; wer einen Stil löscht, auf dem andere basieren, schreibt dessen Einstellungen in diese, sodass sich ihre Kästen nicht ändern. Im Abschnitt **Rahmenstile** behält das Zusammenführen mit **Nur das Aussehen vergleichen** einen Stil, dessen Kästen woanders stehen, als solchen schlanken Stil, wenn **Jeden Kasten an seinem Platz lassen** an ist (Standard), und kein Kasten bewegt sich. Seit postext 1.39.

### Der Container `:::callout`

Eine Zeile `:::callout{type="<id>"}` öffnet den Kasten, eine bloße Zeile `:::` schließt ihn. Die öffnende Zeile nimmt fünf Attribute an – `type` (die ID des Stils), `title` (überschreibt den Titel des Stils), `span`, `placement` und `columns` (überschreiben die Werte des Stils) –, und der Inhalt dazwischen wird im Kasten gesetzt: ein optionaler Titel, dann die Absätze, Listen, Zitatblöcke, Formeln oder Ressourceneinbettungen, jeweils mit der Typografie `body` / `lists` des Stils (Überschriften behalten ihre üblichen Stile). Außenabstände zwischen Kindblöcken fallen wie im Fließtext zusammen; das Innere verlässt das Grundlinienraster, und der Fluss rastet nach dem Kasten mit mindestens `marginBottom` darunter wieder darauf ein (das Raster hat Vorrang; der Außenabstand ist ein Mindestwert – dieselbe Konvention, der Ressourcen folgen). Ein Stil mit `snapToGrid: false` behält stattdessen das genaue `marginBottom`, und der Text nach dem Kasten bleibt bis zur nächsten Überschrift oder zum nächsten Listenende außerhalb des Rasters. Eine Überschrift unmittelbar vor einem Kasten bleibt bei ihm.

Grenzen in dieser Version:

- Ein Kasten wird zusammengehalten, sofern sein Stil nicht `keepTogether: false` setzt. Passt er nicht in den verbleibenden Spaltenraum, wandert er ganz in die nächste Spalte oder auf die nächste Seite – auch aus einer leeren Spalte, die Gleitobjekte am Kopf oder Fuß oder eine Höhengrenze des Spaltenbereichs verkürzt haben, solange eine volle Spalte ihn fassen würde. Ein Kasten, der höher als eine volle Spalte ist, wird stattdessen geteilt, wie ein teilbarer; nur einer, den kein Schnitt teilen kann (eine Abbildung oder Tabelle, die höher als die Spalte ist, oder ein `splitMinLines`, das kein Schnitt erfüllt), wird trotzdem platziert und läuft über; das Layout vermerkt dann eine Warnung `calloutOverflow` (`VDTDocument.warnings`), die die Sandbox auflistet. Eine Gruppe `:::columns` wird wie der Kasten um sie herum geschnitten, zwischen ihren Unterspalten (seit postext 1.25); sie bleibt nur mit `layout.flowColumns: false` oder in einem verschachtelten Kasten ganz und kann dann ebenso überlaufen. Ein teilbarer Kasten lässt den passenden Teil zurück – ganze Kindblöcke oder die Zeilen eines Absatzes bis hinab zu `splitMinLines` auf jeder Seite (eine Abbildung, Tabelle oder abgesetzte Formel allein genügt für eine Seite) – und geht in einem Kasten ohne Symbol in der nächsten Spalte oder auf der nächsten Seite weiter, ohne Titel, sofern der Stil ihn nicht wiederholt, und optional mit einem Vermerk unter dem verlassenen Teil (siehe [Vermerke an einem geteilten Kasten](#vermerke-an-einem-geteilten-kasten)).
- Gleitobjekte weichen einem unteilbaren Kasten. Ist der Block direkt nach dem Verweis auf eine Abbildung ein Kasten mit `keepTogether`, wird ein Platz, der dem Kasten keine Spalte des aktuellen Spaltenbereichs ließe, in der er stehen kann (die verweisende Spalte oder eine leere danach, die ihn vor dem Gleitobjekt aufgenommen hat), nicht genommen: Die Abbildung geht zu ihrem nächsten Platz weiter, meist auf der nächsten Seite, und der Kasten bleibt im Fluss – so, wie ein Setzer ihn setzen würde, statt den Kasten von der Seite zu drängen und die Spalte mit der Abbildung allein zu lassen.
- `span: 'page'` in einem mehrspaltigen Layout macht den Kasten zu einem **seitenbreiten Block**: Er wird auf die volle Inhaltsbreite gesetzt und teilt die Seite in Spaltenbereiche – die Textspalten darüber werden an der Schnittlinie geschlossen, der Kasten nimmt eine eigene Spalte über die volle Breite ein, und darunter öffnet sich ein neuer Spaltenbereich mit Textspalten, sodass der Fluss in jeder Spalte unter dem Kasten weitergeht. Wo die Spalten *ausgeglichen* sind – am Kopf einer Seite, direkt unter einer Auftaktüberschrift mit `span: 'page'`, direkt unter einem anderen seitenbreiten Block oder direkt unter einem Gleitobjekt am Seitenkopf –, schneidet der Kasten einfach dort. Kommt er mitten auf der Seite an, bei ungleichen Spalten, wird er so gesetzt, wie es ein Setzer täte: Der Text darüber wird über alle Spalten ausgeglichen geschnitten (die Engine wiederholt die Platzierung mit Spalten des Spaltenbereichs, die auf dieselbe Zahl von Rasterzeilen gekürzt sind, sodass der Text natürlich von Spalte zu Spalte überläuft und jede Regel zu Waisen, Witwen und Zusammenhalt mit dem Folgenden weiterhin gilt), der Kasten überspannt die Seite, und die Spalten gehen darunter weiter. Der Schnitt kostet einige zusätzliche Platzierungsdurchgänge; ließe die Schnittlinie keinen Raum für den Kasten plus das Witwenminimum an Fließtextzeilen darunter, oder passt nach einigen Versuchen keine Anordnung, wandert der Kasten an den Kopf der nächsten Seite. Der Text darüber hält sich an den Schnitt: Ein Absatz, der in den wenigen Zeilen, die eine Spalte unter einer Abbildung darüber freihält, nicht beginnen kann, geht in die nächste Spalte (die Abbildung steht dann allein in ihrer Spalte), und würde ein Block dennoch über den Schnitt hinauslaufen, wird der Schnitt eine Zeile tiefer gesetzt, statt dort, wo dieser Block endet. Ein geteilter Kasten, der den Spaltenbereich eröffnet, wird ebenfalls dort geschnitten, sodass sein Rest nie über den Schnitt hinausläuft. Mit `headings.balancing.beforeSpan` (dem Standard) wird der verlassene Spaltenbereich hinter ihm ausgeglichen abgeschnitten – wie der letzte Spaltenbereich eines Kapitels –, und wenn der Stil das Teilen erlaubt (`keepTogether: false`), schließt der Teil des Kastens, der unter die ausgeglichenen Spalten passt, die Seite ab, und der Rest eröffnet die nächste; mit `beforeSpan: false` wird die verlassene Seite einfach wie üblich ausgeglichen, ohne einen Seitenumbruch zu erzwingen. Eine Überschrift direkt vor einem seitenbreiten Block wandert nicht mit ihm. In einspaltigen Layouts ist `span: 'page'` einfach ein Kasten im Fluss.
- `placement: 'fixed'` nimmt den Kasten aus dem Fluss: Er wird gesetzt (`width: 'auto'` passt sich eng an den Titel an; `'fill'` nimmt die Breite der Textspalte unter dem Ankerpunkt) und auf der Seite, auf der er im Fluss vorkommt, an der Position fixiert, die `fixed.anchor` / `fixed.offset` beschreiben – standardmäßig die linke untere Ecke des Inhaltsbereichs. Die Textspalten, die er überdeckt, geben diese Zone frei (von unten abgeschnitten oder von oben, wenn die Spalte noch leer ist), genau wie bei einem Gleitobjekt am Kopf oder Fuß; enthält die Zone bereits Text, ein Gleitobjekt oder einen seitenbreiten Block, wandert der Kasten auf die nächste Seite. Ein fixierter Kasten, der das Kapitel abschließt (der nächste Block ist ein Kapitelauftakt, ein `:::part`, ein Kasten, der als Schranke wirkt, oder das Ende des Dokuments), gleicht zuerst die Spalten darüber aus (`headings.balancing.trailing`), sodass eine kurze Schlussseite ausgeglichen über dem Abzeichen darunter endet. Rahmenblock und Kindblöcke stehen in `page.floats` und werden in jeder Ausgabe außerhalb des Spaltenbeschnitts gezeichnet.
- `placement: 'top' | 'bottom'` lässt den Kasten wie eine Ressource **gleiten**: Er verlässt den Fluss an seiner Stelle und nimmt den ersten freien Bereich nach diesem Punkt – den Fuß der aktuellen Seite (`'bottom'`) oder Kopf / Fuß der nächsten Seite, die der Fluss eröffnet – in Spaltenbreite (`span: 'column'`) oder in voller Inhaltsbreite (`span: 'page'`); der Text danach füllt die verlassene Seite. Rahmenblock und Kindblöcke kommen in `page.floats`, wie bei einem fixierten Kasten. Ein gleitender Kasten, der eine neue Seite anführt, wird vor den Abbildungen gesetzt, die auf diese Seite warten, und eine Abbildung, auf die auf einer früheren Seite verwiesen wurde und die dann darunter passt, nimmt den Rest dieser Seite, auch wenn weniger als drei Textzeilen übrig blieben (eine Galerieseite: Kasten plus Abbildung, kein Text dazwischen). Ein Kasten mit `span: 'side'` gleitet nie: Er stapelt sich neben dem Text, gleich welche Platzierung er hat. Mit `columns` über 1 (im Stil oder als Attribut des Kastens, seit postext 1.18) nimmt ein Kasten mit `span: 'column'` so viele benachbarte Spalten ein: den Kopf einer Folge leerer Spalten, die auf gleicher Höhe beginnen, oder den Fuß der aktuellen Spalte und der leeren danach, wie in `:::callout{placement="top" columns="2"}`.
- `width: 'auto'` passt sich nur eng an den Titel an; Kindblöcke werden ignoriert.
- Ein in einem anderen Kasten verschachteltes `:::callout` ist ein eigener Kasten: Es wird mit seinem eigenen Stil (Hintergrund, Kontur, Radius, Innenabstand, Streifen, Titel, Symbol, Marke, Etikett, Typografie) auf die volle Innenbreite seines Elternkastens gesetzt und stapelt sich als ein Kindblock darin, wobei sein `marginTop` / `marginBottom` mit den Nachbarn zusammenfällt. Sein `span` und `placement` (aus der öffnenden Zeile oder dem Stil) werden ignoriert – ein verschachtelter Kasten fließt immer in seinem Elternkasten –, ebenso `floatBarrier` und `snapToGrid`. Kästen lassen sich beliebig tief verschachteln und können in einer Gruppe `:::columns` stehen (jeder ganz, in einer Spalte). Wird der Elternkasten geteilt, fällt der Schnitt vor oder nach einem verschachtelten Kasten oder in ihn, wenn der verschachtelte Stil das Teilen erlaubt; jedes Fragment zeichnet die Konturen der Kästen neu, die es durchschneidet, und ein verschachtelter Kasten, der aus dem vorigen Fragment fortgesetzt wird, verliert Titel und Symbol, wie eine Fortsetzung auf oberster Ebene.
- Eine Gruppe `:::columns{count=N}` … `:::` unter den Kindblöcken setzt diese Kindblöcke im Kasten in `N` gleich breiten Spalten im Abstand `columnGap`: Die Folge wird an den Block- oder Zeilengrenzen geschnitten, die die Spalten am besten ausgleichen (ein mittendrin geschnittener Absatz oder Listeneintrag geht am Kopf der nächsten Spalte ohne sein Aufzählungszeichen weiter), jede Spalte beginnt am Kopf der Gruppe, und die Gruppe ist so hoch wie ihre höchste Spalte; die Kindblöcke danach kehren zur vollen Breite zurück. Ein Kasten, der sich teilt (`keepTogether: false` oder höher als eine Spalte), schneidet auch innerhalb einer Gruppe, zwischen ihren Spalten: Eine fortlaufende Gruppe füllt ihre Spalten der Reihe nach und geht im nächsten Fragment weiter, eine parallele (`breaks`) geht Strang für Strang weiter (seit postext 1.25; siehe [Dokumentformat › `:::columns`](/de/docs/document-format-directives#columns)). Ein `gap` in der öffnenden Zeile ersetzt `columnGap` für diese Gruppe, und `rule` zieht eine Linie durch jeden Spaltenabstand. Verwenden Sie es für eine zweispaltige Zusammenfassung von Kernpunkten oder für nebeneinandergesetzte Tabellen eines breiten Kastens.
- Das sechste Attribut der öffnenden Zeile, `label`, erscheint auf dem Etikett des Stils (siehe `label` oben) – `:::callout{type="box" label="BOX 1-1" title="The octet rule"}`; hat der Stil kein `label`, wird das Attribut ignoriert.

Im VDT ist der Kasten ein Rahmenblock mit `type: 'callout'`, dessen Gestaltung (Hintergrund, Streifen, Symbol, Titel) in `designOverlay` liegt, gefolgt von seinen Kindblöcken in derselben Spalte; der Rahmenblock und jeder Kindblock haben die `containerId` des Kastens. Ein verschachtelter Kasten ist ein eigener Rahmenblock mit `type: 'callout'` unter den Kindblöcken, gefolgt von seinen Blöcken; sie behalten die `containerId` des äußersten Kastens (Platzierung und Ausgleich sehen weiterhin eine Einheit) und fügen `calloutPath` hinzu, die Container-IDs der umgebenden verschachtelten Kästen, der äußerste zuerst (die eigene ID eines verschachtelten Rahmenblocks ist der letzte Eintrag). Das getaggte PDF gibt jedem verschachtelten Kasten ein `Div` innerhalb des `Div` seines Elternkastens. Symbolbilder werden wie Ressourcenbilder aufgelöst: über das Bildregister des Canvas, die HTML-Option `resourceImageUrl` und den Anbieter `resourceBytes` des PDF.

```ts
const resolved = resolveCalloutStylesConfig(config.calloutStyles, resolvedBodyText, resolvedHeadings, resolvedUnorderedLists, config.locale);
// => every inherited field filled from the resolved sections; the optional
//    locale picks the language of the continuation strings

const minimal  = stripCalloutStylesDefaults(config.calloutStyles);
// => undefined for the built-in `note` default; static defaults dropped
```

Ein Beweis ist ein Stil mit einer nicht nummerierten Bezeichnung und einem Schlusszeichen:

```ts
calloutStyles: [
  { id: 'theorem', numbering: { label: 'Theorem' }, body: { italic: true } },
  { id: 'lemma', numbering: { label: 'Lemma', counter: 'theorem' }, body: { italic: true } },
  { id: 'definition', numbering: { label: 'Definition' } },
  { id: 'proof', backgroundEnabled: false, endMark: '□',
    numbering: { label: 'Proof', counter: false, bold: false, italic: true } },
]
```

In einem Buch, das Kapitel für Kapitel gesetzt wird, zählen die Zähler vom vorigen Kapitel aus weiter (`LayoutContinuation.statementCounters`, das `continuationAfter` füllt), und die Gliederung des Buchs gibt dem Anker jedes nummerierten Kastens seine Bezeichnung (`OutlineEntry.numberLabel`), sodass ein Verweis aus einem anderen Kapitel sie ausgibt.

### Typografie im Kasten

Ein Kasten setzt seinen Inhalt mit seiner eigenen Typografie `body` und `lists`; alles andere behält die Stile des Dokuments:

- **Absätze** übernehmen den `body` des Kastens: Schrift, Größe, Zeilenabstand, Farbe, Auszeichnungsfarben, Schriftstärken, `italic`, `smallCaps`, Ausrichtung, Silbentrennung, Einzug und Absatzabstand. Ein nicht gesetztes Feld erbt `bodyText`. Eine geerbte Auszeichnungsfarbe behält ihre Bindung an die Palette, sodass sich fetter und kursiver Text sowie Bezeichnungen von `:ref` in einem Kasten mit `colorPalette` ändern wie außerhalb. (Bis postext 1.4 blieb Fettes in einem Kasten `#295AA3`, gleich welche Hauptfarbe galt.)
- **Aufzählungen** übernehmen die `lists` des Kastens (Aufzählungszeichen, Farbe, Glyphengröße, -stärke und -schrift, Einzug, Abstand, Eintragsabstand, Listenabstände) über `unorderedLists`, und ihr Text ist der Text des Kastens. Ein `lists.bulletChar` oder `lists.color`, das von dem des Dokuments (`unorderedLists`) abweicht, ersetzt Aufzählungszeichen oder Farbe jeder Ebene; eines, das ihn wiederholt oder nicht gesetzt ist, lässt jeder Ebene ihren eigenen Wert (`unorderedLists.levels`), sodass verschachtelte Striche im Kasten erhalten bleiben.
- **Nummerierte Listen** übernehmen `lists.indent`, `gap` und `itemSpacing` sowie `lists.color`, sobald der Stil es setzt – auch wenn es die Farbe der Aufzählungszeichen des Dokuments ist; ein Stil, der es nicht setzt, behält die Nummern in `orderedLists.color`. (Bis postext 1.4 erreichte die Farbe die Nummern nur, wenn sie von `unorderedLists.color` abwich, sodass es nichts bewirkte, sie auf genau diese Farbe zu setzen.) Die Nummer selbst – Schrift, Größe und Trennzeichen – stammt aus dem globalen `orderedLists`, da `lists` nur Felder für Aufzählungszeichen hat: Gestalten Sie die Nummern eines Kastens dort.
- **`:::paragraphs` im Kasten** verwenden ihr Absatzformat, auch in verschachtelten Kästen. Die Felder, die das Format nicht setzt, erben den `bodyText` des Dokuments, nicht den `body` des Kastens (auch nicht dessen Kursive oder Kapitälchen).
- **Gruppen `:::columns`** haben keinen eigenen Stil: Jede Spalte teilt die Text- und Listentypografie des Kastens, und `columnGap` setzt den Abstand zwischen ihnen.
- **Zitatblöcke** übernehmen Schrift, Größe und Schriftstärken des Kastentexts (kursiv und grau, wie im Fließtext) sowie seine Kapitälchen. **Überschriften** behalten die Überschriftenstile, **abgesetzte Formeln** die Mathematik-Einstellungen.
- **Abbildungen und Tabellen** behalten die Legenden- und Tabellenstile des Dokuments, in der Innenbreite des Kastens; ihre normalen und fetten Schriftstärken folgen denen des `body` des Kastens.
- **Chips** behalten ihren Chip-Stil; eine Größe in `em` wird an der Schriftgröße des Kastentexts gemessen.
- **`:::space`** wird in Zeilen des Kastentexts gemessen (siehe [`:::space`](/de/docs/document-format-directives#space) dazu, wo es entfällt).
- **Ein verschachtelter Kasten** übernimmt seinen eigenen Stil vollständig; sein `span`, `placement`, `floatBarrier` und `snapToGrid` werden ignoriert.

**Hängende Anmerkungen.** Anmerkungen unter einer Tabelle, eine nummerierte Legende oder ein Quellenverzeichnis stellen ihr Zeichen vor den Text: das Zeichen an die Innenkante des Kastens, den Text und alle Folgezeilen etwas weiter eingerückt. `body.hangingIndent` (seit postext 1.71) setzt so jeden Absatz eines Kastens oder eines Rahmens mit diesem Stil:

- **Eine Länge** setzt jede Zeile außer der ersten in diesem Abstand zur Innenkante des Kastens, wie das `hangingIndent` eines Absatzformats (siehe [Absatzformate](/de/docs/configuration-styles#absatzformate)). Die erste Zeile beginnt an der Kante oder bei `body.firstLineIndent`, wenn der Stil diesen Wert selbst setzt; ein von `bodyText` geerbter Erstzeileneinzug entfällt.
- **`true`** liest `body.firstLineIndent` als Einzug jeder Zeile außer der ersten, wie `bodyText.hangingIndent` im Fließtext; `false` setzt den Kasten ohne hängenden Einzug in einem Buch, dessen Fließtext hängend eingezogen ist. Ohne Wert übernimmt der Kasten `bodyText.hangingIndent`.

Ein Tabulator an derselben Position führt den Text nach dem Zeichen an die Kante der Folgezeilen, wie breit das Zeichen auch ist:

```ts
calloutStyles: [{
  id: 'notes',
  padding: { top: { value: 0, unit: 'mm' }, right: { value: 0, unit: 'mm' }, bottom: { value: 0, unit: 'mm' }, left: { value: 0, unit: 'mm' } },
  body: {
    fontSize: { value: 7, unit: 'pt' },
    hangingIndent: { value: 4.5, unit: 'mm' },
    tabStops: [{ position: { value: 4.5, unit: 'mm' } }],
  },
}],
```

```markdown
:::callout{type="notes"}
\*	Die Preise enthalten die Lieferung innerhalb der Stadt.

\*\*	Mitglieder zahlen die Hälfte; der Nachlass ist nicht mit anderen Angeboten kombinierbar und gilt bis zum Ende der Saison.
:::
```

Jede Anmerkung ist ein eigener Absatz; zwischen Zeichen und Text steht ein Tabulatorzeichen oder `:tab`. Das Sternchen ist maskiert, weil `*` mit einem Tabulator am Zeilenanfang einen Listeneintrag eröffnet. Die Zeilen werden so gemessen, daher setzen Canvas, PDF, Display-Liste und EPUB (mit `padding-inline-start` und negativem `text-indent`) sie gleich, und ein Word-Export schreibt denselben hängenden Einzug. Listeneinträge behalten ihren eigenen Einzug (`lists.indent`, `lists.gap`), ein Absatz in einem `:::paragraphs`-Block den seines Stils. Ein negativer `firstLineIndent` zählt weiterhin als `0`: Die erste Zeile kann nicht im Innenabstand des Kastens beginnen. Ein Zitatblock im Kasten hängt mit dem Kasten, wenn `hangingIndent` `true` ist; bei einer Länge hängen nur die eigenen Absätze des Kastens.

### Vermerke an einem geteilten Kasten

Teilt sich ein Kasten über Spalten oder Seiten (`keepTogether: false` oder ein Kasten, der höher als eine Spalte ist), beginnt jeder Teil nach dem ersten ohne Titel und Symbol, und standardmäßig sagt nichts dem Leser, dass der Kasten weitergeht. Zwei Optionen fügen die Vermerke hinzu, die ein Buch oder ein Drehbuch verwendet:

- **`repeatTitle: true`** wiederholt den Titel am Kopf jeder Fortsetzung, gefolgt von `continuedSuffix` – standardmäßig „Key points (cont.)“. Die Wiederholung übernimmt den Titelstil, sodass sie mit `textTransform: 'uppercase'` das „HAMLET (CONT'D)“ eines Drehbuchs ergibt. Symbol und Etikett bleiben am ersten Teil.
- **`continuesMarkerEnabled: true`** setzt `continuesMarker` – „Continued“ oder „Continúa“ in einem spanischen Dokument – unter die letzte Zeile jedes weitergehenden Teils, innerhalb des Kastens, in Schrift und Größe des Kastentexts: kursiv, sofern `continuesMarkerItalic` nicht `false` ist, rechtsbündig, sofern `continuesMarkerAlign` nicht `'left'` oder `'center'` angibt. Der Vermerk nimmt Raum in dem Teil ein, den er abschließt, und der Schnitt wird so gewählt, dass er passt.

```ts
calloutStyles: [{
  id: 'speech',
  keepTogether: false,
  titleStyle: { textTransform: 'uppercase' },
  repeatTitle: true,
  continuedSuffix: "(CONT'D)",
  continuesMarkerEnabled: true,
  continuesMarker: '(MORE)',
  continuesMarkerAlign: 'center',
  continuesMarkerItalic: false,
}],
```

```md
:::callout{type="speech" title="Hamlet"}
A speech long enough to run over the foot of the page…
:::
```

Der Teil, der die Seite abschließt, endet mit „(MORE)“, und die nächste Seite beginnt mit „HAMLET (CONT'D)“. Beide gehören nicht zum Text, sondern zur Seitengestaltung: In einem barrierefreien PDF sind es Artefakte, und im HTML sind sie vor assistiven Technologien verborgen, sodass der Titel nur einmal vorgelesen wird. Im VDT sind es Textblöcke in `designOverlay` mit dem Flag `artifact: true`.

### Gestaltung im Kasten

`design` setzt die Elemente einer Überschriftengestaltung (Texte, Bilder, Linien, Rahmen; siehe [Seitenbreite und erweiterte Gestaltung](/de/docs/configuration-headings#seitenbreite-und-erweiterte-gestaltung)) in ein Band unter dem Titel des Kastens, über seine ganze Innenbreite. Der Inhalt des Kastens folgt dem Band, mit dem Abstand des Titels dazwischen. Ein Kasten, der sich über Spalten oder Seiten teilt, zeichnet das Band nur auf seinem ersten Teil. Seit postext 1.45.

Die Texte der Gestaltung lesen diese Platzhalter:

- `{titleText}`: der Titel, den der Kasten druckt, also das `title` der Einfassung oder sonst das des Stils.
- `{boxText}`: der Inhalt des Kastens als reiner Text, ein Absatz oder Listenpunkt pro Zeile. Leere werden ausgelassen.
- `{boxText.<n>}`: der `n`-te Absatz oder Listenpunkt, ab 1 gezählt; leer, wenn der Kasten weniger hat.
- `{attr.<key>}`: ein Attribut, das auf der Einfassung steht. Jeder Name ist möglich, neben denen, die die Einfassung selbst liest: `:::callout{type="card" kicker="Hinweis"}` gibt `{attr.kicker}` den Wert `Hinweis`. Ein fehlendes Attribut druckt nichts.
- die Platzhalter des Dokuments `{title}`, `{subtitle}`, `{author}` und `{publishDate}`.

Das `resourceId` eines Bilds nimmt dieselben Platzhalter an, sodass jeder Kasten eine eigene Ressource zeichnen kann. Nur eine Kastengestaltung liest `{boxText}`; eine Überschriftengestaltung druckt dafür nichts.

Mit `setsContent: true` dient ein einziger Stil allen Kästen derselben Form, jedem mit seinen eigenen Wörtern. In einem Schreibheft ist jede Übungszeile ein Kasten, dessen Inhalt das abzuschreibende Wort ist: Die Gestaltung druckt das Wort in einer Schulschrift und setzt es danach in Punkten zum Nachspuren (`dotted`), so oft die Zeile es fasst (`repeat`; siehe [Inline-Auszeichnungen und Konturen](/de/docs/configuration-headers-footers#inline-auszeichnungen-und-konturen)).

```ts
calloutStyles: [{
  id: 'practice',
  backgroundEnabled: false,
  border: { enabled: true, color: { hex: '#9aa6b2', model: 'hex' }, width: { value: 0.5, unit: 'pt' } },
  design: {
    setsContent: true,
    minHeight: { value: 16, unit: 'mm' },
    slot: { elements: [
      { kind: 'text', id: 'model', content: '{boxText}', fontFamily: 'Playwrite DE Grundschrift', fontSize: { value: 26, unit: 'pt' },
        placement: { anchor: { to: 'container', edge: 'top-left' } } },
      { kind: 'text', id: 'copies', content: '{boxText}', fontFamily: 'Playwrite DE Grundschrift', fontWeight: 100, fontSize: { value: 26, unit: 'pt' },
        dotted: {}, repeat: { gap: { value: 8, unit: 'mm' } },
        placement: { anchor: { to: '#model', edge: 'right-of' }, offset: { x: { value: 8, unit: 'mm' } } } },
    ] },
  },
}],
```

```md
:::callout{type="practice"}
Haus
:::

:::callout{type="practice"}
Mond
:::
```

Die erste Zeile druckt *Haus* und danach eine Reihe gepunkteter Kopien von *Haus*, die zweite ebenso mit *Mond*, und keines der beiden Wörter wird unter seinem Band noch einmal gesetzt. Wer das Wort im Markdown ändert, ändert die Vorlage und jede Kopie. Bleibt `setsContent` auf `false`, liest die Gestaltung `{boxText}` ebenso, und der Inhalt wird unter dem Band gesetzt.

Im VDT sind die Elemente des Bands Gestaltungsblöcke im `designOverlay` des Rahmens, neben dem Titel.
