# WebMCP

**Un agente nel tuo browser lavora sul libro aperto nella Sandbox: guarda le pagine, le cambia e le guarda di nuovo.**

La [Sandbox](/it/docs/sandbox) dà a un agente strumenti propri tramite
[WebMCP](https://webmachinelearning.github.io/webmcp/), una bozza di standard web
che permette a una pagina di passare strumenti al modello di IA con cui parla il browser. Grazie a questi,
l’agente non deve fare clic nell’interfaccia: legge il libro, chiede un’immagine
della pagina 12, imposta `bodyText.fontSize` a 10,5 pt, vede che il capitolo
è passato da 18 a 19 pagine e lo rimette com’era. Fa quello che tu fai a occhio, e
lo fa con il tuo libro, nel tuo browser.

Ci sono 53 strumenti il cui nome comincia con `sandbox_`, registrati mentre la
Sandbox è sullo schermo, e 8 strumenti del sito, `site_*`, su ogni pagina di
postext.dev. Questa pagina li raggruppa in base a ciò che chiederesti a un agente, e
per ciascuno riporta la chiamata.

## Collegare un agente

### In un browser con WebMCP

Gli strumenti vengono registrati con `document.modelContext` quando la Sandbox viene montata
e ritirati quando la lasci. Qualunque agente a cui il browser fornisce gli strumenti della pagina
li trova lì. Dal lato di Postext non c’è nulla da installare o configurare.

WebMCP è ancora una bozza. Chrome lo offre come origin trial e tramite il
flag `chrome://flags/#enable-webmcp-testing`. Gli strumenti seguono la pagina: nella
home page o nella documentazione l’agente ha gli strumenti `site_*`; quando la
Sandbox è sullo schermo, compaiono anche i 53 strumenti `sandbox_*`.

### In qualunque altro browser: `window.postextWebMcp`

La pagina mette gli stessi strumenti anche su `window.postextWebMcp`, con o senza
WebMCP. Qualunque agente che possa eseguire script nella pagina può usarli: uno
strumento di automazione come Puppeteer o Playwright, un server MCP che pilota il
browser ed esegue script (Chrome DevTools MCP), un’estensione del browser, oppure
tu, nella console per sviluppatori:

```js
// What is on this page
postextWebMcp.listTools().map((t) => t.name);

// Run one tool: the name, then an object with its arguments
await postextWebMcp.executeTool('sandbox_get_state', {});
await postextWebMcp.executeTool('sandbox_set_config', {
  changes: [{ path: 'bodyText.fontSize', value: '10.5pt' }],
});
```

Lo stesso da uno script Puppeteer, che salva una pagina come immagine:

```js
import fs from 'node:fs';
import puppeteer from 'puppeteer';

const browser = await puppeteer.launch();
const page = await browser.newPage();
await page.goto('https://postext.dev/en/sandbox');
await page.waitForFunction(() => window.postextWebMcp?.listTools().some((t) => t.name === 'sandbox_get_state'));
await page.waitForFunction(async () => (await window.postextWebMcp.executeTool('sandbox_get_state', {})).ready);

const result = await page.evaluate(() =>
  window.postextWebMcp.executeTool('sandbox_render_page', { chapter: 1, position: 1, width: 1200, format: 'png' }),
);
const picture = result.content.find((part) => part.type === 'image');
fs.writeFileSync('page-1.png', Buffer.from(picture.data, 'base64'));
await browser.close();
```

Un profilo di browser nuovo ha un proprio spazio di archiviazione, quindi parte dagli esempi,
non dai tuoi progetti. Per lavorare sui tuoi libri, usa il browser in cui li hai
creati.

### Com’è fatta ogni risposta

Uno strumento risponde con un oggetto JSON. `ok: true` e ciò che è stato chiesto, oppure `ok:
false` e un `error` che dice che cosa non andava e che cosa chiedere invece:

```json
{
  "ok": false,
  "error": "bodyText.fontSize is a length: give { \"value\": 11, \"unit\": \"pt\" }, a number (in pt) or a text such as \"11pt\". The units: cm, mm, in, pt, px, em, rem."
}
```

Gli argomenti vengono confrontati con lo schema dello strumento prima di qualsiasi esecuzione, quindi
un parametro scritto male viene rifiutato con l’elenco di quelli giusti. Uno strumento che
restituisce immagini (`sandbox_render_page`) risponde nella forma MCP, `{
content: [...] }`: una parte di testo con un JSON che descrive le pagine, poi una parte
immagine per pagina, codificata in base64.

## Il ciclo di lavoro

Ogni strumento che modifica il libro aspetta che l’impaginazione si aggiorni prima di
rispondere, e indica di quante pagine è risultato ogni capitolo. Così l’agente, quando guarda di nuovo, vede
sempre le pagine nuove, e l’agente può lavorare come fa un grafico:

1. **Vedere a che punto si è**: `sandbox_get_state` dà il libro, i suoi
   capitoli con le loro pagine, il capitolo e la pagina sullo schermo e il
   pannello aperto.
2. **Guardare**: `sandbox_render_page` disegna una pagina, `sandbox_inspect_pages`
   la descrive come dati, `sandbox_get_warnings` elenca ciò che hanno trovato le verifiche.
3. **Cambiare**: `sandbox_set_config`, `sandbox_edit_text`,
   `sandbox_save_resource`…
4. **Guardare di nuovo**, e tenere la modifica o annullarla.

Una pagina viene impaginata e disegnata per lo strumento qualunque sia il visualizzatore sullo schermo, così
l’agente può guardare il capitolo 7 mentre tu leggi il capitolo 2.

## Che cosa puoi chiedere, e come si fa

### Scoprire che cosa è aperto

```jsonc
// sandbox_get_state
{}
```

```json
{
  "ok": true,
  "ready": true,
  "book": { "kind": "sample", "id": "postext-guide", "name": "Postext guide" },
  "pages": 3,
  "chapters": [
    { "chapter": 1, "id": "a", "title": "Opening", "onScreen": true, "words": 1007, "pages": 2 },
    { "chapter": 2, "id": "b", "title": "Second", "words": 101, "pages": 1 }
  ],
  "view": { "viewer": "canvas", "panel": "none", "scope": "chapter", "chapter": 1 },
  "resources": 0,
  "warnings": 0
}
```

`ready: false` arriva con `waitingFor`, che dice perché (un libro ancora in caricamento).
`question` e `notice` compaiono quando la Sandbox aspetta una tua risposta; vedi
[Domande e notifiche](#domande-e-notifiche).

Ogni strumento che prevede un `chapter` accetta la posizione del capitolo nel libro (da 1),
il titolo o l’id. Se lo ometti, è il capitolo sullo schermo.

### Guardare una pagina

**Un’immagine.** «Mostrami l’apertura del capitolo 3», «com’è la doppia pagina
24-25?»:

```jsonc
// sandbox_render_page: a spread, 1200 px wide per page
{ "chapter": 3, "page": 24, "count": 2, "width": 1200 }
```

`page` è il numero stampato sulla pagina; `position` è il posto della pagina
tra le pagine del capitolo (da 1), per le pagine senza numero. Senza
nessuno dei due, è la pagina sullo schermo. `crop` ingrandisce una parte della pagina, in
frazioni della sua larghezza e altezza a partire dall’angolo in alto a sinistra, per giudicare da vicino caratteri e
spaziature:

```jsonc
// sandbox_render_page: the bottom right quarter, magnified
{ "chapter": 3, "page": 24, "crop": { "x": 0.5, "y": 0.5, "width": 0.5, "height": 0.5 }, "width": 1600 }
```

`printPreview: true` mostra la prova a video del profilo di stampa con le guide del rifilo,
dell’abbondanza e della zona di sicurezza; `trimmed: true` toglie il margine con i
segni di taglio.

**La stessa pagina come dati.** «Quali righe di questa pagina sono lasche?», «la
seconda colonna è piena?»:

```jsonc
// sandbox_inspect_pages: without a page, one line per page of the chapter
{ "chapter": 1 }
```

```json
{
  "chapter": 1, "title": "Opening", "chapterPages": 2, "converged": true,
  "pages": [
    { "position": 1, "label": "1", "role": "opener", "blank": false, "lines": 45, "figures": 0, "starts": "Opening" },
    { "position": 2, "label": "2", "role": "body", "blank": false, "lines": 37, "figures": 0, "starts": "decades. Print typography spent five centuries…" }
  ]
}
```

Con `page` o `position` elenca ogni blocco della pagina: il tipo, la colonna,
il testo, il numero di righe, le righe che finiscono con un trattino e le righe giustificate
lasche con la larghezza dei loro spazi, il riquadro che occupa sulla pagina; in più, quanto è piena ogni
colonna (`fill: 0.99`).

**Che cosa c’è in un punto.** Quando l’agente vede qualcosa in un’immagine, chiede
che cosa sia con le stesse frazioni che ha usato per il ritaglio:

```jsonc
// sandbox_inspect_point
{ "chapter": 3, "page": 24, "x": 0.71, "y": 0.42 }
```

La risposta dà il blocco, la riga e la colonna del sorgente Markdown in quel punto
(e la parola), un link e la pagina a cui porta, la cella di tabella o la didascalia di
una risorsa. Con `select: true` fa anche ciò che fa un clic: il
pannello Testo si apre con il cursore in quel punto (`word: true` seleziona la
parola, `to` seleziona fino a un secondo punto).

La risposta riporta anche `elements`: ciò che si trova in quel punto, dall’interno verso l’esterno, nell’ordine in cui un clic sulla pagina li seleziona e ogni clic successivo, o Esc, risale dall’uno all’altro (un glifo, il suo paragrafo, il riquadro che lo circonda, la cornice di una pagina composta, il suo gruppo, la pagina e il suo modello; oppure un elemento grafico e il suo slot). Per ciascuno sono indicati l’id stabile, l’origine (un tratto del Markdown, un percorso della configurazione, un attributo, una risorsa) e il nome nel percorso mostrato dalla Sandbox (`path`). Con `select: true`, `level` (`block`, `frame`, `template`, `design`…) ne sceglie uno come farebbe una persona: in modalità Contenuto ne seleziona il Markdown, in modalità Grafica ne apre la cornice, lo stile o il modello. `sandbox_get_state` riporta l’elemento scelto in `pageSelection`.

### Cambiare la grafica

Qualunque impostazione della [configurazione](/it/docs/configuration) si può cambiare tramite
il suo percorso. Un agente raramente conosce il percorso all’inizio, quindi lo cerca:

```jsonc
// sandbox_find_setting
{ "query": "orphans" }
```

```json
{
  "ok": true,
  "paths": [
    { "path": "bodyText.avoidOrphans", "effective": true },
    { "path": "bodyText.avoidOrphansInLists", "effective": true }
  ],
  "sections": [{ "section": "Body text", "group": "Typography", "settingsGroup": "text", "configKeys": ["bodyText"] }]
}
```

`sandbox_get_config` legge un’impostazione o un’intera sezione: `set` è ciò che il libro
memorizza, `effective` ciò che risulta una volta riempiti i valori predefiniti, e quindi mostra anche
tutte le impostazioni della sezione.

```jsonc
// sandbox_get_config
{ "path": "headings.levels[level=2]" }
```

Un percorso indica un elemento di un elenco tramite il campo che lo distingue:
`headings.levels[level=2].fontSize`, `header.elements[id=titleOdd].italic`,
`calloutStyles[id=note].title`. Poi `sandbox_set_config` cambia tutte le
impostazioni che vuoi in una sola chiamata:

```jsonc
// sandbox_set_config
{
  "changes": [
    { "path": "bodyText.fontSize", "value": "10.5pt" },
    { "path": "page.margins.top", "value": { "value": 2.5, "unit": "cm" } },
    { "path": "headings.levels[level=2].color", "value": "#1f3a5f" },
    { "path": "bodyText.avoidOrphans", "value": true }
  ]
}
```

Una lunghezza è `"2.5cm"`, `{ "value": 2.5, "unit": "cm" }` o un numero nell’unità
dell’impostazione; un colore è `"#1f3a5f"`. Un valore `null` rimuove l’impostazione, e torna in vigore
il valore della grafica. La risposta dice all’agente come giudicare la modifica e come
annullarla:

```json
{
  "ok": true,
  "changed": [
    {
      "path": "bodyText.fontSize",
      "from": null,
      "to": { "value": 10.5, "unit": "pt" },
      "effective": { "from": { "value": 10, "unit": "pt" }, "to": { "value": 10.5, "unit": "pt" } }
    }
  ],
  "followed": [
    { "path": "captionStyle.fontSize.value", "from": 10, "to": 10.5 },
    { "path": "tableStyle.bodyFontSize.value", "from": 10, "to": 10.5 }
  ],
  "pagesBefore": 212,
  "pagesAfter": 219,
  "chapters": [{ "chapter": 1, "title": "Opening", "pages": 19, "pagesBefore": 18 }]
}
```

`from` è il valore memorizzato prima (qui `null`: il libro non lo impostava), quindi
la stessa chiamata con `from` come valore annulla la modifica. `followed` elenca le
impostazioni che dipendono da questa e sono cambiate insieme a lei. Compare una `note` quando il
motore ha risolto qualcosa di diverso da ciò che era stato chiesto (un limite, un’impostazione che
dipende da un’altra), e un valore della forma sbagliata, o una configurazione che il
motore non riesce a risolvere, viene rifiutato senza cambiare nulla.

Ogni chiamata è un passo della cronologia della Sandbox: `sandbox_undo` la annulla, come Cmd/Ctrl+Z annulla una modifica fatta nel pannello Grafica.

Per modifiche più ampie, `patch` fonde un oggetto nella configurazione (gli oggetti
si fondono, `null` rimuove, gli elenchi si sostituiscono interi) e `replace` mette un’intera
configurazione al posto di quella del libro, per esempio un’esportazione `postext-config.json`.
`sandbox_reset_to_original` con `part: "config"` rimette la grafica da cui il
libro era partito.

Un libro in più lingue ha impostazioni generali che ogni edizione legge, e
ciascuna edizione conserva i campi che imposta da sé (vedi [Impostazioni generali e
impostazioni per lingua](/it/docs/configuration-bundles#impostazioni-generali-e-impostazioni-per-lingua)).
`sandbox_get_config` e `sandbox_set_config` accettano `scope`: `"all"` legge o
scrive le impostazioni generali, `"edition"` l’edizione a schermo. Se manca, vale
lo scope in cui si trova il pannello Grafica. In un libro così `sandbox_get_config`
risponde con `scope` e `ownFields`, i percorsi che l’edizione a schermo imposta
da sé:

```jsonc
// sandbox_set_config
{ "scope": "all", "changes": [{ "path": "bodyText.fontSize", "value": "10.5pt" }] }
```

```json
{ "ok": true, "scope": "all", "keptBy": ["ar"], "changed": [ … ] }
```

Una scrittura nelle impostazioni generali arriva a ogni edizione che non imposta
da sé quel campo. `keptBy` nomina le lingue che lo impostano, e che conservano il
loro valore. Per cambiare anche quelle, apri ciascuna (`sandbox_open_book` con
`language`) e scrivi il percorso con `scope: "edition"`: un valore uguale a quello
generale smette di essere proprio dell’edizione. In un libro in una sola lingua
`scope: "all"` viene rifiutato, perché tutte le sue impostazioni sono proprie.

Anche i font sono impostazioni: `sandbox_list_fonts` con `search: "Garamond"` trova
famiglie nel catalogo aperto, e basta scriverne il nome in un’impostazione `fontFamily`
per caricarla.

Gli stili di riquadro hanno una raccolta propria: `sandbox_frame_styles` elenca
ogni stile con i punti in cui il libro lo usa (cornici dei modelli, pagine
composte, riquadri `:::callout` per capitolo) e propone di unire gli stili quasi
identici, come fa **Grafica › Riquadri › Stili delle cornici**.
`sandbox_merge_styles` accetta `groups` (`{ keep, merge }`) o `all: true` e
riscrive ogni cornice e ogni blocco che usava uno stile unito. Con
`lookOnly: true` confronta anche gli stili i cui riquadri si trovano in punti diversi:
uno stile di questo tipo conserva allora solo la posizione ed estende lo stile
mantenuto (`extends`), così i suoi riquadri restano dove sono; la risposta lo elenca in
`keptForTheirPlace`. Con `keepPlaces: false` viene unito del tutto, e i suoi
riquadri si spostano.
La risposta riporta `undoSteps`: un passo per capitolo riscritto e uno per gli stili, che `sandbox_undo` annulla cominciando dagli stili.

Rinominare o togliere un elemento con nome cambia più della sua voce, perciò queste azioni hanno strumenti propri che lavorano come il pannello Design. `sandbox_rename_design_item` dà un altro id a uno stile, un aspetto, un modello di pagina, una cornice o un gruppo di un modello, oppure a uno stile di nuvoletta, un personaggio o uno stile di vignetta di un fumetto. Tutto ciò che nomina l'elemento lo segue: i blocchi `:::callout` e `::::page`, i nomi degli slot delle pagine, gli ancoraggi delle immagini e le righe `::label`, le tabelle e gli spartiti che usano uno stile, e il cast. `sandbox_remove_design_item` toglie un elemento come fa il pannello: gli stili basati su uno stile di riquadro tolto ne prendono l'aspetto, e le impostazioni che usavano un colore della tavolozza mantengono quel colore, senza più legame con la tavolozza. `sandbox_language_defaults` elenca i valori per cinese, giapponese o arabo di Design › Testo e li applica con `apply: true`. `sandbox_print_profile` carica o toglie il profilo ICC proprio della sezione Stampa. `sandbox_save_layout_as_template` trasforma una pagina composta già impaginata in un nuovo modello di pagina. Impostare `layout.bitmapResolution` a `"file"` legge anche la risoluzione salvata in ogni file d'immagine già presente.

### Modificare il testo

Il testo di ogni capitolo è Markdown con le estensioni di Postext (vedi
[Formato del documento](/it/docs/document-format)). L’agente lo legge con i numeri
di riga, trova un passo e sostituisce brani esatti:

```jsonc
// sandbox_read_text: lines 40 to 80 of chapter 2
{ "chapter": 2, "fromLine": 40, "toLine": 80 }
```

```jsonc
// sandbox_search_text: where a passage occurs, and on which page
{ "query": "baseline grid", "pages": true }
```

```jsonc
// sandbox_edit_text
{
  "chapter": 2,
  "edits": [
    { "find": "The last words of the opening.", "replace": "The closing words of the opening." },
    { "find": "colour", "replace": "color", "all": true }
  ]
}
```

Ogni `find` deve corrispondere esattamente al sorgente e comparire una sola volta, a meno che non sia
impostato `all`. O si applicano tutte le modifiche o nessuna: un passo che non c’è viene
rifiutato con il consiglio di rileggere il capitolo. L’intera chiamata è un solo passo
per `sandbox_undo_text`, che la annulla (`redo: true` la ripristina).
`sandbox_write_text` sostituisce un capitolo intero, da `markdown` o da un file `.md`.

Per mostrarti un punto del testo, `sandbox_select_text` apre il pannello Testo
con quel passo selezionato (per `text`, `line` o `offset`), come fa un clic su
un risultato del pannello Verifiche.

### Organizzare i capitoli

`sandbox_manage_chapters` aggiunge, rinomina, sposta, divide, unisce e mostra
i capitoli:

```jsonc
// add a chapter in third place
{ "action": "add", "title": "Epilogue", "markdown": "# Epilogue\n\nThe end.\n", "position": 3 }

// split a chapter where a passage starts
{ "action": "split", "chapter": "Opening", "before": "## Second part" }

// one chapter per level-1 heading
{ "action": "split_at_headings", "chapter": 1 }
```

`sandbox_remove_chapter` ne elimina uno, e l’operazione non si può annullare.

### Aggiungere immagini, tabelle, video e font

`sandbox_save_resource` aggiunge una risorsa o ne modifica una, come fa il pannello
Risorse. Un file arriva tramite `url` (un indirizzo `https:` che la pagina può scaricare, o un
URL `data:`) oppure come `base64`:

```jsonc
// a picture with its caption and alternative text
{
  "id": "harbour",
  "image": { "url": "https://example.org/harbour.jpg" },
  "caption": "The harbour at dawn",
  "altText": "Fishing boats moored at a stone quay, mist over the water",
  "placement": { "position": "top", "span": "page" }
}
```

```jsonc
// a table from rows of text; the first row is the header
{
  "id": "prices",
  "caption": "Prices in 1850",
  "table": { "rows": [["Item", "Price"], ["Bread", "2 d"], ["Ink", "6 d"]], "columnWidths": [2, 1] }
}
```

```jsonc
// a YouTube video: its poster, frame size and title are fetched
{ "id": "interview", "video": { "url": "https://www.youtube.com/watch?v=…" }, "caption": "The author at work" }
```

La risposta dà il record memorizzato e la riga che lo colloca,
`::resource{id="prices"}`, che l’agente poi scrive nel testo con
`sandbox_edit_text`. Con un `id` esistente, la chiamata cambia solo ciò che le passi:
una didascalia, le celle di una tabella, la collocazione, la zona sicura di un’immagine. `newId`
rinomina una risorsa e, per impostazione predefinita, ogni riferimento a essa nel libro.
`sandbox_list_resources` le elenca e, con un `id`, ne dà una per intero (le celle di una
tabella con la loro formattazione, il sorgente di un SVG).

Le `marks` di un’immagine contengono anche le ancore. In una mappa o in uno schema sono i punti in cui si collocano le righe `::label`: un `id`, `x` e `y` (frazioni dell’immagine intera) e i campi che assume un’etichetta posta lì (`style`, `align`, `verticalAlign`, `rotate`, `width`, `writingMode`). La risposta segnala uno stile di etichetta che manca nella grafica, e i nuovi segni di una risorsa sono un passo della cronologia (`sandbox_undo` risponde `kind: "resource"`). Su un SVG, `marks.svgSymbols` (`idPrefix`, `className`) aggiunge una zona da evitare sopra ogni elemento del disegno indicato, oltre alle zone fornite dalla chiamata o già presenti nell’immagine (da postext 1.43).

```jsonc
// due ancore di una mappa, con i loro stili di etichetta
{ "id": "map", "marks": { "anchors": [
  { "id": "albar", "x": 0.19, "y": 0.41, "style": "city", "verticalAlign": "bottom" },
  { "id": "senne", "x": 0.22, "y": 0.54, "style": "river", "rotate": 68 }
] } }
```

I font caricati nel libro passano da `sandbox_save_font`:

```json
{ "action": "add", "family": "My Serif", "weight": 700, "style": "italic", "file": { "url": "https://example.org/MySerif-BoldItalic.woff2" } }
```

### Verificare il libro

```jsonc
// sandbox_get_warnings: every chapter
{ "scope": "book" }
```

La risposta è ciò che dice il pannello Verifiche, per qualunque capitolo o per il libro intero,
indipendentemente da ciò che è sullo schermo: font e immagini mancanti, markup che il motore non è riuscito a
leggere, elementi grafici che non entrano, testo troppo tenue rispetto allo sfondo,
righe lasche, vedove, riquadri che debordano e il preflight di stampa. Ogni avviso
ha la sua categoria, il capitolo, la riga e gli offset, la pagina, e l’impostazione o la
risorsa a cui si riferisce:

```json
{
  "ok": true,
  "scope": "book",
  "total": 3,
  "byCategory": { "typesetting": 2, "design": 1 },
  "warnings": [
    {
      "kind": "headerFooterMetadataMissing",
      "category": "design",
      "title": "Placeholder metadata missing",
      "detail": "header · {title} — The metadata referenced by this placeholder is not set — it will render empty."
    }
  ]
}
```

Da un avviso l’agente può andare al punto a cui si riferisce (`sandbox_select_text` con
`offset` e `toOffset`, oppure `sandbox_go_to_page`), guardare la pagina e
cambiare il testo o l’impostazione. `category` restringe l’elenco; in un libro lungo
`scope: "book"` impagina ogni capitolo e richiede un po’ di tempo.

Un libro con più edizioni (il pacchetto di un esempio o un progetto importato da un pacchetto) ha i controlli delle pagine composte anche in ogni lingua: `sandbox_get_composed_checks` impagina ogni edizione ed elenca i controlli per lingua, capitolo, pagina e cornice, come fa il pannello Verifiche sotto *Pagine composte*; con `language` li limita a una sola lingua (da postext 1.40). `sandbox_get_warnings` continua a controllare un capitolo della lingua a schermo.

### Mostrare al lettore

Ciò che l’agente cambia, tu lo vedi. Per indicarti qualcosa:

```jsonc
// sandbox_set_view: the Canvas with facing pages and loose lines highlighted
{ "viewer": "canvas", "pages": "spread", "fit": "height", "guides": { "looseLines": true, "baselineGrid": true } }
```

```jsonc
// sandbox_go_to_page: where a figure is set
{ "anchor": "harbour" }
```

`sandbox_set_view` sceglie anche il visualizzatore (`canvas`, `pdf`, `folio`, `html`,
`epub`, `scorm`), la modalità Contenuto o Grafica (`mode`), il pannello laterale, capitolo o libro intero, lo zoom, il corpo del testo
per il lettore, l’anteprima di stampa e il gruppo del pannello Grafica, e nella scheda SCORM il
contenuto (`scormLayout`), la versione (`scormVersion`) e i capitoli e le
sezioni che il pacchetto prende (`scormPick`, id dai `contents` della scheda). `sandbox_go_to_page` sfoglia
le pagine per `step`, `page`, `position`, un passo di `text`, un `anchor` o una
voce dei `contents` di un EPUB. `sandbox_run_viewer` preme un pulsante della barra degli strumenti:
`regenerate` scrive di nuovo il PDF, l’EPUB o il pacchetto SCORM e lo aspetta, `print` apre la
finestra di stampa perché tu la confermi, `download` salva il PDF, l’EPUB o un nuovo pacchetto SCORM, e
`play_video` e `stop_video` avviano e fermano un video su una pagina.

### Tavole a fumetti

`sandbox_inspect_comic` dà le vignette, le linee di suddivisione e le nuvolette di una tavola
con le loro posizioni; `sandbox_edit_comic` esegue le modifiche che una persona farebbe
con il puntatore e le scrive nel sorgente:

```jsonc
// move a balloon's centre to a point of its panel's picture, in percent
{ "comic": 1, "action": "move_balloon", "balloon": 2, "at": { "x": 30, "y": 18 } }

// move the first split line to 45 % of its cell
{ "comic": 1, "action": "move_splitter", "splitter": 1, "start": 45 }
```

La risposta avvisa quando una nuvoletta finisce su un volto o esce dalla sua vignetta. Vedi
[Fumetti](/it/docs/comics) per il formato.

### Libri, file e Word

- **Aprire e conservare libri.** `sandbox_list_books` elenca gli esempi e i tuoi
  progetti; `sandbox_open_book` ne apre uno (`{ "kind": "sample", "id": "postext-guide",
  "language": "es" }`); `sandbox_save_book` con `action: "copy_current"` conserva
  il libro sullo schermo come tuo progetto, `new_blank` ne comincia uno vuoto.
  Su un progetto, `add_language` con `language` (`"fr"`, `"zh-Hant"`) copia
  la lingua sullo schermo in una nuova edizione in quella lingua e la apre, e
  `rename` con `thisLanguageOnly: true` dà il nome soltanto alla lingua sullo schermo;
  `set_cover` e `remove_cover` gli danno una copertina o gliela tolgono.
- **Esportare.** `sandbox_export` scrive `pdf`, `epub`, `postext`, `docx`,
  `markdown` o `config`. Per impostazione predefinita il browser scarica il file; con
  `deliver: "data"` un PDF o un EPUB torna all’agente codificato in base64:

  ```json
  { "format": "pdf", "scope": "book", "deliver": "data" }
  ```

- **Importare un file `.postext`** con `sandbox_import_book` (`inspect: true` dice
  quali lingue contiene senza importarlo).
- **Importare un manoscritto Word** con `sandbox_import_word`. Eseguilo prima con
  `dryRun: true`: non cambia nulla e risponde con il rapporto di qualità, ogni
  stile di Word con ciò che diventerebbe, e i capitoli e le risorse che
  creerebbe. Poi correggi la mappatura ed eseguilo davvero:

  ```json
  {
    "file": { "url": "https://example.org/manuscript.docx" },
    "destination": "book",
    "mapping": { "paragraphs": { "Epigraph": { "kind": "quote" }, "Chapter Title": { "kind": "chapter" } } },
    "saveTemplateAs": "My publisher"
  }
  ```

  Con `characterSpacing` (da postext 1.40; attivo per impostazione predefinita quando gli stili
  di Word hanno una spaziatura da riportare) la spaziatura tra le lettere degli stili
  Word in uso passa, in em, agli stili di paragrafo, agli stili di titolo, ai
  livelli di titolo e ai titoli dei riquadri del libro a cui sono assegnati, dove
  il libro non ne fissa nessuna. La prova a secco la elenca sotto
  `characterSpacing`.

  `sandbox_word_templates` elenca, legge, salva ed elimina le mappature
  salvate, che usa anche l’esportazione in Word.

### Domande e notifiche

Quando un link apre un libro di cui hai già una tua versione, la Sandbox
chiede se sostituire la tua copia, e `sandbox_get_state` lo segnala come
`question` con `ready: false`. `sandbox_answer` risponde: `replaceCopy:
false` tiene la tua, `true` la sostituisce con il libro pubblicato ed elimina
la tua copia. `dismissNotice: true` chiude il messaggio del pannello Libri.

## Tre sessioni dall’inizio alla fine

**«Ingrandisci un po’ il testo, ma tieni il libro sotto le 220 pagine.»**
`sandbox_get_state` (212 pagine) → `sandbox_set_config` con
`bodyText.fontSize` a `"10.5pt"` (219 pagine) → `sandbox_render_page` su una
pagina fitta per giudicarla → `sandbox_get_warnings` con `category:
"typesetting"` per le nuove vedove → se qualcosa è andato storto, di nuovo `sandbox_set_config`
con i valori `from` della prima risposta.

**«Correggi ciò che le verifiche hanno trovato nel capitolo 4.»** `sandbox_get_warnings` con
`chapter: 4` → per ogni avviso, `sandbox_read_text` intorno alla sua `line` e
`sandbox_render_page` della sua `page` → `sandbox_edit_text` o
`sandbox_set_config` → di nuovo `sandbox_get_warnings` finché non torna vuoto.
Una cornice di pagina composta il cui testo non entra arriva con le sue correzioni (`proposals`): `sandbox_apply_proposal` con il `frame` e il numero di una correzione la applica, reimpagina il capitolo e risponde `fits`.

**«Crea un libro da questo file Word e dammi il PDF.»** `sandbox_save_book`
con `action: "new_blank"` → `sandbox_import_word` con `dryRun: true` →
`mapping` corretta, poi l’importazione vera con `destination: "book"` →
`sandbox_get_warnings` con `scope: "book"` → `sandbox_export` con `format:
"pdf"` e `scope: "book"`.

## Che cosa richiede il tuo consenso

Sei strumenti fanno cose che non si possono annullare, e sono contrassegnati come operazioni con conseguenze
(`consequentialHint`), così il browser può chiederti conferma prima che vengano eseguiti:
`sandbox_remove_chapter`, `sandbox_delete_resource`, `sandbox_delete_book`,
`sandbox_reset_to_original`, `sandbox_import_word` (può sostituire l’intero
libro) e `sandbox_answer` (può eliminare la tua copia di un libro). Nel dubbio, chiedi all’agente
di esportare prima una copia `.postext`.

Gli strumenti che si limitano a leggere sono contrassegnati con `readOnlyHint`, e quelli la cui risposta contiene
testo non scritto dalla pagina (il testo stesso del libro, un file scaricato) con
`untrustedContentHint`, così il browser può evitare che quel testo venga preso per
istruzioni.

## Limiti

- **Tutto resta nel tuo browser.** Gli strumenti non raggiungono nulla che la Sandbox
  stessa non raggiunga: i tuoi libri sono nello spazio di archiviazione di questo browser, e un file indicato
  tramite `url` viene scaricato dalla pagina, quindi il suo server deve consentirlo (CORS). Un
  URL `data:` o `base64` funziona sempre.
- **Il lavoro lungo richiede tempo.** Uno strumento aspetta l’impaginazione prima di rispondere;
  `wait: false` risponde subito. Un PDF o un EPUB di un libro lungo richiede minuti.
- **Annulla**: `sandbox_undo` annulla l’ultima modifica, al testo o alla grafica, nell’ordine in cui sono state fatte, come Cmd/Ctrl+Z nella Sandbox: quanto scritto nel pannello Testo, le modifiche degli strumenti e quelle fatte sulle anteprime, le impostazioni cambiate con `sandbox_set_config` o nel pannello Grafica, le cornici trascinate. `redo: true` la ripristina. `sandbox_undo_text` annulla solo una modifica al testo, e lo dice quando l’ultima riguardava la grafica. I capitoli aggiunti, eliminati o spostati, le risorse e i font non sono nella cronologia; la cronologia si svuota quando apri un altro libro o ricarichi la pagina. `sandbox_get_state` dice che cosa annullerebbe ciascuno (`history`).
- **Il libro sullo schermo.** Gli strumenti lavorano sul libro aperto. Solo
  `sandbox_export` di un file `.postext`, `sandbox_save_book` con
  `duplicate`, `rename` o una copertina, `sandbox_delete_book` e
  `sandbox_reset_to_original` con `sample` raggiungono un altro libro
  senza aprirlo.

## Gli strumenti del sito

Su ogni pagina di postext.dev, Sandbox compresa:

- `site_get_context`: la pagina sullo schermo, la sua lingua e il tema, le
  sezioni e ogni pagina della documentazione.
- `site_search`: la documentazione e il Ricettario, per parole, nomi di impostazioni
  (`bodyText.avoidOrphans`) o direttive (`::resource`).
- `site_read_page`: una pagina del sito come Markdown, senza lasciare la pagina
  sullo schermo.
- `site_open_page`: mostra una pagina, con `#heading` per arrivare a una sezione.
- `site_list_recipes` e `site_open_recipe_in_sandbox`: trovano una ricetta del
  Ricettario e la aprono nella Sandbox come libro modificabile.
- `site_lookup_term`: un termine del glossario (vedova, crenatura, kinsoku…).
- `site_set_preferences`: la lingua e il tema del sito.

Un agente che parte dalla home page può quindi cercare nel Ricettario, aprire
una ricetta nella Sandbox e proseguire lì con gli strumenti `sandbox_*`.

## Tutti gli strumenti

Raggruppati come li registra la Sandbox. La descrizione completa e lo schema di
ciascuno arrivano con `postextWebMcp.listTools()`.

- **Che cosa è aperto**: `sandbox_get_state`.
- **Le pagine**: `sandbox_render_page`, `sandbox_inspect_pages`,
  `sandbox_inspect_point`.
- **Il testo**: `sandbox_read_text`, `sandbox_write_text`, `sandbox_edit_text`,
  `sandbox_undo_text`, `sandbox_select_text`, `sandbox_search_text`,
  `sandbox_manage_chapters`, `sandbox_remove_chapter`.
- **La grafica**: `sandbox_get_config`, `sandbox_set_config`,
  `sandbox_find_setting`, `sandbox_reset_to_original`,
  `sandbox_frame_styles`, `sandbox_merge_styles`.
- **Annullare**: `sandbox_undo`.
- **Come viene mostrato**: `sandbox_set_view`, `sandbox_go_to_page`,
  `sandbox_run_viewer`.
- **Risorse e font**: `sandbox_list_resources`, `sandbox_save_resource`,
  `sandbox_delete_resource`, `sandbox_list_fonts`, `sandbox_save_font`.
- **Fumetti**: `sandbox_inspect_comic`, `sandbox_edit_comic`.
- **Libri e file**: `sandbox_list_books`, `sandbox_open_book`,
  `sandbox_save_book`, `sandbox_delete_book`, `sandbox_import_book`,
  `sandbox_export`.
- **Word**: `sandbox_import_word`, `sandbox_word_templates`.
- **Domande**: `sandbox_answer`.
- **Le verifiche**: `sandbox_get_warnings`, `sandbox_get_composed_checks`, `sandbox_apply_proposal`.

## Quando incorpori la Sandbox

`<PostextSandbox>` registra gli strumenti mentre è montato; `webmcp={false}`
li esclude (vedi [Prop](/it/docs/sandbox-embedding#prop)). Una pagina host può aggiungere
strumenti propri tramite lo stesso modulo:

```ts
import { registerWebMcpTools } from 'postext-sandbox/webmcp';

const controller = new AbortController();
registerWebMcpTools([
  {
    name: 'shop_list_titles',
    description: 'The titles of this shop, with the id of the Postext project of each one.',
    inputSchema: { type: 'object', properties: {}, additionalProperties: false },
    annotations: { readOnlyHint: true },
    execute: async () => ({ titles: await fetchTitles() }),
  },
], controller.signal);
// controller.abort() takes them back
```

Vengono registrati con WebMCP dove il browser lo offre e sempre su
`window.postextWebMcp`, con gli argomenti confrontati con `inputSchema`.
