# Konfiguration: Anmerkungen und Verweise


## Fußnoten

Die Eigenschaft `footnotes` legt fest, wohin die mit `[^id]` zitierten Anmerkungen kommen, wie sie nummeriert werden und wie sie aussehen. Das Markup ist unter [Dokumentformat](/de/docs/document-format-notes-references#fußnoten) beschrieben.

```ts
interface FootnotesConfig {
  placement?: 'column' | 'chapterEnd' | 'spread'; // Foot of the citing column, after the chapter, or beside the text of a spread.
  numbering?: 'chapter' | 'document' | 'page' | 'column' | 'spread'; // Start again at each chapter, run on, or start again on each page / column / spread.
  numberFormat?: string;      // decimal, lower-roman, circled-decimal (①)…
  symbols?: string[];         // The note symbols of numberFormat: 'symbols'.
  markerPosition?: 'auto' | 'superscript' | 'inline' | 'side' | 'right'; // Raised, on the baseline, beside the word, or right of a vertical line.
  markerSize?: Dimension;     // Inline, side or right marker size; em is the text around it.
  markerTemplate?: string;    // How the number is written: '({n})' gives «(١)».
  noteNumberPosition?: 'auto' | 'superscript' | 'inline'; // The note's own number, raised or on the line.
  numberGap?: 'en' | 'em';    // Space after the note's own number.
  chapterEndAlign?: 'foot' | 'text';   // chapterEnd: notes at the column foot, or under the text.
  fontSize?: Dimension;       // Note size; em is the body size.
  lineHeight?: Dimension;     // Note leading; em is the note size.
  color?: ColorValue;         // Note colour; the body colour when unset.
  textAlign?: TextAlign;      // The body alignment when unset.
  wordBreak?: 'normal' | 'keep-all'; // The document's cjk.wordBreak when unset.
  hangingIndent?: Dimension;  // Indent of a note's turnover lines.
  spaceBetween?: Dimension;   // Space between two notes.
  spaceAbove?: Dimension;     // Space between the text and the rule; em is the body size.
  spaceBelowRule?: Dimension; // Space between the rule and the first note.
  separator?: {
    enabled?: boolean;        // Draw the rule.
    width?: number;           // Rule length, a fraction of the column width.
    lineWidth?: Dimension;    // Rule thickness.
    color?: ColorValue;       // The note colour when unset.
  };
}
```

```ts
  lineHeight: { value: 9.5, unit: 'pt' },

```

**Japanische Bücher.** Ein japanisches Dokument (`locale: 'ja'`, seit postext 1.16) gibt den Feldern, die es nicht setzt, die Werte aus JLReq §4.2. Ein Buch in vertikaler Schrift setzt seine Anmerkungen nach dem Kapitel (`placement: 'chapterEnd'`, 後注), kapitelweise nummeriert, mit den Zeichen `（{n}）` rechts der Zeile (`markerPosition: 'right'`, Ziffern aufrecht durch `cjk.uprightDigits`); ein Buch in horizontaler Schrift setzt sie an den Fuß der Seite, seitenweise nummeriert, mit hochgestellten Zeichen. Beide zeichnen die Linie mit einem Drittel der Satzbreite (`separator.width: 1/3`), und Anmerkungen nach dem Kapitel erhalten `numberGap: 'em'` und einen hängenden Einzug von zwei Geviert. Ein ausdrücklich gesetzter Wert hat Vorrang und wird beim Speichern beibehalten (`stripFootnotesDefaults` vergleicht mit den Standardwerten des jeweiligen Dokuments); chinesische, arabische und lateinische Dokumente werden wie bisher aufgelöst. `footnoteDocumentDefaults(locale, writingMode, placement?)` gibt diese Werte zurück. Setzen Sie ein Zeichen vor ein satzschließendes 。 (`先生[^1]。`): Es bleibt beim vorangehenden Zeichen, und 。 eröffnet nie eine Zeile. Siehe [Japanischer Satz › Anmerkungen](/de/docs/japanese-layout#anmerkungen).

So werden die Anmerkungen am Spaltenfuß gesetzt:

- **Anmerkung und Zitierstelle teilen sich eine Spalte.** Bevor das Layout eine Zeile platziert, addiert es die Höhe der Anmerkungen, die diese Zeile zum ersten Mal zitiert (und die Linie, bei der ersten Anmerkung der Spalte). Eine Zeile, deren Anmerkungen nicht darunter passen, wandert mit dem Rest ihres Absatzes in die nächste Spalte, nach den Regeln für Waisen und Witwen. Der Textbereich der Spalte verkleinert sich um die Höhe der Anmerkungen, sodass der Spaltenausgleich und der letzte Spaltenbereich eines Kapitels nur den Text zählen.
- **Mehrere Anmerkungen** in einer Spalte stapeln sich in der Reihenfolge der Zitierung unter einer Linie. Eine Anmerkung, die später erneut zitiert wird, behält ihre Nummer und wird nicht noch einmal gesetzt.
- **Gleitobjekte unten.** Eine Abbildung, die den Fuß einer Spalte einnimmt, nachdem deren Anmerkungen gesetzt wurden, kommt über sie; Anmerkungen, die nach der Abbildung gesetzt werden, kommen über die Abbildung.
- **Kästen.** Eine Anmerkung, die in einem Kasten zitiert wird (im Textfluss, gleitend oder fest platziert), kommt an den Fuß der Spalte, in der der Text nach dem Kasten weitergeht, meist dieselbe Spalte. Ein Kasten, der das Dokument abschließt, lässt seine Anmerkungen am Fuß der Spalte, in der der Text endete.
- **Grenzen.** Eine Anmerkung wird nie geteilt: Eine, die höher als eine Spalte ist, läuft über sie hinaus. Zeichen in Legenden, Tabellenzellen und Überschriften werden nicht ausgewertet (sie werden so ausgegeben, wie sie geschrieben sind).
- **Ausgabe.** Canvas, HTML und PDF zeichnen die Anmerkungen, die Zeichen (eine hochgestellte Nummer) und die Linie. Im PDF verlinkt jedes Zeichen auf seine Anmerkung, und ein getaggtes PDF legt jede Anmerkung als Element `Note` mit einer eindeutigen `/ID` an, die im `/IDTree` des Strukturbaums aufgeführt ist (PDF/UA-1). Die Anmerkungen sind `VDTBlock`s mit gesetztem `footnoteNote` in `page.floats`; die Linien liegen in `page.footnoteAreas`.
- **Warnungen.** `undefinedFootnote` (ein Zeichen ohne Definition: Die Nummer steht über einer leeren Anmerkung) und `unusedFootnote` (eine Definition, die kein Zeichen zitiert: Sie wird nicht gesetzt).

Resolver und Stripper arbeiten wie in den anderen Abschnitten:

```ts
import { DEFAULT_FOOTNOTES_CONFIG, resolveFootnotesConfig, stripFootnotesDefaults, footnoteDocumentDefaults } from 'postext';

resolveFootnotesConfig(config.footnotes, 'ja', 'vertical-rl'); // unset fields take the Japanese vertical defaults
```


## Zeilennummern

Die Eigenschaft `lineNumbers` setzt die Nummer jeder fünften (oder jeder n-ten) Zeile daneben auf den Rand, wie es kritische Ausgaben, Gedichtanthologien, Gesetzestexte und Schulausgaben tun. Sie zählt die Zeilen von Gedichten in `:::verse` oder jede Zeile des Texts. Standardmäßig ist sie ausgeschaltet. Jede Nummer wird auf die Grundlinie ihrer Zeile gesetzt, in einer eigenen Größe, und verschiebt nie eine Zeile: Die Seite wird genau so gesetzt, wie sie es ohne Nummern würde. Seit postext 1.23.

```ts
interface LineNumbersConfig {
  enabled?: boolean;        // Off by default.
  count?: 'verse' | 'all';  // The lines of poems, or every line of the text.
  interval?: number;        // Print the multiples of N.
  numberFirst?: boolean;    // Also print the first line after each restart.
  restart?: 'document' | 'chapter' | 'section' | 'page' | 'poem'; // Where the count starts again.
  startAt?: number;         // The number of the first line after a restart.
  position?: 'outer' | 'inner' | 'left' | 'right' | 'start' | 'end' | 'side';
  multiColumn?: 'each' | 'gutter' | 'outer-edges'; // Pages of two or more columns.
  gap?: Dimension;          // From the text to the number; em is the number's size.
  align?: 'auto' | 'left' | 'right';
  fontFamily?: string;      // The body family when unset.
  fontSize?: Dimension;     // em is the body size.
  fontWeight?: number;      // The body weight when unset.
  italic?: boolean;
  color?: ColorValue;       // The body colour when unset.
  format?: string;          // decimal, lower-roman, arabic-indic, 一…
}
```

Was gezählt wird und was nicht:

- **Nie gezählt** werden Überschriften, Legenden, Tabellen und Bilder, abgesetzte Formeln, Gestaltungstext (Kapitelauftakte, Kolumnentitel), Fußnoten und Anmerkungen am Kapitelende, das Inhaltsverzeichnis, die Einträge von Register und Literaturverzeichnis sowie Vakatseiten.
- **Kästen und Prosa.** Der Text eines Kastens wird nicht gezählt, und unter `count: 'verse'` auch keine Prosa, es sei denn, das Absatzformat, in dem sie gesetzt ist, gibt `lineNumbers: true` an; ein Format mit `lineNumbers: false` wird nie gezählt (siehe [Absatzformate](/de/docs/configuration-styles#absatzformate)).
- **Ein einzelnes Gedicht.** Die öffnende Zeile eines Gedichts nimmt `numbered=false` (seine Zeilen werden nicht gezählt), `lineStart=N` (seine erste Zeile ist N, und die Zählung beginnt dort neu) und `interval=N` an. `:::numbering{lines=N}` gibt der nächsten gezählten Zeile die Nummer N, wo immer sie steht. Siehe [Dokumentformat › `:::verse`](/de/docs/document-format-directives#verse) und [`:::numbering`](/de/docs/document-format-directives#numbering).

In einem Buch, das Kapitel für Kapitel gesetzt wird, führt `restart: 'document'` die Zählung über `continuation.lineNumber` von einem Kapitel ins nächste fort. `continuationAfter` zählt die Verse aus dem Text; mit `count: 'all'` hängt die Zählung vom Layout ab, deshalb gibt die Host-Anwendung das `lastLineNumber` aus dem Dokument des vorigen Kapitels weiter, wie es die Sandbox tut.

Mit `position: 'side'` teilen sich die Nummern die Seitenspalte mit seitlichen Kästen, seitlichen Legenden und seitlichen Abbildungen. Eine Nummer, die eines dieser Elemente überlappt, wird trotzdem gezeichnet, keines von beiden verschiebt sich, und der Build meldet eine Inhaltswarnung `lineNumberOverlap`, die auf die nummerierte Zeile zeigt.

**Ausgabe.** Canvas, PDF, HTML-Betrachter und EPUB mit festem Layout zeichnen die Nummern. In einem getaggten PDF sind sie Layout-Artefakte, und jede trägt ein leeres `/ActualText`, sodass kopierter oder extrahierter Text ohne sie von Zeile zu Zeile läuft. Die HTML-Ausgabe verbirgt sie vor assistiven Technologien (`aria-hidden`), vor der Auswahl und vor kopiertem Text. Das umfließende EPUB, dessen Zeilen das Lesesystem setzt, behält nur die Nummern von Versen: ein `pt-line-number`-Span (ebenfalls `aria-hidden`) im Anfangsrand der Strophe neben jeder Zeile, die im Druck eine Nummer trägt. Im VDT sind die Nummern ein Gestaltungsfeld jeder Seite (`page.lineNumbers`, ihre Textblöcke mit `artifact` gekennzeichnet) und eine Liste von Markierungen (`page.lineNumberMarks`: `number`, `label`, `columnIndex`, `blockId`, `lineIndex`); das Dokument verzeichnet `lastLineNumber`.

**Nicht unterstützt** werden Zeilennummern in vertikaler Schrift, ein Querverweis, der die Nummer einer Zeile ausgibt, Anmerkungen, die sich auf Zeilennummern beziehen, und Nummern für die Zeilen von Tabellenzellen, Legenden oder Codelistings.

In der Sandbox bilden diese Einstellungen den Abschnitt **Zeilennummern** im Bedienfeld Gestaltung. Resolver und Stripper arbeiten wie in den anderen Abschnitten; Schrift, Schriftstärke und Farbe kommen vom Fließtext:

```ts
import { DEFAULT_LINE_NUMBERS_CONFIG, resolveLineNumbersConfig, stripLineNumbersDefaults } from 'postext';

resolveLineNumbersConfig(config.lineNumbers, resolvedBodyText); // unset font, weight and colour follow the body
```


## Querverweise

Die Eigenschaft `crossRefs` legt die Wörter fest, die ein [Querverweis](/de/docs/document-format-notes-references#querverweise-und-verweisziele) um eine Nummer oder eine Seite herum ausgibt, sowie den Stil, den ein `:ref` ohne eigenen Stil erhält. Jede Vorlage enthält `{n}` an der Stelle der Nummer; eine Vorlage ohne `{n}` erhält die Nummer nach einem geschützten Leerzeichen (`"§"` ergibt *§ 3.2*). Eine nicht gesetzte Vorlage folgt der Sprache des Dokuments: *chapter / section / p.* im Englischen, *capítulo / sección / pág.* im Spanischen, `第{n}章` / `第{n}节` / `第{n}页` im Chinesischen, `第{n}章` / `{n}節` / `{n}ページ` im Japanischen, `الفصل {n}` / `القسم {n}` / `ص {n}` im Arabischen und entsprechend im Französischen, Deutschen, Italienischen, Portugiesischen, Katalanischen und Niederländischen.

```ts
interface CrossRefsConfig {
  chapter?: string;  // Words around a level-1 heading's number: "chapter {n}".
  section?: string;  // Around any other heading's number: "section {n}".
  page?: string;     // Around a page number: "p. {n}".
  defaultStyle?: 'default' | 'number' | 'title' | 'page'; // A :ref without style=.
  breakLabels?: boolean; // A label of words breaks at its spaces.
}
```

```ts
    entrySpacing?: Dimension;
```

## Links im Druck

Die Eigenschaft `links` legt fest, was die gedruckte Seite von der Adresse hinter einem Link `[Text](https://…)` zeigt. Der Link bleibt in jeder Ausgabe anklickbar, die ihm folgen kann (Canvas im Sandbox, PDF, HTML, EPUB, SCORM und Folio); auf Papier bliebe nur sein Text, und niemand wüsste, wohin er führt. Wie Links geschrieben werden, steht unter [Dokumentformat](/de/docs/document-format-notes-references#links-im-druck). Seit postext 1.65.

```ts
interface LinksConfig {
  print?: 'none' | 'inline' | 'notes'; // Nichts, die Adresse in Klammern oder eine Anmerkung.
  show?: 'url' | 'qr' | 'both';        // print: 'notes': was die Anmerkung druckt.
  urlDisplay?: 'full' | 'short';       // short: ohne https://, ohne führendes www. und abschließenden /.
  repeat?: 'every' | 'first';          // first: eine im Kapitel schon vermerkte Adresse nutzt diese Anmerkung.
  visibleUrls?: 'skip' | 'note';       // Ein Link, dessen Text seine eigene Adresse ist.
  qr?: {
    size?: Dimension;                  // Seitenlänge des Codes samt Ruhezone.
    errorCorrection?: 'L' | 'M' | 'Q' | 'H';
    quietZone?: number;                // Helle Module um den Code (0–8).
    color?: ColorValue;                // Ohne Wert die Farbe der Anmerkungen.
    side?: 'start' | 'end';            // Auf welcher Seite der Anmerkungszeilen der Code steht.
    gap?: Dimension;                   // Abstand zwischen Code und Zeilen; em ist der Schriftgrad der Anmerkung.
  };
}
```

Eine Druckausgabe, die mit Code und gekürzter Adresse ins Web verweist:

```ts
links: {
  print: 'notes',
  show: 'both',
  urlDisplay: 'short',
  repeat: 'first',
  qr: { size: { value: 18, unit: 'mm' } },
}
```

- **Welche Links.** Nur Adressen mit `http:` und `https:`. Ein `mailto:`, ein `tel:` und ein Link an eine Stelle im Buch werden gedruckt, wie sie sind. `<https://…>` und eine nackte Adresse liest Postext als gewöhnlichen Text, der schon auf der Seite steht; sie erhalten nichts.
- **Wo.** Absätze, Listenpunkte, Blockzitate und der Text von Kästen. Überschriften (ihr Text geht ins Inhaltsverzeichnis und in die Kolumnentitel) und Einträge des Literaturverzeichnisses (deren DOI und URL `citations.bibliography.doi` folgen) bleiben unverändert. Ein Link in einer Fußnote erhält seine Adresse in Klammern, gleich was `print` sagt, denn eine Anmerkung kann keine eigene Anmerkung tragen.
- **Eine Konfiguration pro Ausgabe.** Meist behält ein Verlag in der digitalen Ausgabe `print: 'none'` und setzt in der Konfiguration der Druckausgabe `print: 'notes'` mit `show: 'both'`; das Markdown bleibt dasselbe.
- **PDF.** Der Code wird als Vektorgrafik gezeichnet und ist ein Link auf die Adresse. In einem getaggten PDF ist er eine `Figure` in einem `Link`, mit der Adresse als Alternativtext.

Resolver und Stripper arbeiten wie in den anderen Abschnitten:

```ts
import { DEFAULT_LINKS_CONFIG, resolveLinksConfig, stripLinksDefaults } from 'postext';
```

## Inhaltsverzeichnis

Die Eigenschaft `toc` konfiguriert, was eine Direktive `:::toc` ausgibt (siehe [Dokumentformat](/de/docs/document-format-directives#toc)). Das Inhaltsverzeichnis wird aus der **Gliederung** des Dokuments zusammengestellt – jede Überschrift mit ihrer Nummer und ihrer Seitenbezeichnung, jeder `:::part` –, es folgt also den Kapiteln: Benennen Sie eines um, verschieben Sie es in einen anderen Teil, ändern Sie seine Autoren, und die Einträge ändern sich mit. Ein Eintrag besteht aus der Nummer der Überschrift in einer eigenen Spalte, dem Titel, Füllzeichen und der Seitenbezeichnung am rechten Rand, dann optional einer Untertitelzeile; ein Teil ist eine Zeile, die `parts.design` gestaltet.

```ts
const config: PostextConfig = {

    levels: [{ level: 1, fontWeight: 700, color: { hex: '#00507b', model: 'hex' }, numberWidth: { value: 7.4, unit: 'mm' } }],
    unnumbered: { color: { hex: '#000000', model: 'hex' } },
    pageNumber: { fontWeight: 400, width: { value: 8, unit: 'mm' } },
    leader: { char: '.', gap: { value: 1, unit: 'mm' } },
    subtitle: { enabled: true, attr: 'author', italic: true, fontSize: { value: 8.5, unit: 'pt' } },
    parts: {
      height: { value: 23, unit: 'pt' },
      marginTop: { value: 11.5, unit: 'pt' },
      design: { elements: [/* a band box, 'SECTION {number}', '{titleText}', '{pageNumber}' */] },
    },
  },
};
```

Die Seitenbezeichnungen sind diejenigen, die das Dokument ausgibt. `buildDocument()` setzt ein Dokument mit einem `:::toc` erneut mit den Bezeichnungen des vorigen Durchgangs, bis sie feststehen (höchstens drei zusätzliche Durchgänge); eine Host-Anwendung, die ein Buch Kapitel für Kapitel setzt, liefert stattdessen die Gliederung des ganzen Buchs als `PostextContent.outline`, zusammengestellt aus `contentOutline()` (Überschriften und Teile allein aus dem Text) und `outlineFromDoc()` (dieselben Einträge mit den Seitenbezeichnungen eines Layouts), und setzt das Kapitel mit dem Inhaltsverzeichnis erneut, sobald sich `outlineKey()` dieser Gliederung ändert. Jeder Überschrifteneintrag enthält die `number`, die das Inhaltsverzeichnis ausgibt, und bei einer nummerierten Überschrift ihren `counter`: den laufenden Zähler der Ebene nach einem etwaigen `startAt`, gleich was die Vorlage ausgibt – das, was eine Host-Anwendung in ihren eigenen Listen neben einem Kapitel anzeigt.

## Register

Die Eigenschaft `index` konfiguriert, was eine Direktive `:::index` ausgibt (siehe [Dokumentformat](/de/docs/document-format-notes-references#register)): die im Text mit `:index[…]` und `:index{term="…"}` markierten Begriffe, sortiert, nach Anfangsbuchstaben gruppiert (im Chinesischen nach Pinyin-Anlaut oder Strichzahl, im Japanischen nach Gojūon-Reihe, siehe `groupBy`), jeder mit den Seiten, auf die er fällt. Ein Eintrag besteht aus seinem Begriff, einem Trennzeichen und seinen Seitenzahlen; seine Untereinträge folgen, eine Einzugsstufe pro Ebene, und umbrochene Zeilen hängen um `turnoverIndent`, sodass sie nie mit einem Untereintrag fluchten.

```ts
const config: PostextConfig = {
  headingStyles: [
    // The index in two columns, under its own heading.
    { id: 'index', numbered: false, layout: { layoutType: 'double', gutterWidth: { value: 6, unit: 'mm' } } },
  ],
  index: {
    fontSize: { value: 8.5, unit: 'pt' },
    lineHeight: { value: 11, unit: 'pt' },
    rangeFormat: 'chicago',
    groups: { fontFamily: 'Source Sans 3', fontWeight: 700, color: { hex: '#8a1c1c', model: 'hex' } },
  },
};
```

Die Seitenzahlen kommen aus der Gliederung des Buchs, wie die des Inhaltsverzeichnisses: `computeOutline()` und `contentOutline()` führen die Registermarkierungen eines Texts als Einträge der Art `'indexMark'` auf (mit `indexMark.path`, `sort`, `see`, `seeAlso`, `main`, `range` und `index`), und `outlineFromDoc()` gibt jedem die Seite, auf der er steht und die der Build in `doc.indexMarks` verzeichnet (`{ sourceStart, pageIndex }` pro Markierung). `buildDocument()` setzt ein Dokument, das sein eigenes Register enthält, erneut, bis die Nummern feststehen; eine Host-Anwendung, die ein Buch Kapitel für Kapitel setzt, übergibt dem Kapitel mit `:::index` die Gliederung des ganzen Buchs als `PostextContent.outline`. `tocOutline()` und `indexOutline()` teilen eine Gliederung in das auf, was Inhaltsverzeichnis und Register lesen, sodass eine Host-Anwendung jedes Kapitel an den Teil binden kann, den es ausgibt: Die Sandbox setzt das Registerkapitel nur dann neu, wenn sich eine Markierung verschiebt, und das Kapitel mit dem Inhaltsverzeichnis nur, wenn sich eine Überschrift verschiebt. `contentOutline()` gibt außerdem an, ob ein Text ein Register enthält (`hasIndex`).
