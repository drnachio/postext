# 配置：字体、颜色与输出


## 单位与颜色

### 尺寸

Postext中所有物理量都用`Dimension`类型表示，即一个数值加一个单位：

```ts
interface Dimension {
  value: number;
  unit: DimensionUnit; // 'cm' | 'mm' | 'in' | 'pt' | 'px' | 'em' | 'rem'
}
```

**绝对单位**：`cm`、`mm`、`in`、`pt`、`px`，按配置的DPI换算成像素。在300 DPI下，`1 cm`约等于118 px。

**相对单位**：`em`、`rem`，随当前字号缩放。`em`相对于元素自身的字号，`rem`相对于正文字号。

### 颜色

颜色同时保存一个十六进制表示和一个目标颜色模型：

```ts
interface ColorValue {
  hex: string;         // '#ff0000'、'transparent' 等
  model: ColorModel;   // 'hex' | 'rgb' | 'cmyk' | 'hsl'
  cmyk?: CmykPercent;  // 以CMYK定义的颜色的准确印刷色数值。
  paletteId?: string;  // 它所跟随的colorPalette条目。
}
```

`model`字段指明预期的色彩空间。网页渲染通常用`'hex'`或`'rgb'`。印刷流程中，`'cmyk'`表明这个颜色是以CMYK定义的，`cmyk`保存它的数值：CMYK印刷渲染原样使用这些数值，`hex`是它们在屏幕上的呈现（见[以CMYK定义的颜色](#以cmyk定义的颜色)）。

Postext面向出版级输出，所以正文的默认颜色带有`model: 'cmyk'`（`#000000`）。标题、粗体、斜体和列表的颜色默认链接到调色板中的**主色**（`#295AA3`，`model: 'hex'`）。页面背景和界面叠加层（基线网格、裁切线、调试标记）默认为`model: 'hex'`。如果需要不同的导出语义，可以在任意字段上覆盖`color.model`。

### 透明度

颜色可以是半透明的。`hex`接受带alpha通道的写法：`#rgba`或`#rrggbbaa`。它也接受`rgb()` / `rgba()`颜色，逗号语法和空格语法都可以，alpha可以写成数字或百分比。`transparent`表示完全透明：

```ts
const config: PostextConfig = {
  header: {
    elements: [{
      kind: 'box',
      id: 'veil',
      placement: {
        anchor: { to: 'bleed', edge: 'top-left' },
        size: { width: 'fill', height: { value: 40, unit: 'mm' } },
      },
      style: { backgroundColor: { hex: '#ffffffb3', model: 'hex' } }, // 白色，不透明度70%
    }],
  },
  bodyText: { color: { hex: 'rgba(0, 0, 0, 0.85)', model: 'rgb' } },
};
```

三个后端的绘制结果相同。Canvas和HTML阅读器把这个值当作CSS颜色。PDF后端把颜色的不透明度设为常量alpha，即一个`ExtGState`，填充用`ca`，描边用`CA`。文字、线条、框、表格的填充和边框、行内标签、色块和公式都是如此。半透明颜色叠加在它之前绘制的内容之上。页眉或页脚中的框最后绘制，因此会遮在其下的文字上；章首页色带中的框最先绘制，因此会给文字下方的页面着色。强制把PDF转换到另一色彩空间时（`pdfGeneration.forceColorSpace`配合`colorSpace: 'cmyk'`或`'grayscale'`），颜色随之转换，alpha保持不变。在沙盒中，取色器的不透明度滑块以`#rrggbbaa`写入这些值，取色器也能读取其他写法。


## 自定义字体

Postext把每个`fontFamily`字符串**同时**与Google Fonts字体目录和文档的`customFonts`列表匹配。名称冲突时自定义字体优先：如果你声明了`customFonts: [{ name: 'Roboto', … }]`，Postext会使用你上传的文件，而不是Google Fonts的“Roboto”。Google Fonts没有的字体族，沙盒从Fontsource获取。通用名称（`serif`、`system-ui`）和操作系统自带的字体（Arial、Segoe UI、PingFang SC……）从不向Fontsource查询：这样的字体族用读者电脑上已有的字体排版，**字体**面板显示为*未找到*，PDF和SVG图片也没有它的文件可嵌入。书若用它排版，请把它作为自定义字体上传。

以下情况适合使用自定义字体：

- 文档需要品牌字体或授权字体，而Google Fonts上没有。
- 运行环境（离线、内网或注重隐私的环境）无法访问字体CDN，即jsDelivr（沙盒从这里获取Fontsource的文件）或Google Fonts。
- 字体文件必须保密，不能上传给第三方。

### 配置结构

```ts
type CustomFontFormat = 'woff2' | 'woff' | 'ttf' | 'otf';
type CustomFontStyle = 'normal' | 'italic';

interface CustomFontVariant {
  weight: number;           // CSS font-weight，100..900
  style: CustomFontStyle;
  fileId: string;           // 二进制文件在外部存储中的不透明id
  format: CustomFontFormat;
  fileName?: string;        // 上传时的原始文件名（可选，显示在界面中）
}

interface CustomFontFamily {
  name: string;             // 可用在任何能填Google Fonts字体族名的地方
  variants: CustomFontVariant[];
  redistributable?: boolean; // false：只在书里使用，不会被复制出去
  fallback?: string;        // 宽度相近的开放字体，用于没有文件的字形（自postext 1.42起）
}

interface PostextConfig {
  // ...
  customFonts?: CustomFontFamily[];
}
```

各个变体的二进制文件**不**嵌入配置本身。配置只保存`fileId`指针，字节数据存放在配置之外。在沙盒里，这指的是IndexedDB（浏览器里的键值存储，只供该文档使用）。把Postext嵌入其他宿主的集成方可以用任何方式解析`fileId`，例如服务器接口、service worker缓存等，只要字节数据在`buildDocument`运行前到达主线程即可。

### 在沙盒中管理自定义字体

从左侧活动栏打开**字体**面板（位于资源和版面设计之间）。其中的**本书使用的字体**列表列出版面设计用到的每个字体族，以及它的用途和来源：Google Fonts、Fontsource（Google Fonts没有的字体族）、你的文件，或者哪里都没有（*未找到*）。在**你的字体文件**下，对每个字体族：

1. **添加字体族**：新建一个空的字体族，可直接在原处重命名。
2. **上传变体**：选择字重（100–900）和样式（normal / italic），然后选择一个*或多个*`.woff2`、`.woff`、`.ttf`或`.otf`文件。每个文件成为一个独立变体，绑定到当前选中的（字重，样式）；上传的文件名会被记住并显示在该行，便于区分各个变体。之后随时可以用下拉菜单重新调整变体的字重或样式。
3. **允许变体重复**。如果两个文件落在同一个（字重，样式）位置，两者都会保留，并出现**字体变体重复**警告，提醒你为多出来的文件调整设置加以区分。
4. **删除变体**或**删除字体族**：从配置中移除该条目，*同时*删除IndexedDB中保存的字节数据。

字体族一经声明，所有字体选择器都会把它归入**自定义**组，排在Google Fonts列表上方。选中它，这个字体族就会写入你用它的每个字体族字段。

### 授权字体的替代字体

一本书可能用了所有者无权转给他人的字体。把这个字体族标为`redistributable: false`，`.postext`文件就不带它的文件。在`fallback`里写一个宽度相近的开放字体族，那么没有这些文件时打开这个文件，断行位置仍接近真实字体，不会因为备用字体更宽而在框里放不下。家族中没有文件的字重和样式，会改用`fallback`中字重和倾斜相同的字体排版，名称仍是授权字体的名称；预览、排版工作线程、PDF和命令行都是如此。有文件的家族照用自己的文件，只从`fallback`借自己没有文件的倾斜（例如斜体）；介于它自己各个文件之间的字重，照常像任何字体族那样选取。在字体面板里，名称填在**替代字体**一栏（在字体族内、文件上方）；留空则家族保持原样。这样排版的书，PDF嵌入的是开放字体，所以最终的PDF要用授权字体的文件来生成。自postext 1.42起。自postext 1.43起，授权字体不能去的地方，开放字体也能去：从沙盒或`postext`导出的EPUB或HTML，会以授权字体的名称带上替代字体，文字用这个家族排的SVG图片也一样；这样阅读系统排这本书时所用字体的宽度，与断行时依据的宽度一致。家族自己的文件始终不会离开这本书。没有`fallback`的家族，或替代字体没有文件的家族，仍像以前一样只写名称、不带文件；沙盒的EPUB标签页会列出改用替代字体排版的家族。

### 渲染行为

内部机制如下：

- `customFonts`变化时，每个已声明的字体族都会自动以`FontFace`条目注册到`document.fonts`上。这样HTML阅读器、Canvas视口（它通过`document.fonts`测量）以及任何直接引用它的CSS都能用上自定义字体，用户无需先打开字体选择器。
- 排版工作线程通过现有的字体数据传输通道接收同样的ArrayBuffer，因此测量（`buildFontString`、pretext）的方式与字体目录中的字体族相同。
- 修改或删除某个变体时，工作线程会丢弃该字体族的缓存字体，并在下次构建时重新注册，使预览与当前的变体集合保持同步。
- **PDF导出**：上传的二进制文件走同一条`PdfFontProvider`流程。`.woff2`文件会被解压；`.ttf`和`.otf`直接传入。`.woff`会被拒绝并给出明确的错误（pdf-lib无法嵌入原始WOFF，请改为上传`.woff2`/`.ttf`/`.otf`）。CFF风格的OpenType（带`OTTO`标识的`.otf`）**不做子集化**直接嵌入，因为pdf-lib的CFF子集化程序在`save()`时会遍历每个字形，对实际字体可能卡住好几分钟；跳过子集化，PDF会稍大一些，换来稳定的渲染时间。

### 缺失字体警告

沙盒的**检查**面板在其*字体*组中列出三种自定义字体特有的问题（都由同一个`debug.warnings.missingFont`开关控制，这个开关原本就管着通用的“未加载”警告）：

- **未知字体族**：某个`fontFamily`引用的名称在Google Fonts和Fontsource中都没有，也不是当前已声明的自定义字体族。当你删除一个仍被某个`fontFamily`字段引用的自定义字体族时，这条警告也会立刻出现，不必等DOM察觉。
- **缺少字体变体**：字体族存在，但书中用到的某种字重和样式没有上传文件，例如只有常规体的字体族却用于粗体标题。警告会列出缺少的组合。由该字体族的`fallback`提供的斜体不算缺少。
- **字体变体重复**：同一字体族中，两个或更多上传文件占用同一个（字重，样式）位置。渲染时只会用到其中一个文件；警告提醒你重新调整其余条目。

点击其中任何一条警告都会打开字体面板，方便你上传缺少的变体、重新添加字体族或区分重复的变体。

有了排版结果之后，面板还会列出引擎报告的**排版时使用了后备字体**（`fontFallback`）：页面测量时没有用上的字体，要么根本没有，要么是浏览器借同一字体族的另一个字重或倾斜画出来的。已经作为未知字体族或缺少变体列出的字体族不会重复列出。在第一次排版之前，由针对`document.fonts`的检查代替它。

面板还会列出**字符取自其他字体**（`glyphFallback`）：文本用某字体排、而该字体没有字形的字符，每个字体一条；检查能判断时，还会给出绘制它们的通用字体族（`serif`、`sans-serif`、`monospace`）。

## 数字样式

`figureStyle`通过字体的OpenType特性，让文本样式的字体使用某一种数字：正文用旧式数字，表格用等宽的等高数字。这个字段出现在`bodyText`、`paragraphStyles[]`、`headings`和`headings.levels[]`、`headingStyles[]`、`tableStyle`和`tableStyles[]`（表头单元格和表体单元格都适用）、`captionStyle`（标签和说明文字，也包括资源类型的`captionStyle`），以及设计中的文本元素（页眉、页码、章首页或篇页上的文字）。在沙盒中，它是版面设计面板里各个样式字体旁边的**数字样式**字段（正文为**正文 › 字体**）。

组合值同时决定字形和宽度。没有该特性的字体保留自身的数字，所以依赖它之前先确认字体有`onum`或`lnum`。宿主程序没有文件的字体族，例如只安装在读者系统上的字体（沙盒不会下载这类字体），不接受数字样式：其文字在该字体本身中保留字体自身的数字。用这个名称上传了文件的书则能得到这些数字。Google Fonts和Fontsource提供的切分文件常常去掉`onum`和`lnum`（Source Serif 4的latin文件只保留`pnum`和`tnum`）；用这样的文件时，要求这些特性的样式保留字体自身的数字。字体厂商发布的完整文件带有这些特性，上传它们即可得到旧式数字或等高数字。通用字体族（`serif`、`sans-serif`）不接受特性。列表之外的值会作为未知设置值报告（`unknownConfigValue`，见[配置警告](#配置警告)），并按未设置处理。

```ts
const config: PostextConfig = {
  bodyText: { fontFamily: 'EB Garamond', figureStyle: 'oldstyle' },
  tableStyle: { figureStyle: 'lining-tabular' },
  paragraphStyles: [{ id: 'timetable', figureStyle: 'lining-tabular' }],
  headings: { figureStyle: 'lining' },
};
```

正文的年份和页码用旧式数字排出，沿用正文字体族的题注和列表也是如此。所有表格的单元格和`timetable`样式的段落用等宽的等高数字对齐各位。各级标题都在标题的字体族中使用等高数字。

### 样式取用哪种数字

- 从另一个样式取用字体族的样式，也取用它的数字。段落样式、表格、题注、列表和标注框的正文在没有指定其他字体族时使用正文字体族，所以`bodyText.figureStyle`会作用到它们全部。
- 指定了自己的`fontFamily`的样式，使用该字体的默认数字，除非它也设置了`figureStyle`。
- 没有自己`figureStyle`的标题级别取用`headings.figureStyle`；级别指定了自己的`fontFamily`时也一样。标题样式的`figureStyle`作用于使用该样式的级别的字体族。
- 设计中的文本元素指定自己的字体族（默认为`'EB Garamond'`），所以正文的数字不会作用到页码：要与旧式数字的正文相配，就在元素上设置`figureStyle: 'oldstyle'`。
- `'default'`使用字体自身的数字，取消继承来的数字：`paragraphStyles: [{ id: 'plain', figureStyle: 'default' }]`为该样式去掉正文的旧式数字。

### 各种输出中的数字

文本按启用特性后的宽度测量，所以在Canvas预览、HTML、PDF和EPUB（固定版式与流式版式）中，各行在相同的宽度处断行。

- **Canvas预览和布局worker**：浏览器以带特性的字体族名称再次声明基础字体族的文件，并加上`FontFace`的`featureSettings`描述符。名称是字体族加上`@`和特性（`EB Garamond@onum`、`EB Garamond@lnum+tnum`），会出现在字体字符串和部分警告中。
- **HTML和EPUB**（固定版式与流式版式）：使用基础字体族，并加上`font-variant-numeric`（`oldstyle-nums`、`lining-nums tabular-nums`）。
- **PDF**：嵌入基础字体族的文件，并启用特性排版文本。
- **命令行**：`postext`绘制所用的Canvas，即Skia，不应用特性。因此命令行注册一份字体副本，其`cmap`把特性替换的每个字符（数字）映射到特性选择的字形。只采用单一替换；通过上下文替换得到数字的字体，在那里保留自身的数字。

## 调色板

`PostextConfig`上的`colorPalette`属性让你定义一组可复用的命名颜色，并在配置中任何`ColorValue`里引用它们。它相当于Postext中的CSS自定义属性，或InDesign的色板面板：改一次调色板条目，所有指向它的颜色都会在整个文档中随之更新。

```ts
interface ColorPaletteEntry {
  id: string;       // 稳定的标识符，由ColorValue.paletteId引用
  name: string;     // 在沙盒界面中显示的名称
  value: ColorValue;
}
```

### 默认调色板

Postext自带一个只有一个条目的默认调色板，名为**主色**（`id: 'main-color'`，十六进制值`#295AA3`）。多项默认值，包括标题颜色、正文粗体/斜体颜色、`:ref`颜色、项目符号和编号的颜色，都通过`paletteId: 'main-color'`引用这个条目，所以改动这一个色板，文档中所有用到它的地方都会重新着色。

可以通过三个导出项查看、复制默认调色板，或与之比较：

```ts
import {
  DEFAULT_COLOR_PALETTE,
  cloneDefaultColorPalette,
  isDefaultColorPalette,
} from 'postext';

// 内置调色板的只读快照。
DEFAULT_COLOR_PALETTE;
// => [{ id: 'main-color', name: 'Main Color', value: { hex: '#295AA3', model: 'hex' } }]

// 独立副本：修改这个，不要修改DEFAULT_COLOR_PALETTE。
const palette = cloneDefaultColorPalette();

// 检测用户是否改动过调色板。
isDefaultColorPalette(palette); // true
```

调色板位于配置的顶层：

```ts
const config: PostextConfig = {
  colorPalette: [
    { id: 'ink',    name: 'Ink',    value: { hex: '#0a0a0a', model: 'cmyk' } },
    { id: 'accent', name: 'Accent', value: { hex: '#b8860b', model: 'hex' } },
  ],
  bodyText: { color: { hex: '#000000', model: 'cmyk', paletteId: 'ink' } },
  headings: { color: { hex: '#000000', model: 'hex', paletteId: 'accent' } },
};
```

### 引用调色板条目

配置中的任何`ColorValue`都可以带一个可选的`paletteId`字段，指向`colorPalette`中的某个条目：页面背景、正文颜色（包括`:ref`颜色）、标题颜色、栏间线、列表颜色，表、题注、行内标签和标注框的颜色（框、色条、图标、标记、页签、标题、正文），裁切线和基线网格的颜色，调试标记，以及版面设计中的所有颜色：书眉、标题的章首页设计和栏内设计、标题样式的版面设计和书眉、篇名页以及目录中的篇条目（文字、线条、框的填充和边框、轮廓、首字下沉）。存在`paletteId`时，调色板条目的`hex` / `model`优先于一起保存的备用`hex` / `model`。只有在调色板缺失、为空或不含该id时才会使用内联的备用值；如果配置要交给不理解调色板的工具读取，这一点很有用。

**postext 1.5中的变更**。在postext 1.4及以前，调色板只作用于一份固定的设置清单。其余设置，即版面设计的颜色（书眉、章首页、标题样式、篇、目录条目）、`bodyText.referenceColor`、标注框页签的颜色以及标注框正文的粗体/斜体颜色，都沿用与`paletteId`一起保存的`hex`。保存的值与调色板条目不同的文档（凡是在条目改动后又在沙盒中编辑过的文档，以及主色不是`#295AA3`时的所有`:ref`），现在会照链接所指，印出调色板中的颜色。要让某个颜色保持原样，删除它的`paletteId`。

### 调色板如何生效

`buildDocument`在两处应用调色板，这样无论是你明确写出的覆盖值，还是之后才填入的默认值，引用的颜色都能生效：

1. `applyPaletteToConfig(config)`：解析原始用户配置中每个带`paletteId`的`ColorValue`。想查看引擎实际看到的配置时可以用它。
2. `applyPaletteToResolvedConfig(resolved, palette)`：在默认值解析*之后*运行，把链接到调色板的默认值（标题颜色、正文粗体/斜体颜色、`:ref`颜色、列表颜色、默认版面设计的颜色）改写为当前调色板的值。

两者都会遍历整个配置，不会遗漏任何链接到调色板的颜色。文本流中的大多数颜色（正文、标题、列表、表、题注、行内标签，以及标注框的框、标题和正文）输出为普通值。其余颜色，即版面设计的颜色、`:ref`颜色和标注框页签，取调色板的`hex` / `model`，并**保留各自的`paletteId`**。篇的`palette`属性和标题样式的`palette`正是通过这个链接在各自的页面上覆盖颜色（见[篇](/zh/docs/configuration-styles#篇)），所以必须保留它。`htmlViewer.overrides`保持原样：HTML阅读器先合并它，它带的调色板随后会作用于所有内容，版面设计也包括在内。

你很少需要自己调用这两个函数，但它们都已导出，便于查看或复用：

```ts
import {
  applyPaletteToConfig,
  applyPaletteToResolvedConfig,
  resolveColorValue,
} from 'postext';

const flat = applyPaletteToConfig(config);
// 原始配置中每个带paletteId的ColorValue现在都带有
// 调色板条目的hex/model（版面设计的颜色保留其paletteId）。

// `applyPaletteToResolvedConfig`通常由buildDocument处理；如果你自己构建
// ResolvedConfig并希望应用调色板，可以直接调用它。
```

`resolveColorValue(value, palette, fallback)`是处理单个值的版本，适合以命令式方式组装配置、需要逐个解析颜色的场合。

### 编辑调色板

如果某个颜色的`paletteId`找不到对应条目，就会印出它保存的`hex` / `model`，而这个值可能比条目后来赋予它的颜色更旧。因此，删除条目之前，应先把链接到它的每个`ColorValue`改写为普通颜色，填入该条目的当前值。沙盒的*调色板*部分（**版面设计 › 颜色**）在你删除条目时会自动这样做，无论该颜色位于何处（包括版面设计和标注框页签），并在确认对话框中列出所有用到该条目的设置：按名称，或按它在配置中的路径（`header.elements[2].color`）。

## Canvas查看器

`canvasViewer`属性设置沙盒Canvas标签页中各页之间的间距（自postext 1.43起）。它属于查看器，而不属于书：数值是屏幕像素，与缩放无关；修改它只会移动屏幕上的页面，不会重新排版，所以分页、已保存的版面和PDF都保持原样。PDF、HTML阅读器和其他输出都会忽略它。图片横跨左右两页的书应设置`pageGap: 0`。

## PDF生成（配置）

`pdfGeneration`属性控制PDF后端如何输出最终文档。这些设置由`postext-pdf`包在导出时使用；Canvas和HTML阅读器会忽略它们。

`buildDocument`把它们以`doc.config.pdfGeneration`的形式放进VDT；`renderToPdf`对每项设置，从下列来源中第一个给出该设置的地方取值：

1. 它自己的选项（`outlines`、`accessible`、`colorSpace`）；
2. 它渲染的第一个文档的`pdfGeneration`（对于一本书，第一章的设置作用于整个文件）；
3. 默认值：开启书签和标签，RGB颜色。

所以`renderToPdf(doc, { fontProvider })`遵循配置，而传给`renderToPdf`的选项只在该项设置上优先。`forceColorSpace`和`colorSpace`合起来对应`colorSpace`选项：`forceColorSpace`开启时采用配置中的`colorSpace`，关闭时PDF为RGB。早期版本的`postext-pdf`只读取选项；现在，设置了`pdfGeneration`的配置会改变不传选项的调用方所生成的PDF。

```ts
type PdfColorSpace = 'rgb' | 'cmyk' | 'grayscale';

interface PdfGenerationConfig {
  outlines?: boolean;          // 根据标题树生成PDF书签。
  forceColorSpace?: boolean;   // 把所有颜色转换为`colorSpace`。
  colorSpace?: PdfColorSpace;  // `forceColorSpace`为true时使用的目标色彩空间。
  accessible?: boolean;        // 带标签、面向PDF/UA的输出（结构树、替代文字、语言）。
}
```

## 印刷输出（配置）

`print`属性规定一本书怎样付印：文件的PDF/X标准、CMYK分色所用的输出特性文件、黑色怎样印刷，以及印前检查的阈值。排版不读取它，所以改动它不会让任何一行移动。读取它的有三处：写出文件时的`postext-pdf`，检查排好的文档时的`preflightDocument`，以及Canvas和书页视图的印刷预览。

}

### PDF/X-1a与PDF/X-4

两种标准都会写出：

- 输出意图（`GTS_PDFX`），写明印刷条件并嵌入目标特性文件；
- Info字典中的标识（`GTS_PDFXVersion`、`/Trapped /False`、标题和日期）和XMP元数据中的标识（`pdfxid:GTSPDFXVersion`、文档id和版本id）；文件带标签时，与PDF/UA标识合并；
- 每一页的TrimBox和BleedBox（没有裁切线时就是整个页面）；
- 文件尾的`/ID`；
- 经特性文件转换为DeviceCMYK（或灰度）的所有颜色，以及用套准色绘制的裁切线；
- 不含链接注释：交付印刷的文件在出血框内不带任何注释，所以屏幕PDF中的链接被略去（书签保留）。

PDF/X-1a:2003是不带对象流的PDF 1.4，不允许透明：半透明的颜色换算成它印在纸上的颜色，图片的alpha拼合到白色上，调试用的页面负片被略去（并给出`pageNegativeIgnored`警告）。PDF/X-4是PDF 1.6：保留透明，每页带一个在CMYK中混合的透明组，因`convertImages: false`而保留的RGB图片通过`/DefaultRGB`标为sRGB。

PDF印刷母版（`svg.pdfFileId`）原样嵌入，所以它的颜色、字体和透明都是它自己的；印前检查会报告它带进来的内容。

`preflightDocument(doc, options)`对排好的文档运行这些检查，返回一个问题列表。每个问题带有`kind`、`severity`（`'critical'`、`'warning'`或`'info'`）、全书范围的页序`pageIndex`、出问题的`rect`（页面px），以及元素有源码范围时的源码范围。`kind`有`lowImageResolution`、`declaredPixelsMismatch`、`rgbImage`、`thinRule`、`smallProcessText`、`inkLimit`、`safeZone`和`nearTrim`。没有`transform`时，中性色算一种墨，其他颜色算三种，也不检查总墨量；给出`transform`时，墨数和总墨量都是准确的。图片的分辨率按资源声明的像素计算；`imageSize(fileId)`给出文件本身的像素时（对字节调用`bitmapInfo`，或取自解码后的图像），则按文件的像素计算：声明与文件相差超过一个像素时，报告一次`declaredPixelsMismatch`；如果声明的像素多于文件实有的像素，它的级别为警告。`placedImageResolutions(doc, { resources, imageSize })`列出每张放置的位图及其有效ppi，不论印前检查是否开启。图中的标注在`smallProcessText`、`inkLimit`和`safeZone`中按文字计算。

```ts
import { bitmapInfo, outputTransform, parseIccProfile, preflightDocument, resolvePrintConfig } from 'postext';
import { inspectPrintMaster } from 'postext-pdf';

const print = resolvePrintConfig(config.print);
const transform = outputTransform(parseIccProfile(fogra51Bytes), { intent: print.renderingIntent });
const issues = preflightDocument(doc, {
  print,
  transform,
  resources,                                    // 位图的像素尺寸
  imageSize: (fileId) => bitmapInfo(bytesOf(fileId)),  // 文件的实际像素
  imageColor: (fileId) => colourOf(fileId),     // 'rgb' | 'cmyk' | 'gray'，取自文件
});
if (issues.some((i) => i.severity === 'critical')) process.exit(1);

const master = await inspectPrintMaster(masterBytes);
// => { nonEmbeddedFonts: ['Helvetica'], rgb: true, transparency: false }
```

### 印刷预览

Canvas页面可以按印出来的样子绘制。`createPrintPreview(transform, print, { paper, dpi, grayscale })`为一套设置构建软打样：每个像素都经特性文件分色（中性色只用K，与PDF相同），再显示回屏幕上；`paper`为true时，显示在纸张自身的白色上；大到足以用复合黑的黑色区域显示为复合黑。设置`grayscale`时，打样的是灰度印刷：强制为灰度的PDF把每种颜色的明度只用黑墨印出，不用复合黑。把它作为`printPreview`交给`renderPageToCanvas`。作为工作视图而不是打样时，`guides`加上成品线、出血线和安全区线，`marksFor`勾出页面上的区域（印前检查给出的`rect`）；沙盒两者都不用，因此它的预览只显示印出来的内容。`postext-folio`接受同一个对象作为`printPreview`；`paper: true`时，请同时给书设置中性的纸色（`folio.paper.shade`），否则纸张会着两次色。

```ts
import { createPrintPreview, renderPageToCanvas } from 'postext';

const preview = createPrintPreview(transform, print, { paper: true, dpi: doc.config.page.dpi });
renderPageToCanvas(page, doc, canvas, {
  printPreview: { ...preview, guides: { safeZonePx: 59 }, marksFor: () => issues.map((i) => i.rect!).filter(Boolean) },
});
```

### 色彩引擎

postext使用的色彩管理也已导出，可供你自己的工具使用。它用纯TypeScript读取ICC v2和v4特性文件（矩阵/TRC，以及`mft1`、`mft2`、`mAB`、`mBA`查找表），不用WebAssembly。

- `parseIccProfile(bytes)`读取特性文件；`deviceChannels(profile)`给出它的通道数。
- `outputTransform(profile, { intent, blackPointCompensation, preserveNeutrals })`返回`fromRgb(r, g, b)`（sRGB 0..1 → CMYK 0..1）、`toLab(cmyk, paper?)`和`proof(cmyk, paper?)`（CMYK → 屏幕sRGB）。
- `cmykToLab`、`labToCmyk`、`srgbToLab`、`labToSrgb`、`deltaE`和`totalAreaCoverage`是单项转换；`buildRgbLut` / `sampleRgbLut`生成和读取用于像素处理的密集查找表。
- `OUTPUT_PROFILES`、`outputProfileInfo(id)`和`loadOutputProfile(id, baseUrl?)`提供特性文件目录；`srgbProfileBytes()`写出PDF/X-4标记RGB时所用的sRGB特性文件；`authoredCmykColors(config)`列出配置中以CMYK定义的颜色。

解析函数和精简函数与其他部分一致：`resolvePrintConfig`、`stripPrintDefaults`和`profileInkLimit(config)`（配置所指特性文件的上限，不计`inkLimit`覆盖），以及`DEFAULT_PRINT_CONFIG`、`DEFAULT_PRINT_BLACK_CONFIG`、`DEFAULT_PRINT_PREFLIGHT_CONFIG`和`DEFAULT_RICH_BLACK`。

### 接受的配色

移植会保留原书的色板，其中有些配色低于阈值：框内文字后面的浅色底，书眉上的品牌色。`allow`可以接受它们，而不必关闭检查（自 postext 1.52 起）。每一项写出文字颜色`fg`和底色`bg`（十六进制，按配置中的写法或实际绘制的颜色），或者一个`style`：框样式（`calloutStyles`，或组版页面中版框的`style`）、段落样式、标题样式、行内标签样式或图注标签样式的 id。一项中写出的每个字段都必须吻合，所以`{ style: 'note', fg: '#7a8a99' }`只在`note`框内接受这种灰色。三者都没写的项不匹配任何文字。

```ts
contrast: {
  allow: [
    { fg: '#b7820f', bg: '#ffffff', reason: '出版社书眉用的赭色' },
    { style: 'margin-note', reason: '原书的边注用浅灰色排' },
  ],
}
```

被接受的配色仍会报告：与之匹配的每条结果都带有`accepted`（该项的`reason`，以及它的`fg`、`bg`和`style`），被接受的结果排在其他结果之后。Sandbox 在“检查”中把它们列在“已接受的对比度配色”下，附上理由，但不计数；`postext check`把它们作为提示输出，`--strict`不会因此失败。在该项所指范围之外使用相同颜色的文字仍是警告。

### 屏幕和印刷

Postext排出的同一批页面既供屏幕显示，也供印刷机印刷，而同一种颜色在两者上看起来并不一样。

- **屏幕**是sRGB颜色的WCAG 2对比度，即对两者的相对亮度计算`(L1 + 0.05) / (L2 + 0.05)`：Canvas、HTML阅读器、EPUB和RGB PDF显示的就是这个结果。
- **印刷**用同一个公式，但取每种颜色在纸上的亮度。颜色先经印刷所用的输出特性文件分色（以CMYK定义的颜色保留其数值），再经特性文件把分色结果读回，亮度相对于白纸计算：白纸是印刷页面上的白，正如显示器的白是屏幕上的白。油墨从来不是纯黑：白底上的实地黑，在涂布纸上约为14:1（FOGRA39、FOGRA51），在非涂布纸上约为8:1（FOGRA47、FOGRA52），在新闻纸上约为5:1（IFRA26、SNAP），而屏幕上是21:1。在屏幕上合格的灰色到了纸上可能不合格：白底上的`#767676`在屏幕上是4.54:1，在涂布纸上约为3.3:1。

计算印刷对比度需要输出特性文件的转换（`options.transform`，用`outputTransform`构建）。没有它时，印刷方面只检查反白字。

### 反白字

反白在有墨底色上的浅色文字，字小或笔画细时印刷会糊版：底色的油墨向字内扩散，由几种油墨叠成的底色还要靠各块印版套准。对比度反映不出这一点，因为深蓝底上的白字超过10:1。印刷检查把这类文字单独报告（`reversedText`）：字号小于`minSize`的，或者为斜体或字重不大于`lightWeight`、字号又小于`minFineSize`的。每个问题都写明底色由四色油墨中的几种叠成。

### 检查哪些内容

检查读取每个块的各行及其行内颜色（粗体、斜体、引用、行内标签）、列表标记、首字下沉、题注、注释和表格单元格，以及版面设计槽位中的文字：书眉、章首页、标题的版面设计、框标题。底色是文字下方最上面的一层填充：版面设计的方框、标注框、题注的底条、表格单元格、行内标签，否则就是页面颜色（`page.backgroundColor`，或篇的调色板为该篇页面指定的纸色）。半透明的颜色先与它下面的颜色混合。压在图片上的文字不检查，因为它的底色不是单一颜色；漫画嵌字、注音和公式也不检查。图中标注的文字在其底板上读取，带光晕的则在光晕内读取；直接放在图片上的标注，和其他压在图片上的文字一样跳过。

在模板页上，检查按页面的绘制顺序进行：各个框按图层排列，模板的`decoration`位于第0层。框里的文字，如果框的样式画了底框，就以这个底框为底色；否则看它下面的装饰方框（下面是装饰中的图片时跳过，与其他图片上的文字相同）；再没有，就看页面颜色。所以装饰中彩色页签上的白字，是拿那个页签的颜色来衡量的。旋转或缩放过的框先放到纸面上再读取底色，装饰本身的文字也按同样方式检查。自postext 1.37起。

### 运行检查

`contrastDocument(doc, options)`返回排好的文档中查出的问题，对比度最低的排在最前。每个问题带有全书范围的页序`pageIndex`、在纸面上的`rect`（页面px）和首次出现处的源码范围，实际绘出的两种颜色（`color`、`background`），这样排的文字所用的最小字号`sizePt`及其`weight`和`italic`，一个`role`（`'body'`、`'heading'`、`'caption'`、`'table'`、`'runningHead'`、`'design'`、`'chip'`、`'marker'`或`'label'`（图中标注的文字）），第一个文本片段的`text`，以及这样排的文本片段数`count`。同一对颜色在每个阈值下只报告一次，不论有多少行用到它。

- `lowContrast`另有`level`、`large`、`required`，所检查的每种介质下的对比度（`screen`、`print`），以及`failing`，即低于`required`的那些介质。
- `reversedText`另有`reasons`（`'small'`、`'italic'`、`'light'`）、`minimumPt`和`inks`。

选项有`contrast`（解析后的设置，不用文档自己的设置时给出）、`media`（要检查的介质，不管`mode`怎么设）和`transform`。

```ts
import { contrastDocument, outputTransform, parseIccProfile } from 'postext';

const transform = outputTransform(parseIccProfile(fogra51Bytes));
for (const issue of contrastDocument(doc, { transform })) {
  if (issue.kind === 'lowContrast') {
    console.log(`${issue.color} on ${issue.background}: ${issue.screen}:1, ${issue.level} asks for ${issue.required}:1`);
  }
}
```

`contrastPairs(doc, options)`返回文档中出现的每一对文字与底色，不论合格与否，带有`screen`对比度、给出转换时的`print`对比度、要求的对比度`required`，以及配置中所写的颜色（`textColor`、`groundColor`）：设计工具在颜色字段旁显示的就是这些。不管`enabled`怎么设，它都会运行。

这些度量也已导出，可供你自己的工具使用：

- `contrastRatio(a, b)`和`relativeLuminance(color)`给出sRGB颜色的WCAG 2对比度和相对亮度。
- `isLargeText(sizePt, weight)`和`contrastThreshold(level, large)`给出某一字号和字重的阈值。
- `blendColors(top, under)`给出一种半透明颜色叠在另一种颜色上的结果，格式为`#rrggbb`。
- `printContrastRatio(a, b, context)`、`printLuminance(color, context)`和`printSeparation(color, context)`给出纸上的相应结果。上下文中有`transform`，以及作为`authored`传入的`authoredCmykColors(config)`的结果。
- `contrastMedia(doc.config, contrast)`给出`mode`对某个文档解析出的介质。

解析函数和精简函数与其他部分一致：`resolveContrastConfig`和`stripContrastDefaults`，以及`DEFAULT_CONTRAST_CONFIG`、`DEFAULT_CONTRAST_REVERSED_TEXT_CONFIG`、`CONTRAST_LEVELS`和`CONTRAST_MODES`。


## 正文检查（配置）

### 设计文字如何读取

- 它的字面文字是去掉所有占位符（`{name}`、`{attr.key}`、`{firstMark.key}`）后的`content`，转义`{{`和`}}`读作花括号，`\n`读作换行。
- 没有字母和数字的文字（一排引导点、装饰符、一个`·`）永远不算正文。
- 词是空格之间含有字母或数字的部分：单独的`·`或`|`不算词，`postext.dev`这样的地址算一个词。中文、日文等不用空格分词的文字不数词，只按字数计算。
- 先去掉`allow`中的短语，以及文档元数据（即前置元数据）中的`title`、`subtitle`、`author`和`publisher`，书眉常常重复这些内容。
- 剩下的部分超过`maxWords`个词或`maxChars`个字母和数字时，就算正文。

所有版面设计槽位都会读取：`header`、`footer`、各级标题的`advancedDesign.slot`、各标题样式的`advancedDesign.slot`、`header`和`footer`、`parts.design`、`parts.versoDesign`、`toc.parts.design`，以及`htmlViewer.overrides`中的相同位置。`configDesignSlots(config)`列出它们及其路径，`designTextLiteral(content)`返回模板的字面文字。

### 警告

`collectConfigWarnings`（以及`VDTDocument.configWarnings`）为每个存放正文的设置给出一条`contentInConfig`警告：某个标题样式（其`id`在`ownerId`中）、某一级标题、页眉、某个篇的设计。`path`指出该设置，`count`是有问题的设计文字数，`chars`是它们的字母和数字数，`elements`是每条文字的路径（前20条），`value`是第一条的开头（最多40个字符）。把文档的元数据作为第二个参数传入，即可允许其书名和作者；排版时会自动这样做。

```js
import { collectConfigWarnings } from 'postext';

collectConfigWarnings(config, { metadata: { title: 'A Year of Weather' } });
// [{ kind: 'contentInConfig', path: 'headingStyles[3]', ownerId: 'lesson-4',
//    value: 'Look at the picture and answer the questi…', used: '',
//    count: 30, chars: 1017, elements: ['headingStyles[3].header.elements[2]', …] }]
```

**解决方法**：把文字移到Markdown中，作为所属章节的标题、标注框或段落，设计中只保留占位符。每章不同的值可以写在标题行上，用`{attr.key}`读取：`# 地图 {kicker="第四课"}`，设计中写`{attr.kicker}`。属于版式的短语，例如页眉中的出版社名称，放进`allow`。

沙盒在**检查**面板中列出这条警告，并在**版面设计 › 高级 › 配置中的正文**中提供这项检查；`postext check`会打印它。

### 在你自己的Canvas中标出松散行

引擎把松散行高亮导出为两个辅助函数，供你在自己绘制的页面上使用：

```ts
import { buildDocument, renderPageToCanvas, drawLooseLines, findLooseLines } from 'postext';

const doc = buildDocument(content, config);
const canvas = document.querySelector('canvas')!;
renderPageToCanvas(doc.pages[0], doc, canvas, { scale: 0.5 });
drawLooseLines(canvas.getContext('2d')!, doc.pages[0], doc, { threshold: 2.5 });

// 同样的行也可以作为数据使用：生成报告、SVG叠加层、按页计数。
for (const { ratio, line, block } of findLooseLines(doc, { threshold: 2.5 })) {
  console.log(`page ${block.pageIndex + 1}: ${ratio.toFixed(2)}× — ${line.text}`);
}
```

- <strong>`findLooseLines(doc, { threshold?, pageIndex? })`</strong>按阅读顺序返回每一个词间距超过`threshold`的两端对齐行：`{ block, line, ratio, x, y, width, height }`。`ratio`就是`lineWordSpacing(line)`：`minWordSpacing`和`maxWordSpacing`所约束的词间距（行内含有其他字体的空格时取`justifiedSpaceLimitRatio`，否则取`justifiedSpaceRatio`），所以排在上限上、又含有粗体空格的行，在阈值等于`maxWordSpacing`时不会被报告。这个矩形以页面像素计，就是高亮覆盖的横条：在该行的高度上横跨整个块宽。沙盒高亮的、并在检查面板中报告为`looseLine`的正是这些行。
- <strong>`drawLooseLines(ctx, page, doc, { threshold?, color? })`</strong>在一页上填充这些横条，并返回它绘制的行。它在上下文当前的变换下以页面像素绘制，所以要在同一个canvas上紧接着`renderPage`或`renderPageToCanvas`调用它：这两个函数都会让上下文保持按页面缩放。`color`可以是任何canvas填充样式。
- **默认值**。两个辅助函数都使用默认阈值（3）和默认颜色（`#ff000040`），而不是文档的`debug.looseLineHighlight`：那项设置属于沙盒。要遵循某个配置，传入`resolveDebugConfig(config.debug).looseLineHighlight.threshold`和`.color.hex`。

### 配置警告

配置本身的下列错误一定会报告出来，除了最后一项提到的开关，没有任何开关能隐藏它们。引擎不会因此失败：它会换用一个值，或略去该设置，并说明这样做了：

- **未知编号格式**：有序列表的`numberFormat`、`page.pageNumbering.format`或资源类型的`counterFormat`不属于任何一种[编号格式写法](/zh/docs/configuration-page-layout#编号格式的写法)。此时按十进制编号。
- **字体族中写了字体栈**：`fontFamily`（或任何`…FontFamily`）中写了CSS字体栈。文字用字体栈中的第一个字体族排（见[每个`fontFamily`只写一个字体族](/zh/docs/configuration-text#每个fontfamily只写一个字体族)）。
- **侧栏没有空间**：`'oneAndHalf'`版式的`sideColumnPercent`（文档的，或标题样式自己的`layout`中的）会使其中一栏不足内容宽度的1%，或者不是数字。各栏按两者都能接受的最接近的值截取，`used`给出该值（`sideColumnPercentClamped`；见[`'oneAndHalf'`版式](/zh/docs/configuration-page-layout#版式类型)）。
- **栏数超出范围**：`'multiple'`版式的`columnCount`（文档的，或标题样式自己的`layout`中的）不是3到8之间的整数。页面按最接近的有效栏数分栏（不是数字时为3），`used`给出这个数（`columnCountClamped`；见[`'multiple'`版式](/zh/docs/configuration-page-layout#版式类型)）。
- **字符网格过大**：`cjk.grid`的每行字数或每页行数超出了页边距内能容纳的数量。网格按能容纳的最大数量排，`used`给出这个数（`cjkGridClamped`；见[字格](/zh/docs/configuration-east-asian#字格)）。
- **未知标题设置**：`headings`、`headings.balancing`、某个标题级别、标题样式或段落样式中没有的键：拼错的`letterSpacng`、从其他工具借来的`tracking`、标题样式上的`level`、段落样式上的`fontStyle: 'italic'`（段落样式要用`italic: true`）。制表位也同样检查（用`leaders`代替`leader`），首字下沉、`lineNumbers`、`canvasViewer`、`checks`、`codeStyle`和漫画设置也一样。引擎会忽略它（postext 1.4及以前是悄无声息地忽略）。`value`是这个键，`used`为空，如果某个设置与它只差一两个字母或只有大小写不同，`suggestion`会给出最接近的那个设置（`unknownConfigKey`）。
- **未知设置值**：只能取几个固定词的设置写了别的值，例如`direction: 'right'`（可取`auto`、`ltr`或`rtl`）。引擎改用默认值，`used`给出实际结果：对`direction`而言，是文档语言的书写方向（`unknownConfigValue`）。制表位的`align`不是它的四个取值之一时，按`'start'`读取；`position`既不是长度、`'end'`也不是百分比时，略去该制表位（`used`为`'none'`）。漫画设置中的词同样会检查（[漫画 › 漫画警告](/zh/docs/comics#漫画警告)）：`used`是该设置最终解析出的值（对内置样式而言，是该对白框样式自己的默认值），值与某个词接近时，`suggestion`给出最接近的那个词。对比度检查的`level`和`mode`同样会检查：`used`为`'AA'`或`'auto'`。`canvasViewer.pageGap`和`canvasViewer.rowGap`的检查方式相同：`used`是该值最终读成的0到200之间的整数（自postext 1.43起）。`print.standard`、`print.outputProfile`和`print.renderingIntent`也同样检查（`used`是默认值得出的结果），`checks.contentInConfig`中不是0或更大整数的`maxWords`或`maxChars`也一样。
- **竖排文字中的行号**：竖排文档（`layout.writingMode: 'vertical-rl'`）中写了`lineNumbers.enabled: true`。竖排页面不标行号，`used`为`false`（`lineNumbersUnsupported`；见[行号](/zh/docs/configuration-notes-references#行号)）。
- **竖排中的文字绕排**：竖排文档中资源类型的`defaultPlacement.wrap`。竖排页面不在图旁排正文，`used`为`none`（`wrapUnsupported`；见[文档格式 › 文字绕排](/zh/docs/document-format-resources#文字绕排)）。不指明一侧的`wrap`是未知的设置值。
- **基于其他样式的标注框样式**：标注框样式的`extends`指向`calloutStyles`中不存在的样式（`calloutStyleExtendsUnknown`，`suggestion`给出最接近的id），或沿`extends`追溯会回到它自己（`calloutStyleExtendsCycle`，`value`为环`a → b → a`）。该样式单独成立，未设置的项使用内置默认值（见[基于其他样式的样式](/zh/docs/configuration-callouts#基于其他样式的样式)）。
- **页面模板和标注样式**：`pageTemplates`或`labelStyles`中的问题，包括id或名称重复，`extends`、锚定或框接续成环，样式、框或模板不存在，最小值大于最大值，锚点的标注样式不在`labelStyles`中（传入资源时检查：`collectConfigWarnings(config, { resources })`）。这些警告的`path`是JSON指针（`/pageTemplates/3/frames/2/style`）；每种警告的原因和解决办法见[页面模板警告](/zh/docs/configuration-composed-pages#页面模板警告)。
- **设计中的正文**：设计文字元素在占位符之外的文字超过一个简短标签的长度，也就是把书的正文存放在了配置中。每个设置（某个标题样式、页眉、某个篇的设计）一条警告，附每条文字的路径（`contentInConfig`；见[正文检查](#正文检查配置)）。与其他警告不同，它可以关闭：`checks.contentInConfig.enabled: false`。

沙盒在**检查**面板中列出这些警告，并附上设置的路径。在代码中，`buildDocument`把它们作为`configWarnings`放在文档上（配置没有问题时不存在该字段），`collectConfigWarnings(config)`则不做排版直接返回它们：

```js
import { buildDocument, collectConfigWarnings } from 'postext';

// 纯JavaScript：在TypeScript中，'roman'根本通不过类型检查。
const config = { bodyText: { fontFamily: 'EB Garamond, serif' }, orderedLists: { numberFormat: 'roman' } };
const doc = buildDocument({ markdown }, config);
doc.configWarnings;
// [{ kind: 'fontFamilyStack', path: 'bodyText.fontFamily', value: 'EB Garamond, serif', used: 'EB Garamond' },
//  { kind: 'unknownNumberFormat', path: 'orderedLists.numberFormat', value: 'roman', used: 'arabic' }]
collectConfigWarnings(config); // 同一个列表
```

所有嵌套的部分配置也会被检查：标题样式、篇内的列表、`htmlViewer.overrides`、设计元素。

`formatWarning`（见[文档中的警告](/zh/docs/configuration-programmatic-usage#文档中的警告)）同样会描述这些警告，并把设置的路径放在最前面，例如`bodyText.fontFamily: font stack "EB Garamond, serif" — set in "EB Garamond"`、`headingStyles[0].letterSpacng: unknown setting "letterSpacng" — ignored (did you mean "letterSpacing"?)`，这样宿主程序可以用一个循环记录一次构建返回的全部三个列表。
