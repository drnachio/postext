# Configuration : styles et parties


## Styles de paragraphe

La propriété `paragraphStyles` déclare des styles nommés qu’un document applique à une suite de paragraphes avec un conteneur `:::paragraphs{style="…"}` : bibliographies, glossaires, notes, tout bloc d’entrées qui demande sa propre police, sa graisse, son inclinaison, son corps, son interlignage, des capitales, des petites capitales ou un retrait suspendu. Chaque champ typographique est facultatif et hérite du texte courant s’il n’est pas défini : un style n’énonce que ce qui le distingue du texte courant.

```ts
const config: PostextConfig = {
  paragraphStyles: [
    {
      id: 'bibliography',
      name: 'Bibliography',
      fontSize: { value: 7, unit: 'pt' },
      lineHeight: { value: 1.2, unit: 'em' },
      hangingIndent: { value: 2, unit: 'em' },
      spaceBetween: { value: 0.25, unit: 'em' },
      marginTop: { value: 1, unit: 'em' },
      marginBottom: { value: 1, unit: 'em' },
    },
  ],
};
```

```md
## References

:::paragraphs{style="bibliography"}
Knuth, D. E. (1984). *The TeXbook*. Addison-Wesley.

Bringhurst, R. (2004). *The Elements of Typographic Style*. Hartley & Marks.
:::
```

Une pièce de théâtre compose ses didascalies en italique et sa liste des personnages en petites capitales :

```ts
paragraphStyles: [
  { id: 'direction', italic: true, fontSize: { value: 9, unit: 'pt' } },
  { id: 'cast', smallCaps: true, textAlign: 'center', fontWeight: 600 },
],
```

```md
:::paragraphs{style="direction"}
Elsinore. A platform before the castle. *Francisco* at his post.
:::
```

La didascalie s’imprime en italique et le nom qu’elle contient en romain ; les graisses, `italic` et `smallCaps` d’un style s’appliquent aussi à l’intérieur des encadrés.

Un recueil de poésie met certains vers en retrait et renfonce le retour d’un vers trop long pour la ligne plus loin que le vers lui-même. `indent` décale vers l’intérieur chaque ligne du paragraphe, et le retrait suspendu se compte à partir de là :

```ts
paragraphStyles: [
  { id: 'verse', textAlign: 'left', firstLineIndent: { value: 0, unit: 'em' }, hangingIndent: { value: 4, unit: 'em' } },
  { id: 'verse-indented', textAlign: 'left', indent: { value: 1.5, unit: 'em' }, hangingIndent: { value: 2.5, unit: 'em' } },
],
```

Un vers en `verse-indented` commence à 1,5 em et son retour à 4 em, au même niveau que les retours des vers en `verse`. Sans `indent`, un style peut mettre en retrait la première ligne ou suspendre les autres, mais pas les deux : `firstLineIndent` est ignoré dès que `hangingIndent` est défini.

Un menu aligne chaque prix sur la fin de la ligne, derrière des points de conduite :

```ts
paragraphStyles: [
  {
    id: 'menu',
    textAlign: 'left',
    firstLineIndent: { value: 0, unit: 'em' },
    tabStops: [{ position: 'end', align: 'end', leader: '. ' }],
  },
],
```

```md
:::paragraphs{style="menu"}
Onion soup :tab 8.50

Grilled sea bream with fennel and lemon :tab 21.00
:::
```

Les points de chaque ligne s’arrêtent un demi-cadratin avant le prix (`leaderGap`). Un plat trop long pour sa ligne passe à la ligne, et sa dernière ligne garde les points de conduite et le prix ; quand le prix ne tient pas à côté du dernier mot, ce mot descend avec lui.

### Le conteneur `:::paragraphs`

Une ligne `:::paragraphs{style="<id>"}` ouvre le conteneur et une ligne `:::` seule le ferme ; chaque paragraphe compris entre les deux prend le style nommé, tandis que les titres, les listes et les autres blocs à l’intérieur gardent leur style habituel. Les conteneurs peuvent s’imbriquer dans d’autres conteneurs délimités. Un identifiant de `style` inconnu n’est pas une erreur : les paragraphes se rendent comme du texte courant ordinaire, et le Sandbox signale l’identifiant.

Le délimiteur d’ouverture accepte aussi `align` (`start`, `end`, `left`, `right`, `center`, `justify`), `indent` et `endIndent` (les nombres seuls sont en em), avec ou sans style : avec un style, ils le surchargent ; sans style, ils s’appliquent par-dessus le style du conteneur englobant, ou par-dessus le style de texte de l’endroit où se trouve le délimiteur (le texte courant, une partie, une section stylée ou un encadré). `:::paragraphs{align=end}` compose un bloc aligné sur la fin de la ligne (地付き) et `:::paragraphs{align=end endIndent=1}` un caractère avant elle. Depuis postext 1.16.

À l’intérieur du conteneur, le flux quitte la grille de ligne de base (une entrée de 7 pt avec un interlignage de 1,2 em ne peut pas tenir sur une grille de 8 pt/1,5 em) et le dernier paragraphe recale le flux sur la grille (la grille l’emporte ; l’espace en dessous est un minimum, la même convention que suivent les titres). Les entrées se coupent d’une colonne et d’une page à l’autre comme les paragraphes du texte courant, avec la même protection contre les orphelines et les veuves ; un titre placé juste avant le conteneur reste avec son premier paragraphe.

L’espace sous le conteneur est le plus grand de `spaceBetween` et `marginBottom` du style et de l’espacement de paragraphe du texte qui l’entoure (une ligne quand `bodyText.paragraphSpacing` est actif), et il se fond avec l’espace que le bloc suivant garde au-dessus de lui, comme l’espace entre deux paragraphes du texte courant : un titre placé après une bibliographie se trouve à son propre `marginTop` sous la dernière entrée (ou à l’espace du style, s’il est plus grand), et un paragraphe qui suit un groupe d’entrées plus serrées garde l’espacement de paragraphe du texte. Le flux se recale d’abord sur la grille sous le texte, et ce que le recalage n’a pas couvert est reporté en lignes de grille entières : le texte qui suit le conteneur tombe ainsi sur la grille. Jusqu’à postext 1.4, l’espace du style se plaçait sous la dernière ligne avant le recalage, l’espace au-dessus du bloc suivant s’ajoutait en dessous, et l’espacement de paragraphe n’était pas pris en compte ; `bodyText.paragraphContainerSpacing: 'add'` garde cette règle, et les configurations enregistrées avant elle se lisent avec elle. Un style avec `snapToGrid: false` ne se recale pas : le texte qui suit le conteneur se place exactement à cet espace en dessous, hors de la grille jusqu’au prochain bloc qui se recale. Un conteneur qui se ferme sur une liste est composé comme dans la 1.4 avec l’une ou l’autre règle : la liste garde son propre espace en dessous, et `marginBottom` suit cet espace, en se fondant avec celui du bloc suivant.

Un style peut fixer la règle de ses propres conteneurs avec `containerSpacing` : `'add'` sur le style d’un grand chiffre (un nombre composé en grand) ou d’une liste de références termine ses groupes sur l’espace propre du style, dans le texte comme à l’intérieur d’un encadré, tandis que tous les autres conteneurs du document gardent `'collapse'` ; `'collapse'` sur un style fait l’inverse dans un document qui se lit avec `'add'`. Un conteneur qui n’indique aucun style suit le document.

À l’intérieur d’un `:::callout`, le conteneur prend les marges de son style de la même façon : `marginTop` et `marginBottom` fusionnent avec l’espacement des blocs qui l’entourent (une valeur négative les rapproche), et un conteneur qui ouvre l’encadré ne prend pas de marge supérieure, comme en haut d’une colonne. Un encadré n’a pas de grille de ligne de base sur laquelle se recaler : l’espace sous le dernier paragraphe est donc le plus grand de `marginBottom`, de `spaceBetween` et de l’espacement de paragraphe propre à l’encadré (son `body.paragraphSpacing`, une ligne de son texte ; non pris en compte avec `paragraphContainerSpacing: 'add'`), ou la marge supérieure propre au bloc suivant, si elle est plus grande encore ; un `marginBottom` négatif remonte au contraire le bloc suivant. (Jusqu’à postext 1.4, un conteneur à l’intérieur d’un encadré ignorait les deux marges.)

Dans un encadré, les champs typographiques qu’un style laisse sans valeur viennent de l’encadré (depuis postext 1.52) : la police, la taille, l’interligne, les graisses et la couleur que le style laisse au texte sont ceux du texte de l’encadré, si bien que `:::paragraphs{style="centred"}` avec un style qui ne fixe que `textAlign: 'center'` se compose dans la linéale d’un encadré et dans le romain d’un autre. Les champs que le style fixe restent. `bodyText.paragraphStylesInBoxes: 'document'` garde plutôt le texte du document, comme jusqu’à postext 1.51.

```ts
const resolved = resolveParagraphStylesConfig(config.paragraphStyles, resolvedBodyText);
// => every unset field filled from the resolved body text

const minimal  = stripParagraphStylesDefaults(config.paragraphStyles);
// => undefined when the list is empty; zero margins and `name === id` dropped
```


## Styles de pastille

La propriété `chipStyles` déclare les styles nommés de la pastille en ligne `:chip[text]{style="…"}` : les petits cadres arrondis et teintés d’une banque de mots, d’une touche de clavier, d’une étiquette (la syntaxe et ses règles de coupure de ligne se trouvent dans la référence du format du document). Un style, `chip`, est fourni par défaut (un fond bleu pâle avec un filet extra-fin dans la couleur principale, légèrement arrondi, le texte comme les mots qui l’entourent) : `:chip[…]` fonctionne donc sans aucune configuration ; déclarer `chipStyles` remplace cette liste par défaut. Une pastille sans `style`, ou dont l’identifiant n’est déclaré par aucun style, prend le premier style (le Sandbox signale l’identifiant inconnu).

```ts
const config: PostextConfig = {
  chipStyles: [
    { id: 'chip', name: 'Word bank' },
    {
      id: 'key',
      name: 'Keyboard key',
      background: { hex: '#fff4d6', model: 'hex' },
      borderColor: { hex: '#8a6d1f', model: 'hex' },
      borderRadius: { value: 2, unit: 'pt' },
      bold: true,
    },
  ],
};
```

```md
Classify: :chip[battery] :chip[cable] :chip[switch]

Press :chip[Ctrl]{style="key"} + :chip[C]{style="key"}.
```

Quand le cadre devient plus haut que le pas de ligne, une pastille peut empiéter sur une pastille de la ligne du dessus ou du dessous : le Sandbox affiche alors un avertissement « Pastilles touchant la ligne voisine » quand deux pastilles de lignes différentes se chevauchent, avec le chevauchement en points, pour que vous puissiez réduire `paddingY`, le contour ou `fontSize`. Une pastille dotée d’un attribut `field` est un champ de formulaire à remplir dans le PDF et un champ de formulaire InDesign dans l’export IDML. Dans le VDT, une pastille est un segment de ligne de `kind: 'chip'` dont le champ `chip` contient les segments de texte (chacun avec sa chaîne de police et sa largeur), la géométrie du cadre (`boxWidth`, `ascent`, `descent`, `paddingX`, `borderWidth`, `borderRadius`, les marges d’espacement) et ses couleurs ; le `text` du segment est un caractère de substitution unique : les positions en texte brut et les correspondances avec la source comptent donc une pastille comme un seul caractère.

```ts
const resolved = resolveChipStylesConfig(config.chipStyles);
// => the built-in `chip` style when unset; every field filled

const minimal  = stripChipStylesDefaults(config.chipStyles);
// => undefined for the built-in default; static defaults dropped

const style = pickChipStyle(resolved, 'key');
// => the `key` style, else the first one
```


## Styles de caractère

La propriété `characterStyles` déclare les apparences nommées d’une suite de mots. Une suite en reçoit une avec la directive `:span`, `:span[quelques mots]{style="id"}`, seul moyen de donner une apparence nommée à une suite de mots. Un style de caractère règle le texte : une police (famille, corps, graisse, inclinaison), une couleur, une approche, des capitales ou des petites capitales. Une bande derrière les mots ou un trait sous eux ou à travers eux relève d’un [style de surlignage](#styles-de-surlignage), que le style de caractère nomme avec `mark`. Contrairement à une pastille, une suite stylée passe à la ligne et se coupe comme le texte qui l’entoure. Aucun style n’est livré par défaut, et un livre n’en a aucun tant qu’il n’en déclare pas. Une suite dont aucun style ne déclare l’id est composée comme le texte qui l’entoure, et le panneau Révision la signale (*Style de caractère inconnu*).

```ts
const config: PostextConfig = {
  markStyles: [
    { id: 'mark' },
    {
      id: 'pen',
      name: 'Marker pen',
      background: { hex: '#ffe14d', model: 'hex' },
      opacity: 70,
      paddingTop: { value: -0.35, unit: 'em' },
      rough: 30,
    },
    { id: 'struck', backgroundEnabled: false, line: { position: 'through', color: { hex: '#b23a2a', model: 'hex' } } },
  ],
  characterStyles: [
    { id: 'marker', name: 'Marker', mark: 'pen' },
    {
      id: 'drug',
      name: 'Drug name',
      fontFamily: 'Source Sans 3',
      fontWeight: 600,
      color: { hex: '#1f4e79', model: 'hex' },
      letterSpacing: { value: 0.02, unit: 'em' },
    },
    { id: 'wrong', name: 'Wrong answer', mark: 'struck' },
  ],
};
```

```md
Le :span[traitement de première ligne]{style="marker"} est la :span[metformine]{style="drug"}, jamais :span[l’insuline d’emblée]{style="wrong"}.
```

**Un mécanisme pour chaque chose.** Un style de caractère règle les lettres ; un style de surlignage dessine ce qui les accompagne, une bande ou un trait, comme pour `:mark[…]`. Un simple soulignement reste `:underline[…]`, un simple barré `~~…~~` et un simple surlignage `:mark[…]` ; un style de caractère sert à une apparence que le livre nomme et réutilise. La forme à crochets et barres qu’emploient certains autres outils (`[mots]|id|`) n’est pas une syntaxe Postext : elle reste du texte, telle qu’elle est écrite.

**Imbrication.** Une suite peut contenir d’autres marques en ligne (`:span[un mot en **gras**]{style="marker"}`, un lien, une référence, une formule) et d’autres suites : le style le plus intérieur l’emporte (`:span[a :span[b]{style="drug"} c]{style="marker"}`). Une suite ne peut pas franchir un paragraphe.

**Où.** Paragraphes, éléments de liste, citations, encadrés, notes de bas de page, légendes, notes et cellules de tableau, et titres tant que `headings.inlineMarks` est activé. Les titres courants, la table des matières et les entrées d’index prennent les mots sans le style. Sur une page verticale (livres chinois et japonais composés verticalement), la suite est composée comme le texte qui l’entoure, et le trait de son surlignage court à droite des caractères, comme un trait latéral.

**Sortie.** Le canvas, le PDF, le HTML et les sorties vectorielles (SVG, IDML) dessinent le surlignage que nomme un style à partir de la même géométrie que chaque `:mark[…]`. L’EPUB traduit chaque style en une classe (`pt-cs-<id>`) avec sa police, son corps, sa graisse, son inclinaison, sa couleur, son approche et ses petites capitales ; il ne dessine aucun surlignage, pas plus qu’il ne dessine les `:mark[…]`. Un export Word fait de chaque style un style de caractère Word nommé *Postext Style: …*, la bande du surlignage devenant une trame et son trait le soulignement Word le plus proche ou un barré, et un import Word ramène à lui un style de caractère qui porte le nom d’un style du livre, ou *Postext Style: …* dans n’importe quelle langue du site.

Dans le VDT, un segment stylé porte `charStyle: { id, style }` (la suite et l’id du style) ; sa police et son approche sont déjà dans `fontString` et `tracking`, sa couleur dans `color`, et un segment que le style a composé en capitales porte le texte écrit dans `sourceText`.

```ts
const resolved = resolveCharacterStylesConfig(config.characterStyles, new Set(['pen', 'struck']));
// => every field filled; a `mark` that names no highlight style dropped

const minimal  = stripCharacterStylesDefaults(config.characterStyles);
// => static defaults dropped; undefined for an empty list

const style = pickCharacterStyle(resolved, 'drug');
// => the `drug` style, or undefined when no style has that id
```

## Styles de surlignage

La propriété `markStyles` déclare les styles nommés du `:mark[texte]{style="…"}` en ligne (et des surlignages que les styles de caractère nomment avec `mark`) : la bande de couleur derrière une phrase, et un trait sous elle ou à travers elle, comme un manuel surligne ses mots clés (la syntaxe et ses règles de coupure sont dans la référence du format de document). Un style est fourni par défaut, `mark` (une bande jaune pâle qui dépasse un peu de la phrase, aux extrémités droites, le texte dans sa propre couleur) : `:mark[…]` fonctionne donc sans aucune configuration ; déclarer `markStyles` remplace cette liste. Une marque sans `style`, ou avec un identifiant qu’aucun style ne déclare, prend le premier style (le Sandbox signale l’identifiant inconnu).

```ts
const config: PostextConfig = {
  markStyles: [
    { id: 'mark', name: 'Key idea' },
    {
      id: 'key',
      name: 'Definition',
      background: { hex: '#cdebd5', model: 'hex' },
      color: { hex: '#14532d', model: 'hex' },
    },
  ],
};
```

```md
The sun warms the sea and :mark[water rises into the air as vapour].

- :mark[Evaporation]{style="key"}: water turns into vapour.
```

Le trait continue sous les espaces entre les mots de l’expression et s’arrête à sa dernière lettre là où l’expression passe à la ligne suivante. Ce sont les mêmes traits que tracent `:underline[…]` et `~~…~~`, si bien qu’un trait de marque se place là où se placent ceux-ci.

**Transparence.** Une bande d’opacité inférieure à 100 % est translucide sur le canvas, en HTML, dans un PDF numérique et dans un PDF/X-4, qui admettent la transparence. Un PDF/X-1a n’en admet aucune : la bande y est composée telle qu’elle s’imprime sur papier blanc, une teinte de sa couleur, sur la plaque de son encre s’il s’agit d’un ton direct. L’export Word et les sorties vectorielles (SVG, IDML) la composent de la même façon, sur blanc ; sur une page de couleur ou sur une image, cette teinte diffère de la bande translucide.

Les longueurs en em (`paddingX`, `paddingY`, `paddingTop`, `paddingBottom`, `borderRadius`) se rapportent à la taille du texte marqué. La bande ne prend aucune place : le texte est composé comme sans la marque, la bande est peinte dessous, et sa marge empiète sur les espaces entre les mots et sur l’interligne. Dans le VDT, les segments des mots marqués ont un `mark` (`{ style, id, start?, end?, from?, to? }`) et chaque ligne garde ses bandes dans `highlights` (`{ x, y, width, height, color, radiusLeft, radiusRight, opacity?, rough?, seed? }`, relatives au `bbox.x` et à la ligne de base de la ligne), que les moteurs de rendu canvas, PDF et HTML peignent avant le texte de la ligne ; les traits vont dans les `marks` de la ligne, marqués `markLine`, et sont peints après lui.

```ts
const resolved = resolveMarkStylesConfig(config.markStyles);

const minimal  = stripMarkStylesDefaults(config.markStyles);
// => undefined for the built-in default; static defaults dropped

const style = pickMarkStyle(resolved, 'key');
// => the `key` style, else the first one
```


## Listings de code

La propriété `codeStyle` règle l’aspect des listings de code : les blocs délimités ```` ``` ```` et `~~~` du texte (voir [Format du document › Blocs de code](/fr/docs/document-format#blocs-de-code)), et le code en ligne quand il demande une police de code. Un listing est composé ligne par ligne tel qu’il est écrit, dans une police à chasse fixe, dans un cadre : aucune ligne n’est coupée par césure ni justifiée, chaque espace garde sa largeur, et une tabulation passe au taquet suivant. Le cadre vient de la même mécanique qu’un `:::callout` : un listing se coupe donc entre deux lignes d’une colonne et d’une page à l’autre, chaque partie dans son propre cadre, et un bloc délimité à l’intérieur d’un encadré est un cadre imbriqué dans celui-ci. Toutes les propriétés sont facultatives. Depuis postext 1.23.

### Coloration syntaxique

Il lit le listing entier : un commentaire ou une chaîne qui s’étend sur plusieurs lignes reste un seul jeton. Un hôte branche son propre surligneur (Shiki, Prism, highlight.js) avec `registerCodeHighlighter`. Les configurations sont des données sérialisables : la fonction s’enregistre donc auprès du moteur, elle ne s’écrit pas dans `codeStyle` :

```ts
import { registerCodeHighlighter } from 'postext';

// fn(code, lang) returns the listing's lines, each as runs whose texts join into the line.
registerCodeHighlighter('rust', (code) => code.split('\n').map((line) => [
  { text: line, token: line.trimStart().startsWith('//') ? 'comment' : undefined },
]));
registerCodeHighlighter('*', null); // remove the one registered for every language
```

Un surligneur enregistré pour un langage l’emporte sur un surligneur enregistré pour `'*'`, qui l’emporte lui-même sur l’analyseur intégré. Un segment indique soit un type de jeton, `token` (coloré par `tokens`), soit une `color` propre (un hexadécimal CSS). Un surligneur qui renvoie `undefined`, lève une exception ou renvoie des lignes qui ne reconstituent pas celles du listing est ignoré. La mise en page lit le registre au moment de composer un listing : enregistrez avant de construire, et dans un web worker (le Sandbox met en page dans l’un d’eux), enregistrez à l’intérieur du worker.

### Composition d’un listing

- **Une ligne par ligne de source.** Les lignes sont construites à partir des chasses propres à la police de code, pas par l’algorithme de coupure des paragraphes : les espaces gardent leur largeur, une suite d’espaces est conservée, les espaces en tête créent un retrait. Un listing dans un livre de droite à gauche se lit de gauche à droite, ses lignes composées depuis le côté opposé du cadre comme une citation de gauche à droite, ses numéros dans la marge à leur gauche. Dans un livre vertical, un listing suit le flux vertical (son texte latin couché, comme le compose le texte vertical) et ne prend pas de numéros de ligne.
- **Coupure.** Un listing plus haut que la place restante se coupe entre deux lignes d’une colonne et d’une page à l’autre, chaque partie encadrée séparément, sans jamais laisser moins de `splitMinLines` lignes d’un côté ; la suite d’une ligne coupée reste avec elle quand une autre coupe tient.
- **Sorties.** Le canvas, la visionneuse HTML et le PDF peignent les lignes et le cadre tels qu’ils sont mis en page. La visionneuse HTML conserve les espaces (`white-space: pre`) : une sélection copie le listing avec son indentation et un saut de ligne après chaque ligne de source, sans numéros ni marques de coupure. Un PDF balisé compose chaque listing comme un paragraphe contenant un élément `Code`, avec de vrais glyphes d’espace, ses numéros et ses marques de coupure étant des artefacts. L’EPUB recomposable écrit `<pre><code class="language-…">` avec les couleurs des jetons et une feuille de style tirée de `codeStyle` ; l’EPUB à mise en page fixe reprend l’imprimé.
- **Polices.** Le Sandbox et `configFontFamilies` chargent la police de code quand le texte contient un bloc délimité (ou que la configuration a une section `codeStyle`), en graisses normale et grasse, en romain et en italique ; le PDF incorpore les polices qu’utilisent les lignes.

## Parties

La propriété `parts` configure les pages de partie qu’un document ouvre avec un conteneur `:::part{number="…" title="…"}` : la page « Partie I — Fondements » qui regroupe une suite de chapitres. Une partie occupe toujours une page à elle seule : le conteneur saute à une nouvelle page de la parité configurée, la convertit en page à une seule colonne dont la zone de texte vient de `parts.margins`, pose la maquette d’ouverture sur toute la page, et saute de nouveau après le délimiteur de fermeture pour que le chapitre suivant (avec son propre `breakBefore.parity`) commence proprement ; avec les réglages par défaut du H1, on obtient la page de partie classique sur un recto, un verso blanc, et le chapitre sur le recto suivant.

```ts
const config: PostextConfig = {

    breakBefore: { parity: 'odd' },
    breakAfter: { enabled: true, parity: 'any' },
    margins: { top: { value: 9, unit: 'cm' }, left: { value: 3, unit: 'cm' }, right: { value: 3, unit: 'cm' } },
    design: {
      elements: [
        {
          kind: 'text', id: 'number', content: 'Part {numberRoman}',
          fontSize: { value: 12, unit: 'pt' }, fontWeight: 600, align: 'left',
          placement: { anchor: { to: 'page', edge: 'top-left' }, offset: { x: { value: 3, unit: 'cm' }, y: { value: 5, unit: 'cm' } }, size: { width: 'auto', height: 'auto' } },
        },
        {
          kind: 'text', id: 'title', content: '{titleText}',
          fontSize: { value: 28, unit: 'pt' }, fontWeight: 700, align: 'left', overflow: 'wrap',
          placement: { anchor: { to: '#number', edge: 'below' }, size: { width: { value: 15, unit: 'cm' }, height: 'auto' } },
```

### Variables de la maquette de partie

La zone de maquette résout le jeu de variables des titres avec les valeurs propres à la partie : `{titleText}` est le `title` du délimiteur ; `{number}`, le `number` tel qu’il est écrit ; `{numberDecimal}`, `{numberRoman}`, `{numberRomanLower}`, `{numberAlpha}`, `{numberAlphaLower}` le reformatent. Le numéro est lu comme un nombre décimal, un chiffre romain ou des chiffres chinois, avec ou sans les mots qui les encadrent (`"IV"`, `"iv"`, `"4"`, `"４"`, `"四"`, `"卷四"` et `"第四卷"` donnent tous `{numberDecimal}` = `4`), et ces variables valent `''` pour toute autre chose. `{partTitle}` / `{partNumber}`, `{chapterTitle}` / `{chapterNumber}` (le chapitre qui précède la partie), `{pageNumber}`, `{totalPages}`, `{bookTotalPages}` et les variables de métadonnées sont aussi disponibles. `{attr.<key>}` lit les attributs du H1 du chapitre en cours.

### La maquette du verso

`versoDesign` décore la page qui suit immédiatement une page de partie quand cette page ne contient rien : le dos du feuillet de partie. La partie elle-même ne laisse jamais cette page blanche. `breakAfter.parity` vaut `'any'` par défaut : le contenu qui suit le délimiteur de fermeture commence donc sur la page suivante, sauf si quelque chose demande une parité :

- **Le titre du chapitre suivant.** Le `breakBefore` par défaut du H1 est `'always-odd'`, et `'odd'` fait de même après une page de partie sur un recto : le chapitre passe au recto suivant et le verso reste blanc. La maquette du verso se peint.
- **`parts.breakAfter: { enabled: true, parity: 'odd' }`.** La partie demande elle-même le recto suivant, quoi que fasse le titre suivant. Utilisez-le quand les chapitres peuvent s’ouvrir d’un côté comme de l’autre (`breakBefore.parity: 'any'`, ou `breakBefore.enabled: false`).

Sans l’un ni l’autre, le chapitre s’ouvre sur le verso et aucune maquette de verso n’est dessinée. Avec `breakAfter.enabled: false`, le contenu continue sur la page de partie elle-même. Le verso prend la palette de la partie : un `palette="band=#…"` sur le délimiteur le recolore aussi.

```ts
parts: {
  breakBefore: { parity: 'odd' },
  breakAfter: { enabled: true, parity: 'odd' },   // always a blank verso to paint
  versoDesign: {
    elements: [{
      kind: 'box', id: 'field',
      style: { backgroundColor: { hex: '#b07d2b', model: 'hex', paletteId: 'band' } },
      placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } },
    }],
  },
}
```

**Une partie qui clôt son chapitre.** Dans un livre mis en page chapitre par chapitre (le Sandbox, `buildBundle`), une partie `:::part` peut former un chapitre à elle seule, ou terminer un chapitre. Sa page de partie est alors la dernière page du chapitre, et le chapitre suivant reprend ce que la partie doit encore : il applique `breakAfter` avant son premier bloc et peint `versoDesign` sur sa première page quand cette page reste blanche. Les pages sortent comme elles sortiraient avec tout le livre dans un seul document. Seules des directives qui ne placent rien (`:::numbering`, `:::space`) peuvent suivre le délimiteur de fermeture ; tout le reste est du contenu du chapitre, qui prend alors le saut lui-même. Un chapitre vide juste après la partie est une page à lui seul : cette page est le verso. Un hôte qui met lui-même les chapitres en page obtient ce comportement de `continuationAfter()`, qui signale `afterPartPage: true` pour un chapitre qui se termine par une partie ; transmettez-le dans la `continuation` du chapitre suivant.

### Le conteneur `:::part`

Une ligne `:::part{number="…" title="…"}` ouvre la partie et un `:::` seul la ferme ; les deux attributs sont facultatifs (ils valent `''` par défaut). Les blocs placés entre les deux (en général la liste des chapitres) s’écoulent dans la colonne unique de la page de partie avec `bodyStyle`, à partir de `margins.top` ; un contenu plus long que la page continue sur des pages ordinaires. La page est classée `role: 'part'` (`VDTPage.partInfo` contient le numéro et le titre) : les éléments d’en-tête et de pied de page peuvent donc la cibler ou l’éviter avec `pages: 'part'` / `pages: 'body'` ; le moteur PDF ajoute la partie aux signets, au-dessus de ses chapitres. Un contenu vide (`:::part{…}` directement suivi de `:::`) est le cas courant et produit quand même la page : des parties consécutives ne partagent jamais une page. Un `:::part` imbriqué dans une autre partie est aplati dans la partie extérieure.

Deux autres attributs agissent sur les chapitres de la partie. `style="<id>"` les compose dans l’un des styles de chapitre du livre (voir *Une partie dans un style de chapitre* plus bas). `page=false` (ou `no`, `0`, `off`) n’imprime pas de page de partie pour cette partie, comme le fait `parts.page: false` pour toutes : le corps du conteneur n’est pas composé, et le numéro, le titre, la palette et le style de la partie s’appliquent à partir du contenu suivant, sans saut propre. Cela convient à une partie qui se poursuit sans page de séparation, comme les pages de fin d’un livre dont les autres parties en ont une. L’attribut ne peut que supprimer la page : quand `parts.page` vaut `false`, aucune ligne `:::part` n’en ouvre.

Un troisième attribut, `palette="<id>=<hex>[, <id>=<hex>…]"`, donne à la partie ses propres couleurs : sur la page de partie et sur chaque page qui la suit, jusqu’à la partie suivante, chaque couleur de maquette (en-tête, pied de page, bandeau d’ouverture, maquettes de partie et de verso) liée à l’un de ces identifiants de palette prend la valeur de la partie au lieu de celle de la palette du document. C’est ainsi que les sections d’un livre recolorent l’onglet de coin, le point du titre courant et le bandeau d’ouverture de chapitre sans seconde maquette : `:::part{number="II" title="…" palette="band=#f6c297"}`. Le flux de texte suit aussi : sur les mêmes pages, toute couleur du flux égale à la valeur de base d’une entrée de palette remplacée (titres, couleurs du gras, de l’italique et des renvois, puces et numéros de liste, étiquettes et barres de légende, texte, filets et fonds des tableaux (en-tête, corps, lignes alternées et fond propre d’une cellule), encadrés (fond, bordure, bande, titre) et pastilles (fond, contour et texte)) prend la valeur de la partie : un `headings.levels[1].color` lié à `band` compose donc les titres de chaque section dans sa propre couleur. Les pastilles de couleur en ligne gardent la couleur écrite en elles. Les paires sont séparées par des virgules, des points-virgules ou des espaces, `=` ou `:` joint l’identifiant et la couleur, le `#` est facultatif. Une partie reste en vigueur après son délimiteur de fermeture : `{partTitle}`, `{partNumber}` et la palette suivent le flux dans les chapitres qui la suivent et, grâce à `continuation.part`, que signale `continuationAfter()`, dans les chapitres mis en page séparément : le deuxième chapitre d’une section affiche donc la section dans ses titres courants exactement comme le premier.

Deux entrées de palette peuvent partager une valeur de base et prendre pourtant des valeurs différentes dans une partie, quand la partie remplace l’une et pas l’autre ou leur donne des couleurs différentes. La valeur seule ne dit pas de quelle entrée vient une couleur du flux : chaque couleur du flux est donc rapprochée des réglages dont elle peut venir, et prend la valeur à laquelle ces réglages sont liés. Sont distingués :

- les couleurs du texte d’un bloc : la couleur du texte, les couleurs du gras, de l’italique et des renvois, la marque de liste (une puce ou un numéro) et le séparateur qui suit un numéro. Avec `bodyText.color` lié à `ink` et `bodyText.boldColor` lié à `accent`, tous deux `#1a1a1a`, une partie avec `palette="accent=#b8413d"` recolore les passages en gras et laisse le texte ; avec plutôt `unorderedLists.color` lié à `accent`, elle recolore les puces et laisse le texte des éléments ;
- chaque niveau de titre, et chaque style de titre qui fixe une couleur ;
- le texte d’une ligne de la table des matières, son numéro, ainsi que son numéro de page et son sous-titre ;
- dans chaque style d’encadré, les fonds (fond, bande, onglet), la bordure, les filets (marque et onglet) et le texte (titre, icône, glyphe de la marque, onglet) ;
- chaque couleur de chaque style de tableau, de pastille et de légende. Un style de tableau nommé est distinct de `tableStyle`, et le style de légende d’un type de ressource de `captionStyle`. Le fond propre d’une cellule suit son propre lien.

Un cas se décide encore par la valeur : des réglages situés à des endroits différents qui fixent la même couleur d’un bloc. `bodyText.color`, `bodyText.blockquote.color`, le `color` d’un style de paragraphe et le `body.color` d’un style d’encadré fixent tous la couleur du texte d’un bloc, par exemple. Quand deux d’entre eux sont liés à des entrées qui partagent une valeur de base et que la partie les distingue, la couleur prend le remplacement (le dernier écrit, quand les deux sont remplacés). Donnez à ces entrées des valeurs de base qui leur sont propres.

```ts
const resolved = resolvePartsConfig(config.parts, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => margins filled from the page, bodyStyle from the body / list configs

const minimal = stripPartsDefaults(config.parts);
// => undefined when only static defaults remain
```

## Styles de titre

La propriété `headingStyles` déclare des styles nommés qu’un document applique à un titre avec `# Title {style="<id>"}`. Un style fait deux choses. Il remplace la typographie, la maquette et la numérotation du niveau du titre (tous les champs d’une entrée de niveau sauf `level` : police, taille, couleur, `breakBefore`, `span`, `advancedDesign`, `textTransform`, `hidden`, `numberingTemplate`…) et il régit la **section** que le titre ouvre : ses pages, jusqu’au titre suivant de même niveau ou de niveau supérieur (de n’importe quel niveau avec `sectionEnd: 'heading'`), prennent les titres courants, la géométrie de page, la typographie du texte et la palette du style. C’est ainsi que les pages liminaires d’un livre (une préface sur une seule colonne large, avec des folios en chiffres romains et des bandeaux bleus) prennent place dans un manuel à deux colonnes numéroté en chiffres arabes, sans seconde configuration.

```ts
const config: PostextConfig = {
  headingStyles: [
    {
      id: 'front-matter',
      numbered: false,
      breakBefore: { enabled: true, parity: 'odd' },
      span: 'page',
      advancedDesign: { enabled: true, minHeight: { value: 52, unit: 'mm' }, slot: { elements: [/* bands, `{titleText}` */] } },
      header: { elements: [/* folio | rule | `{title}. {subtitle}` */] },
      margins: { left: { value: 50, unit: 'mm' }, right: { value: 17, unit: 'mm' } },
      layout: { layoutType: 'single' },
      bodyStyle: { fontSize: { value: 10.5, unit: 'pt' }, textAlign: 'justify' },
      palette: { band: '#547396' },
    },
  ],
};
```

Une section se ferme au titre suivant de même niveau ou de niveau supérieur : un `#` sans style après un titre stylé revient aux titres courants et à la géométrie du document ; un titre stylé ouvre sa propre section. Les pages que la section a laissées blanches pour la parité lui appartiennent, comme pour les titres de chapitre. Avec `sectionEnd: 'heading'`, la section se ferme au titre suivant de n’importe quel niveau, ce dont a besoin une couverture composée comme le seul titre de niveau 1 du livre :

```ts
headingStyles: [
  { id: 'cover', numbered: false, toc: false, header: { elements: [] }, footer: { elements: [] }, sectionEnd: 'heading' },
],
```

```md
# Le Gardien du phare {style="cover"}

## La chambre de la lanterne

…
```

La page de la couverture n’imprime aucun titre courant, et à partir de *La chambre de la lanterne* les pages reprennent l’en-tête et le pied de page du document. Avec la valeur par défaut, `'level'`, la section de la couverture durerait jusqu’au titre de niveau 1 suivant, que ce livre n’a pas, et aucune de ses pages ne porterait de titre courant.

**Un saut de page ne remplace pas le saut propre au titre.** Un style hérite du `breakBefore` de son niveau (la valeur par défaut du niveau 1 est `{ enabled: true, parity: 'always-odd' }`), et un titre l’applique où qu’il se trouve, juste après un `:::pagebreak` aussi. Le saut de page ouvre une nouvelle page, puis le titre demande encore son côté de la double page. Avec `parity: 'odd'`, un saut qui tombe sur un verso est suivi d’une page blanche : le titre s’ouvre donc sur le recto suivant. Avec `'always-odd'`, la page blanche de séparation s’ajoute aussi, et le saut de page ne change rien, puisque le titre aurait de toute façon ouvert cette page. Un style destiné à commencer sur la page qu’ouvre un saut manuel, comme une page de table des matières après la page de titre, désactive son propre saut :

```ts
headingStyles: [
  // Starts where the text puts it: on the page the `:::pagebreak` before it opened.
  { id: 'contents', numbered: false, toc: false, breakBefore: { enabled: false } },
],
```

Pour garder une page à soi sans choisir de côté, réglez plutôt `breakBefore: { parity: 'any' }` et omettez le `:::pagebreak`.

**À quelle section appartient une page.** Les titres courants et la palette se choisissent par page, non par titre. Une page prend la section en vigueur après le dernier changement de section qu’elle contient : là où une section se termine et une autre commence sur la même page (deux courtes lettres d’un dictionnaire, par exemple), la page affiche les titres courants et la palette de la seconde ; là où une section stylée se termine au milieu de la page sur un titre sans style, la page revient à ceux du document. `{chapterTitle}` suit la même règle : une page où deux chapitres se rencontrent affiche le titre du second. Les pages blanches suivent la règle des [titres de chapitre](/fr/docs/configuration-headings#à-qui-appartiennent-les-pages-blanches) : une page blanche de parité (`blankForParity`) appartient à la section qui s’ouvre après elle, et la page de séparation qu’ajoute un saut `'always-odd'` / `'always-even'` (`blankForForce`) à la section qui la précède. Une page de partie ferme la section ouverte.

```md
# A {style="letter"}

Aardvark, abacus.

# B {style="letter"}

Babble, badger… (runs on to the next page)
```

Les deux lettres commencent en page 1 : la page 1 prend donc les titres courants de la section `B`. Un onglet de tranche placé dans l’en-tête du style y affiche « B », et aucune page n’affiche l’onglet de « A ». Donnez à chaque section une page à elle (`breakBefore`) quand chacune a besoin de son onglet.

Des annexes désignées par des lettres après des chapitres numérotés, et une page de dédicace que la table des matières et les signets PDF listent, mais dont la page n’affiche pas le titre :

```ts
headingStyles: [
  { id: 'appendix', numberingTemplate: 'Appendix {1:A}' },
  { id: 'silent', hidden: true, numbered: false },
],
```

```md
# Dedication {style="silent"}

For M., who read every draft.

# Method

…

# Survey instrument {style="appendix" startAt=1}

# Raw data {style="appendix"}
```

Avec `numberingTemplate: '{1}.'` au niveau 1, les chapitres impriment *1.*, *2.*…, les annexes *Appendix A* et *Appendix B*. La dédicace ouvre sa page (le `breakBefore` de son niveau), n’imprime que son paragraphe et apparaît malgré tout sous le nom *Dedication* dans `:::toc`, dans les titres courants `{chapterTitle}` et dans les signets du PDF ; ajoutez `toc: false` au style pour l’exclure de la table des matières. Une planche ou une carte composée comme un H1 au milieu d’un chapitre demande l’inverse de la dédicace : un style avec `runningChapter: false` (en général avec `numbered: false` et `toc: false`) garde les titres courants sur le chapitre qu’elle interrompt.

```ts
const resolved = resolveHeadingStylesConfig(config.headingStyles, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => level overrides normalised, margins filled from the page, bodyStyle from the body

const minimal = stripHeadingStylesDefaults(config.headingStyles);
// => undefined when no style remains
```

## Styles de chapitre

Un livre dont les chapitres n’ont pas tous la même allure (des annexes sur deux colonnes en caractères plus petits, une partie imprimée dans une autre couleur, un glossaire avec ses propres titres courants) déclare des **styles de chapitre**, et un chapitre en prend un en le nommant dans son en-tête YAML :

```ts
interface ChapterStyleConfig {
  id: string;              // What a chapter's front matter names.
  name?: string;           // A name to show for it.
  config: ConfigOverride;  // The settings it changes.
}
```

```ts
chapterStyles: [
  {
    id: 'appendix',
    name: 'Appendix',
    config: {
      layout: { layoutType: 'double' },
      page: { margins: { left: { value: 15, unit: 'mm' }, right: { value: 15, unit: 'mm' } } },
      bodyText: { fontSize: { value: 9, unit: 'pt' } },
      header: { elements: [] },
    },
  },
],
```

```markdown
---
chapterStyle: appendix
---
# Appendix A
```

Le `config` d’un style se fusionne sur la configuration du livre comme la couche d’une langue (voir `mergeConfigLayers`) : les objets clé par clé, une couleur ou une longueur en bloc, les listes de styles entrée par entrée sur leur `id`, et `null` retire une valeur du livre. Ainsi, les colonnes et les marges, la typographie et les styles de paragraphe, de titre et d’encadré, les couleurs et les encres, les titres courants et les formats de folio peuvent changer d’un chapitre à l’autre, tandis que ce que le style ne nomme pas reste au livre. Ce que tout le livre partage reste au livre : dans `page`, le format, la résolution, les traits de coupe et la reliure ; et aussi la langue et le sens d’écriture, les chiffres, les polices déclarées et la police de symboles, les types de ressource, la production d’impression, la génération du PDF, les visionneuses et les vérifications. Un style qui en fixe un est ignoré sur ce point, et les avertissements de configuration le signalent par `chapterStyleBookSetting`. Dans le Sandbox, une modification de l’un de ces réglages faite pendant l’édition d’un style va au livre.

La numérotation des pages, les compteurs, les notes et la table des matières se poursuivent à travers le chapitre comme pour n’importe quel autre. Toutes les sorties le lisent : le canvas, le PDF, l’EPUB, le HTML et un paquet composé avec `buildBundle`, ainsi qu’un chapitre composé seul avec `buildDocument`, puisque le moteur applique le style que nomme son texte. Dans un livre, seul l’en-tête YAML du premier chapitre est celui du livre ; celui d’un chapitre ultérieur est effacé, sauf sa ligne `chapterStyle:`. Le `{style="…"}` d’un titre se superpose toujours au style du chapitre, pour une section.

L’export Word le lit aussi. Dans le document mis en page, chaque chapitre est une section Word avec les marges, les colonnes et la numérotation des pages de son style, et chaque style de paragraphe ou de caractère dont le style de chapitre change le texte reçoit sa propre version, nommée d’après lui (*Normal (Appendix)*), qu’un aller-retour par Word conserve ; les lignes `chapterStyle:` et les lignes `:::part` reviennent de Word telles qu’elles étaient. Le document sémantique garde sa page A4 simple et ne nomme à part que les styles que la mise en page simple compose encore autrement. Dans le Sandbox, la visionneuse HTML qui lit le livre entier compose elle aussi chaque chapitre dans son style. Un programme qui compose un livre entier comme un seul document indique où se trouve chaque chapitre (`content.chapters`) : le moteur compose ensemble les chapitres d’un même style, et ceux du style suivant à partir d’une nouvelle page.

Dans le Sandbox, la barre « Style de chapitre » en haut du panneau Maquette choisit ce que le panneau modifie : le livre ou l’un de ses styles. Quand un style est choisi, le panneau l’affiche par-dessus le livre, et ce que vous modifiez est conservé dans le style comme sa différence avec le livre ; la barre renomme le style, le supprime et revient au livre, et son bouton + en crée un nouveau. Un chapitre prend un style depuis son menu dans le panneau Chapitres, qui écrit pour lui la ligne `chapterStyle:` ; son entrée affiche le nom du style. Pendant qu’un style est modifié, un champ que le style fixe porte sa marque, dont le menu reprend la valeur du livre ou fait de celle du style celle du livre. Dans un livre en plusieurs langues, les styles sont conservés dans la couche que modifie le panneau : les réglages de toutes les langues ou l’édition à l’écran. Un chapitre composé dans le style de sa partie affiche ce style sur sa ligne, et le premier élément de son menu indique « Style de la partie : … ».

### Une partie dans un style de chapitre

Une partie peut composer tous ses chapitres dans un style : la ligne `:::part` le nomme avec `style`, et le chapitre que cette ligne ouvre et tous ceux qui le suivent, jusqu’à la partie suivante, sont composés dans ce style.

```markdown
:::part{number="IV" title="Annexes" style="appendix"}
:::

# Annexe A
```

Le `chapterStyle:` propre à un chapitre l’emporte sur celui de sa partie, et une partie qui ne nomme aucun style compose ses chapitres avec les réglages du livre. La ligne `:::part` se place en tête du chapitre qui ouvre la partie, avant son titre : si elle nomme un style après le début du texte du chapitre, elle déclenche un avertissement `partStyleMidChapter` et le style commence au chapitre suivant. Un chapitre composé seul reçoit le style de sa partie par sa continuation (`continuation.part.style`, que renvoie `continuationAfter()`), comme le titre et la palette de la partie. Un style que `chapterStyles` ne contient pas, nommé par `chapterStyle:` ou par une partie, déclenche un avertissement `chapterStyleUnknown`, et le chapitre est composé avec les réglages du livre. La ligne `::section{style="…"}` de postext 1.78, qui changeait de style à l’intérieur d’un chapitre, n’est plus lue : son texte reste dans le chapitre, avec les réglages du chapitre, et la ligne déclenche un avertissement `partStyleMidChapter` ; faites de ce texte un chapitre à part dans une partie de ce style, ou donnez-lui `chapterStyle:`.
