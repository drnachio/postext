# Konfiguration: Stile und Teile


## Absatzformate

Die Eigenschaft `paragraphStyles` legt benannte Stile fest, die ein Dokument mit einem Container `:::paragraphs{style="…"}` auf eine Folge von Absätzen anwendet – Literaturverzeichnisse, Glossare, Anmerkungen, jeder Block von Einträgen, der eine eigene Schrift, Schriftstärke, Neigung, Größe, einen eigenen Zeilenabstand, Versalien, Kapitälchen oder einen hängenden Einzug verlangt. Jedes typografische Feld ist optional und erbt, wenn nicht gesetzt, den Wert des Fließtexts; ein Stil nennt also nur, was vom Fließtext abweicht.

```ts
const config: PostextConfig = {
  paragraphStyles: [
    {
      id: 'bibliography',
      name: 'Bibliography',
      fontSize: { value: 7, unit: 'pt' },
      lineHeight: { value: 1.2, unit: 'em' },
      hangingIndent: { value: 2, unit: 'em' },
      spaceBetween: { value: 0.25, unit: 'em' },
      marginTop: { value: 1, unit: 'em' },
      marginBottom: { value: 1, unit: 'em' },
    },
  ],
};
```

```md
## References

:::paragraphs{style="bibliography"}
Knuth, D. E. (1984). *The TeXbook*. Addison-Wesley.

Bringhurst, R. (2004). *The Elements of Typographic Style*. Hartley & Marks.
:::
```

Ein Theaterstück setzt seine Regieanweisungen kursiv und sein Personenverzeichnis in Kapitälchen:

```ts
paragraphStyles: [
  { id: 'direction', italic: true, fontSize: { value: 9, unit: 'pt' } },
  { id: 'cast', smallCaps: true, textAlign: 'center', fontWeight: 600 },
],
```

```md
:::paragraphs{style="direction"}
Elsinore. A platform before the castle. *Francisco* at his post.
:::
```

Die Anweisung erscheint kursiv, der Name darin aufrecht; Schriftstärken, `italic` und `smallCaps` eines Stils gelten auch in Kästen.

Ein Gedichtband rückt manche Zeilen ein und rückt die Folgezeile einer für die Satzbreite zu langen Zeile tiefer ein als die Zeile selbst. `indent` rückt jede Zeile des Absatzes ein, und der hängende Einzug zählt von dort aus:

```ts
paragraphStyles: [
  { id: 'verse', textAlign: 'left', firstLineIndent: { value: 0, unit: 'em' }, hangingIndent: { value: 4, unit: 'em' } },
  { id: 'verse-indented', textAlign: 'left', indent: { value: 1.5, unit: 'em' }, hangingIndent: { value: 2.5, unit: 'em' } },
],
```

Eine Zeile in `verse-indented` beginnt bei 1,5 em und ihre Folgezeile bei 4 em, bündig mit den Folgezeilen der Zeilen in `verse`. Ohne `indent` kann ein Stil die erste Zeile einrücken oder die übrigen hängend einrücken, nicht beides: `firstLineIndent` wird ignoriert, sobald `hangingIndent` gesetzt ist.

Eine Speisekarte setzt jeden Preis bündig an das Ende der Satzbreite, hinter eine Punktlinie:

```ts
paragraphStyles: [
  {
    id: 'menu',
    textAlign: 'left',
    firstLineIndent: { value: 0, unit: 'em' },
    tabStops: [{ position: 'end', align: 'end', leader: '. ' }],
  },
],
```

```md
:::paragraphs{style="menu"}
Onion soup :tab 8.50

Grilled sea bream with fennel and lemon :tab 21.00
:::
```

Die Punkte jeder Zeile enden ein halbes Geviert vor dem Preis (`leaderGap`). Ein Gericht, das für seine Zeile zu lang ist, wird umbrochen, und seine letzte Zeile behält Punktlinie und Preis; passt der Preis nicht neben das letzte Wort, geht dieses Wort mit ihm in die nächste Zeile.

### Der Container `:::paragraphs`

Eine Zeile `:::paragraphs{style="<id>"}` öffnet den Container, eine bloße Zeile `:::` schließt ihn; jeder Absatz dazwischen erhält den benannten Stil, während Überschriften, Listen und andere Blöcke darin ihre übliche Gestaltung behalten. Container dürfen in anderen Containern verschachtelt werden. Eine unbekannte `style`-ID ist kein Fehler: Die Absätze erscheinen als schlichter Fließtext, und die Sandbox meldet die ID.

Die öffnende Zeile nimmt außerdem `align` (`start`, `end`, `left`, `right`, `center`, `justify`), `indent` und `endIndent` (bloße Zahlen sind Geviert) an, mit oder ohne Stil: Mit Stil überschreiben sie ihn; ohne gelten sie über dem Stil des umschließenden Containers oder über dem Textstil an der Stelle des Blocks (der Fließtext, ein Teil, ein gestalteter Abschnitt oder ein Kasten). `:::paragraphs{align=end}` setzt einen Block bündig an das Zeilenende (地付き) und `:::paragraphs{align=end endIndent=1}` ein Zeichen davor. Seit postext 1.16.

Im Container verlässt der Textfluss das Grundlinienraster – ein Eintrag in 7 pt mit 1,2 em Zeilenabstand passt nicht auf ein Raster von 8 pt/1,5 em –, und der letzte Absatz rastet den Fluss wieder darauf ein (das Raster hat Vorrang; der Abstand darunter ist ein Mindestwert, dieselbe Konvention, der Überschriften folgen). Einträge teilen sich über Spalten und Seiten wie Absätze des Fließtexts, mit demselben Schutz vor Witwen und Waisen; eine Überschrift unmittelbar vor dem Container bleibt bei dessen erstem Absatz.

Der Abstand unter dem Container ist der größere von `spaceBetween` und `marginBottom` des Stils und dem Absatzabstand des umgebenden Texts (eine Zeile, wenn `bodyText.paragraphSpacing` eingeschaltet ist), und er verschmilzt mit dem Abstand, den der nächste Block über sich hält, wie es der Abstand zwischen zwei Absätzen des Fließtexts tut: Eine Überschrift nach einem Literaturverzeichnis steht um ihr eigenes `marginTop` unter dem letzten Eintrag (oder um den Abstand des Stils, wenn dieser größer ist), und ein Absatz nach einer Gruppe engerer Einträge behält den Absatzabstand des Texts. Der Fluss rastet zuerst unter dem Text wieder auf das Raster ein, und was das Einrasten nicht abgedeckt hat, wird in ganzen Rasterzeilen weitergeführt, sodass der Text nach dem Container auf dem Raster steht. Bis postext 1.4 wurde der Abstand des Stils vor dem Einrasten unter die letzte Zeile gesetzt und der obere Abstand des nächsten Blocks darunter addiert, und der Absatzabstand blieb außen vor; `bodyText.paragraphContainerSpacing: 'add'` behält diese Regel, und vorher gespeicherte Konfigurationen werden damit gelesen. Ein Stil mit `snapToGrid: false` rastet nicht ein: Der Text nach dem Container steht um den genauen Abstand darunter, außerhalb des Rasters bis zum nächsten einrastenden Block. Ein Container, der mit einer Liste schließt, wird unter beiden Regeln wie in 1.4 gesetzt: Die Liste behält ihren eigenen Abstand darunter, und `marginBottom` folgt diesem Abstand und verschmilzt mit dem des nächsten Blocks.

Ein Stil kann die Regel für seine eigenen Container mit `containerSpacing` festlegen: `'add'` am Stil einer großen Kennzahl (einer groß gesetzten Zahl) oder eines Literaturverzeichnisses beendet seine Gruppen mit dem eigenen Abstand des Stils, im Text und in einem Kasten, während jeder andere Container des Dokuments `'collapse'` behält; `'collapse'` an einem Stil bewirkt das Umgekehrte in einem Dokument, das mit `'add'` gelesen wird. Ein Container, der keinen Stil nennt, folgt dem Dokument.

In einem `:::callout` übernimmt der Container die Außenabstände seines Stils auf dieselbe Weise: `marginTop` und `marginBottom` fallen mit dem Abstand der umgebenden Blöcke zusammen (ein negativer Wert zieht sie näher heran), und ein Container, der den Kasten eröffnet, erhält keinen oberen Außenabstand, wie am Kopf einer Spalte. Ein Kasten hat kein Grundlinienraster zum Einrasten, daher ist der Abstand unter dem letzten Absatz der größte von `marginBottom`, `spaceBetween` und dem eigenen Absatzabstand des Kastens (sein `body.paragraphSpacing`, eine Zeile seines Texts; entfällt mit `paragraphContainerSpacing: 'add'`), oder der eigene obere Außenabstand des nächsten Blocks, wenn dieser noch größer ist; ein negatives `marginBottom` zieht stattdessen den nächsten Block nach oben. (Bis postext 1.4 ignorierte ein Container in einem Kasten beide Außenabstände.)

Im Kasten kommen die Satzfelder, die ein Stil offen lässt, aus dem Kasten (seit postext 1.52): Schrift, Größe, Zeilenabstand, Stärken und Farbe, die der Stil dem Text überlässt, sind die des Kastentexts, sodass `:::paragraphs{style="centred"}` mit einem Stil, der nur `textAlign: 'center'` setzt, im einen Kasten in der Grotesk und im anderen in der Antiqua steht. Felder, die der Stil setzt, bleiben. `bodyText.paragraphStylesInBoxes: 'document'` behält stattdessen den Text des Dokuments, wie bis postext 1.51.

```ts
const resolved = resolveParagraphStylesConfig(config.paragraphStyles, resolvedBodyText);
// => every unset field filled from the resolved body text

const minimal  = stripParagraphStylesDefaults(config.paragraphStyles);
// => undefined when the list is empty; zero margins and `name === id` dropped
```


## Chip-Stile

Die Eigenschaft `chipStyles` deklariert die benannten Stile des Inline-Elements `:chip[text]{style="…"}` – die abgerundeten, getönten Kästchen eines Wortspeichers, einer Tastaturtaste, eines Schlagworts (Syntax und Umbruchregeln stehen in der Referenz zum Dokumentformat). const config: PostextConfig = {

## Hervorhebungsstile

## Code-Listings

Die Eigenschaft `codeStyle` legt fest, wie Code-Listings aussehen: die mit ```` ``` ```` und `~~~` abgegrenzten Codeblöcke des Texts (siehe [Dokumentformat › Codeblöcke](/de/docs/document-format#codeblöcke)) und Inline-Code, wenn er eine Code-Schrift verlangt. Ein Listing wird Zeile für Zeile so gesetzt, wie es geschrieben ist, in einer dicktengleichen Schrift, in einem Kasten: Keine Zeile wird getrennt oder im Blocksatz gesetzt, jedes Leerzeichen behält seine Breite, und ein Tabulator springt zum nächsten Tabstopp. Der Kasten stammt aus derselben Mechanik wie ein `:::callout`, sodass sich ein Listing zwischen Zeilen über Spalten und Seiten teilt, jeder Teil in einem eigenen Kasten, und ein Codeblock in einem Kasten ein darin verschachtelter Kasten ist. Ein Host bindet mit `registerCodeHighlighter` seinen eigenen Highlighter ein (Shiki, Prism, highlight.js). Konfigurationen sind serialisierbare Daten, daher wird die Funktion bei der Engine registriert, nicht in `codeStyle` geschrieben:

```ts
import { registerCodeHighlighter } from 'postext';

// fn(code, lang) returns the listing's lines, each as runs whose texts join into the line.
registerCodeHighlighter('rust', (code) => code.split('\n').map((line) => [
  { text: line, token: line.trimStart().startsWith('//') ? 'comment' : undefined },
]));
registerCodeHighlighter('*', null); // remove the one registered for every language
```

Ein für eine Sprache registrierter Highlighter hat Vorrang vor einem für `'*'` registrierten, der wiederum Vorrang vor dem eingebauten Tokenizer hat. ### Wie ein Listing gesetzt wird

- **Eine Zeile pro Quellzeile.** Die Zeilen werden aus den eigenen Dickten der Code-Schrift gebildet, nicht vom Absatzumbruch: Leerzeichen behalten ihre Breite, eine Folge davon bleibt erhalten, führende Leerzeichen rücken ein. Ein Listing in einem Buch mit Leserichtung von rechts nach links liest sich von links nach rechts, seine Zeilen werden von der gegenüberliegenden Seite des Kastens aus gesetzt, wie ein Zitat mit Leserichtung von links nach rechts, seine Nummern stehen in der Leiste links davon. In einem vertikal gesetzten Buch folgt ein Listing dem vertikalen Fluss (sein lateinischer Text seitlich gedreht, wie ihn vertikaler Text setzt) und erhält keine Zeilennummern.
- **Teilung.** Ein Listing, das höher als der verbleibende Raum ist, teilt sich zwischen Zeilen über Spalten und Seiten, jeder Teil als eigener Kasten gerahmt, und lässt nie weniger als `splitMinLines` Zeilen auf einer Seite; der Rest einer umbrochenen Zeile bleibt bei ihr, wenn ein anderer Schnitt passt.
- **Ausgabeformate.** Canvas, HTML-Betrachter und PDF zeichnen die Zeilen und den Kasten so, wie sie gesetzt sind. Der HTML-Betrachter behält die Leerzeichen (`white-space: pre`), sodass eine Auswahl das Listing mit seiner Einrückung und einem Zeilenvorschub nach jeder Quellzeile kopiert, ohne Nummern oder Umbruchzeichen. Ein getaggtes PDF setzt jedes Listing als Absatz mit einem Element `Code`, mit echten Leerzeichen-Glyphen, seine Nummern und Umbruchzeichen als Artefakte. Das umfließende EPUB schreibt `<pre><code class="language-…">` mit den Farben der Token und einem Stylesheet aus `codeStyle`; das EPUB mit festem Layout entspricht dem Druck.
- **Schriften.** Die Sandbox und `configFontFamilies` laden die Code-Schrift, wenn der Text einen Codeblock enthält (oder die Konfiguration einen Abschnitt `codeStyle` hat), in ihren normalen und fetten Schnitten, aufrecht und kursiv; das PDF bettet die Schnitte ein, die die Zeilen verwenden.

## Teile

Die Eigenschaft `parts` konfiguriert die Teiltitelseiten, die ein Dokument mit einem Container `:::part{number="…" title="…"}` eröffnet – die Seite „Teil I – Grundlagen“, die eine Folge von Kapiteln zusammenfasst. Ein Teil belegt immer eine eigene Seite: Der Container beginnt eine neue Seite der konfigurierten Parität, wandelt sie in eine einspaltige Seite um, deren Textbereich aus `parts.margins` stammt, legt die Auftaktgestaltung über die ganze Seite und erzwingt nach der schließenden Zeile erneut einen Seitenumbruch, sodass das nächste Kapitel (mit seinem eigenen `breakBefore.parity`) sauber beginnt – mit den Standardeinstellungen für H1 ergibt das die klassische Teiltitelseite rechts, eine leere linke Seite und das Kapitel auf der nächsten rechten Seite.

### Platzhalter der Teilgestaltung

Das Gestaltungsfeld löst die Platzhalter der Überschriften mit den eigenen Werten des Teils auf: `{titleText}` ist der `title` der öffnenden Zeile; `{number}` die `number` genau so, wie sie geschrieben ist; `{numberDecimal}`, `{numberRoman}`, `{numberRomanLower}`, `{numberAlpha}`, `{numberAlphaLower}` formatieren sie um – die Nummer wird als Dezimalzahl, römische Zahl oder chinesische Zahlzeichen gelesen, mit oder ohne die Wörter, die sie einrahmen (`"IV"`, `"iv"`, `"4"`, `"４"`, `"四"`, `"卷四"` und `"第四卷"` ergeben alle `{numberDecimal}` = `4`), und ergeben bei allem anderen `''`. `{partTitle}` / `{partNumber}`, `{chapterTitle}` / `{chapterNumber}` (das Kapitel vor dem Teil), `{pageNumber}`, `{totalPages}`, `{bookTotalPages}` und die Metadaten-Platzhalter stehen ebenfalls zur Verfügung. `{attr.<key>}` liest die Attribute der H1 des aktuellen Kapitels.

### Die Gestaltung der linken Seite

`versoDesign` schmückt die Seite direkt nach einer Teiltitelseite, wenn diese Seite keinen Inhalt hat: die Rückseite des Teiltitelblatts. Der Teil selbst lässt diese Seite nie leer. `breakAfter.parity` ist standardmäßig `'any'`, sodass der Inhalt nach dem Teilblock auf der unmittelbar folgenden Seite beginnt, sofern nicht etwas eine Parität verlangt:

- **Die Überschrift des nächsten Kapitels.** Das Standard-`breakBefore` von H1 ist `'always-odd'`, und `'odd'` bewirkt nach einer rechten Teiltitelseite dasselbe: Das Kapitel wandert auf die nächste rechte Seite, und die linke bleibt leer. Die Gestaltung der linken Seite wird gezeichnet.
- **`parts.breakAfter: { enabled: true, parity: 'odd' }`.** Der Teil verlangt selbst die nächste rechte Seite, was immer die nächste Überschrift tut. Verwenden Sie es, wenn Kapitel auf beiden Seiten beginnen dürfen (`breakBefore.parity: 'any'` oder `breakBefore.enabled: false`).

Mit keinem von beiden beginnt das Kapitel auf der linken Seite, und es wird keine Gestaltung der linken Seite gezeichnet. Mit `breakAfter.enabled: false` geht der Inhalt auf der Teiltitelseite selbst weiter. Die linke Seite übernimmt die Palette des Teils, sodass ein `palette="band=#…"` in der öffnenden Zeile auch sie umfärbt.

```ts
parts: {
  breakBefore: { parity: 'odd' },
  breakAfter: { enabled: true, parity: 'odd' },   // always a blank verso to paint
  versoDesign: {
    elements: [{
      kind: 'box', id: 'field',
      style: { backgroundColor: { hex: '#b07d2b', model: 'hex', paletteId: 'band' } },
      placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } },
    }],
  },
}
```

**Ein Teil, der sein Kapitel abschließt.** In einem Buch, das Kapitel für Kapitel gesetzt wird (die Sandbox, `buildBundle`), kann ein `:::part`-Block ein eigenes Kapitel sein oder das Ende eines Kapitels. Seine Teiltitelseite ist dann die letzte Seite des Kapitels, und das nächste Kapitel übernimmt, was der Teil noch schuldet: Es wendet `breakAfter` vor seinem ersten Block an und zeichnet `versoDesign` auf seiner ersten Seite, wenn diese leer bleibt. Die Seiten fallen so aus, wie sie es mit dem ganzen Buch in einem Dokument täten. Nur Direktiven, die nichts platzieren (`:::numbering`, `:::space`), dürfen dem Block folgen; alles andere ist Inhalt des Kapitels, das dann den Umbruch selbst übernimmt. Ein leeres Kapitel direkt nach dem Teil ist eine eigene Seite: Diese Seite ist die linke Seite. Ein Host, der Kapitel selbst setzt, erhält dies von `continuationAfter()`, das für ein Kapitel, das mit einem Teil endet, `afterPartPage: true` meldet; geben Sie es in der `continuation` des nächsten Kapitels weiter.

### Der Container `:::part`

Eine Zeile `:::part{number="…" title="…"}` öffnet den Teil, ein bloßes `:::` schließt ihn; beide Attribute sind optional (Standard ist `''`). Die Blöcke dazwischen – typischerweise die Kapitelliste – fließen mit `bodyStyle` in der einzigen Spalte der Teiltitelseite, beginnend bei `margins.top`; ein Inhalt, der länger als die Seite ist, geht auf gewöhnlichen Seiten weiter. Die Seite wird als `role: 'part'` eingestuft (`VDTPage.partInfo` enthält Nummer und Titel), sodass Elemente der Kopf- und Fußzeile sie mit `pages: 'part'` / `pages: 'body'` ansteuern oder auslassen können; die PDF-Ausgabe fügt den Teil der Gliederung über seinen Kapiteln hinzu. Ein leerer Inhalt (`:::part{…}` direkt gefolgt von `:::`) ist der übliche Fall und erzeugt trotzdem die Seite – aufeinanderfolgende Teile teilen sich nie eine. Ein in einem anderen Teil verschachteltes `:::part` wird in den äußeren eingeebnet.

Ein drittes Attribut, `palette="<id>=<hex>[, <id>=<hex>…]"`, gibt dem Teil eigene Farben: Auf der Teiltitelseite und auf jeder folgenden Seite – bis zum nächsten Teil – nimmt jede Gestaltungsfarbe (Kopfzeile, Fußzeile, Auftaktband, Teil- und Rückseitengestaltung), die an eine dieser Paletten-IDs gebunden ist, den Wert des Teils statt den der Dokumentpalette an. So färben die Abschnitte eines Buchs das Etikett in der Ecke, den Punkt im Kolumnentitel und das Band des Kapitelauftakts ohne zweite Gestaltung um: `:::part{number="II" title="…" palette="band=#f6c297"}`. Der Textfluss folgt ebenfalls: Auf denselben Seiten nimmt jede Flussfarbe, die dem Grundwert eines überschriebenen Paletteneintrags gleicht – Farben von Überschriften, Fettem, Kursivem und Verweisen, Aufzählungszeichen und Listennummern, Legendenbezeichnungen und Legendenbalken, Tabellentext, Tabellenlinien und -flächen (Kopf, Inhalt, Zebrastreifen und die eigene Fläche einer Zelle), Kästen (Hintergrund, Kontur, Streifen, Titel) und Chips (Fläche, Umrisslinie und Text) –, den Wert des Teils an, sodass ein an `band` gebundenes `headings.levels[1].color` die Überschriften jedes Abschnitts in dessen eigener Farbe setzt. Inline-Farbfelder behalten die in ihnen geschriebene Farbe. Paare werden durch Kommas, Semikolons oder Leerzeichen getrennt, `=` oder `:` verbindet ID und Farbe, das `#` ist optional. Ein Teil bleibt wirksam, nachdem sein Block geschlossen ist: `{partTitle}`, `{partNumber}` und die Palette folgen dem Fluss in die Kapitel danach und – über `continuation.part`, das `continuationAfter()` meldet – in einzeln gesetzte Kapitel, sodass das zweite Kapitel eines Abschnitts den Abschnitt in seinen Kolumnentiteln genau wie das erste zeigt.

Zwei Paletteneinträge können denselben Grundwert haben und in einem Teil dennoch unterschiedliche Werte annehmen, wenn der Teil den einen überschreibt und den anderen nicht oder ihnen verschiedene Farben gibt. Der Wert allein sagt nicht, aus welchem Eintrag eine Flussfarbe stammt; daher wird jede Farbe des Flusses mit den Einstellungen abgeglichen, aus denen sie stammen kann, und nimmt den Wert an, an den diese Einstellungen gebunden sind. Unterschieden werden:

- die Farben des Texts eines Blocks: die Textfarbe, die Farben von Fettem, Kursivem und Verweisen, das Listenzeichen (ein Aufzählungszeichen oder eine Nummer) und das Trennzeichen nach einer Nummer. Mit `bodyText.color` an `ink` und `bodyText.boldColor` an `accent` gebunden, beide `#1a1a1a`, färbt ein Teil mit `palette="accent=#b8413d"` den fetten Text um und lässt den übrigen Text unverändert; ist stattdessen `unorderedLists.color` an `accent` gebunden, färbt er die Aufzählungszeichen um und lässt den Text der Einträge unverändert;
- jede Überschriftenebene und jeder Überschriftenstil, der eine Farbe setzt;
- der Text einer Zeile des Inhaltsverzeichnisses, ihre Nummer sowie ihre Seitenzahl und ihr Untertitel;
- in jedem Kastenstil die Flächen (Hintergrund, Streifen, Etikett), die Kontur, die Linien (Marke und Etikett) und der Text (Titel, Symbol, Zeichen der Marke, Etikett);
- jede Farbe jedes Tabellen-, Chip- und Legendenstils. Ein benannter Tabellenstil ist von `tableStyle` getrennt, der Legendenstil eines Ressourcentyps von `captionStyle`. Die eigene Fläche einer Zelle folgt ihrer eigenen Bindung.

Ein Fall wird weiterhin nach dem Wert entschieden: Einstellungen an verschiedenen Stellen, die dieselbe Farbe eines Blocks setzen. `bodyText.color`, `bodyText.blockquote.color`, das `color` eines Absatzformats und das `body.color` eines Kastenstils setzen beispielsweise alle die Textfarbe eines Blocks. Sind zwei davon an Einträge mit demselben Grundwert gebunden und unterscheidet der Teil sie, nimmt die Farbe die Überschreibung an (die zuletzt geschriebene, wenn beide überschrieben sind). Geben Sie solchen Einträgen eigene Grundwerte.

```ts
const resolved = resolvePartsConfig(config.parts, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => margins filled from the page, bodyStyle from the body / list configs

const minimal = stripPartsDefaults(config.parts);
// => undefined when only static defaults remain
```

## Überschriftenstile

Die Eigenschaft `headingStyles` deklariert benannte Stile, die ein Dokument mit `# Title {style="<id>"}` auf eine Überschrift anwendet. Ein Stil leistet zweierlei. Er überschreibt Typografie, Gestaltung und Nummerierung der Überschriftenebene – jedes Feld eines Ebeneneintrags außer `level` (Schrift, Größe, Farbe, `breakBefore`, `span`, `advancedDesign`, `textTransform`, `hidden`, `numberingTemplate` …) –, und er bestimmt den **Abschnitt**, den die Überschrift eröffnet: Dessen Seiten, bis zur nächsten Überschrift derselben oder einer höheren Ebene (jeder Ebene mit `sectionEnd: 'heading'`), übernehmen Kolumnentitel, Seitengeometrie, Texttypografie und Palette des Stils. So steht die Titelei eines Buchs (ein Vorwort in einer einzigen breiten Spalte mit römischen Seitenzahlen und blauen Bändern) in einem zweispaltigen, dezimal nummerierten Handbuch, ohne dass es eine zweite Konfiguration braucht.

```ts
const config: PostextConfig = {
  headingStyles: [
    {
      id: 'front-matter',
      numbered: false,
      breakBefore: { enabled: true, parity: 'odd' },
      span: 'page',
      advancedDesign: { enabled: true, minHeight: { value: 52, unit: 'mm' }, slot: { elements: [/* bands, `{titleText}` */] } },
      header: { elements: [/* folio | rule | `{title}. {subtitle}` */] },
      margins: { left: { value: 50, unit: 'mm' }, right: { value: 17, unit: 'mm' } },
      layout: { layoutType: 'single' },
      bodyStyle: { fontSize: { value: 10.5, unit: 'pt' }, textAlign: 'justify' },
      palette: { band: '#547396' },
    },
  ],
};
```

Ein Abschnitt endet an der nächsten Überschrift derselben oder einer höheren Ebene: Ein ungestaltetes `#` nach einem gestalteten kehrt zu Kolumnentiteln und Geometrie des Dokuments zurück; ein gestaltetes eröffnet seinen eigenen Abschnitt. Seiten, die der Abschnitt für die Parität leer gelassen hat, gehören zu ihm, wie es bei Kapiteltiteln der Fall ist. Mit `sectionEnd: 'heading'` endet der Abschnitt an der nächsten Überschrift jeder Ebene, wie es ein Umschlag braucht, der als einzige Überschrift der Ebene 1 im Buch gesetzt ist:

```ts
headingStyles: [
  { id: 'cover', numbered: false, toc: false, header: { elements: [] }, footer: { elements: [] }, sectionEnd: 'heading' },
],
```

```md
# Der Leuchtturmwärter {style="cover"}

## Die Laternenstube

…
```

Die Seite des Umschlags druckt keine Kolumnentitel, und ab *Die Laternenstube* übernehmen die Seiten wieder Kopf- und Fußzeile des Dokuments. Mit dem Standardwert `'level'` dauerte der Abschnitt des Umschlags bis zur nächsten Überschrift der Ebene 1, die dieses Buch nicht hat, und keine seiner Seiten trüge einen Kolumnentitel.

**Ein Seitenumbruch ersetzt nicht den eigenen Umbruch der Überschrift.** Ein Stil erbt das `breakBefore` seiner Ebene (der Standard für Ebene 1 ist `{ enabled: true, parity: 'always-odd' }`), und eine Überschrift wendet es an, wo immer sie steht, auch direkt nach einem `:::pagebreak`. Der Seitenumbruch eröffnet eine neue Seite, und die Überschrift verlangt dann trotzdem ihre Seite der Doppelseite. Mit `parity: 'odd'` folgt auf einen Umbruch, der auf eine linke Seite fällt, eine Vakatseite, sodass die Überschrift auf der nächsten rechten Seite beginnt. Mit `'always-odd'` kommt auch die trennende Vakatseite hinzu, und der Seitenumbruch ändert nichts, da die Überschrift diese Seite ohnehin eröffnet hätte. Ein Stil, der auf der Seite beginnen soll, die ein manueller Umbruch eröffnet, etwa eine Inhaltsseite nach der Titelseite, schaltet seinen eigenen Umbruch aus:

```ts
headingStyles: [
  // Starts where the text puts it: on the page the `:::pagebreak` before it opened.
  { id: 'contents', numbered: false, toc: false, breakBefore: { enabled: false } },
],
```

Um eine eigene Seite zu behalten, ohne eine Seite der Doppelseite zu wählen, setzen Sie stattdessen `breakBefore: { parity: 'any' }` und lassen das `:::pagebreak` weg.

**Zu welchem Abschnitt eine Seite gehört.** Kolumnentitel und Palette werden pro Seite gewählt, nicht pro Überschrift. Eine Seite übernimmt den Abschnitt, der nach dem letzten Abschnittswechsel auf ihr gilt: Wo ein Abschnitt auf derselben Seite endet und ein anderer beginnt – etwa zwei kurze Buchstaben eines Wörterbuchs –, trägt die Seite Kolumnentitel und Palette des zweiten; wo ein gestalteter Abschnitt mitten auf der Seite an einer ungestalteten Überschrift endet, kehrt die Seite zu denen des Dokuments zurück. `{chapterTitle}` folgt derselben Regel: Eine Seite, auf der zwei Kapitel zusammentreffen, zeigt den Titel des späteren. Leere Seiten folgen der Regel für [Kapiteltitel](/de/docs/configuration-headings#zugehörigkeit-leerer-seiten): Eine Vakatseite für die Parität (`blankForParity`) gehört zum Abschnitt, der nach ihr beginnt, und die Trennseite, die ein Umbruch `'always-odd'` / `'always-even'` hinzufügt (`blankForForce`), zum Abschnitt davor. Ein Teiltitel schließt den offenen Abschnitt.

```md
# A {style="letter"}

Aardvark, abacus.

# B {style="letter"}

Babble, badger… (runs on to the next page)
```

Beide Buchstaben beginnen auf Seite 1, also übernimmt Seite 1 die Kolumnentitel des Abschnitts `B`: Ein im Kopf des Stils gesetztes Daumenregister zeigt dort „B“, und keine Seite trägt das Register für „A“. Geben Sie jedem Abschnitt eine eigene Seite (`breakBefore`), wenn jeder sein Daumenregister braucht.

Mit Buchstaben gezählte Anhänge nach nummerierten Kapiteln und eine Widmungsseite, die Inhaltsverzeichnis und PDF-Lesezeichen aufführen, die Seite selbst aber nicht betitelt:

```ts
headingStyles: [
  { id: 'appendix', numberingTemplate: 'Appendix {1:A}' },
  { id: 'silent', hidden: true, numbered: false },
],
```

```md
# Dedication {style="silent"}

For M., who read every draft.

# Method

…

# Survey instrument {style="appendix" startAt=1}

# Raw data {style="appendix"}
```

Mit `numberingTemplate: '{1}.'` auf Ebene 1 erscheinen die Kapitel als *1.*, *2.* …, die Anhänge als *Appendix A* und *Appendix B*. Die Widmung eröffnet ihre Seite (das `breakBefore` ihrer Ebene), zeigt nur ihren Absatz und erscheint trotzdem als *Dedication* in `:::toc`, in Kolumnentiteln mit `{chapterTitle}` und in der PDF-Gliederung – fügen Sie dem Stil `toc: false` hinzu, um sie aus dem Inhaltsverzeichnis herauszuhalten. Eine Tafel oder Karte, die mitten in einem Kapitel als H1 gesetzt ist, verlangt das Gegenteil der Widmung: Ein Stil mit `runningChapter: false` (meist mit `numbered: false` und `toc: false`) hält die Kolumnentitel bei dem Kapitel, das sie unterbricht.

```ts
const resolved = resolveHeadingStylesConfig(config.headingStyles, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => level overrides normalised, margins filled from the page, bodyStyle from the body

const minimal = stripHeadingStylesDefaults(config.headingStyles);
// => undefined when no style remains
```
