# Sandbox

**An interactive playground for the Postext layout engine.**

The Sandbox provides a VS Code-like interface where you can write markdown, manage resources and fonts, adjust layout configuration, and see the results rendered in real time through three synchronized output modes — **canvas**, **HTML** and **PDF**. It is designed for experimentation: tweak typography settings, change column counts, test resource placement strategies, and watch how the engine responds.

## Interface layout

The Sandbox follows a familiar IDE paradigm with three main areas: a narrow **activity bar** for switching panels, a resizable **sidebar** hosting the active panel, and a **viewport** on the right with the three output tabs.

### Activity bar

A narrow strip on the left edge contains icon buttons for navigating between panels. The top section holds six panel toggles, top to bottom:

- **Projects** (`Files` icon) — Opens the projects panel: local projects plus the read-only preset bundles
- **Markdown Editor** (`FileCode` icon) — Opens the markdown editing panel
- **Resources** (`FolderOpen` icon) — Opens the resource management panel
- **Fonts** (`Type` icon) — Opens the custom font management panel
- **Configuration** (`Settings2` icon) — Opens the layout configuration panel
- **Warnings** (`AlertTriangle` icon) — Opens the diagnostics panel; the icon carries a live count badge of current warnings, capped at `99+`

Clicking the active panel's icon collapses the sidebar. Clicking a different icon switches to that panel.

The bar also hosts slots injected by the host application: an optional **home logo link** at the very top (via the `homeUrl` or `homeLink` props), plus a **theme toggle** and a **language switcher** at the bottom. The Export and Import buttons that used to live here are gone — whole projects are exchanged as `.postext` files from the Projects panel, and the Markdown and Configuration panel headers export their own part (see [Export and import](#export-and-import)).

### Sidebar panels

The sidebar is resizable: drag the separator between the sidebar and the viewport to adjust its width (the viewport always keeps at least 200 px for itself). The sidebar collapses entirely when no panel is active, and its width is remembered between sessions.

#### Markdown editor

A CodeMirror 6-based editor with:

- **Syntax highlighting** — Headings, emphasis, links, code blocks, and blockquotes are visually distinct, with dedicated highlighting for **YAML frontmatter** and **LaTeX math** regions
- **Line numbers** and active line highlighting
- **Line wrapping** for long paragraphs
- **Toolbar** — Starts with **Undo / Redo**, followed by bold, italic, heading levels 1–3, link, inline code, blockquote, ordered and unordered lists, plus two directive inserters:
  - `:::pagebreak`
  - `:::numbering{format="decimal" startAt=1}` — inserted with example attributes ready to adjust

Host applications can extend the toolbar with their own `extraActions`. The editor also reports its cursor and selection to the previews, enabling click-to-caret sync: clicking text in the rendered output moves the caret to the matching markdown position, and the previews can highlight the current selection.

The panel header offers three actions:

- **Reset** (confirm popover) — Reloads the **document part** of the active preset: the markdown and the whole resource set are replaced with the preset's (for the built-in preset, the locale's sample document and example resources); the configuration is left alone except for the preset's custom fonts. See [Projects panel](#projects-panel).
- **Export** — Downloads the markdown as a plain `.md` file (named after the active project, or `document.md`)
- **Import** — Replaces the document with the contents of a `.md` file

#### Projects panel

The first panel in the activity bar. It has two groups:

- **Projects** — Local, editable documents stored in the browser (IndexedDB). While a project is active, the working document *is* that project: every edit to the markdown, configuration, resources and fonts is saved into it automatically (with the same 1-second debounce as `localStorage`), so switching projects and back restores everything. Projects are created with the header buttons — **New from current** (copies the active document, its resources and fonts into a new project), **New blank** — or by duplicating any row. Each project row offers **Rename** (inline, Enter commits and Escape cancels; the active row also renames on double-click), **Duplicate**, **Export** and **Delete** (confirm popover). Opening a project never asks for confirmation unless a preset with unsaved edits is active. Deleting the active project falls back to the built-in preset.
- **Presets** — Read-only starting points, listed below the projects. **Duplicate as project** turns any preset into a local project that owns its own copies of the bundle's files, so later edits to the bundle on disk never touch the project; **Export** downloads the preset as a `.postext` file.

The header also carries **Import** (a `.postext` file becomes a new, active project) and **Export** (the active document, project or preset, as `.postext`). A `.postext` file is a preset bundle directory zipped (see [Export and import](#export-and-import)).

Reset buttons in the Markdown and Configuration panels restore the preset a project was duplicated from; a blank or imported project has no baseline, so they are hidden while it is active.

##### Presets

A **preset bundle** is a whole starting point loaded as one unit: a markdown document, a `PostextConfig`, the resources (with their bitmap/SVG payloads and table models), and the custom font files the config refers to. The panel lists every preset the sandbox can reach and marks the active one:

- **Built-in preset** — *Postext guide*, the default sample document shipped with the package, always available and always first in the list. It is a **public** preset.
- **Remote presets** — Bundles served over HTTP from the base URLs passed in the `presetSources` prop (see [Props](#props)). Each source is either public or **private**; private presets are tagged *Private* in the list and are meant for material that must not leave a machine — the public website only advertises a private source in local development, where the Next.js app serves the folder named by `POSTEXT_PRIVATE_PRESETS_DIR` through `/api/private-presets`. Production never lists it.
- **`default: true`** — A private preset flagged as default is loaded automatically the first time a *pristine* sandbox (untouched built-in document) opens; when several are flagged, the one whose `locale` matches the UI locale wins. Public presets are never auto-loaded.

Each row shows the preset's name, an optional description, its locale tag and its *Private* / *Default* tags. Clicking a row (confirm popover) loads the preset **in full** — document, resources, configuration and fonts — after writing the font files and resource blobs to IndexedDB, so the viewports never see a half-applied document. The active row carries a **Reload** text button and the panel header a matching icon; both reload the active preset in full. Loading a *different* preset always asks for confirmation; reloading the active one only asks when the document has local changes (an untouched document makes the reload idempotent).

**Live presets.** Remote presets are followed automatically: whenever a preset is applied the sandbox records the bundle's *fingerprint* along with hashes of the markdown, configuration and resource set it applied. While the page is visible it polls the fingerprint every 3 seconds (and immediately when the tab becomes visible or the window regains focus). When the fingerprint changes:

- If the document is **untouched** — markdown, configuration and resources still hash to what the preset applied — the preset is re-applied in full and a brief *Preset updated from disk* notice appears in the panel.
- If there are **local changes**, they are kept: a persistent banner at the top of the panel (*The preset has changed on disk. Your local changes are kept.*) offers a **Reload** button, and the Projects icon in the activity bar shows a dot until the preset is reloaded. Bundles are only followed while a preset is active; a project duplicated from one keeps its own copy.

The same check runs on load, so editing a bundle and then opening the sandbox picks the new version up when the document was untouched. The fingerprint comes from `<preset-dir>/fingerprint.json`, a virtual file the development route answers with a metadata-only hash of the directory (see the [Preset bundle format](#preset-bundle-format) appendix); sources that do not serve it simply are not followed.

The active preset also defines what the other panels' **Reset** buttons restore:

| Panel | Reset restores |
|-------|----------------|
| Markdown editor | The preset's markdown and its resource set (the document part) |
| Configuration | The preset's configuration, custom fonts included |
| Projects (Reload) | Everything: document, resources, configuration and fonts |

A preset that was active in an earlier session but is no longer listed by any source (typically a private preset in a build that does not serve it) still appears, greyed out as *Not available in this build*, so the sandbox keeps the loaded content instead of silently swapping it for the built-in one. The active preset id is persisted under the `postext-sandbox-preset` key (see [Persistence](#persistence)); the bundle format is described in the [Preset bundle format](#preset-bundle-format) appendix.

#### Resources panel

Manages the document's resources — bitmap images, SVG figures, and tables — referenced from the markdown via `::resource{id="…"}` blocks and `:ref{id="…"}` inline references. For the reference syntax and the float model, see [Document format → Resources](/en/docs/document-format#resources).

**List view.** Resources are grouped by their resource-type name; resources whose `typeId` no longer matches a configured type fall into an *Untyped* group so they stay reachable. Each item shows a 36 px thumbnail — a real preview for bitmaps and SVGs, a glyph for tables — next to its caption and id. A **New** dropdown offers three entry points:

- **Upload image** — PNG, JPEG, WebP, or GIF
- **Upload SVG**
- **New table** — starts as a 2×2 grid with one header row

The whole panel is also a drag-and-drop target: drop files from disk and they upload in bulk, with ids slugified from their filenames. Unsupported files are skipped, and a short note reports how many were added and how many skipped.

**Detail view.** Selecting a resource opens its editor:

- **ID** — Editable and slug-validated; duplicate ids are flagged and never committed, and an empty id gets a suggestion derived from the caption. Renaming preserves the stored binary payload.
- **Type** — Select among the configured resource types
- **Caption** — Supports inline Markdown (bold, italic, code, and `:ref`)
- **Note** — An optional source line, credit, or remark set in a smaller run under the resource (same inline formatting as the caption); styled by the *Note* group of the *Captions* configuration section
- **Alt text** — Accessibility description for the HTML output
- **Placement** — Position (`top` / `bottom` / `here`) plus span (`column` / `page`, disabled when the position is `here`), matching the engine defaults of `top` + `column`
- **Payload** — Replace uploaders for the bitmap or SVG file
- **Preview** — A live mock embed showing how the resource will look, with `#` standing in for the number (real numbers depend on where the resource lands in the document)
- **Delete** — Guarded by a confirm popover that warns how many `::resource` / `:ref` references in the markdown would be left dangling

**Table editor.** Table resources open an interactive grid editor:

- Toolbar with add/remove row and column, merge/split cells, header-row and header-column toggles, and per-cell alignment
- **Column widths** — One numeric weight per column under the grid (`2, 1, 1` gives the first column half the width; empty means equal widths), written to `table.model.columnWidths`. Adding or removing a column keeps the weights aligned; an *Equal widths* link clears them
- **Paste-as-table** — Pasting TSV (or simple quoted CSV) fills the grid
- **Undo/redo** — Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z
- **Keyboard navigation** — Tab / Shift-Tab (with row wrap) and arrow keys move between cells

All edits go through pure model functions exported by the postext core — `addRow`, `addColumn`, `removeRow`, `removeColumn`, `mergeCells`, `unmergeCell`, `setCellContent`, `setAlignment`, `parseTSV` — so the same table model behaves identically inside and outside the sandbox.

#### Fonts panel

Manages custom font families alongside the built-in Google Fonts catalogue:

- **Add, rename, and delete families**
- **Upload variant files** per weight (100–900) and style (normal / italic). Accepted formats are WOFF2, WOFF, TTF, and OTF, detected by file extension; the files are stored in the browser's IndexedDB.
- Custom families appear in every font picker under a **Custom** group alongside the Google Fonts results, and a custom family **takes precedence** over a Google Font with the same name.
- Orphaned font files — uploads no longer referenced by any family — are pruned from IndexedDB automatically.

#### Configuration panel

A form-based editor for `PostextConfig`. It renders 19 collapsible sections, in order:

- **Design** — *Color Palette* (named colors reused by every color picker), *Page* (size, margins — with a **mirrored** toggle that turns left/right into inner/outer margins for facing pages — DPI, cut lines, baseline grid, page numbering), *Layout* (single, double, or column-and-a-half, gutter, side column), *Header & Footer* (per-slot text, rule, and box elements with placeholders picked from the engine allow-list — page number, total pages, title, subtitle, author, publish date, chapter title and number, part title and number, and `{attr.key}` for a chapter attribute — parity, a **pages** filter — all, body, chapter openers, part dividers or blank pages — overflow, and anchored placement to the container, to a sibling element, or to the **page** / **bleed** frame for edge-to-edge bands)
- **Text** — *Body Text* (font, size, line height, alignment, hyphenation), *Headings* (general defaults plus per-level H1–H6 settings, letter case, break-before with parity, span, and an advanced per-level design slot editor with a minimum opener height), *Parts* (`parts`: the parity of the page a `:::part` opens on, an optional break after the part with its own parity, the margins of the part page — inheriting the page margins, with the same mirrored inner/outer labels — an **opener design** slot laid out against the page trim box whose placeholder picker adds the heading set: current title and its number in decimal, roman or alphabetic form; and a **body style** for the blocks inside the part that inherits the body text and the list colours), *Unordered Lists*, *Ordered Lists*, *Math*
- **Resources** — *Tables* (`tableStyle`: body and header typography, fills, borders with a **rules** pattern — full grid, horizontal only, outer frame, or none — and cell padding), *Captions* (`captionStyle`: typeface, size, alignment, **position** above or below the resource, an optional **background bar** with its colour and padding, independent label and description styling, and a **Note** group for the resource note's size, colour, slant, alignment and gap), *Paragraph Styles* (`paragraphStyles`: named styles for `:::paragraphs{style="…"}` containers — add, remove, and rename ids, then set font, size, line height, colour, alignment, hyphenation, first-line and hanging indents, space between paragraphs, and margins; unset fields inherit the body text), *Callout Styles* (`calloutStyles`: named styles for `:::callout{type="…"}` — add, duplicate, remove, and rename ids, then set the default title, span, placement, width, background, border, corner radius, padding, an edge **stripe**, an **icon** that is either a text glyph or an SVG/bitmap picked from the Resources panel, title typography, and body and list overrides that inherit the document text), *Diagrams* (`diagramStyle`: a **single-ink** toggle that recolors SVG diagrams to tints of one ink for single-colour printing, plus an ink-colour picker defaulting to the palette's main colour), *Resource Types* (per-type names, short labels, numbering templates with `{n}` and `{h1}`…`{h6}` placeholders, counter format and reset level, caption prefix, a live "Fig. 1.7"-style preview, and a collapsible **caption style override** that replaces only the caption fields you set for that type — position, bar, colours, typeface — and inherits the rest)
- **Output and tooling** — *HTML Viewer*, *PDF Generation*, *Debug*, *Warnings* (thresholds for the diagnostics panel)

The panel follows a consistent **override model**: each section remembers its open/closed state across sessions; a section header shows a reset button (with confirm) only while it contains overrides; and every control grows a small per-field reset that appears whenever its value differs from the default. Only the overridden subtree is ever saved or exported — defaults are stripped, so a pristine sandbox stores an empty configuration.

Controls are context-aware: gutter width only appears for multi-column layouts, hyphenation settings only appear when text is justified, and side column percentage only shows for the column-and-a-half layout. Changes take effect immediately in the viewport preview. For a full reference of all configuration options and their defaults, see the [Configuration](/en/docs/configuration) page.

The panel header offers **Reset** (confirm popover; only shown when the configuration differs from the active preset's — it restores that preset's configuration, custom fonts included), **Export**, and **Import** — see [Export and import](#export-and-import).

#### Warnings panel

Live diagnostics recomputed from the markdown, the configuration, the resources, and the last build — the same count that badges the activity bar icon. Representative kinds:

- **Fonts** — Missing font family; missing or duplicate weight/style variants in a custom family
- **Typography** — Loose lines (interword spacing stretched past the configured threshold); heading-hierarchy skips (e.g. H1 → H3); consecutive headings with no body text between them
- **Math** — Invalid or unclosed `$…$` / `$$…$$` formulas
- **Directives and containers** — Unknown directive names (every name the parser knows — `pagebreak`, `numbering`, `callout`, `paragraphs`, `part` — is accepted); invalid numbering or parity attributes; a `:::` container fence left unclosed at the end of the document (click focuses its opening line); a `:::paragraphs{style="…"}` whose style id is not configured; a `:::callout{type="…"}` whose type is not among the configured callout styles
- **Headers & footers** — Placeholder names outside the engine allow-list (`{attr.…}` and the part placeholders are accepted); placeholders whose document metadata is missing
- **Design** — Cyclic or dangling anchors between design elements; text elements whose clip overflow always truncates
- **Resources** — Unknown resource id in a `::resource` / `:ref`; unused resources; duplicate resource ids; dangling resource-type references; bitmaps rendered substantially larger than their pixel size; storage unavailable (IndexedDB missing)

Each entry shows an icon, a title, a one-line detail, and — where applicable — the source line; clicking an entry with a source location focuses the editor at that spot.

### Main viewport

The right side of the interface displays the rendered output. Three tabs are available, one per rendering mode — **Canvas**, **HTML** and **PDF**. Switching tabs does not re-run layout: the same VDT feeds every backend, so the content you see is consistent across modes.

Each viewport runs the layout pipeline inside a dedicated **Web Worker** (`postext/worker`). A per-viewport `useLayoutWorker` hook owns the worker handle, ships fonts into it as transferable `ArrayBuffer`s, and drives builds with **last-wins cancellation** — a keystroke or slider drag aborts the previous build's `AbortSignal` before the next one starts, so fast typing never queues up stale work on the main thread. Unmounting a viewport disposes its worker and rejects any pending build. See [Configuration → Running layout in a Web Worker](/en/docs/configuration#running-layout-in-a-web-worker) for the integration pattern used here.

#### Canvas tab

Renders a rasterized preview of the document on an HTML5 `<canvas>` element. This provides a pixel-accurate representation of how the final typeset document will look, including precise text positioning, column layout, and resource placement.

A toolbar at the top of the canvas viewport provides:

- **Zoom controls** — Zoom in and out (1.25x per step, range 0.25x–4x). Manual zooming disables fit mode.
- **Fit modes** — Fit to page width or fit to page height. Toggles on/off; fitting recalculates automatically on window resize.
- **View modes** — Single page (one page per row) or double-page spread (book-like layout where the first page appears on the right as a recto, and subsequent pages are paired as spreads).

Pages render lazily via `IntersectionObserver` — only visible pages (plus a 200px margin) are drawn to canvas, keeping GPU memory usage low for long documents.

#### HTML tab

Renders the postext output inside a Shadow DOM container, ensuring complete style isolation from the host page. The editorial CSS (typography, spacing, column rules) is injected inside the shadow root so it cannot be affected by or leak into the surrounding application styles.

A toolbar at the top of the viewport provides:

- **Font-scale controls** — Shrink or grow body text while preserving every relative measurement in the configuration.
- **Column modes** — Single (one tall scrollable column) or multi (as many columns as the viewport fits at the configured measure, with horizontal scroll-snap between them).

Column geometry is driven by the **HTML Viewer** section of the configuration sidebar: `maxCharsPerLine` sets the target measure in characters of the body font, `columnGap` the horizontal gap between columns in multi mode, and `optimalLineBreaking` toggles Knuth–Plass inside the viewer. See the [HTML Viewer configuration reference](/en/docs/configuration#html-viewer) and the end-to-end [integration example](/en/docs/configuration#integrating-the-html-viewer) for the same pattern used internally by the sandbox.

#### PDF tab

Generates a real PDF of the current document via the `postext-pdf` package and displays it inside an embedded browser PDF viewer. The PDF is rebuilt automatically on first mount and on every subsequent regeneration, using the same VDT that feeds the canvas and HTML tabs — so line breaks, page boundaries, and resource placement match pixel-for-pixel across the three backends, down to the compression of overfull final lines that Knuth–Plass occasionally accepts.

A floating toolbar at the bottom-right of the viewport provides:

- **Regenerate** (`RefreshCw` icon) — Rebuilds the PDF from the current markdown and configuration. Useful after changing a setting that does not auto-trigger a rebuild, or when fonts have finished loading.
- **Download** (`Download` icon) — Saves the current PDF to disk. The filename is derived from the document's first H1 heading (falling back to `document.pdf`).
- **Print** (`Printer` icon) — Opens the browser's print dialog against the embedded PDF viewer, which in most browsers lets you either print or save as PDF again.

Under the hood the sandbox uses a `createPdfFontProvider()` helper that fetches per-weight static WOFF2 files from the Fontsource jsdelivr CDN, decompresses them to TTF in the browser, and hands the bytes to `pdf-lib` via `renderToPdf`. Per-weight static fonts (rather than a single variable font) are required so that bold text actually embeds at the bold weight. See [Generating PDFs](/en/docs/configuration#generating-pdfs) for the same pattern used outside the sandbox.

## Persistence

The Sandbox automatically saves your work to the browser:

- **Markdown and configuration** — Auto-saved to `localStorage` after 1 second of inactivity, with configuration defaults stripped so only your overrides are stored
- **UI state** — The active panel and viewport tab, sidebar width, configuration section open states, canvas zoom/fit/view modes, HTML font scale and column mode, and toolbar pin states are all persisted in `localStorage`
- **Active project** — The id of the active local project is stored in `localStorage` under `postext-sandbox-project`; the projects themselves (markdown, configuration and resource records) live in the `projects` store of the sandbox's IndexedDB database, and their binary payloads share the blob and font stores with the working document. Payloads are garbage-collected when neither the working document nor any project references them
- **Active preset** — The id of the last loaded preset is stored in `localStorage` under `postext-sandbox-preset`, so the panels' Reset buttons keep restoring that preset across sessions (a preset that is no longer served shows as unavailable). What that preset applied — its bundle fingerprint plus hashes of the markdown, configuration and resource set — is stored under `postext-sandbox-preset-applied`, which is how the next visit tells an untouched document from an edited one
- **Resources and fonts** — Resource records, their binary blobs (bitmaps and SVGs), and custom font files persist in **IndexedDB**; when IndexedDB is unavailable (e.g. some private-browsing modes), a *storage unavailable* warning appears in the Warnings panel

Storage is **shared across UI locales**. A pristine default document swaps to the current locale's default markdown and reseeds the example resources when the locale changes — so opening the Spanish sandbox shows Spanish examples. Any user edit opts the document out of this behavior. All previews also derive a hyphenation locale from the UI locale when none is set in the configuration.

### Export and import

A whole document travels as a **`.postext` file**: a zip archive with exactly the layout of a preset bundle directory — `preset.json`, `document.md`, `resources/*` and `fonts/*` (see [Preset bundle format](#preset-bundle-format)). The **Projects panel** header exports the active document and imports a file as a new project; every project and preset row has its own Export. Import accepts the files at the archive root or under one top-level folder (as produced by zipping the folder itself; `__MACOSX` entries and dotfiles are ignored). Fonts are written as separate files, never inside `config.customFonts`; `.woff` faces are skipped with a warning both ways, as are resources whose bytes are missing. Unzip an exported file into `<presets-root>/<dir>/` and add an `index.json` entry to serve it as a preset.

The markdown and configuration also export separately from their panel headers.

The **Configuration panel** header downloads `postext-config.json` with defaults stripped:

```json
{
  "type": "postext-config",
  "version": 1,
  "config": { ... }
}
```

The **Markdown panel** header downloads the document as a plain `.md` file and its **Import** button replaces the document with a `.md` file's contents. The Configuration **Import** button opens a file picker for `.json` files validated against the expected `type` and `version`; invalid files are silently ignored. The `postext-markdown.json` wrapper and the combined `postext-sandbox.json` format from earlier versions no longer exist.

## Standalone usage

The Sandbox is available as a standalone React package (`postext-sandbox`) that can be embedded in any React application:

```bash
npm install postext-sandbox postext
```

```tsx
import { PostextSandbox } from 'postext-sandbox';

function App() {
  return (
    <PostextSandbox
      initialMarkdown="# Hello World"
      initialConfig={{ layout: { layoutType: 'double' } }}
      onMarkdownChange={(md) => console.log(md)}
      onConfigChange={(cfg) => console.log(cfg)}
    />
  );
}
```

### Props

| Prop | Type | Description |
|------|------|-------------|
| `initialMarkdown` | `string` | Starting markdown content |
| `initialConfig` | `PostextConfig` | Starting layout configuration |
| `className` | `string` | CSS class for the root container |
| `labels` | `Partial<SandboxLabels>` | UI label replacements, merged over the built-in English defaults — pass translated labels together with `locale` when embedding in another language |
| `locale` | `string` | UI locale (defaults to `'en'`). Selects the localized default resource types and example resources, and provides the hyphenation locale the previews use when none is configured |
| `presetSources` | `{ url: string; private?: boolean }[]` | Remote preset sources, tried in order after the built-in preset. Each `url` is a base URL serving an `index.json` (see [Preset bundle format](#preset-bundle-format)); `private: true` tags the source's presets as private and makes their `default` flag eligible for auto-loading. Sources that fail to respond simply contribute nothing |
| `onConfigChange` | `(config) => void` | Callback when config changes |
| `onMarkdownChange` | `(markdown) => void` | Callback when markdown changes |
| `themeToggle` | `ReactNode` | Custom theme toggle component, slotted at the bottom of the activity bar |
| `languageSwitcher` | `ReactNode` | Custom language switcher component, slotted at the bottom of the activity bar |
| `homeUrl` | `string` | When set, renders a home logo link at the top of the activity bar pointing to this URL |
| `homeLink` | `ReactNode` | Custom node for the home slot, replacing the default logo link (takes precedence over `homeUrl`) |

### CSS requirements

The package uses Tailwind CSS utility classes that reference CSS custom properties. Your host application must provide these variables:

- `--background`, `--foreground` — Base colors
- `--surface` — Elevated surface color
- `--gilt` — Accent color (gold)
- `--slate` — Muted text color
- `--rule` — Border/divider color
- `--accent-blue` — Link/accent color
- `--font-mono` — Monospace font family (for the code editor)

## Preset bundle format

Appendix. A preset source is a directory (served over HTTP) whose root holds an `index.json` listing preset directories; each directory holds a `preset.json` manifest plus the markdown, resource and font files it refers to. The `scripts/presets/` tooling in the repository scaffolds bundles in exactly this shape, and a `.postext` file exported from the sandbox is one such directory zipped (without the `index.json`).

```
<presets-root>/
  index.json
  <preset-dir>/
    preset.json
    <document>.md          (one per locale if needed)
    resources/             figures: .svg / .png / .jpg / .jpeg / .webp / .gif
    fonts/                 .otf / .ttf / .woff2 single faces
```

### `index.json`

```jsonc
{
  "version": 1,
  "presets": [
    {
      "id": "acme-journal",          // stable id, [a-z0-9-]
      "dir": "acme-journal",         // directory name relative to index.json
      "name": "Acme Journal",
      "description": "Two-column journal article",   // optional
      "locale": "en",                 // optional
      "default": true                 // optional, at most one
    }
  ]
}
```

### `preset.json`

```jsonc
{
  "version": 1,
  "id": "acme-journal",
  "name": "Acme Journal",
  "description": "Two-column journal article",       // optional
  "locale": "en",                                     // optional
  "default": true,                                    // optional

  // A single file, or one per locale
  "markdown": "article.md",
  // "markdown": { "en": "article.en.md", "es": "article.es.md" },

  // Optional PostextConfig JSON (page, margins, columns, typography...).
  // Do NOT put customFonts here: fonts come from the `fonts` array below.
  "config": { },

  "resources": [
    {
      "id": "fig-1-1",                 // referenced from markdown (:ref)
      "typeId": "figure",              // resource type id (figure, table, ...)
      "kind": "svg",                   // "svg" | "bitmap" | "table"
      "file": "resources/fig-1-1.svg", // svg/bitmap only, relative to preset.json
      "width": 240.5,                  // optional, pt (svg) / px (bitmap)
      "height": 180,                   // optional
      "caption": "Caption text",
      "altText": "Accessible description",            // optional
      "placement": { "position": "top", "span": "column" },  // optional
      "note": "Source: ...",                          // optional
      "table": { "model": { "rows": [[{ "content": "A", "isHeader": true }]], "headerRowCount": 1 } }
                                                      // kind "table" only
    }
  ],

  "fonts": [
    {
      "name": "Some Family",           // family name used by the config
      "variants": [
        { "weight": 400, "style": "normal", "file": "fonts/SomeFamily-Regular.otf" },
        { "weight": 400, "style": "italic", "file": "fonts/SomeFamily-Italic.otf" },
        { "weight": 700, "style": "normal", "file": "fonts/SomeFamily-Bold.otf" }
      ]
    }
  ]
}
```

Notes:

- `id` in `preset.json` must match the `index.json` entry; `description`, `locale` and `default` in the manifest override the index values once the preset is loaded.
- `markdown` is a file name or a locale → file map; the sandbox picks the entry matching the UI locale (exact tag, then base language, then the preset's own `locale`, then the first entry).
- `width` / `height` are optional for `svg` and `bitmap` resources — when missing they are read from the file at load time.
- `table.model` is a Postext `TableModel`: `rows` is a row-major array of cells (`content`, optional `colSpan`, `rowSpan`, `isHeader`, `align`, `verticalAlign`), `headerRowCount` the number of leading header rows, and `columnWidths` an optional array of relative column weights.
- Font files are stored in IndexedDB under ids derived from the preset id and file path, and the families are appended to `config.customFonts` when the preset is applied; a missing or malformed `index.json` yields no presets rather than an error.
- `<preset-dir>/fingerprint.json` is optional and, on the development route, **virtual**: when no such file exists, `GET` answers `{ "fingerprint": "<sha1 hex>", "files": <n> }` computed from the directory's file metadata (relative path, modification time and size of every file up to four levels deep, dotfiles and `node_modules` skipped), never from file contents, with `Cache-Control: no-store`. The sandbox polls it to follow edits to the bundle (see [Projects panel](#projects-panel)). A static host can serve a real `fingerprint.json` with the same shape, or none at all, in which case its presets are not followed.
