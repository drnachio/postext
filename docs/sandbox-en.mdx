# Sandbox

**An interactive playground for the Postext layout engine.**

The Sandbox gives you an editor-style interface where you write the text, manage figures and fonts, adjust the design, and see the result in real time in three synchronized output modes: **canvas**, **HTML** and **PDF**. It is built for experimenting. You can change the typography or the number of columns, try different figure placements, and watch how the engine responds. The panels use editorial words (books, figures, boxes, running heads) rather than engine terms, so people from publishing can find their way without knowing the configuration schema. Every control is keyboard- and screen-reader-accessible.

## Interface layout

The Sandbox has three main areas: a narrow **activity bar** for switching panels, a resizable **sidebar** that holds the active panel, and a **viewport** on the right with the three output tabs. The panel headers, the viewport's tab bar and the logo cell at the top of the activity bar share one height, so the top band reads as a single rule across the window.

### Activity bar

A narrow strip on the left edge has one button per panel. Each button shows an icon with a one-word label under it, and a longer hint as its tooltip (the same hint is the button's accessible description). From top to bottom:

- **Books** (`Files` icon): your books and the sample books
- **Chapters** (`BookOpen` icon): the open book and its chapters
- **Text** (`FileCode` icon): write and edit the text of the current chapter
- **Figures** (`FolderOpen` icon): images, diagrams and tables used in the book
- **Fonts** (`Type` icon): the typefaces the book uses, and your own font files
- **Design** (`Settings2` icon): page, typography, headings, figures, boxes and export settings
- **Checks** (`AlertTriangle` icon): typesetting problems found in the layout. The icon carries a live count badge of current warnings, capped at `99+`.

Clicking the active panel's button collapses the sidebar, and clicking a different button switches to that panel. The bar is a single tab stop: the arrow keys (↑ / ↓, wrapping), **Home** and **End** move focus between the buttons, and Enter or Space opens the focused panel.

The host application can add its own items to the bar: an optional **home logo link** in the top cell (via the `homeUrl` or `homeLink` props), and a **theme toggle** and **language switcher** at the bottom. Whole books are exchanged as `.postext` files from the Books panel, and the Text and Design panel headers export their own part (see [Export and import](#export-and-import)).

### Sidebar panels

The sidebar is resizable. Drag the separator between the sidebar and the viewport, or focus it with Tab and use the keyboard: ← / → change the width by 2 % (10 % with Shift), and **Home** / **End** jump to the narrowest and widest sizes. The separator announces its current value to screen readers, and the viewport always keeps at least 200 px. The sidebar collapses entirely when no panel is active, and its width is remembered between sessions.

Settings rows put their label beside the control, or above it when the sidebar is narrow. This uses container queries, so it follows the sidebar's width rather than the window's.

#### Text panel

A CodeMirror 6 editor for the chapter's Markdown. Screen readers announce it as *Chapter text*. It has:

- **Syntax highlighting**: headings, emphasis, links, code blocks and blockquotes are visually distinct, with dedicated highlighting for **YAML front matter**, **LaTeX math** regions, **inline chips** (`:chip[…]`: the brackets and attributes are marked and the chip text is tinted) **small capitals** (`:smallcaps[…]`: the brackets are marked and the text is shown in small caps), the **orientation marks** of vertical text (`:tcy[…]`, `:upright[…]`, `:sideways[…]`: the brackets marked, the text with a dotted underline) and the **Chinese annotations** (`:dots[…]`, `:name[…]` and `:book[…]` with their marks drawn under the text; `:ruby[…]{rt="…"}` and `{紅樓|hóng|lóu}`; `:warichu[…]` with the note set smaller). Typing `:do`, `:na`, `:bo`, `:ru` or `:wa` offers the directive
- **Chip completion**: typing `:c` at the start of a word offers `:chip[…]` (the caret lands between the brackets). Inside `{style="…"}` the configured chip style ids are offered.
- **Small-caps completion**: typing `:sm` at the start of a word (or right after `*` / `_`) offers `:smallcaps[…]`, with the caret between the brackets.
- **Line numbers** and active-line highlighting
- **Line wrapping** for long paragraphs
- **Toolbar**: starts with **Undo / Redo**, followed by bold, italic, heading levels 1–3, link, inline code, **chip** (wraps the selection in `:chip[…]`), **small caps** (wraps it in `:smallcaps[…]`), blockquote, ordered and unordered lists, plus three directive inserters:
  - `:::pagebreak`
  - `:::space`: one line of vertical space (`:::space{lines=N}` for more)
  - `:::numbering{format="decimal" startAt=1}`: inserted with example attributes you can adjust

Host applications can add their own toolbar buttons through `extraActions`. The editor also reports its cursor and selection to the previews, which enables click-to-caret sync: clicking text in the rendered output moves the caret to the matching Markdown position, and the previews can highlight the current selection.

The panel header is a **chapter switcher**: previous/next arrows, the chapter's position and title, and a menu listing every chapter of the book with its page range once its pagination is known (see [Books and chapters](#books-and-chapters)). Each chapter has its own editor instance, so undo history and caret position are kept per chapter. The header then offers three actions:

- **Reset** (asks for confirmation): reloads the **document part** of the open sample book. Every chapter and the whole figure set are replaced with the sample's (for the built-in sample, the locale's sample document and example resources). The design is left alone except for the sample's own fonts. See [Books panel](#books-panel).
- **Export**: downloads the active chapter as a plain `.md` file, named `<book>-<nn>-<chapter>.md` in a multi-chapter book, and otherwise after the open book or `document.md`
- **Import**: replaces the active chapter with the contents of a `.md` file

#### Books panel

The first panel in the activity bar: the gallery of your books and the sample books, with the **New** menu, the status of the last operation and the banner of a sample book that has a new version. In code and storage a book is still called a *project*, and a sample book a *preset*.

Clicking a book (or one of a sample book's language tags) opens it, and once it is on screen the sidebar moves to the [Chapters panel](#chapters-panel). Clicking the book that is already open goes there straight away. The row menus (rename, duplicate, download, hide, delete) never change panels. The open book stays marked in the list. The panel has two groups:

- **My books**: local, editable books stored in the browser (IndexedDB). The open one is marked; its chapters are in the Chapters panel.

  While a book of your own is open, the working document *is* that book. Every edit to the text, design, figures and fonts is saved into it automatically (with the same 1-second debounce as `localStorage`), so you can switch books and come back without losing anything. You create books from the header's **New** menu:
    - **Copy of the open book** copies the open book, its figures and fonts into a new book.
    - **Blank book** starts an empty one.
    - **Open a .postext file…** imports a file.

  You can also duplicate any row. While you have no books of your own, the group shows an empty state with the same shortcut. Each row has one labelled **⋯** menu (*More actions for "…"*) with **Rename…**, **Duplicate**, **Download (.postext)** and **Delete…**. Delete asks for confirmation right next to the ⋯ button.

  Rename opens inline name and description fields. Enter in either field commits both, and Escape cancels.

  A book also carries a **cover image**, shown where a sample book shows its thumbnail. Making a copy of a sample book (or of another book) adopts its cover. While a row is being renamed, the cover is the control that sets it: click it to choose a PNG, JPEG, WebP, GIF or SVG, or use the X beside it to remove the current one. The cover belongs to the book, not to its figures, and travels with it through export and import.

  A book without a cover gets one from its **first page** (the first page of its first chapter): the first time that page is laid out and painted in the Canvas tab, the Sandbox takes a small picture of it (240 px wide, JPEG) while the browser is idle, once the fonts and the page's pictures are in. It is stored as the book's cover, so a download carries it as the bundle's `thumbnail`. A sample book that ships no thumbnail gets one the same way, kept in the browser (the `presetCovers` store of the IndexedDB database, one per sample and language), shown in its row and adopted by a copy or a download of it. An existing cover is never replaced, whether it came with the sample, with an imported file, from your own choice or from an earlier capture. A cover you remove is taken again from the first page on a later visit.

  Opening a book never asks for confirmation: the book you leave is saved first, whatever it is. While the next one loads, the viewport shows *Opening the book…* instead of the book you left. Deleting the open book falls back to the built-in sample.

- **Sample books**: starting points, listed below your books. The bundle itself is never changed, but your edits to a sample book are kept: the first change saves a copy of it (its *draft*) in the browser, one per sample and language, and the row shows an *Edited* tag. Opening that sample again, in that language, brings your version back; a sample you never changed opens as published. The ⋯ menu of each row offers:
    - **Make my own copy** turns the sample into a book of your own that holds its own copies of the bundle's files, so later edits to the bundle on disk never touch it.
    - **Download (.postext)** saves the sample as a `.postext` file.
    - **Hide from the list** removes the sample from the list (the built-in one cannot be hidden).
    - **Restore the original…** discards your changes to the sample (in every language) and, when it is open, loads the published version in its place. It asks first, and only appears on edited samples.

  A sample in several languages shows one tag per language, in the order its manifest lists them: 繁 and 简 for Traditional and Simplified Chinese, the language code (EN, ES) for the others; the tooltip names the language in the interface language (*Load the Traditional Chinese version*). A sample whose original is in another language than the interface (a Chinese novel with an English translation) says which one it opens in (`openLocale`, see [Preset bundle format](#preset-bundle-format)), so a click on its row brings up the original.

  Hidden samples are collected under a *Hidden sample books* disclosure at the bottom of the group, each with **Show in the list**. The choice is remembered in `localStorage`.

A `.postext` file opened from the **New** menu becomes a new, open book. A file in several languages first asks which one to import, starting from the one it is written in (its manifest's `locale`). Exporting is a per-row action: the open book's row exports what is on screen. A `.postext` file is a preset bundle directory zipped (see [Export and import](#export-and-import)).

The Reset buttons in the Text and Design panels restore the sample a book was copied from. A blank or imported book has no original, so the buttons are hidden while it is open.

#### Chapters panel

The second panel in the activity bar shows only the open book. At the top, its name, what kind of book it is (*Your book*, or *Sample book* with its language and an *Edited* tag once you change it) and a ⋯ menu with the actions on it: **Rename…** for your books (a double-click on the name does the same), **Duplicate** or **Make my own copy**, **Download (.postext)**, and **Restore the original…** for an edited sample book.

Below, its **chapters** fill the rest of the panel and scroll on their own (see [Books and chapters](#books-and-chapters)). Each chapter row shows its page range and word count, and the active chapter is marked. A Chinese, Japanese or Korean book counts characters instead: each Han character, kana or hangul counts one, and so does each Latin word among them. **Add chapter** sits in the panel header next to the chapter count, rows reorder by dragging their grip (or with the arrow keys on it), and each chapter's ⋯ menu offers **Rename**, **Move up / down**, **Split at level-1 headings**, **Merge into previous chapter** and **Delete** (the last chapter can never be deleted).

##### Sample books (presets)

A **preset bundle** is a whole starting point loaded as one unit: the chapters' Markdown, a `PostextConfig`, the resources (with their bitmap/SVG payloads and table models), and the custom font files the config refers to. The panel lists every preset the Sandbox can reach and marks the open one:

- **Built-in preset**: the *Postext guide*, the default sample book shipped with the package. It is always available, always first in the list, and **public**. It comes in English, Spanish and Simplified Chinese (the row's ES, EN and 简 buttons; `#preset=postext-guide&lang=zh-Hans` links to the Chinese edition). The Chinese edition has a design of its own (Noto Serif SC and Noto Sans SC, mainland punctuation and line breaking) and figures drawn with Chinese labels; the interface stays in English or Spanish, and an untouched Chinese guide stays Chinese when the Sandbox is opened in either.
- **Remote presets**: bundles served over HTTP from the base URLs passed in the `presetSources` prop (see [Props](#props)). Each source is either public or **private**. Private presets are tagged *Private* in the list and are meant for material that must not leave a machine. The public website only lists a private source in local development, where the Next.js app serves the folder named by `POSTEXT_PRIVATE_PRESETS_DIR` through `/api/private-presets`. Production never lists it. The website's public source, `/presets`, serves its bilingual sample books: *Bioquímica*, *Deep Sky*, *Don Quijote*, *Physics (OpenStax)*, *Spanish Painting* and *Signals 2020*, each with its licence and credits.
- **`default: true`**: a private preset flagged as default is loaded automatically the first time a *pristine* Sandbox (untouched built-in document) opens. When several are flagged, the one whose `locale` matches the UI locale wins. Public presets are never loaded automatically.

Each row shows the preset's name, an optional description, its locale tag and its *Private* / *Default* tags. Clicking a row loads the preset **in full**: text, figures, design and fonts. The Sandbox first writes the font files and figure data to IndexedDB, so the viewports never see a half-applied document. Clicking a row opens the sample in the interface language, unless you have only edited it in another language: then your most recent version opens. A bilingual sample's language tags open it in that language (your version there, if you have one).

**Live presets.** Remote presets are followed automatically. Whenever a preset is applied, the Sandbox records the bundle's *fingerprint* along with hashes of the Markdown, configuration and resource set it applied. While the page is visible, it polls the fingerprint every 3 seconds, and immediately when the tab becomes visible or the window regains focus. When the fingerprint changes:

- If the book is **untouched** (Markdown, configuration and resources still hash to what the preset applied), the preset is re-applied in full and a brief notice appears in the panel.
- If there are **local changes**, they are kept. A banner at the top of the panel (*This sample book has a new version. Your changes are kept.*) offers **Load the new version**, which asks before it discards your changes to that language of the sample, and the Books button in the activity bar shows a dot meanwhile. The draft remembers the version it was made from, so the banner comes back each time you open it until you load the new version. Figures of the draft whose files changed in the new version keep the bytes they had: the draft gets its own copy of them before the bundle's are written. Bundles are only followed while a sample book is open. A book copied from one keeps its own copy.

The same check runs on load, so if you edit a bundle and then open the Sandbox, it picks up the new version as long as the book was untouched. The fingerprint comes from `<preset-dir>/fingerprint.json`. On the development route this is a virtual file that returns a metadata-only hash of the directory (see the [Preset bundle format](#preset-bundle-format) appendix). Sources that do not serve it are not followed.

A preset that was open in an earlier session but is no longer listed by any source (typically a private preset in a build that does not serve it) still appears, greyed out as *Not available in this build*. The Sandbox keeps the loaded content instead of silently swapping it for the built-in sample. The open preset's id is persisted under the `postext-sandbox-preset` key (see [Persistence](#persistence)). #### Figures panel

Manages the book's resources: bitmap images, SVG figures and tables. The text refers to them with `::resource{id="…"}` blocks and `:ref{id="…"}` inline references. For the reference syntax and the float model, see [Document format → Resources](/en/docs/document-format#resources).

**List view.** The header shows the number of resources. Resources are grouped by their resource-type name, and each group is a counted list. Resources whose `typeId` no longer matches a configured type fall into an *Untyped* group so you can still reach them. Each item shows a 36 px thumbnail next to its caption and id: a real preview for bitmaps and SVGs, and a glyph for tables. When the book has more than six resources, a **search** field (*Search figures and tables…*) filters the list by caption and id, ignoring accents. When the book has no resources yet, an empty state explains how to add them and place them in the text with `:ref{#id}`. A **New** dropdown offers three ways to add one:

- **Upload image**: PNG, JPEG, WebP or GIF
- **Upload SVG**
- **New table**: starts as a 2×2 grid with one header row

You can also drag and drop files from disk onto the panel. They upload in bulk, with ids slugified from their filenames. Unsupported files are skipped, and a short note reports how many were added and how many were skipped.

**Detail view.** Selecting a resource opens its editor:

- **ID**: editable and slug-validated. Duplicate ids are flagged and never committed, and an empty id gets a suggestion derived from the caption. Renaming keeps the stored image or SVG file.
- **Type**: one of the configured resource types
- **Caption**: supports inline Markdown (bold, italic, code and `:ref`). `\\`, or a backslash ending a line, starts a new line; a plain line break counts as a space
- **Note**: an optional source line, credit or remark, set in a smaller run under the resource (same inline formatting and line breaks as the caption). It is styled by the *Note* group of the *Captions* settings.
- **Alt text**: accessibility description for the HTML output
- **Table style**: for tables, the named style the table is set in (`table.styleId`). This is either *Document table style* (the default) or one of the *Table styles* declared in the settings. An id that no style declares is listed as missing and renders with the document table style.
- **Placement**:
  - **Position**: `auto` (the first free slot, the default), `top`, `bottom` or `here`.
  - **Span**: `column`, `page` or `side`. It is disabled when the position is `here`. The defaults match the engine's, `auto` + `column`.
  - **Orientation**: upright, or turned a quarter turn (top to the left, or to the right). A turned resource takes a page of its own, flush to the spine, so the span select is disabled.
  - **Width**: a width fraction with an alignment, for floats and inline embeds narrower than their column. The alignment also places a bitmap or SVG narrower than its slot at full width (a bitmap smaller than the column, or a figure `layout.fitFiguresToPage` shrank), so it stays enabled for pictures; for a table it needs a width under 100%. A turned resource has neither.
  - **Caption beside the figure**: a toggle for the side column of a column-and-a-half layout. It applies to column floats, so it is hidden when the position is `here`.
- **Payload**: uploaders that replace the bitmap or SVG file
- **SVG source**: for SVG figures, a source editor under the uploader. Only the text nodes accept edits: the content of `<text>` / `<tspan>` elements, tinted in the editor. Typing anywhere else is rejected, and `<`, `>` and `&` typed into a text node are escaped so the file stays well-formed. Each change is saved after a short pause as a **new** stored file, and the figure re-renders (single-ink recolouring included). The editor notes when the SVG has no text nodes.
- **Preview**: a live mock-up of how the resource will look, with `#` standing in for the number (real numbers depend on where the resource lands in the document). The caption opens with the label the document sets: the type's caption prefix and the number (`Figure #.`), the prefix alone for a type numbered with an empty template (`Do.`), and nothing for a type with no caption prefix
- **Delete**: asks for confirmation first, and warns how many `::resource` / `:ref` references in the text would be left pointing at nothing

**Table editor.** Table resources open an interactive grid editor:

- **Toolbar**:
  - Add or remove rows and columns, and merge or split cells.
  - Toggle a header row or a header column.
  - Set each cell's horizontal and vertical alignment (top, middle or bottom). The cell content moves as one unit inside a taller row.
  - Set each cell's fill: a colour picker, palette-linkable, with a clear button. The fill is written to `TableCell.background` and shown in the grid.
- **Column widths**: one numeric weight per column under the grid (`2, 1, 1` gives the first column half the width; empty means equal widths), written to `table.model.columnWidths`. Adding or removing a column keeps the weights aligned, and an *Equal widths* link clears them.
- **Paste as table**: pasting TSV (or simple quoted CSV) fills the grid
- **Undo/redo**: Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z
- **Keyboard navigation**: Tab / Shift-Tab (with row wrap) and the arrow keys move between cells
- **Click to edit from the preview**: click a table cell, a caption, a note, or a text fragment of an SVG figure on either preview tab. The Figures panel opens on that resource and focuses the matching field, with the caret on the clicked glyph. Dragging selects a range inside the same cell or field, and a double-click selects the word. While the field has focus, its selection is mirrored back onto the page as a highlight (a thin caret when collapsed) on both the Canvas and HTML tabs.

All edits go through pure model functions exported by the postext core (`addRow`, `addColumn`, `removeRow`, `removeColumn`, `mergeCells`, `unmergeCell`, `setCellContent`, `setAlignment` and `parseTSV`), so the same table model behaves identically inside and outside the Sandbox.

#### Fonts panel

Shows the typefaces the book uses and manages your own font files alongside the built-in Google Fonts catalogue:

- **Typefaces in this book** lists every family the design uses. Each family name is set in its own typeface, with its role (*Body text*, *Headings* or *Other elements*) and its source (*Google Fonts* or *Your file*). You change the typefaces themselves in **Design → Typography** and **Headings & contents**.
- **Your font files** is where you add, rename and delete custom families.
  - **Upload variant files** per weight (100–900) and style (normal / italic). Accepted formats are WOFF2, WOFF, TTF and OTF, detected by file extension. The files are stored in the browser's IndexedDB.
  - Custom families appear in every font picker under a **Custom** group alongside the Google Fonts results. A custom family **takes precedence** over a Google Font with the same name.
  - In a Chinese document every font picker lists first, under *Simplified Chinese* or *Traditional Chinese*, the Google families that hold the document's characters (Fontsource's `chinese-simplified`, `chinese-traditional` and `chinese-hongkong` subsets), then the rest.
  - Orphaned font files (uploads no longer used by any family) are removed from IndexedDB automatically.

#### Design panel

A form-based editor for `PostextConfig`, with more than five hundred fields.

**Overview.** When the Design panel opens, it shows an overview:

- A **This book** card with a live drawing of the page. The drawing uses true proportions and shows the margins, the columns and the page and ink colours, as a spread when the margins are mirrored. A vertical book's lines are drawn down the page from the right, its columns as tiers. Beside it are the trim size, the column layout, the writing system, the body typeface and size, and the palette. The writing system line names the document language and, when they are a choice, the direction and the binding (*Vertical · bound on the right · 中文（繁體）*); it opens **Writing system**.
- The list of the twelve **settings groups**. Each group has a one-sentence description and the number of sections you have changed in it.

**One page per group.** Opening a group shows that group's sections as their own page. Only that group is built, which keeps the panel fast even on large books.

- A breadcrumb (**Design › group**) leads back to the overview.
- Chips under the page heading jump to each section on the page.
- A **Next** link at the bottom opens the following group.
- Focus moves to the page heading when you open a group, and back to the group's row when you return.
- The open group is remembered between sessions.

The groups, in browsing order:

- **Page & columns**
  - *Page*: fields are grouped as **Size**, **Margins**, **Paper**, **Numbering** and **Print preparation**.
    - **Size**: the size presets say what they are for: *Pocket book* 11 × 17, *Novel, narrative* 12 × 19, *Essay, handbook* 17 × 24 and *Textbook, magazine* 21 × 28, or *Custom*.
    - **Margins**: each margin is tied to the page drawing. Pointing at a margin field or focusing it tints that margin on the drawing. A **mirrored** switch turns left/right into inner/outer margins for facing pages.
    - **Paper**: the page background colour.
    - **Numbering**: the page-number format and the number the pages start at.
    - **Print preparation**: DPI and cut lines.
  - *Columns*: the layout is chosen from picture cards: *One column* (novels, essays), *Two columns* (textbooks, magazines, reference works) or *Column and a half* (a main column plus a narrow side column for notes and small figures). The section also has the gutter, the side column, **Shrink figures that don't fit** (`layout.fitFiguresToPage`), **Space around inline figures** (`layout.inlineResourceGap`), **Space around figures in boxes** (`layout.inlineResourceGapInBoxes`), **Lines of a paragraph at a box cut** (`layout.boxChildSplitMinLines`) and **Closing floats hug the text** (`layout.hugClosingFloats`).
- **Writing system**. The page opens with the drawing of Page & columns. Its spread carries folios: 2 | 3 in a book bound on the left, 3 | 2 in one bound on the right, whose odd page is the left one; the caption says when the book is bound on the right and when its lines are vertical.
  - *Language and direction*:
    - **Document language**, with Chinese as 中文（简体）, 中文（繁體） and 中文（香港）. A tag the list lacks (`es-ES`, `zh-TW`, `sv`) shows as an extra option, named after the language it reads as. Changing it renames the built-in figure and table types when they are still the ones of the previous language (a Spanish book switched to Chinese prints 图 and 表, not *Figura* and *Tabla*); types you renamed keep their names.
    - **Writing mode**, from picture cards: *Horizontal*, or *Vertical*, lines running top to bottom and right to left (`layout.writingMode`).
    - **Binding**: *Auto*, which names what it resolves to (the right edge for a vertical book), *Left edge* or *Right edge* (`page.binding`).
    - **Chinese defaults**: **Review…** lists what setting the book up for Chinese changes. Pick *Simplified 简体* or *Traditional 繁體* and the direction: a new Traditional book starts vertical, a new Simplified one horizontal, and a book already in Chinese keeps its direction. Each row shows the setting as it is and as it becomes: the document language (a Chinese tag of the same script, such as `zh-TW`, is kept), the writing mode with the binding it gives, Noto Serif and Noto Sans in SC, TC or HK for the body and the headings (the heading row also names the faces heading levels and heading styles set for themselves, and ticked it sets those in the Chinese face too), a 2 em first-line indent, indent after headings, no space between paragraphs, justified text, no hyphenation, 图 or 圖 and 表 numbered by chapter (`{h1}-{n}`), captions set 图1-1　标题 (nothing before the number, an ideographic space after it), chapters numbered 第一章 (`第{1:一}章`, an ideographic space before the title) and numbered lists 一、 （一） 1. （1） ①. Only what differs is listed. A setting you changed yourself comes unticked, marked *your setting*, and stays as it is unless you tick it; the language and the direction always apply, and so does hyphenation, which a Chinese document turns off by itself (unless you turned it on for a Latin language you named in the hyphenation language). **Apply** makes the ticked changes in one step, and **Undo** beside the confirmation takes that step back in the same book: every setting it changed returns to what it was, even when you have changed other settings of the same group since; one you have changed again since stays as you left it, and the confirmation says so. Opening another book drops the Undo.
  - *East Asian typography* (`cjk`): **Regional conventions** (mainland China, Taiwan, Hong Kong) at the top, then the fields in four groups: **Line edges** (**Line breaking**: none, basic, GB, strict; **Trim brackets at line edges**; **Hanging punctuation**), **Punctuation widths** (**Punctuation width**: kaiming, full width, half at line end, half width; **Compress adjacent marks**), **Spacing** (**Space between Han and Latin**), **Vertical text** (**Numbers in one upright cell**: off, or up to 2, 3 or 4 digits, `cjk.uprightDigits`), **Annotations** (**Emphasis in Chinese text**: what `*…*` prints, dots or italics; **Book titles (:book)**: 《》, a wavy line or nothing; **Mark colour**), **Ruby** (the readings' typeface, size, colour and position), **Warichu notes** (the notes' size, colour and opening and closing brackets) and **Character grid** (characters per line, lines per page, the grid drawn on screen, and the 字 × 行 read-out with the margins the grid sets). Every *Auto* follows the document language and names what it resolves to. In a document whose language is not Chinese, Japanese or Korean and that sets none of these, the section shows one line saying so and a **Show the settings** button; a search shows the fields in any document. See [East Asian typography](/en/docs/configuration#east-asian-typography), [Vertical writing](/en/docs/configuration#vertical-writing), [Numbers in vertical text](/en/docs/configuration#numbers-in-vertical-text) and [Binding](/en/docs/configuration#binding).
- **Colours**
  - *Palette*: named colours reused by every colour picker. Changing an entry updates every reference to it.
- **Typography**
  - *Body text*: opens with a true-size **type specimen** set in the current typeface, size, leading and colour, in the document's language: a Chinese book shows the opening of 紅樓夢 in its script, `*…*` with emphasis dots, and sets it top to bottom when its lines are vertical. Its line breaks are the browser's; the page uses Postext's. The fields are grouped as:
    - **Typeface**: font, size, line height, and the regular and bold weights.
    - **Paragraphs**: alignment (with hyphenation, the justification limits and **Most letter-spacing to justify** (`bodyText.maxJustifyTracking`) when the text is justified, and **Hyphenate ragged text** with its zone, **Optimal Line Breaking** and **Optimal Breaking of Ragged Text** (`bodyText.optimalRagged`) when it is not; under a justified body **Optimal Breaking of Ragged Text** follows **Optimal Line Breaking**, for the ragged paragraph styles and boxes; **Hyphenate across columns** (`bodyText.hyphenateAcrossColumns`) under hyphenation when the body is justified, and under **Optimal Breaking of Ragged Text**, while that is on, when the body is ragged; **Hyphenate compounds** (`bodyText.hyphenation.compounds`) with the hyphenation language), **Break After Dashes** (`bodyText.breakAfterDashes`), **Break After Hyphens** (`bodyText.breakAfterHyphens`), **Repeat Hyphen on Next Line** (`bodyText.repeatHyphen`), indents and paragraph spacing.
    - **Colour**: the text, bold and italic colours.
    - **Language**: the document language, named in its own language. It is set under **Writing system**; the row opens that group.
    - **Widows, orphans and short lines** (collapsible): includes **Graded runt penalty** (`bodyText.gradedRuntPenalty`), **Tighten to pull a runt back** (`bodyText.tightenRunts`), **Most letter-spacing tightening** (`bodyText.maxRuntTracking`), and **Keep colon with list** with **Room Under the Colon** (`bodyText.colonListRoom`): how much room the line ending in a colon needs under it to stay with its list, what the first item needs or one line as up to postext 1.4.
    - **Blockquotes** (collapsible): the colour of `>` quotes, **Italic Blockquotes**, **Blockquote Indent** and **Blockquote First Line Indent** (`bodyText.blockquote`).
    - **Cross-references** (collapsible).
  - *Paragraph styles* (`paragraphStyles`): named styles for `:::paragraphs{style="…"}` containers. You can add, remove and rename ids, then set the font, size, line height, colour, the colours of bold and italic runs, regular and bold weights, **italic** and **small caps** switches, alignment, hyphenation, the left indent of every line, first-line and hanging indents (measured from the left indent), space between paragraphs, margins, **Snap to grid** (`paragraphStyles[].snapToGrid`) and **Letter case** (`textTransform`, capitals). Unset fields inherit the body text. Above the styles, **Space under a container** (`bodyText.paragraphContainerSpacing`) says how the space under a container meets the block after it: *Collapse*, or *Add (1.4)*.
  - *Inline labels* (`chipStyles`): named styles for the inline `:chip[text]{style="…"}`. The built-in `chip` style is shown while the configuration has none. You can add, remove and rename ids, then set:
    - **Text**: font, size, colour, bold and italic. Each inherits the surrounding text until you set it.
    - **Box**: fill, outline width and colour, corner radius, horizontal and vertical padding (with **Top padding** and **Bottom padding** to pad them apart, which centres a capital in a round chip), and the minimum gap to the neighbouring words.
  - *Formulas* (`math`), with **Indent after a display** (`math.indentAfterDisplay`) and **Keep with its lead-in line** (`math.keepWithLeadIn`).
  - *Footnotes* (`footnotes`): **Placement** (column foot or end of chapter), **Position in the column** at the end of a chapter, **Numbering** (per chapter or continuous), the note size, leading, colour, alignment and hanging indent, the spaces above and between the notes, and the **Separator rule** (length, thickness, colour). See [Footnotes](/en/docs/configuration#footnotes).
- **Headings & contents**
  - *Headings*: general defaults plus per-level H1–H6 settings. They include:
    - letter case, **Letter spacing** (`levels[].letterSpacing`, negative to tighten), alignment (ragged right, justified, centred or ragged left), break-before with parity, and span;
    - a **Snap back to the grid after headings** switch (`headings.snapToGrid`, on by default: the text snaps back to the baseline grid under a heading), and per level **Snap back to the grid after this heading** (`levels[].snapToGrid`), which overrides it for that level;
    - an **Inline marks in headings** switch (`headings.inlineMarks`, on by default): a heading sets the italic, bold, scripts, small capitals and links written in it, as a paragraph does; off, it prints the marked words in its own style;
    - per level, **Hidden (structural)** (`levels[].hidden`): the heading prints nothing and takes no room, but still breaks, numbers and feeds the contents, the running heads and the PDF bookmarks;
    - an advanced per-level design slot editor with a minimum opener height; each element of a heading design has a **Reserves space** switch (off: it paints without adding to the height the heading reserves);
    - the column-balancing levers, with their per-lever caps, and **Box Closing a Column** (`balancing.closingBox`): when a box that ends a short column moves down to the column's foot — first, after the other levers, or never.
  - *Heading styles* (`headingStyles`): named styles applied with `{style="…"}` on a heading line. You can add, remove and rename ids, and for each style:
    - choose whether the heading is numbered and listed in the contents, and give it a numbering template of its own;
    - turn off **Named in running heads** (`runningChapter`) for a plate or a map set as an H1 inside a chapter, so the running heads keep naming the chapter it interrupts;
    - override the heading typography (letter spacing included), break and span, **Snap back to the grid after this heading** and **Hidden (structural)**;
    - give the section its own running heads, optionally starting from the document's;
    - set its margins and column layout (with the side column's role and edge, as in *Columns*, and its own *Shrink figures that don't fit*);
    - set the body style, list overrides and palette colours.
  - *Contents* (`toc`): the heading levels a `:::toc` lists, with the entry typography of each. It also covers the unnumbered entries, page numbers, leader dots, the subtitle line read from a heading attribute, and the part rows with their own design slot.
- **Lists**
  - *Bulleted lists*, with **Snap Top to Grid** (`unorderedLists.snapTopToGrid`), which rounds the space above a list up so its first item sits on the baseline grid.
  - *Numbered lists*: for each level, the separator's font, weight, italic, colour and gap next to its numbering; **Snap Top to Grid** (`orderedLists.snapTopToGrid`), as for bulleted lists; and **Number column** (`orderedLists.numberWidth`): where the text of an item starts, after the widest number of its own run (*Per run*) or of its level in the chapter (*Per level*).
- **Figures & tables**
  - *Numbering & placement* (`resourceTypes`): for each resource type:
    - names and short labels;
    - numbering templates with `{n}` and `{h1}`…`{h6}` placeholders, the counter format and reset level, and the caption prefix, with a live "Fig. 1.7"-style preview;
    - a **Placement** group: the type's default position, span (column, page or the side column) and rotation, a width fraction, an alignment for resources narrower than their slot (floats and embeds narrowed by the width, and pictures narrower than the column), and a caption-beside-figure switch;
    - a collapsible **caption style override** that replaces only the caption fields you set for that type (position, bar, colours, typeface) and inherits the rest.
  - *Captions* (`captionStyle`): typeface, size, alignment and **position** above or below the resource. There is an optional **background bar** with its colour and padding, and the label and description are styled independently. A **Note** group sets the resource note's size, colour, slant, alignment and gap.
  - *Tables* (`tableStyle`):
    - body and header typography, with the header's **Letter spacing** (`headerLetterSpacing`) and **Letter case** (`headerTextTransform`), and fills;
    - borders, with a **rules** pattern: full grid, horizontal only, outer frame or none;
    - a **corner radius** for the outer frame;
    - cell padding;
    - under *Body cells*, **Zebra rows** (`bodyAlternateBackgroundEnabled`), which fills every second body row with the **Alternate row color** (`bodyAlternateBackground`) shown while it is on.
  - *Table styles* (`tableStyles`): named table styles. You can add, remove and rename ids (renaming carries along the tables that use the id), then set any of the *Tables* fields. Each control shows the value inherited from *Tables* until you set it.
  - *Diagrams* (`diagramStyle`): a **single-ink** switch that recolours SVG diagrams to tints of one ink for single-colour printing, plus an ink-colour picker that defaults to the palette's main colour.
- **Boxes**
  - *Box styles* (`calloutStyles`): named styles for `:::callout{type="…"}`. You can add, duplicate, remove and rename ids, then set:
    - the default title, span, placement and width;
    - the background, border, corner radius and padding, and an edge **stripe**;
    - an **icon**: either a text glyph or an SVG/bitmap picked from the Figures panel. It can be set inline or as a corner badge, with its corner side and a width for non-square artwork.
    - a **Label tab** group (`calloutStyles[].label`): font, size, weight, colour, fill, corner, height, padding, offset and inset, an icon resource beside the tab, and a rule along the top edge;
    - title typography, with letter spacing, indent and **Title line height** (`titleStyle.lineHeight`);
    - body and list overrides that inherit the document text. These include the body's bold and **italic colours**, its regular and bold weights, **italic** and **small caps** switches, and the bullet's size and weight.
    - a column gap for `:::columns` groups inside the box;
    - a **Snap to grid** switch (`calloutStyles[].snapToGrid`, on by default; off keeps the exact bottom margin for stacked boxes);
    - the marker column, a fixed anchor, keep-together and split-min-lines, and the float-barrier controls;
    - a **Side Box at a Column End** choice (`sideAtColumnEnd`) for side boxes whose text does not go on in the same column: beside the text before the fence, or beside the text after it;
    - a **Split boxes** group: repeat the title with a suffix on every continuation (`repeatTitle`, `continuedSuffix`), and a continuation marker under each part that goes on, with its text, alignment and italic (`continuesMarkerEnabled`, `continuesMarker`, `continuesMarkerAlign`, `continuesMarkerItalic`). The strings default to the document language.
- **Headers & footers**
  - *Headers & footers*: per-slot text, rule, box and image elements.
    - **Text elements**: vertical alignment, **text alignment** within their own box (`align`: flush left, centred or flush right, visible when the box is wider than the text, or justified, which stretches the spaces of every line but the last of each paragraph to fill the box and, with **Hyphenation** on, splits a word at a syllable to fill a line), line height, letter spacing (negative to tighten a display title), letter case, a fitted, filled or fixed width and height, and a maximum width. **Inline marks** (`inlineMarks`) sets `**bold**`, `*italic*` and the other inline marks in the element's text, and an outline draws the letters' contour: **Outline width**, **Outline color** and **Hollow letters** (`stroke`).
    - **Rules**: horizontal or vertical.
    - **Placeholders**, picked from the engine allow-list: page number, total pages, book total pages, title, subtitle, author, publish date, chapter title and number, part title and number, and `{attr.key}` for a chapter attribute. Headers and footers also take the chapter title and number at the top of the page, `{chapterTitleAtTop}` / `{chapterNumberAtTop}` (see [Chapter at the top of the page](/en/docs/configuration#chapter-at-the-top-of-the-page)), and the guide words `{firstMark.h2}` / `{lastMark.h2}` (a heading level or a paragraph style id after the dot; see [Guide words](/en/docs/configuration#guide-words-first-and-last-mark)).
    - **Where a slot appears**: parity, and a **pages** filter: all, body, chapter openers, part dividers or blank pages.
    - **Placement**: overflow, and an anchor to the container, to a sibling element, or to the **page** / **bleed** frame for edge-to-edge bands; header and footer elements can also anchor to the **Outer margin** (`'outer'`), the margin away from the spine.
    - **Writing mode** of a text element: *Horizontal*, or *Vertical, lines right to left* (`writingMode`), for running heads set down the fore-edge of a vertical book. The header editor's **Fore-edge heads (vertical)** adds the chapter title four characters below the head of the type area and the folio five above its foot, both vertical, at 80 % of the body size, anchored to the outer margin (see [Vertical text elements](/en/docs/configuration#vertical-text-elements)).
    - A **Drop cap** group (lines, font, weight, size, colour and gap) and a paragraph indent. A text with a drop cap wraps whatever its **Overflow**, and with no size set the letter's top is level with the capitals of the first line.
    - Every other design slot offers the same text controls.
- **Parts**
  - *Parts* (`parts`):
    - **Part title page** (`parts.page`): turning it off opens no page, and the part's number, title and colours simply apply from the next content. It also hides the settings below.
    - the parity of the page a `:::part` opens on, and an optional break after the part with its own parity;
    - the margins of the part page. They inherit the page margins, with the same mirrored inner/outer labels.
    - an **opener design** slot laid out against the page trim box. Its placeholder picker adds the heading set: the current title, and its number in decimal, roman or alphabetic form.
    - a **body style** for the blocks inside the part. It inherits the body text and the list colours, and it includes the list overrides (numbering format and offsets, margins, hanging indent, and the task-list fields).
- **Export**
  - *PDF*.
  - *Web reader (HTML)*: the `htmlViewer` settings.
- **Advanced**
  - *On-screen aids* (`debug`): the **baseline grid** (`page.baselineGrid`), which lives here rather than under *Page*, and the other layout-checking overlays.
  - *Warnings*: which problems the Checks panel reports, and their thresholds.

**Finding a setting.** The toolbar under the header works across every group:

- **Search settings…** filters every field in every section by its label, help text and option names. It ignores accents and matches the start of words: *marg* finds *Top margin* and *Margen superior*, and *h3* opens *Headings › H3*. Results are grouped by settings group. Matching sections open automatically, non-matching rows and sections are hidden, and hits are highlighted. Escape clears the search, then leaves the field.
- **Changed** shows only the fields whose value differs from its default.

**Help text.** Every field has a short explanation. Screen readers hear it as the field's description, and it stays hidden on screen until you open it with the row's **?** button (*What is "…"?*). The header's **Show every explanation** switch opens every explanation at once, and the choice is remembered.

**Changed values.** The panel follows a consistent **override model**:

- Section headers carry a badge with the number of changed fields inside, counted through nested groups.
- A section header shows a reset button (which asks for confirmation) only while it contains changes.
- A changed field has a dot beside its label (read as *changed*) and a small reset button of its own.
- Only the changed subtree is ever saved or exported. Defaults are stripped, so a pristine Sandbox stores an empty configuration.
- Resetting *Page* leaves the baseline grid alone, since the grid is edited under *Advanced*.

**The controls:**

- Choices are dropdowns whose options can carry a one-line description, or segmented buttons when there are only a few.
- On/off settings are switches.
- Numbers have − / + steppers. The arrow keys step the value, ten times as much with Shift and a tenth with Alt.
- Lengths have a unit selector that converts the value when the unit changes (cm, mm, in, pt, px, em, rem).
- A colour is a single button showing the swatch and the value.
- The font picker can be navigated with the arrow keys.

Controls are context-aware. The gutter width only appears for multi-column layouts, the justification settings only appear when text is justified (ragged text shows **Hyphenate ragged text** instead, and a paragraph style or box shows its hyphenation switch when it is justified or ragged hyphenation is on), and the side-column percentage only appears for the column-and-a-half layout. Changes take effect immediately in the viewport preview. For a full reference of every configuration option and its default, see the [Configuration](/en/docs/configuration) page.

The panel header also offers **Reset** (asks for confirmation; only shown when the design differs from the open sample book's, and it restores that sample's design, fonts included), **Export** and **Import**. See [Export and import](#export-and-import).

#### Checks panel

Live diagnostics, recomputed from the text, the design, the figures and the last build. The count matches the badge on the activity bar button. Warnings are grouped by kind, in triage order: what breaks the output first, then the markup, then the fine typesetting that usually comes in many small items. Each group is collapsible and shows its count:

- **Fonts**: a missing font family, or missing or duplicate weight/style variants in a custom family, and *Font stack in a font family*: a `fontFamily` setting that holds a CSS font stack (the text is set in its first family; the entry names the setting's path)
- **Figures & tables**: an unknown resource id in a `::resource` / `:ref` — also in the caption, note or cells of a figure the text uses, or as a table cell's image — duplicate resource ids, references to a resource type that does not exist, bitmaps rendered substantially larger than their pixel size, a table whose style id names no table style, a table grid left irregular (a merged cell whose covered cells are missing, or a row with a hole: merge the cells again in the table editor), and an image whose file is missing from storage or does not decode (it shows as a placeholder)
- **Text & markup**:
  - heading-hierarchy skips (for example H1 → H3), and consecutive headings with no body text between them;
  - invalid or unclosed `$…$` / `$$…$$` formulas;
  - unknown directive names (every name the parser knows is accepted: `pagebreak`, `columnbreak`, `space`, `numbering`, `toc`, `callout`, `paragraphs`, `part` and `columns`), invalid numbering or parity attributes, and a `:::space{lines=N}` outside 0–20 lines;
  - a `:::` container fence left unclosed at the end of the document (clicking it focuses its opening line);
  - a `:::paragraphs{style="…"}`, `:::callout{type="…"}`, `:chip[…]{style="…"}` or heading `{style="…"}` whose style is not configured;
  - a `::resource` line that prints as text — malformed, or glued under a paragraph without a blank line;
  - *Fullwidth markup*: markup typed with a Chinese or Japanese input method (`：：：`, `＃`, `［＾…］`, `｛…｝`, `＊＊…＊＊`), which prints as text; the entry shows the ASCII form to type;
  - *Attribute key not read*: an attribute key written outside ASCII (`作者=曹雪芹`), which the parser ignores;
  - *Front matter ignored*: a chapter other than the first that starts with a front-matter block (only the first chapter's front matter belongs to the book).
- **Design**:
  - header and footer placeholder names outside the engine allow-list (`{attr.…}` and the part placeholders are accepted), and placeholders whose document metadata is missing;
  - cyclic anchors between design elements, or anchors to an element that does not exist. This check and the placeholder check cover every design slot: the running heads, the part opener, the blank verso after a part page, the part rows of the contents, each heading level's design, and each heading style's design and the running heads of its section. An entry from a heading style names the style, as in `{style="index"} header · #rh → #missing`, and one from the verso or the contents' part rows names its setting, as in `toc.parts.design · #row → #missing`;
  - text elements whose clip overflow always truncates;
  - *Heading design cut off*: a heading design taller than its page can hold — text of an opener laid out past the foot of the page, or of an in-column design past the foot of its column (a long lead on a small screen page). The heading claims the rest of its page or column, so the text after it starts on the next one, but that part of the design is lost; clicking the entry focuses the heading;
  - *Side column out of range*: a column-and-a-half side column the engine had to clamp to leave room for the main column;
  - *Unknown number format*: a list, page or resource-type number format the engine does not know, which numbers in decimal;
  - *Unknown setting*: a key that the headings, a heading level or a heading style does not have (a misspelt `letterSpacng`), which the engine ignores; the entry suggests the setting it is closest to, when one is.

  These last three, like *Font stack in a font family*, come from the configuration rather than the text: the entry names the setting's path, and clicking it does not move the editor.
- **Typesetting**:
  - loose lines (word spacing stretched past the configured threshold);
  - *CJK line set short*: a line of Chinese, Japanese or Korean text left short of its measure because filling it would spread its characters past the limit;
  - *Marks crowd the next line* and *Readings crowd the next line*: emphasis dots, name and title lines, or ruby readings that need more line gap than the paragraph has; the entry gives both, in em;
  - boxes that overflow their column;
  - *Chips touch the next line*: a chip whose box runs into a chip on the line above or below (the overlap is given in points); a tall chip with no chip above or below it is not flagged;
  - parity cascades;
  - *No hyphenation patterns for this language*: the document language (its hyphenation locale, else `locale`) has no bundled patterns, so its text is hyphenated with the US English ones. It goes away when hyphenation is switched off.
- **Browser**: storage unavailable (IndexedDB missing)

Each entry shows an icon, a title, a one-line detail and, where it applies, the chapter and source line (*Ch. 2 · Line 12* in a multi-chapter book). Clicking an entry with a source location switches to that chapter and focuses the editor at that spot. When nothing is wrong, the panel shows **All clear**. Which checks run is set in **Design → Advanced → Warnings**.

### Main viewport

The right side of the interface displays the rendered output. Three tabs are available, one per rendering mode — **Canvas**, **HTML** and **PDF**. Switching tabs does not re-run layout: the same VDT feeds every backend, so the content you see is consistent across modes.

Each viewport runs the layout pipeline inside a dedicated **Web Worker** (`postext/worker`). A per-viewport `useLayoutWorker` hook owns the worker handle, ships fonts into it as transferable `ArrayBuffer`s, and drives builds with **last-wins cancellation** — a keystroke or slider drag aborts the previous build's `AbortSignal` before the next one starts, so fast typing never queues up stale work on the main thread. Unmounting a viewport disposes its worker and rejects any pending build. See [Configuration → Running layout in a Web Worker](/en/docs/configuration#running-layout-in-a-web-worker) for the integration pattern used here.

#### Canvas tab

Renders a rasterized preview of the document on an HTML5 `<canvas>` element. This provides a pixel-accurate representation of how the final typeset document will look, including precise text positioning, column layout, and resource placement.

A toolbar at the top of the canvas viewport provides:

- **Zoom controls** — Zoom in and out (1.25x per step, range 0.25x–4x). Manual zooming disables fit mode.
- **Fit modes** — Fit to page width or fit to page height. Toggles on/off; fitting recalculates automatically on window resize.
- **View modes** — Single page (one page per row) or double-page spread (book-like layout where the first page appears on the right as a recto, and subsequent pages are paired as spreads). A book bound on the right (`page.binding`, vertical Chinese) shows its spreads the other way round: page 1 alone on the left, then `[3 | 2]`, `[5 | 4]`. On a vertical page a click lands on the character under the pointer, and the caret is a bar across the column.

Pages render lazily via `IntersectionObserver` — only visible pages (plus a 200px margin) are drawn to canvas, keeping GPU memory usage low for long documents.

#### HTML tab

Renders the postext output inside a Shadow DOM container, ensuring complete style isolation from the host page. The editorial CSS (typography, spacing, column rules) is injected inside the shadow root so it cannot be affected by or leak into the surrounding application styles.

Markdown links are live here and in the PDF (see [Document format › Links](/en/docs/document-format#links)). In this tab, clicking one opens its target in a new browser tab, so the Sandbox stays open; `:ref` citations still jump within the document.

A toolbar at the top of the viewport provides:

- **Font-scale controls** — Shrink or grow body text while preserving every relative measurement in the configuration.
- **Column modes** — Single (one tall scrollable column) or multi (the number of columns whose width comes closest to the configured measure, with horizontal scroll-snap between pages). A double-column document keeps its two-column pages, but the viewer may show an odd number of columns — three rather than two stretched or four squeezed — when that is the nearest fit; the last one then belongs to the next page, half in view.

Column geometry is driven by the **Web reader (HTML)** section of the Design panel (**Design → Export**): `maxCharsPerLine` sets the target measure in characters of the body font, `columnGap` the horizontal gap between columns in multi mode, and `optimalLineBreaking` toggles Knuth–Plass inside the viewer. See the [HTML Viewer configuration reference](/en/docs/configuration#html-viewer) and the end-to-end [integration example](/en/docs/configuration#integrating-the-html-viewer) for the same pattern used internally by the sandbox.

#### PDF tab

Generates a real PDF of the current document via the `postext-pdf` package and displays it inside an embedded browser PDF viewer. The PDF is rebuilt automatically on first mount and on every subsequent regeneration, using the same VDT that feeds the canvas and HTML tabs — so line breaks, page boundaries, and resource placement match pixel-for-pixel across the three backends, down to the compression of overfull final lines that Knuth–Plass occasionally accepts.

A floating toolbar at the bottom-right of the viewport provides:

- **Regenerate** (`RefreshCw` icon) — Rebuilds the PDF from the current markdown and configuration. Useful after changing a setting that does not auto-trigger a rebuild, or when fonts have finished loading.
- **Download** (`Download` icon) — Saves the current PDF to disk. The filename is derived from the document's first H1 heading (falling back to `document.pdf`).
- **Print** (`Printer` icon) — Opens the browser's print dialog against the embedded PDF viewer, which in most browsers lets you either print or save as PDF again.
- **Current chapter / Whole book** (selector at the left of the tab bar, books with more than one chapter) — Renders every chapter as one continuous PDF instead of the active chapter continued after the ones before it (the default). Changing it regenerates the PDF. The canvas has a selector of its own (see [Books and chapters](#books-and-chapters)).

Under the hood the sandbox uses a `createPdfFontProvider()` helper that fetches per-weight static WOFF2 files from the Fontsource jsdelivr CDN, decompresses them to TTF in the browser, and hands the bytes to `pdf-lib` via `renderToPdf`. Per-weight static fonts (rather than a single variable font) are required so that bold text actually embeds at the bold weight. See [Generating PDFs](/en/docs/configuration#generating-pdfs) for the same pattern used outside the sandbox.

## Books and chapters

Everything you open in the Sandbox is a **book**, the way an InDesign book file groups one document per chapter: the configuration, the custom fonts and the resource set are shared by the whole book, and each **chapter** is its own markdown document. Long works — a five-hundred-page textbook — are edited one chapter at a time, while numbering, cross-references and export still see one document.

- **Structure** lives in the Chapters panel and in the Text panel's chapter switcher: add, rename (double-click a row), reorder, split a chapter into one per level-1 heading, merge a chapter into the previous one, delete. Every chapter keeps its own undo history and caret.
- **One chapter at a time.** By default the previews lay out the **active chapter**, continued after the chapters before it: its first page number follows the last page of the previous chapter, level-1 headings keep counting (chapter 4 is numbered 4, its figures 4.1, 4.2, …), `{chapterNumber}` and `{chapterTitle}` running heads follow, recto/verso parity is kept (a chapter opener pads a blank page exactly as it would mid-book), and a `:ref` to a figure first mentioned in chapter 1 keeps that number. The page counts of the preceding chapters come from the layout that last showed each of them; chapters never visited (or edited since) are laid out in the background, one after the other, and the chapter list reads *pages pending* until they land. Page ranges are exact for chapters that open on a fresh page (the default); a chapter whose text would have run on from the previous page is placed at the top of its own page instead.
- **Whole book.** The canvas, the HTML preview and the PDF tab can show the whole book as one continuous document: pick **Whole book** in the selector at the left of the tab bar (books with more than one chapter). The canvas then lays out every chapter in order, each after the pages the ones before it came to, and shows the documents stitched together — an edit re-lays out its chapter alone, and the chapters after it only when their first page moved; the chapter list, the `chapter=` and `page=` parts of the permalink and the editor sync follow the page's chapter. The choice is kept with the book (a short novel reads as one document, a textbook one chapter at a time), and a preset can open that way through the manifest's `view.canvasScope`. The HTML preview shares the canvas choice and lays the whole book out as one document from its first page, the contents rows and the fragment following each page's chapter; the PDF tab keeps its own selector.
- **Long books.** A book of 120 chapters works like a short one. The chapter menu in the Text panel's header scrolls within the window and opens on the active chapter; the arrow keys move from it. A book in parts (`:::part` fences in its chapters) lists its chapters under their parts, in the menu and in the Chapters panel, and a click on a part in the menu opens its first chapter. Above 30 chapters the menu has a search field at the top that matches chapter numbers (`27`) and words of the titles and part names (`埋香`, `卷三`); Enter opens the first match. While an input method is composing (Zhuyin, Cangjie, pinyin, kana), Enter and the arrow keys belong to it: Enter confirms the conversion and opens nothing. A sample book's chapter files load eight at a time, and while the chapters are paginated in the background the Chapters panel shows the progress (*Paginating 34/120*). The canvas and the HTML preview show a book of more than 80 chapters one chapter at a time, whatever the book or its manifest ask: laying out every chapter of a 1,800-page book at once would hold the whole book in memory. The PDF tab can still export it whole.
- **Front matter.** The first chapter's front matter is the book's front matter (title, author, …). A front-matter block at the top of any other chapter is ignored, and the Checks panel says so. `buildBundle` follows the same rule, so a book renders the same in the Sandbox and in your own program.
- **Page counts.** Each chapter is laid out as a document of its own, so `{totalPages}` counts the chapter's pages. `{bookTotalPages}` counts the whole book: once every chapter's pages are known, the previews lay each chapter out with that total (only when a header, footer or design prints it). Until then a chapter prints the pages up to its own end. The PDF tab's **Whole book** counts the pages it lays out, so the file always prints the book's real total.
- **Chapter openers.** No page break is forced between chapters: a chapter whose first block is a level-1 heading opens on a fresh page through the heading's own *break before* setting, exactly like a chapter that starts mid-document.
- **Sync.** Clicking a paragraph of any chapter in the Canvas or HTML preview switches the editor to that chapter and places the caret; the editor caret is highlighted in the previews wherever the chapter sits in the book. Warnings carry their chapter.
- **Existing documents** open as a book with one chapter; nothing changes until a second chapter is added.

## Persistence

The Sandbox automatically saves your work to the browser:

- **Book and configuration** — The chapters, the active chapter and the canvas scope are auto-saved to `localStorage` under `postext-sandbox-book` (a single document saved by an earlier version is read from `postext-sandbox-markdown` as a one-chapter book and migrated on the first save); the configuration is saved after 1 second of inactivity with defaults stripped so only your overrides are stored, together with its version (`postext-sandbox-config-version`); a configuration saved before the version existed is read as described under *Heading breaks saved by postext 1.4 or earlier* below
- **UI state** — The active panel and viewport tab, sidebar width, the Design panel's open group (`postext-sandbox-settings-group`), its *Show every explanation* switch (`postext-sandbox-settings-help`) and section open states, hidden sample books, canvas zoom/fit/view modes, HTML font scale and column mode, and toolbar pin states are all persisted in `localStorage`
- **Open book** — The id of the open book of your own (a *project*) is stored in `localStorage` under `postext-sandbox-project`; the projects themselves (chapters, configuration and resource records; record `version: 8`, the engine's `CONFIG_VERSION`, which the working configuration and `postext-config.json` exports are stamped with too, so each is migrated once when the engine's rules change; single-document records from earlier versions are migrated when read, the heading breaks of records older than version 3, the maths size of records older than version 4, the space under inline figures of records older than version 5, the space around inline figures in boxes, the heading marks, the drop-cap sizes, the room under a colon line and the box cuts of records older than version 6, the breaks at dashes and the breaking of ragged text of records older than version 7, and the splits under a heading, the breaks at compounds' hyphens and the space under the `:::paragraphs` containers of records older than version 8 are pinned as described below) live in the `projects` store of the sandbox's IndexedDB database, and their binary payloads share the blob and font stores with the working document. Payloads are garbage-collected when neither the working document nor any project references them
- **Edited sample books** — Your version of a sample book (its chapters, active chapter, canvas scope, configuration and resource records, with what the sample applied when you opened it) is saved in the `presetDrafts` store of the sandbox's IndexedDB database, one record per sample and content language, and its files are kept by the garbage collection like a project's. Restoring the original deletes it
- **Sample book covers** — The cover taken from the first page of a sample book that ships no thumbnail is kept in the `presetCovers` store of the sandbox's IndexedDB database, one record per sample and content language (see [Books panel](#books-panel)). A book of your own keeps its cover in its project record.
- **Saving on the way out** — Pending edits are written at once when the page is hidden or closed, when you leave the sandbox through a link (the logo) and before another book opens, rather than after the 1-second pause
- **Open sample book** — The id of the last loaded preset is stored in `localStorage` under `postext-sandbox-preset`, so the panels' Reset buttons keep restoring that preset across sessions (a preset that is no longer served shows as unavailable). What that preset applied — its bundle fingerprint plus hashes of the markdown, configuration and resource set — is stored under `postext-sandbox-preset-applied`, which is how the next visit tells an untouched document from an edited one
- **Resources and fonts** — Resource records, their binary blobs (bitmaps and SVGs), and custom font files persist in **IndexedDB**; when IndexedDB is unavailable (e.g. some private-browsing modes), a *storage unavailable* warning appears in the Checks panel (under *Browser*)
- **Permalink** — The URL fragment names what is on screen, so a reload, a bookmark or a link passed to someone else lands on the same page of the same book in the same viewer: `#preset=bioquimica-feduchi&lang=es&view=canvas&chapter=1&page=7` opens the Bioquímica preset in Spanish on the Canvas tab at chapter 1, page 7 (the number printed on the page). A local project is named as `project=ID` — its storage id, so only the browser holding the project can follow such a link. The sandbox keeps the fragment current as you switch books, tabs and chapters and as you scroll. A part left out means whatever is there (no page: the chapter's first page; no book: the one last open), and a book the browser cannot open is passed over. Pasting a link into the address bar of an open sandbox opens it in place. When the page is opened on a link to another book than the one last open, the sandbox shows its loading state until the linked book is in, never the previous one. A host can also link to books of its own with the `hashBundles` prop (see [Props](#props)): the website opens a Cookbook recipe with `#recipe=<slug>&lang=es`. The first visit imports the recipe's `.postext` file as one of your books; later visits of the same link open that book, your edits included, and the fragment then names the project. The interface language stays in the path (`/en/sandbox`, `/es/sandbox`); `lang` is the content language of a bilingual bundle, any BCP 47 tag, kept in canonical case (`lang=zh-hant` reads `zh-Hant`). A tag the bundle does not list opens the edition that serves it: `zh-TW` and `zh-HK` open the Traditional Chinese one (`zh-Hant`), `zh` and `zh-CN` the Simplified one (`zh-Hans`), `en-GB` the English one. The other Chinese script is read only when the bundle has no edition in the reader's: a `zh-TW` link to a book in `zh-Hans` and English opens the Simplified text, not the English. A link without `lang` opens the bundle's `openLocale` when it names one, else the edition in the interface language. The chapter and page of a link apply to the edition it opens, and the fragment then names that edition by its own tag (`lang=zh-TW&chapter=28` becomes `lang=zh-Hant&chapter=28`).

**Heading breaks saved by postext 1.4 or earlier.** Up to postext 1.4, a configuration with a `headings` object laid its level-1 headings out with no page break unless it set the H1 *Break before* switch explicitly (and saving dropped a switched-off H1 break), a partial H1 break took its missing field from the no-break default, and a heading style's break did the same instead of merging onto its level's. The engine now keeps each level's default — H1 opens on a fresh recto (`always-odd`) — and merges a partial break onto it. So that a book saved then keeps the pages it had, the Sandbox writes those breaks out when it reads a project record older than version 3 or an unversioned working configuration: `enabled: false` on H1 where the break was off, and `parity: 'any'` beside an `enabled: true` that named no parity, on H1 and on heading styles. The Design panel then shows the break the pages were laid out with. Files record the version too since postext 1.5: a `.postext` file whose manifest has no `configVersion`, and a `postext-config.json` with none, were written by postext 1.4 or earlier, and are read the same way when they are imported or opened (see [Bundles written by postext 1.4 or earlier](/en/docs/configuration#bundles-written-by-postext-14-or-earlier)).

**Maths size saved before postext 1.5.** Up to postext 1.4 every formula came out 1.131 times larger than its *Size scale* says (see [Formula size](/en/docs/configuration#math)). So that a book saved then keeps its pages, the Sandbox pins that size when it reads a project record older than version 4, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 4`, or a `postext-config.json` exported before it: *Size scale* becomes the saved scale × 1.1312 and a display margin in `em` is divided by 1.1312, so the formulas and the space around them stay as they were. A book whose chapters have no `$` is left as it was (a `postext-config.json` carries no chapters, so its size is pinned whenever maths is on), and so is one with *Enable LaTeX* off. The Formulas section then shows the values the book is laid out with; reset *Size scale*, *Display margin top* and *Display margin bottom* to set it at today's size. The pin is written once: the record is saved again under the current version and read as it is from then on. A preset applied then and never edited still counts as untouched (the Sandbox compares it with its pinned values, and this holds for the heading-break pin too): reloading it or switching books does not ask to discard edits you never made, and a newer version of the preset, such as the built-in guide's, still replaces it.

**Inline figures saved before postext 1.5.** Up to postext 1.4 a figure or table set inline in the text (placement *Inline (here)*) kept a line of space above it only: the text after it resumed at the next grid line, however close that was. It now keeps the same line below it (**Columns → Space around inline figures**, *Above and below*). So that a book saved then keeps its pages, the Sandbox sets *Space around inline figures* to *Above only* when it reads a project record older than version 5, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 5`, or a `postext-config.json` exported before it, when a line of the book embeds a resource — `::resource{id="…"}` alone on its line, not a mention in the text. A `postext-config.json` carries no chapters, so there it is set whenever the file is older. Choose *Above and below* to lay the book out with today's spacing.

**Inline figures in boxes saved before postext 1.5.** Up to postext 1.4 a figure or table set inline inside a box sat right against the box text around it. It now keeps a line of the box text above it, and below it too with *Above and below* (**Columns → Space around figures in boxes**). So that a book saved then keeps its pages, the Sandbox switches *Space around figures in boxes* off when it reads a project record older than version 6, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 6`, or a `postext-config.json` exported before it, when a box of the book embeds a resource on a line of its own. A `postext-config.json` carries no chapters, so there it is switched off whenever the file is older. Switch it on to lay the book out with today's spacing.

**Heading marks and drop caps saved before postext 1.5.** Up to postext 1.4 a heading printed the words of its `*italic*`, `**bold**` and other marks in its own plain style, and a drop cap with no size was as tall as all the lines it spans, its top above the first line. A heading now sets its marks (**Headings → Inline marks in headings**), and a drop cap's top is level with the capitals of the first line. So that a book saved then keeps its pages, the Sandbox turns *Inline marks in headings* off when it reads a project record older than version 6, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 6`, or a `postext-config.json` exported before it, when a heading of the book carries a mark (a `postext-config.json` carries no chapters, so there it is turned off whenever the file is older); and it writes the size each drop cap was set at into its **Drop cap size**. Turn the switch on, or clear the size, to set the book with today's rules. Mind that an italic heading whose whole title is marked `*…*` then comes out upright.

**Lists after a colon saved before postext 1.5.** Up to postext 1.4 *Keep colon with list* took one line of room under the line ending in a colon as enough for the list, so a two-line first item that the orphan and widow rules keep whole went on to the next column and left the colon line alone at the foot. It now asks for the room the first item needs (**Typography → Body text → Widows, orphans and short lines → Room Under the Colon**, *What the first item needs*). So that a book saved then keeps its pages, the Sandbox sets *Room Under the Colon* to *One line (1.4)* when it reads a project record older than version 6, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 6`, or a `postext-config.json` exported before it, when a list of the book follows a line ending in a colon. A `postext-config.json` carries no chapters, so there it is set whenever the file is older. Choose *What the first item needs* to lay the book out with today's rule.

**Box cuts saved before postext 1.5.** Up to postext 1.4 a box that split inside a paragraph or list item could leave one line of it on a side, as long as each side of the box held its *Lines kept on each side of a split*. A cut now leaves at least two lines of the paragraph or item on each side (**Columns → Lines of a paragraph at a box cut**). So that a book saved then keeps its pages, the Sandbox sets *Lines of a paragraph at a box cut* to 1 when it reads a project record older than version 6, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 6`, or a `postext-config.json` exported before it, when a chapter of the book opens a `:::callout`. A `postext-config.json` carries no chapters, so there it is set whenever the file is older. Set it back to 2 to lay the book out with today's rule.

**Dashes and ragged text saved before postext 1.5.** Up to postext 1.4 optimal line breaking never ended a line after an em or en dash set closed between words (`say—that’s`), and ragged text was always set line by line, each line filled before the next. A line may now end after such a dash (**Typography → Body text → Paragraphs → Break After Dashes**), and ragged running text is broken with Knuth-Plass too (**Optimal Breaking of Ragged Text**). So that a book saved then keeps its pages, the Sandbox switches *Break After Dashes* off when it reads a project record older than version 7, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 7`, or a `postext-config.json` exported before it, when a chapter of the book sets such a dash (a `postext-config.json` carries no chapters, so there it is switched off whenever the file is older); and it switches *Optimal Breaking of Ragged Text* off when the configuration sets some running text ragged: the body text, a paragraph style, a box body, the body of a part or the body of a section style. Switch them on to lay the book out with today's rules.

**Splits under a heading saved before postext 1.5.** Up to postext 1.4 the paragraph under a heading at the foot of a column kept as many lines as fit there, however few went on to the next column. It now keeps the orphan minimum too, or the heading moves on with it (**Headings & contents → Headings → Split Under a Heading**). So that a book saved then keeps its pages, the Sandbox sets *Split Under a Heading* to *Fill the column* when it reads a project record older than version 8, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 8`, or a `postext-config.json` exported before it, when a chapter of the book has a heading (a `postext-config.json` carries no chapters, so there it is set whenever the file is older) and the configuration keeps *Keep With Next* and orphan control on. Set it to *By the rules* to lay the book out with today's rule.

**Paragraph containers saved before postext 1.5.** Up to postext 1.4 the space under a `:::paragraphs` container was the style's own (the larger of its space between paragraphs and its bottom margin), set under the last line before the text snapped back to the grid; the space a heading keeps above itself was added under it, and the body's paragraph spacing did not count, so a heading sat further from a bibliography than from a paragraph, and the paragraph after a group of tight entries sat closer to it than to any other. The space now merges with the next block's own and is at least the text's paragraph spacing (**Typography → Paragraph styles → Space under a container**, *Collapse*). So that a book saved then keeps its pages, the Sandbox sets *Space under a container* to *Add (1.4)* when it reads a project record older than version 8, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 8`, or a `postext-config.json` exported before it, when the configuration declares a paragraph style and a chapter of the book opens a `:::paragraphs` container. A `postext-config.json` carries no chapters, so there it is set whenever the file is older and declares a paragraph style. Choose *Collapse* to lay the book out with today's rule.

**Compounds saved before postext 1.5.** Up to postext 1.4 optimal line breaking never ended a justified line after the hyphen of a compound (`well-known`) in a paragraph without bold, italics or other formatting, while it did in one with formatting. A line may now end there in every paragraph (**Typography → Body text → Paragraphs → Break After Hyphens**). So that a book saved then keeps its pages, the Sandbox switches *Break After Hyphens* off when it reads a project record older than version 8, a working configuration saved under an older stamp (or none), a `.postext` file whose manifest is older than `configVersion: 8`, or a `postext-config.json` exported before it, when a chapter of the book sets a hyphen between two letters (a `postext-config.json` carries no chapters, so there it is switched off whenever the file is older). Switch it on to lay the book out with today's rule.

These pins hold back what each of those rule changes would move. Version 1.5 also fixes layout bugs, and a fix has no pin, so a saved book can still see a page move where one of them applies: the band of a page-wide chapter heading without a design, a drop cap in a heading design, a paragraph in a box, a loose paragraph that balancing stretches, a floated box with a margin wider than a line, a centred or right-aligned running head with tracking, the second column under a page-wide opener, a running head taken from a heading broken after a hyphen, a word wider than its line cut next to its own hyphen, the rest of a word wider than its line, which now keeps its own break points, the item after a list nested in another (see [Formula size](/en/docs/configuration#math) for the list).

Storage is **shared across UI locales**. A pristine default document swaps to the current locale's default markdown and reseeds the example resources when the locale changes — so opening the Spanish sandbox shows Spanish examples. Any user edit opts the document out of this behavior. All previews also derive a hyphenation locale from the UI locale when the configuration names no language (neither a hyphenation locale nor `locale`).

### Export and import

A whole book travels as a **`.postext` file**: a zip archive with exactly the layout of a preset bundle directory — `preset.json`, `chapters/*.md`, `resources/*` and `fonts/*` (see [Preset bundle format](#preset-bundle-format)). The archive also carries the book's **pagination** as `layouts.json` — each chapter's page count and numbering, stamped with the engine version, configuration and resources it was built with — so an imported book opens paginated and only what those stamps no longer vouch for is laid out again. The active document exports the pagination it holds; a project or preset exported from its row carries the one recorded while it was last the working book. A cover image is written as the manifest's `thumbnail`, so it survives the round trip. The **Books panel**'s **New** menu (**Open a .postext file…**) imports a file as a new book; every row's ⋯ menu has its own **Download (.postext)**, and the open book's exports the working document. Files written by earlier versions (a version 1 manifest with a single `document.md`) import as a one-chapter book. A book in one language keeps the figure and table labels of that language whatever the interface language: a Spanish file opened from `/en/sandbox` prints *Figura* and *Tabla* unless its configuration names other resource types. The language is the one the file names or, when it names none, the one its configuration sets (`locale`, then the hyphenation language). Import accepts the files at the archive root or under one top-level folder (as produced by zipping the folder itself; `__MACOSX` entries and dotfiles are ignored). Fonts are written as separate files, never inside `config.customFonts`; `.woff` faces are skipped with a warning both ways, as are resources whose bytes are missing. Unzip an exported file into `<presets-root>/<dir>/` and add an `index.json` entry to serve it as a preset.

The same files are read and written by the `postext` package (`openBundle`, `createBundle`, `buildBundle`; see [Bundles](/en/docs/configuration#bundles-postext-files)). A book exported here opens in your own program, and a book your program writes opens here. That makes the Sandbox a place to inspect and fine-tune what a program lays out: export it from the program, import it here, fix it with the live preview, export it again and load it back in the program. The [agent skill](/en/docs/skill) delivers its ports as `.postext` files too.

The text and the design also export separately from the Text and Design panel headers.

The **Design panel** header downloads `postext-config.json` with defaults stripped:

```json
{
  "type": "postext-config",
  "version": 1,
  "config": { ... }
}
```

The **Text panel** header downloads the active chapter as a plain `.md` file and its **Import** button replaces the active chapter with a `.md` file's contents. The Design panel's **Import** button opens a file picker for `.json` files validated against the expected `type` and `version`; invalid files are silently ignored. The `postext-markdown.json` wrapper and the combined `postext-sandbox.json` format from earlier versions no longer exist.

## Standalone usage

The Sandbox is available as a standalone React package (`postext-sandbox`) that can be embedded in any React application:

```bash
npm install postext-sandbox postext
```

```tsx
import { PostextSandbox } from 'postext-sandbox';

function App() {
  return (
    <PostextSandbox
      initialMarkdown="# Hello World"
      initialConfig={{ layout: { layoutType: 'double' } }}
      onMarkdownChange={(md) => console.log(md)}
      onConfigChange={(cfg) => console.log(cfg)}
    />
  );
}
```

### CSS requirements

The package uses Tailwind CSS utility classes that reference CSS custom properties. Your host application must provide these variables:

- `--background`, `--foreground` — Base colors
- `--surface` — Elevated surface color; `--surface-2` — Hovered rows and highlighted options (falls back to `--background`)
- `--slate` — Muted text color
- `--rule` — Border/divider color; `--rule-strong` — Stronger rule for hovered controls (falls back to `--slate`)
- `--brand` — Accent color: the active panel marker, focus rings, switches and selected choices
- `--brand-hover` — Accent color on hover
- `--brand-soft` — Translucent accent fill behind selected choices (falls back to `--surface`)
- `--brand-contrast` — Knob of a checked switch (falls back to `--background`)
- `--destructive` — Color of destructive actions and errors
- `--accent-blue` — Link/accent color
- `--font-sans` — UI font family
- `--font-mono` — Monospace font family (for the code editor)
- `--font-display`, `--brand-blue`, `--brand-gilt` — Optional face and colours of the default logo mark in the activity bar (fall back to Georgia, `#2b4acb` and `#d8a21a`)

The website sets `--brand` to gilt in the dark theme and blue in the light one. Earlier versions read `--gilt` and `--gilt-hover`; the sandbox no longer uses them.

Popovers, menus and tooltips render in a portal on `document.body`, so define the variables on `:root` (or `body`), not only on the element that wraps the sandbox. The host's Tailwind build must scan the package's sources (`@source "…/postext-sandbox/src/**/*.tsx"` in Tailwind 4) so the utility classes it uses are generated.

## Preset bundle format

Appendix. A preset source is a directory (served over HTTP) whose root holds an `index.json` listing preset directories; each directory holds a `preset.json` manifest plus the markdown, resource and font files it refers to. The `scripts/presets/` tooling in the repository scaffolds bundles in exactly this shape, and a `.postext` file exported from the sandbox is one such directory zipped (without the `index.json`).

```
<presets-root>/
  index.json
  <preset-dir>/
    preset.json
    chapters/              one .md per chapter, in order (a version 1 manifest names a single document instead)
    resources/             figures: .svg / .png / .jpg / .jpeg / .webp / .gif (+ optional .pdf print masters)
    fonts/                 .otf / .ttf / .woff2 single faces
```

### `index.json`

```jsonc
{
  "version": 1,
  "presets": [
    {
      "id": "acme-journal",          // stable id, [a-z0-9-]
      "dir": "acme-journal",         // directory name relative to index.json
      "name": "Acme Journal",
      "description": "Two-column journal article",   // optional
      "locale": "en",                 // optional
      "default": true,                // optional, at most one
      "locales": ["en", "es"],        // optional: every locale the bundle carries
      "openLocale": "en",             // optional: the locale it opens in when none is asked for
      "thumbnail": "thumbnail.jpg",   // optional: preview shown in the picker
      "license": "CC BY 4.0",         // optional: shown as a tag
      "credits": "Text and images: ESO",  // optional: one line under the description
      "tags": ["magazine", "two-column"], // optional
      "binding": "left"               // optional: the edge the website's shelf draws the spine on ("right" for a right-bound book)
    }
  ]
}
```

### `preset.json`

```jsonc
{
  "version": 2,
  "id": "acme-journal",
  "name": "Acme Journal",
  "description": "Two-column journal article",       // optional
  "locale": "en",                                     // optional
  "default": true,                                    // optional
  "configVersion": 8,                                 // optional: the configuration rules `config` is written for
  // The same optional showcase fields as the index entry:
  // "locales", "openLocale", "thumbnail", "license", "credits", "tags"

  // The book's chapters, in order — or one list per locale
  "chapters": [
    { "title": "Introduction", "file": "chapters/01-introduction.md" },
    { "title": "Methods", "file": "chapters/02-methods.md" }
  ],
  // "chapters": { "en": [ … ], "es": [ … ] },
  // Version 1 manifests use a single document instead and are still accepted:
  // "version": 1, "markdown": "article.md"  (or a locale → file map)

  // Optional PostextConfig JSON (page, margins, columns, typography...).
  // Do NOT put customFonts here: fonts come from the `fonts` array below.
  "config": { },

  "resources": [
    {
      "id": "fig-1-1",                 // referenced from markdown (:ref)
      "typeId": "figure",              // resource type id (figure, table, ...)
      "kind": "svg",                   // "svg" | "bitmap" | "table"
      "file": "resources/fig-1-1.svg", // svg/bitmap only, relative to preset.json
      "width": 240.5,                  // optional, pt (svg) / px (bitmap)
      "pdfFile": "resources/fig-1-1.pdf", // optional, svg only: vector print master (see notes)
      "height": 180,                   // optional
      "caption": "Caption text",
      "altText": "Accessible description",            // optional
      "placement": { "position": "top", "span": "column" },  // optional
      "note": "Source: ...",                          // optional
      "table": { "model": { "rows": [[{ "content": "A", "isHeader": true }]], "headerRowCount": 1 } }
                                                      // kind "table" only
    }
  ],

  "fonts": [
    {
      "name": "Some Family",           // family name used by the config
      "variants": [
        { "weight": 400, "style": "normal", "file": "fonts/SomeFamily-Regular.otf" },
        { "weight": 400, "style": "italic", "file": "fonts/SomeFamily-Italic.otf" },
        { "weight": 700, "style": "normal", "file": "fonts/SomeFamily-Bold.otf" }
      ]
    }
  ]
}
```

Notes:

- `id` in `preset.json` must match the `index.json` entry; `description`, `locale` and `default` in the manifest override the index values once the preset is loaded, as do the showcase fields `locales`, `openLocale`, `license`, `credits` and `tags`. `openLocale`, one of `locales`, is the language the book opens in when a link or a click asks for none (the home page's shelf links to it too): set it when the original is not in the reader's language, as the 紅樓夢 showcase does with `zh-Hant`, so that its English translation does not open for every English-speaking reader. Without it the interface language picks. The picker shows every locale in `locales` (or `locale`) and the licence as tags, the credits under the description, and `thumbnail` — a small page image relative to the preset directory — in place of the row's check-mark column; a book copied from the preset (**Make my own copy**) keeps it as its cover. The public showcase presets under `apps/web/public/presets/` use every field and carry a `CREDITS.md` with the licence and source of each text and image.
- `configVersion` (optional) names the configuration rules `config` and the `localized` configurations are written for. Every writer since postext 1.5 sets it to 8. A manifest without it was written by postext 1.4 or earlier, and its heading breaks, maths size, space around inline figures (in the text and in boxes), heading marks, drop caps, room under a colon line, box cuts, breaks at dashes and at compounds' hyphens, ragged text, splits under a heading and space under paragraph containers are read as 1.4 laid them out (see *Heading breaks saved by postext 1.4 or earlier*, *Maths size saved before postext 1.5*, *Inline figures saved before postext 1.5*, *Inline figures in boxes saved before postext 1.5*, *Heading marks and drop caps saved before postext 1.5*, *Lists after a colon saved before postext 1.5*, *Box cuts saved before postext 1.5*, *Dashes and ragged text saved before postext 1.5*, *Compounds saved before postext 1.5*, *Splits under a heading saved before postext 1.5* and *Paragraph containers saved before postext 1.5* under [Persistence](#persistence)); one stamped 3 to 7 (a 1.5 prerelease) gets the pins of the later rules only. With 3 that is the maths size, the inline gap, the five pins of rules 6, the two of rules 7 and the three of rules 8; with 4, the inline gap and the pins of rules 6, 7 and 8; with 5, the pins of rules 6, 7 and 8; with 6, the pins of rules 7 and 8; with 7, the pins of rules 8 alone. Set it to 8 when you write a manifest by hand for today's rules.
- `view` (optional) says how the sandbox opens the bundle: `{ "canvasScope": "book" }` lays the whole book out on the canvas (see [Books and chapters](#books-and-chapters)); absent, the canvas shows one chapter at a time. Exported books carry it when it is set.
- `localized` (optional) holds per-locale overrides for a bilingual bundle: `{ "es": { "config": { … }, "resources": [ { "id": "fig-1", "caption": "…", "note": "…", "altText": "…" } ] } }`. The overrides of the locale the chapters were picked from apply on top of the shared `config` (top-level keys replaced wholesale — `resourceTypes` with translated caption prefixes, typically) and `resources` (caption, note, alt text and table cells merged by id); a locale without an entry keeps the shared wording.
- `chapters` (version 2) is a list of `{ title, file }` in book order, or a locale → list map; `markdown` (version 1) is a file name or a locale → file map. In both cases the sandbox picks the entry matching the locale asked for (exact tag, case aside; then the same language and script, so `zh-TW` reads `zh-Hant` before `zh-Hans`; then the same language in the other script, so a `zh-TW` reader of a bundle keyed by bare `zh` gets the Chinese; then the preset's own `locale`, then the first entry), and only that locale's chapter files are read. An empty chapter `title` is derived from the file's first level-1 heading. The sandbox always writes version 2.
- `width` / `height` are optional for `svg` and `bitmap` resources — when missing they are read from the file at load time.
- `pdfFile` (svg resources only) points to a single-page PDF holding the same figure as vectors — typically the original Illustrator or PDF export the SVG was derived from. The PDF export embeds that page verbatim (fonts, gradients and colour spaces intact) instead of the SVG; the canvas and HTML previews keep using the SVG. It is ignored in single-ink mode, whose recolouring pass only operates on SVG markup, and a missing file only drops the master, never the figure. Editing the SVG source in the resource detail detaches the master (it was made for the source as it was), so the PDF export follows the edited SVG from then on; restore the original (**Restore the original…** in the Books panel) to get it back. SVGs without a master are emitted as vector paths when they stay within the PDF backend's subset (basic shapes, paths, groups, `use`, clip paths, solid fills and strokes, opacity, and `text` / `tspan` runs set in the fonts the document can load — custom fonts first, then Google-hosted families) and rasterised at 600 dpi otherwise.
- SVG `text` renders in the sandbox's custom fonts everywhere: the previews inline the matching `@font-face` data into the SVG before decoding it (an `<img>` cannot see the page's fonts), and the PDF export sets the runs as real, selectable text in the same embedded faces. Name the family in `font-family` exactly as it appears under Fonts.
- The SVG source editor only lets you type inside text nodes (tinted) so a figure cannot be broken by accident; the lock button in its header opens the whole source — coordinates, colours, structure — and locking again rescans the text nodes.
- `table.model` is a Postext `TableModel`: `rows` is a row-major array of cells (`content`, optional `colSpan`, `rowSpan`, `isHeader`, `align`, `verticalAlign`), `headerRowCount` the number of leading header rows, and `columnWidths` an optional array of relative column weights. `table.styleId` optionally names one of the config's `tableStyles`.
- Font files are stored in IndexedDB under ids derived from the preset id and file path, and the families are appended to `config.customFonts` when the preset is applied; a missing or malformed `index.json` yields no presets rather than an error.
- `<preset-dir>/fingerprint.json` is optional and, on the development route, **virtual**: when no such file exists, `GET` answers `{ "fingerprint": "<sha1 hex>", "files": <n> }` computed from the directory's file metadata (relative path, modification time and size of every file up to four levels deep, dotfiles and `node_modules` skipped), never from file contents, with `Cache-Control: no-store`. The sandbox polls it to follow edits to the bundle (see [Books panel](#books-panel)). A static host can serve a real `fingerprint.json` with the same shape, or none at all, in which case its presets are not followed.
