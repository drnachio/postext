# Configurazione: font, colori e output


## Unità e colori

### Dimensioni

Tutte le misure fisiche in Postext usano il tipo `Dimension`, un valore abbinato a un’unità:

```ts
interface Dimension {
  value: number;
  unit: DimensionUnit; // 'cm' | 'mm' | 'in' | 'pt' | 'px' | 'em' | 'rem'
}
```

**Unità assolute** (`cm`, `mm`, `in`, `pt`, `px`): vengono convertite in pixel con i DPI configurati. A 300 DPI, `1 cm` equivale a circa 118 px.

**Unità relative** (`em`, `rem`): scalano con il corpo corrente. Un `em` è relativo al corpo dell’elemento stesso; `rem` è relativo al corpo del testo corrente.

### Colori

I colori si memorizzano con una rappresentazione esadecimale e con un modello di colore di destinazione:

```ts
interface ColorValue {
  hex: string;         // '#ff0000', 'transparent', etc.
  model: ColorModel;   // 'hex' | 'rgb' | 'cmyk' | 'hsl'
  cmyk?: CmykPercent;  // The exact process values of a colour authored in CMYK.
  paletteId?: string;  // La voce di colorPalette che segue.
}
```

Il campo `model` indica lo spazio colore previsto. Per il rendering web, sono tipici `'hex'` o `'rgb'`. Per i flussi di stampa, `'cmyk'` dice che il colore è stato specificato in CMYK, e `cmyk` ne conserva i valori: un rendering di stampa in CMYK li imposta così come sono, con `hex` come loro resa a schermo (vedi [Colori definiti in CMYK](#colori-definiti-in-cmyk)).

Poiché Postext punta a un output di qualità editoriale, il colore predefinito del testo corrente ha `model: 'cmyk'` (`#000000`). I colori di titoli, grassetto, corsivo ed elenchi sono collegati per impostazione predefinita al **Main Color** della tavolozza (`#295AA3`, `model: 'hex'`). Lo sfondo della pagina e le sovrimpressioni dell’interfaccia (griglia della linea di base, segni di taglio, indicatori di debug) hanno per impostazione predefinita `model: 'hex'`. Sostituisci `color.model` su qualsiasi campo se ti serve una semantica di esportazione diversa.

### Trasparenza

Un colore può essere traslucido. `hex` accetta un canale alfa, come `#rgba` o `#rrggbbaa`. Accetta anche un colore `rgb()` / `rgba()`, con la sintassi a virgole o a spazi, con l’alfa come numero o come percentuale. `transparent` è del tutto trasparente:

```ts
const config: PostextConfig = {
  header: {
    elements: [{
      kind: 'box',
      id: 'veil',
      placement: {
        anchor: { to: 'bleed', edge: 'top-left' },
        size: { width: 'fill', height: { value: 40, unit: 'mm' } },
      },
      style: { backgroundColor: { hex: '#ffffffb3', model: 'hex' } }, // white at 70 %
    }],
  },
  bodyText: { color: { hex: 'rgba(0, 0, 0, 0.85)', model: 'rgb' } },
};
```

I tre backend lo disegnano allo stesso modo. Il canvas e il visualizzatore HTML prendono il valore come colore CSS. Il backend PDF imposta l’opacità del colore come alfa costante, un `ExtGState` con `ca` per i riempimenti e `CA` per i tratti. Questo vale per testo, filetti, riquadri, riempimenti e bordi delle tabelle, chip, campioni di colore e formule. Un colore traslucido si compone sopra tutto ciò che è stato disegnato prima. Un riquadro nell’intestazione o nel piè di pagina viene disegnato per ultimo, quindi vela il testo sottostante; un riquadro in una fascia di apertura viene disegnato per primo, quindi tinge la pagina sotto il testo. Quando il PDF viene forzato in un altro spazio colore (`pdfGeneration.forceColorSpace` con `colorSpace: 'cmyk'` o `'grayscale'`), il colore viene convertito e la sua alfa mantenuta. Nella Sandbox, il cursore dell’opacità del selettore di colore scrive questi valori come `#rrggbbaa`, e il selettore legge anche le altre forme.


## Font personalizzati

Postext risolve ogni stringa `fontFamily` sia nel catalogo di Google Fonts **sia** nella lista `customFonts` del documento. In caso di omonimia prevalgono i font personalizzati: se dichiari `customFonts: [{ name: 'Roboto', … }]`, Postext usa il file che hai caricato invece del «Roboto» di Google Fonts. Le famiglie che Google Fonts non ha, la Sandbox le prende da Fontsource. Non interroga mai Fontsource per un nome generico (`serif`, `system-ui`) né per un font fornito con un sistema operativo (Arial, Segoe UI, PingFang SC…): una famiglia del genere viene composta con quello che ha il computer del lettore, il pannello **Font** la mostra come *Non trovato*, e il PDF e le immagini SVG non ne hanno alcun file da incorporare. Se il libro è composto in quel font, caricalo come font personalizzato.

Usa i font personalizzati quando:

- Il documento ha bisogno di un carattere di marca o con licenza che non è su Google Fonts.
- L’ambiente non può raggiungere le CDN dei font, jsDelivr (da cui la Sandbox prende i file di Fontsource) o Google Fonts (offline, intranet, contesti sensibili alla privacy).
- Devi tenere privato il file binario del font e non caricarlo presso terzi.

### Schema di configurazione

```ts
type CustomFontFormat = 'woff2' | 'woff' | 'ttf' | 'otf';
type CustomFontStyle = 'normal' | 'italic';

interface CustomFontVariant {
  weight: number;           // CSS font-weight, 100..900
  style: CustomFontStyle;
  fileId: string;           // opaque id of the binary in out-of-band storage
  format: CustomFontFormat;
  fileName?: string;        // original upload filename (optional, shown in UI)
}

interface CustomFontFamily {
  name: string;             // used anywhere a Google Font family name fits
  variants: CustomFontVariant[];
  redistributable?: boolean; // false: usata qui, mai copiata fuori dal libro
  fallback?: string;        // famiglia libera di larghezza simile per i tagli senza file (da postext 1.42)
}

interface PostextConfig {
  // ...
  customFonts?: CustomFontFamily[];
}
```

Il binario di ogni variante **non** è incorporato nella configurazione stessa. La configurazione contiene solo puntatori `fileId`; i byte stanno altrove. Nella Sandbox, questo significa IndexedDB (archivio chiave-valore, solo nel browser, privato del documento). Chi integra Postext in un altro host è libero di risolvere `fileId` come preferisce (un endpoint di un server, una cache di un service worker, qualsiasi cosa), purché i byte arrivino al thread principale prima che venga eseguito `buildDocument`.

### Gestire i font personalizzati nella Sandbox

Apri il pannello **Font** dalla barra delle attività a sinistra (tra Risorse e Grafica). La sua lista **Caratteri di questo libro** mostra ogni famiglia che il progetto grafico usa, con il suo ruolo e la sua provenienza: Google Fonts, Fontsource (per una famiglia che Google Fonts non ha), un tuo file o da nessuna parte (*Non trovato*). In **I tuoi file di font**, per ogni famiglia:

1. **Aggiungi famiglia**: crea una famiglia vuota; rinominala direttamente nella riga.
2. **Carica varianti**: scegli un peso (100–900) e uno stile (normale / corsivo), poi seleziona uno *o più* file `.woff2`, `.woff`, `.ttf` o `.otf`. Ogni file diventa una variante a sé legata alla coppia (peso, stile) selezionata in quel momento; il nome del file caricato viene memorizzato e mostrato nella riga, così puoi distinguere le varianti. Puoi regolare di nuovo il peso o lo stile di una variante dai suoi menu a tendina in qualsiasi momento.
3. **Le varianti duplicate sono ammesse.** Se due file finiscono nella stessa posizione (peso, stile), vengono tenuti entrambi e compare un avviso **Variante di font duplicata**, così sai che devi distinguere le impostazioni di quelli in più.
4. **Elimina variante** o **Elimina famiglia**: rimuove la voce dalla configurazione *e* i byte memorizzati da IndexedDB.

Una volta dichiarata una famiglia, ogni selettore di font la raggruppa sotto **Personalizzati**, sopra la lista di Google Fonts. Quando la selezioni, la famiglia viene collegata a ogni campo di famiglia di font a cui la applichi.

### Una famiglia sostitutiva per una famiglia con licenza

Un libro può essere composto in un carattere che il suo titolare non può cedere. Segna la famiglia con `redistributable: false` e un file `.postext` ne lascia fuori i file. Se in `fallback` nomini una famiglia libera di larghezza simile, il file che si apre senza di essi va a capo quasi negli stessi punti del carattere vero, invece di far traboccare le sue cornici con un font di riserva più largo. I tagli di cui la famiglia non ha il file sono composti nei tagli del `fallback` con lo stesso peso e la stessa inclinazione, con il nome della famiglia con licenza, nelle anteprime, nel worker di impaginazione, nel PDF e nella riga di comando. Una famiglia con file li mantiene; dal `fallback` prende soltanto l’inclinazione di cui non ha alcun file, un corsivo per esempio, e i pesi intermedi tra i suoi file si scelgono come per qualsiasi famiglia. Nel pannello Font, **Famiglia sostitutiva** (dentro la famiglia, sopra i suoi file) riceve il nome; vuoto, la famiglia resta com’era. Il PDF di un libro composto così incorpora il carattere libero, quindi il PDF finale si fa con i file con licenza. Da postext 1.42. Da postext 1.43 la famiglia libera va anche dove quella con licenza non può andare: un EPUB o un'esportazione HTML, dalla Sandbox o da `postext`, porta gli stili della sostitutiva con il nome della famiglia con licenza, come le immagini SVG il cui testo è composto in quella famiglia; il sistema di lettura compone così il libro in un carattere della larghezza per cui sono state spezzate le righe. I file propri della famiglia non escono mai dal libro. Una famiglia senza `fallback`, o con una sostitutiva senza file, viene indicata senza file, come prima; la scheda EPUB della Sandbox elenca le famiglie composte in una sostitutiva.

### Comportamento del rendering

Dietro le quinte:

- Quando `customFonts` cambia, ogni famiglia dichiarata viene registrata automaticamente come voci `FontFace` su `document.fonts`: così il visualizzatore HTML, la vista Canvas (che misura tramite `document.fonts`) e qualsiasi riferimento CSS diretto prendono il carattere personalizzato senza che l’utente debba prima aprire il selettore di font.
- Il worker di impaginazione riceve gli stessi ArrayBuffer attraverso il percorso di trasferimento dei font già esistente, quindi la misurazione (`buildFontString`, pretext) funziona come per una famiglia del catalogo.
- Quando modifichi o rimuovi una variante, il worker scarta il carattere che teneva in cache per quella famiglia e lo registra di nuovo alla build successiva, così le anteprime restano allineate all’insieme di varianti corrente.
- **Esportazione PDF**: i binari caricati passano per la stessa pipeline `PdfFontProvider`. I file `.woff2` vengono decompressi; `.ttf` e `.otf` passano così come sono. `.woff` viene rifiutato con un errore chiaro (pdf-lib non può incorporare WOFF grezzo: ricaricalo come `.woff2`/`.ttf`/`.otf`). L’OpenType con contorni CFF (`.otf` con il magic number `OTTO`) viene incorporato **senza sottoinsieme**, perché il generatore di sottoinsiemi CFF di pdf-lib percorre ogni glifo al momento di `save()` e su font reali può restare bloccato per minuti; rinunciare al sottoinsieme significa ottenere un PDF un po’ più grande in cambio di tempi di rendering costanti.

### Avvisi di font mancanti

Il pannello **Verifiche** della Sandbox elenca nel suo gruppo *Font* tre tipi di problema specifici dei font personalizzati (tutti attivati dallo stesso interruttore `debug.warnings.missingFont` che già controlla l’avviso generico «non caricato»):

- **Famiglia di caratteri sconosciuta**: un `fontFamily` richiama un nome che non hanno né Google Fonts né Fontsource e che non è una famiglia personalizzata dichiarata. Scatta anche subito quando elimini una famiglia personalizzata che qualche campo `fontFamily` richiama ancora, invece di aspettare che se ne accorga il DOM.
- **Variante di font mancante**: la famiglia esiste, ma il libro le chiede un peso e uno stile per cui non c’è alcun file caricato: titoli in grassetto, per esempio, in una famiglia che ha solo il tondo. L’avviso elenca le combinazioni che mancano. Un’inclinazione fornita dal `fallback` della famiglia non conta come mancante.
- **Variante di font duplicata**: due o più file caricati condividono la stessa posizione (peso, stile) dentro una famiglia. Al momento del rendering se ne usa davvero uno solo; l’avviso ti invita a regolare di nuovo le voci rimanenti.

Un clic su uno qualsiasi di questi avvisi apre il pannello Font, così puoi caricare la variante mancante, aggiungere di nuovo la famiglia o distinguere i duplicati.

Quando esiste un’impaginazione, il pannello elenca anche il **Font di ripiego nell’impaginazione** del motore (`fontFallback`): un carattere senza il quale sono state misurate le pagine, mancante oppure disegnato dal browser a partire da un altro peso o da un’altra inclinazione. Una famiglia già indicata come sconosciuta o priva di una variante non viene elencata due volte. Prima della prima impaginazione, la sostituisce un controllo su `document.fonts`.

Il pannello elenca anche i **Caratteri presi da un altro font** (`glyphFallback`): caratteri che il testo compone in un font privo di glifi per loro, una volta per font, con la famiglia generica che li ha disegnati (`serif`, `sans-serif`, `monospace`) quando il controllo può dirlo.

## Stili delle cifre

`figureStyle` chiede al font di uno stile di testo un certo tipo di cifre, attraverso le funzionalità OpenType del font: cifre elzeviriane nel testo corrente, cifre allineate tabulari nelle tabelle. Il campo si trova in `bodyText`, `paragraphStyles[]`, `headings` e `headings.levels[]`, `headingStyles[]`, `tableStyle` e `tableStyles[]` (celle di intestazione e di corpo allo stesso modo), `captionStyle` (etichetta e descrizione, e il `captionStyle` di un tipo di risorsa) e negli elementi di testo di un design (testatine, numeri di pagina, i testi di una pagina d’apertura o di una pagina di parte). Nella Sandbox è il campo **Cifre** del pannello Grafica, accanto al carattere di ciascuno di questi stili (**Testo corrente → Carattere** per il corpo del testo).

Una coppia fissa una forma e una larghezza. Un font senza la funzionalità mantiene le proprie cifre: controlla che il font abbia `onum` o `lnum` prima di contarci. Una famiglia di cui l’host non ha alcun file, come un font installato solo sul sistema del lettore (la Sandbox non li scarica), non prende alcuno stile delle cifre: il suo testo mantiene le cifre di quel font, nel font stesso. Un libro che carica file con quel nome ottiene le cifre. I tagli serviti da Google Fonts e Fontsource spesso lasciano fuori `onum` e `lnum` (il file latin di Source Serif 4 conserva solo `pnum` e `tnum`); con un file del genere, uno stile che li chiede mantiene le cifre del font. I file completi della fonderia li hanno: caricali per avere cifre elzeviriane o allineate. Una famiglia generica (`serif`, `sans-serif`) non prende funzionalità. Un valore fuori dalla lista viene segnalato come valore di impostazione sconosciuto (`unknownConfigValue`, vedi [Avvisi di configurazione](#avvisi-di-configurazione)) e letto come non impostato.

```ts
const config: PostextConfig = {
  bodyText: { fontFamily: 'EB Garamond', figureStyle: 'oldstyle' },
  tableStyle: { figureStyle: 'lining-tabular' },
  paragraphStyles: [{ id: 'timetable', figureStyle: 'lining-tabular' }],
  headings: { figureStyle: 'lining' },
};
```

Il testo compone anni e numeri di pagina con cifre elzeviriane, e così fanno le didascalie e gli elenchi, che prendono la famiglia del corpo del testo. Le celle di tutte le tabelle e i paragrafi dello stile `timetable` mettono in colonna le cifre con cifre allineate tabulari. Tutti i livelli di titolo compongono cifre allineate nella famiglia dei titoli.

### Quali cifre prende uno stile

- Uno stile che prende la famiglia da un altro ne prende anche le cifre. Gli stili di paragrafo, le tabelle, le didascalie, gli elenchi e il contenuto dei riquadri prendono la famiglia del corpo del testo quando non ne nominano un’altra, quindi `bodyText.figureStyle` arriva a tutti.
- Uno stile che nomina un proprio `fontFamily` compone le cifre predefinite di quel font, a meno che non imposti anche `figureStyle`.
- Un livello di titolo senza un proprio `figureStyle` prende `headings.figureStyle`, anche nel proprio `fontFamily` quando ne nomina uno. Il `figureStyle` di uno stile di titolo si applica alla famiglia del livello su cui lo stile è usato.
- Un elemento di testo di un design nomina una propria famiglia (`'EB Garamond'` come predefinita), quindi le cifre del corpo del testo non arrivano a un numero di pagina: imposta lì `figureStyle: 'oldstyle'` per accordarlo a un testo in cifre elzeviriane.
- `'default'` compone le cifre del font e annulla quelle ereditate: `paragraphStyles: [{ id: 'plain', figureStyle: 'default' }]` toglie a quello stile le cifre elzeviriane del corpo del testo.

### Le cifre in ogni uscita

Il testo viene misurato con le funzionalità, così le righe vanno a capo alle stesse larghezze nell’anteprima Canvas, nell’HTML, nel PDF e nell’EPUB, a layout fisso come fluido.

- **Anteprima Canvas e worker di impaginazione**: il browser dichiara una seconda volta i file della famiglia di base con un nome di famiglia con funzionalità e il descrittore `featureSettings` di `FontFace`. Il nome è la famiglia seguita dalle sue funzionalità dopo `@` (`EB Garamond@onum`, `EB Garamond@lnum+tnum`) e compare nelle stringhe di font e in alcuni avvisi.
- **HTML ed EPUB** (layout fisso e fluido): la famiglia di base, con `font-variant-numeric` (`oldstyle-nums`, `lining-nums tabular-nums`).
- **PDF**: incorpora i file della famiglia di base e compone il testo con le funzionalità.
- **Riga di comando**: Skia, il canvas con cui disegna `postext`, non applica funzionalità. La riga di comando registra una copia del font la cui `cmap` porta ogni carattere che le funzionalità sostituiscono, le cifre, al glifo che scelgono. Si prendono solo le sostituzioni semplici; un font che arriva alle proprie cifre con sostituzioni contestuali lì mantiene le sue.

## Tavolozza dei colori

La proprietà `colorPalette` di `PostextConfig` ti permette di definire un insieme riutilizzabile di colori con nome e di richiamarli da qualsiasi `ColorValue` della configurazione. È l’equivalente in Postext delle proprietà personalizzate CSS o del pannello Campioni di InDesign: modifichi una volta la voce della tavolozza, e ogni colore che vi punta si aggiorna in tutto il documento.

```ts
interface ColorPaletteEntry {
  id: string;       // stable identifier — referenced by ColorValue.paletteId
  name: string;     // human label shown in sandbox UIs
  value: ColorValue;
}
```

### La tavolozza predefinita

Postext viene fornito con una tavolozza predefinita di una sola voce chiamata **Main Color** (`id: 'main-color'`, hex `#295AA3`). Diversi valori predefiniti (colore dei titoli, colore del grassetto e del corsivo del testo corrente, colore di `:ref`, colori dei punti elenco e dei numeri degli elenchi) richiamano questa voce tramite `paletteId: 'main-color'`, quindi basta cambiare quel campione per ricolorare ogni parte del documento che lo usa.

Puoi ispezionare, clonare o confrontare la tavolozza predefinita con tre esportazioni:

```ts
import {
  DEFAULT_COLOR_PALETTE,
  cloneDefaultColorPalette,
  isDefaultColorPalette,
} from 'postext';

// Read-only snapshot of the shipped palette.
DEFAULT_COLOR_PALETTE;
// => [{ id: 'main-color', name: 'Main Color', value: { hex: '#295AA3', model: 'hex' } }]

// Independent copy — mutate this, not DEFAULT_COLOR_PALETTE.
const palette = cloneDefaultColorPalette();

// Detect whether a user has customised the palette at all.
isDefaultColorPalette(palette); // true
```

Una tavolozza sta al livello superiore della configurazione:

```ts
const config: PostextConfig = {
  colorPalette: [
    { id: 'ink',    name: 'Ink',    value: { hex: '#0a0a0a', model: 'cmyk' } },
    { id: 'accent', name: 'Accent', value: { hex: '#b8860b', model: 'hex' } },
  ],
  bodyText: { color: { hex: '#000000', model: 'cmyk', paletteId: 'ink' } },
  headings: { color: { hex: '#000000', model: 'hex', paletteId: 'accent' } },
};
```

### Richiamare una voce della tavolozza

Qualsiasi `ColorValue` della configurazione può portare un campo facoltativo `paletteId` che punta a una voce di `colorPalette`: sfondo della pagina, colori del testo corrente (compreso il colore di `:ref`), colori dei titoli, filetti tra le colonne, colori degli elenchi, colori di tabelle, didascalie, chip e riquadri (riquadro, banda, icona, indicatore, etichetta, titolo, corpo), colori dei segni di taglio e della griglia della linea di base, indicatori di debug e ogni colore della grafica: le testatine, le aperture dei titoli e la grafica nella colonna, la grafica e le testatine degli stili dei titoli, le pagine di parte e le righe delle parti nell’indice (testo, filetto, riempimento e bordo del riquadro, contorno, capolettera). Quando è presente, `hex` / `model` della voce della tavolozza prevalgono sui valori di riserva `hex` / `model` memorizzati accanto. Il valore di riserva in linea si usa solo se la tavolozza manca, è vuota o non contiene quell’id: utile quando distribuisci una configurazione che verrà letta da uno strumento che non conosce le tavolozze.

**Cambiato in postext 1.5.** Fino a postext 1.4 la tavolozza raggiungeva solo una lista fissa di impostazioni: i colori della grafica (testatine, aperture, stili dei titoli, parti, righe dell’indice), `bodyText.referenceColor`, i colori delle etichette dei riquadri e i colori del grassetto e del corsivo del corpo dei riquadri mantenevano l’`hex` memorizzato accanto al loro `paletteId`. Un documento il cui valore memorizzato è diverso dalla voce della tavolozza (ogni documento modificato nella Sandbox dopo che la voce è cambiata, e ogni `:ref` quando il Main Color non è `#295AA3`) ora stampa il colore della tavolozza, come prevede il collegamento. Per mantenere un colore com’era, rimuovi il suo `paletteId`.

### Come si applicano le tavolozze

`buildDocument` applica la tavolozza in due punti, così i colori richiamati funzionano sia per le sostituzioni che hai scritto esplicitamente sia per i valori predefiniti che vengono compilati dopo:

1. `applyPaletteToConfig(config)`: risolve ogni `ColorValue` della configurazione grezza dell’utente che porta un `paletteId`. Utile quando vuoi ispezionare ciò che il motore vedrà davvero.
2. `applyPaletteToResolvedConfig(resolved, palette)`: viene eseguita *dopo* la risoluzione dei valori predefiniti e riscrive i valori predefiniti collegati alla tavolozza (colore dei titoli, colore del grassetto e del corsivo del testo corrente, colore di `:ref`, colori degli elenchi, i colori della grafica predefinita) perché corrispondano alla tavolozza attiva.

Entrambe percorrono l’intera configurazione, quindi nessun colore collegato alla tavolozza resta indietro. La maggior parte dei colori del flusso del testo (testo corrente, titoli, elenchi, tabelle, didascalie, chip, il riquadro, il titolo e il corpo dei riquadri) ne esce come valori semplici. Tutti gli altri (i colori della grafica, il colore di `:ref`, le etichette dei riquadri) prendono `hex` / `model` della tavolozza e **mantengono il loro `paletteId`**. Quel collegamento è ciò che l’attributo `palette` di una parte e la sostituzione `palette` di uno stile di titolo modificano sulle loro pagine (vedi [Parti](/it/docs/configuration-styles#parti)), quindi deve sopravvivere. `htmlViewer.overrides` resta come è scritto: il visualizzatore HTML lo unisce per primo, e una tavolozza che contiene si applica poi a tutto, grafica compresa.

Raramente avrai bisogno di chiamarle tu, ma entrambe sono esportate, così puoi ispezionarle o riutilizzarle:

```ts
import {
  applyPaletteToConfig,
  applyPaletteToResolvedConfig,
  resolveColorValue,
} from 'postext';

const flat = applyPaletteToConfig(config);
// Every ColorValue with a paletteId in the raw config now carries the
// palette entry's hex/model (a design colour keeps its paletteId).

// `applyPaletteToResolvedConfig` is typically handled by buildDocument; use it
// directly if you build a ResolvedConfig yourself and want the palette applied.
```

`resolveColorValue(value, palette, fallback)` è la variante per un singolo valore, comoda quando componi configurazioni in modo imperativo e devi risolvere un colore alla volta.

### Modificare la tavolozza

Un colore il cui `paletteId` non corrisponde ad alcuna voce stampa i suoi `hex` / `model` memorizzati, che possono essere più vecchi del colore che la voce gli aveva dato. Quindi, prima di rimuovere una voce, riscrivi ogni `ColorValue` collegato a essa come colore semplice con il valore attuale della voce. La sezione *Tavolozza* della Sandbox (**Grafica → Colori**) lo fa quando elimini una voce, ovunque si trovi il colore (grafica ed etichette dei riquadri comprese), e la sua conferma elenca ogni impostazione che usa la voce: per nome, o con il suo percorso nella configurazione (`header.elements[2].color`).

## Visualizzatore Canvas

## Generazione del PDF (configurazione)

La proprietà `pdfGeneration` controlla come il backend PDF produce il documento finale. Queste impostazioni le usa il pacchetto `postext-pdf` al momento dell’esportazione; i visualizzatori canvas e HTML le ignorano.

`buildDocument` le porta nel VDT, come `doc.config.pdfGeneration`, e `renderToPdf` prende ogni impostazione dal primo punto che la fornisce:

1. le sue opzioni (`outlines`, `accessible`, `colorSpace`);
2. il `pdfGeneration` del primo documento di cui fa il rendering (in un libro, le impostazioni del primo capitolo valgono per l’intero file);
3. i valori predefiniti: segnalibri e tag attivi, colore RGB.

Quindi `renderToPdf(doc, { fontProvider })` segue la configurazione, e un’opzione passata a `renderToPdf` prevale solo per quell’impostazione. `forceColorSpace` e `colorSpace` insieme fanno le veci dell’opzione `colorSpace`: il `colorSpace` della configurazione si applica mentre `forceColorSpace` è attivo, e il PDF è RGB mentre è disattivo. Le versioni precedenti di `postext-pdf` leggevano solo le opzioni; una configurazione che imposta `pdfGeneration` ora cambia il PDF di un chiamante che non passa alcuna opzione.

```ts
type PdfColorSpace = 'rgb' | 'cmyk' | 'grayscale';

interface PdfGenerationConfig {
  outlines?: boolean;          // Emit PDF bookmarks from the heading tree.
  forceColorSpace?: boolean;   // Convert every colour to `colorSpace`.
  colorSpace?: PdfColorSpace;  // Target space used when `forceColorSpace` is true.
  accessible?: boolean;        // Tagged, PDF/UA-oriented output (structure tree, alt text, language).
}
```

## Produzione di stampa (configurazione)

La proprietà `print` stabilisce come un libro va in stampa: lo standard PDF/X del file, il profilo di output con cui si separa il suo CMYK, come si stampa il nero e le soglie del preflight. L’impaginazione la ignora, quindi cambiarla non sposta mai una riga. La leggono tre cose: `postext-pdf` quando scrive il file, `preflightDocument` quando verifica un documento impaginato e l’anteprima di stampa dei visualizzatori canvas e Folio.

  convertImages?: boolean;                 // Separate RGB pictures (PDF/X-1a always does).
  inkLimit?: number;                       // Total area coverage, percent.
  black?: PrintBlackConfig;
  preflight?: PrintPreflightConfig;

  name: string;           // Its description, or the file name.
  fileId: string;         // The stored .icc file.
  registryName?: string;  // The condition's ICC registry name (FOGRA51…), else 'Custom'.
  inkLimit?: number;
}

### PDF/X-1a e PDF/X-4

Entrambi gli standard scrivono:

- l’output intent (`GTS_PDFX`) che indica la condizione di stampa e incorpora il profilo di destinazione;
- l’identificazione nel dizionario Info (`GTS_PDFXVersion`, `/Trapped /False`, il titolo e le date) e nei metadati XMP (`pdfxid:GTSPDFXVersion`, gli id del documento e della versione), unita all’identificazione PDF/UA quando il file ha i tag;
- un TrimBox e un BleedBox su ogni pagina (l’intera pagina quando non ci sono linee di taglio);
- l’`/ID` del trailer;
- ogni colore in DeviceCMYK (o grigio) attraverso il profilo, e i segni di taglio in colore di registro;
- nessuna annotazione di collegamento: un file per la stampa non ne contiene alcuna dentro il suo bleed box, quindi i collegamenti del PDF per lo schermo vengono esclusi (i segnalibri restano).

PDF/X-1a:2003 è PDF 1.4 senza flussi di oggetti e non ha trasparenza: un colore traslucido viene composto come verrebbe stampato sulla carta, l’alfa di un’immagine viene appiattita sul bianco e il negativo di pagina di debug viene escluso (con un avviso `pageNegativeIgnored`). PDF/X-4 è PDF 1.6: la trasparenza resta, ogni pagina riceve un gruppo di trasparenza che fonde in CMYK, e le immagini RGB mantenute da `convertImages: false` vengono marcate sRGB tramite `/DefaultRGB`.

Un master di stampa PDF (`svg.pdfFileId`) viene incorporato così com’è, quindi i suoi colori, font e trasparenze sono i suoi; il preflight segnala ciò che contiene.

`preflightDocument(doc, options)` esegue le verifiche su un documento impaginato e restituisce una lista di problemi, ognuno con un `kind`, una `severity` (`'critical'`, `'warning'` o `'info'`), il `pageIndex` assoluto nel libro, il `rect` incriminato (px della pagina) e, quando l’elemento ce l’ha, il suo intervallo nella sorgente. I tipi sono `lowImageResolution`, `declaredPixelsMismatch`, `rgbImage`, `thinRule`, `smallProcessText`, `inkLimit`, `safeZone` e `nearTrim`. Senza un `transform` un neutro conta come un inchiostro e qualsiasi altro colore come tre, e la copertura non viene verificata; con un `transform`, i conteggi e la copertura sono esatti. La risoluzione di un’immagine si ricava dai pixel che la sua risorsa dichiara, o da quelli del file stesso quando `imageSize(fileId)` li fornisce (`bitmapInfo` sui byte, o l’immagine decodificata): una dichiarazione che si discosta dal file di più di un pixel viene segnalata una volta come `declaredPixelsMismatch`, un avviso quando dichiara più pixel di quanti ne abbia il file. `placedImageResolutions(doc, { resources, imageSize })` elenca ogni bitmap collocata con i suoi ppi effettivi, che il preflight sia attivo o no. Le etichette di una figura contano come testo per `smallProcessText`, `inkLimit` e `safeZone`.

```ts
import { bitmapInfo, outputTransform, parseIccProfile, preflightDocument, resolvePrintConfig } from 'postext';
import { inspectPrintMaster } from 'postext-pdf';

const print = resolvePrintConfig(config.print);
const transform = outputTransform(parseIccProfile(fogra51Bytes), { intent: print.renderingIntent });
const issues = preflightDocument(doc, {
  print,
  transform,
  resources,                                    // pixel sizes of the bitmaps
  imageSize: (fileId) => bitmapInfo(bytesOf(fileId)),  // the files' real pixels
  imageColor: (fileId) => colourOf(fileId),     // 'rgb' | 'cmyk' | 'gray', from the file
});
if (issues.some((i) => i.severity === 'critical')) process.exit(1);

const master = await inspectPrintMaster(masterBytes);
// => { nonEmbeddedFonts: ['Helvetica'], rgb: true, transparency: false }
```

### Anteprima di stampa

Una pagina canvas si può disegnare come verrà stampata. `createPrintPreview(transform, print, { paper, dpi, grayscale })` costruisce la prova a video di una configurazione: ogni pixel viene separato con il profilo (neutri solo in K, come nel PDF) e riportato a schermo, sul bianco proprio della carta quando `paper` è true; le aree nere abbastanza grandi per il nero ricco appaiono in nero ricco. Con `grayscale`, la prova è una stampa in scala di grigi: un PDF forzato in scala di grigi stampa la luma di ogni colore con il solo inchiostro nero, senza nero ricco. Passala a `renderPageToCanvas` come `printPreview`. Per una vista di lavoro, non una prova, `guides` aggiunge le linee del taglio, dell’abbondanza e della zona sicura e `marksFor` contorna aree di una pagina (i `rect` del preflight); la Sandbox li esclude entrambi, quindi la sua anteprima mostra solo la stampa. `postext-folio` accetta lo stesso oggetto come `printPreview`; con `paper: true`, dai intanto al libro una tinta di carta neutra (`folio.paper.shade`), altrimenti la carta viene tinta due volte.

```ts
import { createPrintPreview, renderPageToCanvas } from 'postext';

const preview = createPrintPreview(transform, print, { paper: true, dpi: doc.config.page.dpi });
renderPageToCanvas(page, doc, canvas, {
  printPreview: { ...preview, guides: { safeZonePx: 59 }, marksFor: () => issues.map((i) => i.rect!).filter(Boolean) },
});
```

### Motore del colore

La gestione del colore che usa postext è esportata per i tuoi strumenti. Legge i profili ICC v2 e v4 (matrice/TRC e le tabelle di ricerca `mft1`, `mft2`, `mAB`, `mBA`) in TypeScript puro, senza WebAssembly.

- `parseIccProfile(bytes)` legge un profilo; `deviceChannels(profile)` ne dà il numero di canali.
- `outputTransform(profile, { intent, blackPointCompensation, preserveNeutrals })` restituisce `fromRgb(r, g, b)` (sRGB 0..1 → CMYK 0..1), `toLab(cmyk, paper?)` e `proof(cmyk, paper?)` (CMYK → sRGB dello schermo).
- `cmykToLab`, `labToCmyk`, `srgbToLab`, `labToSrgb`, `deltaE` e `totalAreaCoverage` sono le singole conversioni; `buildRgbLut` / `sampleRgbLut` creano e leggono tabelle di ricerca dense per il lavoro sui pixel.
- `OUTPUT_PROFILES`, `outputProfileInfo(id)` e `loadOutputProfile(id, baseUrl?)` forniscono il catalogo; `srgbProfileBytes()` scrive il profilo sRGB con cui PDF/X-4 marca l’RGB; `authoredCmykColors(config)` elenca i colori che una configurazione ha definito in CMYK.

Le funzioni di risoluzione e di pulizia si comportano come nelle altre sezioni: `resolvePrintConfig`, `stripPrintDefaults` e `profileInkLimit(config)` (il limite del profilo indicato da una configurazione, prima di qualsiasi sostituzione con `inkLimit`), con `DEFAULT_PRINT_CONFIG`, `DEFAULT_PRINT_BLACK_CONFIG`, `DEFAULT_PRINT_PREFLIGHT_CONFIG` e `DEFAULT_RICH_BLACK`.

### Coppie accettate

Un porting conserva la tavolozza dell’originale, e alcune sue coppie restano sotto la soglia: una tinta chiara dietro il testo di un riquadro, un colore del marchio in una testatina. `allow` le accetta senza spegnere il controllo (da postext 1.52). Una voce indica il colore del testo `fg` e quello del fondo `bg` (in esadecimale, come li scrive la configurazione o come sono dipinti), oppure uno `style`: l’id di uno stile di riquadro (`calloutStyles`, o lo `style` di una cornice di pagina composta), di paragrafo, di titolo, di etichetta in linea o di etichetta di figura. Ogni campo che una voce dà deve corrispondere, quindi `{ style: 'note', fg: '#7a8a99' }` accetta quel grigio solo dentro i riquadri `note`. Una voce che non dà nessuno dei tre non corrisponde a nulla.

```ts
contrast: {
  allow: [
    { fg: '#b7820f', bg: '#ffffff', reason: "L'ocra dell'editore per le testatine" },
    { style: 'nota-margine', reason: "L'originale compone le note a margine in un grigio chiaro" },
  ],
}
```

Una coppia accettata viene ancora segnalata: ogni risultato che vi corrisponde porta `accepted` (il `reason` della voce, con il suo `fg`, `bg` e `style`), e i risultati accettati vengono dopo gli altri. Il Sandbox li elenca nei Controlli, sotto Coppie di contrasto accettate, con il motivo, e non li conta; `postext check` li stampa come note, che non fanno fallire `--strict`. Gli stessi colori fuori da ciò che la voce indica restano un avviso.

### Schermo e stampa

Postext compone le stesse pagine per uno schermo e per una macchina da stampa, e un colore non si legge allo stesso modo sui due.

- **Schermo** è il rapporto di contrasto WCAG 2 dei colori sRGB, `(L1 + 0.05) / (L2 + 0.05)` sulle loro luminanze relative: ciò che mostrano il canvas, il visualizzatore HTML, un EPUB e un PDF RGB.
- **Stampa** è la stessa formula applicata alla luminanza che ogni colore ha sulla carta. Il colore viene separato con il profilo di output del lavoro (uno definito in CMYK mantiene i suoi valori), la separazione viene riletta attraverso il profilo, e la sua luminanza viene presa rispetto alla carta nuda, che è il bianco di una pagina stampata come il bianco del display è il bianco di uno schermo. L’inchiostro non è mai un nero perfetto: il nero pieno su bianco arriva a circa 14:1 su carta patinata (FOGRA39, FOGRA51), 8:1 su carta usomano (FOGRA47, FOGRA52) e 5:1 su carta da giornale (IFRA26, SNAP), dove uno schermo dà 21:1. Un grigio che supera la verifica a schermo può non superarla sulla carta: `#767676` su bianco è 4,54:1 a schermo e circa 3,3:1 su carta patinata.

Il rapporto di stampa ha bisogno della trasformazione del profilo di output (`options.transform`, costruita con `outputTransform`). Senza di essa, per la stampa si verifica solo il testo in negativo.

### Testo in negativo

Il testo chiaro ricavato in risparmio da un fondo inchiostrato si impasta in macchina quando è piccolo o i suoi tratti sono sottili: l’inchiostro del fondo si allarga dentro le lettere, e un fondo fatto di più inchiostri dipende anche dal fatto che le lastre restino a registro. Il rapporto non lo mostra, perché il bianco su blu scuro supera 10:1. La verifica di stampa segnala questo testo a parte (`reversedText`) quando è sotto `minSize`, o sotto `minFineSize` quando è in corsivo o con un peso di `lightWeight` o inferiore. Ogni risultato indica di quanti dei quattro inchiostri è fatto il fondo.

### Che cosa si legge

La verifica legge le righe di ogni blocco con i loro colori in linea (grassetto, corsivo, rimandi, chip), i segni degli elenchi, i capilettera, le didascalie, le note e le celle di tabella, e il testo degli spazi della grafica: testatine, aperture, grafica dei titoli, titoli dei riquadri. Il fondo è il riempimento più in alto sotto il testo: un riquadro della grafica, un riquadro di testo, una barra di didascalia, una cella di tabella, un chip, oppure il colore della pagina (`page.backgroundColor`, o la carta che la tavolozza di una parte dà alle sue pagine). Un colore traslucido viene fuso con ciò che sta sotto. Il testo sopra un’immagine viene saltato, perché il suo fondo non è un solo colore, e lo stesso vale per il lettering dei fumetti, le letture ruby e le formule. Le parole delle etichette di una figura si leggono sulla loro piastra o, altrimenti, dentro il loro alone; le etichette nude sull’immagine vengono saltate, come ogni testo su un’immagine.

In una pagina composta la verifica segue l'ordine in cui la pagina viene dipinta: le cornici per livello, con la `decoration` del modello al livello 0. Il testo di una cornice si legge sul riquadro della cornice stessa quando il suo stile ne dipinge uno; altrimenti sul riquadro della decorazione che sta sotto (un'immagine della decorazione lo esclude, come ogni immagine); altrimenti sul colore della pagina. Lettere bianche su una linguetta colorata della decorazione vengono quindi misurate contro quella linguetta. Una cornice ruotata o scalata viene riportata sul foglio prima di leggerne il fondo, e il testo della decorazione stessa si verifica allo stesso modo. Da postext 1.37.

### Eseguire la verifica

`contrastDocument(doc, options)` restituisce i risultati di un documento impaginato, a partire dal rapporto più basso. Ognuno ha il `pageIndex` assoluto nel libro, il `rect` sul foglio (px della pagina) e l’intervallo nella sorgente della sua prima occorrenza, i due colori come vengono disegnati (`color`, `background`), il `sizePt` più piccolo con cui è composto con il suo `weight` e `italic`, un `role` (`'body'`, `'heading'`, `'caption'`, `'table'`, `'runningHead'`, `'design'`, `'chip'`, `'marker'` o `'label'`, le parole delle etichette di una figura), il `text` della prima sequenza e il `count` delle sequenze composte così. Una coppia viene segnalata una volta per soglia, per quante righe la usino.

- `lowContrast` aggiunge `level`, `large`, `required`, il rapporto in ogni resa verificata (`screen`, `print`) e `failing`, le rese sotto `required`.
- `reversedText` aggiunge `reasons` (`'small'`, `'italic'`, `'light'`), `minimumPt` e `inks`.

Le opzioni sono `contrast` (le impostazioni risolte, quando non sono quelle del documento), `media` (le rese, qualunque sia il valore di `mode`) e `transform`.

```ts
import { contrastDocument, outputTransform, parseIccProfile } from 'postext';

const transform = outputTransform(parseIccProfile(fogra51Bytes));
for (const issue of contrastDocument(doc, { transform })) {
  if (issue.kind === 'lowContrast') {
    console.log(`${issue.color} on ${issue.background}: ${issue.screen}:1, ${issue.level} asks for ${issue.required}:1`);
  }
}
```

`contrastPairs(doc, options)` restituisce ogni coppia di testo e fondo che il documento compone, che superi la verifica o no, con il suo rapporto `screen`, il suo rapporto `print` quando si fornisce la trasformazione, il rapporto `required` e i colori come li scrive la configurazione (`textColor`, `groundColor`): ciò che uno strumento di progettazione mostra accanto a un campo colore. Viene eseguita qualunque sia il valore di `enabled`.

Le misure sono esportate per i tuoi strumenti:

- `contrastRatio(a, b)` e `relativeLuminance(color)` danno il rapporto WCAG 2 e la luminanza dei colori sRGB.
- `isLargeText(sizePt, weight)` e `contrastThreshold(level, large)` danno la soglia di un corpo e di un peso.
- `blendColors(top, under)` dà un colore traslucido sopra un altro, come `#rrggbb`.
- `printContrastRatio(a, b, context)`, `printLuminance(color, context)` e `printSeparation(color, context)` danno lo stesso sulla carta. Il contesto contiene il `transform` e, come `authored`, il risultato di `authoredCmykColors(config)`.
- `contrastMedia(doc.config, contrast)` dà le rese a cui `mode` si risolve per un documento.

Le funzioni di risoluzione e di pulizia si comportano come nelle altre sezioni: `resolveContrastConfig` e `stripContrastDefaults`, con `DEFAULT_CONTRAST_CONFIG`, `DEFAULT_CONTRAST_REVERSED_TEXT_CONFIG`, `CONTRAST_LEVELS` e `CONTRAST_MODES`.


## Controllo del contenuto (configurazione)

La proprietà `checks` raccoglie i controlli che leggono la configurazione stessa. Oggi ne ha uno, `contentInConfig`, che avvisa quando la grafica contiene il testo del libro. ### Come si legge un testo grafico

- Il suo testo letterale è il suo `content` senza alcun segnaposto (`{name}`, `{attr.key}`, `{firstMark.key}`), con gli escape `{{` e `}}` letti come parentesi graffe e `\n` come a capo.
- Un testo senza lettere né cifre (una fila di puntini di guida, un ornamento, un `·`) non è mai contenuto.
- Una parola è ciò che sta fra due spazi e contiene una lettera o una cifra: un `·` o una `|` isolati non sono parole, e un indirizzo come `postext.dev` è una parola.
- Prima si tolgono le frasi di `allow`, e anche `title`, `subtitle`, `author` e `publisher` dei metadati del documento (il suo front matter), che una testatina ripete spesso.
- Ciò che resta è contenuto quando ha più di `maxWords` parole o più di `maxChars` lettere e cifre.

Si leggono tutti gli spazi della grafica: `header`, `footer`, l’`advancedDesign.slot` di ogni livello di titolo, l’`advancedDesign.slot`, l’`header` e il `footer` di ogni stile di titolo, `parts.design`, `parts.versoDesign`, `toc.parts.design`, e gli stessi dentro `htmlViewer.overrides`. `configDesignSlots(config)` li elenca con i loro percorsi, e `designTextLiteral(content)` restituisce il testo letterale di un modello.

### L’avviso

`collectConfigWarnings` (e `VDTDocument.configWarnings`) dà un avviso `contentInConfig` per ogni impostazione che contiene contenuto: uno stile di titolo (con il suo `id` in `ownerId`), un livello di titolo, l’intestazione, la grafica delle parti. `path` indica l’impostazione, `count` i testi grafici coinvolti, `chars` le loro lettere e cifre, `elements` il percorso di ciascuno (i primi 20) e `value` l’inizio del primo (al massimo 40 caratteri). Passa i metadati del documento come secondo argomento per ammetterne titolo e autore; un’impaginazione lo fa da sola.

```js
import { collectConfigWarnings } from 'postext';

collectConfigWarnings(config, { metadata: { title: 'A Year of Weather' } });
// [{ kind: 'contentInConfig', path: 'headingStyles[3]', ownerId: 'lesson-4',
//    value: 'Look at the picture and answer the questi…', used: '',
//    count: 30, chars: 1017, elements: ['headingStyles[3].header.elements[2]', …] }]
```

**Soluzione:** sposta il testo nel Markdown, come titolo, riquadro o paragrafo del capitolo a cui appartiene, e lascia solo segnaposto nella grafica. Un valore che cambia a ogni capitolo può viaggiare sulla riga del titolo ed essere letto con `{attr.key}`: `# Carte {kicker="Lezione 4"}` e `{attr.kicker}` nella grafica. Una frase che è forma, come il nome dell’editore in una testatina, va in `allow`.

La Sandbox mostra l’avviso nel pannello **Verifiche** e offre il controllo in **Grafica → Avanzate → Contenuto nella configurazione**; `postext check` lo stampa.

Una pagina in formato da giornale (`page.sizePreset` `'broadsheet'`, `'berliner'`, `'tabloid'` o `'compact'`) viene mostrata come un giornale quando la configurazione non indica né una carta né una legatura: carta `newsprint` e legatura `folded` (da postext 1.18). Una carta o una legatura indicata dalla configurazione viene mantenuta, quindi `paper: { type: 'uncoated' }` stampa un tabloid su carta offset. I campi della carta impostati senza una carta (una `grammage`, uno `shade`) si applicano alla carta da giornale. La funzione di risoluzione e quella di pulizia prendono il formato come secondo argomento, e `folioForTrim(folio, sizePreset)` scrive i due valori predefiniti nella configurazione:

```ts
resolveFolioConfig({ tilt: 30 }, 'tabloid');
// => { tilt: 30, paper: { type: 'newsprint', grammage: 48, bulk: 1.5, … }, binding: { type: 'folded', coverMaterial: 'paper', … }, … }

stripFolioDefaults({ paper: { type: 'newsprint' }, binding: { type: 'folded' } }, 'tabloid');
// => undefined
```

I colori seguono i collegamenti alla tavolozza come qualsiasi altro colore della configurazione (`paletteId`). Le funzioni di risoluzione e di pulizia si comportano come nelle altre sezioni; quella di pulizia elimina i valori della carta uguali a quelli della carta scelta:

```ts
import { FOLIO_PAPER_STOCKS, DEFAULT_FOLIO_CONFIG, resolveFolioConfig, stripFolioDefaults } from 'postext';

resolveFolioConfig({ paper: { type: 'bible' } }).paper;
// => { type: 'bible', grammage: 40, bulk: 1.1, finish: 'uncoated', texture: 'vellum', textureStrength: 1, shade: { hex: '#f9f6ee', … }, showThrough: true }

stripFolioDefaults({ paper: { type: 'bible', grammage: 40 } });
// => { paper: { type: 'bible' } }
```

Nella Sandbox queste impostazioni sono il gruppo **Folio** del pannello Grafica (**Grafica → Folio → Visualizzatore Folio (3D)**), e la scheda Folio le mostra mentre le modifichi, senza reimpaginare il libro. Vedi [Un libro in 3D](/it/docs/configuration-html-folio-epub#un-libro-in-3d-postext-folio) per il visualizzatore stesso, e [Formato del documento › `:::paper`](/it/docs/document-format-directives#paper) per una sequenza di pagine su un’altra carta.

### Righe lasche nel tuo canvas

Il motore esporta l’evidenziazione delle righe lasche come due funzioni di supporto, per una pagina che dipingi tu:

```ts
import { buildDocument, renderPageToCanvas, drawLooseLines, findLooseLines } from 'postext';

const doc = buildDocument(content, config);
const canvas = document.querySelector('canvas')!;
renderPageToCanvas(doc.pages[0], doc, canvas, { scale: 0.5 });
drawLooseLines(canvas.getContext('2d')!, doc.pages[0], doc, { threshold: 2.5 });

// The same lines as data: a report, an SVG overlay, a count per page.
for (const { ratio, line, block } of findLooseLines(doc, { threshold: 2.5 })) {
  console.log(`page ${block.pageIndex + 1}: ${ratio.toFixed(2)}× — ${line.text}`);
}
```

- **`findLooseLines(doc, { threshold?, pageIndex? })`** restituisce, in ordine di lettura, ogni riga giustificata la cui spaziatura tra le parole supera `threshold`: `{ block, line, ratio, x, y, width, height }`. `ratio` è `lineWordSpacing(line)`: la spaziatura così come la limitano `minWordSpacing` e `maxWordSpacing` (`justifiedSpaceLimitRatio` quando la riga contiene spazi di un altro carattere, altrimenti `justifiedSpaceRatio`), così una riga composta al limite con uno spazio in grassetto non viene segnalata con una soglia pari a `maxWordSpacing`. Il rettangolo, in pixel della pagina, è la fascia coperta dall’evidenziazione: l’intera larghezza del blocco lungo la riga. Sono le righe che la Sandbox evidenzia e segnala come `looseLine` nel suo pannello **Verifiche**.
- **`drawLooseLines(ctx, page, doc, { threshold?, color? })`** riempie quelle fasce per una pagina e restituisce le righe che ha dipinto. Disegna in pixel della pagina sotto la trasformazione corrente del contesto, quindi chiamala subito dopo `renderPage` o `renderPageToCanvas` sullo stesso canvas: entrambe lasciano il contesto scalato alla pagina. `color` è qualunque stile di riempimento del canvas.
- **Valori predefiniti.** Entrambe le funzioni usano la soglia (3) e il colore (`#ff000040`) predefiniti, non il `debug.looseLineHighlight` del documento: quell’impostazione appartiene alla Sandbox. Per seguire una configurazione, passa `resolveDebugConfig(config.debug).looseLineHighlight.threshold` e `.color.hex`.

### Avvisi

`debug.warnings` decide quali problemi di composizione compaiono nel pannello **Verifiche** della Sandbox (si modifica in **Grafica → Avanzate → Avvisi**). Ogni chiave è un interruttore booleano indipendente; impostane una a `false` per silenziare quell’avviso senza disattivare gli altri.

### Avvisi di configurazione

Questi errori della configurazione stessa non passano mai sotto silenzio, e nessun interruttore li nasconde, tranne quello indicato nell’ultimo punto. Il motore non si blocca su nessuno di essi: sostituisce un valore, o tralascia l’impostazione, e lo segnala:

- **Formato di numerazione sconosciuto**: un `numberFormat` di un elenco numerato, un `page.pageNumbering.format` o il `counterFormat` di un tipo di risorsa che non corrisponde a nessuna delle [grafie dei formati di numerazione](/it/docs/configuration-page-layout#grafie-dei-formati-di-numerazione). Numera in decimale.
- **Elenco di font in una famiglia di caratteri**: un `fontFamily` (o qualunque `…FontFamily`) che contiene una pila di font CSS. Il testo viene composto nella prima famiglia della pila (vedi [Una sola famiglia per `fontFamily`](/it/docs/configuration-text#una-sola-famiglia-per-fontfamily)).
- **Colonna laterale senza spazio**: il `sideColumnPercent` di un’impaginazione `'oneAndHalf'` (quello del documento, o il `layout` proprio di uno stile di titolo) che lascerebbe una delle colonne sotto l’1% della larghezza del contenuto, o che non è un numero. Le colonne vengono tagliate al valore più vicino che entrambe possono accettare, e `used` lo indica (`sideColumnPercentClamped`; vedi l’[impaginazione `'oneAndHalf'`](/it/docs/configuration-page-layout#tipi-di-impaginazione)).
- **Numero di colonne fuori intervallo**: il `columnCount` di un’impaginazione `'multiple'` (quello del documento, o il `layout` proprio di uno stile di titolo) che non è un numero intero da 3 a 8. La pagina viene divisa nel numero valido più vicino (3 per un valore che non è un numero), e `used` lo indica (`columnCountClamped`; vedi l’[impaginazione `'multiple'`](/it/docs/configuration-page-layout#tipi-di-impaginazione)).
- **Griglia dei caratteri troppo grande**: un `cjk.grid` con più caratteri per riga o righe per pagina di quanti ne lascino entrare i margini. La griglia viene impostata con il massimo che ci sta, e `used` indica il numero (`cjkGridClamped`; vedi [Griglia dei caratteri](/it/docs/configuration-east-asian#griglia-di-caratteri)).
- **Impostazione dei titoli sconosciuta**: una chiave che `headings`, `headings.balancing`, un livello di titolo, uno stile di titolo o uno stile di paragrafo non hanno: un `letterSpacng` scritto male, un `tracking` preso da un altro strumento, un `level` in uno stile di titolo, un `fontStyle: 'italic'` in uno stile di paragrafo (che accetta `italic: true`). Un tabulatore viene controllato allo stesso modo (un `leaders` al posto di `leader`), e così un capolettera, `lineNumbers`, `canvasViewer`, `checks`, `codeStyle` e le impostazioni dei fumetti. Il motore la ignora (fino a postext 1.4 lo faceva senza dire nulla). `value` è la chiave, `used` è vuoto, e `suggestion` indica l’impostazione più vicina, quando ce n’è una che dista una o due lettere o che differisce solo per maiuscole e minuscole (`unknownConfigKey`).
- **Valore di impostazione sconosciuto**: un’impostazione che accetta una tra poche parole e ne contiene un’altra, come `direction: 'right'` (accetta `auto`, `ltr` o `rtl`). Il motore legge invece il valore predefinito, e `used` indica a che cosa corrisponde: per `direction`, la direzione della lingua del documento (`unknownConfigValue`). L’`align` di un tabulatore che non è nessuna delle sue quattro parole viene letto come `'start'`, e una `position` che non è né una lunghezza, né `'end'`, né una percentuale tralascia il tabulatore (`used` è `'none'`). Vengono controllate anche le parole delle impostazioni dei fumetti ([Fumetti › Avvisi dei fumetti](/it/docs/comics#avvisi-dei-fumetti)): `used` è il valore a cui l’impostazione si è risolta (il predefinito proprio di uno stile di nuvoletta, per uno stile incorporato), e `suggestion` indica la parola più vicina al valore, quando ce n’è una vicina. Il `level` e il `mode` della verifica del contrasto vengono controllati allo stesso modo: `used` è `'AA'` o `'auto'`. `canvasViewer.pageGap` e `canvasViewer.rowGap` si controllano allo stesso modo: `used` è l’intero da 0 a 200 con cui è stato letto il valore (da postext 1.43). Lo stesso vale per `print.standard`, `print.outputProfile` e `print.renderingIntent` (`used` è ciò che ha dato il predefinito) e per un `maxWords` o un `maxChars` di `checks.contentInConfig` che non sia un intero uguale o maggiore di 0.
- **Numeri di riga nel testo verticale**: `lineNumbers.enabled: true` in un documento composto in verticale (`layout.writingMode: 'vertical-rl'`). Le pagine verticali non hanno numeri di riga, e `used` è `false` (`lineNumbersUnsupported`; vedi [Numeri di riga](/it/docs/configuration-notes-references#numeri-di-riga)).
- **Scontorno nel testo verticale**: il `defaultPlacement.wrap` di un tipo di risorsa in un documento composto in verticale. Le pagine verticali non compongono testo accanto a una figura, e `used` è `none` (`wrapUnsupported`; vedi [Formato del documento › Testo intorno alle immagini](/it/docs/document-format-resources#testo-intorno-alle-immagini)). Un `wrap` che non indica nessun lato è un valore di impostazione sconosciuto.
- **Stile di riquadro basato su un altro**: uno stile di riquadro il cui `extends` non indica alcuno stile di `calloutStyles` (`calloutStyleExtendsUnknown`, con l’id più vicino in `suggestion`), o la cui catena di `extends` torna a esso (`calloutStyleExtendsCycle`, `value` il cerchio `a → b → a`). Lo stile resta da solo, con i valori predefiniti per ciò che lascia vuoto (vedi [Stili basati su un altro](/it/docs/configuration-callouts#stili-basati-su-un-altro)).
- **Modelli di pagina e stili delle etichette**: un problema in `pageTemplates` o `labelStyles`: un id o un nome ripetuto, `extends`, ancoraggi o cornici concatenate che girano in cerchio, uno stile, una cornice o un modello che non esiste, un minimo maggiore del suo massimo, uno stile di etichetta di un ancoraggio che `labelStyles` non ha (controllato quando si passano le risorse: `collectConfigWarnings(config, { resources })`). Il loro `path` è un puntatore JSON (`/pageTemplates/3/frames/2/style`); ogni tipo è descritto con causa e rimedio in [Avvisi dei modelli di pagina](/it/docs/configuration-composed-pages#avvisi-dei-modelli-di-pagina).
- **Contenuto nella grafica**: un elemento di testo grafico il cui testo, oltre ai segnaposto, è più lungo di un’etichetta breve, cioè il testo del libro tenuto nella configurazione. Un avviso per impostazione (uno stile di titolo, l’intestazione, la grafica delle parti), con il percorso di ogni testo (`contentInConfig`; vedi [Controllo del contenuto](#controllo-del-contenuto-configurazione)). A differenza degli altri, si può disattivare: `checks.contentInConfig.enabled: false`.

La Sandbox li elenca nel pannello **Verifiche** con il percorso dell’impostazione. Nel codice, `buildDocument` li mette sul documento come `configWarnings` (assente quando la configurazione è pulita), e `collectConfigWarnings(config)` li restituisce senza impaginare nulla:

```js
import { buildDocument, collectConfigWarnings } from 'postext';

// Plain JavaScript: in TypeScript, 'roman' does not type-check to begin with.
const config = { bodyText: { fontFamily: 'EB Garamond, serif' }, orderedLists: { numberFormat: 'roman' } };
const doc = buildDocument({ markdown }, config);
doc.configWarnings;
// [{ kind: 'fontFamilyStack', path: 'bodyText.fontFamily', value: 'EB Garamond, serif', used: 'EB Garamond' },
//  { kind: 'unknownNumberFormat', path: 'orderedLists.numberFormat', value: 'roman', used: 'arabic' }]
collectConfigWarnings(config); // the same list
```

Viene controllata anche ogni configurazione parziale annidata: stili di titolo, gli elenchi dentro le parti, `htmlViewer.overrides`, gli elementi grafici.

Anche `formatWarning` (vedi [Avvisi nel documento](/it/docs/configuration-programmatic-usage#avvisi-nel-documento)) li descrive, con il percorso dell’impostazione in testa (`bodyText.fontFamily: font stack "EB Garamond, serif" — set in "EB Garamond"`, `headingStyles[0].letterSpacng: unknown setting "letterSpacng" — ignored (did you mean "letterSpacing"?)`), così un’applicazione ospite può registrare in un solo ciclo tutte e tre le liste che una composizione restituisce.
