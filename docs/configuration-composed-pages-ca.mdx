# Configuració: pàgines compostes


## Plantilles de pàgina

Una pàgina composta és una pàgina que pren la forma d'una **plantilla de pàgina** de la configuració i el contingut del Markdown d'un bloc de pàgina, el bloc `::::page{template="…"}`, delimitat per quatre signes de dos punts. La plantilla dona nom a uns rectangles, anomenats **marcs**; el Markdown envia cada peça de contingut a un marc pel seu nom (la ranura). La geometria mai no apareix al Markdown, i el text del contingut mai no apareix a la plantilla. La propietat `pageTemplates` conté les plantilles del llibre:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

### Marcs

Un marc és un rectangle amb nom que rep contingut compost. El `name` és la ranura que indica el Markdown, i és únic dins la plantilla (un grup tampoc no pot portar el nom d'un marc, perquè els ancoratges fan referència a tots dos de la mateixa manera).

Un marc es col·loca segons la cel·la de `grid` quan la plantilla té retícula i, si no, segons el `placement`, que funciona com el d'un element de disseny: un ancoratge (`'container'` és l'àrea, `'page'`, `'bleed'`, o `'#name'` per a un altre marc o grup), una vora, un desplaçament i una mida. Un marc ancorat a un altre es mou amb ell. Sense cap dels dos, el marc comença a l'angle superior esquerre de l'àrea, amb tota l'amplada de l'àrea i tan alt com digui la regla d'alçada. Com s'aboca el contingut als marcs, com s'encadenen i com es retallen s'explica a [Pàgines compostes › Com es compon la pàgina](/ca/docs/composed-pages#com-es-compon-la-pàgina).

### Grups

Un grup és una pila (de dalt a baix) o una filera (del principi al final) de marcs que es reparteixen l'espai i es mouen junts. Dins d'un grup, s'ignora la posició pròpia dels marcs en la direcció del grup: el grup els col·loca en ordre, amb `gap` entre ells. Quan creix el text d'un marc, els marcs que van darrere es desplacen. Un grup és una caixa a la qual es poden ancorar marcs i decoració (`'#pagina'`).

### Com es reparteixen l'espai els grups

Un marc declara la seva mida: un `height` fix o `'auto'`, és a dir, l'alçada del que conté, mantinguda entre `minHeight` i `maxHeight`. En una plantilla treta d'una pàgina impresa, dona a cada caixa com a `minHeight` l'alçada que té a la pàgina: amb un text curt la caixa es queda com està dibuixada, i un text més llarg la fa més alta. La pàgina es maqueta dues vegades en la mateixa passada, una tal com la declara la plantilla i una altra tal com la demana el contingut, i les diferències entre totes dues formen el [registre de reajustament](/ca/docs/composed-pages#registre-de-reajustament).

**Pila.** Els marcs d'una pila van l'un sota l'altre, cadascun a la seva alçada, amb `gap` entre ells. Cada marc conserva la posició horitzontal i l'amplada; la posició vertical s'ignora.

- Un grup sense `placement` ni `grid` propis comença allà on es col·loca el primer marc (segons el `placement`, o la cel·la `grid` en una plantilla amb retícula) i baixa tant com ho necessitin els marcs, fins al peu de l'àrea de la plantilla. Quan un marc creix, els marcs que el segueixen baixen la mateixa distància.
- Un grup amb caixa pròpia col·loca els marcs dins d'aquesta caixa. Quan necessiten més espai del que hi ha, en cedeixen els marcs amb `shrink` més gran que 0, començant per la `priority` més baixa; els marcs d'una mateixa prioritat en cedeixen en proporció al seu `shrink`, i cap no baixa del seu `minHeight`. L'espai sobrant va als marcs amb `grow` més gran que 0, en proporció a aquest valor, fins al seu `maxHeight`; si no n'hi ha cap, `align` col·loca els marcs (`'end'` al peu, `'center'`, `'space-between'`). Un marc del grup sense col·locació pròpia pren la caixa del grup com a àrea.
- Quan ja no pot cedir res més, cedeixen primer els marcs més propers al peu del grup, cadascun fins al seu `minHeight`; un marc d'alçada fixa la conserva, de manera que un espai de resposta buit o el lloc d'una imatge sota una caixa que creix es queda a la pàgina i és el text de la caixa el que cedeix. Cap marc no passa del peu del grup: si el contingut d'un marc no hi cap, el marc recorre l'escala de reajustament (vegeu [Quan el contingut no hi cap](#quan-el-contingut-no-hi-cap)), i el que tot i així no hi cap es talla allà i Postext en dona un avís `frameOverflow`. Un marc retallat per sota del `minHeight` o de l'alçada fixa també dona avís, tingui contingut o no.
- Un marc amb `height: 'fill'` demana el `minHeight` i pren l'espai sobrant com si tingués `grow: 1`.

**Filera.** Els marcs d'una filera van l'un al costat de l'altre a les amplades declarades, i tots fan l'alçada de la filera: la de la caixa del grup o, si el grup no en té de pròpia, la més gran de les alçades que indiquen els marcs (una `height` fixa o, si no, el `minHeight`, perquè un marc `'auto'` no en declara cap altra) o, si no n'indiquen cap, la del contingut més alt (un marc d'alçada fixa conserva la seva). Quan el text d'un marc passa de l'alçada de la filera, el marc s'eixampla: primer amb l'amplada sobrant de la filera, després amb la dels altres marcs que tenen `shrink` més gran que 0, començant per la `priority` més baixa, sense deixar-ne cap més estret que l'amplada en què encara hi cap el text. L'amplada que pren és el mínim de mil·límetres sencers amb què el text hi cap; si ni tot l'espai disponible no n'hi ha prou, el marc no en pren gens, i una filera sense caixa pròpia es fa més alta. Així, unes targetes amb `height: 'auto'` i un `minHeight` es reparteixen l'amplada a aquesta alçada, i la filera només creix quan cap no té amplada per donar. L'amplada sobrant va als marcs amb `grow` més gran que 0 i, després, a `align`. Les fileres van d'esquerra a dreta.

**Marcs fixats.** Un marc amb `pin: true` conserva la caixa que li dona la plantilla, encara que el marc al qual està ancorat creixi o es mogui: una caixa dibuixada perquè coincideixi amb la il·lustració s'hi queda a sobre. Dins d'un grup, un marc fixat no es mou i els altres marcs el salten, amb el `gap` a banda i banda; un marc fixat de fora del grup fa el mateix amb els marcs del grup que trepitjaria.

**Decoració.** Un element de decoració ancorat a un marc (`anchor: { to: '#dinero' }`) es mou amb el marc quan aquest creix o es desplaça. Un element amb `pin: true` es queda on la plantilla dibuixa aquell marc.

```ts
  { name: 'ahorro', style: 'caja-amarilla', width: { value: 186, unit: 'mm' }, minHeight: { value: 30, unit: 'mm' } },
],
groups: [{ name: 'cajas', kind: 'stack', frames: ['dinero', 'gasto', 'ahorro'], gap: { value: 12, unit: 'mm' } }],
```

El resultat només depèn del contingut de la pàgina, de la plantilla i de la tipografia: la mateixa entrada dona la mateixa pàgina, mesurada en el mateix ordre i amb els mateixos passos. La negociació mai no llegeix cap altra pàgina, de manera que un canvi en una pàgina composta deixa totes les altres com estaven, sempre que el contingut no surti de la pàgina.

**Mantenir marcs al peu d'una targeta (des de postext 1.42).** Un marc ancorat sota el text que té a sobre segueix aquest text: en una edició on el text és una línia més curt o més llarg, els marcs de sota pugen o baixen, mentre que el que dibuixa la plantilla (una targeta, una franja, el peu) es queda on és. Perquè els marcs es mantinguin al peu d'una targeta, on la plantilla els posa, reuneix els marcs de la targeta en una pila amb una caixa de l'alçada de la targeta. Els marcs que van damunt dels retinguts prenen l'espai sobrant (`grow: 1`) i el retornen (`shrink: 1`); els retinguts escriuen un `minHeight`. Un text més curt deixa els marcs retinguts on eren. Si és més llarg, s'estreny per damunt d'ells: els retinguts conserven el `minHeight`, el text de dalt es redueix i, si tot i així no hi cap, la maquetació avisa amb `frameOverflow` i el registre de reajustament anota `textScaled` i `overflow` per al marc de dalt. Un marc ancorat al peu del contenidor (`bottom-left`) també conserva el lloc, però res no l'uneix als marcs de damunt: un text més llarg hi passa per sobre, res no s'estreny per ell i la superposició no s'avisa.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

El marc que creix fa tant com l'espai lliure, contingui el que contingui, així que un estil amb fons visible el pintaria sencer: pinta la targeta a la decoració de la plantilla i deixa el marc de text sense estil.

### Graelles que repeteixen un joc de marcs

Una pàgina de fitxes amb fotos, una pàgina de fitxes d'activitats o una pàgina de retrats amb un nom sota cadascun és la mateixa targeta dibuixada moltes vegades. Un grup de tipus graella amb `repeat` la dibuixa una sola vegada a la plantilla: els marcs d'una targeta, el que s'anomena joc de marcs, que la graella col·loca una vegada per cada element que li dona el Markdown de la pàgina. Així, quantes targetes té una pàgina ho decideix el Markdown, i una traducció que afegeix una targeta no necessita cap plantilla nova. Des de postext 1.48.

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **El joc.** El primer marc de `repeat.frames` és el marc **principal** de la cel·la: pren l'amplada de la cel·la i conserva la seva regla d'alçada (`'auto'` és l'alçada del contingut, entre `minHeight` i `maxHeight`). Els altres marcs del joc es col·loquen com els dibuixa la plantilla, ancorats al marc principal o entre si: aquí la píndola del peu penja del peu de la foto. Un marc del joc ancorat a un marc de fora del joc es queda on el posa aquest ancoratge.
- **Elements.** Cada tros `:::frame{slot="foto"}` de la pàgina és un element: els trossos d'una ranura repetida no s'ajunten. Dins del tros, un bloc que indica un membre del joc (`:::frame{slot="pie"}`, `::resource{… slot="pie"}`) va a aquell membre de la mateixa targeta; la resta va al marc principal. Vegeu [Pàgines compostes › Ranures repetides](/ca/docs/composed-pages#ranures-repetides).
- **Instàncies.** Els marcs de cada targeta es diuen `<frame>[n]`, comptant a partir d'1: `foto[2]` i `pie[2]` són la segona targeta. Els avisos, el registre de reajustament, el mapa d'origen i el Sandbox fan servir aquests noms, els ids dels marcs són `cp<n>:foto[2]`, i un element de decoració o un connector es poden ancorar a `'#foto[2]'`. El `to: '#foto[*]'` d'un connector arriba a totes les targetes de la pàgina. Un element ancorat a `'#foto'` llegeix la caixa de la graella.
- **Cel·les.** Les cel·les omplen les fileres des del costat d'inici, de manera que en una pàgina de dreta a esquerra la primera targeta queda a la dreta. Una filera fa l'alçada de la seva cel·la més alta, comptant el que penja per sobre del marc principal (una pestanya) i per sota (una píndola); `rowAlign` col·loca les més baixes. La caixa de la graella és el seu `placement` o la seva cel·la de `grid`; si no en té, comença on la plantilla dibuixa el marc principal i arriba fins a la vora dreta i el peu de l'àrea.
- **Quan les targetes no hi caben.** Una filera que passa del peu de la graella es talla allà, cada targeta recorre l'escala de reajustament pel seu compte, i l'última targeta tallada dona `frameOverflow`. Amb `overflow.continueIn` al marc principal (`'next-page'`, `'template:<id>'`), la graella continua **per fileres senceres**: la primera filera que no hi cap, i totes les que la segueixen, es col·loquen a la pàgina afegida, a la graella d'una plantilla que repeteix el mateix joc de marcs. Una cel·la més alta que tota la graella dona un avís en lloc de continuar indefinidament.
- **`max`.** Els elements que passen de `repeat.max` van al marc de flux, o després de la pàgina si la plantilla no en té, i cadascun genera `repeatOverflow`.

Una graella sense `repeat` col·loca els marcs que llista, un per cel·la, en l'ordre en què estan escrits. Un marc d'un joc repetit que apareix a la llista d'un altre grup se salta en aquell grup (`groupFrameTwice`), i un nom que la plantilla no té és `groupFrameUnknown`. `grow` i `shrink` no s'apliquen a les fileres d'una graella, ni `redistribute` a les seves targetes.

### Mòduls

Una pàgina d'un llibre de text sovint apila blocs que tornen a sortir al llarg del llibre en un altre ordre: una caixa amb una foto al costat, un arbre de tres idees, una graella de quatre fotos sota un encapçalament. Dibuixar una plantilla per a cada ordre multiplica les plantilles. Un **mòdul** és un d'aquests blocs dibuixat una sola vegada: una plantilla amb `role: 'module'`, amb marcs, grups i decoració (connectors inclosos), i sense pàgina pròpia. Una plantilla de pàgina pren mòduls en un grup amb `modules: true`; el Markdown de la pàgina diu quins mòduls conté i en quin ordre (vegeu [Pàgines compostes › Mòduls en una pàgina](/ca/docs/composed-pages#mòduls-en-una-pàgina)). Des de postext 1.48.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **Què té un mòdul.** Marcs, grups (també una graella que es repeteix), decoració i connectors. No té `area`, `header`, `footer`, `variants`, `spread`, `gutter` ni `overflowTemplate`: cadascun d'aquests camps es dona com a `unknownConfigValue` i s'ignora. `extends` funciona entre mòduls (una plantilla que estén un mòdul és un mòdul).
- **La seva caixa.** Un mòdul fa l'amplada del seu grup i l'alçada fins on arriben els seus marcs; el grup apila els mòduls des de dalt, amb `gap` entremig. Dins d'un mòdul, `'container'` és la caixa del mòdul, per als seus marcs (també `'fill'` i els percentatges) i per a la seva decoració: un fons amb la mida `{ to: 'container', edge: 'bottom' }` cobreix el mòdul sigui quina sigui l'alçada que li donin les paraules.
- **Noms.** Els marcs, els grups i els elements d'un mòdul porten com a prefix el nom de la instància del mòdul: `<name>.<frame>`, amb el nom que dona el Markdown (`name="ramas"`) o, si no, `<template>[n]`, el número d'ordre del mòdul entre els mòduls d'aquella plantilla a la pàgina (`arbol[2].raiz`). Els ancoratges, `next`, `continueIn: '#x'` i els connectors de dins d'un mòdul es reescriuen cap als seus propis marcs, de manera que dos arbres en una pàgina no s'uneixen mai entre si. L'id d'un marc és `cp0:arbol[2].raiz`.
- **Quan els mòduls no hi caben.** Un mòdul que passa del peu del grup es talla allà i els seus marcs recorren l'escala de reajustament; `frameOverflow` es dona una sola vegada per al grup. Amb `overflow.continueIn` al grup de mòduls (`'next-page'` o `'template:<id>'`), el primer mòdul que no hi cap i tots els que el segueixen continuen **sencers** a la pàgina afegida, amb els mateixos noms, al capdamunt del grup de mòduls d'aquella pàgina. En una filera o una graella de mòduls, la filera continua sencera: els seus mòduls no es reparteixen mai entre dues pàgines.
- **L'un al costat de l'altre.** Un grup de mòduls amb `kind: 'row'` col·loca els seus mòduls de l'inici al final, cadascun amb el `width` de la seva plantilla (una longitud, `{ percent: 48 }` o `'fill'`, una part igual del que queda), i la filera tan alta com el seu mòdul més alt; `kind: 'grid'` els col·loca en `columns` columnes iguals, filera rere filera. `rowAlign` situa un mòdul més baix que la seva filera. Les fileres comencen pel costat d'inici de la línia, de manera que una pàgina de dreta a esquerra posa el primer mòdul a la dreta. Des de postext 1.50.
- **Grups dins de la pila.** Un grup de mòduls amb `within: '<pila>'` queda dins de la pila de mòduls de la pàgina, i `templates` diu quins mòduls rep: cada tanda seguida d'aquests mòduls al Markdown forma una filera o una graella de la pila, on va el seu primer mòdul. Amb els grups de sota, dos blocs `aviso` seguits de quatre blocs `tarjeta` formen una filera de dos requadres sobre una graella de 2 × 2 targetes, i el Markdown només porta blocs `:::module`.
- **Grups dins de grups.** Des de postext 1.51 `within` pot anomenar qualsevol grup de mòduls, també una fila o una graella, a qualsevol profunditat. Amb `banda` una fila dins de `cuerpo` i `columna` una pila dins de `banda`, un requadre seguit de dues targetes es col·loca al costat d'una columna amb les dues targetes. Un marc de la pàgina ancorat a `#banda` es col·loca després dels mòduls.
- **Repartir una fila.** Des de postext 1.51 l'espai que deixa una fila de mòduls es reparteix segons el `grow` de cada mòdul, i una fila més ampla que el seu grup cedeix amplada segons `shrink`.
- **Encara no.** Un mòdul dins d'un altre mòdul (`moduleNested`) i cel·les `grid` de plantilla dins d'un mòdul.

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### Quan el contingut no hi cap

Quan el contingut d'un marc és més alt que l'espai que li dona el grup, la maquetació prova per ordre els passos de l'[escala de reajustament](/ca/docs/composed-pages#quan-tot-i-així-no-hi-cap) i s'atura al primer que el fa cabre: l'espai lliure fins a `maxHeight`, el grup que empeny i cedeix, imatges més petites, els altres marcs del grup fins al seu mínim, text més petit i continuació en una altra pàgina. Aquests paràmetres del marc determinen fins on pot arribar cada pas:

- `maxHeight` en un marc amb un `height` fix: el marc pot créixer fins aquí abans que es redueixi res.
- `minHeight` en els altres marcs del grup: fins on tornen espai; un marc no baixa mai del que necessita el seu contingut.
- `fit.scaleImages` i `fit.imageMinScale`: si les imatges del marc i del seu grup es poden compondre més petites, i fins a quina escala (80 % per defecte).
- `fit.shrinkText` i `fit.minScale`: si el text del marc es pot compondre més petit, i fins a quina escala (90 % per defecte). L'escala és la mateixa per a la mida de la lletra, l'interlineat i els espais; el marc conserva la seva mida.
- `overflow.continueIn`: on continua el contingut quan res d'això no n'hi ha prou: en un altre marc o en una altra pàgina (`'next-page'`, `'template:<id>'`, `'page:<id>'`), on el text continua a mida completa després de l'`overflow.mark` del tros. Un marc que pot continuar en una altra pàgina ho fa abans que les imatges i el text es componguin més petits, tret que tingui `fit.preferContinue` a `false`.

Les escales van en passos del 2,5 % i la maquetació pren la més gran amb què el contingut hi cap, de manera que un text que fa una línia de més es compon al 97,5 %, no al mínim. Una caixa que ha de conservar la mida de la lletra porta `fit: { shrinkText: false }`; en una pàgina amb imatges que han de conservar la mida, els marcs del grup porten `fit: { scaleImages: false }`:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

Si tot i així no hi cap, Postext en dona un avís `frameOverflow`, amb els passos provats i propostes amb el valor que caldria: vegeu [L'avís i les seves propostes](/ca/docs/composed-pages#lavís-i-les-seves-propostes).

### Herència i variants

Una plantilla amb `extends` parteix de la plantilla que indica (que al seu torn en pot estendre una altra) i canvia només el que escriu:

- Un camp com `area`, `header` o `overflowTemplate` substitueix el del pare. `grid` es combina clau a clau. `spread`, `gutter` i `role` també s'hereten; `id`, `name` i `extends` són propis de la plantilla.
- `frames` i `groups` es combinen **per nom**: una entrada amb el nom d'una d'heretada canvia els camps que escriu i conserva la resta (`fit`, `overflow` i `padding` es combinen clau a clau; `placement` se substitueix sencer); `remove: true` la treu; un nom nou s'afegeix darrere dels heretats.
- Els elements de decoració es combinen per `id` de la mateixa manera; un element amb un id nou, o sense id, s'afegeix. Des de postext 1.42, `{ id: 'capcalera-parell', remove: true }` a `decoration.elements` d'una plantilla filla o d'una variant treu l'element heretat amb aquest `id`, com fa `remove: true` amb un marc; un `id` que la plantilla no hereta no canvia res. Un element nou amb el mateix `id` pot seguir l'eliminació a la mateixa llista.

`variants.recto` i `variants.verso` s'escriuen com una plantilla i es combinen igual, en una pàgina senar o en una de parella. S'apliquen després de tota la cadena d'`extends`, primer la variant de l'arrel. Una doble pàgina té els dos costats, de manera que no se li aplica cap variant.

Un element de `variants.recto` amb `parity: 'even'`, o de `variants.verso` amb `'odd'`, no es dibuixa mai: `unknownConfigValue`.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Quan el Sandbox desa una plantilla, mai no descarta un valor igual al valor per defecte: en una plantilla que n'estén una altra, o en una variant, aquest valor substitueix el del pare.

Des del codi, `resolvePageTemplate(config, id, { parity })` retorna una plantilla amb tota la cadena d'herència combinada, la variant del costat aplicada, tots els valors per defecte omplerts i cada referència resolta com descriuen els avisos de més avall; `validatePageTemplates(config)` retorna els avisos.

### Es dibuixa si la pàgina ho diu

Un element de la decoració, i un del `header` o el `footer` de la plantilla, pot portar `when` o `unless`, cadascun amb el nom d'un atribut del bloc de pàgina. `when: 'folio'` dibuixa l'element només a les pàgines el bloc de les quals fixa `folio`; `unless: 'frontmatter'` el treu de les pàgines el bloc de les quals fixa `frontmatter`. Un bloc fixa un atribut quan l'escriu sol (`::::page{template="pagina" frontmatter}`) o amb qualsevol valor llevat de `false`. Així una sola plantilla serveix per als preliminars, que no porten foli ni banda, i per a les pàgines del cos, que porten totes dues coses: el Markdown diu què és la pàgina i la plantilla guarda el dibuix. Des de postext 1.50.

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- Un element ancorat a un altre que queda fora, o amb la mida mesurada fins a ell, també queda fora.
- Amb les dues claus, l'element es dibuixa on el bloc fixa l'atribut de `when` i no el d'`unless`.
- Els encapçalaments del document i els d'una secció també les llegeixen. Una pàgina que no és composta no té bloc de pàgina i no fixa res. Els dissenys de títol, de part i de caixa no les tenen en compte.
- Un valor que no és un text no buit, o un d'escrit en un disseny de títol, de part o de caixa, s'avisa com a `unknownConfigValue` i l'element es dibuixa com si no en tingués. `postext check` afegeix una nota, `conditionNeverMet`, per cada `when` o `unless` amb un atribut que cap pàgina del llibre no fixa: aquell element no es dibuixa mai, o sempre. També un `{attr.x}` que res defineix: queda buit.
- Amb el llibre maquetat, una pàgina que no dibuixa res d'un foli o un titolet (un text de `header` o `footer`, un text de la decoració que llegeix `{pageNumber}`, un nom corregut o `{attr.x}`) que sí que dibuixen la majoria de les pàgines de la seva plantilla i del seu costat s'avisa com a `folioMissing`, amb la pàgina, la plantilla i l'element. No compta una pàgina el bloc de la qual apaga l'element, ni una la plantilla de la qual no el té. Des de postext 1.53.
- Al Sandbox, cada targeta d'element d'un encapçalament i de la decoració d'una plantilla té els camps **Es dibuixa si la pàgina ho diu** i **No es dibuixa si la pàgina ho diu**, que ofereixen els atributs que fan servir les pàgines del llibre.

### El que aplica la maquetació

La maquetació aplica la col·locació i les mides de cada marc (retícula, ancoratges, `min`/`max`, `verticalAlign`), el seu estil i el seu `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (i el seu `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) amb `overflow.mark` i `overflow.fromMark`, i el seu `fit` (la reducció del text i de les imatges de l'escala de reajustament, vegeu [Quan el contingut no hi cap](#quan-el-contingut-no-hi-cap)); el repartiment de l'espai d'un grup (`grow`, `shrink`, `priority`, `pin`, i el `gap` i l'`align` del grup, vegeu [Com es reparteixen l'espai els grups](#com-es-reparteixen-lespai-els-grups)); i l'`area`, la `grid`, la `decoration`, el `header`, el `footer`, les `variants`, `spread` i l'`overflowTemplate` de la plantilla. Des de postext 1.42 aplica també la `palette` de la plantilla, el `look` d'un marc i l'amplada `'auto'` (la de la línia més llarga del marc). El `writingMode` i la `direction` d'un marc s'apliquen des de postext 1.39. Des de postext 1.48 aplica les graelles i el seu `repeat`, els grups de mòduls i les plantilles de mòdul, els connectors i els elements de traçat de la decoració, i l'`overlap` d'un marc. Es llegeix i es comprova, però encara no s'aplica: el `bodyStyle` de la plantilla.

### Dobles pàgines

En una plantilla de doble pàgina, totes les coordenades es refereixen al full de les dues pàgines, amb el llom al centre: `area`, `grid`, els ancoratges a `container`, `page` i `bleed` i les mides `fill` llegeixen l'amplada doble. `bleed` arriba a la capçalera, al peu i a les dues vores exteriors, mai al llom. La línia del temps a doble pàgina d'un llibre de text és una sola plantilla:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … d'era-2 a era-6, una columna de la graella cadascuna, i les notes sota la tira
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Un espai entre columnes més ample que el `gutter` manté les fitxes d'una graella simètrica lluny del llom, així que cap no es mou. La segona banda i la tira de dibuixos porten `crossGutter` per travessar-lo: cadascuna es llegeix a la pàgina on té el centre i es pinta a totes dues. Totes les paraules de la pàgina, també els noms de les edats de les pestanyes, es queden al Markdown.

En un llibre vertical (`vertical-rl`), la doble pàgina es compon en el sistema de coordenades del flux de les pàgines, com les pàgines compostes soles: el capdamunt de la pàgina és la vora dreta de la doble pàgina i les línies baixen, de manera que la `x` de la plantilla baixa per la doble pàgina i la `y` va de la vora dreta a l'esquerra. La doble pàgina és la pàgina dreta seguida de l'esquerra al llarg de `y`, el llom és una línia que travessa la plantilla, i `gutter`, `crossGutter` i el tall entre les pàgines llegeixen aquest eix; la decoració es continua component sobre la doble pàgina física i es talla al llom. Una línia del temps horitzontal dibuixada per a un llibre horitzontal surt girada en un de vertical: escriu la plantilla d'un llibre vertical en el sistema de coordenades del seu flux. Des de postext 1.38. Una fitxa que s'hagi de llegir al llarg de la doble pàgina porta `writingMode: 'horizontal-tb'`: es compon en horitzontal i queda dreta a la pàgina vertical (des de postext 1.39).

### Connectors

Un connector és una línia de la decoració que uneix marcs: les branques d'un diagrama en arbre, un organigrama, les línies que baixen d'una línia del temps, les fletxes d'un diagrama de flux, el punter d'una nota cap a un lloc d'un mapa. Es col·loca quan els marcs ja tenen la caixa definitiva, de manera que segueix un text que creix, una edició amb paraules més llargues o un grup que mou els seus marcs, i es dibuixa com a línia vectorial a totes les sortides, així que la plantilla no necessita cap imatge de les línies. Els connectors són elements de la `decoration` d'una plantilla de pàgina o d'un mòdul; les capçaleres i els dissenys d'encapçalament no tenen marcs per unir, i un connector en aquests llocs es dona com a avís (`unknownConfigValue`) i no es dibuixa. Des de postext 1.48.

```ts
decoration: {
  elements: [
    { kind: 'connector', id: 'ramas', routing: 'tree', radius: { value: 2, unit: 'mm' },
      width: { value: 1.25, unit: 'pt' }, from: { to: '#raiz' }, to: [{ to: '#a' }, { to: '#b' }], endCap: 'arrow' },
```

**Extrems que no hi són.** Un extrem en un marc que la pàgina no mostra (plegat, opcional i buit, una targeta més enllà dels elements de la pàgina, un punt de la imatge que el seu marc retalla) es deixa fora: un arbre conserva els altres fills, i el registre de reajustament de la pàgina ho anota (`connectorDropped`). Si no queda cap `from` o cap `to`, no es dibuixa res.

**Pintura.** Els connectors es pinten com a traçats vectorials: al canvas, al PDF, al visor HTML i a l'EPUB de maquetació fixa, i com a artefacte de maquetació en un PDF etiquetat; l'EPUB de maquetació fluida els deixa fora amb la resta de la decoració. Un connector amb un extrem `anchor` es pinta sobre tots els marcs de la pàgina, de manera que una línia que entra dins d'una imatge es veu sobre el marc de la imatge sense posar-hi `layer`; els altres connectors queden amb la decoració, sota els marcs. `over: true` puja una línia entre marcs, `over: false` manté sota els marcs una línia que assenyala. En una doble pàgina, un connector entre marcs de les dues pàgines travessa el llom i s'hi talla com la resta de la decoració; en una pàgina de dreta a esquerra, `start` i `end` segueixen el flux en mirall.

```ts
frames: [
  { name: 'mapa', width: { value: 118, unit: 'mm' } },
  { name: 'nota', style: 'nota', width: { value: 44, unit: 'mm' } },
],
decoration: { elements: [
  { kind: 'connector', id: 'a-lago', from: { to: '#nota', side: 'end' },
    to: { to: '#mapa', anchor: 'lago', gap: { value: 1.2, unit: 'mm' } }, endCap: 'dot' },
] },
```

**Revisions.** Un extrem amb un `to` que no indica res és `frameAnchorUnknown` (a `…/from/to` o `…/to/<k>/to`) i es deixa fora; `[*]` només és vàlid a `to` i en un marc repetit. Un `anchor` que cap imatge del marc no té és `labelAnchorUnknown`, amb l'id del connector. Una paraula fora de les opcions de `routing`, `startCap`, `endCap` o `side`, i un `at` fora de l'interval de 0 a 1, són `unknownConfigValue`. Un `opacity` que no és un nombre de 0 a 1 també és `unknownConfigValue` (un nombre fora de l'interval s'hi ajusta).

## Aspectes de marc

Una graella de targetes amb foto les píndoles de les quals només canvien de color, o una pàgina de requadres en una dotzena de tons, conserva un sol estil de requadre i una sola plantilla: els colors van a `frameLooks`, una llista d'aspectes amb nom, i el Markdown n'indica un a cada tros que el porta. frameLooks: [
```ts
  { id: 'rojo', name: 'Red pill', background: { hex: '#e63946', model: 'hex' }, body: { color: { hex: '#ffffff', model: 'hex' } } },
  { id: 'verde', background: { hex: '#6a994e', model: 'hex' } },
  { id: 'marino', border: { color: { hex: '#264653', model: 'hex' } } },
]
```

## Estils de rètol

Un rètol sense estil, o amb un estil que no fixa la lletra, pren la família, la mida, el gruix i el color del text de cos. Un rètol reduït per cabre conserva l'halo en proporció.

`start` i `end` segueixen la direcció del rètol: en un rètol àrab, `start` és la vora dreta. Una àncora que comparteixen les edicions d'esquerra a dreta i de dreta a esquerra d'un mateix mapa funciona millor amb el rètol centrat a sobre o a sota del punt. Un rètol amb `width` es talla entre paraules; una paraula més ampla que la mesura redueix tot el rètol, fins al `minScale` de l'estil. Com es dibuixen els rètols s'explica a [Pàgines compostes](/ca/docs/composed-pages).

Una línia de referència surt pel costat de la caixa del rètol (la placa o, si no en té, les línies) que mira cap al punt a través de l'espai més ample, des del centre d'aquest costat, de manera que la línia no travessa mai les paraules del rètol, tampoc si el rètol està girat. Un punt que queda sota la caixa del rètol, o una línia més curta que la seva marca final, no dibuixa res. Les línies de referència es pinten sota els rètols, amb la imatge, a totes les sortides que dibuixen rètols, i segueixen la imatge quan es retalla, s'escala, es reflecteix o es compon a través d'una doble pàgina.

```ts
anchors: [
  { id: 'peaks', x: 0.42, y: 0.8, labelAt: { x: 0.62, y: 0.6 }, style: 'name', leader: true },
  { id: 'lake', x: 0.531, y: 0.865, labelAt: { x: 0.76, y: 0.93 }, style: 'name', leader: { routing: 'elbow' } },
],
```

## Avisos de les plantilles de pàgina

A la resta de la configuració, el motor ignora una clau que no coneix. Les plantilles de pàgina i els estils de rètol, en canvi, es comproven, i cada problema és un avís de configuració a `postext check` i al tauler Revisió del Sandbox. El camp `path` d'aquests avisos és un punter JSON al camp que falla: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Quan el camp és heretat, el punter indica la plantilla que el va escriure. Un avís sobre un id o un nom que no existeix proposa a més el nom existent que s'hi assembla més.

Una clau mal escrita d'una plantilla, un marc, un grup, una retícula, `fit`, `overflow`, una variant o un estil de rètol és un `unknownConfigKey`; una paraula fora de les opcions d'un paràmetre (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`, `overlap`, `rowAlign`, el `routing`, les marques d'extrem i el `side` d'un connector, i les marques d'extrem i el `routing` d'una línia de referència) és un `unknownConfigValue`, i el paràmetre conserva el valor per defecte. Una plantilla sense `id`, o un marc o un grup sense `name`, s'ignora amb un `unknownConfigValue` en aquest camp. Els aspectes de marc (`frameLooks`) es revisen igual: un aspecte sense `id` s'ignora, i una clau que el `look` d'un marc no té és un `unknownConfigKey`.
