# Configuração: páginas compostas


## Modelos de página

Uma página composta é uma página que tira a forma de um **modelo de página** da configuração e o conteúdo do Markdown de um contêiner `::::page{template="…"}`, aberto com quatro sinais de dois-pontos. O modelo dá nome a retângulos, chamados **blocos**; o Markdown manda cada parte do conteúdo para um bloco pelo nome (o slot, isto é, o nome do bloco de destino). A geometria nunca aparece no Markdown, e o texto do conteúdo nunca aparece no modelo. A propriedade `pageTemplates` guarda os modelos do livro:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

### Blocos

Um bloco é um retângulo com nome que recebe conteúdo diagramado. O `name` dele é o slot que o Markdown pede e é único no modelo (um grupo também não pode ter o nome de um bloco, já que as âncoras nomeiam os dois do mesmo jeito).

Um bloco é posicionado pela célula de `grid` quando o modelo tem grade e, senão, pelo `placement`, que funciona como o de um elemento de design: uma âncora (`'container'` é a área, `'page'`, `'bleed'`, ou `'#name'` para outro bloco ou grupo), uma borda, um deslocamento e um tamanho. Um bloco ancorado a outro se move com ele. Sem nenhum dos dois, o bloco começa no canto superior esquerdo da área, com a largura da área inteira e a altura que a regra de altura dele indicar. Como o conteúdo é distribuído pelos blocos, encadeado e cortado está descrito em [Páginas compostas › Como a página é diagramada](/pt/docs/composed-pages#como-a-página-é-diagramada).

### Grupos

Um grupo é uma pilha (de cima para baixo) ou uma fileira (do início ao fim) de blocos que dividem o espaço e se movem juntos. Dentro de um grupo, a posição própria dos blocos na direção do grupo é ignorada: o grupo os arranja em ordem, com `gap` entre eles. Quando o texto de um bloco cresce, os blocos que vêm depois se deslocam. Um grupo é uma caixa à qual blocos e decoração podem se ancorar (`'#pagina'`).

### Como os grupos dividem o espaço

Um bloco declara o próprio tamanho: um `height` fixo, ou `'auto'`, a altura do que ele contém, mantida entre `minHeight` e `maxHeight`. Num modelo tirado de uma página impressa, dê a cada caixa como `minHeight` a altura que ela tem na página: com um texto curto a caixa fica como está desenhada, e um texto mais longo a deixa mais alta. A página é diagramada duas vezes na mesma passada, uma como o modelo a declara e outra como o conteúdo precisa, e as diferenças entre as duas formam o [registro de reajustes](/pt/docs/composed-pages#registro-de-reajustes).

**Pilha.** Os blocos de uma pilha ficam um embaixo do outro, cada um na própria altura, com `gap` entre eles. Cada um mantém a posição horizontal e a largura; a posição vertical própria é ignorada.

- Um grupo sem `placement` nem `grid` próprios começa onde o primeiro bloco dele é posicionado (pelo `placement` ou, num modelo com grade, pela célula `grid`) e desce o quanto os blocos precisarem, até o pé da área do modelo. Quando um bloco cresce, os blocos que vêm depois dele descem o mesmo tanto.
- Um grupo com caixa própria arranja os blocos dentro dela. Quando eles precisam de mais do que ela comporta, os blocos com `shrink` acima de 0 devolvem espaço, primeiro os de `priority` mais baixa; blocos da mesma prioridade cedem na proporção do `shrink` de cada um, e nenhum fica abaixo do próprio `minHeight`. O espaço que sobra vai para os blocos com `grow` acima de 0, na proporção desse valor, até o `maxHeight` de cada um; se não houver nenhum, `align` posiciona os blocos (`'end'` no pé, `'center'`, `'space-between'`). Um bloco do grupo sem posicionamento próprio usa a caixa do grupo como área.
- Quando nada mais pode ceder, cedem primeiro os blocos mais próximos do pé do grupo, cada um até o próprio `minHeight`; um bloco de altura fixa a mantém, de modo que um espaço de resposta vazio ou o lugar de uma imagem sob uma caixa que cresce fica na página, e é o texto da caixa que cede. Nenhum bloco passa do pé do grupo: o bloco cujo conteúdo não cabe percorre a escada de ajuste (veja [Quando o conteúdo não cabe](#quando-o-conteúdo-não-cabe)), e o que ainda assim não cabe é cortado ali e aparece como `frameOverflow`. Um bloco cortado abaixo do `minHeight` ou da altura fixa dele também aparece no aviso, tenha conteúdo ou não.
- Um bloco com `height: 'fill'` pede o `minHeight` e fica com o espaço que sobra como se tivesse `grow: 1`.

**Fileira.** Os blocos de uma fileira ficam lado a lado nas larguras declaradas, todos com a altura da fileira: a da caixa do grupo ou, se o grupo não tiver caixa própria, a maior altura que os blocos dele definem: uma `height` fixa, senão um `minHeight` (um bloco `'auto'` não declara mais nada), ou, se não definirem nenhuma, a do conteúdo mais alto (um bloco de altura fixa mantém a própria). Quando o texto de um bloco passa da altura da fileira, o bloco ganha largura: primeiro a que sobra na fileira, depois a dos outros blocos com `shrink` acima de 0, primeiro os de `priority` mais baixa, sem que nenhum fique mais estreito que a largura em que o próprio texto ainda cabe. A largura tomada é o menor número de milímetros inteiros com que o texto cabe; se nem todo o espaço disponível bastar, o bloco não toma nada, e uma fileira sem caixa própria fica mais alta. Assim, cartões com `height: 'auto'` e um `minHeight` dividem a largura nessa altura, e a fileira só cresce quando nenhum tem largura para ceder. A largura que sobra vai para os blocos com `grow` acima de 0 e depois para `align`. As fileiras vão da esquerda para a direita.

**Blocos fixos.** Um bloco com `pin: true` mantém a caixa que o modelo declara para ele, mesmo quando o bloco ao qual está ancorado cresce ou se move: uma caixa desenhada para coincidir com a ilustração continua sobre ela. Num grupo, um bloco fixo não sai do lugar e os outros blocos passam por ele, com o `gap` mantido dos dois lados; um bloco fixo fora do grupo faz o mesmo com os blocos do grupo que ele encobriria.

**Decoração.** Um elemento de decoração ancorado a um bloco (`anchor: { to: '#dinero' }`) acompanha o bloco quando ele cresce ou se move. Um elemento com `pin: true` fica onde o modelo desenha aquele bloco.

O resultado depende só do conteúdo da página, do modelo e da tipografia: a mesma entrada dá a mesma página, medida na mesma ordem e com os mesmos passos. A negociação nunca lê outra página; por isso, uma mudança numa página composta deixa todas as outras como estavam, desde que o conteúdo continue na mesma página.

**Manter blocos no pé de um cartão (desde o postext 1.42).** Um bloco ancorado abaixo do texto que tem acima segue esse texto: numa edição em que o texto tem uma linha a menos ou a mais, os blocos de baixo sobem ou descem, enquanto o que o modelo desenha (um cartão, uma faixa, o pé) fica onde está. Para que os blocos fiquem no pé de um cartão, onde o modelo os põe, reúna os blocos do cartão numa pilha com uma caixa da altura do cartão. Os blocos acima dos retidos tomam o espaço que sobra (`grow: 1`) e o devolvem (`shrink: 1`); os retidos escrevem um `minHeight`. Um texto mais curto deixa os blocos retidos onde estavam. Um mais longo é apertado acima deles: eles mantêm o `minHeight`, o texto de cima é reduzido e, se ainda assim não couber, a diagramação avisa com `frameOverflow` e o registro de reajustes anota `textScaled` e `overflow` para o bloco de cima. Um bloco ancorado no pé do contêiner (`bottom-left`) também mantém o lugar, mas nada o liga aos blocos de cima: um texto mais longo passa por cima dele, nada é apertado por causa dele e a sobreposição não é avisada.

```json
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }

}
```

O bloco que cresce tem a altura do espaço livre, qualquer que seja o conteúdo, e por isso um estilo com fundo visível o pintaria inteiro: pinte o cartão na decoração do modelo e deixe o bloco de texto sem estilo.

### Grades que repetem um conjunto de blocos

Uma página de cartões com fotos, uma página de fichas de atividades ou uma página de retratos com um nome embaixo de cada um é o mesmo cartão desenhado muitas vezes. Um grupo de grade com `repeat` o desenha uma vez no modelo: os blocos de um cartão, chamados de conjunto de blocos, que a grade dispõe uma vez por item que o Markdown da página lhe dá. Quantos cartões uma página tem passa a depender do Markdown, e uma tradução que acrescenta um cartão não precisa de modelo novo. Desde o postext 1.48.

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **O conjunto.** O primeiro bloco de `repeat.frames` é o bloco **principal** da célula: ele toma a largura da célula e mantém a própria regra de altura (`'auto'` é a altura do conteúdo, entre `minHeight` e `maxHeight`). Os outros blocos do conjunto são dispostos como o modelo os desenha, ancorados no bloco principal ou uns nos outros: aqui, a pílula da legenda pende do pé da foto. Um bloco do conjunto ancorado num bloco de fora dele fica onde essa âncora o põe.
- **Itens.** Cada trecho `:::frame{slot="foto"}` da página é um item: os trechos de um slot repetido não são juntados. Dentro do trecho, um elemento que indica um membro do conjunto (`:::frame{slot="pie"}`, `::resource{… slot="pie"}`) vai para esse membro do mesmo cartão; o resto vai para o bloco principal. Veja [Páginas compostas › Slots repetidos](/pt/docs/composed-pages#slots-repetidos).
- **Instâncias.** Os blocos de cada cartão se chamam `<frame>[n]`, contados a partir de 1: `foto[2]` e `pie[2]` são o segundo cartão. Os avisos, o registro de reajustes, o mapa de origem e o Sandbox usam esses nomes, os ids dos blocos são `cp<n>:foto[2]`, e um elemento de decoração ou um conector pode se ancorar em `'#foto[2]'`. O `to: '#foto[*]'` de um conector chega a todos os cartões que a página tem. Um elemento ancorado em `'#foto'` lê a caixa da grade.
- **Células.** As células preenchem as filas a partir do lado inicial; assim, numa página da direita para a esquerda o primeiro cartão fica à direita. Uma fila tem a altura da célula mais alta, contando o que pende acima do bloco principal (uma aba) e abaixo dele (uma pílula); `rowAlign` posiciona as mais baixas. A caixa da grade é o `placement` ou a célula `grid` dela; sem nenhum dos dois, ela começa onde o modelo desenha o bloco principal e vai até a borda direita e o pé da área.
- **Quando os cartões não cabem.** Uma fila que passa do pé da grade é cortada ali, cada cartão sobe a escada de ajuste por conta própria, e o último cartão cortado gera `frameOverflow`. Com `overflow.continueIn` no bloco principal (`'next-page'`, `'template:<id>'`), a grade continua **por filas inteiras**: a primeira fila que não cabe, e todas as seguintes, vão para a página acrescentada, na grade de um modelo que repete o mesmo conjunto de blocos. Uma célula mais alta que a grade inteira gera um aviso em vez de continuar sem fim.
- **`max`.** Os itens além de `repeat.max` vão para o bloco de fluxo, ou para depois da página quando o modelo não tem um, e cada um gera `repeatOverflow`.

Uma grade sem `repeat` dispõe os blocos que lista, um por célula, na ordem em que estão escritos. Um bloco de um conjunto repetido listado em outro grupo é pulado ali (`groupFrameTwice`), e um nome que o modelo não tem é `groupFrameUnknown`. `grow` e `shrink` não se aplicam às filas de uma grade, nem `redistribute` aos cartões dela.

### Módulos

Uma página de livro didático costuma empilhar conjuntos que se repetem pelo livro em outra ordem: um boxe com uma foto ao lado, uma árvore de três ideias, uma grade de quatro fotos sob um título. Desenhar um modelo para cada ordem multiplica os modelos. Um **módulo** é um desses conjuntos desenhado uma vez: um modelo com `role: 'module'`, com blocos, grupos e decoração (conectores incluídos), e sem página própria. Um modelo de página recebe módulos num grupo com `modules: true`; o Markdown da página diz que módulos ela contém e em que ordem (veja [Páginas compostas › Módulos numa página](/pt/docs/composed-pages#módulos-numa-página)). Desde o postext 1.48.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **O que um módulo tem.** Blocos, grupos (inclusive uma grade que se repete), decoração e conectores. Não tem `area`, `header`, `footer`, `variants`, `spread`, `gutter` nem `overflowTemplate`: cada um deles é apontado como `unknownConfigValue` e ignorado. `extends` funciona entre módulos (um modelo que estende um módulo é um módulo).
- **A caixa dele.** Um módulo tem a largura do grupo e a altura até onde chegam os blocos dele; o grupo empilha os módulos a partir do alto, com `gap` entre eles. Dentro de um módulo, `'container'` é a caixa do módulo, para os blocos dele (`'fill'` e porcentagens também) e para a decoração: um fundo dimensionado até `{ to: 'container', edge: 'bottom' }` cobre o módulo, qualquer que seja a altura que as palavras lhe deem.
- **Nomes.** Os blocos, grupos e elementos de um módulo ficam no escopo do nome da instância do módulo: `<name>.<frame>`, com o nome que o Markdown dá (`name="ramas"`) ou então `<template>[n]`, a posição do módulo entre os módulos da página com esse modelo (`arbol[2].raiz`). As âncoras, `next`, `continueIn: '#x'` e os conectores dentro de um módulo são reescritos para os blocos do próprio módulo; assim, duas árvores numa mesma página nunca se ligam uma à outra. Um id de bloco fica `cp0:arbol[2].raiz`.
- **Quando os módulos não cabem.** Um módulo que passa do pé do grupo é cortado ali e os blocos dele sobem a escada de ajuste; `frameOverflow` é gerado uma vez para o grupo. Com `overflow.continueIn` no grupo de módulos (`'next-page'` ou `'template:<id>'`), o primeiro módulo que não cabe e todos os seguintes continuam **inteiros** na página acrescentada, com os mesmos nomes, no alto do grupo de módulos dessa página. Numa fileira ou numa grade de módulos, a fileira continua inteira: os módulos dela nunca se dividem entre duas páginas.
- **Lado a lado.** Um grupo de módulos com `kind: 'row'` põe os módulos do início ao fim, cada um com a `width` do seu modelo (um comprimento, `{ percent: 48 }` ou `'fill'`, uma parte igual do que sobra), e a fileira com a altura do módulo mais alto; `kind: 'grid'` os põe em `columns` colunas iguais, fileira após fileira. `rowAlign` posiciona um módulo mais baixo que a fileira. As fileiras começam pelo lado onde a linha começa, então uma página da direita para a esquerda põe o primeiro módulo à direita. Desde o postext 1.50.
- **Grupos dentro da pilha.** Um grupo de módulos com `within: '<pilha>'` fica dentro da pilha de módulos da página, e `templates` diz quais módulos ele recebe: cada sequência deles no Markdown forma uma fileira ou uma grade da pilha, onde vem o seu primeiro módulo. Com os grupos abaixo, dois blocos `aviso` seguidos de quatro blocos `tarjeta` formam uma fileira de dois quadros sobre uma grade de 2 × 2 cartões, e o Markdown só tem blocos `:::module`.
- **Grupos dentro de grupos.** Desde o postext 1.51 `within` pode nomear qualquer grupo de módulos, também uma fileira ou uma grade, em qualquer profundidade. Com `banda` uma fileira dentro de `cuerpo` e `columna` uma pilha dentro de `banda`, um quadro seguido de dois cartões fica ao lado de uma coluna com os dois cartões. Um bloco da página ancorado a `#banda` é posto depois dos módulos.
- **Dividir uma fileira.** Desde o postext 1.51 o espaço que uma fileira de módulos deixa vai pelo `grow` de cada módulo, e uma fileira mais larga que seu grupo cede largura segundo `shrink`.
- **Ainda não.** Um módulo dentro de um módulo (`moduleNested`) e células `grid` do modelo dentro de um módulo.

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### Quando o conteúdo não cabe

Quando o conteúdo de um bloco é mais alto que o espaço que o grupo lhe dá, a diagramação tenta, em ordem, os passos da [escada de ajuste](/pt/docs/composed-pages#quando-ainda-assim-não-cabe) e para no primeiro que faz o conteúdo caber: espaço livre até `maxHeight`, o grupo empurrando e cedendo, imagens menores, os outros blocos do grupo até o mínimo, texto menor, continuação em outra página. Estas configurações do bloco decidem até onde cada passo pode ir:

- `maxHeight` num bloco com `height` fixo: o bloco pode crescer até esse valor antes que algo seja reduzido.
- `minHeight` nos outros blocos do grupo: até onde eles devolvem espaço; um bloco nunca fica abaixo do que o próprio conteúdo precisa.
- `fit.scaleImages` e `fit.imageMinScale`: se as imagens do bloco e do grupo podem ser diagramadas menores, e até que escala (80 % por padrão).
- `fit.shrinkText` e `fit.minScale`: se o texto do bloco pode ser diagramado menor, e até que escala (90 % por padrão). A escala é a mesma para o corpo, a entrelinha e o espaçamento; o bloco mantém o tamanho.
- `overflow.continueIn`: onde o conteúdo continua quando nada disso basta: em outro bloco ou em outra página (`'next-page'`, `'template:<id>'`, `'page:<id>'`), onde o texto segue no tamanho integral depois da `overflow.mark` do trecho. Um bloco que pode continuar em outra página faz isso antes que as imagens e o texto sejam diagramados menores, a não ser que o `fit.preferContinue` dele seja `false`.

As escalas vão em passos de 2,5 % e a diagramação usa a maior com que o conteúdo cabe; por isso, um texto que passa uma linha do limite fica em 97,5 %, não no mínimo. Uma caixa que precisa manter o corpo do texto usa `fit: { shrinkText: false }`; numa página cujas imagens precisam manter o tamanho, os blocos do grupo usam `fit: { scaleImages: false }`:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

O que ainda assim não cabe aparece como `frameOverflow`, com os passos tentados e propostas que trazem os valores delas: veja [O aviso e suas propostas](/pt/docs/composed-pages#o-aviso-e-suas-propostas).

### Herança e variantes

Um modelo com `extends` parte do modelo que indica (que por sua vez pode estender outro) e muda só o que escreve:

- Um campo como `area`, `header` ou `overflowTemplate` substitui o do pai. `grid` é mesclado chave a chave. `spread`, `gutter` e `role` também são herdados; `id`, `name` e `extends` são do próprio modelo.
- `frames` e `groups` são mesclados **pelo nome**: uma entrada com o nome de uma herdada muda os campos que escreve e mantém o resto (`fit`, `overflow` e `padding` são mesclados chave a chave; `placement` é substituído inteiro); `remove: true` a remove; um nome novo é acrescentado depois dos herdados.
- Os elementos de decoração são mesclados por `id` do mesmo jeito; um elemento com um id novo, ou sem id, é acrescentado. Desde o postext 1.42, `{ id: 'cabecalho-par', remove: true }` em `decoration.elements` de um modelo filho ou de uma variante tira o elemento herdado com esse `id`, como `remove: true` faz com um bloco; um `id` que o modelo não herda não muda nada. Um elemento novo com o mesmo `id` pode seguir a remoção na mesma lista.

`variants.recto` e `variants.verso` são escritos como um modelo e mesclados do mesmo jeito, numa página ímpar ou numa par. Eles se aplicam depois de toda a cadeia de `extends`, primeiro a variante da raiz. Uma página dupla tem os dois lados; por isso, nenhuma variante se aplica a ela.

Um elemento de `variants.recto` com `parity: 'even'`, ou de `variants.verso` com `'odd'`, nunca é desenhado: `unknownConfigValue`.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Quando o Sandbox salva um modelo, um valor igual ao padrão nunca é descartado: num modelo que estende outro, ou numa variante, esse valor substitui o do pai.

No código, `resolvePageTemplate(config, id, { parity })` devolve um modelo com a cadeia mesclada, a variante do lado aplicada, todos os padrões preenchidos e cada referência resolvida como os avisos abaixo descrevem; `validatePageTemplates(config)` devolve os avisos.

### Desenhado quando a página diz

Um elemento da decoração, e um do `header` ou do `footer` do modelo, pode ter `when` ou `unless`, cada um com o nome de um atributo do contêiner de página. `when: 'folio'` desenha o elemento só nas páginas cujo contêiner define `folio`; `unless: 'frontmatter'` o tira das páginas cujo contêiner define `frontmatter`. Um contêiner define um atributo quando o escreve sozinho (`::::page{template="pagina" frontmatter}`) ou com qualquer valor exceto `false`. Assim um só modelo serve às páginas pré-textuais, sem fólio nem faixa, e às páginas do miolo, que têm os dois: o Markdown diz o que a página é e o modelo guarda o desenho. Desde o postext 1.50.

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- Um elemento ancorado a um elemento deixado de fora, ou com o tamanho medido até ele, também fica de fora.
- Com as duas chaves, o elemento é desenhado onde o contêiner define o atributo de `when` e não o de `unless`.
- Os cabeçalhos do documento e os de uma seção também as leem. Uma página que não é composta não tem contêiner e não define nada. Os desenhos de título, de parte e de caixa as ignoram.
- Um valor que não é um texto não vazio, ou um escrito num desenho de título, de parte ou de caixa, é avisado como `unknownConfigValue`, e o elemento é desenhado como se não o tivesse. O `postext check` acrescenta uma nota, `conditionNeverMet`, para um `when` ou `unless` com um atributo que nenhuma página do livro define: esse elemento nunca é desenhado, ou sempre. O mesmo vale para um `{attr.x}` que nada define: fica vazio.
- Com o livro diagramado, uma página que não desenha nada de um fólio ou cabeço (um texto de `header` ou `footer`, um texto da decoração que lê `{pageNumber}`, um nome corrido ou `{attr.x}`) que a maioria das páginas do seu modelo e do seu lado desenha é avisada como `folioMissing`, com a página, o modelo e o elemento. Não conta uma página cujo contêiner desliga o elemento, nem uma cujo modelo não o tem. Desde o postext 1.53.
- No Sandbox, cada cartão de elemento de um cabeçalho e da decoração de um modelo tem os campos **Desenhado quando a página diz** e **Não desenhado quando a página diz**, cujas opções são os atributos que os contêineres de página do livro usam.

### O que a diagramação aplica

A diagramação aplica o posicionamento e os tamanhos de cada bloco (grade, âncoras, `min`/`max`, `verticalAlign`), o estilo e o `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (e o `wrap` correspondente), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) com `overflow.mark` e `overflow.fromMark`, e o `fit` (a redução do texto e das imagens na escada de ajuste, veja [Quando o conteúdo não cabe](#quando-o-conteúdo-não-cabe)); a negociação de espaço de um grupo (`grow`, `shrink`, `priority`, `pin`, e o `gap` e o `align` do grupo, veja [Como os grupos dividem o espaço](#como-os-grupos-dividem-o-espaço)); e `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` e `overflowTemplate` do modelo. Desde o postext 1.42 aplica também a `palette` do modelo, o `look` de um bloco e a largura `'auto'` (a da linha mais longa do bloco). O `writingMode` e a `direction` de um bloco são aplicados desde o postext 1.39. Desde o postext 1.48 aplica os grupos de grade e o `repeat` deles, os grupos de módulos e os modelos de módulo, os conectores e os elementos de caminho da decoração, e o `overlap` de um bloco. É lido e verificado, mas ainda não aplicado: o `bodyStyle` do modelo.

### Páginas duplas

Em um modelo de página dupla todas as coordenadas valem sobre a folha formada pelas duas páginas, com a lombada no meio: `area`, `grid`, as âncoras em `container`, `page` e `bleed` e os tamanhos `fill` leem a largura dupla. `bleed` chega à cabeça, ao pé e às duas bordas externas, nunca à lombada. A linha do tempo em página dupla de um livro didático é um só modelo:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … de era-2 a era-6, uma coluna da grade cada, e as notas sob a tira
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Um espaço entre colunas maior que o `gutter` mantém as fichas de uma grade simétrica longe da lombada, e nenhuma é movida. A segunda faixa e a tira de ilustrações têm `crossGutter` para atravessá-la: cada uma é lida na página que contém o centro dela e pintada nas duas. Todas as palavras da página, inclusive os nomes das eras nas abas, ficam no Markdown.

Num livro vertical (`vertical-rl`) a página dupla é composta no referencial do fluxo das páginas, como as páginas compostas avulsas desse livro: o alto da página é a borda direita da folha e as linhas descem; por isso, o `x` do modelo desce pela folha, e o `y` vai da borda direita da folha para a esquerda. A folha é a página direita seguida da esquerda ao longo de `y`, a lombada é uma linha que atravessa o modelo, e `gutter`, `crossGutter` e o corte entre as páginas leem esse eixo; a decoração continua composta sobre a folha física e cortada na lombada. Uma linha do tempo horizontal desenhada para um livro horizontal sai girada num vertical: escreva o modelo de um livro vertical no referencial do fluxo dele. Desde o postext 1.38. Um cartão que deva ser lido na largura da folha leva `writingMode: 'horizontal-tb'`: é composto na horizontal e fica de pé na página vertical (desde o postext 1.39).

### Conectores

Um conector é uma linha da decoração que liga blocos: os ramos de um diagrama em árvore, um organograma, os traços de uma linha do tempo, as setas de um fluxograma, o ponteiro de uma nota para um lugar num mapa. Ele é posicionado depois que os blocos têm as caixas definitivas; assim, acompanha um texto que cresce, uma edição com palavras mais longas ou um grupo que move os blocos, e é desenhado como linha vetorial em todas as saídas, de modo que o modelo não precisa de uma imagem das linhas. Os conectores são elementos da `decoration` de um modelo de página ou de um módulo; os cabeços e os designs de título não têm blocos para ligar, e um conector ali é apontado (`unknownConfigValue`) e não é desenhado. Desde o postext 1.48.

```ts
decoration: {
  elements: [
    { kind: 'connector', id: 'ramas', routing: 'tree', radius: { value: 2, unit: 'mm' },
      width: { value: 1.25, unit: 'pt' }, from: { to: '#raiz' }, to: [{ to: '#a' }, { to: '#b' }], endCap: 'arrow' },
  ],
},
```

<table>
  <thead>
    <tr>
      <th style={{ width: '170px' }}>Propriedade</th>
      <th style={{ width: '200px' }}>Tipo</th>
      <th style={{ width: '120px' }}>Padrão</th>

**Pontas que não estão lá.** Uma ponta num bloco que a página não mostra (recolhido, opcional e vazio, um cartão além dos itens da página, um ponto da imagem que o bloco dela corta) fica de fora: uma árvore mantém os outros filhos, e o registro de reajustes da página informa isso (`connectorDropped`). Sem nenhum `from` ou nenhum `to` restante, nada é desenhado.

**Pintura.** Os conectores são pintados como caminhos vetoriais: no canvas, no PDF, no visualizador HTML e no EPUB de layout fixo, e como artefato de layout num PDF marcado; o EPUB refluível os deixa de fora junto com o resto da decoração. Um conector com uma extremidade `anchor` é pintado sobre todos os blocos da página, de modo que uma linha que aponta para dentro de uma imagem aparece sobre o bloco da imagem sem `layer`; os outros conectores ficam com a decoração, sob os blocos. `over: true` leva uma linha entre blocos para cima, `over: false` mantém uma linha que aponta por baixo. Numa página dupla, um conector entre blocos das duas páginas atravessa a lombada e é cortado ali, como o resto da decoração; numa página da direita para a esquerda, `start` e `end` seguem o fluxo espelhado.

```ts
frames: [
  { name: 'mapa', width: { value: 118, unit: 'mm' } },
  { name: 'nota', style: 'nota', width: { value: 44, unit: 'mm' } },
],
decoration: { elements: [
  { kind: 'connector', id: 'a-lago', from: { to: '#nota', side: 'end' },
    to: { to: '#mapa', anchor: 'lago', gap: { value: 1.2, unit: 'mm' } }, endCap: 'dot' },
] },
```

**Verificações.** Uma ponta cujo `to` não indica nada é `frameAnchorUnknown` (em `…/from/to` ou `…/to/<k>/to`) e fica de fora; `[*]` só é válido em `to` e num bloco repetido. Um `anchor` que nenhuma imagem do bloco tem é `labelAnchorUnknown`, com o id do conector. Uma palavra fora das opções de `routing`, `startCap`, `endCap` ou `side`, e um `at` fora de 0 a 1, são `unknownConfigValue`. Um `opacity` que não é um número de 0 a 1 também é `unknownConfigValue` (um número fora do intervalo é ajustado a ele).

## Aparências de bloco

Uma grade de cartões com foto cujas pílulas só mudam de cor, ou uma página de boxes em uma dúzia de tons, mantém um só estilo de boxe e um só modelo: as cores vão em `frameLooks`, uma lista de aparências com nome, e o Markdown indica uma em cada trecho que a usa. Desde o postext 1.50.

```ts
frameLooks: [
  { id: 'rojo', name: 'Red pill', background: { hex: '#e63946', model: 'hex' }, body: { color: { hex: '#ffffff', model: 'hex' } } },
  { id: 'verde', background: { hex: '#6a994e', model: 'hex' } },
  { id: 'marino', border: { color: { hex: '#264653', model: 'hex' } } },
]
```

## Estilos de rótulo

A propriedade `labelStyles` dá nome às aparências dos rótulos colocados sobre uma imagem: os mares e as cidades de um mapa, as partes de um esquema. Um rótulo fica numa âncora da imagem (um ponto guardado com o recurso, como as âncoras de personagem dos quadrinhos) e usa o estilo que a âncora ou o rótulo indica. No Sandbox eles são editados em **Design › Figuras e tabelas › Estilos de rótulo** (desde o postext 1.42). Renomear ali um estilo reescreve as âncoras e as linhas `::label` que o citam (desde o postext 1.43).

```ts
labelStyles: [
  { id: 'mar', fontStyle: 'italic', textTransform: 'uppercase', letterSpacing: 0.12,
    color: { hex: '#2b6ca3', model: 'hex' } },
```

`start` e `end` seguem a direção do rótulo: num rótulo árabe, `start` é a borda direita. Uma âncora compartilhada pelas edições da esquerda para a direita e da direita para a esquerda de um mesmo mapa funciona melhor com o rótulo centrado acima ou abaixo do ponto. Um rótulo com `width` quebra entre palavras; uma palavra mais larga que a medida reduz o rótulo inteiro, até o `minScale` do estilo dele. Como os rótulos são desenhados está em [Páginas compostas](/pt/docs/composed-pages).

Uma linha de chamada sai do rótulo pelo lado da caixa dele (a placa, senão as linhas) que fica voltado para o ponto através do maior intervalo, a partir do meio desse lado; assim, a linha nunca atravessa as palavras do rótulo, nem mesmo num rótulo girado. Um ponto sob a caixa do rótulo, ou uma linha de chamada mais curta que a marca da ponta, não desenha nada. As linhas de chamada são pintadas sob os rótulos, com a imagem, em todas as saídas que desenham rótulos, e acompanham a imagem quando ela é recortada, escalada, espelhada ou posta numa página dupla.

```ts
anchors: [
  { id: 'peaks', x: 0.42, y: 0.8, labelAt: { x: 0.62, y: 0.6 }, style: 'name', leader: true },
  { id: 'lake', x: 0.531, y: 0.865, labelAt: { x: 0.76, y: 0.93 }, style: 'name', leader: { routing: 'elbow' } },
],
```

## Avisos dos modelos de página

No resto da configuração, o motor ignora uma chave que não conhece. Os modelos de página e os estilos de rótulo, por outro lado, são verificados, e cada problema é um aviso de configuração no `postext check` e no painel Verificações do Sandbox. O campo `path` desses avisos é um ponteiro JSON para o campo com problema: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Quando o campo foi herdado, o ponteiro indica o modelo que o escreveu. Um aviso que cita um id ou um nome inexistente também sugere o existente mais parecido.

Uma chave digitada errado de um modelo, bloco, grupo, grade, `fit`, `overflow`, variante ou estilo de rótulo é um `unknownConfigKey`; uma palavra fora das opções de um ajuste (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`, `overlap`, `rowAlign`, o `routing`, as pontas e o `side` de um conector, as pontas e o `routing` de uma linha de chamada) é um `unknownConfigValue`, e o ajuste mantém o valor padrão. Um modelo sem `id`, ou um bloco ou grupo sem `name`, é ignorado com um `unknownConfigValue` nesse campo. As aparências de bloco (`frameLooks`) são verificadas do mesmo jeito: uma aparência sem `id` é ignorada, e uma chave que o `look` de um bloco não tem é um `unknownConfigKey`.
