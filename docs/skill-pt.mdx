# Skill para agentes

**Transforme uma publicação existente em um projeto do Postext com um agente de programação.**

Muita gente chega ao Postext com um livro que já existe: um livro didático
em PDF de impressão, um relatório no Word, um curso no PowerPoint, um
catálogo no InDesign, um EPUB. Portá-lo significa dois trabalhos:

- **Conteúdo**: o Markdown enriquecido de cada capítulo, com as diretivas
  e microformatos.
- **Design**: um manifesto de configuração que reproduz as regras de
  diagramação do original (geometria da página, grade de linhas de base,
  tipos, aberturas, cabeços, boxes, flutuantes, tabelas, partes).

Um LLM consegue fazer boa parte desse trabalho, mas só se souber como o
Postext funciona. O Markdown do Postext não é CommonMark, e a configuração tem
armadilhas que só aparecem quando uma página sai errada. A skill
**`postext-port`** reúne esse conhecimento junto com as ferramentas que usamos
para construir cada predefinição do Sandbox, para que seu agente faça a
conversão direito.

Ela segue o formato aberto [Agent Skills](https://agentskills.io); por isso,
funciona com Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode e
[muitos outros agentes](https://skills.sh).

## Assista ao tutorial

Cinco minutos, sem código: preparar a pasta, trazer os originais vetoriais,
acrescentar um PDF de referência, pedir ao agente e conferir o resultado no
Sandbox.

## O que a skill contém

- **Um fluxo de trabalho**:
  1. combinar o briefing;
  2. fazer o inventário do original;
  3. medir o design em uma ficha de especificações;
  4. montar o esqueleto do projeto;
  5. extrair o conteúdo;
  6. revisá-lo e passá-lo para o Markdown do Postext;
  7. preparar fontes e imagens;
  8. verificar página por página;
  9. empacotar.
- **Referências**:
  - o formato do documento e o manifesto de configuração, ambos conferidos
    com o motor;
  - o formato do projeto (pacote);
  - um roteiro por formato de origem;
  - um método de análise de design;
  - um catálogo de casos de diagramação resolvidos: partes com cores próprias,
    aberturas de capítulo, verso, notas de margem, notas de rodapé, índices remissivos, boxes
    flutuantes, divididos e aninhados, originais vetoriais de impressão, figuras com texto vivo, imagens em células
    de tabela, tabelas em paisagem, edições bilíngues e mais;
  - livros chineses, compostos na horizontal ou na vertical e encadernados à
    direita: o que perguntar no briefing (escrita, região, direção,
    encadernação), como medir uma grade de caracteres, como ler PDFs
    verticais, o rubi e o warichu do InDesign, o layout asiático
    do Word e os EPUBs da direita para a esquerda, e como recortar fontes CJK para
    o livro (veja [Composição chinesa](/pt/docs/chinese-layout));
  - livros japoneses, romances bunko e tankōbon verticais encadernados à
    direita ou livros técnicos horizontais: o idioma que liga as regras
    japonesas (`ja`, nunca uma tag chinesa), o que perguntar (direção, grade,
    furigana, notas, a ortografia da edição), como medir a mancha em
    caracteres e linhas, a marcação de furigana e de bōten, textos do Aozora
    Bunko convertidos com `aozora.py`, digitalizações de edições em domínio
    público da Biblioteca Nacional da Dieta, e fontes japonesas recortadas com
    os kana e as formas verticais (veja [Composição japonesa](/pt/docs/japanese-layout));
  - livros árabes, modernos ou clássicos e vocalizados, compostos da direita
    para a esquerda e encadernados à direita: o idioma que põe o livro inteiro
    da direita para a esquerda, o que perguntar (região e algarismos, vocalização, verso, sumário no fim),
    como medir uma página espelhada, como ler árabe em PDFs, no Word e na
    Wikisource, poemas como `:::verse`, notas «(١)» por página, e fontes
    árabes recortadas com as tabelas de ligação (veja [Composição em árabe](/pt/docs/arabic-layout));
  - quadrinhos, mangás e tiras de jornal: a divisão que corta uma página em
    quadros, as imagens dos quadros com as âncoras de personagem e as áreas
    seguras, um roteiro por idioma que o motor letreira (balões, recordatórios,
    onomatopeias), mangás da direita para a esquerda e edições árabes, e como
    portar a partir de desenhos sem texto mais traduções, de digitalizações
    letreiradas ou de um roteiro com desenhos gerados (veja [Quadrinhos](/pt/docs/comics));
  - as páginas compostas: páginas fixas de livros didáticos, cadernos de
    exercícios e revistas portadas como modelos de página cujos blocos são
    preenchidos pelo Markdown, qual rodada de porte o Postext instalado aceita e
    as verificações que cada edição precisa passar (veja [Páginas compostas](/pt/docs/composed-pages));
  - o objeto impresso: como ler o papel, a encadernação, as capas e a lombada
    do original e defini-los nas configurações `folio` que o [visualizador Folio](/pt/docs/sandbox-previews#aba-folio)
    mostra, conferidas pelo linter.
- **Scripts** (Python e Node), descritos na próxima seção.

## Instalação

### Qualquer agente (skills.sh)

A CLI [`skills`](https://skills.sh) detecta seus agentes e instala a skill
para eles:

```bash
npx skills add drnachio/postext --skill postext-port
```

Escolha os agentes explicitamente com `-a`, e instale globalmente (em todos os
projetos) com `-g`:

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

O site também publica a mesma skill; por isso, isto também funciona:

```bash
npx skills add https://postext.dev
```

### Plugin do Claude Code

O repositório do Postext também é um marketplace de plugins do Claude Code.
Dentro do Claude Code:

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

Ou a partir de um shell:

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### Deixe o agente instalá-la

Você pode pedir a seu agente que faça isso, por exemplo: *“Instale a skill de
conversão do Postext (`npx skills add drnachio/postext --skill postext-port`) e
use-a para portar este PDF.”* Os agentes que leem `https://postext.dev/llms.txt`
encontram ali esta página e o comando de instalação.

### Ferramentas que os scripts usam

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

O Pandoc é necessário para originais em Word, PowerPoint, EPUB e HTML, o poppler
para as imagens das páginas do original, e o numpy para `comic_panels.py`. Os pacotes do Node fazem funcionar o renderizador
sem interface (Node 22.15 ou mais recente); `@napi-rs/canvas` é um canvas
pré-compilado que permite pintar as páginas do livro direto em JPEG.
Ferramentas opcionais: `ocrmypdf` para digitalizações, ImageMagick e veraPDF
para verificações PDF/UA.

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

Escolha o arquivo do seu sistema (`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`); com o Node, `npx postext-cli` também funciona.

O ciclo de trabalho roda na [linha de comando](/pt/docs/command-line), um executável autônomo que não precisa ser instalado: o agente mantém o projeto descompactado e deixa `postext build --watch` rodando sobre as páginas em que está trabalhando, de modo que cada mudança aparece como JPEG cerca de um segundo depois, mesmo num livro longo. Os pacotes do Node são opcionais: eles rodam o `render.mjs`, que acrescenta as verificações extras do Sandbox. Os dois diagramam o livro com `bodyText.shapingLanguage: 'host'`, seja qual for a configuração do livro; por isso, uma linha pode quebrar numa palavra diferente da do Sandbox (veja [Diferenças em relação ao Sandbox](/pt/docs/command-line#diferenças-em-relação-ao-sandbox)).

## Como usar

Coloque os arquivos originais na sua pasta de trabalho e peça a conversão. Por exemplo:

- *“Porte os capítulos 1–3 de `manual.pdf` para o Postext, reproduzindo a
  diagramação em duas colunas, as aberturas de capítulo e os boxes.”*
- *“Converta `course.docx` em um livro do Postext. Os estilos ‘Nota’ e
  ‘Actividad’ são boxes.”*
- *“Transforme `deck.pptx` em uma apostila do Postext: os slides viram seções,
  as notas do apresentador viram o texto.”*
- *“Temos o pacote do InDesign (IDML + PDF de impressão) deste livro didático.
  Monte a predefinição do Postext para o capítulo 1 em espanhol e em inglês.”*

Para um livro do InDesign, dê ao agente a pasta que **Arquivo › Empacotar**
cria no InDesign (o `.idml`, o PDF de impressão, as fontes e as ilustrações
vinculadas). A skill deduz delas as regras de diagramação, o que o importador
de IDML não faz: [InDesign: importar, exportar e portar](/pt/docs/indesign)
compara os dois.

O agente segue o fluxo de trabalho:

1. **Briefing.** Ele pergunta o que não consegue deduzir: uma reprodução fiel
   ou um redesenho, um capítulo de amostra ou o livro inteiro, idiomas,
   impressão ou tela, e os direitos sobre o texto, as imagens e as fontes.
2. **Inventário e medição.** Ele lê o original e escreve uma ficha de
   especificações com fatos medidos: refile, margens, colunas, entrelinha,
   papéis tipográficos, paleta, aberturas, cabeços, famílias de boxes e
   hábitos de colocação. Ele classifica cada página como texto corrido ou
   como página composta (boxes, rótulos e mapas em lugares fixos). Com o
   Postext 1.35 ou mais recente, agrupa as páginas compostas por tipo e
   monta cada tipo a partir de um modelo de página, de modo que a diagramação
   continua idêntica e o texto continua editável e traduzível. Com uma
   versão anterior, se mais de um terço das páginas for composta, pergunta se
   você prefere a diagramação idêntica ou um texto que possa editar e traduzir.
3. **Projeto.** Ele monta o esqueleto de `my-book/` com um gerador
   `build_preset.py` que guarda a especificação como constantes e produz o
   `preset.json`.
4. **Conteúdo.** Ele extrai rascunhos de capítulos com o extrator certo e
   depois os revisa e passa para o Markdown do Postext: boxes, estilos de
   parágrafo, partes, atributos de título para as aberturas, citações `:ref`,
   recursos de tabela e de figura.
5. **Verificação.** Ele passa o linter e deixa `postext build --watch`
   rodando sobre o projeto descompactado: muda um capítulo ou uma
   configuração, olha o JPEG da página, repintado cerca de um segundo
   depois, e muda de novo até que as quebras de página, as figuras e os
   boxes coincidam com o original página por página. A cada etapa concluída
   ele roda as verificações completas (`postext check` e o linter). O PDF é
   gerado para as verificações de impressão, não a cada olhada.
6. **Entrega.** Ele define o papel, a encadernação e as capas do livro para o
   visualizador Folio e empacota `my-book.postext`.

Abra o resultado no [Sandbox](/pt/sandbox): **Livros → Novo → Abrir um arquivo .postext…**.
A importação traz os capítulos e os textos no idioma do Sandbox. Para
trabalhar com uma pasta de projetos em uma cópia local do Postext, defina
`POSTEXT_PRIVATE_PRESETS_DIR` (veja [Sandbox](/pt/docs/sandbox)).

### Carregar o resultado a partir de código

O arquivo entregue não está preso ao Sandbox. O pacote `postext` o abre com `openBundle`, diagrama o livro com `buildBundle` e o renderiza em canvas, HTML ou PDF (veja [Pacotes](/pt/docs/configuration-bundles#pacotes-arquivos-postext)). Uma conversão pode, portanto, alimentar um programa diretamente. Quando a saída desse programa precisar de ajustes, exporte-a de volta para um arquivo `.postext` com `createBundle`, faça o ajuste fino no Sandbox e carregue de novo o arquivo corrigido. O `render.mjs` sem interface da skill também aceita um arquivo `.postext` empacotado, além de uma pasta de projeto.

## O que esperar

- **Os extratores produzem rascunhos; o agente os revisa.** Conte com uma
  rodada de revisão por capítulo, comparando com as páginas originais. É dessa revisão
  que vem a qualidade.
- **O texto fica no Markdown.** A configuração guarda o projeto gráfico e cada
  palavra do livro está nos capítulos; por isso, uma correção ou uma tradução é
  só uma edição do Markdown. Com o Postext 1.35 ou mais recente, as páginas
  compostas são modelos de página na configuração, cujos blocos se preenchem
  com o Markdown de cada capítulo: um boxe cresce com uma tradução mais longa e
  empurra os de baixo, e a partir da 1.37 as palavras de um mapa são rótulos
  escritos no Markdown. Com uma versão anterior, elas são montadas com boxes
  fixados no lugar, imagens de página sem texto e figuras SVG com rótulos
  em texto vivo. O relatório diz qual dos dois caminhos o agente seguiu e com
  qual versão. Quando o Postext não consegue expressar algo sem digitar texto na
  configuração, o agente para, escreve a lacuna como rascunho de issue e
  pergunta a você. A skill nunca altera o motor para encaixar um livro.
- **Um só arquivo para todos os idiomas.** Uma tradução é um conjunto de
  capítulos no mesmo arquivo `.postext`, com legendas e rótulos de figura
  próprios, verificado com `postext check` em cada idioma.
- **Os direitos são decisão sua.** O agente pergunta antes de reproduzir
  imagens ou fontes cujas licenças não estejam claras. As fontes licenciadas
  são marcadas com `redistributable: false`, e por isso os projetos exportados
  as deixam de fora.
- **Fidelidade onde importa.** O objetivo é a mesma grade, os mesmos tipos,
  aberturas, boxes, colocação das figuras e quebras de página na maioria das
  páginas (com diferença de no máximo uma página por capítulo), não quebras de
  linha idênticas.

## Onde ela fica

A skill está no repositório em
[`plugins/postext/skills/postext-port`](https://github.com/drnachio/postext/tree/main/plugins/postext/skills/postext-port).
Ela cobre todos os casos encontrados ao construir as predefinições do Sandbox,
públicas e privadas. Quando uma conversão topar com um caso que ela ainda não
cobre, abra uma issue ou um pull request que melhore a skill, para que a
próxima conversão já o receba pronto.
