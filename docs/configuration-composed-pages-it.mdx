# Configurazione: pagine composte


## Modelli di pagina

Una pagina composta è una pagina la cui forma viene da un **modello** della configurazione e il cui contenuto viene dal Markdown di un blocco di pagina, il blocco `::::page{template="…"}` che si apre con quattro segni di due punti. Il modello dà un nome a dei rettangoli, chiamati **cornici**; il Markdown manda ogni parte del contenuto a una cornice per nome (il suo slot). La geometria non compare mai nel Markdown, e il testo del contenuto non compare mai nel modello. La proprietà `pageTemplates` contiene i modelli del libro:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

Un modello che imposta solo il suo `id` e una cornice è una pagina intera in cui quella cornice riempie l’area del contenuto. Tutti gli altri campi sono facoltativi:

### Cornici

Una cornice è un rettangolo con un nome che riceve contenuto composto. Il suo `name` è lo slot che il Markdown indica, ed è unico nel suo modello (nemmeno un gruppo può prendere il nome di una cornice, perché gli ancoraggi indicano entrambi allo stesso modo).

Una cornice si colloca nella cella indicata da `grid`, se il modello ha una griglia, altrimenti secondo `placement`, che funziona come quello di un elemento grafico: un ancoraggio (`'container'` è l’area, `'page'`, `'bleed'`, o `'#name'` per un’altra cornice o un altro gruppo), un bordo, uno scostamento e una dimensione. Una cornice ancorata a un’altra si sposta con essa. Senza né l’una né l’altro, la cornice parte dall’angolo in alto a sinistra dell’area, larga quanto l’area e alta quanto dice la sua regola di altezza. Come il contenuto viene distribuito tra le cornici, concatenato e tagliato è descritto in [Pagine composte › Come si compone la pagina](/it/docs/composed-pages#come-si-compone-la-pagina).

**Cornici rigate.** Uno spazio per la risposta in un quaderno di attività è una cornice con `rules`: le sue righe seguono la sua altezza, quindi è il Markdown a decidere quante sono. Una cornice vuota di altezza fissa riceve le righe che vi entrano; una cornice `'auto'` che riceve `:::space{lines=4}` ne riceve quattro, e una cornice che cresce con il suo testo ne riceve di più. Le righe si disegnano sopra lo sfondo della cornice e sotto il suo testo, nel canvas, nell’HTML, nel PDF e nell’EPUB a layout fisso; l’ispettore delle cornici della Sandbox le attiva in Aspetto.

```ts
frames: [

],
groups: [{ name: 'actividad', kind: 'stack', gap: { value: 3, unit: 'mm' }, frames: ['pregunta', 'respuesta'] }],
```

```markdown
:::frame{slot="respuesta"}

:::space{lines=4}

:::
```

### Gruppi

Un gruppo è una pila (dall’alto in basso) o una fila (dall’inizio alla fine) di cornici che si dividono lo spazio e si spostano insieme. Dentro un gruppo, la posizione propria delle cornici lungo la direzione del gruppo viene ignorata: il gruppo le dispone in ordine, con `gap` tra l’una e l’altra. Quando il testo di una cornice cresce, le cornici che la seguono si spostano. Un gruppo è un riquadro a cui si possono ancorare cornici e decorazione (`'#pagina'`).

### Come i gruppi si dividono lo spazio

Una cornice dichiara la sua dimensione: un `height` fisso, oppure `'auto'`, cioè l’altezza di ciò che contiene, tenuta fra `minHeight` e `maxHeight`. In un modello ricalcato su una pagina stampata, dai a ogni riquadro come `minHeight` l’altezza che ha su quella pagina: con un testo breve il riquadro resta come è disegnato, con uno più lungo diventa più alto. Nella stessa passata la pagina viene disposta due volte, una come la dichiara il modello e una come la richiede il contenuto, e le differenze fra le due finiscono nel [registro di reimpaginazione](/it/docs/composed-pages#registro-di-reimpaginazione).

**Pila.** Le cornici di una pila si dispongono l’una sotto l’altra, ciascuna alla sua altezza, con `gap` fra l’una e l’altra. Ognuna mantiene la propria posizione orizzontale e la propria larghezza; la sua posizione verticale viene ignorata.

- Un gruppo senza `placement` né `grid` propri comincia dove è collocata la sua prima cornice (il suo `placement`, o la sua cella `grid` in un modello con griglia) e scende quanto serve alle sue cornici, fino al piede dell’area del modello. Quando una cornice cresce, quelle che la seguono scendono della stessa misura.
- Un gruppo con un riquadro proprio dispone le sue cornici dentro quel riquadro. Se le cornici richiedono più spazio di quanto il riquadro ne offra, cedono spazio quelle con `shrink` maggiore di 0, a cominciare da quelle con la `priority` più bassa; le cornici con la stessa priorità cedono in proporzione al loro `shrink`, e nessuna scende sotto il suo `minHeight`. Lo spazio libero va alle cornici con `grow` maggiore di 0, in proporzione a quel valore e fino al loro `maxHeight`; se nessuna ha `grow`, le cornici vengono collocate secondo `align` (`'end'` al piede, `'center'`, `'space-between'`). Una cornice del gruppo senza una collocazione propria prende come area il riquadro del gruppo.
- Quando più niente può cedere, cedono per prime le cornici più vicine al piede del gruppo, ciascuna fino al suo `minHeight`; una cornice con altezza fissa la tiene, così uno spazio di risposta vuoto o il posto di un’immagine sotto un riquadro che cresce resta sulla pagina, ed è il testo del riquadro a cedere. Nessuna cornice oltrepassa il piede del gruppo: la cornice il cui contenuto non entra percorre la sequenza di reimpaginazione (vedi [Quando il contenuto non entra](#quando-il-contenuto-non-entra)), e quello che ancora non entra viene tagliato lì e segnalato come `frameOverflow`. Anche una cornice ridotta sotto il suo `minHeight` o la sua altezza fissa viene segnalata, che abbia contenuto o no.
- Una cornice con `height: 'fill'` chiede il suo `minHeight` e prende lo spazio libero come se avesse `grow: 1`.

**Fila.** Le cornici di una fila si affiancano alle larghezze dichiarate e sono tutte alte quanto la fila, cioè quanto il riquadro del gruppo o, se il gruppo non ne ha uno proprio, quanto la maggiore fra le altezze che scrivono le sue cornici: una `height` fissa, altrimenti un `minHeight` (una cornice `'auto'` non dichiara altro), oppure, se non ne scrivono nessuna, quanto il contenuto più alto (una cornice con altezza fissa tiene la sua). Quando il testo di una cornice supera l’altezza della fila, la cornice si allarga: prima prende la larghezza libera della fila, poi quella delle cornici vicine con `shrink` maggiore di 0, a cominciare da quelle con la `priority` più bassa, e nessuna di queste diventa più stretta della larghezza in cui il suo testo entra ancora. La cornice prende il minor numero di millimetri interi che basta a far entrare il testo; se non basterebbe nemmeno tutto lo spazio disponibile, non prende nulla, e una fila senza riquadro proprio diventa invece più alta. Così delle schede con `height: 'auto'` e un `minHeight` si dividono la larghezza a quell’altezza, e la fila cresce solo quando nessuna ha larghezza da cedere. La larghezza libera va alle cornici con `grow` maggiore di 0, e quella che resta si distribuisce secondo `align`. Le file vanno da sinistra a destra.

**Cornici fissate.** Una cornice con `pin: true` mantiene il riquadro che il modello le dichiara anche quando la cornice a cui è ancorata cresce o si sposta: un riquadro disegnato su misura dell’illustrazione le resta sopra. In un gruppo, una cornice fissata tiene il suo posto e le altre cornici la scavalcano, con `gap` su entrambi i lati. Una cornice fissata fuori dal gruppo fa lo stesso con le cornici del gruppo che altrimenti la coprirebbero.

**Decorazione.** Un elemento della decorazione ancorato a una cornice (`anchor: { to: '#dinero' }`) la segue quando la cornice cresce o si sposta. Un elemento con `pin: true` resta dove il modello disegna quella cornice.

Il risultato dipende solo dal contenuto della pagina, dal modello e dalla tipografia: a parità di dati si ottiene la stessa pagina, misurata nello stesso ordine e con gli stessi passi. Mentre divide lo spazio, l’impaginazione non legge mai un’altra pagina, quindi una modifica su una pagina composta lascia invariate tutte le altre, purché il contenuto resti sulla sua pagina.

**Tenere le cornici al piede di una scheda (da postext 1.42).** Una cornice ancorata sotto il testo che ha sopra segue quel testo: in un’edizione in cui il testo è una riga più corto o più lungo, le cornici sotto salgono o scendono, mentre ciò che il modello disegna (una scheda, una fascia, il piede) resta dov’è. Per tenere le cornici al piede di una scheda, dove il modello le mette, riunisci le cornici della scheda in una pila con un riquadro proprio alto quanto la scheda. Le cornici sopra quelle trattenute prendono lo spazio che avanza (`grow: 1`) e lo restituiscono (`shrink: 1`); quelle trattenute scrivono un `minHeight`. Un testo più corto lascia le cornici trattenute dove erano. Uno più lungo viene stretto sopra di esse: mantengono il loro `minHeight`, il testo sopra si riduce e, se ancora non entra, l’impaginazione segnala `frameOverflow` e il registro di reimpaginazione annota `textScaled` e `overflow` per la cornice sopra. Anche una cornice ancorata al piede del contenitore (`bottom-left`) mantiene il suo posto, ma nulla la lega alle cornici sopra: un testo più lungo la ricopre, nulla viene stretto per lei e la sovrapposizione non viene segnalata.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

La cornice che cresce è alta quanto lo spazio libero, qualunque cosa contenga, quindi uno stile con sfondo visibile la colorerebbe tutta: disegna la scheda nella decorazione del modello e lascia la cornice di testo senza stile.

### Griglie che ripetono un insieme di cornici

Una pagina di schede con foto, una pagina di schede di attività o una pagina di ritratti con un nome sotto ciascuno sono la stessa scheda disegnata molte volte. Un gruppo a griglia con `repeat` la disegna una sola volta nel modello: le cornici di una scheda, dette insieme di cornici, che la griglia dispone una volta per ogni elemento che il Markdown della pagina le dà. Quante schede ha una pagina lo decide allora il Markdown, e una traduzione che aggiunge una scheda non ha bisogno di un nuovo modello. Da postext 1.48.

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **L’insieme.** La prima cornice di `repeat.frames` è la cornice **principale** della cella: prende la larghezza della cella e mantiene la propria regola di altezza (`'auto'` è l’altezza del suo contenuto, fra `minHeight` e `maxHeight`). Le altre cornici dell’insieme si dispongono come le disegna il modello, ancorate alla cornice principale o l’una all’altra: qui la pastiglia della didascalia pende dal piede della foto. Una cornice dell’insieme ancorata a una cornice esterna resta dove la mette quell’ancoraggio.
- **Elementi.** Ogni pezzo `:::frame{slot="foto"}` della pagina è un elemento: i pezzi di uno slot ripetuto non vengono uniti. Dentro il pezzo, un blocco che indica un membro dell’insieme (`:::frame{slot="pie"}`, `::resource{… slot="pie"}`) va a quel membro della stessa scheda; il resto va alla cornice principale. Vedi [Pagine composte › Slot ripetuti](/it/docs/composed-pages#slot-ripetuti).
- **Istanze.** Le cornici di ogni scheda si chiamano `<frame>[n]`, contando da 1: `foto[2]` e `pie[2]` sono la seconda scheda. Gli avvisi, il registro di reimpaginazione, la mappa delle origini e la Sandbox usano questi nomi, gli id delle cornici sono `cp<n>:foto[2]`, e un elemento della decorazione o un connettore può ancorarsi a `'#foto[2]'`. Il `to: '#foto[*]'` di un connettore raggiunge tutte le schede della pagina. Un elemento ancorato a `'#foto'` legge il riquadro della griglia.
- **Celle.** Le celle riempiono le righe dal lato d’inizio, quindi in una pagina da destra a sinistra la prima scheda sta a destra. Una riga è alta quanto la sua cella più alta, contando ciò che pende sopra la cornice principale (una linguetta) e sotto (una pastiglia); `rowAlign` colloca quelle più basse. Il riquadro della griglia è il suo `placement` o la sua cella `grid`; se non ne ha, comincia dove il modello disegna la cornice principale e arriva al bordo destro e al piede dell’area.
- **Quando le schede non entrano.** Una riga che supera il piede della griglia viene tagliata lì, ogni scheda percorre da sola la scala di reimpaginazione, e l’ultima scheda tagliata segnala `frameOverflow`. Con `overflow.continueIn` sulla cornice principale (`'next-page'`, `'template:<id>'`), la griglia prosegue **per righe intere**: la prima riga che non entra, e tutte quelle che la seguono, si dispongono nella pagina aggiunta, nella griglia di un modello che ripete lo stesso insieme di cornici. Una cella più alta dell’intera griglia dà un avviso invece di proseguire all’infinito.
- **`max`.** Gli elementi oltre `repeat.max` vanno alla cornice di flusso, o dopo la pagina quando il modello non ne ha una, e ciascuno produce `repeatOverflow`.

Una griglia senza `repeat` dispone le cornici che elenca, una per cella, nell’ordine in cui sono scritte. Una cornice di un insieme ripetuto elencata in un altro gruppo viene saltata lì (`groupFrameTwice`), e un nome che il modello non ha è `groupFrameUnknown`. `grow` e `shrink` non si applicano alle righe di una griglia, né `redistribute` alle sue schede.

### Moduli

Una pagina di libro di scuola impila spesso blocchi che tornano lungo il libro in un altro ordine: un riquadro con una foto accanto, un albero di tre idee, una griglia di quattro foto sotto un titolo. Disegnare un modello per ogni ordine moltiplica i modelli. Un **modulo** è uno di questi blocchi disegnato una volta sola: un modello con `role: 'module'`, che contiene cornici, gruppi e decorazione (connettori compresi), e nessuna pagina propria. Un modello di pagina prende i moduli in un gruppo con `modules: true`; il Markdown della pagina dice quali moduli contiene e in che ordine (vedi [Pagine composte › Moduli in una pagina](/it/docs/composed-pages#moduli-in-una-pagina)). Da postext 1.48.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **Che cosa ha un modulo.** Cornici, gruppi (compresa una griglia che si ripete), decorazione e connettori. Non ha `area`, `header`, `footer`, `variants`, `spread`, `gutter` né `overflowTemplate`: ciascuno di questi viene segnalato come `unknownConfigValue` e ignorato. `extends` funziona fra moduli (un modello che estende un modulo è un modulo).
- **Il suo riquadro.** Un modulo è largo quanto il suo gruppo e alto fin dove arrivano le sue cornici; il gruppo impila i moduli dalla sua cima, con `gap` fra l’uno e l’altro. Dentro un modulo, `'container'` è il riquadro del modulo, per le sue cornici (anche `'fill'` e le percentuali) e per la sua decorazione: un fondo dimensionato a `{ to: 'container', edge: 'bottom' }` copre il modulo qualunque altezza gli diano le sue parole.
- **Nomi.** Le cornici, i gruppi e gli elementi di un modulo prendono come prefisso il nome dell’istanza del modulo: `<name>.<frame>`, con il nome che dà il Markdown (`name="ramas"`) oppure `<template>[n]`, il numero d’ordine del modulo tra i moduli della pagina con quel modello (`arbol[2].raiz`). Gli ancoraggi, `next`, `continueIn: '#x'` e i connettori dentro un modulo vengono riscritti verso le sue cornici, così due alberi sulla stessa pagina non si uniscono mai fra loro. L’id di una cornice è `cp0:arbol[2].raiz`.
- **Quando i moduli non entrano.** Un modulo che supera il piede del gruppo viene tagliato lì e le sue cornici percorrono la scala di reimpaginazione; `frameOverflow` viene segnalato una volta per il gruppo. Con `overflow.continueIn` sul gruppo di moduli (`'next-page'` o `'template:<id>'`), il primo modulo che non entra e tutti quelli che lo seguono proseguono **interi** nella pagina aggiunta, con gli stessi nomi, in cima al gruppo di moduli di quella pagina. In una fila o in una griglia di moduli una fila prosegue intera: i suoi moduli non vengono mai divisi tra due pagine.
- **Affiancati.** Un gruppo di moduli con `kind: 'row'` mette i suoi moduli dall’inizio alla fine, ciascuno largo quanto la `width` del suo modello (una lunghezza, `{ percent: 48 }` o `'fill'`, una parte uguale di ciò che resta), con la fila alta quanto il suo modulo più alto; `kind: 'grid'` li mette in `columns` colonne uguali, fila dopo fila. `rowAlign` colloca un modulo più basso della sua fila. Le file partono dal lato in cui inizia la riga, quindi una pagina da destra a sinistra mette il primo modulo a destra. Da postext 1.50.
- **Gruppi dentro la pila.** Un gruppo di moduli con `within: '<pila>'` sta dentro la pila di moduli della pagina, e `templates` dice quali moduli riceve: ogni serie consecutiva di questi nel Markdown forma una fila o una griglia della pila, dove viene il suo primo modulo. Con i gruppi qui sotto, due blocchi `aviso` seguiti da quattro blocchi `tarjeta` danno una fila di due riquadri sopra una griglia di 2 × 2 schede, e il Markdown contiene solo blocchi `:::module`.
- **Gruppi dentro gruppi.** Da postext 1.51 `within` può nominare qualsiasi gruppo di moduli, anche una riga o una griglia, a qualsiasi profondità. Con `banda` una riga dentro `cuerpo` e `columna` una pila dentro `banda`, un riquadro seguito da due schede sta accanto a una colonna con le due schede. Una cornice della pagina ancorata a `#banda` viene messa dopo i moduli.
- **Dividere una riga.** Da postext 1.51 lo spazio che una riga di moduli lascia va secondo il `grow` di ogni modulo, e una riga più larga del suo gruppo cede larghezza secondo `shrink`.
- **Non ancora.** Un modulo dentro un modulo (`moduleNested`) e celle `grid` del modello dentro un modulo.

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### Quando il contenuto non entra

Quando il contenuto di una cornice è più alto dello spazio che le dà il suo gruppo, l’impaginazione prova in ordine i passi della [sequenza di reimpaginazione](/it/docs/composed-pages#quando-il-contenuto-ancora-non-entra) e si ferma al primo che lo fa entrare: lo spazio libero fino a `maxHeight`, il gruppo che spinge e cede, immagini più piccole, le altre cornici del gruppo portate al loro minimo, testo più piccolo, la prosecuzione in un’altra pagina. Queste impostazioni della cornice stabiliscono fin dove può spingersi ciascun passo:

- `maxHeight` su una cornice con `height` fisso: la cornice può crescere fin lì prima di qualsiasi riduzione.
- `minHeight` sulle altre cornici del gruppo: fin dove restituiscono spazio; una cornice non scende mai sotto quanto richiede il suo contenuto.
- `fit.scaleImages` e `fit.imageMinScale`: se le immagini della cornice e del suo gruppo si possono rimpicciolire, e fino a quale scala (80 % per impostazione predefinita).
- `fit.shrinkText` e `fit.minScale`: se il testo della cornice si può rimpicciolire, e fino a quale scala (90 % per impostazione predefinita). La scala è la stessa per il corpo, l’interlinea e le spaziature; la cornice mantiene la sua dimensione.
- `overflow.continueIn`: dove prosegue il contenuto quando tutto questo non basta, in un’altra cornice o in un’altra pagina (`'next-page'`, `'template:<id>'`, `'page:<id>'`), dove il testo riprende a dimensione piena dopo l’`overflow.mark` del pezzo. Una cornice che può proseguire in un’altra pagina lo fa prima che le sue immagini e il suo testo si riducano, a meno che il suo `fit.preferContinue` sia `false`.

Le scale vanno a passi del 2,5 % e l’impaginazione sceglie la più grande che funziona, così un testo che eccede di una riga viene composto al 97,5 %, non al minimo. Un riquadro che deve mantenere il suo corpo imposta `fit: { shrinkText: false }`; una pagina le cui immagini devono mantenere la loro dimensione imposta `fit: { scaleImages: false }` sulle cornici del suo gruppo:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

Quello che ancora non entra viene segnalato come `frameOverflow`, con i passi tentati e proposte che portano i loro valori: vedi [L’avviso e le sue proposte](/it/docs/composed-pages#lavviso-e-le-sue-proposte).

### Ereditarietà e varianti

Un modello con `extends` parte dal modello che indica (che a sua volta può estenderne un altro) e cambia solo ciò che scrive:

- Un campo come `area`, `header` o `overflowTemplate` sostituisce quello del genitore. `grid` si unisce chiave per chiave. Anche `spread`, `gutter` e `role` si ereditano; `id`, `name` ed `extends` sono propri del modello.
- `frames` e `groups` si uniscono **per nome**: una voce con il nome di una ereditata cambia i campi che scrive e tiene gli altri (`fit`, `overflow` e `padding` si uniscono chiave per chiave; `placement` si sostituisce per intero); `remove: true` la elimina; un nome nuovo si aggiunge dopo quelli ereditati.
- Gli elementi della decorazione si uniscono per `id` allo stesso modo; un elemento con un id nuovo, o senza id, si aggiunge. Da postext 1.42, `{ id: 'testata-pari', remove: true }` in `decoration.elements` di un modello figlio o di una variante toglie l’elemento ereditato con quell’`id`, come `remove: true` fa per una cornice; un `id` che il modello non eredita non cambia nulla. Un nuovo elemento con lo stesso `id` può seguire la rimozione nella stessa lista.

`variants.recto` e `variants.verso` si scrivono come un modello e si uniscono allo stesso modo, su una pagina di destra o di sinistra. Si applicano dopo tutta la catena di `extends`, prima la variante della radice. Una doppia pagina ha entrambi i lati, quindi nessuna variante vale per essa.

Un elemento di `variants.recto` con `parity: 'even'`, o di `variants.verso` con `'odd'`, non viene mai disegnato: `unknownConfigValue`.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Un valore uguale a un predefinito non viene mai scartato quando la Sandbox salva un modello: in un modello che ne estende un altro, o in una variante, sostituisce il valore del genitore.

Dal codice, `resolvePageTemplate(config, id, { parity })` restituisce un modello con la catena unita, la variante del lato applicata, ogni valore predefinito compilato e ogni riferimento risolto come descrivono gli avvisi più sotto; `validatePageTemplates(config)` restituisce gli avvisi.

### Disegnato quando la pagina lo dice

Un elemento della decorazione, e uno dell’`header` o del `footer` del modello, può avere `when` o `unless`, ciascuno con il nome di un attributo del blocco della pagina. `when: 'folio'` disegna l’elemento solo nelle pagine il cui blocco imposta `folio`; `unless: 'frontmatter'` lo toglie dalle pagine il cui blocco imposta `frontmatter`. Un blocco imposta un attributo quando lo scrive da solo (`::::page{template="pagina" frontmatter}`) o con un valore diverso da `false`. Così un solo modello serve alle pagine preliminari, senza folio né banda, e alle pagine del testo, che hanno entrambi: il Markdown dice che cosa è la pagina e il modello tiene il disegno. Da postext 1.50.

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- Un elemento ancorato a un elemento tolto, o con la misura che arriva fino a esso, viene tolto anche lui.
- Con entrambe le chiavi, l’elemento si disegna dove il blocco imposta l’attributo di `when` e non quello di `unless`.
- Le testatine del documento e quelle di una sezione le leggono anch’esse. Una pagina che non è composta non ha blocco e non imposta nulla. I disegni di titolo, di parte e di riquadro le ignorano.
- Un valore che non è un testo non vuoto, o uno scritto in un disegno di titolo, di parte o di riquadro, viene segnalato come `unknownConfigValue`, e l’elemento si disegna come se non lo avesse. `postext check` aggiunge una nota, `conditionNeverMet`, per un `when` o un `unless` su un attributo che nessuna pagina del libro imposta: quell’elemento non si disegna mai, oppure sempre. Lo stesso per un `{attr.x}` che nulla imposta: resta vuoto.
- A libro impaginato, una pagina che non disegna nulla di un folio o di una testatina (un testo di `header` o `footer`, un testo della decorazione che legge `{pageNumber}`, un nome corrente o `{attr.x}`) che la maggior parte delle pagine del suo modello e del suo lato disegna viene segnalata come `folioMissing`, con la pagina, il modello e l’elemento. Non conta una pagina il cui blocco spegne l’elemento, né una il cui modello non ha quell’elemento. Da postext 1.53.
- Nel Sandbox, ogni scheda di elemento di una testatina e della decorazione di un modello ha i campi **Disegnato quando la pagina lo dice** e **Non disegnato quando la pagina lo dice**, che offrono gli attributi usati dai blocchi di pagina del libro.

### Che cosa applica l’impaginazione

L’impaginazione applica la collocazione e le dimensioni di ogni cornice (griglia, ancoraggi, `min`/`max`, `verticalAlign`), il suo stile e il suo `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (e il suo `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) con `overflow.mark` e `overflow.fromMark`, e il suo `fit` (la riduzione del testo e delle immagini nella scala di riadattamento, vedi [Quando il contenuto non entra](#quando-il-contenuto-non-entra)); la ripartizione dello spazio in un gruppo (`grow`, `shrink`, `priority`, `pin`, e il `gap` e l’`align` del gruppo, vedi [Come i gruppi si dividono lo spazio](#come-i-gruppi-si-dividono-lo-spazio)); e `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` e `overflowTemplate` del modello. Da postext 1.42 applica anche la `palette` del modello, il `look` di una cornice e la larghezza `'auto'` (quella della riga più lunga della cornice). Il `writingMode` e la `direction` di una cornice sono applicati da postext 1.39. Da postext 1.48 applica i gruppi a griglia e il loro `repeat`, i gruppi di moduli e i modelli di modulo, i connettori e gli elementi tracciato nella decorazione, e l’`overlap` di una cornice. Viene letto e controllato, ma non ancora applicato: il `bodyStyle` del modello.

### Doppie pagine

In un modello a doppia pagina tutte le coordinate valgono sul foglio delle sue due pagine, con il dorso al centro: `area`, `grid`, gli ancoraggi a `container`, `page` e `bleed` e le misure `fill` leggono la larghezza doppia. `bleed` arriva alla testa, al piede e ai due bordi esterni, mai al dorso. La linea del tempo a doppia pagina di un libro di testo è un solo modello:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … da era-2 a era-6, una colonna della griglia ciascuna, e le note sotto la striscia
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Un’intercolonna più larga del `gutter` tiene le schede di una griglia simmetrica lontane dal dorso, quindi nessuna si sposta. La seconda fascia e la striscia di immagini hanno `crossGutter` per attraversarlo: ciascuna si legge sulla pagina che ne contiene il centro e si disegna su entrambe. Tutte le parole della pagina, anche i nomi delle epoche sulle linguette, restano nel Markdown.

In un libro verticale (`vertical-rl`) la doppia pagina si compone nel sistema di riferimento del flusso delle pagine, come le sue pagine composte singole: l’alto della pagina è il bordo destro del foglio e le righe scendono, quindi la `x` del modello scende lungo il foglio e la sua `y` va dal bordo destro del foglio a quello sinistro. Il foglio è la pagina destra seguita dalla sinistra lungo `y`, il dorso è una linea che attraversa il modello, e `gutter`, `crossGutter` e il taglio fra le pagine leggono quell’asse; la decorazione si compone sempre sul foglio fisico e si taglia al dorso. Una linea del tempo orizzontale disegnata per un libro orizzontale esce ruotata in uno verticale: scrivi il modello di un libro verticale nel sistema di riferimento del suo flusso. Da postext 1.38. Una scheda da leggere in orizzontale sul foglio prende `writingMode: 'horizontal-tb'`: viene composta in orizzontale e sta dritta sulla pagina verticale (da postext 1.39).

### Connettori

Un connettore è una linea della decorazione che unisce delle cornici: i rami di uno schema ad albero, un organigramma, le stanghette di una linea del tempo, le frecce di un diagramma di flusso, il puntatore di una nota verso un luogo di una carta. Si colloca quando le cornici hanno già il loro riquadro definitivo, quindi segue un testo che cresce, un’edizione con parole più lunghe o un gruppo che sposta le sue cornici, e si disegna come linea vettoriale in ogni uscita, così il modello non ha bisogno di un’immagine delle linee. I connettori sono elementi della `decoration` di un modello di pagina o di un modulo; le testatine e la grafica dei titoli non hanno cornici da unire, e un connettore lì viene segnalato (`unknownConfigValue`) e non disegnato. Da postext 1.48.

```ts
decoration: {
  elements: [
    { kind: 'connector', id: 'ramas', routing: 'tree', radius: { value: 2, unit: 'mm' },
      width: { value: 1.25, unit: 'pt' }, from: { to: '#raiz' }, to: [{ to: '#a' }, { to: '#b' }], endCap: 'arrow' },
  ],
},
```

**Estremità che non ci sono.** Un’estremità su una cornice che la pagina non mostra (ridotta a zero, facoltativa e vuota, una scheda oltre gli elementi della pagina, un punto dell’immagine che la sua cornice taglia fuori) viene tralasciata: un albero tiene gli altri figli, e il registro di reimpaginazione della pagina lo annota (`connectorDropped`). Se non resta un `from` o un `to`, non si disegna nulla.

**Disegno.** I connettori si disegnano come tracciati vettoriali: nel canvas, nel PDF, nel visualizzatore HTML e nell’EPUB a layout fisso, e come artefatto di impaginazione in un PDF taggato; l’EPUB a layout fluido li lascia fuori insieme al resto della decorazione. Un connettore con un’estremità `anchor` si disegna sopra tutte le cornici della pagina, così una linea che punta dentro un’immagine si vede sopra la cornice dell’immagine senza un `layer`; gli altri connettori restano con la decorazione, sotto le cornici. `over: true` porta sopra una linea fra cornici, `over: false` tiene sotto una linea che punta. In una doppia pagina un connettore fra cornici delle due pagine attraversa il dorso e viene tagliato lì come il resto della decorazione; in una pagina da destra a sinistra `start` ed `end` seguono il flusso specchiato.

```ts
frames: [
  { name: 'mapa', width: { value: 118, unit: 'mm' } },
  { name: 'nota', style: 'nota', width: { value: 44, unit: 'mm' } },
],
decoration: { elements: [
  { kind: 'connector', id: 'a-lago', from: { to: '#nota', side: 'end' },
    to: { to: '#mapa', anchor: 'lago', gap: { value: 1.2, unit: 'mm' } }, endCap: 'dot' },
] },
```

**Controlli.** Un’estremità il cui `to` non indica nulla è `frameAnchorUnknown` (in `…/from/to` o `…/to/<k>/to`) e viene tralasciata; `[*]` vale solo in `to` e su una cornice ripetuta. Un’`anchor` che nessuna immagine della cornice ha è `labelAnchorUnknown`, con l’id del connettore. Una parola fuori dalle scelte di `routing`, `startCap`, `endCap` o `side`, e un `at` fuori dall’intervallo da 0 a 1, sono `unknownConfigValue`. Un’`opacity` che non è un numero da 0 a 1 è anch’essa `unknownConfigValue` (un numero fuori dall’intervallo viene riportato al suo interno).

## Aspetti delle cornici

Una griglia di schede con foto le cui pastiglie differiscono solo per il colore, o una pagina di riquadri in una dozzina di tinte, tiene un solo stile di riquadro e un solo modello: i colori vanno in `frameLooks`, un elenco di aspetti con nome, e il Markdown ne indica uno su ogni pezzo che lo porta. Da postext 1.50.

```ts
frameLooks: [
  { id: 'rojo', name: 'Red pill', background: { hex: '#e63946', model: 'hex' }, body: { color: { hex: '#ffffff', model: 'hex' } } },
  { id: 'verde', background: { hex: '#6a994e', model: 'hex' } },
  { id: 'marino', border: { color: { hex: '#264653', model: 'hex' } } },
]
```

- **Dove si applica.** Un pezzo `:::frame{slot="…" look="<id>"}` porta l’aspetto. In una griglia, il pezzo principale dell’elemento e il `:::frame` annidato di un membro indicano ciascuno il proprio (vedi [Pagine composte › Aspetti delle cornici](/it/docs/composed-pages#aspetti-delle-cornici)).

Vale solo per quel pezzo. Lo portano anche le cornici in cui prosegue il suo testo (una catena, una pagina aggiunta per continuazione).

- **Verifiche.** Una voce senza `id` viene ignorata (`unknownConfigValue`), e una chiave che un aspetto non ha è un `unknownConfigKey` a qualsiasi profondità, con il nome più vicino. Un pezzo che indica un id che nessuna voce ha tiene i colori della sua cornice e produce `lookUnknown`.

## Stili delle etichette

La proprietà `labelStyles` dà un nome agli aspetti delle etichette messe su un’immagine: i mari e le città di una carta, le parti di uno schema. `start` ed `end` seguono la direzione dell’etichetta: in un’etichetta araba `start` è il suo bordo destro. Un’ancora condivisa dalle edizioni da sinistra a destra e da destra a sinistra della stessa mappa si legge meglio con l’etichetta centrata sopra o sotto il punto. Un’etichetta con `width` va a capo tra le parole; una parola più larga della giustezza riduce tutta l’etichetta, fino al `minScale` del suo stile. Come vengono disegnate le etichette è spiegato in [Pagine composte](/it/docs/composed-pages).

Una linea di richiamo lascia l’etichetta dal lato del suo riquadro (la piastra, altrimenti le righe) rivolto verso il punto lungo lo spazio più ampio, dal centro di quel lato, così la linea non attraversa mai le parole dell’etichetta, anche quando è ruotata. Un punto che cade sotto il riquadro dell’etichetta, o una linea più corta del suo segno finale, non disegna nulla. Le linee di richiamo si disegnano sotto le etichette, con l’immagine, in ogni uscita che disegna le etichette, e seguono l’immagine quando viene ritagliata, ridotta, specchiata o distesa su una doppia pagina.

```ts
anchors: [
  { id: 'peaks', x: 0.42, y: 0.8, labelAt: { x: 0.62, y: 0.6 }, style: 'name', leader: true },
  { id: 'lake', x: 0.531, y: 0.865, labelAt: { x: 0.76, y: 0.93 }, style: 'name', leader: { routing: 'elbow' } },
],
```

## Avvisi dei modelli di pagina

Altrove il motore ignora una chiave che non conosce. I modelli di pagina e gli stili delle etichette invece vengono verificati, e ogni problema diventa un avviso di configurazione in `postext check` e nel pannello Verifiche della Sandbox. Il `path` di questi avvisi è un puntatore JSON al campo in errore: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Quando il campo è stato ereditato, il puntatore indica il modello che l’ha scritto. Un avviso che cita un id o un nome inesistente suggerisce anche quello esistente più vicino.

Una chiave scritta male di un modello, di una cornice, di un gruppo, di una griglia, di `fit`, di `overflow`, di una variante o di uno stile di etichetta è un `unknownConfigKey`; una parola fuori dalle scelte di un’impostazione (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`, `overlap`, `rowAlign`, il `routing`, le estremità e il `side` di un connettore, le estremità e il `routing` di una linea di richiamo) è un `unknownConfigValue`, e l’impostazione tiene il suo valore predefinito. Un modello senza `id`, o una cornice o un gruppo senza `name`, viene ignorato con un `unknownConfigValue` su quel campo. Gli aspetti delle cornici (`frameLooks`) si verificano allo stesso modo: un aspetto senza `id` viene ignorato, e una chiave che il `look` di una cornice non ha è un `unknownConfigKey`.
