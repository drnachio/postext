# Skill para agentes

**Convierte una publicación existente en un proyecto de Postext con un agente de programación.**

Mucha gente llega a Postext con un libro que ya existe: un manual en PDF de
imprenta, un informe en Word, un curso en PowerPoint, un catálogo en InDesign,
un EPUB. Portarlo supone dos trabajos:

- **El contenido**: el Markdown enriquecido de cada capítulo, con sus
  directivas y microformatos.
- **El diseño**: un manifiesto de configuración que reproduzca las reglas de
  maquetación del original (geometría de página, rejilla base, tipografía,
  aperturas, titulillos, recuadros, flotantes, tablas, partes).

Un LLM puede hacer buena parte de este trabajo, pero solo si sabe cómo
funciona Postext. El Markdown de Postext no es CommonMark, y la configuración
tiene trampas que solo se descubren cuando una página sale mal compuesta. La
skill **`postext-port`** reúne ese conocimiento con las herramientas que
usamos para construir cada preset del Sandbox, para que tu agente haga bien
la conversión.

Sigue el formato abierto [Agent Skills](https://agentskills.io), así que
funciona con Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode
y [muchos otros agentes](https://skills.sh).

## Mira el tutorial

Cinco minutos, sin programar: prepara la carpeta, reúne los originales
vectoriales, añade un PDF de referencia, haz el encargo al agente y revisa el
resultado en el Sandbox.

## Qué contiene la skill

- **Un flujo de trabajo**:
  1. acordar el encargo;
  2. inventariar el original;
  3. medir el diseño y anotarlo en una ficha de especificaciones;
  4. crear el esqueleto del proyecto;
  5. extraer el contenido;
  6. pulirlo hasta convertirlo en Markdown de Postext;
  7. preparar fuentes e imágenes;
  8. verificar página a página;
  9. empaquetar.
- **Referencias**:
  - el formato de documento y el manifiesto de configuración, ambos
    comprobados contra el motor;
  - el formato de proyecto (paquete);
  - una guía para cada formato de origen;
  - un método de análisis del diseño;
  - un catálogo de casos de maquetación ya resueltos: partes con colores
    propios, aperturas de capítulo, poesía, glosas al margen, notas al pie,
    índices analíticos, recuadros flotantes, partidos y anidados, originales
    vectoriales para imprenta, figuras con texto vivo, imágenes en celdas de
    tabla, tablas apaisadas, ediciones bilingües y más;
  - libros chinos, compuestos en horizontal o en vertical y encuadernados por
    la derecha: qué preguntar en el encargo (escritura, región, dirección,
    encuadernación), cómo medir una retícula de caracteres, cómo leer PDF
    verticales, el ruby y el warichu de InDesign, la maquetación de Asia
    oriental de Word y los EPUB de derecha a izquierda, y cómo recortar las
    fuentes CJK a los caracteres del libro (véase [Composición china](/es/docs/chinese-layout));
  - libros japoneses, ya sean novelas bunko y tankōbon en vertical y
    encuadernadas por la derecha o libros técnicos en horizontal: el idioma
    que activa las reglas japonesas (`ja`, nunca una etiqueta china), qué
    preguntar (dirección, retícula, furigana, notas, la ortografía de la
    edición), cómo medir la caja de texto en caracteres y líneas, el marcado
    de furigana y bōten, los textos de Aozora Bunko convertidos con
    `aozora.py`, los escaneos de ediciones de dominio público de la
    Biblioteca Nacional de la Dieta y las fuentes japonesas recortadas con
    sus kana y sus formas verticales (véase [Composición japonesa](/es/docs/japanese-layout));
  - libros árabes, modernos o clásicos y vocalizados, compuestos de derecha a
    izquierda y encuadernados por la derecha: el idioma que pone todo el
    libro de derecha a izquierda, qué preguntar (región y cifras,
    vocalización, poesía, índice al final), cómo medir una página en espejo,
    cómo leer el árabe de PDF, Word y Wikisource, los poemas como `:::verse`,
    las notas «(١)» numeradas por página y las fuentes árabes recortadas con
    sus tablas de enlace (véase [Composición
    árabe](/es/docs/arabic-layout));
  - cómics, manga y tiras de prensa: la división que corta una página en
    viñetas, las imágenes de las viñetas con sus anclas de personaje y sus
    zonas seguras, un guion por idioma que el motor rotula (bocadillos,
    cartelas, onomatopeyas), el manga de derecha a izquierda y las ediciones
    árabes, y cómo portar a partir de dibujos sin texto y sus traducciones,
    de escaneos ya rotulados o de un guion con imágenes generadas (véase [Cómics](/es/docs/comics));
  - las páginas compuestas: las páginas fijas de libros de texto, cuadernos
    y revistas portadas como plantillas de página cuyos marcos se llenan desde
    el Markdown, qué ronda de porte admite el Postext instalado y las
    comprobaciones que debe pasar cada edición (consulta [Páginas compuestas](/es/docs/composed-pages));
  - el objeto impreso: cómo leer el papel, la encuadernación, las cubiertas
    y el lomo del original y fijarlos en los ajustes `folio` que muestra el
    [visor Folio](/es/docs/sandbox-previews#pestaña-folio), con la comprobación del linter.
- **Scripts** (Python y Node), descritos en la sección siguiente.

## Instalación

### Cualquier agente (skills.sh)

La CLI [`skills`](https://skills.sh) detecta tus agentes e instala la skill
para ellos:

```bash
npx skills add drnachio/postext --skill postext-port
```

Elige agentes concretos con `-a` e instálala para todos tus proyectos con `-g`:

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

La web publica la misma skill, así que esto también funciona:

```bash
npx skills add https://postext.dev
```

### Plugin de Claude Code

El repositorio de Postext es también un marketplace de plugins de Claude
Code. Dentro de Claude Code:

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

O desde la terminal:

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### Que la instale el agente

Puedes pedírselo a tu propio agente, por ejemplo: *«Instala la skill de Postext
para portar publicaciones (`npx skills add drnachio/postext --skill postext-port`)
y úsala para portar este PDF»*. Los agentes que leen
`https://postext.dev/llms.txt` encuentran allí esta página y el comando de
instalación.

### Herramientas que usan los scripts

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

Pandoc es necesario para los originales en Word, PowerPoint, EPUB y HTML;
poppler, para las imágenes de las páginas del original, y numpy, para `comic_panels.py`. Los paquetes de Node
hacen funcionar el renderizador sin navegador (Node 22.15 o posterior);
`@napi-rs/canvas` es un canvas precompilado con el que pinta las páginas del
libro directamente en JPEG. Herramientas opcionales: `ocrmypdf` para
escaneos, ImageMagick y veraPDF, para comprobar PDF/UA.

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

Elige el archivo de tu sistema (`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`); con Node, también funciona `npx postext-cli`.

El ciclo de trabajo se apoya en la [línea de comandos](/es/docs/command-line), un ejecutable autónomo que no requiere instalación: el agente mantiene el proyecto descomprimido y deja `postext build --watch` en marcha sobre las páginas en las que trabaja, de modo que cada cambio aparece como JPEG alrededor de un segundo después, incluso en un libro largo. Los paquetes de Node son opcionales: sirven para ejecutar `render.mjs`, que añade las comprobaciones adicionales del Sandbox. Los dos maquetan el libro con `bodyText.shapingLanguage: 'host'`, diga lo que diga su configuración, así que una línea puede cortarse en una palabra distinta que en el Sandbox (véase [Diferencias con el Sandbox](/es/docs/command-line#diferencias-con-el-sandbox)).

## Cómo usarla

Deja los archivos de origen en tu carpeta de trabajo y pide la conversión.
Por ejemplo:

- *«Porta los capítulos 1 a 3 de `manual.pdf` a Postext, reproduciendo su
  maquetación a dos columnas, las aperturas de capítulo y los recuadros».*
- *«Convierte `curso.docx` en un libro de Postext. Los estilos “Nota” y
  “Actividad” son recuadros».*
- *«Convierte `presentacion.pptx` en un dossier de Postext: las diapositivas
  serán secciones, y las notas del orador, el texto».*
- *«Tenemos el paquete de InDesign (IDML + PDF de imprenta) de este manual.
  Prepara el preset de Postext del capítulo 1 en español e inglés».*

Para un libro de InDesign, dale al agente la carpeta que crea **Archivo ›
Empaquetar** en InDesign (el `.idml`, el PDF de imprenta, las fuentes y las
ilustraciones enlazadas). La skill deduce a partir de ellos las reglas de
maquetación, cosa que el importador de IDML no hace: [InDesign: importar,
exportar y portar](/es/docs/indesign) compara los dos.

El agente sigue el flujo de trabajo:

1. **Encargo.** Pregunta lo que no puede deducir: si quieres una reproducción
   fiel o un rediseño, un capítulo de muestra o el libro entero, en qué
   idiomas, si es para imprimir o para pantalla, y qué derechos tienes sobre
   los textos, las imágenes y las fuentes.
2. **Inventario y medición.** Lee el original y escribe una ficha con los
   datos medidos: formato, márgenes, columnas, interlineado, roles
   tipográficos, paleta, aperturas, titulillos, familias de recuadros y
   hábitos de colocación. Clasifica cada página como texto corrido o como
   página compuesta (recuadros, rótulos y mapas en lugares fijos). Con
   Postext 1.35 o posterior, agrupa las páginas compuestas por tipo y compone
   cada tipo a partir de una plantilla de página, de modo que la maquetación
   sigue siendo idéntica y el texto se puede editar y traducir. Con una
   versión anterior, si más de un tercio de las páginas son compuestas, te
   pregunta si prefieres la maquetación idéntica o un texto que puedas editar
   y traducir.
3. **Proyecto.** Crea `mi-libro/` con un generador, `build_preset.py`, que
   guarda la ficha como constantes y produce `preset.json`.
4. **Contenido.** Extrae los capítulos en borrador con el extractor adecuado
   y los pule hasta convertirlos en Markdown de Postext: recuadros, estilos
   de párrafo, partes, atributos de encabezado para las aperturas, citas
   `:ref` y recursos de tabla y de figura.
5. **Verificación.** Pasa el linter y deja `postext build --watch` en marcha
   sobre el proyecto descomprimido: cambia un capítulo o un ajuste, mira el
   JPEG de la página, que se vuelve a pintar alrededor de un segundo
   después, y repite hasta que los saltos de página, las figuras y los
   recuadros coinciden con el original página a página. En cada hito ejecuta
   las comprobaciones completas (`postext check` y el linter). El PDF solo se
   genera para las comprobaciones de imprenta, no cada vez que revisa una
   página.
6. **Entrega.** Fija el papel, la encuadernación y las cubiertas del libro
   para el visor Folio y empaqueta `mi-libro.postext`.

Abre el resultado en el [Sandbox](/es/sandbox): **Libros → Nuevo → Abrir un archivo .postext…**.
La importación toma los capítulos y los textos del idioma del Sandbox. Para
trabajar con una carpeta de proyectos en una copia local de Postext, define
`POSTEXT_PRIVATE_PRESETS_DIR` (véase [Sandbox](/es/docs/sandbox)).

### Cargar el resultado desde código

El archivo entregado no depende del Sandbox. El paquete `postext` lo abre con `openBundle`, compone el libro con `buildBundle` y lo dibuja en canvas, HTML o PDF (véase [Paquetes](/es/docs/configuration-bundles#paquetes-archivos-postext)). Así, el resultado de una conversión puede alimentar directamente un programa. Si lo que produce ese programa necesita ajustes, vuelve a exportarlo a un archivo `.postext` con `createBundle`, retócalo en el Sandbox y carga de nuevo el archivo corregido. El `render.mjs` de la skill, que compone sin navegador, acepta tanto un archivo `.postext` empaquetado como una carpeta de proyecto.

## Qué esperar

- **Los extractores producen borradores; el agente los pule.** Cuenta con una
  revisión de cada capítulo frente a las páginas originales: de esa revisión
  sale la calidad.
- **El texto se queda en el Markdown.** La configuración guarda el diseño y
  cada palabra del libro está en los capítulos, así que una corrección o una
  traducción es una edición del Markdown. Con Postext 1.35 o posterior, las
  páginas compuestas son plantillas de página de la configuración cuyos
  marcos se llenan con el Markdown de cada capítulo: un recuadro crece con
  una traducción más larga y empuja a los que tiene debajo, y desde la 1.37
  los nombres de un mapa son rótulos escritos en el Markdown. Con una versión
  anterior, se montan con recuadros fijos en su sitio, imágenes de página sin
  texto y figuras SVG con rótulos vivos. El informe indica cuál de las dos
  vías ha usado el agente y con qué versión. Cuando Postext no puede expresar
  algo sin escribir texto en la configuración, el agente se detiene, redacta
  la carencia como borrador de incidencia y te pregunta. La skill nunca
  modifica el motor para adaptarlo a un libro concreto.
- **Un solo archivo para todos los idiomas.** Una traducción es un juego de
  capítulos dentro del mismo archivo `.postext`, con sus propios pies y
  rótulos de figura, y se comprueba con `postext check` en cada idioma.
- **Los derechos los decides tú.** El agente pregunta antes de reproducir
  imágenes o fuentes con licencias dudosas. Las fuentes con licencia se
  marcan con `redistributable: false`, así que los proyectos exportados no
  las incluyen.
- **Fidelidad donde importa.** El objetivo es conseguir la misma rejilla,
  tipografía, aperturas, recuadros, colocación de figuras y saltos de página
  en la mayoría de las páginas (con un margen de una página por capítulo), no
  cortes de línea idénticos.

## Dónde está

La skill está en el repositorio, en
