# 配置：样式与篇


## 段落样式

`paragraphStyles`属性声明命名样式，文档用`:::paragraphs{style="…"}`容器把样式套用到一组段落上。参考文献、术语表、注释都可以这样排，凡是需要自己的字体、字重、倾斜、字号、行距、大写、小型大写字母或悬挂缩进的一组条目都可以。每个排版字段都可以不设，不设时沿用正文，所以样式里只需写出与正文不同的地方。

```ts
const config: PostextConfig = {
  paragraphStyles: [
    {
      id: 'bibliography',
      name: 'Bibliography',
      fontSize: { value: 7, unit: 'pt' },
      lineHeight: { value: 1.2, unit: 'em' },
      hangingIndent: { value: 2, unit: 'em' },
      spaceBetween: { value: 0.25, unit: 'em' },
      marginTop: { value: 1, unit: 'em' },
      marginBottom: { value: 1, unit: 'em' },
    },
  ],
};
```

```md
## References

:::paragraphs{style="bibliography"}
Knuth, D. E. (1984). *The TeXbook*. Addison-Wesley.

Bringhurst, R. (2004). *The Elements of Typographic Style*. Hartley & Marks.
:::
```

剧本把舞台说明排成斜体，把演员表排成小型大写字母：

```ts
paragraphStyles: [
  { id: 'direction', italic: true, fontSize: { value: 9, unit: 'pt' } },
  { id: 'cast', smallCaps: true, textAlign: 'center', fontWeight: 600 },
],
```

```md
:::paragraphs{style="direction"}
Elsinore. A platform before the castle. *Francisco* at his post.
:::
```

舞台说明印成斜体，其中的人名印成正体；样式的字重、`italic`和`smallCaps`在标注框内同样适用。

诗集里有些诗行要缩进；一行诗超出行长时，转行还要比这一行本身缩得更深。`indent`把段落的每一行向内移，悬挂缩进从那里量起：

```ts
paragraphStyles: [
  { id: 'verse', textAlign: 'left', firstLineIndent: { value: 0, unit: 'em' }, hangingIndent: { value: 4, unit: 'em' } },
  { id: 'verse-indented', textAlign: 'left', indent: { value: 1.5, unit: 'em' }, hangingIndent: { value: 2.5, unit: 'em' } },
],
```

`verse-indented`中的诗行从1.5 em处开始，转行从4 em处开始，与`verse`中各行的转行对齐。没有`indent`时，一个样式只能缩进首行或悬挂其余各行，不能两者兼得：一旦设置了`hangingIndent`，`firstLineIndent`就不起作用。

菜单用一串前导点引出价格，价格与行尾对齐：

```ts
paragraphStyles: [
  {
    id: 'menu',
    textAlign: 'left',
    firstLineIndent: { value: 0, unit: 'em' },
    tabStops: [{ position: 'end', align: 'end', leader: '. ' }],
  },
],
```

```md
:::paragraphs{style="menu"}
洋葱汤 :tab 8.50

茴香柠檬烤鲷鱼 :tab 21.00
:::
```

每一行的前导点都在价格前0.5 em处结束（`leaderGap`）。菜名一行排不下时会转行，最后一行保留前导点和价格；最后一个词旁边放不下价格时，这个词随价格一起移到下一行。

### `:::paragraphs`容器

以`:::paragraphs{style="<id>"}`一行开始容器，以单独一行`:::`结束；其间的每个段落都用指定的样式，其中的标题、列表等其他块保持各自平常的样式。容器可以嵌在其他容器指令里。`style`写了未知的id不算错误：这些段落按普通正文排，Sandbox会标出这个id。

开始行还可以写`align`（`start`、`end`、`left`、`right`、`center`、`justify`）、`indent`和`endIndent`（不带单位的数字按em计），有没有样式都行：有样式时，它们覆盖样式的设置；没有样式时，它们叠加在外层容器的样式上，或者叠加在容器所在位置的文字样式上（正文、篇、带样式的区段或标注框）。`:::paragraphs{align=end}`把一块文字排得与行尾对齐（地付き），`:::paragraphs{align=end endIndent=1}`则离行尾一个字。自postext 1.16起。

在容器内，文字离开基线网格（字号7 pt、行距1.2 em的条目不可能落在8 pt/1.5 em的网格上），到最后一段再重新对齐网格（以网格为准，下方空白只是最小值，与标题的约定相同）。条目像正文段落一样可以跨栏、跨页拆开，同样有段首孤行和段末孤行保护；紧挨在容器前面的标题与容器第一段排在一起，不拆开。

容器下方的空白取三者中的最大值：样式的`spaceBetween`、`marginBottom`，以及周围文字的段落间距（开启`bodyText.paragraphSpacing`时为一行）。这段空白再与下一个块在自身上方保留的空白合并，就像两个正文段落之间那样：参考文献后面的标题，与最后一个条目相距它自己的`marginTop`（样式的空白更大时取样式的空白）；一组排得较紧的条目后面的段落，保持正文的段落间距。文字先在容器下方重新对齐网格，对齐没有补足的部分按整行网格顺延，所以容器之后的文字落在网格上。在postext 1.4及以前，样式的空白加在对齐前的最后一行下方，下一个块上方的空白再加在它下面，而且不计段落间距；`bodyText.paragraphContainerSpacing: 'add'`保留这一规则，在它出现之前保存的配置也按它读取。设了`snapToGrid: false`的样式不对齐网格：容器之后的文字恰好排在容器下方指定的距离处，离开网格，直到下一个会对齐网格的块。以列表结束的容器，在两种规则下都按1.4的方式排：列表保留自身下方的空白，`marginBottom`接在这段空白之后，再与下一个块的空白合并。

样式可以用`containerSpacing`给自己的容器定规则：给大号数字或参考文献表的样式设`'add'`，它的段落组无论在正文里还是在框内，都以样式自身的间距收尾，文档里其他容器仍用`'collapse'`；文档用`'add'`时，给样式设`'collapse'`效果正好相反。没有指定样式的容器跟随文档。

在`:::callout`内，容器以同样的方式采用样式的外边距：`marginTop`和`marginBottom`与周围块的间距合并（负值会让它们靠得更近）；位于框开头的容器不取上外边距，与栏顶一样。框内没有可以重新对齐的基线网格，所以最后一段下方的空白取`marginBottom`、`spaceBetween`和框自身段落间距（即框的`body.paragraphSpacing`，框内文字的一行；使用`paragraphContainerSpacing: 'add'`时不计）中的最大值；如果下一个块自身的上外边距更大，就取后者。负的`marginBottom`则把下一个块往上拉。（在postext 1.4及以前，标注框内的容器忽略这两个外边距。）

在框内，样式未设置的排版字段取自框（postext 1.52 起）：样式留给正文的字体、字号、行距、字重和颜色都取框的正文，所以一个只设`textAlign: 'center'`的样式用在`:::paragraphs{style="centred"}`里，在一个框中排成无衬线体，在另一个框中排成衬线体。样式自己设定的字段保持不变。设`bodyText.paragraphStylesInBoxes: 'document'`则改取文档正文，与 postext 1.51 及以前相同。

```ts
const resolved = resolveParagraphStylesConfig(config.paragraphStyles, resolvedBodyText);
// => 每个未设置的字段都从解析后的正文填入

const minimal  = stripParagraphStylesDefaults(config.paragraphStyles);
// => 列表为空时为undefined；去掉为零的外边距和`name === id`
```


## 行内标签样式

`chipStyles`属性为行内的`:chip[text]{style="…"}`声明命名样式。行内标签是带底色的圆角小框，用于词库、键盘按键、标签等（语法和断行规则见文档格式参考）。默认自带一个样式`chip`（浅蓝色底，主色细线轮廓，略带圆角，文字与周围文字相同），所以`:chip[…]`不做任何配置也能用；声明`chipStyles`会替换这份默认列表。没有写`style`、或者写的id没有任何样式声明的行内标签，套用第一个样式（Sandbox会标出未知的id）。

```ts
const config: PostextConfig = {

      borderColor: { hex: '#8a6d1f', model: 'hex' },
      borderRadius: { value: 2, unit: 'pt' },
      bold: true,

  ],
};
```

```md
Classify: :chip[battery] :chip[cable] :chip[switch]
```

## 高亮样式

## 代码清单

`codeStyle`属性设定代码清单的外观，包括正文中的```` ``` ````和`~~~`代码围栏（见[文档格式 › 代码块](/zh/docs/document-format#代码块)），以及设为用代码字体排的行内代码。清单用等宽字体照原样逐行排在一个框里：任何一行都不断词、不两端对齐，每个空格保持自己的宽度，制表符前进到下一个制表位。这个框与`:::callout`用的是同一套机制，所以清单可以在两行之间断开，跨栏、跨页，每一部分各自成框；标注框里的代码围栏就是嵌在标注框里的框。所有属性都可以不设。自postext 1.23起。

### 语法着色

宿主程序可以用`registerCodeHighlighter`接入自己的高亮器（Shiki、Prism、highlight.js）。配置是可序列化的数据，所以这个函数注册到引擎上，而不是写在`codeStyle`中：

```ts
import { registerCodeHighlighter } from 'postext';

// fn(code, lang) returns the listing's lines, each as runs whose texts join into the line.
registerCodeHighlighter('rust', (code) => code.split('\n').map((line) => [
  { text: line, token: line.trimStart().startsWith('//') ? 'comment' : undefined },
]));
registerCodeHighlighter('*', null); // remove the one registered for every language
```

为某种语言注册的高亮器优先于为`'*'`注册的高亮器，后者又优先于内置分词器。每个片段要么指明一个`token`类别（由`tokens`着色），要么带有自己的`color`（CSS十六进制值）。高亮器返回`undefined`、抛出异常，或返回的各行拼不回清单本身的各行时，就跳过它。引擎在排清单时才读取注册表，所以要在构建之前注册；在web worker中排版时（沙盒就在worker中排版），要在worker内注册。

### 清单如何排版

- **一行源文对应一行。** 各行按代码字体自身的前进宽度构建，不经过段落断行器：空格保持宽度，连续的空格都保留，行首空格形成缩进。在从右向左的书中，清单从左向右读，各行从框的另一侧排起，与从左向右的引文一样，行号在左侧的行号栏里。在竖排的书中，清单随竖排方向排（其中的拉丁文按竖排的惯例横躺），不带行号。
- **拆分。** 比剩余空间高的清单在行与行之间断开，跨栏跨页，每部分各自成框，每侧至少留下`splitMinLines`行；只要还有别的断开位置可用，折行的余下部分就与它所属的行留在一起。
- **输出。** 画布、HTML阅读器和PDF按排版结果画出各行和框。HTML阅读器保留空格（`white-space: pre`），所以选区复制出的清单带有缩进，每行源文之后有一个换行，不带行号和折行标记。带标签的PDF把每段清单设为一个包含`Code`元素的段落，空格是真正的空格字形，行号和折行标记是artifact。流式EPUB写出`<pre><code class="language-…">`，带有记号的颜色和一份由`codeStyle`生成的样式表；固定版式的EPUB与印刷版相同。
- **字体。** 正文含有围栏（或配置中有`codeStyle`分区）时，沙盒和`configFontFamilies`会加载代码字体的常规和粗体字重，正体和斜体都有；PDF嵌入各行所用的字体。

## 篇

`parts`属性配置篇名页。文档用`:::part{number="…" title="…"}`容器开始一篇；篇名页就是“第一篇 基础”那样、把一组章归到一起的页面。篇名页总是独占一页：容器先按设定的奇偶另起一页，把这一页改成单栏，版心取自`parts.margins`，再把篇名页的设计铺满整页；容器的结束行之后再分一次页，让下一章（按它自己的`breakBefore.parity`）从新的一页开始。用一级标题的默认设置时，得到的就是经典排法：篇名页在右页（奇数页），背面的左页（偶数页）空白，章从下一个右页开始。

```ts
const config: PostextConfig = {
  parts: {
    breakBefore: { parity: 'odd' },
    breakAfter: { enabled: true, parity: 'any' },
    margins: { top: { value: 9, unit: 'cm' }, left: { value: 3, unit: 'cm' }, right: { value: 3, unit: 'cm' } },
    design: {
      elements: [
        {
          kind: 'text', id: 'number', content: 'Part {numberRoman}',
          fontSize: { value: 12, unit: 'pt' }, fontWeight: 600, align: 'left',
          placement: { anchor: { to: 'page', edge: 'top-left' }, offset: { x: { value: 3, unit: 'cm' }, y: { value: 5, unit: 'cm' } }, size: { width: 'auto', height: 'auto' } },
        },
        {
          kind: 'text', id: 'title', content: '{titleText}',
          fontSize: { value: 28, unit: 'pt' }, fontWeight: 700, align: 'left', overflow: 'wrap',
          placement: { anchor: { to: '#number', edge: 'below' }, size: { width: { value: 15, unit: 'cm' }, height: 'auto' } },
        },
      ],
    },
    bodyStyle: { fontSize: { value: 11, unit: 'pt' }, numberColor: { hex: '#AA0000', model: 'hex' } },
  },
};
```

### 篇设计的占位符

设计中可用的标题占位符取篇自己的值：`{titleText}`是容器的`title`；`{number}`是原样写出的`number`；`{numberDecimal}`、`{numberRoman}`、`{numberRomanLower}`、`{numberAlpha}`、`{numberAlphaLower}`把它换成别的格式。编号可以按十进制数、罗马数字或中文数字解析，前后带不带其他字都行（`"IV"`、`"iv"`、`"4"`、`"４"`、`"四"`、`"卷四"`和`"第四卷"`得到的`{numberDecimal}`都是`4`），其他写法一律解析为`''`。`{partTitle}` / `{partNumber}`、`{chapterTitle}` / `{chapterNumber}`（篇之前的那一章）、`{pageNumber}`、`{totalPages}`、`{bookTotalPages}`以及元数据占位符也都可用。`{attr.<key>}`读取当前章一级标题的属性。

### 左页设计

`versoDesign`装饰篇名页之后的那一页，前提是那一页没有内容，也就是篇名页的背面。篇本身从不让这一页空着：`breakAfter.parity`默认为`'any'`，所以除非另有奇偶要求，结束行之后的内容就从紧接着的下一页开始。奇偶要求可能来自：

- **下一章的标题**。一级标题默认的`breakBefore`是`'always-odd'`；篇名页在右页时，`'odd'`的效果也一样：章移到下一个右页，左页留空，左页设计就会画出来。
- <strong>`parts.breakAfter: { enabled: true, parity: 'odd' }`。</strong>不管下一个标题怎么设置，篇自己要求下一个右页。章可能从任意一侧开始时（`breakBefore.parity: 'any'`或`breakBefore.enabled: false`）用这种写法。

两者都没有时，章从左页开始，不画左页设计。`breakAfter.enabled: false`时，内容就接着排在篇名页上。左页采用篇的调色板，所以容器上的`palette="band=#…"`也会给它换色。

```ts
parts: {
  breakBefore: { parity: 'odd' },
  breakAfter: { enabled: true, parity: 'odd' },   // 总会留出一张可以绘制的空白左页
  versoDesign: {
    elements: [{
      kind: 'box', id: 'field',
      style: { backgroundColor: { hex: '#b07d2b', model: 'hex', paletteId: 'band' } },
      placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } },
    }],
  },
}
```

**结束一章的篇**。在逐章排版的书中（沙盒、`buildBundle`），一个`:::part`容器可以单独成为一章，也可以是某一章的结尾。这时篇名页就是该章的最后一页，篇还没做完的事由下一章接手：下一章在第一个块之前执行`breakAfter`，如果自己的第一页空着，就在上面画出`versoDesign`。排出的页面与整本书放在一个文档里时完全一样。结束行之后只能跟不放置任何内容的指令（`:::numbering`、`:::space`）；其他任何东西都算这一章的内容，分页就由这一章自己完成。紧跟在篇后面的空章自成一页，那一页就是左页。自行逐章排版的宿主程序可以从`continuationAfter()`得到这一信息：以篇结尾的章会报告`afterPartPage: true`，把它传进下一章的`continuation`即可。

### `:::part`容器

`:::part{number="…" title="…"}`一行开启一篇，单独的`:::`结束它；两个属性都可省略（默认为`''`）。中间的各块（通常是章节列表）以`bodyStyle`排在篇名页的单栏里，从`margins.top`开始；正文超出一页时，在普通页面上接着排。这一页标为`role: 'part'`（`VDTPage.partInfo`带有编号和标题），所以页眉页脚元素可以用`pages: 'part'` / `pages: 'body'`专门作用于这一页或跳过它；PDF后端把篇加进书签大纲，排在它的各章上一级。正文为空（`:::part{…}`后面直接是`:::`）是常见情况，照样生成这一页；相邻的两篇从不共用一页。嵌套在另一篇中的`:::part`会并入外层的篇。

第三个属性`palette="<id>=<hex>[, <id>=<hex>…]"`给篇指定自己的颜色：在篇名页以及其后直到下一篇的每一页上，凡是链接到这些调色板id的设计颜色（页眉、页脚、章首色带、篇名页设计和左页设计），都改用篇给出的值，不再用文档调色板的值。这样，书的各部分不必另做设计，就能给角标、书眉圆点和章首色带换上各自的颜色：`:::part{number="II" title="…" palette="band=#f6c297"}`。正文流的颜色也随之变化。在这些页面上，凡是等于某个被覆盖条目基准值的颜色都改用篇的值，包括：标题，粗体、斜体和引用的颜色，项目符号和列表编号，题注标签和题注色条，表格的文字、线条和填充（表头、表体、斑马纹行以及单元格自己的填充），标注框的背景、边框、色条和标题，以及行内标签的填充、轮廓和文字；因此把`headings.levels[1].color`链接到`band`，每个部分的标题就会用各自的颜色排出。行内色块保留其中写明的颜色。各组之间用逗号、分号或空格分隔，id和颜色之间用`=`或`:`连接，`#`可以省略。篇在结束行之后继续生效：`{partTitle}`、`{partNumber}`和调色板随正文流进入其后的各章，并通过`continuationAfter()`报告的`continuation.part`进入单独排版的章，所以一个部分的第二章在书眉中显示该部分的方式与第一章完全相同。

两个调色板条目可以有相同的基准值，而在篇中取不同的值：篇只覆盖其中一个，或给两者不同的颜色。单看数值，无法判断正文流中的某个颜色来自哪个条目，所以引擎把流中的每个颜色与可能产生它的设置对应起来，取这些设置所链接的值。以下各项分别处理：

- 一个块的文字颜色：文字颜色，粗体、斜体和引用的颜色，列表标记（项目符号或编号）以及编号后的分隔符。假设`bodyText.color`链接到`ink`、`bodyText.boldColor`链接到`accent`，两者都是`#1a1a1a`，那么带`palette="accent=#b8413d"`的篇会给粗体片段换色而保留正文颜色；如果链接到`accent`的是`unorderedLists.color`，它就给项目符号换色而保留列表项的文字；
- 每一级标题，以及每个设了颜色的标题样式；
- 目录行的文字、编号，以及它的页码和副标题；
- 每个标注框样式中的填充（背景、色条、页签）、边框、线条（标记和页签的线条）和文字（标题、图标、标记字形、页签）；
- 每个表格样式、行内标签样式和题注样式的每一种颜色。命名表格样式与`tableStyle`分开，资源类型的题注样式与`captionStyle`分开。单元格自己的填充按它自己的链接处理。

仍有一种情况按数值判断：不同位置的设置给一个块设定同一种颜色。例如`bodyText.color`、`bodyText.blockquote.color`、段落样式的`color`和标注框样式的`body.color`都设定块的文字颜色。当其中两个链接到基准值相同的条目，而篇把它们区分开时，颜色取覆盖值（两个都被覆盖时取最后写的那个）。遇到这种情况，请给这些条目各自不同的基准值。

```ts
const resolved = resolvePartsConfig(config.parts, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => margins从页面补全，bodyStyle取自正文和列表配置

const minimal = stripPartsDefaults(config.parts);
// => 只剩静态默认值时为undefined
```


## 标题样式

`headingStyles`属性声明命名样式，文档用`# Title {style="<id>"}`把它套用到标题上。样式做两件事。一是覆盖标题所在级别的字体样式、设计和编号，即级别条目中除`level`之外的所有字段（字体、字号、颜色、`breakBefore`、`span`、`advancedDesign`、`textTransform`、`hidden`、`numberingTemplate`…）；二是管理标题开启的**区段**：从这个标题到下一个同级或更高级标题（设了`sectionEnd: 'heading'`时为下一个任意级别的标题）之间的页面，采用该样式的书眉、页面几何、正文字体样式和调色板。这样，一本双栏、用阿拉伯数字编号的手册，不需要第二套配置，就能放进风格不同的前辅文：序言排成一个宽栏，用罗马数字页码，配蓝色色带。

```ts
const config: PostextConfig = {
  headingStyles: [
    {
      id: 'front-matter',
      numbered: false,
      breakBefore: { enabled: true, parity: 'odd' },
      span: 'page',

      header: { elements: [/* 页码 | 线条 | `{title}. {subtitle}` */] },
      margins: { left: { value: 50, unit: 'mm' }, right: { value: 17, unit: 'mm' } },
      layout: { layoutType: 'single' },
      bodyStyle: { fontSize: { value: 10.5, unit: 'pt' }, textAlign: 'justify' },
      palette: { band: '#547396' },
    },
  ],
};
```

区段在下一个同级或更高级标题处结束：带样式的标题之后出现不带样式的`#`，就回到文档的书眉和页面几何；带样式的标题则开启它自己的区段。区段为凑奇偶留下的空白页属于该区段，这一点与章标题相同。设了`sectionEnd: 'heading'`后，区段在下一个任意级别的标题处结束，作为全书唯一一级标题的封面正需要这样：

```ts
headingStyles: [
  { id: 'cover', numbered: false, toc: false, header: { elements: [] }, footer: { elements: [] }, sectionEnd: 'heading' },
],
```

```md
# 守灯人 {style="cover"}

## 灯室

…
```

封面页不印书眉，从“灯室”起，各页重新采用文档的页眉和页脚。若取默认值`'level'`，封面的区段会延续到下一个一级标题，而这本书没有下一个一级标题，于是全书没有一页带书眉。

**分页符不能代替标题自身的分页**。样式继承所在级别的`breakBefore`（一级的默认值是`{ enabled: true, parity: 'always-odd' }`），标题无论出现在哪里都会执行它，紧跟在`:::pagebreak`之后也一样。分页符开启新页，标题随后仍然要求落在跨页中它那一侧。使用`parity: 'odd'`时，如果分页符开启的是左页，后面会再跟一张空白页，标题从下一个右页开始。使用`'always-odd'`时还会多出分隔空白页，而分页符不起任何作用，因为标题本来就会开启那一页。如果一个样式要从手动分页开启的那一页开始，比如扉页之后的目录页，就关掉它自己的分页：

```ts
headingStyles: [
  // 从正文安排的位置开始：即前面的`:::pagebreak`开启的那一页。
  { id: 'contents', numbered: false, toc: false, breakBefore: { enabled: false } },
],
```

如果想独占一页又不指定左右，改用`breakBefore: { parity: 'any' }`，并去掉`:::pagebreak`。

**页面属于哪个区段**。书眉和调色板按页选择，而不是按标题选择。一页采用该页上最后一次区段切换之后生效的区段：一个区段结束、另一个区段在同一页开始时（比如词典中两个很短的字母部分），这一页使用第二个区段的书眉和调色板；带样式的区段在页中遇到不带样式的标题而结束时，这一页回到文档的设置。`{chapterTitle}`遵循同样的规则：两章交汇的页面显示后一章的标题。空白页遵循[章标题](/zh/docs/configuration-headings#空白页的归属)的规则：为凑奇偶留的空白页（`blankForParity`）属于其后开启的区段，`'always-odd'` / `'always-even'`断页添加的分隔页（`blankForForce`）属于其前的区段。篇名页会结束当前的区段。

```md
# A {style="letter"}

Aardvark, abacus.

# B {style="letter"}

Babble, badger… (runs on to the next page)
```

两个字母都从第1页开始，所以第1页采用`B`区段的书眉：样式页眉里设置的书口索引标签在这一页上显示“B”，没有哪一页带“A”的标签。如果每个区段都需要自己的标签，就给每个区段单独一页（`breakBefore`）。

下面是排在编号章之后、用字母编号的附录，以及一张目录和PDF书签都列出、但页面上不印标题的献词页：

```ts
headingStyles: [
  { id: 'appendix', numberingTemplate: 'Appendix {1:A}' },
  { id: 'silent', hidden: true, numbered: false },
],
```

```md
# Dedication {style="silent"}

For M., who read every draft.

# Method

…

# Survey instrument {style="appendix" startAt=1}

# Raw data {style="appendix"}
```

一级设为`numberingTemplate: '{1}.'`时，各章印作*1.*、*2.*…，附录印作*Appendix A*和*Appendix B*。献词开启自己的一页（按所在级别的`breakBefore`），只印出它的段落，但仍以*Dedication*出现在`:::toc`、`{chapterTitle}`书眉和PDF书签大纲中；给样式加上`toc: false`，就能把它排除在目录之外。章中间以一级标题排的图版或地图，需要的恰好与献词相反：使用`runningChapter: false`的样式（通常同时设`numbered: false`和`toc: false`），书眉就会保持在被它打断的那一章上。
