# Konfiguration: Schriften, Farben und Ausgabe


## Einheiten und Farben

### Maße

Alle physischen Maße in Postext verwenden den Typ `Dimension` – einen Wert zusammen mit einer Einheit:

```ts
interface Dimension {
  value: number;
  unit: DimensionUnit; // 'cm' | 'mm' | 'in' | 'pt' | 'px' | 'em' | 'rem'
}
```

**Absolute Einheiten** – `cm`, `mm`, `in`, `pt`, `px` – werden mit der konfigurierten DPI-Zahl in Pixel umgerechnet. Bei 300 DPI entspricht `1 cm` etwa 118 px.

**Relative Einheiten** – `em`, `rem` – skalieren mit der aktuellen Schriftgröße. Ein `em` bezieht sich auf die eigene Schriftgröße des Elements, `rem` auf die Schriftgröße des Grundtexts.

### Farben

Farben werden mit einer Hex-Darstellung und einem Zielfarbmodell gespeichert:

```ts
interface ColorValue {
  hex: string;         // '#ff0000', 'transparent', etc.
  model: ColorModel;   // 'hex' | 'rgb' | 'cmyk' | 'hsl'
  cmyk?: CmykPercent;  // The exact process values of a colour authored in CMYK.
  paletteId?: string;  // Der Eintrag von colorPalette, dem sie folgt.
}
```

Das Feld `model` gibt den beabsichtigten Farbraum an. Für die Darstellung im Web sind `'hex'` oder `'rgb'` üblich. Für Druck-Workflows sagt `'cmyk'`, dass die Farbe in CMYK angegeben wurde, und `cmyk` bewahrt ihre Werte: Eine CMYK-Druckausgabe setzt sie unverändert, mit `hex` als ihrer Bildschirmdarstellung (siehe [In CMYK angelegte Farben](#in-cmyk-angelegte-farben)).

Weil Postext auf Ausgabe in Publikationsqualität zielt, wird die Standardfarbe des Grundtexts mit `model: 'cmyk'` (`#000000`) ausgeliefert. Die Farben von Überschriften, Fett, Kursiv und Listen sind standardmäßig an die Palettenfarbe **Main Color** (`#295AA3`, `model: 'hex'`) gekoppelt. Seitenhintergrund und Überlagerungen der Oberfläche (Grundlinienraster, Schnittmarken, Debug-Anzeigen) haben standardmäßig `model: 'hex'`. Überschreiben Sie `color.model` in einem beliebigen Feld, wenn Sie eine andere Bedeutung für den Export brauchen.

### Transparenz

Eine Farbe kann durchscheinend sein. `hex` akzeptiert einen Alphakanal als `#rgba` oder `#rrggbbaa`. Es akzeptiert auch eine Farbe `rgb()` / `rgba()` in der Komma- oder der Leerzeichen-Syntax, mit dem Alphawert als Zahl oder Prozentwert. `transparent` ist vollständig durchsichtig:

```ts
const config: PostextConfig = {
  header: {
    elements: [{
      kind: 'box',
      id: 'veil',
      placement: {
        anchor: { to: 'bleed', edge: 'top-left' },
        size: { width: 'fill', height: { value: 40, unit: 'mm' } },
      },
      style: { backgroundColor: { hex: '#ffffffb3', model: 'hex' } }, // white at 70 %
    }],
  },
  bodyText: { color: { hex: 'rgba(0, 0, 0, 0.85)', model: 'rgb' } },
};
```

Die drei Backends malen sie gleich. Canvas und HTML-Betrachter übernehmen den Wert als CSS-Farbe. Das PDF-Backend setzt die Deckkraft der Farbe als konstantes Alpha, einen `ExtGState` mit `ca` für Flächen und `CA` für Konturen. Das gilt für Text, Linien, Kästen, Tabellenflächen und -rahmen, Chips, Farbfelder und Formeln. Eine durchscheinende Farbe legt sich über alles, was vor ihr gemalt wurde. Ein Kasten in der Kopf- oder Fußzeile wird zuletzt gemalt und verschleiert daher den Text darunter; ein Kasten in einem Auftaktband wird zuerst gemalt und tönt daher die Seite unter dem Text. Wird das PDF in einen anderen Farbraum gezwungen (`pdfGeneration.forceColorSpace` mit `colorSpace: 'cmyk'` oder `'grayscale'`), wird die Farbe umgerechnet und ihr Alpha bleibt erhalten. In der Sandbox schreibt der Deckkraftregler des Farbwählers diese Werte als `#rrggbbaa`, und der Farbwähler liest auch die anderen Formen.


## Eigene Schriften

Postext löst jede Zeichenkette `fontFamily` **sowohl** gegen den Katalog von Google Fonts als auch gegen die Liste `customFonts` des Dokuments auf. Bei Namensgleichheit haben eigene Schriften Vorrang – wenn Sie `customFonts: [{ name: 'Roboto', … }]` deklarieren, verwendet Postext Ihre hochgeladene Datei statt der „Roboto“ von Google Fonts. Eine Familie, die Google Fonts nicht hat, holt die Sandbox von Fontsource. Nach einem generischen Namen (`serif`, `system-ui`) oder einer Schrift, die ein Betriebssystem mitbringt (Arial, Segoe UI, PingFang SC …), fragt sie Fontsource nie: Eine solche Familie wird mit dem gesetzt, was der Rechner des Lesers hat, das Bedienfeld **Schriften** zeigt sie als *Nicht gefunden*, und PDF und SVG-Bilder haben keine Datei von ihr zum Einbetten. Wird das Buch in ihr gesetzt, laden Sie sie als eigene Schrift hoch.

Verwenden Sie eigene Schriften, wenn:

- das Dokument eine Haus- oder lizenzierte Schrift braucht, die es bei Google Fonts nicht gibt;
- die Umgebung die Schrift-CDNs nicht erreicht, also jsDelivr (woher die Sandbox die Dateien von Fontsource bezieht) oder Google Fonts (offline, Intranet, datenschutzsensibel);
- Sie die Schriftdatei privat halten müssen und sie nicht bei einem Dritten hochladen dürfen.

### Konfigurationsschema

```ts
type CustomFontFormat = 'woff2' | 'woff' | 'ttf' | 'otf';
type CustomFontStyle = 'normal' | 'italic';

interface CustomFontVariant {
  weight: number;           // CSS font-weight, 100..900
  style: CustomFontStyle;
  fileId: string;           // opaque id of the binary in out-of-band storage
  format: CustomFontFormat;
  fileName?: string;        // original upload filename (optional, shown in UI)
}

interface CustomFontFamily {
  name: string;             // used anywhere a Google Font family name fits
  variants: CustomFontVariant[];
  redistributable?: boolean; // false: wird hier verwendet, nie aus dem Buch kopiert
  fallback?: string;        // freie Schrift ähnlicher Breite für Schnitte ohne Datei (seit postext 1.42)
}

interface PostextConfig {
  // ...
  customFonts?: CustomFontFamily[];
}
```

Die Binärdatei jeder Variante ist **nicht** in die Konfiguration selbst eingebettet. Die Konfiguration enthält nur Verweise `fileId`; die Bytes liegen getrennt davon. In der Sandbox heißt das IndexedDB (Schlüssel-Wert-Speicher, nur im Browser, privat für das Dokument). Wer Postext in einen anderen Host einbettet, kann `fileId` beliebig auflösen – über einen Server-Endpunkt, einen Service-Worker-Cache, was auch immer –, solange die Bytes den Hauptthread erreichen, bevor `buildDocument` läuft.

### Eigene Schriften in der Sandbox verwalten

Öffnen Sie das Bedienfeld **Schriften** über die linke Aktivitätsleiste (zwischen Ressourcen und Gestaltung). Seine Liste **Schriften in diesem Buch** zeigt jede Familie, die die Gestaltung verwendet, mit ihrer Rolle und ihrer Herkunft: Google Fonts, Fontsource (für eine Familie, die Google Fonts nicht hat), Ihre Datei oder nirgends (*Nicht gefunden*). Unter **Ihre Schriftdateien** gilt für jede Familie:

1. **Schriftfamilie hinzufügen** – legt eine leere Familie an; benennen Sie sie direkt um.
2. **Datei hochladen** – wählen Sie eine Schriftstärke (100–900) und einen Stil (normal / kursiv) und dann eine *oder mehrere* Dateien `.woff2`, `.woff`, `.ttf` oder `.otf`. Jede Datei wird zu einer eigenen Variante, gebunden an das gerade gewählte Paar (Schriftstärke, Stil); der Name der hochgeladenen Datei wird gespeichert und in der Zeile angezeigt, damit Sie Varianten unterscheiden können. Schriftstärke oder Stil einer Variante lassen sich jederzeit über ihre Auswahllisten nachstellen.
3. **Doppelte Varianten sind erlaubt.** Fallen zwei Dateien auf dieselbe Kombination aus Schriftstärke und Stil, werden beide behalten, und die Warnung **Doppelte Schriftvariante** erscheint, damit Sie die Einstellungen der zusätzlichen Dateien eindeutig machen.
4. **Variante löschen** oder **Familie löschen** – entfernt den Eintrag aus der Konfiguration *und* die gespeicherten Bytes aus IndexedDB.

Sobald eine Familie deklariert ist, führt jeder Schriftwähler sie in der Gruppe **Eigene** über der Liste von Google Fonts. Wenn Sie sie auswählen, wird die Familie in jedes Feld für Schriftfamilien eingetragen, auf das Sie sie anwenden.

### Eine Ersatzschrift für eine lizenzierte Familie

Ein Buch kann in einer Schrift gesetzt sein, die ihr Inhaber nicht weitergeben darf. Markieren Sie die Familie mit `redistributable: false`, und eine `.postext`-Datei lässt ihre Dateien weg. Geben Sie in `fallback` eine freie Familie ähnlicher Breite an, bricht die Datei, die ohne sie geöffnet wird, ihre Zeilen ungefähr dort um, wo es die echte Schrift tut, statt mit einer breiteren Ersatzschrift ihre Rahmen zu überfüllen. Schnitte, von denen die Familie keine Datei hat, werden unter dem Namen der lizenzierten Familie in den Schnitten der `fallback`-Familie mit gleicher Stärke und Schriftlage gesetzt, in den Vorschauen, im Layout-Worker, im PDF und auf der Kommandozeile. Eine Familie mit Dateien behält sie; von der `fallback`-Familie nimmt sie nur die Schriftlage, von der sie keine Datei hat, etwa eine Kursive, und die Stärken zwischen ihren eigenen Dateien werden wie bei jeder Familie gewählt. Im Bedienfeld Schriften nimmt **Ersatzschrift** (in der Familie, über ihren Dateien) den Namen auf; ein leeres Feld lässt die Familie, wie sie war. Das PDF eines so gesetzten Buches bettet die freie Schrift ein, das endgültige PDF entsteht also mit den lizenzierten Dateien. Seit postext 1.42. Seit postext 1.43 geht die freie Schrift auch dorthin, wohin die lizenzierte nicht darf: Ein EPUB oder ein HTML-Export, aus der Sandbox oder mit `postext`, enthält die Schnitte der Ersatzschrift unter dem Namen der lizenzierten, ebenso die SVG-Bilder, deren Text in dieser Schrift gesetzt ist; das Lesesystem setzt das Buch also in einer Schrift der Breite, für die seine Zeilen umbrochen wurden. Die eigenen Dateien der Schrift verlassen das Buch nie. Eine Schrift ohne `fallback` oder mit einem Ersatz ohne Datei wird wie bisher ohne Dateien aufgeführt; der EPUB-Tab der Sandbox listet die Schriften, die in einem Ersatz gesetzt sind.

### Verhalten bei der Darstellung

Unter der Haube:

- Ändert sich `customFonts`, wird jede deklarierte Familie automatisch als Einträge `FontFace` in `document.fonts` registriert – so übernehmen der HTML-Betrachter, der Canvas-Viewport (der über `document.fonts` misst) und jeder direkte CSS-Verweis die eigene Schrift, ohne dass der Benutzer zuerst den Schriftwähler öffnen muss.
- Der Layout-Worker erhält dieselben ArrayBuffers über den bestehenden Übertragungsweg für Schriftdaten, sodass die Messung (`buildFontString`, Pretext) genauso funktioniert wie bei einer Familie aus dem Katalog.
- Wird eine Variante geändert oder entfernt, verwirft der Worker die zwischengespeicherte Schrift dieser Familie und registriert sie beim nächsten Build neu, sodass die Vorschauen mit dem aktuellen Variantensatz synchron bleiben.
- **PDF-Export**: Hochgeladene Binärdateien laufen durch dieselbe Pipeline `PdfFontProvider`. Dateien `.woff2` werden dekomprimiert; `.ttf` und `.otf` werden direkt durchgereicht. `.woff` wird mit einer klaren Fehlermeldung abgewiesen (pdf-lib kann rohes WOFF nicht einbetten – laden Sie die Schrift als `.woff2`/`.ttf`/`.otf` erneut hoch). OpenType mit CFF-Konturen (`.otf` mit der Signatur `OTTO`) wird **ohne Teilmengenbildung** eingebettet, weil der CFF-Subsetter von pdf-lib beim `save()` jede Glyphe durchläuft und bei echten Schriften minutenlang hängen kann; der Verzicht auf die Teilmenge tauscht ein etwas größeres PDF gegen gleichmäßige Darstellungszeiten.

### Warnungen zu fehlenden Schriften

Das Bedienfeld **Prüfungen** der Sandbox listet in seiner Gruppe *Schriften* drei Fehlerarten, die eigene Schriften betreffen (alle über denselben Schalter `debug.warnings.missingFont` eingeschaltet, der schon die allgemeine Warnung „nicht geladen“ steuert):

- **Unbekannte Schriftfamilie** – ein `fontFamily` verweist auf einen Namen, den weder Google Fonts noch Fontsource haben und der keine aktuell deklarierte eigene Familie ist. Die Warnung erscheint auch sofort, wenn Sie eine eigene Familie löschen, auf die noch ein Feld `fontFamily` verweist, statt zu warten, bis das DOM es bemerkt.
- **Schriftvariante fehlt** – die Familie existiert, aber das Buch verlangt von ihr eine Schriftstärke und einen Stil, für die es keine hochgeladene Datei gibt: fette Überschriften etwa in einer Familie, die nur den normalen Schnitt hat. Die Warnung nennt die fehlenden Kombinationen. Eine Schräglage, die der `fallback` der Familie liefert, gilt nicht als fehlend.
- **Doppelte Schriftvariante** – zwei oder mehr hochgeladene Dateien teilen sich innerhalb einer Familie dieselbe Kombination aus Schriftstärke und Stil. Bei der Darstellung wird nur eine Datei verwendet; die Warnung erinnert Sie daran, die übrigen Einträge nachzustellen.

Ein Klick auf eine dieser Warnungen öffnet das Bedienfeld Schriften, damit Sie die fehlende Variante hochladen, die Familie wieder hinzufügen oder die Duplikate eindeutig machen können.

Sobald ein Layout existiert, listet das Bedienfeld auch die Warnung **Ersatzschrift im Layout** der Engine (`fontFallback`): eine Schrift, ohne die die Seiten gemessen wurden, weil sie fehlt oder weil der Browser sie aus einer anderen Schriftstärke oder Neigung gezeichnet hat. Eine Familie, die bereits als unbekannt oder als unvollständig gemeldet ist, wird nicht doppelt aufgeführt. Vor dem ersten Layout vertritt eine Prüfung gegen `document.fonts` diese Meldung.

Das Panel listet außerdem **Zeichen aus einer anderen Schrift** (`glyphFallback`): Zeichen, die der Text in einer Schrift ohne passende Glyphe setzt, einmal je Schrift, mit der generischen Familie, aus der sie stammen (`serif`, `sans-serif`, `monospace`), sofern die Prüfung das feststellen kann.

## Ziffernarten

`figureStyle` wählt für die Schrift eines Textstils eine bestimmte Ziffernart, über die OpenType-Features der Schrift: Mediävalziffern im Fließtext, Versalziffern als Tabellenziffern in den Tabellen. Das Feld gibt es in `bodyText`, `paragraphStyles[]`, `headings` und `headings.levels[]`, `headingStyles[]`, `tableStyle` und `tableStyles[]` (Kopf- und Körperzellen gleichermaßen), `captionStyle` (Bezeichnung und Beschreibung, auch im `captionStyle` eines Ressourcentyps) und in den Textelementen eines Designs (Kolumnentitel, Seitenzahlen, die Texte einer Kapitelauftaktseite oder einer Teilseite). In der Sandbox ist es das Feld **Ziffern** im Bedienfeld Gestaltung, neben der Schrift jedes dieser Stile (**Grundtext → Schrift** für den Grundtext).

Ein Paar legt eine Form und eine Breite fest. Eine Schrift ohne das Feature behält ihre eigenen Ziffern; prüfen Sie also, ob die Schrift `onum` oder `lnum` hat, bevor Sie sich darauf verlassen. Eine Familie, von der der Host keine Datei hat, etwa eine nur auf dem System des Lesers installierte Schrift (die Sandbox lädt solche nicht), nimmt keine Ziffernart an: Ihr Text behält die eigenen Ziffern dieser Schrift, in der Schrift selbst. Ein Buch, das Dateien unter diesem Namen hochlädt, bekommt die Ziffern. Die Schnitte, die Google Fonts und Fontsource ausliefern, lassen `onum` und `lnum` oft weg (die latin-Datei von Source Serif 4 behält nur `pnum` und `tnum`); mit einer solchen Datei behält ein Stil, der sie verlangt, die eigenen Ziffern der Schrift. Die vollständigen Dateien der Schriftgießerei haben sie: Laden Sie diese hoch, um Mediäval- oder Versalziffern zu bekommen. Eine generische Familie (`serif`, `sans-serif`) nimmt keine Features an. Ein Wert, der nicht in der Liste steht, wird als unbekannter Einstellungswert gemeldet (`unknownConfigValue`, siehe [Konfigurationswarnungen](#konfigurationswarnungen)) und wie nicht gesetzt gelesen.

```ts
const config: PostextConfig = {
  bodyText: { fontFamily: 'EB Garamond', figureStyle: 'oldstyle' },
  tableStyle: { figureStyle: 'lining-tabular' },
  paragraphStyles: [{ id: 'timetable', figureStyle: 'lining-tabular' }],
  headings: { figureStyle: 'lining' },
};
```

Der Fließtext setzt Jahreszahlen und Seitenzahlen in Mediävalziffern, ebenso die Legenden und die Listen, die die Familie des Grundtexts übernehmen. Die Zellen aller Tabellen und die Absätze im Format `timetable` stellen ihre Stellen in Versalziffern als Tabellenziffern untereinander. Alle Überschriftenebenen setzen Versalziffern in der Familie der Überschriften.

### Welche Ziffern ein Stil bekommt

- Ein Stil, der seine Familie von einem anderen übernimmt, übernimmt auch dessen Ziffern. Absatzformate, Tabellen, Legenden, Listen und der Inhalt von Kästen übernehmen die Familie des Grundtexts, wenn sie keine eigene nennen; `bodyText.figureStyle` reicht also bis zu ihnen allen.
- Ein Stil, der eine eigene `fontFamily` nennt, setzt die Standardziffern dieser Schrift, sofern er nicht auch `figureStyle` setzt.
- Eine Überschriftenebene ohne eigenes `figureStyle` übernimmt `headings.figureStyle`, auch in ihrer eigenen `fontFamily`, wenn sie eine nennt. Das `figureStyle` eines Überschriftenstils gilt für die Familie der Ebene, auf der der Stil verwendet wird.
- Ein Textelement eines Designs nennt eine eigene Familie (`'EB Garamond'` als Standard), daher erreichen die Ziffern des Grundtexts eine Seitenzahl nicht: setzen Sie dort `figureStyle: 'oldstyle'`, damit sie zu einem Text in Mediävalziffern passt.
- `'default'` setzt die eigenen Ziffern der Schrift und hebt geerbte auf: `paragraphStyles: [{ id: 'plain', figureStyle: 'default' }]` nimmt diesem Format die Mediävalziffern des Grundtexts.

### Ziffern in jeder Ausgabe

Der Text wird mit den Features gemessen, sodass seine Zeilen in der Canvas-Vorschau, im HTML, im PDF und im EPUB, mit festem Layout wie umfließend, an denselben Breiten umbrechen.

- **Canvas-Vorschau und Layout-Worker**: Der Browser deklariert die Dateien der Basisfamilie ein zweites Mal, unter dem Namen einer Feature-Familie, mit dem Deskriptor `featureSettings` von `FontFace`. Der Name besteht aus der Familie und ihren Features nach `@` (`EB Garamond@onum`, `EB Garamond@lnum+tnum`) und erscheint in Font-Strings und in manchen Warnungen.
- **HTML und EPUB** (festes Layout und umfließend): die Basisfamilie, mit `font-variant-numeric` (`oldstyle-nums`, `lining-nums tabular-nums`).
- **PDF**: bettet die Dateien der Basisfamilie ein und setzt den Text mit den Features.
- **Kommandozeile**: Skia, die Canvas, mit der `postext` zeichnet, wendet keine Features an. Die Kommandozeile registriert eine Kopie der Schrift, deren `cmap` jedes Zeichen, das die Features ersetzen (die Ziffern), auf die Glyphe abbildet, die sie wählen. Übernommen werden nur einfache Ersetzungen; eine Schrift, die ihre Ziffern über kontextabhängige Ersetzungen erreicht, behält dort ihre eigenen.

## Farbpalette

Mit der Eigenschaft `colorPalette` von `PostextConfig` legen Sie einen wiederverwendbaren Satz benannter Farben an und verweisen von jedem `ColorValue` der Konfiguration darauf. Sie ist die Postext-Entsprechung von CSS Custom Properties oder dem Farbfelder-Bedienfeld von InDesign: Ändern Sie den Paletteneintrag einmal, und jede Farbe, die auf ihn zeigt, ändert sich im ganzen Dokument.

```ts
interface ColorPaletteEntry {
  id: string;       // stable identifier — referenced by ColorValue.paletteId
  name: string;     // human label shown in sandbox UIs
  value: ColorValue;
}
```

### Die Standardpalette

Postext wird mit einer Standardpalette aus einem einzigen Eintrag namens **Main Color** (`id: 'main-color'`, Hex `#295AA3`) ausgeliefert. Mehrere Voreinstellungen – Überschriftenfarbe, Farbe für Fett und Kursiv im Grundtext, Farbe von `:ref`, Farben von Aufzählungszeichen und Nummern – verweisen über `paletteId: 'main-color'` auf diesen Eintrag; ändern Sie dieses eine Farbfeld, färben sich alle Teile des Dokuments um, die es verwenden.

Über drei Exporte können Sie die Standardpalette ansehen, klonen oder mit ihr vergleichen:

```ts
import {
  DEFAULT_COLOR_PALETTE,
  cloneDefaultColorPalette,
  isDefaultColorPalette,
} from 'postext';

// Read-only snapshot of the shipped palette.
DEFAULT_COLOR_PALETTE;
// => [{ id: 'main-color', name: 'Main Color', value: { hex: '#295AA3', model: 'hex' } }]

// Independent copy — mutate this, not DEFAULT_COLOR_PALETTE.
const palette = cloneDefaultColorPalette();

// Detect whether a user has customised the palette at all.
isDefaultColorPalette(palette); // true
```

Eine Palette steht auf der obersten Ebene der Konfiguration:

```ts
const config: PostextConfig = {
  colorPalette: [
    { id: 'ink',    name: 'Ink',    value: { hex: '#0a0a0a', model: 'cmyk' } },
    { id: 'accent', name: 'Accent', value: { hex: '#b8860b', model: 'hex' } },
  ],
  bodyText: { color: { hex: '#000000', model: 'cmyk', paletteId: 'ink' } },
  headings: { color: { hex: '#000000', model: 'hex', paletteId: 'accent' } },
};
```

### Auf einen Paletteneintrag verweisen

Jeder `ColorValue` der Konfiguration kann ein optionales Feld `paletteId` haben, das auf einen Eintrag in `colorPalette` zeigt: Seitenhintergrund, Farben des Grundtexts (einschließlich der Farbe von `:ref`), Überschriftenfarben, Spaltenlinien, Listenfarben, die Farben von Tabellen, Legenden, Chips und Kästen (Kasten, Streifen, Symbol, Markierung, Etikett, Titel, Text), Farben von Schnittmarken und Grundlinienraster, Debug-Anzeigen und jede Farbe einer Gestaltung – die Kolumnentitel, die Überschriftenauftakte und Gestaltungen in der Spalte, Gestaltungen und Kolumnentitel der Überschriftenstile, die Teiltitelseiten und die Teilzeilen des Inhaltsverzeichnisses (Text, Linie, Kastenfläche und -kontur, Buchstabenkontur, Initiale). Ist es vorhanden, haben `hex` / `model` des Paletteneintrags Vorrang vor dem daneben gespeicherten Ersatzwert `hex` / `model`. Der eingebettete Ersatzwert wird nur verwendet, wenn die Palette fehlt, leer ist oder diese ID nicht enthält – nützlich, wenn Sie eine Konfiguration ausliefern, die ein Werkzeug ohne Palettenunterstützung lesen wird.

**Geändert in postext 1.5.** Bis postext 1.4 erreichte die Palette nur eine feste Liste von Einstellungen: Die Farben der Gestaltungen (Kolumnentitel, Auftakte, Überschriftenstile, Teile, Zeilen des Inhaltsverzeichnisses), `bodyText.referenceColor`, die Etikettfarben der Kästen und die Farben für Fett und Kursiv im Kastentext behielten den `hex`, der neben ihrer `paletteId` gespeichert war. Ein Dokument, dessen gespeicherter Wert vom Paletteneintrag abweicht – jedes, das nach der Änderung des Eintrags in der Sandbox bearbeitet wurde, und jedes `:ref`, wenn die Main Color nicht `#295AA3` ist –, zeigt jetzt die Palettenfarbe, wie es die Verknüpfung verlangt. Um eine Farbe so zu behalten, wie sie war, entfernen Sie ihre `paletteId`.

### Wie Paletten angewendet werden

`buildDocument` wendet die Palette an zwei Stellen an, damit verknüpfte Farben sowohl für ausdrücklich angegebene Werte als auch für später ergänzte Voreinstellungen funktionieren:

1. `applyPaletteToConfig(config)` – löst jeden `ColorValue` der rohen Benutzerkonfiguration auf, der eine `paletteId` hat. Nützlich, wenn Sie sehen wollen, was die Engine tatsächlich erhält.
2. `applyPaletteToResolvedConfig(resolved, palette)` – läuft, *nachdem* die Voreinstellungen aufgelöst sind, und schreibt die an die Palette gekoppelten Voreinstellungen (Überschriftenfarbe, Farbe für Fett und Kursiv im Grundtext, Farbe von `:ref`, Listenfarben, die Farben der Standardgestaltungen) passend zur aktiven Palette um.

Beide durchlaufen die gesamte Konfiguration, sodass keine an die Palette gekoppelte Farbe zurückbleibt. Die meisten Farben des Textflusses (Grundtext, Überschriften, Listen, Tabellen, Legenden, Chips, Kasten, Titel und Text des Kastens) kommen als einfache Werte heraus. Jede andere – die Farben der Gestaltungen, die Farbe von `:ref`, die Etiketten der Kästen – übernimmt `hex` / `model` der Palette und **behält ihre `paletteId`**. Über diese Verknüpfung überschreiben das Attribut `palette` eines Teils und das `palette` eines Überschriftenstils die Farben auf ihren Seiten (siehe [Teile](/de/docs/configuration-styles#teile)); sie muss daher erhalten bleiben. `htmlViewer.overrides` bleibt, wie es geschrieben ist: Der HTML-Betrachter führt es zuerst zusammen, und eine Palette darin gilt dann für alles, auch für die Gestaltungen.

Sie müssen diese Funktionen selten selbst aufrufen, aber beide werden exportiert, damit Sie sie untersuchen oder wiederverwenden können:

```ts
import {
  applyPaletteToConfig,
  applyPaletteToResolvedConfig,
  resolveColorValue,
} from 'postext';

const flat = applyPaletteToConfig(config);
// Every ColorValue with a paletteId in the raw config now carries the
// palette entry's hex/model (a design colour keeps its paletteId).

// `applyPaletteToResolvedConfig` is typically handled by buildDocument; use it
// directly if you build a ResolvedConfig yourself and want the palette applied.
```

`resolveColorValue(value, palette, fallback)` ist die Variante für einen einzelnen Wert, praktisch, wenn Sie Konfigurationen imperativ zusammensetzen und jeweils eine Farbe auflösen müssen.

### Die Palette bearbeiten

Eine Farbe, deren `paletteId` auf keinen Eintrag verweist, erscheint mit ihrem gespeicherten `hex` / `model`, der älter sein kann als die Farbe, die der Eintrag ihr gab. Schreiben Sie daher vor dem Entfernen eines Eintrags jeden damit verknüpften `ColorValue` als einfache Farbe mit dem aktuellen Wert des Eintrags um. Der Abschnitt *Palette* der Sandbox (**Gestaltung → Farben**) tut das, wenn Sie einen Eintrag löschen, wo immer die Farbe steht (Gestaltungen und Etiketten der Kästen eingeschlossen), und seine Bestätigung listet jede Einstellung auf, die den Eintrag verwendet: mit Namen oder mit ihrem Pfad in der Konfiguration (`header.elements[2].color`).

## PDF-Erzeugung (Konfiguration)

Die Eigenschaft `pdfGeneration` steuert, wie das PDF-Backend das fertige Dokument ausgibt. Diese Einstellungen liest das Paket `postext-pdf` beim Export; Canvas- und HTML-Betrachter ignorieren sie.

`buildDocument` übernimmt sie in den VDT als `doc.config.pdfGeneration`, und `renderToPdf` nimmt jede Einstellung von der ersten Stelle, die sie angibt:

1. aus seinen eigenen Optionen (`outlines`, `accessible`, `colorSpace`);
2. aus `pdfGeneration` des ersten Dokuments, das es rendert (in einem Buch gelten die Einstellungen des ersten Kapitels für die ganze Datei);
3. aus den Voreinstellungen: Lesezeichen und Tagging an, RGB-Farbe.

`renderToPdf(doc, { fontProvider })` folgt also der Konfiguration, und eine an `renderToPdf` übergebene Option gewinnt nur für diese eine Einstellung. `forceColorSpace` und `colorSpace` stehen zusammen für die Option `colorSpace`: Das `colorSpace` der Konfiguration gilt, solange `forceColorSpace` an ist, und das PDF ist RGB, solange es aus ist. Frühere Versionen von `postext-pdf` lasen nur die Optionen; eine Konfiguration, die `pdfGeneration` setzt, ändert jetzt das PDF eines Aufrufers, der keine Optionen übergibt.

```ts
type PdfColorSpace = 'rgb' | 'cmyk' | 'grayscale';

interface PdfGenerationConfig {
  outlines?: boolean;          // Emit PDF bookmarks from the heading tree.
  forceColorSpace?: boolean;   // Convert every colour to `colorSpace`.
  colorSpace?: PdfColorSpace;  // Target space used when `forceColorSpace` is true.
  accessible?: boolean;        // Tagged, PDF/UA-oriented output (structure tree, alt text, language).
}
```

### PDF/X-1a und PDF/X-4

Beide Standards schreiben:

- den Output Intent (`GTS_PDFX`), der die Druckbedingung nennt und das Zielprofil einbettet;
- die Kennung im Info-Dictionary (`GTS_PDFXVersion`, `/Trapped /False`, Titel und Datumsangaben) und in den XMP-Metadaten (`pdfxid:GTSPDFXVersion`, die Dokument- und Versions-IDs), zusammengeführt mit der PDF/UA-Kennung, wenn die Datei getaggt ist;
- auf jeder Seite eine TrimBox und eine BleedBox (die ganze Seite, wenn es keine Schnittlinien gibt);
- die `/ID` im Trailer;
- jede Farbe in DeviceCMYK (oder Grau) über das Profil und die Schnittmarken in Passerfarbe;
- keine Link-Annotationen: Eine Datei für die Druckmaschine enthält keine innerhalb ihrer BleedBox, daher entfallen die Links des Bildschirm-PDFs (die Lesezeichen bleiben).

PDF/X-1a:2003 ist PDF 1.4 ohne Objektströme und kennt keine Transparenz: Eine durchscheinende Farbe wird so gesetzt, wie sie auf dem Papier drucken würde, das Alpha eines Bildes wird auf Weiß verrechnet, und das Debug-Seitennegativ entfällt (mit der Warnung `pageNegativeIgnored`). PDF/X-4 ist PDF 1.6: Die Transparenz bleibt, jede Seite erhält eine Transparenzgruppe, die in CMYK verrechnet, und RGB-Bilder, die `convertImages: false` beibehält, werden über `/DefaultRGB` als sRGB gekennzeichnet.

Eine PDF-Druckvorlage (`svg.pdfFileId`) wird unverändert eingebettet, ihre Farben, Schriften und Transparenz sind also ihre eigenen; der Preflight meldet, was sie mitbringt.

`preflightDocument(doc, options)` führt die Prüfungen an einem gesetzten Dokument aus und gibt eine Liste von Befunden zurück, jeder mit einer `kind`, einer `severity` (`'critical'`, `'warning'` oder `'info'`), dem buchweiten `pageIndex`, dem betroffenen `rect` (Seitenpixel) und, wenn das Element einen hat, seinem Quellbereich. Die Arten sind `lowImageResolution`, `declaredPixelsMismatch`, `rgbImage`, `thinRule`, `smallProcessText`, `inkLimit`, `safeZone` und `nearTrim`. Ohne `transform` zählt eine neutrale Farbe als eine Druckfarbe und jede andere als drei, und der Farbauftrag wird nicht geprüft; mit einem sind Zählung und Farbauftrag exakt. Die Auflösung eines Bildes wird aus den Pixeln berechnet, die seine Ressource angibt, oder aus denen der Datei selbst, wenn `imageSize(fileId)` sie liefert (`bitmapInfo` auf den Bytes oder das dekodierte Bild): Eine Angabe, die mehr als ein Pixel von der Datei abweicht, wird einmal als `declaredPixelsMismatch` gemeldet, als Warnung, wenn sie mehr Pixel behauptet, als die Datei hat. `placedImageResolutions(doc, { resources, imageSize })` listet jede platzierte Bitmap mit ihrer effektiven ppi-Zahl auf, ob der Preflight an ist oder nicht. Die Beschriftungen einer Abbildung zählen für `smallProcessText`, `inkLimit` und `safeZone` als Text.

```ts
import { bitmapInfo, outputTransform, parseIccProfile, preflightDocument, resolvePrintConfig } from 'postext';
import { inspectPrintMaster } from 'postext-pdf';

const print = resolvePrintConfig(config.print);
const transform = outputTransform(parseIccProfile(fogra51Bytes), { intent: print.renderingIntent });
const issues = preflightDocument(doc, {
  print,
  transform,
  resources,                                    // pixel sizes of the bitmaps
  imageSize: (fileId) => bitmapInfo(bytesOf(fileId)),  // the files' real pixels
  imageColor: (fileId) => colourOf(fileId),     // 'rgb' | 'cmyk' | 'gray', from the file
});
if (issues.some((i) => i.severity === 'critical')) process.exit(1);

const master = await inspectPrintMaster(masterBytes);
// => { nonEmbeddedFonts: ['Helvetica'], rgb: true, transparency: false }
```

### Druckvorschau

Eine Canvas-Seite lässt sich so malen, wie sie drucken wird. `createPrintPreview(transform, print, { paper, dpi, grayscale })` baut den Softproof einer Einrichtung: Jedes Pixel wird über das Profil separiert (neutrale Farben nur in K, wie im PDF) und auf dem Bildschirm zurückgezeigt, auf dem eigenen Weiß des Papiers, wenn `paper` `true` ist; schwarze Flächen, die groß genug für Tiefschwarz sind, erscheinen als Tiefschwarz. Mit `grayscale` ist der Proof ein Graustufendruck – ein in Graustufen gezwungenes PDF druckt die Luminanz jeder Farbe allein in Schwarz, ohne Tiefschwarz. Übergeben Sie ihn `renderPageToCanvas` als `printPreview`. Für eine Arbeitsansicht statt eines Proofs fügt `guides` die Linien für Endformat, Anschnitt und Sicherheitsabstand hinzu, und `marksFor` umrandet Bereiche einer Seite (die `rect`s des Preflights); die Sandbox lässt beides weg, ihre Vorschau zeigt also nur den Druck. `postext-folio` nimmt dasselbe Objekt als `printPreview`; geben Sie dem Buch bei `paper: true` währenddessen einen neutralen Papierton (`folio.paper.shade`), sonst wird das Papier doppelt getönt.

```ts
import { createPrintPreview, renderPageToCanvas } from 'postext';

const preview = createPrintPreview(transform, print, { paper: true, dpi: doc.config.page.dpi });
renderPageToCanvas(page, doc, canvas, {
  printPreview: { ...preview, guides: { safeZonePx: 59 }, marksFor: () => issues.map((i) => i.rect!).filter(Boolean) },
});
```

### Farb-Engine

Das Farbmanagement, das postext verwendet, wird für Ihre eigenen Werkzeuge exportiert. Es liest ICC-Profile der Versionen 2 und 4 (Matrix/TRC und die Lookup-Tabellen `mft1`, `mft2`, `mAB`, `mBA`) in reinem TypeScript, ohne WebAssembly.

- `parseIccProfile(bytes)` liest ein Profil; `deviceChannels(profile)` gibt seine Kanalzahl an.
- `outputTransform(profile, { intent, blackPointCompensation, preserveNeutrals })` gibt `fromRgb(r, g, b)` (sRGB 0..1 → CMYK 0..1), `toLab(cmyk, paper?)` und `proof(cmyk, paper?)` (CMYK → Bildschirm-sRGB) zurück.
- `cmykToLab`, `labToCmyk`, `srgbToLab`, `labToSrgb`, `deltaE` und `totalAreaCoverage` sind die einzelnen Umrechnungen; `buildRgbLut` / `sampleRgbLut` erzeugen und lesen dichte Lookup-Tabellen für die Arbeit an Pixeln.
- `OUTPUT_PROFILES`, `outputProfileInfo(id)` und `loadOutputProfile(id, baseUrl?)` liefern den Katalog; `srgbProfileBytes()` schreibt das sRGB-Profil, mit dem PDF/X-4 RGB kennzeichnet; `authoredCmykColors(config)` listet die Farben auf, die eine Konfiguration in CMYK angelegt hat.

Resolver und Stripper entsprechen den anderen Abschnitten: `resolvePrintConfig`, `stripPrintDefaults` und `profileInkLimit(config)` (der Grenzwert des Profils, das eine Konfiguration nennt, vor jeder Überschreibung durch `inkLimit`), mit `DEFAULT_PRINT_CONFIG`, `DEFAULT_PRINT_BLACK_CONFIG`, `DEFAULT_PRINT_PREFLIGHT_CONFIG` und `DEFAULT_RICH_BLACK`.

### Akzeptierte Paare

Eine Portierung behält die Palette der Vorlage, und manche ihrer Paare liegen unter der Schwelle: ein heller Ton hinter dem Text eines Kastens, eine Markenfarbe im Kolumnentitel. `allow` akzeptiert sie, ohne die Prüfung abzuschalten (seit postext 1.52). Ein Eintrag nennt die Textfarbe `fg` und den Grund `bg` (hexadezimal, wie die Konfiguration sie schreibt oder wie sie gemalt werden) oder einen `style`: die Id eines Kastenstils (`calloutStyles` oder der `style` eines Rahmens einer komponierten Seite), eines Absatz-, Überschriften-, Chip- oder Bildbeschriftungsstils. Jedes Feld, das ein Eintrag angibt, muss passen, also akzeptiert `{ style: 'note', fg: '#7a8a99' }` dieses Grau nur in `note`-Kästen. Ein Eintrag ohne eines der drei Felder passt auf nichts.

```ts
contrast: {
  allow: [
    { fg: '#b7820f', bg: '#ffffff', reason: 'Der Ocker des Verlags für die Kolumnentitel' },
    { style: 'randnotiz', reason: 'Die Vorlage setzt ihre Randnotizen in hellem Grau' },
  ],
}
```

Ein akzeptiertes Paar wird weiter gemeldet: Jeder Befund, auf den es passt, trägt `accepted` (den `reason` des Eintrags mit seinem `fg`, `bg` und `style`), und die akzeptierten Befunde stehen hinter den anderen. Der Sandbox führt sie in den Prüfungen unter Akzeptierte Kontrastpaare mit dem Grund auf und zählt sie nicht mit; `postext check` gibt sie als Hinweise aus, an denen `--strict` nicht scheitert. Dieselben Farben außerhalb dessen, was der Eintrag nennt, bleiben eine Warnung.

### Bildschirm und Druck

Postext setzt dieselben Seiten für einen Bildschirm und für eine Druckmaschine, und eine Farbe wirkt auf beiden nicht gleich.

- **Bildschirm** ist das WCAG-2-Kontrastverhältnis der sRGB-Farben, `(L1 + 0.05) / (L2 + 0.05)` über ihre relativen Luminanzen: das, was Canvas, HTML-Betrachter, ein EPUB und ein RGB-PDF zeigen.
- **Druck** ist dieselbe Formel über die Luminanz, die jede Farbe auf Papier hat. Die Farbe wird über das Ausgabeprofil des Auftrags separiert (eine in CMYK angelegte behält ihre Werte), die Separation wird über das Profil zurückgelesen, und ihre Luminanz wird relativ zum unbedruckten Papier genommen, das das Weiß einer gedruckten Seite ist, so wie das Weiß des Displays das Weiß eines Bildschirms ist. Druckfarbe ist nie ein vollkommenes Schwarz: Volles Schwarz auf Weiß erreicht etwa 14:1 auf gestrichenem Papier (FOGRA39, FOGRA51), 8:1 auf ungestrichenem Papier (FOGRA47, FOGRA52) und 5:1 auf Zeitungspapier (IFRA26, SNAP), wo ein Bildschirm 21:1 liefert. Ein Grau, das am Bildschirm besteht, kann auf Papier durchfallen: `#767676` auf Weiß hat am Bildschirm 4,54:1 und auf gestrichenem Papier etwa 3,3:1.

Das Druckverhältnis braucht die Transformation des Ausgabeprofils (`options.transform`, gebaut mit `outputTransform`). Ohne sie wird für den Druck nur der negative Text geprüft.

### Negativer Text

Heller Text, der aus einem bedruckten Untergrund ausgespart ist, läuft im Druck zu, wenn er klein ist oder seine Striche dünn sind: Die Farbe des Untergrunds breitet sich in die Buchstaben aus, und ein Untergrund aus mehreren Druckfarben hängt zudem davon ab, dass die Platten im Passer bleiben. Das Verhältnis zeigt das nicht, denn Weiß auf Dunkelblau liegt über 10:1. Die Druckprüfung meldet solchen Text eigens (`reversedText`), wenn er unter `minSize` liegt oder unter `minFineSize`, während er kursiv ist oder eine Schriftstärke von `lightWeight` oder weniger hat. Jeder Befund nennt, aus wie vielen der vier Druckfarben der Untergrund aufgebaut ist.

### Was geprüft wird

Die Prüfung liest die Zeilen jedes Blocks mit ihren Inline-Farben (fett, kursiv, Verweise, Chips), Listenzeichen, Initialen, Legenden, Anmerkungen und Tabellenzellen sowie den Text der Gestaltungsfelder: Kolumnentitel, Auftakte, Überschriftengestaltungen, Kastentitel. Der Untergrund ist die oberste Fläche unter dem Text: ein Gestaltungskasten, ein Kasten, ein Legendenbalken, eine Tabellenzelle, ein Chip, sonst die Seitenfarbe (`page.backgroundColor` oder das Papier, das die Palette eines Teils seinen Seiten gibt). Eine durchscheinende Farbe wird mit dem verrechnet, was unter ihr liegt. Text über einem Bild wird übersprungen, weil sein Untergrund nicht einfarbig ist, ebenso Comic-Lettering, Ruby-Lesungen und Formeln. Die Wörter der Beschriftungen einer Abbildung werden auf ihrer Unterlage gelesen, sonst innerhalb ihres Lichthofs; Beschriftungen direkt auf dem Bild werden übergangen wie jeder Text über einem Bild.

Auf einer zusammengesetzten Seite folgt die Prüfung der Reihenfolge, in der die Seite gemalt wird: die Rahmen nach Ebene, die `decoration` der Vorlage auf Ebene 0. Rahmentext steht auf dem eigenen Kasten des Rahmens, wenn dessen Stil einen malt, sonst auf dem Dekorationskasten darunter (ein Bild der Dekoration nimmt ihn aus der Prüfung, wie jedes Bild), sonst auf der Seitenfarbe. Weiße Schrift auf einem farbigen Etikett der Dekoration wird also an diesem Etikett gemessen. Ein gedrehter oder skalierter Rahmen wird erst auf das Blatt gebracht, dann wird sein Grund gelesen; der Text der Dekoration selbst wird ebenso geprüft. Seit postext 1.37.

### Die Prüfung ausführen

`contrastDocument(doc, options)` gibt die Befunde eines gesetzten Dokuments zurück, das niedrigste Verhältnis zuerst. Jeder hat den buchweiten `pageIndex`, das `rect` auf dem Blatt (Seitenpixel) und den Quellbereich seines ersten Vorkommens, die beiden Farben, wie sie gemalt sind (`color`, `background`), die kleinste `sizePt`, in der er gesetzt ist, mit `weight` und `italic`, eine `role` (`'body'`, `'heading'`, `'caption'`, `'table'`, `'runningHead'`, `'design'`, `'chip'`, `'marker'` oder `'label'`, die Wörter der Beschriftungen einer Abbildung), den `text` des ersten Abschnitts und die Anzahl `count` der so gesetzten Abschnitte. Ein Paar wird je Schwellenwert einmal gemeldet, wie viele Zeilen es auch verwenden.

- `lowContrast` ergänzt `level`, `large`, `required`, das Verhältnis in jeder geprüften Wiedergabe (`screen`, `print`) und `failing`, die Wiedergaben unter `required`.
- `reversedText` ergänzt `reasons` (`'small'`, `'italic'`, `'light'`), `minimumPt` und `inks`.

Die Optionen sind `contrast` (die aufgelösten Einstellungen, wenn es nicht die des Dokuments sind), `media` (die Wiedergaben, unabhängig von `mode`) und `transform`.

```ts
import { contrastDocument, outputTransform, parseIccProfile } from 'postext';

const transform = outputTransform(parseIccProfile(fogra51Bytes));
for (const issue of contrastDocument(doc, { transform })) {
  if (issue.kind === 'lowContrast') {
    console.log(`${issue.color} on ${issue.background}: ${issue.screen}:1, ${issue.level} asks for ${issue.required}:1`);
  }
}
```

`contrastPairs(doc, options)` gibt jedes Paar aus Text und Untergrund zurück, das das Dokument setzt, ob es besteht oder nicht, mit seinem Verhältnis `screen`, seinem Verhältnis `print`, wenn die Transformation übergeben wird, dem geforderten Verhältnis `required` und den Farben, wie die Konfiguration sie schreibt (`textColor`, `groundColor`): das, was ein Gestaltungswerkzeug neben einem Farbfeld anzeigt. Sie läuft unabhängig von `enabled`.

Die Maße werden für Ihre eigenen Werkzeuge exportiert:

- `contrastRatio(a, b)` und `relativeLuminance(color)` liefern das WCAG-2-Verhältnis und die Luminanz von sRGB-Farben.
- `isLargeText(sizePt, weight)` und `contrastThreshold(level, large)` liefern den Schwellenwert einer Größe und Schriftstärke.
- `blendColors(top, under)` liefert eine durchscheinende Farbe über einer anderen als `#rrggbb`.
- `printContrastRatio(a, b, context)`, `printLuminance(color, context)` und `printSeparation(color, context)` liefern dasselbe auf Papier. Der Kontext enthält die `transform` und als `authored` das Ergebnis von `authoredCmykColors(config)`.
- `contrastMedia(doc.config, contrast)` liefert die Wiedergaben, zu denen `mode` für ein Dokument aufgelöst wird.

Resolver und Stripper entsprechen den anderen Abschnitten: `resolveContrastConfig` und `stripContrastDefaults`, mit `DEFAULT_CONTRAST_CONFIG`, `DEFAULT_CONTRAST_REVERSED_TEXT_CONFIG`, `CONTRAST_LEVELS` und `CONTRAST_MODES`.


## Inhaltsprüfung (Konfiguration)

Die Eigenschaft `checks` fasst die Prüfungen zusammen, die die Konfiguration selbst lesen. Bisher ist es eine, `contentInConfig`: Sie warnt, wenn eine Gestaltung den Text des Buches enthält. Ein Kolumnentitel, die Gestaltung einer Überschrift, eine Teiltitelseite und die Zeile eines Teils im Inhaltsverzeichnis sind Form: Sie enthalten Platzhalter (`{chapterTitle}`, `{titleText}`, `{number}`) und höchstens ein oder zwei eigene Wörter, etwa *Kapitel* vor `{chapterNumber}`. Text, der zum Buch gehört, steht im Markdown, wo ihn das Inhaltsverzeichnis, die Suche, Übersetzungen, das getaggte PDF und das EPUB sehen. Der Satz liest die Prüfung nicht, eine Änderung verschiebt also keine Zeile.

interface ChecksConfig {
  contentInConfig?: {
    enabled?: boolean;
    allow?: string[];
    maxWords?: number;
    maxChars?: number;
  };
}

### Wie ein Gestaltungstext ausgewertet wird

- Sein wörtlicher Text ist sein `content` ohne jeden Platzhalter (`{name}`, `{attr.key}`, `{firstMark.key}`), die Maskierungen `{{` und `}}` als Klammern und `\n` als Zeilenumbruch gelesen.
- Ein Text ohne Buchstaben oder Ziffern (eine Reihe Füllpunkte, ein Ornament, ein `·`) ist nie Inhalt.
- Ein Wort ist, was zwischen Leerzeichen steht und einen Buchstaben oder eine Ziffer enthält: Ein einzelnes `·` oder `|` ist kein Wort, eine Adresse wie `postext.dev` ist eines.
- Zuerst werden die Wendungen aus `allow` herausgenommen, ebenso `title`, `subtitle`, `author` und `publisher` aus den Metadaten des Dokuments (seinem Frontmatter), die ein Kolumnentitel oft wiederholt.
- Was übrig bleibt, ist Inhalt, wenn es mehr als `maxWords` Wörter oder mehr als `maxChars` Buchstaben und Ziffern hat.

Gelesen werden alle Gestaltungsfelder: `header`, `footer`, das `advancedDesign.slot` jeder Überschriftenebene, `advancedDesign.slot`, `header` und `footer` jedes Überschriftenstils, `parts.design`, `parts.versoDesign`, `toc.parts.design` und dasselbe in `htmlViewer.overrides`. `configDesignSlots(config)` zählt sie mit ihren Pfaden auf, `designTextLiteral(content)` gibt den wörtlichen Text einer Vorlage zurück.

### Die Warnung

`collectConfigWarnings` (und `VDTDocument.configWarnings`) gibt eine `contentInConfig`-Warnung je Einstellung mit Inhalt: ein Überschriftenstil (seine `id` in `ownerId`), eine Überschriftenebene, die Kopfzeile, die Gestaltung der Teile. `path` nennt die Einstellung, `count` die betroffenen Gestaltungstexte, `chars` ihre Buchstaben und Ziffern, `elements` den Pfad jedes Textes (die ersten 20) und `value` den Anfang des ersten (höchstens 40 Zeichen). Übergeben Sie die Metadaten des Dokuments als zweites Argument, um seinen Titel und Autor zu erlauben; ein Satzlauf tut das selbst.

```js
import { collectConfigWarnings } from 'postext';

collectConfigWarnings(config, { metadata: { title: 'A Year of Weather' } });
// [{ kind: 'contentInConfig', path: 'headingStyles[3]', ownerId: 'lesson-4',
//    value: 'Look at the picture and answer the questi…', used: '',
//    count: 30, chars: 1017, elements: ['headingStyles[3].header.elements[2]', …] }]
```

**Abhilfe:** Verschieben Sie den Text ins Markdown, als Überschrift, Kasten oder Absatz des Kapitels, zu dem er gehört, und lassen Sie in der Gestaltung nur Platzhalter. Ein Wert, der sich je Kapitel ändert, kann in der Überschriftenzeile stehen und mit `{attr.key}` gelesen werden: `# Karten {kicker="Lektion 4"}` und `{attr.kicker}` in der Gestaltung. Eine Wendung, die Form ist, etwa der Verlagsname in einem Kolumnentitel, gehört in `allow`.

Die Sandbox zeigt die Warnung im Bedienfeld **Prüfungen** und führt die Prüfung unter **Gestaltung → Erweitert → Inhalt in der Konfiguration**; `postext check` gibt sie aus.


## Folio-Betrachter (Konfiguration)

Die Eigenschaft `folio` legt fest, wie der Folio-Betrachter (`postext-folio`) das gedruckte Buch in 3D zeigt: den Blickwinkel, das Papier, die Bindung, die Unterlage, auf der das Buch liegt, und das Licht. Das Layout ignoriert sie, ebenso die Ausgaben Canvas, HTML und PDF. `buildDocument` übernimmt die aufgelösten Einstellungen in den VDT als `doc.config.folio`, wenn die Konfiguration welche setzt; ein Dokument ohne sie behält also seinen Layout-Hash.

Eine Seite in einem Zeitungsformat (`page.sizePreset` `'broadsheet'`, `'berliner'`, `'tabloid'` oder `'compact'`) wird als Zeitung gezeigt, wenn die Konfiguration weder Sorte noch Bindung angibt: Papier `newsprint` und Bindung `folded` (seit postext 1.18). Eine Sorte oder Bindung, die die Konfiguration angibt, bleibt erhalten; `paper: { type: 'uncoated' }` druckt ein Tabloid also auf Offsetpapier. Papierfelder, die ohne Sorte gesetzt sind (ein `grammage`, ein `shade`), gelten für das Zeitungspapier. Resolver und Stripper nehmen das Format als zweites Argument, und `folioForTrim(folio, sizePreset)` schreibt die beiden Standardwerte in die Konfiguration:

```ts
resolveFolioConfig({ tilt: 30 }, 'tabloid');
// => { tilt: 30, paper: { type: 'newsprint', grammage: 48, bulk: 1.5, … }, binding: { type: 'folded', coverMaterial: 'paper', … }, … }

stripFolioDefaults({ paper: { type: 'newsprint' }, binding: { type: 'folded' } }, 'tabloid');
// => undefined
```

Die Farben folgen Palettenverknüpfungen wie jede andere Farbe der Konfiguration (`paletteId`). Resolver und Stripper entsprechen den anderen Abschnitten; der Stripper entfernt Papierwerte, die denen der gewählten Sorte gleichen:

```ts
import { FOLIO_PAPER_STOCKS, DEFAULT_FOLIO_CONFIG, resolveFolioConfig, stripFolioDefaults } from 'postext';

resolveFolioConfig({ paper: { type: 'bible' } }).paper;
// => { type: 'bible', grammage: 40, bulk: 1.1, finish: 'uncoated', texture: 'vellum', textureStrength: 1, shade: { hex: '#f9f6ee', … }, showThrough: true }

stripFolioDefaults({ paper: { type: 'bible', grammage: 40 } });
// => { paper: { type: 'bible' } }
```

In der Sandbox bilden diese Einstellungen die Gruppe **Folio** des Bedienfelds Gestaltung (**Gestaltung → Folio → Folio-Betrachter (3D)**), und der Tab Folio zeigt Änderungen sofort, ohne das Buch neu zu setzen. Zum Betrachter selbst siehe [Ein 3D-Buch](/de/docs/configuration-html-folio-epub#ein-3d-buch-postext-folio), und zu einer Seitenfolge auf einer anderen Papiersorte [Dokumentformat › `:::paper`](/de/docs/document-format-directives#paper).

### Zu lockere Zeilen im eigenen Canvas

Die Engine exportiert die Hervorhebung zu lockerer Zeilen als zwei Hilfsfunktionen für eine Seite, die Sie selbst malen:

```ts
import { buildDocument, renderPageToCanvas, drawLooseLines, findLooseLines } from 'postext';

const doc = buildDocument(content, config);
const canvas = document.querySelector('canvas')!;
renderPageToCanvas(doc.pages[0], doc, canvas, { scale: 0.5 });
drawLooseLines(canvas.getContext('2d')!, doc.pages[0], doc, { threshold: 2.5 });

// The same lines as data: a report, an SVG overlay, a count per page.
for (const { ratio, line, block } of findLooseLines(doc, { threshold: 2.5 })) {
  console.log(`page ${block.pageIndex + 1}: ${ratio.toFixed(2)}× — ${line.text}`);
}
```

- **`findLooseLines(doc, { threshold?, pageIndex? })`** gibt in Lesereihenfolge jede Zeile im Blocksatz zurück, deren Wortabstand `threshold` übersteigt: `{ block, line, ratio, x, y, width, height }`. `ratio` ist `lineWordSpacing(line)`: der Abstand so, wie `minWordSpacing` und `maxWordSpacing` ihn begrenzen (`justifiedSpaceLimitRatio`, wenn die Zeile Zwischenräume eines anderen Schnitts enthält, sonst `justifiedSpaceRatio`); eine Zeile, die an der Grenze gesetzt ist und einen fetten Zwischenraum enthält, wird bei einem Schwellenwert gleich `maxWordSpacing` also nicht gemeldet. Das Rechteck in Seitenpixeln ist der Streifen, den die Hervorhebung abdeckt: die volle Breite des Blocks über die Zeile hinweg. Es sind die Zeilen, die die Sandbox hervorhebt und in ihrem Bedienfeld Prüfungen als `looseLine` meldet.
- **`drawLooseLines(ctx, page, doc, { threshold?, color? })`** füllt diese Streifen für eine Seite und gibt die gemalten Zeilen zurück. Sie zeichnet in Seitenpixeln unter der aktuellen Transformation des Kontexts; rufen Sie sie also direkt nach `renderPage` oder `renderPageToCanvas` auf demselben Canvas auf: Beide hinterlassen den Kontext auf die Seite skaliert. `color` ist ein beliebiger Füllstil des Canvas.
- **Standardwerte.** Beide Hilfsfunktionen verwenden den Standardschwellenwert (3) und die Standardfarbe (`#ff000040`), nicht `debug.looseLineHighlight` des Dokuments: Diese Einstellung gehört der Sandbox. Um einer Konfiguration zu folgen, übergeben Sie `resolveDebugConfig(config.debug).looseLineHighlight.threshold` und `.color.hex`.

### Konfigurationswarnungen

Diese Fehler in der Konfiguration selbst bleiben nie stumm, und kein Schalter blendet sie aus, außer dem im letzten Punkt. Die Engine scheitert an keinem davon; sie setzt einen Wert ein oder lässt die Einstellung weg und meldet das:

- **Unbekanntes Zahlenformat** – ein `numberFormat` einer geordneten Liste, ein `page.pageNumbering.format` oder ein `counterFormat` eines Ressourcentyps, das keiner der [Schreibweisen der Nummernformate](/de/docs/configuration-page-layout#schreibweisen-der-nummernformate) entspricht. Es wird dezimal nummeriert.
- **Schriftliste in einer Schriftfamilie** – ein `fontFamily` (oder ein beliebiges `…FontFamily`), das eine CSS-Schriftliste enthält. Der Text wird in der ersten Familie der Liste gesetzt (siehe [Eine Familie pro `fontFamily`](/de/docs/configuration-text#eine-familie-pro-fontfamily)).
- **Seitenspalte ohne Platz** – ein `sideColumnPercent` eines Layouts `'oneAndHalf'` (des Dokuments oder im eigenen `layout` eines Überschriftenstils), das einer der Spalten weniger als 1 % der Satzspiegelbreite ließe oder keine Zahl ist. Die Spalten werden beim nächstgelegenen Wert geteilt, den beide annehmen können, und `used` nennt ihn (`sideColumnPercentClamped`; siehe das [Layout `'oneAndHalf'`](/de/docs/configuration-page-layout#layout-typen)).
- **Spaltenzahl außerhalb des Bereichs** – ein `columnCount` eines Layouts `'multiple'` (des Dokuments oder im eigenen `layout` eines Überschriftenstils), das keine ganze Zahl von 3 bis 8 ist. Die Seite wird in die nächstgelegene gültige Anzahl geteilt (3 für einen Wert, der keine Zahl ist), und `used` nennt sie (`columnCountClamped`; siehe das [Layout `'multiple'`](/de/docs/configuration-page-layout#layout-typen)).
- **Zeichenraster zu groß** – ein `cjk.grid` mit mehr Zeichen pro Zeile oder Zeilen pro Seite, als die Ränder Platz lassen. Das Raster wird mit dem Höchstwert gesetzt, der passt, und `used` nennt die Zahl (`cjkGridClamped`; siehe [Zeichenraster](/de/docs/configuration-east-asian#zeichenraster)).
- **Unbekannte Überschrifteneinstellung** – ein Schlüssel, den `headings`, `headings.balancing`, eine Überschriftenebene, ein Überschriftenstil oder ein Absatzformat nicht kennt: ein falsch geschriebenes `letterSpacng`, ein aus einem anderen Werkzeug entlehntes `tracking`, ein `level` in einem Überschriftenstil, ein `fontStyle: 'italic'` in einem Absatzformat (das `italic: true` erwartet). Ein Tabulator wird genauso geprüft (ein `leaders` statt `leader`), ebenso eine Initiale, `lineNumbers`, `canvasViewer`, `checks`, `codeStyle` und die Comic-Einstellungen. Die Engine ignoriert ihn (bis postext 1.4 tat sie das wortlos). `value` ist der Schlüssel, `used` ist leer, und `suggestion` nennt die Einstellung, der er am nächsten kommt, wenn eine nur ein oder zwei Buchstaben entfernt ist oder sich nur in Groß- und Kleinschreibung unterscheidet (`unknownConfigKey`).
- **Unbekannter Einstellungswert** – eine Einstellung, die eines von wenigen Wörtern annimmt, aber ein anderes enthält, etwa `direction: 'right'` (sie nimmt `auto`, `ltr` oder `rtl`). Die Engine liest stattdessen den Standardwert, und `used` nennt, was daraus wurde: bei `direction` die Schreibrichtung der Dokumentsprache (`unknownConfigValue`). Ein `align` eines Tabulators, das keines seiner vier Wörter ist, wird als `'start'` gelesen, und eine `position`, die weder Länge noch `'end'` noch Prozentwert ist, lässt den Tabulator weg (`used` ist `'none'`). Auch die Wörter der Comic-Einstellungen werden geprüft ([Comics › Comic-Warnungen](/de/docs/comics#comic-warnungen)): `used` ist der Wert, zu dem die Einstellung aufgelöst wurde (bei einem eingebauten Stil der eigene Standardwert des Sprechblasenstils), und `suggestion` nennt das Wort, dem der Wert am nächsten kommt, wenn eines nahe liegt. `level` und `mode` der Kontrastprüfung werden genauso geprüft: `used` ist `'AA'` oder `'auto'`. `canvasViewer.pageGap` und `canvasViewer.rowGap` werden ebenso geprüft: `used` ist die ganze Zahl von 0 bis 200, als die der Wert gelesen wurde (seit postext 1.43). Ebenso `print.standard`, `print.outputProfile` und `print.renderingIntent` (`used` ist, was der Standard ergab), und ein `maxWords` oder `maxChars` von `checks.contentInConfig`, das keine ganze Zahl ab 0 ist.
- **Zeilennummern im vertikalen Text** – `lineNumbers.enabled: true` in einem vertikal gesetzten Dokument (`layout.writingMode: 'vertical-rl'`). Vertikale Seiten erhalten keine Zeilennummern, und `used` ist `false` (`lineNumbersUnsupported`; siehe [Zeilennummern](/de/docs/configuration-notes-references#zeilennummern)).
- **Textumfluss in vertikalem Text** – ein `defaultPlacement.wrap` eines Ressourcentyps in einem vertikal gesetzten Dokument. Vertikale Seiten setzen keinen Text neben eine Abbildung, und `used` ist `none` (`wrapUnsupported`; siehe [Dokumentformat › Textumfluss](/de/docs/document-format-resources#textumfluss)). Ein `wrap`, das keine Seite angibt, ist ein unbekannter Einstellungswert.
- **Kastenstil auf Basis eines anderen** – ein Kastenstil, dessen `extends` auf keinen Stil aus `calloutStyles` verweist (`calloutStyleExtendsUnknown`, mit der nächstliegenden ID als `suggestion`), oder dessen `extends`-Kette zu ihm zurückkehrt (`calloutStyleExtendsCycle`, `value` der Kreis `a → b → a`). Der Stil steht für sich, mit den eingebauten Werten für alles, was er offenlässt (siehe [Stile, die auf einem anderen basieren](/de/docs/configuration-callouts#stile-die-auf-einem-anderen-basieren)).
- **Seitenvorlagen und Beschriftungsstile** – ein Problem in `pageTemplates` oder `labelStyles`: eine doppelte ID oder ein doppelter Name, `extends`, Anker oder verkettete Rahmen im Kreis, ein Stil, Rahmen oder eine Vorlage, die es nicht gibt, ein Minimum über seinem Maximum, ein Beschriftungsstil eines Ankers, den `labelStyles` nicht hat (geprüft, wenn die Ressourcen übergeben werden: `collectConfigWarnings(config, { resources })`). Ihr `path` ist ein JSON-Pointer (`/pageTemplates/3/frames/2/style`); jede Art steht mit Ursache und Abhilfe unter [Warnungen zu Seitenvorlagen](/de/docs/configuration-composed-pages#warnungen-zu-seitenvorlagen).
- **Inhalt in einer Gestaltung** – ein Gestaltungstext, dessen Text neben den Platzhaltern länger ist als eine kurze Beschriftung: der Text des Buches in der Konfiguration. Eine Warnung je Einstellung (ein Überschriftenstil, die Kopfzeile, die Gestaltung der Teile) mit dem Pfad jedes Textes (`contentInConfig`; siehe [Inhaltsprüfung](#inhaltsprüfung-konfiguration)). Anders als die übrigen lässt sie sich abschalten: `checks.contentInConfig.enabled: false`.

Die Sandbox listet sie im Bedienfeld **Prüfungen** mit dem Pfad der Einstellung auf. Im Code legt `buildDocument` sie als `configWarnings` am Dokument ab (das fehlt, wenn die Konfiguration fehlerfrei ist), und `collectConfigWarnings(config)` gibt sie zurück, ohne etwas zu setzen:

```js
import { buildDocument, collectConfigWarnings } from 'postext';

// Plain JavaScript: in TypeScript, 'roman' does not type-check to begin with.
const config = { bodyText: { fontFamily: 'EB Garamond, serif' }, orderedLists: { numberFormat: 'roman' } };
const doc = buildDocument({ markdown }, config);
doc.configWarnings;
// [{ kind: 'fontFamilyStack', path: 'bodyText.fontFamily', value: 'EB Garamond, serif', used: 'EB Garamond' },
//  { kind: 'unknownNumberFormat', path: 'orderedLists.numberFormat', value: 'roman', used: 'arabic' }]
collectConfigWarnings(config); // the same list
```

Auch jede verschachtelte Teilkonfiguration wird geprüft: Überschriftenstile, die Listen innerhalb von Teilen, `htmlViewer.overrides`, Gestaltungselemente.

`formatWarning` (siehe [Warnungen im Dokument](/de/docs/configuration-programmatic-usage#warnungen-im-dokument)) beschreibt sie ebenfalls, mit dem Pfad der Einstellung voran – `bodyText.fontFamily: font stack "EB Garamond, serif" — set in "EB Garamond"`, `headingStyles[0].letterSpacng: unknown setting "letterSpacng" — ignored (did you mean "letterSpacing"?)` –, sodass ein Host alle drei Listen, die ein Build zurückgibt, in einer einzigen Schleife protokollieren kann.
