# Skill pour agents

**Transformer une publication existante en projet Postext avec un agent de programmation.**

Beaucoup de gens arrivent à Postext avec un livre qui existe déjà : un manuel
en PDF d’impression, un rapport sous Word, un cours sous PowerPoint, un
catalogue sous InDesign, un EPUB. Le porter dans Postext demande deux tâches :

- **Le contenu** : le Markdown enrichi de chaque chapitre, avec ses directives et
  ses microformats.
- **La maquette** : un manifeste de configuration qui reproduit les règles de
  mise en page de l’original (géométrie de la page, grille de ligne de base,
  caractères, ouvertures, titres courants, encadrés, flottants, tableaux,
  parties).

Un LLM peut faire une bonne partie de ce travail, mais seulement s’il sait comment
fonctionne Postext. Le Markdown de Postext n’est pas du CommonMark, et la
configuration a des pièges qui n’apparaissent que lorsqu’une page sort mal.
Le skill **`postext-port`** réunit ce savoir et les outils avec lesquels nous
avons construit chaque préréglage du Sandbox, pour que votre agent fasse le
portage correctement.

Il suit le format ouvert [Agent Skills](https://agentskills.io) et fonctionne
donc avec Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode et
[beaucoup d’autres agents](https://skills.sh).

## Regarder le tutoriel

Cinq minutes, sans code : préparer le dossier, apporter les originaux
vectoriels, ajouter un PDF de référence, faire la demande à l’agent et vérifier
le résultat dans le Sandbox.

## Ce que contient le skill

- **Une méthode de travail** :
  1. s’accorder sur le cahier des charges ;
  2. faire l’inventaire de la source ;
  3. mesurer la maquette et la consigner dans une fiche technique ;
  4. créer la structure du projet ;
  5. extraire le contenu ;
  6. le mettre au propre en Markdown Postext ;
  7. préparer les polices et les images ;
  8. vérifier page par page ;
  9. empaqueter le tout.
- **Des références** :
  - le format du document et le manifeste de configuration, tous deux vérifiés
    par rapport au moteur ;
  - le format du projet (paquet) ;
  - un guide pratique par format de source ;
  - une méthode d’analyse de la maquette ;
  - un catalogue de cas de mise en page résolus : parties avec leurs propres couleurs,
    ouvertures de chapitre, vers, gloses marginales, notes de bas de page, index, encadrés flottants, coupés ou
    imbriqués, originaux vectoriels pour l’impression, figures en texte réel, images dans
    des cellules de tableau, tableaux à l’italienne, éditions bilingues, et d’autres encore ;
  - les livres chinois, composés horizontalement ou verticalement et reliés à droite :
    quoi demander dans le cahier des charges (écriture, région, sens, reliure), comment
    mesurer une grille de caractères, comment extraire le texte de PDF verticaux, le ruby
    et le warichu d’InDesign, la mise en page est-asiatique de Word et les EPUB de droite à
    gauche, et comment réduire les polices CJK aux caractères du livre (voir [Mise en page chinoise](/fr/docs/chinese-layout)) ;
  - les livres japonais, romans bunko et tankōbon verticaux reliés à droite ou
    livres techniques horizontaux : la langue qui active les règles japonaises
    (`ja`, jamais une balise chinoise), quoi demander (sens, grille,
    furigana, notes, orthographe de l’édition), comment mesurer la zone de
    contenu en caractères et en lignes, le balisage des furigana et des bōten, les textes
    d’Aozora Bunko convertis avec `aozora.py`, les numérisations d’éditions du domaine public de
    la Bibliothèque nationale de la Diète, et des polices japonaises réduites avec leurs kana et leurs
    formes verticales (voir [Mise en page japonaise](/fr/docs/japanese-layout)) ;
  - les livres arabes, modernes ou classiques et vocalisés, composés de droite à gauche et
    reliés à droite : la langue qui fait passer tout le livre de droite à gauche, quoi demander (région
    et chiffres, vocalisation, vers, table des matières à la fin), comment mesurer une
    page en miroir, comment extraire l’arabe de PDF, de Word et de Wikisource, les poèmes
    en `:::verse`, les notes « (١) » par page, et des polices arabes réduites avec leurs
    tables de liaison (voir [Mise en page arabe](/fr/docs/arabic-layout)) ;
  - la bande dessinée, les mangas et les strips de presse : l’expression de découpage qui divise une planche en
    cases, les images des cases avec leurs ancres de locuteur et leurs zones de sécurité, un
    script par langue, que le moteur lettre (bulles, récitatifs, onomatopées),
    les mangas et les éditions arabes de droite à gauche, et comment porter à partir d’images sans
    texte accompagnées de traductions, de numérisations déjà lettrées ou d’un script
    avec des images générées (voir [Bande dessinée](/fr/docs/comics)) ;
  - les pages composées : les pages fixes de manuels, de cahiers et de magazines
    portées en gabarits de page dont les blocs se remplissent depuis le Markdown,
    la passe de portage que gère le Postext installé et les vérifications que
    chaque édition doit passer (voir [Pages composées](/fr/docs/composed-pages)) ;
  - l’objet imprimé : comment relever le papier, la reliure, les couvertures et le dos de
    la source et les traduire en réglages `folio` qu’affiche la [visionneuse Folio](/fr/docs/sandbox-previews#onglet-folio),
    vérifiés par le linter.
- **Des scripts** (Python et Node), décrits dans la section suivante.

## L’installer

### N’importe quel agent (skills.sh)

La CLI [`skills`](https://skills.sh) détecte vos agents et installe le
skill pour eux :

```bash
npx skills add drnachio/postext --skill postext-port
```

Choisissez les agents explicitement avec `-a`, et installez globalement (pour tous les projets) avec
`-g` :

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

Le site publie le même skill, donc ceci fonctionne aussi :

```bash
npx skills add https://postext.dev
```

### Plugin Claude Code

Le dépôt Postext est aussi une marketplace de plugins Claude Code. Dans Claude
Code :

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

Ou depuis un shell :

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### Laisser l’agent l’installer

Vous pouvez demander à votre agent de le faire, par exemple : *« Installez le skill
de portage Postext (`npx skills add drnachio/postext --skill postext-port`) et utilisez-le pour
porter ce PDF. »* Les agents qui lisent `https://postext.dev/llms.txt` y trouvent cette
page et la commande d’installation.

### Outils utilisés par les scripts

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

Pandoc est nécessaire pour les sources Word, PowerPoint, EPUB et HTML, poppler pour
les images des pages de la source, et numpy pour `comic_panels.py`. Les paquets npm font tourner le moteur de rendu sans interface (Node 22.15 ou
plus récent) ; `@napi-rs/canvas` est un canvas précompilé qui lui permet de dessiner les
pages du livre directement en JPEG. Outils facultatifs : `ocrmypdf` pour les numérisations, ImageMagick, et veraPDF pour
les vérifications PDF/UA.

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

Choisissez le fichier de votre système (`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`) ; avec Node, `npx postext-cli` fonctionne aussi.

La boucle de travail s’exécute en [ligne de commande](/fr/docs/command-line), avec un seul exécutable autonome, sans rien à installer : l’agent garde le projet décompressé et laisse `postext build --watch` tourner sur les pages sur lesquelles il travaille : chaque modification apparaît ainsi en JPEG environ une seconde plus tard, même dans un long livre. Les paquets npm sont facultatifs : ils font tourner `render.mjs`, qui ajoute les vérifications supplémentaires du Sandbox. Les deux mettent le livre en page avec `bodyText.shapingLanguage: 'host'`, quelle que soit sa configuration ; une ligne peut donc se couper à un autre mot que dans le Sandbox (voir [Différences avec le Sandbox](/fr/docs/command-line#différences-avec-le-sandbox)).

## L’utiliser

Placez les fichiers source dans votre dossier de travail et demandez le portage. Par exemple :

- *« Portez les chapitres 1 à 3 de `manual.pdf` vers Postext, en reproduisant sa mise en page
  sur deux colonnes, ses ouvertures de chapitre et ses encadrés. »*
- *« Convertissez `course.docx` en livre Postext. Les styles “Nota” et “Actividad”
  sont des encadrés. »*
- *« Transformez `deck.pptx` en support de cours Postext : les diapositives deviennent des sections, les notes
  de l’orateur deviennent le texte. »*
- *« Nous avons le dossier InDesign (IDML + PDF d’impression) de ce manuel. Construisez le
  préréglage Postext du chapitre 1 en espagnol et en anglais. »*

Pour un livre InDesign, donnez à l’agent le dossier que produit **Fichier › Assembler**
dans InDesign (le `.idml`, le PDF d’impression, les polices et les illustrations liées).
Le skill en dégage les règles de mise en page, ce que ne fait pas l’importateur IDML :
[InDesign : import, export et portage](/fr/docs/indesign) compare les deux.

L’agent suit la méthode de travail :

1. **Cahier des charges.** Il demande ce qu’il ne peut pas déduire : une reproduction fidèle ou une
   nouvelle maquette, un chapitre d’essai ou tout le livre, les langues, l’impression ou l’écran,
   et les droits sur le texte, les images et les polices.
2. **Inventaire et mesure.** Il lit la source et rédige une fiche technique
   de faits mesurés : format, marges, colonnes, interlignage, rôles
   typographiques, palette, ouvertures, titres courants, familles d’encadrés
   et habitudes de placement. Il classe chaque page en texte courant ou en
   page composée (encadrés, étiquettes et cartes à des places fixes) ; avec
   Postext 1.35 ou plus récent, il regroupe les pages composées par type de
   page et monte chaque type à partir d’un gabarit : la mise en page reste
   identique et le texte peut quand même être corrigé et traduit ; avec
   une version plus ancienne, si plus d’un tiers des pages sont composées, il
   vous demande si vous voulez une mise en page identique ou un texte que vous
   pourrez corriger et traduire.
3. **Projet.** Il crée la structure de `my-book/` avec un générateur `build_preset.py`
   qui garde la fiche technique sous forme de constantes et produit `preset.json`.
4. **Contenu.** Il extrait des brouillons de chapitres avec l’extracteur adapté, puis
   les met au propre en Markdown Postext : encadrés, styles de paragraphe, parties,
   attributs de titre pour les ouvertures, citations `:ref`, ressources de tableau et
   de figure.
5. **Vérification.** Il passe le projet au linter et laisse `postext build --watch`
   tourner sur le projet décompressé : il modifie un chapitre ou un réglage, regarde
   le JPEG de la page, redessiné environ une seconde plus tard, et recommence
   jusqu’à ce que les sauts de page, les figures et les encadrés correspondent à la source page par page. À
   chaque étape importante, il lance toutes les vérifications (`postext check` et le linter).
   Le PDF est construit pour les vérifications d’impression, pas à chaque coup d’œil.
6. **Livraison.** Il définit le papier, la reliure et les couvertures du livre pour la visionneuse
   Folio et empaquette `my-book.postext`.

Ouvrez le résultat dans le [Sandbox](/fr/sandbox) : **Livres → Nouveau → Ouvrir un fichier .postext…**.
À l’import, le Sandbox prend les chapitres et les textes de sa propre langue. Pour travailler
sur un dossier de projets dans une copie locale de Postext, définissez
`POSTEXT_PRIVATE_PRESETS_DIR` (voir [Sandbox](/fr/docs/sandbox)).

### Charger le résultat depuis du code

Le fichier livré n’est pas lié au Sandbox. Le paquet npm `postext` l’ouvre avec `openBundle`, met le livre en page avec `buildBundle` et le rend en canvas, en HTML ou en PDF (voir [Paquets](/fr/docs/configuration-bundles#paquets-fichiers-postext)). Un portage peut donc alimenter directement un programme. Quand la sortie de ce programme demande des retouches, exportez-la de nouveau en fichier `.postext` avec `createBundle`, affinez-la dans le Sandbox et rechargez le fichier corrigé. Le `render.mjs` sans interface du skill accepte lui aussi un fichier `.postext` empaqueté en plus d’un dossier de projet.

## À quoi s’attendre

- **Les extracteurs produisent des brouillons ; l’agent les met au propre.** Comptez une passe
  de relecture par chapitre, comparée aux pages de l’original. C’est de cette relecture
  que vient la qualité.
- **Le texte reste dans le Markdown.** La configuration contient la maquette et
  chaque mot du livre se trouve dans les chapitres : une correction ou une
  traduction se fait donc dans le Markdown. Avec Postext 1.35 ou plus récent,
  les pages composées sont des gabarits de page dans la configuration, dont
  les blocs se remplissent avec le Markdown de chaque chapitre : un encadré
  s’allonge avec une traduction plus longue et repousse ceux du dessous, et
  depuis la 1.37 les noms d’une carte sont des étiquettes écrites dans le
  Markdown. Avec une version plus ancienne, elles sont montées avec des
  encadrés fixés à leur place, des images de page sans texte et des figures
  SVG dont les étiquettes restent du vrai texte. Le rapport indique laquelle
  des deux voies l’agent a suivie, et avec quelle version. Quand Postext ne sait
  pas exprimer quelque chose sans écrire du texte dans la configuration,
  l’agent s’arrête, rédige la lacune sous forme de brouillon de ticket et vous
  pose la question. Le skill ne modifie jamais le moteur pour l’adapter à un
  livre.
- **Un seul fichier pour toutes les langues.** Une traduction est un jeu de
  chapitres dans le même fichier `.postext`, avec ses propres légendes et
  étiquettes de figures, vérifié avec `postext check` dans chaque langue.
- **Les droits relèvent de votre décision.** L’agent demande avant de reproduire des images ou des polices
  dont les licences ne sont pas claires. Les polices sous licence sont marquées
  `redistributable: false` : les projets exportés ne les incluent donc pas.
- **La fidélité là où elle compte.** L’objectif est d’obtenir la même grille, les mêmes caractères, les mêmes ouvertures,
  les mêmes encadrés, le même placement des figures et les mêmes sauts de page sur la plupart des pages (à une page près par
  chapitre), pas des coupures de lignes identiques.

## Où il se trouve

Le skill se trouve dans le dépôt, à l’emplacement
[`plugins/postext/skills/postext-port`](https://github.com/drnachio/postext/tree/main/plugins/postext/skills/postext-port).
Il couvre tous les cas rencontrés en construisant les préréglages du Sandbox, publics et
privés. Quand un portage tombe sur un cas qu’il ne couvre pas encore, ouvrez une issue
ou une pull request qui améliore le skill, pour que le portage suivant en profite d’office.
