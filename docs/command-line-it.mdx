# Riga di comando

**`postext` compone il tuo libro da un terminale, da uno script o da un agente.**

La [Sandbox](/it/sandbox) è il posto in cui scrivi un libro e ne curi la grafica guardando il risultato. La
riga di comando prende lo stesso libro e ne produce i file senza browser:
un PDF pronto per la stampa, le pagine in HTML, un EPUB, l’immagine di una pagina o di tutte
le pagine, un documento Word. Inoltre crea i pacchetti `.postext` e li estrae, importa
documenti Word, descrive un libro e lo controlla in cerca di problemi.

È **un unico eseguibile autonomo** per ogni sistema. Il motore di postext, i
generatori di PDF, EPUB, HTML e Word, il motore di disegno delle pagine (Skia), HarfBuzz per
l’arabo e le altre scritture complesse, i profili ICC di stampa e i font
predefiniti (EB Garamond e Open Sans) sono tutti al suo interno. Non c’è nessun runtime,
pacchetto o libreria da installare, e l’impaginazione è quella della Sandbox: lo stesso libro
si divide nelle stesse pagine.

## Come ottenerlo

Con [Homebrew](https://brew.sh), su macOS o Linux:

```bash
brew install drnachio/postext/postext
```

Con [Scoop](https://scoop.sh), su Windows:

```powershell
scoop bucket add postext https://github.com/drnachio/scoop-postext
scoop install postext
```

Entrambi installano l’eseguibile dell’ultima versione come comando `postext`,
verificato con il suo checksum, e `brew upgrade postext` o
`scoop update postext` portano la successiva. Senza un gestore di pacchetti,
scarica tu il file.

Ogni versione di Postext pubblica gli eseguibili nella sua
[GitHub Release](https://github.com/drnachio/postext/releases/latest), con
i relativi checksum (`SHA256SUMS`) e un `readme.txt`:

Ogni file pesa tra 115 e 140 MB. Il link
`https://github.com/drnachio/postext/releases/latest/download/<file>` dà
sempre il più recente.

Su Linux o macOS:

```bash
curl -fL -o postext https://github.com/drnachio/postext/releases/latest/download/postext-linux-x64
chmod +x postext
./postext
```

Spostalo in una cartella del tuo `PATH` (`/usr/local/bin`, `~/.local/bin`) per eseguirlo
come `postext` da qualsiasi posizione. macOS mette in quarantena un file scaricato con un
browser; rimuovi il contrassegno una volta sola:

```bash
xattr -d com.apple.quarantine postext-macos-arm64
```

Su Windows, in PowerShell:

```powershell
Invoke-WebRequest https://github.com/drnachio/postext/releases/latest/download/postext-windows-x64.exe -OutFile postext.exe
.\postext.exe
```

Se hai Node.js installato, `npx postext-cli` scarica da npm l’eseguibile del tuo
sistema e lo avvia, e `npm install -g postext-cli` lo installa come comando
`postext`.

Eseguito senza argomenti, `postext` stampa la guida; `postext help <command>`
elenca le opzioni di un comando.

## Un primo libro

Tre file Markdown in una cartella sono un libro, un capitolo ciascuno, in ordine di nome:

```bash
postext pdf chapters/ --name "Field notes" -o field-notes.pdf
```

Il front matter del primo capitolo dà al libro titolo e autore, e i valori
predefiniti del motore fanno il resto: due colonne, una griglia della linea di base, testo giustificato e
sillabato, testatine. Aggiungi una configurazione e delle immagini quando ti
servono:

```bash
postext pdf chapters/ --config design.json --resources pictures/ -o field-notes.pdf
```

Un libro fatto nella Sandbox (**Libri → Esporta .postext**) funziona così com’è:

```bash
postext pdf my-book.postext -o my-book.pdf
postext image my-book.postext --page 1 -o cover.png
```

## Che cosa può essere un libro

Ogni comando che legge un libro accetta una qualsiasi di queste forme:

- **Un file `.postext`**: il pacchetto che la Sandbox esporta e apre (vedi
  [Pacchetti](/it/docs/configuration-bundles#pacchetti-file-postext)).
- **Una cartella di libro**: un pacchetto decompresso, con il suo `preset.json`, i capitoli,
  le risorse e i font. È ciò che consegna la skill per agenti, e `postext unpack`
  ne scrive una.
- **Markdown sparso**: uno o più file `.md`, un capitolo ciascuno nell’ordine
  indicato, oppure una cartella i cui file `.md` vengono presi per nome (`01-intro.md`,
  `02-method.md`…). Insieme a questi:
  - `--config design.json`: la configurazione, come semplice oggetto di
    configurazione o come `preset.json` completo;
  - `--resources pictures/`: le immagini, ciascuna una figura che prende il nome dal file
    senza estensione (`map.png` è `::resource{id="map"}`); in alternativa, un
    `resources.json` nella cartella le descrive (id, tipi,
    didascalie, testo alternativo), nella stessa forma delle `resources` di un
    `preset.json`;
  - `--fonts fonts/`: i file dei font che il libro porta con sé (TTF, OTF, WOFF2), identificati dalla
    famiglia indicata nelle loro tabelle;
  - `--name "Title"`: il nome del libro.

`--config` funziona anche su un pacchetto o su una cartella: viene unito sopra la
configurazione del libro. Un pacchetto multilingue viene letto nella sua lingua, a meno che
`--locale` non ne chieda un’altra (`--locale en`).

### pdf

```bash
postext pdf book.postext -o book.pdf
postext pdf book/ --pdfx x4 --profile fogra51 -o book-print.pdf
postext pdf book/ --color-space grayscale --no-outlines
```

Il PDF segue le impostazioni del libro (vedi
[Generazione del PDF](/it/docs/configuration-fonts-colors-viewers#generazione-del-pdf-configurazione) e
[Produzione per la stampa](/it/docs/configuration-fonts-colors-viewers#produzione-di-stampa-configurazione)); queste opzioni
le cambiano per una singola esecuzione:

- `--pdfx none|x1a|x4`: lo standard PDF/X per una tipografia.
- `--profile NAME|FILE`: il profilo ICC di output, per nome (`fogra39`,
  `fogra51`, `fogra52`, `swop5`, `gracol2006`, `snap2007`, `ifra26` e gli
  altri profili delle impostazioni di stampa) o come file `.icc`.
- `--color-space rgb|cmyk|grayscale`.
- `--accessible` / `--no-accessible`: la struttura marcata per gli screen reader.
- `--no-outlines`: esclude i segnalibri.
- `--page-negative`: pagine in negativo, per alcuni flussi di stampa.
- `--die-line page|none`: la linea di fustella di un libro con fustelle, su una lastra propria
  (`page`, il predefinito) oppure omessa (`none`); vedi
  [La linea di fustella nel PDF](/it/docs/special-inks-die-cuts#la-linea-di-fustella-nel-pdf).

### html

```bash
postext html book.postext -o book.html
postext html book.postext -o site/ --mode single
```

Un percorso che termina in `.html` produce un unico file con dentro immagini e font,
facile da inviare. Qualsiasi altro percorso è una cartella: `index.html` accanto ad `assets/`, che
contiene le immagini, i font e i video ospitati in proprio. `--assets embed|folder`
sceglie l’una o l’altra modalità per qualsiasi percorso. Le pagine sono l’impaginazione di stampa, mostrata a
dimensione schermo: affiancate (`--mode multi`, il valore predefinito) o una sotto l’altra
(`--mode single`). I font marcati `redistributable: false` vengono citati per nome ma non
copiati. Se la famiglia indica un `fallback`, al loro posto vengono scritti gli stili di quella famiglia libera, con il nome della famiglia originale (da postext 1.43).

### epub

```bash
postext epub book.postext -o book.epub
postext epub book.postext --layout reflowable --cover cover.jpg
```

`--layout fixed` (il valore predefinito) conserva ogni pagina come stampata, con testo
selezionabile; `--layout reflowable` lascia che il sistema di lettura ricomponga il testo per il suo
schermo (vedi [Libri EPUB](/it/docs/configuration-html-folio-epub#libri-epub-postext-epub)). La
copertina è la miniatura del libro, a meno che `--cover` non indichi un’immagine. I metadati del
pacchetto (titolo, autori, lingua, identificatore) vengono dal front matter del primo capitolo,
come nella Sandbox. I font marcati `redistributable: false` non vengono copiati; una famiglia che indica un `fallback` viene incorporata con gli stili di quella famiglia libera, ma con il proprio nome (da postext 1.43).

### image e images

```bash
postext image book.postext --page 12 -o page-12.png
postext image book.postext --page "#1" --dpi 300 -f jpeg -o cover.jpg
postext images book.postext -o pages/ --dpi 100
postext images book.postext --pages 1-10,iv -f webp --pattern "{chapter}-{label}"
```

Le pagine si indicano **come sono stampate** (`12`, `iv`, un intervallo `7-9`) o **per posizione**
nel libro con `#` (`#1` è la prima pagina qualunque numero stampi, `#10-#20`,
`#30-` fino alla fine). `--pages` accetta un elenco separato da virgole. Il disegno è lo stesso della
vista Canvas della Sandbox, quindi un’immagine mostra la pagina esattamente come è impaginata, senza
passare da un PDF.

- `--format png|jpeg|webp` (o l’estensione di `-o`), `--quality 1-100` per
  JPEG e WebP.
- `--dpi`: la risoluzione, 150 per impostazione predefinita; 72–100 bastano per leggere una pagina, 300
  per la stampa.
- `--pattern`: i nomi dei file di `images`, a partire da `{n}` (la posizione, `{n:03}`
  con zeri iniziali fino a tre cifre), `{label}` (il numero stampato) e `{chapter}`;
  `page-{n:03}` per impostazione predefinita.
- `--print-preview`: la pagina come la riprodurrà la tipografia, attraverso il
  profilo di output, con il rifilo e l’abbondanza disegnati.
- `--jobs N`: quante immagini vengono codificate contemporaneamente (per impostazione
  predefinita, tante quanti sono i processori del computer).

### docx e import-docx

```bash
postext docx book.postext -o book.docx
postext docx book/ --variant semantic -o words.docx
postext docx book/ --variant facsimile -o pages.docx
postext import-docx book.docx book/ --dry-run
postext import-docx book.docx book/
postext import-docx manuscript.docx -o manuscript/ --locale es --report
```

`docx` scrive i documenti Word che esporta la Sandbox (vedi
[Sandbox › Documenti Word](/it/docs/sandbox-books-saving#documenti-word)) e un
terzo. `--variant formatted`, il valore predefinito, costruisce dal Markdown un
documento modificabile, con i titoli, gli elenchi, le note a piè di pagina, le
tabelle, le equazioni e le sezioni propri di Word, composto con il progetto
grafico del libro fin dove Word lo consente e con i font del libro incorporati
(`--no-embed-fonts` si limita a nominarli); ciò che in Word non ha una struttura
viaggia come sorgente in controlli contenuto *Postext Source*.
`--variant semantic` scrive lo stesso testo come solo contenuto: un documento
semplice (A4, una colonna, Arial) in stili Word che dicono che cos’è ogni parte,
senza nulla del progetto della pagina e senza font incorporati. Nessuno dei due
richiede di impaginare; entrambi si aprono in Word e in Google Docs, ed entrambi
tornano con `import-docx`. `--variant facsimile` impagina il libro come fa `pdf`
e scrive ogni pagina come una sezione di Word, con ogni riga in una casella di
testo fissa e i font incorporati: un file per guardare l’impaginazione in Word
per computer, non per correggere e non per Google Docs. Una famiglia che il
libro non può cedere (`redistributable: false` in `customFonts`) resta fuori ed
entra la sua alternativa libera, come nell’EPUB; un font la cui licenza vieta di
incorporarlo, uno con contorni PostScript e un font variabile vengono segnalati
e solo nominati. In `build`, `--docx FILE` scrive lo stesso file, con
`--docx-variant` e `--no-docx-fonts`. Da postext 1.68; `--template` non vale più
per `docx` né per `build`.

Con un libro dopo il file, `import-docx` riporta le correzioni fatte in un
documento che `docx` ha esportato da quel libro. Legge la mappa che il file
porta con sé, confronta il testo con la copia dei capitoli fatta
all’esportazione e unisce ogni correzione al libro così com’è ora: i file dei
capitoli di una cartella, di un `.postext` o di Markdown sciolto, e il testo
delle risorse (didascalie, note, testo alternativo, celle di tabella) in
`preset.json`, oppure nel `resources.json` di `--resources DIR` per il Markdown
sciolto. Per un libro in più lingue, `--locale` indica l’edizione da cui è
stato esportato il file, e una correzione al testo di una risorsa va nel blocco
`localized` di quell’edizione. Ogni correzione è segnalata su una riga propria:

- `applied`, con il file e la riga in cui è andata;
- `conflict`: il testo è cambiato anche nel libro dopo l’esportazione, il
  capitolo o la risorsa non c’è più, o due correzioni si sovrappongono;
- `rejected`: testo che genera il libro stesso (numeri, etichette delle
  didascalie, ciò che uno stile di citazione scrive a partire dalla
  bibliografia) o una formattazione che attraversa il markup di Postext.

Una correzione dentro una citazione vi ritorna quando cade in una parte scritta
dall’autore: il localizzatore, o le parole prima o dopo l’opera. In
`[see also @simmons1991, 346–47]` un intervallo di pagine corretto in `346–48`
in Word diventa `[see also @simmons1991, 346–48]`. La riga nomina la citazione
(`citation simmons1991: locator "7" → "8"`). Una modifica al nome dell’autore,
al titolo o a *Ibid.* viene rifiutata, e una parte stampata diversamente da
come è scritta (`346--47` stampato `346–47`) viene rifiutata con la sua
posizione nel libro, per essere cambiata lì.

Le revisioni si considerano accettate, e i commenti sono elencati con autore e
posizione ma non scritti. Il codice di uscita è 3 quando una correzione non è
stata applicata. `--dry-run` (`-n`) stampa il rapporto e un diff unificato di
ogni file che cambierebbe, e non scrive nulla. Ogni file viene scritto accanto
alla sua destinazione e rinominato al suo posto, così un’esecuzione interrotta
non lascia mai mezzo capitolo; un file di capitolo cambiato mentre
l’importazione era in corso viene lasciato com’è, con un avviso
`docx.fileChanged`. `-o` non va con un libro. Con `--json` la risposta contiene
`variant` (l’esportazione che è il file: `formatted`, `semantic` o
`facsimile`), `writer` (il generatore che nominano le sue proprietà),
`exportId`, `edits` (ciascuna con `status`, `reason`, `kind`, `before`, `after`
e `at`, e dentro una citazione `citation` e `citationPart`), `comments`,
`files` e, in una prova a vuoto, `diff`.

Anche un file modificato in Google Docs e scaricato come `.docx` torna. Docs non
conserva la mappa né la copia dei capitoli; l’importazione riscrive la mappa a
partire dal libro, e lo dice nel rapporto. Poiché quel file non porta con sé
alcuna copia del testo esportato, viene confrontato con il libro così com’è ora.
Se il libro è cambiato dopo l’esportazione, il rapporto lo segnala, e un
cambiamento fatto nel frattempo nel libro può comparire come una modifica che lo
annulla. Importa un file di Docs nel libro da cui è stato esportato, prima di
cambiare quel libro; un file salvato da Word conserva la sua mappa e viene unito
ai cambiamenti successivi del libro. Docs elimina anche il segnalibro nascosto
di un testo sostituito per intero (un titolo, una cella di tabella, una
didascalia, il titolo di un riquadro, una nota a piè di pagina). L’importazione
ritrova quel testo dal suo posto tra i vicini, quindi un titolo resta un titolo
e una didascalia va alla sua risorsa. Quando non si può decidere, per esempio
perché accanto è stato scritto anche un paragrafo e nulla li distingue, il
rapporto mostra al loro posto un’eliminazione e un’aggiunta. Importare lo stesso
file una seconda volta non porta nulla.

Senza un libro, `import-docx` trasforma qualsiasi documento Word in un nuovo
libro: un capitolo a ogni titolo di livello 1 (`--no-split` ne tiene uno solo),
immagini e tabelle come risorse, e `--report` stampa il rapporto di qualità che
mostra la Sandbox (stili in uso, formattazione diretta, numerazione digitata a
mano…). `--template` accetta un modello di importazione (un `.json` salvato
dalla Sandbox o un `.docx` che ne contiene uno).

La spaziatura tra i caratteri appartiene allo stile, non al testo, e quindi non sta nel
Markdown. `docx` scrive il `letterSpacing` degli stili di paragrafo, degli stili di titolo
e dei livelli di titolo come spaziatura tra i caratteri dello stile Word, e `import-docx`
lo rilegge in em del corpo dello stile: lo imposta come `letterSpacing` sugli stili del libro
che non ne hanno uno (gli stili di paragrafo e di titolo del file `--config` a cui corrispondono
gli stili Word, e i livelli di titolo), e lascia com’è ogni spaziatura che il libro definisce già.
Con `--json`, `styleTracking` elenca ciò che è stato impostato (`applied`) e ciò che è rimasto
fuori (`skipped`). Da postext 1.39.

### idml

```bash
postext idml book/ -o book.idml
postext idml book.postext -o book.idml --images link
postext idml book/ -o out/book.idml --lines reflow --fonts
```

`idml` impagina il libro come fa `pdf` e scrive le pagine come pacchetto
InDesign Markup, da rifinire in InDesign: le pagine in spread ai lati del
dorso per un libro con margini a pagine affiancate (una pagina per spread per
ogni altro), filetti, riquadri, tracciati e immagini come elementi di pagina,
le tabelle come tabelle di InDesign, il testo di ogni cornice di una pagina
composta come una cornice di testo con un proprio brano (le cornici
concatenate con `next` ne condividono uno), gli stili di riquadro come stili
di paragrafo e i colori CMYK dell’autore come campioni. I chip che portano un
campo di modulo diventano campi di modulo di InDesign. `--lines keep`
(predefinito) chiude ogni riga dove l’ha chiusa Postext, quindi InDesign
mostra le stesse righe del PDF; `--lines reflow` lascia i paragrafi al
compositore di InDesign, e gli a capo possono cambiare. `--spreads facing` o
`--spreads single` accoppia le pagine, o no, qualunque cosa dicano i margini.
`--images link` mette
le immagini accanto al file, in `Links/`, invece che al suo interno. `--fonts`
scrive i file di font delle varianti usate accanto al pacchetto, in `Document
fonts/`, dove InDesign li trova per quel documento; richiede che `-o` indichi
un file, e una famiglia che il libro non può ridistribuire resta fuori, con un
avviso. Ciò che il pacchetto non può portare com’è nel libro (i punti di enfasi del testo
verticale, la cornice arrotondata di una tabella) viene segnalato con un
avviso `idml.*`. Il generatore è il pacchetto `postext-idml`: vedi [Uso
programmatico › Pacchetti
InDesign](/it/docs/configuration-programmatic-usage#pacchetti-indesign-postext-idml).
In `build`, `--idml FILE` scrive lo stesso pacchetto, con `--idml-images`, `--idml-lines`, `--idml-spreads` e `--idml-fonts`.
Da postext 1.71; `--lines` e `--fonts` da 1.76, `--spreads` da 1.78.

### import-idml

```bash
postext import-idml book.idml -o book/
postext import-idml book.idml -o book.postext --layout flow --links pictures/
postext import-idml book.idml --report --json
postext import-idml package.zip -o book.postext
postext import-idml package.zip --document Book/Book.idml -o book/
```

`import-idml` legge un pacchetto InDesign Markup e scrive un nuovo libro, in una cartella o in un `.postext`: i capitoli in Markdown, la configurazione che danno gli stili e le pagine del documento, e le sue immagini e tabelle come risorse. Un `.indd` non viene letto: salvalo prima da InDesign come InDesign Markup. `--layout pages` segue il documento pagina per pagina con pagine composte, ogni cornice dov’era; `--layout flow` scrive un libro di testo continuo, in ordine di lettura e con gli stili del documento, che Postext impagina di nuovo; `auto` (predefinito) sceglie uno dei due e dice perché. Il file può anche essere un pacchetto InDesign compresso, la cartella che crea **File › Pacchetto** con l’IDML aggiunto (**Include IDML** in InDesign in inglese), inviata come un solo `.zip`: il comando ne importa l’IDML con le immagini della sua cartella `Links/` e mette nel libro i file dei font della sua cartella `Document fonts/`. Se lo zip contiene più documenti IDML, `--document` indica quello da importare con il suo percorso nello zip (`--document Book/Book.idml`); senza questa opzione, il comando li elenca. Un pacchetto che contiene solo il `.indd` viene rifiutato, con il modo di ottenere l’IDML. Le immagini collegate vengono lette prima da `--links`, poi dal pacchetto, poi dalla cartella del file e dalla sua `Links/`, e quelle non trovate vengono elencate. Vengono elencati anche i font che il documento nomina: un `.idml` da solo non contiene file di font, quindi vanno indicati con `--font-dir` quando si genera il libro. Con un pacchetto, un font trovato in `--font-dir` entra nel libro al posto del file del pacchetto. Una raccolta di font (`.ttc`, `.otc`), nel pacchetto o in `--font-dir`, viene divisa in stili singoli, e entrano solo gli stili che il libro usa (da postext 1.83).

Un libro esportato da Postext torna con le stesse righe. Un documento fatto in InDesign viene letto con perdite: il comando stampa il verdetto (`faithful`, `approximate` o `lossy`), i conteggi e ciò che è andato perso o è stato approssimato; `--report` aggiunge le note e come è stato letto ogni stile di paragrafo, e `--json` porta tutto come dati. `--hidden`, `--pasteboard` e `--non-printing` leggono anche i livelli e gli oggetti nascosti, il tavolo di montaggio e gli oggetti non stampabili; `--conditions all` legge tutto il testo condizionale, `--changes reject` legge le revisioni come rifiutate e `--no-masters` lascia fuori gli elementi delle pagine mastro. `--name` e `--locale` danno il titolo e la lingua. L’importatore è `idmlToPostext`, del pacchetto `postext-idml`: vedi [Uso programmatico › Pacchetti InDesign](/it/docs/configuration-programmatic-usage#pacchetti-indesign-postext-idml). L’importazione copia il documento così com’è; per portare un libro da tenere, con le sue regole di impaginazione ricavate, usa invece la skill per agenti (vedi [InDesign: importazione, esportazione e porting](/it/docs/indesign)).

### design

```bash
postext design book.postext -o novel.postext
postext design book/ --parts page,text,headings -o type.postext
postext pdf other/ --design novel.postext -o other.pdf
```

Un file di progetto contiene il progetto grafico di un libro e niente del suo testo: le impostazioni delle parti richieste (i gruppi del pannello Grafica, vedi [File di progetto grafico](/it/docs/configuration-bundles#file-di-progetto-grafico)) con i file dei font e il profilo colore che nominano. Un font segnato come non ridistribuibile resta indietro. `--parts` prende solo alcune parti, separate da virgole; `--design-name`, `--id` e `--description` danno un nome al progetto. Lo stesso libro dà sempre gli stessi byte.

`--design FILE`, un’opzione di tutti i comandi che leggono un libro, compone il libro in un file di progetto o nel progetto di un altro libro, prima di `--config` e `--set`: le impostazioni delle sue parti sostituiscono quelle del libro, gli stili con nome si uniscono per id e i font del progetto si aggiungono a quelli del libro. `--design-parts` ne prende solo alcune parti. Il pannello Grafica della Sandbox importa ed esporta gli stessi file.

`--composition TAG`, anch’essa un’opzione di tutti i comandi che leggono un libro, imposta le regole di composizione della tradizione di una lingua dopo `--design` (da postext 1.80): `es`, `en-US` (o `en`), `en-GB`, `fr` o `de`, oppure `auto` per la lingua del libro. Le regole della convenzione sostituiscono quelle del libro e le altre tornano ai valori predefiniti; la tipografia resta com’è. Vedi [Convenzioni di composizione](/it/docs/configuration-text#convenzioni-di-composizione).

```bash
postext pdf book/ --composition auto -o book.pdf
postext design book/ --composition es --parts composition -o house-rules.postext
```

### pack e unpack

```bash
postext pack my-book/ -o my-book.postext
postext pack 01.md 02.md --name "Notes" --config design.json --resources img/ -o notes.postext
postext unpack my-book.postext -o my-book/
```

`pack` comprime una cartella di libro così com’è, o costruisce un pacchetto da Markdown sparso.
Lo stesso input dà sempre gli stessi byte, quindi due pacchetti si possono confrontare,
anche tramite il loro hash. Per il Markdown sparso, `--id`, `--description` e `--thumbnail FILE`
(un’immagine di copertina) impostano l’id, la descrizione e la miniatura del pacchetto; l’id è
per impostazione predefinita uno slug del nome. Una cartella mantiene ciò che dice il suo
`preset.json`. Un libro che non indica una copertina riceve come copertina la sua prima pagina (`thumbnail.jpg`, 1024 px sul lato lungo), l’immagine che un gestore di file può mostrare per il file; `--no-auto-thumbnail` la omette. `unpack` si rifiuta di scrivere in una cartella non vuota a meno che
non venga indicato `--force`.

### info e check

```bash
postext info book.postext --pages
postext check book.postext
postext check chapters/ --strict --json
```

`info` elenca i capitoli (titolo, parole, file e, con `--pages`, le loro
pagine), le risorse e ogni famiglia di font con la sua provenienza (il
libro, una cartella, l’eseguibile, la cache dei download o il font di ripiego). Per un libro che indica dove comincia (`start` in `preset.json`: un estratto che si apre a pagina 58, nel capitolo 4), stampa anche questo, e ogni comando impagina il libro da lì.

`check` impagina il libro e segnala ciò che mostra il pannello **Verifiche** della Sandbox:
Markdown non chiuso, risorse, direttive e stili sconosciuti, riquadri
che l’impaginazione ha dovuto forzare, font mancanti, impostazioni che il motore ha dovuto
sostituire e, per un libro preparato per la stampa (o con `--preflight`), il
preflight: immagini a bassa risoluzione, linee sottilissime, testo piccolo in più inchiostri, inchiostro
oltre il limite, testo vicino al rifilo. Elenca anche il testo che si legge male
sul suo sfondo (`contrast`), una volta per coppia di colori, con il rapporto sullo schermo
e, per la stampa, sulla carta del profilo di output. Ogni problema indica il
file del capitolo, la riga e la pagina. Il codice di uscita è 3 quando si trova un errore, o un avviso qualsiasi
con `--strict`.

Segnala anche i testi grafici della configurazione che contengono il testo del
libro invece dei segnaposto (`contentInConfig`), una volta per stile di
titolo, testatina o grafica di parte, con il percorso di ogni testo:
sposta quel testo nel Markdown, oppure aggiungi un titolo o il nome
dell’editore a `checks.contentInConfig.allow`.

In un libro con modelli di pagina, `check` segnala anche il testo che non entra nella sua cornice (`frameOverflow`, con i passi provati dalla scala di reimpaginazione e le modifiche che lo farebbero entrare), un flusso di testo che supera le pagine che una cornice può aggiungere (`frameContinuationLimit`), un salto verso una pagina che non viene dopo (`continueTargetMissing`), le etichette di figura che non si possono disegnare o che si sovrappongono (`labelAnchorUnknown`, `anchorUnlabelled`, `labelOverflow`, `labelOverlap`), le cornici nascoste sotto altre cornici o che escono dal loro bordo (`frameCovered`, `frameOutsideArea`), più schede di quante ne contiene una griglia (`repeatOverflow`) e i moduli che una pagina non può disporre (`moduleUnknown`, `moduleAsPage`, `moduleNested`, `moduleNameRejected`). Dopo gli avvisi stampa una riga `reflow` per ogni pagina composta con eventi, e `--json` include come dati i passi, le proposte e il registro di reimpaginazione. Vedi [Pagine composte › Avvisi](/it/docs/composed-pages#avvisi) e [Registro di reimpaginazione](/it/docs/composed-pages#registro-di-reimpaginazione).

### build e --watch

```bash
postext build book/ --pdf out/book.pdf --html out/book.html --images out/pages --pages 1-4
postext build chapters/ --pdf book.pdf --watch
```

`build` impagina il libro una volta e scrive ogni output che indichi (`--pdf`,
`--html`, `--epub`, `--images`, `--docx`, `--idml`), con le opzioni di ciascun comando.
`--watch` resta in esecuzione: quando cambiano un capitolo, la configurazione o un’immagine,
il libro viene impaginato di nuovo con i font e il motore ancora
caricati, di solito in una frazione di secondo per un capitolo, e gli output vengono
riscritti. Un salvataggio che rompe il libro stampa l’errore e conserva gli ultimi
file validi.

## Font

Un libro che porta con sé i propri font (un pacchetto, o `--fonts` con il Markdown sparso) viene
composto con quelli e con nient’altro. Per ogni famiglia nominata dalla configurazione che
il libro non porta con sé, `postext` cerca, in quest’ordine:

1. nelle cartelle indicate con `--font-dir`;
2. tra i caratteri compilati nell’eseguibile: EB Garamond e Open Sans,
   i valori predefiniti del motore;
3. nella cache dei download;
4. su [Google Fonts](https://fonts.google.com), che fornisce file TrueType statici
   interi, o su [Fontsource](https://fontsource.org) per una famiglia
   che Google Fonts non ha (Commit Mono, FiraGO); vengono conservati nella
   cache, quindi una famiglia si scarica una volta sola.

Un peso che una famiglia non offre viene composto nel carattere che sceglierebbe un browser
(la corrispondenza dei font del CSS: sopra 500 si provano prima i pesi più forti, sotto 400 prima
i più leggeri, quindi un 600 di una famiglia con un 400 e un 700 diventa il suo 700, e così anche un
550), e un’inclinazione che manca viene composta in tondo. Ciascuno si usa così com’è, nelle immagini
delle pagine come nel PDF: un carattere display con un solo peso usa le proprie lettere anche per
il grassetto, e una famiglia solo in tondo usa il tondo anche per il corsivo.

I pesi nominati dalla configurazione sono quelli che vengono scaricati: regular, bold e
i loro corsivi per ogni famiglia, e qualsiasi altro peso indicato da un’impostazione, compreso
quello del grassetto (`bodyText.boldFontWeight: 600` chiede il carattere 600). Quando un
peso fornito dalla famiglia non si è potuto caricare (offline senza file in cache, un
download fallito, una cartella di font senza il file), il testo viene composto nel
carattere della famiglia che lo sostituisce secondo la stessa regola e `postext check`
lo elenca come avviso `fontFallback`: le sue righe possono andare a capo diversamente rispetto alla Sandbox.

Un carattere per cui un font non ha glifo viene disegnato con un altro font. `postext check` legge la tabella `cmap` di ogni font che carica ed elenca questi caratteri una volta per font per tutto il libro come avviso `glyphFallback`; con `--json`, il suo `data` riporta i caratteri e quanti sono.

La cache è `~/.cache/postext` (`%LOCALAPPDATA%\postext\cache` su Windows);
`POSTEXT_CACHE_DIR` o `--cache-dir` la spostano. `--offline` salta il download.
Una famiglia non trovata da nessuna parte viene composta in EB Garamond con il proprio nome, così l’impaginazione
e il PDF restano coerenti, e un avviso `missingFont` la nomina. `postext info`
mostra da dove proviene ogni famiglia.

Un pacchetto che lascia fuori i file di una famiglia con licenza può nominare per essa una famiglia libera di larghezza simile (`fallback` nella voce `fonts` del manifest, da postext 1.42). `postext` cerca allora quella famiglia seguendo i passi descritti sopra e compone gli stili che mancano al libro con i tagli di quella famiglia dello stesso peso e della stessa inclinazione, ma con il nome della famiglia con licenza: l’impaginazione somiglia a quella ottenuta con i file e `postext check` non segnala un `missingFont` per essa. Una famiglia che il libro porta solo in parte prende dal `fallback` soltanto l’inclinazione di cui non ha alcun file. Il PDF incorpora il carattere libero.

## Per script e agenti

La riga di comando è fatta per essere pilotata da altri programmi, compresi gli agenti
di programmazione.

- **`--json`** stampa un unico oggetto JSON sullo standard output quando il comando
  termina; ogni messaggio va sullo standard error. Il rapporto elenca ciò che è stato
  scritto, le pagine, ogni avviso con la sua origine e quanto è durata ogni fase
  (in millisecondi):

```json
{
  "ok": true,
  "command": "pdf",
  "version": "1.22.1",
  "book": { "name": "notes", "id": "notes", "locale": "en", "chapters": 2 },
  "pages": 3,
  "outputs": [{ "kind": "pdf", "path": "notes.pdf", "bytes": 29746, "pages": 3 }],
  "warnings": [
    {
      "kind": "unknownResourceId",
      "severity": "warning",
      "message": "Unknown resource id \"map\" in ::resource — nothing is embedded (offset 26)",
      "at": "notes/02-more.md:5"
    }
  ],
  "timings": { "read": 13, "fonts": 8.4, "math": 28.2, "layout": 51.6, "pdf": 132.1, "total": 1638 },
  "exitCode": 0
}
```

- **Codici di uscita**: `0` completato, `1` fallito, `2` uso errato (un’opzione sconosciuta, un
  input mancante), `3` `check` ha trovato errori (o avvisi con `--strict`),
  o `import-docx` ha lasciato fuori una correzione di Word.
- **Nessuna domanda.** Non attende mai un input; una cartella non vuota viene
  rifiutata senza chiedere nulla.
- **Standard output**: `-o -` vi scrive un PDF, un’immagine o un pacchetto, da
  passare in pipe ad altri comandi.
- **Velocità.** L’eseguibile si avvia in pochi centesimi di secondo. Un libro breve
  diventa un PDF o l’immagine di una pagina in molto meno di un secondo; uno lungo impiega
  quanto richiede la sua impaginazione (un romanzo illustrato di 140 pagine, circa dieci secondi). Per
  guardare alcune pagine di un libro lungo, combina `--chapters` con `image` o
  `images --pages`. Per lavorare su un libro attraverso molte modifiche, tieni
  `postext build --watch` in esecuzione e leggi i suoi output.

La [skill per agenti](/it/docs/skill) usa la riga di comando per generare le pagine su cui
sta lavorando e per verificare un porting.

## Python

`pip install postext` fa della riga di comando una libreria Python. Il
pacchetto è Python puro, senza dipendenze, e la sua versione è quella di
postext. La prima volta che esegue un comando scarica l’eseguibile del tuo
sistema dalla GitHub Release di quella versione, lo verifica con `SHA256SUMS`
e lo conserva nella cache descritta sopra, in `bin/<versione>/`. Se
`POSTEXT_BIN` indica un eseguibile che hai già (da Homebrew, da Scoop o
compilato da te), non viene scaricato nulla.

```python
import postext

report = postext.pdf("book.postext", out="book.pdf", set={"page.dpi": 300}, locale="es")
print(report.output.pages)
for warning in report.warnings:
    print(warning.kind, warning.at, warning.message)

pdf = postext.pdf_bytes(open("book.postext", "rb").read())
```

- **Una funzione per comando**: `pdf`, `html`, `epub`, `image`, `images`,
  `docx`, `idml`, `import_docx`, `import_idml`, `design`, `pack`, `unpack`,
  `info`, `check` e `build`. Le opzioni mantengono il loro nome, con i trattini
  bassi (`color_space`, `font_dirs`, `dry_run`). `set` riceve un dizionario,
  `config` un file o un dizionario, `chapters` un numero, una lista, un `range`
  o `"1,3-5"`. Ogni funzione che legge un libro accetta `design=`, un file di
  progetto come percorso o come byte, `design_parts=`, una lista o
  `"page,text"`, e `composition=`, un codice di lingua o `"auto"`.
- **Rapporti come oggetti.** Ogni funzione esegue il suo comando con `--json` e
  restituisce il rapporto: `outputs`, `pages`, `timings` e `warnings`, ogni
  avviso un `Diagnostic` con `kind`, `severity`, `message`, `at` e `page`.
  `info` aggiunge `chapters`, `resources` e `fonts`; `check` aggiunge `passed`,
  `error_count` e `warning_count`; `design` aggiunge `name` e `parts`;
  `import_idml` aggiunge `layout`, `reason`, `chapters`, `quality`, `fonts`,
  `missing_links` e `package`.
- **Errori come eccezioni.** Un fallimento solleva `PostextError`, un’opzione
  sbagliata `UsageError`. Quando `check` trova errori solleva `ProblemsFound`,
  il cui `report` li elenca; con `raise_on_problems=False` restituisce il
  rapporto.
- **Byte.** Un libro può essere dato come i byte di un pacchetto `.postext`.
  Con `out="-"` il file torna in `report.content`; `pdf_bytes`, `html_bytes`,
  `epub_bytes`, `image_bytes`, `docx_bytes`, `idml_bytes`, `pack_bytes` e
  `design_bytes` lo restituiscono direttamente.
- `postext.Postext(binary, cwd=…, timeout=…)` usa un eseguibile preciso, e
  `python -m postext …` è la riga di comando stessa.

Ogni chiamata avvia di nuovo l’eseguibile. Il [README](https://github.com/drnachio/postext/tree/main/packages/postext-python) del
pacchetto elenca tutte le opzioni.

## Come è fatto

La riga di comando è il pacchetto `postext-cli` del
[repository](https://github.com/drnachio/postext/tree/main/packages/postext-cli).
[Bun](https://bun.sh) lo compila, insieme al motore e ai suoi generatori, in un
eseguibile per ogni sistema, e [Skia](https://skia.org) (tramite `@napi-rs/canvas`)
misura e disegna il testo, come fa il canvas del browser nella Sandbox. Un’immagine SVG che contiene un’immagine raster (un PNG o un JPEG incorporato come data URI, come scrive `pdftocairo -svg` le illustrazioni ritagliate da un PDF) viene invece disegnata da [resvg](https://github.com/linebender/resvg), perché il renderer SVG di Skia tralascia queste immagini. A
ogni versione gli eseguibili vengono compilati, eseguiti su Linux, Alpine, macOS e
Windows e allegati alla GitHub Release; npm riceve `postext-cli` e
un pacchetto `postext-cli-<system>` per ogni eseguibile.

Per eseguirla da una copia del repository:

```bash
pnpm install
pnpm --filter postext-cli start pdf book.postext
pnpm --filter postext-cli build:bin --current
```

Il primo comando la esegue dai sorgenti; il secondo scrive l’eseguibile di questo computer
in `packages/postext-cli/bin/`.

## Differenze rispetto alla Sandbox

- **L’HTML** è l’impaginazione di stampa mostrata a dimensione schermo. La scheda HTML della Sandbox
  ricompone il testo per la finestra.
- **`--chapters`** impagina i capitoli da soli: i loro numeri di pagina ricominciano,
  mentre la Sandbox prosegue la numerazione del libro.
- **I font** vengono dal libro, dalle tue cartelle, dall’eseguibile, da Google Fonts o da
  Fontsource (per una famiglia che Google Fonts non ha), mai dai font
  installati sul computer, quindi un libro esce uguale su ogni macchina.
- **La lingua del testo** in un browser è quella del documento
  (`bodyText.shapingLanguage: 'document'`, il valore predefinito da postext 1.30).
  Il canvas di Skia accetta una lingua ma esegue lo shaping senza tenerne conto, quindi la riga di comando
  misura le forme della lingua predefinita di ciascun font e impagina sempre i suoi libri
  con `shapingLanguage: 'host'`, qualunque cosa dica la configurazione; il suo PDF
  e le sue immagini disegnano quelle stesse forme. Un libro il cui carattere ha forme per una
  lingua (una `l·l` catalana, una `fi` turca, le cifre di un carattere cinese in un
  libro inglese) qui viene composto con le forme predefinite. Ciò che `'document'` misura
  altrimenti (le parti di una parola divisa a fine riga, una parola da destra a sinistra, un
  testo grafico) qui viene misurato come lo misura `'host'`, quindi una riga può andare a capo
  su una parola diversa rispetto alla Sandbox.
