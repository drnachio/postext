# Configurazione: riquadri


## Stili dei riquadri

La proprietà `calloutStyles` dichiara gli stili di riquadro con nome che un documento applica con un contenitore `:::callout{type="…"}`: note, suggerimenti, avvertenze, obiettivi di apprendimento, qualsiasi contenuto separato dal testo corrente in un riquadro colorato o bordato. Per impostazione predefinita è incluso uno stile neutro, `note` (sfondo grigio chiaro, nessun bordo, nessuna banda, nessuna icona, nessun titolo), così `:::callout` funziona senza alcuna configurazione; dichiarare `calloutStyles` sostituisce questo elenco predefinito.

```ts
const config: PostextConfig = {
  calloutStyles: [
    { id: 'note', name: 'Note' },
    {
      id: 'objectives',
      name: 'Learning objectives',
      title: 'Objectives',
      stripe: { enabled: true, side: 'left' },
      icon: { kind: 'glyph', glyph: '✓' },
      titleStyle: { textTransform: 'uppercase' },
      lists: { bulletChar: '–' },
    },
    {
      id: 'warning',
      title: 'Warning',
      backgroundEnabled: false,
      border: { enabled: true, color: { hex: '#AA0000', model: 'hex' }, width: { value: 1, unit: 'pt' } },
      borderRadius: { value: 1, unit: 'mm' },
      titleStyle: { color: { hex: '#AA0000', model: 'hex' } },
    },
  ],
};
```

```md
:::callout{type="objectives"}
- Describe the parts of the lantern.
- Trim the wick at dusk.
:::

:::callout{type="warning" title="Do not touch the lens"}
The glass stays hot for an hour after the flame is out.
:::
```

### Angoli, lati e linguette unite

Un riquadro non deve per forza essere un rettangolo con quattro angoli uguali e un solo bordo. Da postext 1.48 uno stile può arrotondare alcuni angoli e non altri, tracciare il bordo solo su alcuni lati e far nascere la linguetta dal riquadro come un’unica forma: la scheda di un libro di scuola in cui la linguetta del titolo e il corpo sono un solo contorno, disegnato dallo stile invece che dipinto in un’immagine dietro la pagina.

```ts
calloutStyles: [
  // Arrotondato solo in alto, un filetto sopra il riquadro e un piede più spesso.
  { id: 'ficha', background: { model: 'hex', hex: '#fff4d6' },
    borderRadius: { topLeft: { value: 3, unit: 'mm' }, topRight: { value: 3, unit: 'mm' } },
    border: { enabled: false, color: { model: 'hex', hex: '#c58b00' }, width: { value: 0.75, unit: 'pt' },
      sides: { top: { enabled: true }, bottom: { enabled: true, width: { value: 2, unit: 'pt' } } } } },
  // Una scheda la cui linguetta nasce dal bordo superiore.
  { id: 'tarjeta', background: { model: 'hex', hex: '#ffffff' }, borderRadius: { value: 3, unit: 'mm' },
    border: { enabled: true, color: { model: 'hex', hex: '#2a6f97' }, width: { value: 1, unit: 'pt' } },
    label: { position: 'top-left', inset: { value: 4, unit: 'mm' }, joined: true, fillet: { value: 2, unit: 'mm' },
      color: { model: 'hex', hex: '#2a6f97' } } },
]
```

- **Angoli.** `borderRadius` è una sola lunghezza per i quattro angoli, oppure `{ topLeft, topRight, bottomRight, bottomLeft }`. Un angolo assente dall’oggetto resta vivo. Gli angoli sono quelli del foglio. Due angoli non prendono mai più del lato che li separa; ciascuno cede in proporzione.
- **Lati.** `border.sides.top`, `right`, `bottom` e `left` accettano `enabled`, `color` e `width`, e ogni campo assente è quello del bordo intero. Un riquadro con il bordo solo in alto è `border: { enabled: false, sides: { top: { enabled: true } } }`, oppure `enabled: true` con gli altri tre lati spenti. Il bordo interno di un lato segue il suo spessore, quindi un angolo arrotondato fra un lato sottile e uno spesso si curva come lo disegna CSS.
- **Linguetta unita.** Con `label.joined: true` la linguetta e il riquadro sono un solo contorno, un solo riempimento (il `background` del riquadro; quello proprio della linguetta non viene disegnato) e un solo bordo che gira attorno alla linguetta. La linguetta sta sul bordo, fuori dal riquadro per la sua altezza: il suo `offset` deve essere `0` (un altro valore viene segnalato come `unknownConfigValue` e letto come `0`). I suoi angoli esterni prendono il raggio dell’angolo del riquadro a cui aderisce, e gli angoli interni dove incontra il riquadro sono arrotondati da `fillet` (predefinito: quel raggio). Una linguetta a filo con il lato del riquadro (un `inset` sotto il mezzo pixel) sale dritta da quel lato. Dai alle parole un colore che si legga sul riempimento del riquadro (`label.color`), perché la linguetta non ha più un riempimento suo. Con `label.ownBackground: true` una linguetta unita è colorata con il `background` proprio dell’etichetta, sopra il riempimento del riquadro e sotto il bordo: una linguetta bianca può così stare su un riquadro tinto, o una colorata su un riquadro senza riempimento.
- **Angoli della linguetta.** `label.borderRadius` dà alla linguetta angoli propri: una lunghezza, oppure `{ topLeft, topRight, bottomRight, bottomLeft }` sugli angoli del foglio, come il `borderRadius` del riquadro. Una linguetta separata dal riquadro ha angoli retti se non li imposta. Una linguetta unita arrotonda così i suoi due angoli esterni (`topLeft` e `topRight` per una linguetta in alto, `bottomLeft` e `bottomRight` in basso); se non impostati, prendono il raggio dell’angolo del riquadro. I raccordi mantengono `fillet` in entrambi i casi.
- **Linguette in basso.** `position: 'bottom-right'`, `'bottom-left'`, `'bottom-start'` o `'bottom-end'` appende la linguetta al piede del riquadro, semplice o unita: è la linguetta superiore capovolta, `offset` sotto il piede, il `rule` lungo il piede. Non ci sono linguette laterali: le parole di una linguetta corrono in orizzontale.

Tutte le uscite disegnano queste forme: il canvas e il PDF come contorni vettoriali, il visualizzatore HTML e l’EPUB a layout fisso con CSS per angolo e per lato. L’EPUB a layout fluido scrive angoli e lati nel suo CSS e compone una linguetta unita come una linguetta semplice. Il `look.border.color` di una cornice ricolora tutti i lati, e la tavolozza di una parte li ricolora uno per uno. Uno stile con tutti gli angoli e tutti i lati uguali si impagina come prima.

```ts
label: {

  icon: { kind: 'glyph', glyph: '◉', placement: 'inside', scale: 1.1 },
}
```

### Stili basati su un altro

`extends` indica un altro stile di `calloutStyles`, e ogni campo che lo stile lascia vuoto viene da quello. Gli oggetti come `padding`, `border`, `titleStyle` o `fixed` si uniscono chiave per chiave, così uno stile può cambiare un solo lato della spaziatura interna o il solo `fixed.offset`; un colore o una lunghezza si prendono interi; `id` e `name` non si ereditano mai. Uno stile di partenza può a sua volta basarsi su un altro. Un libro con riquadri in molti punti tiene uno stile per il loro aspetto e uno stile minimo per ogni posizione:

```ts
calloutStyles: [
  {
    id: 'caja',
    background: { model: 'hex', hex: '#dff0fa' },
    padding: { top: { value: 3, unit: 'mm' }, right: { value: 4, unit: 'mm' }, bottom: { value: 3, unit: 'mm' }, left: { value: 4, unit: 'mm' } },
  },
  { id: 'caja-p5', extends: 'caja', placement: 'fixed', fixed: { offset: { x: { value: 12, unit: 'mm' }, y: { value: -40, unit: 'mm' } } } },
  { id: 'caja-p9', extends: 'caja', placement: 'fixed', fixed: { anchor: { to: 'container', edge: 'top-right' } } },
]
```

Cambia l’aspetto di `caja` e tutti i riquadri lo seguono, ognuno dove si trova. Un `extends` che non indica alcuno stile esistente produce `calloutStyleExtendsUnknown` (l’avviso propone l’id più vicino, e lo stile resta da solo, con i valori predefiniti), e gli stili basati l’uno sull’altro in un ciclo producono `calloutStyleExtendsCycle` (restano da soli finché uno di essi non si basa su uno stile fuori dal ciclo). Nella Sandbox lo imposta il campo **Basato su** di uno stile di riquadro; eliminare uno stile su cui altri si basano scrive le sue impostazioni in questi, e i loro riquadri non cambiano. Nella sezione **Stili delle cornici**, unire con **Confronta solo l’aspetto** conserva come stile minimo di questo tipo lo stile i cui riquadri stanno altrove quando **Lascia ogni riquadro dov’è** è attivo (predefinito), e nessun riquadro si sposta. Da postext 1.39.

### Il contenitore `:::callout`

Una riga `:::callout{type="<id>"}` apre il riquadro e una riga `:::` da sola lo chiude. La riga di apertura accetta cinque attributi: `type` (l’id dello stile), `title` (sostituisce il titolo dello stile), `span`, `placement` e `columns` (sostituiscono i valori dello stile); il contenuto tra le due righe si impagina dentro il riquadro: un titolo facoltativo, poi i paragrafi, gli elenchi, le citazioni in blocco, le formule o le risorse inserite, ciascuno composto con la tipografia `body` / `lists` dello stile (i titoli mantengono i loro stili consueti). I margini tra i figli si fondono come nel testo corrente; l’interno esce dalla griglia della linea di base, e il flusso vi si riaggancia dopo il riquadro con almeno `marginBottom` sotto (vince la griglia; il margine è un minimo, la stessa convenzione seguita dalle risorse). Uno stile con `snapToGrid: false` mantiene invece il `marginBottom` esatto, e il testo dopo il riquadro resta fuori griglia fino al titolo successivo o alla fine di un elenco. Un titolo subito prima di un riquadro resta unito a esso.

Limiti di questa versione:

- Un riquadro resta intero a meno che il suo stile non imposti `keepTogether: false`. Quando non sta nello spazio rimanente della colonna passa intero alla colonna o alla pagina successiva, anche uscendo da una colonna vuota che fasce di elementi flottanti o un limite di fascia hanno accorciato, purché una colonna intera possa contenerlo. Un riquadro più alto di una colonna intera si divide invece, come uno divisibile; solo uno che nessun taglio può dividere (una figura o una tabella più alta della colonna, o uno `splitMinLines` che nessun taglio soddisfa) viene collocato comunque ed eccede; l’impaginazione registra allora un avviso `calloutOverflow` (`VDTDocument.warnings`), che la Sandbox elenca. Un gruppo `:::columns` si taglia come il riquadro che lo contiene, tra le sue sottocolonne (da postext 1.25); resta intero, e può eccedere allo stesso modo, solo con `layout.flowColumns: false` o dentro un riquadro annidato. Un riquadro divisibile lascia indietro la parte che ci sta (figli interi, o le righe di un paragrafo fino a `splitMinLines` su ciascun lato; una figura, una tabella o una formula in evidenza da sola basta per un lato) e prosegue in un riquadro senza icona nella colonna o pagina successiva, senza il titolo a meno che lo stile non lo ripeta, e facoltativamente con un segno sotto la parte che lascia (vedi [Segni su un riquadro diviso](#segni-su-un-riquadro-diviso)).
- Gli elementi flottanti cedono il passo a un riquadro indivisibile. Quando il blocco subito dopo il richiamo di una figura è un riquadro `keepTogether`, uno slot che non lascerebbe al riquadro alcuna colonna della fascia corrente in cui finire (la colonna del richiamo o una vuota dopo di essa, che lo conteneva prima dell’elemento flottante) non viene preso: la figura passa al suo slot successivo, di solito la pagina successiva, e il riquadro resta nel flusso, come lo comporrebbe un compositore, invece di spingere il riquadro fuori dalla pagina lasciando la colonna con la sola figura.
- `span: 'page'` in un’impaginazione a più colonne fa del riquadro un **blocco a tutta larghezza**: si impagina all’intera larghezza del contenuto e divide la pagina in fasce di colonne; le colonne di testo sopra di esso si chiudono alla linea di taglio, il riquadro prende una propria colonna a tutta larghezza, e sotto di esso si apre una nuova fascia di colonne di testo, così il flusso prosegue sotto il riquadro in ogni colonna. Dove le colonne sono *livellate* (in cima a una pagina, subito sotto un titolo di apertura `span: 'page'`, subito sotto un altro blocco a tutta larghezza, o subito sotto una fascia di elementi flottanti in testa) il riquadro taglia semplicemente lì. Quando arriva a metà pagina, con le colonne disuguali, si compone come farebbe un compositore: il testo sopra di esso viene tagliato alla stessa altezza in tutte le colonne (il motore ripete il posizionamento con le colonne della fascia accorciate allo stesso numero di righe della griglia, così il testo passa naturalmente da una colonna all’altra e tutte le regole su orfane, vedove e unione con il blocco successivo continuano ad applicarsi), il riquadro occupa tutta la larghezza della pagina, e le colonne riprendono sotto di esso. Il taglio richiede un paio di passate di posizionamento in più; quando la linea di taglio non lascerebbe spazio per il riquadro più il minimo di righe di testo per le vedove sotto di esso, o nessuna disposizione funziona dopo alcuni tentativi, il riquadro passa in cima alla pagina successiva. Il testo sopra rispetta il taglio: un paragrafo che non può iniziare nelle poche righe che una colonna sotto una figura conserva sopra di esso passa alla colonna successiva (la figura resta allora sola nella sua colonna), e quando un blocco supererebbe comunque il taglio, il taglio si prende una riga più in basso invece che dove termina quel blocco. Anche un riquadro diviso che apre la fascia viene tagliato lì, così il suo resto non supera mai il taglio. Con `headings.balancing.beforeSpan` (il valore predefinito) la fascia che lascia viene tagliata livellata dietro di esso, come la fascia di chiusura di un capitolo, e, quando lo stile consente la divisione (`keepTogether: false`), la parte del riquadro che sta sotto le colonne livellate chiude la pagina e il resto apre la successiva; con `beforeSpan: false` la pagina che lascia viene semplicemente bilanciata come al solito, senza forzare un’interruzione di pagina. Un titolo subito prima di un blocco a tutta larghezza non viaggia con esso. Nelle impaginazioni a una colonna `span: 'page'` è semplicemente in linea.
- `placement: 'fixed'` toglie il riquadro dal flusso: viene impaginato (`width: 'auto'` si adatta al titolo; `'fill'` prende la larghezza della colonna di testo sotto il punto di ancoraggio) e fissato alla pagina in cui compare nel flusso, nella posizione descritta da `fixed.anchor` / `fixed.offset` (per impostazione predefinita l’angolo inferiore sinistro dell’area del contenuto). Le colonne di testo che copre cedono quella zona (tagliate dal basso, o dall’alto quando la colonna è ancora vuota), esattamente come una fascia di elementi flottanti; quando la zona contiene già testo, un elemento flottante o un blocco a tutta larghezza, il riquadro passa alla pagina successiva. Un riquadro fisso che chiude il capitolo (il blocco successivo è un’apertura di capitolo, un `:::part`, un riquadro barriera o la fine del documento) livella prima le colonne sopra di esso (`headings.balancing.trailing`), così una breve pagina di chiusura termina livellata con il bollino sottostante. Il riquadro e i figli stanno in `page.floats` e si disegnano fuori dal ritaglio delle colonne in ogni backend.
- `placement: 'top' | 'bottom'` **fa flottare** il riquadro come una risorsa: esce dal flusso nel punto in cui compare e prende la prima fascia libera dopo quel punto (il piede della pagina corrente, con `'bottom'`, o la testa / il piede della pagina successiva che il flusso apre) alla larghezza della colonna (`span: 'column'`) o all’intera larghezza del contenuto (`span: 'page'`); il testo che lo segue riempie la pagina che ha lasciato. Il riquadro e i suoi figli vanno in `page.floats`, come per un riquadro fisso. Un riquadro flottante in testa a una pagina nuova si colloca prima delle figure in attesa di quella pagina, e una figura citata in una pagina precedente che ci sta poi sotto di esso prende il resto di quella pagina anche quando resterebbero meno di tre righe di testo (una pagina da galleria: riquadro più figura, senza testo in mezzo). Un riquadro `span: 'side'` non flotta mai: si impila accanto al testo qualunque sia il suo posizionamento. Con `columns` superiore a 1 (nello stile o come attributo della riga di apertura, da postext 1.18) un riquadro `span: 'column'` occupa altrettante colonne adiacenti: la testa di una serie di colonne vuote che iniziano alla stessa altezza, o il piede della colonna corrente e di quelle vuote che la seguono, come in `:::callout{placement="top" columns="2"}`.
- `width: 'auto'` si adatta solo al titolo; i figli vengono ignorati.
- Un `:::callout` annidato dentro un altro riquadro è un riquadro a sé: si impagina con il proprio stile (sfondo, bordo, raggio, spaziatura interna, banda, titolo, icona, marcatore, linguetta, tipografia) all’intera larghezza interna del genitore e si impila come uno dei suoi figli, con `marginTop` / `marginBottom` che si fondono con quelli dei vicini. I suoi `span` e `placement` (della riga di apertura o dello stile) vengono ignorati, perché un riquadro annidato scorre sempre dentro il genitore, e così `floatBarrier` e `snapToGrid`. I riquadri si annidano a qualsiasi profondità e possono stare dentro un gruppo `:::columns` (ciascuno intero, in una colonna). Quando il genitore si divide, il taglio cade prima o dopo un riquadro annidato, o al suo interno quando lo stile annidato consente la divisione; ogni frammento ridisegna i bordi dei riquadri che attraversa, e un riquadro annidato che prosegue dal frammento precedente perde il titolo e l’icona, come un seguito di primo livello.
- Un gruppo `:::columns{count=N}` … `:::` tra i figli impagina quei figli in `N` colonne di uguale larghezza, a distanza `columnGap`, dentro il riquadro: la sequenza si taglia ai confini di blocco o di riga che livellano meglio le colonne (un paragrafo o un elemento di elenco tagliato a metà prosegue in testa alla colonna successiva senza il suo punto elenco), ogni colonna inizia alla sommità del gruppo e il gruppo è alto quanto la sua colonna più alta; i figli successivi tornano all’intera larghezza. Un riquadro che si divide (`keepTogether: false`, o più alto di una colonna) taglia anche dentro un gruppo, tra le sue colonne: un gruppo a serpentina riempie a turno le sue colonne e prosegue nel frammento successivo, uno parallelo (`breaks`) prosegue flusso per flusso (da postext 1.25; vedi [Formato del documento › `:::columns`](/it/docs/document-format-directives#columns)). Un `gap` nella riga di apertura sostituisce `columnGap` per quel gruppo, e `rule` traccia un filetto lungo ogni intercolonna. Usalo per un riepilogo dei punti chiave su due colonne, o per affiancare le tabelle di un riquadro largo.
- Il sesto attributo della riga di apertura, `label`, si stampa sulla linguetta dello stile (vedi `label` sopra): `:::callout{type="box" label="BOX 1-1" title="The octet rule"}`; senza uno stile `label` l’attributo viene ignorato.

Nel VDT il riquadro è un blocco cornice `type: 'callout'` la cui decorazione (sfondo, banda, icona, titolo) sta in `designOverlay`, seguito dai suoi blocchi figli nella stessa colonna; la cornice e ogni figlio hanno il `containerId` del blocco. Un riquadro annidato è una cornice `type: 'callout'` a sé tra i figli, seguita dai suoi blocchi; questi mantengono il `containerId` del blocco di primo livello (il posizionamento e il bilanciamento continuano a vedere un’unica unità) e aggiungono `calloutPath`, gli id dei contenitori annidati che li circondano, dal più esterno (l’id proprio di una cornice annidata è l’ultima voce). Il PDF con tag dà a ogni riquadro annidato un `Div` dentro quello del genitore. Le immagini delle icone si risolvono come le immagini delle risorse: il registro delle immagini del canvas, l’opzione HTML `resourceImageUrl` e il provider PDF `resourceBytes`. L’EPUB a layout fluido scrive l’icona per prima nel suo riquadro, nascosta alle tecnologie assistive, e la fa fluttuare dove la disegna la pagina: sopra una banda laterale, in una colonna sua o su un angolo superiore; un libro verticale la colloca lungo le sue righe. Un’immagine dipinta in un solo colore (`tint`, un colore `#rrggbb`) entra nel libro come copia dell’SVG in quel colore; una bitmap vi conserva i propri colori.

```ts
const resolved = resolveCalloutStylesConfig(config.calloutStyles, resolvedBodyText, resolvedHeadings, resolvedUnorderedLists, config.locale);
// => every inherited field filled from the resolved sections; the optional
//    locale picks the language of the continuation strings

const minimal  = stripCalloutStylesDefaults(config.calloutStyles);
// => undefined for the built-in `note` default; static defaults dropped
```

### Enunciati numerati e dimostrazioni

Uno stile con `numbering` conta i suoi riquadri, come `amsthm` di LaTeX conta gli ambienti teorema (da postext 1.19). calloutStyles: [

```ts
  { id: 'definition', numbering: { label: 'Definition' } },
```

### Tipografia in un riquadro

Un riquadro compone il suo contenuto con la propria tipografia `body` e `lists`; tutto il resto mantiene gli stili del documento:

- **I paragrafi** prendono il `body` del riquadro: carattere, corpo, interlinea, colore, colori dell’enfasi, pesi, `italic`, `smallCaps`, allineamento, sillabazione, rientro e spaziatura tra paragrafi. Un campo non impostato eredita da `bodyText`. Un colore dell’enfasi ereditato mantiene il suo collegamento alla tavolozza, quindi grassetto, corsivo ed etichette `:ref` in un riquadro cambiano con `colorPalette` come fanno fuori da esso. (Fino a postext 1.4 il grassetto in un riquadro restava `#295AA3` qualunque fosse il colore principale.)
- **Gli elenchi puntati** prendono il `lists` del riquadro (carattere del punto elenco, colore, corpo, peso e carattere del glifo, rientro, spazio, spaziatura tra gli elementi, margini) al posto di `unorderedLists`, e il loro testo è il testo del riquadro. Un `lists.bulletChar` o `lists.color` diverso da quello del documento (`unorderedLists`) sostituisce il punto elenco o il colore di ogni livello; uno che lo ripete, o che resta non impostato, lascia a ogni livello il proprio (`unorderedLists.levels`), così i trattini annidati sopravvivono nel riquadro.
- **Gli elenchi ordinati** prendono `lists.indent`, `gap` e `itemSpacing`, e `lists.color` ogni volta che lo stile lo imposta, anche quando è il colore del punto elenco del documento; uno stile che lo lascia non impostato mantiene i numeri in `orderedLists.color`. (Fino a postext 1.4 il colore arrivava ai numeri solo quando era diverso da `unorderedLists.color`, quindi impostarlo proprio su quel colore non faceva nulla.) Il numero stesso (il suo carattere, il suo corpo e il suo separatore) viene dall’`orderedLists` globale, perché `lists` ha solo campi per i punti elenco: definisci lì lo stile dei numeri di un riquadro.
- **I `:::paragraphs` dentro un riquadro** usano il loro stile di paragrafo, anche nei riquadri annidati. I campi che lo stile lascia non impostati ereditano dal `bodyText` del documento, non dal `body` del riquadro (né dal suo corsivo o dal suo maiuscoletto).
- **I gruppi `:::columns`** non hanno uno stile proprio: ogni colonna condivide la tipografia del testo e degli elenchi del riquadro, e `columnGap` imposta lo spazio tra di esse.
- **Le citazioni in blocco** prendono il carattere, il corpo e i pesi del testo del riquadro (corsivo e grigio, come nel testo corrente), e il suo maiuscoletto. **I titoli** mantengono gli stili dei titoli; **le formule in evidenza** le impostazioni delle formule.
- **Le figure e le tabelle** mantengono gli stili delle didascalie e delle tabelle del documento, alla larghezza interna del riquadro; i loro pesi normale e grassetto seguono i pesi del `body` del riquadro.
- **I chip** mantengono il loro stile di chip; una dimensione in `em` si legge rispetto al corpo del testo del riquadro.
- **`:::space`** si misura in righe del testo del riquadro (vedi [`:::space`](/it/docs/document-format-directives#space) per i casi in cui viene scartato).
- **Un riquadro annidato** prende per intero il proprio stile; i suoi `span`, `placement`, `floatBarrier` e `snapToGrid` vengono ignorati.

**Note con rientro sporgente.** Le note sotto una tabella, una legenda numerata o un elenco di fonti fanno sporgere il segno davanti al testo: il segno sul bordo interno del riquadro, il testo e tutte le righe successive un po’ più dentro. `body.hangingIndent` (da postext 1.71) compone così tutti i paragrafi di un riquadro o di una cornice con quello stile:

- **Una lunghezza** colloca tutte le righe tranne la prima a quella distanza dal bordo interno del riquadro, come l’`hangingIndent` di uno stile di paragrafo (vedi [Stili di paragrafo](/it/docs/configuration-styles#stili-di-paragrafo)). La prima riga comincia al bordo, o a `body.firstLineIndent` quando è lo stile stesso a impostarlo; un rientro di prima riga ereditato da `bodyText` non si applica.
- **`true`** legge `body.firstLineIndent` come il rientro di tutte le righe tranne la prima, come fa `bodyText.hangingIndent` nel testo corrente; `false` compone il riquadro senza rientro sporgente in un libro il cui testo corrente lo ha. Se non è impostato, il riquadro segue `bodyText.hangingIndent`.

Un tabulatore nella stessa posizione porta il testo che segue il segno fino al bordo delle righe successive, qualunque sia la larghezza del segno:

```ts
calloutStyles: [{
  id: 'notes',
  padding: { top: { value: 0, unit: 'mm' }, right: { value: 0, unit: 'mm' }, bottom: { value: 0, unit: 'mm' }, left: { value: 0, unit: 'mm' } },
  body: {
    fontSize: { value: 7, unit: 'pt' },
    hangingIndent: { value: 4.5, unit: 'mm' },
    tabStops: [{ position: { value: 4.5, unit: 'mm' } }],
  },
}],
```

```markdown
:::callout{type="notes"}
\*	I prezzi comprendono la consegna in città.

\*\*	I soci pagano la metà; lo sconto non si somma ad altre offerte e vale fino alla fine della stagione.
:::
```

Ogni nota è un paragrafo a sé; tra il segno e il testo va un carattere di tabulazione o `:tab`. L’asterisco è preceduto da una barra rovesciata, perché `*` seguito da una tabulazione a inizio riga apre un elemento di elenco. Le righe sono misurate così, per cui il canvas, il PDF, la lista di visualizzazione e l’EPUB (con `padding-inline-start` e un `text-indent` negativo) le compongono allo stesso modo, e l’esportazione Word scrive lo stesso rientro. Gli elementi di elenco mantengono il proprio rientro (`lists.indent`, `lists.gap`), e un paragrafo in un blocco `:::paragraphs` quello del suo stile. Un `firstLineIndent` negativo conta ancora come `0`: la prima riga non può cominciare dentro la spaziatura interna del riquadro. Una citazione in blocco dentro un riquadro segue il rientro sporgente del riquadro quando `hangingIndent` è `true`; con una lunghezza, il rientro sporgente tocca solo ai paragrafi propri del riquadro.

### Segni su un riquadro diviso

Quando un riquadro si divide tra colonne o pagine (`keepTogether: false`, o un riquadro più alto di una colonna), ogni parte dopo la prima si apre senza il titolo e l’icona, e per impostazione predefinita nulla dice al lettore che il riquadro prosegue. Due opzioni aggiungono i segni che usano un libro o una sceneggiatura:

- **`repeatTitle: true`** ripete il titolo in testa a ogni seguito, accompagnato da `continuedSuffix`, per impostazione predefinita «Key points (cont.)». La ripetizione prende lo stile del titolo, quindi con `textTransform: 'uppercase'` dà il «HAMLET (CONT'D)» di una sceneggiatura. L’icona e la linguetta restano sulla prima parte.
- **`continuesMarkerEnabled: true`** colloca `continuesMarker` («Continued», o «Continúa» in un documento spagnolo) sotto l’ultima riga di ogni parte che prosegue, dentro il riquadro, nel carattere e nel corpo del testo del riquadro: in corsivo a meno che `continuesMarkerItalic` non sia `false`, allineato a destra a meno che `continuesMarkerAlign` non indichi `'left'` o `'center'`. Il segno occupa spazio nella parte che chiude, e il taglio viene scelto in modo che ci stia.

```ts
calloutStyles: [{
  id: 'speech',
  keepTogether: false,
  titleStyle: { textTransform: 'uppercase' },
  repeatTitle: true,
  continuedSuffix: "(CONT'D)",
  continuesMarkerEnabled: true,
  continuesMarker: '(MORE)',
  continuesMarkerAlign: 'center',
  continuesMarkerItalic: false,
}],
```

```md
:::callout{type="speech" title="Hamlet"}
A speech long enough to run over the foot of the page…
:::
```

La parte che chiude la pagina termina con «(MORE)», e la pagina successiva si apre con «HAMLET (CONT'D)». Entrambi sono elementi di servizio dell’impaginazione: in un PDF accessibile sono artefatti e nell’HTML sono nascosti alle tecnologie assistive, così il titolo si legge una sola volta. Nel VDT sono blocchi di testo `designOverlay` contrassegnati `artifact: true`.

### Progetti grafici nei riquadri

`design` dispone gli elementi del progetto grafico di un titolo (testi, immagini, filetti, cornici; vedi [Estensione e grafica avanzata](/it/docs/configuration-headings#estensione-e-grafica-avanzata)) in una banda sotto il titolo del riquadro, su tutta la sua larghezza interna. Il contenuto del riquadro segue la banda, con la distanza del titolo tra le due. Un riquadro diviso tra colonne o pagine disegna la banda solo sulla prima parte. Da postext 1.45.

I testi del progetto grafico leggono questi segnaposto:

- `{titleText}`: il titolo che il riquadro stampa, il `title` del recinto o, in sua assenza, quello dello stile.
- `{boxText}`: il contenuto del riquadro come testo semplice, un paragrafo o una voce di elenco per riga. Quelli vuoti si saltano.
- `{boxText.<n>}`: il paragrafo o la voce di elenco numero `n`, contando da 1; vuoto se il riquadro ne ha meno.
- `{attr.<key>}`: un attributo scritto sul recinto. Va bene qualsiasi nome, oltre a quelli che il recinto legge da sé: `:::callout{type="card" kicker="Nota"}` dà a `{attr.kicker}` il valore `Nota`. Un attributo mancante non stampa nulla.
- i segnaposto del documento `{title}`, `{subtitle}`, `{author}` e `{publishDate}`.

Il `resourceId` di un’immagine accetta gli stessi segnaposto, così ogni riquadro può disegnare una risorsa propria. Solo il progetto grafico di un riquadro legge `{boxText}`; quello di un titolo non stampa nulla al suo posto.

Con `setsContent: true` un solo stile serve tutti i riquadri della stessa forma, ognuno con le sue parole. In un quaderno di scrittura ogni riga di esercizio è un riquadro il cui contenuto è la parola da ricopiare: il progetto grafico stampa la parola in una grafia scolastica e poi la ripete a puntini da ricalcare (`dotted`), tante volte quante ne stanno nella riga (`repeat`; vedi [Segni in linea e contorni](/it/docs/configuration-headers-footers#segni-in-linea-e-contorni)).

```ts
calloutStyles: [{
  id: 'practice',
  backgroundEnabled: false,
  border: { enabled: true, color: { hex: '#9aa6b2', model: 'hex' }, width: { value: 0.5, unit: 'pt' } },
  design: {
    setsContent: true,
    minHeight: { value: 16, unit: 'mm' },
    slot: { elements: [
      { kind: 'text', id: 'model', content: '{boxText}', fontFamily: 'Playwrite IT Moderna', fontSize: { value: 26, unit: 'pt' },
        placement: { anchor: { to: 'container', edge: 'top-left' } } },
      { kind: 'text', id: 'copies', content: '{boxText}', fontFamily: 'Playwrite IT Moderna', fontWeight: 100, fontSize: { value: 26, unit: 'pt' },
        dotted: {}, repeat: { gap: { value: 8, unit: 'mm' } },
        placement: { anchor: { to: '#model', edge: 'right-of' }, offset: { x: { value: 8, unit: 'mm' } } } },
    ] },
  },
}],
```

```md
:::callout{type="practice"}
gatto
:::

:::callout{type="practice"}
luna
:::
```

La prima riga stampa *gatto* seguito da una fila di copie a puntini di *gatto*, la seconda fa lo stesso con *luna*, e nessuna delle due parole si compone di nuovo sotto la sua banda. Cambiando la parola nel Markdown cambiano il modello e tutte le copie. Con `setsContent` lasciato a `false` il progetto grafico legge `{boxText}` allo stesso modo, e il contenuto si compone sotto la banda.

Nel VDT gli elementi della banda sono blocchi di progetto grafico nel `designOverlay` della cornice, accanto al titolo.
