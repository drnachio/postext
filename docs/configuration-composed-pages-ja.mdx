# 設定：テンプレートページ


## ページテンプレート

テンプレートページは、形を設定の**テンプレート**から、中身を`::::page{template="…"}`のページブロックに書いたMarkdownから受け取るページです。テンプレートは**枠**と呼ぶ長方形に名前を付け、Markdownはそれぞれの中身を名前（スロット）で枠に送ります。Markdownに位置や大きさが現れることはなく、テンプレートに本文が現れることもありません。本のテンプレートは`pageTemplates`プロパティに入れます。

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

`id`と枠1つだけを指定したテンプレートは、その枠が版面いっぱいに広がる1ページになります。ほかの項目はすべて省略できます。

### 枠

枠は、組まれた中身を受け取る名前付きの長方形です。`name`がMarkdownの指定するスロットで、テンプレートの中で一意です（アンカーは枠とグループを同じ書き方で指すので、グループも枠の名前を使えません）。

テンプレートにグリッドがあれば枠は`grid`のセルで、なければ`placement`で配置します。`placement`はデザイン要素の配置と同じしくみで、アンカー（`'container'`は領域、`'page'`、`'bleed'`、ほかの枠やグループなら`'#name'`）、辺、オフセット、サイズからなります。ほかの枠に固定した枠は、その枠と一緒に動きます。どちらもなければ、枠は領域の左上の角から始まり、幅は領域と同じで、高さは高さの指定に従います。中身を枠に流し込み、つなぎ、切り詰める仕組みは、[テンプレートページ › ページの組み方](/ja/docs/composed-pages#ページの組み方)で説明しています。

### グループが空間を分け合うしくみ

枠は自分の大きさを宣言します。固定の`height`か、`'auto'`です。`'auto'`は中身の高さで、`minHeight`と`maxHeight`のあいだに収まります。印刷されたページをもとにテンプレートを作るときは、各囲みのページ上の高さを`minHeight`に指定します。文章が短ければ囲みは描いたとおりの大きさのままで、長ければ高くなります。ページは1回の処理の中で2度組まれます。1度はテンプレートの宣言どおりに、もう1度は中身が必要とするとおりに組み、その2つの違いが[再配置の記録](/ja/docs/composed-pages#再配置の記録)になります。

**積み重ね（`stack`）**：積み重ねの枠は、それぞれの高さで上から順に並び、あいだに`gap`を空けます。横の位置と幅は各枠のものを保ち、枠自身の縦の位置は無視されます。

- 自分の`placement`も`grid`も持たないグループは、最初の枠が置かれた位置（その`placement`、グリッドのあるテンプレートでは`grid`のセル）から始まり、枠が必要とするだけ下へ伸びます。伸びる先はテンプレートの領域の下端までです。ある枠が高くなると、その後の枠が同じだけ下がります。
- 自分の矩形があるグループは、その矩形の中に枠を並べます。枠が矩形に入りきらないときは、`shrink`が0より大きい枠が空間を返します。返すのは`priority`の低い枠からで、優先度が同じなら`shrink`の比で返し、どの枠も`minHeight`より小さくはなりません。余った空間は、`grow`が0より大きい枠にその比で、`maxHeight`まで配られます。そういう枠がなければ、`align`が枠の位置を決めます（`'end'`なら下端、`'center'`なら中央、`'space-between'`なら上下の端に寄せてあいだを均等に空けます）。グループの中で自分の配置がない枠は、グループの矩形を領域として使います。
- どの枠もそれ以上返せなくなったら、グループの下端に近い枠から順に、それぞれ`minHeight`まで縮みます。高さを固定した枠はその高さを保つので、伸びた囲みの下にある空の解答欄や画像の枠はページに残り、縮むのは囲み自身の文章です。グループの下端を越える枠はありません。中身が入りきらない枠は収めるための手順を順に試し（[内容が収まらないとき](#内容が収まらないとき)を参照）、それでも入りきらない分はそこで切れ、`frameOverflow`として報告されます。`minHeight`や固定の高さより低く切り詰められた枠も、中身の有無にかかわらず報告されます。
- `height: 'fill'`の枠は、`minHeight`を求めたうえで、`grow: 1`を指定したものとして余った空間を受け取ります。

**並び（`row`）**：並びの枠は、宣言した幅で横に並び、どれも並びと同じ高さになります。その高さはグループの矩形の高さで、グループに自分の矩形がなければ、枠が書いた高さ（固定の`height`、なければ`minHeight`。`'auto'`の枠はそれ以上を宣言しません）のうち最も大きいもので、どの枠も書いていなければ最も高い中身の高さです（高さを固定した枠は自分の高さを保ちます）。ある枠の文章が並びの高さを超えると、その枠は幅を広げます。まず並びの余った幅を使い、次に`shrink`が0より大きい兄弟の枠から、`priority`の低い順に幅をもらいます。どの枠も、自分の文章がまだ収まる幅より狭くはなりません。広げる幅は、文章が収まる最少の整数ミリメートルです。使える空間をすべてもらっても収まらないなら幅は広げず、代わりに、自分の矩形のない並びが高くなります。そのため、`height: 'auto'`に`minHeight`を付けたカードは、まずその高さで幅を分け合い、どのカードも幅を譲れないときにだけ並びが高くなります。余った幅は`grow`が0より大きい枠に配られ、残りは`align`に従います。並びは左から右へ進みます。

**ピン留め（`pin`）**：`pin: true`の枠は、固定先の枠が高くなったり動いたりしても、テンプレートが宣言した矩形を保ちます。絵柄に合わせて描いた囲みは、絵柄の上から離れません。グループの中では、ピン留めした枠は自分の位置を守り、ほかの枠は前後に`gap`を空けてそれを飛び越えます。グループの外にあるピン留めの枠も、重なりそうなグループの枠に対して同じように働きます。

**装飾**：枠に固定した装飾の要素（`anchor: { to: '#dinero' }`）は、枠が高くなったり動いたりすると一緒に動きます。`pin: true`の要素は、テンプレートがその枠を描く位置にとどまります。

教科書のページにある3つの囲みです。それぞれに描かれた高さがあり、文章に合わせて高くなります。

```ts
frames: [
  { name: 'dinero', style: 'caja-azul', width: { value: 186, unit: 'mm' }, minHeight: { value: 36, unit: 'mm' },
    placement: { anchor: { to: '#texto', edge: 'below' }, offset: { y: { value: 9, unit: 'mm' } } } },
  { name: 'dinero-fotos', layer: 2, width: { value: 58, unit: 'mm' },
    placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
  { name: 'gasto', style: 'caja-verde', width: { value: 186, unit: 'mm' }, minHeight: { value: 62, unit: 'mm' } },
  { name: 'ahorro', style: 'caja-amarilla', width: { value: 186, unit: 'mm' }, minHeight: { value: 30, unit: 'mm' } },
],
groups: [{ name: 'cajas', kind: 'stack', frames: ['dinero', 'gasto', 'ahorro'], gap: { value: 12, unit: 'mm' } }],
```

結果を決めるのは、ページの中身、テンプレート、組版の設定だけです。同じ入力からは同じページができ、測る順序も手順も変わりません。この調整はほかのページを読まないので、中身が自分のページに収まっているかぎり、あるテンプレートページを変えてもほかのページは元のままです。

**枠をカードの下端に留める（postext 1.42以降）。** 上の文章の下に固定した枠は、その文章に従って動きます。文章が1行短い版や長い版では、その下の枠が上がったり下がったりし、テンプレートが描くもの（カード、帯、下端）はそのまま残ります。枠をテンプレートが置いたとおりカードの下端に留めるには、カードの枠を、カードと同じ高さの枠を含む積み重ね（`stack`）にまとめます。留める枠より上の枠は、余った空間を受け取り（`grow: 1`）、返します（`shrink: 1`）。留める枠には`minHeight`を書きます。文章が短ければ、留めた枠は元の位置のままです。長ければ、押し縮められるのはその上です。留めた枠は`minHeight`を保ち、上の文章が縮小され、それでも収まらなければ、組版は`frameOverflow`を報告し、再配置の記録には上の枠の`textScaled`と`overflow`が載ります。コンテナーの下端（`bottom-left`）に固定した枠も位置を保ちますが、上の枠とは何もつながっていません。長い文章はその枠に重なり、その枠のために何かが押し縮められることはなく、重なりも報告されません。

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

大きくなるほうの枠は、中身にかかわらず空き領域と同じ高さになります。そのため背景の見えるスタイルを付けると全体が塗られてしまいます。カードはテンプレートの装飾に描き、テキストの枠にはスタイルを付けないでください。

### 枠のセットを繰り返すグリッド

写真のカードのページ、学習活動のカードのページ、名前を下に添えた肖像のページは、どれも同じカードを何度も描いたものです。`repeat`を付けたグリッドのグループは、それをテンプレートの中で1度だけ描きます。1枚のカードの枠を枠のセットと呼び、グリッドはページのMarkdownが渡す項目ごとに1回ずつそのセットを配置します。そのためページのカードの枚数はMarkdownで決まり、翻訳でカードが1枚増えても新しいテンプレートはいりません。postext 1.48以降。

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **セット**：`repeat.frames`の最初の枠がセルの**主枠**です。主枠はセルの幅を取り、高さは自分の規則に従います（`'auto'`は`minHeight`と`maxHeight`の範囲での中身の高さです）。セットのほかの枠はテンプレートが描くとおりに、主枠かほかのセットの枠にアンカーして配置します。この例では、キャプションの札が写真の下端から下がります。セットの外の枠にアンカーしたセットの枠は、そのアンカーが示す位置にとどまります。
- **項目**：ページの`:::frame{slot="foto"}`の1つ1つが1つの項目です。繰り返すスロットの内容はつながりません。内容の中で、セットの構成要素を指定したブロック（`:::frame{slot="pie"}`、`::resource{… slot="pie"}`）は、同じカードのその構成要素に入り、それ以外は主枠に入ります。[テンプレートページ › 繰り返すスロット](/ja/docs/composed-pages#繰り返すスロット)を参照してください。
- **インスタンス**：各カードの枠は、1から数えて`<frame>[n]`と名付けられます。`foto[2]`と`pie[2]`が2枚目のカードです。警告、再配置の記録、ソースマップ、Sandboxはこの名前を使い、枠のidは`cp<n>:foto[2]`になります。装飾の要素やコネクターは`'#foto[2]'`にアンカーできます。コネクターの`to: '#foto[*]'`は、ページにあるすべてのカードに届きます。`'#foto'`にアンカーした要素は、グリッドのボックスを読みます。
- **セル**：セルは行を始端側から埋めるので、右から左へ進むページでは最初のカードが右に来ます。行の高さはいちばん高いセルに合わせ、主枠の上に出るもの（タブ）と下に下がるもの（札）も数えます。低いセルの位置は`rowAlign`で決まります。グリッドのボックスは、それ自身の`placement`か`grid`のセルです。どちらもなければ、テンプレートが主枠を描く位置から始まり、領域の右端と下端まで広がります。
- **カードが収まらないとき**：グリッドの下端を越えた行はそこで切れ、各カードはそれぞれ収めるための手順を試し、最後に切れたカードが`frameOverflow`を出します。主枠に`overflow.continueIn`（`'next-page'`、`'template:<id>'`）があれば、グリッドは**行単位で**続きます。収まらない最初の行とそれ以降のすべての行は、同じ枠のセットを繰り返すテンプレートのグリッドに入れて、追加ページに配置します。グリッド全体より高いセルは、いつまでも続ける代わりに警告を出します。
- **`max`**：`repeat.max`を超えた項目は流し込み枠に入り、テンプレートに流し込み枠がなければページの後に入ります。そのたびに`repeatOverflow`が出ます。

`repeat`のないグリッドは、挙げた枠を書いた順に1つのセルに1つずつ配置します。繰り返すセットの枠をほかのグループにも挙げると、そちらでは飛ばされ（`groupFrameTwice`）、テンプレートにない名前は`groupFrameUnknown`になります。`grow`と`shrink`はグリッドの行には働かず、`redistribute`もカードには働きません。

### モジュール

教科書のページは、本の中で繰り返し現れるブロックを、別の順で積み重ねていることがよくあります。写真を横に添えた囲み、3つの考えの木、見出しの下に並ぶ4枚の写真のグリッドなどです。並べ方ごとにテンプレートを描けば、テンプレートはどんどん増えます。**モジュール**は、そうしたブロックを1度だけ描いたものです。`role: 'module'`のテンプレートで、枠、グループ、装飾（コネクターを含む）を持ち、それ自身のページは持ちません。ページテンプレートは`modules: true`のグループでモジュールを受け取り、どのモジュールをどの順で入れるかはページのMarkdownが決めます（[テンプレートページ › ページの中のモジュール](/ja/docs/composed-pages#ページの中のモジュール)を参照）。postext 1.48以降。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **モジュールが持つもの**：枠、グループ（繰り返すグリッドを含む）、装飾、コネクターです。`area`、`header`、`footer`、`variants`、`spread`、`gutter`、`overflowTemplate`は持たず、書くとそれぞれ`unknownConfigValue`として報告され、無視されます。`extends`はモジュールどうしで使えます（モジュールを拡張したテンプレートはモジュールです）。
- **ボックス**：モジュールの幅はそのグループと同じで、高さは枠が届くところまでです。グループはモジュールを上から積み重ね、その間に`gap`を空けます。モジュールの中では、`'container'`はモジュールのボックスを指し、枠（`'fill'`とパーセントも）と装飾はそれを基準にします。`{ to: 'container', edge: 'bottom' }`まで広げた地は、言葉の量でモジュールの高さがどう変わっても、モジュール全体を覆います。
- **名前**：モジュールの枠、グループ、要素は、モジュールのインスタンス名のもとにまとまります。`<name>.<frame>`で、名前はMarkdownが与えるもの（`name="ramas"`）、なければ`<template>[n]`です。nはページの中でそのテンプレートを使うモジュールの何番目かを示します（`arbol[2].raiz`）。モジュールの中のアンカー、`next`、`continueIn: '#x'`、コネクターはそのモジュール自身の枠に書き換えられるので、1ページに木が2つあっても互いにつながりません。枠のidは`cp0:arbol[2].raiz`です。
- **モジュールが収まらないとき**：グループの下端を越えたモジュールはそこで切れ、その枠が収めるための手順を試します。`frameOverflow`はグループにつき1回出ます。モジュールのグループに`overflow.continueIn`（`'next-page'`または`'template:<id>'`）があれば、収まらない最初のモジュールとそれ以降のすべてのモジュールが、同じ名前のまま**丸ごと**追加ページへ移り、そのページのモジュールのグループの先頭に入ります。 モジュールの行やグリッドでは、行がまるごと続きます。1つの行のモジュールが2ページに分かれることはありません。
- **横に並べる**：`kind: 'row'`のモジュールグループは、モジュールを行頭から行末へ並べます。各モジュールの幅はテンプレートの`width`（長さ、`{ percent: 48 }`、または`'fill'`で残りの等分）で、行の高さは最も高いモジュールに合わせます。`kind: 'grid'`は`columns`個の等しい列に、行ごとに並べます。`rowAlign`は行より低いモジュールの位置を決めます。行は文字の行が始まる側から並ぶので、右から左のページでは最初のモジュールが右に来ます。postext 1.50から。
- **スタックの中のグループ**：`within: '<スタック>'`を持つモジュールグループはページのモジュールスタックの中に置かれ、`templates`で受け取るモジュールを決めます。Markdownでそれらが続けて書かれたひとまとまりごとに、最初のモジュールの位置でスタックの1行または1つのグリッドになります。下のグループでは、`aviso`ブロック2つに続けて`tarjeta`ブロック4つを書くと、2つの囲みを横に並べた行の下に2 × 2のカードが並び、Markdownには`:::module`ブロックしかありません。
- **グループの中のグループ**：postext 1.51からは、`within`にどのモジュールグループも指定できます。行やグリッドも、何段でも指定できます。`banda`を`cuerpo`の中の行、`columna`を`banda`の中のスタックにすると、囲みに続けて2枚のカードを書けば、囲みの横に2枚のカードの列が並びます。`#banda`に固定したページの枠は、モジュールのあとに置かれます。
- **行を分け合う**：postext 1.51からは、モジュールの行で残った幅を各モジュールの`grow`で分け、グループより広い行は`shrink`で幅を譲ります。
- **まだできないこと**：モジュールの中のモジュール（`moduleNested`）と、モジュールの中でのテンプレートの`grid`のセルです。

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### 内容が収まらないとき

枠の中身がグループの与える場所より高いとき、割り付けは[収めるための手順](/ja/docs/composed-pages#それでも収まらないとき)を順に試し、最初に中身が収まったところで止まります。`maxHeight`までの空き場所、グループの押し下げと譲り合い、画像の縮小、グループのほかの枠を最小まで縮めること、テキストの縮小、別のページへの続き、の順です。各手順をどこまで進めてよいかは、次の枠の設定で決まります。

- `height`を固定した枠の`maxHeight`：何かを縮小する前に、枠はそこまで伸びられます。
- グループのほかの枠の`minHeight`：それらがどこまで空間を返すかを決めます。どの枠も、自分の中身に必要な高さより小さくはなりません。
- `fit.scaleImages`と`fit.imageMinScale`：枠とそのグループの画像を小さくしてよいか、どこまで小さくしてよいか（既定は80%）。
- `fit.shrinkText`と`fit.minScale`：枠のテキストを小さくしてよいか、どこまで小さくしてよいか（既定は90%）。文字サイズ、行送り、アキは同じ比率で縮み、枠の大きさは変わりません。
- `overflow.continueIn`：これらのどれでも足りないとき、中身の続きをどこに流すか。別の枠か、別のページ（`'next-page'`、`'template:<id>'`、`'page:<id>'`）で、続き先では断片の`overflow.mark`の後、テキストが元の大きさで続きます。別のページへ続けられる枠は、`fit.preferContinue`が`false`でないかぎり、画像とテキストを小さくする前に続きます。

縮小率は2.5%刻みで、割り付けは収まるもっとも大きな値を選びます。1行だけ長いテキストなら、最小値ではなく97.5%で組まれます。文字サイズを変えてはいけない囲みには`fit: { shrinkText: false }`を、画像の大きさを変えてはいけないページにはグループの枠に`fit: { scaleImages: false }`を設定します。

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

それでも収まらない分は`frameOverflow`として報告され、試した手順と、値の付いた修正案が付きます。[警告と修正案](/ja/docs/composed-pages#警告と修正案)を参照してください。

### 継承とバリアント

`extends`を指定したテンプレートは、指定したテンプレート（それ自身がさらにほかのテンプレートを拡張していてもかまいません）から始まり、書いたところだけを変えます。

- `area`、`header`、`overflowTemplate`などの項目は親の値を置き換えます。`grid`はキーごとに統合します。`spread`、`gutter`、`role`も継承しますが、`id`、`name`、`extends`はテンプレート自身のものです。
- `frames`と`groups`は**名前で**統合します。継承した項目と同じ名前の項目は、書いたフィールドだけを変えて残りを保ちます（`fit`、`overflow`、`padding`はキーごとに統合し、`placement`は丸ごと置き換えます）。`remove: true`はその項目を取り除き、新しい名前は継承した項目の後に加わります。
- 装飾の要素も同じように`id`で統合します。新しいidの要素やidのない要素は加わります。postext 1.42以降、子テンプレートやバリアントの`decoration.elements`に`{ id: 'head-even', remove: true }`と書くと、継承した同じ`id`の要素を外せます。枠の`remove: true`と同じ働きです。継承していない`id`を指定しても何も起きません。同じリストの中で、削除のあとに同じ`id`の新しい要素を続けて書くこともできます。

`variants.recto`と`variants.verso`はテンプレートと同じように書き、同じように統合して、右ページと左ページに適用します。適用は`extends`の連鎖全体の後で、根のテンプレートのバリアントが先です。見開きには両方の側があるので、どちらのバリアントも適用しません。

`variants.recto`の要素に`parity: 'even'`、`variants.verso`の要素に`'odd'`を書くと、その要素は描かれません（`unknownConfigValue`）。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Sandboxがテンプレートを保存するとき、既定値と同じ値も捨てずに残します。ほかのテンプレートを拡張するテンプレートやバリアントの中では、その値が親の値を上書きするからです。

コードからは、`resolvePageTemplate(config, id, { parity })`が、連鎖を統合し、その側のバリアントを適用し、すべての既定値を埋め、下の警告で説明するとおりにすべての参照を解決したテンプレートを返します。`validatePageTemplates(config)`は警告を返します。

### ページが指定したときに描く

装飾の要素と、テンプレートの`header`・`footer`の要素には、`when`または`unless`を付けられます。どちらもページブロックの属性名を書きます。`when: 'folio'`はブロックに`folio`があるページにだけ要素を描き、`unless: 'frontmatter'`はブロックに`frontmatter`があるページでは要素を描きません。属性は単独で書くか（`::::page{template="pagina" frontmatter}`）、`false`以外の値を付ければ指定したことになります。これでひとつのテンプレートが、ノンブルも帯も入れない前付と、両方を入れる本文ページの両方をまかなえます。ページが何であるかはMarkdownが示し、図柄はテンプレートが持ちます。postext 1.50以降。

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- 描かない要素にアンカーした要素や、その要素までの寸法をとる要素も描きません。
- 両方のキーがあるときは、ブロックに`when`の属性があり、`unless`の属性がないページで描きます。
- 文書の柱とノンブル、セクションの柱とノンブルもこのキーを読みます。テンプレートページでないページにはページブロックがなく、どの属性もありません。見出し・部扉・ボックスのデザインはこのキーを無視します。
- 空でない文字列でない値や、見出し・部扉・ボックスのデザインに書いた値は`unknownConfigValue`として報告し、要素はキーがないものとして描きます。`postext check`は、本のどのページブロックにもない属性を`when`や`unless`が指していると、注記`conditionNeverMet`を出します。その要素は一度も描かれないか、常に描かれます。何も設定しない`{attr.x}`も同様で、常に空になります。
- 本を組み終えると、同じテンプレート・同じ側のページの多くが描くノンブルや柱（`header` や `footer` のテキスト、または `{pageNumber}`、柱の名前、`{attr.x}` を読む装飾のテキスト）を何も描かないページが `folioMissing` として、ページ、テンプレート、要素とともに報告されます。ブロックがその要素を消しているページと、テンプレートにその要素がないページは数えません。postext 1.53 から。
- Sandboxでは、柱とノンブルやテンプレートの装飾の要素カードごとに**ページが指定したときに描く**と**ページが指定したときは描かない**の欄があり、本のページブロックが使う属性から選べます。

### 割り付けに反映される設定

割り付けに反映されるのは、各枠の配置と大きさ（グリッド、アンカー、`min`/`max`、`verticalAlign`）、スタイルと`padding`、`columns`、`rules`、`layer`、`rotate`、`exclude`（とその`wrap`）、`flow`、`takes`、`next`、`overflow.continueIn`（`"#frame"`、`"next-page"`、`"template:<id>"`、`"page:<id>"`）と`overflow.mark`、`overflow.fromMark`、枠の`fit`（組み直しの段階で文字と画像を縮める設定。[内容が収まらないとき](#内容が収まらないとき)を参照）、グループによる空間の配分（`grow`、`shrink`、`priority`、`pin`、グループの`gap`と`align`。[グループが空間を分け合うしくみ](#グループが空間を分け合うしくみ)を参照）、そしてテンプレートの`area`、`grid`、`decoration`、`header`、`footer`、`variants`、`spread`、`overflowTemplate`です。postext 1.42以降は、テンプレートの`palette`、枠の`look`、幅の`'auto'`（枠のいちばん長い行に合わせた幅）も反映されます。枠の`writingMode`と`direction`は、postext 1.39以降は反映されます。postext 1.48以降は、グリッドのグループとその`repeat`、モジュールのグループとモジュールのテンプレート、装飾のコネクターとパス要素、枠の`overlap`も反映されます。テンプレートの`bodyStyle`は読み込まれて検査されますが、まだ割り付けには反映されません。

### 見開き

見開きのテンプレートでは、すべての座標が2ページ分の版面の上にあり、のどがその中央に来ます。`area`、`grid`、`container`・`page`・`bleed`へのアンカー、`fill`のサイズは、どれも2倍の幅で読みます。`bleed`は天・地・左右の小口まで届き、のどには届きません。教科書の見開きの年表は1つのテンプレートで書けます。

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2からera-6まで、それぞれグリッド1列ずつ、さらに帯の下の注記
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

列の間隔を`gutter`より広くしておけば、左右対称のグリッドのカードはのどにかからず、どれも動きません。2本目の帯と絵の帯は`crossGutter`でのどをまたぎ、それぞれ中心のあるページで読まれ、両方のページに描かれます。タブに書く時代の名前も含め、ページの言葉はすべてMarkdownに置きます。

縦組み（`vertical-rl`）の本では、見開きのテンプレートも1ページのテンプレートページと同じく、ページの文章の流れの座標で割り付けます。ページの「上」は紙の右端で、行は下へ進むので、テンプレートの`x`は紙を下へ、`y`は紙の右端から左へ進みます。見開きは`y`に沿って右ページ、次に左ページと並び、のどはテンプレートを横切る線になり、`gutter`、`crossGutter`、ページ間の切り分けはこの軸で読みます。装飾は従来どおり実際の紙の上に置かれ、のどで切られます。横組みの本のために描いた横長の年表は、縦組みの本では回転して出ます。縦組みの本のテンプレートは、文章の流れの座標で書いてください（postext 1.38以降）。紙面を横に読ませたいカードには`writingMode: 'horizontal-tb'`を指定します。横組みで組まれ、縦組みのページの上で正立します（postext 1.39以降）。

### コネクター

コネクターは、枠どうしを結ぶ装飾の線です。樹形図の枝、組織図、年表から下ろす線、流れ図の矢印、注記から地図の一点を指す線などに使います。枠のボックスが確定してから置くので、長くなった文章、語の長い版、枠を動かしたグループにもついていきます。どの出力でもベクターの線として描くので、テンプレートに線の画像を用意する必要はありません。コネクターはページテンプレートかモジュールの`decoration`の要素です。柱と見出しのデザインには結ぶ枠がないので、そこに置いたコネクターは報告され（`unknownConfigValue`）、描かれません。postext 1.48以降。

```ts
      width: { value: 1.25, unit: 'pt' }, from: { to: '#raiz' }, to: [{ to: '#a' }, { to: '#b' }], endCap: 'arrow' },
```

```ts
  { kind: 'connector', id: 'a-lago', from: { to: '#nota', side: 'end' },

] },
```

**検査**：`to`が何も指さない端は`frameAnchorUnknown`（`…/from/to`または`…/to/<k>/to`）になり、省かれます。`[*]`は`to`の中で、繰り返す枠に対してだけ使えます。枠のどの画像にもない`anchor`は、コネクターのidを添えて`labelAnchorUnknown`になります。`routing`、`startCap`、`endCap`、`side`の選択肢にない語と、0から1の範囲外の`at`は`unknownConfigValue`です。0から1の数でない`opacity`も`unknownConfigValue`です（範囲外の数は範囲内に収められます）。

## 枠の見た目

写真カードのグリッドで札の色だけが違う場合や、1ページの囲みが十数色に分かれる場合でも、囲みスタイルとテンプレートは1つで済みます。色は名前の付いた見た目のリスト`frameLooks`に書き、Markdownはその見た目を使う内容ごとに名前を指定します。postext 1.50以降。

```ts
frameLooks: [
  { id: 'rojo', name: 'Red pill', background: { hex: '#e63946', model: 'hex' }, body: { color: { hex: '#ffffff', model: 'hex' } } },
  { id: 'verde', background: { hex: '#6a994e', model: 'hex' } },
  { id: 'marino', border: { color: { hex: '#264653', model: 'hex' } } },
]
```

- **パレット**：パレットの項目にリンクした色は、設定のほかの色と同じくパレットに従います。部のパレットやページの`palette`で色が替わります。

## ページテンプレートの警告

ほかの設定では、エンジンは知らないキーを無視します。ページテンプレートとラベルスタイルはそうではなく検査され、問題はすべて設定の警告として`postext check`とSandboxの**検査**パネルに出ます。これらの警告の`path`は、問題のある項目を指すJSONポインターです。たとえば`/pageTemplates/3/frames/2/style`、`/pageTemplates/0/variants/recto/frames/1/next`、`/resources/4/anchors/0/style`です。項目が継承されたものなら、ポインターはそれを書いたテンプレートを指します。存在しないidや名前を指す警告は、存在するもののうち最も近いものも示します。

テンプレート、枠、グループ、グリッド、`fit`、`overflow`、バリアント、ラベルスタイルのキーの綴り違いは`unknownConfigKey`になります。設定の選択肢にない語（`area`、`verticalAlign`、`exclude`、`wrap`、`takes`、`kind`、`align`、`writingMode`、`direction`、`fontStyle`、`textTransform`、`overlap`、`rowAlign`、コネクターの`routing`、端の印と`side`、引き出し線の端の印と`routing`）は`unknownConfigValue`になり、その設定は既定値のままです。`id`のないテンプレートや、`name`のない枠とグループは無視され、その項目に`unknownConfigValue`が出ます。枠の見た目（`frameLooks`）も同じように検査します。`id`のない見た目は無視され、枠の`look`にないキーは`unknownConfigKey`になります。
