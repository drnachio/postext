# Línea de comandos

**`postext` compone tu libro desde una terminal, un script o un agente.**

El [Sandbox](/es/sandbox) es donde escribes y diseñas un libro viéndolo. La línea de comandos toma
el mismo libro y genera sus archivos sin navegador: un PDF listo para imprenta, las páginas en HTML,
un EPUB, la imagen de una página o de todas, un documento de Word. También empaqueta y desempaqueta
archivos `.postext`, importa documentos de Word, describe un libro y lo revisa en busca de
problemas.

Es **un ejecutable autónomo** para cada sistema. Lleva dentro el motor de postext, los generadores
de PDF, EPUB, HTML y Word, el motor de dibujo de páginas (Skia), HarfBuzz para el árabe y otras
escrituras complejas, los perfiles ICC de imprenta y las fuentes predeterminadas (EB Garamond y Open
Sans). No hay que instalar ningún entorno de ejecución, paquete ni biblioteca, y la maquetación es
la misma que la del Sandbox: el mismo libro se reparte en las mismas páginas.

## Cómo conseguirlo

Con [Homebrew](https://brew.sh), en macOS o Linux:

```bash
brew install drnachio/postext/postext
```

Con [Scoop](https://scoop.sh), en Windows:

```powershell
scoop bucket add postext https://github.com/drnachio/scoop-postext
scoop install postext
```

Los dos instalan el ejecutable de la última versión como comando `postext`,
comprobado con su suma de verificación, y `brew upgrade postext` o
`scoop update postext` traen la siguiente. Sin gestor de paquetes, descarga
tú el archivo.

Cada versión de Postext publica los ejecutables en su
[GitHub Release](https://github.com/drnachio/postext/releases/latest), con
sus sumas de verificación (`SHA256SUMS`) y un `readme.txt`:

Cada archivo pesa entre 115 y 140 MB. El enlace
`https://github.com/drnachio/postext/releases/latest/download/<file>` da
siempre el más reciente.

En Linux o macOS:

```bash
curl -fL -o postext https://github.com/drnachio/postext/releases/latest/download/postext-linux-x64
chmod +x postext
./postext
```

Muévelo a una carpeta de tu `PATH` (`/usr/local/bin`, `~/.local/bin`) para
ejecutarlo como `postext` desde cualquier sitio. macOS pone en cuarentena un
archivo descargado con el navegador; quita la marca una vez:

```bash
xattr -d com.apple.quarantine postext-macos-arm64
```

En Windows, en PowerShell:

```powershell
Invoke-WebRequest https://github.com/drnachio/postext/releases/latest/download/postext-windows-x64.exe -OutFile postext.exe
.\postext.exe
```

Con Node.js instalado, `npx postext-cli` descarga de npm el ejecutable de tu
sistema y lo ejecuta, y `npm install -g postext-cli` lo deja instalado como
comando `postext`.

Sin argumentos, `postext` muestra su ayuda; `postext help <command>` enumera
las opciones de un comando.

## Un primer libro

Tres archivos Markdown en una carpeta forman un libro, con un capítulo cada uno, por orden de
nombre:

```bash
postext pdf chapters/ --name "Field notes" -o field-notes.pdf
```

El frontmatter del primer capítulo da al libro su título y su autor, y los valores predeterminados
del motor hacen el resto: dos columnas, una rejilla base, texto justificado y con separación
silábica, titulillos. Añade una configuración e imágenes cuando las necesites:

```bash
postext pdf chapters/ --config design.json --resources pictures/ -o field-notes.pdf
```

Un libro hecho en el Sandbox (**Libros → Descargar (.postext)**) funciona tal
cual:

```bash
postext pdf my-book.postext -o my-book.pdf
postext image my-book.postext --page 1 -o cover.png
```

## Qué puede ser un libro

Todos los comandos que leen un libro aceptan cualquiera de estas formas:

- **Un archivo `.postext`**: el paquete que el Sandbox exporta y abre (consulta
  [Paquetes](/es/docs/configuration-bundles#paquetes-archivos-postext)).
- **Una carpeta de libro**: un paquete desempaquetado, con su `preset.json`, sus capítulos, sus
  recursos y sus fuentes. Es lo que entrega la skill para agentes, y lo que escribe
  `postext unpack`.
- **Markdown suelto**: uno o varios archivos `.md`, con un capítulo cada uno en el orden en que se
  indican, o una carpeta cuyos archivos `.md` se toman por orden de nombre (`01-intro.md`,
  `02-method.md`…). En este caso:
  - `--config design.json`: la configuración, ya sea un objeto de
    configuración suelto o un `preset.json` completo;
  - `--resources pictures/`: las imágenes, cada una como una figura cuyo id es el nombre de su
    archivo sin la extensión (`map.png` es `::resource{id="map"}`); si la carpeta tiene un
    `resources.json`, es este el que las describe (ids, tipos, pies, texto alternativo), con la
    misma forma que los `resources` de un `preset.json`;
  - `--fonts fonts/`: los archivos de fuente que incluye el libro (TTF, OTF, WOFF2), identificados
    por el nombre de familia que indican sus tablas;
  - `--name "Title"`: el nombre del libro.

`--config` funciona también con un paquete o una carpeta: se combina con la configuración propia del
libro, por encima de ella. Un paquete multilingüe se lee en su propio idioma, salvo que `--locale`
pida otro (`--locale en`).

Cada comando escribe en la carpeta desde la que lo ejecutas, con el nombre de

la salida estándar.

### pdf

```bash
postext pdf book.postext -o book.pdf
postext pdf book/ --pdfx x4 --profile fogra51 -o book-print.pdf
postext pdf book/ --color-space grayscale --no-outlines
```

El PDF sigue los ajustes del propio libro (consulta
[Generación de PDF](/es/docs/configuration-fonts-colors-viewers#generación-de-pdf-configuración) y
[Producción para imprenta](/es/docs/configuration-fonts-colors-viewers#producción-para-imprenta-configuración));
estas opciones los cambian para una sola ejecución:

- `--pdfx none|x1a|x4`: la norma PDF/X para una imprenta.
- `--profile NAME|FILE`: el perfil ICC de salida, por nombre (`fogra39`,
  `fogra51`, `fogra52`, `swop5`, `gracol2006`, `snap2007`, `ifra26` y los
  demás perfiles de los ajustes de imprenta) o un archivo `.icc`.
- `--color-space rgb|cmyk|grayscale`.
- `--accessible` / `--no-accessible`: la estructura etiquetada para lectores
  de pantalla.
- `--no-outlines`: deja fuera los marcadores.
- `--page-negative`: páginas en negativo, para algunos flujos de imprenta.
- `--die-line page|none`: la línea de troquel de un libro con troqueles, en su propia plancha
  (`page`, por defecto) u omitida (`none`); véase
  [La línea de troquel en el PDF](/es/docs/special-inks-die-cuts#la-línea-de-troquel-en-el-pdf).

### html

```bash
postext html book.postext -o book.html
postext html book.postext -o site/ --mode single
```

Una ruta que termina en `.html` genera un único archivo con las imágenes y las fuentes dentro, fácil
de enviar. Cualquier otra ruta es una carpeta: `index.html` junto a `assets/`, que contiene las
imágenes, las fuentes y los vídeos alojados en el propio libro. `--assets embed|folder` elige una u
otra forma para cualquier ruta. Las páginas son las de la maquetación impresa, mostradas a tamaño de
pantalla: una al lado de otra (`--mode multi`, el valor predeterminado) o una debajo de otra
(`--mode single`). Las fuentes marcadas con `redistributable: false` se mencionan pero no se copian.
Si la familia indica un `fallback`, se escriben en su lugar las variantes de esa familia abierta,
con el nombre de la familia original (desde postext 1.43).

### epub

```bash
postext epub book.postext -o book.epub
postext epub book.postext --layout reflowable --cover cover.jpg
```

`--layout fixed` (el valor predeterminado) conserva cada página tal como se imprime, con el texto
seleccionable; `--layout reflowable` deja que el sistema de lectura vuelva a componer el texto para
su pantalla (consulta
[Libros EPUB](/es/docs/configuration-html-folio-epub#libros-epub-postext-epub)). La cubierta es la
miniatura del libro, salvo que `--cover` indique una imagen. Los metadatos del paquete (título,
autores, idioma, identificador) salen del frontmatter del primer capítulo, como en el Sandbox. Las
fuentes marcadas con `redistributable: false` no se copian; una familia que indica un `fallback` se
incrusta con las variantes de esa familia abierta, bajo su propio nombre (desde postext 1.43).

### image e images

```bash
postext image book.postext --page 12 -o page-12.png
postext image book.postext --page "#1" --dpi 300 -f jpeg -o cover.jpg
postext images book.postext -o pages/ --dpi 100
postext images book.postext --pages 1-10,iv -f webp --pattern "{chapter}-{label}"
```

Las páginas se indican **tal como se imprimen** (`12`, `iv`, un intervalo `7-9`) o **por su
posición** en el libro con `#` (`#1` es la primera página, sea cual sea el número que lleve impreso;
`#10-#20`; `#30-`, hasta el final). `--pages` acepta una lista separada por comas. Las imágenes se
dibujan como en la vista Canvas del Sandbox, así que una imagen muestra la página exactamente como
se maquetó, sin pasar por un PDF.

- `--format png|jpeg|webp` (o la extensión de `-o`), `--quality 1-100` para
  JPEG y WebP.
- `--dpi`: la resolución, 150 por defecto; de 72 a 100 basta para leer una
  página, 300 para imprenta.
- `--pattern`: los nombres de archivo de `images`, a partir de `{n}` (la posición; `{n:03}`,
  completada con ceros hasta tres cifras), `{label}` (el número impreso) y `{chapter}`; por defecto,
  `page-{n:03}`.
- `--print-preview`: la página tal como la reproducirá la imprenta, a través
  del perfil de salida, con el corte y el sangrado dibujados.
- `--jobs N`: cuántas imágenes se codifican a la vez (por defecto, tantas como
  procesadores tenga el ordenador).

### docx e import-docx

```bash
postext docx book.postext -o book.docx
postext docx book/ --variant semantic -o words.docx
postext docx book/ --variant facsimile -o pages.docx
postext import-docx book.docx book/ --dry-run
postext import-docx book.docx book/
postext import-docx manuscript.docx -o manuscript/ --locale es --report
```

`docx` escribe los documentos de Word que exporta el Sandbox (véase
[Sandbox › Documentos de Word](/es/docs/sandbox-books-saving#documentos-de-word))
y un tercero. `--variant formatted`, el valor por defecto, construye un
documento editable a partir del Markdown, con los encabezados, las listas, las
notas al pie, las tablas, las ecuaciones y las secciones propios de Word,
compuesto con el diseño del libro hasta donde Word lo permite y con las fuentes
del libro incrustadas (`--no-embed-fonts` solo las nombra); lo que no tiene
estructura en Word viaja como fuente en controles de contenido *Postext Source*.
`--variant semantic` escribe el mismo texto como solo contenido: un documento
sencillo (A4, una columna, Arial) en estilos de Word que dicen qué es cada
parte, sin nada del diseño de la página y sin fuentes incrustadas. Ninguno de
los dos necesita maquetar; los dos se abren en Word y en Google Docs, y los dos
vuelven con `import-docx`. `--variant facsimile` maqueta el libro como lo hace
`pdf` y escribe cada página como una sección de Word, con cada línea en un
cuadro de texto fijo y las fuentes incrustadas: un archivo para mirar la
maquetación en Word de escritorio, no para editar ni para Google Docs. Una
familia que el libro no puede ceder (`redistributable: false` en `customFonts`)
se deja fuera y entra su alternativa abierta, como en el EPUB; una fuente cuya
licencia prohíbe incrustarla, una con contornos PostScript y una fuente variable
se notifican y solo se nombran. En `build`, `--docx ARCHIVO` escribe el mismo
archivo, con `--docx-variant` y `--no-docx-fonts`. Desde postext 1.68;
`--template` ya no se aplica a `docx` ni a `build`.

Con un libro detrás del archivo, `import-docx` trae de vuelta las correcciones
hechas en un documento que `docx` exportó desde ese libro. Lee el mapa que lleva
el archivo, compara el texto con la copia de los capítulos hecha en la
exportación y combina cada corrección con el libro tal como está ahora: los
archivos de capítulo de una carpeta, de un `.postext` o de Markdown suelto, y el
texto de los recursos (pies, notas, texto alternativo, celdas de tabla) en
`preset.json`, o en el `resources.json` de `--resources DIR` si es Markdown
suelto. En un libro con varios idiomas, `--locale` indica la edición desde la
que se exportó el archivo, y la corrección del texto de un recurso va al bloque
`localized` de esa edición. Cada corrección se notifica en una línea propia:

- `applied`, con el archivo y la línea a los que fue;
- `conflict`: el texto también cambió en el libro desde la exportación, el
  capítulo o el recurso ya no existe, o dos correcciones se solapan;
- `rejected`: texto que genera el propio libro (números, etiquetas de pie, lo
  que un estilo de cita escribe a partir de la bibliografía) o un formato que
  cruza el marcado de Postext.

Una corrección dentro de una cita vuelve a ella cuando cae en una parte que
escribió el autor: el localizador, o las palabras antes o después de la obra.
En `[véase también @simmons1991, 346–47]`, un intervalo de páginas corregido a
`346–48` en Word queda `[véase también @simmons1991, 346–48]`. La línea
nombra la cita (`citation simmons1991: locator "7" → "8"`). Un cambio en el
nombre del autor, el título o *Ibid.* se rechaza, y una parte que se imprime
de otro modo que como está escrita (`346--47` impreso `346–47`) se rechaza con
su lugar en el libro, para cambiarla allí.

Los cambios con control de cambios se toman como aceptados, y los comentarios se
enumeran con su autor y su lugar, pero no se escriben. El código de salida es 3
si una corrección no se aplicó. `--dry-run` (`-n`) imprime el informe y un diff
unificado de cada archivo que cambiaría, y no escribe nada. Cada archivo se
escribe junto a su destino y se renombra encima, así que una ejecución
interrumpida nunca deja medio capítulo; un archivo de capítulo que cambió
mientras corría la importación se deja como está, con un aviso
`docx.fileChanged`. `-o` no va con un libro. Con `--json`, la respuesta lleva
`variant` (la exportación que es el archivo: `formatted`, `semantic` o
`facsimile`), `writer` (el generador que nombran sus propiedades), `exportId`,
`edits` (cada una con `status`, `reason`, `kind`, `before`, `after` y `at`, y
dentro de una cita `citation` y `citationPart`), `comments`, `files` y, en una
prueba en seco, `diff`.

Un archivo editado en Google Docs y descargado como `.docx` también vuelve. Docs
no guarda el mapa ni la copia de los capítulos; la importación escribe el mapa
de nuevo a partir del libro, y lo dice en el informe. Como ese archivo no lleva
ninguna copia del texto exportado, se compara con el libro tal como está ahora.
Si el libro cambió desde la exportación, el informe avisa de ello, y un cambio
hecho entretanto en el libro puede aparecer como una edición que lo deshace.
Importa un archivo de Docs en el libro del que se exportó, antes de cambiar ese
libro; un archivo guardado por Word conserva su mapa y se combina con los
cambios posteriores del libro. Docs elimina además el marcador oculto de un
texto que se sustituye entero (un encabezado, una celda de tabla, un pie, el
título de un recuadro, una nota al pie). La importación encuentra ese texto por
su lugar entre sus vecinos, así que un encabezado sigue siendo un encabezado y
un pie va a su recurso. Cuando eso no se puede decidir, por ejemplo porque
también se escribió un párrafo a su lado y nada los distingue, el informe
muestra una eliminación y una adición en su lugar. Importar el mismo archivo por
segunda vez no trae nada.

Sin un libro, `import-docx` convierte cualquier documento de Word en un libro
nuevo: un capítulo en cada encabezado de nivel 1 (`--no-split` deja uno solo),
las imágenes y las tablas como recursos, y `--report` imprime el informe de
calidad que muestra el Sandbox (estilos en uso, formato directo, numeración
escrita a mano…). `--template` toma una plantilla de importación (un `.json`
guardado desde el Sandbox o un `.docx` que la contenga).

El espaciado entre caracteres es una propiedad del estilo, no del texto, así que no aparece en el
Markdown. `docx` escribe el `letterSpacing` de los estilos de párrafo, de los estilos de encabezado
y de los niveles de encabezado como espaciado entre caracteres del estilo de Word, e `import-docx`
lo recupera en em del cuerpo del estilo: lo fija como `letterSpacing` en los estilos del libro que
no tienen ninguno (los estilos de párrafo y de encabezado del archivo de `--config` que corresponden
a los estilos de Word, y los niveles de encabezado), y deja como están los espaciados que el libro
ya define. Con `--json`, `styleTracking` enumera lo que se aplicó (`applied`) y lo que se dejó como
estaba (`skipped`). Desde postext 1.39.

### idml

```bash
postext idml libro/ -o libro.idml
postext idml libro.postext -o libro.idml --images link
postext idml libro/ -o out/libro.idml --lines reflow --fonts
```

`idml` maqueta el libro como lo hace `pdf` y escribe las páginas como un
paquete de InDesign Markup, para terminarlo en InDesign: las páginas en
pliegos a ambos lados del lomo en un libro con márgenes simétricos (una página
por pliego en cualquier otro), filetes, recuadros, trazados e imágenes como
elementos de página, las tablas como tablas de InDesign, el texto de cada
marco de una página compuesta como un marco de texto con su propia historia
(los marcos encadenados con `next` comparten una), los estilos de recuadro
como estilos de párrafo y los colores CMYK de autor como muestras. Los chips
con campo de formulario pasan a ser campos de formulario de InDesign. `--lines
keep` (el valor por defecto) termina cada línea donde la terminó Postext, así
que InDesign muestra las mismas líneas que el PDF; `--lines reflow` deja los
párrafos al componedor de InDesign, y los cortes de línea pueden variar.
El texto corrido de las páginas compuestas en columnas va en un solo artículo, enlazado por un marco por columna, que el importador lee como libro de flujo; `--text frames` escribe en su lugar un marco y un artículo por bloque (desde postext 1.85.0). `--spreads facing` o `--spreads single` empareja las páginas, o no, digan lo que digan los márgenes.
`--images link` deja las imágenes junto al archivo, en `Links/`, en lugar de
dentro. `--fonts` escribe los archivos de fuente de las variantes usadas junto
al paquete, en `Document fonts/`, donde InDesign los encuentra para ese
documento; necesita que `-o` nombre un archivo, y una familia que el libro no
puede redistribuir se deja fuera con un aviso. Lo que el paquete no puede
llevar como está en el libro (los puntos de énfasis del texto vertical, el marco
redondeado de una tabla) se notifica como aviso `idml.*`. El generador es el paquete
`postext-idml`: véase [Uso programático › Paquetes de
InDesign](/es/docs/configuration-programmatic-usage#paquetes-de-indesign-postext-idml).
En `build`, `--idml ARCHIVO` escribe el mismo paquete, con `--idml-images`, `--idml-lines`, `--idml-spreads`, `--idml-text` y `--idml-fonts`.
Desde postext 1.71; `--lines` y `--fonts`, desde 1.76, y `--spreads`, desde 1.78.

### import-idml

```bash
postext import-idml libro.idml -o libro/
postext import-idml libro.idml -o libro.postext --layout flow --links pictures/
postext import-idml libro.idml --report --json
postext import-idml libro.zip -o libro.postext
postext import-idml libro.zip --document Libro/Libro.idml -o libro/
```

`import-idml` lee un paquete de InDesign Markup y escribe un libro nuevo, en una carpeta o en un `.postext`: los capítulos en Markdown, la configuración que dan los estilos y las páginas del documento, y sus imágenes y tablas como recursos. Un `.indd` no se lee: guárdalo antes desde InDesign como InDesign Markup. `--layout pages` sigue el documento página a página con páginas compuestas, cada marco donde estaba; `--layout flow` escribe un libro de texto corrido, en orden de lectura y con los estilos del documento, para que Postext lo maquete de nuevo; `auto` (el valor por defecto) elige uno de los dos y dice por qué. El archivo también puede ser un armado de InDesign comprimido, la carpeta que hace **Archivo › Empaquetar** con **Incluir IDML** marcado, enviada como un solo `.zip`: la orden importa su IDML con las imágenes de su carpeta `Links/` y pone en el libro los archivos de fuente de su carpeta `Document fonts/`. Si el zip guarda varios documentos IDML, `--document` nombra el que se importa por su ruta dentro del zip (`--document Libro/Libro.idml`); sin esa opción, la orden los enumera. Un armado que solo guarda el `.indd` se rechaza, con el modo de obtener el IDML. Las imágenes enlazadas se leen primero de `--links`, luego del armado y luego de la carpeta del archivo y de su `Links/`, y las que no aparecen se enumeran. También se enumeran las fuentes que nombra el documento: un `.idml` suelto no lleva archivos de fuente, así que hay que darlos con `--font-dir` al generar el libro. Con un armado, una fuente que esté en `--font-dir` entra en el libro en lugar del archivo del armado. Una colección de fuentes (`.ttc`, `.otc`), en el armado o en `--font-dir`, se separa en caras sueltas, y solo entran las caras que usa el libro (desde postext 1.83).

Un libro exportado desde Postext vuelve con las mismas líneas. Un documento hecho en InDesign se lee con pérdidas: el comando imprime el veredicto (`faithful`, `approximate` o `lossy`), los recuentos y lo que se perdió o se aproximó; `--report` añade las notas y cómo se leyó cada estilo de párrafo, y `--json` lo lleva todo como datos. `--hidden`, `--pasteboard` y `--non-printing` leen también las capas y los objetos ocultos, la mesa de trabajo y los objetos no imprimibles; `--conditions all` lee todo el texto condicional, `--changes reject` lee los cambios registrados como si se hubieran rechazado y `--no-masters` deja fuera los elementos de las páginas maestras. `--name` y `--locale` dan el título y el idioma. El importador es `idmlToPostext`, del paquete `postext-idml`: véase [Uso programático › Paquetes de InDesign](/es/docs/configuration-programmatic-usage#paquetes-de-indesign-postext-idml). La importación copia el documento tal como está; para portar un libro que vas a conservar, con sus reglas de maquetación deducidas, usa en su lugar la skill para agentes (véase [InDesign: importar, exportar y portar](/es/docs/indesign)).

### design

```bash
postext design book.postext -o novel.postext
postext design book/ --parts page,text,headings -o type.postext
postext pdf other/ --design novel.postext -o other.pdf
```

Un archivo de diseño guarda el diseño de un libro y nada de su texto: los ajustes de las partes pedidas (los grupos del panel Diseño, véase [Archivos de diseño](/es/docs/configuration-bundles#archivos-de-diseño)) con los archivos de fuente y el perfil de color que nombran. Una fuente marcada como no redistribuible se queda fuera. `--parts` toma solo algunas partes, separadas por comas; `--design-name`, `--id` y `--description` dan nombre al diseño. El mismo libro da siempre los mismos bytes.

`--design ARCHIVO`, una opción de todas las órdenes que leen un libro, pone el libro en un archivo de diseño o en el diseño de otro libro, antes de `--config` y `--set`: los ajustes de sus partes sustituyen a los del libro, los estilos con nombre se combinan por id y las fuentes del diseño se suman a las del libro. `--design-parts` toma solo algunas de sus partes. El panel Diseño del Sandbox importa y exporta los mismos archivos.

`--composition ETIQUETA`, también una opción de todas las órdenes que leen un libro, pone las reglas de composición de la tradición de un idioma después de `--design` (desde postext 1.80): `es`, `en-US` (o `en`), `en-GB`, `fr` o `de`, o `auto` para el idioma del libro. Las reglas de la convención sustituyen a las del libro y las demás vuelven a sus valores por defecto; la tipografía se queda como está. Véase [Convenciones de composición](/es/docs/configuration-text#convenciones-de-composición).

```bash
postext pdf book/ --composition auto -o book.pdf
postext design book/ --composition es --parts composition -o house-rules.postext
```

### pack y unpack

```bash
postext pack my-book/ -o my-book.postext
postext pack 01.md 02.md --name "Notes" --config design.json --resources img/ -o notes.postext
postext unpack my-book.postext -o my-book/
```

`pack` comprime en zip una carpeta de libro tal como está, o crea un paquete a partir de Markdown
suelto. La misma entrada da siempre los mismos bytes, así que se pueden comparar paquetes o calcular
su hash. Con Markdown suelto, `--id`, `--description` y `--thumbnail FILE` (una
imagen de cubierta) fijan el id, la descripción y la miniatura del paquete; por defecto, el id
es el nombre convertido en slug. Una carpeta conserva lo que diga su `preset.json`. Un libro que no indica cubierta recibe su primera página como tal (`thumbnail.jpg`, 1024 px en su lado largo), la imagen que un gestor de archivos puede mostrar para el fichero; `--no-auto-thumbnail` la omite. `unpack` no escribe en una carpeta que no esté vacía, salvo que se indique `--force`.

### info y check

```bash
postext info book.postext --pages
postext check book.postext
postext check chapters/ --strict --json
```

`info` enumera los capítulos (título, palabras, archivo y, con `--pages`, sus páginas), los recursos
y cada familia de fuentes con su procedencia (el libro, una carpeta, el ejecutable, la caché de
descargas o la fuente de reserva). Si el libro indica dónde empieza (`start` en `preset.json`: un
extracto que empieza en la página 58, en el capítulo 4), también lo muestra, y todos los comandos
maquetan el libro desde ese punto.

`check` maqueta el libro e informa de lo mismo que muestra el panel **Revisión** del Sandbox:
Markdown que no se cierra; recursos, directivas y estilos desconocidos; recuadros que la maquetación
tuvo que forzar; fuentes que faltan; ajustes que el motor tuvo que sustituir y, en un libro
preparado para imprenta (o con `--preflight`), la verificación previa a la impresión: imágenes de
baja resolución, filetes demasiado finos, texto pequeño en varias tintas, tinta por encima del
límite, texto cerca del corte. También enumera el texto que se lee mal sobre su fondo (`contrast`),
una vez por cada par de colores, con la relación de contraste en pantalla y, para imprenta, sobre el
papel del perfil de salida. Cada problema indica el archivo del capítulo, la línea y la página. El
código de salida es 3 si se encuentra un error o, con `--strict`, cualquier aviso.

También avisa de los textos de los diseños de la configuración que contienen el texto del libro en
lugar de marcadores (`contentInConfig`), una vez por cada estilo de encabezado, titulillo o diseño
de parte, con la ruta de cada texto: pasa ese texto al Markdown, o añade el título o el nombre de la
editorial a `checks.contentInConfig.allow`.

En un libro con plantillas de página, `check` informa además del texto que no cabe en su marco (`frameOverflow`, con los pasos que probó la escalera de reajuste y los cambios que lo resolverían), de una historia que supera las páginas que un marco puede añadir (`frameContinuationLimit`), de un salto a una página que no viene después (`continueTargetMissing`), de los rótulos de figura que no se pueden dibujar o que chocan entre sí (`labelAnchorUnknown`, `anchorUnlabelled`, `labelOverflow`, `labelOverlap`), de los marcos tapados por otros marcos o que se salen de su borde (`frameCovered`, `frameOutsideArea`), de más tarjetas de las que admite una rejilla (`repeatOverflow`) y de los módulos que una página no puede colocar (`moduleUnknown`, `moduleAsPage`, `moduleNested`, `moduleNameRejected`). Después de los avisos imprime una línea `reflow` por cada página compuesta con sucesos, y `--json` incluye los pasos, las propuestas y el registro de recomposición como datos. Consulta [Páginas compuestas › Avisos](/es/docs/composed-pages#avisos) y [Registro de recomposición](/es/docs/composed-pages#registro-de-recomposición).

### build y --watch

```bash
postext build book/ --pdf out/book.pdf --html out/book.html --images out/pages --pages 1-4
postext build chapters/ --pdf book.pdf --watch
```

`build` maqueta el libro una vez y escribe todas las salidas que indiques (`--pdf`, `--html`,
`--epub`, `--images`, `--docx`, `--idml`), con las opciones de cada comando. `--watch` sigue en marcha: cuando
cambia un capítulo, la configuración o una imagen, el libro se vuelve a maquetar con las fuentes y
el motor ya cargados (normalmente, en una fracción de segundo para un capítulo) y las salidas se
reescriben. Si al guardar el libro queda roto, se muestra el error y se conservan los últimos
archivos correctos.

## Fuentes

Un libro que incluye sus fuentes (un paquete, o `--fonts` con Markdown suelto) se compone con ellas
y con ninguna otra. Para cada familia que indica la configuración y que el libro no incluye,
`postext` busca, por este orden:

1. en las carpetas indicadas con `--font-dir`;
2. entre las fuentes compiladas en el ejecutable: EB Garamond y Open Sans, las predeterminadas del
   motor;
3. en la caché de descargas;
4. en [Google Fonts](https://fonts.google.com), que da archivos TrueType
   estáticos completos, o en [Fontsource](https://fontsource.org) si Google
   Fonts no tiene la familia (Commit Mono, FiraGO); se guardan en la caché,
   así que cada familia se descarga una sola vez.

Si la familia no tiene un peso, se usa la variante que elegiría un navegador (la selección de
fuentes de CSS: por encima de 500, primero las más gruesas; por debajo de 400, primero las más
finas; así, el 600 de una familia con 400 y 700 es su 700, y el 550 también), y si no tiene una
inclinación, se usa su redonda. En ambos casos la variante se usa tal cual, tanto en las imágenes de
página como en el PDF: una fuente de titulares con un solo peso conserva sus propias letras para la
negrita, y una familia sin cursiva conserva su redonda para la cursiva.

Se descargan los pesos que indica la configuración: redonda, negrita y sus cursivas para cada
familia, y cualquier otro peso que fije un ajuste, incluido el de la negrita
(`bodyText.boldFontWeight: 600` pide la variante de peso 600). Si un peso que la familia sí tiene no
se pudo cargar (sin conexión y sin archivo en la caché, una descarga fallida, una carpeta de fuentes
sin el archivo), el texto se compone con la variante de la familia que elige la misma regla en su
lugar, y `postext check` lo muestra como aviso `fontFallback`: sus líneas pueden cortarse de otra
manera que en el Sandbox.

Un carácter para el que una fuente no tiene glifo se dibuja con otra fuente. `postext check` lee la tabla `cmap` de cada fuente que carga y muestra esos caracteres una vez por fuente para todo el libro como aviso `glyphFallback`; con `--json`, su `data` lleva los caracteres y cuántos son.

La caché está en `~/.cache/postext` (`%LOCALAPPDATA%\postext\cache` en Windows); `POSTEXT_CACHE_DIR`
o `--cache-dir` la cambian de sitio. `--offline` se salta la descarga. Una familia que no se
encuentra en ningún sitio se compone en EB Garamond con su propio nombre, para que la maquetación y
el PDF sigan coincidiendo, y un aviso `missingFont` la menciona. `postext info` muestra de dónde
salió cada familia.

Un paquete que no incluye los archivos de una familia con licencia puede indicar para ella una familia abierta de ancho parecido (`fallback` en las `fonts` del manifiesto, desde postext 1.42). En ese caso, `postext` busca esa familia siguiendo los pasos anteriores y compone las variantes que el libro no incluye con las suyas del mismo peso e inclinación, con el nombre de la familia con licencia, de modo que la maquetación se parece a la que se obtiene con los archivos originales y `postext check` no da el aviso `missingFont` para ella. Una familia que el libro incluye solo en parte toma del `fallback` únicamente las inclinaciones para las que no tiene variante. El PDF incrusta la variante abierta.

## Para scripts y agentes

La línea de comandos está hecha para que la manejen otros programas, también
los agentes de programación.

- **`--json`** imprime un objeto JSON en la salida estándar cuando termina el comando; todos los
  mensajes van a la salida de errores. El informe enumera lo que se escribió, las páginas, cada
  aviso con su origen y cuánto tardó cada paso (en milisegundos):

```json
{
  "ok": true,
  "command": "pdf",
  "version": "1.22.1",
  "book": { "name": "notes", "id": "notes", "locale": "en", "chapters": 2 },
  "pages": 3,
  "outputs": [{ "kind": "pdf", "path": "notes.pdf", "bytes": 29746, "pages": 3 }],
  "warnings": [
    {
      "kind": "unknownResourceId",
      "severity": "warning",
      "message": "Unknown resource id \"map\" in ::resource — nothing is embedded (offset 26)",
      "at": "notes/02-more.md:5"
    }
  ],
  "timings": { "read": 13, "fonts": 8.4, "math": 28.2, "layout": 51.6, "pdf": 132.1, "total": 1638 },
  "exitCode": 0
}
```

- **Códigos de salida**: `0` terminado, `1` fallido, `2` uso incorrecto (una
  opción desconocida, una entrada que falta), `3` `check` encontró errores (o
  avisos, con `--strict`), o `import-docx` dejó fuera una corrección de Word.
- **Sin preguntas.** Nunca espera una respuesta; si una carpeta no está vacía, se rechaza en lugar
  de preguntar qué hacer.
- **Salida estándar**: `-o -` escribe ahí un PDF, una imagen o un paquete,
  para pasarlo por una tubería a otro programa.
- **Velocidad.** El ejecutable arranca en unas centésimas de segundo. Un libro corto se convierte en
  PDF o en imagen de página en bastante menos de un segundo; uno largo tarda lo que tarde su
  maquetación (una novela ilustrada de 140 páginas, unos diez segundos). Para ver unas pocas páginas
  de un libro largo, combina `--chapters` con `image` o con `images --pages`. Para trabajar en un
  libro a lo largo de muchos cambios, deja `postext build --watch` en marcha y lee sus salidas.

La [skill para agentes](/es/docs/skill) usa la línea de comandos para generar imágenes de las
páginas en las que está trabajando y para revisar un libro portado.

## Python

`pip install postext` convierte la línea de comandos en una biblioteca de
Python. El paquete es Python puro, sin dependencias, y su versión es la de
postext. La primera vez que ejecuta un comando descarga el ejecutable de tu
sistema de la GitHub Release de esa versión, lo comprueba con `SHA256SUMS` y lo
guarda en la caché de arriba, en `bin/<versión>/`. Si `POSTEXT_BIN` apunta a un
ejecutable que ya tienes (de Homebrew, de Scoop o compilado por ti), no se
descarga nada.

```python
import postext

report = postext.pdf("book.postext", out="book.pdf", set={"page.dpi": 300}, locale="es")
print(report.output.pages)
for warning in report.warnings:
    print(warning.kind, warning.at, warning.message)

pdf = postext.pdf_bytes(open("book.postext", "rb").read())
```

- **Una función por comando**: `pdf`, `html`, `epub`, `image`, `images`,
  `docx`, `idml`, `import_docx`, `import_idml`, `design`, `pack`, `unpack`,
  `info`, `check` y `build`. Las opciones conservan su nombre, con guiones
  bajos (`color_space`, `font_dirs`, `dry_run`). `set` recibe un diccionario,
  `config` un archivo o un diccionario, `chapters` un número, una lista, un
  `range` o `"1,3-5"`. Toda función que lee un libro admite `design=`, un
  archivo de diseño como ruta o como bytes, `design_parts=`, una lista o
  `"page,text"`, y `composition=`, una etiqueta de idioma o `"auto"`.
- **Informes como objetos.** Cada función ejecuta su comando con `--json` y
  devuelve el informe: `outputs`, `pages`, `timings` y `warnings`, cada aviso
  un `Diagnostic` con `kind`, `severity`, `message`, `at` y `page`. `info`
  añade `chapters`, `resources` y `fonts`; `check` añade `passed`,
  `error_count` y `warning_count`; `design` añade `name` y `parts`;
  `import_idml` añade `layout`, `reason`, `chapters`, `quality`, `fonts`,
  `missing_links` y `package`.
- **Errores como excepciones.** Un fallo lanza `PostextError`; una opción
  equivocada, `UsageError`. Cuando `check` encuentra errores lanza
  `ProblemsFound`, cuyo `report` los enumera; con `raise_on_problems=False`
  devuelve el informe.
- **Bytes.** Un libro puede darse como los bytes de un paquete `.postext`. Con
  `out="-"` el archivo vuelve en `report.content`; `pdf_bytes`, `html_bytes`,
  `epub_bytes`, `image_bytes`, `docx_bytes`, `idml_bytes`, `pack_bytes` y
  `design_bytes` lo devuelven directamente.
- `postext.Postext(binary, cwd=…, timeout=…)` usa un ejecutable concreto, y
  `python -m postext …` es la propia línea de comandos.

Cada llamada arranca el ejecutable de nuevo. El
[README](https://github.com/drnachio/postext/tree/main/packages/postext-python) del paquete recoge todas las opciones.

## Cómo está hecho

La línea de comandos es el paquete `postext-cli` del
[repositorio](https://github.com/drnachio/postext/tree/main/packages/postext-cli).
[Bun](https://bun.sh) lo compila, junto con el motor y sus generadores, en un ejecutable para cada
sistema, y [Skia](https://skia.org) (a través de `@napi-rs/canvas`) mide y pinta el texto, como hace
el canvas del navegador en el Sandbox. Una ilustración SVG que contiene un mapa de bits (un PNG o un
JPEG incrustado como URI de datos, que es como `pdftocairo -svg` escribe las ilustraciones extraídas
de un PDF) se dibuja, en cambio, con [resvg](https://github.com/linebender/resvg), porque el
renderizador de SVG de Skia omite esas imágenes. En cada versión, los ejecutables se compilan, se
prueban en Linux, Alpine, macOS y Windows y se adjuntan a la GitHub Release; npm recibe
`postext-cli` y un paquete `postext-cli-<system>` por cada ejecutable.

Para ejecutarlo desde una copia del repositorio:

```bash
pnpm install
pnpm --filter postext-cli start pdf book.postext
pnpm --filter postext-cli build:bin --current
```

El primero lo ejecuta desde sus fuentes; el segundo escribe el ejecutable de
este ordenador en `packages/postext-cli/bin/`.

## Diferencias con el Sandbox

- **HTML** es la maquetación impresa mostrada a tamaño de pantalla. La pestaña **HTML** del Sandbox,
  en cambio, vuelve a componer el texto para la ventana.
- **`--chapters`** compone los capítulos por separado: sus números de página
  empiezan de nuevo, mientras que el Sandbox continúa la numeración del libro.
- **Las fuentes** salen del libro, de tus carpetas, del ejecutable, de Google
  Fonts o de Fontsource (para una familia que Google Fonts no tiene), nunca de
  las fuentes instaladas en el ordenador, así que un libro sale igual en
  cualquier máquina.
- **El idioma del texto** es, en un navegador, el del propio documento
  (`bodyText.shapingLanguage: 'document'`, el valor predeterminado desde postext 1.30). El canvas de
  Skia acepta un idioma, pero da forma al texto sin tenerlo en cuenta, así que la línea de comandos
  mide las formas del idioma predeterminado de cada fuente y maqueta siempre sus libros con
  `shapingLanguage: 'host'`, diga lo que diga la configuración; su PDF y sus imágenes de página
  dibujan esas mismas formas. Un libro cuya fuente tiene formas propias de un idioma (una `l·l`
  catalana, una `fi` turca, las cifras de una fuente china en un libro en inglés) se compone aquí
  con las formas predeterminadas. Lo que `'document'` mide de otra manera (las partes de una palabra
  cortada al final de una línea, una palabra de derecha a izquierda, un texto de diseño) se mide
  aquí como lo mide `'host'`, así que una línea puede cortarse por una palabra distinta que en el
  Sandbox.
