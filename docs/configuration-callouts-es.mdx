# Configuración: recuadros


## Estilos de recuadro

La propiedad `calloutStyles` declara los estilos de recuadro con nombre que el documento aplica mediante un contenedor `:::callout{type="…"}`: notas, consejos, advertencias, objetivos de aprendizaje o cualquier contenido separado del texto corrido en un recuadro coloreado o con borde. Por defecto se incluye un estilo neutro, `note` (fondo gris claro, sin borde, sin franja, sin icono, sin título), de modo que `:::callout` funciona sin configuración alguna; declarar `calloutStyles` sustituye esa lista por defecto.

```ts
const config: PostextConfig = {
  calloutStyles: [
    { id: 'note', name: 'Nota' },
    {
      id: 'objectives',
      name: 'Objetivos de aprendizaje',
      title: 'Objetivos',
      stripe: { enabled: true, side: 'left' },
      icon: { kind: 'glyph', glyph: '✓' },
      titleStyle: { textTransform: 'uppercase' },
      lists: { bulletChar: '–' },
    },
    {
      id: 'warning',
      title: 'Advertencia',
      backgroundEnabled: false,
      border: { enabled: true, color: { hex: '#AA0000', model: 'hex' }, width: { value: 1, unit: 'pt' } },
      borderRadius: { value: 1, unit: 'mm' },
      titleStyle: { color: { hex: '#AA0000', model: 'hex' } },
    },
  ],
};
```

```md
:::callout{type="objectives"}
- Describir las partes de la linterna.
- Recortar la mecha al anochecer.
:::

:::callout{type="warning" title="No toques la lente"}
El cristal sigue caliente una hora después de apagar la llama.
:::
```

### Esquinas, lados y pestañas unidas

Un recuadro no tiene por qué ser un rectángulo con cuatro esquinas iguales y un solo borde. Desde postext 1.48, un estilo puede redondear unas esquinas y otras no, dibujar su borde solo en algunos lados y hacer que la pestaña salga del recuadro como una sola forma: la ficha de un libro de texto cuya pestaña de título y cuyo cuerpo son un único contorno, dibujado por el estilo y no pintado en una imagen detrás de la página.

```ts
calloutStyles: [
  // Redondeado solo arriba, con un filete sobre el recuadro y un pie más grueso.
  { id: 'ficha', background: { model: 'hex', hex: '#fff4d6' },
    borderRadius: { topLeft: { value: 3, unit: 'mm' }, topRight: { value: 3, unit: 'mm' } },
    border: { enabled: false, color: { model: 'hex', hex: '#c58b00' }, width: { value: 0.75, unit: 'pt' },
      sides: { top: { enabled: true }, bottom: { enabled: true, width: { value: 2, unit: 'pt' } } } } },
  // Una tarjeta cuya pestaña sale de su borde superior.
  { id: 'tarjeta', background: { model: 'hex', hex: '#ffffff' }, borderRadius: { value: 3, unit: 'mm' },
    border: { enabled: true, color: { model: 'hex', hex: '#2a6f97' }, width: { value: 1, unit: 'pt' } },
    label: { position: 'top-left', inset: { value: 4, unit: 'mm' }, joined: true, fillet: { value: 2, unit: 'mm' },
      color: { model: 'hex', hex: '#2a6f97' } } },
]
```

- **Esquinas.** `borderRadius` es una medida para las cuatro esquinas, o `{ topLeft, topRight, bottomRight, bottomLeft }`. La esquina que no aparece en el objeto queda en ángulo recto. Las esquinas son las de la hoja. Dos esquinas nunca ocupan más que el lado que las separa; si hace falta, cada una cede en proporción.
- **Lados.** `border.sides.top`, `right`, `bottom` y `left` admiten `enabled`, `color` y `width`, y cada campo que no se indica es el del borde completo. Un recuadro con borde solo arriba es `border: { enabled: false, sides: { top: { enabled: true } } }`, o `enabled: true` con los otros tres lados desactivados. El borde interior de un lado sigue su grosor, así que una esquina redondeada entre un lado fino y uno grueso se curva como la dibuja CSS.
- **Pestaña unida.** Con `label.joined: true`, la pestaña y el recuadro tienen un solo contorno, un solo fondo (el `background` del recuadro; el `background` propio de la pestaña no se pinta) y un solo borde que rodea la pestaña. La pestaña se apoya en el borde, fuera del recuadro en toda su altura: su `offset` debe ser `0` (otro valor se notifica como `unknownConfigValue` y se lee como `0`). Sus esquinas exteriores toman el radio de la esquina del recuadro a la que se pega, y `fillet` redondea las esquinas interiores donde se une al recuadro (por defecto, ese mismo radio). Una pestaña a ras del lado del recuadro (con un `inset` de menos de medio píxel) sube en línea recta desde ese lado. Da a las palabras un color que se lea sobre el fondo del recuadro (`label.color`), porque la pestaña ya no tiene fondo propio. Con `label.ownBackground: true`, una pestaña unida se pinta con el `background` propio de la etiqueta, sobre el relleno del recuadro y bajo el borde, de modo que una pestaña blanca puede apoyarse en un recuadro teñido, o una de color en un recuadro sin relleno.
- **Esquinas de la pestaña.** `label.borderRadius` da a la pestaña esquinas propias: una longitud, o `{ topLeft, topRight, bottomRight, bottomLeft }` sobre las esquinas de la hoja, como el `borderRadius` del recuadro. Una pestaña separada del recuadro es recta si no las fija. Una pestaña unida redondea con él sus dos esquinas exteriores (`topLeft` y `topRight` en una pestaña arriba, `bottomLeft` y `bottomRight` abajo); sin valor, toman el radio de la esquina del recuadro. Los empalmes conservan `fillet` en ambos casos.
- **Pestañas al pie.** `position: 'bottom-right'`, `'bottom-left'`, `'bottom-start'` o `'bottom-end'` cuelga la pestaña del pie del recuadro, suelta o unida: es la pestaña superior dada la vuelta, `offset` por debajo del pie y con el `rule` a lo largo del pie. No hay pestañas laterales: las palabras de una pestaña van en horizontal.

Todas las salidas dibujan estas formas: el canvas y el PDF como contornos vectoriales, y el visor HTML y el EPUB de maquetación fija con CSS por esquina y por lado. El EPUB de maquetación fluida escribe las esquinas y los lados en su CSS y compone una pestaña unida como una pestaña normal. El `look.border.color` de un marco cambia el color de todos los lados, y la paleta de una parte cambia el de cada uno. Un estilo cuyas esquinas y lados son todos iguales se maqueta igual que antes.

### Un glifo en la pestaña

`label.icon` puede poner un carácter de una fuente en lugar de una imagen: `kind: 'glyph'` con `glyph: '◉'`. label: {
```ts
  position: 'top-left', background: { model: 'hex', hex: '#0885bf' }, color: { model: 'hex', hex: '#ffffff' },
  icon: { kind: 'glyph', glyph: '◉', placement: 'inside', scale: 1.1 },
}
```

### Estilos basados en otro

`extends` indica otro estilo de `calloutStyles`, y todo campo que el estilo no fija lo toma de él. Los objetos como `padding`, `border`, `titleStyle` o `fixed` se combinan clave a clave, así que un estilo puede cambiar solo un lado del relleno o solo `fixed.offset`; un color o una longitud se toman enteros; `id` y `name` nunca se heredan. Un estilo base puede basarse a su vez en otro. Un libro con recuadros en muchos sitios guarda un estilo para su aspecto y un estilo mínimo por sitio:

```ts
calloutStyles: [
  {
    id: 'caja',
    background: { model: 'hex', hex: '#dff0fa' },
    padding: { top: { value: 3, unit: 'mm' }, right: { value: 4, unit: 'mm' }, bottom: { value: 3, unit: 'mm' }, left: { value: 4, unit: 'mm' } },
  },
  { id: 'caja-p5', extends: 'caja', placement: 'fixed', fixed: { offset: { x: { value: 12, unit: 'mm' }, y: { value: -40, unit: 'mm' } } } },
  { id: 'caja-p9', extends: 'caja', placement: 'fixed', fixed: { anchor: { to: 'container', edge: 'top-right' } } },

```

Cambia el aspecto de `caja` y todos los recuadros lo siguen, cada uno donde está. Un `extends` que no remite a ningún estilo da el aviso `calloutStyleExtendsUnknown` (propone el id más parecido, y el estilo queda solo, con los valores de serie), y los estilos basados unos en otros en bucle dan `calloutStyleExtendsCycle` (quedan solos hasta que uno se base en un estilo de fuera del bucle). En el Sandbox lo fija el campo **Basado en** de un estilo de recuadro; borrar un estilo en el que se basan otros escribe sus ajustes en ellos, así que sus recuadros no cambian. En la sección **Estilos de marco**, fusionar con **Comparar solo el aspecto** conserva como estilo mínimo de ese tipo el estilo cuyos recuadros están en otro sitio si **Dejar cada recuadro donde está** está activado (por defecto), y ningún recuadro se mueve. Desde postext 1.39.

### El contenedor `:::callout`

Una línea `:::callout{type="<id>"}` abre el recuadro y una línea `:::` sola la cierra. La línea de apertura admite cinco atributos: `type` (el id del estilo), `title` (sustituye al título del estilo), `span`, `placement` y `columns` (sustituyen a los valores del estilo), y el contenido que hay entre ambas líneas se compone dentro del recuadro: un título opcional y después los párrafos, listas, citas, fórmulas o recursos insertados, cada uno con la tipografía `body` / `lists` del estilo (los encabezados conservan sus estilos habituales). Los márgenes entre hijos se funden como en el texto corrido; el interior abandona la rejilla base y el flujo vuelve a ella tras el recuadro garantizando al menos `marginBottom` por debajo (manda la rejilla; el margen es un mínimo, la misma convención que siguen los recursos). Un estilo con `snapToGrid: false` conserva en cambio el `marginBottom` exacto, y el texto tras el recuadro queda fuera de la rejilla hasta el siguiente encabezado o final de lista. Un encabezado inmediatamente anterior a un recuadro se mantiene unido a él.

Límites de esta versión:

- Un recuadro se mantiene entero salvo que su estilo indique `keepTogether: false`. Cuando no cabe en el espacio restante de la columna, pasa entero a la columna o página siguiente, también desde una columna vacía que las bandas de flotantes o un tope de banda han acortado, siempre que una columna completa lo alojara. Un recuadro más alto que una columna completa se parte en su lugar, como uno divisible; solo el que ningún corte puede partir (una figura o tabla más alta que la columna, o un `splitMinLines` que ningún corte cumple) se coloca de todos modos y desborda; la maquetación registra entonces un aviso `calloutOverflow` (`VDTDocument.warnings`), que el Sandbox muestra. Un grupo `:::columns` se corta como el recuadro que lo rodea, entre sus subcolumnas (desde postext 1.25); solo se mantiene entero, y puede desbordar de la misma manera, con `layout.flowColumns: false` o dentro de un recuadro anidado. Un recuadro divisible deja atrás la parte que cabe (hijos enteros, o las líneas de un párrafo hasta `splitMinLines` a cada lado; en un lado basta una figura, una tabla o una fórmula en bloque) y continúa en un recuadro sin icono en la columna o página siguiente, sin título salvo que el estilo lo repita y, si se quiere, con un indicador bajo la parte que deja (véase [Marcas de un recuadro partido](#marcas-de-un-recuadro-partido)).
- Los flotantes ceden ante un recuadro indivisible. Cuando el bloque que sigue a la referencia de una figura es un recuadro `keepTogether`, la figura no ocupa un hueco que dejaría al recuadro sin ninguna columna de la banda actual donde caer (la columna de la referencia o una vacía posterior, que antes del flotante la alojaba): la figura pasa a su siguiente hueco, normalmente la página siguiente, y el recuadro sigue en el flujo, como la compondría un cajista, en lugar de expulsar el recuadro de la página y dejar la columna con la figura sola.
- `span: 'page'` en una disposición multicolumna convierte el recuadro en un **bloque a ancho de página**: se compone al ancho completo del área de contenido y divide la página en bandas de columnas: las columnas de texto que hay encima se cierran en la línea de corte, el recuadro ocupa su propia columna a todo el ancho y debajo se abre una banda nueva de columnas de texto, de modo que el flujo continúa bajo el recuadro en todas las columnas. Donde las columnas están *niveladas* (al principio de una página, justo debajo de un encabezado de apertura con `span: 'page'`, de otro bloque a ancho de página o de una banda superior de flotantes), el recuadro simplemente corta ahí. Si llega a mitad de página, con las columnas desiguales, se compone como lo haría un cajista: el texto que hay encima se corta nivelado en todas las columnas (el motor repite la colocación con las columnas de la banda acortadas al mismo número de líneas de rejilla, de modo que el texto desborda de columna en columna de forma natural y siguen aplicándose todas las reglas de huérfanas, viudas y encabezados unidos a su texto), el recuadro ocupa el ancho de la página y las columnas continúan debajo. El corte cuesta un par de pasadas de colocación adicionales; cuando la línea de corte no dejaría sitio para el recuadro y, debajo, el mínimo de líneas de texto que exige la regla de viudas, o ninguna disposición encaja tras unos pocos intentos, el recuadro pasa al inicio de la página siguiente. El texto de encima respeta el corte: un párrafo que no puede empezar en las pocas líneas que le quedan a una columna bajo una figura pasa a la columna siguiente (la figura queda sola en su columna), y cuando un bloque aún pasaría del corte, el corte se baja una línea en lugar de quedarse donde termina ese bloque. Un recuadro partido que abre la banda también se corta ahí, de modo que su resto nunca pasa del corte. Con `headings.balancing.beforeSpan` (el valor por defecto) la banda que deja se corta nivelada tras él (como la banda de cierre de un capítulo) y, cuando el estilo permite partirlo (`keepTogether: false`), la parte del recuadro que cabe bajo las columnas niveladas cierra la página y el resto abre la siguiente; con `beforeSpan: false` la página que deja simplemente se equilibra como siempre, sin forzar un salto de página. Un encabezado justo antes de un bloque a ancho de página no viaja con él. En disposiciones de una columna `span: 'page'` es simplemente en línea.
- `placement: 'fixed'` saca el recuadro del flujo: se compone (`width: 'auto'` se ajusta al título; `'fill'` toma el ancho de la columna de texto bajo el punto de anclaje) y se fija a la página en la que aparece en el flujo, en la posición que describen `fixed.anchor` / `fixed.offset` (por defecto, la esquina inferior izquierda del área de contenido). Las columnas de texto que cubre ceden esa zona (recortada por abajo, o por arriba cuando la columna aún está vacía), exactamente como una banda de flotantes; cuando la zona ya contiene texto, un flotante o un bloque a ancho de página, el recuadro pasa a la página siguiente. Un recuadro fijo que cierra el capítulo (el bloque siguiente es una apertura de capítulo, un `:::part`, un recuadro barrera de flotantes o el final del documento) nivela primero las columnas que quedan encima (`headings.balancing.trailing`), de modo que una página de cierre corta termina nivelada con el distintivo debajo. El recuadro y sus hijos están en `page.floats` y se pintan fuera del recorte de columna en todos los backends.
- `placement: 'top' | 'bottom'` hace **flotar** el recuadro como un recurso: sale del flujo donde aparece y toma la primera banda libre a partir de ese punto (el pie de la página actual, con `'bottom'`, o la cabeza o el pie de la siguiente página que abre el flujo), al ancho de la columna (`span: 'column'`) o al ancho completo del área de contenido (`span: 'page'`); el texto que lo sigue rellena la página que dejó. Su marco y sus hijos van a `page.floats`, como los de un recuadro fijo. Un recuadro flotante que encabeza una página nueva se coloca antes que las figuras que esperan esa página, y una figura citada en una página anterior que entonces cabe bajo él toma el resto de esa página aunque quedaran menos de tres líneas de texto (una página galería: recuadro más figura, sin texto entre ambas). Un recuadro `span: 'side'` nunca flota: se apila junto al texto sea cual sea su `placement`. Con `columns` mayor que 1 (en el estilo o como atributo del bloque, desde postext 1.18), un recuadro `span: 'column'` ocupa ese número de columnas contiguas: la cabeza de una serie de columnas vacías que empiezan a la misma altura, o el pie de la columna en curso y de las vacías que la siguen, como en `:::callout{placement="top" columns="2"}`.
- `width: 'auto'` se ajusta solo al título; los hijos se ignoran.
- Un `:::callout` anidado dentro de otro es un recuadro propio: se compone con su propio estilo (fondo, borde, radio, relleno, franja, título, icono, marcador, pestaña, tipografía) al ancho interior completo de su recuadro contenedor y se apila como un hijo más, y su `marginTop` / `marginBottom` se funden con los de los bloques vecinos. Su `span` y su `placement` (del bloque o del estilo) se ignoran —un recuadro anidado siempre fluye dentro de su contenedor—, igual que `floatBarrier` y `snapToGrid`. Los recuadros se anidan a cualquier profundidad y pueden ir dentro de un grupo `:::columns` (cada uno entero, en una columna). Cuando el recuadro contenedor se parte, el corte cae antes o después de un recuadro anidado, o dentro de él si su estilo permite partirlo; cada fragmento vuelve a dibujar los marcos que atraviesa el corte, y un recuadro anidado que continúa del fragmento anterior pierde su título y su icono, como una continuación de primer nivel.
- Un grupo `:::columns{count=N}` … `:::` entre los hijos compone esos hijos en `N` columnas de igual ancho, separadas por `columnGap`, dentro del recuadro: la secuencia se corta por los límites de bloque o de línea que mejor nivelan las columnas (un párrafo o elemento de lista cortado a medias sigue en la cabeza de la columna siguiente sin su viñeta), cada columna empieza en la parte superior del grupo y el grupo mide lo que la columna más alta; los hijos posteriores recuperan el ancho completo. Un recuadro que se parte (`keepTogether: false`, o más alto que una columna) también corta dentro de un grupo, entre sus columnas: un grupo en serpentina llena sus columnas por turno y sigue en el fragmento siguiente, y uno paralelo (`breaks`) sigue flujo a flujo (desde postext 1.25; véase [Formato del documento › `:::columns`](/es/docs/document-format-directives#columns)). Un `gap` en la línea de apertura sustituye a `columnGap` para ese grupo, y `rule` traza un filete a lo largo de cada medianil. Sirve para un resumen de ideas clave a dos columnas o para las tablas de un recuadro ancho puestas lado a lado.
- El sexto atributo del bloque, `label`, se imprime en la pestaña `label` del estilo (véase arriba): `:::callout{type="recuadro" label="RECUADRO 1-1" title="La regla del octeto"}`; sin estilo de pestaña el atributo se ignora.

En el VDT el recuadro es un bloque marco de `type: 'callout'` cuya decoración (fondo, franja, icono, título) está en `designOverlay`, seguido de sus bloques hijos en la misma columna; el marco y cada hijo llevan el `containerId` del bloque. Un recuadro anidado es un marco `type: 'callout'` propio entre los hijos, seguido de sus bloques; estos conservan el `containerId` del bloque de primer nivel (la colocación y el equilibrado siguen viendo una sola unidad) y añaden `calloutPath`, los ids de contenedor de los bloques anidados que los rodean, del más externo al más interno (el de un marco anidado es la última entrada). El PDF etiquetado da a cada recuadro anidado un `Div` dentro del de su contenedor. Las imágenes de icono se resuelven como las de los recursos: el registro de imágenes del canvas, la opción `resourceImageUrl` del HTML y el proveedor `resourceBytes` del PDF. El EPUB de maquetación fluida escribe el icono en primer lugar dentro de su recuadro, oculto para las tecnologías de apoyo, y lo flota donde lo dibuja la página: sobre una franja lateral, en una columna propia o en una esquina superior; un libro vertical lo coloca a lo largo de sus líneas. Una imagen pintada en un solo color (`tint`, un color `#rrggbb`) entra en el libro como una copia del SVG en ese color; un mapa de bits conserva allí sus propios colores.

```ts
const resolved = resolveCalloutStylesConfig(config.calloutStyles, resolvedBodyText, resolvedHeadings, resolvedUnorderedLists, config.locale);
// => cada campo heredado se rellena desde las secciones resueltas; el locale
//    opcional elige el idioma de las cadenas de continuación

const minimal  = stripCalloutStylesDefaults(config.calloutStyles);
// => undefined para el `note` por defecto; se eliminan los valores estáticos por defecto
```

### Enunciados numerados y demostraciones

Un estilo con `numbering` cuenta sus recuadros, como el paquete `amsthm` de LaTeX cuenta los entornos de teorema (desde postext 1.19). ### Tipografía dentro de un recuadro

Un recuadro compone su contenido con la tipografía `body` y `lists` de su estilo; todo lo demás conserva los estilos del documento:

- **Los párrafos** toman el `body` del recuadro: fuente, cuerpo, interlineado, color, colores de énfasis, pesos, `italic`, `smallCaps`, alineación, separación silábica, sangría y espaciado entre párrafos. Un campo sin definir hereda de `bodyText`. Un color de énfasis heredado conserva su vínculo con la paleta, así que las negritas, las cursivas y las etiquetas de `:ref` de un recuadro cambian con `colorPalette` igual que fuera de él. (Hasta postext 1.4 la negrita de un recuadro se quedaba en `#295AA3` fuera cual fuera el color principal).
- **Las listas de viñetas** toman el `lists` del recuadro (carácter de viñeta, color, tamaño, peso y fuente del glifo, sangría, separación, espaciado entre elementos, márgenes) sobre `unorderedLists`, y su texto es el del cuerpo del recuadro. Un `lists.bulletChar` o un `lists.color` distinto del del documento (`unorderedLists`) sustituye la viñeta o el color de todos los niveles; uno que lo repite, o que no se define, deja a cada nivel los suyos (`unorderedLists.levels`), de modo que las rayas de los niveles anidados se conservan en el recuadro.
- **Las listas ordenadas** toman `lists.indent`, `gap` e `itemSpacing`, y `lists.color` siempre que el estilo lo define, también cuando coincide con el color de viñeta del documento; un estilo que no lo define deja los números en `orderedLists.color`. (Hasta postext 1.4 el color solo llegaba a los números si era distinto de `unorderedLists.color`, así que darle justo ese color no tenía efecto). El número (su fuente, su cuerpo y su separador) viene de los `orderedLists` globales, porque `lists` solo tiene campos de viñeta: es ahí donde se da estilo a los números de un recuadro.
- **Los `:::paragraphs` dentro de un recuadro** usan su estilo de párrafo, también en recuadros anidados. Los campos que el estilo no define heredan del `bodyText` del documento, no del `body` del recuadro (ni de su cursiva ni de sus versalitas).
- **Los grupos `:::columns`** no tienen estilo propio: todas las columnas comparten la tipografía de texto y de listas del recuadro, y `columnGap` fija la separación entre ellas.
- **Las citas** toman la fuente, el cuerpo y los pesos del texto del recuadro (en cursiva y en gris, como en el texto corrido) y sus versalitas. **Los encabezados** conservan sus estilos; **las fórmulas en bloque**, los ajustes de matemáticas.
- **Las figuras y las tablas** conservan los estilos de pie y de tabla del documento, al ancho interior del recuadro; sus pesos normal y negrita siguen los pesos del `body` del recuadro.
- **Los chips** conservan su estilo de chip; un tamaño en `em` se mide sobre el cuerpo del texto del recuadro.
- **`:::space`** se mide en líneas del texto del recuadro (consulta en [`:::space`](/es/docs/document-format-directives#space) dónde se descarta).
- **Un recuadro anidado** toma su propio estilo completo; su `span`, su `placement`, su `floatBarrier` y su `snapToGrid` se ignoran.

**Notas con sangría francesa.** Las notas al pie de una tabla, una leyenda numerada o una lista de fuentes cuelgan su marca delante del texto: la marca en el borde interior del recuadro, y el texto y todas sus líneas siguientes algo más adentro. `body.hangingIndent` (desde postext 1.71) lo hace con todos los párrafos de un recuadro o de un marco con ese estilo:

- **Una longitud** sitúa todas las líneas menos la primera a esa distancia del borde interior del recuadro, como el `hangingIndent` de un estilo de párrafo (véase [Estilos de párrafo](/es/docs/configuration-styles#estilos-de-párrafo)). La primera línea empieza en el borde, o en `body.firstLineIndent` si el estilo la fija él mismo; una sangría de primera línea heredada de `bodyText` cede el sitio.
- **`true`** lee `body.firstLineIndent` como la sangría de todas las líneas menos la primera, igual que `bodyText.hangingIndent` en el texto corrido; `false` compone el recuadro sin sangría francesa en un libro cuyo texto base la lleva. Sin valor, el recuadro toma `bodyText.hangingIndent`.

Una tabulación en la misma posición lleva el texto que sigue a la marca hasta el borde de las líneas siguientes, sea cual sea el ancho de la marca:

```ts
calloutStyles: [{
  id: 'notes',
  padding: { top: { value: 0, unit: 'mm' }, right: { value: 0, unit: 'mm' }, bottom: { value: 0, unit: 'mm' }, left: { value: 0, unit: 'mm' } },
  body: {
    fontSize: { value: 7, unit: 'pt' },
    hangingIndent: { value: 4.5, unit: 'mm' },
    tabStops: [{ position: { value: 4.5, unit: 'mm' } }],
  },
}],
```

```markdown
:::callout{type="notes"}
\*	Los precios incluyen la entrega dentro de la ciudad.

\*\*	Los socios pagan la mitad; la rebaja no se suma a otras ofertas y vale hasta el final de la temporada.
:::
```

Cada nota es un párrafo propio; entre la marca y el texto va un carácter de tabulación o `:tab`. El asterisco va escapado, porque `*` y una tabulación al principio de una línea abren un elemento de lista. Las líneas se miden así, de modo que el canvas, el PDF, la lista de visualización y el EPUB (con `padding-inline-start` y un `text-indent` negativo) las componen igual, y la exportación a Word escribe la misma sangría francesa. Los elementos de lista conservan su propia sangría (`lists.indent`, `lists.gap`), y un párrafo dentro de un bloque `:::paragraphs`, la de su estilo. Un `firstLineIndent` negativo sigue contando como `0`: la primera línea no puede empezar dentro del relleno del recuadro. Una cita dentro de un recuadro cuelga con él cuando `hangingIndent` es `true`; con una longitud, solo llevan sangría francesa los párrafos propios del recuadro.

### Marcas de un recuadro partido

Cuando un recuadro se parte entre columnas o páginas (`keepTogether: false`, o un recuadro más alto que una columna), cada parte posterior a la primera empieza sin el título ni el icono y, por defecto, nada avisa al lector de que el recuadro continúa. Dos opciones añaden las marcas que usan un libro o un guion:

- **`repeatTitle: true`** repite el título al principio de cada continuación, seguido de `continuedSuffix` («Ideas clave (cont.)», por defecto). La repetición toma el estilo del título, así que con `textTransform: 'uppercase'` da el «HAMLET (CONT.)» de un guion. El icono y la pestaña de etiqueta se quedan en la primera parte.
- **`continuesMarkerEnabled: true`** pone `continuesMarker` («Continúa» en un documento en español, «Continued» en inglés) bajo la última línea de cada parte que continúa, dentro del recuadro, en la fuente y el cuerpo del texto del recuadro: en cursiva salvo que `continuesMarkerItalic` sea `false`, y alineado a la derecha salvo que `continuesMarkerAlign` diga `'left'` o `'center'`. El indicador ocupa sitio en la parte que cierra, y el corte se elige para que quepa.

```ts
calloutStyles: [{
  id: 'parlamento',
  keepTogether: false,
  titleStyle: { textTransform: 'uppercase' },
  repeatTitle: true,
  continuedSuffix: '(CONT.)',
  continuesMarkerEnabled: true,
  continuesMarker: '(SIGUE)',
  continuesMarkerAlign: 'center',
  continuesMarkerItalic: false,
}],
```

```md
:::callout{type="parlamento" title="Hamlet"}
Un parlamento lo bastante largo para pasar del pie de la página…
:::
```

La parte que cierra la página termina con «(SIGUE)» y la página siguiente empieza con «HAMLET (CONT.)». Las dos son elementos de paginación: en un PDF accesible son artefactos y en el HTML se ocultan a las tecnologías de apoyo, de modo que el título se lee una sola vez. En el VDT son bloques de texto de `designOverlay` marcados con `artifact: true`.

### Diseños de recuadro

`design` coloca los elementos de un diseño de encabezado (textos, imágenes, filetes, cajas; véase [Apertura a toda página y diseño avanzado](/es/docs/configuration-headings#apertura-a-toda-página-y-diseño-avanzado)) en una banda bajo el título del recuadro, a todo su ancho interior. El contenido del recuadro sigue a la banda, con la separación del título entre ambos. Un recuadro partido entre columnas o páginas dibuja la banda solo en su primera parte. Desde postext 1.45.

Los textos del diseño leen estos marcadores:

- `{titleText}`: el título que imprime el recuadro, el `title` de la valla o, si no lo hay, el del estilo.
- `{boxText}`: el contenido del recuadro como texto plano, un párrafo o elemento de lista por línea. Los vacíos se omiten.
- `{boxText.<n>}`: el párrafo o elemento de lista número `n`, contando desde 1; vacío si el recuadro tiene menos.
- `{attr.<clave>}`: un atributo escrito en la valla. Sirve cualquier nombre, además de los que lee la propia valla: `:::callout{type="card" kicker="Nota"}` da a `{attr.kicker}` el valor `Nota`. Un atributo ausente no imprime nada.
- los marcadores del documento `{title}`, `{subtitle}`, `{author}` y `{publishDate}`.

El `resourceId` de una imagen admite los mismos marcadores, así que cada recuadro puede dibujar un recurso propio. Solo un diseño de recuadro lee `{boxText}`; un diseño de encabezado no imprime nada en su lugar.

Con `setsContent: true` un solo estilo sirve para todos los recuadros de la misma forma, cada uno con sus palabras. En un cuaderno de caligrafía cada renglón de práctica es un recuadro cuyo contenido es la palabra que hay que copiar: el diseño imprime la palabra en una letra escolar y luego la vuelve a poner en puntos para repasar (`dotted`), tantas veces como caben en el renglón (`repeat`; véase [Marcas en línea y contornos](/es/docs/configuration-headers-footers#marcas-en-línea-y-contornos)).

```ts
calloutStyles: [{
  id: 'practice',
  backgroundEnabled: false,
  border: { enabled: true, color: { hex: '#9aa6b2', model: 'hex' }, width: { value: 0.5, unit: 'pt' } },
  design: {
    setsContent: true,
    minHeight: { value: 16, unit: 'mm' },
    slot: { elements: [
      { kind: 'text', id: 'model', content: '{boxText}', fontFamily: 'Playwrite ES', fontSize: { value: 26, unit: 'pt' },
        placement: { anchor: { to: 'container', edge: 'top-left' } } },
      { kind: 'text', id: 'copies', content: '{boxText}', fontFamily: 'Playwrite ES', fontWeight: 100, fontSize: { value: 26, unit: 'pt' },
        dotted: {}, repeat: { gap: { value: 8, unit: 'mm' } },
        placement: { anchor: { to: '#model', edge: 'right-of' }, offset: { x: { value: 8, unit: 'mm' } } } },
    ] },
  },
}],
```

```md
:::callout{type="practice"}
sol
:::

:::callout{type="practice"}
pan
:::
```

El primer renglón imprime *sol* seguido de una fila de copias punteadas de *sol*; el segundo hace lo mismo con *pan*, y ninguna de las dos palabras se vuelve a componer bajo su banda. Si se cambia la palabra en el Markdown, cambian el modelo y todas las copias. Con `setsContent` en `false` el diseño lee `{boxText}` igualmente, y el contenido se compone bajo la banda.

En el VDT los elementos de la banda son bloques de diseño en el `designOverlay` del marco, junto al título.
