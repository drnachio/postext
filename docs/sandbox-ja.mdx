# Sandbox

**Postextの組版エンジンを試すための、インタラクティブな実験の場です。**

Sandbox（ブラウザーで動く編集環境）は、エディターのような画面で本文を書き、リソースとフォントを管理し、デザインを調整できる場所です。結果は5つの同期したビュー、**Canvas**、**PDF**、**Folio**（印刷された本を3Dで表示）、**HTML**、**EPUB 3**にその場で表示されます。実験のために作られているので、文字組みや段の数を変えたり、図の配置をいろいろ試したりして、エンジンがどう応えるかを確かめられます。パネルではエンジンの用語ではなく編集の言葉（本、図、囲み、柱）を使っているので、出版に携わる人が設定のスキーマを知らなくても操作できます。どのコントロールもキーボードとスクリーンリーダーで操作できます。

## インターフェースの構成

Sandboxは3つの主な領域からなります。パネルを切り替える細い**アクティビティバー**、表示中のパネルを収める幅を変えられる**サイドバー**、そして右側の出力タブを備えた**ビューポート**です。パネルのヘッダー、ビューポートのタブバー、アクティビティバー最上部のロゴ欄は同じ高さにそろえてあるので、画面の上端は1本の帯としてウィンドウを横切って見えます。

### アクティビティバー

左端の細い帯に、パネルごとのボタンが並びます。各ボタンはアイコンとその下の短いラベルを表示し、ツールチップでより詳しい説明を示します（同じ説明がボタンのアクセシブルな説明にもなります）。上から順に次のとおりです。

- **本**（`Files`アイコン）：自分の本と見本の本
- **章**（`BookOpen`アイコン）：開いている本とその章
- **本文**（`FileCode`アイコン）：現在の章の本文を書き、編集する
- **リソース**（`FolderOpen`アイコン）：本で使う画像、SVGの図、表
- **フォント**（`Type`アイコン）：本で使う書体と、自分のフォントファイル
- **デザイン**（`Settings2`アイコン）：ページ、文字組み、見出し、図、囲み、書き出しの設定
- **検査**（`AlertTriangle`アイコン）：レイアウトで見つかった組版上の問題。アイコンには現在の警告の数がバッジでその場で表示され、上限は`99+`です。

表示中のパネルのボタンをクリックするとサイドバーが閉じ、別のボタンをクリックするとそのパネルに切り替わります。バー全体でタブ移動の止まる位置は1つだけです。矢印キー（↑ / ↓、端で折り返す）と**Home**、**End**でボタン間のフォーカスを移し、EnterまたはSpaceでフォーカスのあるパネルを開きます。

ホストアプリケーションは、バーに独自の項目を加えられます。最上部の欄には任意の**ホームへのロゴリンク**（`homeUrl`または`homeLink`プロパティで指定）を、下端には**テーマの切り替え**と**言語の切り替え**を置けます。本全体は**本**パネルから`.postext`ファイルとしてやり取りし、**本文**パネルと**デザイン**パネルのヘッダーはそれぞれ自分の担当部分を書き出します（[書き出しと読み込み](#書き出しと読み込み)を参照）。

### サイドバーのパネル

サイドバーの幅は変えられます。サイドバーとビューポートの間の区切り線をドラッグするか、Tabで区切り線にフォーカスを移してキーボードで操作します。← / →で幅が2 %ずつ（Shiftを押しながらなら10 %ずつ）変わり、**Home** / **End**で最小と最大の幅に移ります。区切り線は現在の値をスクリーンリーダーに伝え、ビューポートには常に200 px以上の幅が残ります。表示中のパネルがないときはサイドバー全体が閉じ、その幅はセッションをまたいで記憶されます。

設定の行では、ラベルをコントロールの横に置き、サイドバーが狭いときはコントロールの上に置きます。これはコンテナークエリーによるもので、ウィンドウではなくサイドバーの幅に従います。

#### 本文パネル

章のMarkdownを書くCodeMirror 6のエディターです。スクリーンリーダーには「章の本文」として読み上げられます。次の機能があります。

- **構文の強調表示**：見出し、強調、リンク、コードブロック、引用ブロックを見分けやすく表示します。さらに**YAMLフロントマター**、**LaTeXの数式**の範囲、**インラインチップ**（`:chip[…]`：角括弧と属性に印を付け、チップの文字に色を付ける）、**スモールキャピタル**（`:smallcaps[…]`：角括弧に印を付け、文字をスモールキャピタルで表示する）、縦組みの**向きの指定**（`:tcy[…]`、`:upright[…]`、`:sideways[…]`：角括弧に印を付け、文字に点線の下線を引く）、**中国語の注記**（`:dots[…]`、`:name[…]`、`:book[…]`は文字の下に印を描く。`:ruby[…]{rt="…"}`と`{紅樓|hóng|lóu}`。`:warichu[…]`は注を小さく表示する）にはそれぞれ専用の強調表示があります。`:do`、`:na`、`:bo`、`:ru`、`:wa`と入力すると、対応するディレクティブの候補が表示されます
- **チップの補完**：語の先頭で`:c`と入力すると`:chip[…]`の候補が出ます（キャレットは角括弧の間に入ります）。`{style="…"}`の中では、設定済みのチップスタイルのIDが候補になります。
- **スモールキャピタルの補完**：語の先頭（または`*` / `_`の直後）で`:sm`と入力すると`:smallcaps[…]`の候補が出て、キャレットは角括弧の間に入ります。
- **タブ**：`:tab`と`:tab{…}`は、ほかのインラインディレクティブと同じく強調表示され、補完の候補にも出ます。エディターのTabキーではタブ文字を入力できないので、Sandboxでは`:tab`と書いてタブを入れます。文章と一緒に貼り付けたタブ文字は保たれ、タブ位置を設定したスタイルの段落ではタブになります。
- **行番号**と、カーソルのある行の強調表示
- 長い段落の**折り返し**
- **右から左の行**：アラビア文字またはヘブライ文字で始まる行は右から左に進み、キャレットと矢印キーもそれに従います。行の中のマークアップ（`{…}`の属性、`[^id]`のラベル、ディレクティブの名前、`:ref[fig-1]`全体、数式、コード、リンク先）は左から右のまま残るので、入力したとおりに読めます。コードフェンス、フロントマター、ラテン文字の語で始まる行は、これまでどおり左から右です。
- **ツールバー**：先頭に**取り消し / やり直し**があり、続いて太字、イタリック、見出しレベル1～3、リンク、インラインコード、**チップ**（選択範囲を`:chip[…]`で囲む）、**スモールキャピタル**（選択範囲を`:smallcaps[…]`で囲む）、引用ブロック、番号付きリストと箇条書きリスト、さらに3つのディレクティブの挿入ボタンが並びます。
  - `:::pagebreak`
  - `:::space`：1行分の縦のアキ（それより多いときは`:::space{lines=N}`）
  - `:::numbering{format="decimal" startAt=1}`：調整できる例の属性付きで挿入されます

コードリスト（```` ``` ````か`~~~`のフェンスとその行）は、エディターでは1つの領域になります。コードの背景が付き、中にあるPostextのマークアップ（数式、チップ、タブ、索引マーク）は、エンジンが読まないのと同じく色分けされません。ホストアプリケーションは`extraActions`で独自のツールバーボタンを加えられます。エディターはカーソルと選択範囲をプレビューにも伝えるので、クリックによるキャレットの同期が働きます。描画された出力の文字をクリックするとキャレットが対応するMarkdownの位置に移り、プレビューは現在の選択範囲を強調表示できます。

パネルのヘッダーは**章の切り替え**です。前後の章への矢印、章の位置とタイトル、そして本のすべての章を並べたメニューがあり、メニューには章ごとのページ範囲がページ割りの判明しだい表示されます（[本と章](#本と章)を参照）。章ごとに独立したエディターがあるので、取り消しの履歴とキャレットの位置は章ごとに保たれます。ヘッダーにはさらに5つの操作があります。

- **リセット**（確認があります）：開いている見本の本の**文書部分**を読み込み直します。すべての章と図の一式が見本のものに置き換わります（組み込みの見本では、ロケールの見本文書と例のリソース）。デザインは、見本自身のフォントを除いてそのままです。[本パネル](#本パネル)を参照してください。
- **書き出し**：表示中の章をプレーンな`.md`ファイルとしてダウンロードします。ファイル名は、複数の章からなる本では`<book>-<nn>-<chapter>.md`、それ以外では開いている本の名前か`document.md`になります
- **読み込み**：表示中の章を`.md`ファイルの内容で置き換えます
- **Word文書を読み込む**：`.docx`の原稿を開き、何かを変更する前に、そのWordスタイルをPostextのスタイルに対応づけます（[Word文書](#word文書)を参照）
- **Wordに書き出す**：章または本全体を`.docx`としてダウンロードします。もう一度読み込むと、すべてのスタイルが元どおりに戻ります

#### 本パネル

アクティビティバーの最初のパネルで、自分の本と見本の本のギャラリーです。**新規**メニュー、最後の操作の状態、新しい版が出た見本の本のバナーもここに表示されます。コードとストレージの中では、本は今も「project」、見本の本は「preset」と呼ばれています。

本（または見本の本の言語タグ）をクリックするとその本が開き、画面に表示された時点でサイドバーは[章パネル](#章パネル)に移ります。すでに開いている本をクリックすると、すぐに章パネルに移ります。各行のメニュー（名前の変更、複製、ダウンロード、隠す、削除）では、パネルは切り替わりません。開いている本には一覧の中で印が付いたままになります。パネルは2つのグループに分かれています。

- **自分の本**：ブラウザー（IndexedDB）に保存される、編集できるローカルの本です。開いている本には印が付き、その章は**章**パネルにあります。

  自分の本を開いている間は、作業中の文書がその本そのものです。本文、デザイン、図、フォントへの編集はすべて自動的にその本に保存されるので（`localStorage`と同じく1秒のデバウンスで）、ほかの本に切り替えて戻っても何も失われません。本はヘッダーの**新規**メニューから作ります。
    - **開いている本の複製**：開いている本とその図、フォントを新しい本に複製します。
    - **白紙の本**：空の本を始めます。
    - **.postextファイルを開く…**：ファイルを読み込みます。

  どの行も複製できます。自分の本がまだないときは、グループに空の状態の表示と同じショートカットが出ます。各行にはラベル付きの「⋯」メニューが1つあり（「『…』のその他の操作」）、項目は**名前を変更…**、**複製**、**ダウンロード（.postext）**、**削除…**。削除の確認は⋯ボタンのすぐ横で求められます。

  名前を変更すると、その場に名前と説明の入力欄が開きます。どちらの欄でもEnterで両方を確定し、Escapeで取り消します。

  本には**表紙画像**もあり、見本の本ではサムネイルが出る位置に表示されます。見本の本（またはほかの本）を複製すると、その表紙を引き継ぎます。行の名前を変更している間は、表紙が表紙を設定するコントロールになります。クリックしてPNG、JPEG、WebP、GIF、SVGを選ぶか、横の×で現在の表紙を外します。表紙は図ではなく本に属し、書き出しと読み込みでも本と一緒に移ります。

  表紙のない本には、**最初のページ**（最初の章の1ページ目）から表紙が作られます。そのページがCanvasタブで初めて組まれて描画されると、フォントとページ内の画像がそろった後、ブラウザーの手が空いたときにSandboxがその小さな画像（幅240 px、JPEG）を撮ります。これが本の表紙として保存されるので、ダウンロードしたファイルにはバンドルの`thumbnail`として入ります。サムネイルを同梱していない見本の本も同じ方法で表紙を得ます。これはブラウザーに保存され（IndexedDBデータベースの`presetCovers`ストア、見本と言語ごとに1つ）、その行に表示され、複製やダウンロードにも引き継がれます。すでにある表紙は、見本に付いてきたもの、読み込んだファイルのもの、自分で選んだもの、以前に撮ったもののいずれであっても置き換えられません。外した表紙は、次に訪れたときに最初のページから撮り直されます。

  本を開くときに確認は求められません。離れる本は、どの本であっても先に保存されます。次の本を読み込んでいる間、ビューポートには離れた本ではなく「本を開いています…」と表示されます。開いている本を削除すると、組み込みの見本に戻ります。

- **見本の本**：自分の本の下に並ぶ、作業の出発点です。バンドルそのものは変わりませんが、見本の本への編集は保たれます。最初の変更でその複製（下書き）が見本と言語ごとに1つブラウザーに保存され、行に**編集済み**のタグが付きます。同じ見本を同じ言語でもう一度開くと、自分の版が戻ってきます。一度も変更していない見本は公開されたとおりに開きます。各行の⋯メニューには次の項目があります。
    - **自分用に複製**：見本を自分の本に変えます。その本はバンドルのファイルの複製を自分で持つので、あとでディスク上のバンドルが変更されても影響を受けません。
    - **ダウンロード（.postext）**：見本を`.postext`ファイルとして保存します。
    - **一覧から隠す**：見本を一覧から外します（組み込みの見本は隠せません）。
    - **元に戻す…**：見本への変更を（すべての言語で）破棄し、その見本が開いていれば公開版を代わりに読み込みます。実行前に確認があり、編集済みの見本にだけ表示されます。

  複数の言語がある見本には、マニフェストに並ぶ順で言語ごとのタグが付きます。繁体字中国語と簡体字中国語は繁と简、それ以外は言語コード（EN、ES）です。ツールチップはその言語をインターフェースの言語で示します（「繁体字中国語版を開く」）。原文がインターフェースとは別の言語の見本（英訳の付いた中国語の小説など）は、どの言語で開くかを示し（`openLocale`、[プリセットバンドルの形式](#プリセットバンドルの形式)を参照）、行をクリックすると原文が開きます。

  隠した見本は、グループの下端にある**隠した見本の本**の開閉部分にまとめられ、それぞれに**一覧に表示**があります。この選択は`localStorage`に記憶されます。

**新規**メニューから開いた`.postext`ファイルは、新しい本として開いた状態になります。複数の言語を含むファイルは、まずどの言語を読み込むかを尋ね、ファイルが書かれた言語（マニフェストの`locale`）を最初に示します。書き出しは行ごとの操作で、開いている本の行は画面に表示されている内容を書き出します。`.postext`ファイルは、プリセットバンドルのディレクトリーをzipにしたものです（[書き出しと読み込み](#書き出しと読み込み)を参照）。

**本文**パネルと**デザイン**パネルの**リセット**ボタンは、本の複製元の見本の状態に戻します。白紙の本や読み込んだ本には元がないので、それを開いている間はこのボタンは表示されません。

#### 章パネル

アクティビティバーの2番目のパネルで、開いている本だけを表示します。上部には本の名前、本の種類（**自分の本**、または言語と、変更後は**編集済み**のタグが付いた**見本の本**）、本に対する操作を集めた⋯メニューがあります。メニューの項目は、自分の本では**名前を変更…**（名前をダブルクリックしても同じ）、**複製**または**自分用に複製**、**ダウンロード（.postext）**、そして編集済みの見本の本では**元に戻す…**。

その下では本の**章**がパネルの残りを占め、独立してスクロールします（[本と章](#本と章)を参照）。章の各行にはページ範囲と語数が表示され、表示中の章には印が付きます。中国語、日本語、韓国語の本では語ではなく文字を数えます。漢字、かな、ハングルは1字を1と数え、その中に混じるラテン文字の語も1語を1と数えます。**章を追加**はパネルのヘッダーの章の数の横にあります。行は持ち手をドラッグして（または持ち手の上で矢印キーを使って）並べ替えられ、各章の⋯メニューには**名前を変更**、**上へ移動 / 下へ移動**、**レベル1見出しで分割**、**前の章に結合**、**削除**があります（最後の1章は削除できません）。

##### 見本の本（プリセット）

**プリセットバンドル**は、1つの単位として読み込まれる出発点一式です。章のMarkdown、`PostextConfig`、リソース（ビットマップやSVGのデータと表のモデルを含む）、設定が参照するカスタムフォントのファイルからなります。パネルはSandboxから届くすべてのプリセットを一覧にし、開いているものに印を付けます。

- **組み込みのプリセット**：パッケージに同梱された既定の見本の本、**Postextガイド**です。常に利用でき、常に一覧の先頭にあり、**公開**されています。英語、スペイン語、カタルーニャ語、アラビア語、簡体字中国語、日本語、ブラジル・ポルトガル語の版があります（行のES、CA、EN、ع、简、日、PTのボタン。`#preset=postext-guide&lang=zh-Hans`は中国語版に、`lang=ar`はアラビア語版に、`lang=ja`は日本語版に、`lang=pt-BR`はブラジル・ポルトガル語版にリンクします）。アラビア語版はアラビア語の本です。右から左に進み、右綴じで、アラビア・インド数字を使い、Amiri、Noto Kufi Arabic、IBM Plex Sans Arabicで組まれ、カシーダによる両端そろえを行い、図は左右を反転してアラビア語のラベルで描かれています。中国語版は独自のデザイン（Noto Serif SCとNoto Sans SC、中国大陸の約物と禁則処理）を持ち、図は中国語のラベルで描かれています。インターフェースは英語やスペイン語のままで、手を加えていない中国語版ガイドは、そのどちらのインターフェースでSandboxを開いても中国語のままです。日本語版も縦組みの本で、日本語の組版規則（JLReq）に従って組まれています。Noto Serif JPとNoto Sans JPを使い、9.25 ptの文字を34字詰め2段に組み、節見出しは3行取り、柱とアラビア数字のノンブルを天と地に置き、図は日本語のラベルで描かれています。Sandboxのインターフェースは日本語にも対応しており、日本語のインターフェースではこの日本語版が開きます。ほかのインターフェース言語から開いた、手を加えていない日本語版ガイドは日本語のまま残ります。
- **リモートのプリセット**：`presetSources`プロパティで渡したベースURLからHTTPで配信されるバンドルです（[Props](#props)を参照）。各ソースは公開か**非公開**のどちらかです。非公開のプリセットは一覧で**非公開**のタグが付き、マシンの外に出してはならない素材のためのものです。公開のWebサイトが非公開のソースを一覧に出すのはローカルの開発環境だけで、そこではNext.jsアプリが`POSTEXT_PRIVATE_PRESETS_DIR`で指定したフォルダーを`/api/private-presets`から配信します。本番環境では一覧に出ません。Webサイトの公開ソース`/presets`は、見本の本を配信しています。スペイン語版と英語版のある*Bioquímica*、*Deep Sky*、『ドン・キホーテ』、『物理学』（OpenStax）、『スペイン絵画』、*Signals 2020*、3つの版のある『紅楼夢』、そしてVerityの注を脚注とし、Doréの版画を収めた英語の『失楽園』です。どれにもライセンスとクレジットが付いています。
- **`default: true`**：既定として指定された非公開のプリセットは、手つかずの（組み込みの文書に手を加えていない）Sandboxを初めて開いたときに自動で読み込まれます。複数が指定されている場合は、`locale`がUIのロケールに一致するものが選ばれます。公開のプリセットが自動で読み込まれることはありません。

各行には、プリセットの名前、任意の説明、ロケールのタグ、**非公開** / **既定**のタグが表示されます。行をクリックすると、プリセットが本文、図、デザイン、フォントまで**丸ごと**読み込まれます。Sandboxはまずフォントファイルと図のデータをIndexedDBに書き込むので、ビューポートに中途半端に適用された文書が表示されることはありません。行をクリックすると見本はインターフェースの言語で開きますが、別の言語でだけ編集していた場合は、最後に編集した版が開きます。2か国語の見本の言語タグをクリックすると、その言語で開きます（その言語で自分の版があればそれが開きます）。

**プリセットの追従**。リモートのプリセットは自動的に追従されます。プリセットを適用するたびに、Sandboxはバンドルの「フィンガープリント」と、適用したMarkdown、設定、リソース一式のハッシュを記録します。ページが表示されている間は3秒ごとにフィンガープリントを確認し、タブが表示されたときやウィンドウにフォーカスが戻ったときにはすぐに確認します。フィンガープリントが変わった場合は次のようになります。

- 本が**手つかず**（Markdown、設定、リソースのハッシュがプリセットを適用したときのまま）なら、プリセットが丸ごと適用し直され、パネルに短い通知が出ます。
- **ローカルの変更**がある場合は、変更が保たれます。パネル上部のバナー（「この見本の本に新しい版があります。変更内容は保持されています。」）に**新しい版を開く**があり、見本のその言語への変更を破棄する前に確認を求めます。その間、アクティビティバーの**本**ボタンには点が付きます。下書きは自分の作られた元の版を覚えているので、新しい版を読み込むまでは、開くたびにバナーが再び表示されます。新しい版でファイルが変わった図のうち下書きにあるものは、元のバイト列を保ちます。バンドルのファイルが書き込まれる前に、下書きがそれらの複製を自分で持つからです。バンドルを追従するのは見本の本が開いている間だけです。見本から複製した本は、自分の複製を持ち続けます。

同じ確認は読み込み時にも行われるので、バンドルを編集してからSandboxを開いても、本が手つかずなら新しい版が反映されます。フィンガープリントは`<preset-dir>/fingerprint.json`から取得します。開発用のルートでは、これはディレクトリーのメタデータだけから作ったハッシュを返す仮想ファイルです（付録の[プリセットバンドルの形式](#プリセットバンドルの形式)を参照）。このファイルを配信しないソースは追従されません。

以前のセッションで開いていたプリセットが、どのソースの一覧にも載らなくなった場合（典型的には、非公開のプリセットを配信しないビルド）も、そのプリセットは「このビルドでは利用できません」としてグレー表示で残ります。Sandboxは読み込み済みの内容を保ち、黙って組み込みの見本に差し替えることはしません。開いているプリセットのIDは`postext-sandbox-preset`キーに保存されます（[作業内容の保存](#作業内容の保存)を参照）。バンドルの形式は付録の[プリセットバンドルの形式](#プリセットバンドルの形式)で説明しています。

#### リソースパネル

本のリソース、つまりビットマップ画像、SVGの図、表、動画を管理します。本文からは`::resource{id="…"}`ブロックと`:ref{id="…"}`のインライン参照でリソースを指します。参照の構文とフロートのモデルについては、[文書形式 → リソース](/ja/docs/document-format#リソース)を参照してください。

**一覧表示**。ヘッダーにはリソースの数が表示されます。リソースはリソースタイプの名前ごとにまとめられ、各グループは件数付きの一覧になります。`typeId`が設定済みのどのタイプにも一致しなくなったリソースは**種類なし**のグループに入るので、引き続き開けます。各項目には、キャプションとIDの横に36 pxのサムネイルが表示されます。ビットマップとSVGでは実際のプレビュー、動画では再生バッジ付きのポスター画像、表では記号です。本のリソースが6つを超えると**検索**欄（「リソースを検索…」）が現れ、キャプションとIDで一覧を絞り込みます。アクセント記号の有無は区別しません。本にまだリソースがないときは、追加のしかたと、`:ref{#id}`で本文に配置する方法を説明する空の状態が表示されます。**新規**のドロップダウンには、リソースを加える4つの方法があります。

- **画像をアップロード**：PNG、JPEG、WebP、GIF
- **SVGをアップロード**
- **新しい表**：見出し行1行を含む2×2のグリッドから始まります
- **動画を追加**：YouTubeやVimeoの動画、動画ファイル、または動画のアドレス（MP4やHLSストリーム。下記の**動画**を参照）。リソースタイプが動画の登場より前に作られた本では、最初の動画を加えたときに組み込みの**動画**タイプが加わります。

ディスクのファイルをパネルにドラッグ＆ドロップすることもでき、動画ファイル（MP4、WebM、Ogg、QuickTime）も受け付けます。ファイルはまとめてアップロードされ、IDはファイル名からスラッグとして作られます。対応していないファイルは飛ばされ、追加した数と飛ばした数が短いメモで報告されます。

**詳細表示**。リソースを選ぶとエディターが開きます。

- **ID**：編集でき、スラッグとして正しいかが検証されます。重複するIDには印が付き、確定されません。IDが空のときは、キャプションから作った候補が示されます。名前を変えても、保存済みの画像やSVGのファイルはそのままです。
- **種類**：設定済みのリソースタイプのいずれか
- **キャプション**：インラインのMarkdown（太字、イタリック、コード、`:ref`）が使えます。`\\`または行末のバックスラッシュで改行し、ふつうの改行はスペースとして扱われます
- **注記**：任意の出典、クレジット、補足の1行で、リソースの下に小さく組まれます（インラインの書式と改行はキャプションと同じです）。スタイルは**キャプション**設定の**注記**グループで決まります。
- **代替テキスト**：HTML出力のためのアクセシビリティ用の説明
- **表スタイル**：表の場合に、その表を組む名前付きのスタイル（`table.styleId`）です。**文書の表スタイル**（既定）か、設定で宣言した**表スタイル**のいずれかを選びます。どのスタイルも宣言していないIDは見つからないものとして一覧に示され、文書の表スタイルで描画されます。
- **配置**：
  - **位置**：`auto`（最初の空き位置。既定）、`top`、`bottom`、`here`のいずれかです。
  - **幅**：`column`、`page`、`side`のいずれかです。位置が`here`のときは無効になります。既定値はエンジンと同じ`auto` + `column`です。
  - **段数**：複数段のページで、段のフロートがまたぐ隣り合った段の数です（`placement.columns`）。たとえば新聞の4段のうち2段にまたがる写真です。ページの段数と同じにするとページ幅になります。本かその節のどれかが2段以上で、幅が`column`のときに表示されます。位置が`here`のリソースや回転したリソースには表示されません。
  - **回転**：正立、または90度回転（上辺を左へ、または右へ）。回転したリソースは背にそろえて1ページを占めるので、幅の選択は無効になります。
  - **幅**：段より狭いフロートやインラインの埋め込みのための、幅の割合とそろえです。そろえは、配置先より狭いビットマップやSVGを全幅で置くときの位置も決めるので（段より小さいビットマップや、`layout.fitFiguresToPage`で縮小された図）、画像では常に有効です。表では幅が100%未満のときに有効になります。回転したリソースにはどちらもありません。
  - **図の横にキャプション**：1段半組みのサイド段のためのスイッチです。段のフロートに適用されるので、位置が`here`のときは表示されません。
  - **収まるよう縮小**：フロートの図版について、*しない*、*新しいページ*、*任意の位置*（`placement.shrink`）を選び、縮小するときは**最小倍率**（`placement.minScale`）も指定します。回転していない図版には**キャプションの幅**（*位置*または*図版*、`placement.captionMeasure`）もあります。リソースの種類の既定の配置にも同じ3項目があります。
  - **参照するページの先頭に置く**：回転していない段幅またはページ幅の、上または自動のフロート（`placement.citingPage`）。参照する行のあるページまたは段の先頭に置け、参照より前の本文はその下に送られます。リソースの種類の既定の配置にも同じスイッチがあります。
  - **回り込み**：本文中に置いたリソースまたは 1 段幅のフロートについて、*なし*か、本文を横に組んで置く段の側（`placement.wrap`）と、回り込むときの**回り込みの間隔**（`placement.wrapGap`）。幅を指定していない回り込むリソースにはレイアウトの既定の割合が表示されます。リソースタイプでは既定の配置で両方を設定できます。
- **データ**：ビットマップやSVGのファイルを差し替えるアップローダー
- **サイズと解像度**：ビットマップについて、ピクセル数、ファイルに記載された解像度（*記載なし*、または未指定として扱う旨を添えた72や96）、組まれる解像度での原寸（mm）、現在のレイアウトで配置された位置で印刷されるppi（複数回配置されていれば最も低い値）を表示します。プリフライトの最低解像度を下回ると警告のスタイルで、重大とする解像度を下回ると重大のスタイルで表示され、印刷向けに設定した本では**検査で開く**が付きます。**解像度**は画像自体のppiを設定し（`bitmap.resolution`。[文書形式 › ビットマップのサイズ](/ja/docs/document-format#ビットマップのサイズ)を参照）、**ファイルの… ppiを使う**はその値をファイルから入れます。アップロードした画像は、ファイルに記載された解像度を保持します（`bitmap.fileResolution`）。
- **動画**：動画リソースの場合（[文書形式 › 動画](/ja/docs/document-format#動画)）：
  - **配信元**：**YouTube**、**Vimeo**、**ファイル**のいずれか。
  - **動画のアドレス**（YouTube、Vimeo）：その動画の任意のリンク。新しい動画を指すと、ポスター画像、フレームの寸法、タイトルがプラットフォームから取得されます（代替テキストが空ならタイトルがそこに入ります）。**ポスター画像を再取得**でもう一度取得します。プラットフォームのどの動画も指さないリンクには、欄の下に印が付きます。
  - **動画ファイル**（ファイル）：MP4、WebM、Ogg、QuickTimeのファイルのアップローダーで、形式、サイズ、長さが表示されます。最初のポスター画像は全体の10分の1の位置で撮られます。**ポスター画像のフレーム**でファイルを再生し、印刷したいフレームで止めるか、シークしてから**このフレームをポスター画像にする**を押します。**公開先のアドレス**：公開した動画の置き場所（`https://…`）で、QRコードとPDFのリンクから開かれます。これがないと、印刷物にはQRコードもリンクも付きません。
  - **動画のアドレス**（ファイルで、ファイルをアップロードしていない場合）：動画をアドレスだけから再生します。サーバー上のMP4やWebM、またはHLSストリーム（`.m3u8`。欄の上に**HLSストリーム**と表示されます）です。アドレスを入力すると動画の寸法と長さが読み取られ、**ポスター画像のフレーム**はそのアドレスから再生します。HLSも同じです。フレームを選ぶには、クロスオリジンの読み込み（CORS）を許可するサーバーが必要です。許可されていなければパネルにそう表示される（「動画のサーバーがフレームの読み込みを許可していません（CORS）。代わりにポスター画像をアップロードしてください」）ので、ポスター画像をアップロードします。QRコードとPDFのリンクは、このアドレスを開きます。
  - **ポスター画像**：印刷される画像とそのサイズ、そして自分の画像に差し替えるためのアップローダー。
  - **開始（秒）** / **終了（秒）**：再生する部分です。0にすると開始や終了はそのままです。
  - **プレーヤー**：この動画のスイッチ（コントロール、ダウンロードボタン、全画面、速度メニュー、ピクチャー・イン・ピクチャー、自動再生、ミュートでの開始、ループ、他の動画と同時に再生）で、それぞれ**本の設定**、**はい**、**いいえ**から選びます。一覧に出るのは、その動画のプレーヤーが従うスイッチだけです。
- **セーフエリア**：ビットマップとSVGの場合に、画像の中で常に表示される部分です（`Resource.safeArea`。[文書形式 › セーフエリア](/ja/docs/document-format#セーフエリア)を参照）。欄には範囲に印を付けたサムネイルとその大きさ（パーセント）が表示され、画像にセーフエリアがなければ**なし**と表示されます。**セーフエリアを指定** / **セーフエリアを編集**と**セーフエリアを削除**のボタンがあります。ダイアログには画像が表示されます。四角形の外側をドラッグすると新しい四角形を描き、内側をドラッグすると移動し、ハンドルをドラッグすると大きさが変わります。四角形にフォーカスがあるときは、矢印キーで移動し、Shiftを押しながら矢印キーで大きさを変えます。**左**、**上**、**幅**、**高さ**の欄でパーセントで指定でき、2つのプレビューが、その範囲で許される最も縦長の切り抜きと最も横長の切り抜きを示します。
- **SVGソース**：SVGの図の場合に、アップローダーの下に表示されるソースエディターです。編集できるのはテキストノード、つまり`<text>` / `<tspan>`要素の内容だけで、エディターでは色付きで表示されます。それ以外の場所への入力は受け付けず、テキストノードに入力した`<`、`>`、`&`はエスケープされるので、ファイルは整形式のまま保たれます。変更は少し間を置いて**新しい**ファイルとして保存され、図が描き直されます（単色インクへの色の置き換えも含みます）。SVGにテキストノードがないときは、エディターがそのことを知らせます。
- **プレビュー**：リソースがどう見えるかをその場で示す見本で、番号の代わりに`#`が表示されます（実際の番号は、リソースが文書のどこに置かれるかで決まります）。キャプションは文書が設定するラベルで始まります。タイプのキャプションの接頭辞と番号（`Figure #.`）、空のテンプレートで番号を付けるタイプでは接頭辞だけ（`Do.`）、キャプションの接頭辞がないタイプでは何も付きません
- **削除**：先に確認を求め、本文の`::resource` / `:ref`の参照のうちいくつが行き先を失うかを警告します

**表エディター**。表のリソースでは、対話的なグリッドエディターが開きます。

- **ツールバー**：
  - 行と列の追加と削除、セルの結合と分割。
  - 見出し行と見出し列の切り替え。
  - 各セルの水平方向と垂直方向のそろえ（上、中央、下）の設定。行が高いとき、セルの内容は1つのまとまりとして移動します。
  - 各セルの塗りの設定。パレットと連動できるカラーピッカーと、消去ボタンがあります。塗りは`TableCell.background`に書き込まれ、グリッドにも表示されます。
- **列幅**：グリッドの下に、列ごとに1つの数値の重みを指定します（`2, 1, 1`なら最初の列が幅の半分になり、空欄なら均等な幅になります）。値は`table.model.columnWidths`に書き込まれます。列を追加または削除しても重みの対応は保たれ、**均等な幅**のリンクで重みを消去します。
- **表として貼り付け**：TSV（または単純な引用符付きCSV）を貼り付けると、グリッドが埋まります
- **取り消し / やり直し**：Cmd/Ctrl+ZとShift+Cmd/Ctrl+Z
- **キーボードでの移動**：Tab / Shift-Tab（行の端で折り返す）と矢印キーでセル間を移動します
- **プレビューからクリックして編集**：どちらのプレビュータブでも、表のセル、キャプション、注記、またはSVGの図の文字の一部をクリックできます。**リソース**パネルがそのリソースで開き、対応する欄にフォーカスが移って、クリックした字の位置にキャレットが置かれます。ドラッグすると同じセルや欄の中で範囲を選択し、ダブルクリックすると語を選択します。欄にフォーカスがある間は、その選択範囲がCanvasタブとHTMLタブの両方でページ上に強調表示として映し出されます（範囲が空のときは細いキャレット）。

すべての編集は、postextのコアがエクスポートする純粋なモデル関数（`addRow`、`addColumn`、`removeRow`、`removeColumn`、`mergeCells`、`unmergeCell`、`setCellContent`、`setAlignment`、`parseTSV`）を通して行われるので、同じ表のモデルはSandboxの中でも外でもまったく同じように振る舞います。

#### フォントパネル

本で使われている書体を表示し、組み込みのGoogle Fontsのカタログと並べて、自分のフォントファイルを管理します。

- **この本の書体**は、デザインで使われているすべてのファミリーを一覧にします。各ファミリーの名前はそのファミリー自身の書体で表示され、役割（**本文**、**見出し**、**その他の要素**）と入手元（**Google Fonts**または**自分のファイル**）が付きます。書体そのものは**デザイン → 文字組み**と**見出しと目次**で変更します。
- **自分のフォントファイル**では、カスタムファミリーを追加、名前変更、削除します。
  - ウェイト（100～900）とスタイル（normal / italic）ごとに**ファイルをアップロード**します。受け付ける形式はWOFF2、WOFF、TTF、OTFで、ファイルの拡張子で判定します。ファイルはブラウザーのIndexedDBに保存されます。
  - カスタムファミリーは、どのフォントピッカーでもGoogle Fontsの結果と並んで**カスタム**グループに表示されます。同じ名前のGoogle Fontがあるときは、カスタムファミリーが**優先されます**。
  - 中国語の文書では、どのフォントピッカーも、文書の文字を収めたGoogleのファミリー（Fontsourceの`chinese-simplified`、`chinese-traditional`、`chinese-hongkong`サブセット）を**簡体字中国語**または**繁体字中国語**の下に先に並べ、その後に残りを並べます。
  - アラビア語（またはアラビア文字で書くほかの言語）の文書では、どのフォントピッカーも、Fontsourceの`arabic`サブセットを持つGoogleのファミリーを**アラビア語**の下に先に並べます。その中でも書籍用の書体（Amiri、Noto Naskh Arabic、Scheherazade New、Markazi Text、Lateef、続いてNoto Kufi Arabic、Reem Kufi、Aref Ruqaa、El Messiri）が先頭です。プレビューは最初のレイアウトの前に各書体のアラビア文字用のファイルを読み込み、本文が両方の文字を使うときは、PDFはラテン文字用のファイルと一緒にそれを埋め込みます。
  - 孤立したフォントファイル（どのファミリーにも使われなくなったアップロード）は、IndexedDBから自動的に削除されます。

#### デザインパネル

`PostextConfig`をフォームで編集するエディターで、500を超える項目があります。

**概要**。**デザイン**パネルを開くと、まず概要が表示されます。

- ページの図をその場で描く**この本**のカード。図は実際の比率でページを描き、余白、段、ページとインクの色を示します。余白が左右対称（見開き）のときは見開きで描きます。縦組みの本では行がページの右から下へ向かって描かれ、段は段（tier）として描かれます。横には仕上がりサイズ、段組み、表記体系、本文の書体とサイズ、パレットが並びます。表記体系の行は文書の言語を示し、選択の余地があるときは方向と綴じも示します（「縦組み · 右綴じ · 中文（繁體）」、「右から左 · 右綴じ · العربية」）。この行から**表記体系**が開きます。
- 13の**設定グループ**の一覧。各グループには1文の説明と、そのグループ内で変更した節の数が付きます。

**グループごとに1ページ**。グループを開くと、そのグループの節が独立したページとして表示されます。組み立てるのはそのグループだけなので、大きな本でもパネルの動作は軽いままです。

- パンくずリスト（**デザイン › グループ**）から概要に戻れます。
- ページの見出しの下にあるチップで、ページ内の各節に移動できます。
- 下端の**次へ**のリンクで次のグループを開きます。
- グループを開くとフォーカスはページの見出しに移り、戻るとそのグループの行に戻ります。
- 開いていたグループはセッションをまたいで記憶されます。

グループは、表示順に次のとおりです。

- **ページと段組み**
  - **ページ**：項目は**サイズ**、**余白**、**紙**、**ノンブル**にまとめられています。
    - **サイズ**：サイズのプリセットは用途を示しています。**ポケット判** 11 × 17、**小説、物語** 12 × 19、**評論、手引書** 17 × 24、**教科書、雑誌** 21 × 28、新聞の判型の**ブランケット判** 37.5 × 59.7、**ベルリナー判** 31.5 × 47、**タブロイド判** 28 × 43、**コンパクト判** 29.7 × 42（postext 1.18以降）、または**カスタム**です。<strong>レイアウト解像度（1インチあたりのpx）</strong>（`page.dpi`）もここにあります。レイアウトが扱うピクセル数で、画像の解像度ではありません。ただし、自身の解像度を持たないビットマップはこの値のppiで印刷されます。
    - **余白**：各余白はページの図と連動しています。余白の項目にポインターを合わせるかフォーカスを移すと、図上のその余白に色が付きます。**見開きの余白**のスイッチで、左右の余白が見開きページ用ののどと小口の余白に変わります。
    - **紙**：ページの背景色。
    - **ノンブル**：ページ番号の書式と、ページの開始番号。
  - **段組み**：レイアウトは図入りのカードから選びます。**1段組み**（小説、評論）、**2段組み**（教科書、雑誌、参考図書）、**1段半組み**（本文の段に、注や小さな図のための細いサイド段を加えたもの）、**多段組み**（新聞や雑誌向けの同じ幅の3〜8段。段数は**段数**で指定。postext 1.18以降）です。この節には段間、サイド段、**収まらない図を縮小**（`layout.fitFiguresToPage`）、**ビットマップの解像度**（`layout.bitmapResolution`。**ページのdpi**、以前にアップロードした画像の解像度も読み取る**ファイルから**、またはppiを指定する**固定**）、**フロートの図版を縮小**とその**最小倍率**（`layout.floatShrink`）、**フロートを参照するページの先頭に置く**（`layout.floatsAtCitingPage`）とその**参照ページ先頭のフロートの最大比率**（`layout.maxTopFraction`）、**インラインの図の前後のアキ**（`layout.inlineResourceGap`）、**囲み内の図の前後のアキ**（`layout.inlineResourceGapInBoxes`）、**囲みの分割位置に残す段落の行数**（`layout.boxChildSplitMinLines`）、**章末のフロートを本文に寄せる**（`layout.hugClosingFloats`）もあります。
  - *回り込み*：**本文回り込みの間隔**、**横の本文の最小幅**、**横の最小行数**、**回り込みの幅**（`layout.wrap`）。本文が回り込む図版とボックスの既定値です。
- **表記体系**：ページの冒頭には**ページと段組み**の図が表示されます。その見開きにはノンブルが付き、左綴じの本では2 | 3、右綴じの本では3 | 2となります（右綴じでは奇数ページが左側です）。キャプションは、本が右綴じのときと、行が縦組みのときにそれを示します。
  - **言語と書字方向**：

- **文字組み**

    - **色**：本文、太字、イタリックの色。
    - **言語**：文書の言語を、その言語自身の名前で示します。設定は**表記体系**で行い、この行からそのグループが開きます。
    - **ウィドウ、オーファン、短い行**（折りたたみ可）：**段階的なラントのペナルティ**（`bodyText.gradedRuntPenalty`）、**詰めてラントを解消**（`bodyText.tightenRunts`）、**字間を詰める上限**（`bodyText.maxRuntTracking`）、そして**コロンとリストを離さない**と**コロンの下に必要な余地**（`bodyText.colonListRoom`）を含みます。後者は、コロンで終わる行がリストと離れずにいるために、その下に必要な余地を決めるもので、最初の項目が必要とする分か、postext 1.4までと同じ1行かを選びます。
    - **引用ブロック**（折りたたみ可）：`>`の引用の色、**引用ブロックをイタリックに**、**引用ブロックのインデント**、**引用ブロックの1行目の字下げ**（`bodyText.blockquote`）。
    - **詩**（折りたたみ可）：**区切りのない詩**（*行ごと*、または*半句として（1.22）*）、**空白1つの字下げ**、**折り返し**（*ぶら下げ*または*右寄せ*）とその**折り返しの字下げ**または**折り返しの記号**、**連と連のあき**、**短い連を分けない**、**折り返す前に詰める**（`bodyText.verse`。行ごとに組む`:::verse`の詩の既定値）。
    - **相互参照**（折りたたみ可）。
  - **段落スタイル**（`paragraphStyles`）：`:::paragraphs{style="…"}`コンテナーのための名前付きスタイルです。IDの追加、削除、名前変更ができ、フォント、サイズ、行の高さ、色、太字とイタリックの部分の色、標準と太字のウェイト、**イタリック**と**スモールキャピタル**のスイッチ、そろえ、ハイフネーション、すべての行の左インデント、1行目の字下げとぶら下げインデント（左インデントから測る）、段落間のアキ、余白、**グリッドに合わせる**（`paragraphStyles[].snapToGrid`）、**大文字・小文字**（`textTransform`、大文字）、**行番号**（`paragraphStyles[].lineNumbers`：**文書に従う**、**数える**、**数えない**）、本文と同じように設定する**タブ位置**と**既定のタブ間隔**（`paragraphStyles[].tabStops`、`tabInterval`）、**ドロップキャップ**（`paragraphStyles[].dropCap`）を設定します。ドロップキャップでは、またがる行数と沈む行数、大きくする文字数、書体、ウェイト、イタリック、サイズ、色、アキ、**始め括弧類**（**頭文字と一緒に**、**外にぶら下げる**、**最初の行に置く**）、**リードイン**（なし、語数、または最初の行。スモールキャピタルか大文字）、**短い段落**の扱い（**空きを取る**、**頭文字を小さくする**、**ドロップキャップなし**）、項目の並ぶカタログのための**すべての段落**を指定します（[ドロップキャップ](/ja/docs/configuration#ドロップキャップ)を参照）。設定していない項目は本文から継承されます。スタイルの上にある**コンテナーの下のアキ**（`bodyText.paragraphContainerSpacing`）は、コンテナーの下のアキと後続のブロックとの関係を決めます（**相殺**または**加算（1.4）**）。
  - **インラインラベル**（`chipStyles`）：インラインの`:chip[text]{style="…"}`のための名前付きスタイルです。設定にスタイルがない間は、組み込みの`chip`スタイルが表示されます。IDの追加、削除、名前変更ができ、次の項目を設定します。
    - **テキスト**：フォント、サイズ、色、太字、イタリック。どれも設定するまでは周りの本文を継承します。
    - **ボックス**：塗り、枠線の太さと色、角の半径、左右と上下の内側余白（**上の内側余白**と**下の内側余白**で上下を別々に指定でき、丸いチップの中で大文字を中央に置けます）、隣の語との最小の間隔。
  - **コード**（`codeStyle`）：**コードフェンス**と**字下げのコード**（コードリストの読み取り方）、**コードの書体**、サイズ、行送り、**グリッドに合わせる**、色、**タブ幅**、**枠**（ページ幅、背景、枠線、角の半径、内側余白、上下のアキ）、**長い行**（**枠より長い行**：*折り返す*、**最小サイズ**付きの*縮小*、*切る*。**続きの字下げ**と**続きの記号**）、**行番号と強調行**（**行番号を付ける**、番号の色とそのあとのアキ、フェンスが強調する行の色）、**段・ページをまたぐとき**の分割（分割しない、分割の前後に残す行数、タイトルの繰り返し、「続く」マーカー）、**構文の色分け**（*組み込み*か*なし*、字句の種類ごとの色とスタイル。パレットの色も使えます）、背景を付けてコードの書体で組む**インラインコード**。[コードリスト](/ja/docs/configuration#コードリスト)を参照してください。
  - **数式**（`math`）：**別行立て数式の後の字下げ**（`math.indentAfterDisplay`）と**導入行と離さない**（`math.keepWithLeadIn`）があります。
  - **脚注**（`footnotes`）：**配置**（段の末尾か章末か）、章末に置く場合の**段内の位置**、**番号付け**（章ごとか通しか）、注のサイズ、行送り、色、そろえ、ぶら下げインデント、注の上と注同士の間のアキ、**区切り罫**（長さ、太さ、色）。[脚注](/ja/docs/configuration#脚注)を参照してください。
  - **行番号**（`lineNumbers`）：**行番号を付ける**、**数える行**（**詩行**または**すべての行**）、**間隔**、**最初の行にも付ける**、**数え直し**（しない、または章、節、ページ、詩ごと）と**最初の番号**、**位置**（小口側またはのど側の余白、左、右、行頭側、行末側、サイド段）、**段組のとき**（外側の両端、段間、各段の脇）、**本文からの距離**、**そろえ**、番号の書体、サイズ、ウェイト、イタリック、色、**番号の書式**。[行番号](/ja/docs/configuration#行番号)を参照してください。
- **見出しと目次**
  - **見出し**：全体の既定値と、レベルごと（H1～H6）の設定です。次の項目があります。
    - 大文字・小文字、**字間**（`levels[].letterSpacing`、負の値で詰める）、行そろえ（左そろえ、両端そろえ、中央そろえ、右そろえ）、改ページとその奇偶、幅。
    - **見出しの後でグリッドに戻す**スイッチ（`headings.snapToGrid`、既定でオン：見出しの下で本文がベースライングリッドに戻る）と、そのレベルについてこれを上書きするレベルごとの**この見出しの後でグリッドに戻す**（`levels[].snapToGrid`）。
    - **見出し内の文字書式**スイッチ（`headings.inlineMarks`、既定でオン）：見出しの中に書いたイタリック、太字、上付き・下付き、スモールキャピタル、リンクを、段落と同じように組みます。オフにすると、印の付いた語も見出し自身のスタイルで印刷します。
    - レベルごとの**非表示（構造のみ）**（`levels[].hidden`）：見出しは何も印刷せず場所も取りませんが、改ページ、番号付け、目次、柱、PDFのしおりへの反映は行われます。
    - レベルごとの**見出しのあとのドロップキャップ**（`levels[].dropCap`）：そのレベルの見出しのあとの最初の段落をドロップキャップで始めます。項目は段落スタイルのものと同じです。
    - 最小の章扉の高さを指定できる、レベルごとの高度なデザインスロットのエディター。見出しのデザインの各要素には**スペースを確保**スイッチがあります（オフにすると、見出しが確保する高さに加えずに描画します）。
    - 段末そろえの手段とその手段ごとの上限、そして**段末の囲み**（`balancing.closingBox`）：短い段の末尾にある囲みを段の下端に下げるタイミングを、最初に、ほかの手段の後で、しない、から選びます。
  - **見出しスタイル**（`headingStyles`）：見出しの行に`{style="…"}`で適用する名前付きスタイルです。IDの追加、削除、名前変更ができ、スタイルごとに次のことができます。
    - 見出しに番号を付けるか、目次に載せるかを選び、独自の番号のテンプレートを与える。
    - 章の中にH1として置いた図版や地図のために**柱に章名を出す**（`runningChapter`）をオフにし、柱が中断された章の名前を出し続けるようにする。
    - 次の項目を上書きする：見出しの文字組み（字間を含む）、改ページと幅、**この見出しの後でグリッドに戻す**、**非表示（構造のみ）**。また、**見出しのあとのドロップキャップ**を選ぶ：**レベルと同じ**、**独自**（項目は段落スタイルのものと同じ）、**なし**。
    - 節に独自の柱を与える（文書の柱をもとにすることもできます）。
    - 余白と段組みを設定する（**段組み**と同じくサイド段の役割と位置、独自の**収まらない図を縮小**も含みます）。
    - 本文のスタイル、リストの上書き、パレットの色を設定する。
  - **目次**（`toc`）：`:::toc`が載せる見出しレベルと、それぞれの項目の文字組みです。番号のない項目、ページ番号、リーダー罫、見出しの属性から読む副題の行、独自のデザインスロットを持つ部の行も扱います。
- **リスト**
  - **箇条書きリスト**：**上端をグリッドに合わせる**（`unorderedLists.snapTopToGrid`）があり、リストの上のアキを切り上げて、最初の項目がベースライングリッドに乗るようにします。
  - **番号付きリスト**：レベルごとに、番号の横に置く区切りのフォント、ウェイト、イタリック、色、間隔。**上端をグリッドに合わせる**（`orderedLists.snapTopToGrid`）は箇条書きリストと同じです。**番号欄**（`orderedLists.numberWidth`）は項目の本文が始まる位置を決めます。同じ連続部分の中で最も幅の広い番号の後（**連続部分ごと**）か、章内の同じレベルで最も幅の広い番号の後（**レベルごと**）です。
- **図と表**
  - **番号付けと配置**（`resourceTypes`）：リソースタイプごとに次の項目があります。
    - 名前と短いラベル。
    - `{n}`と`{h1}`…`{h6}`のプレースホルダーを使う番号のテンプレート、カウンターの書式とリセットのレベル、キャプションの接頭辞。「Fig. 1.7」のような形のプレビューがその場で表示されます。
    - **配置**グループ：タイプの既定の位置、幅（段、ページ、サイド段）、**段数**（このタイプの段のフロートが複数段のページでまたぐ隣り合った段の数。ページの段数と同じにするとページ幅になります）と回転、幅の割合、配置先より狭いリソース（幅で狭められたフロートや埋め込み、段より狭い画像）のそろえ、図の横にキャプションを置くスイッチ。
    - 折りたたみ式の**キャプションスタイルの上書き**。そのタイプについて設定したキャプションの項目（位置、帯、色、書体）だけを置き換え、残りは継承します。
  - **キャプション**（`captionStyle`）：書体、サイズ、そろえ、リソースの上か下かの**位置**。任意の**背景の帯**とその色と内側余白があり、ラベルと説明は別々にスタイルを設定できます。**注記**グループでは、リソースの注記のサイズ、色、傾き、そろえ、間隔を設定します。
  - **表**（`tableStyle`）：
    - 本体と見出しの文字組み（見出しの**字間**（`headerLetterSpacing`）と**大文字・小文字**（`headerTextTransform`）を含む）と塗り。
    - 罫線と**罫線**のパターン：全面の格子、横罫のみ、外枠のみ、なし、**booktabs（三本罫）**（表の上下に太罫、見出しの下に細罫、まとめ見出しの下に両端を詰めた罫）。booktabs を選ぶと、各罫線の太さ、まとめ見出しの下の罫線とその詰め幅、**グループ罫**、**ページより高い表**の下の「次ページへ続く部分の下の罫線」が表示され、罫線の太さと角の半径は隠れます。
    - 外枠の**角の半径**。
    - セルの内側余白。
    - **本体のセル**の下の**縞模様の行**（`bodyAlternateBackgroundEnabled`）。本体の行を1行おきに**交互の行の色**（`bodyAlternateBackground`）で塗り、この色の項目はスイッチがオンの間だけ表示されます。
  - **表スタイル**（`tableStyles`）：名前付きの表スタイルです。IDの追加、削除、名前変更ができ（名前を変えると、そのIDを使う表も一緒に変わります）、**表**のどの項目も設定できます。各コントロールは、設定するまで**表**から継承した値を表示します。
  - **ダイアグラム**（`diagramStyle`）：単色刷りのためにSVGのダイアグラムを1色のインクの濃淡に置き換える**単色刷りのダイアグラム**のスイッチと、パレットのメインカラーを既定とするインクの色のピッカー。
  - **動画スタイル**（`videoStyle`）：動画のポスター画像に印刷する**再生マーク**（形、位置、サイズ、端からの距離、色、背景の不透明度）と**QRコード**（位置、サイズ、端からの距離、誤り訂正、余白、色、角の半径）。**出力**：ポスター画像を動画にリンクするかどうか、HTMLビューアーでプレーヤーとポスター画像のどちらを表示するか。そして、すべての動画の出発点となる**プレーヤー**のスイッチ。その中の**他の動画と同時に再生**は、オンなら動画ファイルを再生しても他の動画は止まらず、ページ上の無音のループ動画を同時に流せます。オフなら再生すると他の動画を一時停止します。HTMLビューアーとFolioで有効です。
- **囲み**
  - **囲みスタイル**（`calloutStyles`）：`:::callout{type="…"}`のための名前付きスタイルです。IDの追加、複製、削除、名前変更ができ、次の項目を設定します。
    - 既定のタイトル、幅、配置、横幅と**段数**。段数は、浮動する囲み（配置が**自動**、**上**、**下**で、幅が段のもの）が複数段のページでまたぐ隣り合った段の数です。`:::callout`の`columns`属性で上書きできます。
    - 背景、枠線、角の半径、内側余白、端の**帯**。
    - **アイコン**：文字の記号か、**リソース**パネルから選んだSVGやビットマップ。インラインか角のバッジとして置け、角の位置と、正方形でない図版のための幅を指定できます。
    - **ラベルタブ**グループ（`calloutStyles[].label`）：フォント、サイズ、ウェイト、色、塗り、角、高さ、内側余白、オフセット、インセット、タブの横に置くアイコンのリソース、上辺に沿った罫。
    - タイトルの文字組み。字間、字下げ、**タイトルの行送り**（`titleStyle.lineHeight`）を含みます。
    - 文書の本文を継承する本文とリストの上書き。本文の太字と**イタリックの色**、標準と太字のウェイト、**イタリック**と**スモールキャピタル**のスイッチ、**タブ位置**と**既定のタブ間隔**（`body.tabStops`、`body.tabInterval`）、箇条記号のサイズとウェイトを含みます。
    - 囲みの中の`:::columns`グループのための段間。
    - **グリッドに合わせる**スイッチ（`calloutStyles[].snapToGrid`、既定でオン。オフにすると、積み重ねた囲みの下の余白を正確に保ちます）。
    - マーカー欄、固定の位置、分割の禁止と分割時の最小行数、フロートの障壁のコントロール。
    - **段末でのサイドの囲み**の選択（`sideAtColumnEnd`）：本文が同じ段で続かないサイドの囲みを、フェンスの前の本文の横に置くか、後の本文の横に置くかを選びます。
    - **分割された囲み**グループ：続きの部分ごとに接尾辞付きでタイトルを繰り返すこと（`repeatTitle`、`continuedSuffix`）と、続きがある各部分の下に置く継続マーカー、その文字列、そろえ、イタリック（`continuesMarkerEnabled`、`continuesMarker`、`continuesMarkerAlign`、`continuesMarkerItalic`）。文字列は既定で文書の言語に従います。
- **柱とノンブル**
  - **柱とノンブル**：スロットごとのテキスト、罫、ボックス、画像の要素。
    - **テキスト要素**：垂直方向のそろえ、要素自身のボックス内での**行そろえ**（`align`：左そろえ、中央そろえ、右そろえはボックスがテキストより広いときに効きます。両端そろえは、各段落の最終行を除くすべての行のスペースを広げてボックスを埋め、**ハイフネーション**がオンなら音節で語を分けて行を埋めます）、行の高さ、字間（負の値で見出し用の大きなタイトルを詰める）、大文字・小文字、内容に合わせる・埋める・固定の幅と高さ、最大幅。**インラインの書式記号**（`inlineMarks`）は、要素のテキスト内の`**bold**`、`*italic*`などのインライン書式を組みます。輪郭線は文字の輪郭を描きます。**輪郭線の太さ**、**輪郭線の色**、**袋文字**（`stroke`）です。
    - **罫**：水平または垂直。
    - **プレースホルダー**：エンジンの許可リストから選びます。ページ番号、総ページ数、本の総ページ数、タイトル、サブタイトル、著者、発行日、章のタイトルと番号、部のタイトルと番号、章の属性のための`{attr.key}`です。柱とノンブルでは、ページ上端の章のタイトルと番号`{chapterTitleAtTop}` / `{chapterNumberAtTop}`（[ページ上端の章](/ja/docs/configuration#ページ上端の章)を参照）と、柱見出し語`{firstMark.h2}` / `{lastMark.h2}`（ドットの後は見出しレベルか段落スタイルのID。[柱見出し語](/ja/docs/configuration#柱の見出し語最初と最後のマーク)を参照）も使えます。
    - **スロットを表示する場所**：奇偶と、**ページ**の絞り込み（すべて、本文、章扉、部扉、白ページ）。
    - **配置**：はみ出しと、コンテナー、兄弟要素、または端まで届く帯のための**ページ** / **裁ち落とし**の枠への固定。柱とノンブルの要素は、背から離れた側の余白である**小口の余白**（`'outer'`）にも固定できます。
    - テキスト要素の**組み方向**：**横組み**か、縦組みの本の小口に柱を組むための**縦組み（行は右から左へ）**（`writingMode`）。柱のエディターの「**小口の柱（縦組み）**」は、版面の天から4字下に章のタイトルを、地から5字上にノンブルを、どちらも縦組み、本文サイズの80 %で、小口の余白に固定して加えます（[縦組みのテキスト要素](/ja/docs/configuration#縦組みのテキスト要素)を参照）。
    - **ドロップキャップ**グループ（行数、フォント、ウェイト、サイズ、色、間隔）と段落の字下げ。ドロップキャップのあるテキストは**はみ出し**の設定にかかわらず折り返し、サイズを設定しなければ、文字の上端は1行目の大文字の高さにそろいます。
    - ほかのすべてのデザインスロットにも、同じテキストのコントロールがあります。
- **部**
  - **部**（`parts`）：
    - **部扉**（`parts.page`）：オフにするとページを開かず、部の番号、タイトル、色は次の内容からそのまま適用されます。下の設定も非表示になります。
    - `:::part`が開くページの奇偶と、部の後の任意の改ページとその奇偶。
    - 部扉の余白。ページの余白を継承し、同じ見開き用ののどと小口のラベルを使います。
    - ページの仕上がり枠を基準に配置する**部扉のデザイン**のスロット。そのプレースホルダーのピッカーには、見出し用の一式（現在のタイトルと、その番号の算用数字、ローマ数字、アルファベットの形）が加わります。
    - 部の中のブロックのための**本文のスタイル**。本文とリストの色を継承し、リストの上書き（番号の書式とオフセット、余白、ぶら下げインデント、タスクリストの項目）を含みます。
- **書き出し**
  - **印刷の準備**（`print`と`page.cutLines`）：4つのグループがあります。
    - **トンボと塗り足し**：トンボ、裁ち落とし、トンボの長さ・間隔・線幅、画面での色。
    - **PDF/Xと色**：**PDF規格**（<strong>なし（通常のPDF）</strong>、**PDF/X-1a:2003**、**PDF/X-4**）。**出力プロファイル**は、自由に使える15のプロファイルから選びます（既定はFOGRA39、PSO v3の条件にはFOGRA51とFOGRA52、ほかにGRACoL、SWOP、新聞用紙）。印刷所から渡されたプロファイルは**ICCプロファイルをアップロード**で使い、その**印刷条件**（PDF/Xの出力インテントに書き込むレジストリ名）を入力します。アップロードしたプロファイルは削除ボタンで外せます。さらに**レンダリングインテント**、**黒点の補正**、**画像をCMYKに変換**（常に変換するPDF/X-1aでは表示されません）、<strong>総インキ量の上限（%）</strong>があります。
    - **黒**：**グレーと黒はK版のみ**、**墨100%をオーバープリント**、**大きな面にはリッチブラック**と、そのC・M・Y・Kの配合、リッチブラックにする面の大きさ。
    - **プリフライト**：**検査でプリフライト**、画像の最低解像度と重大とする解像度、罫の最小の太さ、複数のインキで刷る文字に印を付けるサイズ、セーフゾーン、ボックスを塗り足しまで伸ばすべき距離、**配置したPDFのフォントを確認**。

    [設定 → 印刷出力](/ja/docs/configuration#印刷出力設定)を参照してください。
  - **PDF**：しおり、アクセシブルな（タグ付きの）PDF、色空間の強制。CMYKへは**印刷の準備**の出力プロファイルで分版されます。
  - **Webリーダー（HTML）**：`htmlViewer`の設定。
- **Folio**
  - **Folioビューアー（3D）**（`folio`）：5つのグループがあります。**視点**（傾きと回転）、**紙**（用紙、坪量、嵩とそこから求まる紙厚、仕上げ、テクスチャーとその強さ、色合い、裏写り）、**製本**（方式、表紙、表紙の素材と色、背の画像。<strong>折り（新聞）</strong>は、一度折った紙を何も留めずに重ねて挟み込む、新聞のような製本です。<strong>中綴じ（ホチキス留め）</strong>と同じく印刷できる背がないので、背の画像は表示されません）、**置き台**（机の素材と色味）、**照明**（環境、露出、影）です。別の用紙を選ぶと、変更していない項目にその用紙の値が入り、変更した項目は自分の値のままです。新聞の判型では、選んでいない用紙と製本は**新聞用紙**と<strong>折り（新聞）</strong>になります。背の画像は**リソース**パネルのビットマップとSVGから選びます。[Folioタブ](#folioタブ)を参照してください。
- **詳細設定**
  - **画面表示の補助**（`debug`）：**ベースライングリッド**（`page.baselineGrid`。**ページ**ではなくここにあります）と、そのほかのレイアウト確認用のオーバーレイ。
  - **警告**：**検査**パネルが報告する問題とそのしきい値。

**設定を探す**。ヘッダーの下のツールバーは、すべてのグループにまたがって働きます。

- <strong>設定を検索…</strong>は、すべての節のすべての項目を、ラベル、説明文、選択肢の名前で絞り込みます。アクセント記号を区別せず、語の先頭に一致します。*marg*で*Top margin*と*Margen superior*が見つかり、*h3*で**見出し › H3**が開きます。結果は設定グループごとにまとめられます。一致する節は自動的に開き、一致しない行と節は非表示になり、一致した箇所は強調表示されます。Escapeで検索を消去し、もう一度押すと欄から離れます。
- **変更あり**は、値が既定値と異なる項目だけを表示します。

**説明文**。どの項目にも短い説明があります。スクリーンリーダーには項目の説明として読み上げられ、画面上では行の「?」ボタン（「『…』とは？」）で開くまで隠れています。ヘッダーの**すべての説明を表示**スイッチですべての説明を一度に開け、その選択は記憶されます。

**変更した値**。パネルは一貫した**上書きモデル**に従います。

- 節のヘッダーには、入れ子のグループまで数えた、中で変更した項目の数のバッジが付きます。
- 節のヘッダーのリセットボタン（確認があります）は、節に変更が含まれる間だけ表示されます。
- 変更した項目のラベルの横には点（「変更あり」と読み上げられます）と、その項目専用の小さなリセットボタンが付きます。
- 保存や書き出しの対象になるのは、変更した部分木だけです。既定値は取り除かれるので、手つかずのSandboxが保存する設定は空です。
- **ページ**をリセットしても、ベースライングリッドはそのままです。グリッドは**詳細設定**で編集するからです。

**コントロール：**

- 選択肢はドロップダウンで、各選択肢に1行の説明を付けられます。選択肢が少ないときはセグメントボタンになります。
- オン・オフの設定はスイッチです。
- 数値には− / +のステッパーがあります。矢印キーで値を1段階ずつ変え、Shiftを押しながらなら10倍、Altを押しながらなら10分の1ずつ変えます。
- 長さには単位の選択があり、単位を変えると値が換算されます（cm、mm、in、pt、px、em、rem）。
- 色は、色見本と値を表示する1つのボタンです。
- フォントピッカーは矢印キーで操作できます。

コントロールは文脈に応じて変わります。段間の幅は段組みのレイアウトでだけ表示され、両端そろえの設定は本文が両端そろえのときだけ表示されます（行末不ぞろいの本文では代わりに**行末不ぞろいのテキストもハイフネーション**が表示され、段落スタイルや囲みでは、それが両端そろえのときか行末不ぞろいのハイフネーションがオンのときにハイフネーションのスイッチが表示されます）。サイド段の割合は1段半組みのレイアウトでだけ表示されます。変更はすぐにビューポートのプレビューに反映されます。すべての設定項目とその既定値の詳しいリファレンスは、[設定](/ja/docs/configuration)のページを参照してください。

パネルのヘッダーには、さらに**リセット**（確認があります。デザインが開いている見本の本のものと異なるときだけ表示され、その見本のデザインをフォントも含めて戻します）、**書き出し**、**読み込み**があります。[書き出しと読み込み](#書き出しと読み込み)を参照してください。

#### 検査パネル

本文、デザイン、図、直近のビルドからその場で計算し直す診断です。件数はアクティビティバーのボタンのバッジと一致します。警告は種類ごとに、対処すべき順にまとめられます。まず出力を壊すもの、次にマークアップ、最後にふつうは細かい項目が数多く出る組版の仕上げです。各グループは折りたたむことができ、件数を表示します。

- **フォント**：フォントファミリーがない、カスタムファミリーでウェイトやスタイルのバリアントが欠けているか重複している、そして**フォントファミリーにフォントスタックを指定**：`fontFamily`の設定がCSSのフォントスタックを持っている（本文はその最初のファミリーで組まれます。項目は設定のパスを示します）
- **図と表**：`::resource` / `:ref`の中の不明なリソースID（本文が使う図のキャプション、注記、セルの中や、表のセルの画像としてのものも含む）、重複するリソースID、存在しないリソースタイプへの参照、ピクセルサイズより大幅に大きく描画されるビットマップ、どの表スタイルも指さないスタイルIDを持つ表、不規則なまま残った表のグリッド（結合セルが覆うセルが欠けている、または行に穴がある。表エディターでセルを結合し直してください）、ファイルがストレージにないか復号できない画像（プレースホルダーとして表示されます）、ポスター画像のない動画、公開先のアドレスのない動画ファイル（印刷物にQRコードもリンクも付かない）、どの動画も指さないYouTubeやVimeoのアドレス、ページの空きに収めるため小さく組んだフロートの図版（*収まるよう縮小した図版*：項目に倍率と、最小倍率でも版面からはみ出すときはその量をmmで示します）、指定どおりに本文を回り込ませられなかった図版やボックス（*回り込む図版・ボックス*：横の行長が狭すぎる、横に行を組むには低すぎる、次の段へ移った、または縦組み）
- **本文とマークアップ**：
  - 見出しの階層の飛び（たとえばH1 → H3）と、間に本文のない連続した見出し。
  - 不正な、または閉じていない`$…$` / `$$…$$`の数式。
  - 不明なディレクティブ名（パーサーが知っている名前はすべて受け付けます：`pagebreak`、`columnbreak`、`space`、`numbering`、`toc`、`callout`、`paragraphs`、`part`、`columns`）、不正な番号付けや奇偶の属性、0～20行の範囲外の`:::space{lines=N}`。
  - 文書の終わりまで閉じられていない`:::`コンテナーのフェンス（クリックすると開始行にフォーカスが移ります）。
  - スタイルが設定されていない`:::paragraphs{style="…"}`、`:::callout{type="…"}`、`:chip[…]{style="…"}`、見出しの`{style="…"}`。
  - 文字として印刷されてしまう`::resource`の行（書式が不正か、空行なしで段落の下にくっついている）。
  - **全角の記法**：中国語や日本語の入力方式で入力したマークアップ（`：：：`、`＃`、`［＾…］`、`｛…｝`、`＊＊…＊＊`）で、文字として印刷されます。項目には入力すべきASCIIの形が示されます。
  - **読み取れない属性キー**：ASCII以外で書かれた属性キー（`作者=曹雪芹`）で、パーサーは無視します。
  - **閉じていないコードフェンス**：閉じるフェンスのない```` ``` ````か`~~~`のフェンスで、以降のテキストはすべてコードとして組まれます（`unclosedCodeBlock`。クリックするとフェンスにフォーカスが移ります）。
  - **縦組みのタブ**：縦組みのテキストにある`:tab`です。タブ位置は横組みでだけ使えるので、語間スペースとして組まれます（`tabInVerticalText`）。
  - **フロントマターを無視**：最初の章以外の章がフロントマターのブロックで始まっている（本に属するのは最初の章のフロントマターだけです）。
- **デザイン**：
  - エンジンの許可リストにない柱とノンブルのプレースホルダー名（`{attr.…}`と部のプレースホルダーは受け付けます）と、文書のメタデータが欠けているプレースホルダー。
  - デザイン要素間の循環する固定、または存在しない要素への固定。この検査とプレースホルダーの検査は、すべてのデザインスロットを対象にします。柱、部扉、部扉の後の白い偶数ページ、目次の部の行、各見出しレベルのデザイン、各見出しスタイルのデザインとその節の柱です。見出しスタイルから出た項目は`{style="index"} header · #rh → #missing`のようにスタイルを示し、偶数ページや目次の部の行から出た項目は`toc.parts.design · #row → #missing`のように設定を示します。
  - クリップのはみ出しで常に切り詰められるテキスト要素。
  - **デザインのテキストの切り詰め**：幅に収まらず省略記号で終わった、またはボックスの外にはみ出して切り取られたデザインのテキスト（`designTextTruncated`）。項目には配置先と要素、テキストの全文が表示されます。クリックすると切り詰められたページが開き、章の見出しやフロントマターの項目ならエディタで選択されます。章のすべてのページで切り詰められる柱は一度だけ表示されます。
  - **見出しのデザインの欠け**：ページに収まらないほど高い見出しのデザイン。章扉のテキストがページの下端を越えて配置される場合や、段内のデザインのテキストが段の下端を越える場合です（小さな画面用のページでの長いリードなど）。見出しはページや段の残りを確保するので、後に続く本文は次のページや段から始まりますが、デザインのはみ出した部分は失われます。項目をクリックすると見出しにフォーカスが移ります。
  - **範囲外のサイド段**：本文の段の場所を残すためにエンジンが範囲を制限した、1段半組みのサイド段。
  - **範囲外の段数**：`multiple`レイアウトの段数が3〜8の整数ではなかったため、エンジンが範囲内に収めたもの。
  - **不明な番号形式**：エンジンが知らないリスト、ページ、リソースタイプの番号形式で、算用数字で番号が付きます。
  - **不明な設定**：見出し、見出しレベル、見出しスタイル、タブ位置にないキー（つづりを誤った`letterSpacng`など）で、エンジンは無視します。最も近い設定があれば、項目がそれを示します。
  - **縦組みに行番号は付かない**：縦組みの文書で行番号を有効にしています。縦組みの文書には行番号が付きません。

  最後の4つは、**フォントファミリーにフォントスタックを指定**と同じく、本文ではなく設定から出るものです。項目は設定のパスを示し、クリックしてもエディターは移動しません。
- **組版**：
  - ゆるい行（語間が設定のしきい値を越えて広がった行）。
  - **行長に満たないCJKの行**：行を埋めると文字の間隔が限度を越えて広がるため、行長に満たないまま残った中国語、日本語、韓国語の行。
  - **圏点・傍線が次の行に接触**と**ルビが次の行に接触**：圏点、人名・書名の傍線、またはルビが、段落にある行間より広い行間を必要としている。項目は両方の値をemで示します。
  - 段からはみ出す囲み。
  - **チップが隣の行に接触**：チップのボックスが上下の行のチップにぶつかっている（重なりはポイントで示します）。上下にチップのない背の高いチップには印は付きません。
  - 奇偶の連鎖。
  - **行番号がサイド段の囲みに重なる**：サイド段の行番号（`lineNumbers.position: 'side'`）が、その段の囲み、キャプション、図に重なっています。どちらもその位置のまま印字されます。
  - **ドロップキャップが設定どおりに組まれていない**：ドロップキャップが沈む行数より短い段落（項目は、空きを取ったか、頭文字を小さくしたか、省いたかを示します）、頭文字の入りきらない短い段で頭文字の最後の行より前で分かれた段落、最初の文字が次の文字とつながる段落（アラビア文字）、縦組みの段落、文字で始まらない段落です（`dropCap`）。
  - **枠より長いコード行**：枠より長い行のあるコードリストです。**コード → 長い行**の設定どおり、折り返されたか、小さく組まれたか（項目はサイズを示します）、切られています（`codeOverflow`）。
  - **この言語のハイフネーションパターンがありません**：文書の言語（ハイフネーションのロケール、なければ`locale`）に同梱のパターンがないため、本文は米国英語のパターンでハイフネーションされます。ハイフネーションをオフにすると消えます。
- **プリフライト**：印刷向けに設定した本（PDF/X規格、CMYKのPDF、またはトンボ）が対象で、重大な問題から順に並びます。
  - **画像の解像度不足**：印刷サイズで最低解像度に満たない画像（重大とする解像度を下回ると重大）。ファイルが実際に持つピクセル数から求めます。
  - **宣言したピクセル数がファイルと合わない**：宣言した幅と高さがファイルのものと異なるビットマップ（多く宣言している場合は警告）。
  - **RGB画像**：書き出し時にCMYKに分版されます。画像を変換しないPDF/X-4では、RGBのまま残ります。
  - **罫が細すぎます**、**複数インキの小さな文字**、**総インキ量が上限を超えています**（CMYKで指定した色、リッチブラックの配合）。
  - **セーフゾーン内の文字**と**仕上がり線の手前で止まっています**（塗り足しまで伸ばすべきボックスや画像）。
  - **配置したPDFに埋め込まれていないフォント**、**配置したPDFにRGB**、**配置したPDFに透明**（PDF/X-1aでは重大）。各図の印刷用マスターから検出します。

  各項目にはページが示され、クリックするとビューアーでそのページが開きます。
- **ブラウザー**：ストレージが使えない（IndexedDBがない）

各項目には、アイコン、タイトル、1行の詳細と、該当する場合は章とソースの行（複数の章からなる本では「第2章 · 行 12」）が表示されます。ソースの位置を持つ項目をクリックすると、その章に切り替わり、その位置でエディターにフォーカスが移ります。問題がないときは、パネルに**問題なし**と表示されます。どの検査を行うかは**デザイン → 詳細設定 → 警告**で設定します。

### メインビューポート

インターフェースの右側には、描画された出力が表示されます。描画方式ごとに1つ、計5つのタブが**Canvas**、**PDF**、**Folio**、**HTML**、**EPUB 3**の順に並びます。タブを切り替えてもレイアウトは実行し直されません。同じVDTがすべてのバックエンドに渡されるので、どの方式でも表示される内容は一致します。Folioタブは、ブラウザーがWebGL2に対応し、画面がスマートフォンのものでない場合にだけ表示されます（[Folioタブ](#folioタブ)を参照）。

各ビューポートは、専用の**Web Worker**（`postext/worker`）の中でレイアウト処理を実行します。ビューポートごとの`useLayoutWorker`フックがワーカーのハンドルを持ち、フォントを転送可能な`ArrayBuffer`としてワーカーに送り、**後勝ちのキャンセル**でビルドを進めます。キー入力やスライダーのドラッグがあると、次のビルドを始める前に前のビルドの`AbortSignal`を中断するので、速く入力してもメインスレッドに古い処理がたまることはありません。ビューポートをアンマウントすると、そのワーカーは破棄され、待機中のビルドは拒否されます。ここで使っている組み込みのパターンは、[設定 → Web Workerでレイアウトを実行する](/ja/docs/configuration#web-workerでレイアウトを実行する)を参照してください。

#### Canvasタブ

文書のラスタライズしたプレビューを、HTML5の`<canvas>`要素に描画します。正確な文字の位置、段組み、リソースの配置を含め、組み上がった文書の最終的な見た目をピクセル単位で正確に表します。

Canvasのビューポートの上部にあるツールバーには、次の機能があります。

- **ズームのコントロール**：拡大と縮小（1段階ごとに1.25倍、範囲は0.25倍～4倍）。手動でズームすると、合わせるモードは解除されます。
- **合わせるモード**：ページ幅に合わせるか、ページの高さに合わせます。オン・オフを切り替えられ、ウィンドウの大きさが変わると自動的に合わせ直します。
- **表示モード**：単ページ（1行に1ページ）か見開き（本のようなレイアウトで、最初のページは奇数ページとして右側に表示され、以降のページは見開きの組になります）。右綴じの本（`page.binding`、縦組みの中国語）では見開きが逆向きになり、1ページ目が左側に単独で表示され、続いて`[3 | 2]`、`[5 | 4]`となります。縦組みのページでは、クリックするとポインターの下の文字にキャレットが置かれ、キャレットは段を横切る線になります。
- **印刷プレビュー**（`Printer`アイコン）：印刷される見た目でページを表示します。既定ではオフで、ブラウザーが状態を記憶します。すべての色を**印刷の準備**の出力プロファイルで分版し、紙そのものの白の上に表示します。大きな黒い面はリッチブラックで表示し、仕上がり線（青）、塗り足し（マゼンタ）、セーフゾーン（緑の破線）を引き、プリフライトで見つかった箇所を赤い枠で囲みます。Folioタブとスイッチを共有します。ページを描き直すだけで、レイアウトはやり直しません。

ページは`IntersectionObserver`によって遅延描画されます。canvasに描かれるのは表示されているページ（と200pxの余裕）だけなので、長い文書でもGPUのメモリー使用量は少なく抑えられます。

#### PDFタブ

`postext-pdf`パッケージで現在の文書の実際のPDFを生成し、埋め込まれたブラウザーのPDFビューアーに表示します。PDFは最初のマウント時と、その後の再生成のたびに自動で作り直されます。canvasタブとHTMLタブに渡されるのと同じVDTを使うので、改行、ページの区切り、リソースの配置は3つのバックエンドでピクセル単位まで一致します。Knuth–Plassがときに受け入れる、はみ出した最終行の詰めまで同じです。

ビューポートの右下に浮かぶツールバーには、次の機能があります。

- **再計算**（`RefreshCw`アイコン）：現在のMarkdownと設定からPDFを作り直します。自動で再ビルドが始まらない設定を変えた後や、フォントの読み込みが終わったときに使います。
- **ダウンロード**（`Download`アイコン）：現在のPDFをディスクに保存します。ファイル名は文書の最初のH1見出しから作られます（なければ`document.pdf`）。
- **印刷**（`Printer`アイコン）：埋め込まれたPDFビューアーに対してブラウザーの印刷ダイアログを開きます。ほとんどのブラウザーでは、そこから印刷するか、もう一度PDFとして保存できます。
- **現在の章 / 本全体**（タブバーの左端の選択。複数の章を持つ本の場合）：前の章に続けて組んだ表示中の章（既定）の代わりに、すべての章を1つの連続したPDFとして描画します。切り替えるとPDFが再生成されます。Canvasには専用の選択があります（[本と章](#本と章)を参照）。

内部では、Sandboxは`createPdfFontProvider()`ヘルパーを使います。これはFontsourceのjsdelivr CDNからウェイトごとの静的なWOFF2ファイルを取得し、ブラウザー内でTTFに展開して、そのバイト列を`renderToPdf`経由で`pdf-lib`に渡します。太字の文字を実際に太字のウェイトで埋め込むには、（1つの可変フォントではなく）ウェイトごとの静的フォントが必要です。Sandboxの外で同じパターンを使う方法は、[PDFの生成](/ja/docs/configuration#pdfの生成)を参照してください。

#### Folioタブ

本を印刷物として、つまりエンジンが組んだページが製本され、机の上に開いて置かれた姿を3Dで表示します（`postext-folio`、three.js）。ページはcanvasが描いたものそのもので、テクスチャーの1テクセルが1ピクセルに対応するので、文字はCanvasタブと同じくらい鮮明です。変わるのはその周りのすべてです。紙、製本、机、光は**デザイン**パネルの**Folio**グループ（`folio`設定）で決まり、本文中の`:::paper`の範囲は、そのページを別の用紙に印刷します（[文書形式 › `:::paper`](/ja/docs/document-format#paper)を参照）。

- **何を表示するか**。Folioタブは、canvasの**現在の章 / 本全体**の選択に従います。章は本の一部として表示されます。前後のページは2つのページの束の厚みに数えられ、章は見開きの本来の側で始まります。右綴じの本（`page.binding: 'right'`、または縦組みの本）は左右が反転して置かれ、丁を左へめくります。
- **ページをめくる**。ページの端をつかんでドラッグします。半分を越えたところで離すとめくれ、そこまで届かなければ元に戻ります。ページをクリックしてもめくれ（右ページは先へ、左ページは前へ）、ツールバーの‹ ›ボタンや、本にフォーカスがあるときの矢印キー、Page Up/Down、Home、Endでもめくれます。丁はそれぞれの紙に応じてしなります。インディア紙はきつく丸まり、厚紙は大きな弧を描き、板紙と表紙は硬い板としてめくれます。
- **離れたページへの移動**。10ページより離れたページ（ページ欄に入力したもの、パーマリンクが指すもの、リンクや**本文**パネルのキャレットでたどり着いたもの）へは、一度の動きで移ります。間にあるページの束がそのページ数分の厚みのまま一体で持ち上がり、反対側に重ねられます。10ページまでは、丁が1枚ずつめくれます。
- **本の周りを見る**。右ドラッグで、本の周りを回るように視点を動かせます。真上から70°まで傾けて、背、小口、束の厚みを見られます。視点はページをめくっている間も動かしたところにとどまり、**視点をリセット**で設定が決める視点（**傾き**と**回転**）にゆっくり戻ります。**既定の視点として保存**は、表示中の視点をそれらの設定に保存するので、本はその視点で開き、**視点をリセット**もその視点に戻ります。
- **ポインターの動作**。ツールバーの3つのボタンで、本の上で左ボタン（指1本、ペン）が何をするかを選びます。**手でページをめくる**は既定で、上で説明したとおりに働きます。**視点を回転**は右ドラッグと同じで、トラックパッドやタブレット向けです。**テキストを選択**は、傾けたり回したりして見えている本の上で、Canvasタブと同じように働きます。クリックで**本文**パネルにキャレットを置き、ドラッグで選択し、ダブルクリックで語を選び、リンクをクリックするとリンク先に移ります。この選択は記憶され、本にフォーカスがあるときはH、O、Sで切り替えられます。
- **エディターへの追従**。**本文**パネルのキャレットと選択範囲がページの上に描かれ、入力している間もそのまま表示されます。ページは組み直されしだい編集を反映します。エディターでキャレットを表示されていないページに移すと、本がそのページまでめくれます。
- **表紙**。**表紙**を**本文をくるむ表紙**にすると、本は表紙の色の布、厚紙、革でくるまれます。**文書自身のページ**にすると、最初のページが表表紙に、最後のページが（左ページに来る場合は）裏表紙になります。本は表紙をめくるまで閉じたままで、最後の丁をめくると再び閉じます。厚い本は、2つの束の間に背を立てて開きます。
- **ツールバー**。canvasと同じような浮かぶバーで、**再計算**、**視点をリセット**、**既定の視点として保存**、3つのポインターのモード、**印刷プレビュー**（出力プロファイルで校正したページを、本自身の紙の上に表示します。canvasと同じスイッチです）、ピン、‹ ›、ページ欄があります。ページ欄は本のページ番号を受け取り、その見開きまでめくります。開いた見開きの右側のページが、パーマリンクの指すページです（`view=folio&page=N`）。
- **設定はすぐに反映**。Folioの設定はレイアウトの一部ではありません。紙、製本、光を変えると、ページを組み直さずに本が描き直されます。
- **表示される環境**。このタブには、WebGL2と、短辺が600 px以上の画面が必要です。スマートフォンでは3Dの本がブラウザーが1つのタブに割り当てるより多くのメモリーを使うので、そこではタブは表示されません（WebGL2のないブラウザーでも同様です）。幅が560 pxより狭いペインでは、本は1ページずつ表示されますが、丁は背を越えてめくれます。システムで動きを減らす設定になっている場合は、めくる動きなしで見開きが切り替わります。
- **ページの上の動画**。動画のポスター画像をクリックすると、3つのポインターのモードのどれでも、動画はページの上で再生され、丁がめくれて丸まる間も映像は動き続けます。もう一度クリックすると一時停止し、別の動画を再生すると先の動画は止まります（**他の動画と同時に再生**がオンなら止まりません）。その動画が見えない見開きで本が静止すると、動画は止まります。Spaceキーで、開いている見開きの動画を再生または一時停止できます。**自動再生**をオンにした動画は、その見開きが初めて表示されたときにひとりでに再生を始めます。ページをクリックした後なら音声付きで、それより前ならミュートで始まり、クリックするとミュートが解除されます。ガイドの2本の動画はこの設定です。アップロードしたファイルやアドレスにある動画（MP4、HLS）は、そのサーバーがクロスオリジンの読み込みを許可していればこのように再生されます。YouTubeやVimeoの動画では、これまでどおりページがめくれます（[文書形式 › Folioのページで再生する動画](/ja/docs/document-format#folioのページで再生する動画)を参照）。
- **テキストの代替**。各ページは画像として描かれます。そのアクセシブルな名前は、テキストを読むためのHTMLタブと**本文**パネルを案内します。

#### HTMLタブ

postextの出力をShadow DOMのコンテナーの中に描画し、ホストのページとのスタイルを完全に分離します。編集用のCSS（文字組み、アキ、段の罫）はシャドウルートの中に注入されるので、周りのアプリケーションのスタイルから影響を受けることも、そこへ漏れ出すこともありません。

Markdownのリンクは、このタブとPDFで実際に機能します（[文書形式 › リンク](/ja/docs/document-format#リンク)を参照）。このタブでリンクをクリックするとリンク先が新しいブラウザータブで開くので、Sandboxは開いたままです。`:ref`の引用は、これまでどおり文書内を移動します。

動画はここで再生されます。YouTubeやVimeoの動画はそのプラットフォームのプレーヤーで、ファイルやアドレスはブラウザーのプレーヤーで（ブラウザー自身がHLSに対応していなければ、HLSストリームはhls.jsを通して）、**デザイン**パネルの**動画スタイル**と各動画のプレーヤーのオプションに従って再生されます。プレーヤー上のクリックはエディターではなくプレーヤーに届きます。**HTMLビューアーでの表示**を**ポスター画像**にすると、タブには動画にリンクした、印刷用のポスター画像が表示されます。

ビューポートの上部のツールバーには、次の機能があります。

- **文字の大きさのコントロール**：設定のすべての相対的な寸法を保ったまま、本文を小さくしたり大きくしたりします。
- **段のモード**：1段（縦に長くスクロールする1つの段）か段組み（設定された行長に最も近い幅になる段の数で、ページ間を横方向にスクロールスナップします）。2段組みの文書は2段組みのページを保ちますが、それが最も近い場合には、ビューアーは2段を引き伸ばしたり4段を詰めたりする代わりに3段のように奇数の段を表示することがあります。そのとき最後の段は次のページのもので、半分だけ見えます。**多段組み**の文書や節も2段組みのページとして表示されます。3段から8段の印刷用の段は画面の幅では細すぎるので、ビューアーは本文を1ページ2段で組み、行長に合わせて入るだけの段を横に並べます。右綴じの本（`page.binding`）は、段組みのモードではページが右から左へ進みます。ビューアーは右端から開き、‹の矢印で次のページへ進みます。縦組みの本は段組みのモードでだけ読めます。**1段**ボタンは無効になり、ツールチップがその理由を示します。保存した選択は、次の横組みの本で戻ります。

段の配置は、**デザイン**パネルの「**Webリーダー（HTML）**」の節（**デザイン → 書き出し**）で決まります。`maxCharsPerLine`は本文フォントの字数で目標の行長を、`columnGap`は段組みのモードでの段の間の横方向のアキを決め、`optimalLineBreaking`はビューアー内でKnuth–Plassを使うかどうかを切り替えます。Sandboxが内部で使っているのと同じパターンは、[HTMLビューアーの設定リファレンス](/ja/docs/configuration#htmlビューアー)と、最初から最後までの[組み込みの例](/ja/docs/configuration#htmlビューアーの統合)を参照してください。

#### EPUB 3タブ

`postext-epub`パッケージで本全体をEPUB 3ファイルとして書き出し、タブの中のリーダーで表示し、ダウンロードできるようにします。ファイルは、PDFタブが**本全体**で使うのと同じ章ごとのレイアウトからブラウザー内で作られるので、ページ番号、注、相互参照、目次、索引はPDFに印刷されるものと同じです。EPUBは常に本全体を収めるので、このタブには**現在の章 / 本全体**の選択はありません。代わりに、タブバーの左端でレンディションを選べます（スマートフォンではアイコンで表示されます）。

EPUB 3には2つのレンディションがあり、パッケージの`rendition:layout`プロパティで呼び分けます。

- **固定レイアウト**（`pre-paginated`、FXLとも呼ばれる）：すべてのページを印刷どおりに収めます。各ページはそのページの大きさを持つ独立した文書で、文字はPDFと同じ位置に本のフォントで置かれますが、選択、検索、読み上げができる本物のテキストのままです。見開きは印刷どおりに組になり、右綴じの本（アラビア語、縦組みの中国語）は右から左へめくれます。デザイン、つまり段、フロート、柱、章扉、正確な改行が保たれます。絵本、教科書、カタログ、雑誌のように、ページとしてデザインされた本や、大きな画面のリーディングシステムに向いています。小さな画面ではページが縮小され、読者が拡大して読みます。
- **リフロー型**（スマートフォンとコンピューターでの既定で、EPUBの既定でもあります）：本文、図、表を読む順に収め、リーディングシステムが画面と、読者が選んだ書体、文字サイズ、余白に合わせて組み直します。段落は組まれた行から再構成され（行末に加えたハイフンは取り除かれます）、図と表はそれを引用する本文の後に続き、囲みはasideになり、脚注は各章末の注とリンクで行き来し、印刷版のページ番号はページマーカーとして残ります。デザインから作ったスタイルシートが見出し、囲み、表、キャプションの見た目を与えますが、ページの形はなくなります。段も、柱も、固定の改行もありません。小説、評論、報告書のような続けて読む文章や、スマートフォンと電子ペーパーのリーダーに向いています。

どちらかを選ぶまでは、印刷されたページが収まる画面を持つiPadのようなタブレットでは固定レイアウトで、それ以外ではリフロー型でタブが開きます。選択は訪問をまたいで記憶され（`postext-sandbox-epub-layout`）、切り替えるとすぐにファイルが書き直されます。

- **生成**。EPUBは、タブを最初に開いたときと、**再計算**を押したときに書き出されます。進行状況バーが組んでいる章を数え、続いて書き出しの各段階（フォント、画像、表紙。ページまたは章。パッケージ）を示し、ファイルの準備ができたときや失敗したときはスクリーンリーダーに伝えます。編集後は、PDFタブと同じく、**再計算**の横の矢印でファイルが本文と一致しなくなったことを示します。タブを離れるかレンディションを切り替えると、進行中の生成は止まります。長い本では数秒かかり、その間ページは応答しません。
- **ファイルに入るもの**。メタデータは最初の章のフロントマターから取ります。`title`、`subtitle`、`author`（1つの名前またはリスト）、`publishDate`または`date`、`isbn`または`identifier`、`publisher`、`rights`、`description`です。言語は設定の`locale`から取ります。識別子のない本には、プロジェクト（または見本の本とその言語）から作った識別子が付くので、同じ本のEPUBはどれも、読者のライブラリーの中で1つの本として扱われます。デザインが指定するフォントファミリーはすべて埋め込まれます。Google Fontsのスライスは本がその文字を印刷する場合だけ、カスタムファミリーは再配布不可と指定されていない場合です。画像は保存されたとおりに、SVGはフォントをインライン化したソースとして入り、PDFの印刷用マスターが入ることはありません。動画ファイルは`media/`の下に入ってリーダーのプレーヤーで再生されます。バイト列を持たないファイルは公開先のアドレスから再生され、パッケージはそれをリモートのリソースとして宣言します。YouTubeやVimeoの動画は、動画にリンクしたポスター画像になります。表紙は、本自身の画像が幅600 px以上のビットマップならそれを、そうでなければ最初のページをトンボ用の余白なしで幅1,600 pxに描画したものを使います。
- **リーダー**。タブは書き出したばかりのファイル、つまりダウンロードされるのと同じバイト列を開きます。別のプレビューではありません。固定レイアウトは1ページ、またはペインの幅が十分なら見開きを、収まるように縮小して表示します。リフロー型の本は1画面ずつページ送りされ（縦組みの中国語では上から下へ）、ページは章から次の章へと続きます。本の中のリンクはリーダー内を移動し、Webとメールのリンクは新しいブラウザータブで開きます。← / →、Page Up / Page Down、Home、Endでページをめくり、右から左の本では←で先へ進みます。
- **ツールバー**。PDFタブと同じような浮かぶバーで、**再計算**、ピン、ファイルのサイズ付きの**EPUBをダウンロード**（ファイル名は本のタイトルから作られます）、書き出し処理が何か報告したときの警告ボタン、**目次**（本の目次から作った移動用の一覧）、**文字を大きく**と**文字を小さく**（リフロー型だけで、読んでいる位置を保ちます）、‹ ›、固定レイアウトではページ欄があります。ページ欄はファイルの読む順でページを数え、表紙を1とします。各フレームには、そのページの印刷上の番号が名前として付きます。
- **警告**。警告ボタンは、本にあるとおりにはファイルに入れられなかったものを一覧にします。ファイルが保存されていない画像（代わりに空の枠が入ります）、埋め込まれた書体がないファミリー、ウェイト、スタイル（リーディングシステムが代わりの書体を使います）、再配布できない可能性があるため除いたファミリー、そしてレンディションで表現できないものです。同じメッセージがブラウザーのコンソールにも出ます。
- **ファイルの検証**。ガイドと見本の本は、どちらのレンディションも[W3C EPUBCheck](https://www.w3.org/publishing/epubcheck/) 5.4をエラーも警告もなく通ります。自分の本を確かめるには、ダウンロードして`epubcheck book.epub`を実行するか、Apple Books、Thorium Reader、Calibreで開いてください。

同じファイルを自分のコードで書き出す方法は、[EPUBの本](/ja/docs/configuration#epubの本postext-epub)を参照してください。

### スマートフォンと小さな画面

幅が768 px未満になると、Sandboxは専用のレイアウトに切り替わります。

- **パネル**。パネルのバーはウィンドウの下端に移り、同じボタンが同じ順に並びます。開いたパネルはプレビューの横ではなくプレビューを覆って表示されます。プレビューはその下で元の位置にとどまり、タブ移動の対象から外れるので、パネルを閉じると同じページに戻ります。
- **上部のバー**。出力タブ、範囲の選択（EPUBタブではレンディションの選択）、ホストのコントロール（大きなタッチ領域、テーマ、言語）が、プレビューの上のバーに並びます。640 px未満ではバーが2行になり、上の行にロゴ、範囲、コントロール、下の行にタブが全幅を分け合って並びます。320 pxでも5つのタブが収まります。
- **ツールバー**。プレビューの浮かぶツールバーはプレビューの下端に沿って固定され、収まらないときは2行目に折り返します。
- **Folio**。Folioタブはスマートフォンの画面では表示されません（[Folioタブ](#folioタブ)を参照）。
- **PDF**。スマートフォンとタッチ操作だけのタブレットでは、ページの中にPDFを表示できません（Androidにはインラインのビューアーがなく、iOSは最初のページしか描画しません）。そのため、PDFタブには代わりに**PDFを開く**のカードが表示され、ファイルを新しいタブで開きます。ツールバーの**ダウンロード**でも保存できます。

## 本と章

Sandboxで開くものはすべて**本**です。InDesignのブックファイルが章ごとに1つのドキュメントをまとめるのと同じように、設定、カスタムフォント、リソース一式は本全体で共有され、各**章**はそれぞれ独立したMarkdownドキュメントです。500ページの教科書のような長い著作も1章ずつ編集でき、番号付け、相互参照、書き出しでは引き続き1つの文書として扱われます。

- **構成**は**章**パネルと、**本文**パネルの章の切り替えで管理します。追加、名前の変更（行をダブルクリック）、並べ替え、レベル1見出しごとの章の分割、前の章への統合、削除ができます。取り消しの履歴とキャレットの位置は章ごとに保たれます。
- **1章ずつ**。既定では、プレビューは**作業中の章**を、それより前の章の続きとして組みます。最初のページ番号は前の章の最終ページに続き、レベル1見出しの番号も数え続けます（第4章の番号は4、その図は4.1、4.2、…）。`{chapterNumber}`と`{chapterTitle}`の柱もそれに従い、奇数ページと偶数ページの別も保たれます（章扉は本の途中にあるときとまったく同じように白ページを挟みます）。第1章で最初に言及された図への`:ref`も、その番号を保ちます。前の章のページ数は、それぞれの章を最後に表示したときのレイアウトから取ります。一度も開いていない章（またはその後に編集した章）はバックグラウンドで1章ずつ順に組まれ、それが終わるまで章の一覧には「ページ数は計算中」と表示されます。新しいページから始まる章（既定）ではページ範囲は正確です。前のページから続けて組まれるはずだった章は、代わりにその章自身のページの先頭に置かれます。
- **本全体**。Canvas、HTMLプレビュー、PDFタブでは、本全体を1つの連続した文書として表示できます。タブバーの左端にあるセレクターで**本全体**を選びます（2章以上ある本の場合）。Canvasはすべての章を順に、それぞれ前の章が終わったページの後に組み、それらの文書をつなぎ合わせて表示します。編集したときに組み直すのはその章だけで、後続の章は最初のページが動いたときにだけ組み直します。章の一覧、パーマリンクの`chapter=`と`page=`、エディターとの同期は、表示中のページの章に従います。この選択は本ごとに保存されます（短い小説は1つの文書として、教科書は1章ずつ読むなど）。プリセットは、マニフェストの`view.canvasScope`でこの表示のまま開くよう指定できます。HTMLプレビューはCanvasの選択を共有し、本全体を最初のページから1つの文書として組みます。目次の行とフラグメントは各ページの章に従います。PDFタブには独自のセレクターがあります。
- **長い本**。120章の本も短い本と同じように扱えます。**本文**パネルのヘッダーにある章メニューはウィンドウ内でスクロールし、作業中の章の位置で開きます。そこから矢印キーで移動できます。部に分かれた本（章の中に`:::part`のフェンスがあるもの）は、メニューでも**章**パネルでも章を部の下にまとめて表示し、メニューで部をクリックするとその最初の章が開きます。30章を超えると、メニューの上部に検索欄が現れ、章番号（`27`）や、章題と部の名前に含まれる語（`埋香`、`卷三`）で絞り込めます。Enterキーで最初の一致項目を開きます。入力メソッドで変換している間（注音、倉頡、ピンイン、かな）は、Enterキーと矢印キーは入力メソッドが受け取ります。Enterキーは変換を確定するだけで、何も開きません。見本の本の章ファイルは8つずつ読み込まれ、章をバックグラウンドでページ割りしている間は**章**パネルに進行状況（「ページ割り中（34/120）」）が表示されます。200章を超える本は、本やマニフェストの指定にかかわらず、CanvasとHTMLプレビューでは1章ずつ表示します。すべての章を一度に組むと、本全体をメモリーに保持することになるためです。それ以下の本なら全体を開けます。『紅樓夢』（129章、約2,000ページ）はCanvasでおよそ25秒、100 MBかかります。PDFタブではどの本でも全体を書き出せます。
- **フロントマター**。最初の章のフロントマターが本のフロントマター（タイトル、著者など）になります。ほかの章の先頭にあるフロントマターのブロックは無視され、**検査**パネルにその旨が表示されます。`buildBundle`も同じ規則に従うため、本はSandboxでも独自のプログラムでも同じように描画されます。
- **ページ数**。各章はそれぞれ独立した文書として組まれるため、`{totalPages}`はその章のページ数を数えます。`{bookTotalPages}`は本全体を数えます。すべての章のページ数がわかると、プレビューはその合計を使って各章を組みます（ヘッダー、フッター、デザインがこの値を印刷する場合のみ）。それまでは、章はその章の終わりまでのページ数を印刷します。PDFタブの**本全体**は組んだページを数えるため、ファイルにはつねに本の実際の総ページ数が印刷されます。
- **章扉**。章と章の間で改ページを強制することはありません。最初のブロックがレベル1見出しである章は、見出し自身の「前で改ページ」設定によって新しいページから始まります。文書の途中から始まる章とまったく同じです。
- **同期**。CanvasまたはHTMLプレビューでいずれかの章の段落をクリックすると、エディターがその章に切り替わり、キャレットが置かれます。エディターのキャレットは、その章が本のどこにあってもプレビュー上で強調表示されます。警告にはその章が示されます。
- **既存の文書**は1章だけの本として開きます。2つ目の章を追加するまでは何も変わりません。

## 漫画の編集

漫画のページ（`:::page`）や帯漫画（`:::strip`）のある章は、Canvasタブ、HTMLタブ、Folioの**テキストを選択**モードで、ページの上で直接編集できます。段の中に組んだ帯漫画、ページの頭にフロートした帯漫画、ページ幅に組んだ帯漫画でも、行長より狭い帯漫画やキャプションの下の帯漫画でも同じツールが使え、書き込み先は帯漫画自身のフェンスです。変更はどれも、入力した編集と同じように章のMarkdownに書き込まれるので、エディターの取り消しで元に戻せます。マークアップと写植の規則は[漫画](/ja/docs/comics)で説明しています。

- **割り線**。2つのコマの間の間白の上では、ポインターがサイズ変更のカーソルになります。ドラッグすると割り線が動き、離すと新しいパーセントがページの`split`属性に書き込まれ（ページに`split`がなければフェンスに加えます）、ページが組み直されます。Shiftで線が5%刻みにそろい、Altでポインターに近い側の端だけが動いて線が斜めになり、どのコマも5%より狭くはなりません。ドラッグ中は、絵のセーフエリアが見えなくなるコマに印とヒントが表示されます。各割り線はフォーカスできる区切りでもあり、矢印キーで1%（Shiftで5%）動かし、Enterで位置を書き込み、Escapeで元に戻します。
- **分割と結合**。コマの上の小さなツールバーに、**横線で分割**、**縦線で分割**（新しい区画のために、このコマのすぐ後に空の`::panel`の行が加わります）、**次のコマと結合**があります。結合すると間の線が消え、結合したコマは最初のコマの絵を保ち、両方の台本の行を持ちます。コマにはTabキーでも移れます。フォーカスのあるコマは輪郭が表示され、Hで横線、Vで縦線で分割し、Mで次のコマと結合します。ページが組み直された後もフォーカスはそのコマに残ります。Enterでツールバーを開き、Escapeでツールバーからコマに戻ります。
- **吹き出し**。吹き出しをドラッグすると位置が固定されます。離すと台本の行に`at="x% y%"`が付きます。点はコマの絵に対するパーセント（絵のないコマでは区画に対するパーセント）なので、トリミング、割り線のドラッグ、翻訳を経ても、固定した位置は絵の同じ場所にとどまります。連結したまとまりは一体で動き、その最初の吹き出しで固定されます。フォーカスのある吹き出しは矢印キーで1%（Shiftで5%）ずつ動かせ、固定した吹き出しをダブルクリックすると`at`が消え、自動の配置に戻ります。1回クリックすると、エディターのカーソルがその吹き出しの行に移ります。
- **はみ出しのヒント**。吹き出しを動かしている間は、ポインターでも矢印キーでも、プレビューが落ち着き先を確かめます。顔や回避エリアを覆うとき、または今よりもコマからはみ出すときは、動かしている輪郭がオレンジ色になり、コマの顔と回避エリアが破線で描かれ、ツールチップが理由を示します（「ここでは顔を隠してしまいます。」「ここでは画像の空けておく部分を隠してしまいます。」「ここではコマからはみ出します。」）。`break`を付けた行は、コマから出ても印が付きません。このヒントは、場所を空けるためにコマのほかの吹き出しがどう動くかまでは予測しません。
- **しっぽ**。しっぽの先の上では、ポインターが十字カーソルになります。しっぽを向けたい場所へ先をドラッグすると、離したときに行に`to="x% y%"`（コマの絵に対するパーセントで表した点）が付き、しっぽはその点のほうへ向いて、口の手前で止まるときと同じように手前で止まります。Escapeでドラッグを取り消し、先をダブルクリックすると`to`が消えて、しっぽは話者に向き直ります。キーボードでは、フォーカスのある吹き出しでTを押すとしっぽに移ります。矢印キーで指す点を1%（Shiftで5%）動かし、Enterで書き込み、Escapeで元に戻し、Deleteで`to`を消し、Tで吹き出しに戻ります。
- **話者と回避エリア**。[リソースパネル](#リソースパネル)の画像で、**セーフエリアと写植**の項目を開くと、3つのモードを持つダイアログが表示されます。**セーフエリア**は、絵の中で常に見えていなければならない部分を指定します。**話者**は登場人物ごとに1つの点を置きます。絵をクリックするとそこに話者が加わってIDの欄にフォーカスが移ります。IDは台本で使う話し手のキー（`maya: …`）と同じでなければなりません。口、頭（思考の吹き出しの泡が指す点）、顔（どの吹き出しも覆わない範囲）はドラッグして位置を合わせます。**回避エリア**はどの吹き出しも覆わない長方形で、絵の上をドラッグして描きます。どの印も矢印キーで動かせ（Shiftで大きく動きます）、Deleteで削除できます。ダイアログは独自の取り消し履歴を持ち、セーフエリアの外にある話者には印が付きます。
- **設定**。**デザイン**パネルの**マンガ**グループに漫画の設定がまとまっています。読む方向と絵の左右反転、枠と間白、既定のコマと名前付きのコマのスタイル、写植、吹き出しのスタイルで、吹き出しのスタイルにはそれぞれ輪郭のプレビューがあります。
- **エディターと検査**。テキストエディターは`:::page`、`:::strip`、`::panel`の行と、台本の行のキーと属性を色分けします。**検査**パネルは漫画の警告（読めないコマ割り、コマと区画の数の不一致、収まらない吹き出しなど）を対象の行に表示します。[漫画 › 漫画の警告](/ja/docs/comics#漫画の警告)を参照してください。

## Word文書

原稿はたいていWordファイルで届きます。本文パネルは`.docx`を直接読み込みます。AIエージェントもインストールも必要なく、InDesignの*配置*と同じようにスタイルを対応づけます。**Word文書を読み込む**はファイルをブラウザーの中で読み（アップロードはしません）、ダイアログを開きます。本が変わるのは**読み込む**を押したときだけです。Word文書でないファイル、たとえば古いバイナリ形式の`.doc`は、その旨のメッセージを表示して受け付けません。先にWordで`.docx`として保存してください。

ダイアログは次の部分からなり、それぞれ折りたためます。

- **元の文書の品質**。原稿の作り方の診断で、*スタイルが整っています*（そのまま変換できます）、*スタイルは一部だけです*（手作業で書式を設定した段落があります）、*スタイルがありません*（すべてNormal（標準）なので、本文は通常の段落として読み込まれます）のいずれかです。その下に件数（段落、そのうちNormal以外のスタイルの段落、画像、表、注）と見つかった事柄が並び、それぞれに該当する段落のいくつかの書き出しが添えられます。見つかる事柄は、手作業で書式（フォント、サイズ、色、配置）を設定した段落（この書式はデザインで決まるので読み込みません）、手入力の見出しらしい太字の短い段落、Wordのリストの代わりに手入力した番号や行頭記号、手動の改行、手動の改ページ、間隔を空けるための空の段落、タブと連続した2つのスペース、変更履歴（挿入は残し、削除は読み込みません。先にWordで承諾するか元に戻してください）、コメント（読み込みません）、テキストボックス（各ボックスの文章は、アンカーのある段落の後に続きます）、数式（TeXに変換します。確認してください）、隠し文字、ブラウザーで表示できない形式（EMF、WMF、TIFF）の画像です。
- **読み込みテンプレート**。使用中の対応づけで、*自動*（スタイル名で判定）、保存したテンプレート、またはSandboxから書き出したファイルなら*この文書に保存されたもの*です。**新しいテンプレートとして保存**は名前を尋ね、この文書のすべてのスタイルを含めて対応づけをブラウザーに保存します。**変更を保存**は選択中のテンプレートを更新します。ダウンロードボタンはテンプレートを`.json`ファイルとして書き出し、アップロードボタンはそのファイルを読み込むので、チーム全体で同じテンプレートを共有できます。削除の前には確認があります。次回は、最後に使ったテンプレートが最初に示されます。
- **段落スタイル**。文書が使っている段落スタイルごとに、それを使う段落の数、その1つの書き出し、変換先が表示されます。変換先は**本文**、**見出し**（1から6のレベルと、デザインに見出しスタイルがあればそのうちの1つ）、**段落スタイル**（デザインの段落スタイルの1つ。このスタイルの段落が続くと1つの`:::paragraphs`グループになります）、**囲み**（続く段落がその種類の1つの囲みになります）、**囲みの見出し**（段落の文字を見出しにした囲みを開始します）、**引用**、**隣の画像または表のキャプション**、**新しい章の始まり**、**Postext Markdown（書かれたまま）**（Wordで入力したディレクティブのために、文字をそのまま写します）、**読み込まない**のいずれかです。Wordの番号付きリストと箇条書きの段落は、スタイルにかかわらず、番号と入れ子を保ったままPostextのリストになります。<strong>詩（:::verse、行ごと）</strong>は、そのスタイルの段落を`:::verse`の詩として組みます。デザインの段落スタイルの1つを指定することもできます。Shift+Enterで詩の行を区切り、1つの段落が1つの連、1行の段落が続けば1つの連、空の段落が連の区切りです。Verse、Poem、詩という名前のスタイルにはこれが推測されます。
- **文字スタイル**。文字スタイルも同様で、変換先は**書式なし**、**太字**、**イタリック**、**太字イタリック**、**スモールキャピタル**、**上付き**、**下付き**、**チップ**（デザインのチップスタイルの1つ）、**Postext Markdown（書かれたまま）**、**読み込まない**のいずれかです。
- **オプション**。手動の改行（Shift+Enter）は、段落内の改行として残す（Markdownの行末にバックスラッシュを置きます。既定）か、スペースを挟んでつなげるか、新しい段落にします。手作業で設定した太字、イタリック、スモールキャピタル、上付き・下付きは、残すか読み込まないかを選べます。太字の短い段落は、段落のままにするか、いずれかのレベルの見出しにします。手動の改ページは読み込まない（改ページはデザインで決まる）か、`:::pagebreak`として残します。画像と表をリソースとして追加するかどうかも選べます。
- **Markdownのプレビュー**。対応づけを変えるたびに更新されます。

ダイアログの下部で本文の行き先を選びます。**この章を置き換える**、**この章の後に新しい章を作る**、**本全体を置き換える**のいずれかで、後の2つではレベル1の見出しごとに新しい章が始まります。画像（PNG、JPEG、GIF、WebP、SVG）は図のリソースに、表は表のリソースになります（ヘッダー行、結合したセル、列幅、セルの塗りは保たれます）。どちらも元の位置に`::resource{id="…"}`で置かれ、隣のキャプションの段落がキャプションになります。Postextはリソースに番号を付けるので、手入力の番号（*図3.*）は読み込みません。脚注と文末脚注はPostextの脚注（`[^1]`）に、Wordの索引項目（XEフィールド）は`:index`の印になります。リンクはリンクのまま、数式は`$…$` / `$$…$$`になります。本文のタブは、Wordが設定したタブ位置を付けた`:tab`（`:tab{at=432pt align=end leader="."}`）になります。段落が、独自のタブ位置を持つ本の段落スタイルに対応づけられる場合は、何も付けない`:tab`になります。Wordの点、ハイフン、中黒のリーダーは`.`、`-`、`·`に、下線と太線のリーダーは罫線になります。見出し、表のセル、注の中のタブはスペースになります。

自動の対応づけは、名前でスタイルを照合する前に、インターフェースの言語にかかわらずWord自身の役割（*見出し 1*–*6*、*表題*、*引用文*、*図表番号*。目次、索引、ヘッダー、フッターの段落は読み込みません）と、デザインのスタイルを認識します。本の段落スタイル、囲みの種類、見出しスタイル、チップスタイルと同じ名前（IDまたは名前で照合し、大文字と小文字、アクセントは区別しません）のWordスタイルは、そのスタイルに対応づけられます。

**Wordに書き出す**は、開いている章または本全体を、Wordで作業してもらうための`.docx`としてダウンロードします。同じテンプレートを逆向きに適用します。見出しにはWordの見出しスタイルが付き、段落スタイル、囲み、引用、チップにはそれぞれ専用のWordスタイル（*囲み: 注*、*チップ: キー*のように、デザインのスタイルにちなんだ名前）が付きます。リストはWordのリストに、脚注はWordの脚注になり、リンクはリンクのままです。`:tab`はWordのタブになり、独自のタブ位置を持つ`:tab{…}`は書いたとおりに残ります。段落スタイルのタブ位置のうち長さで指定したものは、そのWordスタイルのタブ位置になり、リーダーはWordの最も近いものになります（`'end'`や割合で指定したタブ位置は、Wordが文章を組むページによって変わるので書き出しません）。Wordで表示できないもの（フロントマター、フェンス、ディレクティブ、`:ref`、数式、`:index`の印、リソースの行）は、灰色の*Postext Markup*スタイルで書かれたまま残ります。本を書き出すと、各章の先頭に*Postext Chapter*の段落が入ります。テンプレートはファイルの中に保存されるので、編集した文書は同じ対応づけで読み込み直され、章の段落があれば本全体として読み込まれます。灰色の文字をそのままにしておけば、本文は書き出したときのとおりに戻ります。脚注のラベルは振り直されます（`[^1]`、`[^2]`…）が、印刷結果は変わりません。また、`_italic_`は`*italic*`として戻ります。

このダイアログで扱わない変換（PDF、PowerPoint、EPUB、IDMLの原稿や、元のレイアウト規則の再現）には、[エージェントスキル](/ja/docs/skill)を使ってください。

## 作業内容の保存

Sandboxは作業内容を自動的にブラウザーに保存します。

- **本と設定**：章、作業中の章、Canvasの表示範囲は`localStorage`の`postext-sandbox-book`に自動保存されます（以前のバージョンで保存された単一の文書は`postext-sandbox-markdown`から1章の本として読み込まれ、最初の保存時に移行されます）。設定は操作が1秒止まった後に既定値を除いて保存されるため、変更した値だけが残ります。あわせてそのバージョン（`postext-sandbox-config-version`）も保存されます。バージョンが導入される前に保存された設定は、後述の「postext 1.4以前に保存された見出しの改ページ」のとおりに読み込まれます。
- **UIの状態**：作業中のパネルとビューポートのタブ、サイドバーの幅、**デザイン**パネルで開いているグループ（`postext-sandbox-settings-group`）、その「すべての説明を表示」スイッチ（`postext-sandbox-settings-help`）とセクションの開閉状態、非表示にした見本の本、Canvasのズーム、フィット、表示モード、HTMLの文字の倍率と段組みのモード、EPUBタブのレイアウト形式（`postext-sandbox-epub-layout`）、ツールバーの固定状態は、すべて`localStorage`に保存されます。
- **開いている本**：開いている自分の本（「プロジェクト」）のidは`localStorage`の`postext-sandbox-project`に保存されます。プロジェクト本体（章、設定、リソースのレコード）は、SandboxのIndexedDBデータベースの`projects`ストアにあり、そのバイナリーデータは作業中の文書とblobストア、フォントストアを共有します。レコードは`version: 9`で、これはエンジンの`CONFIG_VERSION`です。作業中の設定と`postext-config.json`の書き出しにも同じ値が記録されるため、エンジンの規則が変わったときに、それぞれ一度だけ移行されます。以前のバージョンの単一文書のレコードは読み込み時に移行されます。バージョン3より古いレコードの見出しの改ページ、バージョン4より古いレコードの数式のサイズ、バージョン5より古いレコードのインラインの図の下のアキ、バージョン6より古いレコードの囲み内のインラインの図の前後のアキ、見出しの文字書式、ドロップキャップのサイズ、コロンの行の下の余地、囲みの分割、バージョン7より古いレコードのダッシュでの改行と行末不ぞろいのテキストの改行、バージョン8より古いレコードの見出し直下の分割、複合語のハイフンでの改行、`:::paragraphs`コンテナーの下のアキは、後述のとおり固定されます。作業中の文書からもどのプロジェクトからも参照されなくなったデータは、ガベージコレクションで削除されます。
- **編集した見本の本**：見本の本を自分で編集した版（章、作業中の章、Canvasの表示範囲、設定、リソースのレコード、および開いたときに見本が適用した内容）は、SandboxのIndexedDBデータベースの`presetDrafts`ストアに、見本と内容の言語ごとに1レコードとして保存されます。そのファイルは、プロジェクトのファイルと同じくガベージコレクションでも保持されます。元に戻すと、このレコードは削除されます。
- **見本の本の表紙**：サムネイルを同梱していない見本の本の最初のページから取った表紙は、SandboxのIndexedDBデータベースの`presetCovers`ストアに、見本と内容の言語ごとに1レコードとして保存されます（[本パネル](#本パネル)を参照）。自分の本は、表紙をそのプロジェクトのレコードに保持します。
- **離れるときの保存**：保留中の編集は、1秒の待ち時間を待たずに、ページが非表示になるか閉じられたとき、リンク（ロゴ）からSandboxを離れるとき、別の本を開く前に、ただちに書き込まれます。
- **開いている見本の本**：最後に読み込んだプリセットのidは`localStorage`の`postext-sandbox-preset`に保存されるため、各パネルの**リセット**ボタンはセッションをまたいでそのプリセットを復元し続けます（配信されなくなったプリセットは利用不可と表示されます）。そのプリセットが適用した内容（バンドルのフィンガープリントと、Markdown、設定、リソース一式のハッシュ）は`postext-sandbox-preset-applied`に保存され、次に開いたときに未編集の文書と編集済みの文書を区別するのに使われます。
- **リソースとフォント**：リソースのレコード、そのバイナリーのblob（ビットマップとSVG）、カスタムフォントのファイルは**IndexedDB**に保存されます。IndexedDBを利用できない場合（一部のプライベートブラウジングモードなど）は、**検査**パネルの「ブラウザー」の下に「ストレージを利用できません」という警告が表示されます。
- **パーマリンク**：URLのフラグメントは画面に表示している内容を示します。そのため、再読み込みしても、ブックマークからでも、ほかの人に渡したリンクからでも、同じビューアーで同じ本の同じページが開きます。`#preset=bioquimica-feduchi&lang=es&view=canvas&chapter=1&page=7`は、Bioquímicaプリセットをスペイン語でCanvasタブに、第1章の7ページ（ページに印刷されている番号）で開きます。`view`は`canvas`、`pdf`、`folio`、`html`、`epub`のいずれかです。Folioタブでは、ページは開いている見開きの右ページです。ローカルのプロジェクトは`project=ID`で示します。これは保存領域のidなので、そのプロジェクトを持つブラウザーでしかリンクをたどれません。Sandboxは、本、タブ、章を切り替えたときやスクロールしたときに、フラグメントを最新の状態に保ちます。省略した部分は現在の状態のままという意味になり（ページがなければその章の最初のページ、本がなければ最後に開いていた本）、ブラウザーで開けない本は無視されます。開いているSandboxのアドレスバーにリンクを貼り付けると、その場で開きます。最後に開いていた本とは別の本へのリンクでページを開いた場合、Sandboxはリンク先の本が読み込まれるまで読み込み中の状態を表示し、前の本は表示しません。ホストは`hashBundles`プロパティ（[Props](#props)を参照）で独自の本にリンクすることもできます。このウェブサイトでは、レシピ集のレシピを`#recipe=<slug>&lang=es`で開きます。初回は、レシピの`.postext`ファイルを自分の本の1冊として読み込みます。同じリンクを再び開くと、まず確認が表示されます（「この本はすでにあります」）。**自分の複製を開く**は編集内容を含めてその本を開き、**公開版に置き換える**はレシピを新たに読み込み直し（その後修正されている可能性があります）、新しい本が開いた時点で手元の複製を削除します。Escapeキーを押すと複製はそのまま残ります。その後、フラグメントはプロジェクトを示すようになります。インターフェースの言語はパスに含まれます（`/en/sandbox`、`/es/sandbox`）。`lang`は多言語バンドルの内容の言語で、任意のBCP 47タグを正規の大文字・小文字表記で保持します（`lang=zh-hant`は`zh-Hant`として読まれます）。バンドルにないタグの場合は、それに対応する版が開きます。`zh-TW`と`zh-HK`は繁体字中国語版（`zh-Hant`）、`zh`と`zh-CN`は簡体字中国語版（`zh-Hans`）、`en-GB`は英語版を開きます。もう一方の中国語の字体は、読者の字体の版がバンドルにない場合にのみ使われます。`zh-Hans`と英語の本への`zh-TW`のリンクは、英語ではなく簡体字のテキストを開きます。`lang`のないリンクは、バンドルが`openLocale`を指定していればその言語で、なければインターフェースの言語の版で開きます。リンクの章とページは開いた版に適用され、その後フラグメントはその版を独自のタグで示します（`lang=zh-TW&chapter=28`は`lang=zh-Hant&chapter=28`になります）。

**postext 1.4以前に保存された見出しの改ページ**。postext 1.4までは、`headings`オブジェクトを持つ設定では、H1の「前で改ページ」スイッチを明示的に設定しないかぎり、レベル1見出しを改ページなしで組んでいました（また、保存時にオフにしたH1の改ページは削除されていました）。H1の改ページを部分的に指定すると、足りないフィールドは改ページなしの既定値から補われ、見出しスタイルの改ページも、そのレベルの改ページに統合されずに同じ扱いを受けていました。現在のエンジンは各レベルの既定値（H1は新しい奇数ページから始まる`always-odd`）を保ち、部分的な指定をそこに統合します。当時保存した本のページを保つため、Sandboxはバージョン3より古いプロジェクトのレコード、またはバージョンのない作業中の設定を読み込むときに、それらの改ページを書き込みます。改ページがオフだったH1には`enabled: false`を、奇数・偶数の指定がない`enabled: true`には、H1でも見出しスタイルでも`parity: 'any'`を添えます。これにより、**デザイン**パネルにはページを組んだときの改ページ設定が表示されます。postext 1.5からはファイルにもバージョンが記録されます。マニフェストに`configVersion`のない`.postext`ファイルや、それのない`postext-config.json`はpostext 1.4以前で書き出されたもので、読み込むときや開くときに同じように扱われます（[postext 1.4以前で書き出したバンドル](/ja/docs/configuration#postext-14以前で書き出したバンドル)を参照）。

**postext 1.5より前に保存された数式のサイズ**。postext 1.4までは、すべての数式が「サイズの倍率」の指定より1.131倍大きく組まれていました（[数式のサイズ](/ja/docs/configuration#数式)を参照）。当時保存した本のページを保つため、Sandboxは、バージョン4より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 4`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、そのサイズを固定します。「サイズの倍率」は保存された倍率×1.1312になり、別行立て数式の`em`単位のマージンは1.1312で割られるため、数式とその周りのアキは元のままです。どの章にも`$`がない本はそのまま残し（`postext-config.json`は章を含まないため、数式が有効ならつねにサイズを固定します）、「LaTeXを有効化」がオフの本もそのままです。**数式**セクションには、本を組んでいる値が表示されます。現在のサイズで組むには、「サイズの倍率」「別行立て数式の上のアキ」「別行立て数式の下のアキ」をリセットします。固定は一度だけ書き込まれます。レコードは現在のバージョンで保存し直され、以後はそのまま読み込まれます。当時適用して一度も編集していないプリセットは、引き続き未編集として扱われます（Sandboxは固定後の値と比較します。見出しの改ページの固定も同様です）。そのため、再読み込みや本の切り替えで、行っていない編集を破棄するかどうか尋ねられることはなく、組み込みのガイドなどプリセットの新しいバージョンは引き続きそれを置き換えます。

**postext 1.5より前に保存されたインラインの図**。postext 1.4までは、本文中にインラインで置いた図や表（配置「インライン（この位置）」）は上にだけ1行分のアキを取っていました。その後のテキストは、どれほど近くても次のグリッド線から再開していました。現在は下にも同じ1行分を取ります（**段組み → インラインの図の前後のアキ**、「上下」）。当時保存した本のページを保つため、Sandboxは、バージョン5より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 5`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本のどこかの行がリソースを埋め込んでいれば（本文中での言及ではなく、行に単独で置かれた`::resource{id="…"}`）、「インラインの図の前後のアキ」を「上のみ」にします。`postext-config.json`は章を含まないため、ファイルが古ければつねにこの設定になります。現在のアキで組むには「上下」を選びます。

**postext 1.5より前に保存された囲み内のインラインの図**。postext 1.4までは、囲みの中にインラインで置いた図や表は、周りの囲みのテキストに接して置かれていました。現在は上に囲みのテキスト1行分のアキを取り、「上下」の場合は下にも取ります（**段組み → 囲み内の図の前後のアキ**）。当時保存した本のページを保つため、Sandboxは、バージョン6より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 6`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本の囲みが単独の行でリソースを埋め込んでいれば、「囲み内の図の前後のアキ」をオフにします。`postext-config.json`は章を含まないため、ファイルが古ければつねにオフになります。現在のアキで組むにはオンにします。

**postext 1.5より前に保存された見出しの文字書式とドロップキャップ**。postext 1.4までは、見出しは`*italic*`、`**bold**`などの書式が付いた語も見出し自身のプレーンなスタイルで印刷し、サイズを指定しないドロップキャップは、かかる行すべてを合わせた高さになり、その上端は1行目より上に出ていました。現在、見出しは書式を反映し（**見出し → 見出し内の文字書式**）、ドロップキャップの上端は1行目の大文字の高さにそろいます。当時保存した本のページを保つため、Sandboxは、バージョン6より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 6`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本の見出しに書式が含まれていれば「見出し内の文字書式」をオフにします（`postext-config.json`は章を含まないため、ファイルが古ければつねにオフになります）。また、各ドロップキャップが組まれていたサイズを**ドロップキャップのサイズ**に書き込みます。現在の規則で組むには、スイッチをオンにするか、サイズを空にします。その場合、タイトル全体を`*…*`で囲んだイタリックの見出しは立体で組まれる点に注意してください。

**postext 1.5より前に保存されたコロンの後のリスト**。postext 1.4までは、「コロンとリストを離さない」は、コロンで終わる行の下に1行分の余地があればリストには十分とみなしていました。そのため、オーファンとウィドウの規則で分割されない2行の最初の項目は次の段に送られ、コロンの行だけが段の末尾に残りました。現在は、最初の項目に必要な余地を求めます（**文字組み → 本文 → ウィドウ、オーファン、短い行 → コロンの下に必要な余地**、「最初の項目に必要な分」）。当時保存した本のページを保つため、Sandboxは、バージョン6より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 6`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本のリストがコロンで終わる行の後に続いていれば、「コロンの下に必要な余地」を「1行（1.4）」にします。`postext-config.json`は章を含まないため、ファイルが古ければつねにこの設定になります。現在の規則で組むには「最初の項目に必要な分」を選びます。

**postext 1.5より前に保存された囲みの分割**。postext 1.4までは、段落やリスト項目の途中で分割される囲みは、囲みの前後それぞれに「分割の前後に残す行数」が保たれていれば、その段落や項目の1行だけを片側に残すことがありました。現在は、分割位置で段落や項目の少なくとも2行を前後それぞれに残します（**段組み → 囲みの分割位置に残す段落の行数**）。当時保存した本のページを保つため、Sandboxは、バージョン6より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 6`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本の章が`:::callout`を開いていれば、「囲みの分割位置に残す段落の行数」を1にします。`postext-config.json`は章を含まないため、ファイルが古ければつねにこの設定になります。現在の規則で組むには2に戻します。

**postext 1.5より前に保存されたダッシュと行末不ぞろいのテキスト**。postext 1.4までは、最適改行は、語と語の間に詰めて置かれたエムダッシュやエンダッシュ（`say—that’s`）の後で行を終えることがなく、行末不ぞろいのテキストはつねに1行ずつ、各行を埋めてから次の行に進む方法で組まれていました。現在は、そのようなダッシュの後で行を終えることができ（**文字組み → 本文 → 段落 → ダッシュの後での改行**）、行末不ぞろいの本文もKnuth-Plassで改行されます（**行末不ぞろいの最適改行**）。当時保存した本のページを保つため、Sandboxは、バージョン7より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 7`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本の章にそのようなダッシュがあれば「ダッシュの後での改行」をオフにし（`postext-config.json`は章を含まないため、ファイルが古ければつねにオフになります）、設定が本文の一部を行末不ぞろいにしていれば「行末不ぞろいの最適改行」をオフにします。対象は本文、段落スタイル、囲みの本文、部の本文、節スタイルの本文です。現在の規則で組むには、これらをオンにします。

**postext 1.5より前に保存された見出し直下の分割**。postext 1.4までは、段の末尾にある見出しの下の段落は、次の段に送られる行がどれほど少なくても、そこに収まるだけの行を残していました。現在は、オーファンの最小行数も守り、守れなければ見出しも一緒に次へ送ります（**見出しと目次 → 見出し → 見出し直下での分割**）。当時保存した本のページを保つため、Sandboxは、バージョン8より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 8`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本の章に見出しがあり（`postext-config.json`は章を含まないため、ファイルが古ければつねにこの設定になります）、かつ設定で「次と分離しない」とオーファンの制御がオンになっていれば、「見出し直下での分割」を「段を埋める」にします。現在の規則で組むには「規則どおり」にします。

**postext 1.5より前に保存された段落コンテナー**。postext 1.4までは、`:::paragraphs`コンテナーの下のアキはスタイル自身のもの（段落間のアキと下マージンの大きいほう）で、最終行の下に取られた後、テキストがグリッドに戻っていました。見出しが自分の上に取るアキはその下に加算され、本文の段落間のアキは考慮されませんでした。そのため、見出しは段落の後よりも参考文献の後で離れて置かれ、詰めて組んだ項目群の後の段落は、ほかのどの段落の後よりも近くに置かれていました。現在、このアキは次のブロック自身のアキと相殺され、少なくともテキストの段落間のアキになります（**文字組み → 段落スタイル → コンテナーの下のアキ**、「相殺」）。当時保存した本のページを保つため、Sandboxは、バージョン8より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 8`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、設定が段落スタイルを宣言し、本の章が`:::paragraphs`コンテナーを開いていれば、「コンテナーの下のアキ」を「加算（1.4）」にします。`postext-config.json`は章を含まないため、ファイルが古く、段落スタイルを宣言していればつねにこの設定になります。現在の規則で組むには「相殺」を選びます。

**postext 1.5より前に保存された複合語**。postext 1.4までは、太字やイタリックなどの書式のない段落では、最適改行は両端そろえの行を複合語（`well-known`）のハイフンの後で終えることがなく、書式のある段落では終えていました。現在は、どの段落でもそこで行を終えられます（**文字組み → 本文 → 段落 → ハイフンの後での改行**）。当時保存した本のページを保つため、Sandboxは、バージョン8より古いプロジェクトのレコード、古いバージョンの記録で（または記録なしで）保存された作業中の設定、マニフェストが`configVersion: 8`より古い`.postext`ファイル、それ以前に書き出された`postext-config.json`を読み込むときに、本の章で2つの文字の間にハイフンがあれば「ハイフンの後での改行」をオフにします（`postext-config.json`は章を含まないため、ファイルが古ければつねにオフになります）。現在の規則で組むにはオンにします。

**postext 1.23より前に保存された詩とぶら下げインデントのスタイル**。postext 1.22までは、行に`||`のない`:::verse`の詩は各行を1つの半句として中央に置いて組み、段落スタイルのぶら下げインデントは1行目の字下げに取って代わっていました。いまはそうした詩を行ごとに組み（**文字組み → 本文 → 詩 → 区切りのない詩**、*行ごと*）、両方の字下げを決めたスタイルは1行目を1行目の字下げから始めます。当時保存した本のページを保つため、Sandboxはバージョン9より古いプロジェクトの記録、作業中の設定、9未満と記された`postext-config.json`のエクスポートで、章にそうした詩があるものを読むときに*区切りのない詩*を*半句として（1.22）*にし、ぶら下げもするスタイルから1行目の字下げを外します。また、章に行末がバックスラッシュで終わる行や、後ろにスペースのある`\\`があれば（postext 1.22まではそのまま印字されていました）、**強制改行**（**文字組み → 本文 → 段落**）をオフにします。章を持たない`postext-config.json`のエクスポートでは常にオフにします。さらに、章に```` ``` ````か`~~~`のフェンスがあれば、**コードフェンス**（**文字組み → コード**）をオフにします。そのフェンスの行は、postext 1.22まではMarkdownとして読まれていました（エクスポートでは常にオフにします）。

**postext 1.23で保存した詩**。postext 1.23では、一行ずつ組む詩で行長よりわずかでも長い行は折り返していました。現在は語間を最小語間まで詰め、それで足りれば一行に収めます（**文字組み → 本文 → 詩 → 折り返す前に詰める**）。当時保存した本のページを保つため、Sandboxは、版が9以下で章に一行ずつ組む詩があるプロジェクトの記録、作業中の設定、`postext-config.json`の書き出しを読むと、*折り返す前に詰める*をオフにします（章を含まない書き出しでは常にオフ）。

**postext 1.23で保存したデザインのテキスト**。postext 1.23までは、はみ出しを設定していない見出しのデザインや部扉のテキスト要素は、省略記号付きの1行に切り詰められていました。現在は複数行に折り返し、**テキストを追加**も*はみ出し*を配置先に任せます。当時保存した本のページが変わらないよう、Sandboxはスタンプが9以下のプロジェクトの記録、作業中の構成、`.postext`ファイル、`postext-config.json`の書き出しを読み込むときに、これらの要素の*はみ出し*を*末尾を省略（…）*にします。

これらの固定は、それぞれの規則の変更で動くはずだった部分を抑えるものです。バージョン1.5ではレイアウトのバグも修正されていますが、修正には固定がないため、保存した本でも、次のいずれかに当てはまる箇所ではページが動くことがあります。デザインのないページ幅の章見出しの帯、見出しデザイン内のドロップキャップ、囲み内の段落、段末そろえで引き伸ばされるゆるい段落、1行より広いマージンを持つフロートとして配置した囲み、トラッキングを設定した中央そろえまたは右そろえの柱、ページ幅の章扉の下の2段目、ハイフンの後で改行された見出しから取った柱、行より広い語がそれ自身のハイフンの隣で切られる場合、行より広い語の残り（現在はそれ自身の分割位置を保ちます）、別のリストに入れ子になったリストの後の項目です（一覧は[数式のサイズ](/ja/docs/configuration#数式)を参照）。

保存領域は**UIの言語をまたいで共有されます**。未編集の既定の文書は、言語が変わるとその言語の既定のMarkdownに切り替わり、例のリソースも入れ直されます。そのため、スペイン語のSandboxを開くとスペイン語の例が表示されます。ユーザーが編集すると、その文書はこの動作の対象外になります。また、設定で言語が指定されていない場合（ハイフネーションの言語も`locale`もない場合）、すべてのプレビューはUIの言語からハイフネーションの言語を導きます。

### 書き出しと読み込み

本全体は、**`.postext`ファイル**として持ち運べます。これはプリセットバンドルのディレクトリーとまったく同じ構成のzipアーカイブで、`preset.json`、`chapters/*.md`、`resources/*`、`fonts/*`を含みます（[プリセットバンドルの形式](#プリセットバンドルの形式)を参照）。アーカイブには本の**ページ割り**も`layouts.json`として含まれます。これは各章のページ数と番号付けで、組んだときのエンジンのバージョン、設定、リソースが記録されています。そのため、読み込んだ本はページ割り済みの状態で開き、記録と一致しなくなった部分だけが組み直されます。複数言語のバンドルは言語ごとに独自の設定で組まれるため、代わりに言語ごとに1つ、`layouts.<locale>.json`（`layouts.zh-Hant.json`）を含むことがあり、これは`layouts.json`より先に読まれます。作業中の文書は、保持しているページ割りを書き出します。行から書き出したプロジェクトやプリセットには、最後に作業中の本だったときに記録したページ割りが含まれます。表紙画像はマニフェストの`thumbnail`として書き込まれるため、書き出しと読み込みを経ても失われません。**本**パネルの**新規**メニュー（**.postextファイルを開く…**）は、ファイルを新しい本として読み込みます。各行の⋯メニューにもそれぞれ書き出しの項目（**ダウンロード（.postext）**）があり、開いている本の項目は作業中の文書を書き出します。以前のバージョンで書き出したファイル（単一の`document.md`を持つバージョン1のマニフェスト）は、1章の本として読み込まれます。1つの言語の本は、インターフェースの言語にかかわらず、その言語の図と表のラベルを保ちます。`/en/sandbox`で開いたスペイン語のファイルは、設定で別のリソースタイプを指定していないかぎり「Figura」「Tabla」と印刷します。言語は、ファイルが指定する言語、指定がなければ設定の言語（`locale`、次にハイフネーションの言語）です。読み込みでは、アーカイブのルートにあるファイルも、1つの最上位フォルダーの下にあるファイル（フォルダーそのものをzip圧縮した場合）も受け付けます（`__MACOSX`のエントリーとドットファイルは無視されます）。フォントは`config.customFonts`の中ではなく、つねに別のファイルとして書き込まれます。`.woff`のフェイスは書き出しでも読み込みでも警告付きでスキップされ、バイトデータのないリソースも同様です。書き出したファイルを`<presets-root>/<dir>/`に展開し、`index.json`にエントリーを追加すれば、プリセットとして配信できます。

同じファイルは`postext`パッケージでも読み書きできます（`openBundle`、`createBundle`、`buildBundle`。[バンドル](/ja/docs/configuration#バンドルpostextファイル)を参照）。ここで書き出した本は独自のプログラムで開け、プログラムが書き出した本はここで開けます。そのため、Sandboxはプログラムが組んだものを確認し、微調整する場として使えます。プログラムから書き出し、ここで読み込み、ライブプレビューで修正し、再び書き出してプログラムに読み込み直します。[エージェントスキル](/ja/docs/skill)も、移植の成果を`.postext`ファイルで渡します。

テキストとデザインは、**本文**パネルと**デザイン**パネルのヘッダーから個別に書き出すこともできます。

**デザイン**パネルのヘッダーからは、既定値を除いた`postext-config.json`をダウンロードできます。

```json
{
  "type": "postext-config",
  "version": 1,
  "config": { ... }
}
```

**本文**パネルのヘッダーからは作業中の章をプレーンな`.md`ファイルとしてダウンロードでき、その**読み込み**ボタンは作業中の章を`.md`ファイルの内容で置き換えます。**デザイン**パネルの**読み込み**ボタンは`.json`ファイルを選ぶダイアログを開き、ファイルを想定する`type`と`version`で検証します。無効なファイルは何も通知されずに無視されます。以前のバージョンにあった`postext-markdown.json`のラッパーと、ひとまとめの`postext-sandbox.json`形式はなくなりました。

## 単体での利用

Sandboxは単体のReactパッケージ（`postext-sandbox`）としても提供されており、任意のReactアプリケーションに組み込めます。

```bash
npm install postext-sandbox postext
```

```tsx
import { PostextSandbox } from 'postext-sandbox';

function App() {
  return (
    <PostextSandbox
      initialMarkdown="# Hello World"
      initialConfig={{ layout: { layoutType: 'double' } }}
      onMarkdownChange={(md) => console.log(md)}
      onConfigChange={(cfg) => console.log(cfg)}
    />
  );
}
```

### CSSの要件

このパッケージは、CSSカスタムプロパティを参照するTailwind CSSのユーティリティクラスを使います。ホストアプリケーションは次の変数を用意する必要があります。

- `--background`、`--foreground`：基本色
- `--surface`：一段浮いた面の色。`--surface-2`：ホバーした行と強調表示した選択肢（`--background`にフォールバック）
- `--slate`：控えめなテキストの色
- `--rule`：境界線と区切り線の色。`--rule-strong`：ホバーしたコントロールの濃い罫線（`--slate`にフォールバック）
- `--brand`：アクセントカラー。作業中のパネルの目印、フォーカスリング、スイッチ、選択した選択肢に使います
- `--brand-hover`：ホバー時のアクセントカラー
- `--brand-soft`：選択した選択肢の背後に敷く半透明のアクセントの塗り（`--surface`にフォールバック）
- `--brand-contrast`：オンのスイッチのつまみ（`--background`にフォールバック）
- `--destructive`：破壊的な操作とエラーの色
- `--accent-blue`：リンクとアクセントの色
- `--font-sans`：UIのフォントファミリー
- `--font-mono`：等幅のフォントファミリー（コードエディター用）
- `--font-display`、`--brand-blue`、`--brand-gilt`：アクティビティバーにある既定のロゴマークの書体と色（省略可。フォールバックはGeorgia、`#2b4acb`、`#d8a21a`）

このウェブサイトでは、`--brand`をダークテーマで金色、ライトテーマで青にしています。以前のバージョンは`--gilt`と`--gilt-hover`を読んでいましたが、現在のSandboxはこれらを使いません。

ポップオーバー、メニュー、ツールチップは`document.body`上のポータルに描画されるため、変数はSandboxを包む要素だけでなく、`:root`（または`body`）に定義してください。ホストのTailwindのビルドは、パッケージが使うユーティリティクラスが生成されるよう、パッケージのソースを走査する必要があります（Tailwind 4では`@source "…/postext-sandbox/src/**/*.tsx"`）。

## プリセットバンドルの形式

付録です。プリセットの配信元は（HTTPで配信される）ディレクトリーで、そのルートにはプリセットのディレクトリーを列挙した`index.json`があります。各ディレクトリーには`preset.json`マニフェストと、それが参照するMarkdown、リソース、フォントのファイルが入ります。リポジトリーの`scripts/presets/`にあるツールはまさにこの形でバンドルのひな形を作り、Sandboxから書き出した`.postext`ファイルは、そうしたディレクトリーの1つを（`index.json`を除いて）zip圧縮したものです。

```
<presets-root>/
  index.json
  <preset-dir>/
    preset.json
    chapters/              one .md per chapter, in order (a version 1 manifest names a single document instead)
    resources/             figures: .svg / .png / .jpg / .jpeg / .webp / .gif (+ optional .pdf print masters)
    fonts/                 .otf / .ttf / .woff2 single faces
```

### `index.json`

```jsonc
{
  "version": 1,
  "presets": [
    {
      "id": "acme-journal",          // stable id, [a-z0-9-]
      "dir": "acme-journal",         // directory name relative to index.json
      "name": "Acme Journal",
      "description": "Two-column journal article",   // optional
      "locale": "en",                 // optional
      "default": true,                // optional, at most one
      "locales": ["en", "es"],        // optional: every locale the bundle carries
      "openLocale": "en",             // optional: the locale it opens in when none is asked for
      "thumbnail": "thumbnail.jpg",   // optional: preview shown in the picker
      "license": "CC BY 4.0",         // optional: shown as a tag
      "credits": "Text and images: ESO",  // optional: one line under the description
      "tags": ["magazine", "two-column"], // optional
      "binding": "left"               // optional: the edge the website's shelf draws the spine on ("right" for a right-bound book)
    }
  ]
}
```

### `preset.json`

```jsonc
{
  "version": 2,
  "id": "acme-journal",
  "name": "Acme Journal",
  "description": "Two-column journal article",       // optional
  "locale": "en",                                     // optional
  "default": true,                                    // optional
  "configVersion": 8,                                 // optional: the configuration rules `config` is written for
  // The same optional showcase fields as the index entry:
  // "locales", "openLocale", "thumbnail", "license", "credits", "tags"

  // The book's chapters, in order — or one list per locale
  "chapters": [
    { "title": "Introduction", "file": "chapters/01-introduction.md" },
    { "title": "Methods", "file": "chapters/02-methods.md" }
  ],
  // "chapters": { "en": [ … ], "es": [ … ] },
  // Version 1 manifests use a single document instead and are still accepted:
  // "version": 1, "markdown": "article.md"  (or a locale → file map)

  // Optional PostextConfig JSON (page, margins, columns, typography...).
  // Do NOT put customFonts here: fonts come from the `fonts` array below.
  "config": { },

  "resources": [
    {
      "id": "fig-1-1",                 // referenced from markdown (:ref)
      "typeId": "figure",              // resource type id (figure, table, ...)
      "kind": "svg",                   // "svg" | "bitmap" | "table"
      "file": "resources/fig-1-1.svg", // svg/bitmap only, relative to preset.json
      "width": 240.5,                  // optional, pt (svg) / px (bitmap)
      "resolution": 300,               // optional, bitmap only: ppi at its natural print size
      "pdfFile": "resources/fig-1-1.pdf", // optional, svg only: vector print master (see notes)
      "height": 180,                   // optional
      "caption": "Caption text",
      "altText": "Accessible description",            // optional
      "safeArea": { "x": 0.18, "y": 0.25, "width": 0.5, "height": 0.6 }, // optional, svg/bitmap only: the part always shown, in fractions of the picture
      "placement": { "position": "top", "span": "column" },  // optional
      "note": "Source: ...",                          // optional
      "table": { "model": { "rows": [[{ "content": "A", "isHeader": true }]], "headerRowCount": 1 } }
                                                      // kind "table" only
    }
  ],

  "fonts": [
    {
      "name": "Some Family",           // family name used by the config
      "variants": [
        { "weight": 400, "style": "normal", "file": "fonts/SomeFamily-Regular.otf" },
        { "weight": 400, "style": "italic", "file": "fonts/SomeFamily-Italic.otf" },
        { "weight": 700, "style": "normal", "file": "fonts/SomeFamily-Bold.otf" }
      ]
    }
  ]
}
```

補足：

- `preset.json`の`id`は`index.json`のエントリーと一致させる必要があります。マニフェストの`description`、`locale`、`default`は、プリセットを読み込んだ時点でindexの値を上書きします。ショーケース用のフィールド`locales`、`openLocale`、`license`、`credits`、`tags`も同様です。`openLocale`は`locales`のいずれかで、リンクやクリックで言語が指定されないときに本を開く言語です（ホームページの書棚もこの言語にリンクします）。原典が読者の言語でない場合に設定します。『紅樓夢』のショーケースは`zh-Hant`を設定しており、英語圏の読者全員に英訳が開くことはありません。設定しない場合はインターフェースの言語で決まります。選択画面では、`locales`（または`locale`）のすべての言語とライセンスがタグとして、クレジットが説明の下に表示され、行のチェックマークの列の代わりに`thumbnail`（プリセットのディレクトリーからの相対パスで指定する小さなページ画像）が表示されます。プリセットから複製した本（**自分用に複製**）は、これを表紙として引き継ぎます。`apps/web/public/presets/`にある公開ショーケースのプリセットはすべてのフィールドを使い、各テキストと画像のライセンスと出典を記した`CREDITS.md`を同梱しています。
- `configVersion`（省略可）は、`config`と`localized`の設定がどの設定規則に基づいて書かれているかを示します。postext 1.5以降のすべての書き出しは8を設定します。これのないマニフェストはpostext 1.4以前で書き出されたもので、見出しの改ページ、数式のサイズ、インラインの図の前後のアキ（本文中と囲みの中）、見出しの文字書式、ドロップキャップ、コロンの行の下の余地、囲みの分割、ダッシュと複合語のハイフンでの改行、行末不ぞろいのテキスト、見出し直下の分割、段落コンテナーの下のアキは、1.4の組み方どおりに読み込まれます（[作業内容の保存](#作業内容の保存)の「postext 1.4以前に保存された見出しの改ページ」「postext 1.5より前に保存された数式のサイズ」「postext 1.5より前に保存されたインラインの図」「postext 1.5より前に保存された囲み内のインラインの図」「postext 1.5より前に保存された見出しの文字書式とドロップキャップ」「postext 1.5より前に保存されたコロンの後のリスト」「postext 1.5より前に保存された囲みの分割」「postext 1.5より前に保存されたダッシュと行末不ぞろいのテキスト」「postext 1.5より前に保存された複合語」「postext 1.5より前に保存された見出し直下の分割」「postext 1.5より前に保存された段落コンテナー」を参照）。3から7の値を持つもの（1.5のプレリリース）は、それより後の規則の固定だけを受けます。3の場合は数式のサイズ、インラインのアキ、規則6の5つの固定、規則7の2つ、規則8の3つ、4の場合はインラインのアキと規則6、7、8の固定、5の場合は規則6、7、8の固定、6の場合は規則7と8の固定、7の場合は規則8の固定だけです。現在の規則に合わせてマニフェストを手で書く場合は8を設定します。
- `view`（省略可）は、Sandboxがバンドルをどう開くかを指定します。`{ "canvasScope": "book" }`はCanvasで本全体を組みます（[本と章](#本と章)を参照）。省略するとCanvasは1章ずつ表示します。設定されていれば、書き出した本にも含まれます。200章を超える本は、指定にかかわらず1章ずつ開きます。
- `localized`（省略可）は、多言語バンドルの言語ごとの上書きを保持します。`{ "es": { "config": { … }, "resources": [ { "id": "fig-1", "caption": "…", "note": "…", "altText": "…" } ] } }`のように書きます。章を選んだ言語の上書きが、共有の`config`（最上位のキーは丸ごと置き換え。典型的には、キャプションの接頭辞を翻訳した`resourceTypes`）と`resources`（キャプション、注記、代替テキスト、表のセルをidでマージ）の上に適用されます。エントリーのない言語は共有の文言を使います。エントリーには独自の`view`を含めることもでき、その版では共有のものより優先されます。『紅樓夢』は中国語の版を本全体で開き、全体の描画がずっと遅いJolyの英訳は1章ずつ開きます（`"en": { "view": { "canvasScope": "chapter" } }`）。
- `chapters`（バージョン2）は本の順に並べた`{ title, file }`のリスト、または言語→リストのマップです。`markdown`（バージョン1）はファイル名、または言語→ファイルのマップです。どちらの場合も、Sandboxは要求された言語に一致するエントリーを選び、その言語の章ファイルだけを読み込みます。選ぶ順序は、大文字と小文字の違いを除いてタグが完全に一致するもの、次に言語と字体が同じもの（`zh-TW`は`zh-Hans`より先に`zh-Hant`を読みます）、次に字体が異なる同じ言語（素の`zh`をキーにしたバンドルでは、`zh-TW`の読者に中国語が渡ります）、次にプリセット自身の`locale`、最後に最初のエントリーです。章の`title`が空の場合は、ファイルの最初のレベル1見出しから取ります。Sandboxはつねにバージョン2で書き出します。
- `width` / `height`は、`svg`と`bitmap`のリソースでは省略できます。ない場合は読み込み時にファイルから読み取ります。ビットマップには`resolution`（原寸で印刷したときのppi）と`fileResolution`（ファイルに記載された解像度。設定で`layout.bitmapResolution: 'file'`を指定しているときは読み込み時に読み取ります）も指定できます。
- `pdfFile`（svgリソースのみ）は、同じ図をベクターで収めた1ページのPDFを指します。典型的には、SVGの元になったIllustratorのオリジナルやPDF書き出しです。PDFの書き出しでは、SVGの代わりにそのページをそのまま（フォント、グラデーション、色空間を保って）埋め込みます。CanvasとHTMLのプレビューは引き続きSVGを使います。単色モードでは無視されます。単色モードの色替えの処理はSVGのマークアップにしか作用しないためです。ファイルがなくても失われるのはマスターだけで、図は残ります。リソースの詳細でSVGのソースを編集するとマスターは外れ（マスターは編集前のソースに合わせて作られたものです）、以後、PDFの書き出しは編集後のSVGに従います。マスターを戻すには、元の状態に戻します（**本**パネルの**元に戻す…**）。マスターのないSVGは、PDFバックエンドのサブセット（基本図形、パス、グループ、`use`、クリップパス、単色の塗りと線、不透明度、文書が読み込めるフォント（まずカスタムフォント、次にGoogleがホストするファミリー）で組まれた`text` / `tspan`の連なり）に収まる場合はベクターパスとして出力され、それ以外は600 dpiでラスタライズされます。
- SVGの`text`は、どの出力でもSandboxのカスタムフォントで描画されます。プレビューはデコードの前に、一致する`@font-face`のデータをSVGに埋め込みます（`<img>`からはページのフォントが見えないため）。PDFの書き出しは、同じ埋め込みフェイスを使い、選択可能な実際のテキストとして組みます。`font-family`にはファミリー名を、**フォント**パネルに表示されるとおりに正確に書いてください。
- SVGのソースエディターでは、誤って図を壊さないよう、テキストノード（色付きで表示）の中でしか入力できません。ヘッダーの鍵ボタンを押すと、座標、色、構造を含むソース全体を編集できるようになり、再びロックするとテキストノードを探し直します。
- `table.model`はPostextの`TableModel`です。`rows`はセル（`content`と、省略可能な`colSpan`、`rowSpan`、`isHeader`、`align`、`verticalAlign`）を行ごとに並べた配列、`headerRowCount`は先頭のヘッダー行の数、`columnWidths`は列の相対的な幅の比を表す省略可能な配列です。`table.styleId`では、設定の`tableStyles`のいずれかを指定できます（省略可）。
- フォントファイルは、プリセットのidとファイルパスから導いたidでIndexedDBに保存され、プリセットを適用したときにそのファミリーが`config.customFonts`に追加されます。`index.json`がない場合や形式が正しくない場合は、エラーにはならず、プリセットがないものとして扱われます。
- `<preset-dir>/fingerprint.json`は省略可能で、開発用のルートでは**仮想**のファイルです。そのファイルがない場合、`GET`は`{ "fingerprint": "<sha1 hex>", "files": <n> }`を`Cache-Control: no-store`付きで返します。値はディレクトリーのファイルのメタデータ（4階層までのすべてのファイルの相対パス、更新日時、サイズ。ドットファイルと`node_modules`は除外）から計算し、ファイルの内容は使いません。Sandboxはこれをポーリングしてバンドルの編集を追跡します（[本パネル](#本パネル)を参照）。静的ホストは、同じ形の実際の`fingerprint.json`を配信することも、まったく配信しないこともできます。配信しない場合、そのプリセットは追跡されません。

## ロードマップ

今後のバージョンで次の機能を予定しています。

- **共同編集**：複数のブラウザーから1冊の本を一緒に編集します
