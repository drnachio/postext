# Konfiguration: Überschriften


## Überschriften

Die Eigenschaft `headings` steuert die Typografie aller Überschriftenebenen (H1–H6). Sie können allgemeine Standardwerte setzen, die für alle Ebenen gelten, und dann einzelne Eigenschaften pro Ebene überschreiben.

Zentrierte Überschriften für Gedichte oder die Akte eines Theaterstücks, ohne Gestaltungsfeld:

```ts
headings: {
  textAlign: 'center',
  levels: [{ level: 2, textTransform: 'uppercase' }],
}
```

Übergeben Sie ein Objekt `headings`, bleibt jeder Standardwert einer Ebene erhalten, den Sie nicht erneut angeben, der Seitenumbruch vor der H1 eingeschlossen (siehe [Überschreibungen pro Ebene](#überschreibungen-pro-ebene)).

### Überschreibungen pro Ebene

Jede Überschriftenebene kann die allgemeinen Standardwerte über das Array `levels` überschreiben. Standardmäßig unterscheidet sich nur `fontSize` (dazu `breakBefore` der H1, siehe unten) – alle anderen Eigenschaften werden von den allgemeinen Überschrifteneinstellungen geerbt.

Der Standard der H1 bildet den Kapitelaufbau eines Buchs nach: Jede Überschrift der obersten Ebene beginnt auf einer neuen rechten (ungeraden) Seite, mit einer zwingend eingefügten Vakatseite als Trennung vom vorigen Kapitel. Überschreiben Sie ihn über `levels[0].breakBefore`, wenn Ihr Dokument flacher gegliedert ist als ein Buch.

Das `breakBefore` einer Ebene wird Feld für Feld über diesen Standard gelegt, und ein Objekt `headings`, das es nicht erwähnt, behält ihn. `{ parity: 'odd' }` auf der H1 behält den Umbruch und ändert nur die Parität; `{ enabled: false }` lässt die Kapitel fortlaufend weiterlaufen:

```ts
headings: {
  fontFamily: 'Merriweather',                               // H1 still breaks to a fresh recto (always-odd)
  levels: [{ level: 1, breakBefore: { parity: 'odd' } }],    // …or: a recto, with no mandatory blank
}

headings: { levels: [{ level: 1, breakBefore: { enabled: false } }] } // chapters run on
```

**Geändert in postext 1.5.** Bis postext 1.4 schaltete jedes Objekt `headings` den Umbruch der H1 aus, sofern `levels[0].breakBefore` nicht erneut angegeben wurde, und ein unvollständiges `breakBefore` füllte sein fehlendes Feld aus dem Standard ohne Umbruch. Eine für 1.4 im Code geschriebene Konfiguration mit einem Objekt `headings` und ohne Umbruch der H1 eröffnet daher jetzt jedes Kapitel auf einer neuen rechten Seite, mit linken Vakatseiten, wo nötig. Damit die Kapitel fortlaufend weiterlaufen, geben Sie dem Eintrag der H1 in `levels` ein Feld:

```ts
headings: { fontFamily: 'Merriweather', levels: [{ level: 1, breakBefore: { enabled: false } }] } // as 1.4 laid it out
```

Kommt die Konfiguration aus einem Speicher, erkennt die Engine, dass sie alt ist, und erledigt das für Sie: die Sandbox für die Bücher und Konfigurationen, die sie damals gespeichert hat (siehe **Sandbox → Speichern**), und `openBundle` / `readBundle` für ein `.postext`-Paket, das postext 1.4 oder älter geschrieben hat (siehe [Pakete, die postext 1.4 oder früher geschrieben hat](/de/docs/configuration-bundles#pakete-die-postext-14-oder-früher-geschrieben-hat)). Eine Konfiguration, die Sie selbst gespeichert haben, können Sie an `migrateConfig(config)` aus `postext/bundle` übergeben; es schreibt die Umbrüche aus, die 1.4 gesetzt hat (`pinLegacyHeadingBreaks`): `enabled: false` auf einer H1, die keinen Umbruch hatte, und `parity: 'any'` neben einem `enabled: true` ohne Parität, auf der H1 und auf Überschriftenstilen. Es fixiert außerdem, wie 1.4 sie setzte, die Größe der Mathematik, den Abstand um Inline-Abbildungen (auch in Kästen), die Inline-Auszeichnungen der Überschriften, die Größen der Initialen, den Platz unter einer Zeile mit Doppelpunkt, die eine Liste einleitet, die Zeilen eines Absatzes oder Listenpunkts, die ein Schnitt in einem Kasten übrig lässt, die Zeilenumbrüche an Gedankenstrichen, den zeilenweisen Umbruch von Flattersatz, die Teilung eines Absatzes unter einer Überschrift, die Zeilenumbrüche am Bindestrich eines Kompositums und den Abstand unter Containern `:::paragraphs`. Übergeben Sie das Markdown des Buchs als drittes Argument, `{ content }`, dann lässt es die Mathematik-Fixierung weg, wenn der Text kein `$` enthält, die Abstandsfixierungen, wenn keine Zeile eine Ressource einbettet (die Fixierung des Kastenabstands, wenn keine es in einem Kasten tut), die Fixierung der Überschriftenauszeichnungen, wenn keine Überschrift eine Auszeichnung enthält, die Fixierung der Doppelpunktzeile, wenn keine Liste auf eine Zeile mit Doppelpunkt am Ende folgt, die Fixierung des Kastenschnitts, wenn der Text kein `:::callout` öffnet, die Strich-Fixierung, wenn kein Strich ohne Abstand zwischen Wörtern steht, die Fixierung der Teilung unter Überschriften, wenn der Text keine Überschrift hat, die Container-Fixierung, wenn der Text keinen Container `:::paragraphs` öffnet, und die Kompositum-Fixierung, wenn kein Bindestrich zwischen zwei Buchstaben steht; die Fixierung des Flattersatzumbruchs erhält nur eine Konfiguration, die laufenden Text im Flattersatz setzt, und die Container-Fixierung nur eine, die ein Absatzformat deklariert (siehe [Pakete, die postext 1.4 oder früher geschrieben hat](/de/docs/configuration-bundles#pakete-die-postext-14-oder-früher-geschrieben-hat)). Nur für die Umbrüche rufen Sie `pinLegacyHeadingBreaks(config)` auf.

`snapToGrid` funktioniert auch pro Ebene. Ohne Wert folgt eine Ebene `headings.snapToGrid`; mit Wert überschreibt sie es – so kann ein Dokument seine H2 anderthalb Zeilen über ihren Text setzen, bis zum nächsten Einrastpunkt außerhalb des Rasters, während seine H3 den Abstand unter sich auf ganze Rasterzeilen aufrunden. Ein Überschriftenstil kann es ebenfalls setzen, für die Überschriften, die ihn verwenden.

```ts
headings: {
  marginBottom: { value: 1.5, unit: 'em' },
  levels: [
    { level: 2, snapToGrid: false }, // exactly 1.5 em under every H2
    { level: 3 },                    // inherits headings.snapToGrid: true
  ],
}
```

### Umbruch davor

`breakBefore` ist unabhängig von den Nummerierungseinstellungen: Ist es eingeschaltet, erzwingt es einen Seitenumbruch, aber der Zähler wird nur zurückgesetzt, wenn Sie ausdrücklich eine Direktive `:::numbering` einfügen. Leere Paritätsseiten zählen als echte Seiten der Folge und erhalten Kopf- und Fußzeilen nach ihren normalen Regeln für ungerade und gerade Seiten.

Ein `:::pagebreak` direkt vor einer solchen Überschrift ersetzt ihren Umbruch nicht: Die Überschrift wendet ihre Parität nach der Seite an, die die Direktive eröffnet hat, was eine leere Seite hinzufügen kann. Siehe [Überschriftenstile](/de/docs/configuration-styles#überschriftenstile) für eine Überschrift, die direkt nach einem manuellen Umbruch beginnen soll.

#### Zugehörigkeit leerer Seiten

Leere Seiten, die `breakBefore` einfügt, erhalten Kopfzeilen mit dem Kapiteltitel je nachdem, *warum* sie eingefügt wurden:

- Seiten, die eingefügt werden, um eine Paritätsbedingung zu erfüllen (`'odd'`, `'even'` oder das Paritätsende von `'always-*'`), gehören zum **kommenden** Kapitel. Ihr Platzhalter `{chapterTitle}` in der Kopfzeile wird zum Titel des neuen Kapitels aufgelöst – denn die leere Seite existiert nur, um das neue Kapitel auf die richtige Parität zu schieben.
- Die zwingende vorangehende Trennseite, die `'always-odd'` / `'always-even'` einfügen, gehört zum **vorigen** Kapitel. Sie ist ein bewusstes Atemholen am Kapitelende, daher zeigt die Kopfzeile mit `{chapterTitle}` weiterhin den Titel des alten Kapitels.

Lebende Kolumnentitel und Palette eines gestalteten Abschnitts (siehe [Überschriftenstile](/de/docs/configuration-styles#überschriftenstile)) folgen auf leeren Seiten denselben beiden Regeln.

#### Ausnahme am Dokumentanfang

Ist der allererste Block des Dokuments eine Überschrift mit eingeschaltetem `breakBefore` – oder beginnt die Quelle mit `:::pagebreak` –, wird die Parität nicht erzwungen, solange die erste Seite noch leer ist. Die Überschrift steht wie geschrieben auf Seite 1, unabhängig von der eingestellten Parität, sodass ein Dokument, das mit einem auf `parity: 'odd'` eingestellten `# Chapter 1` beginnt, keine unnötige leere Seite am Anfang erbt. Sobald Inhalt platziert wurde, verhält sich die Parität normal.

**Ein Auftakt so hoch wie die Seite.** Reicht die reservierte Höhe über den Fuß der Spalte hinaus – ein Umschlag, dessen `minHeight` die Seitenhöhe ist, ein Bild oder ein Kasten, der an der Seite oder am Anschnitt verankert ist und bis zum Beschnitt hinabreicht –, beansprucht der Auftakt den Rest der Seite: Der Text danach beginnt auf der nächsten Seite, in jeder Spalte eines zweispaltigen wie eines Anderthalb-Spalten-Layouts. Ein Umschlag braucht daher kein `:::pagebreak` danach (eines schadet nicht: Es fügt keine leere Seite hinzu). Eine Überschrift in der Spalte (`span: 'column'`), deren Gestaltung höher als ihre Spalte ist, beansprucht diese Spalte, und der Text beginnt am Kopf der nächsten. Der Block der Überschrift reicht dann bis zum Fuß der beanspruchten Spalte, und ihre Gestaltung wird an diesem Band ausgelegt: Oben verankerte Elemente bleiben, wo sie verankert sind, und die, die dem Band folgen – an seiner Mitte oder seinem Fuß verankert oder mit Höhe `'fill'` –, halten sich an den Raum, den die Überschrift beansprucht, wie sie sich an die reservierte Höhe halten, wenn sie passt (bis postext 1.4 behielt der Block die Höhe seines Texts, sodass diese Elemente an einem Band von einer Titelhöhe ausgelegt wurden und der Text danach unter der Gestaltung weiterlief). Seitenelemente, die die Seite nicht beanspruchen sollen – ein Streifen am Vorderschnitt über die ganze Seite, ein Ornament am Seitenfuß –, gehört stattdessen in die Gestaltung von Kopf- oder Fußzeile: An `'page'` oder `'bleed'` verankert und mit `pages: 'opener'` angezeigt, werden sie auf der Auftaktseite gezeichnet und reservieren keinen Raum im Fließtext.

- `{titleText}` – der reine Text der Überschrift (ohne Nummernpräfix). Ein erzwungener Umbruch im Titel (`\\`) ist hier ein Zeilenumbruch, in einem Auftaktband wie in einer Gestaltung in der Spalte (bis postext 1.4 setzte eine Gestaltung in der Spalte dort ein Leerzeichen, während ihre Höhe mit dem Umbruch gemessen wurde). Die Zeilen, auf die die verborgene Überschrift in ihrer Spalte umbricht, werden wieder zum Titel wie geschrieben verbunden: Ein nach seinem eigenen Bindestrich umbrochenes Wort behält den Bindestrich ohne Leerzeichen danach, ein Wort, das die Spalte getrennt hat, ist wieder ganz, ohne den Trennstrich, den der Umbruch hinzufügte, eine durch ein geschütztes Leerzeichen verbundene Gruppe, die breiter als die Spalte war und an diesem Leerzeichen geteilt wurde, erhält ihr geschütztes Leerzeichen zurück (`Capítulo XVIII`, nicht `CapítuloXVIII`), und jeder andere Umbruch gibt sein eines Leerzeichen zurück. Bis postext 1.4 wurde jeder Zeilenumbruch zu einem Leerzeichen, sodass ein Titel, der an einem Bindestrich umbrach, als `Word- Book` erschien, und ein erzwungener Umbruch in einem solchen Titel entfiel.
- `{number}` – die formatierte Nummer nach dem `numberingTemplate` der Ebene.
- `{numberDecimal}`, `{numberRoman}`, `{numberRomanLower}`, `{numberAlpha}`, `{numberAlphaLower}` – der Zähler der Überschrift (die laufende Zählung ihrer Ebene, gleich was die Vorlage ausgibt) in anderen Zahlformaten: Das dritte Kapitel ergibt `3`, `III`, `iii`, `C`, `c`, mit oder ohne `numberingTemplate`. Eine nicht nummerierte Überschrift (ein Stil mit `numbered: false`) lässt sie leer.
- `{numberWords}`, `{numberWordsLower}`, `{numberOrdinalWords}`, `{numberOrdinalWordsLower}` – derselbe Zähler ausgeschrieben, mit großem Anfangsbuchstaben oder klein: *Drei* / *drei*, *Dritte* / *dritte* (siehe [Ausgeschriebene Zahlen](#ausgeschriebene-zahlen)).
- `{numberHan}` – derselbe Zähler in chinesischen Zahlzeichen, in der Schrift des `locale` des Dokuments: Ein mit `第{numberHan}回` gesetzter Auftakt zeigt für das zwölfte Kapitel 第十二回, während das Inhaltsverzeichnis `12` aufführt.
- `{chapterNumber}`, `{chapterTitle}`, `{pageNumber}`, `{totalPages}`, `{bookTotalPages}`, `{title}`, `{subtitle}`, `{author}`, `{publishDate}` – gemeinsame Metadaten-Platzhalter.
- `{attr.<key>}` – ein Attribut, das auf der Überschriftenzeile selbst steht (`# Title {author="I. Zango Martín"}`), ersatzweise das Attribut der H1 des aktuellen Kapitels. Fehlende Attribute werden ohne Warnung zu einer leeren Zeichenkette aufgelöst.
- `{boxText}`, `{boxText.<n>}` – der Inhalt eines Kastens, den nur die Gestaltung eines Kastenstils liest (siehe [Kästen › Gestaltung im Kasten](/de/docs/configuration-callouts#gestaltung-im-kasten)); eine Überschriftengestaltung druckt dafür nichts.

`{chapterNumber}` gibt aus, was die lebenden Kolumnentitel für das Kapitel ausgeben: die Nummer der H1, wenn ihre Ebene (oder ihr Stil) ein `numberingTemplate` hat, sonst die Ordnungszahl des Kapitels – `1`, `2` …, fortgesetzt über die vor diesem gesetzten Kapitel hinaus – und nichts für ein nicht nummeriertes Kapitel oder einen Stil, dessen Vorlage `''` ist. Eine Überschriftengestaltung liest das Kapitel, zu dem ihre Überschrift gehört: eine Überschrift der Ebene 1 ihr eigenes, eine tiefere Überschrift die letzte Überschrift der Ebene 1 vor ihr. Das gilt auch, wo zwei Kapitel auf einer Seite aufeinandertreffen, während die lebenden Kolumnentitel dieser Seite das spätere Kapitel ausgeben. Die Höhe, die ein Auftakt reserviert, wird mit demselben Wert gemessen. Bis postext 1.4 wurde sie mit dem Nummernpräfix der Überschrift gemessen (ohne Vorlage leer), sodass eine Gestaltung, deren Höhe von `{chapterNumber}` abhängt, höher gezeichnet werden konnte als der Raum, den sie nahm; und die Gestaltung gab das Kapitel der Seite aus, sodass das erste von zwei Kapiteln, die sich eine Seite teilen, die Nummer des zweiten zeigte.

Die Zähler-Platzhalter folgen dem Buch über Kapitel hinweg, die einzeln gesetzt werden (die Zähler, die `continuationAfter()` weitergibt), und das Attribut `startAt` einer Überschrift setzt sie neu (siehe **Dokumentformat → Attribute von Überschriften**). Ein Auftakt, der *Chapter III* über einem Titel zeigt, der im Textfluss und im Inhaltsverzeichnis mit `3.` nummeriert ist:

```ts
{
  level: 1,
  span: 'page',
  numberingTemplate: '{1}.',
  advancedDesign: {
    enabled: true,
    slot: { elements: [
      { kind: 'text', id: 'label', content: 'Chapter {numberRoman}', fontSize: { value: 10, unit: 'pt' }, overflow: 'ellipsis-end',
        placement: { anchor: { to: 'container', edge: 'top-left' }, size: { width: 'fill', height: 'auto' } } },
      { kind: 'text', id: 'title', content: '{titleText}', fontSize: { value: 24, unit: 'pt' }, overflow: 'wrap',
        placement: { anchor: { to: '#label', edge: 'below' }, size: { width: 'fill', height: 'auto' } } },
    ] },
  },
}
```

#### Reservierte Höhe

Eine Überschrift mit erweiterter Gestaltung nimmt in der Spalte Raum ein wie jeder Block: Der Fließtext danach beginnt unter diesem Raum. Der Raum ist die größte von drei Höhen, alle von der Oberkante der Überschrift abwärts gemessen (bei einem Auftakt, der seine Seite beginnt, von der Oberkante des Satzspiegels):

1. der eigene Text der Überschrift, in der Typografie der Ebene gesetzt (er ist unter der Gestaltung verborgen, behält aber seine Zeilen);
2. die Unterkante des Gestaltungsinhalts – die tiefste Unterkante unter den Elementen, die zählen (siehe unten);
3. `advancedDesign.minHeight`.

Danach kommt das `marginBottom` der Überschrift hinzu (aus ihrem Überschriftenstil, ihrer Ebene oder `headings.marginBottom`; standardmäßig 0,5 em), und das Ergebnis wird auf das Grundlinienraster aufgerundet, wenn Überschriften einrasten. Bei einem Auftakt (`span: 'page'`) wird dasselbe Band in jeder Spalte der Seite freigehalten. Bei einer Überschrift in der Spalte, die in ihre Spalte passt, wird die Gestaltung im Rechteck der Überschrift ausgelegt, das genau so hoch ist.

**Welche Elemente zählen.** Jedes Element der Gestaltung zählt – Text, Linien, Kästen und Bilder gleichermaßen (bis postext 1.4 zählte ein Element `image` nie, sodass der Text über einem Bild im Band beginnen konnte, wenn `minHeight` ihn nicht fernhielt) –, außer:

- **Elementen mit `reserve: false`** – Dekoration, die unter dem Text liegen darf;
- **Elementen, die dem Band selbst folgen** – an der mittleren Reihe (`left`, `center`, `right`) oder der unteren Reihe (`bottom-left`, `bottom`, `bottom-right`) des Containers verankert, mit einer Höhe `'fill'` gegenüber dem Container (ein Kasten oder eine senkrechte Linie ohne Höhe füllt ihn standardmäßig), und jedem Element, das an einem davon verankert ist. Der Container ist das reservierte Band, daher sitzen diese auf seinem Fuß oder überspannen es: eine Linie unter dem Band, eine getönte Fläche hinter dem Titel. Sie folgen der Höhe; sie legen sie nie fest. Ein Text darunter, der seine eigene Höhe behält, braucht dennoch Platz: Ein am Fuß des Bands verankerter Titel macht das Band mindestens so hoch wie den Titel, sodass der Titel nie über der Oberkante der Überschrift beginnt. Mit `minHeight: 36mm` und dem Titel an `bottom-left` verankert ist das Rechteck der Überschrift 36 mm plus ihr `marginBottom` hoch, auf das Raster aufgerundet, und der Titel sitzt am Fuß dieses Rechtecks, direkt über dem folgenden Text; ohne `minHeight` macht ein Titel, der mehr Zeilen braucht als der eigene Text der Überschrift, das Band so tief wie den Titel. Bis postext 1.4 wurde ein solcher Titel nach oben über den Text über der Überschrift gezeichnet. Kästen, Linien und Bilder, die dem Band folgen, setzen keine solche Untergrenze, sodass eine am Fuß verankerte Fläche über die Überschrift hinausreichen kann.

An Seite und Anschnitt verankerte Elemente zählen danach, wie weit sie unter die Oberkante der Überschrift reichen. Ein Band oben über die Seite, das über der Überschrift endet, zählt nichts; ein randabfallendes Bild, das darüber hinausläuft, schiebt den Text bis zu seiner Unterkante hinunter. Ebenso alles, was tief auf der Seite steht: Ein Siegel 25 mm über dem Seitenfuß, ein Seitenband in voller Höhe oder ein Rahmen reserviert die Seite bis zu seiner Unterkante, und der Text beginnt meist auf der nächsten Seite. Kennzeichnen Sie solche Dekoration mit `reserve: false` – sie wird weiterhin gezeichnet, und Elemente können weiterhin an ihr verankert werden – und geben Sie der Überschrift den nötigen Raum mit ihren Textelementen oder `minHeight`:

```json
{
  "kind": "image", "id": "seal", "resourceId": "seal", "reserve": false,
  "placement": {
    "anchor": { "to": "page", "edge": "bottom-right" },
    "offset": { "x": { "value": -25, "unit": "mm" }, "y": { "value": -25, "unit": "mm" } },
    "size": { "width": { "value": 30, "unit": "mm" } }
  }
}
```

Ein Element, das an einem nicht reservierenden verankert ist, zählt weiterhin, sofern es nicht ebenfalls gekennzeichnet ist (eine auf das Siegel gesetzte Legende braucht ihr eigenes `reserve: false`).

**Wo sie gezeichnet wird.** Die Gestaltung eines Auftakts (`span: 'page'`) wird vor dem Fließtext gezeichnet, sodass Dekoration, die nichts reserviert, unter dem Text liegt. Die Gestaltung einer Überschrift in der Spalte wird mit dem Block der Überschrift gezeichnet – über den Blöcken darüber in der Spalte, unter denen danach –, wo immer sie oberhalb des Fußes ihrer Spalte platziert ist: auch in den Seitenrändern, im Kopfsteg, im Anschnitt und in den benachbarten Spalten. Der Fuß der Spalte schneidet sie ab, im Canvas und im PDF, da der Textfluss dort endet (siehe **Höher als die Spalte** unten). Bis postext 1.4 schnitten Canvas und PDF sie auch am Kopf ihrer Spalte ab, sodass ein oben an Seite oder Anschnitt verankertes Band in die Seitenränder lief, aber am Kopfsteg aufhörte. Dekoration, die am Seitenfuß verankert ist, gehört in einen Auftakt oder in die Gestaltung der Fußzeile mit `pages: 'opener'`.

**Höher als die Spalte.** Reicht der Raum über den Fuß der Spalte hinaus – ein `minHeight` so hoch wie die Seite, ein Bild oder Rahmen, das bzw. der bis zum Beschnitt hinabreicht –, beansprucht die Überschrift den Rest ihrer Seite (ein Auftakt, in jeder Spalte) oder ihrer Spalte (eine Überschrift in der Spalte), und der Text danach beginnt auf der nächsten Seite oder in der nächsten Spalte. Ihr Block reicht dann bis zum Fuß der Spalte und wird nie auf die Höhe ihres Texts zurückgeschnitten, sodass das Band, an dem ihre Gestaltung ausgelegt wird, der beanspruchte Raum ist (`minHeight` eingeschlossen, bis zum Fuß). Eine Gestaltung, die höher als die Seite selbst ist – ein langer Vorspann auf einer kleinen Bildschirmseite –, wird weiterhin am Seitenfuß abgeschnitten (eine Gestaltung in der Spalte am Fuß ihrer Spalte): Die Sandbox führt das im Bedienfeld **Prüfungen** als *Überschriftengestaltung abgeschnitten* auf. Das Layout gibt dafür keine Warnung aus – ein Umschlag, der seine Seite beansprucht, ist der übliche Fall und verliert nichts –, aber jeder Host kann dieselbe Prüfung am fertigen Layout ausführen: `collectHeadingDesignCuts(doc)` liefert ein `{ kind: 'headingDesignCut', pageIndex, level, where, overflowPx, sourceStart, sourceEnd }` für jede Überschrift, deren Gestaltungstext über den Fuß des Seitenbeschnitts (`where: 'page'`, ein Auftakt) oder ihrer Spalte (`where: 'column'`) hinausreicht, und `formatWarning` beschreibt jede. Siehe **Ein Auftakt so hoch wie die Seite** unter [Seitenbreite und erweiterte Gestaltung](#seitenbreite-und-erweiterte-gestaltung).

**Eine Überschrift, die ihre Spalte füllt.** Eine Überschrift in der Spalte (`span: 'column'`), deren reservierte Höhe bis zum Fuß der Spalte reicht, sodass der Text danach in der nächsten Spalte oder Seite beginnt, löst die Inhaltswarnung `headingClaimsColumn` aus (`level`, `element`). `element` ist die ID des Gestaltungselements, das am tiefsten reicht; sie fehlt, wenn `minHeight` die Höhe bestimmt. Setzen Sie `reserve: false` auf das Element, wenn es Dekoration ist, verringern Sie `minHeight`, oder geben Sie der Ebene `span: 'page'`, wenn die Seite der Überschrift gehören soll. Ein seitenbreiter Auftakt beansprucht seine Seite absichtlich und wird nicht gemeldet; ebenso wenig eine Überschrift auf einer einspaltigen Seite, wo die Spalte die Seite ist, oder eine, auf die ein ausdrücklicher Umbruch folgt (`:::pagebreak`, ein `breakBefore`, ein Spaltenumbruch). Die Sandbox führt sie im Bedienfeld **Prüfungen** als *Die Gestaltung der Überschrift füllt ihre Spalte* auf. Seit postext 1.43.

**Die Seitenspalte.** In einem Anderthalb-Spalten-Layout, dessen Seitenspalte Gleitobjekte aufnimmt (`sideColumnRole: 'floats'`), hält ein Element der Gestaltung einer Überschrift in der Spalte, das in der Seitenspalte steht – eine an der Seite verankerte Kapitelziffer in der äußeren Randspalte eines Lehrbuchauftakts –, den Stapel der Seitenspalte von sich fern. Jede Abbildung, Tabelle oder jeder Kasten mit `span: 'side'`, den die Seite nach der Überschrift setzt, hält einen Gleitobjektabstand zu jedem solchen Element frei: Er bleibt, wo der Stapel ihn hinsetzt, wenn er über dem Element passt, und geht sonst darunter – oder wartet auf die nächste Seite, wenn der Rest der Seitenspalte ihn dort nicht fassen kann. Eine Ziffer am Kopf des Kanals hält also den ganzen Stapel unter sich, während eine Abschnittsnummer, die neben einer weiter unten stehenden Überschrift im Rand hängt, den Kopf des Kanals den Abbildungen überlässt, auf die die Seite verweist (die Randabbildung sitzt weiterhin oben auf ihrer Seite). Was die Seitenspalte schon enthält, wenn die Überschrift platziert wird, wird nicht bewegt: Eine früher auf der Seite gestapelte Abbildung, die bis zum Element der Überschrift hinabreicht, bleibt, wo sie ist, unter dem Element; bei einer Gestaltung, deren Element mitten auf der Seite in der Seitenspalte steht, sollte also erst nach der Überschrift auf die Abbildungen verwiesen werden. Elemente mit `reserve: false` lassen die Seitenspalte frei, wie sie den Text freilassen. Ein Auftakt (`span: 'page'`) braucht nichts dergleichen: Sein Band ist in jeder Spalte reserviert, die Seitenspalte eingeschlossen. Bis postext 1.4 wurde eine Seitenabbildung, auf die ein solcher Auftakt verwies, am Kopf der Seitenspalte über die Ziffer gesetzt.

**Umschläge.** Eine Umschlagüberschrift, die ihre Seite füllt – `minHeight` so hoch wie die Seite oder ein ganzseitiges Bild in ihrer Gestaltung –, verschiebt den Text danach daher von selbst auf die nächste Seite, in ein- wie mehrspaltigen Layouts. Ein `:::pagebreak` direkt danach ist optional und schadet nicht: Ein Seitenumbruch auf einer noch leeren Seite bewirkt nichts und fügt daher nie eine leere Seite hinzu. Er wird nur gebraucht, wenn die Gestaltung des Umschlags vor dem Seitenfuß aufhört und der Text dennoch auf einer neuen Seite beginnen soll.

```md
# Annual report 2026 {style="cover"}

:::pagebreak

# Letter from the chair
```

Eine Verzeichnisseite, die im Fließtext gesetzt ist und deren Titel in einer Überschriftengestaltung steht, zeigt dasselbe: Ein am Anschnitt verankerter Kasten, der bis zum Beschnitt reicht, reserviert die ganze Spalte, und der erste Eintrag des Verzeichnisses rückt auf die nächste Seite und lässt die Seite leer. Kennzeichnen Sie den Kasten mit `reserve: false`. Braucht das Verzeichnis einen Grund unter dem ganzen Blatt, setzen Sie es besser in einem Rahmen einer [zusammengesetzten Seite](/de/docs/composed-pages): Die Dekoration der Vorlage wird unter den Text gezeichnet, auf jeder Seite, die das Verzeichnis einnimmt.

#### In Kästen und Rahmen

Eine Überschrift in einem Kasten (`:::callout`) oder in einem Rahmen einer [zusammengesetzten Seite](/de/docs/composed-pages) wird ebenfalls von ihrer Gestaltung gezeichnet: Das `advancedDesign` ihrer Ebene oder ihres Überschriftenstils setzt Reiter, Band, Linien und `{titleText}` an die Stelle ihrer Zeilen, wie in einer Spalte der Seite. Die Gestaltung wird am eigenen Kasten der Überschrift ausgerichtet, so breit wie der Text des Kastens, und der Kasten hält den Platz frei, den sie braucht: das Höchste aus dem Text der Überschrift, der Unterkante des Gestaltungsinhalts und `minHeight` ([Reservierte Höhe](#reservierte-höhe)). Ein Kasten hat kein Grundlinienraster, darum wird dieser Platz nicht auf eine Rasterzeile aufgerundet; danach folgt das `marginBottom` der Überschrift, wie nach jeder Überschrift im Kasten. Ein Element, das mit negativem Versatz am Container verankert ist, ragt aus dem Kasten der Überschrift heraus, über den Innenabstand oder den Reiter des Kastens; der Kasten schneidet es nicht ab, außer der Inhalt eines Rahmens läuft über dessen Fuß hinaus (ein überlaufender Rahmen beschneidet alles, was er enthält). An `'page'` oder `'bleed'` verankerte Elemente bleiben auf die Seite bezogen.

Eine Überschrift mit `span: 'page'` in einem Kasten wird wie eine Überschrift in der Spalte gesetzt, in der Breite des Kastens: Ein Kasten eröffnet weder eine Seite noch ein Auftaktband. Ihr Überschriftenstil gibt ihr weiterhin ihr Aussehen, doch eine Überschrift in einem Kasten eröffnet keinen gestalteten Abschnitt: Kolumnentitel, die Rolle der Seite und die `{attr.…}`-Werte des Kapitels kommen weiter aus den Überschriften des Textflusses. Ein Kasten wird nie zwischen den Zeilen einer Überschrift getrennt, die ihre Gestaltung zeichnet.

In einem Rahmen, dessen Text die Einpassstufen verkleinern (die Schritte, mit denen Inhalt passend gemacht wird; `fit.minScale`), wird die Gestaltung mit dem Text verkleinert, und ein an der Seite verankertes Element bleibt an der Ecke der Seite, seine Versätze im selben Maßstab; ein gedrehter Rahmen dreht die Gestaltung mit; auf einer Doppelseite zeigt auch die Hälfte eines Rahmens auf der gegenüberliegenden Seite die Gestaltung. Ein Klick auf den Titel, den die Gestaltung ausgibt, führt zum Markdown der Überschrift (`sourceAt`). Bis postext 1.36 wurden die Überschriften von Kästen ohne Gestaltung gesetzt: Ein fixierter, gleitender oder auf einer zusammengesetzten Seite stehender Kasten zeichnete keine, die Gestaltung eines Überschriftenstils wurde in keinem Kasten gezeichnet, und die einer Ebene wurde in einem Kasten der Spalte in die Höhe des Überschriftentexts gezwängt, über das, was folgte. Seit postext 1.37.

Die Schreibung des Suffixes legt die Schreibung der Wörter fest, wie `A` / `a` es für Buchstaben tut:

Englisch, Spanisch, Französisch, Italienisch, Deutsch, Katalanisch, Portugiesisch, Chinesisch, Japanisch und Arabisch werden ausgeschrieben; jede andere Sprache erhält die englischen Wörter, wie bei den eingebauten Fortsetzungstexten von Tabellen. Chinesisch schreibt die informellen Zahlzeichen von `simp-chinese-informal` oder `trad-chinese-informal`, je nach Schrift von `locale` (一万 / 一萬), mit 第 vor einer Ordnungszahl; Han-Zeichen kennen keine Groß- und Kleinschreibung, daher ergeben die drei Schreibungen eines Suffixes dasselbe. Englisch folgt dem amerikanischen Gebrauch (*one hundred five*, ohne *and*). Spanisch verwendet standardmäßig männliche Formen, wie ein *capítulo* oder ein *libro* nummeriert wird (*capítulo primero*, *tercero*, *veintiuno*), und schreibt die Ordnungszahlen von 13 bis 29 in einem Wort, wie es die RAE bevorzugt (*decimotercero*, *vigesimoprimero*). Grundzahlen werden bis 999 999 ausgeschrieben und spanische, katalanische und portugiesische Ordnungszahlen bis 999; größere Zahlen erscheinen in Ziffern.

Französisch folgt der traditionellen Schreibung (*vingt et un*, *soixante et onze*, *quatre-vingts*, *deux cent un*) und schreibt *premier* für eins (*Chapitre premier*, aber *vingt et unième*); Italienisch schreibt jede Zahl in einem Wort (*ventuno*, *ventitré*, *duemilaventiquattro*; *primo*, *ventunesimo*), Deutsch ebenso (*einundzwanzig*, *hunderteins*; *erste*, *einundzwanzigste*), mit *ss* statt *ß* im Schweizer Hochdeutsch (`de-CH`); Katalanisch folgt dem IEC (*vint-i-u*, *dos-cents*; *primer*, *cinquè*, *vint-i-unè*), und Portugiesisch ist das brasilianische (*dezesseis*), sofern `locale` keine andere Region nennt (`pt-PT`: *dezasseis*), mit den lateinischen Ordnungszahlen (*vigésimo primeiro*). Katalanische und portugiesische Ordnungszahlen werden wie die spanischen bis 999 ausgeschrieben.

Die romanischen Sprachen lesen den Genus-Modifikator: `-feminine` (oder `-f`) gleicht die Wörter an ein weibliches Substantiv an (`Parte {1:ordinal-f}` ergibt auf Italienisch *Parte prima*, `{1:Ordinal-f} partie` auf Französisch *Première partie*; ebenso *veintiuna*, *vint-i-una*, *duzentas*), `-masculine` (`-m`) ist der Standard. Im Deutschen bleibt die Grundzahl unverändert (*Kapitel eins*), die Ordnungszahl nicht: Ohne Modifikator erhält sie die Endung nach dem Artikel, die in allen drei Genera gleich ist (`Das {1:ordinal} Kapitel` ergibt *Das erste Kapitel*); vor einem Substantiv ohne Artikel ergibt `-masculine` *Erster Teil*, `-feminine` *Erste Lektion* und `-neuter` (`-n`) *Erstes Kapitel*. Zahlwörter schreibt das Deutsche klein (`Kapitel {1:words}` ergibt *Kapitel eins*); `{1:Words}` setzt einen Großbuchstaben an den Anfang, für ein Wort, mit dem die Überschrift beginnt, und `{1:WORDS}` schreibt ß als SS.

Arabische Zahlen richten sich im Genus nach dem gezählten Substantiv, daher nimmt das Suffix einen Modifikator an: `-feminine` (oder `-f`) für ein weibliches Substantiv, `-masculine` (`-m`, der Standard) für ein männliches; `-classical` schreibt die Hunderter مائة, wie es Bulaq und die meisten ägyptischen Drucke tun, statt des modernen مئة. `{1:ordinal}` schreibt die bestimmte Ordnungszahl im Nominativ, die eine Überschrift verwendet: `الفصل {1:ordinal}` ergibt *الفصل الأول*, *الفصل الحادي عشر*, *الفصل الحادي والعشرون*; `الليلة {1:ordinal-feminine}` ergibt *الليلة الأولى*, *الليلة الحادية عشرة*, *الليلة الحادية والعشرون*, *الليلة المئتان* und über hundert die klassische „Nach“-Formel: *الليلة الخامسة والأربعون بعد الثلاثمئة*, *الليلة الحادية بعد الألف*. `{1:words}` schreibt die Grundzahl (واحد وعشرون; weiblich إحدى عشرة, واحدة وعشرون). Ordnungszahlen werden bis 9 999 und Grundzahlen bis 99 999 ausgeschrieben; die Modifikatoren lassen sich kombinieren (`{1:ordinal-f-classical}`); die romanischen Sprachen und Deutsch lesen nur das Genus (siehe oben), und andere Sprachen ignorieren sie. Arabisch kennt keine Großbuchstaben, daher ändert die Schreibung des Suffixes nichts. Die Gestaltungsplatzhalter `{numberWords}` und `{numberOrdinalWords}` schreiben die männlichen Formen; für einen weiblichen Auftakt setzen Sie die Ordnungszahl in die Vorlage der Ebene und geben sie mit `{number}` aus.

In einer Überschriftengestaltung schreiben `{numberWords}` / `{numberWordsLower}` und `{numberOrdinalWords}` / `{numberOrdinalWordsLower}` den Zähler der Überschrift auf dieselbe Weise aus, sodass der Auftakt *Chapter One* sagen kann, während das Inhaltsverzeichnis `1` aufführt. `textTransform: 'uppercase'` eines Textelements liefert die Versalien:

```ts
// Spanish novel: "CAPÍTULO PRIMERO" above the title, "1." in the contents.
{ level: 1, numberingTemplate: '{1}.', span: 'page',
  advancedDesign: { enabled: true, slot: { elements: [
    { kind: 'text', id: 'n', content: 'Capítulo {numberOrdinalWordsLower}', textTransform: 'uppercase', /* … */ },
    { kind: 'text', id: 't', content: '{titleText}', /* … */ },
  ] } } }
```
