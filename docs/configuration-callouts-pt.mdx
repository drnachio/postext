# Configuração: boxes


## Estilos de boxe

A propriedade `calloutStyles` declara os estilos de boxe nomeados que um documento aplica com um contêiner `:::callout{type="…"}`: notas, dicas, avisos, objetivos de aprendizagem, qualquer conteúdo separado do texto corrido em um boxe com fundo ou contorno. Um estilo neutro, `note`, vem por padrão (fundo cinza-claro, sem contorno, sem faixa, sem ícone, sem título), de modo que `:::callout` funciona sem nenhuma configuração; declarar `calloutStyles` substitui essa lista padrão.

```ts
const config: PostextConfig = {
  calloutStyles: [
    { id: 'note', name: 'Note' },
    {
      id: 'objectives',
      name: 'Learning objectives',
      title: 'Objectives',
      stripe: { enabled: true, side: 'left' },
      icon: { kind: 'glyph', glyph: '✓' },
      titleStyle: { textTransform: 'uppercase' },
      lists: { bulletChar: '–' },
    },
    {
      id: 'warning',
      title: 'Warning',
      backgroundEnabled: false,
      border: { enabled: true, color: { hex: '#AA0000', model: 'hex' }, width: { value: 1, unit: 'pt' } },
      borderRadius: { value: 1, unit: 'mm' },
      titleStyle: { color: { hex: '#AA0000', model: 'hex' } },
    },
  ],
};
```

```md
:::callout{type="objectives"}
- Describe the parts of the lantern.
- Trim the wick at dusk.
:::

:::callout{type="warning" title="Do not touch the lens"}
The glass stays hot for an hour after the flame is out.
:::
```

A imagem mantém as próprias cores; por isso, um anel branco sobre uma aba colorida e um anel colorido sobre uma branca são dois recursos, um em cada estilo. <code>'beside'</code>, o padrão, põe a imagem além da borda da aba. Uma imagem sem transparência vira um retângulo liso. No PDF um SVG mantém as bordas e um bitmap é recortado onde é meio transparente; o original de impressão (<code>svg.pdfFileId</code>) não é usado, porque uma página PDF não pode ser recolorida. ### Cantos, lados e abas unidas

Um boxe não precisa ser um retângulo com quatro cantos iguais e uma só borda. Desde o postext 1.48, um estilo pode arredondar alguns cantos e outros não, traçar a borda só em alguns lados e fazer a aba sair do boxe como uma única forma: o cartão de um livro didático cuja aba de título e cujo corpo são um só contorno, desenhado pelo estilo e não pintado numa imagem atrás da página.

```ts
calloutStyles: [
  // Rounded at the top only, a rule over the box and a heavier foot.
  { id: 'ficha', background: { model: 'hex', hex: '#fff4d6' },
    borderRadius: { topLeft: { value: 3, unit: 'mm' }, topRight: { value: 3, unit: 'mm' } },
    border: { enabled: false, color: { model: 'hex', hex: '#c58b00' }, width: { value: 0.75, unit: 'pt' },
      sides: { top: { enabled: true }, bottom: { enabled: true, width: { value: 2, unit: 'pt' } } } } },
  // A card whose tab grows out of its top edge.
  { id: 'tarjeta', background: { model: 'hex', hex: '#ffffff' }, borderRadius: { value: 3, unit: 'mm' },
    border: { enabled: true, color: { model: 'hex', hex: '#2a6f97' }, width: { value: 1, unit: 'pt' } },
    label: { position: 'top-left', inset: { value: 4, unit: 'mm' }, joined: true, fillet: { value: 2, unit: 'mm' },
      color: { model: 'hex', hex: '#2a6f97' } } },
]
```

- **Cantos.** `borderRadius` é um comprimento para os quatro cantos, ou `{ topLeft, topRight, bottomRight, bottomLeft }`. Um canto que fica fora do objeto é reto. Os cantos são os da folha. Dois cantos nunca tomam mais do que o lado entre eles; cada um cede na proporção.
- **Lados.** `border.sides.top`, `right`, `bottom` e `left` recebem `enabled`, `color` e `width`, e cada campo omitido é o da borda inteira. Um boxe com borda só em cima é `border: { enabled: false, sides: { top: { enabled: true } } }`, ou `enabled: true` com os outros três lados desligados. A borda interna de um lado acompanha a largura dele; assim, um canto arredondado entre um lado fino e um grosso faz a curva como o CSS a desenha.
- **Aba unida.** Com `label.joined: true`, a aba e o boxe são um só contorno, um só fundo (o `background` do boxe; o `background` próprio da aba não é pintado) e uma só borda que dá a volta na aba. A aba fica sobre a borda, fora do boxe na medida da altura dela: o `offset` dela tem de ser `0` (outro valor é apontado como `unknownConfigValue` e lido como `0`). Os cantos externos dela tomam o raio do canto do boxe em que ela encosta, e os cantos internos, onde ela encontra o boxe, são arredondados por `fillet` (padrão: esse raio). Uma aba rente ao lado do boxe (um `inset` de menos de meio pixel) sobe reta a partir desse lado. Dê às palavras uma cor que se leia sobre o fundo do boxe (`label.color`), porque a aba já não tem fundo próprio. Com `label.ownBackground: true`, uma aba unida é pintada com o `background` do próprio rótulo, sobre o preenchimento do boxe e sob a borda, de modo que uma aba branca pode ficar sobre um boxe tingido, ou uma aba colorida sobre um boxe sem preenchimento.
- **Cantos da aba.** `label.borderRadius` dá à aba cantos próprios: um comprimento, ou `{ topLeft, topRight, bottomRight, bottomLeft }` nos cantos da folha, como o `borderRadius` do boxe. Uma aba separada do boxe é reta se não os definir. Uma aba unida arredonda com ele os dois cantos externos (`topLeft` e `topRight` numa aba no alto, `bottomLeft` e `bottomRight` no pé); sem valor, tomam o raio do canto do boxe. As concordâncias mantêm `fillet` nos dois casos.
- **Abas embaixo.** `position: 'bottom-right'`, `'bottom-left'`, `'bottom-start'` ou `'bottom-end'` pendura a aba no pé do boxe, simples ou unida: é a aba de cima virada, `offset` abaixo do pé, com o `rule` ao longo do pé. Não há abas laterais: as palavras de uma aba correm na horizontal.

Todas as saídas desenham essas formas: o canvas e o PDF como contornos vetoriais, o visualizador HTML e o EPUB de layout fixo com CSS por canto e por lado. O EPUB refluível escreve os cantos e os lados no CSS dele e compõe uma aba unida como uma aba simples. O `look.border.color` de um bloco recolore todos os lados, e a paleta de uma parte recolore cada um deles. Um estilo com todos os cantos e lados iguais é diagramado como antes.

### Estilos baseados em outro

`extends` indica outro estilo de `calloutStyles`, e todo campo que o estilo deixa sem valor vem dele. Objetos como `padding`, `border`, `titleStyle` ou `fixed` são combinados chave a chave; por isso, um estilo pode mudar só um lado do preenchimento ou só `fixed.offset`; uma cor ou um comprimento vêm inteiros; `id` e `name` nunca são herdados. Um estilo base pode, por sua vez, basear-se em outro. Um livro com boxes em muitos lugares guarda um estilo para a aparência e um estilo mínimo por lugar:

```ts
calloutStyles: [
  {
    id: 'caja',
    background: { model: 'hex', hex: '#dff0fa' },
    padding: { top: { value: 3, unit: 'mm' }, right: { value: 4, unit: 'mm' }, bottom: { value: 3, unit: 'mm' }, left: { value: 4, unit: 'mm' } },
  },
  { id: 'caja-p5', extends: 'caja', placement: 'fixed', fixed: { offset: { x: { value: 12, unit: 'mm' }, y: { value: -40, unit: 'mm' } } } },
  { id: 'caja-p9', extends: 'caja', placement: 'fixed', fixed: { anchor: { to: 'container', edge: 'top-right' } } },
]
```

Mude a aparência de `caja` e todos os boxes acompanham, cada um onde está. Um `extends` que não indica nenhum estilo existente gera `calloutStyleExtendsUnknown` (o aviso sugere o id mais próximo, e o estilo fica sozinho, com os valores padrão), e estilos baseados uns nos outros em círculo geram `calloutStyleExtendsCycle` (ficam sozinhos até que um se baseie num estilo fora do círculo). No Sandbox, o campo **Baseado em** de um estilo de boxe define isso; apagar um estilo em que outros se baseiam grava as configurações dele nesses estilos, e os boxes deles não mudam. Na seção **Estilos de bloco**, ao fundir com **Comparar só a aparência**, se **Deixar cada boxe onde está** estiver ativado (o padrão), um estilo cujos boxes ficam em outro lugar é mantido como um desses estilos mínimos, e nenhum boxe se move. Desde o postext 1.39.

### O contêiner `:::callout`

Uma linha `:::callout{type="<id>"}` abre o boxe e uma linha `:::` sozinha o fecha. O delimitador aceita cinco atributos, `type` (o id do estilo), `title` (substitui o título do estilo), `span`, `placement` e `columns` (substituem os valores do estilo), e o conteúdo entre as duas linhas é composto dentro do boxe: um título opcional e depois os parágrafos, listas, citações, fórmulas ou recursos incorporados, cada um com a tipografia `body` / `lists` do estilo (os títulos mantêm os estilos habituais). As margens entre os filhos se fundem como no texto corrido; o interior sai da grade de linhas de base, e o fluxo volta a ela depois do boxe com pelo menos `marginBottom` abaixo (a grade prevalece; a margem é um mínimo, a mesma convenção que os recursos seguem). Um estilo com `snapToGrid: false` mantém, em vez disso, o `marginBottom` exato, e o texto depois do boxe fica fora da grade até o próximo título ou fim de lista. Um título imediatamente antes de um boxe fica junto dele.

Limites desta versão:

- Um boxe é mantido inteiro, a menos que o estilo dele defina `keepTogether: false`. Quando não cabe no espaço restante da coluna, passa inteiro para a coluna ou página seguinte, inclusive saindo de uma coluna vazia que as faixas de flutuantes ou um limite de faixa encurtaram, desde que uma coluna completa o comportasse. Um boxe mais alto que uma coluna completa se divide em vez disso, como um divisível; só aquele que nenhum corte consegue dividir (uma figura ou tabela mais alta que a coluna, ou um `splitMinLines` que nenhum corte satisfaz) é colocado mesmo assim e transborda; o layout registra então um aviso `calloutOverflow` (`VDTDocument.warnings`), que o Sandbox lista. Um grupo `:::columns` é cortado como o boxe que o envolve, entre as subcolunas (desde o postext 1.25); ele só fica inteiro, e pode transbordar do mesmo modo, com `layout.flowColumns: false` ou dentro de um boxe aninhado. Um boxe divisível deixa para trás a parte que cabe (filhos inteiros, ou as linhas de um parágrafo até `splitMinLines` de cada lado; uma figura, tabela ou fórmula em destaque sozinha basta para um lado) e continua em um boxe sem ícone na coluna ou página seguinte, sem o título a menos que o estilo o repita e, opcionalmente, com uma marca sob a parte que deixa (veja [Marcas em um boxe dividido](#marcas-em-um-boxe-dividido)).
- Os flutuantes cedem a um boxe indivisível. Quando o bloco logo depois da referência a uma figura é um boxe `keepTogether`, um espaço que deixaria o boxe sem nenhuma coluna da faixa atual onde cair (a coluna da referência ou uma vazia depois dela, que o comportava antes do flutuante) não é tomado: a figura passa para o próximo espaço disponível, normalmente a página seguinte, e o boxe continua no fluxo, como um compositor o comporia, em vez de empurrar o boxe para fora da página e deixar a coluna só com a figura.
- `span: 'page'` em um layout de várias colunas faz do boxe um **bloco de largura de página**: ele é composto na largura total do conteúdo e divide a página em faixas de colunas. As colunas de texto acima dele são fechadas na linha de corte, o boxe ocupa uma coluna própria de largura total e uma nova faixa de colunas de texto se abre abaixo dele, de modo que o fluxo continua sob o boxe em todas as colunas. Onde as colunas estão *niveladas* (no alto de uma página, logo abaixo de um título de abertura `span: 'page'`, logo abaixo de outro bloco de largura de página ou logo abaixo de uma faixa de flutuantes superior), o boxe simplesmente corta ali. Chegando no meio da página, com as colunas desiguais, ele é composto como um compositor faria: o texto acima é cortado nivelado em todas as colunas (o motor refaz a colocação com as colunas da faixa encurtadas para o mesmo número de linhas da grade, de modo que o texto passa de coluna em coluna naturalmente e todas as regras de órfãs, viúvas e manter com o seguinte continuam valendo), o boxe ocupa a largura da página e as colunas continuam abaixo dele. O corte custa algumas passadas extras de colocação; quando a linha de corte não deixaria espaço para o boxe mais o mínimo de linhas do corpo para viúvas abaixo dele, ou nenhuma disposição cabe depois de algumas tentativas, o boxe passa para o alto da página seguinte. O texto acima respeita o corte: um parágrafo que não consegue começar nas poucas linhas que uma coluna mantém acima, sob uma figura, passa para a coluna seguinte (a figura fica então sozinha na coluna), e quando um bloco ainda ultrapassaria o corte, o corte é feito uma linha abaixo em vez de onde esse bloco termina. Um boxe dividido que abre a faixa também é cortado ali, de modo que o resto dele nunca ultrapassa o corte. Com `headings.balancing.beforeSpan` (o padrão), a faixa que ele deixa é cortada nivelada atrás dele, como a faixa de fechamento de um capítulo, e, quando o estilo permite a divisão (`keepTogether: false`), a parte do boxe que cabe sob as colunas niveladas fecha a página e o resto abre a seguinte; com `beforeSpan: false`, a página que ele deixa é simplesmente equilibrada como de costume, sem forçar uma quebra de página. Um título logo antes de um bloco de largura de página não o acompanha. Em layouts de uma coluna, `span: 'page'` é simplesmente em linha.
- `placement: 'fixed'` tira o boxe do fluxo: ele é composto (`width: 'auto'` se ajusta ao título; `'fill'` toma a largura da coluna de texto sob o ponto de ancoragem) e fixado na página em que aparece no fluxo, na posição descrita por `fixed.anchor` / `fixed.offset` (por padrão, o canto inferior esquerdo da área de conteúdo). As colunas de texto que ele cobre cedem essa zona (cortada por baixo, ou por cima quando a coluna ainda está vazia), exatamente como uma faixa de flutuantes; quando a zona já contém texto, um flutuante ou um bloco de largura de página, o boxe passa para a página seguinte. Um boxe fixo que fecha o capítulo (o bloco seguinte é uma abertura de capítulo, um `:::part`, um boxe barreira de flutuantes ou o fim do documento) primeiro nivela as colunas acima dele (`headings.balancing.trailing`), de modo que uma página final curta termina nivelada, com o selo embaixo. A moldura e os filhos ficam em `page.floats` e são renderizados fora do recorte das colunas em todos os renderizadores.
- `placement: 'top' | 'bottom'` faz o boxe **flutuar** como um recurso: ele sai do fluxo onde aparece e toma a primeira faixa livre depois desse ponto, isto é, o pé da página atual (`'bottom'`) ou o alto / o pé da próxima página que o fluxo abrir, na largura da coluna (`span: 'column'`) ou na largura total do conteúdo (`span: 'page'`); o texto que vem depois preenche a página que ele deixou. A moldura e os filhos dele vão para `page.floats`, como os de um boxe fixo. Um boxe flutuante no alto de uma página nova é colocado antes das figuras que esperam por essa página, e uma figura citada em uma página anterior que então caiba sob ele fica com o resto da página, mesmo que restem menos de três linhas de texto (uma página de galeria: boxe mais figura, sem texto entre eles). Um boxe `span: 'side'` nunca flutua: ele se empilha ao lado do texto, qualquer que seja o posicionamento. Com `columns` acima de 1 (no estilo ou como atributo do delimitador, desde o postext 1.18), um boxe `span: 'column'` ocupa esse número de colunas adjacentes: o alto de uma sequência de colunas vazias que começam niveladas, ou o pé da coluna atual e das vazias depois dela, como em `:::callout{placement="top" columns="2"}`.
- `width: 'auto'` se ajusta só ao título; os filhos são ignorados.
- Um `:::callout` aninhado dentro de outro boxe é um boxe próprio: é composto com o próprio estilo (fundo, contorno, raio, margem interna, faixa, título, ícone, marcador, aba, tipografia) na largura interna total do pai e se empilha como um filho dele, com o `marginTop` / `marginBottom` se fundindo com os vizinhos. O `span` e o `placement` dele (do delimitador ou do estilo) são ignorados (um boxe aninhado sempre flui dentro do pai), assim como `floatBarrier` e `snapToGrid`. Os boxes se aninham em qualquer profundidade e podem ficar dentro de um grupo `:::columns` (cada um inteiro, em uma coluna). Quando o pai se divide, o corte cai antes ou depois de um boxe aninhado, ou dentro dele quando o estilo aninhado permite a divisão; cada fragmento redesenha as molduras que atravessa, e um boxe aninhado que continua do fragmento anterior perde o título e o ícone, como uma continuação de primeiro nível.
- Um grupo `:::columns{count=N}` … `:::` entre os filhos compõe esses filhos em `N` colunas de mesma largura, separadas por `columnGap`, dentro do boxe: a sequência é cortada nos limites de bloco ou de linha que melhor nivelam as colunas (um parágrafo ou item de lista cortado no meio continua no alto da coluna seguinte sem o marcador), cada coluna começa no alto do grupo e o grupo tem a altura da coluna mais alta; os filhos depois dele voltam à largura total. Um boxe que se divide (`keepTogether: false`, ou mais alto que uma coluna) também corta dentro de um grupo, entre as colunas dele: um grupo em serpentina (`snake`) preenche as colunas uma após a outra e continua no fragmento seguinte, e um paralelo (`breaks`) continua fluxo por fluxo (desde o postext 1.25; veja [Formato do documento › `:::columns`](/pt/docs/document-format-directives#columns)). Um `gap` no delimitador substitui `columnGap` para esse grupo, e `rule` traça um fio ao longo de cada medianiz. Use-o para um resumo de pontos-chave em duas colunas, ou para as tabelas de um boxe largo postas lado a lado.
- O sexto atributo do delimitador, `label`, é impresso na aba de rótulo do estilo (veja `label` acima): `:::callout{type="box" label="BOX 1-1" title="The octet rule"}`; sem um estilo `label`, o atributo é ignorado.

No VDT, o boxe é um bloco de moldura `type: 'callout'` cuja decoração (fundo, faixa, ícone, título) fica em `designOverlay`, seguido dos blocos filhos na mesma coluna; a moldura e cada filho levam o `containerId` do delimitador. Um boxe aninhado é uma moldura `type: 'callout'` própria entre os filhos, seguida dos blocos dele; eles mantêm o `containerId` do delimitador de primeiro nível (a colocação e o equilíbrio continuam vendo uma só unidade) e acrescentam `calloutPath`, os ids de contêiner dos delimitadores aninhados em volta deles, do mais externo para o mais interno (o id da própria moldura aninhada é a última entrada). O PDF marcado dá a cada boxe aninhado um `Div` dentro daquele do pai. As imagens de ícone são resolvidas como as imagens de recursos: o registro de imagens do canvas, a opção `resourceImageUrl` do HTML e o provedor `resourceBytes` do PDF.

```ts
const resolved = resolveCalloutStylesConfig(config.calloutStyles, resolvedBodyText, resolvedHeadings, resolvedUnorderedLists, config.locale);
// => todo campo herdado é preenchido a partir das seções resolvidas; o locale
//    opcional escolhe o idioma das strings de continuação

const minimal  = stripCalloutStylesDefaults(config.calloutStyles);
// => undefined para o padrão `note` embutido; os padrões estáticos são removidos
```

### Tipografia dentro de um boxe

Um boxe compõe o conteúdo com a própria tipografia `body` e `lists`; todo o resto mantém os estilos do documento:

- **Parágrafos** recebem o `body` do boxe: fonte, tamanho, entrelinha, cor, cores de ênfase, pesos, `italic`, `smallCaps`, alinhamento, hifenização, recuo e espaçamento entre parágrafos. Um campo não definido herda `bodyText`. Uma cor de ênfase herdada mantém o vínculo com a paleta, de modo que o negrito, o itálico e os rótulos de `:ref` em um boxe mudam com `colorPalette` como mudam fora dele. (Até o postext 1.4, o negrito em um boxe ficava `#295AA3` qualquer que fosse a cor principal.)
- **Listas com marcadores** recebem o `lists` do boxe (caractere do marcador, cor, tamanho, peso e fonte do glifo, recuo, espaço, espaçamento entre itens, margens) por cima de `unorderedLists`, e o texto delas é o texto do corpo do boxe. Um `lists.bulletChar` ou `lists.color` diferente do documento (`unorderedLists`) substitui o marcador ou a cor de todos os níveis; um que o repita, ou que fique sem definir, deixa a cada nível o seu (`unorderedLists.levels`), de modo que os travessões aninhados se mantêm no boxe.
- **Listas numeradas** recebem `lists.indent`, `gap` e `itemSpacing`, e `lists.color` sempre que o estilo a define, inclusive quando é a cor dos marcadores do documento; um estilo que a deixa sem definir mantém os números em `orderedLists.color`. (Até o postext 1.4, a cor só chegava aos números quando era diferente de `unorderedLists.color`, de modo que defini-la com essa mesma cor não fazia nada.) O número em si (fonte, corpo e separador) vem do `orderedLists` global, já que `lists` só tem campos de marcador: estilize ali os números de um boxe.
- **`:::paragraphs` dentro de um boxe** usam o próprio estilo de parágrafo, também em boxes aninhados. Os campos que o estilo deixa sem definir herdam o `bodyText` do documento, não o `body` do boxe (nem o itálico ou os versaletes dele).
- **Grupos `:::columns`** não têm estilo próprio: todas as colunas compartilham a tipografia de corpo e de listas do boxe, e `columnGap` define o espaço entre elas.
- **Citações** recebem a fonte, o tamanho e os pesos do corpo do boxe (em itálico e cinza, como no texto corrido), e os versaletes dele. **Títulos** mantêm os estilos de título; **fórmulas em destaque**, as configurações de matemática.
- **Figuras e tabelas** mantêm os estilos de legenda e de tabela do documento, na largura interna do boxe; os pesos regular e negrito delas seguem os pesos do `body` do boxe.
- **Chips** mantêm o estilo de chip; um tamanho em `em` é medido sobre o tamanho do corpo do boxe.
- **`:::space`** é medido em linhas do corpo do boxe (veja [`:::space`](/pt/docs/document-format-directives#space) para saber onde ele é descartado).
- **Um boxe aninhado** recebe o próprio estilo por inteiro; o `span`, o `placement`, o `floatBarrier` e o `snapToGrid` dele são ignorados.

**Notas com recuo deslocado.** As notas sob uma tabela, uma legenda numerada ou uma lista de fontes deixam a marca pendurada à frente do texto: a marca na borda interna do boxe, e o texto e todas as linhas seguintes um pouco mais para dentro. `body.hangingIndent` (desde o postext 1.71) faz isso em todos os parágrafos de um boxe ou de um bloco de modelo com esse estilo:

- **Um comprimento** coloca todas as linhas menos a primeira a essa distância da borda interna do boxe, como o `hangingIndent` de um estilo de parágrafo (veja [Estilos de parágrafo](/pt/docs/configuration-styles#estilos-de-parágrafo)). A primeira linha começa na borda, ou em `body.firstLineIndent` quando o próprio estilo o define; um recuo de primeira linha herdado de `bodyText` deixa de valer.
- **`true`** lê `body.firstLineIndent` como o recuo de todas as linhas menos a primeira, como `bodyText.hangingIndent` faz no texto corrido; `false` compõe o boxe sem recuo deslocado num livro cujo corpo do texto o usa. Sem valor, o boxe segue `bodyText.hangingIndent`.

Uma parada de tabulação na mesma posição leva o texto depois da marca até a borda das linhas seguintes, qualquer que seja a largura da marca:

```ts
calloutStyles: [{
  id: 'notes',
  padding: { top: { value: 0, unit: 'mm' }, right: { value: 0, unit: 'mm' }, bottom: { value: 0, unit: 'mm' }, left: { value: 0, unit: 'mm' } },
  body: {
    fontSize: { value: 7, unit: 'pt' },
    hangingIndent: { value: 4.5, unit: 'mm' },
    tabStops: [{ position: { value: 4.5, unit: 'mm' } }],
  },
}],
```

```markdown
:::callout{type="notes"}
\*	Os preços incluem a entrega dentro da cidade.

\*\*	Os sócios pagam metade; o desconto não se soma a outras ofertas e vale até o fim da temporada.
:::
```

Cada nota é um parágrafo próprio; entre a marca e o texto vai um caractere de tabulação ou `:tab`. O asterisco vai escapado, porque `*` seguido de uma tabulação no início de uma linha abre um item de lista. As linhas são medidas assim, de modo que o canvas, o PDF, a lista de exibição e o EPUB (com `padding-inline-start` e um `text-indent` negativo) as compõem igual, e uma exportação para o Word escreve o mesmo recuo. Os itens de lista mantêm o próprio recuo (`lists.indent`, `lists.gap`), e um parágrafo num contêiner `:::paragraphs`, o do seu estilo. Um `firstLineIndent` negativo continua contando como `0`: a primeira linha não pode começar dentro do espaçamento interno do boxe. Uma citação dentro de um boxe acompanha o recuo deslocado do boxe quando `hangingIndent` é `true`; com um comprimento, só os parágrafos do próprio boxe recebem o recuo.

### Marcas em um boxe dividido

Quando um boxe se divide entre colunas ou páginas (`keepTogether: false`, ou um boxe mais alto que uma coluna), cada parte depois da primeira começa sem o título e sem o ícone e, por padrão, nada avisa o leitor de que o boxe continua. Duas opções acrescentam as marcas que um livro ou um roteiro usa:

- **`repeatTitle: true`** repete o título no alto de cada continuação, seguido de `continuedSuffix` (“Pontos-chave (cont.)” por padrão). A repetição usa o estilo do título, de modo que, com `textTransform: 'uppercase'`, ela dá o “HAMLET (CONT'D)” de um roteiro. O ícone e a aba de rótulo ficam na primeira parte.
- **`continuesMarkerEnabled: true`** põe `continuesMarker` (“Continued”, ou “Continúa” em um documento em espanhol) sob a última linha de cada parte que continua, dentro do boxe, na fonte e no tamanho do corpo do boxe: em itálico a menos que `continuesMarkerItalic` seja `false`, alinhado à direita a menos que `continuesMarkerAlign` diga `'left'` ou `'center'`. A marca ocupa espaço na parte que fecha, e o corte é escolhido de modo que ela caiba.

```ts
calloutStyles: [{
  id: 'speech',
  keepTogether: false,
  titleStyle: { textTransform: 'uppercase' },
  repeatTitle: true,
  continuedSuffix: "(CONT'D)",
  continuesMarkerEnabled: true,
  continuesMarker: '(MORE)',
  continuesMarkerAlign: 'center',
  continuesMarkerItalic: false,
}],
```

```md
:::callout{type="speech" title="Hamlet"}
A speech long enough to run over the foot of the page…
:::
```

A parte que fecha a página termina com “(MORE)”, e a página seguinte começa com “HAMLET (CONT'D)”. As duas são elementos de paginação: em um PDF acessível são artefatos e no HTML ficam ocultas para as tecnologias assistivas, de modo que o título é lido uma só vez. No VDT são blocos de texto de `designOverlay` marcados com `artifact: true`.

### Designs de boxe

`design` dispõe os elementos do design de um título (textos, imagens, fios, caixas; veja [Largura e design avançado](/pt/docs/configuration-headings#largura-e-design-avançado)) numa faixa sob o título do boxe, em toda a sua largura interna. O conteúdo do boxe vem depois da faixa, com o espaço do título entre os dois. Um boxe dividido entre colunas ou páginas desenha a faixa só na primeira parte. Desde o postext 1.45.

Os textos do design leem estes marcadores:

- `{titleText}`: o título que o boxe imprime, o `title` do delimitador ou, na falta dele, o do estilo.
- `{boxText}`: o conteúdo do boxe como texto simples, um parágrafo ou item de lista por linha. Os vazios ficam de fora.
- `{boxText.<n>}`: o parágrafo ou item de lista de número `n`, contado a partir de 1; vazio quando o boxe tem menos.
- `{attr.<key>}`: um atributo escrito no delimitador. Qualquer nome serve, além dos que o próprio delimitador lê: `:::callout{type="card" kicker="Nota"}` dá a `{attr.kicker}` o valor `Nota`. Um atributo ausente não imprime nada.
- os marcadores do documento `{title}`, `{subtitle}`, `{author}` e `{publishDate}`.

O `resourceId` de uma imagem aceita os mesmos marcadores, de modo que cada boxe pode desenhar um recurso próprio. Só o design de um boxe lê `{boxText}`; o design de um título não imprime nada no lugar dele.

Com `setsContent: true` um único estilo serve a todos os boxes da mesma forma, cada um com as suas palavras. Num caderno de caligrafia cada linha de exercício é um boxe cujo conteúdo é a palavra a copiar: o design imprime a palavra numa letra escolar e depois a repete em pontos para cobrir (`dotted`), quantas vezes couberem na linha (`repeat`; veja [Marcas em linha e contornos](/pt/docs/configuration-headers-footers#marcas-em-linha-e-contornos)).

```ts
calloutStyles: [{
  id: 'practice',
  backgroundEnabled: false,
  border: { enabled: true, color: { hex: '#9aa6b2', model: 'hex' }, width: { value: 0.5, unit: 'pt' } },
  design: {
    setsContent: true,
    minHeight: { value: 16, unit: 'mm' },
    slot: { elements: [
      { kind: 'text', id: 'model', content: '{boxText}', fontFamily: 'Playwrite BR', fontSize: { value: 26, unit: 'pt' },
        placement: { anchor: { to: 'container', edge: 'top-left' } } },
      { kind: 'text', id: 'copies', content: '{boxText}', fontFamily: 'Playwrite BR', fontWeight: 100, fontSize: { value: 26, unit: 'pt' },
        dotted: {}, repeat: { gap: { value: 8, unit: 'mm' } },
        placement: { anchor: { to: '#model', edge: 'right-of' }, offset: { x: { value: 8, unit: 'mm' } } } },
    ] },
  },
}],
```

```md
:::callout{type="practice"}
gato
:::

:::callout{type="practice"}
lua
:::
```

A primeira linha imprime *gato* seguido de uma fileira de cópias pontilhadas de *gato*, a segunda faz o mesmo com *lua*, e nenhuma das duas palavras é composta de novo sob a sua faixa. Mudar a palavra no Markdown muda o modelo e todas as cópias. Com `setsContent` em `false` o design lê `{boxText}` do mesmo jeito, e o conteúdo é composto sob a faixa.

No VDT os elementos da faixa são blocos de design no `designOverlay` do quadro, ao lado do título.
