# Configuration : polices, couleurs et sortie


## Unités et couleurs

### Dimensions

Toutes les mesures physiques de Postext utilisent le type `Dimension`, une valeur associée à une unité :

```ts
interface Dimension {
  value: number;
  unit: DimensionUnit; // 'cm' | 'mm' | 'in' | 'pt' | 'px' | 'em' | 'rem'
}
```

**Unités absolues** (`cm`, `mm`, `in`, `pt`, `px`) : elles sont converties en pixels selon la résolution (DPI) configurée. À 300 DPI, `1 cm` vaut environ 118 px.

**Unités relatives** (`em`, `rem`) : elles suivent le corps courant. Un `em` est relatif au corps de l’élément lui-même ; un `rem` est relatif au corps du texte courant.

### Couleurs

Les couleurs sont stockées avec une représentation hexadécimale et un modèle colorimétrique cible :

```ts
interface ColorValue {
  hex: string;         // '#ff0000', 'transparent', etc.
  model: ColorModel;   // 'hex' | 'rgb' | 'cmyk' | 'hsl'
  cmyk?: CmykPercent;  // The exact process values of a colour authored in CMYK.
  paletteId?: string;  // L’entrée de colorPalette qu’elle suit.
}
```

Le champ `model` indique l’espace colorimétrique visé. Pour le rendu web, `'hex'` ou `'rgb'` sont les valeurs habituelles. Pour les flux d’impression, `'cmyk'` indique que la couleur a été définie en CMJN, et `cmyk` conserve ses valeurs : un rendu d’impression en CMJN les applique telles quelles, `hex` servant de rendu à l’écran (voir [Couleurs définies en CMJN](#couleurs-définies-en-cmjn)).

Comme Postext vise une sortie de qualité éditoriale, la couleur par défaut du texte courant est livrée avec `model: 'cmyk'` (`#000000`). Les couleurs des titres, du gras, de l’italique et des listes renvoient par défaut à la **Main Color** de la palette (`#295AA3`, `model: 'hex'`). Le fond de page et les calques d’interface (grille de ligne de base, traits de coupe, indicateurs de débogage) utilisent par défaut `model: 'hex'`. Remplacez `color.model` sur n’importe quel champ si vous avez besoin d’une autre sémantique à l’export.

### Transparence

Une couleur peut être translucide. `hex` accepte un canal alpha, sous la forme `#rgba` ou `#rrggbbaa`. Il accepte aussi une couleur `rgb()` / `rgba()`, en syntaxe à virgules ou à espaces, avec l’alpha en nombre ou en pourcentage. `transparent` est entièrement transparent :

```ts
const config: PostextConfig = {
  header: {
    elements: [{
      kind: 'box',
      id: 'veil',
      placement: {
        anchor: { to: 'bleed', edge: 'top-left' },
        size: { width: 'fill', height: { value: 40, unit: 'mm' } },
      },
      style: { backgroundColor: { hex: '#ffffffb3', model: 'hex' } }, // white at 70 %
    }],
  },
  bodyText: { color: { hex: 'rgba(0, 0, 0, 0.85)', model: 'rgb' } },
};
```

Les trois moteurs de rendu la peignent de la même façon. Le canvas et la visionneuse HTML prennent la valeur comme une couleur CSS. Le moteur PDF applique l’opacité de la couleur comme un alpha constant, un `ExtGState` avec `ca` pour les remplissages et `CA` pour les contours. Cela couvre le texte, les filets, les boîtes, les fonds et bordures de tableau, les pastilles, les pastilles de couleur et les formules. Une couleur translucide se compose par-dessus tout ce qui a été peint avant elle. Une boîte de l’en-tête ou du pied de page est peinte en dernier, elle voile donc le texte situé dessous ; une boîte dans un bandeau d’ouverture est peinte en premier, elle teinte donc la page sous le texte. Quand le PDF est forcé dans un autre espace colorimétrique (`pdfGeneration.forceColorSpace` avec `colorSpace: 'cmyk'` ou `'grayscale'`), la couleur est convertie et son alpha conservé. Dans le Sandbox, le curseur d’opacité du sélecteur de couleur écrit ces valeurs sous la forme `#rrggbbaa`, et le sélecteur lit aussi les autres formes.


## Polices personnalisées

Postext résout chaque chaîne `fontFamily` à la fois dans le catalogue Google Fonts **et** dans la liste `customFonts` du document. En cas de nom identique, les polices personnalisées l’emportent : si vous déclarez `customFonts: [{ name: 'Roboto', … }]`, Postext utilise le fichier que vous avez importé au lieu de la « Roboto » de Google Fonts. Le Sandbox prend chez Fontsource les familles que Google Fonts n’a pas. Il n’interroge jamais Fontsource pour un nom générique (`serif`, `system-ui`) ni pour une police fournie avec un système d’exploitation (Arial, Segoe UI, PingFang SC…) : une telle famille est composée avec ce qu’a l’ordinateur du lecteur, le panneau **Polices** l’affiche comme *Introuvable*, et le PDF et les images SVG n’en ont aucun fichier à intégrer. Si le livre est composé dans cette police, importez-la comme police personnalisée.

Utilisez des polices personnalisées quand :

- le document a besoin d’un caractère de marque ou sous licence absent de Google Fonts ;
- l’environnement ne peut pas joindre les CDN de polices, jsDelivr (d’où le Sandbox tire les fichiers de Fontsource) ou Google Fonts (hors ligne, intranet, contraintes de confidentialité) ;
- vous devez garder le fichier de police privé et ne pas l’envoyer à un tiers.

### Schéma de configuration

```ts
type CustomFontFormat = 'woff2' | 'woff' | 'ttf' | 'otf';
type CustomFontStyle = 'normal' | 'italic';

interface CustomFontVariant {
  weight: number;           // CSS font-weight, 100..900
  style: CustomFontStyle;
  fileId: string;           // opaque id of the binary in out-of-band storage
  format: CustomFontFormat;
  fileName?: string;        // original upload filename (optional, shown in UI)
}

interface CustomFontFamily {
  name: string;             // used anywhere a Google Font family name fits
  variants: CustomFontVariant[];
  redistributable?: boolean; // false : sert ici, n’est jamais copiée hors du livre
  fallback?: string;        // famille libre de chasse proche pour les faces sans fichier (depuis postext 1.42)
}

interface PostextConfig {
  // ...
  customFonts?: CustomFontFamily[];
}
```

Le fichier binaire de chaque variante n’est **pas** intégré à la configuration. Celle-ci ne contient que des pointeurs `fileId` ; les octets sont stockés à part. Dans le Sandbox, cela veut dire IndexedDB (stockage clé-valeur, propre au navigateur, privé au document). Un intégrateur qui embarque Postext dans un autre hôte est libre de résoudre `fileId` comme il l’entend (point d’accès serveur, cache de service worker, n’importe quoi d’autre), pourvu que les octets atteignent le thread principal avant l’exécution de `buildDocument`.

### Gérer les polices personnalisées dans le Sandbox

Ouvrez le panneau **Polices** depuis la barre d’activité de gauche (entre Ressources et Design). Sa liste **Caractères de ce livre** montre chaque famille utilisée par la maquette, avec son rôle et sa provenance : Google Fonts, Fontsource (pour une famille absente de Google Fonts), votre fichier, ou nulle part (*Introuvable*). Sous **Vos fichiers de police**, pour chaque famille :

1. **Ajouter une famille** : crée une famille vide ; renommez-la sur place.
2. **Importer des variantes** : choisissez une graisse (100–900) et un style (normal / italique), puis sélectionnez un *ou plusieurs* fichiers `.woff2`, `.woff`, `.ttf` ou `.otf`. Chaque fichier devient une variante liée au couple (graisse, style) sélectionné ; le nom du fichier importé est mémorisé et affiché sur la ligne pour que vous puissiez distinguer les variantes. Vous pouvez ajuster à tout moment la graisse ou le style d’une variante depuis ses listes déroulantes.
3. **Les variantes en double sont permises.** Si deux fichiers occupent le même emplacement (graisse, style), les deux sont conservés et un avertissement **Variante de police en double** apparaît pour que vous corrigiez les réglages des fichiers en trop.
4. **Supprimer la variante** ou **Supprimer la famille** : retire l’entrée de la configuration *et* les octets stockés dans IndexedDB.

Une fois une famille déclarée, chaque sélecteur de police la range sous **Personnalisées**, au-dessus de la liste Google Fonts. La choisir l’applique à chaque champ de famille de police où vous la sélectionnez.

### Une famille de remplacement pour une famille sous licence

Un livre peut être composé dans un caractère que son propriétaire n’a pas le droit de transmettre. Marquez la famille `redistributable: false` et un fichier `.postext` laisse ses fichiers de côté. Indiquez dans `fallback` une famille libre de chasse proche : le fichier qui s’ouvre sans eux coupe ses lignes près de l’endroit où les coupe le vrai caractère, au lieu de déborder de ses blocs dans une police de secours plus large. Les faces dont la famille n’a aucun fichier sont composées dans les styles du `fallback` de même graisse et de même inclinaison, sous le nom de la famille sous licence, dans les aperçus, le worker de mise en page, le PDF et la ligne de commande. Une famille qui a des fichiers les garde ; elle ne prend au `fallback` que l’inclinaison dont elle n’a aucun fichier, un italique par exemple, et les graisses intermédiaires entre ses propres fichiers sont choisies comme pour toute famille. Dans le panneau Polices, **Famille de remplacement** (dans la famille, au-dessus de ses fichiers) reçoit le nom ; vide, la famille reste comme avant. Le PDF d’un livre composé ainsi embarque la face libre : le PDF final se fait donc avec les fichiers sous licence. Depuis postext 1.42. Depuis postext 1.43, la famille libre va aussi là où la famille sous licence ne peut pas aller : un EPUB ou un export HTML, depuis le Sandbox ou depuis `postext`, embarque les fontes de la famille de remplacement sous le nom de la famille sous licence, tout comme les images SVG dont le texte est composé dans cette famille ; le système de lecture compose ainsi le livre dans une fonte de la chasse pour laquelle ses lignes ont été coupées. Les fichiers propres de la famille ne quittent jamais le livre. Une famille sans `fallback`, ou dont le remplacement n’a pas de fichier, est déclarée sans fichiers, comme avant ; l’onglet EPUB du Sandbox liste les familles composées dans une famille de remplacement.

### Comportement au rendu

En coulisse :

- Quand `customFonts` change, chaque famille déclarée est automatiquement enregistrée sous forme d’entrées `FontFace` dans `document.fonts` ; la visionneuse HTML, la vue Canvas (qui mesure via `document.fonts`) et toute référence CSS directe utilisent ainsi le caractère personnalisé sans que l’utilisateur doive d’abord ouvrir le sélecteur de police.
- Le worker de mise en page reçoit les mêmes ArrayBuffers par le chemin existant de transfert des polices, de sorte que la mesure (`buildFontString`, pretext) fonctionne comme pour une famille du catalogue.
- Modifier ou supprimer une variante vide le cache du worker pour cette famille et la réenregistre à la composition suivante, ce qui garde les aperçus synchronisés avec le jeu de variantes courant.
- **Export PDF** : les fichiers importés passent par le même pipeline `PdfFontProvider`. Les fichiers `.woff2` sont décompressés ; les `.ttf` et `.otf` sont transmis tels quels. Le `.woff` est refusé avec une erreur explicite (pdf-lib ne sait pas intégrer du WOFF brut : réimportez en `.woff2`/`.ttf`/`.otf`). L’OpenType à contours CFF (`.otf` avec la signature `OTTO`) est intégré **sans sous-ensemble**, car le découpage CFF de pdf-lib parcourt chaque glyphe au moment de `save()` et peut bloquer plusieurs minutes sur de vraies polices ; renoncer au sous-ensemble produit un PDF un peu plus lourd en échange de temps de rendu réguliers.

### Avertissements de police manquante

Le panneau **Vérifications** du Sandbox signale trois défaillances propres aux polices personnalisées dans son groupe *Polices* (toutes activées par le même interrupteur `debug.warnings.missingFont` qui commande déjà l’avertissement générique « non chargée ») :

- **Famille de police inconnue** : un `fontFamily` désigne un nom que ni Google Fonts ni Fontsource n’ont et qui n’est pas une famille personnalisée déclarée. Il se déclenche aussi immédiatement quand vous supprimez une famille personnalisée encore référencée par un champ `fontFamily`, sans attendre que le DOM s’en aperçoive.
- **Variante de police manquante** : la famille existe, mais le livre lui demande une graisse et un style sans fichier importé : des titres en gras, par exemple, dans une famille qui n’a que le romain. L’avertissement énumère les combinaisons manquantes. Une inclinaison fournie par le `fallback` de la famille ne compte pas comme manquante.
- **Variante de police en double** : deux fichiers importés ou plus partagent le même emplacement (graisse, style) dans une même famille. Un seul fichier sert réellement au rendu ; l’avertissement vous invite à réajuster les autres entrées.

Un clic sur l’un de ces avertissements ouvre le panneau Polices pour que vous importiez la variante manquante, ajoutiez de nouveau la famille ou départagiez les doublons.

Dès qu’une mise en page existe, le panneau liste aussi le **Remplacement de police dans la mise en page** (`fontFallback`) relevé par le moteur : un caractère sans lequel les pages ont été mesurées, soit absent, soit dessiné par le navigateur à partir d’une autre graisse ou d’une autre inclinaison. Une famille déjà signalée comme inconnue ou incomplète n’est pas listée deux fois. Avant la première mise en page, une vérification sur `document.fonts` en tient lieu.

Le panneau liste aussi les **Caractères pris dans une autre police** (`glyphFallback`) : des caractères que le texte compose dans une police qui n’a pas de glyphe pour eux, une fois par police, avec la famille générique qui les a dessinés (`serif`, `sans-serif`, `monospace`) quand la vérification peut le dire.

## Styles de chiffres

`figureStyle` demande à la police d’un style de texte un jeu de chiffres précis, par les fonctionnalités OpenType de la police : chiffres elzéviriens dans le texte courant, chiffres alignés tabulaires dans les tableaux. Le champ existe dans `bodyText`, `paragraphStyles[]`, `headings` et `headings.levels[]`, `headingStyles[]`, `tableStyle` et `tableStyles[]` (cellules d’en-tête et de corps de la même façon), `captionStyle` (étiquette et description, ainsi que le `captionStyle` d’un type de ressource) et les éléments de texte d’un design (titres courants, folios, textes d’une page d’ouverture ou d’une page de partie). Dans le Sandbox, c’est le champ **Chiffres** du panneau Maquette, à côté du caractère de chacun de ces styles (**Texte courant → Caractère** pour le corps du texte).

Une paire fixe une forme et une chasse. Une police sans la fonctionnalité garde ses propres chiffres : vérifiez que la police a `onum` ou `lnum` avant de compter dessus. Une famille dont l’hôte n’a aucun fichier, comme une police installée seulement sur le système du lecteur (le Sandbox ne les télécharge pas), ne prend aucun style de chiffres : son texte garde les chiffres de cette police, dans la police elle-même. Un livre qui téléverse des fichiers sous ce nom obtient les chiffres. Les coupes que servent Google Fonts et Fontsource laissent souvent `onum` et `lnum` de côté (le fichier latin de Source Serif 4 ne garde que `pnum` et `tnum`) ; avec un tel fichier, un style qui les demande garde les chiffres de la police. Les fichiers complets de la fonderie les ont : téléversez-les pour obtenir des chiffres elzéviriens ou alignés. Une famille générique (`serif`, `sans-serif`) ne prend aucune fonctionnalité. Une valeur hors de la liste est signalée comme valeur de réglage inconnue (`unknownConfigValue`, voir [Avertissements de configuration](#avertissements-de-configuration)) et lue comme non définie.

```ts
const config: PostextConfig = {
  bodyText: { fontFamily: 'EB Garamond', figureStyle: 'oldstyle' },
  tableStyle: { figureStyle: 'lining-tabular' },
  paragraphStyles: [{ id: 'timetable', figureStyle: 'lining-tabular' }],
  headings: { figureStyle: 'lining' },
};
```

Le texte compose ses années et ses numéros de page en chiffres elzéviriens, de même que les légendes et les listes, qui prennent la famille du corps du texte. Les cellules de tous les tableaux et les paragraphes du style `timetable` alignent leurs chiffres en chiffres alignés tabulaires. Tous les niveaux de titre composent des chiffres alignés dans la famille des titres.

### Quels chiffres prend un style

- Un style qui prend la famille d’un autre prend aussi ses chiffres. Les styles de paragraphe, les tableaux, les légendes, les listes et le contenu des encadrés prennent la famille du corps du texte quand ils n’en nomment pas d’autre : `bodyText.figureStyle` les atteint tous.
- Un style qui nomme sa propre `fontFamily` compose les chiffres par défaut de cette police, sauf s’il fixe aussi `figureStyle`.
- Un niveau de titre sans `figureStyle` propre prend `headings.figureStyle`, y compris dans sa propre `fontFamily` quand il en nomme une. Le `figureStyle` d’un style de titre s’applique à la famille du niveau sur lequel le style est employé.
- Un élément de texte d’un design nomme sa propre famille (`'EB Garamond'` par défaut) ; les chiffres du corps du texte n’atteignent donc pas un folio : donnez-lui `figureStyle: 'oldstyle'` pour l’accorder à un texte en chiffres elzéviriens.
- `'default'` compose les chiffres de la police et annule ceux qui sont hérités : `paragraphStyles: [{ id: 'plain', figureStyle: 'default' }]` retire à ce style les chiffres elzéviriens du corps du texte.

### Les chiffres dans chaque sortie

Le texte est mesuré avec les fonctionnalités : ses lignes se coupent aux mêmes largeurs dans l’aperçu Canvas, le HTML, le PDF et l’EPUB, en mise en page fixe comme recomposable.

- **Aperçu Canvas et worker de mise en page** : le navigateur déclare une seconde fois les fichiers de la famille de base sous un nom de famille à fonctionnalités, avec le descripteur `featureSettings` de `FontFace`. Le nom est la famille suivie de ses fonctionnalités après `@` (`EB Garamond@onum`, `EB Garamond@lnum+tnum`) ; il apparaît dans les chaînes de police et dans certains avertissements.
- **HTML et EPUB** (mise en page fixe et recomposable) : la famille de base, avec `font-variant-numeric` (`oldstyle-nums`, `lining-nums tabular-nums`).
- **PDF** : incorpore les fichiers de la famille de base et compose le texte avec les fonctionnalités.
- **Ligne de commande** : Skia, le canvas avec lequel dessine `postext`, n’applique aucune fonctionnalité. La ligne de commande enregistre une copie de la police dont la `cmap` envoie chaque caractère que les fonctionnalités remplacent, les chiffres, vers le glyphe qu’elles choisissent. Seules les substitutions simples sont prises ; une police qui atteint ses chiffres par des substitutions contextuelles y garde ses propres chiffres.

## Palette de couleurs

La propriété `colorPalette` de `PostextConfig` vous permet de définir un jeu réutilisable de couleurs nommées et d’y faire référence depuis n’importe quelle `ColorValue` de la configuration. C’est l’équivalent dans Postext des propriétés personnalisées CSS ou du panneau Nuancier d’InDesign : modifiez une fois l’entrée de la palette, et chaque couleur qui y renvoie se met à jour dans tout le document.

```ts
interface ColorPaletteEntry {
  id: string;       // stable identifier — referenced by ColorValue.paletteId
  name: string;     // human label shown in sandbox UIs
  value: ColorValue;
}
```

### La palette par défaut

Postext est livré avec une palette par défaut d’une seule entrée appelée **Main Color** (`id: 'main-color'`, hex `#295AA3`). Plusieurs valeurs par défaut (couleur des titres, couleur du gras et de l’italique du texte courant, couleur de `:ref`, couleurs des puces et des numéros de liste) renvoient à cette entrée via `paletteId: 'main-color'` ; modifier cette seule pastille de couleur reteinte donc toutes les parties du document qui l’utilisent.

Trois exports permettent d’examiner la palette par défaut, de la cloner ou de s’y comparer :

```ts
import {
  DEFAULT_COLOR_PALETTE,
  cloneDefaultColorPalette,
  isDefaultColorPalette,
} from 'postext';

// Read-only snapshot of the shipped palette.
DEFAULT_COLOR_PALETTE;
// => [{ id: 'main-color', name: 'Main Color', value: { hex: '#295AA3', model: 'hex' } }]

// Independent copy — mutate this, not DEFAULT_COLOR_PALETTE.
const palette = cloneDefaultColorPalette();

// Detect whether a user has customised the palette at all.
isDefaultColorPalette(palette); // true
```

Une palette se place au premier niveau de la configuration :

```ts
const config: PostextConfig = {
  colorPalette: [
    { id: 'ink',    name: 'Ink',    value: { hex: '#0a0a0a', model: 'cmyk' } },
    { id: 'accent', name: 'Accent', value: { hex: '#b8860b', model: 'hex' } },
  ],
  bodyText: { color: { hex: '#000000', model: 'cmyk', paletteId: 'ink' } },
  headings: { color: { hex: '#000000', model: 'hex', paletteId: 'accent' } },
};
```

### Faire référence à une entrée de la palette

Toute `ColorValue` de la configuration peut avoir un champ facultatif `paletteId` qui pointe vers une entrée de `colorPalette` : fond de page, couleurs du texte courant (y compris la couleur de `:ref`), couleurs des titres, filets de colonne, couleurs des listes, couleurs des tableaux, des légendes, des pastilles et des encadrés (boîte, bande, icône, marqueur, étiquette, titre, corps), couleurs des traits de coupe et de la grille de ligne de base, indicateurs de débogage, et chaque couleur d’une maquette : titres courants, ouvertures de titre et maquettes en colonne, maquettes et titres courants des styles de titre, pages de partie et lignes de partie de la table des matières (texte, filet, fond et bordure de boîte, contour, lettrine). Quand il est présent, le `hex` / `model` de l’entrée de palette l’emporte sur le `hex` / `model` de repli stocké à côté. Ce repli en ligne ne sert que si la palette est absente, vide ou ne contient pas cet identifiant : pratique pour livrer une configuration qui sera lue par un outil ignorant les palettes.

**Modifié dans postext 1.5.** Jusqu’à postext 1.4, la palette n’atteignait qu’une liste fixe de réglages : les couleurs des maquettes (titres courants, ouvertures, styles de titre, parties, lignes de la table des matières), `bodyText.referenceColor`, les couleurs des étiquettes d’encadré et les couleurs du gras et de l’italique dans le corps des encadrés gardaient le `hex` stocké à côté de leur `paletteId`. Un document dont la valeur stockée diffère de l’entrée de palette (tout document modifié dans le Sandbox après le changement de l’entrée, et chaque `:ref` quand la Main Color n’est pas `#295AA3`) imprime désormais la couleur de la palette, comme le lien l’indique. Pour garder une couleur telle qu’elle était, retirez son `paletteId`.

### Application des palettes

`buildDocument` applique la palette à deux endroits, pour que les couleurs référencées fonctionnent aussi bien pour les remplacements que vous avez écrits que pour les valeurs par défaut renseignées plus tard :

1. `applyPaletteToConfig(config)` : résout chaque `ColorValue` de la configuration utilisateur brute qui a un `paletteId`. Utile pour examiner ce que le moteur verra réellement.
2. `applyPaletteToResolvedConfig(resolved, palette)` : s’exécute *après* la résolution des valeurs par défaut et réécrit les valeurs par défaut liées à la palette (couleur des titres, couleur du gras et de l’italique du texte courant, couleur de `:ref`, couleurs des listes, couleurs des maquettes par défaut) pour qu’elles correspondent à la palette active.

Les deux parcourent toute la configuration : aucune couleur liée à la palette n’est donc oubliée. La plupart des couleurs du flux de texte (texte courant, titres, listes, tableaux, légendes, pastilles, boîte, titre et corps de l’encadré) en sortent comme de simples valeurs. Toutes les autres (couleurs des maquettes, couleur de `:ref`, étiquettes d’encadré) prennent le `hex` / `model` de la palette et **gardent leur `paletteId`**. C’est ce lien que l’attribut `palette` d’une partie et le `palette` d’un style de titre remplacent sur leurs pages (voir [Parties](/fr/docs/configuration-styles#parties)) ; il doit donc subsister. `htmlViewer.overrides` reste tel qu’il est écrit : la visionneuse HTML le fusionne en premier, et une palette qu’il contient s’applique alors à tout, maquettes comprises.

Vous aurez rarement besoin d’appeler ces fonctions vous-même, mais elles sont toutes deux exportées pour que vous puissiez les examiner ou les réutiliser :

```ts
import {
  applyPaletteToConfig,
  applyPaletteToResolvedConfig,
  resolveColorValue,
} from 'postext';

const flat = applyPaletteToConfig(config);
// Every ColorValue with a paletteId in the raw config now carries the
// palette entry's hex/model (a design colour keeps its paletteId).

// `applyPaletteToResolvedConfig` is typically handled by buildDocument; use it
// directly if you build a ResolvedConfig yourself and want the palette applied.
```

`resolveColorValue(value, palette, fallback)` est la variante pour une seule valeur, pratique quand vous composez des configurations par programme et devez résoudre une couleur à la fois.

### Modifier la palette

Une couleur dont le `paletteId` ne désigne aucune entrée imprime son `hex` / `model` stocké, qui peut être plus ancien que la couleur que lui donnait l’entrée. Avant de supprimer une entrée, réécrivez donc chaque `ColorValue` qui y est liée en couleur simple contenant la valeur actuelle de l’entrée. La section *Palette* du Sandbox (**Maquette → Couleurs**) le fait quand vous supprimez une entrée, où que se trouve la couleur (maquettes et étiquettes d’encadré comprises), et sa confirmation liste chaque réglage qui utilise l’entrée : par son nom, ou par son chemin dans la configuration (`header.elements[2].color`).

## Visionneuse Canvas

La propriété `canvasViewer` règle l’espace entre les pages dans l’onglet Canvas du Sandbox (depuis postext 1.43). ## Génération PDF (configuration)

La propriété `pdfGeneration` règle la façon dont le moteur PDF produit le document final. Ces réglages sont lus par le paquet `postext-pdf` au moment de l’export ; les visionneuses canvas et HTML les ignorent.

`buildDocument` les transporte dans le VDT, sous `doc.config.pdfGeneration`, et `renderToPdf` prend chaque réglage au premier endroit qui le fournit :

1. ses propres options (`outlines`, `accessible`, `colorSpace`) ;
2. le `pdfGeneration` du premier document qu’il rend (dans un livre, les réglages du premier chapitre s’appliquent à tout le fichier) ;
3. les valeurs par défaut : signets et balisage activés, couleur RVB.

Ainsi, `renderToPdf(doc, { fontProvider })` suit la configuration, et une option passée à `renderToPdf` l’emporte pour ce seul réglage. `forceColorSpace` et `colorSpace` réunis tiennent lieu de l’option `colorSpace` : le `colorSpace` de la configuration s’applique tant que `forceColorSpace` est activé, et le PDF est en RVB quand il est désactivé. Les versions précédentes de `postext-pdf` ne lisaient que les options ; une configuration qui définit `pdfGeneration` modifie désormais le PDF d’un appelant qui ne passe aucune option.

```ts
type PdfColorSpace = 'rgb' | 'cmyk' | 'grayscale';

interface PdfGenerationConfig {
  outlines?: boolean;          // Emit PDF bookmarks from the heading tree.
  forceColorSpace?: boolean;   // Convert every colour to `colorSpace`.
  colorSpace?: PdfColorSpace;  // Target space used when `forceColorSpace` is true.
  accessible?: boolean;        // Tagged, PDF/UA-oriented output (structure tree, alt text, language).
}
```

## Production pour l’impression (configuration)

La propriété `print` indique comment un livre part chez l’imprimeur : la norme PDF/X du fichier, le profil de sortie avec lequel son CMJN est séparé, la façon dont le noir s’imprime et les seuils du contrôle en amont (preflight). La mise en page l’ignore : la modifier ne déplace jamais une ligne. Trois éléments la lisent : `postext-pdf` quand il écrit le fichier, `preflightDocument` quand il contrôle un document mis en page, et l’aperçu d’impression des visionneuses canvas et Folio.

```ts
type PdfXStandard = 'none' | 'pdfx1a' | 'pdfx4';

  renderingIntent?: 'relative' | 'perceptual';
  blackPointCompensation?: boolean;
  convertImages?: boolean;                 // Separate RGB pictures (PDF/X-1a always does).
  inkLimit?: number;                       // Total area coverage, percent.
  black?: PrintBlackConfig;
  preflight?: PrintPreflightConfig;
}

interface CustomOutputProfile {
  name: string;           // Its description, or the file name.
  fileId: string;         // The stored .icc file.
  registryName?: string;  // The condition's ICC registry name (FOGRA51…), else 'Custom'.
  inkLimit?: number;
}
```

### PDF/X-1a et PDF/X-4

Les deux normes écrivent :

- l’output intent (`GTS_PDFX`) qui indique la condition d’impression et intègre le profil de destination ;
- l’identification dans le dictionnaire Info (`GTS_PDFXVersion`, `/Trapped /False`, le titre et les dates) et dans les métadonnées XMP (`pdfxid:GTSPDFXVersion`, les identifiants du document et de la version), fusionnée avec l’identification PDF/UA quand le fichier est balisé ;
- une TrimBox et une BleedBox sur chaque page (la page entière quand il n’y a pas de traits de coupe) ;
- l’`/ID` du trailer ;
- chaque couleur en DeviceCMYK (ou en gris) via le profil, et les traits de coupe en couleur de repérage ;
- aucune annotation de lien : un fichier destiné à la presse n’en contient aucune dans sa zone de fond perdu : les liens du PDF écran sont donc omis (les signets restent).

Le PDF/X-1a:2003 est du PDF 1.4 sans flux d’objets et sans transparence : une couleur translucide est appliquée telle qu’elle s’imprimerait sur le papier, l’alpha d’une image est aplati sur du blanc, et le négatif de page de débogage est omis (avec un avertissement `pageNegativeIgnored`). Le PDF/X-4 est du PDF 1.6 : la transparence reste, chaque page reçoit un groupe de transparence qui mélange en CMJN, et les images RVB conservées par `convertImages: false` sont étiquetées sRGB via `/DefaultRGB`.

Un fichier maître PDF pour l’impression (`svg.pdfFileId`) est intégré tel quel ; ses couleurs, ses polices et sa transparence sont donc les siennes ; le contrôle en amont signale ce qu’il apporte.

`preflightDocument(doc, options)` exécute les contrôles sur un document mis en page et renvoie une liste de problèmes, chacun avec un `kind`, une `severity` (`'critical'`, `'warning'` ou `'info'`), l’index de page `pageIndex` absolu dans le livre, le `rect` fautif (en px de page) et, quand l’élément en a une, sa position dans la source. Les types sont `lowImageResolution`, `declaredPixelsMismatch`, `rgbImage`, `thinRule`, `smallProcessText`, `inkLimit`, `safeZone` et `nearTrim`. Sans `transform`, un neutre compte pour une encre et toute autre couleur pour trois, et l’encrage n’est pas vérifié ; avec une transformation, les décomptes et l’encrage sont exacts. La résolution d’une image est calculée à partir des pixels que déclare sa ressource, ou de ceux du fichier lui-même quand `imageSize(fileId)` les fournit (`bitmapInfo` sur les octets, ou l’image décodée) : une déclaration qui s’écarte de plus d’un pixel du fichier est signalée une fois comme `declaredPixelsMismatch`, un avertissement quand elle annonce plus de pixels que le fichier n’en a. `placedImageResolutions(doc, { resources, imageSize })` liste chaque image matricielle placée avec sa résolution effective en ppi, que le contrôle en amont soit activé ou non. Les étiquettes d’une figure comptent comme du texte pour `smallProcessText`, `inkLimit` et `safeZone`.

```ts
import { bitmapInfo, outputTransform, parseIccProfile, preflightDocument, resolvePrintConfig } from 'postext';
import { inspectPrintMaster } from 'postext-pdf';

const print = resolvePrintConfig(config.print);
const transform = outputTransform(parseIccProfile(fogra51Bytes), { intent: print.renderingIntent });
const issues = preflightDocument(doc, {
  print,
  transform,
  resources,                                    // pixel sizes of the bitmaps
  imageSize: (fileId) => bitmapInfo(bytesOf(fileId)),  // the files' real pixels
  imageColor: (fileId) => colourOf(fileId),     // 'rgb' | 'cmyk' | 'gray', from the file
});
if (issues.some((i) => i.severity === 'critical')) process.exit(1);

const master = await inspectPrintMaster(masterBytes);
// => { nonEmbeddedFonts: ['Helvetica'], rgb: true, transparency: false }
```

### Aperçu d’impression

Une page canvas peut être peinte telle qu’elle s’imprimera. `createPrintPreview(transform, print, { paper, dpi, grayscale })` construit l’épreuve écran d’une configuration : chaque pixel est séparé via le profil (neutres en K seul, comme dans le PDF) et réaffiché à l’écran, sur le blanc propre du papier quand `paper` vaut true ; les zones noires assez grandes pour le noir enrichi apparaissent en noir enrichi. Avec `grayscale`, l’épreuve est une impression en niveaux de gris : un PDF forcé en niveaux de gris imprime la luminance de chaque couleur avec la seule encre noire, sans noir enrichi. Passez-la à `renderPageToCanvas` sous `printPreview`. Pour une vue de travail plutôt qu’une épreuve, `guides` ajoute les lignes de coupe, de fond perdu et de zone de sécurité, et `marksFor` entoure des zones d’une page (les `rect` du contrôle en amont) ; le Sandbox omet les deux, son aperçu ne montre donc que l’impression. `postext-folio` accepte le même objet sous `printPreview` ; avec `paper: true`, donnez entre-temps au livre une teinte de papier neutre (`folio.paper.shade`), sinon le papier est teinté deux fois.

```ts
import { createPrintPreview, renderPageToCanvas } from 'postext';

const preview = createPrintPreview(transform, print, { paper: true, dpi: doc.config.page.dpi });
renderPageToCanvas(page, doc, canvas, {
  printPreview: { ...preview, guides: { safeZonePx: 59 }, marksFor: () => issues.map((i) => i.rect!).filter(Boolean) },
});
```

### Moteur colorimétrique

La gestion des couleurs qu’utilise postext est exportée pour vos propres outils. Elle lit les profils ICC v2 et v4 (matrice/TRC et les tables de correspondance `mft1`, `mft2`, `mAB`, `mBA`) en TypeScript pur, sans WebAssembly.

- `parseIccProfile(bytes)` lit un profil ; `deviceChannels(profile)` donne son nombre de canaux.
- `outputTransform(profile, { intent, blackPointCompensation, preserveNeutrals })` renvoie `fromRgb(r, g, b)` (sRGB 0..1 → CMJN 0..1), `toLab(cmyk, paper?)` et `proof(cmyk, paper?)` (CMJN → sRGB écran).
- `cmykToLab`, `labToCmyk`, `srgbToLab`, `labToSrgb`, `deltaE` et `totalAreaCoverage` sont les conversions unitaires ; `buildRgbLut` / `sampleRgbLut` créent et lisent des tables de correspondance denses pour le travail au pixel.
- `OUTPUT_PROFILES`, `outputProfileInfo(id)` et `loadOutputProfile(id, baseUrl?)` donnent le catalogue ; `srgbProfileBytes()` écrit le profil sRGB avec lequel le PDF/X-4 étiquette le RVB ; `authoredCmykColors(config)` liste les couleurs qu’une configuration a définies en CMJN.

Le résolveur et la fonction de nettoyage correspondent à ceux des autres sections : `resolvePrintConfig`, `stripPrintDefaults` et `profileInkLimit(config)` (la limite du profil que désigne une configuration, avant tout remplacement par `inkLimit`), avec `DEFAULT_PRINT_CONFIG`, `DEFAULT_PRINT_BLACK_CONFIG`, `DEFAULT_PRINT_PREFLIGHT_CONFIG` et `DEFAULT_RICH_BLACK`.

### Paires acceptées

Un portage garde la palette de l’original, et certaines de ses paires passent sous le seuil : une teinte pâle derrière le texte d’un encadré, une couleur de marque dans un titre courant. `allow` les accepte sans couper la vérification (depuis postext 1.52). Une entrée nomme la couleur du texte `fg` et celle du fond `bg` (en hexadécimal, telles que la configuration les écrit ou telles qu’elles sont peintes), ou un `style` : l’id d’un style d’encadré (`calloutStyles`, ou le `style` d’un bloc de page composée), d’un style de paragraphe, de titre, de pastille ou d’étiquette de figure. Tous les champs que donne une entrée doivent correspondre : `{ style: 'note', fg: '#7a8a99' }` accepte ce gris dans les encadrés `note` seulement. Une entrée qui ne donne aucun des trois ne correspond à rien.

```ts
contrast: {
  allow: [
    { fg: '#b7820f', bg: '#ffffff', reason: "L'ocre de l'éditeur pour les titres courants" },
    { style: 'note-marge', reason: "L'original compose ses notes marginales en gris clair" },
  ],
}
```

Une paire acceptée reste signalée : chaque résultat qui lui correspond porte `accepted` (la `reason` de l’entrée, avec son `fg`, son `bg` et son `style`), et les résultats acceptés viennent après les autres. Le Sandbox les liste dans Vérifications, sous Paires de contraste acceptées, avec la raison, et ne les compte pas ; `postext check` les imprime comme des notes, qui ne font pas échouer `--strict`. Les mêmes couleurs hors de ce que l’entrée nomme restent un avertissement.

### Écran et impression

Postext compose les mêmes pages pour un écran et pour une presse, et une couleur ne se lit pas de la même façon sur les deux.

- **Écran** est le rapport de contraste WCAG 2 des couleurs sRGB, `(L1 + 0.05) / (L2 + 0.05)` sur leurs luminances relatives : ce que montrent le canvas, la visionneuse HTML, un EPUB et un PDF RVB.
- **Impression** est la même formule appliquée à la luminance de chaque couleur sur le papier. La couleur est séparée avec le profil de sortie du travail (une couleur définie en CMJN garde ses valeurs), la séparation est relue via le profil, et sa luminance est prise par rapport au papier nu, qui est le blanc d’une page imprimée comme le blanc de l’affichage est celui d’un écran. L’encre n’est jamais un noir parfait : un noir plein sur blanc atteint environ 14:1 sur papier couché (FOGRA39, FOGRA51), 8:1 sur papier non couché (FOGRA47, FOGRA52) et 5:1 sur papier journal (IFRA26, SNAP), là où un écran donne 21:1. Un gris qui passe à l’écran peut échouer sur le papier : `#767676` sur blanc donne 4,54:1 à l’écran et environ 3,3:1 sur papier couché.

Le rapport d’impression exige la transformation du profil de sortie (`options.transform`, construite avec `outputTransform`). Sans elle, seul le texte en défonce est contrôlé pour l’impression.

### Texte en défonce

Un texte clair réservé dans un fond encré se bouche à l’impression quand il est petit ou que ses traits sont fins : l’encre du fond s’étale dans les lettres, et un fond composé de plusieurs encres dépend aussi du bon repérage des plaques. Le rapport de contraste ne le montre pas, puisque du blanc sur bleu foncé dépasse 10:1. Le contrôle d’impression signale ce texte à part (`reversedText`) quand il est plus petit que `minSize`, ou plus petit que `minFineSize` s’il est en italique ou d’une graisse égale ou inférieure à `lightWeight`. Chaque résultat indique de combien des quatre encres le fond est composé.

### Ce qui est examiné

Le contrôle lit les lignes de chaque bloc avec leurs couleurs en ligne (gras, italique, renvois, pastilles), les marqueurs de liste, les lettrines, les légendes, les notes et les cellules de tableau, ainsi que le texte des zones de maquette : titres courants, ouvertures, maquettes de titre, titres de boîte. Le fond est le remplissage le plus haut sous le texte : une boîte de maquette, un encadré, une barre de légende, une cellule de tableau, une pastille, ou à défaut la couleur de la page (`page.backgroundColor`, ou le papier que la palette d’une partie donne à ses pages). Une couleur translucide est mélangée avec ce qui se trouve dessous. Le texte posé sur une image est ignoré, puisque son fond n’est pas d’une seule couleur, de même que le lettrage de bande dessinée, les lectures ruby et les formules. Les mots des étiquettes d’une figure sont lus sur leur fond, à défaut dans leur halo ; les étiquettes nues sur l’image sont ignorées, comme tout texte sur une image.

Sur une page composée, le contrôle suit l’ordre dans lequel la page est peinte : les blocs par calque, la `decoration` du gabarit au calque 0. Le texte d’un bloc se lit sur la boîte du bloc lui-même quand son style en peint une ; sinon sur la boîte du décor placée dessous (une image du décor l’écarte, comme toute image) ; sinon sur la couleur de la page. Des lettres blanches posées sur un onglet coloré du décor sont donc mesurées contre cet onglet. Un bloc tourné ou mis à l’échelle est ramené sur la feuille avant que son fond soit lu, et le texte du décor est contrôlé de la même façon. Depuis postext 1.37.

### Lancer le contrôle

`contrastDocument(doc, options)` renvoie les résultats d’un document mis en page, du rapport le plus faible au plus élevé. Chacun comporte l’index de page `pageIndex` absolu dans le livre, le `rect` sur la feuille (en px de page) et la position dans la source de sa première occurrence, les deux couleurs telles que peintes (`color`, `background`), la plus petite taille `sizePt` à laquelle il est composé avec son `weight` et son `italic`, un `role` (`'body'`, `'heading'`, `'caption'`, `'table'`, `'runningHead'`, `'design'`, `'chip'`, `'marker'` ou `'label'`, les mots des étiquettes d’une figure), le `text` du premier segment et le nombre `count` de segments composés ainsi. Une paire est signalée une fois par seuil, quel que soit le nombre de lignes qui l’utilisent.

- `lowContrast` ajoute `level`, `large`, `required`, le rapport dans chaque rendu contrôlé (`screen`, `print`) et `failing`, les rendus sous `required`.
- `reversedText` ajoute `reasons` (`'small'`, `'italic'`, `'light'`), `minimumPt` et `inks`.

Les options sont `contrast` (les réglages résolus, quand ce ne sont pas ceux du document), `media` (les rendus, quelle que soit la valeur de `mode`) et `transform`.

```ts
import { contrastDocument, outputTransform, parseIccProfile } from 'postext';

const transform = outputTransform(parseIccProfile(fogra51Bytes));
for (const issue of contrastDocument(doc, { transform })) {
  if (issue.kind === 'lowContrast') {
    console.log(`${issue.color} on ${issue.background}: ${issue.screen}:1, ${issue.level} asks for ${issue.required}:1`);
  }
}
```

`contrastPairs(doc, options)` renvoie chaque paire texte et fond que compose le document, conforme ou non, avec son rapport `screen`, son rapport `print` quand la transformation est fournie, le rapport `required` et les couleurs telles que la configuration les écrit (`textColor`, `groundColor`) : ce qu’un outil de conception affiche à côté d’un champ de couleur. Il s’exécute quelle que soit la valeur d’`enabled`.

Les mesures sont exportées pour vos propres outils :

- `contrastRatio(a, b)` et `relativeLuminance(color)` donnent le rapport WCAG 2 et la luminance de couleurs sRGB.
- `isLargeText(sizePt, weight)` et `contrastThreshold(level, large)` donnent le seuil d’une taille et d’une graisse.
- `blendColors(top, under)` donne une couleur translucide posée sur une autre, sous la forme `#rrggbb`.
- `printContrastRatio(a, b, context)`, `printLuminance(color, context)` et `printSeparation(color, context)` donnent les mêmes valeurs sur le papier. Le contexte contient la `transform` et, sous `authored`, le résultat de `authoredCmykColors(config)`.
- `contrastMedia(doc.config, contrast)` donne les rendus auxquels `mode` se résout pour un document.

Le résolveur et la fonction de nettoyage correspondent à ceux des autres sections : `resolveContrastConfig` et `stripContrastDefaults`, avec `DEFAULT_CONTRAST_CONFIG`, `DEFAULT_CONTRAST_REVERSED_TEXT_CONFIG`, `CONTRAST_LEVELS` et `CONTRAST_MODES`.


## Contrôle du contenu (configuration)

La propriété `checks` regroupe les contrôles qui lisent la configuration elle-même. Elle en compte un aujourd’hui, `contentInConfig`, qui avertit quand une maquette garde le texte du livre. Un titre courant, la maquette d’un titre, une page de partie et la ligne d’une partie dans la table des matières relèvent de la forme : ils contiennent des variables (`{chapterTitle}`, `{titleText}`, `{number}`) et au plus un ou deux mots à eux, comme *Chapitre* devant `{chapterNumber}`. Le texte qui fait partie du livre va dans le Markdown, où la table des matières, la recherche, les traductions, le PDF balisé et l’EPUB le voient. La mise en page ne le lit pas : le modifier ne déplace jamais une ligne.

interface ChecksConfig {
  contentInConfig?: {
    enabled?: boolean;
    allow?: string[];
    maxWords?: number;
    maxChars?: number;
  };
}

### Lecture d’un texte de maquette

- Son texte littéral est son `content` sans aucune variable (`{name}`, `{attr.key}`, `{firstMark.key}`), les échappements `{{` et `}}` lus comme des accolades et `\n` comme un retour à la ligne.
- Un texte sans lettre ni chiffre (une ligne de points de conduite, un ornement, un `·`) n’est jamais du contenu.
- Un mot est ce qui se trouve entre deux espaces et contient une lettre ou un chiffre : un `·` ou un `|` isolé n’est pas un mot, et une adresse comme `postext.dev` en est un.
- Les expressions de `allow` sont retirées d’abord, ainsi que le `title`, le `subtitle`, l’`author` et le `publisher` des métadonnées du document (son en-tête YAML), qu’un titre courant reprend souvent.
- Ce qui reste est du contenu s’il compte plus de `maxWords` mots ou plus de `maxChars` lettres et chiffres.

Toutes les zones de maquette sont lues : `header`, `footer`, l’`advancedDesign.slot` de chaque niveau de titre, l’`advancedDesign.slot`, le `header` et le `footer` de chaque style de titre, `parts.design`, `parts.versoDesign`, `toc.parts.design`, et les mêmes dans `htmlViewer.overrides`. `configDesignSlots(config)` les énumère avec leurs chemins, et `designTextLiteral(content)` renvoie le texte littéral d’un modèle.

### L’avertissement

`collectConfigWarnings` (et `VDTDocument.configWarnings`) donne un avertissement `contentInConfig` par réglage qui contient du contenu : un style de titre (son `id` dans `ownerId`), un niveau de titre, l’en-tête, la maquette des parties. `path` indique le réglage, `count` les textes de maquette en cause, `chars` leurs lettres et chiffres, `elements` le chemin de chacun (les 20 premiers) et `value` le début du premier (40 caractères au plus). Passez les métadonnées du document en second argument pour admettre son titre et son auteur ; une mise en page le fait d’elle-même.

```js
import { collectConfigWarnings } from 'postext';

collectConfigWarnings(config, { metadata: { title: 'A Year of Weather' } });
// [{ kind: 'contentInConfig', path: 'headingStyles[3]', ownerId: 'lesson-4',
//    value: 'Look at the picture and answer the questi…', used: '',
//    count: 30, chars: 1017, elements: ['headingStyles[3].header.elements[2]', …] }]
```

**Correction :** déplacez le texte dans le Markdown, sous forme de titre, d’encadré ou de paragraphe du chapitre auquel il appartient, et ne laissez que des variables dans la maquette. Une valeur qui change à chaque chapitre peut voyager sur la ligne du titre et se lire avec `{attr.key}` : `# Cartes {kicker="Leçon 4"}` et `{attr.kicker}` dans la maquette. Une expression qui relève de la forme, comme le nom de l’éditeur dans un titre courant, va dans `allow`.

Le Sandbox affiche l’avertissement dans le panneau **Vérifications** et propose le contrôle dans **Maquette → Avancé → Contenu dans la configuration** ; `postext check` l’imprime.


## Visionneuse Folio (configuration)

La propriété `folio` règle la façon dont la visionneuse Folio (`postext-folio`) présente le livre imprimé en 3D : l’angle de vue, le papier, la reliure, la surface sur laquelle repose le livre et la lumière. La mise en page l’ignore, tout comme les sorties canvas, HTML et PDF. `buildDocument` transporte les réglages résolus dans le VDT sous `doc.config.folio` quand la configuration en définit : un document qui n’en a pas garde donc son empreinte de mise en page.

Une page au format de journal (`page.sizePreset` `'broadsheet'`, `'berliner'`, `'tabloid'` ou `'compact'`) est présentée comme un journal quand la configuration ne fixe ni papier ni reliure : papier `newsprint` et reliure `folded` (depuis postext 1.18). Un papier ou une reliure que fixe la configuration est conservé : `paper: { type: 'uncoated' }` imprime ainsi un tabloïd sur papier offset. Les champs de papier définis sans sorte de papier (un `grammage`, un `shade`) s’appliquent au papier journal. Le résolveur et la fonction de nettoyage prennent le format en second argument, et `folioForTrim(folio, sizePreset)` écrit les deux valeurs par défaut dans la configuration :

```ts
resolveFolioConfig({ tilt: 30 }, 'tabloid');
// => { tilt: 30, paper: { type: 'newsprint', grammage: 48, bulk: 1.5, … }, binding: { type: 'folded', coverMaterial: 'paper', … }, … }

stripFolioDefaults({ paper: { type: 'newsprint' }, binding: { type: 'folded' } }, 'tabloid');
// => undefined
```

Les couleurs suivent les liens de palette comme n’importe quelle autre couleur de la configuration (`paletteId`). Le résolveur et la fonction de nettoyage correspondent à ceux des autres sections ; la fonction de nettoyage retire les valeurs de papier égales à celles du papier choisi :

```ts
import { FOLIO_PAPER_STOCKS, DEFAULT_FOLIO_CONFIG, resolveFolioConfig, stripFolioDefaults } from 'postext';

resolveFolioConfig({ paper: { type: 'bible' } }).paper;
// => { type: 'bible', grammage: 40, bulk: 1.1, finish: 'uncoated', texture: 'vellum', textureStrength: 1, shade: { hex: '#f9f6ee', … }, showThrough: true }

stripFolioDefaults({ paper: { type: 'bible', grammage: 40 } });
// => { paper: { type: 'bible' } }
```

Dans le Sandbox, ces réglages forment le groupe **Folio** du panneau Maquette (**Maquette → Folio → Visionneuse Folio (3D)**), et l’onglet Folio les montre au fil de vos modifications, sans relancer la mise en page du livre. Voir [Un livre en 3D](/fr/docs/configuration-html-folio-epub#un-livre-en-3d-postext-folio) pour la visionneuse elle-même, et [Format du document › `:::paper`](/fr/docs/document-format-directives#paper) pour une suite de pages sur un autre papier.

### Lignes lâches dans votre propre canvas

Le moteur exporte le surlignage des lignes lâches sous forme de deux fonctions, pour une page que vous peignez vous-même :

```ts
import { buildDocument, renderPageToCanvas, drawLooseLines, findLooseLines } from 'postext';

const doc = buildDocument(content, config);
const canvas = document.querySelector('canvas')!;
renderPageToCanvas(doc.pages[0], doc, canvas, { scale: 0.5 });
drawLooseLines(canvas.getContext('2d')!, doc.pages[0], doc, { threshold: 2.5 });

// The same lines as data: a report, an SVG overlay, a count per page.
for (const { ratio, line, block } of findLooseLines(doc, { threshold: 2.5 })) {
  console.log(`page ${block.pageIndex + 1}: ${ratio.toFixed(2)}× — ${line.text}`);
}
```

- **`findLooseLines(doc, { threshold?, pageIndex? })`** renvoie, dans l’ordre de lecture, chaque ligne justifiée dont l’espacement des mots dépasse `threshold` : `{ block, line, ratio, x, y, width, height }`. `ratio` vaut `lineWordSpacing(line)` : l’espacement tel que `minWordSpacing` et `maxWordSpacing` le bornent (`justifiedSpaceLimitRatio` quand la ligne contient des espaces d’un autre caractère, sinon `justifiedSpaceRatio`) : une ligne composée à la limite et contenant une espace en gras n’est donc pas signalée avec un seuil égal à `maxWordSpacing`. Le rectangle, en pixels de page, est la bande que couvre le surlignage : toute la largeur du bloc à hauteur de la ligne. Ce sont les lignes que le Sandbox surligne et signale comme `looseLine` dans son panneau Vérifications.
- **`drawLooseLines(ctx, page, doc, { threshold?, color? })`** remplit ces bandes pour une page et renvoie les lignes peintes. Elle dessine en pixels de page sous la transformation courante du contexte ; appelez-la donc juste après `renderPage` ou `renderPageToCanvas` sur le même canvas : les deux laissent le contexte mis à l’échelle de la page. `color` accepte n’importe quel style de remplissage canvas.
- **Valeurs par défaut.** Les deux fonctions utilisent le seuil (3) et la couleur (`#ff000040`) par défaut, et non le `debug.looseLineHighlight` du document : ce réglage appartient au Sandbox. Pour suivre une configuration, passez `resolveDebugConfig(config.debug).looseLineHighlight.threshold` et `.color.hex`.

### Avertissements de configuration

Ces erreurs de la configuration elle-même ne passent jamais sous silence, et aucun interrupteur ne les masque, sauf celui que mentionne le dernier point. Le moteur n’échoue sur aucune d’elles ; il substitue une valeur, ou ignore le réglage, et le signale :

- **Format de numérotation inconnu** : un `numberFormat` de liste numérotée, un `page.pageNumbering.format` ou le `counterFormat` d’un type de ressource qui ne correspond à aucune des [graphies de format de numérotation](/fr/docs/configuration-page-layout#graphies-des-formats-de-numérotation). La numérotation se fait en décimal.
- **Pile de polices dans une famille** : un `fontFamily` (ou n’importe quel `…FontFamily`) qui contient une pile de polices CSS. Le texte est composé dans la première famille de la pile (voir [Une seule famille par `fontFamily`](/fr/docs/configuration-text#une-seule-famille-par-fontfamily)).
- **Colonne latérale sans place** : un `sideColumnPercent` de mise en page `'oneAndHalf'` (celui du document, ou la `layout` propre d’un style de titre) qui laisserait l’une des colonnes sous 1 % de la largeur du contenu, ou qui n’est pas un nombre. Les colonnes sont découpées selon la valeur la plus proche que les deux acceptent, et `used` l’indique (`sideColumnPercentClamped` ; voir la [mise en page `'oneAndHalf'`](/fr/docs/configuration-page-layout#types-de-mise-en-page)).
- **Nombre de colonnes hors limites** : un `columnCount` de mise en page `'multiple'` (celui du document, ou la `layout` propre d’un style de titre) qui n’est pas un nombre entier de 3 à 8. La page est découpée selon le nombre valide le plus proche (3 pour une valeur qui n’est pas un nombre), et `used` l’indique (`columnCountClamped` ; voir la [mise en page `'multiple'`](/fr/docs/configuration-page-layout#types-de-mise-en-page)).
- **Grille de caractères trop grande** : un `cjk.grid` avec plus de caractères par ligne ou de lignes par page que les marges ne le permettent. La grille est réglée sur le maximum qui tient, et `used` indique ce nombre (`cjkGridClamped` ; voir [Grille de caractères](/fr/docs/configuration-east-asian#grille-de-caractères)).
- **Réglage de titre inconnu** : une clé que n’ont pas `headings`, `headings.balancing`, un niveau de titre, un style de titre ou un style de paragraphe : un `letterSpacng` mal orthographié, un `tracking` emprunté à un autre outil, un `level` sur un style de titre, un `fontStyle: 'italic'` sur un style de paragraphe (qui attend `italic: true`). Une tabulation est vérifiée de la même façon (un `leaders` au lieu de `leader`), de même qu’une lettrine, `lineNumbers`, `canvasViewer`, `checks`, `codeStyle` et les réglages de bande dessinée. Le moteur l’ignore (jusqu’à postext 1.4, il le faisait sans rien dire). `value` est la clé, `used` est vide, et `suggestion` propose le réglage le plus proche, quand il n’en diffère que d’une ou deux lettres ou seulement par la casse (`unknownConfigKey`).
- **Valeur de réglage inconnue** : un réglage qui accepte un mot parmi quelques-uns et qui en contient un autre, comme `direction: 'right'` (il accepte `auto`, `ltr` ou `rtl`). Le moteur lit la valeur par défaut à la place, et `used` indique ce qu’elle donne : pour `direction`, le sens de la langue du document (`unknownConfigValue`). Un `align` de tabulation qui n’est aucun de ses quatre mots est lu comme `'start'`, et une `position` qui n’est ni une longueur, ni `'end'`, ni un pourcentage fait ignorer la tabulation (`used` vaut `'none'`). Les mots des réglages de bande dessinée sont vérifiés aussi ([Bande dessinée › Avertissements de bande dessinée](/fr/docs/comics#avertissements-de-bande-dessinée)) : `used` est la valeur à laquelle le réglage s’est résolu (la valeur par défaut propre d’un style de bulle, pour un style intégré), et `suggestion` propose le mot le plus proche de la valeur, quand il y en a un. Le `level` et le `mode` du contrôle du contraste sont vérifiés de la même façon : `used` vaut `'AA'` ou `'auto'`. `canvasViewer.pageGap` et `canvasViewer.rowGap` sont vérifiés de la même façon : `used` est l’entier de 0 à 200 en lequel la valeur a été lue (depuis postext 1.43). De même pour `print.standard`, `print.outputProfile` et `print.renderingIntent` (`used` est ce qu’a donné la valeur par défaut), et pour un `maxWords` ou un `maxChars` de `checks.contentInConfig` qui n’est pas un entier égal ou supérieur à 0.
- **Numéros de ligne en texte vertical** : `lineNumbers.enabled: true` dans un document composé verticalement (`layout.writingMode: 'vertical-rl'`). Les pages verticales n’ont pas de numéros de ligne, et `used` vaut `false` (`lineNumbersUnsupported` ; voir [Numéros de ligne](/fr/docs/configuration-notes-references#numéros-de-ligne)).
- **Habillage en texte vertical** : le `defaultPlacement.wrap` d’un type de ressource dans un document composé verticalement. Les pages verticales ne composent pas de texte à côté d’une figure, et `used` vaut `none` (`wrapUnsupported` ; voir [Format du document › Habillage du texte](/fr/docs/document-format-resources#habillage-du-texte)). Un `wrap` qui n’indique aucun côté est une valeur de réglage inconnue.
- **Style d’encadré basé sur un autre** : un style d’encadré dont l’`extends` ne désigne aucun style de `calloutStyles` (`calloutStyleExtendsUnknown`, avec l’identifiant le plus proche dans `suggestion`), ou dont la chaîne d’`extends` revient à lui (`calloutStyleExtendsCycle`, `value` la boucle `a → b → a`). Le style reste seul, avec les valeurs par défaut pour ce qu’il laisse vide (voir [Styles basés sur un autre](/fr/docs/configuration-callouts#styles-basés-sur-un-autre)).
- **Gabarits de page et styles d’étiquette** : un problème dans `pageTemplates` ou `labelStyles` : un identifiant ou un nom en double, des `extends`, des ancrages ou des blocs chaînés qui bouclent, un style, un bloc ou un gabarit qui n’existe pas, un minimum supérieur à son maximum, un style d’étiquette d’ancrage absent de `labelStyles` (vérifié quand les ressources sont fournies : `collectConfigWarnings(config, { resources })`). Leur `path` est un pointeur JSON (`/pageTemplates/3/frames/2/style`) ; chaque type est décrit avec sa cause et sa correction dans [Avertissements des gabarits de page](/fr/docs/configuration-composed-pages#avertissements-des-gabarits-de-page).
- **Contenu dans une maquette** : un élément de texte de maquette dont le texte, en plus de ses variables, dépasse un libellé court, c’est-à-dire le texte du livre gardé dans la configuration. Un avertissement par réglage (un style de titre, l’en-tête, la maquette des parties), avec le chemin de chaque texte (`contentInConfig` ; voir [Contrôle du contenu](#contrôle-du-contenu-configuration)). Contrairement aux autres, il peut être désactivé : `checks.contentInConfig.enabled: false`.

Le Sandbox les liste dans le panneau **Vérifications** avec le chemin du réglage. Dans le code, `buildDocument` les place sur le document sous `configWarnings` (absent quand la configuration est propre), et `collectConfigWarnings(config)` les renvoie sans rien mettre en page :

```js
import { buildDocument, collectConfigWarnings } from 'postext';

// Plain JavaScript: in TypeScript, 'roman' does not type-check to begin with.
const config = { bodyText: { fontFamily: 'EB Garamond, serif' }, orderedLists: { numberFormat: 'roman' } };
const doc = buildDocument({ markdown }, config);
doc.configWarnings;
// [{ kind: 'fontFamilyStack', path: 'bodyText.fontFamily', value: 'EB Garamond, serif', used: 'EB Garamond' },
//  { kind: 'unknownNumberFormat', path: 'orderedLists.numberFormat', value: 'roman', used: 'arabic' }]
collectConfigWarnings(config); // the same list
```

Chaque configuration partielle imbriquée est aussi vérifiée : styles de titre, listes à l’intérieur des parties, `htmlViewer.overrides`, éléments de maquette.

`formatWarning` (voir [Avertissements dans le document](/fr/docs/configuration-programmatic-usage#avertissements-dans-le-document)) les décrit aussi, avec le chemin du réglage en tête (`bodyText.fontFamily: font stack "EB Garamond, serif" — set in "EB Garamond"`, `headingStyles[0].letterSpacng: unknown setting "letterSpacng" — ignored (did you mean "letterSpacing"?)`) : un hôte peut donc journaliser en une seule boucle les trois listes que renvoie une composition.
