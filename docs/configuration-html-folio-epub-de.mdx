# Programmatische Nutzung: HTML, Folio, EPUB und SCORM


## Den HTML-Betrachter einbinden

Der HTML-Betrachter ist der Renderer von Postext, der für den Bildschirm gedacht ist. Statt Seiten zu einer Bitmap zu rastern, gibt er absolut positionierte DOM-Knoten aus, deren Geometrie aus derselben Pipeline stammt, die auch die Druckausgabe erzeugt. Damit ist er die richtige Wahl, wenn Sie im Browser lesbare, auswählbare und auf Größenänderungen reagierende Typografie wollen – eine Lese-App, eine Vorschau im Produkt oder eine eingebettete Dokumentationsoberfläche –, ohne einen PDF-Betrachter einzubinden.

Die wichtigsten Teile der öffentlichen API:

- **`buildDocument(content, config, cache?)`** – durchläuft die gesamte Layout-Pipeline und gibt ein `VDTDocument` zurück.
- **`renderToHtmlIndexed(doc, options)`** – macht aus dem VDT einen einzigen HTML-String sowie eine Aufschlüsselung pro Seite und pro Block. Die Aufschlüsselung erlaubt günstige DOM-Aktualisierungen, wenn sich zwischen zwei Renderings nur wenige Blöcke geändert haben.
- **`resolveHtmlViewerConfig(partial)`** – ergänzt die Standardwerte des HTML-Betrachters (`maxCharsPerLine`, `columnGap`, `optimalLineBreaking`).
- **`buildFontString` + `measureGlyphWidth` + `dimensionToPx`** – Messgrundfunktionen, mit denen sich aus einer Zielzahl von Zeichen eine tatsächliche Spaltenbreite in Pixeln ableiten lässt.
- **`createMeasurementCache` / `clearMeasurementCache`** – austauschbare Caches, mit denen Sie Messungen über Neuaufbauten des Layouts hinweg wiederverwenden.
- **`prepareFonts` / `buildDocumentWithFonts` / `watchFonts` / `onFontsChanged`** – laden die Schnitte des Dokuments vor dem Layout und setzen erneut, wenn Schnitte eintreffen (siehe [Schriften vor dem Layout laden](/de/docs/configuration-programmatic-usage#schriften-vor-dem-layout-laden)).

### Live-Beispiel: ein HTML-String

Der ganze Ablauf in reinem JavaScript, vor der React-Integration weiter unten: das Dokument setzen, das `VDTDocument` an `renderToHtml` übergeben und den String in einen Container einfügen. `mode: 'single'` stapelt die Seiten untereinander; `background` gibt ihnen eine Farbe, da Seiten standardmäßig transparent sind. Der Pen gibt außerdem das erzeugte Markup aus, sodass Sie die absolut positionierten Zeilen sehen, die der Renderer ausgibt – der Browser zeichnet sie, bricht sie aber nie neu um.

### Minimale Einbindung

Das folgende Snippet ist die kürzeste brauchbare Integration: Es setzt das Dokument in der aktuellen Größe der Ansicht, rendert es in einen Container und wiederholt das bei Größenänderungen.

```tsx
import { useEffect, useRef } from 'react';
import {
  buildDocument,
  renderToHtmlIndexed,
  resolveHtmlViewerConfig,
  buildFontString,
  measureGlyphWidth,
  dimensionToPx,
  createMeasurementCache,
  watchFonts,
  onFontsChanged,
} from 'postext';
import type { PostextConfig, MeasurementCache } from 'postext';

// Screen-friendly DPI: at 144 DPI, an 8pt body size resolves to 16 px.
const HTML_DPI = 144;
const PADDING_PX = 24;

// Prose sample used to measure the target column width. Proportional fonts
// make "N × average width" unreliable, so we measure a representative string.
const SAMPLE =
  'The quick brown fox jumps over the lazy dog. Sphinx of black quartz, judge my vow.';

function sampleForChars(n: number): string {
  let s = SAMPLE;
  while (s.length < n) s += ' ' + SAMPLE;
  return s.slice(0, n);
}

export function PostextHtmlViewer({
  markdown,
  config,
  mode = 'multi',
}: {
  markdown: string;
  config: PostextConfig;
  mode?: 'single' | 'multi';
}) {
  const hostRef = useRef<HTMLDivElement | null>(null);
  const cacheRef = useRef<MeasurementCache>(createMeasurementCache());

  useEffect(() => {
    const host = hostRef.current;
    if (!host) return;

    const relayout = () => {
      const rect = host.getBoundingClientRect();
      if (rect.width === 0 || rect.height === 0) return;

      const viewer = resolveHtmlViewerConfig(config.htmlViewer);
      const fontFamily = config.bodyText?.fontFamily ?? 'EB Garamond';
      const fontWeight = config.bodyText?.fontWeight ?? 400;
      const fontSize = config.bodyText?.fontSize ?? { value: 8, unit: 'pt' as const };
      const fontSizePx = dimensionToPx(fontSize, HTML_DPI);

      // Measure the *actual* column width for N characters of body prose.
      const targetColumnPx = measureGlyphWidth(
        sampleForChars(viewer.maxCharsPerLine),
        buildFontString(fontFamily, fontSizePx, String(fontWeight), 'normal'),
      );

      const inner = Math.max(rect.width - PADDING_PX * 2, 100);
      let columnWidthPx: number;
      if (mode === 'single') {
        columnWidthPx = Math.min(targetColumnPx, inner);
      } else {
        // Fit as many columns as we can at the target width.
        const count = Math.max(
          1,
          Math.floor((inner + viewer.columnGap) / (targetColumnPx + viewer.columnGap)),
        );
        columnWidthPx = (inner - viewer.columnGap * (count - 1)) / count;
      }
      columnWidthPx = Math.max(Math.floor(columnWidthPx), 80);

      // Single mode uses one very tall page; multi mode uses the viewport
      // height so each VDT "page" becomes one column.
      const pageHeightPx =
        mode === 'single' ? Math.max(rect.height * 20, 200_000) : Math.max(rect.height - PADDING_PX * 2, 400);

      const override: PostextConfig = {
        ...config,
        page: {
          ...config.page,
          dpi: HTML_DPI,
          width: { value: columnWidthPx, unit: 'px' },
          height: { value: pageHeightPx, unit: 'px' },
          margins: {
            top: { value: 0, unit: 'px' },
            bottom: { value: 0, unit: 'px' },
            left: { value: 0, unit: 'px' },
            right: { value: 0, unit: 'px' },
          },
        },
        layout: { ...config.layout, layoutType: 'single' },
        bodyText: {
          ...config.bodyText,
          optimalLineBreaking: viewer.optimalLineBreaking,
        },
      };

      const doc = buildDocument({ markdown }, override, cacheRef.current);
      const { html } = renderToHtmlIndexed(doc, {
        mode,
        columnGap: viewer.columnGap,
        padding: PADDING_PX,
        background: 'transparent',
      });

      host.innerHTML = html;
    };

    relayout();

    const ro = new ResizeObserver(() => relayout());
    ro.observe(host);

    // Re-measure when web fonts land so glyph widths aren't taken from fallbacks.
    const stopWatching = watchFonts();
    const off = onFontsChanged(() => relayout());

    return () => {
      ro.disconnect();
      off();
      stopWatching();
    };
  }, [markdown, config, mode]);

  return <div ref={hostRef} style={{ width: '100%', height: '100%', overflow: 'auto' }} />;
}
```

Einige Anmerkungen dazu, was dieses Beispiel tut:

- **Die Spalte messen, nicht schätzen.** Da `maxCharsPerLine` ein *Zielwert* in Zeichen ist, hängt die tatsächliche Breite in Pixeln von der Grundschrift ab. `measureGlyphWidth` liefert eine echte Messung mit der gewählten Schrift, sodass die Satzbreite auch beim Wechsel der Schrift stimmig bleibt.
- **Die Seite umschreiben.** Der HTML-Betrachter behandelt jede „Seite“ des VDT als eine Spalte auf dem Bildschirm. Das Beispiel überschreibt `page.width` mit der gemessenen Spaltenbreite, setzt die Ränder auf null (der Innenabstand liegt außerhalb der Seite im umhüllenden div `.pt-doc`) und verwendet `HTML_DPI = 144`, sodass Grundtext in `8pt` zu `16px` aufgelöst wird.
- **Auf das Laden von Schriften achten.** `watchFonts` beobachtet `document.fonts` und verwirft einmal pro Frame, was in den Familien gemessen wurde, deren Schnitte eingetroffen sind; `onFontsChanged` setzt die Spalte dann erneut. Ohne diesen Neuaufbau verwendet das erste Rendering die Metriken einer Ersatzschrift und springt, wenn die echte Schrift eintrifft.
- **Den Mess-Cache wiederverwenden.** Wird der Cache einmal pro Komponente erzeugt, verwenden Größenänderungen und Änderungen des Schriftmaßstabs die Messungen des vorherigen Renderings wieder, statt jeden Absatz neu zu messen.

### Weiterführende Schritte

Das Beispiel oben ist bewusst flach gehalten. Produktive Integrationen ergänzen meist:

- **Isolation per Shadow DOM** – rendern Sie in `host.attachShadow({ mode: 'open' })`, damit kein CSS der umgebenden Seite in den Betrachter durchsickern kann.
- **Inkrementelle Aktualisierung** – `renderToHtmlIndexed` gibt `pages[i].blocks` zurück, jeweils mit einer stabilen `id` und dem äußeren HTML des Blocks. Unterscheiden sich zwischen zwei Renderings nur wenige Blöcke, können Sie diese Block-Hüllen an Ort und Stelle ersetzen, statt `innerHTML` neu aufzubauen.
- **Überlagerungen** – ein absolut positioniertes SVG über jeder `.pt-page` für Cursor, Auswahlen oder Grundlinienraster.
- **Links** – die Wörter eines Markdown-Links werden in `<a href="…" rel="noopener noreferrer">` gehüllt, das die Textfarbe übernimmt und nicht unterstrichen ist; siehe [Dokumentformat › Links](/de/docs/document-format-inline#links). Fangen Sie in einem editorähnlichen Betrachter Klicks auf `a[href]` ab, die nicht mit `#` beginnen, und öffnen Sie sie in einem neuen Tab (Anker von `:ref` verlinken innerhalb des Dokuments).
- **Lösbare Übungen** – das HTML eines Dokuments mit `:::exercise`-Blöcken enthält deren Daten in einem `<script type="application/json" class="pt-exercises">`, aber keinen Code, um sie zu beantworten: Die Bedienelemente fügt die Seite hinzu, die es zeigt. Sobald das Markup steht, rufen Sie `attachExercises(root, options?)` aus `postext` auf dem Element (oder der Shadow-Root) auf, in dem es steht, und rufen die zurückgegebene Funktion auf, bevor Sie das Markup ersetzen. `attachExercises` legt die Eingabe- und Auswahlfelder und die Leiste mit „Prüfen“, „Lösung zeigen“ und „Neu beginnen“ über die Seiten und fügt ein eigenes Stylesheet hinzu. `storageKey` nennt Buch und Kapitel, unter denen die Antworten gespeichert werden, `store` speichert sie anderswo als in `localStorage` (in allem, was `getItem`, `setItem` und `removeItem` hat), und `onResult(result)` erfährt von jeder Prüfung, jedem Neuanfang und jeder gezeigten Lösung, mit der Punktzahl (`right` von `total`) und jeder bewerteten Antwort. Ein Host, der Blöcke aus `renderToHtmlIndexed` einzeln ersetzt, übergibt die `exercises` des Index als `data`. `EXERCISE_SCRIPT` ist derselbe Code als eigenständiges Skript, für eine HTML-Datei ohne Host-Seite, die ihn aufruft. Siehe [Übungen in HTML und EPUB](/de/docs/exercises#übungen-in-html-und-epub).
- **Einfarbige Bilder** – mit eingeschaltetem `diagramStyle.singleInk` erhalten SVG-Elemente `<img>` einen CSS-Filter, sofern Sie nicht `singleInk: false` für URLs übergeben, die bereits umgefärbt sind; siehe [Einfarbmodus auf dem Canvas und in HTML](/de/docs/configuration-resources#einfarbmodus-auf-dem-canvas-und-in-html).
- **Komponierte Seiten und Comicseiten auf einem Druckblatt** – auf einer Seite, die so breit wie der Bildschirm und so hoch wie der Bildlauf ist, stünde ein am Fuß einer komponierten Seite (`::::page{template}`) verankerter Rahmen am Fuß des Bildlaufs. Übergeben Sie `composedViewerLeaf: { width, height, margins? }` (Format und Ränder der gedruckten Seite) in der Konfiguration, die Sie setzen: Jede komponierte Seite wird dann auf einer Seite dieses Formats gesetzt, mit ihrer Druckgeometrie, und Sie skalieren sie auf den Bildschirm (seit postext 1.47); `comics.viewerLeaf` tut dasselbe für Comicseiten, skaliert auf `fitWidth` px (siehe [Comics](/de/docs/configuration-comics)). Beide sind für Hosts gedacht: Der HTML-Viewer der Sandbox setzt sie, und sie werden nie mit einem Dokument gespeichert.

Die Komponente `HtmlPreview` der Sandbox (`packages/postext-sandbox/src/viewport/html/HtmlPreview/index.tsx`) setzt all das auf derselben hier gezeigten API um und kann als Referenz dienen. Sie leitet außerdem jeden Build über einen gemeinsamen Layout-Worker (siehe [Layout in einem Web Worker ausführen](/de/docs/configuration-programmatic-usage#layout-in-einem-web-worker-ausführen)), sodass Live-Bearbeitungen und Größenänderungen den Haupt-Thread nie blockieren – ersetzen Sie den direkten Aufruf `buildDocument(...)` im Snippet oben durch `layoutWorker.build(...)`, sobald Sie das Layout aus dem Haupt-Thread verlagern wollen.

Die transparente Seite ist auf einer dunklen Website wichtig: Eine Vorschau ohne `background` zeigt schwarzen Text auf dem dunklen Hintergrund der Website. Übergeben Sie `renderToHtml(doc, { background: '#ffffff' })` oder geben Sie dem Dokument ein `page.backgroundColor`.

**Die Textformate der Host-Seite bleiben draußen.** Jede Zeile wird in den Breiten gesetzt, die die Engine gemessen hat; ein `letter-spacing`, `word-spacing`, `text-transform` oder `font-variant`, das die Ausgabe von der umgebenden Seite erbt, würde die Glyphenfolgen verbreitern und die Zeilen übereinanderdrucken lassen. Die Wurzel `.pt-doc` setzt deshalb vor ihren eigenen Layout-Deklarationen die vererbten Texteigenschaften zurück – Buchstaben- und Wortabstand, Groß- und Kleinschreibung, Einzug, Leerraum, Schriftstil, Variante, Stärke, Breite, Features und Unterschneidung, Zeilenhöhe, Ausrichtung, Textschatten und Betonung, Trennstriche, Richtung, Schreibrichtung, Textkontur und -füllung sowie die Textvergrößerung auf Mobilgeräten –, sodass die Ausgabe in einer Shadow-Root oder unter einem gestalteten Element gleich aussieht. Die Liste wird als `HTML_TEXT_RESET` exportiert, ein String aus CSS-Deklarationen: Ein Host, der das `innerHtml` der Seiten (aus `renderToHtmlIndexed`) in eigene Container einhängt, setzt ihn auf deren Wurzel. Bis postext 1.4 setzte die Wurzel nichts zurück; der Behelf war eine Hülle mit `all: initial`.


## Ein 3D-Buch (`postext-folio`)

`postext-folio` stellt ein gesetztes Dokument auf dem Bildschirm als gedrucktes Buch dar, das aufgeschlagen auf einem Schreibtisch liegt: Doppelseiten, auf denen die ungeraden Seiten rechts stehen, und Blätter, die der Leser mit den Schaltflächen ‹ ›, den Pfeiltasten, einer Wischgeste, einem Klick auf eine Seite umblättert oder indem er eine Seite an ihrer Kante fasst und hinüberzieht. Jedes Blatt wölbt sich in three.js entsprechend seinem Papier und wirft einen echten Schatten auf die Seiten darunter. Das WebGL-Canvas zeichnet das Buch im Ruhezustand wie beim Umblättern, sodass eine Seite ihr Aussehen nie ändert, wenn sie aufliegt. Es ist der Betrachter der Rezepte und des Tabs **Folio** der Sandbox.

```bash
npm install postext postext-folio three
```

```ts
import { buildDocument } from 'postext';
import { createFolioFromDocument } from 'postext-folio';

const doc = buildDocument({ markdown }, config);
const book = createFolioFromDocument(document.getElementById('book')!, doc, {
  onChange: ({ pages }) => console.log('showing pages', pages),
});

// After an edit: the same viewer, on the same page.
book.setDocument(buildDocument({ markdown: edited }, config));
```

- **Seiten werden gezeichnet, wenn sie gebraucht werden.** `createFolioFromDocument` zeichnet jede Seite mit `renderPageToCanvas` in genau den Gerätepixeln eines Seitenplatzes (WebGL zeigt sie dann Texel für Pixel, so scharf wie die Canvas-Vorschau), und nur die Doppelseiten um die aufgeschlagene herum (`window`, standardmäßig drei auf jeder Seite). Seiten, die aus diesem Fenster fallen, werden freigegeben, sodass ein Buch mit tausend Seiten den Speicher von wenigen kostet. Ein Sprung zu einer weit entfernten Seite zeichnet zuerst diese Doppelseite. Bis zu zehn Seiten weit wenden sich die Blätter einzeln; weiter entfernt hebt sich der Seitenblock dazwischen als eine Platte, so dick wie diese Seiten (ihre Papierstärken summiert), und legt sich auf die andere Seite. `setDocument` behält die Zeichnung jeder Seite, die im neuen Layout gleich lautet (`{ repaint: true }` zeichnet sie alle neu, etwa nachdem ein Bild eingetroffen ist).
- **Das Dokument bestimmt das Buch.** Seine erste Seite öffnet sich allein rechts, wenn sie eine rechte Seite ist (`pageIndexOffset` gerade), ein rechts gebundenes Buch (`page.binding: 'right'` oder ein vertikales Dokument) liegt gespiegelt und wird nach links umgeblättert, Vakatseiten erhalten die Hintergrundfarbe der Seite, und die Endformatbreite der Seite (`pageWidthMm`) skaliert die Papierstärke und die Buchdeckel. Ein mit einer `continuation` gesetztes Kapitel rechnet die übrigen Seiten des Buches (`pageIndexOffset` davor, `bookPageCount` danach) in die Dicke der beiden Seitenblöcke ein, ohne sie zu zeichnen (`extraPages`).
- **Das Dokument bestimmt das Aussehen.** Papier, Bindung, Schreibtisch und Licht sind die [Einstellungen `folio`](/de/docs/configuration-fonts-colors-viewers#folio-betrachter-konfiguration) des Dokuments (`doc.config.folio`). Eine Seite, die innerhalb eines Abschnitts `:::paper` gesetzt ist, trägt ihr eigenes Papier (`VDTPage.paper`), und ihr Blatt wird mit Farbe, Oberfläche, Dicke und Steifigkeit dieses Papiers gezeichnet. Mit `binding.cover: 'pages'` ist die erste Seite der vordere Buchdeckel und die letzte, wenn sie eine linke Seite ist, der hintere (`covers`). Ein Zeitungsformat (`'broadsheet'`, `'berliner'`, `'tabloid'`, `'compact'`), dessen Einstellungen kein Papier und keine Bindung nennen, liegt als gefaltetes Zeitungspapier da, auch wenn der Host sein eigenes `folio` übergibt.
- **Der Container bestimmt die Größe.** Das Buch füllt ihn, mit den Schaltflächen und der Seitenzahl in den Rändern; geben Sie dem Container also eine Höhe. Eine Größenänderung zeichnet die Seiten in der neuen Größe neu. Unter 560 px Breite zeigt der Betrachter jeweils eine Seite (`mode: 'auto'`; `'single'` und `'double'` erzwingen das eine oder andere): Der Rücken verläuft entlang der Innenkante der Seite, und das Blatt wendet sich darüber, ein Ziehen zum Rücken hin blättert vorwärts, eine Wischgeste von ihm weg zurück, ein Tippen blättert um.
- **Was der Zeiger tut.** `interaction` (und später `setInteraction`) legt fest, was die linke Maustaste, ein Finger oder ein Stift auf dem Buch tut: `'hand'` (der Standard) fasst und wendet die Seiten, `'orbit'` dreht die Ansicht wie ein Ziehen mit der rechten Maustaste (für Trackpads und Tablets), `'select'` überlässt den Zeiger dem Host, etwa um Text auszuwählen. `pageAt(event)` liefert die Seite unter einem Zeiger und die Stelle darauf (`{ page, x, y }`, Anteile der Seite ab ihrer linken oberen Ecke), auf dem Buch, wie es zu sehen ist, geneigt oder gedreht; `pointOnScreen(point)` geht den umgekehrten Weg, um eine Einfügemarke oder eine Auswahl über die Seite zu zeichnen. `refreshPage(src)` zeigt ein Seiten-Canvas erneut, das der Host an Ort und Stelle neu gezeichnet hat. Die Sandbox nutzt sie alle, um auf den 3D-Seiten Text auszuwählen und der Einfügemarke des Editors zu folgen.
- **Eine Lupe für kleine Schrift.** `interaction: 'magnify'` hält eine runde Lupe mit schwarzem Rand dort über das Buch, wo der Zeiger ist (ein Finger hält sie über sich, solange er den Bildschirm berührt). Sie zeigt das Buch so, wie das Auge des Lesers es sieht, beleuchtet und gewölbt, wie es daliegt, in der Mitte am stärksten vergrößert und zum Rand hin gekrümmt. Das Mausrad, `+` und `−` ändern die Vergrößerung (`setMagnification(zoom)`, 1,5 bis 10; der Standard zeigt die Seite mit etwa 5,5 CSS-px pro Millimeter), und Esc legt sie weg; `magnifier: { zoom, diameter }` legt beides von Anfang an fest. `createFolioFromDocument` zeichnet die Seiten unter der Lupe erneut, scharf genug für ihre Mitte, sodass sich auch die Grundschrift einer Zeitung lesen lässt; `createFolio` nimmt solche Zeichnungen von `detail: { paint(index, deviceWidth), release() }`. Die Sandbox legt sie auf die Schaltfläche **Lupe** (M). Die Lupe wählt auch Text aus: Über den Seiten ist der Cursor ein Textcursor, `pageAt` gibt den Punkt unter der Mitte der Lupe zurück (auf einem Touchscreen über dem Finger), und in der Sandbox setzt ein Klick dort die Einfügemarke, und ein Ziehen wählt aus.
- **Der Leser kann sich umsehen.** Ein Ziehen mit der rechten Maustaste dreht die Ansicht um das Buch (bis zu 70° von oben), auch während sich Blätter wenden; `resetView()` führt sie sanft zu `tilt` und `yaw` der Einstellungen zurück, und `getView()` liefert die Ansicht, wie sie gerade zu sehen ist (`{ tilt, yaw }`, in Grad), um sie als diese Einstellungen zu speichern. Die Sandbox legt das auf zwei Schaltflächen, **Ansicht zurücksetzen** und **Als Standardansicht speichern**.
- **Videos laufen auf den Seiten.** Ein Klick auf das Vorschaubild eines Videos spielt es auf der Seite ab, in jedem Modus von `interaction`, und es läuft weiter, während sich sein Blatt wendet; ein weiterer Klick hält es an, und es stoppt, wenn das Buch auf einer Doppelseite zur Ruhe kommt, die es nicht zeigt. Ein Video mit `player.autoplay` startet von selbst, wenn seine Doppelseite zum ersten Mal gezeigt wird; eines, das außerdem neben den anderen läuft (`player.exclusive: false`), startet jedes Mal stumm und stoppt, wenn die Doppelseite weggeblättert wird; mehrere können gleichzeitig laufen. Die Optionen `videos`, `videoUrl` und `onVideo` sowie `stopVideo()` am Betrachter; siehe [Dokumentformat › Videos auf den Seiten von Folio](/de/docs/document-format-resources#videos-auf-den-seiten-von-folio).
- **Zuerst Schriften und Bilder.** Wie bei `renderPage` müssen die Schnitte, die das Dokument verwendet, in `document.fonts` geladen und seine Ressourcenbilder mit `registerResourceImage` registriert sein, bevor Seiten gezeichnet werden.
- **Barrierefrei.** Der Betrachter ist eine fokussierbare Gruppe, die ←/→ (bei einem rechts gebundenen Buch gespiegelt), Bild auf/ab, Pos1 und Ende annimmt; seine Schaltflächen und die Seitenzahl sind beschriftet (`labels` übersetzt sie), und jedes Seiten-Canvas hat einen Alternativtext `alt` (`alt: (index) => …`).
- **Ohne WebGL2** oder wenn der Leser reduzierte Bewegung wünscht, wechseln die Doppelseiten einfach. WebGL-Bücher sind für ein Smartphone schwer (eine Textur pro Seitenfläche): Die Sandbox bietet ihren Tab Folio nur dort an, wo WebGL2 verfügbar ist und die kurze Seite des Bildschirms mindestens 600 px misst. `canFlip()` gibt an, ob sich die Blätter hier in 3D wenden: WebGL2 und keine reduzierte Bewegung.

## EPUB-Bücher (`postext-epub`)

`postext-epub` schreibt ein gesetztes Buch als EPUB-3.3-Datei, im Browser oder in Node, ohne Server. `postext` ist eine Peer-Abhängigkeit, wie bei `postext-pdf`: Aktualisieren Sie die beiden gemeinsam, und legen Sie sie auf einem CDN auf dieselbe Version fest.

### Ein Buch schreiben

```ts
import { openBundle, buildBundle } from 'postext';
import { renderToEpub } from 'postext-epub';

const bundle = await openBundle(fileBytes);
const docs = buildBundle(bundle); // one VDTDocument per chapter, in book order

const bytes = await renderToEpub(docs, {
  layout: 'reflowable',
  metadata: { title: 'Lantern', creators: ['Ada Lovelace'], language: 'en' },
  fonts: bundle.fonts.map((f) => ({ family: f.family, weight: f.weight, style: f.style, bytes: new Uint8Array(f.bytes), format: f.format })),
  resourceBytes: (fileId) => {
    const data = bundle.files.get(fileId);
    return data ? { bytes: data, mediaType: '' } : undefined;
  },
  onWarning: (w) => console.warn(w),
});
```

Ein einzelnes Dokument ist ein Buch mit einem Kapitel: `renderToEpub([doc], options)`.

- **`renderToEpub(docs, options): Promise<Uint8Array>`** schreibt die Datei. `options` ist `{ layout, metadata, fonts?, svgFonts?, resourceBytes?, cover?, onProgress?, onWarning?, signal?, kindlePanelView? }`.
- **`metadata`**: `title` und `language` (eine Sprachkennung nach BCP 47) sind erforderlich; `subtitle`, `creators`, `identifier`, `date`, `publisher`, `rights`, `description` und `modified` sind optional. Eine bloße ISBN wird zu `urn:isbn:…`. Ohne `identifier` erhält das Buch eine aus Titel, Urhebern und Sprache abgeleitete `urn:uuid:`, sodass eine neue Version desselben Buches ihren Platz in der Bibliothek eines Lesers behält. Übergeben Sie auch `modified`, um byte-identische Ausgaben zu erhalten.
- **`fonts`**: die einzubettenden Schnitte, `{ family, weight, style, bytes, format, unicodeRange? }`, wobei `format` eines von `woff2`, `woff`, `ttf`, `otf` ist. Jeder Schnitt wird zu einer Datei und einer Regel `@font-face`; mehrere Dateien mit ihrem `unicodeRange` bilden einen Schnitt (die Teile von Google Fonts). Eine Familie, Stärke oder ein Stil, den die Seiten ohne eingebetteten Schnitt verwenden, wird als `missingFont` gemeldet, und Lesesysteme setzen dann eigene Schriften ein. Betten Sie nur Schriften ein, deren Lizenz das erlaubt: Ein Schnitt mit `redistributable: false` wird nie in die Datei geschrieben (das Buch darf damit gesetzt sein, aber seine Datei bleibt draußen, auch aus SVG-Bildern). Ein Host kann stattdessen die Schnitte der freien Schrift unter dem Namen der lizenzierten angeben (es sind gewöhnliche Schnitte); das tun die Sandbox und `postext` für eine Schrift mit `fallback` (seit postext 1.43).
- **`resourceBytes(fileId)`**: die Bilder, die die Seiten platzieren, synchron oder asynchron, als `{ bytes, mediaType }`; ein leerer `mediaType` wird aus den Bytes gelesen. Geben Sie Bitmaps so an, wie sie gespeichert sind, und SVGs als ihren Quelltext, nicht als PDF-Druckoriginal (`svg.pdfFileId`). Jedes Bild wird einmal gespeichert. Bei einem einfarbigen Buch (`diagramStyle.singleInk`) werden die SVGs in der Datei umgefärbt. In ein SVG werden die Schnitte eingebettet, die sein Text nennt, da ein Lesesystem es als Bild zeigt, das die Schriften des Buches nicht sieht (siehe [Schriften in SVG-Text](/de/docs/configuration-resources#schriften-in-svg-text)): aus `fonts` (die Teile, die seine Zeichen enthalten), dann aus **`svgFonts.provider`** für eine Familie, die der Text des Buches nicht verwendet. Familien von Schnitten mit der Markierung `redistributable: false` und solche, die `svgFonts.withhold(family)` nennt, bleiben draußen und werden jeweils einmal als `fontWithheld` gemeldet; eine Familie ohne Schnitt wird als `svgFontUnavailable` gemeldet, Schnitte über `svgFonts.maxBytes` (2 MiB) als `svgFontsTooLarge`. `svgFonts.inline: false`, `diagramStyle.inlineFonts: false` und das `svg.inlineFonts: false` einer Ressource behalten die Bytes so, wie sie übergeben wurden. Ein Bild ohne Bytes wird als `missingImage` gemeldet und als leerer Rahmen belassen. `svgFonts.standIn(family)` (seit postext 1.43) nennt für eine davon eine freie Schrift: `svgFonts.provider` wird nach deren Schnitt gleicher Stärke und gleicher Neigung gefragt, der unter dem Namen der zurückgehaltenen Schrift ins Bild kommt; hat er keinen, bleibt die Schrift draußen und wird gemeldet.
- **`cover`**: `{ bytes, mediaType, alt?, showsFirstPage? }`, ein Bild im Format JPEG, PNG, WebP oder SVG. Das Buch öffnet sich dann mit einem Umschlagdokument, das es enthält, und es ist das `cover-image` des Pakets (das Vorschaubild in einer Bibliothek). Ohne Umschlag nennt das feste Layout seine erste Seite als Umschlag, und das umfließende Buch hat kein Umschlagbild. `showsFirstPage: true` gibt an, dass das Bild eine Aufnahme der ersten gedruckten Seite ist: Das feste Layout verwendet es dann nur als `cover-image` und öffnet sich mit dieser Seite, die sonst zweimal gezeigt würde; das umfließende Buch öffnet sich wie bisher mit dem Umschlagdokument.
- **`kindlePanelView`**: fügt einem festen Layout mit Comicseiten die Kindle-Panelansicht (Kindle Panel View) hinzu, ein Tippziel über jedem Panel, das es vergrößert zeigt, mit den Metadaten, die Kindle verlangt. Jedes Ziel enthält eine Kopie des Comics seiner Seite, sodass jede Seite pro Panel um eine Kopie wächst; verwenden Sie es nur für Bücher, die für Kindle bestimmt sind. Standard `false`. Die Navigation nach Regionen, die jedes Lesesystem nutzen kann, wird in jedem Fall geschrieben (siehe [Comics in jedem Ausgabeformat](/de/docs/comics#comics-in-jedem-ausgabeformat)).
- **`onProgress({ phase, done, total })`**: `resources` (Schriften und Bilder), `documents` (Seiten bei festem Layout, Kapitel bei umfließendem), dann `package`. **`signal`** bricht zwischen den Schritten ab.
- **`readEpub(bytes)`** liest eine Datei für einen Betrachter wieder ein, ohne `DOMParser`: Layout, Metadaten, Leserichtung, jede Datei nach Pfad, das Manifest, den Spine, das Inhaltsverzeichnis, die Seitenliste, den Viewport des festen Layouts und den Umschlag. Der EPUB-Betrachter der Sandbox baut darauf auf.

Beide Darstellungen enthalten Metadaten nach EPUB Accessibility 1.1 (Zugriffsmodi, Merkmale wie das Inhaltsverzeichnis und die gedruckten Seitenzahlen, Gefahren und eine Zusammenfassung) und erheben standardmäßig keinen Anspruch auf WCAG-Konformität. Die vollständige Liste der Optionen und die Einschränkungen stehen in der [README des Pakets](https://www.npmjs.com/package/postext-epub).

### Eine Datei mit EPUBCheck prüfen

[W3C EPUBCheck](https://www.w3.org/publishing/epubcheck/) ist der Referenzvalidator für EPUB; E-Book-Shops prüfen die Dateien, die sie erhalten, damit. Ist er installiert (`brew install epubcheck` oder die Java-Version), listet `epubcheck book.epub` Fehler, Warnungen und Nutzungshinweise auf; die Nutzungshinweise, die eine Ausgabe von Postext übrig lässt (`CSS-028`, `OBS-001`, `HTM_062`), dienen nur der Information. Im Repository von Postext prüft `pnpm --filter postext-epub epubcheck` die Beispielbücher der Testsuite, `node packages/postext-epub/scripts/epubcheck.mjs book.postext --layout both` setzt eine `.postext`-Datei oder einen Preset-Ordner und prüft beide Darstellungen, und `pnpm --filter postext-epub validate` führt die ganze Matrix der Bücher aus (der Leitfaden, die Presets der Schaustücke, chinesische und arabische Bücher sowie Bücher aus den Rezepten), von denen jedes ohne Fehler und Warnungen besteht.

## SCORM-Pakete (`postext-scorm`)

`postext-scorm` schreibt ein Buch oder die daraus gewählten Kapitel und Abschnitte als SCORM-Paket: das Zip-Archiv, das ein Lernmanagementsystem (LMS: Moodle, Canvas, Blackboard, SCORM Cloud und die meisten anderen) als Kurs importiert. Der Inhalt ist der des EPUB-Schreibers, feste Seiten oder umfließender Text, als HTML5-Seiten; jeder Teil, den das LMS verfolgt, läuft in einem kleinen Player, und die Übungen darin senden ihre Punktzahl, den Abschluss und ob bestanden wurde an das LMS. Es ist der Schreiber hinter dem Tab **SCORM** der Sandbox.

```bash
npm install postext postext-epub postext-scorm
```

`postext` und `postext-epub` sind Peer-Abhängigkeiten: Aktualisieren Sie die drei gemeinsam.

### Ein Paket schreiben

```ts
import { openBundle, buildBundle } from 'postext';
import { renderToScorm, scormTree, scormOrganization, treeLeaves } from 'postext-scorm';

const bundle = await openBundle(fileBytes);
const docs = buildBundle(bundle);

// The book's spine: chapters and their headings down to the third level.
const tree = scormTree(bundle.chapters.map((c) => ({ markdown: c.markdown, title: c.title })));
// Chapter 1 whole, and two sections of chapter 2.
const picked = new Set([tree[0]!, tree[1]!.children[0]!, tree[1]!.children[2]!].flatMap(treeLeaves).map((n) => n.id));

const zip = await renderToScorm(docs, {
  version: '1.2',
  layout: 'fixed',
  items: scormOrganization(tree, picked),
  metadata: { title: 'Lantern', language: 'en' },
  fonts, resourceBytes, // as for renderToEpub
});
```

- **`renderToScorm(docs, options): Promise<Uint8Array>`** schreibt das Zip-Archiv. `docs` sind die Kapiteldokumente, die `renderToEpub` nimmt. `options` ist `{ version, layout, items?, metadata, fonts?, svgFonts?, resourceBytes?, cover?, passingScore?, onProgress?, onWarning?, signal? }`; `metadata`, `fonts`, `svgFonts`, `resourceBytes` und `cover` sind die des EPUB-Schreibers.
- **`version`**: `'1.2'` oder `'2004'` (SCORM 2004, 4. Ausgabe). Jedes LMS nimmt SCORM 1.2 an. SCORM 2004 hält Abschluss und Erfolg getrennt, gibt eine skalierte Punktzahl und bewahrt bis zu 64.000 Zeichen gespeicherter Antworten auf, wo SCORM 1.2 nur 4.096 aufbewahrt; wählen Sie es, wenn das LMS es annimmt und diese Punkte wichtig sind.
- **`layout`**: `'fixed'`, jede gedruckte Seite in das Fenster eingepasst, oder `'reflowable'`, der Text für das Fenster neu gesetzt, wie in [Festes Layout und umfließend](#festes-layout-und-umfließend).
- **`items`**: die Gliederung, die das LMS zeigt, ein Baum aus `{ title, doc?, range?, children? }`. Ein Eintrag mit `children` fasst diese zusammen; einer ohne ist ein SCO, ein Teil, den das LMS einzeln startet, verfolgt und bewertet: das Kapitel `doc` ganz oder dessen `range` (`{ start, end? }`, Positionen im Markdown des Kapitels, wie es geschrieben ist, Frontmatter eingeschlossen). Ohne `items` ist jedes Kapitel ein SCO.
- **`scormTree(chapters, config?)`** listet die Kapitel und ihre Überschriften der Ebenen 1 bis 3 auf, jede mit dem Bereich, für den sie steht: von ihrer Zeile bis zur nächsten Überschrift ihrer Ebene oder einer höheren. Die erste Überschrift unter einem Kapitel oder einer Überschrift nimmt auch den Text davor mit, sodass Titel und Einleitungsabsätze eines Kapitels zu seinem ersten Abschnitt gehören. **`scormOrganization(tree, picked)`** macht aus einer Menge gewählter Blatt-IDs `items`: Ein ganz gewählter Knoten ist ein SCO, ein teilweise gewählter fasst die Einträge seiner Kinder zusammen. `treeLeaves(node)` und `pickState(node, picked)` (`'all'`, `'some'`, `'none'`) helfen bei einem Baum mit Kontrollkästchen.
- **`passingScore`**: der Anteil richtiger bewerteter Antworten in Prozent, ab dem bestanden ist, über dem `exercises.digital.passingScore` der Dokumente. `0` oder nicht gesetzt: weder bestanden noch nicht bestanden.

Ein festes SCO enthält jede gedruckte Seite, die sein Teil berührt, sodass eine Seite, die zwei Teile teilen, in beiden erscheint. Ein umfließendes SCO enthält genau den Text seines Teils, an seinen Überschriften geschnitten. Links von den Seiten eines SCO zu denen eines anderen werden entfernt, da ein LMS ein SCO danach verfolgt, was es öffnet. Der Player zeigt ein Dokument auf einmal, mit ← und → (oder Bild auf und Bild ab bei festen Seiten), dem Inhalt des SCO und der Position; ein rechts gebundenes Buch blättert nach links.

### Was beim LMS ankommt

Der Player findet die API des LMS so, wie SCORM es verlangt (`API` für SCORM 1.2, `API_1484_11` für SCORM 2004, die Kette der übergeordneten Fenster hinauf, dann beim öffnenden Fenster), und meldet:

- **Punktzahl.** Eine Übung zählt ihre letzte Prüfung: richtige bewertete Felder von allen bewerteten Feldern, also die Punktzahl, die ihre Leiste zeigt. Die Punktzahl eines SCO ist die Summe der richtigen Felder geteilt durch die Summe der bewerteten Felder seiner Übungen, sodass ein Kreuzworträtsel mit zwanzig Feldern mehr wiegt als eine Richtig-oder-falsch-Aufgabe; eine nie geprüfte Übung zählt kein Feld als richtig. SCORM 1.2 erhält sie als Prozentwert (`cmi.core.score.raw`, von 0 bis 100), SCORM 2004 als Bruch (`cmi.score.scaled`) mit den Feldern als `raw` und `max`. Eine Übung gehört zu dem Teil, in dem ihr Block steht: Nur dieses SCO zählt sie, auch wenn ihre Seite ebenfalls in einem benachbarten SCO erscheint.
- **Abschluss.** Ein SCO ist abgeschlossen, sobald alle seine Seiten oder Dokumente gezeigt wurden und jede Übung, die es zählt, geprüft wurde (oder keine Prüfung mehr hat). Bis dahin ist es unvollständig, und das LMS merkt sich die Stelle des Lesers für den nächsten Besuch.
- **Erfolg.** Mit einer Bestehensgrenze ist ein abgeschlossenes SCO daran gemessen bestanden oder nicht bestanden. Das Manifest trägt sie (`adlcp:masteryscore` in SCORM 1.2, ein primäres Lernziel mit `minNormalizedMeasure` in SCORM 2004), und der Player übernimmt den Wert, den das LMS zurückgibt, sodass ein LMS mit eigener Grenze Vorrang hat.
- **Interaktionen.** Jede Prüfung schreibt die Übung als Interaktion: eine ID aus ihrem Anker oder ihrer Nummer, einen Typ aus ihrer Art (`true-false`, `choice`, `fill-in`, `other`), die Antwort des Lesers, die richtige Antwort, das Ergebnis und eine Gewichtung nach ihren bewerteten Feldern; SCORM 2004 fügt eine Beschreibung hinzu und führt eine Interaktion je Übung, SCORM 1.2 fügt je Prüfung eine hinzu.
- **Rollup.** SCORM 2004 gewichtet im Manifest das Maß jedes SCO nach seinen bewerteten Feldern, sodass die Punktzahl des Kurses alle richtigen Felder von allen bewerteten Feldern ist. SCORM 1.2 hat kein eigenes Rollup: Die Bewertungsmethode des LMS entscheidet (Moodle bietet die höchste Punktzahl, den Durchschnitt oder die Summe der Punktzahlen der SCOs).
- **Antworten.** Sie gehen mit den verbrauchten Prüfungen und Neuanfängen in `cmi.suspend_data`, sodass die Grenzen eines Versuchs ([Bewertung](/de/docs/configuration-exercises#bewertung)) über Besuche und Geräte hinweg gelten. Jenseits der 4.096 Zeichen von SCORM 1.2 gehen die Zähler weiterhin an das LMS, und die Antworten bleiben im Browser des Lesers.

Außerhalb eines LMS (die Startseite allein oder das Paket auf einem Webserver) findet der Player keine API: Das Buch liest sich gleich, und die Übungen behalten ihre Antworten im Browser, wie die eines HTML- oder EPUB-Buchs.

### Ein Paket prüfen

Die Testsuite validiert die Manifeste beider Versionen mit `xmllint` gegen die Schemas von IMS und ADL. Um ein Paket auszuprobieren, importieren Sie das Zip-Archiv in ein LMS (die SCORM-Aktivität von Moodle nimmt beide Versionen an) oder in [SCORM Cloud](https://cloud.scorm.com/). Ein lokaler Ersatz geht auch: [scorm-again](https://github.com/jcputney/scorm-again) stellt die APIs von SCORM 1.2 und 2004 in einer Seite bereit, die die Startseite in einem Rahmen lädt, und weist jeden Wert zurück, den das Datenmodell nicht zulässt.
