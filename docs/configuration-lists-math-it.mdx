# Configurazione: elenchi e matematica


## Elenchi puntati

La proprietà `unorderedLists` controlla come si compongono gli elenchi puntati (`-`, `*`, `+`) e gli elenchi di attività GFM (`- [ ]`, `- [x]`). Sono supportati fino a cinque livelli di annidamento.

### Estensioni per gli elenchi di attività

Le voci di attività GFM (`- [ ] …`, `- [x] …`) si compongono come voci di elenco puntato con una casella al posto del punto elenco. Il motore disegna da sé la casella, un quadrato vuoto che riceve un segno di spunta quando l’attività è completata: non richiede alcun font, quindi è identica su ogni macchina, nel canvas, nel PDF, nell’HTML e nell’EPUB, e le tecnologie assistive leggono `☐` o `☑`. Il lato misura 0,6 em al corpo del segno (`bulletFontSize`, o il `fontSize` del livello), e questo è anche lo spazio che la casella occupa prima del `gap`; al corpo del testo poggia sulla linea di base della prima riga della voce. Lo spessore del tratto segue il `fontWeight` del segno, il colore il `color` del segno. I campi seguenti valgono solo per le voci di attività:

    <tr><td><code>verticalOffset</code></td><td><code>Dimension</code></td><td>Regolazione verticale fine del punto elenco a questo livello.</td></tr>
  </tbody>
</table>

**Cascata dei rientri.** Il livello 1 parte sempre dal valore generale di `indent` (per impostazione predefinita `0 em`: i punti elenco sono fissati al bordo della colonna). Per i livelli 2–5, se lasci `indent` non definito il motore colloca il punto elenco all’inizio del testo del livello *precedente* (rientro del livello superiore + larghezza del punto elenco + `gap`). Imposta un `indent` esplicito su un livello per interrompere la cascata e fissare quel livello dove preferisci.

```ts
unorderedLists: {
  bulletChar: '—',
  gap: { value: 0.4, unit: 'em' },
  hangingIndent: true,
  levels: [
    { level: 2, bulletChar: '·' },
    { level: 3, bulletChar: '◦', color: { hex: '#666666', model: 'hex' } },
  ],
}
```

### Personalizzazioni per livello degli elenchi numerati

Ogni voce di `levels` può ridefinire `numberFormat`, `prefix`, `separator`, `fontFamily`, `fontSize`, `color`, `fontWeight`, `italic`, `indent`, `verticalOffset` e lo stile del separatore (`separatorFontFamily`, `separatorFontWeight`, `separatorItalic`, `separatorColor`, `separatorGap`); vale la stessa cascata dei rientri degli elenchi puntati. Lo stile del separatore di un livello eredita lo stile del numero di quel livello, a meno che non sia data l’impostazione del separatore valida per tutto l’elenco.

**Allineamento a destra.** La pipeline misura il numero formattato più largo di una sequenza e fa rientrare tutte le voci di quella sequenza in modo che i numeri si allineino sul bordo destro. In un elenco di dieci voci composto come `1.` – `10.` i numeri di una cifra vengono spaziati fino ad allinearsi a destra, così il separatore resta nella stessa colonna.

```ts
orderedLists: {
  numberFormat: 'arabic',
  separator: '.',
  levels: [
    { level: 2, numberFormat: 'lower-alpha' },
    { level: 3, numberFormat: 'lower-roman', separator: ')' },
  ],
}
```

Il risultato è la classica combinazione annidata:

```
1. First item
   a. Sub-item
      i) Deep note
   b. Sub-item
2. Second item
```

La gerarchia dei documenti cinesi (GB/T 15834—2011, appendice B.3) prevede cinque livelli: 一、 poi （一） poi 1. poi （1） poi ①:

```ts
orderedLists: {
  levels: [
    { level: 1, numberFormat: 'simp-chinese-informal', separator: '、' },
    { level: 2, numberFormat: 'simp-chinese-informal', prefix: '（', separator: '）' },
    { level: 3, numberFormat: 'arabic', separator: '.' },
```

## Matematica

La proprietà `math` controlla come vengono analizzate e disegnate le formule LaTeX tra i delimitatori `$...$` (in linea) e `$$...$$` (in display). Il motore sottostante è MathJax (il pacchetto `mathjax-full`) in modalità di output SVG, rasterizzato sul canvas e incorporato nel PDF come glifi scalabili.

```ts
interface MathConfig {
  enabled?: boolean;        // Render LaTeX. When false, spans pass through as literal TeX.
  fontSizeScale?: number;   // × the surrounding text's size (the body size for display maths).
  color?: ColorValue;       // Formula colour; inherits body colour if omitted.
  marginTop?: Dimension;    // Space above display math blocks.
  marginBottom?: Dimension; // Minimum space below; baseline grid snap may enlarge it.
  indentAfterDisplay?: boolean; // Indent a paragraph that follows a display formula.
  keepWithLeadIn?: boolean; // Keep a display formula with the line that leads into it.
  equationNumbering?: {      // Number the display formulas that carry a \label.
    enabled?: boolean;           // default true
    numberingTemplate?: string;  // '{n}'; '{h1}.{n}' numbers by chapter
    resetOn?: ResourceCounterReset; // 'never' | 'h1' … 'h6'
    counterFormat?: ResourceCounterFormat; // 'decimal'
    format?: string;             // '({n})': what the formula and \eqref print
  };
}
```

```ts
math: {
  enabled: true,
  fontSizeScale: 1.0,
  color: { hex: '#295AA3', model: 'hex' },
  marginTop: { value: 1, unit: 'em' },
  marginBottom: { value: 1, unit: 'em' },
}
```

**Dimensione delle formule, cambiata in postext 1.5.** MathJax fornisce il riquadro di una formula in `ex`, e un `ex` del suo font TeX vale 0,442 em. Fino a postext 1.4 il motore lo considerava mezzo em, quindi ogni formula veniva composta circa il 13% più grande di `bodyText.fontSize × fontSizeScale`. Ora le formule escono alla dimensione documentata, e le righe e le pagine con formule si reimpaginano. Per mantenere la dimensione delle formule della 1.4, una configurazione scritta in codice per quella versione passa una sola volta per `pinLegacyMathSize` di `postext/bundle`, come qui:

```ts
import { pinLegacyMathSize } from 'postext/bundle';

config = pinLegacyMathSize(config); // formulas, and the space around display formulas, as 1.4 set them
```

Anche altri cambiamenti di regole della 1.5 possono spostare le pagine di un libro: le interruzioni dei titoli, lo spazio attorno a una figura in linea (nel testo corrente e nei riquadri), i segni in linea dei titoli, la dimensione dei capilettera, lo spazio lasciato sotto una riga che termina con i due punti per l’elenco che introduce, le righe di un paragrafo o di una voce di elenco che restano prima del taglio di un riquadro, gli a capo dopo una lineetta, la divisione in righe del testo in bandiera, la divisione di un paragrafo sotto un titolo, gli a capo dopo il trattino di una parola composta e lo spazio sotto un contenitore `:::paragraphs`. `migrateConfig`, eseguito una volta con il Markdown che la configurazione impagina, fissa quelli di cui questo testo ha bisogno, dimensione delle formule compresa (vedi [Pacchetti scritti da postext 1.4 o precedenti](/it/docs/configuration-bundles#pacchetti-scritti-da-postext-14-o-precedenti)):

```ts
import { migrateConfig } from 'postext/bundle';

config = migrateConfig(config, undefined, { content: markdown }); // heading breaks, formulas, inline gaps, heading marks, drop caps, colon lines, box cuts, dash breaks, compound breaks, ragged breaking, splits under a heading and container space as 1.4 set them
```

Così si blocca ciò che quei cambiamenti di regole sposterebbero, ma non conserva ogni pagina della 1.4. La versione 1.5 corregge anche errori di impaginazione, e una correzione non si può fissare: una configurazione vecchia la riceve come una nuova, quindi una pagina interessata può comunque spostarsi. Tra queste correzioni: un titolo a tutta larghezza della pagina senza una grafica propria viene misurato sulla larghezza della pagina e composto con l’interlinea del suo livello; nella grafica di un titolo non si riserva nulla sotto la linea di base di un capolettera; un capolettera prende il colore della tavolozza della sezione, e viene composto anche in un testo grafico il cui `overflow` non è `'wrap'`, che allora va a capo; un paragrafo in un riquadro viene disegnato con la spaziatura tra le lettere con cui è stato misurato; un riquadro diviso mantiene la colonna dell’icona su ogni frammento; una riga di riquadro che allargherebbe i suoi spazi oltre 3× viene composta in bandiera, come nel testo corrente; la leva dei paragrafi laschi non compone mai una riga giustificata più larga di quanto consenta `maxWordSpacing`; un riquadro flottante mantiene un `marginBottom` (in una fascia in alto) o un `marginTop` (in una fascia in basso) più ampio dello spazio dei flottanti; un testo grafico centrato o allineato a destra con spaziatura tra le lettere (una testatina, il titolo di un’apertura) viene collocato in base alle sue lettere, senza la spaziatura dopo l’ultima; sotto un’apertura a tutta larghezza della pagina, il testo che apre la seconda colonna comincia dove comincerebbe il testo subito sotto l’apertura, anche quando un titolo segue l’apertura; i puntini dell’indice si fermano prima del numero di pagina in un carattere che con la crenatura allontana una sequenza di punti; una testatina legge un titolo così come è scritto, senza spazio dove una delle sue righe finisce dopo un trattino o una lineetta o dentro una parola tagliata per larghezza (`MEDIOAMBIENTALES`, non `MEDIOAMBIENTALE S`), e il `{titleText}` della grafica di un titolo lo legge allo stesso modo (`thousand-colour`, non `thousand- colour`); un testo ancorato al piede o al centro della fascia della grafica di un titolo mantiene la fascia abbastanza alta da contenerlo, così non sale più sopra il testo che precede il titolo; una parola più larga della sua riga, tagliata accanto a un trattino che contiene, viene tagliata dopo quel trattino e non ne riceve un secondo; la voce che segue un elenco annidato in un altro prende l’`itemSpacing` del proprio elenco, non quello dell’elenco annidato; e il resto di una parola tagliata perché più larga della sua riga mantiene i propri punti di divisione, così un indirizzo web continua a dividersi nelle sue giunture e una parola composta ai suoi trattini invece che nelle sillabe del dizionario.

`pinLegacyMathSize` moltiplica la scala per 1,1312 (0,5 ÷ 0,442) e divide per lo stesso fattore i margini delle formule in display espressi in `em`. La sola scala non basta per un libro con formule in display: i loro margini sono lunghezze relative alla dimensione della formula stessa, quindi crescerebbero dello stesso 13% e spingerebbero in giù il testo sottostante. Scritti per esteso per i margini predefiniti, i tre valori sono:

```ts
math: {
  fontSizeScale: 1.131,
  marginTop: { value: 0.7072, unit: 'em' },
  marginBottom: { value: 0.7072, unit: 'em' },
} // formulas as large as 1.4 set them, with the space 1.4 left around them
```

Quando la configurazione proviene da un salvataggio, il motore riconosce che è vecchia e lo fa per te: `openBundle` / `readBundle` per un pacchetto `.postext` scritto prima della 1.5 (vedi [Pacchetti scritti da postext 1.4 o precedenti](/it/docs/configuration-bundles#pacchetti-scritti-da-postext-14-o-precedenti)), e la Sandbox per i libri, la copia di lavoro e i file `postext-config.json` salvati allora (vedi **Sandbox → Persistenza**). Vengono letti tramite `migrateConfig`, che fissa la dimensione (`pinLegacyMathSize`): `fontSizeScale` diventa la scala salvata (1 se non impostata) × 1,1312, e un margine delle formule in display in `em` o `rem`, che è una lunghezza relativa alla dimensione della formula stessa, viene diviso per lo stesso fattore, così lo spazio attorno a una formula in display resta quello che lasciava la 1.4 (il valore predefinito di 0,8 em diventa 0,7072 em). Un margine in un’unità di pagina (`pt`, `mm`…) resta com’è, e così una configurazione con `enabled: false` o il cui libro non contiene alcun `$`. Il vecchio libro viene allora impaginato come lo impaginava la 1.4, e la sua sezione `math` mostra la dimensione con cui è composto. Per comporre invece quel libro alla dimensione attuale, reimposta quei valori: **Formule → Scala del corpo**, *Margine sopra le formule* e *Margine sotto le formule* nella Sandbox, oppure in codice:

```ts
math: { ...config.math, fontSizeScale: 1, marginTop: undefined, marginBottom: undefined } // today's size and margins
```

**Equazioni numerate.** Una formula in display con un numero occupa tutta la sua giustezza (la colonna, o la larghezza interna del riquadro in cui si trova): l’equazione è centrata e il suo numero è allineato a destra sulla riga dell’equazione, su ogni riga numerata di un `align`. Un numero nasce da un `\label{eq:x}` (da postext 1.19): le formule con etichetta, e le righe con etichetta di un `align`, `gather`, `alignat`, `flalign` o `eqnarray`, vengono numerate in ordine di lettura secondo `equationNumbering`, a meno che una riga non contenga `\nonumber` o `\notag`. Ambienti come `equation` non vengono numerati di per sé: una formula senza etichetta non ha numero. `\tag{…}` stampa l’etichetta che gli dai, tra parentesi, e `\tag*{…}` così come è scritta; nessuno dei due viene contato, e un `\label` accanto a uno dei due gli dà un nome che i rimandi possono usare. Un’equazione numerata più larga della sua giustezza deborda a destra, come qualsiasi formula in display. (Fino a postext 1.4 una formula con `\tag` non veniva disegnata affatto; fino alla 1.18 solo `\tag` dava un numero.)

`\eqref{eq:x}` nel testo stampa il numero nel suo `format`, (3), e `\ref{eq:x}` il numero nudo; lo stesso fanno `:ref{id="eq:x"}` e `@eq:x` (vedi [Rimandi](/it/docs/document-format-notes-references#rimandi-e-ancore)), e dentro una formula `\eqref` lo stampa come testo. In un libro impaginato capitolo per capitolo il contatore prosegue dal capitolo precedente: `continuationAfter` lo porta in `LayoutContinuation.statementCounters` (`equation`), e lo schema del libro dà a ogni etichetta il suo numero (`OutlineEntry.numberLabel`), così un rimando a un’equazione di un altro capitolo ne stampa il numero.

```ts
math: {
  equationNumbering: { numberingTemplate: '{h1}.{n}', resetOn: 'h1' }, // (1.1), (1.2)… (2.1)
}
```

Il resolver e lo stripper funzionano come quelli delle altre sezioni:

```ts
import {
  DEFAULT_MATH_CONFIG,
  resolveMathConfig,
  stripMathDefaults,
} from 'postext';

const resolved = resolveMathConfig(config.math);
const minimal  = stripMathDefaults(config.math);
```

### Avviare il motore matematico

MathJax viene caricato su richiesta, non insieme al resto del motore. Quando impagini nel thread principale, avvialo prima di costruire un documento che contiene formule:

```ts
import { buildDocument, initMathEngine, renderPage } from 'postext';

await initMathEngine(); // loads MathJax once; later calls resolve at once
const doc = buildDocument({ markdown: 'Euler: $e^{i\\pi}+1=0$.' }, config);
document.body.append(renderPage(doc.pages[0], doc));
```

- **Finché il motore non è avviato, le formule sono segnaposto.** Ognuna viene impaginata come un riquadro grigio di dimensione stimata. Se un documento con formule viene impaginato senza che `initMathEngine()` sia mai stato chiamato, la console mostra un avviso che lo segnala.
- **Il worker di impaginazione lo avvia per te.** Una build in `postext/worker` chiama da sé `initMathEngine()` quando il Markdown contiene un `$`.
- **Impagina subito, e di nuovo quando è pronto.** `isMathReady()` dice se il motore è in funzione. `onMathReady(fn)` chiama `fn` appena lo è (subito, se lo è già) e restituisce una funzione che annulla la chiamata. Un editor può mostrare subito i segnaposto e impaginare di nuovo quando arriva MathJax; mentre `initMathEngine()` è in corso non viene stampato alcun avviso.
- **Errori.** La promessa di `initMathEngine()` viene rifiutata quando MathJax non si può caricare, e una chiamata successiva riprova.
- **Qualsiasi bundler, Node o una CDN.** MathJax è incluso nel pacchetto come un unico modulo già impacchettato (circa 1,8 MB prima della compressione, scaricato solo da `initMathEngine`). Il semplice `import { initMathEngine } from 'https://esm.sh/postext'` funziona; non serve `?bundle`. Il pacchetto `mathjax-full` serve solo a compilare postext, quindi installare postext non lo installa. MathJax e il parser mhchem che include sono distribuiti con licenza Apache-2.0: le loro note e il testo della licenza sono distribuiti accanto al modulo, come `dist/math/THIRD_PARTY_LICENSES.txt`.
- **Un solo motore per pagina.** Il motore e la sua cache delle formule già disegnate sono condivisi da tutto ciò che importa `postext` nello stesso realm JavaScript (vedi [Stato globale condiviso in una pagina](/it/docs/configuration-programmatic-usage#stato-globale-condiviso-in-una-pagina)).

Per la grammatica lato documento (`$...$`, `$$...$$`, l’escape di un dollaro letterale), vedi [Formato del documento](/it/docs/document-format-inline#formule-matematiche).
