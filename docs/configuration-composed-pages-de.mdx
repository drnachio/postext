# Konfiguration: zusammengesetzte Seiten


## Seitenvorlagen

Eine zusammengesetzte Seite ist eine Seite, deren Form aus einer **Seitenvorlage** der Konfiguration stammt und deren Inhalt aus dem Markdown eines Seitenblocks stammt, des Blocks `::::page{template="…"}`, der mit vier Doppelpunkten beginnt. Die Vorlage legt benannte Rechtecke fest, die **Rahmen** heißen; das Markdown weist jedes Inhaltsstück über dessen Namen (den Slot) einem Rahmen zu. Geometrie steht nie im Markdown, und Inhaltstext steht nie in der Vorlage. Die Eigenschaft `pageTemplates` enthält die Vorlagen des Buchs:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

### Rahmen

Ein Rahmen ist ein benanntes Rechteck, das gesetzten Inhalt aufnimmt. Sein `name` ist der Slot, den das Markdown anfordert, und er ist in seiner Vorlage eindeutig (auch eine Gruppe kann nicht den Namen eines Rahmens tragen, da Verankerungen wie `'#name'` beide auf dieselbe Weise ansprechen).

Ein Rahmen wird über seine Rasterzelle (`grid`) platziert, wenn die Vorlage ein Raster hat, sonst über sein `placement`, das wie das eines Gestaltungselements funktioniert: ein Bezugspunkt (`'container'` ist der Bereich, `'page'`, `'bleed'` oder `'#name'` für einen anderen Rahmen oder eine Gruppe), eine Kante, ein Versatz und eine Größe. Ein Rahmen, der an einem anderen verankert ist, bewegt sich mit ihm. Ohne beides beginnt der Rahmen in der oberen linken Ecke des Bereichs, ist so breit wie der Bereich und so hoch, wie seine Höhenregel es vorgibt. Wie der Inhalt in die Rahmen fließt, wie Rahmen verkettet und wie sie beschnitten werden, beschreibt [Zusammengesetzte Seiten › Wie die Seite gesetzt wird](/de/docs/composed-pages#wie-die-seite-gesetzt-wird).

### Gruppen

Eine Gruppe ist ein Stapel (von oben nach unten) oder eine Reihe (vom Anfang zum Ende) von Rahmen, die sich Platz teilen und sich gemeinsam bewegen. Innerhalb einer Gruppe wird die eigene Position der Rahmen in Richtung der Gruppe ignoriert: Die Gruppe ordnet sie der Reihe nach an, mit `gap` dazwischen. Wenn der Text eines Rahmens wächst, rücken die Rahmen danach weiter. Eine Gruppe ist ein Rechteck, an dem Rahmen und Dekoration verankert werden können (`'#pagina'`).

### Wie Gruppen den Platz teilen

Ein Rahmen gibt seine Größe an: eine feste `height` oder `'auto'`, die Höhe seines Inhalts, gehalten zwischen `minHeight` und `maxHeight`. Ist eine Vorlage einer gedruckten Seite nachgezeichnet, bekommt jeder Kasten als `minHeight` die Höhe, die er auf dieser Seite hat: Bei einem kurzen Text bleibt der Kasten so, wie er gezeichnet ist, ein längerer Text macht ihn höher. Die Seite wird im selben Durchgang zweimal angelegt, einmal so, wie die Vorlage sie angibt, und einmal so, wie ihr Inhalt es verlangt; was sich zwischen beiden Fassungen unterscheidet, hält das [Umbruchprotokoll](/de/docs/composed-pages#umbruchprotokoll) fest.

**Stapel.** Die Rahmen eines Stapels stehen in ihrer jeweiligen Höhe untereinander, mit `gap` dazwischen. Jeder behält seine eigene waagerechte Lage und seine Breite; seine eigene senkrechte Lage wird ignoriert.

- Eine Gruppe ohne eigenes `placement` oder `grid` beginnt dort, wo ihr erster Rahmen platziert ist (sein `placement`, oder seine `grid`-Zelle in einer Vorlage mit Raster), und reicht so weit nach unten, wie ihre Rahmen es brauchen, höchstens bis zum Fuß des Bereichs der Vorlage. Wächst ein Rahmen, rücken die Rahmen nach ihm um dasselbe Maß nach unten.
- Eine Gruppe mit eigenem Rechteck legt ihre Rahmen in dieses Rechteck. Brauchen sie mehr Platz, als es bietet, geben die Rahmen mit `shrink` über 0 Platz ab, die mit der niedrigsten `priority` zuerst; Rahmen derselben Priorität geben im Verhältnis ihres `shrink` nach, und keiner wird niedriger als sein `minHeight`. Freier Platz geht an die Rahmen mit `grow` über 0, im Verhältnis zu diesem Wert und bis zu ihrem `maxHeight`; hat kein Rahmen `grow`, verteilt `align` die Rahmen (`'end'` am Fuß, `'center'`, `'space-between'`). Ein Rahmen der Gruppe ohne eigene Platzierung nimmt das Rechteck der Gruppe als seinen Bereich.
- Kann nichts mehr nachgeben, geben zuerst die Rahmen nahe dem Fuß der Gruppe nach, jeder bis auf seine `minHeight`; ein Rahmen mit fester Höhe behält sie, sodass ein leeres Antwortfeld oder ein Bildplatz unter einem wachsenden Kasten auf der Seite bleibt und der Text des Kastens nachgibt. Kein Rahmen läuft über den Fuß der Gruppe hinaus: Der Rahmen, dessen Inhalt nicht passt, durchläuft die Einpassstufen (siehe [Wenn der Inhalt nicht passt](#wenn-der-inhalt-nicht-passt)), und was dann noch nicht passt, wird dort abgeschnitten und als `frameOverflow` gemeldet. Ein Rahmen, der unter seine `minHeight` oder seine feste Höhe gekürzt wird, wird ebenfalls gemeldet, ob er Inhalt hat oder nicht.
- Ein Rahmen mit `height: 'fill'` verlangt sein `minHeight` und nimmt freien Platz, als hätte er `grow: 1`.

**Reihe.** Die Rahmen einer Reihe stehen in ihren angegebenen Breiten nebeneinander und sind alle so hoch wie die Reihe: so hoch wie das Rechteck der Gruppe oder, wenn die Gruppe kein eigenes Rechteck hat, wie die größte Höhe, die ihre Rahmen angeben: eine feste `height`, sonst eine `minHeight` (ein `'auto'`-Rahmen gibt nicht mehr an), oder, wenn sie keine angeben, wie der höchste Inhalt (ein Rahmen mit fester Höhe behält seine). Läuft der Text eines Rahmens über die Höhe der Reihe hinaus, holt sich der Rahmen Breite: zuerst die freie Breite der Reihe, dann Breite von Nachbarn mit `shrink` über 0, die mit der niedrigsten `priority` zuerst, wobei kein Nachbar schmaler wird als die Breite, in die sein eigener Text noch passt. Der Rahmen nimmt so wenige ganze Millimeter, wie sein Text zum Passen braucht; reicht selbst der gesamte verfügbare Platz nicht, nimmt er gar nichts, und eine Reihe ohne eigenes Rechteck wird stattdessen höher. Karten mit `height: 'auto'` und einer `minHeight` teilen sich so die Breite in dieser Höhe, und die Reihe wächst erst, wenn keine Karte Breite abgeben kann. Freie Breite geht an die Rahmen mit `grow` über 0, was dann noch bleibt, verteilt `align`. Reihen laufen von links nach rechts.

**Fixierte Rahmen.** Ein Rahmen mit `pin: true` behält das Rechteck, das die Vorlage für ihn angibt, auch wenn der Rahmen, an dem er verankert ist, wächst oder sich verschiebt: Ein Kasten, der passend zur Illustration gezeichnet ist, bleibt auf ihr liegen. In einer Gruppe behält ein fixierter Rahmen seinen Platz, und die übrigen Rahmen weichen ihm aus, mit `gap` auf beiden Seiten. Ein fixierter Rahmen außerhalb der Gruppe wirkt ebenso auf die Rahmen der Gruppe, die ihn sonst überdecken würden.

**Dekoration.** Ein Dekorationselement, das an einem Rahmen verankert ist (`anchor: { to: '#dinero' }`), bewegt sich mit, wenn der Rahmen wächst oder sich verschiebt. Ein Element mit `pin: true` bleibt dort, wo die Vorlage diesen Rahmen zeichnet.

Die drei Kästen einer Schulbuchseite, jeder so hoch, wie er gezeichnet ist, und jeder wächst mit seinem Text:

```ts
frames: [
  { name: 'dinero', style: 'caja-azul', width: { value: 186, unit: 'mm' }, minHeight: { value: 36, unit: 'mm' },
    placement: { anchor: { to: '#texto', edge: 'below' }, offset: { y: { value: 9, unit: 'mm' } } } },
  { name: 'dinero-fotos', layer: 2, width: { value: 58, unit: 'mm' },
    placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
  { name: 'gasto', style: 'caja-verde', width: { value: 186, unit: 'mm' }, minHeight: { value: 62, unit: 'mm' } },
  { name: 'ahorro', style: 'caja-amarilla', width: { value: 186, unit: 'mm' }, minHeight: { value: 30, unit: 'mm' } },
],

Das Ergebnis hängt nur vom Inhalt der Seite, von der Vorlage und von der Typografie ab: Aus derselben Eingabe entsteht dieselbe Seite, in derselben Reihenfolge und mit denselben Schritten gemessen. Bei der Aufteilung des Platzes wird nie eine andere Seite berücksichtigt. Eine Änderung auf einer zusammengesetzten Seite lässt deshalb alle anderen Seiten unverändert, solange der Inhalt auf seiner Seite bleibt.

**Rahmen am Fuß einer Karte halten (seit postext 1.42).** Ein Rahmen, der unter dem Text über ihm verankert ist, folgt diesem Text: In einer Ausgabe, in der der Text eine Zeile kürzer oder länger ist, rücken die Rahmen darunter nach oben oder unten, während das, was die Vorlage zeichnet (eine Karte, ein Band, der Fuß), stehen bleibt. Damit Rahmen am Fuß einer Karte bleiben, dort, wo die Vorlage sie hinsetzt, fassen Sie die Rahmen der Karte zu einem Stapel mit einem Rechteck in der Höhe der Karte zusammen. Die Rahmen über den gehaltenen nehmen den übrigen Platz (`grow: 1`) und geben ihn zurück (`shrink: 1`); die gehaltenen legen ein `minHeight` fest. Ein kürzerer Text lässt die gehaltenen Rahmen, wo sie waren. Ein längerer wird über ihnen zusammengedrückt: Sie behalten ihr `minHeight`, der Text darüber wird verkleinert, und passt er dann immer noch nicht, meldet das Layout `frameOverflow`, und das Umbruchprotokoll führt `textScaled` und `overflow` für den Rahmen darüber auf. Ein am Fuß des Containers verankerter Rahmen (`bottom-left`) behält zwar auch seinen Platz, aber nichts verbindet ihn mit den Rahmen darüber: Ein längerer Text läuft über ihn, seinetwegen wird nichts zusammengedrückt, und die Überlagerung wird nicht gemeldet.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

Der wachsende Rahmen ist so hoch wie der freie Platz, was auch immer er enthält; ein Stil mit sichtbarem Hintergrund würde ihn ganz ausfüllen. Zeichnen Sie die Karte daher in der Dekoration der Vorlage und lassen Sie den Textrahmen ohne Stil.

### Raster, die einen Rahmensatz wiederholen

Eine Seite mit Fotokarten, eine Seite mit Aufgabenkarten oder eine Seite mit Porträts und einem Namen unter jedem ist dieselbe Karte, viele Male gezeichnet. Eine Rastergruppe mit `repeat` zeichnet sie einmal in der Vorlage: die Rahmen einer Karte, der Rahmensatz, den das Raster einmal je Eintrag setzt, den das Markdown der Seite ihm gibt. Wie viele Karten eine Seite hat, entscheidet dann das Markdown, und eine Übersetzung, die eine Karte hinzufügt, braucht keine neue Vorlage. Seit postext 1.48.

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **Der Satz.** Der erste Rahmen von `repeat.frames` ist der **Hauptrahmen** der Zelle: Er nimmt die Breite der Zelle an und behält seine eigene Höhenregel (`'auto'` ist die Höhe seines Inhalts, zwischen `minHeight` und `maxHeight`). Die übrigen Rahmen des Satzes werden so gesetzt, wie die Vorlage sie zeichnet, am Hauptrahmen oder aneinander verankert: Hier hängt das Etikett mit der Legende am Fuß des Fotos. Ein Rahmen des Satzes, der an einem Rahmen außerhalb des Satzes verankert ist, bleibt dort, wo dieser Anker ihn hinsetzt.
- **Einträge.** Jeder Teil `:::frame{slot="foto"}` der Seite ist ein Eintrag: Teile eines wiederholten Slots werden nicht aneinandergefügt. Innerhalb des Teils kommt ein Block, der ein Mitglied des Satzes nennt (`:::frame{slot="pie"}`, `::resource{… slot="pie"}`), in dieses Mitglied derselben Karte; der Rest kommt in den Hauptrahmen. Siehe [Zusammengesetzte Seiten › Wiederholte Slots](/de/docs/composed-pages#wiederholte-slots).
- **Instanzen.** Die Rahmen jeder Karte heißen `<frame>[n]`, ab 1 gezählt: `foto[2]` und `pie[2]` sind die zweite Karte. Warnungen, das Umbruchprotokoll, die Quellenzuordnung und die Sandbox verwenden diese Namen, die Rahmen-IDs sind `cp<n>:foto[2]`, und ein Dekorationselement oder ein Verbinder kann sich an `'#foto[2]'` verankern. Das `to: '#foto[*]'` eines Verbinders erreicht jede Karte, die die Seite hat. Ein an `'#foto'` verankertes Element liest das Rechteck des Rasters.
- **Zellen.** Die Zellen füllen die Reihen von der Anfangsseite aus; auf einer Seite von rechts nach links steht die erste Karte also rechts. Eine Reihe ist so hoch wie ihre höchste Zelle, einschließlich dessen, was über dem Hauptrahmen (ein Etikett) und unter ihm (eine Legende) hängt; `rowAlign` platziert die niedrigeren. Das Rechteck des Rasters ist sein eigenes `placement` oder seine `grid`-Zelle; ohne beides beginnt es dort, wo die Vorlage den Hauptrahmen zeichnet, und reicht bis zur rechten Kante und zum Fuß des Bereichs.
- **Wenn die Karten nicht passen.** Eine Reihe jenseits des Fußes des Rasters wird dort abgeschnitten, jede Karte durchläuft die Einpassstufen für sich, und die letzte abgeschnittene Karte meldet `frameOverflow`. Mit `overflow.continueIn` am Hauptrahmen (`'next-page'`, `'template:<id>'`) läuft das Raster **in ganzen Reihen** weiter: Die erste Reihe, die nicht passt, und jede Reihe danach werden auf der hinzugefügten Seite gesetzt, im Raster einer Vorlage, die denselben Rahmensatz wiederholt. Eine Zelle, die höher ist als das ganze Raster, löst eine Warnung aus, statt endlos weiterzulaufen.
- **`max`.** Die Einträge jenseits von `repeat.max` kommen in den Flussrahmen oder, wenn die Vorlage keinen hat, hinter die Seite, und jeder löst `repeatOverflow` aus.

Ein Raster ohne `repeat` setzt die Rahmen, die es aufführt, je einen pro Zelle, in der geschriebenen Reihenfolge. Ein Rahmen eines wiederholten Satzes, der in einer anderen Gruppe aufgeführt ist, wird dort übersprungen (`groupFrameTwice`), und ein Name, den die Vorlage nicht hat, ist `groupFrameUnknown`. `grow` und `shrink` gelten nicht für die Reihen eines Rasters, `redistribute` nicht für seine Karten.

### Module

Eine Schulbuchseite stapelt oft Blöcke, die im Buch in anderer Reihenfolge wiederkehren: ein Kasten mit einem Foto daneben, ein Baum aus drei Gedanken, ein Raster aus vier Fotos unter einer Überschrift. Für jede Reihenfolge eine Vorlage zu zeichnen, vervielfacht die Vorlagen. Ein **Modul** ist einer dieser Blöcke, einmal gezeichnet: eine Vorlage mit `role: 'module'`, die Rahmen, Gruppen und Dekoration enthält (Verbinder eingeschlossen) und keine eigene Seite hat. Eine Seitenvorlage nimmt Module in einer Gruppe mit `modules: true` auf; das Markdown der Seite sagt, welche Module sie enthält und in welcher Reihenfolge (siehe [Zusammengesetzte Seiten › Module auf einer Seite](/de/docs/composed-pages#module-auf-einer-seite)). Seit postext 1.48.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **Was ein Modul hat.** Rahmen, Gruppen (auch ein Raster, das sich wiederholt), Dekoration und Verbinder. Es hat kein `area`, `header`, `footer`, `variants`, `spread`, `gutter` oder `overflowTemplate`: Jedes davon wird als `unknownConfigValue` gemeldet und ignoriert. `extends` funktioniert zwischen Modulen (eine Vorlage, die ein Modul erweitert, ist ein Modul).
- **Sein Rechteck.** Ein Modul ist so breit wie seine Gruppe und so hoch, wie seine Rahmen reichen; die Gruppe stapelt die Module von ihrer Oberkante an, mit `gap` dazwischen. Innerhalb eines Moduls ist `'container'` das Rechteck des Moduls, für seine Rahmen (auch `'fill'` und Prozentangaben) und für seine Dekoration: Ein Grund mit der Größe `{ to: 'container', edge: 'bottom' }` bedeckt das Modul, welche Höhe ihm seine Wörter auch geben.
- **Namen.** Die Rahmen, Gruppen und Elemente eines Moduls gelten im Bereich des Instanznamens des Moduls: `<name>.<frame>`, mit dem Namen, den das Markdown gibt (`name="ramas"`), sonst `<template>[n]`, die laufende Nummer des Moduls unter den Modulen dieser Vorlage auf der Seite (`arbol[2].raiz`). Anker, `next`, `continueIn: '#x'` und Verbinder innerhalb eines Moduls werden auf seine eigenen Rahmen umgeschrieben, sodass zwei Bäume auf einer Seite nie ineinanderlaufen. Eine Rahmen-ID lautet `cp0:arbol[2].raiz`.
- **Wenn Module nicht passen.** Ein Modul jenseits des Fußes der Gruppe wird dort abgeschnitten, und seine Rahmen durchlaufen die Einpassstufen; `frameOverflow` wird einmal für die Gruppe ausgelöst. Mit `overflow.continueIn` an der Modulgruppe (`'next-page'` oder `'template:<id>'`) laufen das erste Modul, das nicht passt, und jedes Modul danach **als Ganzes** auf der hinzugefügten Seite weiter, unter denselben Namen, oben in der Modulgruppe dieser Seite. In einer Modulreihe oder einem Modulraster geht eine Reihe ganz weiter: Ihre Module werden nie auf zwei Seiten verteilt.
- **Nebeneinander.** Eine Modulgruppe mit `kind: 'row'` setzt ihre Module vom Anfang zum Ende, jedes so breit wie die `width` seiner Vorlage (eine Länge, `{ percent: 48 }` oder `'fill'`, ein gleicher Teil des Rests), die Reihe so hoch wie ihr höchstes Modul; `kind: 'grid'` setzt sie in `columns` gleiche Spalten, Reihe für Reihe. `rowAlign` platziert ein Modul, das niedriger als seine Reihe ist. Reihen beginnen auf der Seite, auf der die Zeile beginnt: Eine Seite von rechts nach links setzt das erste Modul rechts. Seit postext 1.50.
- **Gruppen im Stapel.** Eine Modulgruppe mit `within: '<Stapel>'` liegt im Modulstapel der Seite, und `templates` sagt, welche Module sie aufnimmt: Jede Folge davon im Markdown bildet eine Reihe oder ein Raster des Stapels, dort, wo ihr erstes Modul steht. Mit den Gruppen unten ergeben zwei `aviso`-Blöcke, gefolgt von vier `tarjeta`-Blöcken, eine Reihe aus zwei Kästen über einem Raster aus 2 × 2 Karten, und das Markdown enthält nur `:::module`-Blöcke.
- **Gruppen in Gruppen.** Seit postext 1.51 kann `within` jede Modulgruppe nennen, auch eine Reihe oder ein Raster, beliebig tief. Mit `banda` als Reihe in `cuerpo` und `columna` als Stapel in `banda` steht ein Kasten mit zwei folgenden Karten neben einer Spalte aus den beiden Karten. Ein Rahmen der Seite, der an `#banda` verankert ist, wird nach den Modulen gesetzt.
- **Eine Reihe teilen.** Seit postext 1.51 geht der Platz, den eine Modulreihe lässt, nach dem `grow` jedes Moduls, und eine Reihe, die breiter als ihre Gruppe ist, gibt nach `shrink` Breite ab.
- **Noch nicht.** Ein Modul in einem Modul (`moduleNested`) und `grid`-Zellen der Vorlage in einem Modul.

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### Wenn der Inhalt nicht passt

Ist der Inhalt eines Rahmens höher als der Platz, den ihm seine Gruppe gibt, probiert das Layout der Reihe nach die [Einpassstufen](/de/docs/composed-pages#wenn-der-inhalt-immer-noch-nicht-passt) durch und hört bei der ersten auf, mit der er passt: freier Platz bis `maxHeight`, die Gruppe, die schiebt und nachgibt, kleinere Bilder, die übrigen Rahmen der Gruppe bis auf ihr Minimum, kleinerer Text, Fortsetzung auf einer anderen Seite. Diese Rahmeneinstellungen bestimmen, wie weit jede Stufe gehen darf:

- `maxHeight` an einem Rahmen mit fester `height`: Bis dahin darf der Rahmen wachsen, bevor irgendetwas verkleinert wird.
- `minHeight` an den übrigen Rahmen der Gruppe: wie weit sie Platz abgeben; ein Rahmen wird nie kleiner als das, was sein eigener Inhalt braucht.
- `fit.scaleImages` und `fit.imageMinScale`: ob die Bilder des Rahmens und seiner Gruppe kleiner gesetzt werden dürfen, und bis zu welchem Maßstab (standardmäßig 80 %).
- `fit.shrinkText` und `fit.minScale`: ob der Text des Rahmens kleiner gesetzt werden darf, und bis zu welchem Maßstab (standardmäßig 90 %). Der Maßstab gilt gleichermaßen für Schriftgröße, Zeilenabstand und Abstände; der Rahmen behält seine Größe.
- `overflow.continueIn`: wo der Inhalt weitergeht, wenn all das nicht reicht, in einem anderen Rahmen oder auf einer anderen Seite (`'next-page'`, `'template:<id>'`, `'page:<id>'`); dort läuft der Text nach der `overflow.mark` des Teils in voller Größe weiter. Ein Rahmen, der auf einer anderen Seite weiterlaufen kann, tut das, bevor seine Bilder und sein Text kleiner gesetzt werden, es sei denn, sein `fit.preferContinue` ist `false`.

Die Maßstäbe gehen in Schritten von 2,5 %, und das Layout nimmt den größten, der passt: Ein Text, der eine Zeile zu lang ist, wird mit 97,5 % gesetzt, nicht mit dem Minimum. Ein Kasten, der seinen Schriftgrad behalten muss, setzt `fit: { shrinkText: false }`; eine Seite, deren Bilder ihre Größe behalten müssen, setzt `fit: { scaleImages: false }` an den Rahmen ihrer Gruppe:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

Was dann noch nicht passt, wird als `frameOverflow` gemeldet, mit den versuchten Stufen und Vorschlägen, die ihre Werte mitbringen: siehe [Die Warnung und ihre Vorschläge](/de/docs/composed-pages#die-warnung-und-ihre-vorschläge).

### Vererbung und Varianten

Eine Vorlage mit `extends` geht von der Vorlage aus, die sie angibt (und die selbst eine andere erweitern kann), und ändert nur, was sie selbst festlegt:

- Ein Feld wie `area`, `header` oder `overflowTemplate` ersetzt das der Elternvorlage. `grid` wird Schlüssel für Schlüssel zusammengeführt. Auch `spread`, `gutter` und `role` werden geerbt; `id`, `name` und `extends` gehören der Vorlage selbst.
- `frames` und `groups` werden **nach Namen** zusammengeführt: Ein Eintrag mit dem Namen eines geerbten ändert die Felder, die er angibt, und behält die übrigen (`fit`, `overflow` und `padding` werden Schlüssel für Schlüssel zusammengeführt; `placement` wird als Ganzes ersetzt); `remove: true` entfernt ihn; ein neuer Name wird nach den geerbten angefügt.
- Dekorationselemente werden auf dieselbe Weise nach `id` zusammengeführt; ein Element mit neuer ID oder ohne ID wird angefügt. Seit postext 1.42 nimmt `{ id: 'kopf-gerade', remove: true }` in `decoration.elements` einer Kindvorlage oder Variante das geerbte Element mit dieser `id` heraus, wie `remove: true` es bei einem Rahmen tut; eine `id`, die die Vorlage nicht erbt, ändert nichts. Ein neues Element mit derselben `id` kann der Entfernung in derselben Liste folgen.

`variants.recto` und `variants.verso` werden wie eine Vorlage geschrieben und auf dieselbe Weise zusammengeführt, auf einer rechten oder einer linken Seite. Sie gelten nach der ganzen `extends`-Kette, die Variante der Wurzel zuerst. Eine Doppelseite hat beide Seiten, daher gilt für sie keine Variante.

Ein Element in `variants.recto` mit `parity: 'even'` oder in `variants.verso` mit `'odd'` wird nie gezeichnet: `unknownConfigValue`.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Ein Wert, der einem Standardwert gleicht, wird beim Speichern einer Vorlage in der Sandbox nie verworfen: In einer Vorlage, die eine andere erweitert, oder in einer Variante überschreibt er den Wert der Elternvorlage.

Im Code liefert `resolvePageTemplate(config, id, { parity })` eine Vorlage mit zusammengeführter Kette, angewandter Variante der jeweiligen Seite, allen eingesetzten Standardwerten und jedem Verweis so aufgelöst, wie es die Warnungen unten beschreiben; `validatePageTemplates(config)` liefert die Warnungen.

### Gezeichnet, wenn die Seite es sagt

Ein Element der Dekoration und ein Element von `header` oder `footer` der Vorlage kann `when` oder `unless` tragen, jeweils mit dem Namen eines Attributs des Seitenblocks. `when: 'folio'` zeichnet das Element nur auf Seiten, deren Block `folio` setzt; `unless: 'frontmatter'` lässt es auf Seiten weg, deren Block `frontmatter` setzt. Ein Block setzt ein Attribut, wenn er es allein schreibt (`::::page{template="pagina" frontmatter}`) oder mit einem Wert außer `false`. So dient eine Vorlage der Titelei, die weder Seitenzahl noch Band druckt, und den Textseiten, die beides drucken: Das Markdown sagt, was die Seite ist, die Vorlage behält die Zeichnung. Seit postext 1.50.

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- Ein Element, das an einem weggelassenen Element verankert ist oder dessen Größe bis zu ihm reicht, fällt ebenfalls weg.
- Mit beiden Schlüsseln wird das Element dort gezeichnet, wo der Block das Attribut von `when` setzt und das von `unless` nicht.
- Die Kopf- und Fußzeilen des Dokuments und die eines Abschnitts lesen sie ebenso. Eine Seite, die nicht zusammengesetzt ist, hat keinen Seitenblock und setzt nichts. Überschriften-, Teil- und Kastengestaltungen beachten sie nicht.
- Ein Wert, der kein nicht leerer Text ist, oder einer in einer Überschriften-, Teil- oder Kastengestaltung, wird als `unknownConfigValue` gemeldet, und das Element wird gezeichnet, als hätte es keinen. `postext check` fügt einen Hinweis hinzu, `conditionNeverMet`, für ein `when` oder `unless` mit einem Attribut, das keine Seite des Buchs setzt: Dieses Element wird nie gezeichnet, oder immer. Ebenso ein `{attr.x}`, das nichts setzt: Es bleibt leer.
- Nach dem Umbruch wird eine Seite, die nichts von einer Pagina oder einem Kolumnentitel zeichnet (ein Text aus `header` oder `footer`, ein Text der Dekoration, der `{pageNumber}`, einen lebenden Namen oder `{attr.x}` liest), den die meisten Seiten ihrer Vorlage auf derselben Buchseite zeichnen, als `folioMissing` gemeldet, mit Seite, Vorlage und Element. Eine Seite, deren Block das Element abschaltet oder deren Vorlage kein solches Element hat, zählt nicht mit. Seit postext 1.53.
- In der Sandbox hat jede Elementkarte einer Kopf- oder Fußzeile und der Dekoration einer Vorlage die Felder **Gezeichnet, wenn die Seite es sagt** und **Nicht gezeichnet, wenn die Seite es sagt**; zur Wahl stehen die Attribute, die die Seitenblöcke des Buchs verwenden.

### Was der Umbruch umsetzt

Der Umbruch setzt Platzierung und Größen jedes Rahmens um (Raster, Verankerungen, `min`/`max`, `verticalAlign`), seinen Stil und sein `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (samt `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) mit `overflow.mark` und `overflow.fromMark` und sein `fit` (das Verkleinern von Text und Bildern in den Einpassstufen, siehe [Wenn der Inhalt nicht passt](#wenn-der-inhalt-nicht-passt)); die Raumverteilung in einer Gruppe (`grow`, `shrink`, `priority`, `pin` sowie `gap` und `align` der Gruppe, siehe [Wie Gruppen den Platz teilen](#wie-gruppen-den-platz-teilen)); dazu `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` und `overflowTemplate` der Vorlage. Seit postext 1.42 setzt er auch die `palette` der Vorlage, den `look` eines Rahmens und die Breite `'auto'` um (so breit wie die längste Zeile des Rahmens). `writingMode` und `direction` eines Rahmens werden seit postext 1.39 umgesetzt. Seit postext 1.48 setzt er Rastergruppen und ihr `repeat` um, Modulgruppen und Modulvorlagen, Verbinder und Pfadelemente in der Dekoration sowie das `overlap` eines Rahmens. Gelesen und geprüft, aber noch nicht umgesetzt wird `bodyStyle` der Vorlage.

### Doppelseiten

In einer Doppelseitenvorlage beziehen sich alle Koordinaten auf das Blatt aus ihren beiden Seiten, mit dem Bund in der Mitte: `area`, `grid`, Verankerungen an `container`, `page` und `bleed` sowie die Größe `fill` lesen die doppelte Breite. `bleed` reicht an Kopf, Fuß und beide Außenränder, nie an den Bund. Die doppelseitige Zeitleiste eines Schulbuchs ist eine einzige Vorlage:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2 bis era-6, je eine Spalte des Rasters, und die Notizen unter dem Streifen
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Ein Spaltenabstand, der breiter ist als der `gutter`, hält die Karten eines symmetrischen Rasters vom Bund fern, sodass keine verschoben wird. Das zweite Band und der Bildstreifen setzen `crossGutter`, um ihn zu überqueren: Jedes gehört zu der Seite, die seine Mitte enthält, und wird auf beiden gezeichnet. Jedes Wort der Seite, auch die Namen der Zeitalter auf den Etiketten, bleibt im Markdown.

In einem senkrecht gesetzten Buch (`vertical-rl`) wird eine Doppelseite im Flussrahmen der Seiten gesetzt, wie seine einzelnen zusammengesetzten Seiten: Die Oberkante einer Seite ist der rechte Rand des Blatts, und die Zeilen laufen nach unten, sodass das `x` der Vorlage das Blatt hinunterläuft und ihr `y` vom rechten Rand des Blatts zum linken. Das Blatt besteht aus der rechten Seite, gefolgt von der linken entlang `y`; der Bund ist eine Linie quer durch die Vorlage, und `gutter`, `crossGutter` und der Schnitt zwischen den Seiten beziehen sich auf diese Achse. Die Dekoration wird weiterhin auf das physische Blatt gesetzt und am Bund geschnitten. Eine waagerechte Zeitleiste, die für ein waagerecht gesetztes Buch gezeichnet ist, erscheint in einem senkrechten gedreht: Legen Sie die Vorlage eines senkrecht gesetzten Buchs im Rahmen seines Textflusses an. Seit postext 1.38. Eine Karte, die quer über den Bogen gelesen werden soll, bekommt `writingMode: 'horizontal-tb'`: Sie wird waagerecht gesetzt und steht aufrecht auf der senkrechten Seite (seit postext 1.39).

### Verbinder

Ein Verbinder ist eine Linie der Dekoration, die Rahmen verbindet: die Äste eines Baumdiagramms, ein Organigramm, die Lote einer Zeitleiste, die Pfeile eines Flussdiagramms, der Zeiger einer Notiz auf einen Ort einer Karte. Er wird gesetzt, nachdem die Rahmen ihre endgültigen Rechtecke haben; er folgt also einem Text, der wächst, einer Ausgabe mit längeren Wörtern oder einer Gruppe, die ihre Rahmen verschiebt, und er wird in jedem Ausgabeformat als Vektorlinie gezeichnet, sodass die Vorlage kein Bild der Linien braucht. Verbinder sind Elemente der `decoration` einer Seitenvorlage oder eines Moduls; Kolumnentitel und Überschriftengestaltungen haben keine Rahmen, die sich verbinden ließen, und ein Verbinder dort wird gemeldet (`unknownConfigValue`) und nicht gezeichnet. Seit postext 1.48.

```ts
decoration: {
  elements: [
    { kind: 'connector', id: 'ramas', routing: 'tree', radius: { value: 2, unit: 'mm' },
      width: { value: 1.25, unit: 'pt' }, from: { to: '#raiz' }, to: [{ to: '#a' }, { to: '#b' }], endCap: 'arrow' },

Bleibt kein `from` oder kein `to` übrig, wird nichts gezeichnet.

**Zeichnen.** Verbinder werden als Vektorpfade gezeichnet: im Canvas, im PDF, im HTML-Betrachter und im EPUB mit festem Layout, und als Layout-Artefakt in einem getaggten PDF; das umfließende EPUB lässt sie mit der übrigen Dekoration weg. Ein Verbinder mit einem `anchor`-Ende wird über allen Rahmen der Seite gezeichnet, sodass eine Linie, die in ein Bild zeigt, ohne `layer` über dem Rahmen des Bilds sichtbar ist; die übrigen Verbinder bleiben bei der Dekoration, unter den Rahmen. `over: true` hebt eine Linie zwischen Rahmen darüber, `over: false` hält eine zeigende Linie darunter. Auf einer Doppelseite überquert ein Verbinder zwischen Rahmen beider Seiten den Bund und wird dort wie die übrige Dekoration geschnitten; auf einer Seite von rechts nach links folgen `start` und `end` dem gespiegelten Fluss.

```ts
frames: [
  { name: 'mapa', width: { value: 118, unit: 'mm' } },
  { name: 'nota', style: 'nota', width: { value: 44, unit: 'mm' } },
],
decoration: { elements: [
  { kind: 'connector', id: 'a-lago', from: { to: '#nota', side: 'end' },
    to: { to: '#mapa', anchor: 'lago', gap: { value: 1.2, unit: 'mm' } }, endCap: 'dot' },
] },
```

**Prüfungen.** Ein Ende, dessen `to` nichts nennt, ist `frameAnchorUnknown` (an `…/from/to` oder `…/to/<k>/to`) und wird weggelassen; `[*]` gilt nur in `to` und an einem wiederholten Rahmen. Ein `anchor`, den kein Bild des Rahmens hat, ist `labelAnchorUnknown`, mit der ID des Verbinders. Ein Wort außerhalb der Auswahl von `routing`, `startCap`, `endCap` oder `side` und ein `at` außerhalb von 0 bis 1 sind `unknownConfigValue`. Ein `opacity`, das keine Zahl von 0 bis 1 ist, ist ebenfalls `unknownConfigValue` (eine Zahl außerhalb wird auf den Bereich begrenzt).

## Rahmenaussehen

Ein Raster aus Fotokarten, deren Etiketten sich nur in der Farbe unterscheiden, oder eine Seite mit Kästen in einem Dutzend Tönen behält einen Kastenstil und eine Vorlage: Die Farben kommen in `frameLooks`, eine Liste benannter Aussehen, und das Markdown nennt eines an jedem Teil, der es trägt. Seit postext 1.50.

```ts
frameLooks: [
  { id: 'rojo', name: 'Red pill', background: { hex: '#e63946', model: 'hex' }, body: { color: { hex: '#ffffff', model: 'hex' } } },
  { id: 'verde', background: { hex: '#6a994e', model: 'hex' } },
  { id: 'marino', border: { color: { hex: '#264653', model: 'hex' } } },
]
```

## Beschriftungsstile

Eine Beschriftung ohne Stil, oder mit einem Stil, der keine Schrift festlegt, übernimmt Schriftfamilie, Größe, Schriftstärke und Farbe des Grundtexts. Die Zeilen einer mehrzeiligen Beschriftung haben einen Zeilenabstand vom 1,15-Fachen ihrer Größe oder den Zeilenabstand des übernommenen Absatzformats. Über `paragraphStyle` übernimmt die Beschriftung auch Kursive und Versalien dieses Formats; `fontStyle: 'italic'` und `textTransform: 'uppercase'` fügen sie einem Stil hinzu, der kein Absatzformat übernimmt. Ein Beschriftungsstil, der `fontStyle: 'normal'` oder `textTransform: 'none'` angibt, schaltet Kursive oder Versalien des übernommenen Absatzformats ab (seit postext 1.40); fehlt die Angabe, gelten die des Absatzformats. Eine zum Einpassen verkleinerte Beschriftung behält ihren Lichthof im selben Verhältnis.

Ein Punkt unter dem Kasten der Beschriftung oder eine Hinweislinie, die kürzer ist als ihre Endmarke, zeichnet nichts. Hinweislinien werden unter den Beschriftungen gezeichnet, mit dem Bild, in jedem Ausgabeformat, das Beschriftungen zeichnet, und sie folgen dem Bild, wenn es beschnitten, skaliert, gespiegelt oder über eine Doppelseite gesetzt wird.

],
```

## Warnungen zu Seitenvorlagen

Anderswo ignoriert die Engine einen Schlüssel, den sie nicht kennt. Seitenvorlagen und Beschriftungsstile werden dagegen geprüft, und jedes Problem ist eine Konfigurationswarnung in `postext check` und im Bedienfeld Prüfungen der Sandbox. Der `path` dieser Warnungen ist ein JSON-Pointer auf das fehlerhafte Feld: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Wurde das Feld geerbt, verweist der Pointer auf die Vorlage, in der es steht. Eine Warnung, die eine nicht vorhandene ID oder einen nicht vorhandenen Namen nennt, schlägt außerdem den nächstliegenden vorhandenen vor.

Ein falsch geschriebener Schlüssel einer Vorlage, eines Rahmens, einer Gruppe, eines Rasters, von `fit`, von `overflow`, einer Variante oder eines Beschriftungsstils ist ein `unknownConfigKey`; ein Wort außerhalb der Auswahl einer Einstellung (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`, `overlap`, `rowAlign`, `routing`, Endmarken und `side` eines Verbinders, Endmarken und `routing` einer Hinweislinie) ist ein `unknownConfigValue`, und die Einstellung behält ihren Standardwert. Eine Vorlage ohne `id` oder ein Rahmen oder eine Gruppe ohne `name` wird mit einem `unknownConfigValue` an diesem Feld ignoriert. Rahmenaussehen (`frameLooks`) werden genauso geprüft: Ein Aussehen ohne `id` wird ignoriert, und ein Schlüssel, den das `look` eines Rahmens nicht hat, ist ein `unknownConfigKey`.
