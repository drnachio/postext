# 文档格式

**Postext读取的是一种有意保持精简的Markdown方言。**

解析器是手写的分词器，并不是完整的CommonMark实现，所以源格式的范围窄，行为也容易预测。这样做有两个目的：让引擎保持小而快；让文档可以毫不费力地在Postext与其他CommonMark阅读器（Obsidian、Pandoc、VS Code……）之间通用。本页没有列出的写法，要么按纯文本处理，要么从行内文本流中移除。

如果你用程序构建文档，`parseMarkdown`函数（见[配置 › 解析](/zh/docs/configuration-programmatic-usage#解析markdown)）会给出排版引擎实际使用的块结构。


## 前置元数据

文档开头可以放一段YAML前置元数据（可选），上下各用一行`---`标出：

```md
---
title: Chapter One
author: Jane Doe
publishDate: 2026-04-15
---

# Chapter One

The story begins here…
```

调用`extractFrontmatter(source)`可以把前置元数据和正文分开。它返回解析后的元数据对象、其余的Markdown，以及正文起始处的字符偏移量；如果你需要把错误或光标位置映射回原始源文本，这个偏移量就很有用。

前置元数据由[`gray-matter`](https://github.com/jonschlinkert/gray-matter)解析，因此任何结构的YAML都能接受。Postext本身只看`title`、`subtitle`、`author`和`publishDate`；其他键保留在`PostextContent.metadata`上，供你自行使用。

如果这一段不是有效的YAML（例如引号没有闭合，或带引号的值后面还有文字），排版也不会中断：`extractFrontmatter`不返回元数据，把结束的`---`之后的文字作为正文，并在`error`中给出解析器报告的原因。文档照常排版，只是没有元数据；构建结果在`contentWarnings`中列出一条`invalidFrontmatter`（沙盒中显示为**前置元数据无效**）。

YAML会给值赋予类型：`1984`是数字，`2026-04-15`是日期，`[Ana Gil, Luis Paz]`是列表。无论类型如何，Postext都把这四个字段作为文本输出：

- 数字按普通十进制形式输出，布尔值输出为`true`或`false`（`title: 1984`输出*1984*）。YAML把数字当作一个值来读，而不是逐位读取：`1.50`输出*1.5*，`017`（八进制）输出*15*，`1:30`（六十进制）输出*90*；
- 日期输出为对应的日历日期，用文档的语言书写（即`locale`设置，未设置时取断词语言）：`publishDate: 2026-04-15`在英文中输出*April 15, 2026*，在西班牙文中输出*15 de abril de 2026*，在德文中输出*15. April 2026*。阿拉伯文日期使用公历，除非标签指定了别的历法（`ar-u-ca-islamic`输出伊斯兰历日期），用哪种数字也由标签决定（`ar-EG`：١٥ أبريل ٢٠٢٦；`ar-u-nu-latn`：15 أبريل 2026）。带时刻的日期按UTC时间取日期，并舍去时刻：`2026-09-24T23:30:00-05:00`是25日UTC 04:30，输出*September 25, 2026*；
- 列表输出为用逗号连接的各项（`author: [Ana Gil, Luis Paz]`输出*Ana Gil, Luis Paz*）。

给值加上引号，就会按写的样子原样输出。数字要保留每一位、日期不能变动时，就这样写：`publishDate: "15/04/2026"`、`title: "1984"`。这段文本会进入`doc.metadata`、占位符（`{title}`、`{publishDate}`……）以及PDF的标题和作者。这四个字段的值如果没有文本形式（嵌套映射、空的`title:`），就不会出现在`doc.metadata`中。`extractFrontmatter`仍按YAML赋予的类型返回这些值；`metadataText(value, locale)`返回Postext为某个值输出的文本。

### 标题属性

标题行末尾可以加一个用花括号括起的属性块，语法与指令的`key="value"`相同：

```markdown
# The Long Road {author="I. Zango Martín" year=1998}
```

花括号及其内容会从标题文本中去掉（上例的标题显示为*The Long Road*），作为`attrs`存在标题上。设计槽位可以用`{attr.<key>}`占位符取用它们：一处是标题自身的高级设计槽位，另一处是页眉和页脚，后者从当前章的H1取值。Postext只识别位于行尾、括号配对且内部不含花括号的块；块前须有一个空格，或者紧跟在中文或日文字符之后，因为中文标题本来就不加空格（`# 回目{style="x"}`）。只有下文的属性语法能读完整个块时，它才算属性块：`{x, y}`、`{紅樓|hóng lóu}`和单独的`{}`都留在标题中，紧贴标题且只有标志的块（`# 第一回{draft}`）也一样。属性之间用空格分隔，因此带逗号的块（`{a="1", b="2"}`）以及Pandoc的`{.class}`也留在标题中。Pandoc的标识符`{#id}`可以识别：它等同于`id="…"`，给标题起一个名字，供[交叉引用](/zh/docs/document-format-notes-references#交叉引用与锚点)使用。用其他文字书写的键会被读取，然后丢弃并给出警告（见下文），所以`# 回目{style="x" 作者=曹雪芹}`仍会采用`style`。见**配置 › 页眉与页脚**。

设计文本输出的值可以占多行：两个字符`\n`表示在此换行，与元素的`overflow`设置无关（`to="Firma X\nStrasse 1\n10115 Berlin"`输出三行地址）。元素设置了`inlineMarks`时，值中的行内标记也会生效：`authors="Ana Ruiz^1^, Luis Gil^2^"`会把作者单位编号排成上标。这种转义只用于属性值（以及设计本身的模板）：标题文本里的`\n`字符（比如写在行内代码中）会原样输出。

有两个属性有特殊含义。`style="<id>"`给标题套用一个命名的[标题样式](/zh/docs/configuration-styles#标题样式)，例如前言或作者名单，它有自己的章首页设计、书眉、页面几何和正文排版；样式设为`numbered: false`时不带章号。`toc="false"`（或`"true"`）决定该标题是否列入`:::toc`生成的目录：

```markdown
# Preface {style="front-matter"}

# Contents {style="front-matter" toc="false"}
```

另外几个属性改变标题输出的内容和计数方式。`hidden="true"`（或`"false"`）覆盖标题所在级别或样式的`hidden`：隐藏的标题不输出任何内容，也不占空间（在正文流中和`:::callout`框内都是如此），但仍照常起页、参与计数，并列入目录、`{chapterTitle}`书眉和PDF书签。`jidori=N`把单行标题均匀拉开到标题自身的`N`个字宽（字取り：`# 序章 {jidori=3}`印作序　章），`jidori=0`关闭其级别或样式设定的均排（见[配置 › 按级别覆盖](/zh/docs/configuration-headings#按级别覆盖)）。`indent=N`让单个标题从行首缩进正文的`N`个字（字下げ：`## 一 {indent=5}`），覆盖其级别或样式的`indent`；不带单位的数字按正文字宽计，`0`让标题回到行首，竖排和横排都适用。`firstLineIndent=N`只缩进单个标题的第一行，覆盖其级别或样式的`firstLineIndent`，其余各行从`indent`定下的位置起排（GB/T 9704的标题：`## 关于加强管理的通知 {firstLineIndent=2}`）；长度的读法与`indent`相同，`0`取消级别上的设定。`startAt=N`（正整数）把该标题所在级别的计数器直接设为`N`，而不是加一；其后的标题从这里接着计数，后面各章也一样，下级标题照常在它之下重新计数。如果标题样式用字母给附录编号（`numberingTemplate: 'Appendix {1:A}'`），可以让第一个附录重新开始计数，读作*Appendix A*，而不是接着各章往下数：

```markdown
# To my mother {hidden="true" toc="false"}

# Survey instrument {style="appendix" startAt=1}

# Raw data {style="appendix"}
```

### 首字下沉

如果段落前面标题的级别或样式，或者段落所在`:::paragraphs`组的段落样式设了首字下沉，段落就以首字下沉开头（见[配置 › 首字下沉](/zh/docs/configuration-text#首字下沉)）：第一个字母放大，排在前几行旁边，这几行让出位置，相应缩短。段落本身不需要任何标记，文字照常书写；复制、搜索和源映射时，这个字母仍属于它所在的词。用`dropcap`属性可以为某一章或某一组单独开关首字下沉：

```markdown
# Lost {dropcap=false}

# The mines {dropcap=2}

:::paragraphs{style="entry" dropcap}
The lamp of the first entry opens with an initial.
:::
```

在标题行上，`dropcap=false`让该标题后的段落不带其级别或样式设定的首字下沉，`dropcap=N`把首字下沉设为`N`行，级别没有设定时，单独写`dropcap`也会给这一段加上首字下沉（三行，用段落的字体）。写在`:::paragraphs`的开始行上时，这个属性对组的第一段起同样的作用；样式设为`each: true`时，则对每一段都起作用。查找标题后的段落时，会跳过围栏、指令、已移出正文流的框和浮动插图；框、列表项、引文或诗歌中的段落从不带首字下沉。自postext 1.23起。

在模板页里，框中排的是正文：框里的`:::paragraphs{style="kaitou" dropcap}`会让它的第一段以首字下沉开头。`:::callout`框里的段落不带首字下沉，在框里要求首字下沉会引发`dropCap`警告。

### 代码块

代码清单写在两条由三个或更多反引号（或三个或更多波浪号）组成的围栏之间，每条围栏单独占一行，最多缩进三个空格。两条围栏之间的内容都按原样保留：行首空格和连续的空格、制表符、空行，以及以`#`、`-`、`1.`、`>`、`$`或`:::`开头的行。其中的内容一概不按Markdown解读：强调、`:ref`、公式、行内标签、指令和标题都不起作用。结束围栏所用的字符与开始围栏相同，长度至少与它相等；所以清单本身要显示围栏时，就用更长的围栏或波浪号围栏把它围起来：

~~~markdown
```bash {title="backup.sh" lineNumbers start=12 highlight="3,5-7"}
#!/usr/bin/env bash
# Copy the photos to the backup disk
rsync -a --delete ~/Photos/ /Volumes/Backup/Photos/
echo "done: $(date)"
```
~~~

开始围栏后面的信息字符串指明语言（取它的第一个词：`js`、`ts`、`python`、`bash`、`console`、`json`……），其余部分按[属性写法](/zh/docs/document-format-directives#属性值)读作属性，属性加不加花括号都可以（`title="app.js" lineNumbers`）。语言之后的其他文字是标题：```` ```console Terminal ````和```` ```python normalize.py ````在清单上方印出*Terminal*和*normalize.py*。

围栏会结束它上面的段落，不论中间有没有空行；结束围栏之后的文字开始一个新段落。没有闭合的围栏一直延续到文字末尾，并给出警告（`unclosedCodeBlock`）。`:::callout`中的围栏成为嵌套在其中的框；在`:::paragraphs`中，清单保持代码样式，不采用段落样式。Postext不支持在列表项下接续内容，所以列表项之后的围栏会结束列表。写在清单中的索引标记和锚点照原样保留。

缩进代码（空行之后以四个空格或一个制表符缩进）只有在打开`codeStyle.indentedCode`时才读作代码清单：Postext的正文常用空格缩进，而列表项正是靠行首空格来嵌套的。

清单的外观（字体、框、制表符宽度、比框更宽的行如何处理、行号、各类语法元素的颜色）由`codeStyle`设定，见[配置 › 代码清单](/zh/docs/configuration-styles#代码清单)。行内代码（`` `x` ``）沿用正文字体，除非`codeStyle.inline`另外指定字体。postext 1.23之前保存的书如果正文里有围栏，仍按当时的方式把它们当作Markdown读取（`codeStyle.blocks: false`）。自postext 1.23起。

## 不支持的内容

Postext不识别以下CommonMark功能。它们要么被当作普通文本（因此会原样出现在输出中），要么直接丢弃，不给任何提示：

- **Setext式标题**：即`===` / `---`下划线形式。请使用ATX（`#`）标题。
- **HTML透传**：Postext不解释原始的`<tags>`，也不支持MDX式标签；Postext源文件是纯Markdown。
- **水平线**：`---`、`***`、`___`。
- **表格**：不解析管道表格。表格以结构化资源的形式放在`PostextContent.resources`中。
- **引用式链接**：`[text][id]`加上定义块。
- **自动链接**：`<https://example.com>`。
- **用行末两个空格表示的换行**：这两个空格会被删去。请改在行末写反斜杠（见[段落内的换行](/zh/docs/document-format-directives#段落内的换行)）。
- **旁注**：尚未实现；类型定义虽然接受`PostextContent.notes`，引擎却会忽略它。脚注和章末注用`[^id]`书写（见[脚注](/zh/docs/document-format-notes-references#脚注)）；在postext 1.5及以前，它们只能作为文本排出。

这份清单会随时间缩短。在此之前，凡是上文没有明确列为支持的写法，都应当视为原样输出的文本。

除语法之外，阿拉伯文和其他从右向左书写的文字从右向左排版，采用双向算法，书在右侧装订（见[阿拉伯文排版](/zh/docs/arabic-layout)）。中文可以横排，也可以竖排，并按所在地区的要求处理断行、标点宽度、字间两端对齐、着重号等标记、注音和双行夹注（见[中文排版](/zh/docs/chinese-layout)）。日文按自己的规则排版，包括禁则、约物间距、振假名、傍点、汉文训读记号和注释（见[日文排版](/zh/docs/japanese-layout)）；韩文使用同一个排版器，按中国大陆的中文规则排版。Postext自带八种语言的断词模式，并为这八种语言以及中文、日文和阿拉伯文提供内置标签。见[语言与文字](/zh/docs/configuration-language#语言与文字)。


## 书写约定

遵守下面几条约定，文档就能顺利解析，不会出现意料之外的结果：

- **块与块之间留一个空行**。用空行隔开的两个段落是两个段落。写在相邻两行的两个段落会合成一段：每一行都并入前面的段落。
- **多余的空行不会增加空白**。用三个空行隔开两个块，效果与一个空行完全相同。想在两个块之间多留些空白时，写一行[`:::space`](/zh/docs/document-format-directives#space)。
- **嵌套的列表项缩进到上一项正文的位置**。在项目符号（`- `）下缩进两个空格，在`1. `下缩进三个，在`10. `下缩进四个，与CommonMark的嵌套方式相同；在`1.`下缩进两个空格也算嵌套。列表项会嵌套在最近的一个未结束的列表项之下，前提是那一项的标记比它至少靠左两列；因此只缩进一个空格不构成嵌套，而且无论每级缩进多少，都不会跳级（postext 1.15及以前的深度为`floor(空格数 / 2) + 1`，`   1.`下的`      1.`会排成第4级）。制表符把位置推到下一个4的倍数列。最大深度为5。
- **第一个列表项不要缩进**。第一级列表项从第0列开始。列表的第一项无论缩进多少都是第一级（postext 1.15及以前，行首空格会提高它的级别），所以要嵌套，上方必须先有一个列表项。
- <strong>任务标记必须写在方括号里，中间一个空格。</strong>只能是`[ ]`、`[x]`、`[X]`，不能有其他写法。`[*]`或`[-]`不是任务标记，会原样作为文本输出。
- **不支持列表中的引用块**。引用块要从第0列开始，写在列表之外。
- **图片和表格放在`resources`中**。行内的`![alt](src)`会被去掉，原因正是行内图片会打乱按栏放置的逻辑。把每张图片声明为资源并按id引用，再由引擎决定它是浮动、截断所在的栏，还是移到下一页顶部。
- <strong>不表示公式时，用`\$`转义美元符号。</strong>Postext把`$…$`当作行内LaTeX，所以正文中单独的`$`会被当作公式的开头。价格、shell提示符以及其他带单独美元符号的内容都应写成`\$`。
- <strong>标记用ASCII字符键入，中文和日文文本中也一样。</strong>中文或日文输入法打出的是全角形式：指令的冒号成了`：：：`，标题成了`＃`，脚注标记成了`［＾1］`，属性成了`｛…｝`，粗体成了`＊＊`。它们会作为文本印出，构建时该行会报出`fullwidthMarkup`警告，并指出应当键入的ASCII形式。属性值可以用任何文字书写，也可以用`“…”`或`「…」`加引号；键名仍须是ASCII。


## 完整示例

一份用到所有受支持结构的短文档：

```md
---
title: The Typesetter's Craft
author: Anon
---

# Opening

A good book reads itself. The **reader** should never notice the
typesetter's work — only the author's voice.

## What makes text readable

Three properties matter most:

1. Line measure — 40 to 75 characters per line.
2. Leading — 1.3 to 1.5 times the font size.
   1. Tighter at short measures.
   2. Looser at long measures.
3. Contrast between body and headings.

Common failure modes include:

- Lines that stretch across the whole page.
- Headings that float without a following paragraph.
- Orphans and widows at column boundaries.

> Typography is the craft of endowing human language with a durable
> visual form.
> — Robert Bringhurst

### Review checklist

- [x] Column width under 75 characters
- [x] Leading set to 1.5
- [ ] Orphan and widow pass
- [ ] Final proofread

### A note on formulas

Inline math such as $a^2 + b^2 = c^2$ flows with the surrounding text, and
display math sits centred on the baseline grid:

$$
\int_0^1 x^2\,dx = \tfrac{1}{3}
$$
```

这份文档经排版引擎处理后，会生成结构化的`VDTDocument`，它的各页把上述每个块都存为带类型的条目。块如何变成几何形状，见[架构](/zh/docs/architecture)一页。
