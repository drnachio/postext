# Configuració: notes i referències


## Notes a peu de pàgina

La propietat `footnotes` fixa on van les notes citades amb `[^id]`, com es numeren i quin aspecte tenen. El marcatge es descriu a [Format del document](/ca/docs/document-format-notes-references#notes-a-peu-de-pàgina).

```ts
interface FootnotesConfig {
  placement?: 'column' | 'chapterEnd' | 'spread'; // Peu de la columna que cita, després del capítol, o al costat del text d'un plec.
  numbering?: 'chapter' | 'document' | 'page' | 'column' | 'spread'; // Reiniciar a cada capítol, continuar, o reiniciar a cada pàgina / columna / plec.
  numberFormat?: string;      // decimal, lower-roman, circled-decimal (①)…
  symbols?: string[];         // Els símbols de crida de numberFormat: 'symbols'.
  markerPosition?: 'auto' | 'superscript' | 'inline' | 'side' | 'right'; // Volada, sobre la línia de base, al costat de la paraula, o a la dreta d'una línia vertical.
  markerSize?: Dimension;     // Mida de la crida en línia, lateral o a la dreta; em és el text que l'envolta.
  markerTemplate?: string;    // Com s'escriu el número: '({n})' dona «(١)».
  noteNumberPosition?: 'auto' | 'superscript' | 'inline'; // El número de la nota mateixa, volat o sobre la línia.
  numberGap?: 'en' | 'em';    // Espai després del número de la nota mateixa.
  chapterEndAlign?: 'foot' | 'text';   // chapterEnd: notes al peu de la columna, o sota el text.
  fontSize?: Dimension;       // Cos de la nota; em és el cos del text.
  lineHeight?: Dimension;     // Interlineat de la nota; em és el cos de la nota.
  color?: ColorValue;         // Color de la nota; sense valor, el del cos.
  textAlign?: TextAlign;      // Sense valor, l'alineació del cos.
  wordBreak?: 'normal' | 'keep-all'; // Sense valor, el cjk.wordBreak del document.
  hangingIndent?: Dimension;  // Sagnat de les línies següents d'una nota.
  spaceBetween?: Dimension;   // Espai entre dues notes.
  spaceAbove?: Dimension;     // Espai entre el text i el filet; em és el cos del text.
  spaceBelowRule?: Dimension; // Espai entre el filet i la primera nota.
  separator?: {
    enabled?: boolean;        // Dibuixar el filet.
    width?: number;           // Longitud del filet, fracció de l'amplada de columna.
    lineWidth?: Dimension;    // Gruix del filet.
    color?: ColorValue;       // Sense valor, el color de les notes.
  };
}
```

```ts
  lineHeight: { value: 9.5, unit: 'pt' },

```

**Llibres japonesos.** Un document japonès (`locale: 'ja'`, des de postext 1.16) dona als camps que no fixa els valors de JLReq §4.2. Un llibre vertical compon les notes després del capítol (`placement: 'chapterEnd'`, 後注), numerades per capítol, amb crides `（{n}）` a la dreta de la línia (`markerPosition: 'right'`, amb les xifres dretes segons `cjk.uprightDigits`); un llibre horitzontal les compon al peu de la pàgina, numerades a cada pàgina, amb crides volades. Tots dos tracen el filet amb un terç de l'amplada de línia (`separator.width: 1/3`), i les notes després del capítol porten `numberGap: 'em'` i un sagnat francès de dos quadratins. Un valor explícit té prioritat i es conserva en desar (`stripFootnotesDefaults` compara amb els valors per defecte del mateix document); els documents xinesos, àrabs i llatins es resolen com abans. `footnoteDocumentDefaults(locale, writingMode, placement?)` retorna aquests valors. La crida s'escriu davant d'un 。 que tanca la frase (`先生[^1]。`): es queda amb el caràcter anterior, i 。 no obre mai una línia. Vegeu [Composició japonesa › Notes](/ca/docs/japanese-layout#notes).

Com es componen les notes al peu de columna:

- **La nota i la crida comparteixen columna.** Abans de col·locar una línia, la maquetació suma l'alçada de les notes que aquella línia cita per primera vegada (i la del filet, si és la primera nota de la columna). Si les notes d'una línia no hi caben a sota, la línia passa a la columna següent amb la resta del paràgraf, segons les regles de vídues i òrfenes. L'àrea de text de la columna s'escurça tant com l'alçada de les notes, de manera que l'equilibratge de columnes i la banda de tancament d'un capítol només compten el text.
- **Diverses notes** en una columna s'apilen en l'ordre de cita sota un únic filet. Una nota que es torna a citar més endavant conserva el número i no es torna a compondre.
- **Flotants al peu.** Una figura que ocupa el peu d'una columna després que s'hagin compost les notes queda per sobre de les notes; les notes compostes després de la figura queden per sobre de la figura.
- **Requadres.** Una nota citada dins d'un requadre (en línia, flotant o fix) va al peu de la columna on continua el text després del requadre, normalment la mateixa. Un requadre que tanca el document deixa les notes al peu de la columna on ha acabat el text.
- **Límits.** Una nota no es parteix mai: si és més alta que la columna, la desborda. Les crides en peus de figura, cel·les de taula i títols no s'interpreten (s'imprimeixen tal com estan).
- **Sortida.** El canvas, l'HTML i el PDF pinten les notes, les crides (un número volat) i el filet. Al PDF, cada crida enllaça amb la nota corresponent, i un PDF etiquetat marca cada nota com a element `Note` amb un `/ID` únic llistat a l'`/IDTree` de l'arbre d'estructura (PDF/UA-1). Les notes són `VDTBlock` amb `footnoteNote`, a `page.floats`; els filets són a `page.footnoteAreas`.
- **Avisos.** `undefinedFootnote` (una crida sense definició: el número s'imprimeix sobre una nota buida) i `unusedFootnote` (una definició que cap crida no cita: no es compon).

El resolutor i el depurador segueixen el patró de les altres seccions:

```ts
import { DEFAULT_FOOTNOTES_CONFIG, resolveFootnotesConfig, stripFootnotesDefaults, footnoteDocumentDefaults } from 'postext';

resolveFootnotesConfig(config.footnotes, 'ja', 'vertical-rl'); // els camps sense fixar prenen els valors japonesos verticals
```


## Numeració de línies

La propietat `lineNumbers` imprimeix al marge, al costat de la línia, el número de cada cinquena línia (o de cada enèsima), com fan les edicions crítiques, les antologies de poesia, els textos legals i les edicions escolars. Compta els versos dels poemes `:::verse`, o bé totes les línies del text. Està desactivada per defecte. Cada número es pinta sobre la línia de base de la línia corresponent, amb un cos propi, i no mou mai cap línia: la pàgina es compon exactament igual que sense números. Des de postext 1.23.

```ts
interface LineNumbersConfig {
  enabled?: boolean;        // Desactivada per defecte.
  count?: 'verse' | 'all';  // Els versos dels poemes, o totes les línies del text.
  interval?: number;        // Imprimir els múltiples de N.
  numberFirst?: boolean;    // Imprimir també la primera línia després de cada reinici.
  restart?: 'document' | 'chapter' | 'section' | 'page' | 'poem'; // On torna a començar el compte.
  startAt?: number;         // El número de la primera línia després d'un reinici.
  position?: 'outer' | 'inner' | 'left' | 'right' | 'start' | 'end' | 'side';
  multiColumn?: 'each' | 'gutter' | 'outer-edges'; // Pàgines de dues columnes o més.
  gap?: Dimension;          // Del text al número; em és el cos del número.
  align?: 'auto' | 'left' | 'right';
  fontFamily?: string;      // La família del cos si no es fixa.
  fontSize?: Dimension;     // em és el cos del text.
  fontWeight?: number;      // El pes del cos si no es fixa.
  italic?: boolean;
  color?: ColorValue;       // El color del cos si no es fixa.
  format?: string;          // decimal, lower-roman, arabic-indic, 一…
}
```

```ts
  italic: true,

```

Què es compta i què no:

- **No es compten mai** els encapçalaments, els peus, les taules i les imatges, les fórmules en bloc, el text de disseny (obertures, capçaleres), les notes a peu de pàgina i les notes de final de capítol, l'índex general, les entrades de l'índex analític i de la bibliografia, ni les pàgines en blanc.
- **Requadres i prosa.** El text d'un requadre no es compta, i amb `count: 'verse'` tampoc la prosa, llevat que l'estil de paràgraf amb què es compon indiqui `lineNumbers: true`; un estil amb `lineNumbers: false` no es compta mai (vegeu [Estils de paràgraf](/ca/docs/configuration-styles#estils-de-paràgraf)).
- **Un poema.** La línia d'obertura d'un poema admet `numbered=false` (els versos no es compten), `lineStart=N` (el primer vers és l'N, i el compte torna a començar en aquest punt) i `interval=N`. `:::numbering{lines=N}` dona el número N a la línia comptada següent, sigui on sigui. Vegeu [Format del document › `:::verse`](/ca/docs/document-format-directives#verse) i [`:::numbering`](/ca/docs/document-format-directives#numbering).

En un llibre compost capítol a capítol, `restart: 'document'` porta el compte d'un capítol al següent a `continuation.lineNumber`. `continuationAfter` compta els versos a partir del text; amb `count: 'all'` el compte depèn de la composició, així que l'aplicació passa el `lastLineNumber` del document del capítol anterior, com fa el Sandbox.

Amb `position: 'side'`, els números comparteixen la columna lateral amb els requadres, els peus i les figures laterals. Si un número se superposa a algun d'aquests elements, es pinta igualment, cap dels dos no es mou, i la composició dona un avís de contingut `lineNumberOverlap` que indica la línia numerada.

**Sortida.** El canvas, el PDF, el visor HTML i l'EPUB de maquetació fixa pinten els números. En un PDF etiquetat són artefactes de paginació i cadascun porta un `/ActualText` buit, de manera que el text copiat o extret passa d'una línia a l'altra sense els números. La sortida HTML els amaga a les tecnologies d'assistència (`aria-hidden`), a la selecció i al text copiat. A l'EPUB de maquetació fluida, on és el sistema de lectura qui compon les línies, només es conserven els números dels versos: un `span` `pt-line-number` (també `aria-hidden`) al marge inicial de l'estrofa, al costat de cada vers que porta número a la versió impresa. Al VDT, els números són una zona de disseny de cada pàgina (`page.lineNumbers`, amb els blocs de text marcats com a `artifact`) i una llista de marques (`page.lineNumberMarks`: `number`, `label`, `columnIndex`, `blockId`, `lineIndex`); el document desa `lastLineNumber`.

**No s'admeten**: números de línia en text vertical, una referència creuada que imprimeixi el número d'una línia, notes enllaçades a números de línia, ni números per a les línies de cel·les de taula, peus o llistats de codi.

Al Sandbox, aquests paràmetres són a la secció **Numeració de línies** del tauler Disseny. El resolutor i el depurador segueixen el patró de les altres seccions; la font, el pes i el color surten del text de cos:

```ts
import { DEFAULT_LINE_NUMBERS_CONFIG, resolveLineNumbersConfig, stripLineNumbersDefaults } from 'postext';

resolveLineNumbersConfig(config.lineNumbers, resolvedBodyText); // font, pes i color sense fixar segueixen el cos
```


## Referències creuades

La propietat `crossRefs` fixa les paraules que una [referència creuada](/ca/docs/document-format-notes-references#referències-creuades-i-àncores) imprimeix al voltant d'un número o d'una pàgina, i l'estil que fa servir un `:ref` que no n'indica cap. Cada plantilla porta `{n}` allà on va el número; si una plantilla no el porta, el número s'hi afegeix després d'un espai de no separació (`"§"` imprimeix *§ 3.2*). Una plantilla sense definir segueix la llengua del document: *capítulo / sección / pág.* en castellà, *chapter / section / p.* en anglès, `第{n}章` / `第{n}节` / `第{n}页` en xinès, `第{n}章` / `{n}節` / `{n}ページ` en japonès, `الفصل {n}` / `القسم {n}` / `ص {n}` en àrab, i el mateix per al francès, l'alemany, l'italià, el portuguès, el català i el neerlandès.

```ts
interface CrossRefsConfig {
  chapter?: string;  // Words around a level-1 heading's number: "chapter {n}".
  section?: string;  // Around any other heading's number: "section {n}".
  page?: string;     // Around a page number: "p. {n}".
  defaultStyle?: 'default' | 'number' | 'title' | 'page'; // A :ref without style=.
  breakLabels?: boolean; // A label of words breaks at its spaces.
}
```

## Cites

La propietat `citations` tria l'estil de cita i l'aspecte de les cites i de la bibliografia. El marcatge es descriu a [Cites i bibliografia](/ca/docs/document-format-notes-references#citacions-i-bibliografia); l'estil l'aplica el paquet `postext-citeproc`.

```ts
    entrySpacing?: Dimension;
    labelWidth?: Dimension;
    labelAlign?: 'left' | 'right';

    includeUncited?: boolean;
    groupByLanguage?: boolean;
  };
}
```

## Enllaços en paper

La propietat `links` decideix què mostra la pàgina impresa de l'adreça que hi ha darrere d'un enllaç escrit `[text](https://…)`. L'enllaç continua funcionant a totes les sortides que el poden seguir (el llenç del Sandbox, el PDF, HTML, EPUB, SCORM i Folio); en paper només en quedaria el text i el lector no sabria on porta. Com s'escriuen els enllaços s'explica a [Format del document](/ca/docs/document-format-notes-references#enllaços-en-paper). Des de postext 1.65.

```ts
interface LinksConfig {
  print?: 'none' | 'inline' | 'notes'; // Res, l'adreça entre parèntesis o una nota.
  show?: 'url' | 'qr' | 'both';        // print: 'notes': què imprimeix la nota.
  urlDisplay?: 'full' | 'short';       // short: sense https://, sense www. inicial ni / final.
  repeat?: 'every' | 'first';          // first: una adreça ja anotada al capítol reutilitza aquella nota.
  visibleUrls?: 'skip' | 'note';       // Un enllaç el text del qual és la seva pròpia adreça.
  qr?: {
    size?: Dimension;                  // Costat del codi amb la zona de silenci.
    errorCorrection?: 'L' | 'M' | 'Q' | 'H';
    quietZone?: number;                // Mòduls clars al voltant del codi (0–8).
    color?: ColorValue;                // Sense valor, el color de les notes.
    side?: 'start' | 'end';            // A quin costat de les línies de la nota va el codi.
    gap?: Dimension;                   // Espai entre el codi i les línies; em és el cos de la nota.
  };
}
```

Una edició impresa que envia el lector al web amb un codi i l'adreça abreujada:

```ts
links: {
  print: 'notes',
  show: 'both',
  urlDisplay: 'short',
  repeat: 'first',
  qr: { size: { value: 18, unit: 'mm' } },
}
```

- **Quins enllaços.** Només les adreces `http:` i `https:`. Un `mailto:`, un `tel:` i un enllaç a un altre punt del llibre s'imprimeixen tal com són. Postext llegeix `<https://…>` i una adreça solta com a text, que ja es veu a la pàgina, i per això no reben res.
- **On.** Paràgrafs, elements de llista, citacions en bloc i el text dels requadres. Els encapçalaments (el seu text passa a l'índex i als titolets) i les entrades de la bibliografia (els seus DOI i URL segueixen `citations.bibliography.doi`) es queden com estan. Un enllaç dins d'una nota a peu de pàgina porta l'adreça entre parèntesis, digui el que digui `print`, perquè una nota no pot tenir nota.
- **Una configuració per edició.** El més habitual és que l'editorial deixi `print: 'none'` a l'edició digital i fixi `print: 'notes'` amb `show: 'both'` a la configuració de la impresa; el Markdown és el mateix a totes dues.
- **PDF.** El codi es dibuixa en vectors i enllaça amb l'adreça. En un PDF etiquetat és un `Figure` dins d'un `Link`, amb l'adreça com a text alternatiu.

El resolutor i el depurador segueixen el patró de les altres seccions:

```ts
import { DEFAULT_LINKS_CONFIG, resolveLinksConfig, stripLinksDefaults } from 'postext';
```

## Índex general

La propietat `toc` configura el que imprimeix una directiva `:::toc` (vegeu [Format del document](/ca/docs/document-format-directives#toc)). L'índex general es construeix a partir de l'**esquema** del document (cada encapçalament amb el número i l'etiqueta de pàgina, cada `:::part`), de manera que segueix els capítols: si en reanomenes un, el mous a una altra part o en canvies els autors, les entrades canvien amb el capítol. Una entrada consta del número de l'encapçalament en una columna pròpia, el títol, una línia de punts i l'etiqueta de pàgina a la vora dreta, i després una línia de subtítol opcional; una part és una fila amb el disseny de `parts.design`.

```ts
const config: PostextConfig = {
  toc: {
    levels: [{ level: 1, fontWeight: 700, color: { hex: '#00507b', model: 'hex' }, numberWidth: { value: 7.4, unit: 'mm' } }],
    unnumbered: { color: { hex: '#000000', model: 'hex' } },
    pageNumber: { fontWeight: 400, width: { value: 8, unit: 'mm' } },
    leader: { char: '.', gap: { value: 1, unit: 'mm' } },
    subtitle: { enabled: true, attr: 'author', italic: true, fontSize: { value: 8.5, unit: 'pt' } },
    parts: {
      height: { value: 23, unit: 'pt' },
      marginTop: { value: 11.5, unit: 'pt' },
      design: { elements: [/* una caixa de banda, 'SECCIÓ {number}', '{titleText}', '{pageNumber}' */] },
    },
  },
};
```

Les etiquetes de pàgina són les que imprimeix el document. `buildDocument()` torna a compondre un document amb `:::toc` amb les etiquetes de la passada anterior fins que s'estabilitzen (com a màxim, tres passades més); en canvi, una aplicació amfitriona que compon un llibre capítol a capítol proporciona l'esquema de tot el llibre com a `PostextContent.outline`, construït amb `contentOutline()` (encapçalaments i parts a partir del text) i `outlineFromDoc()` (les mateixes entrades amb les etiquetes de pàgina d'una composició), i torna a compondre el capítol de l'índex general cada vegada que canvia l'`outlineKey()` d'aquest esquema. Cada entrada d'encapçalament porta el `number` que imprimeix l'índex i, en un encapçalament numerat, el `counter`: el compte acumulat del nivell després de qualsevol `startAt`, imprimeixi el que imprimeixi la plantilla. És el que una aplicació amfitriona mostra al costat d'un capítol a les seves pròpies llistes.

## Índex analític

La propietat `index` configura el que imprimeix una directiva `:::index` (vegeu [Format del document](/ca/docs/document-format-notes-references#índex-analític)): els termes marcats amb `:index[…]` i `:index{term="…"}` al text, ordenats, agrupats per inicial (en xinès, per la inicial del pinyin o per traços, i en japonès, per files del gojūon; vegeu `groupBy`), i cadascun amb les pàgines on apareix. Una entrada consta del terme, un separador i els números de pàgina; a continuació van les subentrades, amb un pas de sagnat per nivell, i les línies que continuen una entrada es sagnen `turnoverIndent` per no alinear-se mai amb una subentrada.

```ts
const config: PostextConfig = {
  headingStyles: [
    // L'índex a dues columnes, sota el seu propi encapçalament.
    { id: 'indice', numbered: false, layout: { layoutType: 'double', gutterWidth: { value: 6, unit: 'mm' } } },
  ],
  index: {
    fontSize: { value: 8.5, unit: 'pt' },
    lineHeight: { value: 11, unit: 'pt' },
    rangeFormat: 'chicago',
    groups: { fontFamily: 'Source Sans 3', fontWeight: 700, color: { hex: '#8a1c1c', model: 'hex' } },
  },
};
```

Els números de pàgina surten de l'esquema del llibre, igual que els de l'índex general: `computeOutline()` i `contentOutline()` enumeren les marques d'un text com a entrades de tipus `'indexMark'` (amb `indexMark.path`, `sort`, `see`, `seeAlso`, `main`, `range` i `index`), i `outlineFromDoc()` assigna a cadascuna la pàgina on ha caigut, que la composició registra a `doc.indexMarks` (`{ sourceStart, pageIndex }` per marca). `buildDocument()` torna a compondre un document que imprimeix el seu propi índex fins que els números s'estabilitzen; una aplicació amfitriona que compon un llibre capítol a capítol passa l'esquema de tot el llibre com a `PostextContent.outline` al capítol que conté `:::index`. `tocOutline()` i `indexOutline()` separen un esquema en la part que llegeix l'índex general i la que llegeix l'analític, perquè l'aplicació amfitriona pugui associar cada capítol amb el que imprimeix: el Sandbox torna a compondre el capítol de l'índex analític només quan es mou una marca, i el de l'índex general només quan es mou un encapçalament. `contentOutline()` indica a més si un text imprimeix un índex analític (`hasIndex`).
