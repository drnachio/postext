# الاستخدام البرمجي: ملفات PDF


## توليد ملفات PDF

يقع إخراج PDF في حزمة منفصلة، **`postext-pdf`**، كي لا تتحمّل عمليات الدمج المخصّصة للويب وحده كلفة `pdf-lib` و`@pdf-lib/fontkit`. لا يعيد مُخرِج PDF قياس النص: فهو يستهلك `VDTDocument` نفسه تمامًا الذي تمرّره إلى `renderToCanvas` أو `renderToHtml`، ويحوّل إحداثياته المقيسة بالبكسل إلى نقاط PDF. لذلك تتطابق المخرجات الثلاثة حتمًا في فواصل الأسطر وارتفاعات الأعمدة ومواضع الموارد.

> **في المتصفح، ابنِ شجرة VDT عبر [عامل الويب (Web Worker)](/ar/docs/configuration-programmatic-usage#تشغيل-الإخراج-في-web-worker).** الدالة `renderToPdf` نفسها سريعة متى وُجدت شجرة VDT، فالجزء المكلف هو مسار الإخراج الذي أنتجها. تشغيل هذا المسار في العامل يُبقي الواجهة مستجيبة، ويتيح لتصدير PDF أن يعيد استخدام ذاكرة القياس المؤقتة نفسها التي سبق أن هيّأتها المعاينة الحية. راجع [تصدير PDF انطلاقًا من العامل](/ar/docs/configuration-programmatic-usage#تصدير-pdf-انطلاقًا-من-العامل) لترى المسار الموصى به. الأمثلة أدناه، التي تعمل على الخيط الرئيسي، هي المرجع لـ*معنى الوسائط*؛ أما في شيفرة الواجهة فابنِ شجرة VDT في العامل أولًا، ولا تستدعِ مباشرةً إلا `renderToPdf`.

### التثبيت

```bash
npm install postext postext-pdf
```

`postext` تبعية نظيرة (peer dependency) للحزمة `postext-pdf`. يحتاج كل إصدار من `postext-pdf` إلى إصدار `postext` الذي صدر معه، أو إلى إصدار لاحق من الإصدار الرئيسي نفسه (نطاقه النظير هو `^` متبوعة بذلك الإصدار، أي `^1.5.0` للإصدار 1.5.0)، لأنه يستورد دوالّ مساعدة أضافتها `postext` في ذلك الإصدار. حدّث الحزمتين معًا، وثبّتهما على شبكة CDN على الإصدار نفسه.

### الواجهة البرمجية العامة

تعرض الحزمة نقطة دخول واحدة وعددًا قليلًا من الأنواع:

- **`renderToPdf(doc, options): Promise<Uint8Array>`** — تأخذ `VDTDocument` (أو فصول كتاب في مصفوفة منها) وتعيد بايتات PDF الخام.
- **`PdfFontProvider`** — توقيع دالة الاستدعاء `(family, weight, style, request?) => Promise<Uint8Array | Uint8Array[]>` التي تستخدمها `renderToPdf` لطلب بايتات الخط حين تحتاج إلى تضمين تركيبة جديدة من العائلة والوزن والنمط. ويتضمّن `request.codePoints` الحروف التي تنضّدها الصفحات بشكل الخط (face) ذاك؛ والجواب ملف واحد، أو عدة ملفات تؤلّف شكل الخط معًا (انظر [خطوط الصينية واليابانية والكورية](#خطوط-الصينية-واليابانية-والكورية)).
- **`declaredFontFile(bytes, { unicodeRange?, order? }): PdfFontFile`** — ملف من ملفات شكل الخط يذكر كيف أعلنته الصفحة: قيمة `unicode-range` في قاعدته `@font-face` وموضعه في ترتيب الإعلان. و`PdfFontFile` هو `Uint8Array` فيه هاتان الخاصيتان الاختياريتان (انظر [خطوط الصينية واليابانية والكورية](#خطوط-الصينية-واليابانية-والكورية)). منذ postext-pdf 1.30.
- **`RenderToPdfOptions`** — `{ fontProvider, forms?, resourceBytes?, previewBytes?, outlines?, accessible?, colorSpace?, pageNegative?, characterGrid?, baselineGrid?, onProgress?, onWarning?, rasterizeSvg?, harfbuzzWasm?, print?, outputProfile?, profileBaseUrl?, date? }`. ويحدّد `forms` كيف تكتب حقول النماذج الأرقام (العملة وموضعها والفواصل) وشكل الخط الذي تعرض به قيمها (`font`؛ انظر [حقول النماذج](#حقول-النماذج)). تأخذ `outlines` و`accessible` و`colorSpace` قيمتها من `pdfGeneration` في المستند حين تُترك (انظر [إنتاج PDF (الإعدادات)](/ar/docs/configuration-fonts-colors-viewers#إنتاج-pdf-الإعدادات)). يُشرح `resourceBytes` في [بايتات الموارد والنسخ الأصلية للطباعة](#بايتات-الموارد-والنسخ-الأصلية-للطباعة)، و`onWarning` في [أشكال الخطوط التي يُسأل عنها المزوّد](#أشكال-الخطوط-التي-يُسأل-عنها-المزوّد) و[التحذيرات في المستند](/ar/docs/configuration-programmatic-usage#التحذيرات-في-المستند). يطبع `characterGrid: true` الشبكة التي يرسمها `cjk.grid.show` على الشاشة، والتي يُسقطها ملف PDF في غير ذلك (انظر [شبكة الحروف](/ar/docs/configuration-east-asian#شبكة-الحروف)). ويحدّد `harfbuzzWasm` المكان الذي يُحمَّل منه الملف `harfbuzz.wasm` الخاص بـHarfBuzz (عنوان URL نسبي إلى الصفحة، أو بايتات الملف) لمستند فيه نص من اليمين إلى اليسار أو نص متصل الحروف؛ وإن تُرك، جرّب postext-pdf النسخة الموجودة بجانب وحدته، ثم إصدار harfbuzzjs نفسه من jsDelivr ثم من esm.sh. يأخذ `print` إعدادات الإخراج للطباعة (معيار PDF/X، وملف التعريف اللوني للإخراج، والأسود، والفحص قبل الطباعة)، وإن لم يُمرَّر أُخذت قيمة `print` من المستند؛ ومع معيار PDF/X، أو مع `colorSpace: 'cmyk'`، يُفصَل كل لون عبر ملف ICC للإخراج، الذي تعطي `outputProfile` بايتاته (وإلا جُلب من `profileBaseUrl`، وافتراضيًا نسخة مجلد `icc/` من postext على شبكة npm). والخيار `date` (كائن `Date` أو زمن بالمللي ثانية أو تاريخ مكتوب، مثل `mtime` في `createBundle`) هو تاريخ إنشاء الملف وتاريخ تعديله، وفي ملف PDF/X هو أيضًا تواريخ حزمة XMP ومنه يُشتق معرّف المستند: المستند نفسه إذا وُلّد مرتين بقيمة `date` واحدة أعطى البايتات نفسها. وإذا تُرك، حمل الملف وقت الاستدعاء. والتاريخ غير الصالح يرمي خطأ.
- **`PdfWarning`** — مشكلة غير قاتلة تصل عبر `onWarning`؛ ميّز نوعها بالحقل `kind`: `'fontFallback'` (`PdfFontFallbackWarning`)، شكل خط نُضّد بشكل آخر من عائلته؛ `'missingGlyph'` (`PdfMissingGlyphWarning`)، حروف لا يحوي أي ملف من ملفات شكل الخط رسمًا (glyph) لها؛ `'variableFontDefaultInstance'` (`PdfVariableFontWarning`)، خط متغيّر طُلب بوزن غير وزن نسخته الافتراضية؛ `'cffEmbeddedWhole'` (`PdfCffEmbeddedWholeWarning`)، شكل خط CFF يتجاوز 2 MB ضُمِّن كاملًا؛ `'complexShapingUnavailable'` (`PdfComplexShapingWarning`)، نص من اليمين إلى اليسار أو متصل الحروف رُسم دون HarfBuzz لتعذّر تحميله (يسرد `reason` الأماكن التي بُحث فيها عنه)، فتقع العلامات العربية في غير مواضعها؛ `'outputProfileUnavailable'` (`PdfPrintWarning`)، إنتاج بألوان CMYK تعذّر تحميل ملف تعريف الإخراج الخاص به، فحُوّلت ألوانه بالمعادلة البسيطة؛ `'pageNegativeIgnored'` (`PdfPrintWarning`)، الصفحة المعكوسة (page negative) التي أُسقطت من ملف PDF/X-1a؛ `'spotTintsExhausted'` (`PdfPrintWarning`)، عرض نفدت فيه الرموز التي تميّز درجات الألوان الخاصة (نحو 25 مليونًا) فطبع الباقي بالألوان الرباعية؛ `'spotInkRenamed'` (`PdfPrintWarning`)، حبر يُكتب لوحه باسم آخر (انظر [الألوان الخاصة](#الألوان-الخاصة))؛ `'imageProfileUnavailable'` (`PdfPrintWarning`)، تعذّر تحميل ملف التعريف المسند إلى صور RGB فاستُعملت ملفات تعريفها الخاصة؛ `'pictureOriginalUnreadable'` (`PdfPrintWarning`)، أصل TIFF أو Photoshop تعذّر فكّه، فطُبع من معاينه (`previewBytes`) أو عنصرًا نائبًا؛ `'plateMixesApproximated'` و`'artworkOffPlates'` (`PdfPrintWarning`)، مهمة على ألواح قليلة (`print.plates`) نفدت رموزها فطبعت الألوان الباقية بأقرب مزيج رمّزته من قبل، أو وضعت صفحة PDF أو صورة تعذّر فكّها بأحبارها الخاصة؛ أو `'missingImage'`، صورة بلا بايتات رُسم مكانها عنصر نائب (لا يصل هذا التحذير إلا إلى `onWarning` تمرّره أنت؛ أما تحذيرات الخطوط فتذهب، في غيابها، إلى `console.warn`).
- **`inspectPrintMaster(bytes): Promise<PrintMasterReport>`** — يقرأ الصفحة الأولى من نسخة أصلية للطباعة بصيغة PDF، ويذكر الخطوط التي تستعملها دون أن تضمّنها (`nonEmbeddedFonts`)، وهل ترسم بألوان RGB (`rgb`)، وهل تستعمل الشفافية (`transparency`)، من أجل [الفحص قبل الطباعة](/ar/docs/configuration-pdf-output#الفحص-قبل-الطباعة).
- **`inspectPrintPdf(bytes): Promise<PrintPdfReport>`** — يقرأ ملف PDF منتهيًا من جديد كما يفعل الفحص المسبق في المطبعة، بكل صفحاته: الإصدار وعدد الصفحات، وتعريف PDF/X وشرط الإخراج (وهل ملف التعريف مضمّن)، والمقاس النهائي وأصغر تجاوز للقص، والصفحات ذات المقاس النهائي المختلف أو بلا TrimBox أو ذات صندوق صفحة لا يتكوّن من أربعة أرقام (`malformedBoxPages`، ويُقرأ الصندوق فيها كأنه غير موجود)، والخطوط (`fonts`: الاسم، مضمّن أم لا، النوع؛ والخط المستعمل مضمّنًا وغير مضمّن يُذكر مرة لكل حالة)، وما يرسم به (CMYK، الرمادي، الألوان الخاصة بأسمائها، لون التسجيل، وRGB مقسومًا إلى `deviceRgb` بلا ملف تعريف و`iccRgb` بملف تعريف، وكلٌّ منهما في الرسم المتجهي `vector` أو في الصور `images`)، والشفافية، والطباعة الفوقية، والتعليقات، والنموذج التفاعلي، وهل هو موسوم. ويقرأ إلى جانب الصفحات مظاهر التعليقات، وحقول النموذج وموارده الافتراضية، والأنماط، وحروف Type 3، والصور المضمّنة في المحتوى. يقرأ ما يقوله الملف لا ما طلبه الإعداد، ولا يقرأ دقة الصور ولا مجموع الحبر ولا الخطوط الشعرية ولا التراكب (trapping). ويمرّ على الصفحات بالطريقة نفسها التي يمرّ بها `inspectPrintMaster`، الذي يبلّغ أيضًا عن RGB في التدرجات والأنماط وحروف Type 3.
- **`decompressWoff2(bytes): Uint8Array`** — دالة مساعدة تحوّل ملف WOFF2 إلى بايتات TTF، وهي الصيغة التي تستطيع `pdf-lib` تضمينها مباشرةً.
- **`createPdfWorker(options?)`**، من `postext-pdf/worker` — الإنتاج نفسه في عامل ويب؛ انظر [إنتاج ملف PDF في عامل](#إنتاج-ملف-pdf-في-عامل).

### مثال مختصر

```ts
import { buildDocument } from 'postext';
import { renderToPdf } from 'postext-pdf';

const vdt = buildDocument(
  { markdown: '# Chapter One\n\nThe story begins here…' },
  {
    page: { sizePreset: '17x24' },
    layout: { layoutType: 'double' },
    bodyText: { fontFamily: 'EB Garamond', fontSize: { value: 9, unit: 'pt' } }, // 9 pt overrides the 8 pt default
  },
);

const pdfBytes = await renderToPdf(vdt, {
  fontProvider: async (family, weight, style) => {
    // Return TTF bytes for this family/weight/style.
    // See the "Font provider" section below for a real implementation.
    const res = await fetch(`/fonts/${family}-${weight}${style === 'italic' ? 'i' : ''}.ttf`);
    return new Uint8Array(await res.arrayBuffer());
  },
});

// `pdfBytes` is a Uint8Array — save, download, or stream it.
const blob = new Blob([pdfBytes], { type: 'application/pdf' });
const url = URL.createObjectURL(blob);
window.open(url);
```

### لماذا مزوّد الخطوط؟

تضمّن `pdf-lib` ملفات خطوط حقيقية داخل ملف PDF: فالخطوط المثبّتة في المتصفح غير متاحة وقت الإنتاج، والخط الذي حمّلته لقياس النص على الشاشة فقط لا يكفي وحده لإنتاج ملف PDF مكتفٍ بذاته. تمسح `renderToPdf` الصفحات بحثًا عن كل شكل خط ترسمه (شكل خط لكل تركيبة `family|weight|style`؛ انظر [أشكال الخطوط التي يُسأل عنها المزوّد](#أشكال-الخطوط-التي-يُسأل-عنها-المزوّد)) وتستدعي المزوّد مرة واحدة لكل تركيبة فريدة. يعيد المزوّد `Uint8Array` من بايتات **TTF أو OTF**، أو قائمة منها لشكل خط يُقدَّم في عدة ملفات (انظر [خطوط الصينية واليابانية والكورية](#خطوط-الصينية-واليابانية-والكورية))؛ وتقتطع `pdf-lib` من خطوط TrueType المجموعة الفرعية (subset) المستخدمة، وتضمّن ملفات CFF (`.otf`) كاملة. ويُعلَن شكل الخط CFF على حقيقته، أي خطًّا من نوع `CIDFontType0` برنامجُه CFF في `FontFile3` (`CIDFontType0C`)، يُدرجه `pdffonts` على أنه `CID Type 0C`، وهو ما يتوقعه الفحص قبل الطباعة. أما شكل الخط CFF المفهرس بمعرّفات CID (Source Han، وملفات `.otf` من Noto CJK) فيبقى معلنًا على أنه TrueType، لأن ترقيم محارفه لا يطابق الترقيم الذي كُتب به النص؛ فاستخدم للطباعة إصدارات TrueType من هذه العائلات. وأشكال الخط التي يجيب عنها المزوّد بالملف نفسه، كشكل عادي يحلّ محل الشكل العريض الذي تفتقر إليه العائلة، تتشارك خطًا مضمَّنًا واحدًا. أما شكل الخط الذي لا ترسم به أي صفحة في النهاية، كشكل الخط المستعمل في نص شكل SVG حين يُرسم هذا الشكل صورةً، فيُستبعد من الملف.

**استخدم خطوطًا ثابتة لكل وزن، لا خطًا متغيّرًا واحدًا.** كثيرًا ما تقدّم Google Fonts ملف WOFF2 متغيّرًا واحدًا لكل عائلة يغطي محور الوزن كله. ولا تستطيع `pdf-lib` أن تضمّن من الملف المتغيّر إلا نسخته الافتراضية، فتُطبع الفقرة العريضة بالوزن العادي. تنشر Fontsource ملفات WOFF2 ثابتة لكل وزن تحل هذه المشكلة حلًا نظيفًا، وهذا هو النمط الذي يتبعه Sandbox، بيئة التجربة في المتصفح. وإذا طُلب ملف متغيّر بوزن غير وزن نسخته الافتراضية، ظهر التحذير `variableFontDefaultInstance`.

**كل كلمة من النص تقع حيث وضعها الإخراج.** في الفقرات وعناصر القوائم والاقتباسات والإطارات وغيرها من النص الجاري، تبدأ كل كلمة في الموضع الذي قاسته شجرة VDT، فلا يتراكم على امتداد السطر أي فرق بين عروض المتصفح وعروض شكل الخط المضمَّن. يُرسم السطر الخالي من التنسيق الداخلي كائنًا نصيًا واحدًا يحرّك القلم بين الكلمات؛ أما الأسطر المضبوطة والموسَّطة والأسطر ذات التنسيق فتُرسم كلمةً بعد كلمة. والحرف الذي ليس لشكل الخط رسم له، والذي قاسه المتصفح بخط آخر ويرسمه ملف PDF مربعَ الرسم المفقود في ذلك الوجه، لا يُزيح أيًّا من الكلمات التي تليه، ويظهر له التحذير `missingGlyph` مرة واحدة لكل شكل خط. والمسافة التي يفتقر إليها الوجه، كالمسافة الضيقة غير القابلة للكسر أو مسافة الأرقام، تأخذ العرض الذي أعطاها إياه المتصفح، ولا تُرسم الحروف غير المرئية كرابط الكلمات (word joiner) والمسافة الصفرية العرض. أما الواصلة غير القابلة للكسر (U+2011) التي يفتقر إليها شكل الخط فتُرسم بواصلة شكل الخط (U+2010)، أو بعلامة الواصلة والناقص (hyphen-minus) إن لم تكن فيه واصلة أيضًا، كما يعرضها المتصفح؛ ومن الخطوط التي تفتقر إلى الاثنتين Open Sans وOutfit. ولا تُعدّ أيّ من الحالتين رسمًا مفقودًا. وثمة استثناءان. فالسطر الذي فيه حروف من اليمين إلى اليسار يُرسم سلسلةً واحدة على أي حال (انظر [اللغات وأنظمة الكتابة](/ar/docs/configuration-language#اللغات-وأنظمة-الكتابة)). والنص الذي يضعه التصميم (الترويسات العلوية والسفلية، وصفحات الافتتاح، وعناوين الإطارات، وغيرها من عناصر التصميم) يُنضَّد بعروض شكل الخط المضمَّن نفسه، فالرسم الذي يفتقر إليه شكل الخط هناك يظل يُزيح باقي سطره.

### أشكال الخطوط التي يُسأل عنها المزوّد

تمرّ `renderToPdf` على الصفحات بالطريقة التي ترسمها بها، ولا تسأل المزوّد إلا عن أشكال الخط التي ترسم بها:

- شكل الخط العادي لكل كتلة تنضّد أي سطر، والشكل العريض أو المائل أو العريض المائل لكل سلسلة نُضّدت فعلًا بتلك الطريقة؛
- سلاسل الشارات (chips)، وعلامات القوائم، ونص خانات التصميم (الترويسات، وأرقام الصفحات، وأشرطة صفحات الافتتاح والأجزاء)؛
- نص التعليق والملاحظة وخلايا الجداول لكل مورد؛
- أشكال الخط التي يذكرها `<text>` في شكل SVG، حين يُضمَّن الشكل. والعائلة التي لا يستطيع المزوّد توفيرها إطلاقًا يُنتقل منها إلى العائلة التالية في قائمة `font-family` في ملف SVG.

فلا يُسأل أبدًا عن الشكل المائل لعائلة عناوين لا تُنضَّد بالمائل، ولا يحتاج شكلٌ بلا ملاحظة إلى أشكال خط الملاحظات.

حين يرفض المزوّد وجهًا، يستمر الإنتاج. يُضمَّن مكانه شكل آخر من العائلة نفسها، ويصدر تحذير `PdfWarning`. والبديل هو أول شكل يُحمَّل، بتجربة الأوزان القياسية التسعة (من 100 إلى 900) بالترتيب الذي تتبعه مطابقة الخطوط في CSS، وهو أيضًا شكل الخط الذي يعرضه المتصفح في المعاينة:

1. النمط نفسه أولًا. للوزن من 400 إلى 500، تأتي الأوزان حتى 500 أولًا، ثم الأخف بدءًا من الأقرب نزولًا، ثم الأثقل بدءًا من 600 صعودًا. وللوزن الأقل من 400، تأتي الأوزان الأخف أولًا بدءًا من الأقرب نزولًا، ثم الأثقل. وللوزن الأكبر من 500، تأتي الأوزان الأثقل أولًا، ثم الأخف؛
2. ثم النمط الآخر، المائل بدل القائم والقائم بدل المائل، بالوزن المطلوب ثم بالأوزان الأخرى بالترتيب نفسه.

لذلك تنضّد العائلة التي لا مائل فيها سلاسلها المائلة قائمةً، وتأخذ العائلة التي لا تقدّم إلا 400 و700 الوزن 600 على أنه 700، وتنضّد العائلة التي لا تقدّم إلا شكلًا واحدًا كل شيء به. ويُسأل المزوّد عن شكل واحد في كل مرة، بذلك الترتيب، ولا يُسأل مرتين عن شكل الخط نفسه، فلا يُضمَّن أبدًا شكل لا يستخدمه شيء. والعائلة التي لا يستطيع المزوّد توفيرها إطلاقًا يُسأل عن أشكالها الثمانية عشر كلها قبل أن يفشل الإنتاج.

```ts
const bytes = await renderToPdf(doc, {
  fontProvider,
  onWarning: (w) => {
    // { kind: 'fontFallback', family: 'Oswald', weight: 700, style: 'italic',
    //   fallback: { weight: 700, style: 'normal' }, reason: '…', message: '…' }
    console.info(w.message);
  },
});
```

في غياب `onWarning`، تذهب الرسالة إلى `console.warn`. يحتفظ النص بمواضعه، وهي مأخوذة من شجرة VDT وقيست بأشكال الخط التي كانت لدى المتصفح، لذا قد يبدو البديل ذو العروض المختلفة متراصًّا أو متخلخلًا. وفّر شكل الخط الحقيقي لإصلاح ذلك. ولا يفشل الإنتاج (`postext-pdf: failed to load font(s): …`) إلا حين لا يستطيع المزوّد توفير أي شكل لعائلة ما بوزن قياسي، قائمًا كان أو مائلًا.

### مزوّد الخطوط في المتصفح (Fontsource + WOFF2)

يأتي Sandbox مع `createPdfFontProvider()` (`packages/postext-sandbox/src/viewport/pdf/pdfFontProvider.ts`)، ويمكنك نسخها إلى أي تطبيق يعمل في المتصفح. هذه أساسياتها:

```ts
import type { PdfFontProvider } from 'postext-pdf';
import { decompressWoff2 } from 'postext-pdf';

const bytesCache = new Map<string, Promise<Uint8Array>>();

function fontsourceId(family: string): string {
  return family.toLowerCase().replace(/\s+/g, '-');
}

function fontsourceWoff2Url(
  family: string,
  weight: number,
  style: 'normal' | 'italic',
): string {
  const id = fontsourceId(family);
  return `https://cdn.jsdelivr.net/npm/@fontsource/${id}@5/files/${id}-latin-${weight}-${style}.woff2`;
}

export function createPdfFontProvider(): PdfFontProvider {
  return async (family, weight, style) => {
    const key = `${family}|${weight}|${style}`;
    const cached = bytesCache.get(key);
    if (cached) return cached;

    const promise = (async (): Promise<Uint8Array> => {
      const url = fontsourceWoff2Url(family, weight, style);
      const res = await fetch(url, { mode: 'cors' });
      if (!res.ok) throw new Error(`font fetch failed: ${res.status} ${url}`);
      // pdf-lib needs TTF bytes, so decompress the WOFF2 wrapper client-side.
      return decompressWoff2(new Uint8Array(await res.arrayBuffer()));
    })();

    bytesCache.set(key, promise);
    return promise;
  };
}
```

ينبغي لنسخة الإنتاج أيضًا أن:

- **تستعلم عن الأوزان المتاحة** (عبر `https://api.fontsource.org/v1/fonts/{id}`) وتقرّب الوزن المطلوب إلى أقرب وزن تقدّمه العائلة فعلًا، فينجح طلب `weight: 600` على عائلة لا تملك إلا `{400, 700}`.
- **تعود من المائل إلى العادي** حين لا يكون للعائلة شكل مائل بالوزن المطلوب، بدل إفشال الإنتاج كله.
- **تعيد استخدام الذاكرة المؤقتة بين عمليات الإنتاج** (أبقِ `bytesCache` على مستوى الوحدة، لا داخل كل استدعاء)، فتصبح إعادة توليد ملف PDF بعد تغيير في الإعدادات شبه مجانية.

### خطوط الصينية واليابانية والكورية

لا يأتي شكل خط CJK في ملف صغير واحد. تقدّم Fontsource الخط Noto Serif SC في نحو مئة ملف لكل وزن، يضم كل منها جزءًا من الحروف، ويُعلَن عنه في ورقة أنماط العائلة مع نطاقه `unicode-range` (`@fontsource/noto-serif-sc/400.css`)؛ ويُنزّل المتصفح الملفات التي يمسّها نص الصفحة. وملف `latin` الذي يجلبه المزوّد أعلاه لا يحوي أي حرف من حروف الهان (Han) على الإطلاق، والمجموعات الفرعية المسمّاة ناقصة: فالمجموعة `chinese-simplified` من Noto Serif SC تفتقر إلى 釵، والمجموعة `chinese-traditional` من Noto Serif TC لا تحوي أيًّا من العلامات كاملة العرض （），！？：；.

لذا يجوز للمزوّد أن يجيب عن شكل الخط بعدة ملفات. تمرّر إليه `renderToPdf` الحروف التي تنضّدها الصفحات بشكل الخط ذاك (`request.codePoints`)، مجموعةً من كل الفصول قبل رسم أي شيء، ويعيد المزوّد الملفات التي تحويها، بالترتيب الذي يبحث به المتصفح فيها. يُضمَّن كل ملف مجموعةً فرعية مستقلة، ويُرسم كل حرف من أول ملف فيه رسم له: فالفصل الذي يمسّ 60 شريحة يضمّن 60 مجموعة فرعية صغيرة. وشكل الخط الذي يُطلب مرة أخرى، لنص شكل SVG مثلًا، لا يُسأل عنه إلا للحروف التي تفتقر إليها ملفاته. والمزوّد الذي يعيد `Uint8Array` واحدة يعمل كما كان. يقرأ مزوّد Sandbox ورقة أنماط Fontsource الخاصة بالوزن والنمط، ويجلب الملفات التي تحوي نطاقاتها النص؛ وهذا جوهره:

```ts
import type { PdfFontProvider } from 'postext-pdf';
import { decompressWoff2 } from 'postext-pdf';

type Slice = { url: string; ranges: Array<[number, number]> };

async function fontsourceSlices(family: string, weight: number, style: 'normal' | 'italic'): Promise<Slice[]> {
  const id = family.toLowerCase().replace(/\s+/g, '-');
  const cssUrl = `https://cdn.jsdelivr.net/npm/@fontsource/${id}@5/${weight}${style === 'italic' ? '-italic' : ''}.css`;
  const css = await (await fetch(cssUrl)).text();
  return [...css.matchAll(/@font-face\s*{([^}]*)}/g)].map(([, rule]) => ({
    url: new URL(/url\(\.?\/?([^)]+\.woff2)\)/.exec(rule)![1], cssUrl).href,
    ranges: /unicode-range:\s*([^;]+);/.exec(rule)![1].split(',').map((part) => {
      const [lo, hi = lo] = part.trim().slice(2).split('-');
      return [parseInt(lo, 16), parseInt(hi, 16)] as [number, number];
    }),
  }));
}

export const sliceFontProvider: PdfFontProvider = async (family, weight, style, request) => {
  // Where ranges overlap, the browser tries the last rule first.
  const slices = (await fontsourceSlices(family, weight, style)).reverse();
  const picked = new Set<Slice>();
  for (const cp of request?.codePoints ?? []) {
    const slice = slices.find((s) => s.ranges.some(([lo, hi]) => cp >= lo && cp <= hi));
    if (slice) picked.add(slice);
  }
  if (picked.size === 0) picked.add(slices[0]!);
  return Promise.all(slices.filter((s) => picked.has(s)).map(async (s) =>
    decompressWoff2(new Uint8Array(await (await fetch(s.url)).arrayBuffer()))));
};
```

وتمرّ العائلة اللاتينية بالشيفرة نفسها: يأخذ النص الإنجليزي ملفه `latin` وحده، ويأخذ النص التشيكي `latin` و`latin-ext`.

والمتصفح لا يكتفي بأول ملف فيه رسم. فهو ينضّد الحرف من الملف المعلَن أخيرًا بين الملفات التي يشمله `unicode-range` فيها، وملفات العائلة تتداخل: يكرّر Fontsource حروف ASCII في Noto Serif JP في ملفه `latin` وفي شرائحه المرقّمة. ولا تقنين أزواج (kerning) بين حرفين منضَّدين من ملفين، فالملف يحدّد العرض: ينضّد Chrome 154 `Shift_JIS` بعرض 4.25 em إذا أُعلنت الشرائح بعد `latin`، أما الملف `latin` وحده، وهو يقنّن `t_` و`_J`، فينضّدها بعرض 4.32 em. ومنذ postext-pdf 1.30 يجوز للمزوّد أن يذكر كيف أعلنت الصفحة كل ملف: تعيد `declaredFontFile(bytes, { unicodeRange, order })` البايتات نفسها ومعها قيمة `unicode-range` في قاعدة الملف، كما تكتبها CSS، وموضع تلك القاعدة بين قواعد الوجه، وهو أي عدد يكبر مع ترتيب الإعلان (والأكبر هو المعلَن أخيرًا).

```ts
import { declaredFontFile } from 'postext-pdf';

declaredFontFile(bytes, { unicodeRange: 'U+0000-00FF,U+0131,U+0152-0153', order: 0 });
```

وإذا كانت ملفات شكل الخط تذكر نطاقاتها، ففي مستند يُشكَّل بلغته ([`bodyText.shapingLanguage: 'document'`](/ar/docs/configuration-text#نص-المتن)، وهي القيمة الافتراضية) يُرسم كل حرف من الملف المعلَن أخيرًا بين الملفات التي يشمله نطاقها وفيها رسم له، كما يختار المتصفح بين قواعد `@font-face`، ويبقى الحرف وعلاماته المركّبة في ملف واحد. والحرف الذي لا يشمله أي نطاق يُرسم من أول ملف فيه رسم له. أما الملفات التي ليست فيها هذه البيانات، وكل ملفات مستند يستعمل `'host'`، فتُقرأ بالترتيب المعطى كما كانت، فالمزوّد الذي يصف ملفاته يظل يضع المعلَن أخيرًا في أول القائمة. وشكل الخط الموصوف هكذا يُسأل عنه مرة أخرى لكل حرف لم يُسأل عنه من قبل، فقد يكون في ملف أُعلن لاحقًا. ومزوّد Sandbox يصف ملفاته.

الحروف التي لا يحوي أي ملف من ملفات شكل الخط رسمًا لها تُرسم بالرسم `.notdef` في الخط (مربع فارغ في معظم الخطوط)، وتُصدر `renderToPdf` تحذيرًا بها مرة واحدة لكل شكل خط بعد رسم الصفحات:

```ts
// { kind: 'missingGlyph', family: 'Noto Serif TC', weight: 400, style: 'normal',
//   characters: ['，', '！', '？'], message: '…' }
```

يسرد Sandbox هذه الحروف، والتحذيرين الواردين أدناه، في لوحة الفحوص (Checks) بعد كل ملف PDF يولّده. وحين يتغيّر الكتاب أو إعداداته أو موارده، تُعلَّم على أنها آتية من ملف PDF سابق إلى أن يحل محلها الملف التالي؛ وفتح كتاب آخر يمسحها.

- **الشكل العريض يحتاج إلى ملف ثابت لكل وزن.** تقدّم Fontsource كل وزن من Noto Serif SC وTC في ملفات ثابتة منفصلة، لذا يعمل الشكل العريض في Sandbox. أما ملفات Google Fonts (`NotoSerifSC[wght].ttf`، 25 MB) فهي خطوط متغيّرة: تضمّن pdf-lib نسختها الافتراضية، فيُطبع الشكل 700 بالوزن 400، وتُصدر `renderToPdf` لذلك التحذير `variableFontDefaultInstance`. ولحزمة الكتاب، اقتطع نسخة ثابتة لكل وزن بأداة fontTools (`fonttools varLib.instancer NotoSerifSC[wght].ttf wght=700`) ثم اقتطع منها المجموعة الفرعية لحروف الكتاب بالأداة `pyftsubset`.
- **استخدم إصدارات TrueType.** ملفات `.otf` من Source Han Serif وNoto Serif CJK ذات مخططات CFF، وتضمّنها postext-pdf كاملة، من 8 إلى 25 MB لكل وزن؛ وإذا تجاوز شكل خط CFF حجم 2 MB، ظهر التحذير `cffEmbeddedWhole`. أما إصدارات TrueType (Google Fonts، Fontsource) فتُقتطع منها الرسوم المستخدمة فقط. وللّغة اليابانية تأتي Noto Serif JP وNoto Sans JP (من Google Fonts، أو الشرائح المرقّمة في Fontsource) وShippori Mincho وZen Old Mincho وBIZ UDMincho بصيغة TrueType؛ أما Source Han Serif JP وملفات `.otf` ذات اللاحقة `JP` من Noto Serif CJK فهي CFF.
- **الأشكال اليابانية في الخطوط الشاملة للغات الصينية واليابانية والكورية.** قد تُرسم نقطة الترميز الواحدة لحرف هاني أو لعلامة ترقيم أو لعلامة اقتباس على نحو في اليابان وعلى نحو آخر في الصين، والخط الشامل (Source Han، Noto CJK) يحوي الشكلين. يُشكّل ملف PDF المستندَ الياباني (`locale: 'ja'`)، والمقطعَ المعزول المكتوب باليابانية (`:ltr[…]{lang=ja}`) في أي مستند، بنظام اللغة `JAN ` في OpenType، فتطبع خاصية `locl` في الخط الأشكالَ اليابانية التي يطبعها Canvas وHTML عبر `lang`. أما المقطع المعزول بلغة أخرى داخل كتاب ياباني فيُشكَّل بأشكال تلك اللغة (الأشكال الافتراضية للخط في حالة الصينية مع `'host'`) ويُوسَم بعنصر `Span` فيه `/Lang` الخاص به. ومع [`bodyText.shapingLanguage: 'document'`](/ar/docs/configuration-text#نص-المتن)، وهي القيمة الافتراضية منذ postext 1.30، يُشكَّل كل مستند وكل مقطع معزول بلغته (`ZHS` للصينية المبسطة)، كما قاسه الإخراج؛ أما مع `'host'` فتُشكَّل المستندات الصينية وغيرها بالأشكال الافتراضية للخط كما كانت. والخط المصمَّم لليابانية مثل Noto Serif JP أشكاله الافتراضية يابانية أصلًا، لكنه يضع “ ” في النص الياباني بشكلها `JAN `.

لا يؤخذ الحرف المفقود من عائلة ما من عائلة أخرى: فلا تستعير Noto Serif TC من Noto Serif SC. احسم التغطية عند بناء ملفات الخطوط؛ فنموذج العرض 红楼梦 ينسخ إلى مجموعاته الفرعية من TC الرسوم التي تفتقر إليها، آخذًا إياها من شكل خط SC.

### مزوّد الخطوط على الخادم (Node، ملفات محلية)

في Node يمكنك تجاوز خطوة WOFF2 كليًا وقراءة ملفات TTF/OTF من القرص:

```ts
import { readFile } from 'node:fs/promises';
import { join } from 'node:path';
import type { PdfFontProvider } from 'postext-pdf';

const FONT_DIR = '/path/to/fonts';

function filename(family: string, weight: number, style: 'normal' | 'italic'): string {
  const slug = family.replace(/\s+/g, '');
  const styleSuffix = style === 'italic' ? 'Italic' : '';
  const weightName =
    weight >= 700 ? 'Bold'
    : weight >= 600 ? 'SemiBold'
    : weight >= 500 ? 'Medium'
    : weight >= 300 ? 'Light'
    : 'Regular';
  return `${slug}-${weightName}${styleSuffix}.ttf`;
}

export const localFontProvider: PdfFontProvider = async (family, weight, style) => {
  const buf = await readFile(join(FONT_DIR, filename(family, weight, style)));
  return new Uint8Array(buf);
};
```

### بايتات الموارد والنسخ الأصلية للطباعة

تعيد `resourceBytes(fileId)` البايتات الخام لصورة، ويتعرّف المُخرِج على صيغتها من البايتات:

- تُضمَّن صور PNG وJPEG وGIF وWebP صورًا؛
- تُرسم شيفرة SVG مسارات متجهية، ويُنضَّد `text` فيها نصًا حقيقيًا بالخطوط المضمَّنة في المستند، أو تُحوَّل إلى صورة نقطية بدقة 600 dpi في المتصفح حين تستخدم ميزات خارج المجموعة المتجهية المدعومة. ويُتخطّى `<style>` لا يحوي إلا قواعد `@font-face` (أشكالَ خطوط ضمّنها المؤلف) فيبقى الشكل متجهيًا (منذ postext-pdf 1.25)؛ أما أي ورقة أنماط أخرى فتجعله صورة نقطية، تُرسم وأشكال الخط التي يذكرها نصه مضمَّنة فيها من `fontProvider` (ما لم تكن `diagramStyle.inlineFonts` أو `svg.inlineFonts` الخاصة بالمورد `false`)؛
- تُطبع مستندات TIFF وPhotoshop (PSD وPSB) من بكسلاتها نفسها: رمادية أو RGB أو CMYK، بعمق 8 أو 16 بت، مع ملف تعريف ICC والدقة اللذين تحملهما. ويحتفظ مستند CMYK بأحباره كما هي؛ أما الرمادي وRGB فيتبعان `print.imageColor`. ويُقرأ مستند Photoshop من الصورة المركّبة التي يحفظها مع خيار «Maximize compatibility»؛ ولا تُقرأ ملفات TIFF المضغوطة بـJPEG؛
- ملف PDF تُضمَّن صفحته الأولى كما هي، في هيئة form XObject.

تُخزَّن كل صورة في الملف مرة واحدة، مهما تكرر رسمها. يصبح ملف SVG المرسوم مسارات متجهية form XObject ترسمه كل صفحة، فالإطار أو الشعار في تصميم صفحات مستند من ثلاثين صفحة يُكتب مرة واحدة لا ثلاثين مرة؛ وتضيف كل صفحة إضافية بضع مئات من البايتات. وحتى الإصدار 1.4 من postext-pdf، كانت كل صفحة تتضمّن نسختها الخاصة من المسارات.

يمكن أن يحدّد شكل SVG **نسخة أصلية للطباعة** (print master) في `svg.pdfFileId`: ملف PDF من صفحة واحدة للشكل نفسه، وهو عادةً الأصل الذي صُدِّر منه ملف SVG. تسأل `renderToPdf` الدالة `resourceBytes` عن معرّف النسخة الأصلية أولًا. وتضمّن تلك الصفحة مكان ملف SVG، بخطوطها وتدرّجاتها وفضاءات ألوانها سليمةً، أينما رُسم ملف SVG: شكلًا، أو صورةً في خلية جدول (`TableCell.image`)، أو صورةَ تصميم، أو أيقونةَ إطار (وعلامته `marker` كذلك). تتضمّن شجرة VDT معرّف النسخة الأصلية في كل استخدام من هذه الاستخدامات (`svg.pdfFileId` على مورد الشكل، و`pdfFileId` على صورة الخلية وعلى كتلة صورة التصميم)، فيحصل كل فصل من فصول الكتاب على النسخة الأصلية. ويواصل مُخرِجا Canvas وHTML رسم ملف SVG. وتُستخدم بايتات ملف SVG نفسه بدلًا منها في ثلاث حالات: حين تكون النسخة الأصلية مفقودة، أو حين لا تكون ملف PDF، أو حين يكون الحبر الواحد مفعّلًا (`diagramStyle.singleInk` يعيد تلوين شيفرة SVG وحدها).

```ts
const resources: Resource[] = [{
  id: 'map', typeId: 'figure', kind: 'svg', createdAt: 0, updatedAt: 0,
  svg: { fileId: 'map.svg', width: 800, height: 600, pdfFileId: 'map.pdf' },
}];
const files = new Map([['map.svg', svgBytes], ['map.pdf', masterPdfBytes]]);
const pdf = await renderToPdf(buildDocument({ markdown, resources }, config), {
  fontProvider,
  resourceBytes: (fileId) => files.get(fileId),
});
```

يمكن للمضيف أيضًا أن يعيد بايتات النسخة الأصلية لمعرّف ملف SVG نفسه، كما تفعل `bundleResourceBytes`؛ والطريقتان تعملان.

لا يستطيع المتصفح عرض ملف TIFF ولا مستند Photoshop، لذا يحتفظ مورد الصورة النقطية المصنوع من أحدهما بملفين: `bitmap.fileId` معاينة بصيغة PNG تعرضها Canvas وHTML وEPUB، و`bitmap.printFileId` (مع `printFormat: 'tiff' | 'psd'`) هو الأصل. ويعيد المضيف بايتات الأصل لـ`bitmap.fileId`، كما تفعل `bundleResourceBytes` وSandbox، ويُطبع ملف PDF منه. ويمرّر المعاين أيضًا بوصفه `previewBytes` (و`bundlePreviewBytes` للحزمة): يُطبع الأصل الذي يتعذّر فكّه من معاينه مع تحذير `pictureOriginalUnreadable`، ومن دونه يُرسم عنصر نائب. وتقرأ `decodePrintRaster(bytes)` و`rasterToRgba(raster)` في `postext` الأصل وتصنعان المعاينة؛ ويصنعها Sandbox عند استيراد الملف، وتخزّن الحزمة الأصل باسم `resources/<name>.tif` أو `.psd` بجانب المعاينة.

ملف Adobe Illustrator المحفوظ مع خيار «Create PDF Compatible File» هو ملف PDF، ويمكن أن يكون نسخة أصلية للطباعة كأي ملف آخر (`.ai`). وعيّناته هي ألواحه الخاصة: يسرد الفحص قبل الطباعة ما يعيد جدول الأحبار تسميته منها، وما لا يعرّفه أي لون في الكتاب، وما لا تطبعه المهمة إن كانت تُطبع على ألواحها الخاصة (`print.plates`)، لأن الملف الموضوع يُطبع كما هو.

### النص العمودي في ملف PDF

تُرسم الصفحة العمودية (`layout.writingMode: 'vertical-rl'`) عبر إطار مُدار ربع دورة، كما ترسمها Canvas، ويُنضَّد نصها نزولًا في العمود:

- **الحروف القائمة** تُعرض عبر خط Type0 ثانٍ من الملف المضمَّن نفسه: الخط CIDFont نفسه والعروض نفسها وجدول ToUnicode نفسه، مع `Encoding /Identity-V` (الوضع العمودي). كل سلسلة من الحروف كائن نصي واحد تتقدّم رسومه بنفسها مسافة em واحدة نزولًا في العمود (`DW2 [880 −1000]`)، فتحدّد برامج القراءة العمود وتستخرجه سطرًا واحدًا. تُشكَّل الرسوم بخاصيتَي OpenType المسمّاتين `vert` و`fwid`، ما يعطي الأقواس وعلامات الاقتباس وعلامات الوقف الصينية القارية وعلامات الحذف والشرطات أشكالها العمودية؛ والحرف الذي يقف قائمًا كما هو يحتفظ برسمه الأفقي. ولا يُضمَّن أي شيء من الخط مرتين.
- **الكلمات اللاتينية والأعداد الطويلة** تجري جانبيًا بالخط الأفقي؛ و**العدد المنضَّد في خلية واحدة** يقف قائمًا، مضغوطًا عرضًا إلى مقدار em حين يكون أعرض منه؛ والعلامة التي ليس لها في الخط شكل عمودي تُدار أو تُزاح، كما في Canvas.
- **تباعد الحروف** يُكتب أعدادًا في `TJ`، وهي في الوضع العمودي تحرّك القلم نزولًا في العمود.
- **كل سطر عمودي** يُعلَّم بـ`/ActualText` فيه نصه، فيقرؤه النسخ واستخراج النص كما كُتب. يقرأ `pdftotext` وpdf.js الأعمدة من الأعلى إلى الأسفل ومن اليمين إلى اليسار؛ ويبدأ pdf.js سطرًا جديدًا عند عدد منضَّد في خلية واحدة.
- **الروابط والإشارات المرجعية والوجهات** تُسقَط على الورقة: الرابط فوق سطر عمودي مستطيل طويل رفيع، والإشارة المرجعية تفتح الصفحة عند أعلى عمود عنوانها.
- **ملف PDF الموسوم** (tagged) يصرّح بنمط الكتابة في عنصره `Document` (السمة `WritingMode /TbRl` من سمات Layout، وترثها كل العناصر)؛ ويجتاز الفصل العمودي التحقق من PDF/UA-1 (veraPDF).
- **برامج العرض:** تعرض Acrobat وPreview وChrome (PDFium) وpdf.js وPoppler الخطوط العمودية. والكتاب المجلّد من اليمين (`page.binding`) يطلب أيضًا من برامج العرض أن تعرض صفحاته المتقابلة من اليمين إلى اليسار (`/Direction /R2L`، `/PageLayout /TwoPageRight`)؛ وتلتزم بذلك Acrobat وFoxit، ولا يلتزم به Chrome.

يبلغ حجم فصل من 43 صفحة منضَّد بخط Noto Serif TC (حروف الكتاب، TrueType) نحو 820 KB، معظمها للمجموعتين الفرعيتين من الخط.

### حقول النماذج

الشارة التي تحمل السمة `field` حقلُ نموذج قابل للتعبئة (AcroForm). تُنضَّد الشارة وترسم إطارها كأي شارة أخرى: يحدّد نمطها مظهرها وأدنى عرض لها (`minWidth`)، وكلماتها هي القيمة الافتراضية للحقل. ويضع ملف PDF حقلًا تفاعليًا فوق الإطار؛ والاسم المستعمل مرتين حقلٌ واحد له عنصرا واجهة (widget).

```md
الكمية :chip[ ]{style="field" field="pos.a.qty" kind="number"}
السعر :chip[120]{style="field" field="pos.a.price" format="currency"}
المجموع :chip[ ]{style="field" field="pos.a.total" format="currency" calc="product(pos.a.qty, pos.a.price)"}
الخدمة :chip[ ]{style="box" field="pkg.a" kind="checkbox" on="1"}
إجمالي الطلب :chip[ ]{style="field" field="order.total" format="currency" calc="sum(pos.a.total, product(pkg.a, 161.75))"}
المقاس :chip[M]{style="field" field="size" kind="choice" options="S|M|L"}
```

- `kind`: `text` (الافتراضي)، و`number`، و`checkbox`، و`choice` (مع `options` مفصولةً بالرمز `|`). والشارة التي لها `format` أو `calc` بلا `kind` حقلٌ رقمي.
- `on` (لمربع الاختيار): اسم حالة التفعيل في المربع، وهو القيمة التي تقرؤها نصوصه البرمجية حين يكون محدَّدًا. مع `on="1"` يُحسب المربع المحدَّد 1 في العملية الحسابية، فيضيف `product(pkg.a, 161.75)` سعرًا ثابتًا حين يُحدَّد المربع. والقيمة الافتراضية `Yes`، وتحسبها العملية الحسابية 0.
- `format`: `currency`، و`decimal` (منزلتان عشريتان)، و`integer`. يُكتب بالدالتين `AFNumber_Format` و`AFNumber_Keystroke` من Acrobat، بفواصل لغة المستند (`1.234,56` في الألمانية) ما لم يحدّد `RenderToPdfOptions.forms.separatorStyle` غير ذلك؛ والعملة هي `forms.currency` (الافتراضية `€`)، وتسبق الرقم ما لم تكن قيمة `forms.currencyBefore` هي `false`. وتُرسم القيمة الافتراضية منسَّقة.
- `calc`: `sum(…)` أو `product(…)` أو `min(…)` أو `max(…)` أو `avg(…)`. والوسائط حقول أخرى بأسمائها، وأرقام (بنقطة عشرية، مثل `161.75`)، وعمليات حسابية متداخلة، مثل `sum(pos.a.total, pos.b.total, product(pkg.a, 161.75))`. وتُكتب العملية الحسابية التي لا تتناول إلا الحقول بالدالة `AFSimple_Calculate`. أما التي تتضمّن أرقامًا أو عمليات متداخلة فلها نص برمجي قصير خاص بها من نوع Calculate، يقرأ كل حقل بالطريقة نفسها (`AFMakeNumber` لقيمته؛ وما ليس رقمًا يُحسب 0) ويقرّب النتيجة إلى ست منازل عشرية. والحقل المحسوب للقراءة فقط، ويراعي ترتيبُ الحساب كلَّ حقل يقرؤه، بما في ذلك الحقول داخل العمليات المتداخلة. وتصدر تحذيرات `formField` في هذه الحالات: عملية حسابية تقرأ حقلًا مجهولًا (يُحسب 0)، ودورة، واسم مستعمل لنوعين، ومربع اختيار في عملية حسابية ليست قيمة `on` فيه رقمًا (يُحسب دائمًا 0).
- `readonly` و`required` و`multiline` و`tooltip` تعمل كما تدل أسماؤها.

يعرض الحقل قيمته، وما يكتبه المستخدم فيه، بشكل خط شارته (`forms.font: 'chip'`، الافتراضي)، أو بشكل من خطوط المستند يسمّيه `forms.font` (`{ family, weight?, style? }`، ويُطلب من `fontProvider` كأي شكل آخر). ويُضمَّن هذا الشكل **كاملًا** لا مجموعةً جزئية، لأن المجموعة الجزئية تخلو من رسوم الحروف التي تُكتب لاحقًا؛ ويُضمَّن مرة واحدة مهما كان عدد الحقول التي تستعمله، ويُذكر اسمه في الموارد الافتراضية للنموذج (`/DR`) وفي المظهر الافتراضي لكل حقل (`/DA`)، وتُرسم به القيم الافتراضية. ويضيف الشكل الكامل ملفه كله إلى PDF (يبلغ خط النصوص اللاتيني عادةً 50–300 KB، وخط CJK عدة MB)، فوق المجموعة الجزئية التي يستعملها نص الصفحات. ويجوز أن يجيب المزوّد بملف TrueType أو OpenType أو WOFF2 (يُفكّ ضغطه قبل التضمين). وتعود الحقول إلى Helvetica، مع تحذير `formField`، حين يتعذّر تضمين الشكل كاملًا: إذا منع ترخيصه التضمين (`fsType` في جدول OS/2 مقيَّد أو للصور النقطية فقط)، أو أعطاه المزوّد في عدة ملفات (خط مجزّأ)، أو كانت صيغته WOFF أو مجموعة خطوط. ومع `forms.font: 'helvetica'` تُستعمل Helvetica دون تضمين شيء. وبعض العارضات (مثل Preview في macOS) ترسم النص في أثناء كتابته بخط من عندها؛ والقيمة واحدة.

تشغّل Acrobat وFoxit وpdf.js (Firefox) ومعظم العارضات هذه النصوص البرمجية. ولا تسمح معايير الطباعة (PDF/X) بالحقول التفاعلية: فتُرسم القيم فيها نصًا، وتُرسم قيمة الحقل الرقمي كما يعرضها النموذج (منسَّقةً، ومحاذاةً إلى نهاية الإطار داخل `paddingX` الخاص بالنمط، بلون الشارة).

ويرسم Canvas الحقل الرقمي بالطريقة نفسها، فتطابق المعاينةُ ملف PDF: مرّر إلى `renderPageToCanvas` (أو `renderPage` أو `renderToCanvas`) خيار `forms` نفسه الذي تمرّره إلى `renderToPdf`؛ وفي الحالتين تُؤخذ الفواصل افتراضيًا من `locale` المستند (وإلا فمن لغة تقطيع كلماته). وقاعدة واحدة تكتب الأرقام في كل مكان، ويصدّرها postext لمولّدات الإخراج الأخرى: يحلّ `formNumberStyle(forms, lang)` الخيارات، وينسّق `formatFieldNumber(value, format, style)` قيمةً (ويعيد undefined لنص ليس رقمًا)، ويعطي `numberFieldText(field, words, style)` ما يعرضه حقل رقمي مرسوم. وتحمل قائمة العرض الحقلَ على مقطع الشارة (`inline.field`، مع `sizePx` و`padPx` من التخطيط).

يستطيع الكتاب أن يحفظ هذه الخيارات في إعداداته: تأخذ `pdfGeneration.forms` الحقول نفسها (`currency`، `currencyBefore`، `separatorStyle`، `font`). ويأخذ `renderToPdf` وCanvas كل حقل من خيار `forms` الخاص بهما أولًا، ثم من `pdfGeneration.forms` في المستند الأول، ثم من القيم الافتراضية. ولا يغيّر ذلك التنضيد، بل طريقة كتابة الحقول ورسمها فقط. وفي Sandbox هي مجموعة **حقول النماذج** في قسم PDF.

```ts
pdfGeneration: {
  forms: { currency: 'USD', currencyBefore: true, separatorStyle: 0, font: { family: 'Lora', weight: 400 } },
}
```

**عند الاستيراد من esm.sh في المتصفح**، استورد `https://esm.sh/postext-pdf?bundle`. فالبناء الافتراضي لمكتبة pdf-lib على esm.sh يضع أصناف التعليقات في وحدة مستقلة، فترفض pdf-lib عنصر كل حقل: تبقى المربعات في PDF لكنها تفقد التنسيقات والحسابات والخصائص، مع تحذير `formField` لكل حقل. أما `?bundle` فيبني pdf-lib وحدةً واحدة ويترك `postext` خارجها مشتركةً مع الصفحة. ولا يتأثر بذلك المجمِّع (Vite وwebpack وNext.js) ولا Node.

ويكتب تصدير IDML الحقول نفسها حقولَ نماذج في InDesign (انظر [الاستخدام البرمجي › حزم InDesign](/ar/docs/configuration-programmatic-usage#حزم-indesign-postext-idml)).

### الروابط في ملف PDF

تصبح كلمات رابط Markdown (انظر [صيغة المستند › الروابط](/ar/docs/document-format-inline#الروابط)) تعليقات روابط توضيحية (annotations) من نوع URI، واحدًا لكل سلسلة من الكلمات المرتبطة في السطر. يغطي كل منها مستطيل السطر، ولا حدود له. وفي الإنتاج الميسَّر الوصول، تكون كل سلسلة عنصر `Link` قيمة `/Contents` فيه هي نصه. لا تُربط إلا الوجهات المطلقة `http:` و`https:` و`mailto:` و`tel:` و`ftp:`، لأن عنوان URL النسبي لا أساس له داخل ملف PDF. وتُرمَّز الحروف الواقعة خارج ASCII القابل للطباعة بترميز النسبة المئوية. وتحتفظ استشهادات `:ref` وصفوف جدول المحتويات بروابطها داخل المستند.

### مثال كامل في المتصفح: البناء والإنتاج والتنزيل

بجمع كل ما سبق: ابنِ شجرة VDT، وأنتج ملف PDF، وأطلق تنزيلًا من المتصفح:

```tsx
import { buildDocument, createMeasurementCache } from 'postext';
import { renderToPdf } from 'postext-pdf';
import { createPdfFontProvider } from './pdfFontProvider';

const fontProvider = createPdfFontProvider();

export async function downloadPdf(markdown: string, config: PostextConfig) {
  const cache = createMeasurementCache();
  const vdt = buildDocument({ markdown }, config, cache);

  const bytes = await renderToPdf(vdt, { fontProvider });

  const blob = new Blob([bytes.slice().buffer], { type: 'application/pdf' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'document.pdf';
  document.body.appendChild(a);
  a.click();
  a.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
}
```

**مهم:** استدعِ `ensureConfigFontsLoaded(config)` (أو ما يعادلها) *قبل* `buildDocument` حين تشير إعداداتك إلى خطوط ويب. يُقاس الإخراج بمقاييس الخط المتوفرة لدى المتصفح لتلك العائلة في تلك اللحظة؛ فإن لم يصل الخط الحقيقي بعد، قيست شجرة VDT بخط بديل ولن يطابق ملف PDF مخرجات Canvas أو HTML. يفعل Sandbox ذلك صراحةً قبل كل إنتاج (انظر `packages/postext-sandbox/src/viewport/pdf/PdfViewport.tsx`).

### مثال حي: ملف PDF في المتصفح

المسار الكامل أعلاه، يعمل في المتصفح: يستورد هذا المثال على CodePen الحزمتين `postext` و`postext-pdf` من شبكة CDN، ويحمّل خطوط الويب، ويبني المستند، ويضمّن أشكال خطوط Fontsource عبر مزوّد الخطوط، ويسلّم البايتات إلى رابط يفتح الملف في تبويب جديد، وإلى رابط تنزيل. ولملف PDF الناتج فواصل الأسطر نفسها التي في مخرجات Canvas وHTML، وخطوط حقيقية مضمَّنة، وإشارات مرجعية في المخطط التفصيلي.

### إنتاج ملف PDF في عامل

تنقل `postext-pdf/worker` الدالة `renderToPdf` خارج الخيط الرئيسي. يكتب العامل النص والأشكال المتجهية وشجرة البنية والملف نفسه. وتحتاج مهمتان إلى الصفحة، فيطلبهما العامل من الخيط الرئيسي: جلب الخطوط، وتحويل SVG إلى صورة نقطية عبر `<img>`. ففي كتاب من مئات الصفحات يستغرق الإنتاج ثواني كانت ستجمّد الصفحة لولا ذلك؛ أما لبضع صفحات فاستدعاء `renderToPdf` مباشرةً أبسط.

```ts
import { createPdfWorker } from 'postext-pdf/worker';

const pdfWorker = createPdfWorker();
const bytes = await pdfWorker.render(docs, {
  fontProvider,                                     // runs on this thread
  resourceBytes: new Map([['map.svg', svgBytes]]),  // a Map; its buffers move to the worker
  onProgress: ({ phase, pages, totalPages }) => showProgress(phase, pages, totalPages),
  onWarning: (w) => console.info(w.message),
});
pdfWorker.dispose();
```

- تأخذ `render(docs, options)` مستندًا واحدًا أو مصفوفة مستندات فصول كتاب. وتأخذ خيارات `renderToPdf`، مع فرقين. فـ`resourceBytes` (و`previewBytes`) هنا `Map<string, Uint8Array>` تُنقل مخازنها المؤقتة (buffers) إلى العامل، فمرّر نسخًا من البايتات التي تحتفظ بها. و`rasterizeSvg`، إن أُعطيت، تعمل على الخيط الرئيسي؛ وافتراضيًا يتولى المهمة `Image` ولوحة canvas الخاصان بالصفحة.
- المقبض الواحد يُنتج مستندًا واحدًا في كل مرة. وتُنهي `dispose()` العامل وترفض أي إنتاج لا يزال معلّقًا بخطأ `AbortError` (`DOMException`)، فعامِله على أنه إلغاء. وإذا أجاب المزوّد بخط أو صورة بعد `dispose()` أُهمِل الرد.
- `inspect(bytes)` يقرأ ملف PDF منتهيًا من جديد في العامل (`inspectPrintPdf`) ويُحَلّ بتقريره، أو بـ`undefined` إذا تعذّرت قراءة البايتات بوصفها PDF. تُنسخ البايتات، فتبقى نسختك صالحة للاستخدام. لا يُقرأ شيء ما لم تستدعِه.
- تأخذ `createPdfWorker({ worker })` كائن `Worker` تنشئه أنت، لأدوات البناء التي تتحكم في عناوين العمّال. ويجب أن يشغّل ذلك العامل `postext-pdf/worker/entry`.

**من شبكة CDN.** افتراضيًا يُحمَّل سكربت العامل من عنوان الحزمة نفسها (`new URL('./pdf.worker.js', import.meta.url)`). وقد لا تستطيع صفحة على أصل (origin) آخر تشغيله: فعند الاستيراد من `esm.sh`، ترمي `createPdfWorker()` الخطأ `Failed to construct 'Worker': Script at 'https://esm.sh/postext-pdf@…/pdf.worker.js' cannot be accessed from origin …`. شغّل بدلًا من ذلك عامل وحدة (module worker) من الأصل نفسه يستورد نقطة الدخول (وإن ثبّتّ إصدارًا، فثبّت الإصدار نفسه في العنوانين):

```js
import { createPdfWorker } from 'https://esm.sh/postext-pdf/worker';

const entry = URL.createObjectURL(new Blob(
  ["import 'https://esm.sh/postext-pdf/worker/entry';"],
  { type: 'text/javascript' },
));
const pdfWorker = createPdfWorker({ worker: new Worker(entry, { type: 'module' }) });
```

أما عامل الإخراج من `postext/worker` فلا يحتاج إليه: يشغّل `createLayoutWorker()` مدخله الخاص من esm.sh دون أي خيار، ومن أي خادم آخر بخياره `url` (انظر [تحميل العامل من CDN](/ar/docs/configuration-programmatic-usage#تحميل-العامل-من-cdn)).

### ملفات PDF جاهزة للطباعة

لسير عمل الطباعة الإنتاجية، اضبط خيارات الإعدادات هذه قبل الإنتاج:

- **`page.cutLines.enabled: true`** — يضيف منطقة النزف وعلامات القص حول حدّ القص، ويعطي كل صفحة TrimBox وBleedBox. انظر [خطوط القص](/ar/docs/configuration-page-layout#خطوط-القص).
- **`print: { standard: 'pdfx4', outputProfile: 'fogra51' }`** (أو `'pdfx1a'`) — ملف PDF/X فيه نية الإخراج (output intent) والتعريف والمربعات (boxes) التي تتحقق منها المطبعة؛ ويُفصَل كل لون وكل صورة RGB عبر ملف تعريف ICC، ويُطبع الأسود 100% K فوق الألوان، وتُطبع المساحات السوداء الكبيرة بالأسود الغني. انظر [الإنتاج الطباعي (الإعدادات)](/ar/docs/configuration-fonts-colors-viewers#الإنتاج-الطباعي-الإعدادات).
- **`colorSpace: 'cmyk'`** (أو `pdfGeneration: { forceColorSpace: true, colorSpace: 'cmyk' }`) — الفصل نفسه من غير تعريف PDF/X (وعلامات القص بلون التسجيل دائمًا). وتُضمَّن نسخ PDF الأصلية للطباعة كما هي.
- **`page.dpi: 300`** — عدد بكسلات الإخراج في البوصة: الصورة النقطية التي ليست لها دقة خاصة بها تُطبع بهذه الدقة بمقاسها الطبيعي. ويُصدر [الفحص قبل الطباعة](/ar/docs/configuration-pdf-output#الفحص-قبل-الطباعة) تحذيرًا بالصور التي تقل دقتها عن 300 ppi بحجمها المطبوع.
- **`ColorValue.cmyk`** — يُطبع اللون المعرّف بقيم CMYK بقيمه الدقيقة.
- **`{ pageNegative: true }`** في `RenderToPdfOptions` — يعكس منطقة حدّ القص باستخدام نمط الدمج Difference (وتبقى علامات القص غير معكوسة). مفيد لفحوص ما قبل الطباعة (preflight) على الطباعة الداكنة فوق الفاتح.
- **`print.dieLine`** — خط القص في كتاب فيه قص بالقالب، يُرسم على لوح خاص به لا تحبّره الآلة أبدًا (`Die` افتراضيًا، في مجموعة محتوى اختياري خارج PDF/X-1a). انظر [خط القص في ملف PDF](/ar/docs/special-inks-die-cuts#خط-القص-في-ملف-pdf).

### الألوان الخاصة

اللون الخاص (Pantone، أو حبر مؤسسي، أو ورنيش) يُطبع على لوحه الخاص. يحمل اللون ذو `model: 'spot'` حبره في `ColorValue.spot`: `name` اسم اللوح كما تعرفه المطبعة، و`cmyk` مظهر الحبر بنسبة 100 % (البديل الذي يعطيه PDF لمن لا يملك الحبر)، و`tint` درجة الحبر بالنسبة المئوية (100 افتراضيًا)، و`overprint` يجعل الحبر يُطبع فوق ما تحته بدل تفريغه، كالورنيش، و`finish` يقول ما الحبر الخاص: معدني، أو رقائق، أو فلوري، أو أبيض معتم، أو ورنيش. أما `hex` فهو تمثيله على الشاشة. ويشرح قسم [الأحبار الخاصة والقص بالقالب](/ar/docs/special-inks-die-cuts#التشطيبات) كيف يُطبع كل تشطيب وكيف يُعرض.

يكتب ملف PDF بنظام CMYK أو PDF/X كل حبر فضاءَ ألوان `Separation` باسمه، ويرسم كل لون من هذا الحبر بدرجته: الألوان ذات `name` الواحد تتشارك لوحًا واحدًا. وبذلك تُغطّى الأعمال المعتادة: لونان (الأسود ولون خاص)، والطباعة الرباعية مع عناصر قليلة بلون خاص، وورنيش مطبوع فوق مناطق مختارة. وإذا استخدم `diagramStyle.singleInk` لونًا خاصًا، طُبعت مخططات SVG بدرجات ذلك اللوح. أما ملف PDF بنظام RGB والشاشة فيرسمان اللون بقيمة `hex`.

**الألوان الخاصة داخل SVG.** انظر [كيف يعمل الحبر الواحد](/ar/docs/configuration-resources#كيف-يعمل-الحبر-الواحد).

```ts
colorPalette: [
  { id: 'brand', name: 'Brand', value: { hex: '#1f3f99', model: 'spot', spot: { name: 'PANTONE 286 C', cmyk: { c: 100, m: 66, y: 0, k: 2 } } } },
  { id: 'brand-40', name: 'Brand 40 %', value: { hex: '#a5b6dd', model: 'spot', spot: { name: 'PANTONE 286 C', cmyk: { c: 100, m: 66, y: 0, k: 2 }, tint: 40 } } },
  { id: 'varnish', name: 'Varnish', value: { hex: '#f4f4ee', model: 'spot', spot: { name: 'Varnish', cmyk: { c: 0, m: 0, y: 10, k: 0 }, finish: { kind: 'varnish', sheen: 'gloss' } } } },
],
diagramStyle: { singleInk: true, inkColor: { hex: '#1f3f99', model: 'spot', paletteId: 'brand' } },
```

يعدّ الفحص قبل الطباعة اللون الخاص حبرًا واحدًا، ويستبعده من حد التغطية، ويسرد الألوان الخاصة في المهمة (`spotInks`)، ومنها الأحبار التي تسمّيها صور SVG. وينبّه إذا عُرّف الحبر نفسه مرتين بقيم مختلفة (`spotInkConflict`؛ يستخدم PDF التعريف الأول)، وإذا سمّى ملف SVG حبرًا لا يعرّفه أي لون في لوحة الألوان ولا أي مدخل في جدول الأحبار يحمل `cmyk` (`spotInkUndefined`؛ يُطبع على لوح خاص به، وقيم CMYK للون SVG بديلًا له، لوح واحد لكل اسم)، وإذا اضطر PDF إلى كتابة اسم لوح بصيغة أخرى (`spotInkName`، انظر أدناه)، وإذا اختلف اسما لوحين في حالة الأحرف أو المسافات فقط (`spotInkSimilar`: `PANTONE 185 C` و`Pantone  185 C` سيكونان لوحين). يعرف `preflightDocument` الأحبار التي يسمّيها ملف SVG من `svgInks(fileId)`، وهي دالة تعيد الأسماء التي يجدها `svgSpotInks(markup)` في الملف؛ وتمرّرها لوحة **الفحوص** في Sandbox و`postext check`.

**أسماء الألواح.** يُكتب الاسم كما أُدخل: تصل الحروف المشكّلة والرموز و`#` إلى PDF بترميز UTF-8 (`Rojo Médica` يصبح `/Rojo#20M#C3#A9dica`)، وهكذا يقرؤه Acrobat وRIP والفحص قبل الطباعة لدى المطبعة. الاسم الذي لا يستطيع اللوح حمله يُكتب باسم آخر: `All` و`None` و`Cyan` و`Magenta` و`Yellow` و`Black`، بأي حالة أحرف، تُلحق بها كلمة ink (`All ink`)؛ وتُحذف محارف التحكم؛ والاسم الذي يتجاوز 127 بايت بترميز UTF-8 يُقطع عند حد محرف وينتهي ببصمة قصيرة (hash)، فيبقى الاسمان الطويلان اللذان يبدآن بالحروف نفسها لوحين. يذكر `spotInkName` في الفحص قبل الطباعة السبب (`problem`: `reserved` أو `process` أو `control` أو `tooLong`) والاسم الذي يكتبه PDF (`written`)، ويُبلغ العرض عن كل تغيير عبر `onWarning` (`spotInkRenamed`). ولتختار الاسم بنفسك، أعطِ الحبر `pdfName` في جدول الأحبار.

**حبر واحد لكل لون.** يتعرّف عرض الطباعة على اللون من قيمة `hex` الخاصة به على الشاشة، لذا لا يجوز للونين يحددان قيم طباعتهما (حبران، أو حبر ولون معرَّف بنظام CMYK) أن يتشاركا القيمة نفسها. فإذا تشاركاها، انتقل اللاحق منهما إلى أقرب قيمة `hex` حرة، على بعد خطوة واحدة لا تُرى على الشاشة، وطُبع كل منهما على لوحه. أما لون الشاشة العادي (`model: 'hex'`) الذي يحمل قيمة `hex` للون خاص فيُطبع بذلك اللون الخاص؛ اربطه بمدخل لوحة الألوان لتجعل ذلك صريحًا. واللون الذي ينتقل يتغيّر على الشاشة أيضًا، خطوة واحدة (1/255) في قناة واحدة، الأزرق أولًا، في كل المخرجات (Canvas وHTML وEPUB وPDF بنظام RGB). وهذا أقل بكثير مما تميّزه العين، وهو ثمن عرض طباعة يقرأ الأحبار من قيمة `hex` المرسومة. ولا تتغيّر الإعدادات المحفوظة.

#### جدول الأحبار

يحدد `print.inks` كيف تصل أحبار المهمة إلى المطبعة، أيًّا كانت الأسماء التي تطلقها عليها الألوان وملفات SVG والملفات المستوردة. أما الحبر غير المدرج في الجدول فيُطبع كما تعرّفه ألوانه.

```ts
interface PrintInk {
  name: string;                    // الحبر كما يسمّيه spot.name أو ملف SVG.
  aliases?: string[];              // أسماء أخرى للحبر نفسه: تُطبع على هذا اللوح.
  pdfName?: string;                // اسم اللوح في PDF. الافتراضي name.
  output?: 'spot' | 'process';     // 'process' يطبع الحبر بنظام CMYK من بديله.
  cmyk?: CmykPercent;              // البديل بنسبة 100 %، مقدَّم على بديل الألوان.
  overprint?: boolean;             // مقدَّم على إعداد الألوان.
  finish?: InkFinish;              // معدني أو رقائق أو فلوري أو أبيض أو ورنيش، مقدَّم على تشطيب الألوان.
}
```

تُطابَق الأسماء والأسماء البديلة دون تمييز حالة الأحرف ولا المسافات المتكررة. إعادة التسمية سطر واحد مهما كان عدد الألوان التي تستخدم الحبر؛ والاسم البديل يجمع على لوح واحد الأسماء التي أعطتها للحبر نفسه عيّنةُ المصمم أو ملف SVG (`data-spot`، `icc-named-color`) أو لوحة ألوان سابقة؛ و`output: 'process'` يطبع الحبر بنظام CMYK عندما لا تملك المطبعة وحدة له، بكل درجاته؛ و`finish` يجعل الحبر خاصًا أيًّا كان مصدر اسمه، ومنه ملف SVG أو ملف مستورد يسمّي `Gold`. وترتيب المداخل هو ترتيب طباعة ورنيشين يلتقيان: على الشاشة وفي Folio يعلو المدخلُ اللاحق السابقَ (انظر [التشطيبات](/ar/docs/special-inks-die-cuts#التشطيبات)).

في Sandbox، يوجد الجدول في **التصميم › التصدير › التجهيز للطباعة › جدول الأحبار**: بطاقة لكل حبر فيها **اسم الحبر** و**أسماء بديلة** و**اسم اللوح في PDF** و**يُطبع بوصفه** و**CMYK البديل** و**الطباعة الفوقية** و**التشطيب** و**اللمعان**. وتسرد **الأحبار التي تستعملها الألوان** أحبار ألوان الكتاب الغائبة عن الجدول، ولكل منها زر يضيفه.

```ts
print: {
  standard: 'pdfx4',
  inks: [
    { name: 'Azul corporativo', pdfName: 'PANTONE 286 C', aliases: ['Pantone 286C', 'Azul'] },
    { name: 'Varnish', output: 'process' },
  ],
},
```

#### الطباعة بحبرين

يحدد `print.plates` الألواح التي تُطبع عليها المهمة، ولا يُطبع شيء غيرها: كتاب بالأسود ولون خاص واحد، أو بلونين خاصين، أو بالأسود وحده. ألواح الطباعة الرباعية هي `Cyan` و`Magenta` و`Yellow` و`Black`؛ ويُسمّى لوح اللون الخاص كما يسمّيه PDF، أو باسم أو اسم بديل من جدول الأحبار.

```ts
interface PrintPlatesConfig {
  inks?: string[];                                // الألواح. فارغة: كل الألواح، كالمعتاد.
  images?: string[];                              // الألواح التي تُطبع عليها الصور: لوح أو لوحان.
  curves?: Record<string, Array<[number, number]>>; // منحنى لوح الصورة: [الدرجة، الحبر] بالنسبة المئوية.
}
```

- اللون الذي ينتمي إلى حبر تطبعه المهمة، أو لون CMYK تطبع المهمة قنواته، يُكتب كما هو.
- أما أي لون آخر فيُسقَط: يُطبع بمزيج من لوح واحد أو لوحين يكون مظهره عبر ملف تعريف الإخراج أقرب ما يكون إليه. ومزيج الحبرين فضاء ألوان `DeviceN` في PDF، ويبقى الرمادي على `Black` وحده. ويُلغى الأسود الغني ما لم تطبع المهمة أحبار الطباعة الرباعية الأربعة كلها.
- تُطبع الصور أحادية اللون (monotone) على لوح واحد، أو ثنائية اللون (duotone) على لوحين: تمرّ درجة كل بكسل (إضاءته) عبر منحنى كل لوح. القيمة الافتراضية لـ`images` هي `Black`، أو اللوح الأول إذا لم تطبع المهمة الأسود. منحنى الصورة الأحادية اللون خط مستقيم؛ والصورة الثنائية اللون تضع لوحها الأول على الظلال ولوحها الثاني على الدرجات المتوسطة. ويحلّ `curves` محلّ أيٍّ منهما.

```ts
print: {
  standard: 'pdfx4',
  plates: {
    inks: ['Black', 'PANTONE 286 C'],
    images: ['Black', 'PANTONE 286 C'],
    curves: { 'PANTONE 286 C': [[0, 0], [50, 35], [100, 70]] },
  },
},
```

يسرد الفحص قبل الطباعة ألواح المهمة وكل لون يحرّكه الإسقاط. اللون الخاص أو لون CMYK الذي لا تطبعه المهمة معلومةٌ إذا وقع مزيجه ضمن ΔE 6 منه، وتنبيهٌ إذا ابتعد أكثر أو ما دام ملف تعريف الإخراج لم يُحمَّل (`offPlateInk`، `offPlateCmyk`)؛ ولون الشاشة الذي يقع على أبعد من ΔE 6 تنبيه أيضًا (`offPlateColor`). ولوح اللون الخاص الذي لا يعرّفه أي لون ولا أي مدخل في جدول الأحبار تنبيه: يُطبع ويظهر في البروفة أسود. في مهمة كهذه يُترك أصل الطباعة للشكل جانبًا ويُطبع ملف SVG الخاص به على الألواح؛ أما صفحة PDF الموضوعة، أو الصورة التي يتعذّر فكّها، فتحتفظ بأحبارها وينبّه التصيير (`artworkOffPlates`). في Sandbox تُختار الألواح من التجهيز للطباعة ← الألواح. وتعرض معايناته ومعاينة الطباعة الألوان كما يعرّفها الكتاب، لا كما تطبعها الألواح: انظر في ملف PDF، حيث يسرد فحص للطباعة الأحبار التي يستعملها.

### ألوان الصور

تُفصل الصورة انطلاقًا من الألوان التي صُنعت بها. ويحدّد `print.imageColor` كيف تُقرأ بكسلاتها:

```ts
interface PrintImageColorConfig {
  embeddedProfile?: 'use' | 'ignore';                  // A picture's own ICC profile. Default 'ignore'.
  assignedRgbProfile?: { name: string; fileId: string }; // Read every RGB picture through this .icc instead.
  grayDotGain?: 'profile' | 'none' | number;           // Greyscale pictures on black. Default 'none'.
  cmykProfile?: 'convert' | 'keep';                    // A CMYK picture of another press. Default 'keep'.
}
```

تُبقي القيم الافتراضية الصور كما كانت الإصدارات السابقة تطبعها: تُقرأ كل صورة RGB على أنها sRGB (`'ignore'`)، وتُفصل الصور الرمادية مثل أي صورة أخرى (`'none'`)، وتحتفظ صورة CMYK بقيمها (`'keep'`). يُفعَّل كل سلوك في القائمة بحقله.

- **ملف تعريفها الخاص.** صورة PNG (`iCCP`) أو JPEG (`ICC_PROFILE`) التي تضمّن ملف تعريف تُقرأ عبره، فتُفصل الصورة الفوتوغرافية بنظام Adobe RGB أو Display P3 كما تبدو لا كما لو كانت sRGB. أما الصورة غير الموسومة، أو الموسومة بـsRGB، فتُقرأ بوصفها sRGB كما في السابق. وتقرأ القيمة `'ignore'` كل الصور بوصفها sRGB.
- **ملف تعريف مُسنَد.** يسمّي `assignedRgbProfile` ملف `.icc` مخزّنًا تُقرأ عبره كل صورة RGB أيًّا كان ما تضمّنه: لدفعة من الصور الفوتوغرافية فقدت ملفات تعريفها مثلًا. وتأتي بايتاته من `resourceBytes`؛ وإن غابت استُخدمت ملفات تعريف الصور نفسها، مع تحذير `imageProfileUnavailable`.
- **محفوظة لمعالج RIP.** في PDF/X-4 مع `convertImages: false`، تُكتب الصورة ذات ملف التعريف غير sRGB بألوانها الخاصة، موسومة بـ`ICCBased` مع ملف التعريف ذاك، ويحوّلها معالج RIP في المطبعة.
- **التدرّج الرمادي.** تُطبع الصورة ذات التدرّج الرمادي (صورة PNG أو JPEG رمادية، أو صورة بملف تعريف رمادي) بالحبر الأسود وحده، ولا تُطبع أبدًا رماديًا رباعي الألوان. وتُطابَق درجاتها، المقروءة عبر ملف تعريفها الخاص (وإلا فكما تعرضها الشاشة)، مع آلة الطباعة: القيمة `'profile'` تمرّ عبر أسود ملف تعريف الإخراج، الذي تتضمّن ظروف الطباعة كسب النقطة فيه أصلًا؛ والرقم هو كسب النقطة في آلة الطباعة عند درجة 50 %، بالنسبة المئوية (من 10 إلى 30 عادةً)، فيُعوَّض بدلًا من ذلك؛ والقيمة `'none'` تكتب القيم كما هي، كما في السابق.

```ts
print: {
  standard: 'pdfx4',
  imageColor: { grayDotGain: 20 },
},
```

- **صورة CMYK من آلة طباعة أخرى.** الصورة بنظام CMYK التي يكون ملف تعريفها الخاص ظروفَ طباعة أخرى (صورة فوتوغرافية مفصولة لـSWOP أو لورق الصحف في كتاب مُعدّ لـFOGRA) تُفصل من جديد لظروف طباعة الإخراج (`cmykProfile: 'convert'`)، ويبقى ما هو بالأسود وحده بالأسود وحده: صورة TIFF أو Photoshop انطلاقًا من بكسلاتها؛ أما صورة JPEG بنظام CMYK، التي لا تُفكّ بكسلاتها، فتُوسم بـ`ICCBased` مع ملف تعريفها الخاص في PDF/X-4 ليحوّلها معالج RIP، وتُمرَّر كما هي في PDF/X-1a، الذي لا يسمح بمثل هذا الوسم؛ وهناك ينبّه الفحص قبل الطباعة إلى ذلك (`cmykImageForeign`) حين يعطيه المضيف ملف تعريف الصورة (`imageProfile`). وفي PDF/X-4 مع `convertImages: false` تُوسم صورة TIFF أو Photoshop بالطريقة نفسها. وتطبع القيمة `'keep'` قيم كل صورة CMYK كما هي.

**إعدادات صورة واحدة.** يقبل `printColor` في المورد الحقول نفسها التي يقبلها `print.imageColor` في الكتاب، ويطبّقها على تلك الصورة وحدها: صورة فوتوغرافية يجب تجاهل ملف تعريفها، وأخرى تُقرأ عبر ملف تعريف مُسنَد، وصورة رمادية بكسب نقطة مختلف. وفي Sandbox، تحدّد بطاقة الصورة ما إذا كانت تُقرأ عبر ملف تعريفها الخاص («اللون في الطباعة»)، وكيف تُضبط رمادياتها على آلة الطباعة («الرماديات في الطباعة»)، وأي ملف تعريف يُسنَد إليها («ملف تعريف مُسنَد»، وهو ملف `.icc`)؛ وتحمل الحزمة ملفات التعريف المُسنَدة، ملف الكتاب وملفات الصور، في مجلدها `profiles/`. وإعدادات الكتاب نفسه في التجهيز للطباعة ← الصور.

```ts
{ id: 'archive-photo', kind: 'bitmap', bitmap: { fileId: 'photo.jpg', format: 'jpeg', width: 2400, height: 1600 },
  printColor: { embeddedProfile: 'ignore' } }
```


### الألوان المعرّفة بقيم CMYK

اللون المكتوب بقيم CMYK يحتفظ بقيمه الدقيقة: يُكتب `ColorValue.cmyk` (بالنسبة المئوية) كما هو في الإخراج الطباعي، ويكون `hex` صورته على الشاشة. ومدخل لوحة الألوان المعرّف بقيم CMYK يشمل كل لون مرتبط به.

```ts
colorPalette: [
  { id: 'brand', name: 'Brand', value: { hex: '#00a0e3', model: 'cmyk', cmyk: { c: 100, m: 0, y: 0, k: 0 } } },
],
```

### الألوان التي تُطبع فوق غيرها

يمكن لأي لون أن يُطبع فوق ما تحته في الإخراج الطباعي: يجعل `overprint: true` في `ColorValue` كل ما يُرسم به (النص، والخطوط الفاصلة، والصناديق، والخلفيات) يُطبع فوق ما تحته بدل تفريغه. ويُكتب اللون الرباعي كما يُفصَل، تحت حالة رسومية للطباعة الفوقية؛ ويُطبع اللون الخاص فوق ما تحته على لوح حبره، حتى حيث يُفرِّغ الحبرُ نفسه في لون آخر. والأسود بنسبة 100% K الذي يُطبع فوق ما تحته يحتفظ بمعالجة الأسود: فالمساحات الكبيرة تظل تُطبع بالأسود الغني (`black.richBlack`). ويتجاهل ذلك ملفُ PDF بنظام RGB والشاشة. اضبطه في مدخل لوحة الألوان ليُطبع فوق ما تحته كل لون مرتبط به، ودرجاته معه؛ فاللون المرتبط يأخذ ضبط المدخل ولا ضبط خاص به. وتحتفظ به لوحة الجزء أو القسم: فالنص المكتوب بلون الجزء يُطبع فوق ما تحته أيضًا.

```ts
colorPalette: [
  { id: 'title', name: 'Title', value: { hex: '#c00020', model: 'cmyk', cmyk: { c: 0, m: 100, y: 80, k: 10 }, overprint: true } },
],
```

يتعرّف الإخراج الطباعي على اللون من قيمة hex التي يرسمها التخطيط، فلا يشترك لون يُطبع فوق ما تحته في قيمته مع لون يُفرِّغ ما تحته أبدًا. وحين تتطابقان، يتزحزح اللون الذي يُطبع فوق ما تحته خطوة واحدة (1/255 في قناة واحدة)، كما تفعل الألوان الخاصة؛ ولون الجزء لمدخل يُطبع فوق ما تحته يبتعد بالطريقة نفسها عن أي لون في الكتاب يُفرِّغ ما تحته. واللون الذي يُطبع فوق ما تحته ولا يضع حبرًا (بياض الورق، أو حبر بنسبة 0%) يختفي في الطباعة: يعدّه الفحص قبل الطباعة حرجًا (`overprintWhite`). والإخراج الذي فيه ألوان مختلفة أكثر مما لديه من رموز (نحو 25 مليونًا) يُفرِّغ ما زاد منها ويحذّر (`overprintsExhausted`). وفي Sandbox، يضبطه مفتاح «طباعة فوقية عند الطباعة» في منتقي الألوان.

تشغّل `preflightDocument(doc, options)` الفحوص على مستند مُخرَج وتعيد قائمة بالمشكلات، لكل منها `kind`، و`severity` (`'critical'` أو `'warning'` أو `'info'`)، و`pageIndex` المطلق في الكتاب، و`rect` العنصر المخالف (ببكسلات الصفحة)، ونطاقه في المصدر حين يكون له نطاق. والأنواع هي `lowImageResolution` و`declaredPixelsMismatch` و`rgbImage` و`thinRule` و`smallProcessText` و`inkLimit` و`safeZone` و`nearTrim`. ومن غير `transform` يُحسب اللون المحايد حبرًا واحدًا وأي لون آخر ثلاثة أحبار، ولا تُفحص التغطية؛ ومعه تكون الأعداد والتغطية دقيقة. وتُحسب دقة الصورة من البكسلات التي يصرّح بها موردها، أو من بكسلات الملف نفسه حين يقدّمها `imageSize(fileId)` (`bitmapInfo` على البايتات، أو الصورة بعد فك ترميزها): والتصريح الذي يبتعد عن الملف بأكثر من بكسل واحد يصدر عنه مرة واحدة تحذير من النوع `declaredPixelsMismatch`، وهو تحذير حين يدّعي بكسلات أكثر مما في الملف. وتسرد `placedImageResolutions(doc, { resources, imageSize })` كل صورة نقطية موضوعة مع دقتها الفعلية بوحدة ppi، سواء كان الفحص قبل الطباعة مفعّلًا أم لا. تُحتسب تسميات الشكل نصًّا في `smallProcessText` و`inkLimit` و`safeZone`.

```ts
import { bitmapInfo, outputTransform, parseIccProfile, preflightDocument, resolvePrintConfig } from 'postext';
import { inspectPrintMaster } from 'postext-pdf';

const print = resolvePrintConfig(config.print);
const transform = outputTransform(parseIccProfile(fogra51Bytes), { intent: print.renderingIntent });
const issues = preflightDocument(doc, {
  print,
  transform,
  resources,                                    // pixel sizes of the bitmaps
  imageSize: (fileId) => bitmapInfo(bytesOf(fileId)),  // the files' real pixels
  imageColor: (fileId) => colourOf(fileId),     // 'rgb' | 'cmyk' | 'gray', from the file
});
if (issues.some((i) => i.severity === 'critical')) process.exit(1);

const master = await inspectPrintMaster(masterBytes);
// => { nonEmbeddedFonts: ['Helvetica'], rgb: true, transparency: false }
```
