# 命令行

**`postext`在终端、脚本或智能体中排版你的书。**

在[沙盒](/zh/sandbox)里，你一边看一边写书、设计书。命令行拿同一本书，不用浏览器就能生成它的各种文件：可直接付印的PDF、HTML页面、EPUB、某一页或每一页的图像、Word文档。它还能打包和解包`.postext`文件包、导入Word文档、列出一本书的概况，并检查书中的问题。

每个系统对应<strong>一个独立的可执行文件</strong>。postext引擎、PDF、EPUB、HTML和Word写入器、页面绘制器（Skia）、用于阿拉伯文和其他复杂文字的HarfBuzz、ICC印刷特性文件以及默认字体（EB Garamond和Open Sans）全都在里面。不需要安装任何运行时、包或库，版面与沙盒完全相同：同一本书会在同样的地方分页。

## 获取

在macOS或Linux上用[Homebrew](https://brew.sh)：

```bash
brew install drnachio/postext/postext
```

在Windows上用[Scoop](https://scoop.sh)：

```powershell
scoop bucket add postext https://github.com/drnachio/scoop-postext
scoop install postext
```

两者都会把最新版本的可执行文件安装为`postext`命令，并用它的校验和核对；`brew upgrade postext`或`scoop update postext`会换成下一个版本。不用包管理器时，自己下载文件。

Postext的每个版本都会在其[GitHub Release](https://github.com/drnachio/postext/releases/latest)上发布这些可执行文件，连同它们的校验和（`SHA256SUMS`）和一份`readme.txt`：

每个文件的大小在115到140 MB之间。链接`https://github.com/drnachio/postext/releases/latest/download/<file>`总是指向最新的版本。

在Linux或macOS上：

```bash
curl -fL -o postext https://github.com/drnachio/postext/releases/latest/download/postext-linux-x64
chmod +x postext
./postext
```

把它移到`PATH`中的某个文件夹（`/usr/local/bin`、`~/.local/bin`），就能在任何地方以`postext`运行。macOS会隔离用浏览器下载的文件；清除一次这个标记即可：

```bash
xattr -d com.apple.quarantine postext-macos-arm64
```

在Windows上，用PowerShell：

```powershell
Invoke-WebRequest https://github.com/drnachio/postext/releases/latest/download/postext-windows-x64.exe -OutFile postext.exe
.\postext.exe
```

装有Node.js时，`npx postext-cli`会从npm下载适合你系统的可执行文件并运行它，`npm install -g postext-cli`则把它安装为`postext`命令。

不带参数运行时，`postext`打印帮助；`postext help <command>`列出某个命令的选项。

## 第一本书

一个文件夹里的三个Markdown文件就是一本书，每个文件一章，按文件名排序：

```bash
postext pdf chapters/ --name "Field notes" -o field-notes.pdf
```

第一章的前置元数据给出书名和作者，其余的交给引擎的默认设置：双栏、基线网格、两端对齐并断词的正文、书眉。需要时再加上配置和图片：

```bash
postext pdf chapters/ --config design.json --resources pictures/ -o field-notes.pdf
```

在沙盒中做好的书（在**书库**面板中导出为`.postext`文件）可以直接使用：

```bash
postext pdf my-book.postext -o my-book.pdf
postext image my-book.postext --page 1 -o cover.png
```

## 书可以是什么

每个读取图书的命令都接受以下任意一种：

- **`.postext`文件**：沙盒导出和打开的文件包（见[文件包](/zh/docs/configuration-bundles#文件包postext文件)）。
- **图书文件夹**：解包后的文件包，含有它的`preset.json`、各章、资源和字体。智能体技能交付的就是这种文件夹，`postext unpack`也会写出一个。
- **零散的Markdown**：一个或多个`.md`文件，按给出的顺序每个文件一章；或者一个文件夹，其中的`.md`文件按文件名排序（`01-intro.md`、`02-method.md`…）。与它们一起使用：
  - `--config design.json`：配置，可以是单纯的配置对象，也可以是完整的`preset.json`；
  - `--resources pictures/`：图片，每张作为一个图，id取去掉扩展名的文件名（`map.png`就是`::resource{id="map"}`）；文件夹中如有`resources.json`，则改由它描述这些图片（id、类型、题注、替代文字），格式与`preset.json`中的`resources`相同；
  - `--fonts fonts/`：书自带的字体文件（TTF、OTF、WOFF2），按字体文件内部记录的字体族名识别；
  - `--name "Title"`：书名。

`--config`也可用于文件包或文件夹：它会合并到书本身的配置之上。多语言文件包按它本身的语言读取，除非`--locale`要求另一种语言（`--locale en`）。

每个命令都把文件写到你运行命令的位置，按输入的名称命名；`-o`可以另给路径（`images`写入`pages/`）。`-o -`把单个输出写到标准输出。

### pdf

```bash
postext pdf book.postext -o book.pdf
postext pdf book/ --pdfx x4 --profile fogra51 -o book-print.pdf
postext pdf book/ --color-space grayscale --no-outlines
```

PDF遵循书本身的设置（见[PDF生成](/zh/docs/configuration-fonts-colors-viewers#pdf生成配置)和[印刷输出](/zh/docs/configuration-fonts-colors-viewers#印刷输出配置)）；以下选项只在本次运行中改变它们：

- `--pdfx none|x1a|x4`：交给印厂的PDF/X标准。
- `--profile NAME|FILE`：输出ICC特性文件，可以按名称指定（`fogra39`、`fogra51`、`fogra52`、`swop5`、`gracol2006`、`snap2007`、`ifra26`以及印刷设置中的其他特性文件），也可以给出一个`.icc`文件。
- `--color-space rgb|cmyk|grayscale`。
- `--accessible` / `--no-accessible`：供屏幕阅读器使用的标签结构。
- `--no-outlines`：不写入书签。
- `--page-negative`：负片页面，用于某些印刷流程。
- `--die-line page|none`：有模切的书的模切线，印在单独的印版上（`page`，默认），或者略去（`none`）；见[PDF中的模切线](/zh/docs/special-inks-die-cuts#pdf中的模切线)。

### html

```bash
postext html book.postext -o book.html
postext html book.postext -o site/ --mode single
```

路径以`.html`结尾时，得到的是一个文件，图片和字体都在里面，便于发送。其他路径都是文件夹：`index.html`旁边有`assets/`，存放图片、字体和自托管的视频。`--assets embed|folder`可以对任何路径选择其中一种方式。页面就是印刷版面，按屏幕尺寸显示：并排显示（`--mode multi`，默认），或上下排列（`--mode single`）。标记为`redistributable: false`的字体只写出名称，不复制文件。如果字体族指定了`fallback`，就改为写出这个开放字体族的字面，名称沿用原字体族（自postext 1.43起）。

### epub

```bash
postext epub book.postext -o book.epub
postext epub book.postext --layout reflowable --cover cover.jpg
```

`--layout fixed`（默认）让每一页保持印刷时的样子，文字可以选取；`--layout reflowable`让阅读系统按自己的屏幕重排文字（见[EPUB电子书](/zh/docs/configuration-html-folio-epub#epub电子书postext-epub)）。封面是书的缩略图，除非`--cover`给出一张图片。EPUB包的元数据（书名、作者、语言、标识符）来自第一章的前置元数据，与沙盒中相同。标记为`redistributable: false`的字体不会复制进去；指定了`fallback`的字体族，以自己的名称嵌入那个开放字体族的字面（自postext 1.43起）。

### image和images

```bash
postext image book.postext --page 12 -o page-12.png
postext image book.postext --page "#1" --dpi 300 -f jpeg -o cover.jpg
postext images book.postext -o pages/ --dpi 100
postext images book.postext --pages 1-10,iv -f webp --pattern "{chapter}-{label}"
```

页面可以**按印出的页码**指定（`12`、`iv`、范围`7-9`），也可以用`#`**按在书中的位置**指定（`#1`是第一页，不管它印的是什么页码；`#10-#20`；`#30-`表示直到末页）。`--pages`接受以逗号分隔的列表。绘制器就是沙盒的Canvas视图，所以图像显示的页面与排版结果完全一致，不必经过PDF。

- `--format png|jpeg|webp`（或由`-o`的扩展名决定），`--quality 1-100`用于JPEG和WebP。
- `--dpi`：分辨率，默认150；阅读页面用72–100就够了，印刷用300。
- `--pattern`：`images`的文件名，由`{n}`（位置，`{n:03}`补足到三位数）、`{label}`（印出的页码）和`{chapter}`组成；默认为`page-{n:03}`。
- `--print-preview`：按印厂印出来的样子显示页面（经过输出特性文件转换），并画出裁切线和出血。
- `--jobs N`：同时编码多少张图片（默认与计算机的处理器数量相同）。

### docx和import-docx

```bash
postext docx book.postext -o book.docx
postext docx book/ --variant semantic -o words.docx
postext docx book/ --variant facsimile -o pages.docx
postext import-docx book.docx book/ --dry-run
postext import-docx book.docx book/
postext import-docx manuscript.docx -o manuscript/ --locale es --report
```

`docx`写出沙盒导出的Word文档（见[沙盒 › Word文档](/zh/docs/sandbox-books-saving#word文档)），另外还有第三种。默认的`--variant formatted`由Markdown生成可编辑的文档，使用Word自身的标题、列表、脚注、表格、公式和节，在Word允许的范围内套用书的设计，并嵌入书中的字体（`--no-embed-fonts`只写字体名）；Word中没有对应结构的内容，以源码形式放在*Postext Source*内容控件中。`--variant semantic`把同样的文字写成只有内容的文档：一份朴素的文档（A4、单栏、Arial），用说明各部分身份的Word样式，不带页面设计，也不嵌入字体。两者都不需要排版，都能在Word和Google文档中打开，也都能通过`import-docx`带回。`--variant facsimile`像`pdf`一样给书排版，把每一页写成一个Word节，每一行放在固定的文本框中，并嵌入字体：这个文件用来在桌面版Word中查看排版，不用于编辑，也不适合Google文档。书不能转授的字体族（`customFonts`中的`redistributable: false`）不嵌入，改为嵌入它的开放替代字体，与EPUB相同；许可禁止嵌入的字体、使用PostScript轮廓的字体和可变字体会给出提示，只写字体名。在`build`中，`--docx FILE`写出同样的文件，可配合`--docx-variant`和`--no-docx-fonts`。postext 1.68起；`--template`不再用于`docx`和`build`。

在文件后面指定一本书时，`import-docx`把在由`docx`从该书导出的文档中所做的校改带回来。它读取文件所带的对照表，把文字与导出时所存的各章副本比较，再把每一处校改合并到书的当前版本中：文件夹、`.postext`或零散Markdown中的章文件，以及`preset.json`中资源的文字（题注、说明、替代文字、表格单元格）；零散Markdown则写入`--resources DIR`的`resources.json`。对于有多种语言的书，`--locale`指明文件是从哪个版本导出的，对资源文字的校改写入该版本的`localized`块。每一处校改各占一行报告：

- `applied`：附上它写入的文件和行；
- `conflict`：导出后书中的这段文字也改过，章或资源已不存在，或者两处校改重叠；
- `rejected`：书自己生成的文字（编号、题注标签、引用样式根据参考文献写出的文字），或跨越Postext标记的格式。

引用中的校改落在作者写的部分，即位置或文献前后的文字时，会回到这条引用中。在`[另见 @simmons1991, 346–47]`中，在Word里把页码范围改成`346–48`，引用就成为`[另见 @simmons1991, 346–48]`。报告的这一行指明是哪条引用（`citation simmons1991: locator "7" → "8"`）。对著者姓名、题名或*Ibid.*的修改不予采用；印出的样子与写法不同的部分（`346--47`印作`346–47`）也不予采用，并给出它在书中的位置，要在那里修改。

修订按已接受处理，批注列出作者和位置，但不写入。有校改未能应用时，退出码为3。`--dry-run`（`-n`）输出报告，以及每个将要改动的文件的统一格式diff，不写入任何内容。每个文件先写在目标旁边，再改名覆盖目标，所以中途被打断也不会留下半个章；导入过程中发生变化的章文件保持原样，并给出`docx.fileChanged`警告。指定书时不能用`-o`。加上`--json`时，回答包含`variant`（文件属于哪种导出：`formatted`、`semantic`或`facsimile`）、`writer`（文件属性中写明的写入器）、`exportId`、`edits`（每项带`status`、`reason`、`kind`、`before`、`after`和`at`，在引用中还带`citation`和`citationPart`）、`comments`、`files`，试运行时还有`diff`。

在Google文档中编辑并下载为`.docx`的文件也能回来。Google文档不保留对照表和各章副本；导入时会根据书重新写出对照表，并在报告中说明。这个文件不带导出文字的副本，所以与书的当前版本比较。如果导出后书改过，报告会给出警告，这期间在书中所做的改动可能显示为一处把它改回去的修改。Google文档的文件要导入它导出时的那本书，并且在改动这本书之前导入；Word保存的文件保留对照表，能与书后来的改动合并。整段替换的文字（标题、表格单元格、题注、框的标题、脚注），Google文档还会删掉它的隐藏书签。导入时按这段文字在前后文字之间的位置找到它，所以标题仍是标题，题注回到它的资源。无法判断时（比如旁边还输入了一个段落，两者无从区分），报告中显示的是一处删除和一处新增。同一个文件再导入一次，不会带来任何修改。

不指定书时，`import-docx`把任意Word文档转成一本新书：每个一级标题开始一章（`--no-split`保留为一章），图片和表格成为资源，`--report`输出沙盒显示的质量报告（使用的样式、直接格式、手打的编号……）。`--template`接受一个导入模板（从沙盒保存的`.json`，或带有模板的`.docx`）。

字符间距属于样式，不属于文字，所以不在Markdown里。`docx`把段落样式、标题样式和各级标题的`letterSpacing`写成Word样式的字符间距，`import-docx`再以样式字号的em为单位把它读回来：书中没有设`letterSpacing`的样式（`--config`文件里与Word样式对应的段落样式和标题样式，以及各级标题）会设上这个值，书中已经设了的字距保持不变。加上`--json`时，`styleTracking`列出已设置的（`applied`）和跳过的（`skipped`）。自postext 1.39起。

### idml

```bash
postext idml book/ -o book.idml
postext idml book.postext -o book.idml --images link
postext idml book/ -o out/book.idml --lines reflow --fonts
```

`idml`像`pdf`一样给书排版，把页面写成InDesign Markup包，供在InDesign中完成后续制作：设了对称页边距的书，页面按对页排在书脊两侧的跨页中（其他的书每个跨页放一页），线条、方框、路径和图片成为页面项目，表格成为InDesign表格，模板页每个框的文字成为一个带有独立文章的文本框（用`next`串接的框共用一篇文章），标注框样式成为段落样式，作者定义的CMYK颜色成为色板。带表单域的行内标签成为InDesign表单域。`--lines keep`（默认）让每一行都在Postext断行的位置结束，因此InDesign显示的行与PDF相同；`--lines reflow`把段落交给InDesign的排版器，换行位置可能不同。`--spreads facing`或`--spreads single`不管页边距怎样设，都决定页面是否成对排成跨页。`--images link`把图片放在文件旁边的`Links/`中，而不放进文件。`--fonts`把用到的字形的字体文件写到包旁边的`Document fonts/`中，InDesign会在那里为这个文档找到它们；它要求`-o`指定一个文件，书无权再分发的字体家族不写出，并给出警告。包无法照原样携带的内容（竖排文字里的着重号、表格的圆角外框）以`idml.*`警告报告。写出这个包的是`postext-idml`包，见[以编程方式使用 › InDesign包](/zh/docs/configuration-programmatic-usage#indesign包postext-idml)。在`build`中，`--idml FILE`写出同一个包，配合`--idml-images`、`--idml-lines`、`--idml-spreads`和`--idml-fonts`。自postext 1.71起；`--lines`和`--fonts`自1.76起，`--spreads`自1.78起。

### import-idml

```bash
postext import-idml book.idml -o book/
postext import-idml book.idml -o book.postext --layout flow --links pictures/
postext import-idml book.idml --report --json
postext import-idml package.zip -o book.postext
postext import-idml package.zip --document Book/Book.idml -o book/
```

`import-idml`读入一个InDesign Markup包，写出一本新书（文件夹或`.postext`文件）：各章为Markdown，配置取自文档的样式和页面，图片和表格成为资源。`.indd`文件不能读入，请先在InDesign中把它存为InDesign Markup。`--layout pages`用模板页逐页照文档排，每个框都在原来的位置；`--layout flow`写出一本连续排文的书，文字按阅读顺序排列并沿用文档的样式，交给Postext重新排版；`auto`（默认）在两者中选一个，并说明理由。文件也可以是压缩成zip的InDesign打包文件，即勾选<strong>包括 IDML</strong>后由<strong>文件 › 打包</strong>生成的文件夹，压成一个`.zip`：命令读入其中的IDML，连同其`Links/`文件夹中的图片，并把其`Document fonts/`文件夹中的字体文件放入书中。zip里有多个IDML文档时，用`--document`按zip内的路径指定要导入的那个（`--document Book/Book.idml`）；不指定时，命令会把它们列出来。只有`.indd`的打包文件会被拒绝，并说明如何得到IDML。链接的图片先从`--links`读取，再从打包文件读取，最后从文件所在的文件夹及其`Links/`读取，找不到的会列出来。文档用到的字体也会列出来：单独的`.idml`里没有字体文件，生成这本书时要用`--font-dir`提供。对于打包文件，`--font-dir`中找到的字体会代替打包文件中的那个放入书中。字体集（`.ttc`、`.otc`）无论在打包文件中还是在`--font-dir`中，都会拆成单个样式，只有书用到的样式才放入（自postext 1.83起）。

从Postext导出的书读回来时行不变。在InDesign中制作的文档读入时有损失：命令会打印结论（`faithful`、`approximate`或`lossy`）、各项计数，以及丢失和近似处理的内容；`--report`再加上各条说明和每种段落样式的读法，`--json`把这些都作为数据输出。`--hidden`、`--pasteboard`和`--non-printing`分别把隐藏的图层和对象、粘贴板上的内容、非打印对象也读进来；`--conditions all`读入全部条件文本，`--changes reject`按拒绝修订来读，`--no-masters`不读主页上的项目。`--name`和`--locale`指定书名和语言。导入器是`postext-idml`包的`idmlToPostext`，见[以编程方式使用 › InDesign包](/zh/docs/configuration-programmatic-usage#indesign包postext-idml)。导入是照原样复制文档；要移植一本你会长期保留的书，并推断出它的版式规则，请改用智能体技能（见[InDesign：导入、导出与移植](/zh/docs/indesign)）。

### design

```bash
postext design book.postext -o novel.postext
postext design book/ --parts page,text,headings -o type.postext
postext pdf other/ --design novel.postext -o other.pdf
```

设计文件只保存一本书的设计，不含正文：所选部分（版面设计面板的分组，见[设计文件](/zh/docs/configuration-bundles#设计文件)）的设置，以及它们引用的字体文件和颜色配置文件。标记为不可再分发的字体不包含在内。`--parts`只取逗号分隔的部分分组；`--design-name`、`--id`和`--description`为设计命名。同一本书总是得到相同的字节。

`--design FILE`是所有读取书的命令都有的选项，在`--config`和`--set`之前，把书设为某个设计文件或另一本书的设计：其各部分的设置替换书中的设置，命名样式按id合并，设计的字体加入书的字体。`--design-parts`只取其中部分。沙盒的版面设计面板也导入和导出同样的文件。

`--composition TAG`同样是所有读取书的命令都有的选项，在`--design`之后设置某种语言的排版传统规则（自postext 1.80起）：`es`、`en-US`（或`en`）、`en-GB`、`fr`或`de`，或用`auto`取书的语言。惯例的规则替换书中的规则，其他规则回到默认值；字体排印保持不变。见[排版惯例](/zh/docs/configuration-text#排版惯例)。

```bash
postext pdf book/ --composition auto -o book.pdf
postext design book/ --composition es --parts composition -o house-rules.postext
```

### pack和unpack

```bash
postext pack my-book/ -o my-book.postext
postext pack 01.md 02.md --name "Notes" --config design.json --resources img/ -o notes.postext
postext unpack my-book.postext -o my-book/
```

`pack`把图书文件夹原样压缩，或者用零散的Markdown构建一个文件包。同样的输入总是生成逐字节相同的文件，所以可以比较文件包，或计算它的哈希。对于零散的Markdown，`--id`、`--description`和`--thumbnail FILE`（一张封面图片）设置文件包的id、描述和缩略图；id默认由名称生成slug。文件夹保留它的`preset.json`所写的内容。没有指定封面的图书会以第一页作为封面（`thumbnail.jpg`，长边1024 px），文件管理器可以把它显示为文件的图标；`--no-auto-thumbnail`不生成它。`unpack`拒绝写入非空的文件夹，除非给出`--force`。

### info和check

```bash
postext info book.postext --pages
postext check book.postext
postext check chapters/ --strict --json
```

`info`列出各章（标题、字数、文件，加上`--pages`时还有页数）、资源，以及每个字体族及其来源（书本身、某个文件夹、可执行文件、下载缓存或后备字体）。如果书指明了从哪里开始（`preset.json`里的`start`：从第58页、第4章开始的节选），`info`也会显示出来，所有命令都从那里开始排版。

`check`排版整本书，并报告沙盒检查面板列出的内容：没有闭合的Markdown，未知的资源、指令和样式，排版时不得不强制处理的框，缺失的字体，引擎不得不替换的设置；对于为印刷设置的书（或加上`--preflight`时），还有印前检查：低分辨率图片、过细的线条、用多种油墨印的小字、超出上限的墨量、靠近裁切线的文字。它还列出在底色上看不清的文字（`contrast`），每对颜色列一次，给出屏幕上的对比度；针对印刷时，还给出在输出特性文件所对应纸张上的对比度。每个问题都指明所在的章文件、行和页。发现错误时退出码为3，加上`--strict`时有任何警告也是3。

它还会报告配置的设计中直接写着书中文字、而没有用占位符的地方（`contentInConfig`），每个标题样式、书眉或篇名页设计报告一次，并附上每段文字的路径：把这些文字移到Markdown中，或者把书名、出版社名这类文字列入`checks.contentInConfig.allow`。

对有页面模板的书，`check`还会报告放不进框的文字（`frameOverflow`，附重排阶梯试过的步骤和能让它放下的改动）、接续的文字超出了框最多能追加的页数（`frameContinuationLimit`）、跳转的目标页不在后面（`continueTargetMissing`）、画不出或相互碰撞的插图标注（`labelAnchorUnknown`、`anchorUnlabelled`、`labelOverflow`、`labelOverlap`）、被别的框遮住或超出边界的框（`frameCovered`、`frameOutsideArea`）、超过网格容量的卡片（`repeatOverflow`），以及页面排不了的模块（`moduleUnknown`、`moduleAsPage`、`moduleNested`、`moduleNameRejected`）。警告之后，每个有重排事件的模板页打印一行`reflow`；加上`--json`时，步骤、建议和重排记录都作为数据输出。见[模板页 › 警告](/zh/docs/composed-pages#警告)和[重排记录](/zh/docs/composed-pages#重排记录)。

### build和--watch

```bash
postext build book/ --pdf out/book.pdf --html out/book.html --images out/pages --pages 1-4
postext build chapters/ --pdf book.pdf --watch
```

`build`把书排版一次，写出你指定的每种输出（`--pdf`、`--html`、`--epub`、`--images`、`--docx`、`--idml`），各自使用对应命令的选项。`--watch`保持运行，字体和引擎一直加载着：某一章、配置或某张图片一改，它就重新排版（一章通常不到一秒），然后重写各个输出。如果某次保存让书出了错，它会打印错误，并保留上一次正确的文件。

## 字体

自带字体的书（文件包，或零散Markdown加上`--fonts`）只用这些字体排版。对于配置中指定而书中未自带的每个字体族，`postext`依次查找：

1. 用`--font-dir`给出的文件夹；
2. 编译进可执行文件的字体：EB Garamond和Open Sans，即引擎的默认字体；
3. 下载缓存；
4. [Google Fonts](https://fonts.google.com)，它提供完整的静态TrueType文件；Google Fonts没有的字体族（Commit Mono、FiraGO）则从[Fontsource](https://fontsource.org)获取。下载的文件保存在缓存中，所以每个字体族只下载一次。

字体族没有的字重，用浏览器会选的那个字体排出（即CSS的字体匹配规则：500以上先取更重的，400以下先取更轻的，所以只有400和700的字体族，600用它的700，550也是）；字体族没有的倾斜用它的正体。两种情况都直接用现有的字体排，页面图像和PDF都一样：只有一个字重的标题字体，粗体仍用它自己的字形；没有斜体的字体族，斜体也用正体。

下载的是配置里写到的字重：每个字体族的常规体、粗体和它们的斜体，以及各项设置给出的其他字重，粗体的字重也在内（`bodyText.boldFontWeight: 600`会请求600字重的字体）。字体族本来带有某个字重，却没能载入时（离线而缓存里没有文件、下载失败、字体文件夹里缺这个文件），文字改用该字体族中按同一规则选出的替代字体排，`postext check`会把它列为一条`fontFallback`警告：这些行的断行可能与沙盒里不同。

某个字体没有字形的字符，会改用另一个字体绘制。`postext check`读取它加载的每个字体的`cmap`表，把这类字符按字体汇总，全书每个字体报告一次`glyphFallback`警告；使用`--json`时，警告的`data`含有这些字符及其数量。

缓存位于`~/.cache/postext`（Windows上为`%LOCALAPPDATA%\postext\cache`）；`POSTEXT_CACHE_DIR`或`--cache-dir`可以改变它的位置。`--offline`跳过下载。在哪里都找不到的字体族以它自己的名称用EB Garamond排版，这样版面和PDF仍然一致，同时一条`missingFont`警告会指出它。`postext info`显示每个字体族的来源。

文件包如果没有带上某个授权字体族的文件，可以为它指定一个宽度相近的开放字体族（清单`fonts`里的`fallback`，自postext 1.42起）。`postext`按上面的步骤查找这个字体族；书中没有自带的字面，就用它同字重、同倾斜的字面来排，名称仍用授权字体族的名称。这样版面与有文件时接近，`postext check`也不会为该字体族报`missingFont`。书中只带了部分字面的字体族，只有自己完全缺少的那种倾斜才从`fallback`中取。PDF嵌入的是开放字体。

## 用于脚本和智能体

命令行就是为了让其他程序驱动而设计的，包括编程智能体。

- <strong>`--json`</strong>在命令结束时向标准输出打印一个JSON对象；所有消息都写到标准错误。报告列出写出了什么、页数、每条警告及其来源，以及每一步用了多长时间（以毫秒计）：

```json
{
  "ok": true,
  "command": "pdf",
  "version": "1.22.1",
  "book": { "name": "notes", "id": "notes", "locale": "en", "chapters": 2 },
  "pages": 3,
  "outputs": [{ "kind": "pdf", "path": "notes.pdf", "bytes": 29746, "pages": 3 }],
  "warnings": [
    {
      "kind": "unknownResourceId",
      "severity": "warning",
      "message": "Unknown resource id \"map\" in ::resource — nothing is embedded (offset 26)",
      "at": "notes/02-more.md:5"
    }
  ],
  "timings": { "read": 13, "fonts": 8.4, "math": 28.2, "layout": 51.6, "pdf": 132.1, "total": 1638 },
  "exitCode": 0
}
```

- **退出码**：`0`完成，`1`失败，`2`用法错误（未知选项、缺少输入），`3`表示`check`发现了错误（加上`--strict`时为警告），或者`import-docx`有Word校改未能导入。
- **不提问**。它从不等待输入；非空的文件夹直接拒绝，而不是询问。
- **标准输出**：`-o -`把PDF、图像或文件包写到那里，以便通过管道交给下一个程序。
- **速度**。可执行文件启动只需几百分之一秒。短书变成PDF或页面图像远不到一秒；长书所需的时间取决于它的排版（一本140页的插图小说，约十秒）。要查看长书中的几页，把`--chapters`与`image`或`images --pages`结合使用。要反复修改一本书时，让`postext build --watch`一直运行，读取它的输出即可。

[智能体技能](/zh/docs/skill)用命令行渲染它正在处理的页面，并检查移植结果。

## Python

`pip install postext`把命令行变成一个Python库。这个包是纯Python的，没有任何依赖，版本号与postext相同。第一次执行命令时，它从该版本的GitHub Release下载适合你系统的可执行文件，用`SHA256SUMS`校验后存入上文所说的缓存目录，位于`bin/<版本>/`下。如果`POSTEXT_BIN`指向你已有的可执行文件（来自Homebrew、Scoop或你自己的构建），就不会下载任何东西。

```python
import postext

report = postext.pdf("book.postext", out="book.pdf", set={"page.dpi": 300}, locale="es")
print(report.output.pages)
for warning in report.warnings:
    print(warning.kind, warning.at, warning.message)

pdf = postext.pdf_bytes(open("book.postext", "rb").read())
```

- **每个命令一个函数**：`pdf`、`html`、`epub`、`image`、`images`、`docx`、`idml`、`import_docx`、`import_idml`、`design`、`pack`、`unpack`、`info`、`check`和`build`。选项沿用原名，改用下划线（`color_space`、`font_dirs`、`dry_run`）。`set`接受字典，`config`接受文件或字典，`chapters`接受数字、列表、`range`或`"1,3-5"`。凡是读取书的函数都接受`design=`（设计文件，路径或字节均可）、`design_parts=`（列表或`"page,text"`）和`composition=`（语言标签或`"auto"`）。
- **报告即对象**。每个函数都用`--json`执行对应命令并返回报告：`outputs`、`pages`、`timings`和`warnings`，每条警告是一个`Diagnostic`，含`kind`、`severity`、`message`、`at`和`page`。`info`另有`chapters`、`resources`和`fonts`；`check`另有`passed`、`error_count`和`warning_count`；`design`另有`name`和`parts`；`import_idml`另有`layout`、`reason`、`chapters`、`quality`、`fonts`、`missing_links`和`package`。
- **错误即异常**。执行失败抛出`PostextError`，选项有误抛出`UsageError`。`check`发现错误时抛出`ProblemsFound`，其`report`列出这些错误；传入`raise_on_problems=False`则改为返回报告。
- **字节**。书可以直接以`.postext`包的字节给出。使用`out="-"`时，文件放在`report.content`中返回；`pdf_bytes`、`html_bytes`、`epub_bytes`、`image_bytes`、`docx_bytes`、`idml_bytes`、`pack_bytes`和`design_bytes`直接返回这些字节。
- `postext.Postext(binary, cwd=…, timeout=…)`使用指定的可执行文件，`python -m postext …`就是命令行本身。

每次调用都会重新启动可执行文件。包的[README](https://github.com/drnachio/postext/tree/main/packages/postext-python)列出了全部选项。

## 构建方式

命令行是[仓库](https://github.com/drnachio/postext/tree/main/packages/postext-cli)中的`postext-cli`包。[Bun](https://bun.sh)把它连同引擎及其写入器，为每个系统编译成一个可执行文件；[Skia](https://skia.org)（通过`@napi-rs/canvas`）测量并绘制文字，就像沙盒中浏览器的canvas那样。包含位图的SVG图片（以data URI嵌入的PNG或JPEG，`pdftocairo -svg`从PDF裁出的图稿就是这样写的）则由[resvg](https://github.com/linebender/resvg)绘制，因为Skia的SVG渲染器会漏掉这类图像。每次发布时，都会构建这些可执行文件，在Linux、Alpine、macOS和Windows上试运行，再附到GitHub Release上；npm上会发布`postext-cli`，以及每个可执行文件对应的一个`postext-cli-<system>`包。

在仓库的副本中运行它：

```bash
pnpm install
pnpm --filter postext-cli start pdf book.postext
pnpm --filter postext-cli build:bin --current
```

第一条从源码运行它；第二条把这台电脑的可执行文件写到`packages/postext-cli/bin/`。

## 与沙盒的区别

- **HTML**是按屏幕尺寸显示的印刷版面。沙盒的HTML标签页会按窗口重新排列文字。
- <strong>`--chapters`</strong>单独排版这些章：它们的页码重新开始，而沙盒会延续整本书的页码。
- **字体**来自书本身、你的文件夹、可执行文件、Google Fonts或Fontsource（用于Google Fonts没有的字体族），从不来自电脑上安装的字体，所以一本书在每台机器上排出来都一样。
- **文字的语言**在浏览器里是文档自己的语言（`bodyText.shapingLanguage: 'document'`，postext 1.30起的默认值）。Skia的canvas接受语言设置，成形时却不用它，所以命令行按每个字体默认语言的字形测量，并且不论配置怎么写，始终用`shapingLanguage: 'host'`排版；它的PDF和页面图像绘制的也是这些字形。字体为某种语言备有专门字形的书（加泰罗尼亚语的`l·l`、土耳其语的`fi`、英文书里中文字体的数字），在这里按默认字形排。`'document'`另有测法的地方（在行末断开的词的两部分、从右到左的词、设计文本），这里按`'host'`的测法测量，所以某一行断开的位置可能与沙盒里不同。
