# مهارة الوكيل

**حوّل منشورًا قائمًا إلى مشروع Postext بمساعدة وكيل برمجة.**

يأتي كثيرون إلى Postext ومعهم كتاب موجود أصلًا: كتاب مدرسي في ملف PDF للطباعة، أو تقرير في Word، أو مقرر دراسي في PowerPoint، أو كتالوج في InDesign، أو ملف EPUB. ونقله يعني عملين:

- **المحتوى**: نص Markdown المُثرى لكل فصل، بتوجيهاته وصيغه الدقيقة (microformats).
- **التصميم**: ملف بيان للإعدادات (manifest) يعيد إنتاج قواعد الإخراج في الأصل (أبعاد الصفحة، وشبكة خطوط الأساس، والحروف، وصفحات افتتاح الفصول، والترويسات، والإطارات، والعناصر العائمة، والجداول، والأجزاء).

يستطيع نموذج لغوي كبير (LLM) أن يقوم بكثير من هذا العمل، لكن بشرط أن يعرف كيف يعمل Postext. فـMarkdown في Postext ليس CommonMark، وفي الإعدادات فخاخ لا تظهر إلا حين تُرسَم صفحة رسمًا خاطئًا. تجمع مهارة **`postext-port`** هذه المعرفة مع الأدوات التي استعملناها لبناء كل إعداد مسبق في Sandbox، ليُنجز وكيلك النقل كما ينبغي.

تتبع المهارة صيغة [Agent Skills](https://agentskills.io) المفتوحة، فتعمل مع Claude Code وCodex وCursor وGemini CLI وGitHub Copilot وOpenCode و[وكلاء كثيرين غيرها](https://skills.sh).

## شاهد الدرس

خمس دقائق، بلا شيفرة: جهّز المجلد، وأحضر الأصول المتجهية، وأضف ملف PDF مرجعيًا، واطلب من الوكيل، ثم تحقق من النتيجة في Sandbox.

## ما الذي تحتويه المهارة

- **سير عمل**:
  1. الاتفاق على المهمة؛
  2. جرد المصدر؛
  3. قياس التصميم وتدوينه في ورقة مواصفات؛
  4. إنشاء هيكل المشروع؛
  5. استخراج المحتوى؛
  6. تنقيحه إلى Markdown الخاص بـPostext؛
  7. تجهيز الخطوط والصور؛
  8. التحقق صفحةً صفحة؛
  9. تحزيمه.
- **مراجع**:
  - صيغة المستند وملف بيان الإعدادات، وكلاهما مُتحقَّق منه مقابل المحرّك؛
  - صيغة المشروع (الحزمة)؛
  - دليل عمل لكل صيغة مصدر؛
  - منهج لتحليل التصميم؛
  - كتالوج لحالات إخراج محلولة: أجزاء بألوانها الخاصة، وصفحات افتتاح الفصول، والشعر، وحواشي الهامش، والحواشي السفلية، والفهارس الأبجدية في آخر الكتاب، والإطارات العائمة والمقسومة والمتداخلة، والأصول المتجهية للطباعة، والأشكال ذات النص الحي، والصور داخل خلايا الجداول، والجداول الأفقية، والطبعات ثنائية اللغة، وغير ذلك؛
  - الكتب الصينية، المنضدة أفقيًا أو عموديًا والمجلدة من اليمين: ما يُسأل عنه في المهمة (الكتابة، والمنطقة، والاتجاه، والتجليد)، وكيف تُقاس شبكة من المحارف، وكيف تُقرأ ملفات PDF العمودية، وruby وwarichu في InDesign، وإخراج شرق آسيا في Word، وملفات EPUB من اليمين إلى اليسار، وكيف تُقصّ خطوط CJK على مقاس الكتاب (انظر [الإخراج الصيني](/ar/docs/chinese-layout))؛
  - الكتب العربية، الحديثة أو التراثية والمشكولة، المنضدة من اليمين إلى اليسار والمجلدة من اليمين: الإعداد المحلي (locale) الذي يقلب اتجاه الكتاب، وما يُسأل عنه (المنطقة والأرقام، والتشكيل، والشعر، والمحتويات في آخر الكتاب)، وكيف تُقاس صفحة معكوسة، وكيف يُقرأ النص العربي من ملفات PDF وWord وويكي مصدر (Wikisource)، والقصائد بوصفها `:::verse`، والحواشي «(١)» لكل صفحة، والخطوط العربية المقصوصة مع جداول الوصل فيها (انظر [الإخراج العربي](/ar/docs/arabic-layout))؛
  - الكتاب المطبوع بوصفه شيئًا ماديًا: كيف يُقرأ ورق المصدر وتجليده وأغلفته وكعبه، وكيف تُضبط بوصفها إعدادات `folio` التي يعرضها [عارض Folio](/ar/docs/sandbox#تبويب-folio)، ويتحقق منها المدقق (linter).
- **برامج نصية** (Python وNode)، موصوفة في القسم التالي.

## تثبيتها

### أي وكيل (skills.sh)

تكتشف أداة سطر الأوامر [`skills`](https://skills.sh) وكلاءك وتثبّت المهارة لهم:

```bash
npx skills add drnachio/postext --skill postext-port
```

اختر الوكلاء صراحةً بـ`-a`، وثبّتها تثبيتًا عامًا (لكل المشاريع) بـ`-g`:

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

ينشر الموقع المهارة نفسها، فيعمل هذا أيضًا:

```bash
npx skills add https://postext.dev
```

### إضافة Claude Code

مستودع Postext هو أيضًا سوق إضافات (plugin marketplace) لـClaude Code. داخل Claude Code:

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

أو من الطرفية:

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### دع الوكيل يثبّتها

يمكنك أن تطلب ذلك من وكيلك، مثلًا: *«ثبّت مهارة النقل إلى Postext (`npx skills add drnachio/postext --skill postext-port`) واستعملها لنقل ملف PDF هذا.»* والوكلاء الذين يقرؤون `https://postext.dev/llms.txt` يجدون هذه الصفحة وأمر التثبيت هناك.

### الأدوات التي تستعملها البرامج النصية

```bash
python3 -m pip install pymupdf pillow fonttools brotli
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

يلزم Pandoc لمصادر Word وPowerPoint وEPUB وHTML، ويلزم poppler لصور صفحات المصدر. وتشغّل حزم Node المُخرِجَ الذي يعمل دون واجهة (Node 22.15 أو أحدث)؛ و`@napi-rs/canvas` لوحة رسم مبنية مسبقًا تتيح له رسم صفحات الكتاب مباشرةً بصيغة JPEG. وأدوات اختيارية: `ocrmypdf` للصفحات الممسوحة ضوئيًا، وImageMagick، وveraPDF لفحوص PDF/UA.

## استعمالها

ضع ملفات المصدر في مجلد عملك واطلب النقل. مثلًا:

- *«انقل الفصول 1–3 من `manual.pdf` إلى Postext، مع إعادة إنتاج إخراجه في عمودين، وصفحات افتتاح الفصول، والإطارات.»*
- *«حوّل `course.docx` إلى كتاب Postext. النمطان 'Nota' و'Actividad' إطاران.»*
- *«حوّل `deck.pptx` إلى مطبوعة Postext: تصبح الشرائح أقسامًا، وتصبح ملاحظات المتحدث النص.»*
- *«لدينا حزمة InDesign (IDML + ملف PDF للطباعة) لهذا الكتاب المدرسي. ابنِ إعداد Postext المسبق للفصل 1 بالإسبانية والإنجليزية.»*

يتبع الوكيل سير العمل:

1. **المهمة.** يسأل عما لا يستطيع استنتاجه: إعادة إنتاج أمينة أم إعادة تصميم، وفصل نموذجي أم الكتاب كله، واللغات، والطباعة أم الشاشة، والحقوق في النص والصور والخطوط.
2. **الجرد والقياس.** يقرأ المصدر ويكتب ورقة مواصفات بحقائق مقيسة: مقاس القص، والهوامش، والأعمدة، وتباعد الأسطر، وأدوار الحروف، ولوحة الألوان، وصفحات افتتاح الفصول، والترويسات، وعائلات الإطارات، وعادات الوضع.
3. **المشروع.** ينشئ هيكل `my-book/` مع مولِّد `build_preset.py` يحفظ المواصفات ثوابتَ ويُنتج `preset.json`.
4. **المحتوى.** يستخرج مسودات الفصول بالمستخرج المناسب، ثم ينقّحها إلى Markdown الخاص بـPostext: الإطارات، وأنماط الفقرات، والأجزاء، وسمات العناوين لصفحات افتتاح الفصول، والاستشهادات بـ`:ref`، وموارد الجداول والأشكال.
5. **التحقق.** يدقق المشروع، ويُخرجه دون واجهة، ويرسم الصفحات التي يعمل عليها صورًا بصيغة JPEG وينظر إليها، ويقارنها بالمصدر صفحةً صفحة حتى تتطابق فواصل الصفحات والأشكال والإطارات. يُبنى ملف PDF لفحوص الطباعة، لا عند كل نظرة.
6. **التسليم.** يضبط ورق الكتاب وتجليده وأغلفته لعارض Folio ويحزم `my-book.postext`.

افتح النتيجة في [Sandbox](/ar/sandbox): **الكتب › جديد › افتح ملف .postext…**. يأخذ الاستيراد الفصول والنصوص بلغة واجهة Sandbox. للعمل على مجلد من المشاريع في نسخة محلية من Postext، اضبط `POSTEXT_PRIVATE_PRESETS_DIR` (انظر [Sandbox](/ar/docs/sandbox)).

### تحميل النتيجة من الشيفرة

الملف المُسلَّم ليس مرتبطًا بـSandbox. تفتحه حزمة `postext` بـ`openBundle`، وتُخرج الكتاب بـ`buildBundle`، وترسمه على اللوحة (Canvas) أو في HTML أو PDF (انظر [الحزم](/ar/docs/configuration#الحزم-ملفات-postext)). لذلك يمكن أن يغذّي النقلُ برنامجًا مباشرةً. وحين تحتاج مخرجات ذلك البرنامج إلى تعديل، صدّرها من جديد إلى ملف `.postext` بـ`createBundle`، وحسّنها في Sandbox، ثم حمّل الملف المصحَّح مرة أخرى. ويقبل `render.mjs` الخاص بالمهارة، الذي يعمل دون واجهة، ملف `.postext` محزومًا كما يقبل مجلد مشروع.

## ما الذي تتوقعه

- **المستخرجات تُنتج مسودات، والوكيل ينقّحها.** توقّع جولة مراجعة لكل فصل مقابل صفحات الأصل. ومن تلك المراجعة تأتي الجودة.
- **الإعدادات وMarkdown فقط.** لا تغيّر المهارة المحرّك أبدًا ليلائم كتابًا واحدًا. وحين لا يستطيع Postext التعبير عن شيء ما، يختار الوكيل أقرب تعبير ويدرجه بوصفه نقصًا معروفًا.
- **الحقوق قرارك.** يسأل الوكيل قبل إعادة إنتاج صور أو خطوط تراخيصها غير واضحة. وتُعلَّم الخطوط المرخّصة بـ`redistributable: false`، فتخلو منها المشاريع المصدَّرة.
- **الأمانة حيث تهم.** الهدف هو الشبكة نفسها، والحروف، وصفحات افتتاح الفصول، والإطارات، ومواضع الأشكال، وفواصل الصفحات في معظم الصفحات (بفارق صفحة واحدة على الأكثر في كل فصل)، لا فواصل أسطر متطابقة.

## أين توجد

المهارة في المستودع في [`plugins/postext/skills/postext-port`](https://github.com/drnachio/postext/tree/main/plugins/postext/skills/postext-port). وتغطي كل حالة صادفناها في أثناء بناء الإعدادات المسبقة في Sandbox، العامة منها والخاصة. وحين يصادف نقلٌ حالة لا تغطيها بعد، نرجو أن تفتح مسألة (issue) أو طلب دمج (pull request) يحسّن المهارة، فيحصل عليها النقل التالي دون عناء.
