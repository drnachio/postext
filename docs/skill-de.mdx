# Agent-Skill

**Machen Sie aus einer vorhandenen Publikation mit einem Coding-Agenten ein Postext-Projekt.**

Viele kommen mit einem Buch zu Postext, das es bereits gibt: ein Lehrbuch als
Druck-PDF, ein Bericht in Word, ein Kurs in PowerPoint, ein Katalog in InDesign,
ein EPUB. Die Übertragung umfasst zwei Aufgaben:

- **Inhalt**: das erweiterte Markdown jedes Kapitels mit seinen Direktiven und
  Mikroformaten.
- **Gestaltung**: ein Konfigurationsmanifest, das die Layoutregeln des Originals
  nachbildet (Seitengeometrie, Grundlinienraster, Schrift, Kapitelauftakte,
  Kolumnentitel, Kästen, Gleitobjekte, Tabellen, Teile).

Ein LLM kann einen großen Teil dieser Arbeit übernehmen, aber nur, wenn es weiß,
wie Postext funktioniert. Postext-Markdown ist kein CommonMark, und die
Konfiguration hat Fallstricke, die erst auffallen, wenn eine Seite falsch
gerendert wird. Der Skill **`postext-port`** bündelt dieses Wissen mit den
Werkzeugen, mit denen wir jede Vorlage in der Sandbox gebaut haben, damit Ihr
Agent die Übertragung sauber erledigen kann.

Er folgt dem offenen Format [Agent Skills](https://agentskills.io) und funktioniert
daher mit Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode und
[vielen anderen Agenten](https://skills.sh).

## Das Tutorial ansehen

Fünf Minuten, kein Code: den Ordner vorbereiten, die Vektororiginale mitbringen,
ein Referenz-PDF hinzufügen, den Agenten beauftragen und das Ergebnis in der
Sandbox prüfen.

## Was der Skill enthält

- **Einen Arbeitsablauf**:
  1. den Auftrag abstimmen;
  2. die Quelle inventarisieren;
  3. die Gestaltung in einem Datenblatt vermessen;
  4. das Projektgerüst anlegen;
  5. den Inhalt extrahieren;
  6. ihn zu Postext-Markdown aufbereiten;
  7. Schriften und Bilder vorbereiten;
  8. Seite für Seite prüfen;
  9. das Paket schnüren.
- **Referenzen**:
  - das Dokumentformat und das Konfigurationsmanifest, beide an der Engine
    geprüft;
  - das Projektformat (Paket);
  - ein Leitfaden je Quellformat;
  - eine Methode zur Gestaltungsanalyse;
  - ein Katalog gelöster Layoutfälle: Teile mit eigenen Farben,
    Kapitelauftakte, Verse, Randglossen, Fußnoten, Register, gleitende,
    geteilte und verschachtelte Kästen, Vektor-Druckvorlagen, Abbildungen mit
    Live-Text, Bilder in Tabellenzellen, Tabellen im Querformat, zweisprachige
    Ausgaben und mehr;
  - chinesische Bücher, waagerecht oder senkrecht gesetzt und rechts gebunden:
    was im Auftrag zu klären ist (Schrift, Region, Richtung, Bindung), wie man
    ein Zeichenraster vermisst, wie man senkrechte PDFs liest, Ruby und Warichu
    aus InDesign, das ostasiatische Layout von Word und EPUBs von rechts nach
    links, und wie man CJK-Schriften auf das Buch zuschneidet (siehe
    [Chinesischer Satz](/de/docs/chinese-layout));
  - japanische Bücher, senkrecht gesetzte Bunko- und Tankōbon-Romane mit
    Bindung rechts oder waagerecht gesetzte Fachbücher: die Sprache (`locale`),
    die die japanischen Regeln einschaltet (`ja`, nie eine chinesische
    Sprachkennung), was zu
    klären ist (Richtung, Raster, Furigana, Anmerkungen, die Orthografie der
    Ausgabe), wie man den Satzspiegel in Zeichen und Zeilen vermisst, die
    Auszeichnung von Furigana und Bōten, mit `aozora.py` umgewandelte Texte aus
    Aozora Bunko, Scans gemeinfreier Ausgaben aus der National Diet Library und
    japanische Schriften, zugeschnitten mit ihren Kana und senkrechten Formen
    (siehe [Japanischer Satz](/de/docs/japanese-layout));
  - arabische Bücher, modern oder klassisch und vokalisiert, von rechts nach
    links gesetzt und rechts gebunden: die Sprache (`locale`), die das ganze
    Buch auf rechts nach links umstellt,
    was zu klären ist (Region und Ziffern, Vokalisierung, Verse, Inhaltsverzeichnis
    am Ende), wie man eine gespiegelte Seite vermisst, wie man Arabisch aus PDFs,
    Word und Wikisource liest, Gedichte als `:::verse`, Anmerkungen «(١)» je
    Seite und arabische Schriften, zugeschnitten mit ihren Verbindungstabellen
    (siehe [Arabischer Satz](/de/docs/arabic-layout));
  - Comics, Manga und Zeitungsstrips: die Aufteilung, die eine Seite in Panels
    schneidet, die Panelbilder mit ihren Sprecherpunkten und Sicherheitsbereichen, ein
    Skript je Sprache, das die Engine lettert (Sprechblasen, Textkästen,
    Geräuschwörter), Manga und arabische Ausgaben von rechts nach links, und wie
    man aus textfreien Zeichnungen samt Übersetzungen, aus geletterten Scans oder
    aus einem Skript mit generierten Bildern überträgt (siehe
    [Comics](/de/docs/comics));
  - zusammengesetzte Seiten: feste Seiten aus Schulbüchern, Arbeitsheften und
    Zeitschriften, portiert als Seitenvorlagen, deren Rahmen aus dem Markdown
    gefüllt werden, welche Portierungsrunde das installierte Postext
    beherrscht und welche Prüfungen jede Ausgabe bestehen muss (siehe [Zusammengesetzte Seiten](/de/docs/composed-pages));
  - das gedruckte Objekt: wie man Papier, Bindung, Umschläge und Buchrücken
    der Quelle abliest und in den Einstellungen `folio` festlegt, die der
    [Folio-Betrachter](/de/docs/sandbox-previews#tab-folio) zeigt; der Linter prüft sie.
- **Skripte** (Python und Node), im nächsten Abschnitt beschrieben.

## Installation

### Jeder Agent (skills.sh)

Das CLI [`skills`](https://skills.sh) erkennt Ihre Agenten und installiert den
Skill für sie:

```bash
npx skills add drnachio/postext --skill postext-port
```

Wählen Sie Agenten ausdrücklich mit `-a` und installieren Sie global (für jedes
Projekt) mit `-g`:

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

Derselbe Skill wird auch über die Website veröffentlicht, daher funktioniert auch:

```bash
npx skills add https://postext.dev
```

### Plug-in für Claude Code

Das Postext-Repository ist zugleich ein Plug-in-Marktplatz für Claude Code. In
Claude Code:

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

Oder aus einer Shell:

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### Den Agenten installieren lassen

Sie können Ihren Agenten darum bitten, zum Beispiel: *„Installiere den Skill zur
Übertragung nach Postext (`npx skills add drnachio/postext --skill postext-port`)
und übertrage damit dieses PDF.“* Agenten, die `https://postext.dev/llms.txt`
lesen, finden dort diese Seite und den Installationsbefehl.

### Werkzeuge, die die Skripte nutzen

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

Pandoc wird für Quellen aus Word, PowerPoint, EPUB und HTML gebraucht, poppler
für die Seitenbilder der Quelle und numpy für `comic_panels.py`. Die Node-Pakete treiben den Renderer ohne
Oberfläche an (Node 22.15 oder neuer); `@napi-rs/canvas` ist ein vorkompiliertes
Canvas, mit dem er die Seiten des Buchs direkt als JPEG zeichnen kann. Optionale
Werkzeuge: `ocrmypdf` für Scans, ImageMagick und veraPDF für PDF/UA-Prüfungen.

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

Wählen Sie die Datei Ihres Systems (`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`); mit Node funktioniert auch `npx postext-cli`.

Die Arbeitsschleife läuft über die [Kommandozeile](/de/docs/command-line), eine eigenständige ausführbare Datei, für die nichts installiert werden muss: Der Agent hält das Projekt entpackt und lässt `postext build --watch` auf den Seiten laufen, an denen er arbeitet, sodass jede Änderung etwa eine Sekunde später als JPEG erscheint, auch in einem langen Buch. Die Node-Pakete sind optional: Sie führen `render.mjs` aus, das die zusätzlichen Prüfungen der Sandbox ergänzt. Beide setzen das Buch mit `bodyText.shapingLanguage: 'host'`, gleich was seine Konfiguration angibt, sodass eine Zeile an einem anderen Wort umbrechen kann als in der Sandbox (siehe [Unterschiede zur Sandbox](/de/docs/command-line#unterschiede-zur-sandbox)).

## Anwendung

Legen Sie die Quelldateien in Ihren Arbeitsordner und bitten Sie um die Übertragung. Zum Beispiel:

- *„Übertrage die Kapitel 1–3 von `manual.pdf` nach Postext und bilde dabei das
  zweispaltige Layout, die Kapitelauftakte und die Kästen nach.“*
- *„Wandle `course.docx` in ein Postext-Buch um. Die Formatvorlagen ‚Nota‘ und
  ‚Actividad‘ sind Kästen.“*
- *„Mach aus `deck.pptx` ein Postext-Handout: Folien werden zu Abschnitten,
  Sprechernotizen werden zum Text.“*
- *„Wir haben das InDesign-Paket (IDML + Druck-PDF) dieses Lehrbuchs. Erstelle
  die Postext-Vorlage für Kapitel 1 auf Spanisch und Englisch.“*

Geben Sie dem Agenten für ein InDesign-Buch den Ordner, den **Datei › Verpacken**
in InDesign anlegt (die `.idml`, das Druck-PDF, die Schriften und die verknüpften
Grafiken). Der Skill erschließt daraus die Layoutregeln, was der IDML-Import nicht tut;
[InDesign: Import, Export und Portierung](/de/docs/indesign) vergleicht beide Wege.

Der Agent folgt dem Arbeitsablauf:

1. **Auftrag.** Er fragt, was er nicht ableiten kann: eine getreue Nachbildung
   oder eine Neugestaltung, ein Beispielkapitel oder das ganze Buch, Sprachen,
   Druck oder Bildschirm sowie die Rechte an Text, Bildern und Schriften.
2. **Inventar und Vermessung.** Er liest die Quelle und schreibt ein
   Datenblatt mit gemessenen Fakten: Endformat, Ränder, Spalten,
   Zeilenabstand, typografische Rollen, Farbpalette, Kapitelauftakte,
   Kolumnentitel, Kastenfamilien und übliche Platzierungen. Er ordnet jede
   Seite als Fließtextseite oder als zusammengesetzte Seite ein (Kästen,
   Beschriftungen und Karten an festen Stellen). Ab Postext 1.35 fasst er die
   zusammengesetzten Seiten nach ihrer Art zusammen und setzt jede Art aus
   einer Seitenvorlage: Das Layout bleibt identisch, und der Text bleibt
   bearbeitbar und übersetzbar. Mit einer älteren Version fragt er, wenn mehr
   als ein Drittel der Seiten zusammengesetzt ist, ob Sie das identische
   Layout wollen oder Text, den Sie bearbeiten und übersetzen können.
3. **Projekt.** Er legt das Gerüst `my-book/` mit einem Generator
   `build_preset.py` an, der das Datenblatt als Konstanten enthält und
   `preset.json` erzeugt.
4. **Inhalt.** Er extrahiert Kapitelentwürfe mit dem passenden Extraktor und
   bereitet sie dann zu Postext-Markdown auf: Kästen, Absatzformate, Teile,
   Attribute von Überschriften für Kapitelauftakte, Verweise mit `:ref`,
   Ressourcen für Tabellen und Abbildungen.
5. **Prüfung.** Er prüft das Projekt mit dem Linter und lässt
   `postext build --watch` auf dem entpackten Projekt laufen: Er ändert ein
   Kapitel oder eine Einstellung, sieht sich das JPEG der Seite an, das etwa eine
   Sekunde später neu gezeichnet ist, und ändert erneut, bis Seitenumbrüche,
   Abbildungen und Kästen Seite für Seite mit der Quelle übereinstimmen. An
   jedem Meilenstein führt er die vollständigen Prüfungen aus (`postext check`
   und den Linter). Das PDF wird nur für die Druckprüfungen erzeugt, nicht bei
   jedem Blick auf eine Seite.
6. **Übergabe.** Er legt Papier, Bindung und Umschläge des Buchs für den
   Betrachter Folio fest und packt `my-book.postext`.

Öffnen Sie das Ergebnis in der [Sandbox](/de/sandbox): **Bücher → Neu → Eine .postext-Datei öffnen …**.
Der Import übernimmt die Kapitel und Texte in der Sprache der Sandbox. Um mit
einem Ordner voller Projekte in einer lokalen Kopie von Postext zu arbeiten,
setzen Sie `POSTEXT_PRIVATE_PRESETS_DIR` (siehe [Sandbox](/de/docs/sandbox)).

### Das Ergebnis per Code laden

Die gelieferte Datei ist nicht an die Sandbox gebunden. Das Paket `postext` öffnet sie mit `openBundle`, setzt das Buch mit `buildBundle` und rendert es als Canvas, HTML oder PDF (siehe [Pakete](/de/docs/configuration-bundles#pakete-dateien-im-format-postext)). Eine Übertragung kann daher direkt ein Programm speisen. Wenn die Ausgabe dieses Programms Anpassungen braucht, exportieren Sie sie mit `createBundle` zurück in eine `.postext`-Datei, stimmen sie in der Sandbox fein ab und laden die korrigierte Datei erneut. Das `render.mjs` des Skills, das ohne Oberfläche läuft, nimmt neben einem Projektordner auch eine gepackte `.postext`-Datei an.

## Was Sie erwarten können

- **Die Extraktoren liefern Entwürfe; der Agent bereitet sie auf.** Rechnen Sie
  mit einem Durchgang je Kapitel, bei dem mit den Originalseiten verglichen wird.
  Erst diese Durchsicht sorgt für die Qualität.
- **Der Text bleibt im Markdown.** Die Konfiguration enthält die Gestaltung,
  jedes Wort des Buchs steht in den Kapiteln; eine Korrektur oder eine
  Übersetzung ist also eine Änderung am Markdown. Ab Postext 1.35 sind
  zusammengesetzte Seiten Seitenvorlagen in der Konfiguration, deren Rahmen aus
  dem Markdown jedes Kapitels gefüllt werden: Ein Kasten wächst mit einer
  längeren Übersetzung und verdrängt die Kästen darunter, und ab 1.37 sind die
  Wörter auf einer Karte Beschriftungen, die im Markdown stehen. Mit einer älteren Version
  entstehen sie aus Kästen, die an ihrem Platz fixiert sind, Seitenbildern
  ohne Text und SVG-Abbildungen, deren Beschriftungen echter Text bleiben. Der
  Bericht nennt den gewählten Weg und die Version. Wenn
  Postext etwas nur ausdrücken könnte, indem Text in die Konfiguration
  geschrieben wird, hält der Agent an, beschreibt die Lücke als Entwurf für
  ein Issue und fragt Sie. Der Skill ändert nie die Engine, um ein einzelnes
  Buch passend zu machen.
- **Eine Datei für alle Sprachen.** Eine Übersetzung ist ein Satz Kapitel in
  derselben `.postext`-Datei, mit eigenen Legenden und
  Abbildungsbeschriftungen, und wird in jeder Sprache mit `postext check` geprüft.
- **Über Rechte entscheiden Sie.** Der Agent fragt nach, bevor er Bilder oder
  Schriften mit unklarer Lizenz übernimmt. Lizenzierte Schriften werden als
  `redistributable: false` gekennzeichnet, sodass exportierte Projekte sie
  weglassen.
- **Treue dort, wo es darauf ankommt.** Das Ziel sind dasselbe Raster, dieselbe
  Schrift, dieselben Kapitelauftakte, Kästen, Abbildungsplatzierungen und
  Seitenumbrüche auf den meisten Seiten (innerhalb einer Seite je Kapitel), nicht
  identische Zeilenumbrüche.

## Wo er liegt

Der Skill liegt im Repository unter
[`plugins/postext/skills/postext-port`](https://github.com/drnachio/postext/tree/main/plugins/postext/skills/postext-port).
Er deckt jeden Fall ab, der beim Bau der öffentlichen und privaten Vorlagen in
der Sandbox aufgetreten ist. Wenn eine Übertragung auf einen Fall stößt, den er
noch nicht abdeckt, eröffnen Sie bitte ein Issue oder einen Pull-Request, der den
Skill verbessert, damit die nächste Übertragung gleich davon profitiert.
