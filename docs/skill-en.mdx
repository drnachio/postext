# Agent skill

**Turn an existing publication into a Postext project with a coding agent.**

Many people come to Postext with a book that already exists: a textbook as a
print PDF, a report in Word, a course in PowerPoint, a catalogue in InDesign,
an EPUB. Porting it means two jobs:

- **Content**: the enriched Markdown of every chapter, with its directives and
  microformats.
- **Design**: a configuration manifest that reproduces the original's layout
  rules (page geometry, baseline grid, type, openers, running heads, boxes,
  floats, tables, parts).

An LLM can do much of this work, but only if it knows how Postext works.
Postext Markdown is not CommonMark, and the configuration has traps that only
show up when a page renders wrong. The **`postext-port`** skill packages that
knowledge together with the tools we used to build every preset in the
sandbox, so your agent can do the port properly.

It follows the open [Agent Skills](https://agentskills.io) format, so it works
with Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode and
[many other agents](https://skills.sh).

## What the skill contains

- **A workflow**:
  1. agree the brief;
  2. take an inventory of the source;
  3. measure the design into a spec sheet;
  4. scaffold the project;
  5. extract the content;
  6. curate it into Postext Markdown;
  7. prepare fonts and images;
  8. verify page by page;
  9. package it.
- **References**:
  - the document format and the configuration manifest, both checked
    against the engine;
  - the project (bundle) format;
  - a playbook per source format;
  - a design-analysis method;
  - a catalogue of solved layout cases: parts with their own colours,
    chapter openers, verse, margin glosses, footnotes, back-of-book indexes, floated/split/nested
    boxes, vector print masters, live-text figures, pictures in table
    cells, landscape tables, bilingual editions, and more;
  - Chinese books, set horizontally or vertically and bound on the right:
    what to ask in the brief (script, region, direction, binding), how to
    measure a grid of characters, how to read vertical PDFs, InDesign ruby
    and warichu, Word's East Asian layout and right-to-left EPUBs, and how to
    cut CJK fonts to the book (see [Chinese layout](/en/docs/chinese-layout));
  - Japanese books, vertical bunko and tankōbon novels bound on the right or
    horizontal technical books: the locale that switches on the Japanese
    rules (`ja`, never a Chinese tag), what to ask (direction, grid,
    furigana, notes, the edition's orthography), how to measure the type
    area in characters and lines, furigana and bōten markup, Aozora Bunko
    texts converted with `aozora.py`, scans of public-domain editions from
    the National Diet Library, and Japanese fonts cut with their kana and
    vertical forms (see [Japanese layout](/en/docs/japanese-layout));
  - Arabic books, modern or classical and vocalised, set right to left and
    bound on the right: the locale that turns the whole book right to left, what to ask (region
    and digits, vocalisation, verse, contents at the end), how to measure a
    mirrored page, how to read Arabic from PDFs, Word and Wikisource, poems
    as `:::verse`, notes «(١)» per page, and Arabic fonts cut with their
    joining tables (see [Arabic layout](/en/docs/arabic-layout));
  - comics, manga and newspaper strips: the split that cuts a page into
    panels, the panel pictures with their speaker anchors and safe areas, one
    script per language, which the engine letters (balloons, captions, sound
    effects), right-to-left manga and Arabic editions, and how to port from
    text-free art plus translations, from lettered scans or from a script
    with generated art (see [Comics](/en/docs/comics));
  - composed pages: fixed textbook, workbook and magazine pages ported as
    page templates whose frames are filled from the Markdown, which porting
    round the installed Postext supports, and the checks each edition must
    pass (see [Composed pages](/en/docs/composed-pages));
  - the printed object: how to read the paper, binding, covers and spine of
    the source and set them as the `folio` settings that the [Folio viewer](/en/docs/sandbox-previews#folio-tab)
    shows, checked by the linter.
- **Scripts** (Python and Node), described in the next section.

## Installing it

### Any agent (skills.sh)

The [`skills`](https://skills.sh) CLI detects your agents and installs the
skill for them:

```bash
npx skills add drnachio/postext --skill postext-port
```

Pick agents explicitly with `-a`, and install globally (every project) with
`-g`:

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

The same skill is published by the website, so this works too:

```bash
npx skills add https://postext.dev
```

### Claude Code plugin

The Postext repository is also a Claude Code plugin marketplace. Inside Claude
Code:

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

Or from a shell:

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### Let the agent install it

You can ask your agent to do it, for example: *"Install the Postext porting
skill (`npx skills add drnachio/postext --skill postext-port`) and use it to
port this PDF."* Agents that read `https://postext.dev/llms.txt` find this
page and the install command there.

### Tools the scripts use

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

Pandoc is needed for Word, PowerPoint, EPUB and HTML sources, poppler for
the source's page images, and numpy for `comic_panels.py`. The Node packages power the headless renderer (Node 22.15 or
newer); `@napi-rs/canvas` is a prebuilt canvas that lets it paint the book's
pages straight to JPEG. Optional tools: `ocrmypdf` for scans, ImageMagick, and veraPDF for
PDF/UA checks.

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

Pick your system's file (`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`); with Node, `npx postext-cli` works too.

The work loop runs on the [command line](/en/docs/command-line), one self-contained executable with nothing to install: the agent keeps the project unpacked and leaves `postext build --watch` running on the pages it is working on, so every change shows up as a JPEG about a second later, even in a long book. The Node packages are optional: they run `render.mjs`, which adds the Sandbox's extra checks. Both lay the book out with `bodyText.shapingLanguage: 'host'`, whatever its configuration says, so a line may break at a different word than in the Sandbox (see [Differences from the Sandbox](/en/docs/command-line#differences-from-the-sandbox)).

## Using it

Put the source files in your working folder and ask for the port. For example:

- *"Port chapters 1–3 of `manual.pdf` to Postext, reproducing its two-column
  layout, chapter openers and boxes."*
- *"Convert `course.docx` into a Postext book. The styles 'Nota' and 'Actividad'
  are boxes."*
- *"Turn `deck.pptx` into a Postext handout: slides become sections, speaker
  notes become the text."*
- *"We have the InDesign package (IDML + print PDF) of this textbook. Build the
  Postext preset for chapter 1 in Spanish and English."*

For an InDesign book, give the agent the folder InDesign's **File › Package**
makes (the `.idml`, the print PDF, the fonts and the linked artwork). The skill
works out the layout rules from them, which the IDML importer does not do:
[InDesign: import, export and porting](/en/docs/indesign) compares the two.

The agent follows the workflow:

1. **Brief.** It asks what it cannot infer: a faithful reproduction or a
   redesign, a sample chapter or the whole book, languages, print or screen,
   and the rights on the text, images and fonts.
2. **Inventory and measurement.** It reads the source and writes a spec sheet
   of measured facts: trim, margins, columns, leading, type roles, palette,
   openers, running heads, box families and placement habits. It classifies
   every page as running text or as a composed page (boxes, labels and maps
   at set places). With Postext 1.35 or later it groups the composed pages by
   kind and sets each kind from one page template, so the layout stays
   identical and the text stays editable and translatable. With an older
   version, when more than a third of the pages are composed, it asks whether
   you want the identical layout or text you can edit and translate.
3. **Project.** It scaffolds `my-book/` with a `build_preset.py` generator
   that holds the spec as constants and produces `preset.json`.
4. **Content.** It extracts draft chapters with the right extractor, then
   curates them into Postext Markdown: callouts, paragraph styles, parts,
   heading attributes for openers, `:ref` citations, table and figure
   resources.
5. **Verification.** It lints the project and leaves `postext build --watch`
   running on the unpacked project: it changes a chapter or a setting, looks
   at the page's JPEG, repainted about a second later, and changes again
   until page breaks, figures and boxes match the source page by page. At
   each milestone it runs the full checks (`postext check` and the linter).
   The PDF is built only for the print checks, not every time it looks.
6. **Delivery.** It sets the book's paper, binding and covers for the Folio
   viewer and packs `my-book.postext`.

Open the result in the [Sandbox](/en/sandbox): **Books → New → Open a .postext file…**.
The import takes the chapters and wording of the sandbox's language. To work
on a folder of projects in a local copy of Postext, set
`POSTEXT_PRIVATE_PRESETS_DIR` (see [Sandbox](/en/docs/sandbox)).

### Loading the result from code

The delivered file is not tied to the Sandbox. The `postext` package opens it with `openBundle`, lays the book out with `buildBundle` and renders it to canvas, HTML or PDF (see [Bundles](/en/docs/configuration-bundles#bundles-postext-files)). A port can therefore feed a program directly. When that program's output needs adjusting, export it back to a `.postext` file with `createBundle`, fine-tune it in the Sandbox and load the corrected file again. The skill's headless `render.mjs` also accepts a packed `.postext` file as well as a project folder.

## What to expect

- **The extractors produce drafts; the agent curates them.** Expect a review
  pass per chapter against the original pages. That review is where the
  quality comes from.
- **The text stays in the Markdown.** The configuration holds the design and
  every word of the book is in the chapters, so a correction or a translation
  is an edit to Markdown. With Postext 1.35 or later, composed pages are page
  templates in the configuration whose frames are filled from each chapter's
  Markdown: a box grows with a longer translation and pushes the boxes below
  it, and from 1.37 the words on a map are labels written in the Markdown.
  With an older version they are set with boxes pinned to their place, page
  pictures without text and SVG figures with live labels. The report says
  which of the two the agent used, and with which version. When
  Postext cannot express something without typing text into the configuration,
  the agent stops, writes the gap as an issue draft and asks you. The skill
  never changes the engine to fit one book.
- **One book file for every language.** A translation is a set of chapters in
  the same `.postext` file, with its own captions and figure labels, checked
  with `postext check` in each language.
- **Rights are your call.** The agent asks before reproducing images or fonts
  whose licences are unclear. Licensed fonts are marked
  `redistributable: false`, so exported projects leave them out.
- **Fidelity where it matters.** The goal is the same grid, type, openers,
  boxes, figure placement and page breaks on most pages (within one page per
  chapter), not identical line breaks.

## Where it lives

The skill is in the repository at
[`plugins/postext/skills/postext-port`](https://github.com/drnachio/postext/tree/main/plugins/postext/skills/postext-port).
It covers every case met while building the presets in the sandbox, public and
private. When a port hits a case it does not cover yet, please open an issue
or a pull request that improves the skill, so the next port gets it for free.
