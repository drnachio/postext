# Linha de comando

**O `postext` compõe seu livro a partir de um terminal, de um script ou de um agente.**

No [Sandbox](/pt/sandbox), você escreve um livro e cuida do design dele vendo
as páginas. A linha de comando recebe o mesmo livro e gera os arquivos dele sem
navegador: um PDF pronto para impressão, as páginas em HTML, um EPUB, uma
imagem de uma página ou de todas, um documento do Word. Ela também empacota e
desempacota pacotes `.postext`, importa documentos do Word, descreve um livro
e verifica se ele tem problemas.

É **um único executável autossuficiente** por sistema. O motor do postext, os
geradores de PDF, EPUB, HTML e Word, o pintor de páginas (Skia), o HarfBuzz
para o árabe e outras escritas complexas, os perfis ICC de impressão e as
fontes padrão (EB Garamond e Open Sans) estão todos dentro dele. Não há
runtime, pacote nem biblioteca para instalar, e a diagramação é a do Sandbox:
o mesmo livro se divide nas mesmas páginas.

## Como obter

Com o [Homebrew](https://brew.sh), no macOS ou no Linux:

```bash
brew install drnachio/postext/postext
```

Com o [Scoop](https://scoop.sh), no Windows:

```powershell
scoop bucket add postext https://github.com/drnachio/scoop-postext
scoop install postext
```

Os dois instalam o executável da versão mais recente como comando `postext`,
conferido com a soma de verificação, e `brew upgrade postext` ou
`scoop update postext` traz a próxima. Sem gerenciador de pacotes, baixe você
mesmo o arquivo.

Cada versão do Postext publica os executáveis na respectiva
[GitHub Release](https://github.com/drnachio/postext/releases/latest), com
as somas de verificação (`SHA256SUMS`) e um `readme.txt`:

Cada arquivo pesa entre 115 e 140 MB. O link
`https://github.com/drnachio/postext/releases/latest/download/<file>` sempre
entrega o mais recente.

No Linux ou no macOS:

```bash
curl -fL -o postext https://github.com/drnachio/postext/releases/latest/download/postext-linux-x64
chmod +x postext
./postext
```

Mova-o para uma pasta do `PATH` (`/usr/local/bin`, `~/.local/bin`) para
executá-lo como `postext` de qualquer lugar. O macOS põe em quarentena um
arquivo baixado pelo navegador; remova essa marca uma única vez:

```bash
xattr -d com.apple.quarantine postext-macos-arm64
```

No Windows, no PowerShell:

```powershell
Invoke-WebRequest https://github.com/drnachio/postext/releases/latest/download/postext-windows-x64.exe -OutFile postext.exe
.\postext.exe
```

Com o Node.js instalado, `npx postext-cli` baixa do npm o executável do seu
sistema e o executa, e `npm install -g postext-cli` o mantém como um comando
`postext`.

Executado sem argumentos, o `postext` mostra a ajuda; `postext help <command>`
lista as opções de um comando.

## Um primeiro livro

Três arquivos Markdown em uma pasta formam um livro, um capítulo cada, na
ordem dos nomes:

```bash
postext pdf chapters/ --name "Field notes" -o field-notes.pdf
```

O front matter do primeiro capítulo define o título e o autor do livro, e os
valores padrão do motor fazem o resto: duas colunas, uma grade de linhas de base,
texto justificado e hifenizado, cabeços. Acrescente uma configuração e imagens
quando precisar delas:

```bash
postext pdf chapters/ --config design.json --resources pictures/ -o field-notes.pdf
```

Um livro feito no Sandbox (**Livros → Baixar (.postext)**) funciona como está:

```bash
postext pdf my-book.postext -o my-book.pdf
postext image my-book.postext --page 1 -o cover.png
```

## O que pode ser um livro

Todo comando que lê um livro aceita qualquer uma destas formas:

- **Um arquivo `.postext`**: o pacote que o Sandbox exporta e abre (veja
  [Pacotes](/pt/docs/configuration-bundles#pacotes-arquivos-postext)).
- **Uma pasta de livro**: um pacote desempacotado, com o `preset.json`, os
  capítulos, os recursos e as fontes. É o que a skill para agentes entrega, e o
  `postext unpack` gera uma.
- **Markdown solto**: um ou mais arquivos `.md`, um capítulo cada na ordem
  dada, ou uma pasta cujos arquivos `.md` são lidos pelo nome (`01-intro.md`,
  `02-method.md`…). Com eles:
  - `--config design.json`: a configuração, seja um objeto de configuração
    simples, seja um `preset.json` inteiro;
  - `--resources pictures/`: as imagens; cada uma vira uma figura com o nome do
    arquivo sem a extensão (`map.png` é `::resource{id="map"}`); em vez disso,
    um `resources.json` na pasta pode descrevê-las (ids, tipos,
    legendas, texto alternativo), na mesma forma que os `resources` de um
    `preset.json`;
  - `--fonts fonts/`: arquivos de fonte que o livro leva (TTF, OTF, WOFF2),
    identificados pela família que as tabelas deles indicam;
  - `--name "Title"`: o nome do livro.

`--config` também funciona com um pacote ou uma pasta: a configuração indicada
é mesclada sobre a do próprio livro. Um pacote em vários idiomas é lido no
próprio idioma, a menos que `--locale` peça outro (`--locale en`).

Todo comando grava na pasta de onde você o executa, com o nome da entrada, a

padrão.

### pdf

```bash
postext pdf book.postext -o book.pdf
postext pdf book/ --pdfx x4 --profile fogra51 -o book-print.pdf
postext pdf book/ --color-space grayscale --no-outlines
```

O PDF segue as configurações do próprio livro (veja
[Geração de PDF](/pt/docs/configuration-fonts-colors-viewers#geração-de-pdf-configuração) e
[Produção gráfica](/pt/docs/configuration-fonts-colors-viewers#produção-gráfica-configuração)); estas opções
as alteram só naquela execução:

- `--pdfx none|x1a|x4`: o padrão PDF/X para uma gráfica.
- `--profile NAME|FILE`: o perfil ICC de saída, pelo nome (`fogra39`,
  `fogra51`, `fogra52`, `swop5`, `gracol2006`, `snap2007`, `ifra26` e os
  outros perfis das configurações de impressão) ou um arquivo `.icc`.
- `--color-space rgb|cmyk|grayscale`.
- `--accessible` / `--no-accessible`: a estrutura marcada para leitores de tela.
- `--no-outlines`: deixa de fora os marcadores.
- `--page-negative`: páginas em negativo, para alguns fluxos de impressão.

### html

```bash
postext html book.postext -o book.html
postext html book.postext -o site/ --mode single
```

Um caminho terminado em `.html` recebe um único arquivo com as imagens e as
fontes dentro dele, fácil de enviar. Qualquer outro caminho é uma pasta:
`index.html` ao lado de `assets/`, que guarda as imagens, as fontes e os
vídeos hospedados no próprio livro. `--assets embed|folder` escolhe uma das
duas formas para qualquer caminho. As páginas são a diagramação de impressão,
mostrada no tamanho da tela: lado a lado (`--mode multi`, o padrão) ou uma
embaixo da outra (`--mode single`). As fontes marcadas com
`redistributable: false` são citadas pelo nome, mas não copiadas. Quando a família indica um `fallback`, são gravadas no lugar dela as faces dessa família aberta, com o nome da família original (desde o postext 1.43).

### epub

```bash
postext epub book.postext -o book.epub
postext epub book.postext --layout reflowable --cover cover.jpg
```

`--layout fixed` (o padrão) mantém cada página como no impresso, com texto
selecionável; `--layout reflowable` deixa o sistema de leitura recompor o
texto para a própria tela (veja [Livros EPUB](/pt/docs/configuration-html-folio-epub#livros-epub-postext-epub)).
A capa é a miniatura do livro, a menos que `--cover` indique uma imagem. Os
metadados do pacote EPUB (título, autores, idioma, identificador) vêm do front
matter do primeiro capítulo, como no Sandbox. As fontes marcadas com `redistributable: false` não são copiadas; uma família que indica um `fallback` é incorporada com as faces dessa família aberta, mas com o nome original (desde o postext 1.43).

### image e images

```bash
postext image book.postext --page 12 -o page-12.png
postext image book.postext --page "#1" --dpi 300 -f jpeg -o cover.jpg
postext images book.postext -o pages/ --dpi 100
postext images book.postext --pages 1-10,iv -f webp --pattern "{chapter}-{label}"
```

As páginas são indicadas **como impressas** (`12`, `iv`, um intervalo `7-9`)
ou **pela posição** no livro com `#` (`#1` é a primeira página, seja qual for
o número que ela imprime, `#10-#20`, `#30-` até o fim). `--pages` aceita uma
lista separada por vírgulas. O pintor é o da visualização Canvas do Sandbox;
por isso, uma imagem mostra a página exatamente como foi diagramada, sem passar
por um PDF.

- `--format png|jpeg|webp` (ou a extensão de `-o`), `--quality 1-100` para
  JPEG e WebP.
- `--dpi`: a resolução, 150 por padrão; 72–100 bastam para ler uma página, 300
  para impressão.
- `--pattern`: os nomes dos arquivos de `images`, a partir de `{n}` (a
  posição, `{n:03}` completada até três dígitos), `{label}` (o número
  impresso) e `{chapter}`; `page-{n:03}` por padrão.
- `--print-preview`: a página como a gráfica vai reproduzi-la, passando pelo
  perfil de saída, com o refile e a sangria desenhados.
- `--jobs N`: quantas imagens são codificadas ao mesmo tempo (por padrão, tantas
  quantos processadores o computador tiver).

### docx e import-docx

```bash
postext docx book.postext -o book.docx
postext docx book/ --variant semantic -o words.docx
postext docx book/ --variant facsimile -o pages.docx
postext import-docx book.docx book/ --dry-run
postext import-docx book.docx book/
postext import-docx manuscript.docx -o manuscript/ --locale es --report
```

`docx` grava os documentos do Word que o Sandbox exporta (veja
[Sandbox › Documentos do Word](/pt/docs/sandbox-books-saving#documentos-do-word))
e um terceiro. `--variant formatted`, o padrão, constrói um documento editável a
partir do Markdown, com os títulos, as listas, as notas de rodapé, as tabelas,
as equações e as seções próprios do Word, composto com o projeto gráfico do
livro até onde o Word permite e com as fontes do livro incorporadas
(`--no-embed-fonts` só as nomeia); o que não tem estrutura no Word viaja como
fonte em controles de conteúdo *Postext Source*. `--variant semantic` grava o
mesmo texto só como conteúdo: um documento simples (A4, uma coluna, Arial) em
estilos do Word que dizem o que é cada parte, sem nada do projeto da página e
sem fontes incorporadas. Nenhum dos dois precisa diagramar; os dois abrem no
Word e no Google Docs, e os dois voltam por `import-docx`. `--variant facsimile`
diagrama o livro como o `pdf` faz e grava cada página como uma seção do Word,
com cada linha numa caixa de texto fixa e as fontes incorporadas: um arquivo
para olhar a diagramação no Word para computador, não para editar nem para o
Google Docs. Uma família que o livro não pode repassar (`redistributable: false`
em `customFonts`) fica de fora e entra a alternativa aberta dela, como no EPUB;
uma fonte cuja licença proíbe a incorporação, uma com contornos PostScript e uma
fonte variável são avisadas e só nomeadas. No `build`, `--docx ARQUIVO` grava o
mesmo arquivo, com `--docx-variant` e `--no-docx-fonts`. Desde o postext 1.68;
`--template` não vale mais para `docx` nem para `build`.

Com um livro depois do arquivo, o `import-docx` traz de volta as correções
feitas num documento que o `docx` exportou desse livro. Ele lê o mapa que o
arquivo leva, compara o texto com a cópia dos capítulos feita na exportação e
combina cada correção com o livro como ele está agora: os arquivos de capítulo
de uma pasta, de um `.postext` ou de Markdown solto, e o texto dos recursos
(legendas, notas, texto alternativo, células de tabela) no `preset.json`, ou no
`resources.json` de `--resources DIR` para Markdown solto. Num livro em várias
línguas, `--locale` indica a edição da qual o arquivo foi exportado, e uma
correção no texto de um recurso vai para o bloco `localized` dessa edição. Cada
correção é informada numa linha própria:

- `applied`, com o arquivo e a linha para onde foi;
- `conflict`: o texto também mudou no livro desde a exportação, o capítulo ou o
  recurso não existe mais, ou duas correções se sobrepõem;
- `rejected`: texto que o próprio livro gera (números, rótulos de legenda, o
  que um estilo de citação escreve a partir da bibliografia) ou uma formatação
  que atravessa a marcação do Postext.

Uma correção dentro de uma citação volta para ela quando cai numa parte que o
autor escreveu: o localizador, ou as palavras antes ou depois da obra. Em
`[see also @simmons1991, 346–47]`, um intervalo de páginas corrigido para
`346–48` no Word vira `[see also @simmons1991, 346–48]`. A linha nomeia a
citação (`citation simmons1991: locator "7" → "8"`). Uma alteração no nome do
autor, no título ou em *Ibid.* é rejeitada, e uma parte impressa de forma
diferente de como está escrita (`346--47` impresso `346–47`) é rejeitada com o
seu lugar no livro, para ser mudada lá.

As alterações controladas são tomadas como aceitas, e os comentários são
listados com autor e lugar, mas não gravados. O código de saída é 3 quando uma
correção não foi aplicada. `--dry-run` (`-n`) imprime o relatório e um diff
unificado de cada arquivo que mudaria, e não grava nada. Cada arquivo é gravado
ao lado do destino e renomeado por cima dele, então uma execução interrompida
nunca deixa meio capítulo; um arquivo de capítulo que mudou enquanto a
importação rodava fica como está, com um aviso `docx.fileChanged`. `-o` não
combina com um livro. Com `--json`, a resposta traz `variant` (a exportação
que o arquivo é: `formatted`, `semantic` ou `facsimile`), `writer` (o gerador
que as propriedades dele nomeiam), `exportId`, `edits` (cada uma com `status`,
`reason`, `kind`, `before`, `after` e `at`, e dentro de uma citação `citation`
e `citationPart`), `comments`, `files` e, num teste sem gravação, `diff`.

Um arquivo editado no Google Docs e baixado como `.docx` também volta. O Docs
não guarda o mapa nem a cópia dos capítulos; a importação grava o mapa de novo a
partir do livro, e diz isso no relatório. Como esse arquivo não leva nenhuma
cópia do texto exportado, ele é comparado com o livro como ele está agora. Se o
livro mudou desde a exportação, o relatório avisa, e uma mudança feita no livro
nesse meio-tempo pode aparecer como uma edição que a desfaz. Importe um arquivo
do Docs no livro do qual ele foi exportado, antes de mudar esse livro; um
arquivo salvo pelo Word mantém o mapa e é combinado com as mudanças posteriores
do livro. O Docs também apaga o indicador oculto de um texto que é substituído
por inteiro (um título, uma célula de tabela, uma legenda, o título de um boxe,
uma nota de rodapé). A importação encontra esse texto pelo lugar dele entre os
vizinhos, então um título continua sendo um título e uma legenda vai para o
recurso dela. Quando isso não pode ser decidido, por exemplo porque um parágrafo
também foi digitado ao lado e nada distingue um do outro, o relatório mostra uma
exclusão e uma adição no lugar. Importar o mesmo arquivo uma segunda vez não
traz nada.

Sem um livro, o `import-docx` transforma qualquer documento do Word em livro
novo: um capítulo a cada título de nível 1 (`--no-split` mantém um só),
imagens e tabelas como recursos, e `--report` imprime o relatório de qualidade
que o Sandbox mostra (estilos em uso, formatação direta, numeração
digitada…). `--template` recebe um modelo de importação (um `.json` salvo no
Sandbox ou um `.docx` que traga um).

O espaçamento entre caracteres é uma propriedade do estilo, não do texto, e por isso não está no
Markdown. `docx` grava o `letterSpacing` dos estilos de parágrafo, dos estilos de título
e dos níveis de título como espaçamento entre caracteres do estilo do Word, e o `import-docx`
o lê de volta, em em relativos ao corpo do estilo: define o `letterSpacing` nos estilos do livro
que não têm nenhum (os estilos de parágrafo e de título do arquivo de `--config` aos quais
os estilos do Word correspondem, e os níveis de título) e deixa como está qualquer tracking
que o livro já define. Com `--json`, `styleTracking` lista o que foi aplicado (`applied`) e o que
ficou de fora (`skipped`). Desde o postext 1.39.

### idml

```bash
postext idml book/ -o book.idml
postext idml book.postext -o book.idml --images link
postext idml book/ -o out/book.idml --lines reflow --fonts
```

`idml` diagrama o livro como o `pdf` faz e grava as páginas como um pacote
InDesign Markup, para finalizar no InDesign: as páginas em spreads dos dois
lados da lombada em um livro com margens de páginas espelhadas (uma página por
spread em qualquer outro), fios, boxes, traçados e imagens como itens de
página, as tabelas como tabelas do InDesign, o texto de cada bloco de uma
página composta como um quadro de texto com a sua própria matéria (os blocos
encadeados por `next` compartilham uma), os estilos de boxe como estilos de
parágrafo e as cores CMYK definidas pelo autor como amostras. Os chips com
campo de formulário viram campos de formulário do InDesign. `--lines keep` (o
padrão) termina cada linha onde o Postext a terminou, então o InDesign mostra
as mesmas linhas do PDF; `--lines reflow` deixa os parágrafos para o
compositor do InDesign, e as quebras de linha podem variar.
`--spreads facing` ou `--spreads single` monta as páginas em pares, ou não, digam as margens o que disserem. `--images link`
deixa as imagens ao lado do arquivo, em `Links/`, em vez de dentro dele.
`--fonts` grava os arquivos de fonte das variantes usadas ao lado do pacote,
em `Document fonts/`, onde o InDesign os encontra para aquele documento;
precisa que `-o` nomeie um arquivo, e uma família que o livro não pode
redistribuir fica de fora, com um aviso. O que o pacote não consegue levar
como está no livro (os pontos de ênfase do texto vertical, a moldura arredondada de uma tabela) é
avisado como `idml.*`. O gerador é o pacote `postext-idml`: veja [Uso
programático › Pacotes do
InDesign](/pt/docs/configuration-programmatic-usage#pacotes-do-indesign-postext-idml).
Em `build`, `--idml ARQUIVO` grava o mesmo pacote, com `--idml-images`, `--idml-lines`, `--idml-spreads` e `--idml-fonts`.
Desde o postext 1.71; `--lines` e `--fonts`, desde o 1.76, e `--spreads`, desde o 1.78.

### import-idml

```bash
postext import-idml book.idml -o book/
postext import-idml book.idml -o book.postext --layout flow --links pictures/
postext import-idml book.idml --report --json
postext import-idml package.zip -o book.postext
postext import-idml package.zip --document Book/Book.idml -o book/
```

`import-idml` lê um pacote InDesign Markup e grava um livro novo, numa pasta ou num `.postext`: os capítulos em Markdown, a configuração que os estilos e as páginas do documento dão, e as imagens e tabelas dele como recursos. Um `.indd` não é lido: salve-o antes, no InDesign, como InDesign Markup. `--layout pages` segue o documento página por página com páginas compostas, cada bloco onde estava; `--layout flow` grava um livro de texto corrido, na ordem de leitura e com os estilos do documento, para o Postext diagramar de novo; `auto` (o padrão) escolhe um dos dois e diz por quê. O arquivo também pode ser um pacote do InDesign compactado, a pasta que **Arquivo › Empacotar** cria com **Include IDML** marcado, enviada como um único `.zip`: o comando importa o IDML dele com as imagens da pasta `Links/` e coloca no livro os arquivos de fonte da pasta `Document fonts/`. Quando o zip guarda vários documentos IDML, `--document` indica o que será importado pelo caminho dele dentro do zip (`--document Book/Book.idml`); sem essa opção, o comando os lista. Um pacote que só guarda o `.indd` é recusado, com o modo de obter o IDML. As imagens vinculadas são lidas primeiro de `--links`, depois do pacote e depois da pasta do arquivo e da `Links/` dela, e as que não forem encontradas são listadas. As fontes que o documento nomeia também são listadas: um `.idml` avulso não leva arquivos de fonte, então indique-os com `--font-dir` ao gerar o livro. Com um pacote, uma fonte encontrada em `--font-dir` entra no livro no lugar do arquivo do pacote. Uma coleção de fontes (`.ttc`, `.otc`), no pacote ou em `--font-dir`, é separada em estilos avulsos, e só entram os estilos que o livro usa (desde o postext 1.83).

Um livro exportado do Postext volta com as mesmas linhas. Um documento feito no InDesign é lido com perdas: o comando imprime o veredito (`faithful`, `approximate` ou `lossy`), as contagens e o que foi perdido ou aproximado; `--report` acrescenta as notas e como cada estilo de parágrafo foi lido, e `--json` leva tudo como dados. `--hidden`, `--pasteboard` e `--non-printing` leem também as camadas e os objetos ocultos, a área de trabalho e os objetos não imprimíveis; `--conditions all` lê todo o texto condicional, `--changes reject` lê as alterações controladas como rejeitadas e `--no-masters` deixa de fora os itens das páginas-mestre. `--name` e `--locale` dão o título e o idioma. O importador é `idmlToPostext`, do pacote `postext-idml`: veja [Uso programático › Pacotes do InDesign](/pt/docs/configuration-programmatic-usage#pacotes-do-indesign-postext-idml). A importação copia o documento como está; para portar um livro que você vai manter, com as regras de diagramação deduzidas, use no lugar dela a skill para agentes (veja [InDesign: importar, exportar e portar](/pt/docs/indesign)).

### design

```bash
postext design book.postext -o novel.postext
postext design book/ --parts page,text,headings -o type.postext
postext pdf other/ --design novel.postext -o other.pdf
```

Um arquivo de projeto guarda o projeto gráfico de um livro e nada do seu texto: as configurações das partes pedidas (os grupos do painel Design, veja [Arquivos de projeto gráfico](/pt/docs/configuration-bundles#arquivos-de-projeto-gráfico)) com os arquivos de fonte e o perfil de cor que elas nomeiam. Uma fonte marcada como não redistribuível fica de fora. `--parts` toma só algumas partes, separadas por vírgulas; `--design-name`, `--id` e `--description` dão nome ao projeto. O mesmo livro sempre dá os mesmos bytes.

`--design ARQUIVO`, uma opção de todos os comandos que leem um livro, compõe o livro num arquivo de projeto ou no projeto de outro livro, antes de `--config` e `--set`: as configurações das suas partes substituem as do livro, os estilos com nome se combinam por id e as fontes do projeto se juntam às do livro. `--design-parts` toma só algumas das suas partes. O painel Design do Sandbox importa e exporta os mesmos arquivos.

`--composition TAG`, também uma opção de todos os comandos que leem um livro, aplica as regras de composição da tradição de um idioma depois de `--design` (desde o postext 1.80): `es`, `en-US` (ou `en`), `en-GB`, `fr` ou `de`, ou `auto` para o idioma do livro. As regras da convenção substituem as do livro e as outras voltam aos valores padrão; a tipografia fica como está. Veja [Convenções de composição](/pt/docs/configuration-text#convenções-de-composição).

```bash
postext pdf book/ --composition auto -o book.pdf
postext design book/ --composition es --parts composition -o house-rules.postext
```

### pack e unpack

```bash
postext pack my-book/ -o my-book.postext
postext pack 01.md 02.md --name "Notes" --config design.json --resources img/ -o notes.postext
postext unpack my-book.postext -o my-book/
```

`pack` compacta uma pasta de livro como ela está, ou monta um pacote a partir
de Markdown solto. A mesma entrada sempre gera os mesmos bytes; por isso, um
pacote pode ser comparado ou ter o hash calculado. Para Markdown solto,
`--id`, `--description` e `--thumbnail FILE` (uma imagem de capa) definem o id,
a descrição e a miniatura do pacote; por padrão, o id é um slug do nome. Uma
pasta mantém o que o seu `preset.json` diz. Um livro que não indica capa recebe a primeira página como capa (`thumbnail.jpg`, 1024 px no lado maior), a imagem que um gerenciador de arquivos pode mostrar para o arquivo; `--no-auto-thumbnail` a deixa de fora. `unpack` se recusa a gravar em
uma pasta que não está vazia, a menos que se passe `--force`.

### info e check

```bash
postext info book.postext --pages
postext check book.postext
postext check chapters/ --strict --json
```

`info` lista os capítulos (título, palavras, arquivo e, com `--pages`, as
páginas), os recursos e cada família tipográfica com a respectiva origem (o livro,
uma pasta, o executável, o cache de downloads ou a fonte substituta). Se o livro diz onde começa (`start` em `preset.json`: um trecho que abre na página 58, no capítulo 4), ele também mostra isso, e todos os comandos diagramam o livro a partir daí.

`check` diagrama o livro e relata o que o painel Verificações do Sandbox
mostra: Markdown que não fecha, recursos, diretivas e estilos desconhecidos,
boxes que a diagramação teve de forçar, fontes que faltam, configurações que o
motor teve de substituir e, para um livro preparado para impressão (ou com
`--preflight`), o preflight: imagens de baixa resolução, fios finos, texto
pequeno em várias tintas, tinta acima do limite, texto perto do refile. Também
lista o texto difícil de ler sobre o fundo (`contrast`), uma vez por par de
cores, com a razão na tela e, para impressão, no papel do perfil de saída. Cada
problema indica o arquivo do capítulo, a linha e a página. O código de saída é
3 quando se encontra um erro, ou qualquer aviso com `--strict`.

Também aponta os textos dos designs da configuração que contêm o texto do livro
em vez de marcadores (`contentInConfig`), uma vez por estilo de título, cabeço
ou design de parte, com o caminho de cada texto: leve esse texto para o
Markdown, ou acrescente o título ou o nome da editora a
`checks.contentInConfig.allow`.

Em um livro com modelos de página, o `check` aponta também o texto que não cabe no bloco (`frameOverflow`, com os passos que a escada de ajuste tentou e as mudanças que o fariam caber), um texto que ultrapassa as páginas que um bloco pode acrescentar (`frameContinuationLimit`), um salto para uma página que não vem depois (`continueTargetMissing`) os rótulos de figura que não podem ser desenhados ou que se sobrepõem (`labelAnchorUnknown`, `anchorUnlabelled`, `labelOverflow`, `labelOverlap`), os blocos escondidos sob outros blocos ou que passam do seu limite (`frameCovered`, `frameOutsideArea`), mais cartões do que uma grade comporta (`repeatOverflow`) e os módulos que uma página não consegue diagramar (`moduleUnknown`, `moduleAsPage`, `moduleNested`, `moduleNameRejected`). Depois dos avisos, imprime uma linha `reflow` por página composta com eventos, e o `--json` traz os passos, as propostas e o registro de reajustes como dados. Veja [Páginas compostas › Avisos](/pt/docs/composed-pages#avisos) e [Registro de reajustes](/pt/docs/composed-pages#registro-de-reajustes).

### build e --watch

```bash
postext build book/ --pdf out/book.pdf --html out/book.html --images out/pages --pages 1-4
postext build chapters/ --pdf book.pdf --watch
```

`build` diagrama o livro uma vez e grava cada saída que você indicar (`--pdf`,
`--html`, `--epub`, `--images`, `--docx`, `--idml`), com as opções de cada comando.
`--watch` continua rodando: quando um capítulo, a configuração ou uma imagem
muda, o livro é diagramado de novo com as fontes e o motor ainda carregados,
em geral numa fração de segundo para um capítulo, e as saídas são gravadas de
novo. Um salvamento que quebra o livro imprime o erro e mantém os últimos
arquivos bons.

## Fontes

Um livro que leva as próprias fontes (um pacote, ou `--fonts` com Markdown solto)
é composto com elas e com nada mais. Para cada família que a configuração
cita e que o livro não leva, o `postext` procura, nesta ordem:

1. nas pastas indicadas com `--font-dir`;
2. entre as faces compiladas no executável: EB Garamond e Open Sans, os
   padrões do motor;
3. no cache de downloads;
4. no [Google Fonts](https://fonts.google.com), que entrega arquivos
   TrueType estáticos completos, ou na [Fontsource](https://fontsource.org)
   quando o Google Fonts não tem a família (Commit Mono, FiraGO); eles ficam
   no cache; por isso, cada família é baixada uma única vez.

Um peso que a família não traz é composto com a face que um navegador
escolheria (a seleção de fontes do CSS: acima de 500, primeiro as mais pesadas;
abaixo de 400, primeiro as mais leves; assim, o 600 de uma família com 400 e
700 é o 700 dela, e o 550 também), e uma inclinação que ela não traz é composta
com a redonda. Cada face é usada tal como é, nas imagens de página e no PDF:
uma fonte de display com um só peso mantém as próprias letras no negrito, e
uma família sem itálico mantém a redonda no itálico.

São baixados os pesos que a configuração cita: regular, negrito e seus
itálicos para cada família, e qualquer outro peso que um ajuste indique,
inclusive o do negrito (`bodyText.boldFontWeight: 600` pede a fonte de peso
600). Quando um peso que a família traz não pôde ser carregado (offline e sem
arquivo no cache, um download que falhou, uma pasta de fontes sem o arquivo),
o texto é composto com a face da família que a mesma regra escolhe no lugar
dele, e o `postext check` o lista como aviso `fontFallback`: as linhas podem
quebrar de modo diferente do Sandbox.

Um caractere para o qual uma fonte não tem glifo é desenhado com outra fonte. `postext check` lê a tabela `cmap` de cada fonte que carrega e lista esses caracteres uma vez por fonte para o livro todo como aviso `glyphFallback`; com `--json`, o `data` traz os caracteres e quantos são.

O cache fica em `~/.cache/postext` (`%LOCALAPPDATA%\postext\cache` no
Windows); `POSTEXT_CACHE_DIR` ou `--cache-dir` o mudam de lugar. `--offline`
pula o download. Uma família que não se encontra em lugar nenhum é composta em
EB Garamond com o próprio nome, para que a diagramação e o PDF continuem
de acordo, e um aviso `missingFont` a aponta. `postext info` mostra de onde
veio cada família.

Um pacote que deixa de fora os arquivos de uma família licenciada pode indicar para ela uma família aberta de largura parecida (`fallback` nas `fonts` do manifesto, desde o postext 1.42). O `postext` procura então essa família pelos passos acima e compõe as faces que o livro não traz nos cortes dela de mesmo peso e mesma inclinação, com o nome da licenciada, de modo que a diagramação fica próxima da obtida com os arquivos e o `postext check` não gera o aviso `missingFont` para ela. Uma família que o livro traz só em parte toma do `fallback` apenas uma inclinação para a qual não tem nenhuma face. O PDF incorpora a face aberta.

## Para scripts e agentes

A linha de comando foi feita para ser comandada por outros programas,
inclusive agentes de programação.

- **`--json`** imprime um único objeto JSON na saída padrão quando o comando
  termina; todas as mensagens vão para a saída de erro. O relatório lista o
  que foi gravado, as páginas, cada aviso com a origem e quanto tempo
  levou cada etapa (em milissegundos):

```json
{
  "ok": true,
  "command": "pdf",
  "version": "1.22.1",
  "book": { "name": "notes", "id": "notes", "locale": "en", "chapters": 2 },
  "pages": 3,
  "outputs": [{ "kind": "pdf", "path": "notes.pdf", "bytes": 29746, "pages": 3 }],
  "warnings": [
    {
      "kind": "unknownResourceId",
      "severity": "warning",
      "message": "Unknown resource id \"map\" in ::resource — nothing is embedded (offset 26)",
      "at": "notes/02-more.md:5"
    }
  ],
  "timings": { "read": 13, "fonts": 8.4, "math": 28.2, "layout": 51.6, "pdf": 132.1, "total": 1638 },
  "exitCode": 0
}
```

- **Códigos de saída**: `0` concluído, `1` falhou, `2` uso incorreto (uma
  opção desconhecida, uma entrada que falta), `3` o `check` encontrou erros
  (ou avisos com `--strict`), ou o `import-docx` deixou de fora uma correção do Word.
- **Sem perguntas.** Ele nunca espera uma resposta; uma pasta que não está
  vazia é recusada em vez de gerar uma pergunta.
- **Saída padrão**: `-o -` grava ali um PDF, uma imagem ou um pacote, para
  passar adiante por um pipe.
- **Velocidade.** O executável inicia em poucos centésimos de segundo. Um
  livro curto vira um PDF ou uma imagem de página em bem menos de um segundo;
  um longo leva o tempo que a diagramação dele exigir (um romance ilustrado de
  140 páginas, uns dez segundos). Para olhar algumas páginas de um livro
  longo, combine `--chapters` com `image` ou `images --pages`. Para trabalhar
  em um livro ao longo de muitas mudanças, deixe `postext build --watch`
  rodando e leia as saídas.

A [skill para agentes](/pt/docs/skill) usa a linha de comando para renderizar
as páginas em que está trabalhando e para verificar uma conversão.

## Python

`pip install postext` transforma a linha de comando em uma biblioteca Python. O
pacote é Python puro, sem dependências, e a versão dele é a do postext. Na
primeira vez que executa um comando, ele baixa o executável do seu sistema da
GitHub Release dessa versão, confere com `SHA256SUMS` e guarda no cache
descrito acima, em `bin/<versão>/`. Se `POSTEXT_BIN` apontar para um
executável que você já tem (do Homebrew, do Scoop ou compilado por você), nada
é baixado.

```python
import postext

report = postext.pdf("book.postext", out="book.pdf", set={"page.dpi": 300}, locale="es")
print(report.output.pages)
for warning in report.warnings:
    print(warning.kind, warning.at, warning.message)

pdf = postext.pdf_bytes(open("book.postext", "rb").read())
```

- **Uma função por comando**: `pdf`, `html`, `epub`, `image`, `images`, `docx`,
  `idml`, `import_docx`, `import_idml`, `design`, `pack`, `unpack`, `info`,
  `check` e `build`. As opções mantêm o nome, com sublinhados (`color_space`,
  `font_dirs`, `dry_run`). `set` recebe um dicionário, `config` um arquivo ou
  um dicionário, `chapters` um número, uma lista, um `range` ou `"1,3-5"`. Toda
  função que lê um livro aceita `design=`, um arquivo de projeto como caminho
  ou como bytes, `design_parts=`, uma lista ou `"page,text"`, e
  `composition=`, uma etiqueta de idioma ou `"auto"`.
- **Relatórios como objetos.** Cada função executa o seu comando com `--json` e
  devolve o relatório: `outputs`, `pages`, `timings` e `warnings`, cada aviso
  um `Diagnostic` com `kind`, `severity`, `message`, `at` e `page`. `info`
  acrescenta `chapters`, `resources` e `fonts`; `check` acrescenta `passed`,
  `error_count` e `warning_count`; `design` acrescenta `name` e `parts`;
  `import_idml` acrescenta `layout`, `reason`, `chapters`, `quality`, `fonts`,
  `missing_links` e `package`.
- **Erros como exceções.** Uma falha levanta `PostextError`; uma opção errada,
  `UsageError`. Quando `check` encontra erros, levanta `ProblemsFound`, cujo
  `report` os lista; com `raise_on_problems=False`, devolve o relatório.
- **Bytes.** Um livro pode ser dado como os bytes de um pacote `.postext`. Com
  `out="-"`, o arquivo volta em `report.content`; `pdf_bytes`, `html_bytes`,
  `epub_bytes`, `image_bytes`, `docx_bytes`, `idml_bytes`, `pack_bytes` e
  `design_bytes` o devolvem diretamente.
- `postext.Postext(binary, cwd=…, timeout=…)` usa um executável específico, e
  `python -m postext …` é a própria linha de comando.

Cada chamada inicia o executável de novo. O [README](https://github.com/drnachio/postext/tree/main/packages/postext-python) do pacote
lista todas as opções.

## Como é feita

A linha de comando é o pacote `postext-cli` do
[repositório](https://github.com/drnachio/postext/tree/main/packages/postext-cli).
O [Bun](https://bun.sh) a compila, com o motor e os geradores dele, em um
executável por sistema, e o [Skia](https://skia.org) (por meio de
`@napi-rs/canvas`) mede e pinta o texto, como o canvas do navegador faz no
Sandbox. Uma ilustração SVG que contém um bitmap (um PNG ou JPEG incorporado como URI de dados, como o `pdftocairo -svg` escreve a arte recortada de um PDF) é desenhada pelo [resvg](https://github.com/linebender/resvg), porque o renderizador de SVG do Skia omite essas imagens. A cada versão, os executáveis são construídos, executados no Linux,
no Alpine, no macOS e no Windows, e anexados à GitHub Release; o npm recebe o
`postext-cli` e um pacote `postext-cli-<system>` por executável.

Para executá-la a partir de uma cópia do repositório:

```bash
pnpm install
pnpm --filter postext-cli start pdf book.postext
pnpm --filter postext-cli build:bin --current
```

O primeiro comando a executa a partir do código-fonte; o segundo grava o
executável deste computador em `packages/postext-cli/bin/`.

## Diferenças em relação ao Sandbox

- **HTML** é a diagramação de impressão mostrada no tamanho da tela. A aba
  HTML do Sandbox recompõe o texto para a janela.
- **`--chapters`** diagrama os capítulos isoladamente: a numeração das páginas
  recomeça, enquanto o Sandbox continua a numeração do livro.
- **As fontes** vêm do livro, das suas pastas, do executável, do Google Fonts
  ou da Fontsource (para uma família que o Google Fonts não tem), nunca das
  fontes instaladas no computador; por isso, um livro sai igual em qualquer
  máquina.
- **O idioma do texto** é, num navegador, o do próprio documento
  (`bodyText.shapingLanguage: 'document'`, o padrão desde o postext 1.30). O
  canvas do Skia aceita um idioma, mas dá forma ao texto sem levá-lo em conta;
  por isso, a linha de comando mede as formas do idioma padrão de cada fonte e
  sempre diagrama os livros com `shapingLanguage: 'host'`, diga o que disser a
  configuração, e o PDF e as imagens de página que ela gera pintam essas mesmas
  formas. Um livro cuja
  fonte tem formas para um idioma (um `l·l` catalão, um `fi` turco, os
  algarismos de uma fonte chinesa num livro em inglês) é composto aqui com as
  formas padrão. O que `'document'` mede de outro modo (as partes de uma
