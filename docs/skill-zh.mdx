# 智能体技能

**借助编程智能体，把现有出版物转换成Postext项目。**

很多人来到Postext时手里已经有一本书：一本印刷用PDF的教材、一份Word报告、一套PowerPoint课程、一本InDesign排的产品目录，或者一本EPUB。移植它要做两件事：

- **内容**：每一章的增强Markdown，连同其中的指令和微格式。
- **版面设计**：一份配置清单，重现原书的版面规则（页面几何、基线网格、字体、章首页、书眉、标注框、浮动体、表、篇）。

大语言模型可以完成其中的大部分工作，但前提是它了解Postext的工作方式。Postext的Markdown不是CommonMark，配置里也有一些陷阱，只有页面排错时才会暴露出来。<strong>`postext-port`</strong>技能把这些知识，连同我们构建沙盒里每个预设时用过的工具打包在一起，让你的智能体把移植做好。

它遵循开放的[Agent Skills](https://agentskills.io)格式，因此可用于Claude Code、Codex、Cursor、Gemini CLI、GitHub Copilot、OpenCode以及[许多其他智能体](https://skills.sh)。

## 技能包含什么

- **一套工作流程**：
  1. 商定需求；
  2. 清点源文件；
  3. 测量版面设计，写成规格表；
  4. 搭建项目框架；
  5. 提取内容；
  6. 整理成Postext Markdown；
  7. 准备字体和图片；
  8. 逐页核对；
  9. 打包。
- **参考资料**：
  - 文档格式和配置清单，两者都对照引擎核实过；
  - 项目（文件包）格式；
  - 每种源格式各一份操作手册；
  - 一套版面设计分析方法；
  - 一份已解决的版面案例目录：各有配色的篇、章首页、诗歌、边注、脚注、索引、浮动/拆分/嵌套的标注框、矢量印刷原稿、保留真实文字的图、表格单元格中的图片、横排表、双语版本等；
  - 中文书籍，横排或竖排、右侧装订：在需求中要问什么（文字、地区、方向、装订），如何测量字符网格，如何读取竖排PDF，InDesign的注音和双行夹注，Word的东亚版式和从右到左的EPUB，以及如何按书中用字裁剪CJK字体（见[中文排版](/zh/docs/chinese-layout)）；
  - 日文书籍，竖排、右侧装订的文库本和单行本小说，或横排的技术书：开启日文规则的语言设置（`ja`，不用任何中文标签），在需求中要问什么（排版方向、版面网格、注音假名、注释、底本的用字），如何按字数和行数测量版面，注音假名和傍点的标记，用`aozora.py`转换的青空文库文本，日本国立国会图书馆公有领域版本的扫描件，以及保留假名和竖排字形的日文字体子集（见[日文排版](/zh/docs/japanese-layout)）；
  - 阿拉伯文书籍，现代的或标注元音的古典版本，从右到左排、右侧装订：让整本书转向的语言设置，在需求中要问什么（地区与数字、元音标注、诗体、目录放在书末），如何测量镜像的页面，如何从PDF、Word和维基文库读取阿拉伯文，把诗排成`:::verse`，每页重新编号的脚注「(١)」，以及保留连写表的阿拉伯文字体子集（见[阿拉伯文排版](/zh/docs/arabic-layout)）；
  - 漫画和报纸连环漫画：把一页分成若干分格的分割表达式，带有说话人锚点和安全区的分格画面，每种语言一份由引擎嵌字的脚本（对白框、旁白框、拟声词），从右到左阅读的日本漫画和阿拉伯文版本，以及如何从无字原画加译文、从已嵌字的扫描页或从脚本加生成的画面进行移植（见[漫画](/zh/docs/comics)）；
  - 特种油墨与模切：PDF或IDML来源中的专色印版和模切厂的印版与图层，每种油墨名称所提示的工艺（金属色、烫印、荧光、不透明白、上光油），并以印刷厂的规格确认，以及按模切线测量的模切形状（见[特种油墨与模切](/zh/docs/special-inks-die-cuts)）；
  - 模板页：把教材、练习册和杂志的固定页面移植为页面模板，模板中的框由Markdown填充；已安装的Postext支持哪一轮移植；每个版本必须通过的检查（见[模板页](/zh/docs/composed-pages)）；
  - 印刷实物：如何读出源书的纸张、装订、封面和书脊，并把它们设为[书页视图](/zh/docs/sandbox-previews#书页标签页)所显示的`folio`设置，由lint脚本检查。
- **脚本**（Python和Node），在下一节介绍。

## 安装

### 任意智能体（skills.sh）

[`skills`](https://skills.sh)命令行工具会检测你的智能体，并为它们安装该技能：

```bash
npx skills add drnachio/postext --skill postext-port
```

用`-a`明确指定智能体，用`-g`全局安装（所有项目可用）：

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

网站也发布了同一个技能，所以这样也行：

```bash
npx skills add https://postext.dev
```

### Claude Code插件

Postext仓库同时也是一个Claude Code插件市场。在Claude Code中执行：

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

或者在终端中执行：

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### 让智能体来安装

你可以让智能体代劳，例如：*“安装Postext移植技能（`npx skills add drnachio/postext --skill postext-port`），然后用它移植这份PDF。”*读取`https://postext.dev/llms.txt`的智能体会在那里找到本页和安装命令。

### 脚本用到的工具

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

Word、PowerPoint、EPUB和HTML源文件需要Pandoc，生成源文件的页面图像需要poppler，`comic_panels.py`需要numpy。Node包驱动无浏览器渲染器（需要Node 22.15或更高版本）；`@napi-rs/canvas`是预编译的画布，渲染器借助它直接把书页画成JPEG。可选工具：用于扫描件的`ocrmypdf`、ImageMagick，以及用于PDF/UA检查的veraPDF。

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

选择适合你的系统的文件（`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`）；有Node时，也可以用`npx postext-cli`。

工作循环用的是[命令行](/zh/docs/command-line)，一个无需安装的独立可执行文件：智能体让项目保持解压状态，并让`postext build --watch`针对正在处理的页面一直运行，这样每次修改大约一秒后就会以JPEG的形式出现，长书也是如此。Node包是可选的：它们运行`render.mjs`，提供沙盒的额外检查。两者都不论配置怎么写，始终用`bodyText.shapingLanguage: 'host'`排版，所以某一行断开的位置可能与沙盒里不同（见[与沙盒的区别](/zh/docs/command-line#与沙盒的区别)）。

## 使用

把源文件放进工作文件夹，然后提出移植要求。例如：

- *“把`manual.pdf`的第1–3章移植到Postext，重现它的双栏版面、章首页和标注框。”*
- *“把`course.docx`转换成一本Postext图书。样式‘Nota’和‘Actividad’是标注框。”*
- *“把`deck.pptx`做成一份Postext讲义：幻灯片变成小节，演讲者备注变成正文。”*
- *“我们有这本教材的InDesign文件包（IDML + 印刷PDF）。为第1章构建西班牙语和英语的Postext预设。”*

对于InDesign书，把InDesign的<strong>文件 › 打包</strong>生成的文件夹（`.idml`、印刷PDF、字体和链接的美术文件）交给智能体。技能根据它们推断出版式规则，IDML导入器做不到这一点：[InDesign：导入、导出与移植](/zh/docs/indesign)比较了这两种方式。

智能体按工作流程进行：

1. **需求**。它询问无法推断的事项：忠实重现还是重新设计，样章还是全书，语言，印刷还是屏幕阅读，以及文字、图片和字体的版权。
2. **清点与测量**。它读取源文件，写出一份实测数据的规格表：成品尺寸、页边距、栏、行距、字体角色、调色板、章首页、书眉、标注框类别和排放习惯。它还把每一页分为正文流排页和组版页（标注框、标签和地图放在固定位置）；在Postext 1.35及以上版本中，它把组版页按版式类型归组，每类用一个页面模板来排，所以与原书一致的版面也保留可以修改和翻译的文字；在更早的版本中，组版页超过三分之一时，它会问你要和原书一模一样的版面，还是要可以修改和翻译的文字。
3. **项目**。它搭建`my-book/`，其中有一个`build_preset.py`生成器，把规格作为常量保存，并生成`preset.json`。
4. **内容**。它用合适的提取器提取章节草稿，再整理成Postext Markdown：标注框、段落样式、篇、用于章首页的标题属性、`:ref`引用、表和图资源。
5. **核对**。它对项目做lint检查，并让`postext build --watch`在解压后的项目上一直运行：修改一章或一项设置，大约一秒后查看重新绘制的页面JPEG，再接着修改，直到分页、图和标注框与源文件逐页对上。每完成一个阶段，它都运行完整的检查（`postext check`和lint）。PDF用于印刷检查，不是每次查看都要生成。
6. **交付**。它为书页视图设置书的纸张、装订和封面，然后打包出`my-book.postext`。

在[沙盒](/zh/sandbox)中打开结果：**书库 › 新建 › 打开.postext文件…**。导入时采用沙盒当前语言的章节和文字。要在Postext的本地副本中处理存放多个项目的文件夹，请设置`POSTEXT_PRIVATE_PRESETS_DIR`（见[沙盒](/zh/docs/sandbox)）。

### 从代码加载结果

交付的文件并不依赖沙盒。`postext`包用`openBundle`打开它，用`buildBundle`排版整本书，并渲染到Canvas、HTML或PDF（见[文件包](/zh/docs/configuration-bundles#文件包postext文件)）。因此，移植结果可以直接供程序使用。程序的输出需要调整时，用`createBundle`把它导出回`.postext`文件，在沙盒中微调，再加载修正后的文件。技能自带的无浏览器`render.mjs`既接受打包好的`.postext`文件，也接受项目文件夹。

## 预期效果

- <strong>提取器产出草稿，由智能体整理。</strong>每一章都要对照原书页面审阅一遍。质量来自这一步审阅。
- **文字留在Markdown里**。配置只放版式设计，书中的每个字都在各章里，所以改错或翻译都是改Markdown。在Postext 1.35及以上版本中，组版页是配置里的页面模板，模板中的框由各章的Markdown填充：译文变长时，标注框随之增高，并把下面的框往下推；从1.37起，地图上的名称是写在Markdown里的标注。在更早的版本中，组版页用固定在原位的标注框、不含文字的整页图片和标签为真实文字的SVG图来排。报告会写明智能体用了哪一种做法，以及所用的版本。如果Postext不把文字写进配置就无法表达某样东西，智能体会停下来，把这个缺口写成议题草稿，再来问你。这个技能从不为了适应某一本书而修改引擎。
- **所有语言共用一个文件**。译本是同一个`.postext`文件里的一组章节，带有自己的题注和图上的标注，并在每种语言下用`postext check`检查。
- **版权由你决定**。对授权不明确的图片或字体，智能体会先询问再复制。有授权限制的字体标记为`redistributable: false`，导出的项目不会包含它们。
- **在要紧处保持一致**。目标是大多数页面的网格、字体、章首页、标注框、图的位置和分页都相同（每章误差不超过一页），而不是断行完全一致。
