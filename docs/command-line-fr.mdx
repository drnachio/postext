# Ligne de commande

**`postext` compose votre livre depuis un terminal, un script ou un agent.**

Le [Sandbox](/fr/sandbox) est l’endroit où vous écrivez et mettez en page un
livre à l’œil. La ligne de commande prend le même livre et en produit les
fichiers sans navigateur : un PDF prêt pour l’impression, les pages en HTML, un
EPUB, l’image d’une page ou de toutes les pages, un document Word. Elle crée et
décompresse aussi les paquets `.postext`, importe des documents Word, décrit un
livre et y cherche des problèmes.

C’est **un exécutable autonome** par système. Le moteur postext, les
générateurs PDF, EPUB, HTML et Word, le moteur de peinture des pages (Skia),
HarfBuzz pour l’arabe et les autres écritures complexes, les profils ICC
d’impression et les polices par défaut (EB Garamond et Open Sans) sont tous à
l’intérieur. Il n’y a ni environnement d’exécution, ni paquet, ni bibliothèque à
installer, et la mise en page est celle du Sandbox : le même livre se coupe en
les mêmes pages.

## L’obtenir

Avec [Homebrew](https://brew.sh), sous macOS ou Linux :

```bash
brew install drnachio/postext/postext
```

Avec [Scoop](https://scoop.sh), sous Windows :

```powershell
scoop bucket add postext https://github.com/drnachio/scoop-postext
scoop install postext
```

Les deux installent l’exécutable de la dernière version comme commande
`postext`, vérifié avec sa somme de contrôle, et `brew upgrade postext` ou
`scoop update postext` apporte la suivante. Sans gestionnaire de paquets,
téléchargez vous-même le fichier.

Chaque version de Postext publie les exécutables sur sa
[GitHub Release](https://github.com/drnachio/postext/releases/latest), avec
leurs sommes de contrôle (`SHA256SUMS`) et un `readme.txt` :

Chaque fichier pèse entre 115 et 140 Mo. Le lien
`https://github.com/drnachio/postext/releases/latest/download/<file>` donne
toujours le plus récent.

Sous Linux ou macOS :

```bash
curl -fL -o postext https://github.com/drnachio/postext/releases/latest/download/postext-linux-x64
chmod +x postext
./postext
```

Placez-le dans un dossier de votre `PATH` (`/usr/local/bin`, `~/.local/bin`)
pour le lancer en tapant `postext` depuis n’importe où. macOS met en
quarantaine un fichier téléchargé avec un navigateur ; retirez l’indicateur une
fois pour toutes :

```bash
xattr -d com.apple.quarantine postext-macos-arm64
```

Sous Windows, dans PowerShell :

```powershell
Invoke-WebRequest https://github.com/drnachio/postext/releases/latest/download/postext-windows-x64.exe -OutFile postext.exe
.\postext.exe
```

Si Node.js est installé, `npx postext-cli` télécharge depuis npm l’exécutable
de votre système et le lance, et `npm install -g postext-cli` le garde comme
commande `postext`.

Lancé sans arguments, `postext` affiche son aide ; `postext help <command>`
liste les options d’une commande.

## Un premier livre

Trois fichiers Markdown dans un dossier forment un livre, d’un chapitre
chacun, dans l’ordre de leurs noms :

```bash
postext pdf chapters/ --name "Field notes" -o field-notes.pdf
```

L’en-tête YAML du premier chapitre donne au livre son titre et son auteur, et
les valeurs par défaut du moteur font le reste : deux colonnes, une grille de
ligne de base, un texte justifié avec césure, des titres courants. Ajoutez une
configuration et des images quand vous en avez besoin :

```bash
postext pdf chapters/ --config design.json --resources pictures/ -o field-notes.pdf
```

Un livre fait dans le Sandbox (**Livres → Exporter .postext**) fonctionne tel
quel :

```bash
postext pdf my-book.postext -o my-book.pdf
postext image my-book.postext --page 1 -o cover.png
```

## Ce que peut être un livre

Toute commande qui lit un livre accepte l’une de ces formes :

- **Un fichier `.postext`** : le paquet que le Sandbox exporte et ouvre (voir
  [Paquets](/fr/docs/configuration-bundles#paquets-fichiers-postext)).
- **Un dossier de livre** : un paquet décompressé, avec son `preset.json`, ses
  chapitres, ses ressources et ses polices. C’est ce que livre le skill pour
  agents, et `postext unpack` en écrit un.
- **Des fichiers Markdown isolés** : un ou plusieurs fichiers `.md`, un
  chapitre chacun dans l’ordre donné, ou un dossier dont les fichiers `.md`
  sont pris par ordre de nom (`01-intro.md`, `02-method.md`…). Avec eux :
  - `--config design.json` : la configuration, soit un objet de configuration
    seul, soit un `preset.json` complet ;
  - `--resources pictures/` : les images, chacune étant une figure nommée
    d’après son nom de fichier sans l’extension (`map.png` est
    `::resource{id="map"}`) ; un `resources.json` dans le dossier les décrit à
    la place (identifiants, types, légendes, texte de remplacement), sous la même forme
    que les `resources` d’un `preset.json` ;
  - `--fonts fonts/` : les fichiers de polices que fournit le livre (TTF, OTF,
    WOFF2), nommés d’après la famille qu’indiquent leurs tables ;
  - `--name "Title"` : le nom du livre.

`--config` fonctionne aussi sur un paquet ou un dossier : il est fusionné
par-dessus la configuration propre du livre. Un paquet multilingue est lu dans
sa propre langue, sauf si `--locale` en demande une autre (`--locale en`).

Chaque commande écrit dans le dossier d’où vous la lancez, sous le nom de
l’entrée, sauf si `-o` donne le chemin (`images` écrit dans `pages/`). `-o -`
écrit une sortie unique sur la sortie standard.

### pdf

```bash
postext pdf book.postext -o book.pdf
postext pdf book/ --pdfx x4 --profile fogra51 -o book-print.pdf
postext pdf book/ --color-space grayscale --no-outlines
```

Le PDF suit les réglages propres du livre (voir
[Génération du PDF](/fr/docs/configuration-fonts-colors-viewers#génération-pdf-configuration) et
[Production pour l’impression](/fr/docs/configuration-fonts-colors-viewers#production-pour-limpression-configuration)) ; ces options
les modifient le temps d’une exécution :

- `--pdfx none|x1a|x4` : la norme PDF/X pour un imprimeur.
- `--profile NAME|FILE` : le profil ICC de sortie, par son nom (`fogra39`,
  `fogra51`, `fogra52`, `swop5`, `gracol2006`, `snap2007`, `ifra26` et les
  autres profils des réglages d’impression) ou un fichier `.icc`.
- `--color-space rgb|cmyk|grayscale`.
- `--accessible` / `--no-accessible` : la structure balisée pour les lecteurs
  d’écran.
- `--no-outlines` : omettre les signets.
- `--page-negative` : des pages en négatif, pour certains flux d’impression.
- `--die-line page|none` : le tracé de découpe d’un livre avec des découpes, sur sa propre plaque
  (`page`, par défaut) ou omis (`none`) ; voir
  [Le tracé de découpe dans le PDF](/fr/docs/special-inks-die-cuts#le-tracé-de-découpe-dans-le-pdf).

### html

```bash
postext html book.postext -o book.html
postext html book.postext -o site/ --mode single
```

Un chemin qui finit par `.html` donne un seul fichier contenant les images et
les polices, facile à envoyer. Tout autre chemin est un dossier : `index.html`
à côté de `assets/`, qui contient les images, les polices et les vidéos
auto-hébergées. `--assets embed|folder` choisit l’une ou l’autre forme pour
n’importe quel chemin. Les pages sont la mise en page imprimée, montrée à la
taille de l’écran : côte à côte (`--mode multi`, par défaut) ou l’une sous
l’autre (`--mode single`). Les polices marquées `redistributable: false` sont
nommées mais pas copiées. Quand la famille indique un `fallback`, ce sont les fontes de cette famille libre qui sont écrites à sa place, sous le nom de la famille (depuis postext 1.43).

### epub

```bash
postext epub book.postext -o book.epub
postext epub book.postext --layout reflowable --cover cover.jpg
```

`--layout fixed` (par défaut) garde chaque page comme à l’impression, avec un
texte sélectionnable ; `--layout reflowable` laisse le système de lecture
recomposer le texte pour son écran (voir [Livres EPUB](/fr/docs/configuration-html-folio-epub#livres-epub-postext-epub)). La
couverture est la vignette du livre, sauf si `--cover` donne une image. Les
métadonnées du paquet EPUB (titre, auteurs, langue, identifiant) viennent du
l’en-tête YAML du premier chapitre, comme dans le Sandbox. Les polices marquées `redistributable: false` ne sont pas copiées ; une famille qui indique un `fallback` est incorporée avec les fontes de cette famille libre, sous son propre nom (depuis postext 1.43).

### image et images

```bash
postext image book.postext --page 12 -o page-12.png
postext image book.postext --page "#1" --dpi 300 -f jpeg -o cover.jpg
postext images book.postext -o pages/ --dpi 100
postext images book.postext --pages 1-10,iv -f webp --pattern "{chapter}-{label}"
```

Les pages se désignent **telles qu’elles sont imprimées** (`12`, `iv`, une
plage `7-9`) ou **par leur position** dans le livre avec `#` (`#1` est la
première page quel que soit son numéro imprimé, `#10-#20`, `#30-` jusqu’à la
fin). `--pages` accepte une liste séparée par des virgules. Le moteur de
peinture est celui de la vue Canvas du Sandbox : une image montre donc la page
exactement telle qu’elle a été mise en page, sans passer par un PDF.

- `--format png|jpeg|webp` (ou l’extension de `-o`), `--quality 1-100` pour le
  JPEG et le WebP.
- `--dpi` : la résolution, 150 par défaut ; 72–100 suffit pour lire une page,
  300 pour l’impression.
- `--pattern` : les noms de fichiers d’`images`, à partir de `{n}` (la
  position, `{n:03}` complétée à trois chiffres), `{label}` (le numéro
  imprimé) et `{chapter}` ; `page-{n:03}` par défaut.
- `--print-preview` : la page telle que l’imprimeur la reproduira, à travers le
  profil de sortie, avec le rognage et le fond perdu dessinés.
- `--jobs N` : le nombre d’images encodées en même temps (par défaut, autant
  que l’ordinateur a de processeurs).

### docx et import-docx

```bash
postext docx book.postext -o book.docx
postext docx book/ --variant semantic -o words.docx
postext docx book/ --variant facsimile -o pages.docx
postext import-docx book.docx book/ --dry-run
postext import-docx book.docx book/
postext import-docx manuscript.docx -o manuscript/ --locale es --report
```

`docx` écrit les documents Word qu’exporte le Sandbox (voir
[Sandbox › Documents Word](/fr/docs/sandbox-books-saving#documents-word)), et un
troisième. `--variant formatted`, la valeur par défaut, construit un document
modifiable à partir du Markdown, avec les titres, les listes, les notes de bas
de page, les tableaux, les équations et les sections propres à Word, composé
avec la maquette du livre autant que Word le permet et avec les polices du livre
incorporées (`--no-embed-fonts` se contente de les nommer) ; ce qui n’a pas de
structure dans Word voyage sous forme de source dans des contrôles de contenu
*Postext Source*. `--variant semantic` écrit le même texte en contenu seul : un
document simple (A4, une colonne, Arial) dans des styles Word qui disent ce
qu’est chaque partie, sans rien de la maquette de la page et sans polices
incorporées. Aucun des deux ne demande de mise en page ; tous deux s’ouvrent
dans Word et dans Google Docs, et tous deux reviennent par `import-docx`.
`--variant facsimile` met le livre en page comme `pdf` et écrit chaque page
comme une section Word, chaque ligne dans une zone de texte fixe, polices
incorporées : un fichier pour regarder la mise en page dans Word pour
ordinateur, pas pour corriger ni pour Google Docs. Une famille que le livre ne
peut pas transmettre (`redistributable: false` dans `customFonts`) est laissée
de côté et sa police de repli libre la remplace, comme dans l’EPUB ; une police
dont la licence interdit l’incorporation, une police à contours PostScript et
une police variable sont signalées et seulement nommées. Dans `build`,
`--docx FICHIER` écrit le même fichier, avec `--docx-variant` et
`--no-docx-fonts`. Depuis postext 1.68 ; `--template` ne s’applique plus à
`docx` ni à `build`.

Avec un livre après le fichier, `import-docx` rapporte les corrections faites
dans un document que `docx` a exporté depuis ce livre. Il lit la carte que
porte le fichier, compare le texte à la copie des chapitres faite à l’export et
fusionne chaque correction avec le livre tel qu’il est maintenant : les
fichiers de chapitre d’un dossier, d’un `.postext` ou de Markdown isolé, et le
texte des ressources (légendes, notes, texte alternatif, cellules de tableau)
dans `preset.json`, ou dans le `resources.json` de `--resources DIR` pour du
Markdown isolé. Pour un livre en plusieurs langues, `--locale` désigne
l’édition depuis laquelle le fichier a été exporté, et une correction du texte
d’une ressource va dans le bloc `localized` de cette édition. Chaque correction
est signalée sur sa propre ligne :

- `applied`, avec le fichier et la ligne où elle est allée ;
- `conflict` : le texte a aussi changé dans le livre depuis l’export, le
  chapitre ou la ressource n’existe plus, ou deux corrections se chevauchent ;
- `rejected` : du texte que produit le livre lui-même (numéros, étiquettes de
  légende, ce qu’un style de citation écrit à partir de la bibliographie) ou une
  mise en forme qui traverse le balisage Postext.

Une correction dans une citation y revient quand elle tombe dans une partie
que l’auteur a écrite : le localisateur, ou les mots avant ou après l’ouvrage.
Dans `[see also @simmons1991, 346–47]`, une plage de pages corrigée en `346–48`
dans Word devient `[see also @simmons1991, 346–48]`. La ligne nomme la citation
(`citation simmons1991: locator "7" → "8"`). Une modification du nom de
l’auteur, du titre ou d’*Ibid.* est refusée, et une partie imprimée autrement
qu’elle n’est écrite (`346--47` imprimé `346–47`) est refusée avec sa place
dans le livre, pour être changée là.

Les modifications suivies sont prises comme acceptées, et les commentaires sont
listés avec leur auteur et leur place, sans être écrits. Le code de sortie est
3 quand une correction n’a pas été appliquée. `--dry-run` (`-n`) affiche le
rapport et un diff unifié de chaque fichier qui changerait, et n’écrit rien.
Chaque fichier est écrit à côté de sa cible puis renommé par-dessus, si bien
qu’une exécution interrompue ne laisse jamais un demi-chapitre ; un fichier de
chapitre qui a changé pendant l’importation est laissé tel quel, avec un
avertissement `docx.fileChanged`. `-o` ne va pas avec un livre. Avec `--json`,
la réponse comporte `variant` (l’export qu’est le fichier : `formatted`,
`semantic` ou `facsimile`), `writer` (le générateur que nomment ses
propriétés), `exportId`, `edits` (chacune avec `status`, `reason`, `kind`,
`before`, `after` et `at`, et dans une citation `citation` et `citationPart`),
`comments`, `files` et, lors d’un essai à blanc, `diff`.

Un fichier modifié dans Google Docs et téléchargé en `.docx` revient aussi. Docs
n’y garde ni la carte ni la copie des chapitres ; l’importation réécrit la carte
à partir du livre, et le dit dans le rapport. Comme ce fichier ne porte aucune
copie du texte exporté, il est comparé au livre tel qu’il est maintenant. Si le
livre a changé depuis l’export, le rapport le signale, et un changement fait
entre-temps dans le livre peut apparaître comme une modification qui l’annule.
Importez un fichier Docs dans le livre dont il a été exporté, avant de changer
ce livre ; un fichier enregistré par Word garde sa carte et se fusionne avec les
changements ultérieurs du livre. Docs supprime aussi le signet masqué d’un texte
remplacé en entier (un titre, une cellule de tableau, une légende, le titre d’un
encadré, une note de bas de page). L’importation retrouve ce texte par sa place
entre ses voisins : un titre reste un titre et une légende va à sa ressource.
Quand cela ne peut pas être décidé, par exemple parce qu’un paragraphe a aussi
été tapé à côté et que rien ne les distingue, le rapport montre à la place une
suppression et un ajout. Importer le même fichier une seconde fois n’apporte
rien.

Sans livre, `import-docx` transforme n’importe quel document Word en nouveau
livre : un chapitre à chaque titre de niveau 1 (`--no-split` en garde un seul),
les images et les tableaux comme ressources, et `--report` affiche le rapport
de qualité que montre le Sandbox (styles utilisés, mise en forme directe,
numérotation tapée à la main…). `--template` accepte un modèle d’importation
(un `.json` enregistré depuis le Sandbox ou un `.docx` qui en contient un).

L’espacement des caractères appartient au style, pas au texte : il n’est donc pas dans le
Markdown. `docx` écrit le `letterSpacing` des styles de paragraphe, des styles de titre
et des niveaux de titre comme espacement des caractères du style Word, et `import-docx`
le relit en em de la taille du style : il le pose en `letterSpacing` sur les styles du livre
qui n’en ont aucun (les styles de paragraphe et de titre du fichier `--config` auxquels
correspondent les styles Word, et les niveaux de titre), et laisse tel quel tout espacement
que le livre définit déjà. Avec `--json`, `styleTracking` énumère ce qui a été posé (`applied`)
et ce qui a été laissé (`skipped`). Depuis postext 1.39.

### idml

```bash
postext idml book/ -o book.idml
postext idml book.postext -o book.idml --images link
postext idml book/ -o out/book.idml --lines reflow --fonts
```

`idml` met le livre en page comme `pdf` et écrit les pages en paquet InDesign
Markup, à finir dans InDesign : les pages en planches de part et d’autre du
dos pour un livre aux marges de pages en regard (une page par planche pour
tout autre), filets, encadrés, tracés et images comme objets de page, les
tableaux comme tableaux InDesign, le texte de chaque bloc d’une page composée
comme un bloc de texte avec son propre article (les blocs chaînés par `next`
en partagent un), les styles d’encadré comme styles de paragraphe et les
couleurs CMJN définies par l’auteur comme nuances. Les pastilles qui portent
un champ de formulaire deviennent des champs de formulaire InDesign. `--lines
keep` (par défaut) finit chaque ligne là où Postext l’a finie, si bien
qu’InDesign affiche les mêmes lignes que le PDF ; `--lines reflow` laisse les
paragraphes au compositeur d’InDesign, et les fins de ligne peuvent changer.
Le texte courant des pages composées en colonnes court dans un seul article, chaîné à travers un bloc par colonne, que l’import relit comme un livre à flux ; `--text frames` écrit à la place un bloc et un article par élément (depuis postext 1.85.0). `--spreads facing` ou `--spreads single` groupe les pages par deux, ou non,
quelles que soient les marges.
`--images link` place les images à côté du fichier, dans `Links/`, au lieu de
les y inclure. `--fonts` écrit les fichiers de police des variantes utilisées
à côté du paquet, dans `Document fonts/`, où InDesign les trouve pour ce
document ; il faut que `-o` nomme un fichier, et une famille que le livre ne
peut pas redistribuer est laissée de côté, avec un avertissement. Ce que le
paquet ne peut pas porter tel que le livre l’a (les points d’emphase du texte vertical, le cadre
arrondi d’un tableau) est signalé par un avertissement `idml.*`. Le générateur
est le paquet `postext-idml` : voir [Utilisation programmatique › Paquets
InDesign](/fr/docs/configuration-programmatic-usage#paquets-indesign-postext-idml).
Dans `build`, `--idml FICHIER` écrit le même paquet, avec `--idml-images`, `--idml-lines`, `--idml-spreads`, `--idml-text` et `--idml-fonts`.
Depuis postext 1.71 ; `--lines` et `--fonts` depuis 1.76, `--spreads` depuis 1.78.

### import-idml

```bash
postext import-idml book.idml -o book/
postext import-idml book.idml -o book.postext --layout flow --links pictures/
postext import-idml book.idml --report --json
postext import-idml package.zip -o book.postext
postext import-idml package.zip --document Book/Book.idml -o book/
```

`import-idml` lit un paquet InDesign Markup et écrit un nouveau livre, dans un dossier ou dans un `.postext` : les chapitres en Markdown, la configuration que donnent les styles et les pages du document, et ses images et tableaux comme ressources. Un `.indd` n’est pas lu : enregistrez-le d’abord depuis InDesign au format InDesign Markup. `--layout pages` suit le document page par page avec des pages composées, chaque bloc là où il était ; `--layout flow` écrit un livre de texte courant, dans l’ordre de lecture et sous les styles du document, que Postext met de nouveau en page ; `auto` (par défaut) choisit l’un des deux et dit pourquoi. Le fichier peut aussi être un assemblage InDesign compressé, le dossier que crée **Fichier › Assembler** avec l’IDML ajouté (**Include IDML** dans l’InDesign anglais), envoyé en un seul `.zip` : la commande en importe l’IDML avec les images de son dossier `Links/` et met dans le livre les fichiers de police de son dossier `Document fonts/`. Quand le zip contient plusieurs documents IDML, `--document` nomme celui à importer par son chemin dans le zip (`--document Book/Book.idml`) ; sans cette option, la commande les liste. Un assemblage qui ne contient que le `.indd` est refusé, avec la manière d’obtenir l’IDML. Les images liées sont lues d’abord dans `--links`, puis dans l’assemblage, puis dans le dossier du fichier et dans son `Links/`, et celles qui manquent sont listées. Les polices que nomme le document sont listées aussi : un `.idml` seul ne contient aucun fichier de police, il faut donc les donner avec `--font-dir` quand le livre est généré. Avec un assemblage, une police trouvée dans `--font-dir` entre dans le livre à la place du fichier de l’assemblage. Une collection de polices (`.ttc`, `.otc`), dans l’assemblage ou dans `--font-dir`, est séparée en styles isolés, et seuls les styles que le livre utilise y entrent (depuis postext 1.83).

Un livre exporté depuis Postext revient avec les mêmes lignes. Un document fait dans InDesign est lu avec des pertes : la commande affiche le verdict (`faithful`, `approximate` ou `lossy`), les décomptes et ce qui a été perdu ou approché ; `--report` ajoute les notes et la façon dont chaque style de paragraphe a été lu, et `--json` porte le tout comme données. `--hidden`, `--pasteboard` et `--non-printing` lisent aussi les calques et les objets masqués, la table de montage et les objets non imprimables ; `--conditions all` lit tout le texte conditionnel, `--changes reject` lit les modifications suivies comme refusées et `--no-masters` laisse de côté les éléments des gabarits. `--name` et `--locale` donnent le titre et la langue. L’importateur est `idmlToPostext`, du paquet `postext-idml` : voir [Utilisation programmatique › Paquets InDesign](/fr/docs/configuration-programmatic-usage#paquets-indesign-postext-idml). L’import copie le document tel qu’il est ; pour porter un livre que vous garderez, avec ses règles de mise en page dégagées, utilisez plutôt le skill pour agents (voir [InDesign : import, export et portage](/fr/docs/indesign)).

### design

```bash
postext design book.postext -o novel.postext
postext design book/ --parts page,text,headings -o type.postext
postext pdf other/ --design novel.postext -o other.pdf
```

Un fichier de maquette garde la maquette d’un livre et rien de son texte : les réglages des parties demandées (les groupes du panneau Maquette, voir [Fichiers de maquette](/fr/docs/configuration-bundles#fichiers-de-maquette)) avec les fichiers de police et le profil de couleur qu’ils nomment. Une police marquée comme non redistribuable reste derrière. `--parts` ne prend que certaines parties, séparées par des virgules ; `--design-name`, `--id` et `--description` nomment la maquette. Le même livre donne toujours les mêmes octets.

`--design FICHIER`, une option de toutes les commandes qui lisent un livre, met le livre dans un fichier de maquette ou dans la maquette d’un autre livre, avant `--config` et `--set` : les réglages de ses parties remplacent ceux du livre, les styles nommés se fusionnent par identifiant et les polices de la maquette s’ajoutent à celles du livre. `--design-parts` n’en prend que certaines parties. Le panneau Maquette du Sandbox importe et exporte les mêmes fichiers.

`--composition ÉTIQUETTE`, également une option de toutes les commandes qui lisent un livre, applique les règles de composition de la tradition d’une langue après `--design` (depuis postext 1.80) : `es`, `en-US` (ou `en`), `en-GB`, `fr` ou `de`, ou `auto` pour la langue du livre. Les règles de la convention remplacent celles du livre et les autres reviennent à leurs valeurs par défaut ; la typographie reste telle quelle. Voir [Conventions de composition](/fr/docs/configuration-text#conventions-de-composition).

```bash
postext pdf book/ --composition auto -o book.pdf
postext design book/ --composition es --parts composition -o house-rules.postext
```

### pack et unpack

```bash
postext pack my-book/ -o my-book.postext
postext pack 01.md 02.md --name "Notes" --config design.json --resources img/ -o notes.postext
postext unpack my-book.postext -o my-book/
```

`pack` compresse un dossier de livre tel quel, ou construit un paquet à partir
de fichiers Markdown isolés. La même entrée donne toujours les mêmes octets :
un paquet peut donc être comparé ou haché. Pour des fichiers Markdown isolés,
`--id`, `--description` et `--thumbnail FILE` (une image de couverture)
fixent l’identifiant, la description et la vignette du paquet ; l’identifiant
est par défaut une version simplifiée du nom (un slug). Un dossier garde ce
qu’indique son `preset.json`. Un livre qui n’indique aucune couverture reçoit sa première page comme couverture (`thumbnail.jpg`, 1024 px sur le grand côté), l’image qu’un gestionnaire de fichiers peut afficher pour le fichier ; `--no-auto-thumbnail` l’omet. `unpack` refuse d’écrire dans un
dossier qui n’est pas vide, sauf avec `--force`.

### info et check

```bash
postext info book.postext --pages
postext check book.postext
postext check chapters/ --strict --json
```

`info` liste les chapitres (titre, mots, fichier et, avec `--pages`, leurs
pages), les ressources et chaque famille de polices avec sa provenance (le
livre, un dossier, l’exécutable, le cache de téléchargement ou la police de
secours). Pour un livre qui indique où il commence (`start` dans `preset.json` : un extrait qui s’ouvre à la page 58, dans le chapitre 4), il l’affiche aussi, et chaque commande met le livre en page à partir de là.

`check` met le livre en page et signale ce que montre le panneau Vérifications
du Sandbox : du Markdown qui ne se ferme pas, des ressources, des directives et
des styles inconnus, des encadrés que la mise en page a dû forcer, des polices
manquantes, des réglages que le moteur a dû remplacer et, pour un livre préparé
pour l’impression (ou avec `--preflight`), le contrôle en amont : images de
basse résolution, filets trop fins, petit texte en plusieurs encres, encrage
au-delà de la limite, texte trop près du rognage. Il liste aussi le texte qui
ne se lit pas sur son fond (`contrast`), une fois par paire de couleurs, avec le
rapport à l’écran et, pour l’impression, sur le papier du profil de sortie.
Chaque problème indique le fichier du chapitre, la ligne et la page. Le code de sortie est 3 quand une erreur est trouvée, ou n’importe quel avertissement
avec `--strict`.

Il signale aussi les textes de maquette de la configuration qui gardent le
texte du livre au lieu de variables (`contentInConfig`), une fois par style de
titre, titre courant ou maquette de partie, avec le chemin de chaque texte :
déplacez ce texte dans le Markdown, ou ajoutez le titre ou le nom de l’éditeur
à `checks.contentInConfig.allow`.

Pour un livre à gabarits de page, `check` signale aussi le texte qui ne tient pas dans son bloc (`frameOverflow`, avec les étapes d’ajustement essayées et les changements qui le feraient tenir), un article qui dépasse les pages qu’un bloc peut ajouter (`frameContinuationLimit`), un renvoi vers une page qui ne suit pas (`continueTargetMissing`), les étiquettes de figure qui ne peuvent pas être dessinées ou qui se heurtent (`labelAnchorUnknown`, `anchorUnlabelled`, `labelOverflow`, `labelOverlap`), les blocs cachés sous d’autres blocs ou qui dépassent leur limite (`frameCovered`, `frameOutsideArea`), une grille qui reçoit plus de cartes qu’elle n’en contient (`repeatOverflow`) et les modules qu’une page ne peut pas placer (`moduleUnknown`, `moduleAsPage`, `moduleNested`, `moduleNameRejected`). Après les avertissements, il imprime une ligne `reflow` par page composée qui a des événements, et `--json` fournit les étapes, les propositions et le journal de recomposition comme données. Voir [Pages composées › Avertissements](/fr/docs/composed-pages#avertissements) et [Journal de recomposition](/fr/docs/composed-pages#journal-de-recomposition).

### build et --watch

```bash
postext build book/ --pdf out/book.pdf --html out/book.html --images out/pages --pages 1-4
postext build chapters/ --pdf book.pdf --watch
```

`build` met le livre en page une fois et écrit chaque sortie que vous indiquez
(`--pdf`, `--html`, `--epub`, `--images`, `--docx`, `--idml`), avec les options de chaque
commande. `--watch` reste actif : quand un chapitre, la configuration ou une
image change, le livre est remis en page avec les polices et le moteur toujours
chargés, en général en une fraction de seconde pour un chapitre, et les sorties
sont réécrites. Un enregistrement qui casse le livre affiche l’erreur et garde
les derniers fichiers valides.

## Polices

Un livre qui contient ses polices (un paquet, ou `--fonts` avec des fichiers
Markdown isolés) est composé avec elles et rien d’autre. Pour chaque famille
qu’indique la configuration et que le livre ne contient pas, `postext` cherche,
dans l’ordre :

1. dans les dossiers donnés avec `--font-dir` ;
2. parmi les caractères compilés dans l’exécutable : EB Garamond et Open Sans,
   les valeurs par défaut du moteur ;
3. dans le cache de téléchargement ;
4. sur [Google Fonts](https://fonts.google.com), qui fournit des fichiers
   TrueType statiques complets, ou sur [Fontsource](https://fontsource.org)
   pour une famille que Google Fonts n’a pas (Commit Mono, FiraGO) ; ils sont
   conservés dans le cache, de sorte qu’une famille n’est téléchargée qu’une
   fois.

Une graisse qu’une famille ne fournit pas est composée dans le caractère qu’un
navigateur choisirait à sa place (correspondance des polices CSS : les plus
grasses d’abord au-dessus de 500, les plus maigres d’abord en dessous de 400 ;
une graisse 600 d’une famille qui a un 400 et un 700 est donc son 700, tout
comme une graisse 550), et une inclinaison qu’elle ne fournit pas dans son
romain, chacun tel quel, dans les images de pages comme dans le PDF : un
caractère de titrage à une seule graisse garde ses propres lettres pour un
gras, et une famille droite pour un italique.

Les graisses qu’indique la configuration sont celles qui sont récupérées : le
normal, le gras et leurs italiques pour chaque famille, et toute autre graisse
qu’un réglage indique, y compris celle du gras (`bodyText.boldFontWeight: 600`
demande le caractère 600). Quand une graisse que la famille fournit n’a pas pu
être chargée (hors ligne sans fichier en cache, un téléchargement qui a échoué,
un dossier de polices sans le fichier), le texte est composé dans le caractère
de la famille qui le remplace selon la même règle, et `postext check` le liste
comme avertissement `fontFallback` : ses lignes peuvent se couper autrement que dans le Sandbox.

Un caractère pour lequel une police n’a pas de glyphe est dessiné avec une autre police. `postext check` lit la table `cmap` de chaque police qu’il charge et liste ces caractères une fois par police pour tout le livre, en avertissement `glyphFallback` ; avec `--json`, son `data` porte les caractères et leur nombre.

Le cache est `~/.cache/postext` (`%LOCALAPPDATA%\postext\cache` sous
Windows) ; `POSTEXT_CACHE_DIR` ou `--cache-dir` le déplace. `--offline` saute
le téléchargement. Une famille introuvable est composée en EB Garamond sous son
propre nom, pour que la mise en page et le PDF restent d’accord, et un
avertissement `missingFont` la signale. `postext info` indique d’où vient chaque
famille.

Un paquet qui laisse de côté les fichiers d’une famille sous licence peut lui associer une famille libre de chasse proche (`fallback` dans les `fonts` du manifeste, depuis postext 1.42). `postext` cherche alors cette famille par les étapes ci-dessus et compose les fontes que le livre n’incorpore pas avec les fontes de même graisse et de même inclinaison de cette famille, sous le nom de la famille sous licence : la mise en page ressemble à celle obtenue avec les fichiers et `postext check` ne signale aucun `missingFont` pour elle. Une famille que le livre n’incorpore qu’en partie ne prend au `fallback` que l’inclinaison dont elle n’a aucun fichier. Le PDF incorpore la fonte libre.

## Pour les scripts et les agents

La ligne de commande est conçue pour être pilotée par d’autres programmes, y
compris des agents de programmation.

- **`--json`** affiche un objet JSON sur la sortie standard à la fin de la
  commande ; tous les messages vont sur la sortie d’erreur. Le rapport liste ce
  qui a été écrit, les pages, chaque avertissement avec sa source et la durée
  de chaque étape (en millisecondes) :

```json
{
  "ok": true,
  "command": "pdf",
  "version": "1.22.1",
  "book": { "name": "notes", "id": "notes", "locale": "en", "chapters": 2 },
  "pages": 3,
  "outputs": [{ "kind": "pdf", "path": "notes.pdf", "bytes": 29746, "pages": 3 }],
  "warnings": [
    {
      "kind": "unknownResourceId",
      "severity": "warning",
      "message": "Unknown resource id \"map\" in ::resource — nothing is embedded (offset 26)",
      "at": "notes/02-more.md:5"
    }
  ],
  "timings": { "read": 13, "fonts": 8.4, "math": 28.2, "layout": 51.6, "pdf": 132.1, "total": 1638 },
  "exitCode": 0
}
```

- **Codes de sortie** : `0` terminé, `1` échec, `2` mauvaise utilisation (une
  option inconnue, une entrée manquante), `3` `check` a trouvé des erreurs (ou
  des avertissements avec `--strict`), ou `import-docx` a laissé de côté une correction Word.
- **Aucune question.** Il n’attend jamais de saisie ; un dossier qui n’est pas
  vide est refusé au lieu de donner lieu à une question.
- **Sortie standard** : `-o -` y écrit un PDF, une image ou un paquet, à
  transmettre par un tube.
- **Vitesse.** L’exécutable démarre en quelques centièmes de seconde. Un livre
  court devient un PDF ou une image de page en bien moins d’une seconde ; un
  long prend le temps que prend sa mise en page (un roman illustré de
  140 pages, une dizaine de secondes). Pour regarder quelques pages d’un long
  livre, combinez `--chapters` avec `image` ou `images --pages`. Pour
  travailler sur un livre au fil de nombreuses modifications, laissez tourner
  `postext build --watch` et lisez ses sorties.

Le [skill pour agents](/fr/docs/skill) utilise la ligne de commande pour rendre
les pages sur lesquelles il travaille et pour vérifier un portage.

## Python

`pip install postext` fait de la ligne de commande une bibliothèque Python. Le
paquet est en Python pur, sans dépendances, et sa version est celle de
postext. La première fois qu’il lance une commande, il télécharge l’exécutable
de votre système depuis la GitHub Release de cette version, le vérifie avec
`SHA256SUMS` et le garde dans le cache décrit plus haut, sous
`bin/<version>/`. Si `POSTEXT_BIN` désigne un exécutable que vous avez déjà
(Homebrew, Scoop ou votre propre compilation), rien n’est téléchargé.

```python
import postext

report = postext.pdf("book.postext", out="book.pdf", set={"page.dpi": 300}, locale="es")
print(report.output.pages)
for warning in report.warnings:
    print(warning.kind, warning.at, warning.message)

pdf = postext.pdf_bytes(open("book.postext", "rb").read())
```

- **Une fonction par commande** : `pdf`, `html`, `epub`, `image`, `images`,
  `docx`, `idml`, `import_docx`, `import_idml`, `design`, `pack`, `unpack`,
  `info`, `check` et `build`. Les options gardent leur nom, avec des tirets bas
  (`color_space`, `font_dirs`, `dry_run`). `set` prend un dictionnaire,
  `config` un fichier ou un dictionnaire, `chapters` un nombre, une liste, un
  `range` ou `"1,3-5"`. Toute fonction qui lit un livre accepte `design=`, un
  fichier de maquette en chemin ou en octets, `design_parts=`, une liste ou
  `"page,text"`, et `composition=`, une étiquette de langue ou `"auto"`.
- **Des rapports en objets.** Chaque fonction lance sa commande avec `--json`
  et renvoie le rapport : `outputs`, `pages`, `timings` et `warnings`, chaque
  avertissement étant un `Diagnostic` avec `kind`, `severity`, `message`, `at`
  et `page`. `info` y ajoute `chapters`, `resources` et `fonts` ; `check`,
  `passed`, `error_count` et `warning_count` ; `design`, `name` et `parts` ;
  `import_idml`, `layout`, `reason`, `chapters`, `quality`, `fonts`,
  `missing_links` et `package`.
- **Des erreurs en exceptions.** Un échec lève `PostextError`, une option
  erronée `UsageError`. Quand `check` trouve des erreurs, il lève
  `ProblemsFound`, dont le `report` les énumère ; avec
  `raise_on_problems=False`, il renvoie le rapport.
- **Des octets.** Un livre peut être donné sous forme des octets d’un paquet
  `.postext`. Avec `out="-"`, le fichier revient dans `report.content` ;
  `pdf_bytes`, `html_bytes`, `epub_bytes`, `image_bytes`, `docx_bytes`,
  `idml_bytes`, `pack_bytes` et `design_bytes` le renvoient directement.
- `postext.Postext(binary, cwd=…, timeout=…)` utilise un exécutable donné, et
  `python -m postext …` est la ligne de commande elle-même.

Chaque appel relance l’exécutable. Le [README](https://github.com/drnachio/postext/tree/main/packages/postext-python) du paquet
liste toutes les options.

## Comment elle est faite

La ligne de commande est le paquet `postext-cli` du
[dépôt](https://github.com/drnachio/postext/tree/main/packages/postext-cli).
[Bun](https://bun.sh) le compile, avec le moteur et ses générateurs, en un
exécutable par système, et [Skia](https://skia.org) (via `@napi-rs/canvas`)
mesure et peint le texte, comme le fait le canvas du navigateur dans le Sandbox. Une image SVG qui contient une image matricielle (un PNG ou un JPEG incorporé en URI de données, comme l’écrit `pdftocairo -svg` pour un dessin découpé dans un PDF) est dessinée par [resvg](https://github.com/linebender/resvg) à la place, parce que le moteur de rendu SVG de Skia omet ces images. À
chaque version, les exécutables sont construits, lancés sous Linux, Alpine,
macOS et Windows, et joints à la GitHub Release ; npm reçoit `postext-cli` et
un paquet `postext-cli-<system>` par exécutable.

Pour le lancer depuis une copie du dépôt :

```bash
pnpm install
pnpm --filter postext-cli start pdf book.postext
pnpm --filter postext-cli build:bin --current
```

La première commande le lance depuis ses sources ; la seconde écrit
l’exécutable de cet ordinateur dans `packages/postext-cli/bin/`.

## Différences avec le Sandbox

- **Le HTML** est la mise en page imprimée montrée à la taille de l’écran.
  L’onglet HTML du Sandbox recompose le texte pour la fenêtre.
- **`--chapters`** met en page les chapitres isolément : leur numérotation des
  pages recommence, là où le Sandbox poursuit la numérotation du livre.
- **Les polices** viennent du livre, de vos dossiers, de l’exécutable, de
  Google Fonts ou de Fontsource (pour une famille que Google Fonts n’a pas),
  jamais des polices installées sur l’ordinateur : un livre sort donc
  identique sur toutes les machines.
- **La langue du texte** est celle du document dans un navigateur
  (`bodyText.shapingLanguage: 'document'`, la valeur par défaut depuis
  postext 1.30). Le canvas de Skia accepte une langue mais met en forme sans en
  tenir compte : la ligne de commande mesure donc les formes de la langue par
  défaut de chaque police et met toujours ses livres en page avec
  `shapingLanguage: 'host'`, quoi que dise la configuration ; son PDF et ses
  images peignent ces mêmes formes. Un livre dont le caractère a des formes
  pour une langue (un `l·l` catalan, un `fi` turc, les chiffres d’un caractère
  chinois dans un livre anglais) est composé ici avec les formes par défaut. Ce
  que `'document'` mesure autrement (les parties d’un mot coupé en fin de
  ligne, un mot de droite à gauche, un texte de maquette) est mesuré ici comme
  le mesure `'host'` : une ligne peut donc se couper sur un autre mot que dans
  le Sandbox.
