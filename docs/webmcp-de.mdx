# WebMCP

**Ein Agent in Ihrem Browser arbeitet an dem Buch, das in der Sandbox geöffnet ist: Er sieht sich die Seiten an, ändert sie und sieht wieder hin.**

Die [Sandbox](/de/docs/sandbox) gibt einem Agenten eigene Werkzeuge über
[WebMCP](https://webmachinelearning.github.io/webmcp/), einen Entwurf für einen
Webstandard, mit dem eine Seite dem KI-Modell, mit dem der Browser spricht,
Werkzeuge übergeben kann. Damit klickt sich der Agent nicht durch die
Oberfläche: Er liest das Buch, fordert ein Bild von Seite 12 an, setzt
`bodyText.fontSize` auf 10,5 pt, sieht, dass das Kapitel von 18 auf 19 Seiten
gewachsen ist, und nimmt die Änderung zurück. Er tut, was Sie mit dem Auge tun,
und er tut es mit Ihrem Buch, in Ihrem Browser.

Solange die Sandbox auf dem Bildschirm ist, sind 53 Werkzeuge registriert,
deren Namen mit `sandbox_` beginnen; dazu kommen auf jeder Seite von
postext.dev 8 Werkzeuge der Website, `site_*`. Diese Seite ordnet sie nach den
Aufgaben, die Sie einem Agenten stellen würden, und zeigt für jedes den Aufruf.

## Einen Agenten verbinden

### In einem Browser mit WebMCP

Die Werkzeuge werden bei `document.modelContext` registriert, wenn die Sandbox
geladen wird, und wieder zurückgenommen, wenn Sie sie verlassen. Ein Agent, dem
der Browser Seitenwerkzeuge übergibt, findet sie dort. Auf der Seite von
Postext muss nichts installiert oder eingerichtet werden.

WebMCP ist noch ein Entwurf. Chrome bietet es als Origin Trial an, außerdem hinter
dem Flag `chrome://flags/#enable-webmcp-testing`. Die Werkzeuge folgen der
Seite: Auf der Startseite oder in der Dokumentation hat der Agent die
Werkzeuge `site_*`; sobald die Sandbox auf dem Bildschirm ist, kommen die 53
Werkzeuge `sandbox_*` hinzu.

### In jedem anderen Browser: `window.postextWebMcp`

Die Seite legt dieselben Werkzeuge außerdem auf `window.postextWebMcp` ab, mit
oder ohne WebMCP. Jeder Agent, der Skripte in der Seite ausführen kann, kann
sie nutzen: ein Automatisierungswerkzeug wie Puppeteer oder Playwright, ein
MCP-Server, der den Browser steuert und Skripte auswertet (Chrome DevTools
MCP), eine Browsererweiterung oder Sie selbst in der Entwicklerkonsole:

```js
// What is on this page
postextWebMcp.listTools().map((t) => t.name);

// Run one tool: the name, then an object with its arguments
await postextWebMcp.executeTool('sandbox_get_state', {});
await postextWebMcp.executeTool('sandbox_set_config', {
  changes: [{ path: 'bodyText.fontSize', value: '10.5pt' }],
});
```

Dasselbe aus einem Puppeteer-Skript, das eine Seite als Bild speichert:

```js
import fs from 'node:fs';
import puppeteer from 'puppeteer';

const browser = await puppeteer.launch();
const page = await browser.newPage();
await page.goto('https://postext.dev/en/sandbox');
await page.waitForFunction(() => window.postextWebMcp?.listTools().some((t) => t.name === 'sandbox_get_state'));
await page.waitForFunction(async () => (await window.postextWebMcp.executeTool('sandbox_get_state', {})).ready);

const result = await page.evaluate(() =>
  window.postextWebMcp.executeTool('sandbox_render_page', { chapter: 1, position: 1, width: 1200, format: 'png' }),
);
const picture = result.content.find((part) => part.type === 'image');
fs.writeFileSync('page-1.png', Buffer.from(picture.data, 'base64'));
await browser.close();
```

Ein frisches Browserprofil hat seinen eigenen Speicher und beginnt daher mit
den Beispielen, nicht mit Ihren Projekten. Um an Ihren eigenen Büchern zu
arbeiten, verwenden Sie den Browser, in dem Sie sie angelegt haben.

### Wie jede Antwort aussieht

Ein Werkzeug antwortet mit einem JSON-Objekt: `ok: true` und dem, was
angefragt wurde, oder `ok: false` und einem `error`, der sagt, was falsch war
und was stattdessen anzufragen ist:

```json
{
  "ok": false,
  "error": "bodyText.fontSize is a length: give { \"value\": 11, \"unit\": \"pt\" }, a number (in pt) or a text such as \"11pt\". The units: cm, mm, in, pt, px, em, rem."
}
```

Die Argumente werden gegen das Schema des Werkzeugs geprüft, bevor irgendetwas
läuft, sodass ein falsch geschriebener Parameter mit der Liste der richtigen
abgewiesen wird. Ein Werkzeug, das Bilder zurückgibt (`sandbox_render_page`),
antwortet im MCP-Format, `{ content: [...] }`: ein Textteil mit JSON,
das die Seiten beschreibt, dann ein Bildteil je Seite, base64-kodiert.

## Der Arbeitszyklus

Jedes Werkzeug, das das Buch ändert, wartet mit seiner Antwort, bis das Layout
nachgezogen hat, und nennt, wie viele Seiten jedes Kapitel nun hat. Der nächste Blick
gilt also immer den neuen Seiten, und der Agent kann arbeiten wie ein
Gestalter:

1. **Den Stand erfassen**: `sandbox_get_state` liefert das Buch, seine
   Kapitel mit ihren Seiten, das Kapitel und die Seite auf dem Bildschirm und
   das geöffnete Bedienfeld.
2. **Hinsehen**: `sandbox_render_page` zeichnet eine Seite,
   `sandbox_inspect_pages` beschreibt sie als Daten, `sandbox_get_warnings`
   listet auf, was die Prüfungen gefunden haben.
3. **Ändern**: `sandbox_set_config`, `sandbox_edit_text`,
   `sandbox_save_resource` …
4. **Erneut hinsehen** und die Änderung behalten oder zurücknehmen.

Eine Seite wird für das Werkzeug gesetzt und gezeichnet, gleich welcher
Betrachter auf dem Bildschirm ist; der Agent kann sich also Kapitel 7 ansehen,
während Sie Kapitel 2 lesen.

## Was Sie verlangen können und wie es geht

### Herausfinden, was geöffnet ist

```jsonc
// sandbox_get_state
{}
```

```json
{
  "ok": true,
  "ready": true,
  "book": { "kind": "sample", "id": "postext-guide", "name": "Postext guide" },
  "pages": 3,
  "chapters": [
    { "chapter": 1, "id": "a", "title": "Opening", "onScreen": true, "words": 1007, "pages": 2 },
    { "chapter": 2, "id": "b", "title": "Second", "words": 101, "pages": 1 }
  ],
  "view": { "viewer": "canvas", "panel": "none", "scope": "chapter", "chapter": 1 },
  "resources": 0,
  "warnings": 0
}
```

Zu `ready: false` gehört `waitingFor`, das den Grund nennt (ein Buch, das noch
lädt). `question` und `notice` erscheinen, wenn die Sandbox auf Sie wartet;
siehe [Rückfragen und Hinweise](#rückfragen-und-hinweise).

Jedes Werkzeug, das ein `chapter` annimmt, akzeptiert seine Position im Buch
(ab 1), seinen Titel oder seine ID. Fehlt die Angabe, gilt das Kapitel auf
dem Bildschirm.

### Eine Seite ansehen

**Ein Bild.** „Zeig mir den Anfang von Kapitel 3“, „wie sieht die Doppelseite
24/25 aus?“:

```jsonc
// sandbox_render_page: a spread, 1200 px wide per page
{ "chapter": 3, "page": 24, "count": 2, "width": 1200 }
```

`page` ist die Seitenzahl, die auf der Seite steht; `position` ist der Platz
der Seite unter den Seiten des Kapitels (ab 1), für Seiten ohne Pagina. Fehlen
beide, gilt die Seite auf dem Bildschirm. `crop` vergrößert einen Teil der
Seite, angegeben in Bruchteilen ihrer Breite und Höhe ab der linken oberen
Ecke, um Schrift und Abstände aus der Nähe zu beurteilen:

```jsonc
// sandbox_render_page: the bottom right quarter, magnified
{ "chapter": 3, "page": 24, "crop": { "x": 0.5, "y": 0.5, "width": 0.5, "height": 0.5 }, "width": 1600 }
```

`printPreview: true` zeichnet den Softproof des Druckprofils mit den
Hilfslinien für Endformat, Anschnitt und Sicherheitsbereich; `trimmed: true` lässt
den Rand mit den Schnittmarken weg.

**Dieselbe Seite als Daten.** „Welche Zeilen auf dieser Seite sind zu locker?“,
„ist die zweite Spalte voll?“:

```jsonc
// sandbox_inspect_pages: without a page, one line per page of the chapter
{ "chapter": 1 }
```

```json
{
  "chapter": 1, "title": "Opening", "chapterPages": 2, "converged": true,
  "pages": [
    { "position": 1, "label": "1", "role": "opener", "blank": false, "lines": 45, "figures": 0, "starts": "Opening" },
    { "position": 2, "label": "2", "role": "body", "blank": false, "lines": 37, "figures": 0, "starts": "decades. Print typography spent five centuries…" }
  ]
}
```

Mit `page` oder `position` listet es jeden Block der Seite auf: seinen Typ,
seine Spalte, seinen Text, die Zahl seiner Zeilen, die Zeilen, die mit einem
Trennstrich enden, und die zu lockeren Blocksatzzeilen mit der Breite ihrer
Wortzwischenräume, sein umschließendes Rechteck auf der Seite, dazu, wie voll jede Spalte ist
(`fill: 0.99`).

**Was an einem Punkt steht.** Sieht der Agent etwas auf einem Bild, fragt er
mit denselben Bruchteilen wie beim Ausschnitt, was es ist:

```jsonc
// sandbox_inspect_point
{ "chapter": 3, "page": 24, "x": 0.71, "y": 0.42 }
```

Die Antwort nennt den Block, die Zeile und Spalte der Markdown-Quelle an dieser
Stelle (und das Wort), einen Link und die Seite, auf die er führt, die
Tabellenzelle oder Legende einer Ressource. Mit `select: true` tut sie
außerdem, was ein Klick tut: Das Bedienfeld Text öffnet sich mit der
Einfügemarke an dieser Stelle (`word: true` wählt das Wort aus, `to` wählt bis
zu einem zweiten Punkt aus).

Die Antwort enthält außerdem `elements`: was an dem Punkt liegt, von innen nach außen, in der Reihenfolge, in der ein Klick auf der Seite sie auswählt und jeder weitere Klick oder Esc eine Ebene nach außen geht (ein Zeichen, sein Absatz, der Kasten darum, der Rahmen einer zusammengesetzten Seite, seine Gruppe, die Seite und ihre Vorlage; oder ein Gestaltungselement und sein Gestaltungsfeld). Jedes Element bringt seine stabile ID mit, seine Quelle (ein Bereich des Markdowns, ein Konfigurationspfad, ein Attribut, eine Ressource) und seinen Namen im Pfad, den die Sandbox zeigt (`path`). Mit `select: true` wählt `level` (`block`, `frame`, `template`, `design` …) eines davon so aus, wie es ein Mensch täte: Im Modus Inhalt wird sein Markdown ausgewählt, im Modus Gestaltung öffnen sich sein Rahmen, sein Stil oder seine Vorlage. `sandbox_get_state` meldet das ausgewählte Element als `pageSelection`.

### Die Gestaltung ändern

Jede Einstellung der [Konfiguration](/de/docs/configuration) lässt sich über
ihren Pfad ändern. Ein Agent kennt den Pfad anfangs selten, also sucht er ihn:

```jsonc
// sandbox_find_setting
{ "query": "orphans" }
```

```json
{
  "ok": true,
  "paths": [
    { "path": "bodyText.avoidOrphans", "effective": true },
    { "path": "bodyText.avoidOrphansInLists", "effective": true }
  ],
  "sections": [{ "section": "Body text", "group": "Typography", "settingsGroup": "text", "configKeys": ["bodyText"] }]
}
```

`sandbox_get_config` liest eine Einstellung oder einen ganzen Abschnitt: `set`
ist, was das Buch speichert, `effective`, was sich mit den eingesetzten
Standardwerten ergibt; das zeigt zugleich jede Einstellung, die der Abschnitt
hat.

```jsonc
// sandbox_get_config
{ "path": "headings.levels[level=2]" }
```

Ein Pfad wählt einen Listeneintrag über das Feld aus, das ihn von den anderen unterscheidet:
`headings.levels[level=2].fontSize`, `header.elements[id=titleOdd].italic`,
`calloutStyles[id=note].title`. Dann ändert `sandbox_set_config` in einem
Aufruf so viele Einstellungen, wie Sie möchten:

```jsonc
// sandbox_set_config
{
  "changes": [
    { "path": "bodyText.fontSize", "value": "10.5pt" },
    { "path": "page.margins.top", "value": { "value": 2.5, "unit": "cm" } },
    { "path": "headings.levels[level=2].color", "value": "#1f3a5f" },
    { "path": "bodyText.avoidOrphans", "value": true }
  ]
}
```

Eine Länge ist `"2.5cm"`, `{ "value": 2.5, "unit": "cm" }` oder eine Zahl in
der Einheit der Einstellung; eine Farbe ist `"#1f3a5f"`. Ein Wert `null`
entfernt die Einstellung, sodass wieder der Wert der Gestaltung gilt. Die
Antwort sagt, wie die Änderung zu beurteilen ist und wie sie sich zurücknehmen
lässt:

```json
{
  "ok": true,
  "changed": [
    {
      "path": "bodyText.fontSize",
      "from": null,
      "to": { "value": 10.5, "unit": "pt" },
      "effective": { "from": { "value": 10, "unit": "pt" }, "to": { "value": 10.5, "unit": "pt" } }
    }
  ],
  "followed": [
    { "path": "captionStyle.fontSize.value", "from": 10, "to": 10.5 },
    { "path": "tableStyle.bodyFontSize.value", "from": 10, "to": 10.5 }
  ],
  "pagesBefore": 212,
  "pagesAfter": 219,
  "chapters": [{ "chapter": 1, "title": "Opening", "pages": 19, "pagesBefore": 18 }]
}
```

`from` ist der zuvor gespeicherte Wert (hier `null`: Das Buch hatte ihn nicht
gesetzt), sodass derselbe Aufruf mit `from` als Wert die Änderung rückgängig
macht. `followed` listet die Einstellungen auf, die von dieser abhängen und
sich mit ihr geändert haben. Ein `note` erscheint, wenn die Engine etwas anderes
aufgelöst hat als verlangt (eine Grenze, eine Einstellung, die von einer
anderen abhängt). Ein Wert in falscher Form oder eine Konfiguration, die
die Engine nicht auflösen kann, wird abgewiesen, ohne dass sich etwas ändert.

Jeder Aufruf ist ein Schritt im Verlauf der Sandbox: `sandbox_undo` nimmt ihn zurück, so wie Cmd/Strg+Z eine Änderung im Bedienfeld Gestaltung zurücknimmt.

Für größere Änderungen führt `patch` ein Objekt mit der Konfiguration zusammen
(Objekte werden zusammengeführt, `null` entfernt, Listen werden als Ganzes
ersetzt), und `replace` ersetzt die Konfiguration des Buchs durch eine ganz
andere, etwa einen Export als `postext-config.json`.
`sandbox_reset_to_original` mit `part: "config"` stellt die Gestaltung wieder
her, mit der das Buch begonnen hat.

Ein Buch in mehreren Sprachen hat allgemeine Einstellungen, die jede Ausgabe
liest, und jede Ausgabe behält die Felder, die sie selbst setzt (siehe
[Allgemeine Einstellungen und sprachspezifische
Abweichungen](/de/docs/configuration-bundles#allgemeine-einstellungen-und-sprachspezifische-abweichungen)).
`sandbox_get_config` und `sandbox_set_config` nehmen `scope` entgegen: `"all"`
liest oder schreibt die allgemeinen Einstellungen, `"edition"` die angezeigte
Ausgabe. Fehlt es, gilt der Bereich, auf dem das Bedienfeld Gestaltung steht.
In einem solchen Buch antwortet `sandbox_get_config` mit `scope` und
`ownFields`, den Pfaden, die die angezeigte Ausgabe selbst setzt:

```jsonc
// sandbox_set_config
{ "scope": "all", "changes": [{ "path": "bodyText.fontSize", "value": "10.5pt" }] }
```

```json
{ "ok": true, "scope": "all", "keptBy": ["ar"], "changed": [ … ] }
```

Ein Schreibvorgang in die allgemeinen Einstellungen erreicht jede Ausgabe, die
das Feld nicht selbst setzt. `keptBy` nennt die Sprachen, die es setzen und
ihren Wert behalten. Um auch sie zu ändern, öffnen Sie jede einzeln
(`sandbox_open_book` mit `language`) und schreiben den Pfad mit
`scope: "edition"`: Ein Wert, der dem allgemeinen gleicht, ist dann kein
eigener Wert der Ausgabe mehr. In einem Buch in nur einer Sprache wird
`scope: "all"` abgewiesen, da alle seine Einstellungen seine eigenen sind.

Auch Schriften sind Einstellungen: `sandbox_list_fonts` mit
`search: "Garamond"` findet Familien im offenen Katalog, und wenn Sie den Namen in eine
Einstellung `fontFamily` schreiben, wird die Schrift geladen.

Kastenstile haben eine eigene Bibliothek: `sandbox_frame_styles` nennt jeden
Stil mit den Stellen, an denen das Buch ihn verwendet (Rahmen von Vorlagen,
zusammengesetzte Seiten, `:::callout`-Kästen je Kapitel), und die
vorgeschlagenen Zusammenführungen fast gleicher Stile, wie Gestaltung › Kästen ›
Rahmenstile. `sandbox_merge_styles` nimmt `groups` (`{ keep, merge }`) oder
`all: true` und schreibt jeden Rahmen und jeden Block um, der einen
zusammengeführten Stil verwendet hat. Mit `lookOnly: true` vergleicht es auch Stile,
deren Kästen an verschiedenen Stellen stehen. Ein solcher Stil behält dann nur
noch seine Position und erweitert den behaltenen Stil (`extends`), sodass seine
Kästen bleiben, wo sie sind; die Antwort führt ihn unter `keptForTheirPlace` auf.
Mit `keepPlaces: false` geht er ganz im behaltenen Stil auf, und seine Kästen
verschieben sich.
Die Antwort nennt `undoSteps`: einen Schritt je umgeschriebenem Kapitel und einen für die Stile; `sandbox_undo` nimmt sie zurück, die Stile zuerst.

Ein benanntes Element umzubenennen oder zu entfernen ändert mehr als seinen eigenen Eintrag. Deshalb haben diese Aktionen eigene Tools, die wie das Design-Panel arbeiten. `sandbox_rename_design_item` gibt einem Stil, einer Optik, einer Seitenvorlage, einem Rahmen oder einer Gruppe einer Vorlage oder einem Sprechblasenstil, einer Figur oder einem Panelstil eines Comics eine neue ID. Alles, was das Element nennt, zieht mit: die Blöcke `:::callout` und `::::page`, die Slot-Namen der Seiten, die Anker der Bilder und die `::label`-Zeilen, die Tabellen und Partituren, die einen Stil verwenden, und die Besetzung. `sandbox_remove_design_item` entfernt ein Element wie das Panel: Stile, die auf einem entfernten Kastenstil beruhen, übernehmen seine Optik, und Einstellungen, die eine Palettenfarbe verwendeten, behalten diese Farbe, ohne Verknüpfung mit der Palette. `sandbox_language_defaults` listet die Vorgaben für Chinesisch, Japanisch oder Arabisch aus Design › Text und wendet sie mit `apply: true` an. `sandbox_print_profile` lädt das eigene ICC-Profil des Abschnitts Druck hoch oder entfernt es. `sandbox_save_layout_as_template` macht aus einer gesetzten komponierten Seite eine neue Seitenvorlage. Wird `layout.bitmapResolution` auf `"file"` gesetzt, wird auch die Auflösung gelesen, die jede vorhandene Bilddatei angibt.

### Den Text bearbeiten

Der Text jedes Kapitels ist Markdown mit den Erweiterungen von Postext (siehe
[Dokumentformat](/de/docs/document-format)). Der Agent liest ihn mit
Zeilennummern, sucht eine Stelle und ersetzt Passagen im genauen Wortlaut:

```jsonc
// sandbox_read_text: lines 40 to 80 of chapter 2
{ "chapter": 2, "fromLine": 40, "toLine": 80 }
```

```jsonc
// sandbox_search_text: where a passage occurs, and on which page
{ "query": "baseline grid", "pages": true }
```

```jsonc
// sandbox_edit_text
{
  "chapter": 2,
  "edits": [
    { "find": "The last words of the opening.", "replace": "The closing words of the opening." },
    { "find": "colour", "replace": "color", "all": true }
  ]
}
```

Jedes `find` muss exakt mit der Quelle übereinstimmen und genau einmal
vorkommen, es sei denn, `all` ist gesetzt. Entweder greift jede Bearbeitung
oder keine: Eine Passage, die nicht vorhanden ist, wird mit dem Rat abgewiesen,
das Kapitel erneut zu lesen. Der ganze Aufruf ist ein Schritt für
`sandbox_undo_text`, das ihn zurücknimmt (`redo: true` stellt ihn wieder her).
`sandbox_write_text` ersetzt ein ganzes Kapitel, aus `markdown` oder aus einer
`.md`-Datei.

Um Ihnen eine Stelle im Text zu zeigen, öffnet `sandbox_select_text` das
Bedienfeld Text und wählt diese Passage aus (über `text`, `line` oder
`offset`), wie es ein Klick auf einen Befund im Bedienfeld Prüfungen tut.

### Die Kapitel ordnen

`sandbox_manage_chapters` fügt Kapitel hinzu, benennt sie um, verschiebt,
teilt, verbindet und zeigt sie:

```jsonc
// add a chapter in third place
{ "action": "add", "title": "Epilogue", "markdown": "# Epilogue\n\nThe end.\n", "position": 3 }

// split a chapter where a passage starts
{ "action": "split", "chapter": "Opening", "before": "## Second part" }

// one chapter per level-1 heading
{ "action": "split_at_headings", "chapter": 1 }
```

`sandbox_remove_chapter` löscht ein Kapitel; das lässt sich nicht rückgängig machen.

### Bilder, Tabellen, Videos und Schriften hinzufügen

`sandbox_save_resource` fügt eine Ressource hinzu oder ändert eine, wie es das
Bedienfeld Ressourcen tut. Eine Datei kommt über `url` (eine `https:`-Adresse,
die die Seite abrufen kann, oder eine `data:`-URL) oder als `base64`:

```jsonc
// a picture with its caption and alternative text
{
  "id": "harbour",
  "image": { "url": "https://example.org/harbour.jpg" },
  "caption": "The harbour at dawn",
  "altText": "Fishing boats moored at a stone quay, mist over the water",
  "placement": { "position": "top", "span": "page" }
}
```

```jsonc
// a table from rows of text; the first row is the header
{
  "id": "prices",
  "caption": "Prices in 1850",
  "table": { "rows": [["Item", "Price"], ["Bread", "2 d"], ["Ink", "6 d"]], "columnWidths": [2, 1] }
}
```

```jsonc
// a YouTube video: its poster, frame size and title are fetched
{ "id": "interview", "video": { "url": "https://www.youtube.com/watch?v=…" }, "caption": "The author at work" }
```

Die Antwort liefert den gespeicherten Datensatz und die Zeile, die die
Ressource platziert, `::resource{id="prices"}`, die der Agent dann mit
`sandbox_edit_text` in den Text schreibt. Bei einer bestehenden `id` ändert der
Aufruf nur, was er angibt: eine Legende, die Zellen einer Tabelle, die
Platzierung, den Sicherheitsbereich eines Bildes. `newId` benennt eine
Ressource um und standardmäßig auch jeden Verweis auf sie im Buch.
`sandbox_list_resources` listet sie auf und liefert mit einer `id` eine davon
vollständig (die Zellen einer Tabelle mit ihrer Formatierung, die Quelle eines
SVG).

Die `marks` eines Bildes enthalten auch seine Anker. Bei einer Karte oder einem Schema sind das die Punkte, an denen seine `::label`-Zeilen stehen: eine `id`, `x` und `y` (Bruchteile des ganzen Bildes) und die Beschriftungsfelder, die eine dort gesetzte Beschriftung übernimmt (`style`, `align`, `verticalAlign`, `rotate`, `width`, `writingMode`). Die Antwort weist auf einen Beschriftungsstil hin, den die Gestaltung nicht hat, und neue Markierungen einer Ressource sind ein Schritt des Verlaufs (`sandbox_undo` antwortet `kind: "resource"`). Bei einem SVG legt `marks.svgSymbols` (`idPrefix`, `className`) eine Sperrzone über jedes Element der Zeichnung, das es benennt – zusätzlich zu den Zonen, die der Aufruf angibt oder die das Bild schon hat (seit postext 1.43).

```jsonc
// zwei Anker einer Karte mit ihren Beschriftungsstilen
{ "id": "map", "marks": { "anchors": [
  { "id": "albar", "x": 0.19, "y": 0.41, "style": "city", "verticalAlign": "bottom" },
  { "id": "senne", "x": 0.22, "y": 0.54, "style": "river", "rotate": 68 }
] } }
```

In das Buch hochgeladene Schriften laufen über `sandbox_save_font`:

```json
{ "action": "add", "family": "My Serif", "weight": 700, "style": "italic", "file": { "url": "https://example.org/MySerif-BoldItalic.woff2" } }
```

### Das Buch prüfen

```jsonc
// sandbox_get_warnings: every chapter
{ "scope": "book" }
```

Die Antwort ist das, was das Bedienfeld Prüfungen meldet, für jedes Kapitel
oder das ganze Buch, gleich was auf dem Bildschirm ist: fehlende Schriften und
Bilder, Auszeichnungen, die die Engine nicht lesen konnte,
Gestaltungselemente, die nicht passen, Text, der für seinen Hintergrund zu
blass ist, zu lockere Zeilen, Witwen, überlaufende Kästen und die
Druckvorstufenprüfung. Jede Warnung hat ihre Kategorie, ihr Kapitel, ihre
Zeile und Offsets, ihre Seite und die Einstellung oder Ressource, auf die sie
sich bezieht:

```json
{
  "ok": true,
  "scope": "book",
  "total": 3,
  "byCategory": { "typesetting": 2, "design": 1 },
  "warnings": [
    {
      "kind": "headerFooterMetadataMissing",
      "category": "design",
      "title": "Placeholder metadata missing",
      "detail": "header · {title} — The metadata referenced by this placeholder is not set — it will render empty."
    }
  ]
}
```

Von einer Warnung aus kann der Agent zu ihrer Stelle gehen
(`sandbox_select_text` mit `offset` und `toOffset` oder `sandbox_go_to_page`),
sich die Seite ansehen und den Text oder die Einstellung ändern. `category`
grenzt die Liste ein; bei einem langen Buch setzt `scope: "book"` jedes Kapitel
und braucht eine Weile.

Ein Buch mit mehreren Ausgaben (das Paket eines Beispiels oder ein daraus importiertes Projekt) hat die Prüfungen seiner zusammengesetzten Seiten auch in jeder Sprache: `sandbox_get_composed_checks` setzt jede Ausgabe und listet die Prüfungen nach Sprache, Kapitel, Seite und Rahmen auf, wie das Bedienfeld Prüfungen unter *Zusammengesetzte Seiten*; mit `language` beschränkt es sich auf eine (seit postext 1.40). `sandbox_get_warnings` prüft weiterhin ein Kapitel in der Sprache auf dem Bildschirm.

### Ihnen etwas zeigen

Was der Agent ändert, sehen Sie. Um Sie auf etwas hinzuweisen:

```jsonc
// sandbox_set_view: the Canvas with facing pages and loose lines highlighted
{ "viewer": "canvas", "pages": "spread", "fit": "height", "guides": { "looseLines": true, "baselineGrid": true } }
```

```jsonc
// sandbox_go_to_page: where a figure is set
{ "anchor": "harbour" }
```

`sandbox_set_view` wählt außerdem den Betrachter (`canvas`, `pdf`, `folio`,
`html`, `epub`, `scorm`), den Modus Inhalt oder Gestaltung (`mode`), das seitliche
Bedienfeld, Kapitel oder ganzes Buch, den Zoom,
die Schriftgröße für den Leser, die Druckvorschau und die Gruppe des Bedienfelds
Gestaltung sowie im Tab SCORM den Inhalt (`scormLayout`), die Version
(`scormVersion`) und die Kapitel und Abschnitte, die das Paket aufnimmt
(`scormPick`, IDs aus den `contents` des Tabs). `sandbox_go_to_page` blättert über `step`, `page`, `position`, eine
Textpassage `text`, einen `anchor` oder einen Eintrag im Inhaltsverzeichnis
eines EPUB (`contents`).
`sandbox_run_viewer` betätigt eine Schaltfläche der Werkzeugleiste:
`regenerate` erzeugt das PDF, das EPUB oder das SCORM-Paket neu und wartet darauf, `print` öffnet
den Druckdialog, den Sie bestätigen, `download` speichert das PDF, das
EPUB oder ein neu erzeugtes SCORM-Paket, und `play_video` und `stop_video` starten und stoppen ein Video auf
einer Seite.

### Comicseiten

`sandbox_inspect_comic` liefert die Panels, Trennlinien und Sprechblasen einer
Comicseite mit ihren Positionen; `sandbox_edit_comic` nimmt die Änderungen vor,
die ein Mensch mit dem Zeiger vornimmt, und schreibt sie in die Quelle:

```jsonc
// move a balloon's centre to a point of its panel's picture, in percent
{ "comic": 1, "action": "move_balloon", "balloon": 2, "at": { "x": 30, "y": 18 } }

// move the first split line to 45 % of its cell
{ "comic": 1, "action": "move_splitter", "splitter": 1, "start": 45 }
```

Die Antwort warnt, wenn eine Sprechblase auf einem Gesicht zu liegen kommt oder aus
ihrem Panel herausragt. Das Format beschreibt [Comics](/de/docs/comics).

### Bücher, Dateien und Word

- **Bücher öffnen und behalten.** `sandbox_list_books` listet die Beispiele und
  Ihre Projekte auf; `sandbox_open_book` öffnet eines (`{ "kind": "sample", "id": "postext-guide",
  "language": "es" }`); `sandbox_save_book` mit `action: "copy_current"` speichert
  das Buch auf dem Bildschirm als Ihr eigenes Projekt, `new_blank` beginnt ein
  leeres. Bei einem Projekt kopiert `add_language` mit `language` (`"fr"`,
  `"zh-Hant"`) die Sprache auf dem Bildschirm in eine neue Ausgabe in dieser
  Sprache und öffnet sie, und `rename` mit `thisLanguageOnly: true` benennt nur
  die Sprache auf dem Bildschirm um; `set_cover` und `remove_cover` geben ihm
  ein Titelbild oder nehmen es weg.
- **Exportieren.** `sandbox_export` schreibt `pdf`, `epub`, `postext`, `docx`,
  `markdown` oder `config`. Standardmäßig lädt der Browser die Datei herunter;
  mit `deliver: "data"` kommt ein PDF oder EPUB base64-kodiert an den Agenten
  zurück:

  ```json
  { "format": "pdf", "scope": "book", "deliver": "data" }
  ```

- **Eine `.postext`-Datei importieren** mit `sandbox_import_book`
  (`inspect: true` sagt, welche Sprachen sie enthält, ohne sie zu importieren).
- **Ein Word-Manuskript übernehmen** mit `sandbox_import_word`. Führen Sie es
  zuerst mit `dryRun: true` aus: Es ändert nichts und antwortet mit dem
  Qualitätsbericht, mit jeder Word-Formatvorlage und dem, was daraus würde, und
  mit den Kapiteln und Ressourcen, die es anlegen würde. Korrigieren Sie dann die
  Zuordnung und führen Sie den Import tatsächlich aus:

  ```json
  {
    "file": { "url": "https://example.org/manuscript.docx" },
    "destination": "book",
    "mapping": { "paragraphs": { "Epigraph": { "kind": "quote" }, "Chapter Title": { "kind": "chapter" } } },
    "saveTemplateAs": "My publisher"
  }
  ```

  Mit `characterSpacing` (standardmäßig an, wenn es etwas zu übernehmen gibt; seit
  postext 1.40) wird die Laufweite der verwendeten Word-Formatvorlagen in em
  auf die Absatzformate, Überschriftenstile, Überschriftenebenen und Kastentitel des
  Buchs übertragen, denen sie zugeordnet sind, soweit das Buch keinen setzt. Der
  Probelauf listet ihn unter `characterSpacing` auf.

  `sandbox_word_templates` listet die gespeicherten Zuordnungen auf, liest,
  speichert und löscht sie; auch der Word-Export verwendet sie.

### Rückfragen und Hinweise

Öffnet ein Link ein Buch, von dem Sie bereits eine eigene Fassung haben, fragt
die Sandbox, ob Ihre Kopie ersetzt werden soll, und `sandbox_get_state` meldet
das als `question` mit `ready: false`. `sandbox_answer` beantwortet die Frage:
`replaceCopy: false` behält Ihre Kopie, `true` ersetzt sie durch das
veröffentlichte Buch und löscht Ihre Kopie. `dismissNotice: true` schließt die
Meldung des Bedienfelds Bücher.

## Drei Sitzungen von Anfang bis Ende

**„Mach die Schrift etwas größer, aber halte das Buch unter 220 Seiten.“**
`sandbox_get_state` (212 Seiten) → `sandbox_set_config` mit
`bodyText.fontSize` auf `"10.5pt"` (219 Seiten) → `sandbox_render_page` auf
einer dichten Seite, um sie zu beurteilen → `sandbox_get_warnings` mit
`category: "typesetting"` für neue Witwen → falls etwas schiefgegangen ist,
erneut `sandbox_set_config` mit den Werten `from` der ersten Antwort.

**„Behebe, was die Prüfungen in Kapitel 4 gefunden haben.“**
`sandbox_get_warnings` mit `chapter: 4` → für jede Warnung `sandbox_read_text`
rund um ihre `line` und `sandbox_render_page` ihrer `page` →
`sandbox_edit_text` oder `sandbox_set_config` → erneut `sandbox_get_warnings`,
bis die Liste leer zurückkommt.
Ein Rahmen einer zusammengesetzten Seite, der nicht passt, bringt seine Lösungen mit (`proposals`): `sandbox_apply_proposal` mit seinem `frame` und der Nummer einer Lösung wendet sie an, setzt das Kapitel neu und antwortet mit `fits`.

**„Mach aus dieser Word-Datei ein Buch und gib mir das PDF.“**
`sandbox_save_book` mit `action: "new_blank"` → `sandbox_import_word` mit
`dryRun: true` → korrigiertes `mapping`, dann der echte Import mit
`destination: "book"` → `sandbox_get_warnings` mit `scope: "book"` →
`sandbox_export` mit `format: "pdf"` und `scope: "book"`.

## Was Ihre Zustimmung verlangt

Sechs Werkzeuge tun etwas, das sich nicht zurücknehmen lässt, und sind als
folgenreich markiert (`consequentialHint`), damit der Browser Sie fragen kann,
bevor sie laufen: `sandbox_remove_chapter`, `sandbox_delete_resource`,
`sandbox_delete_book`, `sandbox_reset_to_original`, `sandbox_import_word` (es
kann das ganze Buch ersetzen) und `sandbox_answer` (es kann Ihre Kopie eines
Buches löschen). Bitten Sie den Agenten im Zweifel, zuerst eine Kopie als
`.postext` zu exportieren.

Werkzeuge, die nur lesen, sind mit `readOnlyHint` markiert, und solche, deren
Antwort Text enthält, den nicht die Seite geschrieben hat (der eigene Text des
Buches, eine abgerufene Datei), mit `untrustedContentHint`, damit der Browser
verhindern kann, dass dieser Text für Anweisungen gehalten wird.

## Grenzen

- **Alles bleibt in Ihrem Browser.** Die Werkzeuge erreichen nichts, was die
  Sandbox selbst nicht erreicht: Ihre Bücher liegen im Speicher dieses
  Browsers, und eine per `url` angegebene Datei wird von der Seite abgerufen,
  ihr Server muss das also erlauben (CORS). Eine `data:`-URL oder `base64`
  funktioniert immer.
- **Lange Arbeiten brauchen Zeit.** Ein Werkzeug wartet mit seiner Antwort auf
  das Layout; `wait: false` antwortet sofort. Ein PDF oder EPUB eines langen
  Buches dauert Minuten.
- **Rückgängig**: `sandbox_undo` nimmt die letzte Änderung zurück, am Text oder an der Gestaltung, in der Reihenfolge, in der die Änderungen gemacht wurden, wie Cmd/Strg+Z in der Sandbox: im Bedienfeld Text getippter Text, die Bearbeitungen der Werkzeuge und die in den Vorschauen, mit `sandbox_set_config` oder im Bedienfeld Gestaltung geänderte Einstellungen, verschobene Rahmen. `redo: true` stellt eine Änderung wieder her. `sandbox_undo_text` nimmt nur eine Textbearbeitung zurück und sagt es, wenn die letzte Änderung die Gestaltung betraf. Hinzugefügte, entfernte oder verschobene Kapitel, Ressourcen und Schriften stehen nicht im Verlauf; ein anderes Buch zu öffnen leert ihn, ebenso das Neuladen der Seite. `sandbox_get_state` sagt, was beide zurücknehmen würden (`history`).
- **Das Buch auf dem Bildschirm.** Die Werkzeuge arbeiten mit dem geöffneten
  Buch. Nur `sandbox_export` einer `.postext`-Datei, `sandbox_save_book` mit
  `duplicate`, `rename` oder einem Titelbild, `sandbox_delete_book` und
  `sandbox_reset_to_original` mit `sample` erreichen ein anderes Buch, ohne es
  zu öffnen.

## Die Werkzeuge der Website

Auf jeder Seite von postext.dev, die Sandbox eingeschlossen:

- `site_get_context`: die Seite auf dem Bildschirm, ihre Sprache und ihr
  Farbschema, die Bereiche und jede Seite der Dokumentation.
- `site_search`: durchsucht die Dokumentation und die Rezepte nach Wörtern, Namen von
  Einstellungen (`bodyText.avoidOrphans`) oder Direktiven (`::resource`).
- `site_read_page`: eine Seite der Website als Markdown, ohne die Seite auf
  dem Bildschirm zu verlassen.
- `site_open_page`: eine Seite anzeigen, mit `#heading`, um direkt zu einem
  Abschnitt zu springen.
- `site_list_recipes` und `site_open_recipe_in_sandbox`: ein Rezept finden
  und es in der Sandbox als bearbeitbares Buch öffnen.
- `site_lookup_term`: ein Begriff aus dem Glossar (Witwe, Unterschneidung,
  Kinsoku …).
- `site_set_preferences`: Sprache und Farbschema der Website.

Ein Agent, der auf der Startseite beginnt, kann also die Rezepte
durchsuchen, ein Rezept in der Sandbox öffnen und dort mit den Werkzeugen
`sandbox_*` weitermachen.

## Alle Werkzeuge

Gruppiert so, wie die Sandbox sie registriert. Die vollständige Beschreibung
und das Schema jedes Werkzeugs liefert `postextWebMcp.listTools()`.

- **Was geöffnet ist**: `sandbox_get_state`.
- **Die Seiten**: `sandbox_render_page`, `sandbox_inspect_pages`,
  `sandbox_inspect_point`.
- **Der Text**: `sandbox_read_text`, `sandbox_write_text`, `sandbox_edit_text`,
  `sandbox_undo_text`, `sandbox_select_text`, `sandbox_search_text`,
  `sandbox_manage_chapters`, `sandbox_remove_chapter`.
- **Die Gestaltung**: `sandbox_get_config`, `sandbox_set_config`,
  `sandbox_find_setting`, `sandbox_reset_to_original`,
  `sandbox_frame_styles`, `sandbox_merge_styles`.
- **Rückgängig**: `sandbox_undo`.
- **Die Anzeige**: `sandbox_set_view`, `sandbox_go_to_page`,
  `sandbox_run_viewer`.
- **Ressourcen und Schriften**: `sandbox_list_resources`, `sandbox_save_resource`,
  `sandbox_delete_resource`, `sandbox_list_fonts`, `sandbox_save_font`.
- **Comics**: `sandbox_inspect_comic`, `sandbox_edit_comic`.
- **Bücher und Dateien**: `sandbox_list_books`, `sandbox_open_book`,
  `sandbox_save_book`, `sandbox_delete_book`, `sandbox_import_book`,
  `sandbox_export`.
- **Word**: `sandbox_import_word`, `sandbox_word_templates`.
- **Rückfragen**: `sandbox_answer`.
- **Die Prüfungen**: `sandbox_get_warnings`, `sandbox_get_composed_checks`, `sandbox_apply_proposal`.

## Wenn Sie die Sandbox einbetten

`<PostextSandbox>` registriert die Werkzeuge, solange die Komponente eingebunden ist;
`webmcp={false}` lässt sie weg (siehe [Props](/de/docs/sandbox-embedding#props)). Eine
Host-Seite kann über dasselbe Modul eigene Werkzeuge hinzufügen:

```ts
import { registerWebMcpTools } from 'postext-sandbox/webmcp';

const controller = new AbortController();
registerWebMcpTools([
  {
    name: 'shop_list_titles',
    description: 'The titles of this shop, with the id of the Postext project of each one.',
    inputSchema: { type: 'object', properties: {}, additionalProperties: false },
    annotations: { readOnlyHint: true },
    execute: async () => ({ titles: await fetchTitles() }),
  },
], controller.signal);
// controller.abort() takes them back
```

Sie werden bei WebMCP registriert, wo der Browser es anbietet, und immer auf
`window.postextWebMcp`, wobei ihre Argumente gegen `inputSchema` geprüft
werden.
