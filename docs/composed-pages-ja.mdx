# テンプレートページ

**ページの形はテンプレートが決め、Markdownは中身を受け持って、それぞれをどの枠に入れるかを示します。**

テンプレートページは、設定の`pageTemplates`に定義したテンプレートから組むページです。テンプレートには、名前の付いた枠（題名の帯、本文、写真の付いた囲み）、まとめて動くグループ、装飾があります。Markdownでは、ページはコロンで囲んだ1つのブロックとして書きます。ブロックは使うテンプレートを指定し、内容を枠の名前で振り分けます。Markdownに位置や大きさを書くことはなく、設定に本文の文章を書くこともありません。そのため翻訳は、同じテンプレートに別の言葉を入れるだけで済みます。

このページでは、Markdownと、そこからページがどう組まれるかを扱います。テンプレートそのもの（枠、大きさ、スタイル、装飾）は[設定 › テンプレートページ](/ja/docs/configuration-composed-pages)で説明しています。テンプレートページのない文書は、これまでとまったく同じに組まれます。

## ページブロック

```md
::::page{template="tema-cajas" fondo="banda-retos"}
# La actividad económica y el dinero

Las personas utilizan :chip[recursos]{style="clave"} que se obtienen de la naturaleza…
::::
```

テンプレートページは*ページブロック*として書きます。**コロン4つ**に`page`と属性を続けた行で始め、**同じ数のコロン**だけの行で閉じます。中では、コロン3つのコンテナー（`:::frame`、`:::callout`、`:::figure`、`:::columns`、`:::paper`）がいつもどおり開いて閉じるので、単独の`:::`はそのうちいちばん内側のものを閉じ、ページを閉じることはありません。コロン5つで始めたページ（`:::::page`）は5つで閉じ、その中ではコロン4つの行はただのテキストです。

テンプレートページはいつも新しいページ（または見開き）から始まり、終了行の後のテキストは次のページから始まります。

コロン3つの`:::page{split=…}`は漫画のページで（[漫画](/ja/docs/comics)を参照）、その意味は変わりません。コロン3つの`:::page`は、`template=`を付けても漫画のページとして読まれ、テンプレートページにはコロンが4つ必要であることを`pageFenceLength`の警告が知らせます。

開始行や終了行が欠けていても、パーサーはテキストを失わずに立て直します。

- 閉じられていないページは章の終わりまで続き、その開始行で閉じていないコンテナーとして報告されます。
- ページが開いている間に`::::page`の行が現れると、まずそこで開いているページを閉じます（同じように報告されます）。
- 終了行は、ページの中でまだ開いている枠や囲みをすべて閉じ、その1つ1つを報告します。
- コロンの数が違う終了行は、そのページを閉じません。テキストに残るので、目で確かめられます。

## 枠とスロット

```md
:::frame{slot="dinero" label="El dinero"}
Es el instrumento utilizado como medio de pago…

Hasta hace pocos años, lo más normal era pagar con dinero en **efectivo**…
:::
```

**スロット**は、内容の行き先となる枠を示す名前で、テンプレートの枠の名前と対応します。`:::frame{slot="…"}`は、中のものをすべてその枠に送ります。中身には、段落、リスト、見出し、チップ、`::resource`の埋め込み、`:ref`の参照、脚注、`:::columns`、入れ子の囲みなど、どんなMarkdownでも書けます。`label`と`title`は、`:::callout`と同じく、枠のタブやタイトルの文字を指定します。枠の見た目は、テンプレートがその枠に割り当てた囲みスタイルで決まり、内容ごとに独自の見た目を指定することもできます（[枠の見た目](#枠の見た目)を参照）。

1つのブロックに、それ自身のスロットを指定することもできます。

内容は次のように振り分けられます。

- 同じスロットを指定した複数の内容は、Markdownの順につながります。ただし繰り返しのグリッドでは、内容の1つ1つがそれぞれ1枚のカードになります（[繰り返すスロット](#繰り返すスロット)を参照）。
- スロットのない内容は、テンプレートの**流し込み枠**（`flow`の付いた枠）に入ります。
- スロットのない見出しは、テンプレートにその見出しのレベルを受け取る枠（`takes: "h1"`）があれば、まずそこに入ります。ですから教科書の単元の題名は、ページの頭に`# 題名`と書くだけで済みます。
- スロットのない`:::toc`は、テンプレートに`takes: "toc"`の枠があればその枠に入ります（下の「枠の中の目次」を参照）。
- テンプレートにないスロットを指定した内容は、流し込み枠に入り、報告されます（`slotUnknown`）。

テンプレートページの外にある`slot`は読まれますが、何も変えません。

### 繰り返すスロット

テンプレートがカードを1度だけ描き、ページに必要な数だけグリッドに並べる場合（`repeat`の付いたグループ。[設定 › 枠のセットを繰り返すグリッド](/ja/docs/configuration-composed-pages#枠のセットを繰り返すグリッド)を参照）、カードの主スロットを指定した`:::frame`の1つ1つが、書いた順に1枚のカードになります。

```md
::::page{template="fotos"}
# 川の動物

:::frame{slot="foto"}
::resource{id="garza"}

:::frame{slot="pie"}
サギ
:::
:::

:::frame{slot="foto"}
::resource{id="nutria"}

:::frame{slot="pie"}
カワウソ
:::
:::
::::
```

- **カードの構成要素**：カードの内容の中で、セットのほかの枠（ここではキャプションの札`pie`）を指定したブロックや`:::frame`は、同じカードのその枠に入ります。それ以外はすべてカードの主枠に入ります。
- **1つのブロックで1枚のカード**：コンテナーの外に単独で置いた`::resource{id="…" slot="foto"}`も1枚のカードになります。
- **名前**：カードには1から番号が付きます。2枚目のカードの枠は`foto[2]`と`pie[2]`で、警告、再配置の記録、Sandboxにもこの名前で現れます。
- **枚数**：ページのカードは内容の数だけできます。動物が5種のスペイン語版と4種の英語版が、同じテンプレートを使えます。`repeat.max`のあるグリッドはその数まで受け取り、超えた内容はそれぞれ`repeatOverflow`を出して流し込み枠に入ります。

セットの枠が`slotEmpty`として報告されるのは、ページのどのカードもその枠を埋めないときだけです。繰り返す枠は見出しを受け取らず、流し込み枠になることもありません。

### 枠の見た目

内容には、名前の付いた見た目を指定できます。見た目は色の組み合わせで、設定の`frameLooks`で定義します（[設定 › 枠の見た目](/ja/docs/configuration-composed-pages#枠の見た目)を参照）。Markdownは見た目の名前を示し、設定はその中身を決めます。グリッドでは、どのカードも同じテンプレートと同じスタイルのまま、カードごとに色を変えられます。

```md
::::page{template="fotos"}
# 川の動物

:::frame{slot="foto"}
::resource{id="garza"}

:::frame{slot="pie" look="rojo"}
サギ
:::
:::

:::frame{slot="foto" look="marino"}
::resource{id="nutria"}

:::frame{slot="pie" look="verde"}
カワウソ
:::
:::
::::
```

- **書く場所**：`look`は、どの`:::frame{slot="…"}`でも開始行に書きます。カードの主な内容（ここでは2枚目の写真の枠）と、その中に入れ子にした構成要素（それぞれのキャプションの札）が、それぞれ自分の見た目を指定します。
- **変わるもの**：見た目は枠のスタイルとテンプレート自身の色の上に重ねられ、その内容だけに効きます。ほかのカードは自分の色のままです。別の枠に続くテキスト（枠のつながりや追加ページ）も、同じ見た目を保ちます。
- **不明なid**：`frameLooks`にないidは、その属性の位置で`lookUnknown`を出し、いちばん近いidを示します。枠は元の色のままです。

### ページの中のモジュール

モジュールのグループ（`modules: true`。[設定 › モジュール](/ja/docs/configuration-composed-pages#モジュール)を参照）を持つページテンプレートは、ブロックを`:::module`コンテナーから受け取り、書いた順に上から積み重ねます。ブロックを描くのはモジュールのテンプレートで、コンテナーにはその言葉を入れます。

```md
::::page{template="tema"}
# 川

:::module{template="caja"}
:::frame{slot="texto" label="知っていますか"}
川は山で生まれます。そこでは雨と雪が集まって流れになります。
:::
::resource{id="rio" slot="foto"}
:::

:::module{template="arbol" name="ramas"}
:::frame{slot="raiz"}
川
:::
:::frame{slot="izq"}
川が運ぶ水
:::
:::frame{slot="der"}
岸辺の生き物
:::
:::
::::
```

- `template`は`role: 'module'`のテンプレートを指定します。`name`は省略できます。モジュールのインスタンスに名前を付けるもので、その枠は`ramas.raiz`、`ramas.izq`になります。省略するとインスタンスは`<template>[n]`で、nはページの中でそのテンプレートを使うモジュールの何番目かを示します（`arbol[1].raiz`）。ページの中ですでに使われている名前や、スペース、`.`、`#`、`[`、`]`を含む名前は、この既定の名前に置き換わります（`moduleNameRejected`）。
- `:::module`の中の**スロット**はそのモジュール自身のものです。`slot="raiz"`はこのモジュールの`raiz`の枠に届き、同じテンプレートのモジュールが1ページに2つあっても、言葉が混ざりません。スロットを指定しない内容はモジュールの流し込み枠に、見出しはそのレベルを`takes`で受け取るモジュールの枠に入ります。どちらもなければ、ページの流し込み枠に入ります。
- **順序**：モジュールはMarkdownの順に積み重なります。ですから別のページでは、新しいテンプレートを作らずに、同じブロックを別の順に並べたり、木をもう1つ加えたりできます。
- **横に並べる**：モジュールグループが行かグリッドのとき、または中に自分のグループ（`within`）を持つとき、同じブロックが横に並びます。`:::module{template="aviso"}`2つに続けて`:::module{template="tarjeta"}`4つを書くと、2つの囲みを並べた行の下に2 × 2のカードが並びます。Markdownが決めるのは、どのモジュールをどの順に置くかだけです（[設定 › モジュール](/ja/docs/configuration-composed-pages#モジュール)を参照）。 postext 1.51からは行の中にもグループを置けるので、囲みの横にカードの列を並べられます。行のモジュールは`grow`と`shrink`で行の幅を分け合います。
- ページブロックの外にある`:::module`は、その内容を入れたただの囲みです。モジュールの中のモジュールは使えません（`moduleNested`）。

## 作例

教科書の1ページです。題名の帯、リスト付きの本文、そしてそれぞれ横に写真を添えた色付きの囲みが3つあります。

```md
::::page{template="tema-cajas" fondo="banda-retos"}
# La actividad económica y el dinero

## La actividad económica

Las personas utilizan :chip[recursos]{style="clave"} que se obtienen de la naturaleza…

- Las :chip[empresas.]{style="clave"} Ofrecen bienes y servicios a cambio de un beneficio.
- Las :chip[personas y familias.]{style="clave"} Adquieren lo que ofrecen las empresas…

:::frame{slot="dinero" label="El dinero"}
Es el instrumento utilizado como medio de pago, ya que su valor es conocido…
:::

::resource{id="dinero-pago" slot="dinero-fotos"}

:::frame{slot="gasto" label="El gasto"}
- **Fijo:** es el que se produce todos los meses…
- **Variable:** puede cambiar según las necesidades…
:::

::resource{id="gasto-compras" slot="gasto-fotos"}

:::frame{slot="ahorro" label="Préstamos y ahorro"}
Si necesitas o quieres comprar algo muy caro…
:::

::resource{id="ahorro-balanza" slot="ahorro-fotos"}
::::
```

題名は`h1`を受け取る枠に、小見出し、段落、リストは流し込み枠に、囲みと写真はそれぞれのスロットの枠に入ります。カタルーニャ語版は、同じ行に別の言葉を入れたものです。テンプレートもスロットも写真も変わりません。

## ページの組み方

テンプレートページは1ページを丸ごと使います（デザイン要素の`pages`フィルターでは役割`composed`のページです）。テンプレートはページが左右どちらに来るかで選ばれ、`variants.recto`か`variants.verso`が当てはまります。そのうえで枠を1つずつ配置して中身を流し込みます。組版の設定は本の他の部分と同じで、段落スタイルと見出しスタイル、リスト、チップ、脚注の合印、そして枠の囲みスタイルが使われます。

### 枠の配置

枠はグリッドのセルに置かれるか、`placement`の指定する位置（デザイン要素と同じく、アンカー、辺、オフセット）に置かれます。どちらもなければ、テンプレートの領域の左上の角に、領域と同じ幅で置かれます。ほかの枠に固定した枠（`"to": "#dinero"`）は、その枠の後に配置され、その枠と一緒に動きます。`below`ならその枠の下に、`right-of`なら横に付き、`top-right`のような角を指定すると、その枠のボックスの同じ角に留められます。

枠の高さは、固定値（長さかパーセント）、`fill`（領域の端まで）、既定の`auto`のいずれかです。`auto`では受け取った中身の高さになり、`minHeight`と`maxHeight`の間に収まって、領域の下端を越えることはありません。枠が中身より高いときは、`verticalAlign`が中身の位置を決めます（`top`、`middle`、`bottom`、またはブロックの間にアキを配る`justify`）。枠の囲みスタイルは、背景、枠線、角丸、帯、アイコンを枠いっぱいの大きさで描き、`:::frame`ブロックの`label`はスタイルのタブに入ります。

### 流し込み枠と見出し

スロットを指定しない内容は`flow`の付いた枠に入り、各レベルの最初の見出しは、`takes`でそのレベルを受け取る枠に入ります。ページ上の枠は、中身がMarkdownに最初に現れた順に、1つずつまとめて読まれます。スクリーンリーダー、タグ付きPDF、リフロー型の出力は、ページの冒頭の本文の後に囲みを読み、本文の途中に割り込ませることはありません。

枠に置いた見出しは、レベルまたは見出しスタイルのデザイン（タブ、帯、デザインが組む`{titleText}`）を保ち、ページの段と同じように枠の幅で組まれ、枠はデザインが必要とする高さを確保します。文字が縮小される枠ではデザインも縮小され、回転した枠ではデザインも回転します。[囲みと枠の中の見出し](/ja/docs/configuration-headings#囲みと枠の中の見出し)を参照してください。postext 1.36までは、このような見出しはデザインなしで組まれていました。

### 枠の中の目次

枠は目次を組めます（postext 1.42以降）。テンプレートに`takes: "toc"`の枠を用意し、ページブロックの中に`:::toc`を書きます。スロットを指定する`:::frame`の中に書いてもかまいません。

```md
::::page{template="contents"}
# この単元で学ぶこと {toc="false"}

:::toc{keep="part" levels="1-2"}
::::
```

枠は、本文の中の目次と同じく、目次自身の規則で各行を組みます。部には専用の行があり、`toc.parts.design`から描かれます。項目は番号、リーダー、ページのラベルを保ち、載せているページへのリンクになります。項目のあいだに枠が段落間隔を足すことはありません。`keep`は枠の中でも働きます。`overflow.continueIn: "next-page"`のとき、枠1つに収まる目次のまとまりは、まるごと追加ページに移ります。枠より高いまとまりは、見出し行と`toc.groups.minEntriesAfterHead`個の項目のあとで切られ、追加ページは繰り返した見出し行（`toc.groups.continuation`）で始まります。切れ目のしるし（`overflow.mark`）と追加ページの先頭の語句（`overflow.fromMark`）は、ほかの枠と同じです。

一覧の上のタイトルは普通の見出しで、見出しスタイルが`toc: false`でない限り、また見出しに`{toc="false"}`を付けない限り、目次に載ります。本文のときと同じです。ページの地、つまり紙面全体の下に敷く色や画像は、テンプレートの装飾です。枠の下に描かれ、目次が増やすどのページにも繰り返されます。部と部のあいだの改ページ（`toc.parts.breakBefore`）は、続きを送れる枠（`overflow.continueIn: "next-page"`、または`next`で続く枠）で働きます。全体が収まる場合でも、最初の部を除く各部の前で枠が切れ、各部は追加されたページか次の枠から始まります。続きを送れない枠は、この改ページを無視します。postext 1.43以降。

### 枠をつなぐ

`next`は、枠に収まりきらない分を同じページの別の枠に送り、その枠からさらに次の枠へ送ります。組版ソフトでテキストフレームを連結するのと同じです。

```json
{ "name": "columna-1", "flow": true, "next": "columna-2", "height": { "value": 120, "unit": "mm" } },
{ "name": "columna-2", "placement": { "anchor": { "to": "#columna-1", "edge": "right-of" } } }
```

テキストは行と行の間で切れて次の枠に続き、その枠の幅で改めて行分けされます。失われる部分も、重複する部分もありません。`overflow.continueIn: "#frame"`も同じ意味です。

枠は本文と同じように切れます。見出しが断片の最後に来ることはなく、見出しはそれが導く行と一緒に移ります。リストの項目と項目の間で切るときは、両側に少なくとも2項目を残します（`bodyText.avoidOrphansInLists`または`bodyText.avoidWidowsInLists`がオフなら1項目）。`bodyText.shortListSplit: 'avoid'`のもとでは、`bodyText.shortListMaxItems`項目までのリストは項目の間で切りません。どの切れ目もこれを満たさないときは、断片は見出しやリストの前で、またはリストのいずれかの項目の途中で終わります。このページの後に加えるページへ続ける方法は、[文章が追加ページに続くとき](#文章が追加ページに続くとき)を参照してください。

### テキストを押しのける枠

`exclude: "push"`を付けた枠は、ほかの枠のテキストを自分の矩形に入れません。ほかの枠の行がこの矩形にかかると、矩形が覆う側で行が短く組まれます。本文の流れでテキストが画像を回り込むのと同じです。囲みの角に固定して`push`を付けた写真があれば、囲みのテキストはその写真の横を流れます。写真のための列を決まった幅で空けておきたい囲みには、代わりに`padding`を使えます。

`"wrap": "contour"`も付けると、枠は矩形ではなく、中に置いた画像の形でテキストを押しのけます。切り抜いたイラストのアルファチャンネルか、リソースの`contour`にある多角形です。ほかの枠の各行はその横にある形の幅だけ短く組まれるので、囲みのテキストは上に重ねた画像の輪郭に沿って流れ、囲みの側で行ごとに何かを指定する必要はありません。押しのける枠の中のキャプションやほかのテキストはそれぞれの矩形のままで、回転した枠は矩形で押しのけます。形がわからない画像も矩形で押しのけ、`textWrap`警告（理由は`noContour`）が出ます。形、しきい値、間隔については[文書形式 › 輪郭に沿った回り込み](/ja/docs/document-format-resources#輪郭に沿った回り込み)を参照してください。

```json
{ "name": "drawing", "exclude": "push", "wrap": "contour", "layer": 2,
  "placement": { "anchor": { "to": "#box", "edge": "top-right" } }, "width": { "value": 150, "unit": "mm" } }
```

### 装飾、柱、レイヤー

テンプレートの装飾（`decoration`。画像、罫線、ボックス、短いテキスト）は、枠のボックスが確定してから置かれるので、要素を枠に固定して（`"to": "#gasto"`）その枠についていかせることができます。[コネクター](/ja/docs/configuration-composed-pages#コネクター)は2つの枠を線で結び、言葉の量で枠が動いても線は枠から離れません。装飾のテキストからはそのページの属性を参照できます。ページブロックに`fondo="banda-retos"`と書けば`{attr.fondo}`になり、たとえば`"resourceId": "{attr.fondo}"`で背景の画像をページごとに選べます。柱とノンブルからもこの属性を参照できます。テンプレートの`header`や`footer`はそのセクションのものに代わり、`false`なら表示されず、どちらも指定しなければセクションの柱とノンブルが入ります。右から左へ進むページや縦組みのページでは、枠は鏡像または回転した流れに従い、装飾は紙面に残ります。行頭側・行末側の辺（`top-start`。[要素の配置](/ja/docs/configuration-headers-footers#要素の配置)を参照）に置いた要素は、どの版でもその枠のそばに来ます。

枠は`layer`の順に描かれます。装飾がレイヤー0、枠は既定でレイヤー1にあり、番号の大きいレイヤーが小さいレイヤーの上に、負のレイヤーは装飾の下に描かれます。`rotate`は枠を中身ごと、枠の中心を軸に任意の角度で回転させます。キャンバス、PDF、HTMLビューアー、固定レイアウトのEPUBのどれでも同じです。

### 収まらない内容

中身が枠より高く、続きを流す次の枠も、続けるページ（`overflow.continueIn`）もない場合、中身はすべて文書に残りますが、表示されるのは収まる分だけです。残りはページ単位の出力では枠の下端で切れ、警告[`frameOverflow`](#frameoverflow)がその量を示します。どの枠も受け取らない内容（流し込み枠がない、またはこのページの側のテンプレートに枠がない）は、テンプレートページの次のページの本文の流れに組まれます。

## 印刷以外：HTML、EPUB、タグ付きPDF

どの出力も、テンプレートページをMarkdownの順に読みます。テンプレートが枠を並べた順や、レイヤーを描く順ではありません。

- **リフロー型EPUB**：ページは1つのセクション（`<section class="pt-composed pt-composed-tema-cajas">`）になり、その先頭にページの改ページマーカーが置かれます。各枠はその中のブロック（`<div class="pt-frame pt-frame-dinero">`）で、内容がMarkdownに最初に現れる位置に置かれます。枠と、その`next`の連鎖が続く枠は、1つのブロックにまとまります。内容が追加ページに続く枠も同じです。断片はつなぎ合わされ、2ページにまたがって切れた段落は1つの段落になり、追加ページの改ページマーカーはその段落の中の、そのページの文章が始まる位置に入ります。囲みスタイルで描く枠は、そのスタイルの囲み（地色、罫、内側余白、本文）を保ち、`label`が囲みの見出しになります。スタイルのない枠はただのブロックです。装飾（背景の画像、カード、デザイン用の文字）は印刷ページのものなので出力しません。
- **図のラベル**：HTMLビューアーと固定レイアウトのEPUBは、描いたラベルを1つずつ、書いた順に画像の直後に文字として書き出します（`<div class="pt-figure-label">`、CSSの行列で回転）。スクリーンリーダーは画像の代替テキストを読んだあと、ラベルの語を読みます。EPUBに入る画像にはラベルの文字がありません。リフロー型の本では、単純なラベルを画像の上に重ねた1つのSVG（`pt-label-layer`）として描きます。座標は画像そのものの座標なので、文字は画像と一緒に拡大縮小します（postext 1.40以降）。太字やイタリック、スタイルの縁取りと下地、`rotate`による回転に対応します。縦組みのラベルと、数式・チップ・マーカーを含むラベルはSVGに含めません。右から左へ綴じる本のラベルは、紙面に置かれるとおりに描きます（postext 1.42以降）。各語は印刷で測ったx位置に置き、右から左へ書く文字の語は、右端を基準にした右から左向きの独立した文字として描くので、ブラウザーが字形をつなぎます。すべてのラベルは画像の後、図の中に並べます。画面には見えないリスト（`pt-figure-labels pt-hidden`）で、スクリーンリーダーは一度だけ読み上げます。描かれないラベル（アンカーが存在しないもの）は、代わりに画像の代替テキストの後に続きます。たとえば`ヨーロッパの地図（マドリード）`です。中国語と日本語のラベルは`（…、…）`、アラビア語のラベルは「،」で区切ります。
- **HTMLビューアーと固定レイアウトのEPUB**：どちらもテンプレートを当てた印刷ページを表示します。各枠は自分の囲みに収まり、`rotate`で回転し、内容があふれれば切り取られ、下のレイヤーの枠の上に描かれます。装飾はレイヤー0です。マークアップは枠を読む順に並べ、`z-index`でレイヤー順に描くので、支援技術はMarkdownの順にたどり、ページの見た目は印刷と同じになります。装飾の画像は支援技術から隠されます（`alt=""`）。装飾に使う書体は、SandboxがEPUBに埋め込む書体に含まれます。そのどれかを欠いたまま固定レイアウトのEPUBを書き出すと、`missingFont`で報告されます。
- **タグ付きPDF**：構造ツリーは同じ順に枠を読みます。各枠（または枠の連鎖）は見出し、段落、リストを含む`Div`です。追加ページに続いた枠の断片も同じ`Div`に入ります（ページの間で切れた段落は1つの`P`、継続マーカーはアーティファクトです）。枠の中の画像はそれぞれ`Figure`となり、その後に、描いたラベルごとに1つの`P`を書いた順に入れた`Div`が続きます。ラベルの縁取りと下地はレイアウトのアーティファクトなので、ラベルの語は一度だけ読まれます。装飾もレイアウトのアーティファクトです。

コードからは、図のラベルはそのブロックの`resourceBlock.labels`にあります。テキスト、アンカーまたは点、スタイル、ソースの範囲に加え、描いたラベルの`layout`（行、矩形、回転、見た目）と`rect`（描かれる位置。`sourceAt`はこれをもとにソースを返します）が含まれます。`composedReadingOrder(composedPaintOrder(page))`はページの装飾と枠を読む順に返します。

### frameOverflow

この警告は上の検査のようにソースを読んで出るものではなく、割り付けから出ます。ページが組み上がってから、検査パネル、`postext check`、文書の`contentWarnings`に現れます。

**原因**：枠に流し込んだ内容（スロットで指定したもの、または流し込み枠に入るもの）が枠より高く、続きを流す`next`の枠も残っておらず、[収めるための手順](#それでも収まらないとき)のどれを試しても収まりません。たいていは枠に収まる以上のテキストがある場合で、原文より長くなった翻訳や、`height`や`maxHeight`で高さを固定した枠がよくある例です。収まらない部分はページ単位の出力では枠の下端で切れますが、文書、ソースとの対応表、リフロー型のEPUBには残ります。警告にはテンプレート、枠、ページ、文書の`locale`、切れた高さ（`overflowMm`）、`configPath`（設定の中の枠を指すJSONポインターで、`/pageTemplates/0/frames/2`）、試した手順（`stepsTried`）、テキストと画像が最後にとどまった縮小率（`scale`、`imageScale`）、そして収めるための変更の案である`proposals`が付きます。

**対処**：修正案のどれかを適用します。どの案にも、そのページで割り出した値が付いています（[警告と修正案](#警告と修正案)を参照）。そうでなければ、枠を広げる、`next`で別の枠につなぐ、テキストを短くする、別のテンプレートでそのページを組む、のいずれかです。

空の枠も報告されます。どの枠もそれ以上返せない積み重ねで、`minHeight`や固定の高さより低く切り詰められた枠（解答欄、画像の枠）は、中身がまったくなくても切られた高さだけはみ出したことになります。修正の提案は、その枠自身の`minHeight`を下げるか、同じグループでそれより中身の少ない枠の`minHeight`を下げるもので、別の空の枠の場所を取ることはありません。

### frameContinuationLimit

**原因**：`overflow.continueIn`が`'next-page'`または`'template:<id>'`の枠が、収めきれない分を追加ページへ送り、そのページの枠がさらに残りを次へ送り、とページを重ねて、テンプレートページが加えられるページ数の上限である16ページに達しました（[文章が追加ページに続くとき](#文章が追加ページに続くとき)を参照）。残った部分は最後の追加ページで枠の下端で切れますが、文書、ソースとの対応表、リフロー型のEPUBには残ります。警告にはそのページのテンプレートと枠、加えたページ数（`pages`）、切れた高さ（`overflowMm`）、枠の`configPath`、ページが付きます。たいていは、追加ページで内容を受け取る枠がテキストよりはるかに小さい場合です。

**対処**：その枠を広げる（高さを上げるか、より大きな枠のある`overflowTemplate`を使う）か、テキストを短くします。数ページにわたって続く囲みは、たいてい本文の流れに置くほうが合っています。

### continueTargetMissing

**原因**：枠の`overflow.continueIn`が`'page:<id>'`なのに（[後ろのページへ飛ぶ](#後ろのページへ飛ぶ)を参照）、記事のあるページより後ろにページブロック`::::page{id="<id>"}`がありません。idのつづりが違う、ページブロックにそのidがない、規則が参照するページブロックの属性（`'page:{attr.sigue}'`）がない、ページブロックが前にある（`before: true`）、のいずれかです。残りは`'next-page'`と同じく、すぐ後に加えるページに続きます。警告にはテンプレート、枠、`target`（探したid）、枠の`configPath`、ページが付きます。このidは、本の後ろの章にあるページブロックのものでもかまいません。`buildDocument`だけで単独に組んだ章で`laterPageIds`がないときは、その章自身のページしか知りません。

**対処**：後ろのページブロックにそのidを付けるか、`continueIn`の名前、またはそれが参照するページブロックの属性を直します。記事より前のページは続きを受け取れないので、そのページブロックを記事の後ろへ移すか、後ろのページを指定します。

### frameCovered

**原因**：枠の一部が、その上に描かれたほかの枠（`layer`が大きいか、同じレイヤーでテンプレートの順で後にある枠）の不透明な部分の下にあります。写真の下に隠れたキャプション、切り抜き画像の下のタブ、帯の下に入った囲みの最後の数行などです。検査はページが組み上がってから、内容が枠に与えたボックスに対して行うので、スペイン語では何も隠れないページが、文章の長い版では覆われることがあります。枠が覆うのは塗り（スタイルの背景や`look.background`、タブ、帯）、画像、テキストの行です。輪郭線は何も覆いません。画像の形に沿ってテキストを押しのける枠（`wrap: 'contour'`）は、ボックスで行を覆うことはありません。覆われうるのは、枠の行、タブとタイトル、画像と表です。画像の上の言葉は報告しません。読めるかどうかはコントラストの検査が受け持ちます。0.3mmより細い重なりは接しているだけとみなし、1mm²に満たない組は数えません。

警告には、テンプレート、枠、覆っている枠（`coveredBy`、`coveredByPath`）、隠れた面積（`overlapMm2`）、覆われた最初の言葉（`text`）または画像（`picture`）、言語、ページが付き、覆われた枠の内容を指します。組ごとに1つの警告です。

**対処**：修正案はどれも、`frameOverflow`と同じくデータです。

- `layer`：覆っている枠の`layer`を、覆われた枠より下にします。それで別のものが隠れない場合にだけ提案します。
- `exclude`：覆っている枠に`'push'`を付け、覆われたテキストがその周りを回り込むようにします（本文の行が隠れる場合だけです）。
- `move`：`frame`、`dxMm`、`dyMm`で、組を離すための覆っている枠の最小の移動です。ページの上で試し、動かした枠とそこにアンカーした枠がほかのどの枠にも重ならず、それを収める範囲の中にとどまるときだけ提案します。どの方向でも重なりが残るときや、覆われた枠が覆っている枠にアンカーしているときは、移動を提案しません。

重なりが意図したもの（わざと本文の上にはみ出させた絵など）なら、どちらかの枠に`overlap: 'allow'`を指定します。postext 1.48以降。

### frameOutsideArea

**原因**：枠がそれを収めるものの外へはみ出しています。テキストが仕上がり線を越えて切れる、塗りや画像が塗り足しを越える（塗り足しがなければどちらも仕上がり線）、または枠のどこかが、その中にアンカーした枠やグループを越える、のいずれかです。最後の例は、カードの中にアンカーした注記（`'#card'`の`top-left`に、内側へずらしたもの）が、テキストに押されてカードの下端を越える場合です。ほかのボックスの外側の辺にアンカーした枠（`below`、`right-of`）は、そのボックスの中にあるとはみなしません。0.3mm未満のはみ出しは数えません。

警告には、`past`（`'trim'`、`'bleed'`、`'frame'`、`'group'`）、`target`（枠またはグループの名前）、`excessMm`（いちばん大きいはみ出し）、`sides`（辺ごとのはみ出し）、言語、ページが付きます。

**対処**：修正案は次のとおりです。`maxHeight`は枠が使える空間です（下端で固定した枠には提案しません。高さを小さくしても中に戻らないためです）。テキストの枠では、収まらなくなった分を続けるための`continueNextPage`が一緒に付きます。`minHeight`は、枠をアンカーした先の枠の高さを、はみ出した分だけ増やすものです。`move`は、はみ出しが1辺だけのときに枠を中へ戻す移動で、ほかの枠に重ならない位置に来る場合に提案します。わざとカードからはみ出させたバッジには`overlap: 'allow'`を指定します。postext 1.48以降。

## 文章が増えたとき

テンプレートページは、テンプレートが宣言した範囲の中で形を組み替えます。枠が積み重ねのグループになっているページで、最初の枠に長い文章を書くと、枠はそれが収まるまで高くなり、下の枠と、そこに固定した写真や装飾が下へずれます。テンプレートは1行も変わりません。文章を短くすれば、枠は宣言した高さに戻ります。`pin`を付けた枠や装飾の要素は、テンプレートが置いた位置にとどまるので、絵柄の上に載せておく必要のある囲みに使えます。積み重ねと並びが空間をどう分け合い、どの枠が先に譲るかはテンプレートで決めます。[設定 › グループが空間を分け合うしくみ](/ja/docs/configuration-composed-pages#グループが空間を分け合うしくみ)を参照してください。

枠が領域の下端に届き、グループのどの枠もそれ以上空間を譲れないときは、収まらない枠が次の節の手順を順に試します。グループが独自の警告を出すことはありません。

## それでも収まらないとき

中身が収まらない枠は、テンプレートが許す場所の空け方を1つずつ試し、最初にうまくいったところで止まります。各手順は前の手順を残したまま、次の順に試されます。

別のページへ続けられる枠は、この段階をもっと早く踏みます。`redistribute`の後、`scaleImages`と`shrinkText`の前です。数ページにわたる記事は1つの文字サイズを保ち、最後のページだけが前のページより小さく組まれることはありません。画像とテキストが縮むのは、それ以上続けられないとき、つまり続きを流すことで加えられる最後のページか、残りを受け取るはずの枠がまったく受け取らないときだけです。`fit.preferContinue: false`にすると表の順序のままになります。ページを増やすより数ポイント小さくなるほうがよい囲みに使います。

どの手順でも中身が収まらないときは、枠が下端で切れ、手順の中で到達した縮小率を保ったまま、割り付けが`frameOverflow`を報告します。追加ページの枠が、受け取った内容をまったく収められない場合は、それ以上先へ送りません（送ればページが際限なく増えます）。この枠も`frameOverflow`を報告し、試した手順に`continue`が含まれます。手順のたびにページ全体を組み直すので、結果はそのページだけで決まります。同じ入力からは同じページができ、あふれる枠はテンプレートの順に扱われ、あるテンプレートページを変えてもほかのページは元のままです。設定は[設定 › 内容が収まらないとき](/ja/docs/configuration-composed-pages#内容が収まらないとき)にあります。

続きを流すのは、[収めるための手順](#それでも収まらないとき)の段階の1つです。枠はまず高くなってグループの中で場所を空け、それでも足りないときは、画像やテキストを小さくする前に下端で切れます（`fit.preferContinue`が`false`なら別です）。テキストと画像は元の大きさのまま、断片の終わりに継続マーカーが付き、残りは切れた行から、受け取る枠の幅で改めて行分けされて続きます。失われる部分も重複する部分もなく、警告も出ません。

- **受け取る枠**：追加ページでは同じ名前の枠が内容を受け取ります。テンプレートにその名前の枠がなければ流し込み枠が、それもなければまだ使われていない最初の枠が受け取ります。`next`で枠をつないだ記事は、つながりの先頭から続きます。3つつないだ段の3段目の残りは、追加ページの1段目（つながりの先頭と同じ名前の枠、なければ流し込み枠）に続くので、自分自身に続く本文のテンプレートは、どのページのどの段も埋めます。同じページの複数の枠が同じテンプレートへ続くとき、そのテンプレートにそれぞれを受ける枠があれば、1枚の追加ページを共有します。なければ、後の枠は自分だけのページを使います。追加ページで何も受け取らない枠は空のままです。
- **何度でも続く**：それでも収まらない断片は、次の追加ページへさらに続きます。そのページの枠に自分の`overflow.continueIn`があればそれに従い、なければ内容を運んできた規則に従います。1つのテンプレートページが続けて加えるページは16ページまでで、最後のページでも収まらない分は切れ、[`frameContinuationLimit`](#framecontinuationlimit)として報告されます。追加ページの枠が小さすぎて何も受け取れない場合は、ページを加えずに`frameOverflow`を報告します。
- **切れる位置**：ページの上と同じです。見出しは最初の数行と一緒にとどまり、リストは両側に2項目ずつを残します（[枠をつなぐ](#枠をつなぐ)を参照）。囲みがまったくページに入らないときは、タブごと囲み全体が次へ続きます。空の断片の上にタブとマーカーだけがページに残ることはありません。このとき囲みは元のページで場所を取りません。また、その下の解答欄が元のページで本来の大きさを保てないときは、囲みは解答欄ごと次へ続きます。
- **ページに残るもの**：切れた枠がまずグループの場所を手放すので、その後の枠は大きさを保ちます。残りを同じテンプレートをもう一度組んだページに続けるときは、積み重ねの中ですぐ後にある空の枠（活動の囲みの下の解答欄のように、中身を受け取らない枠）が一緒に移ります。元のページではそれらは場所をとらず、追加ページでは囲みの残りの下で元の大きさを保ち、そこに固定した装飾も付いてきます。その追加ページのほかの枠は場所をとらず、装飾も描かれません。積み重ねはテンプレートでの最初の枠の位置を保つので、囲みの残りは積み重ねの始まる位置から始まり、ページのリードや柱にかかりません。
- **ふつうのページ**：追加ページは本のページです。ノンブルが付き、そのテンプレートの（またはセクションの）柱が入り、そのページの側の`variants`が当たり、ページブロックの`{attr.x}`も装飾から参照できます。`spread: true`の`overflowTemplate`は次の偶数ページから始まり、必要ならその前に偶奇合わせの白ページを入れ、続く奇数ページまでを使います。`overflowTemplate`が単ページのテンプレートである見開きは、単ページに続きます。ページブロックの後の本文は、最後の追加ページの次のページから始まります。
- **id**：n番目の追加ページの枠は`cp0:<name>~<n>`です。内容を受け取る枠には、ページブロック自身のページで最初に続きを送った枠の名前が付く（`cp0:dinero~1`、`cp0:dinero~2`）ので、どの枠が受け取っても、選択は同じ要素を指したままです。各枠は、どの枠から続いてきたか、どの枠へ続くかを記録し（`continuedFrom`、`continuesTo`）、ページの`VDTPage.composed.continuationOf`はページブロック自身のページのインデックスです。断片のブロックは、分割された囲みと同じく、囲みのidに`-cont-<n>`を付けたidが付きます。
- **組み直し**：内容が続くテンプレートページは、ビルドのたびに追加ページごと新しく組まれます。ページのメモが保持するのは、内容がそのページに収まるページだけです。

### 後ろのページへ飛ぶ

雑誌の記事は、自分のページに収まらないと、ほかの記事を飛び越えて後ろのページへ続きます（「47ページへ続く」）。`overflow.continueIn: 'page:<id>'`は、残りをその`id`を付けたページブロックへ送ります。章の中で後ろにあれば、どこにあってもかまいません。

```markdown
::::page{template="articulo" sigue="p47"}
…
::::

::::page{template="otra"}
…
::::

::::page{template="saltos" id="p47"}
…
::::
```

```json
{ "name": "cuerpo", "flow": true,
  "overflow": { "continueIn": "page:{attr.sigue}",
    "mark": "{page} ページへ続く", "fromMark": "{page} ページから続く" } }
```

- **どのページへ**：`<id>`は`{attr.name}`でもよく、その場合は記事のあるページブロックの属性から読まれます。1つの記事テンプレートですべての記事をまかない、それぞれの飛び先はMarkdownに書けます。
- **どの枠へ**：`'page:<id>#<frame>'`で指定した枠です。指定がなければ、送り出すつながりの先頭と同じ名前の枠、それもなければ、そのページ自身の中身が空のまま残す最初の枠です。そのページのほかの枠には、そのページ自身の中身が入ります。
- **飛んだ後**：その枠に収まらない分は、飛び先のページの後に加えるページへ続き、そこからは`'next-page'`と同じです。飛び先に空いた枠が見つからない記事も、そこへ続きます。
- **idとつながり**：飛び先のページの枠は自分のidを保ちます（`cp2:resto`）。送る枠の`continuesTo`と受け取る枠の`continuedFrom`が断片を結び、送り出したページの再配置の記録には「cuerpo continued on page 47」と書かれます。リフロー型のEPUBとタグ付きPDFは、記事をひと続きのものとして読みます。
- **後ろにないページ**：後ろのどのページブロックにもないidを指定すると[`continueTargetMissing`](#continuetargetmissing)が出て、残りは次のページに続きます。
- **後ろの章ファイルにあるページへ。** 記事ごとに章ファイルを分けた雑誌でも、同じように飛べます。`id`を付けたページは、本の後ろの章にあってもかまいません（postext 1.41以降）。送る側の章が残りを渡し、そのページのある章が、同じファイルの中の飛び先と同じように、そのページが空けている枠に残りを組みます。残りの中の脚注、見出しや図の番号、参照は、元の章が付けた番号のままで、マークには本全体のページ番号が印刷されます。「次は47ページへ」は、そのページのある章が印刷したとおりのページを指し、間の章がページを足しても変わりません。ほかの章から来た語をクリックすると、その語が書かれた章のMarkdownにカーソルが入ります。1つのページに複数の記事を送った場合は、章の順に空いた枠を使います。記事を編集するとそのページのある章が組み直され、間の章を編集しても組み直されません。タグ付きPDFは、残りをそのページの上で、ページ自身の内容の後に読みます。リフロー型のEPUBでは、そのページのある章の中で読みます。残りは本文の組版で組まれ、そのページのある章のスタイル付き節の組版は使いません。残りに書かれた索引マーク、アンカー、見出しは、記事が始まるページではなく、そのページのある章がその語を組んだページのものとして載ります（索引、目次、参照、PDFの移動先のいずれも。postext 1.42以降）。Sandboxのキャンバスでは、送った側の章のエディターの選択範囲とカーソルが、移った語の上に描かれます。

## 見開き

`spread: true`のテンプレートは、向かい合う2ページを1枚として扱う版面です。のどをまたぐ帯、片方の小口からもう片方の小口まで続く画像の帯、左右に並ぶカードなどを置けます。ページの開始行では`spread`でそれを示します。

```md
::::page{template="linea-tiempo" spread}
# Cómo medimos el tiempo

Para saber cuándo comer, trabajar o descansar, las personas siempre han necesitado medir el tiempo…

:::frame{slot="banda-2"}
Con relojes de máquina
:::

::resource{id="tira-tiempo" slot="tira"}
::::
```

- **始まる位置**：見開きはいつも偶数ページから始まり（左から右へ読む本では左ページ、右から左へ読む本では右ページ）、続く奇数ページまでを使います。前の本文が偶数ページで終わると、次のページは白ページになり（漫画の見開きの前と同じ、偶奇合わせの白ページ）、2つの半分が向かい合うようにします。終了行の後の本文は、その奇数ページの次のページから始まります。
- **1枚の版面**：枠は2ページ分の幅の1枚の版面に置かれます。`content`の領域は一方のページの外側の余白からもう一方の外側の余白までで、内側の余白は2つともその中に含まれます。`trim`は仕上がりの2ページを並べたもの、`bleed`は天・地・左右の小口に塗り足しを加えたもので、のどには塗り足しを付けません。`grid`は全体の幅を分けるので、6列なら各ページに3列ずつになります。右から左へ読む本では、版面もページと同じく左右が反転し、最初の列は右ページに来ます。
- **のど**：`gutter`はのどを中心とするその幅の帯です。`crossGutter: true`のない枠はこの帯に入りません。帯全体をまたぐ枠は、中心のある側で帯の端まで切り詰められ、内側の端が帯の中に入る枠はそのまま帯の外へ移ります。`auto`の高さは狭くなった幅で測り直し、ページの再配置の記録にその変更が記録されます（`resized`または`moved`、原因は`gutter`）。`gutter`がなければ帯はのどそのものなので、折り目をまたぐのは指定した枠だけです。
- **のどをまたぐ枠**：`crossGutter: true`の枠はのどをまたいでかまいません。その本文は、枠の中心があるページで一度だけ読まれます。向かいのページは自分の側の半分を描き、自分の版面の端で切るので、帯や画像は開いた本の上で一続きに見えます。タグ付きPDFではこの半分をアーティファクトとし、HTMLでは支援技術から隠すので、選択や検索でもテキストは一度しか見つかりません。
- **装飾**は版面全体に一度だけ組まれ、同じようにのどで切り分けられます。地色、2ページにまたがるカード、右ページの柱などです。`#枠名`にアンカーした要素は、その枠が置かれたページについていきます。見開きは左右両方のページを含むので`variants`は使えません。`header`と`footer`は各ページで通常のページと同じように働きます。

キャンバス、Sandboxの見開き表示、Folioでは2ページが並んで表示されます。PDFは2ページで、それぞれ塗り足しの位置で切られます。固定レイアウトのEPUBでは2ページに`page-spread-left`と`page-spread-right`、さらに`rendition:spread-both`を付けるので、リーダーは縦向きでも横向きでも2ページを並べて表示します。リフロー型のEPUBは、ほかのテンプレートページと同じくMarkdownの順に枠を読みます。

### spreadMismatch

**原因**：ページの開始行とテンプレートが食い違っています。開始行に`spread`があるのにテンプレートが1ページ分か、テンプレートが見開き（自身の`spread: true`、または`extends`で継承したもの）なのに開始行に指定がありません。組版はテンプレートに従い、見開きのテンプレートは向かい合う2ページに、それ以外は1ページに組まれます。警告にはテンプレート、開始行の指定（`fence`）、テンプレートの指定（`templateSpread`）が入り、`spread`属性を、開始行にそれがなければテンプレート名を指します。

**対処**：開始行をテンプレートに合わせてください。見開きのテンプレートなら開始行に`spread`を書き、1ページのテンプレートなら開始行から外すか、別のテンプレートを選びます。

## テキストをスタイルに置いた本の移行

テンプレートページより前に作られた本は、各ページのテキストを見出しスタイルの中に持っていることがあります。各ページに隠れた見出しがあり、その柱が各テキストを印刷されたページと同じ位置に置く作りです。*設定内に置かれた本文*の検査がこれを示します。Sandboxでは、検査パネルの**テキストをMarkdownへ移す**が、各ページのデザインを、テキストがあった位置に枠のあるページテンプレートに、各ページを、テキストを`:::frame`のスロットに入れたページブロックに変えます。各ページの移す前と後を見せ、元に戻すこともできます。[テキストをMarkdownへ移す](/ja/docs/sandbox-composed-pages#テキストをmarkdownへ移す)を参照してください。コードからは`moveTextToMarkdown({ config, chapters, metadata }, options)`が同じことを行い、新しい設定、章、レポートを返します。

`labelsOnPictures: true`（postext 1.38以降）を指定すると、デザインが画像の上に置いた語は枠ではなく、その画像のラベルになります。対象は、1行で4語以内、本文の4分の3以下の大きさ（`labelsOnPictures: { maxFontSize }`で別の上限を指定できます）で、矩形が同じデザインの画像の内側にある文字です。画像は装飾から外れ、描かれていた位置の枠になり、その中に`:::figure`と文字ごとの`::label`行が入ります。各文字は画像のリソースのアンカーになり、デザインが置いていた位置（1行目のベースライン、そろえが示す側、矩形の幅）に、見た目に合わせたラベルスタイルが付きます。入力には本の`resources`を渡してください。結果はアンカー付きのリソースを返し（`result.resources`）、デザインが引き伸ばしていた矩形より小さいビットマップには、その幅になる`resolution`を設定します。複数のページに出る画像はアンカーを共有します。レポートの`labels`は画像、ラベル、アンカー、ラベルスタイルの数です。Sandboxのダイアログでは、ラベルにできる語が本にあるとき、これをオプションとして示します。既定ではオフで、必要なときにオンにします。デザインが画像の上に装飾（地図を横切るタグ）を描いていて、画像の下には何もない場合、画像の枠は装飾より下のレイヤー`-1`に置かれ、タグは地図の上に残ります（postext 1.40以降）。画像の下にも装飾がある場合や、装飾が画像のラベルに重なる場合は、1つの枠では両方の順序を保てません。枠はレイヤー0のままで、そのページは見た目が変わるかもしれないページとして報告されます（`overPicture`）。

## コードから使う

`composedPages(blocks)`は、章を解析したブロック（`parseMarkdownWithIssues(markdown).blocks`）を読み、ページブロックごとに1つのノードを順に返します。ノードには、`template`、`spread`、各値のソース範囲（`attrSources`）を伴う`attrs`、`fenceIndex`（章の中でのページブロックの通し番号で、どの言語でも同じ）、`slots`（スロットごとのブロックの添字。Markdownの順）、`unassigned`（スロットのないブロック）、そしてページ全体のソース範囲が入ります。ブロックは、自分が指定するスロットを、値のソース範囲とともに`ContentBlock.slot`に持ちます。図は`resourceBlock`で、その`figure`に属性とラベルが入り、各ラベルにはテキスト、インラインのスパン、Markdownへ戻るソースマップがあります。`checkComposedSlots(pages, config)`は、それらのページについてスロットの警告3種を返します。

割り付けの後、テンプレートページの`VDTPage.composed`には、テンプレート、適用されたバリアント、ページブロックの属性が記録されます。枠ごとには、id（`cp0:dinero`。ページブロックの通し番号と枠の名前で、どの言語でも同じ）、ボックス、レイヤー、回転、収まらなかった中身の高さ（`overflowPx`）、続きの元や先の枠、設定の中のパス（`/pageTemplates/0/frames/2`）、ブロックのidが入ります。これらのブロックは`page.floats`と`doc.blocks`にある通常の囲みのブロックで、ソース範囲も持っているので、Sandboxのプレビューで回転していない枠をクリックすると、そのMarkdownに移動します。`composedPaintOrder(page)`はレンダラーが枠と装飾を描く順序を、`frameMatrix(frame)`は枠の回転を返します。

## ソースマップ

テンプレートページに描かれるものは、どれも自分がどこに書かれているかを知っています。そのため、エディターはページ上の一点からMarkdownや設定へ、またMarkdownの一部からそれがページ上で何になったかへとたどれます。

`sourceAt(doc, pageIndex, x, y)`は、組み上がったページ上の一点（用紙の左上を原点とするページピクセル）を受け取り、そこにあるものを内側から順に返します。各要素のあとに、それを含む要素が続きます。囲みの中の1文字なら、その行、段落、枠、枠の属するグループ、テンプレートが続き、装飾の中の1語なら、そのデザイン要素、装飾、テンプレートが続きます。各要素は`level`、安定した`id`、`source`を持ち、たいていはページ上の`rect`（回転した枠の`rotate`をかける前の、正立した位置）も持ちます。

右から左へ進むページや縦組みのページでは、枠はページの版面の流れの座標に置かれ、紙面では鏡像になるか四分の一回転して見えます。装飾と柱は紙面に残ります。`sourceAt`は引き続き紙面の点を受け取り、枠については換算します。`rect`が流れの座標にある要素には`flow: true`が付きます（`sourceAt`、`elementsForSource`、`findElement`のいずれでも）。`flowRectToPage(page, rect)`で紙面上の枠が、`flowToPage(page, x, y)`でその中の点が得られます。postext 1.38までは、このようなページの枠上の紙面の点からはテンプレートしか見つかりませんでした。

レベルは内側から順に`text`、`attr`、`label`、`resource`、`line`、`block`、`box`、`frame`、`group`、`design`、`slot`、`template`です。枠とテンプレートは、含んでいるMarkdownの範囲である`content`も持ちます。枠ならそのスロットの内容、テンプレートならページブロック全体です。`file`は、ホストがオプションで渡す名前です（`{ file: 'tema-1.md' }`。複数の章をつないだ文書なら、ページ番号を引数にとる関数）。

```ts
import { buildDocument, sourceAt, elementsForSource, findElement } from 'postext';

const doc = buildDocument({ markdown, resources }, config);
const chain = sourceAt(doc, 0, 640, 1180, { file: 'tema-1.md' });
// [ { level: 'text', id: 'cp0:dinero-c0@12', source: { kind: 'markdown', start: 677, end: 678, file: 'tema-1.md' } },
//   { level: 'line', … }, { level: 'block', id: 'cp0:dinero-c0', … },
//   { level: 'frame', id: 'cp0:dinero', source: { kind: 'config', path: '/pageTemplates/0/frames/2' }, content: { start: 665, end: 942 } },
//   { level: 'template', id: 'cp0', source: { kind: 'config', path: '/pageTemplates/0' } } ]

elementsForSource(doc, 677, 690); // その範囲にかかる行、ブロック、枠、ページ、デザインのテキスト
findElement(doc, 'cp0:dinero');   // 組み直したあとの同じ枠と、その rect
```

`elementsForSource(doc, start, end)`は逆向きにたどり、範囲にかかる行、ブロック、枠、テンプレートページ、デザインのテキストのそれぞれについて`{ pageIndex, element }`を返します。枠の下端より下に組まれた行には`clipped: true`が付きます。ページでは切り取られますが、ソースマップには残ります。見開きでは、のどをまたいで向かいのページで読まれる枠の半分が、`sourceAt`でも`elementsForSource`でも、表示しているブロックのidと`facing: true`の要素として返されます。このとき`elementsForSource`が各ページに返す枠の`rect`は、そのページが描く部分です。のどの近くから始まる帯でも、両方のページにクリックできる点があります。図のラベルは、画像のどこに描かれていても、そのidとアンカーを持つ`label`レベルの要素として返されます。

**安定したid。** テンプレートページは`cp<n>`で、`n`は章の中でのページブロックの順番です。枠は`cp<n>:<枠名>`（後のページへ続く内容のk番目の断片には`~<k>`が付きます）、枠の中のブロックは`cp<n>:<枠名>-c0`、`-c1`…、グループは`cp<n>:group:<名前>`、装飾や柱の要素は`cp<n>:decoration:<id>`、`cp<n>:header:<id>`、`cp<n>:footer:<id>`、図のラベルは`cp<n>:<スロット>:label:<アンカー>`です。どれも位置にも文字にもよらないので、何度組み直しても、章のどの言語版でも同じです。編集しても選択は残り、翻訳でも同じ枠が見つかります。`findElement(doc, id)`で要素をもう一度見つけられます。

**目次の項目。** `:::toc`の各行は、挙げている見出しが章のMarkdown本文のどこにあるか（アウトラインと同じく、フロントマターは数えません）を`tocEntry.headingSource`に持ちます。`sourceAt`はそれを行のブロックの`heading`として返します。

**1ページだけ組み直す。** テンプレートページの組版結果は、読んだものごとに保存されます。テンプレート、そのページのMarkdown、スタイルとフォント、言語、用紙の表裏、寸法です。後の組版で同じページに出会えば（次のパス、章の別の箇所の編集、同じworkerでの再ページ付け）、そのまま使います。ページの中を編集したり、ページブロックの属性を変えたりすると、そのページだけが組み直されます。テンプレートを変えると、それを使うすべてのページが組み直されます。脚注、相互参照、文献引用、目次を含むページは、印刷する内容が本のほかの部分によって決まるため、毎回組み直されます。見開きも、2つのページを1枚の紙として組むので、同じ扱いです。`VDTComposedPage.layoutKey`はページの枠のキーで、`composedPagePaintKey(page)`はそこに枠のまわりのもの（柱とノンブル、装飾、ページ番号）を加えます。キーが変わらないあいだ、ホストは描いたピクセルをそのまま残せます。SandboxのCanvasはそうしています。1ページを編集すると、描き直すのはそのページだけです。

## 漫画ページ

漫画ページ（`:::page{split}`）は、コマ割りから枠が生成されるテンプレートページです。コマごとに1つの枠があり、それぞれに安定したID`cm<n>:<名前>`、斜めのセルには多角形、`box`による囲みスタイル、文章のコマには流し込まれたMarkdownがあります。[漫画 › 漫画ページとテンプレートページ](/ja/docs/comics#漫画ページとテンプレートページ)を参照してください。
