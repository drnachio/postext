# Skill per a agents

**Converteix una publicació existent en un projecte de Postext amb un agent de programació.**

Molta gent arriba a Postext amb un llibre que ja existeix: un manual en PDF
d'impremta, un informe en Word, un curs en PowerPoint, un catàleg en InDesign,
un EPUB. Portar-lo implica dues feines:

- **El contingut**: el Markdown enriquit de cada capítol, amb les seves
  directives i microformats.
- **El disseny**: un manifest de configuració que reprodueixi les regles de
  maquetació de l'original (geometria de pàgina, retícula de base,
  tipografia, obertures, capçaleres, requadres, flotants, taules, parts).

Un LLM pot fer bona part d'aquesta feina, però només si sap com
funciona Postext. El Markdown de Postext no és CommonMark, i la configuració
té paranys que només es veuen quan una pàgina surt malament. La skill
**`postext-port`** reuneix aquest coneixement i les eines amb què hem
construït tots els presets del Sandbox, perquè el teu agent pugui fer bé
l'adaptació.

Segueix el format obert [Agent Skills](https://agentskills.io), així que
funciona amb Claude Code, Codex, Cursor, Gemini CLI, GitHub Copilot, OpenCode
i [molts altres agents](https://skills.sh).

## Mira el tutorial

Cinc minuts, sense programar: prepara la carpeta, aplega els originals
vectorials, afegeix un PDF de referència, demana-ho a l'agent i revisa el
resultat al Sandbox.

## Què conté la skill

- **Un flux de treball**:
  1. acordar l'encàrrec;
  2. inventariar l'original;
  3. mesurar el disseny en una fitxa d'especificacions;
  4. crear l'esquelet del projecte;
  5. extreure el contingut;
  6. revisar-lo i polir-lo com a Markdown de Postext;
  7. preparar fonts i imatges;
  8. verificar pàgina a pàgina;
  9. empaquetar.
- **Referències**:
  - el format de document i el manifest de configuració, tots dos
    contrastats amb el motor;
  - el format de projecte (paquet);
  - una guia per format d'origen;
  - un mètode d'anàlisi del disseny;
  - un catàleg de casos de maquetació ja resolts: parts amb color
    propi, obertures de capítol, poesia, glosses al marge, notes a peu de pàgina,
    índexs analítics,
    requadres flotants, partits i imbricats, originals vectorials per a
    impremta, figures amb text viu, imatges en cel·les, taules apaïsades,
    edicions bilingües i més;
  - llibres xinesos, en horitzontal o en vertical i enquadernats per la
    dreta: què preguntar a l'encàrrec (escriptura, regió, direcció,
    enquadernació), com mesurar una retícula de caràcters, com llegir PDF
    verticals, el ruby i el warichu d'InDesign, la maquetació d'Àsia
    oriental de Word i els EPUB de dreta a esquerra, i com reduir les
    fonts CJK als caràcters del llibre (vegeu [Composició xinesa](/ca/docs/chinese-layout));
  - llibres japonesos, novel·les de bunko i tankōbon en vertical i
    enquadernades per la dreta o llibres tècnics en horitzontal: la llengua
    que activa les regles japoneses (`ja`, mai una etiqueta xinesa), què
    preguntar (direcció, retícula, furigana, notes, l'ortografia de
    l'edició), com mesurar la caixa en caràcters i línies, el marcatge de
    furigana i bōten, els textos d'Aozora Bunko convertits amb `aozora.py`,
    els escanejos d'edicions de domini públic de la Biblioteca Nacional de
    la Dieta i les fonts japoneses reduïdes sense perdre els kana ni les
    formes verticals (vegeu [Composició japonesa](/ca/docs/japanese-layout));
  - llibres àrabs, moderns o clàssics i vocalitzats, compostos de dreta a
    esquerra i enquadernats per la dreta: la llengua que posa tot el llibre de dreta a esquerra,
    què preguntar (regió i xifres, vocalització, vers, índex al final), com
    mesurar una pàgina emmirallada, com llegir l'àrab de PDF, Word i
    Wikisource, els poemes com a `:::verse`, les notes «(١)» per pàgina i
    les fonts àrabs reduïdes sense perdre les taules d'enllaç (vegeu
    [Composició àrab](/ca/docs/arabic-layout));
  - còmics, manga i tires de premsa: la divisió que talla una pàgina en
    vinyetes, les imatges de les vinyetes amb les àncores dels personatges
    i les zones segures, un guió per llengua que el motor retola (bafarades,
    cartel·les, onomatopeies), el manga de dreta a esquerra i les edicions
    àrabs, i com adaptar-los a partir de dibuixos sense text i les
    traduccions, des de pàgines escanejades amb text o des d'un guió amb
    imatges generades (vegeu [Còmics](/ca/docs/comics));
  - les pàgines compostes: les pàgines fixes de llibres de text, quaderns i
    revistes portades com a plantilles de pàgina amb marcs que s'omplen des del
    Markdown, quina ronda de port admet el Postext instal·lat i les
    comprovacions que ha de passar cada edició (consulta [Pàgines compostes](/ca/docs/composed-pages));
  - l'objecte imprès: com llegir el paper, l'enquadernació, les cobertes
    i el llom de l'original i traduir-los als paràmetres `folio` que mostra el
    [visor Folio](/ca/docs/sandbox-previews#pestanya-folio) i que el linter comprova.
- **Scripts** (Python i Node), descrits a la secció següent.

## Instal·lació

### Qualsevol agent (skills.sh)

La CLI [`skills`](https://skills.sh) detecta els teus agents i hi instal·la la skill:

```bash
npx skills add drnachio/postext --skill postext-port
```

Tria agents concrets amb `-a` i instal·la-la per a tots els teus projectes amb `-g`:

```bash
npx skills add drnachio/postext --skill postext-port -a codex -a claude-code -g
```

El web publica la mateixa skill, així que això també funciona:

```bash
npx skills add https://postext.dev
```

### Plugin de Claude Code

El repositori de Postext també és un marketplace de plugins de Claude
Code. Dins de Claude Code:

```text
/plugin marketplace add drnachio/postext
/plugin install postext@postext
```

O des del terminal:

```bash
claude plugin marketplace add drnachio/postext
```

```bash
claude plugin install postext@postext
```

### Que la instal·li l'agent

Pots demanar-ho al teu agent, per exemple: *«Instal·la la skill de Postext per
portar publicacions (`npx skills add drnachio/postext --skill postext-port`) i
fes-la servir per portar aquest PDF»*. Els agents que llegeixen
`https://postext.dev/llms.txt` hi troben aquesta pàgina i l'ordre
d'instal·lació.

### Eines que fan servir els scripts

```bash
python3 -m pip install pymupdf pillow fonttools brotli numpy
```

```bash
brew install pandoc poppler
```

```bash
mkdir -p ~/.cache/postext-tools && cd ~/.cache/postext-tools && npm init -y && npm i postext postext-pdf postext-citeproc react @pdf-lib/fontkit @napi-rs/canvas
```

Cal Pandoc per a fonts en Word, PowerPoint, EPUB i HTML, poppler
per a les imatges de pàgina de la font, i numpy per a `comic_panels.py`. Els paquets de Node fan funcionar el
renderitzador sense navegador (Node 22.15 o posterior); `@napi-rs/canvas` és un
canvas precompilat amb què pinta les pàgines del llibre directament en
JPEG. Eines opcionals: `ocrmypdf` per a
escanejos, ImageMagick, i veraPDF per comprovar PDF/UA.

```bash
mkdir -p ~/.local/bin && curl -fL -o ~/.local/bin/postext https://github.com/drnachio/postext/releases/latest/download/postext-macos-arm64 && chmod +x ~/.local/bin/postext
```

Tria el fitxer del teu sistema (`postext-macos-arm64`, `postext-macos-x64`, `postext-linux-x64`, `postext-linux-arm64`, `postext-linux-x64-musl`, `postext-windows-x64.exe`); amb Node, també funciona `npx postext-cli`.

El cicle de treball funciona amb la [línia d'ordres](/ca/docs/command-line), un executable autònom que no cal instal·lar: l'agent manté el projecte descomprimit i deixa `postext build --watch` en marxa sobre les pàgines en què treballa, de manera que cada canvi apareix com a JPEG al voltant d'un segon després, fins i tot en un llibre llarg. Els paquets de Node són opcionals: executen `render.mjs`, que afegeix les comprovacions addicionals del Sandbox. Tots dos maqueten el llibre amb `bodyText.shapingLanguage: 'host'`, digui el que digui la configuració, de manera que una línia pot acabar en una paraula diferent que al Sandbox (vegeu [Diferències amb el Sandbox](/ca/docs/command-line#diferències-amb-el-sandbox)).

## Com fer-la servir

Deixa els fitxers d'origen a la teva carpeta de treball i demana l'adaptació.
Per exemple:

- *«Porta els capítols 1 a 3 de `manual.pdf` a Postext, reproduint-ne la
  maquetació a dues columnes, les obertures de capítol i els requadres.»*
- *«Converteix `curso.docx` en un llibre de Postext. Els estils "Nota" i
  "Actividad" són requadres.»*
- *«Converteix `presentacion.pptx` en un dossier de Postext: les diapositives
  són seccions i les notes de l'orador, el text.»*
- *«Tenim el paquet d'InDesign (IDML + PDF d'impremta) d'aquest manual.
  Construeix el preset de Postext del capítol 1 en castellà i anglès.»*

Per a un llibre d'InDesign, dona a l'agent la carpeta que crea **File ›
Package** a InDesign (l'`.idml`, el PDF d'impremta, les fonts i les
il·lustracions enllaçades). La skill en dedueix les regles de maquetació,
cosa que l'importador d'IDML no fa: [InDesign: importar, exportar i
portar](/ca/docs/indesign) compara totes dues vies.

L'agent segueix el flux de treball:

1. **Encàrrec.** Pregunta el que no pot deduir: reproducció fidel o
   redisseny, un capítol de mostra o el llibre sencer, llengües, impressió o
   pantalla, i els drets sobre textos, imatges i fonts.
2. **Inventari i mesurament.** Llegeix l'original i escriu una fitxa amb les
   dades mesurades: format, marges, columnes, interlineat, rols tipogràfics,
   paleta, obertures, capçaleres, famílies de requadres i hàbits de
   col·locació. Classifica cada pàgina com a text corregut o com a pàgina
   composta (requadres, rètols i mapes en llocs fixos). Amb Postext 1.35 o
   posterior, agrupa les pàgines compostes per tipus i compon cada tipus a
   partir d'una plantilla de pàgina, de manera que la maquetació es manté
   idèntica i el text continua sent editable i traduïble. Amb una versió
   anterior, si més d'un terç de les pàgines són compostes, et pregunta si
   prefereixes una maquetació idèntica o un text que puguis editar i traduir.
3. **Projecte.** Crea `mi-libro/` amb un generador `build_preset.py` que
   conté la fitxa en forma de constants i genera `preset.json`.
4. **Contingut.** Extreu capítols en esborrany amb l'extractor adequat i
   els revisa i els poleix com a Markdown de Postext: requadres, estils de paràgraf, parts,
   atributs d'encapçalament per a les obertures, citacions `:ref`, recursos de
   taules i figures.
5. **Verificació.** Passa el linter i deixa `postext build --watch` en marxa
   sobre el projecte descomprimit: canvia un capítol o un paràmetre, mira el JPEG
   de la pàgina, repintat al voltant d'un segon després, i torna a canviar
   fins que els salts de pàgina, les figures i els requadres coincideixen
   amb la font pàgina a pàgina. A cada fita passa les comprovacions
   completes (`postext check` i el linter). El PDF només es genera per a les
   comprovacions d'impremta, no cada vegada que mira les pàgines.
6. **Lliurament.** Fixa el paper, l'enquadernació i les cobertes del llibre
   per al visor Folio i empaqueta `mi-libro.postext`.

Obre el resultat al [Sandbox](/ca/sandbox): **Llibres → Nou → Obrir
un fitxer .postext…**. En importar-lo, el Sandbox agafa els capítols i els textos de l'idioma en
què el tens. Per treballar amb una carpeta de projectes en una còpia local de
Postext, defineix `POSTEXT_PRIVATE_PRESETS_DIR` (consulta
[Sandbox](/ca/docs/sandbox)).

### Carregar el resultat des del codi

El fitxer lliurat no depèn del Sandbox. El paquet `postext` l'obre amb `openBundle`, compon el llibre amb `buildBundle` i el renderitza en canvas, HTML o PDF (consulta [Paquets](/ca/docs/configuration-bundles#paquets-fitxers-postext)). Així, una adaptació pot alimentar directament un programa. Quan cal retocar el que produeix aquest programa, torna a exportar-lo a un `.postext` amb `createBundle`, retoca'l al Sandbox i torna a carregar el fitxer corregit. El `render.mjs` de la skill, que compon sense navegador, accepta tant un `.postext` empaquetat com una carpeta de projecte.

## Què cal esperar

- **Els extractors produeixen esborranys; l'agent els revisa i els poleix.**
  Compta que caldrà revisar cada capítol amb les pàgines originals al costat.
  D'aquesta revisió depèn la qualitat.
- **El text es queda al Markdown.** La configuració guarda el disseny i cada
  paraula del llibre és als capítols, de manera que una correcció o una
  traducció és una edició del Markdown. Amb Postext 1.35 o posterior, les
  pàgines compostes són plantilles de pàgina a la configuració amb marcs que
  s'omplen amb el Markdown de cada capítol: un requadre creix amb una
  traducció més llarga i empeny els que té a sota, i des de la 1.37 els noms
  d'un mapa són rètols escrits al Markdown. Amb una versió anterior es munten
  amb requadres fixats al seu lloc, imatges de pàgina sense text i figures SVG
  amb rètols vius. L'informe diu quina de les dues vies ha fet servir l'agent
  i amb quina versió. Quan Postext no pot expressar alguna cosa sense escriure text a
  la configuració, l'agent s'atura, descriu el que falta en un esborrany
  d'incidència i t'ho pregunta. La skill no modifica mai el motor per
  adaptar-lo a un llibre.
- **Un sol fitxer per a tots els idiomes.** Una traducció és un joc de
  capítols dins del mateix `.postext`, amb els peus i els rètols de figura
  propis, comprovat amb `postext check` en cada idioma.
- **Els drets els decideixes tu.** L'agent pregunta abans de reproduir
  imatges o fonts amb llicències dubtoses. Les fonts amb llicència es
  marquen `redistributable: false`, així que els projectes exportats les
  deixen fora.
- **Fidelitat on importa.** L'objectiu és la mateixa retícula, tipografia,
  obertures, requadres, col·locació de figures i salts de pàgina a la
  majoria de les pàgines (amb una diferència màxima d'una pàgina per capítol), no
  talls de línia idèntics.

## On és

La skill és al repositori a
[`plugins/postext/skills/postext-port`](https://github.com/drnachio/postext/tree/main/plugins/postext/skills/postext-port).
Cobreix tots els casos que van sorgir en construir els presets del Sandbox,
públics i privats. Si una adaptació es troba amb un cas que encara no cobreix,
obre una incidència o una pull request que millori la skill, i la pròxima
adaptació el tindrà resolt.
