# 配置：模板页


## 页面模板

模板页的版式来自配置中的**模板**，内容来自`::::page{template="…"}`块中的Markdown。模板给一些矩形命名，这些矩形叫做**框**；Markdown按名称（即框的槽位）把每一段内容送进对应的框。Markdown中从不出现几何信息，模板中也从不出现正文文字。`pageTemplates`属性保存全书的模板：

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

只设了`id`和一个框的模板就是一整页，这个框占满版心。其余字段都是可选的：

### 框

框是接收排好的内容的具名矩形。它的`name`就是Markdown所请求的槽位，在所属模板中唯一（组也不能使用框的名称，因为锚点用同样的方式指向两者）。

模板有网格时，框按它的`grid`单元格放置，否则按它的`placement`放置，后者与设计元素的定位相同：一个锚点（`'container'`表示区域，`'page'`、`'bleed'`，或用`'#name'`表示另一个框或组）、一条边、一个偏移和一个尺寸。锚定到另一个框的框随之移动。两者都没有时，框从区域的左上角开始，宽度与区域相同，高度按它的高度规则确定。内容怎样排进各框、怎样串接和裁切，见[模板页 › 页面如何排出](/zh/docs/composed-pages#页面如何排出)。

### 组

组是一列（从上到下）或一行（从起始到末尾）共享空间、一起移动的框。在组内，框自己沿组方向的位置被忽略：组按顺序排列它们，彼此之间留出`gap`。某个框的文字变长时，其后的框随之移动。组也是一个方框，框和装饰可以锚定到它（`'#pagina'`）。

### 组如何分配空间

框声明自己的尺寸：固定的`height`，或者`'auto'`，即所装内容的高度，限定在`minHeight`和`maxHeight`之间。照着印好的页面做模板时，把每个方框在页面上的高度写成它的`minHeight`：文字短，方框保持画出的大小；文字长，方框就变高。页面在同一遍排版中排两次，一次按模板的声明，一次按内容的需要，两次的差别就是[重排记录](/zh/docs/composed-pages#重排记录)。

**纵向组（`stack`）**：纵向组中的框按各自的高度上下相接，彼此之间留出`gap`。每个框保留自己的横向位置和宽度，它自己的纵向位置被忽略。

- 没有自己的`placement`或`grid`的组，从第一个框所放的位置（它的`placement`，在有网格的模板中则是它的`grid`单元格）开始，按框的需要往下排，最远到模板区域的底边。一个框变高时，后面的框下移同样的距离。
- 有自己方框的组把框排在这个方框之内。框需要的空间超出方框时，`shrink`大于0的框让出空间，`priority`最低的先让；优先级相同的框按各自`shrink`的比例让出；任何框都不会小于它的`minHeight`。多余的空间按比例分给`grow`大于0的框，最多到它们的`maxHeight`；没有这样的框时，由`align`决定框的位置（`'end'`靠底边，`'center'`居中，`'space-between'`首尾贴边、中间均分）。组中没有自己定位的框以组的方框作为它的区域。
- 再也没有框能让出空间时，最靠近组底边的框先让，各自最多让到`minHeight`；固定高度的框保持原高，所以在一个增高的方框下面，空着的答题区或图片位仍留在页面上，让出空间的是方框自己的文字。没有框会越过组的底边：内容放不下的框按逐级重排的步骤依次尝试（见[内容放不下时](#内容放不下时)），仍然放不下的部分在那里截断，并报告为`frameOverflow`。被压到`minHeight`或固定高度以下的框，无论有没有内容，也会报告。
- `height: 'fill'`的框请求它的`minHeight`，并像设了`grow: 1`一样分得多余空间。

**横向组（`row`）**：横向组中的框按声明的宽度左右并排，高度都与这一行相同。行高就是组的方框的高度；组没有自己的方框时，取各框写明的高度中最大的一个：固定的`height`，否则是`minHeight`（`'auto'`框不再声明别的）；都没有写时，取最高的内容高度（固定高度的框保持自己的高度）。某个框的文字超出行高时，这个框会加宽：先用行中多余的宽度，再按`priority`从低到高，向`shrink`大于0的同组框借宽度，每个框都不会窄过它自己的文字仍能放下的宽度。加宽的量是让文字放下所需的最少整毫米数；即使把能用的空间全部给它也放不下时，它不加宽，没有自己方框的行改为加高。因此，`height: 'auto'`并设了`minHeight`的卡片会先在这个高度上分配宽度，只有没有卡片能让出宽度时，行才加高。多余的宽度先分给`grow`大于0的框，剩下的交给`align`。行中的框从左向右排列。

**固定（`pin`）**：`pin: true`的框保持模板为它声明的方框，即使它所锚定的框变高或移动也不变，照着画面画出的方框因此留在画面上。在组中，固定的框守住自己的位置，其他框绕过它继续排，两侧都留出`gap`；组外的固定框，对会与它重叠的组内框也是这样。

**装饰**：锚定到框的装饰元素（`anchor: { to: '#dinero' }`）在框变高或移动时随之移动。`pin: true`的元素留在模板画出那个框的位置。

```ts
  { name: 'ahorro', style: 'caja-amarilla', width: { value: 186, unit: 'mm' }, minHeight: { value: 30, unit: 'mm' } },
],
groups: [{ name: 'cajas', kind: 'stack', frames: ['dinero', 'gasto', 'ahorro'], gap: { value: 12, unit: 'mm' } }],
```

结果只取决于页面的内容、模板和排版设置：同样的输入得到同样的页面，测量的顺序和步骤也都相同。这种协调从不读取别的页面，所以只要内容还留在自己的页上，修改一个模板页不会改变其他任何页面。

**把框固定在卡片底部（自postext 1.42起）。** 锚在上方文字之下的框会跟着那段文字走：在文字少一行或多一行的版本里，它下面的框随之上移或下移，而模板画出的东西（卡片、色带、页脚）留在原处。要让框留在卡片底部、模板放置它们的位置，就把卡片的各个框放进同一个纵向组（`stack`），组的方框与卡片等高。被固定的框上方的框吸收多出来的空间（`grow: 1`），也让出空间（`shrink: 1`）；被固定的框写一个`minHeight`。文字变短时，被固定的框原地不动。文字变长时，挤压发生在它们上方：它们保持`minHeight`，上方的文字被缩小，仍放不下时，排版给出`frameOverflow`，重排记录里上方那个框会记下`textScaled`和`overflow`。锚在容器底部（`bottom-left`）的框同样守住自己的位置，但没有任何东西把它和上方的框联系起来：较长的文字会盖到它上面，不会为它挤压任何东西，重叠也不会报告。

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

增长的那个框和可用空间一样高，不论里面放了什么，所以带可见背景的样式会把整块都涂满：请把卡片画在模板的装饰里，文字框不设样式。

### 重复一组框的网格

一页照片卡片、一页活动卡片，或者一页每张下面写着名字的肖像，都是同一张卡片画了许多次。带`repeat`的网格组在模板里只把它画一次：一张卡片的各个框，叫做框组，网格按页面的Markdown给它的条目，每个条目排一次。这样，一页有几张卡片由Markdown决定，译本多出一张卡片也不需要新的模板。自postext 1.48起。

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **框组。** `repeat.frames`的第一个框是单元格的**主**框：它取单元格的宽度，保留自己的高度规则（`'auto'`是其内容的高度，在`minHeight`和`maxHeight`之间）。框组中的其他框按模板画出的样子排放，锚定到主框或彼此锚定：这里的题注小签挂在照片的底边上。框组中锚定到组外某个框的框，留在那个锚点所定的位置。
- **条目。** 页面上每一段`:::frame{slot="foto"}`内容是一个条目：重复槽位的各段内容不合并。在这段内容里，指明框组中某个成员的块（`:::frame{slot="pie"}`、`::resource{… slot="pie"}`）进入同一张卡片的那个成员；其余进入主框。见[模板页 › 重复的槽位](/zh/docs/composed-pages#重复的槽位)。
- **实例。** 每张卡片的框命名为`<frame>[n]`，从1开始计数：`foto[2]`和`pie[2]`是第二张卡片。警告、重排记录、源码映射和沙盒都用这些名称，框的id是`cp<n>:foto[2]`，装饰元素或连接线可以锚定到`'#foto[2]'`。连接线的`to: '#foto[*]'`指向本页的每一张卡片。锚定到`'#foto'`的元素读取的是网格的方框。
- **单元格。** 单元格从起始一侧开始逐行填充，所以在从右到左的页面上，第一张卡片在右边。一行的高度等于其中最高的单元格，主框上方伸出的部分（页签）和下方挂着的部分（小签）都算在内；`rowAlign`决定较矮的单元格怎样放。网格的方框是它自己的`placement`或`grid`单元格；都没有时，它从模板画出主框的地方开始，延伸到区域的右边和底边。
- **卡片放不下时。** 超出网格底边的一行在那里截断，每张卡片各自按逐级重排的步骤尝试，最后一张被截断的卡片报告`frameOverflow`。主框设了`overflow.continueIn`（`'next-page'`、`'template:<id>'`）时，网格**按整行**接续：第一个放不下的行及其后的每一行，排在追加的页上，放进一个重复同一框组的模板的网格里。比整个网格还高的单元格会给出警告，而不会无休止地接续下去。
- **`max`。** 超出`repeat.max`的条目进入流文框，模板没有流文框时排在这一页之后，每个条目各给出一条`repeatOverflow`。

不带`repeat`的网格按书写顺序排它列出的框，每个单元格一个。重复框组中的框如果又列在别的组里，在那里被跳过（`groupFrameTwice`）；模板中没有的名称是`groupFrameUnknown`。`grow`和`shrink`不作用于网格的行，`redistribute`也不作用于网格的卡片。

### 模块

课本的一页常常叠放几种在全书中反复出现、只是顺序不同的块：一个旁边配照片的方框，一棵有三个要点的树，标题下面四张照片的网格。为每种顺序画一个模板，模板就会成倍增加。**模块**就是把这样的块画一次：一个`role: 'module'`的模板，含有框、组和装饰（包括连接线），没有自己的页面。页面模板在一个`modules: true`的组中接收模块；页面的Markdown说明它有哪些模块、按什么顺序（见[模板页 › 页面中的模块](/zh/docs/composed-pages#页面中的模块)）。自postext 1.48起。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **模块里有什么。** 框、组（包括重复的网格）、装饰和连接线。它没有`area`、`header`、`footer`、`variants`、`spread`、`gutter`或`overflowTemplate`：写了这些中的任何一个，都报告为`unknownConfigValue`并被忽略。`extends`可以用在模块之间（继承模块的模板也是模块）。
- **它的方框。** 模块与所在的组一样宽，高度到它的框伸到的地方为止；组从顶端开始叠放各个模块，彼此之间留出`gap`。在模块内部，`'container'`是模块的方框，它的框（还有`'fill'`和百分比）以及它的装饰都以此为准：尺寸设为`{ to: 'container', edge: 'bottom' }`的底色，不论文字让模块有多高，都铺满整个模块。
- **名称。** 模块的框、组和元素以模块的实例名为范围：`<name>.<frame>`，名称取Markdown给出的（`name="ramas"`），否则是`<template>[n]`，即这个模块在本页同一模板的模块中的序号（`arbol[2].raiz`）。模块内部的锚点、`next`、`continueIn: '#x'`和连接线都改写为指向它自己的框，所以同一页上的两棵树绝不会互相连起来。框的id写作`cp0:arbol[2].raiz`。
- **模块放不下时。** 超出组底边的模块在那里截断，它的框按逐级重排的步骤尝试；整个组只报告一次`frameOverflow`。模块组设了`overflow.continueIn`（`'next-page'`或`'template:<id>'`）时，第一个放不下的模块及其后的每个模块都**整个**转到追加的页上，名称不变，排在那一页模块组的顶端。 在模块行或模块网格中，一行整体接续：一行的模块不会分到两页上。
- **并排。** `kind: 'row'`的模块组把模块从行首排到行尾，每个的宽度取其模板的`width`（一个长度、`{ percent: 48 }`，或`'fill'`，即平分剩余宽度），行高等于其中最高的模块；`kind: 'grid'`把模块排成`columns`个等宽的栏，逐行排列。`rowAlign`决定比所在行矮的模块放在哪里。行从文字行的起始一侧开始，所以从右到左的页面把第一个模块放在右边。从postext 1.50开始。
- **堆叠里的组。** 设了`within: '<堆叠>'`的模块组位于页面的模块堆叠内，`templates`说明它接收哪些模块：Markdown中这些模块每连续的一段，在第一个模块的位置组成堆叠的一行或一个网格。用下面的组，两个`aviso`块后接四个`tarjeta`块，排成一行两个方框，下面是2 × 2的卡片网格，而Markdown里只有`:::module`块。
- **组中之组。** 自 postext 1.51 起，`within` 可以指定任意模块组，包括行或网格，任意层级。若 `banda` 是 `cuerpo` 中的行，`columna` 是 `banda` 中的堆叠，一个方框后接两张卡片，方框就放在由这两张卡片组成的一列旁边。锚定到 `#banda` 的页面框在模块之后放置。
- **分享一行。** 自 postext 1.51 起，模块行剩余的空间按每个模块的 `grow` 分配，比所在组更宽的行按 `shrink` 让出宽度。
- **暂不支持。** 模块里面再套模块（`moduleNested`），以及模块内的模板`grid`单元格。

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### 内容放不下时

框的内容比组给它的空间高时，排版按顺序尝试[逐级重排](/zh/docs/composed-pages#仍然放不下时)的各个步骤，到第一个能让内容放下的为止：先占用空闲空间（最多到`maxHeight`），再由组推挤和让位，然后缩小图片，把组中其他框压到最小高度，缩小文字，最后到另一页接续。下面这些框的设置决定每一步能走多远：

- 固定`height`的框上的`maxHeight`：在缩放任何东西之前，框可以先长到这个高度。
- 组中其他框的`minHeight`：它们最多让出多少空间；框绝不会小于它自己的内容所需。
- `fit.scaleImages`和`fit.imageMinScale`：这个框及其所在组中的图片是否可以缩小，以及最小缩到多少（默认80%）。
- `fit.shrinkText`和`fit.minScale`：框中的文字是否可以缩小，以及最小缩到多少（默认90%）。字号、行距和间距使用同一个比例；框本身的尺寸不变。
- `overflow.continueIn`：这些都不够时，内容到哪里接续：另一个框，或另一页（`'next-page'`、`'template:<id>'`、`'page:<id>'`），文字在那里接在截断部分的`overflow.mark`之后，按原来的大小接续。能接续到另一页的框会先接续，再缩小图片和文字，除非它的`fit.preferContinue`为`false`。

缩放比例每级2.5%，排版取能放下的最大比例，所以只多出一行的文字排成97.5%，而不是直接降到最小值。必须保持字号的方框设`fit: { shrinkText: false }`；图片必须保持原大的页面，在其组中的各个框上设`fit: { scaleImages: false }`：

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

仍然放不下的部分报告为`frameOverflow`，附有尝试过的步骤和带取值的建议：见[警告及其建议](/zh/docs/composed-pages#警告及其建议)。

### 继承与变体

带`extends`的模板以它所指的模板为基础（后者本身也可以继承另一个模板），只改动自己写出的部分：

- `area`、`header`或`overflowTemplate`这类字段替换父模板的值。`grid`逐键合并。`spread`、`gutter`和`role`也会继承；`id`、`name`和`extends`属于模板自己。
- `frames`和`groups`**按名称**合并：与继承项同名的条目改动它写出的字段，其余保留（`fit`、`overflow`和`padding`逐键合并；`placement`整体替换）；`remove: true`去掉该项；新名称追加在继承项之后。
- 装饰元素以同样的方式按`id`合并；id是新的或没有id的元素会被追加。自postext 1.42起，在子模板或变体的`decoration.elements`中写`{ id: 'head-even', remove: true }`，会去掉所继承的、`id`相同的元素，作用与框的`remove: true`相同；模板并未继承的`id`则不起作用。同一列表中，删除之后可以紧跟一个同`id`的新元素。

`variants.recto`和`variants.verso`的写法与模板相同，合并方式也相同，分别作用于右页和左页。它们在整条`extends`链之后应用，根模板的变体最先应用。跨页同时有两面，所以不应用任何变体。

`variants.recto`里`parity: 'even'`的元素、`variants.verso`里`'odd'`的元素永远不会绘制（`unknownConfigValue`）。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

沙盒保存模板时，从不丢掉等于默认值的值：在继承另一个模板的模板中，或在变体中，这个值会覆盖父模板的值。

在代码中，`resolvePageTemplate(config, id, { parity })`返回一个模板：继承链已合并，所在一面的变体已应用，所有默认值已填好，所有引用都已按下文警告所述处理；`validatePageTemplates(config)`返回这些警告。

### 页面标明时才绘制

装饰中的元素，以及模板`header`或`footer`中的元素，可以带`when`或`unless`，各自写出页面块的一个属性名。`when: 'folio'`只在页面块设有`folio`的页面上绘制该元素；`unless: 'frontmatter'`在页面块设有`frontmatter`的页面上不绘制它。页面块单独写出某个属性（`::::page{template="pagina" frontmatter}`），或给它除`false`以外的任意值，就算设有该属性。这样一个模板既能用于不印页码和色带的前置页，也能用于两者都印的正文页：页面是什么由Markdown说明，图样留在模板里。自postext 1.50起。

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- 锚定在未绘制元素上的元素，或尺寸量到该元素的元素，也不绘制。
- 两个键都写时，元素只在页面块设有`when`的属性、且未设`unless`的属性的页面上绘制。
- 文档和章节的页眉页脚同样读取这两个键。非模板页没有页面块，不设任何属性。标题、篇和方框的设计忽略它们。
- 值不是非空字符串，或写在标题、篇或方框的设计中，会报告为`unknownConfigValue`，元素照常绘制，如同没有写。`postext check`会对书中没有任何页面块设置的属性上的`when`或`unless`给出提示`conditionNeverMet`：这样的元素永远不绘制，或总是绘制。没有任何地方设置的`{attr.x}`也一样：它总是空的。
- 全书排好后，如果某一页没有画出同一模板、同一侧的大多数页面都画出的页码或书眉（`header` 或 `footer` 中的文字，或装饰中读取 `{pageNumber}`、书眉名称或 `{attr.x}` 的文字），就会报告 `folioMissing`，并给出页面、模板和元素。页面块关闭该元素的页面，以及模板中没有这个元素的页面，都不计入。自 postext 1.53 起。
- 在Sandbox中，页眉页脚和模板装饰的每张元素卡片都有**页面标明时才绘制**和**页面标明时不绘制**两个字段，可选项是本书页面块用到的属性。

### 排版实际应用的设置

排版会应用每个框的位置和尺寸（网格、锚点、`min`/`max`、`verticalAlign`）、样式和`padding`、`columns`、`rules`、`layer`、`rotate`、`exclude`（及其`wrap`）、`flow`、`takes`、`next`、`overflow.continueIn`（`"#frame"`、`"next-page"`、`"template:<id>"`、`"page:<id>"`）及`overflow.mark`、`overflow.fromMark`，以及框的`fit`（逐级重排中文字和图片的缩小，见[内容放不下时](#内容放不下时)）；组内的空间协调（`grow`、`shrink`、`priority`、`pin`，以及组的`gap`和`align`，见[组如何分配空间](#组如何分配空间)）；还有模板的`area`、`grid`、`decoration`、`header`、`footer`、`variants`、`spread`和`overflowTemplate`。自postext 1.42起，排版也会应用模板的`palette`、框的`look`和宽度`'auto'`（与框中最长的一行同宽）。框的`writingMode`和`direction`自postext 1.39起生效。自postext 1.48起，排版应用网格组及其`repeat`、模块组和模块模板、装饰中的连接线和路径元素，以及框的`overlap`。模板的`bodyStyle`会被读取和检查，但还没有应用。

### 跨页

在跨页模板里，所有坐标都落在由两页组成的整张版面上，书脊在正中：`area`、`grid`、锚定到`container`、`page`和`bleed`，以及`fill`尺寸，读的都是双倍宽度。`bleed`伸到天头、地脚和两侧外边缘，从不伸到书脊。教科书里的跨页时间线就是一个模板：

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2到era-6，各占网格的一栏，以及插图带下面的注释
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

栏间距比`gutter`宽，对称网格里的卡片就不会碰到书脊，也就不会被移动。第二条色带和插图带设了`crossGutter`来跨过书脊：每一个都在其中心所在的那一页读，并在两页上都画出来。页面上的每个字，包括标签上的时代名称，都留在Markdown里。

竖排（`vertical-rl`）书里，跨页模板和单页模板页一样，在页面文字流的坐标中排：页面的“上”是纸张的右边，文字向下走，所以模板的`x`沿纸张向下，`y`从纸张右边走向左边。跨页沿`y`先是右页、后是左页，书脊是横穿模板的一条线，`gutter`、`crossGutter`和两页之间的切分都按这条轴计算；装饰仍铺在实际的纸张上，在书脊处切开。为横排书画的横向年表放进竖排书会转过来：竖排书的模板要按文字流的坐标来写。自postext 1.38起。要在纸面上横着读的卡片设`writingMode: 'horizontal-tb'`：它按横排排版，在竖排页面上正立（自postext 1.39起）。

### 连接线

连接线是装饰中连接框的线：树状图的分支、组织结构图、时间线上垂下的短线、流程图的箭头、从一条说明指到地图上某处的指示线。它在各框的外框确定之后才排放，所以文字变长、某个版本的词更长、组移动了它的框，它都会跟着走；在每种输出中它都画成矢量线，模板不需要一张画着这些线的图片。连接线是页面模板或模块的`decoration`中的元素；书眉和标题设计里没有可连的框，写在那里的连接线会被报告（`unknownConfigValue`），也不会画出。自postext 1.48起。

**绘制。** 连接线是矢量路径：在画布、PDF、HTML阅读器和固定版式EPUB中都是如此，在带标签的PDF中是版面工件；流式EPUB与其他装饰一起略去它们。带`anchor`端的连接线画在页面所有框之上，所以指进图片里的线无需给框设`layer`，就显示在图片的框之上；其余连接线与装饰一起留在框之下。`over: true`把框与框之间的线提到上面，`over: false`让指向图片的线留在下面。在跨页上，连接两页上框的连接线跨过书脊，并与其他装饰一样在那里切开；在从右到左的页面上，`start`和`end`跟随镜像后的文字流。

```ts
frames: [
  { name: 'mapa', width: { value: 118, unit: 'mm' } },
  { name: 'nota', style: 'nota', width: { value: 44, unit: 'mm' } },
],
decoration: { elements: [
  { kind: 'connector', id: 'a-lago', from: { to: '#nota', side: 'end' },
    to: { to: '#mapa', anchor: 'lago', gap: { value: 1.2, unit: 'mm' } }, endCap: 'dot' },
] },
```

## 框的外观

一个照片卡片的网格，各个小签只有颜色不同；或者一页上的方框有十几种色调：这样的书只保留一种标注框样式和一个模板。颜色写在`frameLooks`里，它是一个有名称的外观列表，Markdown在每段采用某种外观的内容上写出它的名称。自postext 1.50起。

```ts
frameLooks: [
  { id: 'rojo', name: 'Red pill', background: { hex: '#e63946', model: 'hex' }, body: { color: { hex: '#ffffff', model: 'hex' } } },
  { id: 'verde', background: { hex: '#6a994e', model: 'hex' } },
  { id: 'marino', border: { color: { hex: '#264653', model: 'hex' } } },
]
```

```ts
],
```

## 页面模板警告

在其他地方，引擎会忽略它不认识的键。页面模板和标注样式则会被检查，每个问题都是一条配置警告，出现在`postext check`和沙盒的检查面板中。这些警告的`path`是指向出错字段的JSON指针：`/pageTemplates/3/frames/2/style`、`/pageTemplates/0/variants/recto/frames/1/next`、`/resources/4/anchors/0/style`。字段是继承来的时，指针指向写出它的模板。指出不存在的id或名称的警告，还会给出最接近的现有名称。

模板、框、组、网格、`fit`、`overflow`、变体或标注样式中拼错的键是`unknownConfigKey`；超出某个设置取值范围的词（`area`、`verticalAlign`、`exclude`、`wrap`、`takes`、`kind`、`align`、`writingMode`、`direction`、`fontStyle`、`textTransform`、`overlap`、`rowAlign`，连接线的`routing`、端点标记和`side`，引线的端点标记和`routing`）是`unknownConfigValue`，该设置保留默认值。没有`id`的模板，或没有`name`的框或组，会被忽略，并在该字段上报告`unknownConfigValue`。框的外观（`frameLooks`）按同样的方式检查：没有`id`的外观会被忽略，框的`look`没有的键是`unknownConfigKey`。

      <td>页面排不了的<code>:::module&#123;template="…"&#125;</code>：id没有对应的模板（<code>reason: 'unknown'</code>），对应的模板不是模块（<code>'notModule'</code>），或者这一页的模板没有模块组（<code>'noGroup'</code>）。它的内容进入流文框。</td>
      <td>改正id，给模板设<code>role: 'module'</code>，或者给这一页的模板加一个<code>modules: true</code>的组。</td>
    </tr>
    <tr>
      <td><code>moduleAsPage</code></td>
      <td>页面块指定的是模块模板。模块排在页面的模块组里，从不单独成页：页面块的内容排进正文，与未知模板的处理相同。</td>
      <td>在页面块上指定一个页面模板，把模块作为<code>:::module</code>放在里面。</td>
    </tr>
    <tr>
      <td><code>moduleNested</code></td>
      <td><code>:::module</code>写在另一个模块里面。这是不支持的：它的各块归外层模块所有。</td>
      <td>先结束外层模块，或者把里面那一块画成外层模块的框。</td>
    </tr>
    <tr>
      <td><code>moduleNameRejected</code></td>
      <td>模块的<code>name="…"</code>已被本页的另一个模块使用（<code>reason: 'taken'</code>），或含有空格、<code>.</code>、<code>#</code>、<code>[</code>或<code>]</code>（<code>'invalid'</code>）。模块改名为<code>used</code>（<code>&lt;template&gt;[n]</code>），它的框也按这个名称来指定。</td>
      <td>给本页的每个模块起一个不重复的名称，只用字母、数字和连字符。</td>
    </tr>

**`connectorDropped`（重排记录）。** 连接线的一端落在页面没有显示的框上（框收拢了、是可选的且为空、是超出本页条目数的卡片，或者是被所在框裁掉的图上的点）时，这一端被略去。这不是警告：页面的[重排记录](/zh/docs/composed-pages#重排记录)会记下它，“connector ramas left out izq (not on the page)”，所以少了一条分支的页面与按计划画出的页面能区分开来。要保留这一端，就给那个框写上内容，或者让连接线只连本页有的框。
