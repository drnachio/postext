# WebMCP

**ブラウザーの中のエージェントが、Sandboxで開いている本を扱います。ページを見て、変えて、もう一度見ます。**

[Sandbox](/ja/docs/sandbox)は、[WebMCP](https://webmachinelearning.github.io/webmcp/)を通じてエージェントに専用のツールを渡します。WebMCPはWeb標準の草案で、ページがブラウザーとやり取りしているAIモデルにツールを渡せるようにするものです。エージェントはこのツールを使うので、画面をクリックしてたどる必要がありません。本を読み、12ページの画像を求め、`bodyText.fontSize`を10.5 ptにし、章が18ページから19ページに増えたのを見て、元に戻します。人が目で確かめながらすることを、あなたの本に対して、あなたのブラウザーの中で行います。

ツールは、名前が`sandbox_`で始まるものが53個あり、Sandboxが画面にある間だけ登録されます。ほかに、postext.devのどのページにもあるサイトのツール`site_*`が8個あります。このページでは、エージェントに頼みたい内容ごとにツールを分け、それぞれの呼び出し方を示します。

## エージェントをつなぐ

### WebMCPのあるブラウザー

ツールはSandboxがマウントされたときに`document.modelContext`に登録され、Sandboxを離れると取り下げられます。ブラウザーからページのツールを受け取るエージェントは、そこでツールを見つけます。Postext側でインストールや設定をするものはありません。

WebMCPはまだ草案の段階です。Chromeではオリジントライアルとして、また`chrome://flags/#enable-webmcp-testing`のフラグで使えます。ツールはページに従います。ホームページやドキュメントでは、エージェントが使えるのは`site_*`のツールで、Sandboxが画面に出ると53個の`sandbox_*`のツールが加わります。

### そのほかのブラウザー：`window.postextWebMcp`

ページは、WebMCPの有無にかかわらず、同じツールを`window.postextWebMcp`にも置きます。ページ内でスクリプトを実行できるエージェントなら、これを使えます。PuppeteerやPlaywrightのような自動化ツール、ブラウザーを操作してスクリプトを評価するMCPサーバー（Chrome DevTools MCP）、ブラウザー拡張機能、あるいは開発者コンソールに向かうあなた自身です。

```js
// このページにあるツール
postextWebMcp.listTools().map((t) => t.name);

// ツールを1つ実行する：名前と、引数を収めたオブジェクト
await postextWebMcp.executeTool('sandbox_get_state', {});
await postextWebMcp.executeTool('sandbox_set_config', {
  changes: [{ path: 'bodyText.fontSize', value: '10.5pt' }],
});
```

同じことをPuppeteerのスクリプトで行い、ページを画像として保存する例です。

```js
import fs from 'node:fs';
import puppeteer from 'puppeteer';

const browser = await puppeteer.launch();
const page = await browser.newPage();
await page.goto('https://postext.dev/ja/sandbox');
await page.waitForFunction(() => window.postextWebMcp?.listTools().some((t) => t.name === 'sandbox_get_state'));
await page.waitForFunction(async () => (await window.postextWebMcp.executeTool('sandbox_get_state', {})).ready);

const result = await page.evaluate(() =>
  window.postextWebMcp.executeTool('sandbox_render_page', { chapter: 1, position: 1, width: 1200, format: 'png' }),
);
const picture = result.content.find((part) => part.type === 'image');
fs.writeFileSync('page-1.png', Buffer.from(picture.data, 'base64'));
await browser.close();
```

新しいブラウザープロファイルは保存領域も別なので、あなたのプロジェクトではなく見本の本から始まります。自分の本で作業するときは、その本を作ったブラウザーを使ってください。

### ツールの応答の形

ツールはJSONのオブジェクトを返します。成功すれば`ok: true`と求められた内容、失敗すれば`ok: false`と、何が誤りで代わりに何を求めればよいかを述べる`error`です。

```json
{
  "ok": false,
  "error": "bodyText.fontSize is a length: give { \"value\": 11, \"unit\": \"pt\" }, a number (in pt) or a text such as \"11pt\". The units: cm, mm, in, pt, px, em, rem."
}
```

引数は、何かを実行する前にツールのスキーマと照合されます。パラメーター名を書き誤ると、正しい名前の一覧を添えて拒否されます。画像を返すツール（`sandbox_render_page`）は、MCPの形`{ content: [...] }`で応答を返します。最初にページを説明するJSONを収めたテキストの部分があり、続いてページごとに1つ、base64でエンコードした画像の部分が並びます。

## 作業の繰り返し

本を変えるツールは、どれもレイアウトが追いつくのを待ってから応答し、各章が何ページになったかを伝えます。そのため次に見るのはいつも新しいページで、エージェントはデザイナーと同じように作業を進められます。

1. **現状を知る**：`sandbox_get_state`は、本、その章と各章のページ、画面に出ている章とページ、開いているパネルを返します。
2. **見る**：`sandbox_render_page`はページを画像に描き、`sandbox_inspect_pages`はページをデータとして説明し、`sandbox_get_warnings`は検査で見つかったものを一覧にします。
3. **変える**：`sandbox_set_config`、`sandbox_edit_text`、`sandbox_save_resource`など。
4. **もう一度見る**：そして変更を残すか、元に戻します。

ページは、画面にどのビューアーが出ていても、ツールのために組まれて描かれます。あなたが第2章を読んでいる間に、エージェントは第7章を見ることができます。

## 頼めることと、そのやり方

### 開いているものを知る

```jsonc
// sandbox_get_state
{}
```

```json
{
  "ok": true,
  "ready": true,
  "book": { "kind": "sample", "id": "postext-guide", "name": "ガイド" },
  "pages": 3,
  "chapters": [
    { "chapter": 1, "id": "a", "title": "はじめに", "onScreen": true, "words": 1007, "pages": 2 },
    { "chapter": 2, "id": "b", "title": "第二章", "words": 101, "pages": 1 }
  ],
  "view": { "viewer": "canvas", "panel": "none", "scope": "chapter", "chapter": 1 },
  "resources": 0,
  "warnings": 0
}
```

`ready: false`のときは、理由を示す`waitingFor`が付きます（本がまだ読み込み中、など）。Sandboxがあなたの返事を待っているときは`question`と`notice`が現れます。[確認と通知](#確認と通知)を参照してください。

`chapter`を受け取るツールは、本の中での位置（1から）、章のタイトル、章のidのどれでも受け付けます。省略すると、画面に出ている章になります。

### ページを見る

**画像**：「第3章の冒頭を見せて」「24ページと25ページの見開きはどう見える？」といった頼みには、次のように呼びます。

```jsonc
// sandbox_render_page：見開き、1ページあたり幅1200 px
{ "chapter": 3, "page": 24, "count": 2, "width": 1200 }
```

`page`はページに印刷されている番号、`position`はその章のページの中での順番（1から）で、番号のないページに使います。どちらもなければ、画面に出ているページになります。`crop`はページの一部を拡大します。位置と大きさは左上の角からの、ページの幅と高さに対する割合で指定し、文字やアキを間近で確かめるのに使います。

```jsonc
// sandbox_render_page：右下の4分の1を拡大
{ "chapter": 3, "page": 24, "crop": { "x": 0.5, "y": 0.5, "width": 0.5, "height": 0.5 }, "width": 1600 }
```

`printPreview: true`は、印刷プロファイルによるソフトプルーフを、仕上がり線、塗り足し、セーフエリアのガイドとともに描きます。`trimmed: true`は、トンボのある余白を省きます。

**データとしての同じページ**：「このページでゆるい行はどれ？」「2段目は埋まっている？」といった問いには、次のように呼びます。

```jsonc
// sandbox_inspect_pages：ページを指定しなければ、章のページごとに1行
{ "chapter": 1 }
```

```json
{
  "chapter": 1, "title": "はじめに", "chapterPages": 2, "converged": true,
  "pages": [
    { "position": 1, "label": "1", "role": "opener", "blank": false, "lines": 45, "figures": 0, "starts": "はじめに" },
    { "position": 2, "label": "2", "role": "body", "blank": false, "lines": 37, "figures": 0, "starts": "数十年が過ぎた。活版印刷は五百年をかけて…" }
  ]
}
```

`page`か`position`を指定すると、そのページのブロックをすべて一覧にします。ブロックごとに、種類、段、テキスト、行数、ハイフンで終わる行、ゆるい両端そろえの行とその語間の幅、ページ上の矩形が示され、さらに各段がどこまで埋まっているか（`fill: 0.99`）も示されます。

**ある点にあるもの**：エージェントは画像の中に何かを見つけると、切り抜きと同じ割合を使って、それが何かを尋ねます。

```jsonc
// sandbox_inspect_point
{ "chapter": 3, "page": 24, "x": 0.71, "y": 0.42 }
```

応答には、そこにあるブロック、Markdownのソースの行と桁（と語）、リンクとその行き先のページ、リソースの表のセルやキャプションが入ります。`select: true`を付けると、クリックと同じことも行います。**本文**パネルが開き、その位置にキャレットが置かれます（`word: true`でその語を選択し、`to`で2つ目の点までを選択します）。

応答には`elements`も含まれます。その点にあるものを内側から外側へ並べたもので、ページ上のクリックで最初に選ばれるものから、さらにクリックするかEscを押すたびに上がっていく順です（グリフ、その段落、それを収めた囲み、テンプレートページの枠、そのグループ、ページとそのテンプレート。あるいはデザイン要素とそのスロット）。それぞれに安定したid、出どころ（Markdownの範囲、設定のパス、属性、リソース）、Sandboxが表示するパス（`path`）での名前が付きます。`select: true`と`level`（`block`、`frame`、`template`、`design`など）を指定すると、人が行うのと同じようにそのうち1つを選びます。**内容**モードではそのMarkdownを選び、**デザイン**モードではその枠、スタイル、テンプレートを開きます。選ばれた要素は`sandbox_get_state`の`pageSelection`に示されます。

### デザインを変える

[設定](/ja/docs/configuration)のどの項目も、パスで指定して変えられます。最初からパスを知っているエージェントはまずいないので、まずパスを探します。

```jsonc
// sandbox_find_setting
{ "query": "orphans" }
```

```json
{
  "ok": true,
  "paths": [
    { "path": "bodyText.avoidOrphans", "effective": true },
    { "path": "bodyText.avoidOrphansInLists", "effective": true }
  ],
  "sections": [{ "section": "Body text", "group": "Typography", "settingsGroup": "text", "configKeys": ["bodyText"] }]
}
```

`sandbox_get_config`は、1つの設定またはセクション全体を読みます。`set`は本が保存している値、`effective`は既定値を補った結果の値で、後者からはそのセクションにあるすべての設定もわかります。

```jsonc
// sandbox_get_config
{ "path": "headings.levels[level=2]" }
```

パスでは、リストの項目をほかと区別する値で指定します。`headings.levels[level=2].fontSize`、`header.elements[id=titleOdd].italic`、`calloutStyles[id=note].title`のようにです。そのうえで`sandbox_set_config`を使えば、1回の呼び出しでいくつでも設定を変えられます。

```jsonc
// sandbox_set_config
{
  "changes": [
    { "path": "bodyText.fontSize", "value": "10.5pt" },
    { "path": "page.margins.top", "value": { "value": 2.5, "unit": "cm" } },
    { "path": "headings.levels[level=2].color", "value": "#1f3a5f" },
    { "path": "bodyText.avoidOrphans", "value": true }
  ]
}
```

長さは`"2.5cm"`、`{ "value": 2.5, "unit": "cm" }`、またはその設定の単位での数値で、色は`"#1f3a5f"`です。値に`null`を渡すと設定が取り除かれ、デザインの値に戻ります。応答には、変更の良し悪しを判断する材料と、元に戻す方法が入っています。

```json
{
  "ok": true,
  "changed": [
    {
      "path": "bodyText.fontSize",
      "from": null,
      "to": { "value": 10.5, "unit": "pt" },
      "effective": { "from": { "value": 10, "unit": "pt" }, "to": { "value": 10.5, "unit": "pt" } }
    }
  ],
  "followed": [
    { "path": "captionStyle.fontSize.value", "from": 10, "to": 10.5 },
    { "path": "tableStyle.bodyFontSize.value", "from": 10, "to": 10.5 }
  ],
  "pagesBefore": 212,
  "pagesAfter": 219,
  "chapters": [{ "chapter": 1, "title": "はじめに", "pages": 19, "pagesBefore": 18 }]
}
```

`from`は変更前に保存されていた値です（ここでは`null`で、本はこの設定を指定していませんでした）。`from`を値にして同じ呼び出しをすれば、変更が元に戻ります。`followed`には、この設定に連動して変わった設定が並びます。エンジンが求められたのと違う値を採用したとき（上限に当たった、ほかの設定に依存している、など）は`note`が付きます。形の合わない値や、エンジンが扱えない設定は拒否され、何も変わりません。

呼び出しはどれもSandboxの履歴の1手になります。デザインパネルでの変更をCmd/Ctrl+Zで取り消すのと同じく、`sandbox_undo`で取り消せます。

大きな変更には、設定にオブジェクトをマージする`patch`（オブジェクトはマージされ、`null`は取り除き、リストは丸ごと置き換わります）と、本の設定を丸ごと別の設定に置き換える`replace`があります。後者には、たとえば書き出した`postext-config.json`を渡せます。`sandbox_reset_to_original`に`part: "config"`を渡すと、本の最初のデザインに戻ります。

複数の言語で書かれた本には、すべての版が読む共通設定があり、各版は自分で設定したフィールドを保ちます（[共通設定と言語ごとの上書き](/ja/docs/configuration-bundles#共通設定と言語ごとの上書き)を参照）。`sandbox_get_config`と`sandbox_set_config`は`scope`を受け取ります。`"all"`は共通設定を、`"edition"`は画面に出ている版を読み書きします。省略すると、デザインパネルで選ばれている範囲になります。そのような本では、`sandbox_get_config`は`scope`と`ownFields`を返します。`ownFields`は、画面の版が自分で設定しているフィールドのパスです。

```jsonc
// sandbox_set_config
{ "scope": "all", "changes": [{ "path": "bodyText.fontSize", "value": "10.5pt" }] }
```

```json
{ "ok": true, "scope": "all", "keptBy": ["ar"], "changed": [ … ] }
```

共通設定への書き込みは、そのフィールドを自分で設定していないすべての版に反映されます。`keptBy`は自分で設定している言語を示し、それらの言語は自分の値を保ちます。そちらも変えるには、各言語を開き（`language`を渡した`sandbox_open_book`）、`scope: "edition"`でそのパスを書き込みます。共通設定と同じ値を書くと、その版独自の値ではなくなります。言語が1つの本では、設定はすべてその本自身のものなので、`scope: "all"`は受け付けられません。

フォントも設定です。`sandbox_list_fonts`に`search: "Garamond"`を渡すと公開カタログからファミリーを探し、その名前を`fontFamily`の設定に書き込むとフォントが読み込まれます。

囲みスタイルには専用のライブラリがあります。`sandbox_frame_styles`は、各スタイルが本のどこで使われているか（テンプレートの枠、テンプレートページ、章ごとの`:::callout`の囲み）と、ほぼ同じスタイルの統合の提案を返します。「デザイン › 囲み › 枠のスタイル」と同じ内容です。`sandbox_merge_styles`は`groups`（`{ keep, merge }`）か`all: true`を受け取り、統合したスタイルを指していた枠とページブロックをすべて書き換えます。`lookOnly: true`にすると、置き場所の違う囲みのスタイルも比べます。そうしたスタイルは位置だけを自分で持ち、残すスタイルを拡張する（`extends`）形で残るので、その囲みは動きません。応答では`keptForTheirPlace`に挙がります。`keepPlaces: false`にすると完全に統合し、その囲みは移動します。
応答の`undoSteps`は、書き換えた章ごとに1つ、スタイルに1つのステップを示します。`sandbox_undo`はこれを、スタイルから先に取り消します。

名前の付いた項目の名前変更や削除は、その項目だけの変更では済みません。そのため、これらの操作にはデザインパネルと同じように働く専用のツールがあります。`sandbox_rename_design_item`は、スタイル、ルック、ページテンプレート、テンプレートのフレームやグループ、漫画のフキダシスタイル・登場人物・コマスタイルに新しいIDを付けます。その項目を名指すものもすべて追従します。`:::callout`と`::::page`のブロック、ページのスロット名、画像のアンカーと`::label`行、スタイルを使う表と楽譜、登場人物です。`sandbox_remove_design_item`はパネルと同じように項目を削除します。削除したボックススタイルを基にしたスタイルはその見た目を引き継ぎ、パレットの色を使っていた設定はその色をパレットとのリンクなしで保ちます。`sandbox_language_defaults`はデザイン › テキストの中国語・日本語・アラビア語の既定値を一覧し、`apply: true`で適用します。`sandbox_print_profile`は印刷セクションの独自ICCプロファイルをアップロードまたは削除します。`sandbox_save_layout_as_template`は組まれたコンポーズドページから新しいページテンプレートを作ります。`layout.bitmapResolution`を`"file"`にすると、既存の各画像ファイルに記録された解像度も読み込みます。

### 本文を編集する

各章の本文は、Postextの拡張を加えたMarkdownです（[文書形式](/ja/docs/document-format)を参照）。エージェントは行番号付きで本文を読み、該当する一節を探し、一節を厳密に指定して置き換えます。

```jsonc
// sandbox_read_text：第2章の40行目から80行目
{ "chapter": 2, "fromLine": 40, "toLine": 80 }
```

```jsonc
// sandbox_search_text：一節が現れる場所と、そのページ
{ "query": "ベースライングリッド", "pages": true }
```

```jsonc
// sandbox_edit_text
{
  "chapter": 2,
  "edits": [
    { "find": "冒頭の最後の言葉。", "replace": "冒頭を締めくくる言葉。" },
    { "find": "コンピュータ", "replace": "コンピューター", "all": true }
  ]
}
```

それぞれの`find`はソースと完全に一致し、`all`を指定しない限り1回だけ現れる必要があります。編集はすべて適用されるか、1つも適用されないかのどちらかです。見つからない一節があると、章を読み直すよう勧めるメッセージとともに拒否されます。1回の呼び出し全体が`sandbox_undo_text`の1ステップになり、このツールで取り消せます（`redo: true`でやり直せます）。`sandbox_write_text`は章全体を、`markdown`または`.md`ファイルの内容で置き換えます。

本文のある場所をあなたに示すときは、`sandbox_select_text`が**本文**パネルを開き、その一節を選択します（`text`、`line`、`offset`で指定）。**検査**パネルで見つかった項目をクリックしたときと同じ動きです。

### 章を整理する

`sandbox_manage_chapters`は、章の追加、名前の変更、移動、分割、結合、表示を行います。

```jsonc
// 3番目に章を加える
{ "action": "add", "title": "エピローグ", "markdown": "# エピローグ\n\nおわり。\n", "position": 3 }

// ある一節が始まる位置で章を分ける
{ "action": "split", "chapter": "はじめに", "before": "## 第二部" }

// レベル1の見出しごとに1つの章にする
{ "action": "split_at_headings", "chapter": 1 }
```

`sandbox_remove_chapter`は章を1つ削除します。この操作は取り消せません。

### 画像、表、動画、フォントを加える

`sandbox_save_resource`は、**リソース**パネルと同じように、リソースを加えたり変えたりします。ファイルは`url`（ページが取得できる`https:`のアドレス、または`data:` URL）か、`base64`で渡します。

```jsonc
// キャプションと代替テキストの付いた画像
{
  "id": "harbour",
  "image": { "url": "https://example.org/harbour.jpg" },
  "caption": "夜明けの港",
  "altText": "石の岸壁に係留された漁船。水面に霧がかかっている",
  "placement": { "position": "top", "span": "page" }
}
```

```jsonc
// テキストの行から作る表。最初の行が見出し行になる
{
  "id": "prices",
  "caption": "1850年の価格",
  "table": { "rows": [["品目", "価格"], ["パン", "2ペンス"], ["インク", "6ペンス"]], "columnWidths": [2, 1] }
}
```

```jsonc
// YouTubeの動画：ポスター画像、フレームの大きさ、タイトルは取得される
{ "id": "interview", "video": { "url": "https://www.youtube.com/watch?v=…" }, "caption": "仕事中の著者" }
```

応答には、保存されたレコードと、それを配置する行`::resource{id="prices"}`が入ります。エージェントはこの行を`sandbox_edit_text`で本文に書き込みます。既存の`id`に対して呼ぶと、渡したものだけが変わります。キャプション、表のセル、配置、画像のセーフエリアなどです。`newId`はリソースの名前を変え、既定では本の中のそのリソースへの参照もすべて書き換えます。`sandbox_list_resources`はリソースを一覧にし、`id`を渡すとその1つを詳しく返します（表なら書式付きのセル、SVGならそのソース）。

画像の`marks`にはアンカーも含まれます。地図や図解では、`::label`の行を置く点のことで、`id`、`x`と`y`（画像全体に対する割合）、そこに置くラベルが引き継ぐラベル設定（`style`、`align`、`verticalAlign`、`rotate`、`width`、`writingMode`）からなります。デザインにないラベルスタイルは応答で指摘され、リソースに加えた新しいマークは履歴の1ステップになります（`sandbox_undo`は`kind: "resource"`を返します）。SVGでは`marks.svgSymbols`（`idPrefix`、`className`）が、指定した図の各要素の上に回避エリアを追加します。このエリアは、呼び出しで指定したエリアや画像にすでにあるエリアに加わります（postext 1.43以降）。

```jsonc
// 地図の2つのアンカーとそのラベルスタイル
{ "id": "map", "marks": { "anchors": [
  { "id": "albar", "x": 0.19, "y": 0.41, "style": "city", "verticalAlign": "bottom" },
  { "id": "senne", "x": 0.22, "y": 0.54, "style": "river", "rotate": 68 }
] } }
```

本にアップロードするフォントは`sandbox_save_font`で扱います。

```json
{ "action": "add", "family": "My Serif", "weight": 700, "style": "italic", "file": { "url": "https://example.org/MySerif-BoldItalic.woff2" } }
```

### 本を検査する

```jsonc
// sandbox_get_warnings：すべての章
{ "scope": "book" }
```

応答は**検査**パネルが示す内容と同じで、画面に何が出ていても、任意の章または本全体について返ります。見つからないフォントや画像、エンジンが読めなかったマークアップ、収まらないデザイン要素、地に対して薄すぎる文字、ゆるい行、ウィドウ、あふれた囲み、印刷のプリフライトです。各警告には、分類、章、行とオフセット、ページ、そして警告の対象となる設定やリソースが付きます。

```json
{
  "ok": true,
  "scope": "book",
  "total": 3,
  "byCategory": { "typesetting": 2, "design": 1 },
  "warnings": [
    {
      "kind": "headerFooterMetadataMissing",
      "category": "design",
      "title": "Placeholder metadata missing",
      "detail": "header · {title} — The metadata referenced by this placeholder is not set — it will render empty."
    }
  ]
}
```

エージェントは警告からその場所に移り（`sandbox_select_text`に`offset`と`toOffset`を渡すか、`sandbox_go_to_page`を使います）、ページを見て、本文か設定を直せます。`category`で一覧を絞り込めます。長い本では、`scope: "book"`はすべての章を組むので時間がかかります。

複数の版を収めた本（サンプルのバンドル、またはそこから読み込んだプロジェクト）では、テンプレートページの検査も各言語で行えます。`sandbox_get_composed_checks`は各版を組み、**検査**パネルの「テンプレートページ」と同じく、言語・章・ページ・枠ごとに検査結果を一覧にします。`language`を指定すると1つの版だけになります（postext 1.40以降）。`sandbox_get_warnings`は、これまでどおり画面に表示中の言語の1つの章だけを検査します。

### 画面で見せる

エージェントが変えたものは、あなたにも見えます。何かを指し示したいときは次のようにします。

```jsonc
// sandbox_set_view：Canvasで見開き表示にし、間延びした行を強調する
{ "viewer": "canvas", "pages": "spread", "fit": "height", "guides": { "looseLines": true, "baselineGrid": true } }
```

```jsonc
// sandbox_go_to_page：図が置かれている場所
{ "anchor": "harbour" }
```

`sandbox_set_view`では、ほかに、ビューアー（`canvas`、`pdf`、`folio`、`html`、`epub`、`scorm`）、内容モードかデザインモードか（`mode`）、サイドパネル、章か本全体か、拡大率、読者側の文字サイズ、印刷プレビュー、**デザイン**パネルのグループも選べます。SCORMタブでは、コンテンツ（`scormLayout`）、バージョン（`scormVersion`）、パッケージに入れる章と節（`scormPick`。IDはタブの`contents`から取ります）も選べます。`sandbox_go_to_page`は、`step`、`page`、`position`、本文の一節`text`、`anchor`、EPUBの目次の項目`contents`でページを移します。`sandbox_run_viewer`はツールバーのボタンを押します。`regenerate`はPDF、EPUB、SCORMパッケージを作り直してそれを待ち、`print`は印刷ダイアログを開いてあなたの確認を待ち、`download`はPDFかEPUB、または新しく作ったSCORMパッケージを保存し、`play_video`と`stop_video`はページ上の動画を再生・停止します。

### 漫画のページの編集

`sandbox_inspect_comic`は、漫画のページのコマ、割り線、吹き出しを位置とともに返します。`sandbox_edit_comic`は、人がポインターで行う編集を行い、ソースに書き込みます。

```jsonc
// 吹き出しの中心を、そのコマの絵の中の一点に動かす（パーセントで指定）
{ "comic": 1, "action": "move_balloon", "balloon": 2, "at": { "x": 30, "y": 18 } }

// 1本目の割り線を、そのセルの45 %の位置に動かす
{ "comic": 1, "action": "move_splitter", "splitter": 1, "start": 45 }
```

吹き出しが顔に重なったり、コマからはみ出したりすると、応答で警告します。形式については[漫画](/ja/docs/comics)を参照してください。

### 本、ファイル、Word

- **本を開いて保存する**：`sandbox_list_books`は見本の本とあなたのプロジェクトを一覧にし、`sandbox_open_book`はそのうちの1冊を開きます（`{ "kind": "sample", "id": "postext-guide", "language": "es" }`）。`sandbox_save_book`に`action: "copy_current"`を渡すと画面の本を自分のプロジェクトとして保存し、`new_blank`を渡すと空の本を始めます。プロジェクトでは、`language`（`"fr"`、`"zh-Hant"`）を付けた`add_language`が画面の言語をその言語の新しい版として複製して開き、`thisLanguageOnly: true`を付けた`rename`は画面の言語だけに名前を付けます。`set_cover`と`remove_cover`は表紙を付けたり外したりします。
- **書き出す**：`sandbox_export`は`pdf`、`epub`、`postext`、`docx`、`markdown`、`config`を書き出します。既定ではブラウザーがファイルをダウンロードします。`deliver: "data"`を渡すと、PDFやEPUBがbase64でエンコードされてエージェントに返ります。

  ```json
  { "format": "pdf", "scope": "book", "deliver": "data" }
  ```

- **`.postext`ファイルを読み込む**：`sandbox_import_book`を使います（`inspect: true`を渡すと、読み込まずに、どの言語が入っているかを返します）。
- **Wordの原稿を取り込む**：`sandbox_import_word`を使います。最初に`dryRun: true`で実行してください。何も変えずに、品質レポート、Wordのスタイルごとに何になるか、作られる章とリソースを返します。そのあとで対応づけを直し、本番の読み込みを実行します。

  ```json
  {
    "file": { "url": "https://example.org/manuscript.docx" },
    "destination": "book",
    "mapping": { "paragraphs": { "Epigraph": { "kind": "quote" }, "Chapter Title": { "kind": "chapter" } } },
    "saveTemplateAs": "わたしの出版社"
  }
  ```

  `characterSpacing`（取り込めるものがあれば既定でオン、postext 1.40以降）を使うと、使われているWordスタイルの字間が、対応する本の段落スタイル、見出しスタイル、見出しレベル、囲みのタイトルにemで設定されます。本がすでに字間を設定しているものは変わりません。ドライランでは`characterSpacing`に一覧が出ます。

  `sandbox_word_templates`は、保存した対応づけの一覧表示、読み取り、保存、削除を行います。この対応づけはWordへの書き出しでも使われます。

### 確認と通知

リンクから開いた本について、あなたがすでに自分のコピーを持っている場合、Sandboxは手元のコピーを置き換えるかどうかを尋ねます。`sandbox_get_state`はこれを`question`として、`ready: false`とともに伝えます。`sandbox_answer`がこれに答えます。`replaceCopy: false`は手元のコピーを残し、`true`は公開版で置き換えて手元のコピーを削除します。`dismissNotice: true`は**本**パネルのメッセージを消します。

## 最初から最後まで、3つの作業例

**「本文を少し大きくして。ただし本は220ページ未満に収めて」**：`sandbox_get_state`（212ページ）→ `bodyText.fontSize`を`"10.5pt"`にする`sandbox_set_config`（219ページ）→ 文字の詰まったページを`sandbox_render_page`で描いて確かめる → `category: "typesetting"`を渡した`sandbox_get_warnings`で新しいウィドウを探す → うまくいかなければ、最初の応答の`from`の値でもう一度`sandbox_set_config`。

**「第4章で検査が見つけたものを直して」**：`chapter: 4`を渡した`sandbox_get_warnings` → 警告ごとに、その`line`の周りを`sandbox_read_text`で読み、その`page`を`sandbox_render_page`で描く → `sandbox_edit_text`または`sandbox_set_config` → 空の一覧が返るまで、もう一度`sandbox_get_warnings`。テンプレートページで収まらない枠には修正案（`proposals`）が付きます。`sandbox_apply_proposal`にその`frame`と修正案の番号を渡すと適用され、章が組み直され、収まったかどうかが`fits`で返ります。

**「このWordファイルから本を作って、PDFをちょうだい」**：`action: "new_blank"`を渡した`sandbox_save_book` → `dryRun: true`を渡した`sandbox_import_word` → `mapping`を直し、`destination: "book"`で本番の読み込み → `scope: "book"`を渡した`sandbox_get_warnings` → `format: "pdf"`と`scope: "book"`を渡した`sandbox_export`。

## あなたの同意を求めるツール

元に戻せない操作をする6つのツールには、重大な操作の印（`consequentialHint`）が付いており、実行の前にブラウザーがあなたに確認を求められます。`sandbox_remove_chapter`、`sandbox_delete_resource`、`sandbox_delete_book`、`sandbox_reset_to_original`、`sandbox_import_word`（本全体を置き換えることがあります）、`sandbox_answer`（手元の本のコピーを削除することがあります）です。迷うときは、先に`.postext`のコピーを書き出すようエージェントに頼んでください。

読み取るだけのツールには`readOnlyHint`が付いています。ページ自身が書いたのではないテキスト（本の本文、取得したファイル）を応答に含むツールには`untrustedContentHint`が付いており、ブラウザーはそのテキストが指示として扱われないようにできます。

## 制限

- **すべてはブラウザーの中にとどまります**：ツールが届くのは、Sandbox自身が届く範囲だけです。本はこのブラウザーの保存領域にあり、`url`で渡したファイルはページが取得するので、そのサーバーが許可している必要があります（CORS）。`data:` URLや`base64`なら必ず使えます。
- **長い作業には時間がかかります**：ツールはレイアウトを待ってから応答します。`wait: false`を渡すとすぐに応答します。長い本のPDFやEPUBには数分かかります。
- **取り消し**：`sandbox_undo`は、本文でもデザインでも、変更した順に直前の変更を取り消します。SandboxでのCmd/Ctrl+Zと同じです。本文パネルで入力した文字、ツールによる編集とプレビュー上での編集、`sandbox_set_config`やデザインパネルで変えた設定、動かした枠が対象です。`redo: true`でやり直します。`sandbox_undo_text`は本文の編集だけを取り消し、直前の変更がデザインだったときはそう伝えます。章の追加・削除・移動、リソースとフォントは履歴に入りません。別の本を開くと履歴は空になり、ページを再読み込みしても同じです。それぞれが何を取り消すかは`sandbox_get_state`が示します（`history`）。
- **画面の本が対象です**：ツールは開いている本に対して働きます。開かずに別の本に届くのは、`.postext`ファイルを書き出す`sandbox_export`、`duplicate`、`rename`、表紙の操作を渡した`sandbox_save_book`、`sandbox_delete_book`、`sample`を渡した`sandbox_reset_to_original`だけです。

## サイトのツール

Sandboxを含む、postext.devのすべてのページにあります。

- `site_get_context`：画面に出ているページ、その言語とテーマ、ドキュメントのセクションとすべてのページ。
- `site_search`：ドキュメントとレシピ集を、語、設定名（`bodyText.avoidOrphans`）、ディレクティブ（`::resource`）で検索します。
- `site_read_page`：サイトのページを、画面のページを離れずにMarkdownとして読みます。
- `site_open_page`：ページを表示します。`#heading`を付けると、そのセクションに移ります。
- `site_list_recipes`と`site_open_recipe_in_sandbox`：レシピ集のレシピを探し、編集できる本としてSandboxで開きます。
- `site_lookup_term`：用語集の用語（ウィドウ、カーニング、禁則など）。
- `site_set_preferences`：サイトの言語とテーマ。

ホームページから始めたエージェントは、レシピ集を検索し、レシピをSandboxで開き、そのまま`sandbox_*`のツールで作業を続けられます。

- **デザイン**：`sandbox_get_config`、`sandbox_set_config`、`sandbox_find_setting`、`sandbox_reset_to_original`、`sandbox_frame_styles`、`sandbox_merge_styles`。
- **取り消し**：`sandbox_undo`。
- **表示**：`sandbox_set_view`、`sandbox_go_to_page`、`sandbox_run_viewer`。
- **リソースとフォント**：`sandbox_list_resources`、`sandbox_save_resource`、`sandbox_delete_resource`、`sandbox_list_fonts`、`sandbox_save_font`。

## Sandboxを埋め込むとき

`<PostextSandbox>`はマウントされている間ツールを登録し、`webmcp={false}`でツールを登録しないようにできます（[Props](/ja/docs/sandbox-embedding#props)を参照）。ホストのページは、同じモジュールを通じて独自のツールを加えられます。

```ts
import { registerWebMcpTools } from 'postext-sandbox/webmcp';

const controller = new AbortController();
registerWebMcpTools([
  {
    name: 'shop_list_titles',
    description: 'The titles of this shop, with the id of the Postext project of each one.',
    inputSchema: { type: 'object', properties: {}, additionalProperties: false },
    annotations: { readOnlyHint: true },
    execute: async () => ({ titles: await fetchTitles() }),
  },
], controller.signal);
// controller.abort()でツールを取り下げる
```

これらのツールは、ブラウザーがWebMCPを提供していればWebMCPに登録され、`window.postextWebMcp`には常に登録されます。引数は`inputSchema`と照合されます。
