# Configuration : encadrés


## Styles d’encadré

La propriété `calloutStyles` déclare les styles d’encadré nommés qu’un document applique avec un conteneur `:::callout{type="…"}` : notes, conseils, avertissements, objectifs d’apprentissage, tout contenu mis à part du texte courant dans un cadre teinté ou bordé. Un style neutre, `note`, est fourni par défaut (fond gris clair, sans bordure, sans bande, sans icône, sans titre) : `:::callout` fonctionne donc sans aucune configuration ; déclarer `calloutStyles` remplace cette liste par défaut.

```ts
const config: PostextConfig = {
  calloutStyles: [
    { id: 'note', name: 'Note' },
    {
      id: 'objectives',
      name: 'Learning objectives',
      title: 'Objectives',
      stripe: { enabled: true, side: 'left' },
      icon: { kind: 'glyph', glyph: '✓' },
      titleStyle: { textTransform: 'uppercase' },
      lists: { bulletChar: '–' },
    },
    {
      id: 'warning',
      title: 'Warning',
      backgroundEnabled: false,
      border: { enabled: true, color: { hex: '#AA0000', model: 'hex' }, width: { value: 1, unit: 'pt' } },
      borderRadius: { value: 1, unit: 'mm' },
      titleStyle: { color: { hex: '#AA0000', model: 'hex' } },
    },
  ],
};
```

```md
:::callout{type="objectives"}
- Describe the parts of the lantern.
- Trim the wick at dusk.
:::

:::callout{type="warning" title="Do not touch the lens"}
The glass stays hot for an hour after the flame is out.
:::
```

Une icône n’a besoin ni d’étiquette ni de titre : un encadré avec un <code>icon</code> et sans <code>label</code> l’affiche dans sa colonne ou, avec <code>position: 'corner'</code>, en pastille sur son coin.</td>

### Coins, côtés et onglets joints

Un encadré n’est pas forcément un rectangle à quatre coins égaux et à une seule bordure. Depuis postext 1.48, un style peut arrondir certains coins et pas les autres, tracer sa bordure sur certains côtés seulement, et faire sortir son onglet de l’encadré d’un seul tenant : la fiche d’un manuel dont l’onglet de titre et le corps forment un seul contour, dessiné par le style plutôt que peint dans une image derrière la page.

```ts
calloutStyles: [
  // Rounded at the top only, a rule over the box and a heavier foot.
  { id: 'ficha', background: { model: 'hex', hex: '#fff4d6' },
    borderRadius: { topLeft: { value: 3, unit: 'mm' }, topRight: { value: 3, unit: 'mm' } },
    border: { enabled: false, color: { model: 'hex', hex: '#c58b00' }, width: { value: 0.75, unit: 'pt' },
      sides: { top: { enabled: true }, bottom: { enabled: true, width: { value: 2, unit: 'pt' } } } } },
  // A card whose tab grows out of its top edge.
  { id: 'tarjeta', background: { model: 'hex', hex: '#ffffff' }, borderRadius: { value: 3, unit: 'mm' },
    border: { enabled: true, color: { model: 'hex', hex: '#2a6f97' }, width: { value: 1, unit: 'pt' } },
    label: { position: 'top-left', inset: { value: 4, unit: 'mm' }, joined: true, fillet: { value: 2, unit: 'mm' },
      color: { model: 'hex', hex: '#2a6f97' } } },
]
```

- **Coins.** `borderRadius` est une longueur pour les quatre coins, ou `{ topLeft, topRight, bottomRight, bottomLeft }`. Un coin absent de l’objet est carré. Les coins sont ceux de la feuille. Deux coins ne prennent jamais plus que le côté qui les sépare ; chacun cède en proportion.
- **Côtés.** `border.sides.top`, `right`, `bottom` et `left` acceptent `enabled`, `color` et `width`, et chaque champ absent reprend celui de la bordure entière. Un encadré bordé seulement en haut s’écrit `border: { enabled: false, sides: { top: { enabled: true } } }`, ou `enabled: true` avec les trois autres côtés désactivés. Le bord intérieur d’un côté suit son épaisseur : un coin arrondi entre un côté fin et un côté épais s’incurve comme le dessine CSS.
- **Onglet joint.** Avec `label.joined: true`, l’onglet et l’encadré ont un seul contour, un seul fond (le `background` de l’encadré ; le `background` propre de l’onglet n’est pas peint) et une seule bordure qui fait le tour de l’onglet. L’onglet se tient sur le bord, à l’extérieur de l’encadré sur toute sa hauteur : son `offset` doit valoir `0` (une autre valeur est signalée comme `unknownConfigValue` et lue comme `0`). Ses coins extérieurs prennent le rayon du coin de l’encadré auquel il se colle, et les coins intérieurs, à sa jonction avec l’encadré, sont arrondis par `fillet` (par défaut : ce rayon). Un onglet aligné sur le côté de l’encadré (un `inset` inférieur à un demi-pixel) monte droit depuis ce côté. Donnez aux mots une couleur qui se lit sur le fond de l’encadré (`label.color`), puisque l’onglet n’a plus de fond propre. Avec `label.ownBackground: true`, un onglet joint est peint dans le `background` propre de l’étiquette, sur le fond de l’encadré et sous la bordure : un onglet blanc peut tenir sur un encadré teinté, ou un onglet coloré sur un encadré sans fond.
- **Coins de l’onglet.** `label.borderRadius` donne à l’onglet ses propres coins : une longueur, ou `{ topLeft, topRight, bottomRight, bottomLeft }` sur les coins de la feuille, comme le `borderRadius` de l’encadré. Un onglet séparé de l’encadré a des coins droits s’il ne les fixe pas. Un onglet joint arrondit ainsi ses deux coins extérieurs (`topLeft` et `topRight` pour un onglet en haut, `bottomLeft` et `bottomRight` en bas) ; sans valeur, ils prennent le rayon du coin de l’encadré. Les raccords gardent `fillet` dans les deux cas.
- **Onglets en bas.** `position: 'bottom-right'`, `'bottom-left'`, `'bottom-start'` ou `'bottom-end'` suspend l’onglet au pied de l’encadré, simple ou joint : c’est l’onglet du haut retourné, `offset` sous le pied, le `rule` le long du pied. Il n’y a pas d’onglets latéraux : les mots d’un onglet courent à l’horizontale.

Toutes les sorties dessinent ces formes : le canvas et le PDF en contours vectoriels, la visionneuse HTML et l’EPUB à mise en page fixe avec du CSS par coin et par côté. L’EPUB recomposable écrit les coins et les côtés dans son CSS et compose un onglet joint comme un onglet simple. Le `look.border.color` d’un bloc recolore tous les côtés, et la palette d’une partie recolore chacun d’eux. Un style dont les coins et les côtés sont tous pareils se met en page comme avant.

### Un glyphe sur l’onglet

}

### Styles basés sur un autre

`extends` désigne un autre style de `calloutStyles`, et tout champ que le style laisse vide vient de lui. Les objets comme `padding`, `border`, `titleStyle` ou `fixed` sont fusionnés clé par clé : un style peut ainsi ne changer qu’un côté de la marge intérieure, ou que `fixed.offset` ; une couleur ou une longueur est prise entière ; `id` et `name` ne s’héritent jamais. Un style parent peut lui-même être basé sur un autre. Un livre dont les encadrés sont placés à de nombreux endroits garde un style pour leur aspect et un style minimal par place :

```ts
calloutStyles: [
  {
    id: 'caja',
    background: { model: 'hex', hex: '#dff0fa' },
    padding: { top: { value: 3, unit: 'mm' }, right: { value: 4, unit: 'mm' }, bottom: { value: 3, unit: 'mm' }, left: { value: 4, unit: 'mm' } },
  },
  { id: 'caja-p5', extends: 'caja', placement: 'fixed', fixed: { offset: { x: { value: 12, unit: 'mm' }, y: { value: -40, unit: 'mm' } } } },
  { id: 'caja-p9', extends: 'caja', placement: 'fixed', fixed: { anchor: { to: 'container', edge: 'top-right' } } },
]
```

Changez l’aspect de `caja` et tous les encadrés suivent, chacun à sa place. Un `extends` qui ne désigne aucun style existant déclenche `calloutStyleExtendsUnknown` (l’avertissement propose l’identifiant le plus proche, et le style reste seul, avec les valeurs par défaut), et des styles basés les uns sur les autres en boucle déclenchent `calloutStyleExtendsCycle` (ils restent seuls tant que l’un d’eux n’est pas basé sur un style hors de la boucle). Dans le Sandbox, le champ **Basé sur** d’un style d’encadré le règle ; supprimer un style sur lequel d’autres sont basés reporte ses réglages dans ceux-ci : leurs encadrés ne changent donc pas. Dans la section **Styles de bloc**, fusionner avec **Comparer l’aspect seulement** garde un style dont les encadrés sont ailleurs sous la forme d’un tel style minimal quand **Laisser chaque encadré à sa place** est activé (par défaut), et aucun encadré ne bouge. Depuis postext 1.39.

### Le conteneur `:::callout`

Une ligne `:::callout{type="<id>"}` ouvre l’encadré et une ligne `:::` seule le ferme. Le délimiteur accepte cinq attributs : `type` (l’identifiant du style), `title` (remplace le titre du style), `span`, `placement` et `columns` (remplacent les valeurs du style) ; le contenu placé entre les deux est mis en page dans l’encadré : un titre facultatif, puis les paragraphes, listes, citations, formules ou insertions de ressources, chacun composé avec la typographie `body` / `lists` du style (les titres gardent leurs styles habituels). Les marges entre enfants fusionnent comme dans le texte courant ; l’intérieur quitte la grille de ligne de base, et le flux y revient après l’encadré avec au moins `marginBottom` en dessous (la grille l’emporte ; la marge est un minimum, la même convention que suivent les ressources). Un style avec `snapToGrid: false` garde plutôt le `marginBottom` exact, et le texte qui suit l’encadré reste hors de la grille jusqu’au titre suivant ou à la fin d’une liste. Un titre placé juste avant un encadré reste avec lui.

Limites de cette version :

- Un encadré est gardé entier, sauf si son style fixe `keepTogether: false`. Quand il ne tient pas dans l’espace restant de la colonne, il passe en entier à la colonne ou à la page suivante, y compris hors d’une colonne vide que des bandes de flottants ou un plafond de bande ont raccourcie, pourvu qu’une colonne pleine puisse le contenir. Un encadré plus haut qu’une colonne pleine se coupe au contraire, comme un encadré sécable ; seul celui qu’aucune coupe ne peut diviser (une figure ou un tableau plus haut que la colonne, ou un `splitMinLines` qu’aucune coupe ne satisfait) est placé malgré tout et déborde ; la mise en page enregistre alors un avertissement `calloutOverflow` (`VDTDocument.warnings`), que le Sandbox liste. Un groupe `:::columns` se coupe comme l’encadré qui l’entoure, entre ses sous-colonnes (depuis postext 1.25) ; il reste entier, et peut déborder de la même façon, seulement avec `layout.flowColumns: false` ou à l’intérieur d’un encadré imbriqué. Un encadré sécable laisse derrière lui la partie qui tient (des enfants entiers, ou les lignes d’un paragraphe jusqu’à `splitMinLines` de chaque côté ; une figure, un tableau ou une formule hors texte suffisent à eux seuls pour un côté) et continue dans un encadré sans icône sur la colonne ou la page suivante, sans le titre sauf si le style le répète, et éventuellement avec une marque sous la partie qu’il laisse (voir [Marques sur un encadré coupé](#marques-sur-un-encadré-coupé)).
- Les flottants cèdent la place à un encadré insécable. Quand le bloc qui suit immédiatement la référence d’une figure est un encadré `keepTogether`, un emplacement qui ne laisserait à l’encadré aucune colonne de la bande en cours où se poser (la colonne de la référence ou une colonne vide après elle, qui le contenait avant le flottant) n’est pas pris : la figure passe à son emplacement suivant, en général la page suivante, et l’encadré reste dans le flux, comme le composerait un compositeur, plutôt que de chasser l’encadré de la page et de laisser la colonne avec la figure seule.
- `span: 'page'` dans une mise en page à plusieurs colonnes fait de l’encadré un **bloc pleine largeur** : il est mis en page sur toute la largeur de contenu et découpe la page en bandes de colonnes ; les colonnes de texte au-dessus sont fermées à la ligne de coupe, l’encadré occupe sa propre colonne pleine largeur, et une nouvelle bande de colonnes de texte s’ouvre en dessous : le flux continue ainsi sous l’encadré dans chaque colonne. Là où les colonnes sont *à niveau* (en haut d’une page, juste sous un titre d’ouverture `span: 'page'`, juste sous un autre bloc pleine largeur, ou juste sous une bande de flottants de tête), l’encadré coupe simplement à cet endroit. S’il arrive en milieu de page, avec des colonnes inégales, il est composé comme le ferait un compositeur : le texte au-dessus est coupé à niveau sur toutes les colonnes (le moteur relance le placement avec les colonnes de la bande raccourcies au même nombre de lignes de grille, pour que le texte passe naturellement d’une colonne à l’autre et que chaque règle d’orpheline, de veuve et de maintien avec le suivant s’applique toujours), l’encadré couvre la page et les colonnes reprennent en dessous. La coupe demande quelques passes de placement supplémentaires ; quand la ligne de coupe ne laisserait pas de place pour l’encadré plus le minimum de lignes de texte contre les veuves en dessous, ou qu’aucune disposition ne convient après quelques essais, l’encadré passe en haut de la page suivante. Le texte au-dessus respecte la coupe : un paragraphe qui ne peut pas commencer dans les quelques lignes qu’une colonne garde sous une figure au-dessus de la coupe passe à la colonne suivante (la figure reste alors seule dans sa colonne), et quand un bloc dépasserait encore la coupe, la coupe est prise une ligne plus bas plutôt qu’à la fin de ce bloc. Un encadré coupé qui ouvre la bande est coupé là aussi : son reste ne dépasse donc jamais la coupe. Avec `headings.balancing.beforeSpan` (la valeur par défaut), la bande qu’il quitte est coupée à niveau derrière lui (comme la bande qui clôt un chapitre) et, quand le style permet la coupe (`keepTogether: false`), la partie de l’encadré qui tient sous les colonnes mises à niveau ferme la page et le reste ouvre la suivante ; avec `beforeSpan: false`, la page qu’il quitte est simplement équilibrée comme d’habitude, sans forcer de saut de page. Un titre placé juste avant un bloc pleine largeur ne voyage pas avec lui. Dans les mises en page à une colonne, `span: 'page'` est simplement en ligne.
- `placement: 'fixed'` retire l’encadré du flux : il est mis en page (`width: 'auto'` s’ajuste au titre ; `'fill'` prend la largeur de la colonne de texte sous le point d’ancrage) et épinglé sur la page où il apparaît dans le flux, à la position que décrivent `fixed.anchor` / `fixed.offset` (par défaut, le coin inférieur gauche de la zone de contenu). Les colonnes de texte qu’il recouvre lui cèdent cette zone (coupée par le bas, ou par le haut quand la colonne est encore vide), exactement comme une bande de flottants ; quand la zone contient déjà du texte, un flottant ou un bloc pleine largeur, l’encadré passe à la page suivante. Un encadré fixe qui clôt le chapitre (le bloc suivant est une ouverture de chapitre, un `:::part`, un encadré barrière pour les flottants ou la fin du document) met d’abord à niveau les colonnes au-dessus de lui (`headings.balancing.trailing`) : une dernière page courte se termine ainsi à niveau, avec le badge en dessous. Le cadre et les enfants vivent dans `page.floats` et sont rendus hors du découpage des colonnes dans tous les moteurs de rendu.
- `placement: 'top' | 'bottom'` **fait flotter** l’encadré comme une ressource : il quitte le flux là où il apparaît et prend la première bande libre après ce point (le pied de la page en cours (`'bottom'`), ou la tête / le pied de la page suivante qu’ouvre le flux), à la largeur de la colonne (`span: 'column'`) ou sur toute la largeur de contenu (`span: 'page'`) ; le texte qui le suit remplit la page qu’il a quittée. Son cadre et ses enfants vont dans `page.floats`, comme pour un encadré fixe. Un encadré flottant en tête d’une nouvelle page est placé avant les figures qui attendent cette page, et une figure citée sur une page précédente qui tient ensuite sous lui prend le reste de cette page même quand il resterait moins de trois lignes de texte (une page de galerie : encadré plus figure, sans texte entre eux). Un encadré `span: 'side'` ne flotte jamais : il s’empile à côté du texte quel que soit son placement. Avec `columns` supérieur à 1 (dans le style ou comme attribut du délimiteur, depuis postext 1.18), un encadré `span: 'column'` occupe autant de colonnes adjacentes : la tête d’une suite de colonnes vides qui commencent à niveau, ou le pied de la colonne en cours et des colonnes vides qui la suivent, comme dans `:::callout{placement="top" columns="2"}`.
- `width: 'auto'` s’ajuste au titre seulement ; les enfants sont ignorés.
- Un `:::callout` imbriqué dans un autre encadré est un encadré à part entière : il est mis en page avec son propre style (fond, bordure, rayon, marge intérieure, bande, titre, icône, marque, onglet, typographie) sur toute la largeur intérieure de son parent et s’empile comme un enfant de celui-ci, ses `marginTop` / `marginBottom` fusionnant avec ses voisins. Son `span` et son `placement` (du délimiteur ou du style) sont ignorés (un encadré imbriqué suit toujours le flux de son parent), tout comme `floatBarrier` et `snapToGrid`. Les encadrés s’imbriquent à toute profondeur et peuvent se trouver dans un groupe `:::columns` (chacun entier, dans une colonne). Quand le parent se coupe, la coupe tombe avant ou après un encadré imbriqué, ou à l’intérieur quand le style imbriqué permet la coupe ; chaque fragment redessine les cadres qu’il traverse, et un encadré imbriqué qui continue depuis le fragment précédent perd son titre et son icône, comme une suite de premier niveau.
- Un groupe `:::columns{count=N}` … `:::` parmi les enfants dispose ces enfants en `N` colonnes de même largeur, séparées de `columnGap`, dans l’encadré : la suite est coupée aux limites de bloc ou de ligne qui mettent le mieux les colonnes à niveau (un paragraphe ou un élément de liste coupé au milieu continue en tête de la colonne suivante sans sa puce), chaque colonne commence en haut du groupe et le groupe est aussi haut que sa colonne la plus haute ; les enfants qui le suivent reviennent à toute la largeur. Un encadré qui se coupe (`keepTogether: false`, ou plus haut qu’une colonne) coupe aussi à l’intérieur d’un groupe, entre ses colonnes : un groupe en serpentin remplit ses colonnes tour à tour et continue dans le fragment suivant, un groupe parallèle (`breaks`) continue flux par flux (depuis postext 1.25 ; voir [Format du document › `:::columns`](/fr/docs/document-format-directives#columns)). Un `gap` sur le délimiteur remplace `columnGap` pour ce groupe, et `rule` trace un filet dans chaque gouttière. Utilisez-le pour un résumé des points clés sur deux colonnes, ou pour les tableaux d’un large encadré placés côte à côte.
- Le sixième attribut du délimiteur, `label`, s’imprime sur l’onglet du style (voir `label` plus haut) : `:::callout{type="box" label="BOX 1-1" title="The octet rule"}` ; sans style `label`, l’attribut est ignoré.

Dans le VDT, l’encadré est un bloc cadre `type: 'callout'` dont le décor (fond, bande, icône, titre) se trouve dans `designOverlay`, suivi de ses blocs enfants dans la même colonne ; le cadre et chaque enfant ont le `containerId` du délimiteur. Un encadré imbriqué est un cadre `type: 'callout'` à part parmi les enfants, suivi de ses blocs ; ceux-ci gardent le `containerId` du délimiteur de premier niveau (le placement et l’équilibrage voient toujours une seule unité) et ajoutent `calloutPath`, les identifiants de conteneur des délimiteurs imbriqués qui les entourent, du plus extérieur au plus intérieur (l’identifiant propre d’un cadre imbriqué est la dernière entrée). Le PDF balisé donne à chaque encadré imbriqué un `Div` à l’intérieur de celui de son parent. Les images d’icône se résolvent comme les images de ressource : le registre d’images du canvas, l’option HTML `resourceImageUrl` et le fournisseur PDF `resourceBytes`. L’EPUB recomposable écrit l’icône en tête de son encadré, masquée aux technologies d’assistance, et la fait flotter là où la page la dessine : sur un filet latéral, dans une colonne à elle ou sur un coin supérieur ; un livre vertical la place le long de ses lignes. Une image peinte d’une seule couleur (`tint`, une couleur `#rrggbb`) entre dans le livre comme une copie du SVG dans cette couleur ; une image bitmap y garde ses propres couleurs.

```ts
const resolved = resolveCalloutStylesConfig(config.calloutStyles, resolvedBodyText, resolvedHeadings, resolvedUnorderedLists, config.locale);
// => every inherited field filled from the resolved sections; the optional
//    locale picks the language of the continuation strings

const minimal  = stripCalloutStylesDefaults(config.calloutStyles);
// => undefined for the built-in `note` default; static defaults dropped
```

### Énoncés numérotés et démonstrations

Un style doté de `numbering` compte ses encadrés, comme `amsthm` de LaTeX compte les environnements de théorème (depuis postext 1.19). Une démonstration est un style avec une étiquette non numérotée et une marque de fin :

```ts
calloutStyles: [
  { id: 'theorem', numbering: { label: 'Theorem' }, body: { italic: true } },
  { id: 'lemma', numbering: { label: 'Lemma', counter: 'theorem' }, body: { italic: true } },
  { id: 'definition', numbering: { label: 'Definition' } },
  { id: 'proof', backgroundEnabled: false, endMark: '□',
    numbering: { label: 'Proof', counter: false, bold: false, italic: true } },
]
```

Dans un livre mis en page chapitre par chapitre, les compteurs reprennent depuis le chapitre précédent (`LayoutContinuation.statementCounters`, que remplit `continuationAfter`), et le plan du livre donne à l’ancre de chaque encadré numéroté son étiquette (`OutlineEntry.numberLabel`) : un renvoi depuis un autre chapitre peut donc l’imprimer.

### Typographie dans un encadré

Un encadré compose son contenu avec sa propre typographie `body` et `lists` ; tout le reste garde les styles du document :

- Les **paragraphes** prennent le `body` de l’encadré : caractère, taille, interlignage, couleur, couleurs d’emphase, graisses, `italic`, `smallCaps`, alignement, césure, retrait et espacement des paragraphes. Un champ non défini hérite de `bodyText`. Une couleur d’emphase héritée garde son lien avec la palette : le gras, l’italique et les étiquettes `:ref` d’un encadré changent donc avec `colorPalette`, comme à l’extérieur. (Jusqu’à postext 1.4, le gras d’un encadré restait `#295AA3` quelle que soit la Main Color.)
- Les **listes à puces** prennent les `lists` de l’encadré (caractère de puce, couleur, taille, graisse et police du glyphe, retrait, écart, espacement des éléments, marges) par-dessus `unorderedLists`, et leur texte est le texte de l’encadré. Un `lists.bulletChar` ou un `lists.color` différent de celui du document (`unorderedLists`) remplace la puce ou la couleur de tous les niveaux ; s’il le répète, ou s’il n’est pas défini, chaque niveau garde la sienne (`unorderedLists.levels`) : les tirets imbriqués sont donc conservés dans l’encadré.
- Les **listes numérotées** prennent `lists.indent`, `gap` et `itemSpacing`, et `lists.color` dès que le style le fixe, y compris quand c’est la couleur de puce du document ; un style qui ne le fixe pas garde les numéros dans `orderedLists.color`. (Jusqu’à postext 1.4, la couleur n’atteignait les numéros que si elle différait de `unorderedLists.color`, et lui donner justement cette couleur n’avait donc aucun effet.) Le numéro lui-même (son caractère, sa taille et son séparateur) vient du `orderedLists` global, puisque `lists` n’a que des champs de puce : c’est là qu’il faut régler le style des numéros d’un encadré.
- Les **`:::paragraphs` dans un encadré** utilisent leur style de paragraphe, dans les encadrés imbriqués aussi. Les champs que le style laisse non définis héritent du `bodyText` du document, non du `body` de l’encadré (ni de son italique ou de ses petites capitales).
- Les **groupes `:::columns`** n’ont pas de style propre : toutes les colonnes partagent la typographie du texte et des listes de l’encadré, et `columnGap` fixe l’écart entre elles.
- Les **citations** prennent le caractère, la taille et les graisses du texte de l’encadré (en italique et en gris, comme dans le texte courant), ainsi que ses petites capitales. Les **titres** gardent les styles de titre ; les **formules hors texte**, les réglages mathématiques.
- Les **figures et tableaux** gardent les styles de légende et de tableau du document, à la largeur intérieure de l’encadré ; leurs graisses normale et grasse suivent les graisses du `body` de l’encadré.
- Les **pastilles** gardent leur style de pastille ; une taille en `em` se lit par rapport à la taille du texte de l’encadré.
- **`:::space`** se mesure en lignes du texte de l’encadré (voir [`:::space`](/fr/docs/document-format-directives#space) pour les cas où il est supprimé).
- **Un encadré imbriqué** prend entièrement son propre style ; ses `span`, `placement`, `floatBarrier` et `snapToGrid` sont ignorés.

**Notes en retrait suspendu.** Les notes sous un tableau, une légende numérotée ou une liste de sources placent leur marque en saillie devant le texte : la marque au bord intérieur de l’encadré, le texte et toutes ses lignes suivantes un peu plus loin. `body.hangingIndent` (depuis postext 1.71) le fait pour tous les paragraphes d’un encadré ou d’un bloc de page composée doté de ce style :

- **Une longueur** place toutes les lignes sauf la première à cette distance du bord intérieur de l’encadré, comme le `hangingIndent` d’un style de paragraphe (voir [Styles de paragraphe](/fr/docs/configuration-styles#styles-de-paragraphe)). La première ligne commence au bord, ou à `body.firstLineIndent` quand le style le fixe lui-même ; un retrait de première ligne hérité de `bodyText` s’efface.
- **`true`** lit `body.firstLineIndent` comme le retrait de toutes les lignes sauf la première, comme `bodyText.hangingIndent` dans le texte courant ; `false` compose l’encadré sans retrait suspendu dans un livre dont le texte courant en a un. Non défini, l’encadré suit `bodyText.hangingIndent`.

Un taquet de tabulation à la même position mène le texte qui suit la marque jusqu’au bord des lignes suivantes, quelle que soit la largeur de la marque :

```ts
calloutStyles: [{
  id: 'notes',
  padding: { top: { value: 0, unit: 'mm' }, right: { value: 0, unit: 'mm' }, bottom: { value: 0, unit: 'mm' }, left: { value: 0, unit: 'mm' } },
  body: {
    fontSize: { value: 7, unit: 'pt' },
    hangingIndent: { value: 4.5, unit: 'mm' },
    tabStops: [{ position: { value: 4.5, unit: 'mm' } }],
  },
}],
```

```markdown
:::callout{type="notes"}
\*	Les prix comprennent la livraison en ville.

\*\*	Les adhérents paient moitié prix ; la réduction ne se cumule pas avec d’autres offres et court jusqu’à la fin de la saison.
:::
```

Chaque note est un paragraphe à part ; entre la marque et le texte se place un caractère de tabulation ou `:tab`. L’astérisque est échappé, car `*` suivi d’une tabulation en début de ligne ouvre un élément de liste. Les lignes sont mesurées ainsi, si bien que le canvas, le PDF, la liste d’affichage et l’EPUB (avec `padding-inline-start` et un `text-indent` négatif) les composent de la même façon, et l’export Word écrit le même retrait. Les éléments de liste gardent leur propre retrait (`lists.indent`, `lists.gap`), et un paragraphe placé dans un `:::paragraphs`, celui de son style. Un `firstLineIndent` négatif compte toujours pour `0` : la première ligne ne peut pas commencer dans la marge intérieure de l’encadré. Une citation placée dans un encadré suit son retrait suspendu quand `hangingIndent` vaut `true` ; avec une longueur, seuls les paragraphes propres à l’encadré sont suspendus.

### Marques sur un encadré coupé

Quand un encadré se coupe entre colonnes ou pages (`keepTogether: false`, ou un encadré plus haut qu’une colonne), chaque partie après la première s’ouvre sans le titre ni l’icône, et par défaut rien n’indique au lecteur que l’encadré continue. Deux options ajoutent les marques qu’emploie un livre ou un scénario :

- **`repeatTitle: true`** répète le titre en tête de chaque suite, suivi de `continuedSuffix` (« Key points (cont.) » par défaut). La répétition prend le style du titre : avec `textTransform: 'uppercase'`, elle donne le « HAMLET (CONT’D) » d’un scénario. L’icône et l’onglet restent sur la première partie.
- **`continuesMarkerEnabled: true`** place `continuesMarker` (« Continued », ou « Continúa » dans un document espagnol) sous la dernière ligne de chaque partie qui se poursuit, à l’intérieur de l’encadré, dans le caractère et la taille du texte de l’encadré : en italique sauf si `continuesMarkerItalic` vaut `false`, au fer à droite sauf si `continuesMarkerAlign` indique `'left'` ou `'center'`. La marque prend de la place dans la partie qu’elle clôt, et la coupe est choisie pour qu’elle tienne.

```ts
calloutStyles: [{
  id: 'speech',
  keepTogether: false,
  titleStyle: { textTransform: 'uppercase' },
  repeatTitle: true,
  continuedSuffix: "(CONT'D)",
  continuesMarkerEnabled: true,
  continuesMarker: '(MORE)',
  continuesMarkerAlign: 'center',
  continuesMarkerItalic: false,
}],
```

```md
:::callout{type="speech" title="Hamlet"}
A speech long enough to run over the foot of the page…
:::
```

La partie qui clôt la page se termine par « (MORE) », et la page suivante s’ouvre sur « HAMLET (CONT’D) ». Les deux relèvent de l’appareil de pagination : dans un PDF accessible, ce sont des artefacts, et dans le HTML elles sont masquées aux technologies d’assistance ; le titre n’est donc lu qu’une fois. Dans le VDT, ce sont des blocs de texte `designOverlay` marqués `artifact: true`.

### Maquettes d’encadré

`design` dispose les éléments d’une maquette de titre (textes, images, filets, cadres ; voir [Étendue et maquette avancée](/fr/docs/configuration-headings#étendue-et-maquette-avancée)) dans un bandeau sous le titre de l’encadré, sur toute sa largeur intérieure. Le contenu de l’encadré suit le bandeau, séparé de lui par l’écart du titre. Un encadré coupé entre colonnes ou pages ne dessine le bandeau que sur sa première partie. Depuis postext 1.45.

Les textes de la maquette lisent ces espaces réservés :

- `{titleText}` : le titre que l’encadré imprime, le `title` de la clôture ou, à défaut, celui du style.
- `{boxText}` : le contenu de l’encadré en texte brut, un paragraphe ou un élément de liste par ligne. Les vides sont omis.
- `{boxText.<n>}` : le paragraphe ou l’élément de liste de rang `n`, compté à partir de 1 ; vide si l’encadré en a moins.
- `{attr.<key>}` : un attribut écrit sur la clôture. N’importe quel nom convient, en plus de ceux que la clôture lit elle-même : `:::callout{type="card" kicker="Note"}` donne à `{attr.kicker}` la valeur `Note`. Un attribut absent n’imprime rien.
- les espaces réservés du document `{title}`, `{subtitle}`, `{author}` et `{publishDate}`.

Le `resourceId` d’une image accepte les mêmes espaces réservés, si bien que chaque encadré peut dessiner sa propre ressource. Seule une maquette d’encadré lit `{boxText}` ; une maquette de titre n’imprime rien à sa place.

Avec `setsContent: true`, un seul style sert à tous les encadrés de même forme, chacun avec ses propres mots. Dans un cahier d’écriture, chaque ligne d’exercice est un encadré dont le contenu est le mot à recopier : la maquette imprime le mot dans une écriture scolaire, puis le reprend en points à repasser (`dotted`), autant de fois que la ligne en contient (`repeat` ; voir [Marques en ligne et contours](/fr/docs/configuration-headers-footers#marques-en-ligne-et-contours)).

```ts
calloutStyles: [{
  id: 'practice',
  backgroundEnabled: false,
  border: { enabled: true, color: { hex: '#9aa6b2', model: 'hex' }, width: { value: 0.5, unit: 'pt' } },
  design: {
    setsContent: true,
    minHeight: { value: 16, unit: 'mm' },
    slot: { elements: [
      { kind: 'text', id: 'model', content: '{boxText}', fontFamily: 'Playwrite FR Moderne', fontSize: { value: 26, unit: 'pt' },
        placement: { anchor: { to: 'container', edge: 'top-left' } } },
      { kind: 'text', id: 'copies', content: '{boxText}', fontFamily: 'Playwrite FR Moderne', fontWeight: 100, fontSize: { value: 26, unit: 'pt' },
        dotted: {}, repeat: { gap: { value: 8, unit: 'mm' } },
        placement: { anchor: { to: '#model', edge: 'right-of' }, offset: { x: { value: 8, unit: 'mm' } } } },
    ] },
  },
}],
```

```md
:::callout{type="practice"}
chat
:::

:::callout{type="practice"}
lune
:::
```

La première ligne imprime *chat* suivi d’une rangée de copies de *chat* en pointillés, la seconde fait de même avec *lune*, et aucun des deux mots n’est composé une seconde fois sous son bandeau. Changer le mot dans le Markdown change le modèle et toutes les copies. Avec `setsContent` laissé à `false`, la maquette lit `{boxText}` de la même façon, et le contenu est composé sous le bandeau.

Dans le VDT, les éléments du bandeau sont des blocs de maquette sur le `designOverlay` du cadre, à côté du titre.
