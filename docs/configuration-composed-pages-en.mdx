# Configuration: composed pages


## Page templates

A composed page is a page whose form comes from a **template** in the configuration and whose content comes from the Markdown of a page fence, the `::::page{template="…"}` block that opens with four colons. The template names rectangles, called **frames**; the Markdown sends each piece of content to a frame by its name (its slot). Geometry never appears in the Markdown, and content text never appears in the template. The `pageTemplates` property holds the templates of the book:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

A template that sets nothing but its `id` and one frame is a whole page with that frame filling the content area. Every other field is optional:

### Frames

A frame is a named rectangle that receives typeset content. Its `name` is the slot the Markdown asks for, and it is unique in its template (a group cannot take the name of a frame either, since anchors name both the same way).

A frame is placed by its `grid` cell when the template has a grid, else by its `placement`, which works like a design element's: an anchor (`'container'` is the area, `'page'`, `'bleed'`, or `'#name'` for another frame or group), an edge, an offset and a size. A frame anchored to another one moves with it. Without either, the frame starts at the top-left corner of the area, as wide as the area, and as tall as its height rule says. How the content is poured into the frames, chained and clipped is described in [Composed pages › How the page is set](/en/docs/composed-pages#how-the-page-is-set).

### Groups

A group is a stack (top to bottom) or a row (start to end) of frames that share space and move together. Inside a group, the frames' own position along the group's direction is ignored: the group lays them out in order, with `gap` between them. When the text of one frame grows, the frames after it move along. A group is a box that frames and decoration can anchor to (`'#pagina'`).

### How groups share space

A frame declares its size: a fixed `height`, or `'auto'`, the height of what it holds, kept between `minHeight` and `maxHeight`. For a template drawn from a printed page, give each box the height it has on the page as `minHeight`: a short text keeps the drawn box, a longer one makes it taller. The page is laid out twice in the same pass, once as the template declares it and once as its content needs, and what differs between the two is the [reflow log](/en/docs/composed-pages#reflow-log).

**Stack.** The frames of a stack go one under another at their heights, `gap` between them. Each keeps its own horizontal place and width; its own vertical place is ignored.

- A group with no `placement` or `grid` of its own starts where its first frame is placed (its `placement`, or its `grid` cell in a template with a grid) and runs down as far as its frames need, to the foot of the template's area. When one frame grows, the frames after it move down by as much.
- A group with a box of its own lays its frames inside that box. When they need more than it holds, the frames with `shrink` above 0 give space back, the lowest `priority` first; frames of the same priority give in proportion to their `shrink`; none goes below its `minHeight`. Spare space goes to the frames with `grow` above 0, in proportion to it, up to their `maxHeight`; with none, `align` places the frames (`'end'` at the foot, `'center'`, `'space-between'`). A frame of the group with no placement of its own takes the group's box as its area.
- When nothing more can give, the frames nearest the group's foot give way first, each down to its `minHeight`; a frame with a fixed height keeps it, so an empty answer space or picture slot under a box that grows stays on the page and the box's own text gives way instead. No frame runs past the group's foot: the frame whose content does not fit climbs the reflow ladder (see [When content does not fit](#when-content-does-not-fit)), and what still does not fit is cut there and reported as `frameOverflow`. A frame cut below its `minHeight` or its fixed height is reported too, whether it holds content or not.
- A frame with `height: 'fill'` asks for its `minHeight` and takes spare space as if it had `grow: 1`.

**Row.** The frames of a row go side by side at their declared widths, all as tall as the row: the height of the group's box, or, with no box of its own, the tallest height its frames set: a fixed `height`, else a `minHeight` (an `'auto'` frame sets nothing more), or, when they set none, the height of the tallest content (a frame with a fixed height keeps its own). When the text of one frame runs past the row's height, the frame takes width: first the spare width of the row, then width from siblings with `shrink` above 0, the lowest `priority` first, each one never narrower than the width its own text still fits in. The width taken is the fewest whole millimetres that make the text fit; if even all the room there is would not, the frame takes none, and a row with no box of its own grows taller instead. Cards with `height: 'auto'` and a `minHeight` thus share width at that height, and the row grows only when no card has width to give. Spare width goes to the frames with `grow` above 0, then to `align`. Rows run from left to right.

**Pins.** A frame with `pin: true` keeps the box the template declares for it, even when the frame it is anchored to grows or moves: a box drawn to match the artwork stays on it. In a group, a pinned frame holds its place and the other frames go past it, `gap` kept on both sides; a pinned frame outside the group does the same for the group's frames it would overlap.

**Decoration.** A decoration element anchored to a frame (`anchor: { to: '#dinero' }`) moves with the frame when the frame grows or moves. An element with `pin: true` stays where the template draws that frame.

The result depends only on the page's content, the template and the typography: the same input gives the same page, measured in the same order with the same steps. **Holding frames at the foot of a card (since postext 1.42).** A frame anchored below the text above it follows that text: in an edition where the text is a line shorter or longer, the frames under it move up or down, while what the template draws (a card, a band, the foot) stays where it is. To keep frames at the foot of a card, where the template puts them, make the card's frames one stack with a box of the card's height. The frames above the held ones take the spare space (`grow: 1`) and give it back (`shrink: 1`); the held ones set a `minHeight`. A shorter text leaves the held frames where they were. A longer one is squeezed above them: they keep their `minHeight`, the text above is scaled down and, if it still does not fit, the layout reports `frameOverflow` and the reflow log lists `textScaled` and `overflow` for the frame above. A frame anchored to the container's foot (`bottom-left`) holds its place too, but nothing links it to the frames above it: a longer text runs over it, nothing is squeezed for it and the overlap is not reported.

```json
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }

```

The frame that grows is as tall as the room, whatever it holds, so a style with a visible background would paint all of it: paint the card in the template's decoration and leave the text frame without a style.

### Grids that repeat a frame set

A page of photo cards, a page of activity cards or a page of portraits with a name under each one is the same card drawn many times. A grid group with `repeat` draws it once in the template: the frames of one card, called the frame set, which the grid lays once per item the page's Markdown gives it. How many cards a page has is then up to the Markdown, and a translation that adds a card needs no new template. Since postext 1.48.

```ts
frames: [
  { name: 'titulo', takes: 'h1' },
  { name: 'foto', style: 'marco', placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } } } },
  { name: 'pie', style: 'pastilla', width: 'auto', layer: 2, overlap: 'allow',
    placement: { anchor: { to: '#foto', edge: 'bottom' }, offset: { y: { value: 4, unit: 'mm' } } } },
],
groups: [{
  name: 'fotos', kind: 'grid', columns: 3,
  columnGap: { value: 6, unit: 'mm' }, rowGap: { value: 10, unit: 'mm' },
  repeat: { frames: ['foto', 'pie'] },
}],
```

- **The set.** The first frame of `repeat.frames` is the cell's **main** frame: it takes the cell's width and keeps its own height rule (`'auto'` is the height of its content, between `minHeight` and `maxHeight`). The other frames of the set are laid as the template draws them, anchored to the main frame or to each other: here the caption pill hangs from the foot of the photo. A frame of the set anchored to a frame outside it stays where that anchor puts it.
- **Items.** Each `:::frame{slot="foto"}` piece of the page is one item: pieces of a repeated slot are not joined. Inside the piece, a block that names a member of the set (`:::frame{slot="pie"}`, `::resource{… slot="pie"}`) goes to that member of the same card; the rest goes to the main frame. See [Composed pages › Repeated slots](/en/docs/composed-pages#repeated-slots).
- **Instances.** Each card's frames are named `<frame>[n]`, counted from 1: `foto[2]` and `pie[2]` are the second card. Warnings, the reflow log, the source map and the Sandbox use these names, the frame ids are `cp<n>:foto[2]`, and a decoration element or a connector can anchor to `'#foto[2]'`. A connector's `to: '#foto[*]'` reaches every card the page has. An element anchored to `'#foto'` reads the grid's box.
- **Cells.** Cells fill the rows from the start side, so on a right-to-left page the first card is on the right. A row is as tall as its tallest cell, counting what hangs above the main frame (a tab) and below it (a pill); `rowAlign` places the shorter ones. The grid's box is its own `placement` or `grid` cell; without one it starts where the template draws the main frame and runs to the right edge and the foot of the area.
- **When the cards do not fit.** A row past the grid's foot is cut there, each card climbs the reflow ladder on its own, and the last card cut reports `frameOverflow`. With `overflow.continueIn` on the main frame (`'next-page'`, `'template:<id>'`), the grid goes on **by whole rows**: the first row that does not fit, and every row after it, are laid on the added page, in the grid of a template that repeats the same frame set. A cell taller than the whole grid warns instead of going on for ever.
- **`max`.** The items past `repeat.max` go to the flow frame, or after the page when the template has none, and each one raises `repeatOverflow`.

A grid without `repeat` lays the frames it lists, one per cell, in the order written. A frame of a repeated set listed in another group is skipped there (`groupFrameTwice`), and a name the template does not have is `groupFrameUnknown`. `grow` and `shrink` do not apply to the rows of a grid, nor `redistribute` to its cards.

### Modules

A textbook page often stacks blocks that recur across the book in another order: a box with a photo beside it, a tree of three ideas, a grid of four photos under a heading. Drawing a template for each order multiplies templates. A **module** is one of those blocks drawn once: a template with `role: 'module'`, holding frames, groups and decoration (connectors included), and no page of its own. A page template takes modules in a group with `modules: true`; the page's Markdown says which modules it holds and in what order (see [Composed pages › Modules in a page](/en/docs/composed-pages#modules-in-a-page)). Since postext 1.48.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'titulo', takes: 'h1' }],
    groups: [{ name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' }, offset: { y: { value: 6, unit: 'mm' } },
        size: { width: 'fill', height: 'fill' } } }] },
  { id: 'arbol', role: 'module',
    frames: [
      { name: 'raiz', style: 'nodo', width: { value: 56, unit: 'mm' }, placement: { anchor: { to: 'container', edge: 'top' } } },
      { name: 'izq', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: -44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
      { name: 'der', style: 'nodo', width: { value: 56, unit: 'mm' },
        placement: { anchor: { to: '#raiz', edge: 'below' }, offset: { x: { value: 44, unit: 'mm' }, y: { value: 10, unit: 'mm' } } } },
    ],
    decoration: { elements: [
      { kind: 'connector', id: 'ramas', routing: 'tree', from: { to: '#raiz' }, to: [{ to: '#izq' }, { to: '#der' }] },
    ] } },
],
```

- **What a module has.** Frames, groups (a grid that repeats included), decoration and connectors. It has no `area`, `header`, `footer`, `variants`, `spread`, `gutter` or `overflowTemplate`: each of those is reported as `unknownConfigValue` and ignored. `extends` works between modules (a template that extends a module is a module).
- **Its box.** A module is as wide as its group and as tall as its frames reach; the group stacks the modules from its top, `gap` between them. Inside a module, `'container'` is the module's box, for its frames (`'fill'` and percentages too) and for its decoration: a ground sized to `{ to: 'container', edge: 'bottom' }` covers the module whatever height its words give it.
- **Names.** A module's frames, groups and elements are scoped by the module's instance name: `<name>.<frame>`, with the name the Markdown gives (`name="ramas"`) or else `<template>[n]`, the module's count among the page's modules of that template (`arbol[2].raiz`). Anchors, `next`, `continueIn: '#x'` and connectors inside a module are rewritten to its own frames, so two trees on one page never join each other. A frame id reads `cp0:arbol[2].raiz`.
- **When modules do not fit.** A module past the group's foot is cut there and its frames climb the reflow ladder; `frameOverflow` is raised once for the group. With `overflow.continueIn` on the modules group (`'next-page'` or `'template:<id>'`), the first module that does not fit and every module after it go on **whole** to the added page, under the same names, at the top of that page's modules group. In a row or a grid of modules a row goes on whole: its modules are never split between two pages.
- **Side by side.** A modules group with `kind: 'row'` sets its modules start to end, each as wide as its template's `width` (a length, `{ percent: 48 }`, or `'fill'`, an equal share of what is left) and the row as tall as its tallest module; `kind: 'grid'` sets them in `columns` equal columns, row after row. `rowAlign` places a module shorter than its row. Rows run from the start side of the line, so a right-to-left page sets the first module on the right. Since postext 1.50.
- **Groups inside the stack.** A modules group with `within: '<stack>'` lies inside the page's modules stack, and `templates` says which modules it takes: each run of them in the Markdown becomes one row or grid of the stack, where its first module comes. With the groups below, two `aviso` blocks followed by four `tarjeta` blocks make a row of two boxes over a 2 × 2 of cards, and the Markdown holds `:::module` blocks alone.
- **Groups inside groups.** Since postext 1.51 `within` may name any modules group, to any depth. With `banda` a row inside `cuerpo` and `columna` a stack inside `banda`, a box followed by two cards stands beside a column of the two cards. A page frame anchored to `#banda` is placed after the modules.
- **Sharing a row.** Since postext 1.51 the room a row of modules leaves goes by each module's `grow`, and a row wider than its group gives width back by `shrink`.
- **Not yet.** A module inside a module (`moduleNested`) and template `grid` cells inside a module.

```ts
groups: [
  { name: 'cuerpo', modules: true, gap: { value: 8, unit: 'mm' } },
  { name: 'par', modules: true, within: 'cuerpo', kind: 'row', templates: ['aviso'], gap: { value: 6, unit: 'mm' } },
  { name: 'tarjetas', modules: true, within: 'cuerpo', kind: 'grid', columns: 2, templates: ['tarjeta'], gap: { value: 6, unit: 'mm' } },
],
```

### When content does not fit

When a frame's content is taller than the room its group gives it, the layout tries, in order, the steps of the [reflow ladder](/en/docs/composed-pages#when-it-still-does-not-fit) and stops at the first that makes it fit: free space up to `maxHeight`, the group pushing and yielding, smaller pictures, the other frames of the group down to their minimum, smaller text, continuation on another page. These frame settings decide how far each step may go:

- `maxHeight` on a frame with a fixed `height`: the frame may grow up to it before anything is scaled.
- `minHeight` on the other frames of the group: how far they give space back; a frame never goes below what its own content needs.
- `fit.scaleImages` and `fit.imageMinScale`: whether the pictures of the frame and of its group may be set smaller, and down to what scale (80 % by default).
- `fit.shrinkText` and `fit.minScale`: whether the frame's text may be set smaller, and down to what scale (90 % by default). The scale is the same for the font size, the leading and the spacing; the frame keeps its size.
- `overflow.continueIn`: where the content goes on when none of this is enough: another frame, or another page (`'next-page'`, `'template:<id>'`, `'page:<id>'`), where the text goes on at full size after the piece's `overflow.mark`. A frame that can go on to another page does so before its pictures and text are set smaller, unless its `fit.preferContinue` is `false`.

Scales go in steps of 2.5 % and the layout takes the largest that fits, so a text that is a line too long is set at 97.5 %, not at the minimum. A box that must keep its type size sets `fit: { shrinkText: false }`; a page whose pictures must keep their size sets `fit: { scaleImages: false }` on the frames of its group:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

What still does not fit is reported as `frameOverflow`, with the steps tried and proposals that carry their values: see [The warning and its proposals](/en/docs/composed-pages#the-warning-and-its-proposals).

### Inheritance and variants

A template with `extends` starts from the template it names (which may itself extend another) and changes only what it writes:

- A field such as `area`, `header` or `overflowTemplate` replaces the parent's. `grid` merges key by key. `spread`, `gutter` and `role` are inherited too; `id`, `name` and `extends` are the template's own.
- `frames` and `groups` merge **by name**: an entry with the name of an inherited one changes the fields it writes and keeps the rest (`fit`, `overflow` and `padding` merge key by key; `placement` is replaced whole); `remove: true` drops it; a new name is added after the inherited ones.
- Decoration elements merge by `id` the same way; an element with a new id, or none, is added. Since postext 1.42, `{ id: 'head-even', remove: true }` in a child template's or variant's `decoration.elements` takes the inherited element of that `id` out, as `remove: true` does for a frame; an `id` the template does not inherit changes nothing. A new element with the same `id` can follow the removal in the same list.

`variants.recto` and `variants.verso` are written like a template and merge the same way, on a right or a left page. They apply after the whole `extends` chain, the root's variant first. A spread has both sides, so no variant applies to it. A variant element with the other side's `parity` is never drawn (`unknownConfigValue`).

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

A value equal to a default is never dropped when the Sandbox saves a template: in a template that extends another, or in a variant, it overrides the parent's value.

From code, `resolvePageTemplate(config, id, { parity })` returns a template with its chain merged, the variant of the side applied, every default filled in and every reference settled as the warnings below describe; `validatePageTemplates(config)` returns the warnings.

### Drawn when the page says

A decoration element, and an element of the template's `header` or `footer`, may carry `when` or `unless`, each naming an attribute of the page fence. `when: 'folio'` draws the element only on pages whose fence sets `folio`; `unless: 'frontmatter'` leaves it off pages whose fence sets `frontmatter`. A fence sets an attribute when it writes it alone (`::::page{template="pagina" frontmatter}`) or with any value but `false`. One template then serves the front matter (no folio, no band) and the body pages: the Markdown says what the page is. Since postext 1.50.

```ts
decoration: { elements: [
  { kind: 'box', id: 'band', unless: 'frontmatter',
    placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: { value: 12, unit: 'mm' } } },
    style: { backgroundColor: { hex: '#2a6f97' } } },
  { kind: 'text', id: 'folio', when: 'folio', content: '{pageNumber}',
    placement: { anchor: { to: 'page', edge: 'bottom-center' }, offset: { y: { value: -8, unit: 'mm' } } } },
] }
```

- An element anchored to an element left out, or sized to it, is left out too.
- With both keys, the element is drawn where the fence sets the `when` attribute and not the `unless` one.
- The document's and a section's running heads read them as well. A page that is not composed has no fence and sets nothing. Heading, part and box designs ignore them.
- A value that is not a non-empty string, or one written in a heading, part or box design, is reported as `unknownConfigValue` and ignored. `postext check` notes (`conditionNeverMet`) a `when` or `unless` on an attribute no page fence sets, and an `{attr.x}` nothing sets.
- After layout, `folioMissing` names a page lacking a folio or running head that most pages of its template and side draw; one whose fence turns it off does not count. Since postext 1.53.
- In the Sandbox, the element cards of running heads and decoration have **Drawn when the page says** and **Not drawn when the page says**, listing the attributes the book's fences use.

### What the layout applies

The layout applies the placement and sizes of every frame (grid, anchors, `min`/`max`, `verticalAlign`), its style and `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (and its `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) with `overflow.mark` and `overflow.fromMark`, and its `fit` (the reflow ladder's text and picture scaling, see [When content does not fit](#when-content-does-not-fit)); a group's negotiation of space (`grow`, `shrink`, `priority`, `pin`, and the group's `gap` and `align`, see [How groups share space](#how-groups-share-space)); and the template's `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` and `overflowTemplate`. Since postext 1.42 it also applies the template's `palette`, a frame's `look` and an `'auto'` width (as wide as the frame's longest line). A frame's `writingMode` and `direction` are applied since postext 1.39. Since postext 1.48 it applies grid groups and their `repeat`, modules groups and module templates, connectors and path elements in the decoration, and a frame's `overlap`. Read and checked, but not yet applied: the template's `bodyStyle`.

### Spreads

On a spread template every coordinate runs over the sheet of its two pages, with the spine in the middle: `area`, `grid`, anchors to `container`, `page` and `bleed`, and `fill` sizes all read the double width. `bleed` reaches the head, the foot and both outer edges, never the spine. A textbook's double-page timeline is one template:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2 to era-6, one grid column each, and the notes under the strip
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

A column gap wider than the `gutter` keeps the cards of a symmetric grid clear of the spine, so none of them is moved. The second band and the picture strip set `crossGutter` to run across it: each is read on the page that holds its centre and painted on both. Every word of the page, the era names on the tabs included, stays in the Markdown.

On a vertical (`vertical-rl`) book a spread is laid in the pages' flow frame, as its single composed pages are: the top of a page is the sheet's right edge and the lines run down, so the template's `x` runs down the sheet and its `y` from the sheet's right edge to its left. The sheet is the right page followed by the left one along `y`, the spine is a line across the template, and `gutter`, `crossGutter` and the cut between the pages read that axis; decoration is still laid over the physical sheet and cut at the spine. A horizontal timeline drawn for a horizontal book comes out turned on a vertical one: write a vertical book's template in its flow's frame. Since postext 1.38. A card that should read across the sheet takes `writingMode: 'horizontal-tb'`: it is set horizontally and stands upright on the vertical page (since postext 1.39).

### Connectors

A connector is a line of the decoration that joins frames: the branches of a tree diagram, an org chart, the drops of a timeline, the arrows of a flow chart, a note's pointer to a place on a map. It is laid after the frames have their final boxes, so it follows a text that grows, an edition with longer words or a group that moves its frames, and it is drawn as a vector line in every output, so the template needs no picture of the lines. Connectors are elements of a page template's or a module's `decoration`; running heads and heading designs have no frames to join, and a connector there is reported (`unknownConfigValue`) and not drawn. Since postext 1.48.

```ts
decoration: {
  elements: [

      width: { value: 1.25, unit: 'pt' }, from: { to: '#raiz' }, to: [{ to: '#a' }, { to: '#b' }], endCap: 'arrow' },
```

A label in no style, or in a style that names no type, takes the body text's family, size, weight and colour. The lines of a label of several lines stand 1.15 times its size apart, or at the borrowed paragraph style's leading. Through `paragraphStyle` a label also takes that style's italics and capitals; `fontStyle: 'italic'` and `textTransform: 'uppercase'` add them to a style that borrows none. A label style that writes `fontStyle: 'normal'` or `textTransform: 'none'` turns off the italics or the capitals of the paragraph style it borrows from (since postext 1.40); when they are left out, the paragraph style's italics and capitals hold. A label set smaller to fit keeps its halo in proportion.

`start` and `end` follow the label's direction: in an Arabic label, `start` is its right edge. An anchor shared by left-to-right and right-to-left editions of one map reads best with the label centred above or below its point. A label with a `width` breaks between words; a word wider than the measure sets the whole label smaller, down to its style's `minScale`. How labels are drawn is described in [Composed pages](/en/docs/composed-pages).

A leader leaves the label by the side of its box (its plate, else its lines) that faces the point across the wider gap, from the middle of that side, so the line never runs through the label's words, a turned label included. A point under the label's box, or a leader shorter than its end mark, draws nothing. Leaders are painted under the labels, with the picture, in every output that draws labels, and they follow the picture when it is cropped, scaled, mirrored or set across a spread.

```ts
anchors: [
  { id: 'peaks', x: 0.42, y: 0.8, labelAt: { x: 0.62, y: 0.6 }, style: 'name', leader: true },
  { id: 'lake', x: 0.531, y: 0.865, labelAt: { x: 0.76, y: 0.93 }, style: 'name', leader: { routing: 'elbow' } },
],
```

## Page template warnings

Elsewhere the engine ignores a key it does not know. Page templates and label styles are checked instead, and every problem is a configuration warning in `postext check` and in the Sandbox's Checks panel. The `path` of these warnings is a JSON pointer to the field at fault: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. When the field was inherited, the pointer names the template that wrote it. A warning that names an id or a name that does not exist also suggests the closest one that does.

A misspelt key of a template, frame, group, grid, `fit`, `overflow`, variant or label style is an `unknownConfigKey`; a word outside a setting's choices (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`, `overlap`, `rowAlign`, a connector's `routing`, caps and `side`, a leader's caps and `routing`) is an `unknownConfigValue`, and the setting keeps its default. A template with no `id`, or a frame or group with no `name`, is ignored with an `unknownConfigValue` at that field. Frame looks (`frameLooks`) are checked the same way: a look with no `id` is ignored, and a key a frame's `look` does not have is an `unknownConfigKey`.
