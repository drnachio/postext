# Configuration : titres


## Titres

La propriété `headings` règle la typographie de tous les niveaux de titre (H1 à H6). Vous pouvez définir des valeurs générales qui s’appliquent à tous les niveaux, puis redéfinir certaines propriétés niveau par niveau.

Des titres centrés pour des poèmes ou les actes d’une pièce, sans zone de maquette :

```ts
headings: {
  textAlign: 'center',
  levels: [{ level: 2, textTransform: 'uppercase' }],
}
```

Passer un objet `headings` conserve toutes les valeurs par défaut des niveaux que vous ne redonnez pas, saut de page du H1 compris (voir [Réglages par niveau](#réglages-par-niveau)).

### Réglages par niveau

Chaque niveau de titre peut redéfinir les valeurs générales par le tableau `levels`. Seul `fontSize` (plus le `breakBefore` du H1, signalé plus bas) diffère par défaut ; toutes les autres propriétés héritent des réglages généraux des titres.

La valeur par défaut du H1 reproduit la mise en page d’un livre par chapitres : chaque titre de premier niveau s’ouvre sur une nouvelle page de droite (impaire), avec une page blanche de séparation obligatoire après le chapitre précédent. Redéfinissez-le dans `levels[0].breakBefore` si votre document est moins structuré qu’un livre.

Le `breakBefore` d’un niveau est fusionné champ par champ avec cette valeur par défaut, et un objet `headings` qui ne le mentionne pas le conserve. `{ parity: 'odd' }` sur le H1 garde le saut et ne change que la parité ; `{ enabled: false }` fait s’enchaîner les chapitres :

```ts
headings: {
  fontFamily: 'Merriweather',                               // H1 still breaks to a fresh recto (always-odd)
  levels: [{ level: 1, breakBefore: { parity: 'odd' } }],    // …or: a recto, with no mandatory blank
}

headings: { levels: [{ level: 1, breakBefore: { enabled: false } }] } // chapters run on
```

**Modifié dans postext 1.5.** Jusqu’à postext 1.4, tout objet `headings` désactivait le saut du H1 à moins de redonner `levels[0].breakBefore`, et un `breakBefore` partiel complétait son champ manquant à partir de la valeur par défaut sans saut. Une configuration écrite en code pour la 1.4 avec un objet `headings` et sans saut de H1 ouvre donc désormais chaque chapitre sur un nouveau recto, avec des versos blancs si nécessaire. Pour garder des chapitres qui s’enchaînent, donnez un champ à l’entrée H1 de `levels` :

```ts
headings: { fontFamily: 'Merriweather', levels: [{ level: 1, breakBefore: { enabled: false } }] } // as 1.4 laid it out
```

Là où la configuration a été enregistrée, le moteur le détecte et s’en charge pour vous : le Sandbox pour les livres et les configurations qu’il a enregistrés à cette époque (voir **Sandbox → Persistance**), et `openBundle` / `readBundle` pour un paquet `.postext` écrit par postext 1.4 ou antérieur (voir [Paquets écrits par postext 1.4 ou antérieur](/fr/docs/configuration-bundles#paquets-écrits-par-postext-14-ou-antérieur)). Une configuration que vous avez enregistrée vous-même peut passer par `migrateConfig(config)` de `postext/bundle`, qui écrit explicitement les sauts que posait la 1.4 (`pinLegacyHeadingBreaks`) : `enabled: false` sur un H1 qui n’avait pas de saut, et `parity: 'any'` à côté d’un `enabled: true` qui n’indiquait aucune parité, sur le H1 et sur les styles de titre. Elle fige aussi la taille des formules, l’espace autour des figures en ligne (dans les encadrés aussi), les marques en ligne des titres, la taille des lettrines, la place sous une ligne terminée par un deux-points qui introduit une liste, les lignes qu’une coupe d’encadré laisse d’un paragraphe ou d’un élément de liste, les sauts de ligne aux tirets, la coupure ligne par ligne du texte en drapeau, la division d’un paragraphe sous un titre, les sauts de ligne au trait d’union d’un mot composé et l’espace sous les conteneurs `:::paragraphs`, tels que la 1.4 les composait. Passez le Markdown du livre en troisième argument, `{ content }`, et elle omet le figeage des mathématiques quand le texte n’a pas de `$`, les figeages d’espacement quand aucune ligne n’insère de ressource (celui des encadrés quand aucune n’en insère dans un encadré), le figeage des marques de titre quand aucun titre ne contient de marque, celui des lignes à deux-points quand aucune liste ne suit une ligne terminée par un deux-points, celui des coupes d’encadré quand le texte n’ouvre aucun `:::callout`, celui des tirets quand aucun tiret n’est composé collé entre deux mots, celui de la division sous un titre quand le texte n’a pas de titre, celui des conteneurs quand le texte n’ouvre aucun conteneur `:::paragraphs`, et celui des mots composés quand aucun trait d’union ne se trouve entre deux lettres ; le figeage de la coupure en drapeau ne va qu’à une configuration qui compose du texte courant en drapeau, et celui des conteneurs qu’à une configuration qui déclare un style de paragraphe (voir [Paquets écrits par postext 1.4 ou antérieur](/fr/docs/configuration-bundles#paquets-écrits-par-postext-14-ou-antérieur)). Pour les sauts seuls, appelez `pinLegacyHeadingBreaks(config)`.

`snapToGrid` fonctionne aussi par niveau. Non défini, un niveau suit `headings.snapToGrid` ; défini, il le remplace. Un même document peut ainsi placer ses H2 une ligne et demie au-dessus de leur texte, hors de la grille jusqu’au point de calage suivant, tandis que ses H3 arrondissent l’espace qui les suit à des lignes entières de la grille. Un style de titre peut aussi le régler, pour les titres qui l’utilisent.

```ts
headings: {
  marginBottom: { value: 1.5, unit: 'em' },
  levels: [
    { level: 2, snapToGrid: false }, // exactly 1.5 em under every H2
    { level: 3 },                    // inherits headings.snapToGrid: true
  ],
}
```

### Saut avant

`breakBefore` est indépendant des réglages de numérotation : l’activer force un saut de page, mais le compteur numérique n’est remis à zéro que si vous insérez explicitement une directive `:::numbering`. Les pages blanches de parité comptent comme de vraies pages dans la séquence et reçoivent en-têtes et pieds de page selon leurs règles habituelles de pages paires et impaires.

Un `:::pagebreak` placé juste avant un tel titre ne remplace pas son saut : le titre applique quand même sa parité après la page que la directive a ouverte, ce qui peut ajouter une page blanche. Voir [Styles de titre](/fr/docs/configuration-styles#styles-de-titre) pour un titre qui doit commencer juste après un saut manuel.

#### À qui appartiennent les pages blanches

Les pages blanches insérées par `breakBefore` portent des en-têtes avec le titre du chapitre selon la *raison* de leur insertion :

- Les pages insérées pour respecter une contrainte de parité (`'odd'`, `'even'`, ou la fin de parité de `'always-*'`) appartiennent au chapitre **à venir**. L’espace réservé `{chapterTitle}` de leur en-tête se résout en titre du nouveau chapitre, puisque la page blanche n’existe que pour amener le nouveau chapitre sur la bonne parité.
- La page de séparation obligatoire insérée par `'always-odd'` / `'always-even'` appartient au chapitre **précédent**. C’est une respiration voulue en fin de chapitre : l’en-tête `{chapterTitle}` affiche donc encore le titre de l’ancien chapitre.

Les titres courants et la palette d’une section stylée (voir [Styles de titre](/fr/docs/configuration-styles#styles-de-titre)) suivent les deux mêmes règles sur les pages blanches.

#### Exception du début de document

Quand le tout premier bloc du document est un titre dont le `breakBefore` est activé, ou que la source s’ouvre sur `:::pagebreak`, la contrainte de parité est ignorée tant que la première page est encore vide. Le titre tombe en page 1, comme écrit, quelle que soit la parité configurée : un document qui commence par un `# Chapter 1` configuré avec `parity: 'odd'` n’hérite donc pas d’une page blanche parasite en tête. Dès qu’un contenu a été placé, la contrainte de parité se comporte normalement.

**Une ouverture aussi haute que la page.** Quand la hauteur réservée dépasse le pied de la colonne (une couverture dont le `minHeight` est la hauteur de la page, une image ou un encadré ancré à la page ou au fond perdu et qui descend jusqu’au format rogné), l’ouverture réclame le reste de la page : le texte qui la suit commence à la page suivante, dans chaque colonne d’une maquette à deux colonnes comme d’une maquette à colonne et demie. Une couverture n’a donc pas besoin d’un `:::pagebreak` après elle (en mettre un ne fait pas de mal : il n’ajoute pas de page blanche). Un titre dans la colonne (`span: 'column'`) dont la maquette est plus haute que sa colonne réclame cette colonne, et le texte commence en tête de la suivante. Le bloc du titre descend alors jusqu’au pied de la colonne qu’il réclame, et sa maquette est mise en page par rapport à cette bande : les éléments ancrés en haut restent là où ils sont ancrés, et ceux qui suivent la bande (ancrés à son milieu ou à son pied, ou de hauteur `'fill'`) se tiennent dans la place que réclame le titre, comme ils se tiennent dans la hauteur réservée quand elle suffit (jusqu’à postext 1.4, le bloc gardait la hauteur de son texte : ces éléments étaient donc mis en page par rapport à une bande de la hauteur d’un titre, et le texte qui suivait passait sous la maquette). Les éléments d’habillage de page qui ne doivent pas réclamer la page (une bande le long de la tranche sur toute la hauteur de la page, un ornement au pied de la page) ont plutôt leur place dans la maquette de l’en-tête ou du pied de page : ancrés à `'page'` ou `'bleed'` et affichés avec `pages: 'opener'`, ils sont dessinés sur la page d’ouverture et ne réservent aucune place dans le texte.

Exemple : une ouverture de chapitre minimaliste qui affiche « Chapter N » au-dessus du titre :

```json
{
  "headings": {
    "levels": [
      {
        "level": 1,
        "span": "page",
        "breakBefore": { "enabled": true, "parity": "always-odd" },
        "advancedDesign": {
          "enabled": true,
          "slot": {
            "elements": [
              {
                "kind": "text",
                "id": "chapterLabel",
                "placement": {
                  "anchor": { "to": "container", "edge": "top" },
                  "offset": { "y": { "value": 48, "unit": "pt" } },
                  "size": { "width": "fill" }
                },
                "content": "Chapter {numberRoman}",
                "fontSize": { "value": 10, "unit": "pt" },
                "align": "center",
                "overflow": "ellipsis-end"
              },
              {
                "kind": "text",
                "id": "chapterTitle",
                "placement": {
                  "anchor": { "to": "#chapterLabel", "edge": "below" },
                  "offset": { "y": { "value": 12, "unit": "pt" } },
                  "size": { "width": "fill" }
                },
                "content": "{titleText}",
                "fontSize": { "value": 24, "unit": "pt" },
                "fontWeight": 700,
                "align": "center",
                "overflow": "wrap",
                "hyphenate": true
              }
            ]
          }
        }
      }
    ]
  }
}
```

Espaces réservés de titre disponibles dans la zone de maquette d’un niveau :

- `{titleText}` : le texte brut du titre (sans préfixe de numérotation). Un saut forcé dans le titre (`\\`) y est un saut de ligne, dans une bande d’ouverture comme dans une maquette dans la colonne (jusqu’à postext 1.4, une maquette dans la colonne imprimait une espace à cet endroit, alors que sa hauteur était mesurée avec le saut). Les lignes sur lesquelles le titre masqué se coupe dans sa colonne sont rassemblées dans le titre tel qu’il est écrit : un mot coupé après son propre trait d’union garde le trait d’union sans espace après lui, un mot que la colonne a divisé redevient entier sans le trait d’union ajouté par la coupure, un groupe soudé par une espace insécable plus large que la colonne et séparé à cette espace retrouve son espace insécable (`Capítulo XVIII`, pas `CapítuloXVIII`), et chaque autre coupure rend son espace unique. Jusqu’à postext 1.4, chaque saut de ligne devenait une espace : un titre coupé à un trait d’union imprimait donc `Word- Book`, et un saut forcé dans un tel titre était perdu.
- `{number}` : le numéro formaté selon le `numberingTemplate` du niveau.
- `{numberDecimal}`, `{numberRoman}`, `{numberRomanLower}`, `{numberAlpha}`, `{numberAlphaLower}` : le compteur du titre (le décompte courant de son niveau, quoi qu’imprime le modèle) dans d’autres formats de numération : le troisième chapitre donne `3`, `III`, `iii`, `C`, `c`, avec ou sans `numberingTemplate`. Un titre non numéroté (un style avec `numbered: false`) les laisse vides.
- `{numberWords}`, `{numberWordsLower}`, `{numberOrdinalWords}`, `{numberOrdinalWordsLower}` : le même compteur en toutes lettres, avec une capitale ou en minuscules : *Trois* / *trois*, *Troisième* / *troisième* (voir [Numéros en toutes lettres](#numéros-en-toutes-lettres)).
- `{numberHan}` : le même compteur en chiffres chinois, dans l’écriture de la `locale` du document : une ouverture composée avec `第{numberHan}回` imprime 第十二回 pour le douzième chapitre tandis que la table des matières affiche `12`.
- `{chapterNumber}`, `{chapterTitle}`, `{pageNumber}`, `{totalPages}`, `{bookTotalPages}`, `{title}`, `{subtitle}`, `{author}`, `{publishDate}` : espaces réservés de métadonnées partagés.
- `{attr.<key>}` : un attribut écrit sur la ligne du titre elle-même (`# Title {author="I. Zango Martín"}`), avec repli sur l’attribut du H1 du chapitre en cours. Les attributs absents se résolvent en chaîne vide, sans avertissement.
- `{boxText}`, `{boxText.<n>}` : le contenu d’un encadré, que seule la maquette d’un style d’encadré lit (voir [Encadrés › Maquettes d’encadré](/fr/docs/configuration-callouts#maquettes-dencadré)) ; une maquette de titre n’imprime rien à leur place.

`{chapterNumber}` imprime ce que les titres courants impriment pour le chapitre : le numéro du H1 quand son niveau (ou son style) a un `numberingTemplate`, sinon le rang du chapitre (`1`, `2`…, en continuant après les chapitres mis en page avant celui-ci), et rien pour un chapitre non numéroté ou un style dont le modèle est `''`. Une maquette de titre se rapporte au chapitre auquel appartient son titre : un titre de niveau 1 le sien, un titre inférieur le dernier titre de niveau 1 qui le précède. Cela vaut aussi là où deux chapitres se rencontrent sur une même page, tandis que les titres courants de cette page impriment le chapitre suivant. La hauteur que réserve une ouverture est mesurée avec cette même valeur. Jusqu’à postext 1.4, elle était mesurée avec le préfixe de numéro du titre (vide sans modèle) : une maquette dont la hauteur dépend de `{chapterNumber}` pouvait donc s’afficher plus haute que la place qu’elle prenait ; et la maquette imprimait le chapitre de la page : le premier de deux chapitres partageant une page affichait donc le numéro du second.

Les espaces réservés de compteur suivent le livre d’un chapitre à l’autre quand les chapitres sont mis en page un par un (les compteurs que transmet `continuationAfter()`), et l’attribut `startAt` d’un titre les fait repartir (voir **Format de document → Attributs de titre**). Une ouverture qui affiche *Chapter III* au-dessus d’un titre numéroté `3.` dans le flux et dans la table des matières :

```ts
{
  level: 1,
  span: 'page',
  numberingTemplate: '{1}.',
  advancedDesign: {
    enabled: true,
    slot: { elements: [
      { kind: 'text', id: 'label', content: 'Chapter {numberRoman}', fontSize: { value: 10, unit: 'pt' }, overflow: 'ellipsis-end',
        placement: { anchor: { to: 'container', edge: 'top-left' }, size: { width: 'fill', height: 'auto' } } },
      { kind: 'text', id: 'title', content: '{titleText}', fontSize: { value: 24, unit: 'pt' }, overflow: 'wrap',
        placement: { anchor: { to: '#label', edge: 'below' }, size: { width: 'fill', height: 'auto' } } },
    ] },
  },
}
```

#### Hauteur réservée

Un titre doté d’une maquette avancée occupe de la place dans la colonne comme n’importe quel bloc : le texte courant qui le suit commence sous cette place. Cette place est la plus grande de trois hauteurs, toutes mesurées vers le bas depuis le haut du titre (le haut de la zone de contenu pour une ouverture qui commence sa page) :

1. le texte propre du titre, composé dans la typographie du niveau (il est masqué sous la maquette, mais garde ses lignes) ;
2. le bas du contenu de la maquette, c’est-à-dire le bord inférieur le plus bas parmi les éléments qui comptent (voir plus bas) ;
3. `advancedDesign.minHeight`.

Le `marginBottom` du titre s’y ajoute (de son style de titre, de son niveau ou de `headings.marginBottom` ; 0,5 em par défaut), et le résultat est arrondi vers le haut à la grille de ligne de base quand les titres se calent. Pour une ouverture (`span: 'page'`), la même bande est laissée libre dans chaque colonne de la page. Pour un titre dans la colonne qui tient dans sa colonne, la maquette est mise en page dans la boîte du titre, qui a exactement cette hauteur.

**Quels éléments comptent.** Tous les éléments de la maquette comptent, textes, filets, boîtes et images confondus (jusqu’à postext 1.4, un élément `image` ne comptait jamais : le texte pouvait donc commencer par-dessus une image de bande, sauf si `minHeight` l’en tenait éloigné), à l’exception :

- **des éléments avec `reserve: false`** : un décor qui peut se trouver sous le texte ;
- **des éléments qui suivent la bande elle-même** : ancrés à la rangée du milieu du conteneur (`left`, `center`, `right`) ou à sa rangée du bas (`bottom-left`, `bottom`, `bottom-right`), avec une hauteur `'fill'` par rapport au conteneur (une boîte ou un filet vertical sans hauteur le remplit par défaut), et de tout élément ancré à l’un d’eux. Le conteneur est la bande réservée : ces éléments se posent donc sur son pied ou la couvrent, comme un filet sous la bande ou un panneau teinté derrière le titre. Ils suivent la hauteur ; ils ne la fixent jamais. Un texte parmi eux qui garde sa propre hauteur a quand même besoin de place : un titre ancré au pied de la bande rend la bande au moins aussi haute que lui : il ne commence donc jamais au-dessus du haut du titre. Avec `minHeight: 36mm` et le titre ancré `bottom-left`, la boîte du titre mesure 36 mm plus son `marginBottom`, arrondis vers le haut à la grille, et le titre se pose au pied de cette boîte, juste au-dessus du texte qui suit ; sans `minHeight`, un titre qui prend plus de lignes que le texte propre du titre rend la bande aussi profonde que lui. Jusqu’à postext 1.4, un tel titre était dessiné vers le haut, par-dessus le texte placé au-dessus du titre. Les boîtes, filets et images qui suivent la bande ne fixent pas un tel plancher : un panneau ancré au pied peut donc monter au-dessus du titre.

Les éléments ancrés à la page ou au fond perdu comptent selon la distance à laquelle ils descendent sous le haut du titre. Une bande en haut de la page qui s’arrête au-dessus du titre ne compte pour rien ; une image à fond perdu qui le dépasse repousse le texte jusqu’à son bord inférieur. De même pour tout ce qui se trouve bas sur la page : un sceau à 25 mm du pied de page, une bande latérale sur toute la hauteur ou un cadre réserve la page jusqu’à son bord inférieur, et le texte commence en général à la page suivante. Marquez un tel décor `reserve: false` (il est toujours dessiné et les éléments peuvent toujours s’y ancrer), et donnez au titre la place dont il a besoin avec ses éléments de texte ou `minHeight` :

```json
{
  "kind": "image", "id": "seal", "resourceId": "seal", "reserve": false,
  "placement": {
    "anchor": { "to": "page", "edge": "bottom-right" },
    "offset": { "x": { "value": -25, "unit": "mm" }, "y": { "value": -25, "unit": "mm" } },
    "size": { "width": { "value": 30, "unit": "mm" } }
  }
}
```

Un élément ancré à un élément qui ne réserve pas compte quand même, sauf s’il est marqué lui aussi (une légende posée sur le sceau a besoin de son propre `reserve: false`).

**Où elle est dessinée.** La maquette d’une ouverture (`span: 'page'`) est dessinée avant le texte : un décor qui ne réserve rien se trouve donc sous le texte. La maquette d’un titre dans la colonne est dessinée avec le bloc du titre (par-dessus les blocs qui le précèdent dans la colonne, sous ceux qui le suivent), où qu’elle soit placée au-dessus du pied de sa colonne : dans les marges latérales, la marge supérieure, le fond perdu et les colonnes voisines aussi. Le pied de la colonne la coupe, sur le canvas et dans le PDF, puisque le flux s’y arrête (voir **Plus haute que la colonne** plus bas). Jusqu’à postext 1.4, le canvas et le PDF la coupaient aussi en haut de sa colonne : une bande ancrée en haut de la page ou du fond perdu débordait donc dans les marges latérales mais s’arrêtait à la marge supérieure. Un décor ancré au pied de la page a sa place dans une ouverture, ou dans la maquette du pied de page avec `pages: 'opener'`.

**Plus haute que la colonne.** Quand la place dépasse le pied de la colonne (un `minHeight` aussi haut que la page, une image ou un cadre qui descend jusqu’au format rogné), le titre réclame le reste de sa page (une ouverture, dans chaque colonne) ou de sa colonne (un titre dans la colonne), et le texte qui le suit commence à la page ou à la colonne suivante. Son bloc descend alors jusqu’au pied de la colonne, sans jamais être ramené à la hauteur de son texte : la bande par rapport à laquelle sa maquette est mise en page est donc la place qu’il réclame (`minHeight` compris, jusqu’au pied). Une maquette plus haute que la page elle-même (un long chapeau sur une petite page d’écran) est quand même coupée au pied de la page (une maquette dans la colonne, au pied de sa colonne) : le Sandbox la signale dans le panneau **Vérifications** sous le nom *Maquette de titre coupée*. La mise en page ne déclenche aucun avertissement pour cela (une couverture qui réclame sa page est le cas habituel et ne perd rien), mais tout hôte peut lancer la même vérification sur la mise en page terminée : `collectHeadingDesignCuts(doc)` renvoie un `{ kind: 'headingDesignCut', pageIndex, level, where, overflowPx, sourceStart, sourceEnd }` pour chaque titre dont le texte de maquette dépasse le pied du format rogné de la page (`where: 'page'`, une ouverture) ou de sa colonne (`where: 'column'`), et `formatWarning` décrit chacun d’eux. Voir **Une ouverture aussi haute que la page** sous [Étendue et maquette avancée](#étendue-et-maquette-avancée).

**Un titre qui remplit sa colonne.** Un titre de colonne (`span: 'column'`) dont la hauteur réservée atteint le pied de sa colonne, de sorte que le texte qui suit commence dans la colonne ou la page suivante, déclenche l’avertissement de contenu `headingClaimsColumn` (`level`, `element`). `element` est l’identifiant de l’élément de la maquette qui descend le plus bas ; il est absent quand `minHeight` fixe la hauteur. Mettez `reserve: false` sur l’élément s’il n’est qu’un décor, baissez `minHeight`, ou donnez `span: 'page'` au niveau si la page doit appartenir au titre. Une ouverture pleine page réclame sa page à dessein et n’est pas signalée ; pas plus qu’un titre sur une page d’une seule colonne, où la colonne est la page, ni qu’un titre suivi d’une coupure explicite (`:::pagebreak`, un `breakBefore`, un saut de colonne). Le Sandbox la signale dans le panneau **Vérifications** sous le nom *La maquette du titre remplit sa colonne*. Depuis postext 1.43.

**La colonne latérale.** Dans une maquette à colonne et demie dont la colonne latérale reçoit les flottants (`sideColumnRole: 'floats'`), un élément de la maquette d’un titre dans la colonne qui se trouve dans la colonne latérale (un numéro de chapitre ancré à la page dans la colonne de marge extérieure d’une ouverture de manuel) en tient la pile latérale éloignée. Chaque figure, tableau ou encadré `span: 'side'` que la page compose après le titre garde un écart de flottant libre autour de chacun de ces éléments : il reste là où la pile le place quand il tient au-dessus de l’élément, et passe sinon dessous, ou attend la page suivante quand le reste de la colonne latérale ne peut pas l’y contenir. Un numéro en tête du couloir latéral tient donc toute la pile sous lui, tandis qu’un numéro de section suspendu dans la marge à côté d’un titre plus bas sur la page laisse la tête du couloir aux figures que la page cite (la figure marginale se place toujours en haut de sa page). Ce que la colonne latérale contient déjà quand le titre est placé n’est pas déplacé : une figure empilée plus tôt sur la page qui descend jusqu’à l’élément du titre reste où elle est, sous l’élément ; une maquette dont l’élément se trouve dans la colonne latérale au milieu de la page veut donc ses figures citées après le titre. Les éléments avec `reserve: false` laissent la colonne latérale libre, comme ils laissent le texte. Une ouverture (`span: 'page'`) n’a besoin de rien de tel : sa bande est réservée dans chaque colonne, colonne latérale comprise. Jusqu’à postext 1.4, une figure latérale citée sur une telle ouverture était placée en tête de la colonne latérale, par-dessus le numéro.

**Couvertures.** Un titre de couverture qui remplit sa page (`minHeight` aussi haut que la page, ou une image pleine page dans sa maquette) envoie donc de lui-même le texte qui le suit à la page suivante, dans les maquettes à une ou à plusieurs colonnes. Un `:::pagebreak` juste après lui est facultatif et ne fait pas de mal : un saut de page sur une page encore vide ne fait rien, il n’ajoute donc jamais de page blanche. Il n’est nécessaire que lorsque la maquette de la couverture s’arrête avant le pied de la page et que le texte doit quand même commencer sur une nouvelle page.

```md
# Annual report 2026 {style="cover"}

:::pagebreak

# Letter from the chair
```

Une page de table des matières composée dans le texte courant, avec le titre dans une maquette de titre, montre la même chose : une boîte ancrée au fond perdu qui descend jusqu’au rognage réserve toute la colonne, et la première entrée de la table passe à la page suivante, laissant la page vide. Marquez la boîte `reserve: false`. Si la table a besoin d’un fond sous toute la feuille, composez-la plutôt dans un bloc d’une [page composée](/fr/docs/composed-pages) : le décor du gabarit est dessiné sous le texte, sur chaque page que prend la table.

#### Dans les encadrés et les blocs

Un titre placé dans un encadré (`:::callout`) ou dans un bloc d’une [page composée](/fr/docs/composed-pages) est lui aussi dessiné par sa maquette : l’`advancedDesign` de son niveau ou de son style de titre pose l’onglet, le bandeau, les filets et `{titleText}` à la place de ses lignes, comme dans une colonne de la page. La maquette se compose sur la boîte du titre lui-même, aussi large que le texte de l’encadré, et l’encadré garde la place qu’elle prend : la plus haute entre le texte du titre, le bas du contenu de la maquette et `minHeight` ([Hauteur réservée](#hauteur-réservée)). Un encadré n’a pas de grille de lignes de base, donc cette place n’est pas arrondie à une ligne ; le `marginBottom` du titre suit, comme après tout titre de l’encadré. Un élément ancré au conteneur avec un décalage négatif sort de la boîte du titre, sur la marge intérieure ou l’onglet de l’encadré ; l’encadré ne le coupe pas, sauf si le contenu d’un bloc dépasse son pied (un bloc qui déborde rogne tout ce qu’il contient). Les éléments ancrés à `'page'` ou `'bleed'` restent rapportés à la page.

Un titre `span: 'page'` dans un encadré se compose comme un titre de colonne, à la largeur de l’encadré : un encadré n’ouvre ni page ni bandeau d’ouverture. Son style de titre lui donne toujours son aspect, mais un titre dans un encadré n’ouvre pas de section stylée : les titres courants, le rôle de la page et les valeurs `{attr.…}` du chapitre viennent toujours des titres du flux. Un encadré n’est jamais coupé entre les lignes d’un titre que sa maquette dessine.

Dans un bloc dont l’ajustement réduit le texte (`fit.minScale`), la maquette est réduite avec le texte et un élément ancré à la page reste au coin de la page, ses décalages à la même échelle ; un bloc pivoté fait pivoter la maquette avec lui ; sur une double page, la moitié d’un bloc vue sur la page d’en face montre aussi la maquette. Un clic sur le titre imprimé par la maquette mène au Markdown du titre (`sourceAt`). Jusqu’à postext 1.36, les titres des encadrés étaient composés sans maquette : un encadré fixe, flottant ou de page composée n’en dessinait aucune, la maquette d’un style de titre n’était dessinée dans aucun encadré, et celle d’un niveau, dans un encadré de la colonne, était serrée dans la hauteur du texte du titre, par-dessus ce qui suivait. Depuis postext 1.37.

### Numéros en toutes lettres

Deux suffixes de modèle de numérotation écrivent un compteur en toutes lettres, dans la langue du document (la `locale` de premier niveau, sinon la langue de césure ; voir [Langue du document](/fr/docs/configuration-language#langue-du-document)) : `words` pour le cardinal et `ordinal` pour l’ordinal. La casse du suffixe fixe la casse des mots, comme `A` / `a` le fait pour les lettres :

  <thead>
    <tr>
      <th>Jeton</th>
      <th>Anglais (21)</th>
      <th>Espagnol (21)</th>
      <th>Chinois (21)</th>
    </tr>
  </thead>
  <tbody>
    <tr><td><code>{'{1:words}'}</code></td><td>twenty-one</td><td>veintiuno</td><td>二十一</td></tr>
    <tr><td><code>{'{1:Words}'}</code></td><td>Twenty-one</td><td>Veintiuno</td><td>二十一</td></tr>
    <tr><td><code>{'{1:WORDS}'}</code></td><td>TWENTY-ONE</td><td>VEINTIUNO</td><td>二十一</td></tr>
    <tr><td><code>{'{1:ordinal}'}</code></td><td>twenty-first</td><td>vigesimoprimero</td><td>第二十一</td></tr>
    <tr><td><code>{'{1:Ordinal}'}</code></td><td>Twenty-first</td><td>Vigesimoprimero</td><td>第二十一</td></tr>
    <tr><td><code>{'{1:ORDINAL}'}</code></td><td>TWENTY-FIRST</td><td>VIGESIMOPRIMERO</td><td>第二十一</td></tr>
  </tbody>
</table>

L’anglais, l’espagnol, le français, l’italien, l’allemand, le catalan, le portugais, le chinois, le japonais et l’arabe sont écrits en toutes lettres ; toute autre langue prend les mots anglais, comme les mentions de suite de tableau intégrées. Le chinois écrit les chiffres informels de `simp-chinese-informal` ou de `trad-chinese-informal`, selon l’écriture de la `locale` (一万 / 一萬), avec 第 devant un ordinal ; les caractères Han n’ont pas de casse, les trois graphies d’un suffixe s’impriment donc de la même façon. L’anglais suit l’usage américain (*one hundred five*, sans *and*). L’espagnol emploie par défaut les formes masculines, comme on numérote un *capítulo* ou un *libro* (*capítulo primero*, *tercero*, *veintiuno*), et écrit les ordinaux de 13 à 29 en un seul mot, comme le préfère la RAE (*decimotercero*, *vigesimoprimero*). Les cardinaux sont écrits en toutes lettres jusqu’à 999 999 et les ordinaux espagnols, catalans et portugais jusqu’à 999 ; les nombres plus grands s’impriment en chiffres.

Le français suit l’orthographe traditionnelle (*vingt et un*, *soixante et onze*, *quatre-vingts*, *deux cent un*) et écrit *premier* pour un (*Chapitre premier*, mais *vingt et unième*) ; l’italien écrit chaque nombre en un seul mot (*ventuno*, *ventitré*, *duemilaventiquattro* ; *primo*, *ventunesimo*), l’allemand aussi (*einundzwanzig*, *hunderteins* ; *erste*, *einundzwanzigste*), avec *ss* pour *ß* en allemand de Suisse (`de-CH`) ; le catalan suit l’IEC (*vint-i-u*, *dos-cents* ; *primer*, *cinquè*, *vint-i-unè*), et le portugais est celui du Brésil (*dezesseis*) sauf si la `locale` indique une autre région (`pt-PT` : *dezasseis*), avec les ordinaux latins (*vigésimo primeiro*). Les ordinaux catalans et portugais, comme les espagnols, sont écrits jusqu’à 999.

Les langues romanes tiennent compte du modificateur de genre : `-feminine` (ou `-f`) accorde les mots avec un nom féminin (`{1:Ordinal-f} partie` donne *Première partie*, `Parte {1:ordinal-f}` donne en italien *Parte prima* ; de même *vingt et une*, *veintiuna*, *vint-i-una*, *duzentas*), et `-masculine` (`-m`) est la valeur par défaut. En allemand, le cardinal ne varie pas (*Kapitel eins*), mais l’ordinal varie : sans modificateur, il prend la terminaison qu’il a après l’article, la même aux trois genres (`Das {1:ordinal} Kapitel` donne *Das erste Kapitel*) ; devant un nom sans article, `-masculine` donne *Erster Teil*, `-feminine` *Erste Lektion* et `-neuter` (`-n`) *Erstes Kapitel*. Les nombres allemands s’écrivent en minuscules, comme le veut la langue (`Kapitel {1:words}` donne *Kapitel eins*) ; `{1:Words}` met une capitale initiale, pour le mot qui ouvre le titre, et `{1:WORDS}` écrit ß en SS.

Les nombres arabes s’accordent en genre avec le nom qu’ils comptent : le suffixe accepte donc un modificateur : `-feminine` (ou `-f`) pour un nom féminin, `-masculine` (`-m`, par défaut) pour un nom masculin ; `-classical` écrit les centaines مائة, comme le font Boulaq et la plupart des imprimés égyptiens, au lieu du moderne مئة. `{1:ordinal}` écrit l’ordinal défini au nominatif qu’emploie un titre : `الفصل {1:ordinal}` donne *الفصل الأول*, *الفصل الحادي عشر*, *الفصل الحادي والعشرون* ; `الليلة {1:ordinal-feminine}` donne *الليلة الأولى*, *الليلة الحادية عشرة*, *الليلة الحادية والعشرون*, *الليلة المئتان*, et au-delà de cent la formule classique « après » : *الليلة الخامسة والأربعون بعد الثلاثمئة*, *الليلة الحادية بعد الألف*. `{1:words}` écrit le cardinal (واحد وعشرون ; au féminin إحدى عشرة, واحدة وعشرون). Les ordinaux sont écrits en toutes lettres jusqu’à 9 999 et les cardinaux jusqu’à 99 999 ; les modificateurs se combinent (`{1:ordinal-f-classical}`) ; les langues romanes et l’allemand n’en retiennent que le genre (voir plus haut), et les autres langues les ignorent. L’arabe n’a pas de capitales : la casse du suffixe ne change donc rien. Les espaces réservés de maquette `{numberWords}` et `{numberOrdinalWords}` écrivent les formes masculines ; pour une ouverture au féminin, mettez l’ordinal dans le modèle du niveau et imprimez-le avec `{number}`.

Dans une maquette de titre, `{numberWords}` / `{numberWordsLower}` et `{numberOrdinalWords}` / `{numberOrdinalWordsLower}` écrivent le compteur du titre de la même façon : l’ouverture peut ainsi afficher *Chapter One* tandis que la table des matières affiche `1`. Le `textTransform: 'uppercase'` d’un élément de texte donne les capitales :

```ts
// Spanish novel: "CAPÍTULO PRIMERO" above the title, "1." in the contents.
{ level: 1, numberingTemplate: '{1}.', span: 'page',
  advancedDesign: { enabled: true, slot: { elements: [
    { kind: 'text', id: 'n', content: 'Capítulo {numberOrdinalWordsLower}', textTransform: 'uppercase', /* … */ },
    { kind: 'text', id: 't', content: '{titleText}', /* … */ },
  ] } } }
```
