# Configuration: exercises


## Exercise styles

The `exerciseStyles` property declares the named styles an exercise picks with `:::exercise{style="…"}`. A style is the form of a family of exercises; the questions and the answers stay in the Markdown (see [Exercises](/en/docs/exercises)). One style, `exercise`, ships by default, so the fence works with no configuration; declaring `exerciseStyles` replaces it, and the first style declared is the one an exercise without `style` takes. Every field is optional, and the defaults follow the document language where schools differ: option labels, true/false letters, the long division layout, the words printed.

```ts
const config: PostextConfig = {
  exerciseStyles: [
    {
      id: 'activity',
      box: 'activity-frame',
      number: { shape: 'disc', background: { hex: '#2a5ea8', model: 'hex' } },
      instruction: { fontFamily: 'Source Sans 3' },
      options: { marker: 'circle' },
      blank: { look: 'dots', width: 'answer' },
      area: { kind: 'grid', lines: 4 },
      level: { glyph: '★', empty: '☆' },
      icons: { pair: { glyph: '👥' } },
    },
    { id: 'quiz', extends: 'activity', options: { layout: 'row', columns: 4 } },
  ],
};
```

## Book settings

The `exercises` property holds the settings of the whole book: the edition, where solutions print, the seed of every shuffle and the screen editions. A book that sets neither `exercises` nor `exerciseStyles` lays out and hashes as before.

```ts
const config: PostextConfig = {
  exercises: {
    edition: 'student',
    solutions: { placement: 'chapterEnd', layout: 'key' },
    seed: 3,
    digital: { check: 'instant' },
  },
};
```

The screen can have its own exercise settings: `htmlViewer.overrides` takes `exercises` and `exerciseStyles` too, merged over the book's before the HTML viewer lays out, so print keeps its solutions at the end of the chapter while the screen hides them, or the screen drops the writing areas a reader has no use for.

```ts
const config: PostextConfig = {
  htmlViewer: {
    overrides: {
      exercises: { solutions: { placement: 'none' } },
      exerciseStyles: [{ id: 'exercise', area: { kind: 'none' }, blank: { minWidth: { value: 6, unit: 'em' } } }],
    },
  },
};
```

### Assessment

By default an exercise is practice: the reader checks as often as they like, starts again and looks at the solution. Four settings make it a test, for the book in `exercises.digital` and for a style in its `digital`, which wins for that style's exercises:

```ts
const config: PostextConfig = {
  exercises: { digital: { passingScore: 60 } },
  exerciseStyles: [
    { id: 'exercise' },
    { id: 'test', extends: 'exercise', digital: { maxChecks: 1, maxResets: 1, showSolution: 'noChecksLeft' } },
  ],
};
```

- **`maxChecks`** counts the Check presses of an attempt. The button shows how many are left ("Check (2 left)"); once they are spent it reads "No checks left", the answers lock and the score stays on the bar.
- **`reset`** and **`maxResets`**: Try again clears the answers and starts a new attempt, with its checks back. `maxResets: 1` allows one fresh start, two attempts in all, and the button shows how many are left; `reset: false` takes the button away.
- **`showSolution`**: `'always'`; `'afterCheck'`, once the attempt has been checked; `'noChecksLeft'`, once its checks are spent or its answers checked all right; `'never'`. While checks are limited, showing the solution ends the attempt.
- **`passingScore`** is what a SCORM package reports passed or failed against (see [SCORM packages](/en/docs/configuration-html-folio-epub#scorm-packages-postext-scorm)).

The words on the buttons follow the document language. With `check: 'instant'` there is no Check button, so `maxChecks` does not apply; the other settings do. The checks and fresh starts used are kept with the answers: in an LMS, a SCORM package keeps them in the LMS, so they hold on any device; in an HTML page or an EPUB book they live in the reader's browser, and a reader who clears its storage starts again.
