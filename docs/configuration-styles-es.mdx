# Configuración: estilos y partes


## Estilos de párrafo

La propiedad `paragraphStyles` declara estilos con nombre que el documento aplica a una serie de párrafos mediante un contenedor `:::paragraphs{style="…"}`: bibliografías, glosarios, notas o cualquier bloque de entradas que necesite su propia letra, peso, cursiva, cuerpo, interlineado, mayúsculas, versalitas o sangría francesa. Todos los campos tipográficos son opcionales y, si no se indican, heredan del texto base, así que un estilo solo especifica lo que lo distingue del texto corrido.

```ts
const config: PostextConfig = {
  paragraphStyles: [
    {
      id: 'bibliography',
      name: 'Bibliografía',
      fontSize: { value: 7, unit: 'pt' },
      lineHeight: { value: 1.2, unit: 'em' },
      hangingIndent: { value: 2, unit: 'em' },
      spaceBetween: { value: 0.25, unit: 'em' },
      marginTop: { value: 1, unit: 'em' },
      marginBottom: { value: 1, unit: 'em' },
    },
  ],
};
```

```md
## Referencias

:::paragraphs{style="bibliography"}
Knuth, D. E. (1984). *The TeXbook*. Addison-Wesley.

Bringhurst, R. (2004). *The Elements of Typographic Style*. Hartley & Marks.
:::
```

Una obra de teatro compone sus acotaciones en cursiva y su reparto en versalitas:

```ts
paragraphStyles: [
  { id: 'acotacion', italic: true, fontSize: { value: 9, unit: 'pt' } },
  { id: 'reparto', smallCaps: true, textAlign: 'center', fontWeight: 600 },
],
```

```md
:::paragraphs{style="acotacion"}
Elsinor. Una explanada ante el castillo. *Francisco* en su puesto.
:::
```

La acotación se imprime en cursiva y el nombre que contiene, en redonda; los pesos, `italic` y `smallCaps` de un estilo también se aplican dentro de los recuadros.

Un libro de poemas sangra algunos versos y, cuando un verso no cabe en la medida, pone lo que sobra más adentro que el propio verso. `indent` desplaza hacia dentro todas las líneas del párrafo, y la sangría francesa se cuenta desde ahí:

```ts
paragraphStyles: [
  { id: 'verso', textAlign: 'left', firstLineIndent: { value: 0, unit: 'em' }, hangingIndent: { value: 4, unit: 'em' } },
  { id: 'verso-sangrado', textAlign: 'left', indent: { value: 1.5, unit: 'em' }, hangingIndent: { value: 2.5, unit: 'em' } },
],
```

Un verso en `verso-sangrado` empieza a 1,5 em y su continuación a 4 em, a la altura de las continuaciones de los versos en `verso`. Sin `indent`, un estilo puede sangrar la primera línea o las demás, no las dos: `firstLineIndent` se ignora en cuanto hay `hangingIndent`.

Una carta de restaurante compone cada precio a ras del final de la medida, tras una línea de puntos:

```ts
paragraphStyles: [
  {
    id: 'carta',
    textAlign: 'left',
    firstLineIndent: { value: 0, unit: 'em' },
    tabStops: [{ position: 'end', align: 'end', leader: '. ' }],
  },
],
```

```md
:::paragraphs{style="carta"}
Sopa de cebolla :tab 8,50

Dorada a la plancha con hinojo y limón :tab 21,00
:::
```

Los puntos de cada línea terminan medio cuadratín antes del precio (`leaderGap`). Si el nombre de un plato no cabe en su línea, continúa en la siguiente, y su última línea conserva los puntos y el precio; si el precio no cabe junto a la última palabra, esa palabra baja con él.

### El contenedor `:::paragraphs`

Una línea `:::paragraphs{style="<id>"}` abre el contenedor y una línea `:::` sola lo cierra; todos los párrafos que hay entre ambas toman el estilo indicado, mientras que los encabezados, las listas y los demás bloques del interior conservan su estilo habitual. Los contenedores pueden anidarse dentro de otros contenedores. Un `style` desconocido no es un error: los párrafos se componen como texto base normal, y el Sandbox señala el id.

La línea de apertura admite también `align` (`start`, `end`, `left`, `right`, `center`, `justify`), `indent` y `endIndent` (los números sin unidad son em), con estilo o sin él: con estilo, prevalecen sobre él; sin estilo, se aplican sobre el estilo del contenedor que lo rodea, o sobre el estilo de texto del lugar donde está el contenedor (el texto base, una parte, una sección con estilo o un recuadro). `:::paragraphs{align=end}` compone un bloque a ras del final de la línea (地付き), y `:::paragraphs{align=end endIndent=1}`, a un carácter de ese final. Desde postext 1.16.

Dentro del contenedor, el flujo sale de la rejilla base (una entrada de 7 pt con un interlineado de 1,2 em no puede encajar en una rejilla de 8 pt / 1,5 em), y el último párrafo lo devuelve a la rejilla (manda la rejilla; el espacio de debajo es un mínimo, la misma convención que siguen los encabezados). Las entradas se reparten entre columnas y páginas igual que los párrafos del texto base, con la misma protección contra viudas y huérfanas; un encabezado justo antes del contenedor se mantiene unido a su primer párrafo.

El espacio bajo el contenedor es el mayor entre el `spaceBetween` y el `marginBottom` del estilo y la separación entre párrafos del texto que lo rodea (una línea, si `bodyText.paragraphSpacing` está activado), y se funde con el espacio que el bloque siguiente deja por encima, igual que el espacio entre dos párrafos del texto base: un encabezado después de una bibliografía queda a su propio `marginTop` de la última entrada (o al espacio del estilo, si es mayor), y un párrafo después de un grupo de entradas más apretadas conserva la separación entre párrafos del texto. Primero el flujo vuelve a la rejilla bajo el texto, y lo que ese ajuste no cubre se arrastra en líneas enteras de la rejilla, para que el texto que sigue al contenedor caiga en ella. Hasta postext 1.4, el espacio del estilo se ponía bajo la última línea antes del ajuste, el espacio superior del bloque siguiente se sumaba debajo y la separación entre párrafos no contaba; `bodyText.paragraphContainerSpacing: 'add'` mantiene esa regla, y las configuraciones guardadas antes se leen con ella. Un estilo con `snapToGrid: false` no se ajusta a la rejilla: el texto que sigue al contenedor queda exactamente a ese espacio, fuera de la rejilla hasta el siguiente bloque que se ajuste. Un contenedor que se cierra con una lista se compone como en la 1.4 con cualquiera de las dos reglas: la lista conserva su propio espacio por debajo, y el `marginBottom` se cuenta a partir de ese espacio y se funde con el del bloque siguiente.

Un estilo puede fijar la regla de sus propios contenedores con `containerSpacing`: `'add'` en el estilo de una cifra grande o de una lista de referencias cierra sus grupos con el espacio del propio estilo, en el texto y dentro de un recuadro, mientras los demás contenedores del documento mantienen `'collapse'`; `'collapse'` en un estilo hace lo contrario en un documento que usa `'add'`. Un contenedor que no indica ningún estilo sigue la regla del documento.

Dentro de un `:::callout`, el contenedor aplica los márgenes de su estilo del mismo modo: `marginTop` y `marginBottom` se funden con el espaciado de los bloques que lo rodean (un valor negativo los acerca), y un contenedor que abre el recuadro no lleva margen superior, igual que en lo alto de una columna. Un recuadro no tiene rejilla base a la que volver, así que el espacio bajo el último párrafo es el mayor entre `marginBottom`, `spaceBetween` y la separación entre párrafos del propio recuadro (su `body.paragraphSpacing`, una línea de su texto; no cuenta con `paragraphContainerSpacing: 'add'`), o el margen superior del bloque siguiente, si es aún mayor; un `marginBottom` negativo, en cambio, acerca el bloque siguiente. (Hasta postext 1.4, un contenedor dentro de un recuadro no aplicaba ninguno de los dos márgenes).

Dentro de un recuadro, los campos tipográficos que un estilo deja sin fijar vienen del recuadro (desde postext 1.52): la fuente, el tamaño, el interlineado, los pesos y el color que el estilo deja al texto son los del texto del recuadro, así `:::paragraphs{style="centred"}` con un estilo que solo fija `textAlign: 'center'` se compone en la palo seco de un recuadro y en la romana de otro. Los campos que el estilo fija se mantienen. `bodyText.paragraphStylesInBoxes: 'document'` conserva en su lugar el texto del documento, como hasta postext 1.51.

```ts
const resolved = resolveParagraphStylesConfig(config.paragraphStyles, resolvedBodyText);
// => cada campo no indicado se rellena desde el texto de cuerpo resuelto

const minimal  = stripParagraphStylesDefaults(config.paragraphStyles);
// => undefined cuando la lista está vacía; se eliminan los márgenes a cero y `name === id`
```


## Estilos de chip

La propiedad `chipStyles` declara los estilos con nombre del `:chip[texto]{style="…"}` en línea: las cajas redondeadas y coloreadas de un banco de palabras, de una tecla o de una etiqueta (la sintaxis y sus reglas de corte de línea se explican en la referencia del formato del documento). Hay un estilo predeterminado, `chip` (relleno azul pálido con un filete fino del color principal, esquinas ligeramente redondeadas y el texto igual que las palabras que lo rodean), así que `:chip[…]` funciona sin configurar nada; declarar `chipStyles` sustituye esa lista predeterminada. Un chip sin `style`, o con un id que ningún estilo declara, usa el primer estilo (el Sandbox señala el id desconocido).

```ts
const config: PostextConfig = {
  chipStyles: [
    { id: 'chip', name: 'Banco de palabras' },
    {
      id: 'key',
      name: 'Tecla',
      background: { hex: '#fff4d6', model: 'hex' },
      borderColor: { hex: '#8a6d1f', model: 'hex' },
      borderRadius: { value: 2, unit: 'pt' },
      bold: true,
    },
  ],
};
```

```md
Clasifica: :chip[pila] :chip[cable] :chip[interruptor]

Pulsa :chip[Ctrl]{style="key"} + :chip[C]{style="key"}.
```

```ts
const resolved = resolveChipStylesConfig(config.chipStyles);

const style = pickChipStyle(resolved, 'key');
// => el estilo `key`, o el primero
```


## Estilos de resaltado

La propiedad `markStyles` declara los estilos con nombre del `:mark[texto]{style="…"}` en línea: la franja de color detrás de una frase, como cuando un libro de texto resalta sus palabras clave (la sintaxis y sus reglas de corte de línea se explican en la referencia del formato del documento). Hay un estilo predeterminado, `mark` (una franja amarillo pálido que sobresale un poco de la frase, con los extremos rectos y el texto en su propio color), así que `:mark[…]` funciona sin configurar nada; declarar `markStyles` sustituye esa lista predeterminada. Una marca sin `style`, o con un id que ningún estilo declara, usa el primer estilo (el Sandbox señala el id desconocido).

```ts
const config: PostextConfig = {
  markStyles: [
    { id: 'mark', name: 'Key idea' },
    {
      id: 'key',
      name: 'Definition',
      background: { hex: '#cdebd5', model: 'hex' },
      color: { hex: '#14532d', model: 'hex' },
    },
  ],
};
```

```md
The sun warms the sea and :mark[water rises into the air as vapour].

- :mark[Evaporation]{style="key"}: water turns into vapour.
```

## Listados de código

La propiedad `codeStyle` define el aspecto de los listados de código: los bloques delimitados con ```` ``` ```` y `~~~` del texto (véase [Formato del documento › Bloques de código](/es/docs/document-format#bloques-de-código)) y el código en línea cuando pide una letra de código. Un listado se compone línea a línea tal como está escrito, en una letra monoespaciada y dentro de una caja: ninguna línea se divide con guiones ni se justifica, cada espacio conserva su ancho y un tabulador avanza hasta la siguiente tabulación. La caja sale del mismo mecanismo que un `:::callout`, así que un listado se parte entre líneas a lo largo de columnas y páginas, cada parte en su propia caja, y un bloque de código dentro de un recuadro es una caja anidada en él. Todas las propiedades son opcionales. Desde postext 1.23.

```ts
const config: PostextConfig = {
  codeStyle: {
    fontFamily: 'JetBrains Mono',
    fontSize: { value: 0.8, unit: 'em' },
    background: { hex: '#0e1116', model: 'hex' },
    color: { hex: '#d3d9df', model: 'hex' },
    padding: { top: { value: 4, unit: 'mm' }, right: { value: 5, unit: 'mm' }, bottom: { value: 4, unit: 'mm' }, left: { value: 5, unit: 'mm' } },
    borderRadius: { value: 2, unit: 'pt' },
    lineNumbers: true,
    tokens: {
      keyword: { color: { hex: '#f2b134', model: 'hex' }, bold: true },
      string: { color: { hex: '#3ddc84', model: 'hex' } },
      comment: { color: { hex: '#8a939d', model: 'hex' }, italic: true },
    },
    inline: { background: { hex: '#eef1f4', model: 'hex' } },
  },
};
```

Una aplicación anfitriona conecta su propio resaltador (Shiki, Prism, highlight.js) con `registerCodeHighlighter`. Las configuraciones son datos serializables, así que la función se registra en el motor, no se escribe en `codeStyle`:

```ts
import { registerCodeHighlighter } from 'postext';

// fn(code, lang) devuelve las líneas del listado, cada una como tramos cuyos textos, unidos, forman la línea.
registerCodeHighlighter('rust', (code) => code.split('\n').map((line) => [
  { text: line, token: line.trimStart().startsWith('//') ? 'comment' : undefined },
]));
registerCodeHighlighter('*', null); // quita el registrado para todos los lenguajes
```

Un resaltador registrado para un lenguaje tiene prioridad sobre uno registrado para `'*'`, que a su vez la tiene sobre el analizador integrado. Cada tramo indica una clase de elemento en `token` (coloreada según `tokens`) o un `color` propio (un hexadecimal de CSS). Si un resaltador devuelve `undefined`, lanza una excepción o devuelve líneas que, unidas, no reproducen las del listado, se descarta. La maquetación lee el registro al componer un listado: registra el resaltador antes de compilar, y en un web worker (el Sandbox maqueta en uno) regístralo dentro del worker.

### Cómo se compone un listado

- **Una línea por cada línea del texto de origen.** Las líneas se construyen con los avances de la propia letra del código, no con el algoritmo de corte de párrafos: los espacios conservan su ancho, varios espacios seguidos se mantienen y los espacios iniciales sangran la línea. En un libro de derecha a izquierda, un listado se lee de izquierda a derecha, con sus líneas compuestas desde el lado opuesto de la caja, como una cita de izquierda a derecha, y sus números en la columna de la izquierda. En un libro vertical, un listado sigue el flujo vertical (con su texto latino girado de lado, como lo compone el texto vertical) y no lleva números de línea.
- **Partición.** Un listado más alto que el espacio que queda se parte entre líneas a lo largo de columnas y páginas, cada parte enmarcada en una caja propia, sin dejar nunca menos de `splitMinLines` líneas a un lado; el resto de una línea cortada se queda con ella si cabe otro corte.
- **Salidas.** El canvas, el visor HTML y el PDF pintan las líneas y la caja tal como se maquetaron. El visor HTML conserva los espacios (`white-space: pre`), así que al seleccionar se copia el listado con su sangría y un salto de línea después de cada línea del texto de origen, sin números ni marcas de continuación. Un PDF etiquetado compone cada listado como un párrafo que contiene un elemento `Code`, con glifos de espacio reales, y con los números y las marcas de continuación como artefactos. El EPUB de maquetación fluida escribe `<pre><code class="language-…">` con los colores de los elementos y una hoja de estilo generada a partir de `codeStyle`; el EPUB de maquetación fija reproduce la versión impresa.
- **Fuentes.** El Sandbox y `configFontFamilies` cargan la letra del código cuando el texto tiene un bloque de código (o la configuración tiene una sección `codeStyle`), en sus pesos normal y negrita, en redonda y en cursiva; el PDF incrusta las fuentes que usan las líneas.

## Partes

La propiedad `parts` configura las portadillas de parte que un documento abre con un contenedor `:::part{number="…" title="…"}`: la página «Parte I. Fundamentos» que agrupa una serie de capítulos. Una parte ocupa siempre una página propia: el contenedor salta a una página nueva con la paridad configurada, la convierte en una página de una sola columna cuya área de contenido sale de `parts.margins`, compone el diseño de apertura sobre la página entera y vuelve a saltar después de la línea de cierre para que el siguiente capítulo (con su propio `breakBefore.parity`) empiece en limpio. Con los ajustes predeterminados de H1, el resultado es la secuencia clásica: la portadilla de parte en página impar, la página par en blanco y el capítulo en la siguiente página impar.

```ts
const config: PostextConfig = {
  parts: {
    breakBefore: { parity: 'odd' },
    breakAfter: { enabled: true, parity: 'any' },
    margins: { top: { value: 9, unit: 'cm' }, left: { value: 3, unit: 'cm' }, right: { value: 3, unit: 'cm' } },
    design: {
      elements: [
        {
          kind: 'text', id: 'number', content: 'Parte {numberRoman}',
          fontSize: { value: 12, unit: 'pt' }, fontWeight: 600, align: 'left',
          placement: { anchor: { to: 'page', edge: 'top-left' }, offset: { x: { value: 3, unit: 'cm' }, y: { value: 5, unit: 'cm' } }, size: { width: 'auto', height: 'auto' } },
        },
        {
          kind: 'text', id: 'title', content: '{titleText}',
          fontSize: { value: 28, unit: 'pt' }, fontWeight: 700, align: 'left', overflow: 'wrap',
          placement: { anchor: { to: '#number', edge: 'below' }, size: { width: { value: 15, unit: 'cm' }, height: 'auto' } },
        },
      ],
    },
    bodyStyle: { fontSize: { value: 11, unit: 'pt' }, numberColor: { hex: '#AA0000', model: 'hex' } },
  },
};
```

### Marcadores del diseño de parte

El diseño resuelve los mismos marcadores que un encabezado, con los valores propios de la parte: `{titleText}` es el `title` del contenedor; `{number}`, el `number` tal como se escribió; `{numberDecimal}`, `{numberRoman}`, `{numberRomanLower}`, `{numberAlpha}` y `{numberAlphaLower}` le dan otro formato: el número se interpreta como decimal, como numeral romano o como numerales chinos, con o sin las palabras que lo rodean (`"IV"`, `"iv"`, `"4"`, `"４"`, `"四"`, `"卷四"` y `"第四卷"` dan todos `{numberDecimal}` = `4`), y con cualquier otra cosa se resuelven como `''`. También están disponibles `{partTitle}` / `{partNumber}`, `{chapterTitle}` / `{chapterNumber}` (el capítulo anterior a la parte), `{pageNumber}`, `{totalPages}`, `{bookTotalPages}` y los marcadores de metadatos. `{attr.<key>}` lee los atributos del H1 del capítulo actual.

### El diseño del verso

`versoDesign` decora la página que sigue a la portadilla cuando esa página no tiene contenido: el reverso de la hoja de la portadilla. La parte, por sí sola, nunca deja esa página en blanco. `breakAfter.parity` vale `'any'` por defecto, así que el contenido que sigue al contenedor empieza en la página siguiente, salvo que algo pida una paridad:

- **El encabezado del capítulo siguiente.** El `breakBefore` predeterminado del H1 es `'always-odd'`, y `'odd'` hace lo mismo después de una portadilla en página impar: el capítulo pasa a la siguiente página impar y la par queda en blanco. Se pinta el diseño del reverso.
- **`parts.breakAfter: { enabled: true, parity: 'odd' }`.** La propia parte pide la siguiente página impar, haga lo que haga el encabezado siguiente. Úsalo cuando los capítulos puedan empezar en cualquier lado (`breakBefore.parity: 'any'` o `breakBefore.enabled: false`).

Sin ninguna de las dos cosas, el capítulo empieza en la página par y no se dibuja el diseño del reverso. Con `breakAfter.enabled: false`, el contenido continúa en la propia portadilla. El reverso toma la paleta de la parte, así que un `palette="band=#…"` en la línea de apertura también cambia sus colores.

```ts
parts: {
  breakBefore: { parity: 'odd' },
  breakAfter: { enabled: true, parity: 'odd' },   // siempre queda un verso en blanco que pintar
  versoDesign: {
    elements: [{
      kind: 'box', id: 'campo',
      style: { backgroundColor: { hex: '#b07d2b', model: 'hex', paletteId: 'band' } },
      placement: { anchor: { to: 'page', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } },
    }],
  },
}
```

**Una parte que cierra su capítulo.** En un libro maquetado capítulo a capítulo (el Sandbox, `buildBundle`), un bloque `:::part` puede ser un capítulo por sí solo, o el final de uno. En ese caso, su portadilla es la última página del capítulo, y el capítulo siguiente se encarga de lo que la parte tiene pendiente: aplica `breakAfter` antes de su primer bloque y pinta `versoDesign` en su primera página si esta queda en blanco. Las páginas salen igual que si el libro entero estuviera en un solo documento. Después del bloque solo pueden venir directivas que no colocan nada (`:::numbering`, `:::space`); cualquier otra cosa es contenido del capítulo, que entonces hace el salto por sí mismo. Un capítulo vacío justo después de la parte es una página propia: esa página es el reverso. Una aplicación anfitriona que maqueta los capítulos por su cuenta obtiene esta información de `continuationAfter()`, que devuelve `afterPartPage: true` para un capítulo que termina con una parte; pásala en la `continuation` del capítulo siguiente.

### El contenedor `:::part`

Una línea `:::part{number="…" title="…"}` abre la parte y un `:::` solo la cierra; los dos atributos son opcionales (por defecto, `''`). Los bloques que hay entre ambas líneas (normalmente, la lista de capítulos) fluyen en la columna única de la portadilla con `bodyStyle`, a partir de `margins.top`; si el contenido no cabe en la página, continúa en páginas normales. La página se clasifica como `role: 'part'` (`VDTPage.partInfo` contiene el número y el título), de modo que los elementos de cabecera y pie pueden dirigirse a ella o saltársela con `pages: 'part'` / `pages: 'body'`; el backend PDF añade la parte al esquema de marcadores, por encima de sus capítulos. Un contenido vacío (`:::part{…}` seguido directamente de `:::`) es el caso habitual y también produce la página: dos partes consecutivas nunca comparten una. Un `:::part` anidado dentro de otra parte se integra en la exterior.

Un tercer atributo, `palette="<id>=<hex>[, <id>=<hex>…]"`, da a la parte sus propios colores: en la portadilla y en todas las páginas que la siguen, hasta la parte siguiente, cada color de diseño (cabecera, pie, banda de apertura, diseños de la portadilla y de su reverso) vinculado a uno de esos ids de paleta toma el valor de la parte en lugar del de la paleta del documento. Así es como las secciones de un libro cambian el color de la pestaña de la esquina, del punto de la cabecera y de la banda de apertura de capítulo sin un segundo diseño: `:::part{number="II" title="…" palette="band=#f6c297"}`. El flujo de texto también lo sigue: en esas mismas páginas, cualquier color del flujo igual al valor base de una entrada de paleta sustituida (encabezados; colores de negrita, cursiva y referencias; viñetas y números de lista; etiquetas y barras de los pies; texto, filetes y rellenos de tablas, es decir, cabecera, cuerpo, filas alternas y el relleno propio de una celda; recuadros, es decir, fondo, borde, franja y título, y chips, es decir, relleno, contorno y texto) toma el valor de la parte, de modo que un `headings.levels[1].color` vinculado a `band` compone los encabezados de cada sección en su propio color. Las muestras de color en línea conservan el color escrito en ellas. Los pares se separan con comas, puntos y comas o espacios; `=` o `:` une el id y el color, y la `#` es opcional. Una parte sigue vigente después de su línea de cierre: `{partTitle}`, `{partNumber}` y la paleta acompañan al flujo en los capítulos siguientes y, mediante `continuation.part` (que devuelve `continuationAfter()`), también en los capítulos maquetados por separado, de modo que el segundo capítulo de una sección muestra la sección en sus cabeceras exactamente igual que el primero.

Dos entradas de la paleta pueden compartir valor base y, aun así, tomar valores distintos en una parte, si la parte sustituye una y no la otra o les da colores distintos. El valor por sí solo no indica de qué entrada viene un color del flujo, así que cada color del flujo se asocia con los ajustes de los que puede venir y toma el valor al que remiten esos ajustes. Se distinguen:

- los colores del texto de un bloque: el color del texto, los de negrita, cursiva y referencias, la viñeta o el número de lista y el separador que sigue al número. Con `bodyText.color` vinculado a `ink` y `bodyText.boldColor` vinculado a `accent`, ambos `#1a1a1a`, una parte con `palette="accent=#b8413d"` recolorea las negritas y deja el texto; si lo que se vincula a `accent` es `unorderedLists.color`, recolorea las viñetas y deja el texto de los elementos;
- cada nivel de encabezado, y cada estilo de encabezado que fija un color;
- el texto de una fila del índice, su número, su número de página y su subtítulo;
- en cada estilo de recuadro, los rellenos (fondo, franja, pestaña de la etiqueta), el borde, los filetes (del marcador y de la etiqueta) y el texto (título, icono, glifo del marcador, etiqueta);
- cada color de cada estilo de tabla, de chip y de pie. Un estilo de tabla con nombre se distingue de `tableStyle`, y el estilo de pie de un tipo de recurso de `captionStyle`. El relleno propio de una celda sigue su propio enlace.

Queda un caso que se resuelve por valor: ajustes de sitios distintos que fijan el mismo color de un bloque. Por ejemplo, `bodyText.color`, `bodyText.blockquote.color`, el `color` de un estilo de párrafo y el `body.color` de un estilo de recuadro fijan todos el color del texto de un bloque. Si dos de ellos remiten a entradas que comparten valor base y la parte las diferencia, el color toma la sustitución (la última escrita, si se sustituyen las dos). Da a esas entradas valores base propios.

```ts
const resolved = resolvePartsConfig(config.parts, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => márgenes rellenados desde la página, bodyStyle desde el cuerpo / las listas

const minimal = stripPartsDefaults(config.parts);
// => undefined cuando solo quedan valores estáticos por defecto
```


## Estilos de encabezado

La propiedad `headingStyles` declara estilos con nombre que un documento aplica a un encabezado con `# Título {style="<id>"}`. Un estilo hace dos cosas. Por un lado, sustituye la tipografía, el diseño y la numeración del nivel del encabezado (cualquier campo de una entrada de nivel salvo `level`: fuente, cuerpo, color, `breakBefore`, `span`, `advancedDesign`, `textTransform`, `hidden`, `numberingTemplate`…). Por otro, rige la **sección** que abre el encabezado: sus páginas, hasta el siguiente encabezado del mismo nivel o de un nivel superior (de cualquier nivel con `sectionEnd: 'heading'`), toman del estilo las cabeceras y pies, la geometría de página, la tipografía del texto base y la paleta. Así, los preliminares de un libro (un prólogo a una sola columna ancha, con folios en números romanos y bandas azules) pueden convivir con un manual a dos columnas y con numeración decimal sin una segunda configuración.

```ts
const config: PostextConfig = {
```

Una sección se cierra en el siguiente encabezado del mismo nivel o de un nivel superior: un `#` sin estilo después de uno con estilo vuelve a las cabeceras y a la geometría del documento; uno con estilo abre su propia sección. Las páginas que la sección deja en blanco por paridad le pertenecen, igual que ocurre con los títulos de capítulo. Con `sectionEnd: 'heading'` la sección se cierra en el siguiente encabezado de cualquier nivel, que es lo que necesita una portada compuesta como único encabezado de nivel 1 del libro:

```ts
headingStyles: [
  { id: 'cover', numbered: false, toc: false, header: { elements: [] }, footer: { elements: [] }, sectionEnd: 'heading' },
],
```

```md
# El farero {style="cover"}

## La sala de la lámpara

…
```

La página de la portada no imprime cabeceras, y desde *La sala de la lámpara* las páginas vuelven a tomar la cabecera y el pie del documento. Con el valor por defecto, `'level'`, la sección de la portada duraría hasta el siguiente encabezado de nivel 1, que este libro no tiene, y ninguna de sus páginas llevaría cabecera.

**Un salto de página no sustituye al salto del propio encabezado.** Un estilo hereda el `breakBefore` de su nivel (el del nivel 1 es, por defecto, `{ enabled: true, parity: 'always-odd' }`), y el encabezado lo aplica esté donde esté, también justo después de un `:::pagebreak`. El salto de página abre una página nueva, y después el encabezado sigue pidiendo su lado de la doble página. Con `parity: 'odd'`, si el salto cae en una página par, se añade una página en blanco, de modo que el encabezado empieza en la siguiente impar. Con `'always-odd'` también se añade la página separadora, y el salto de página no cambia nada, porque el encabezado habría abierto esa página de todos modos. Un estilo que debe empezar en la página que abre un salto manual, como un índice después de la portada, desactiva su propio salto:

```ts
headingStyles: [
  // Empieza donde lo deja el texto: en la página que abrió el `:::pagebreak` anterior.
  { id: 'contents', numbered: false, toc: false, breakBefore: { enabled: false } },
],
```

Para conservar una página propia sin elegir lado, usa en su lugar `breakBefore: { parity: 'any' }` y prescinde del `:::pagebreak`.

**A qué sección pertenece una página.** Las cabeceras y la paleta se eligen por página, no por encabezado. Una página toma la sección vigente después del último cambio de sección que hay en ella: si una sección termina y otra empieza en la misma página (dos letras cortas de un diccionario, por ejemplo), la página lleva las cabeceras y la paleta de la segunda; si una sección con estilo termina a mitad de página en un encabezado sin estilo, la página vuelve a las del documento. `{chapterTitle}` sigue la misma regla: una página en la que se encuentran dos capítulos muestra el título del segundo. Las páginas en blanco siguen la regla de los [títulos de capítulo](/es/docs/configuration-headings#pertenencia-de-las-páginas-en-blanco): una página en blanco por paridad (`blankForParity`) pertenece a la sección que se abre después, y la separadora que añade un salto `'always-odd'` / `'always-even'` (`blankForForce`), a la sección anterior. Una portadilla de parte cierra la sección abierta.

```md
# A {style="letra"}

Aardvark, ábaco.

# B {style="letra"}

Babel, babero… (sigue en la página siguiente)
```

Las dos letras empiezan en la página 1, así que la página 1 toma las cabeceras de la sección `B`: una pestaña de uñero colocada en la cabecera del estilo dice «B» en esa página, y ninguna página lleva la pestaña de la «A». Si todas las secciones necesitan su pestaña, da a cada una una página propia (`breakBefore`).

Apéndices con letra después de capítulos numerados, y una página de dedicatoria que aparece en el índice y en los marcadores del PDF pero que no lleva título en la página:

```ts
headingStyles: [
  { id: 'apendice', numberingTemplate: 'Apéndice {1:A}' },
  { id: 'silencioso', hidden: true, numbered: false },
],
```

```md
# Dedicatoria {style="silencioso"}

Para M., que leyó todos los borradores.

# Método

…

# Cuestionario {style="apendice" startAt=1}
```

Con `numberingTemplate: '{1}.'` en el nivel 1, los capítulos imprimen *1.*, *2.*…, y los apéndices, *Apéndice A* y *Apéndice B*. La dedicatoria abre su página (por el `breakBefore` de su nivel), imprime solo su párrafo y sigue apareciendo como *Dedicatoria* en `:::toc`, en las cabeceras con `{chapterTitle}` y en el esquema del PDF; añade `toc: false` al estilo para dejarla fuera del índice. Una lámina o un mapa que se compone como H1 en mitad de un capítulo necesita lo contrario que la dedicatoria: un estilo con `runningChapter: false` (normalmente con `numbered: false` y `toc: false`) mantiene las cabeceras en el capítulo que interrumpe.

```ts
const resolved = resolveHeadingStylesConfig(config.headingStyles, resolvedPage, resolvedBodyText, resolvedUnorderedLists, resolvedOrderedLists);
// => sobrescrituras de nivel normalizadas, márgenes tomados de la página, bodyStyle del cuerpo

const minimal = stripHeadingStylesDefaults(config.headingStyles);
// => undefined cuando no queda ningún estilo
```
