# Programmatische Nutzung: PDF-Dateien


## PDFs erzeugen

Die PDF-Ausgabe liegt in einem eigenen Paket, **`postext-pdf`**, damit reine Web-Integrationen nicht die Kosten von `pdf-lib` und `@pdf-lib/fontkit` tragen. Das PDF-Backend misst Text nicht neu: Es verarbeitet genau dasselbe `VDTDocument`, das Sie auch an `renderToCanvas` oder `renderToHtml` übergeben würden, und übersetzt dessen Koordinaten im Pixelraum in PDF-Punkte. Die drei Ausgaben stimmen deshalb garantiert in Zeilenumbrüchen, Spaltenhöhen und der Platzierung von Ressourcen überein.

> **Erzeugen Sie den VDT im Browser über den [Web Worker](/de/docs/configuration-programmatic-usage#layout-in-einem-web-worker-ausführen).** `renderToPdf` selbst ist schnell, sobald der VDT existiert – der aufwendige Teil ist die Layout-Pipeline, die ihn erzeugt hat. Läuft diese Pipeline im Worker, bleibt die Oberfläche reaktionsfähig, und ein PDF-Export kann denselben Mess-Cache wiederverwenden, den die Live-Vorschau bereits gefüllt hat. Den empfohlenen Ablauf finden Sie unter [PDF-Export über den Worker](/de/docs/configuration-programmatic-usage#pdf-export-über-den-worker). Die Beispiele für den Haupt-Thread weiter unten dienen als Referenz dafür, *was die Argumente bedeuten* – erzeugen Sie in UI-Code den VDT zuerst im Worker und rufen Sie nur `renderToPdf` direkt auf.

### Installation

```bash
npm install postext postext-pdf
```

`postext` ist eine Peer-Abhängigkeit von `postext-pdf`. Jede Version von `postext-pdf` braucht die Version von `postext`, mit der sie veröffentlicht wurde, oder eine spätere derselben Hauptversion (ihr Peer-Bereich ist ein Caret-Bereich auf diese Version: `^1.5.0` für 1.5.0), weil sie Hilfsfunktionen importiert, die `postext` in dieser Version hinzugefügt hat. Aktualisieren Sie die beiden gemeinsam, und legen Sie sie auf einem CDN auf dieselbe Version fest.

### Öffentliche API von postext-pdf

Das Paket bietet einen einzigen Einstiegspunkt und eine Handvoll Typen:

- **`renderToPdf(doc, options): Promise<Uint8Array>`** – nimmt ein `VDTDocument` (oder die Kapitel eines Buches als Array solcher Dokumente) und gibt die rohen PDF-Bytes zurück.
- **`PdfFontProvider`** – die Callback-Signatur `(family, weight, style, request?) => Promise<Uint8Array | Uint8Array[]>`, mit der `renderToPdf` Schriftbytes anfordert, wenn es eine neue Kombination aus Familie, Stärke und Stil einbetten muss. `request.codePoints` enthält die Zeichen, die die Seiten in diesem Schnitt setzen; die Antwort ist eine Datei oder mehrere, die zusammen den Schnitt bilden (siehe [Chinesische, japanische und koreanische Schriften](#chinesische-japanische-und-koreanische-schriften)).
- **`declaredFontFile(bytes, { unicodeRange?, order? }): PdfFontFile`** – eine Datei eines Schnitts, die angibt, wie die Seite sie deklariert hat: die `unicode-range` ihrer Regel `@font-face` und ihre Stelle in der Deklarationsreihenfolge. Ein `PdfFontFile` ist ein `Uint8Array` mit diesen beiden optionalen Eigenschaften (siehe [Chinesische, japanische und koreanische Schriften](#chinesische-japanische-und-koreanische-schriften)). Seit postext-pdf 1.30.
- **`RenderToPdfOptions`** – `{ fontProvider, forms?, resourceBytes?, previewBytes?, outlines?, accessible?, colorSpace?, pageNegative?, characterGrid?, baselineGrid?, onProgress?, onWarning?, rasterizeSvg?, harfbuzzWasm?, print?, outputProfile?, profileBaseUrl?, date? }`. `forms` legt fest, wie Formularfelder Zahlen schreiben (Währung, auf welcher Seite sie steht, Trennzeichen), und in welchem Schnitt sie ihre Werte zeigen (`font`; siehe [Formularfelder](#formularfelder)). `outlines`, `accessible` und `colorSpace` fallen auf das `pdfGeneration` des Dokuments zurück, wenn sie fehlen (siehe [PDF-Erzeugung (Konfiguration)](/de/docs/configuration-fonts-colors-viewers#pdf-erzeugung-konfiguration)). `resourceBytes` ist unter [Ressourcenbytes und Druckoriginale](#ressourcenbytes-und-druckoriginale) beschrieben, `onWarning` unter [Welche Schnitte beim Provider angefragt werden](#welche-schnitte-beim-provider-angefragt-werden) und [Warnungen im Dokument](/de/docs/configuration-programmatic-usage#warnungen-im-dokument). `characterGrid: true` übernimmt das Raster, das `cjk.grid.show` auf dem Bildschirm zeichnet, auch ins PDF, das es sonst weglässt (siehe [Zeichenraster](/de/docs/configuration-east-asian#zeichenraster)). `harfbuzzWasm` gibt an, woher HarfBuzz’ `harfbuzz.wasm` geladen wird (eine URL, relativ zur Seite, oder die Bytes der Datei), für ein Dokument mit Text von rechts nach links oder verbundener Schrift; fehlt die Angabe, versucht postext-pdf zuerst die Kopie neben seinem eigenen Modul, dann dieselbe Version von harfbuzzjs von jsDelivr und esm.sh. `print` nimmt die Einstellungen der Druckproduktion (PDF/X-Standard, Ausgabeprofil, Schwarz, Preflight) und fällt auf das `print` des Dokuments zurück; mit einem PDF/X-Standard oder `colorSpace: 'cmyk'` wird jede Farbe über das ICC-Ausgabeprofil separiert, dessen Bytes `outputProfile` liefert (sonst wird es von `profileBaseUrl` abgerufen, standardmäßig von der Kopie des Ordners `icc/` von postext auf dem npm-CDN). `date` (ein `Date`, eine Zeit in Millisekunden oder ein Datumsstring, wie `mtime` von `createBundle`) ist das Erstellungs- und Änderungsdatum der Datei und in einer PDF/X-Datei auch das Datum ihres XMP-Pakets und die Quelle ihrer Dokument-ID: Dasselbe Dokument, zweimal mit demselben `date` gerendert, ergibt dieselben Bytes. Fehlt es, erhält die Datei den Zeitpunkt des Aufrufs. Ein ungültiges Datum wirft einen Fehler.
- **`PdfWarning`** – ein nicht fatales Problem, gemeldet über `onWarning`; unterscheiden Sie nach `kind`: `'fontFallback'` (`PdfFontFallbackWarning`), ein Schnitt, der in einem anderen Schnitt seiner Familie gesetzt wurde; `'missingGlyph'` (`PdfMissingGlyphWarning`), Zeichen, für die keine Datei eines Schnitts eine Glyphe hat; `'variableFontDefaultInstance'` (`PdfVariableFontWarning`), eine variable Schrift, die in einer anderen Stärke als ihrer Standardinstanz angefragt wurde; `'cffEmbeddedWhole'` (`PdfCffEmbeddedWholeWarning`), ein CFF-Schnitt über 2 MB, der ganz eingebettet wurde; `'complexShapingUnavailable'` (`PdfComplexShapingWarning`), Text von rechts nach links oder mit verbundener Schrift, gezeichnet ohne HarfBuzz, das nicht geladen werden konnte (`reason` nennt die durchsuchten Orte), sodass arabische Zeichen falsch platziert sind; `'outputProfileUnavailable'` (`PdfPrintWarning`), ein CMYK-Rendering, dessen Ausgabeprofil nicht geladen werden konnte und das mit der naiven Formel umgerechnet wurde; `'pageNegativeIgnored'` (`PdfPrintWarning`), das Seitennegativ, das in einer PDF/X-1a-Datei weggelassen wurde; `'spotTintsExhausted'` (`PdfPrintWarning`), ein Rendering, dem die Codes für unterschiedliche Sonderfarben-Tonwerte ausgingen (rund 25 Millionen) und das den Rest im Vierfarbdruck druckte; `'spotInkRenamed'` (`PdfPrintWarning`), eine Druckfarbe, deren Platte unter einem anderen Namen geschrieben wird (siehe [Sonderfarben](#sonderfarben)); `'imageProfileUnavailable'` (`PdfPrintWarning`), das den RGB-Bildern zugewiesene Profil ließ sich nicht laden, also wurden ihre eigenen Profile verwendet; `'pictureOriginalUnreadable'` (`PdfPrintWarning`), ein TIFF- oder Photoshop-Original, das sich nicht dekodieren ließ, aus seiner Vorschau (`previewBytes`) oder als Platzhalter gedruckt; `'plateMixesApproximated'` und `'artworkOffPlates'` (`PdfPrintWarning`), ein Auftrag auf wenigen Platten (`print.plates`), dem die Codes ausgingen und der die übrigen Farben als nächstliegende bereits codierte Mischung setzte, oder der eine PDF-Seite oder ein nicht dekodierbares Bild mit dessen eigenen Druckfarben platzierte; oder `'missingImage'`, ein Bild ohne Bytes, als Platzhalter gezeichnet (nur an ein von Ihnen übergebenes `onWarning` gemeldet; die Schriftwarnungen gehen ohne ein solches an `console.warn`).
- **`inspectPrintMaster(bytes): Promise<PrintMasterReport>`** – liest die erste Seite eines PDF-Druckoriginals und meldet die Schriften, die es verwendet, ohne sie einzubetten (`nonEmbeddedFonts`), ob es in RGB malt (`rgb`) und ob es Transparenz verwendet (`transparency`), für den [Preflight](/de/docs/configuration-pdf-output#preflight).
- **`inspectPrintPdf(bytes): Promise<PrintPdfReport>`** – liest ein fertiges PDF zurück, wie es der Preflight einer Druckerei täte, alle Seiten: Version und Seitenzahl, PDF/X-Kennung und Ausgabebedingung (und ob ihr Profil eingebettet ist), Endformat und kleinsten Anschnitt, Seiten mit anderem Endformat, ohne TrimBox oder mit einer Seitenbox, die nicht aus vier Zahlen besteht (`malformedBoxPages`, als fehlend gelesen), die Schriften (`fonts`: Name, eingebettet oder nicht, Typ; eine Schrift, die eingebettet und nicht eingebettet vorkommt, wird für jede Form einmal aufgeführt), worin es malt (CMYK, Grau, Sonderfarben mit Namen, Passer sowie RGB, aufgeteilt in `deviceRgb` ohne Profil und `iccRgb` mit Profil, jeweils in `vector`-Malerei oder in `images`), Transparenz, Überdrucken, Anmerkungen, ein interaktives Formular und ob es getaggt ist. Neben den Seiten liest es die Erscheinungsbilder der Anmerkungen, die Felder und Standardressourcen des Formulars, Muster, Type-3-Glyphen und Inline-Bilder. Es liest, was die Datei sagt, nicht, was die Konfiguration verlangte, und es liest weder Bildauflösung noch Gesamtfarbauftrag, Haarlinien oder Überfüllung. Es geht die Seiten so durch wie `inspectPrintMaster`, das auch RGB in Verläufen, Mustern und Type-3-Glyphen meldet.
- **`decompressWoff2(bytes): Uint8Array`** – Hilfsfunktion, die eine WOFF2-Datei in TTF-Bytes umwandelt, das Format, das `pdf-lib` direkt einbetten kann.
- **`createPdfWorker(options?)`** aus `postext-pdf/worker` – dasselbe Rendering in einem Web Worker; siehe [Das PDF in einem Worker rendern](#das-pdf-in-einem-worker-rendern).

### Minimales Beispiel

```ts
import { buildDocument } from 'postext';
import { renderToPdf } from 'postext-pdf';

const vdt = buildDocument(
  { markdown: '# Chapter One\n\nThe story begins here…' },
  {
    page: { sizePreset: '17x24' },
    layout: { layoutType: 'double' },
    bodyText: { fontFamily: 'EB Garamond', fontSize: { value: 9, unit: 'pt' } }, // 9 pt overrides the 8 pt default
  },
);

const pdfBytes = await renderToPdf(vdt, {
  fontProvider: async (family, weight, style) => {
    // Return TTF bytes for this family/weight/style.
    // See the "Font provider" section below for a real implementation.
    const res = await fetch(`/fonts/${family}-${weight}${style === 'italic' ? 'i' : ''}.ttf`);
    return new Uint8Array(await res.arrayBuffer());
  },
});

// `pdfBytes` is a Uint8Array — save, download, or stream it.
const blob = new Blob([pdfBytes], { type: 'application/pdf' });
const url = URL.createObjectURL(blob);
window.open(url);
```

### Warum ein Font-Provider?

`pdf-lib` bettet echte Schriftdateien in das PDF ein – die im Browser installierten Schriften stehen beim Rendern nicht zur Verfügung, und eine Schrift, die Sie nur für die Messung auf dem Bildschirm geladen haben, reicht für sich allein nicht aus, um ein in sich geschlossenes PDF zu erzeugen. `renderToPdf` durchsucht die Seiten nach jedem Schnitt, den sie zeichnen (einer pro Kombination `family|weight|style` – siehe [Welche Schnitte beim Provider angefragt werden](#welche-schnitte-beim-provider-angefragt-werden)), und ruft Ihren Provider einmal pro eindeutiger Kombination auf. Der Provider gibt ein `Uint8Array` mit **TTF- oder OTF**-Bytes zurück oder eine Liste davon für einen Schnitt, der als mehrere Dateien ausgeliefert wird (siehe [Chinesische, japanische und koreanische Schriften](#chinesische-japanische-und-koreanische-schriften)); `pdf-lib` bildet Teilmengen von TrueType-Konturen und bettet CFF-Dateien (`.otf`) ganz ein. Ein CFF-Schnitt wird auch als solcher deklariert, als `CIDFontType0`-Schrift mit ihrem CFF-Programm in `FontFile3` (`CIDFontType0C`), die `pdffonts` als `CID Type 0C` aufführt und die der Druck-Preflight erwartet. Ein CID-basierter CFF-Schnitt (Source Han, die `.otf`-Dateien von Noto CJK) behält die TrueType-Deklaration, weil seine Glyphennummerierung nicht zu der passt, in der der Text geschrieben ist; verwenden Sie für den Druck die TrueType-Fassungen dieser Familien. Schnitte, auf die der Provider mit derselben Datei antwortet, etwa ein normaler Schnitt, der für den fehlenden fetten Schnitt einer Familie einspringt, teilen sich eine eingebettete Schrift. Ein Schnitt, mit dem am Ende keine Seite zeichnet, etwa der Schnitt des Textes einer SVG-Abbildung, die als Bild gezeichnet wird, wird nicht in die Datei aufgenommen.

**Verwenden Sie statische Schriften pro Stärke, keine einzelne variable Schrift.** Google Fonts liefert pro Familie oft eine variable WOFF2-Datei, die die ganze Stärkeachse abdeckt. `pdf-lib` kann aus einer variablen Datei nur die Standardinstanz einbetten, sodass ein fetter Absatz in normaler Stärke erschiene. Fontsource veröffentlicht statische WOFF2-Dateien pro Stärke, die dieses Problem sauber lösen – nach diesem Muster arbeitet die Sandbox. Eine variable Datei, die in einer anderen Stärke als ihrer Standardinstanz angefragt wird, wird als Warnung `variableFontDefaultInstance` gemeldet.

**Jedes Wort des Textes steht genau dort, wo das Layout es hingesetzt hat.** In Absätzen, Listenpunkten, Zitaten, Kästen und anderem fließendem Text beginnt jedes Wort an der Position, die der VDT gemessen hat, sodass sich ein Unterschied zwischen den Breiten des Browsers und denen des eingebetteten Schnitts nie entlang einer Zeile aufsummiert. Eine Zeile ohne Inline-Formatierung wird als ein Textobjekt gezeichnet, das den Stift zwischen den Wörtern bewegt; Zeilen im Blocksatz, zentrierte Zeilen und Zeilen mit Formatierung werden Wort für Wort gezeichnet. Ein Zeichen, für das der Schnitt keine Glyphe hat, das der Browser in einer anderen Schrift gemessen hat und das das PDF als Kasten für fehlende Glyphen des Schnitts zeichnet, verschiebt keines der folgenden Wörter und wird einmal pro Schnitt als Warnung `missingGlyph` gemeldet. Ein Leerzeichen, das dem Schnitt fehlt, etwa ein schmales geschütztes Leerzeichen oder ein Ziffernleerzeichen, erhält die Breite, die der Browser ihm gegeben hat, und unsichtbare Zeichen wie der Word Joiner und das Leerzeichen ohne Breite werden nicht gezeichnet. Ein geschützter Bindestrich (U+2011), der dem Schnitt fehlt, wird mit dem Bindestrich des Schnitts (U+2010) gezeichnet oder, wenn dieser auch fehlt, mit dessen Hyphen-Minus, so wie der Browser ihn zeigt; Open Sans und Outfit etwa fehlen beide Zeichen. Keiner der beiden Fälle zählt als fehlende Glyphe. Es gibt zwei Ausnahmen. Eine Zeile mit Buchstaben, die von rechts nach links laufen, wird weiterhin als eine Folge gezeichnet (siehe [Sprachen und Schriftsysteme](/de/docs/configuration-language#sprachen-und-schriftsysteme)). Text, den eine Gestaltung platziert (Kolumnentitel und Fußzeilen, Auftakte, Kastentitel und andere Gestaltungselemente), wird mit den eigenen Breiten des eingebetteten Schnitts gesetzt, sodass eine dort fehlende Glyphe den Rest ihrer Zeile weiterhin verschiebt.

### Welche Schnitte beim Provider angefragt werden

`renderToPdf` geht die Seiten so durch, wie es sie zeichnet, und fragt beim Provider nur die Schnitte an, die dort tatsächlich vorkommen:

- den normalen Schnitt eines Blocks, der irgendeine Zeile setzt, und den fetten, kursiven oder fettkursiven Schnitt jeder Folge, die tatsächlich so gesetzt ist;
- Chip-Folgen, Listenzeichen und den Text in den Slots von Gestaltungselementen (Kolumnentitel, Paginas, Bänder von Auftakten und Teilen);
- den Text von Legende, Anmerkung und Tabellenzellen jeder Ressource;
- die Schnitte, die das `<text>` einer SVG-Abbildung nennt, wenn die Abbildung eingebettet wird. Eine Familie, die der Provider überhaupt nicht liefern kann, wird durch die nächste Familie in der Liste `font-family` des SVG ersetzt.

Eine Überschriftenfamilie, die niemand kursiv setzt, wird also nie nach ihrer Kursiven gefragt, und eine Abbildung ohne Anmerkung braucht nie die Schnitte für Anmerkungen.

Lehnt der Provider einen Schnitt ab, geht das Rendering weiter. Ein anderer Schnitt derselben Familie wird an seiner Stelle eingebettet, und eine `PdfWarning` wird gemeldet. Der Ersatz ist der erste Schnitt, der lädt; versucht werden die neun Standardstärken (100 bis 900) in der Reihenfolge, die der CSS-Schriftabgleich verwendet; so ergibt sich auch der Schnitt, den der Browser in der Vorschau zeigt:

1. zuerst derselbe Stil. Bei einer Stärke von 400 bis 500 kommen zuerst die Stärken bis 500, dann die leichteren von der nächstgelegenen abwärts, dann die schwereren ab 600 aufwärts. Bei einer Stärke unter 400 kommen zuerst die leichteren Stärken, von der nächstgelegenen abwärts, dann die schwereren. Bei einer Stärke über 500 kommen zuerst die schwereren Stärken, dann die leichteren;
2. dann der andere Stil, kursiv statt aufrecht und aufrecht statt kursiv, in der angefragten Stärke und den anderen Stärken in derselben Reihenfolge.

Eine Familie ohne Kursive setzt ihre kursiven Folgen daher aufrecht, eine Familie, die nur 400 und 700 mitbringt, nimmt für eine 600 die 700, und eine Familie mit einem einzigen Schnitt setzt alles darin. Der Provider wird Schnitt für Schnitt in dieser Reihenfolge gefragt und nie zweimal nach demselben Schnitt, sodass ein Schnitt, den nichts verwendet, nie eingebettet wird. Eine Familie, die der Provider überhaupt nicht liefern kann, wird nach jedem dieser 18 Schnitte gefragt, bevor das Rendering fehlschlägt.

```ts
const bytes = await renderToPdf(doc, {
  fontProvider,
  onWarning: (w) => {
    // { kind: 'fontFallback', family: 'Oswald', weight: 700, style: 'italic',
    //   fallback: { weight: 700, style: 'normal' }, reason: '…', message: '…' }
    console.info(w.message);
  },
});
```

Ohne `onWarning` geht die Meldung an `console.warn`. Der Text behält seine Positionen, die aus dem VDT stammen und mit den Schnitten gemessen wurden, die der Browser hatte; ein Ersatz mit anderen Breiten kann daher eng oder locker wirken. Liefern Sie den echten Schnitt, um das zu beheben. Ein Rendering schlägt nur dann noch fehl (`postext-pdf: failed to load font(s): …`), wenn der Provider keinen einzigen Schnitt einer Familie in einer Standardstärke liefern kann, weder aufrecht noch kursiv.

### Font-Provider im Browser (Fontsource + WOFF2)

Die Sandbox liefert `createPdfFontProvider()` (`packages/postext-sandbox/src/viewport/pdf/pdfFontProvider.ts`), das Sie in jede Browser-App übernehmen können. Das Wesentliche:

```ts
import type { PdfFontProvider } from 'postext-pdf';
import { decompressWoff2 } from 'postext-pdf';

const bytesCache = new Map<string, Promise<Uint8Array>>();

function fontsourceId(family: string): string {
  return family.toLowerCase().replace(/\s+/g, '-');
}

function fontsourceWoff2Url(
  family: string,
  weight: number,
  style: 'normal' | 'italic',
): string {
  const id = fontsourceId(family);
  return `https://cdn.jsdelivr.net/npm/@fontsource/${id}@5/files/${id}-latin-${weight}-${style}.woff2`;
}

export function createPdfFontProvider(): PdfFontProvider {
  return async (family, weight, style) => {
    const key = `${family}|${weight}|${style}`;
    const cached = bytesCache.get(key);
    if (cached) return cached;

    const promise = (async (): Promise<Uint8Array> => {
      const url = fontsourceWoff2Url(family, weight, style);
      const res = await fetch(url, { mode: 'cors' });
      if (!res.ok) throw new Error(`font fetch failed: ${res.status} ${url}`);
      // pdf-lib needs TTF bytes, so decompress the WOFF2 wrapper client-side.
      return decompressWoff2(new Uint8Array(await res.arrayBuffer()));
    })();

    bytesCache.set(key, promise);
    return promise;
  };
}
```

Eine produktive Version sollte außerdem:

- **die verfügbaren Stärken abfragen** (über `https://api.fontsource.org/v1/fonts/{id}`) und die angefragte Stärke auf die nächstgelegene runden, die die Familie tatsächlich mitbringt, sodass eine Anfrage nach `weight: 600` bei einer Familie, die nur `{400, 700}` hat, trotzdem gelingt.
- **von kursiv auf normal zurückfallen**, wenn eine Familie für die angefragte Stärke keinen kursiven Schnitt hat, statt das ganze Rendering scheitern zu lassen.
- **den Cache über Renderings hinweg wiederverwenden** (den `bytesCache` auf Modulebene halten, nicht pro Aufruf), sodass das erneute Erzeugen des PDFs nach einer Konfigurationsänderung praktisch nichts kostet.

### Chinesische, japanische und koreanische Schriften

Ein CJK-Schnitt kommt nicht als eine kleine Datei. Fontsource liefert Noto Serif SC als etwa hundert Dateien pro Stärke aus, von denen jede einen Teil der Zeichen enthält und im Stylesheet der Familie mit ihrer `unicode-range` deklariert ist (`@fontsource/noto-serif-sc/400.css`); der Browser lädt die Dateien herunter, die der Text einer Seite berührt. Die Datei `latin`, die der Provider oben abruft, enthält überhaupt keine Han-Zeichen, und die benannten Teilmengen sind unvollständig: `chinese-simplified` von Noto Serif SC fehlt 釵, und `chinese-traditional` von Noto Serif TC hat keines der Satzzeichen voller Breite （），！？：；.

Ein Provider darf einen Schnitt daher mit mehreren Dateien beantworten. `renderToPdf` übergibt ihm die Zeichen, die die Seiten in diesem Schnitt setzen (`request.codePoints`), gesammelt aus allen Kapiteln, bevor irgendetwas gezeichnet wird, und der Provider gibt die Dateien zurück, die sie enthalten, in der Reihenfolge, in der der Browser sie nachschlägt. Jede Datei wird als eigene Teilmenge eingebettet, und jedes Zeichen wird aus der ersten Datei gezeichnet, die eine Glyphe dafür hat: Ein Kapitel, das 60 Teile berührt, bettet 60 kleine Teilmengen ein. Wird ein Schnitt erneut angefragt, etwa für den Text einer SVG-Abbildung, wird er nur nach den Zeichen gefragt, die seinen Dateien fehlen. Ein Provider, der ein einzelnes `Uint8Array` zurückgibt, funktioniert wie bisher. Der Provider der Sandbox liest das Fontsource-Stylesheet der Stärke und des Stils und ruft die Dateien ab, deren Bereiche den Text enthalten; sein Kern:

```ts
import type { PdfFontProvider } from 'postext-pdf';
import { decompressWoff2 } from 'postext-pdf';

type Slice = { url: string; ranges: Array<[number, number]> };

async function fontsourceSlices(family: string, weight: number, style: 'normal' | 'italic'): Promise<Slice[]> {
  const id = family.toLowerCase().replace(/\s+/g, '-');
  const cssUrl = `https://cdn.jsdelivr.net/npm/@fontsource/${id}@5/${weight}${style === 'italic' ? '-italic' : ''}.css`;
  const css = await (await fetch(cssUrl)).text();
  return [...css.matchAll(/@font-face\s*{([^}]*)}/g)].map(([, rule]) => ({
    url: new URL(/url\(\.?\/?([^)]+\.woff2)\)/.exec(rule)![1], cssUrl).href,
    ranges: /unicode-range:\s*([^;]+);/.exec(rule)![1].split(',').map((part) => {
      const [lo, hi = lo] = part.trim().slice(2).split('-');
      return [parseInt(lo, 16), parseInt(hi, 16)] as [number, number];
    }),
  }));
}

export const sliceFontProvider: PdfFontProvider = async (family, weight, style, request) => {
  // Where ranges overlap, the browser tries the last rule first.
  const slices = (await fontsourceSlices(family, weight, style)).reverse();
  const picked = new Set<Slice>();
  for (const cp of request?.codePoints ?? []) {
    const slice = slices.find((s) => s.ranges.some(([lo, hi]) => cp >= lo && cp <= hi));
    if (slice) picked.add(slice);
  }
  if (picked.size === 0) picked.add(slices[0]!);
  return Promise.all(slices.filter((s) => picked.has(s)).map(async (s) =>
    decompressWoff2(new Uint8Array(await (await fetch(s.url)).arrayBuffer()))));
};
```

Eine lateinische Familie durchläuft denselben Code: Englischer Text erhält nur seine Datei `latin`, Tschechisch erhält `latin` und `latin-ext`.

Ein Browser hört nicht bei der ersten Datei mit einer Glyphe auf. Er setzt ein Zeichen in der zuletzt deklarierten Datei unter denen, deren `unicode-range` es enthält, und die Dateien einer Familie überschneiden sich: Fontsource wiederholt die ASCII-Buchstaben von Noto Serif JP in seiner Datei `latin` und in seinen nummerierten Teilen. Zwei Zeichen, die in zwei Dateien gesetzt sind, werden nicht unterschnitten, also entscheidet die Datei über die Breite: Chrome 154 setzt `Shift_JIS` mit den nach `latin` deklarierten Teilen 4,25 em breit, und die Datei `latin` allein, die `t_` und `_J` unterschneidet, setzt es 4,32 em breit. Seit postext-pdf 1.30 kann ein Provider angeben, wie die Seite jede Datei deklariert hat: `declaredFontFile(bytes, { unicodeRange, order })` gibt dieselben Bytes zurück, versehen mit der `unicode-range` der Regel der Datei, wie CSS sie schreibt, und der Stelle dieser Regel unter den Regeln des Schnitts, eine beliebige Zahl, die mit der Deklarationsreihenfolge wächst (die größte ist zuletzt deklariert).

```ts
import { declaredFontFile } from 'postext-pdf';

declaredFontFile(bytes, { unicodeRange: 'U+0000-00FF,U+0131,U+0152-0153', order: 0 });
```

Sind die Dateien eines Schnitts mit ihren Bereichen versehen, wird in einem Dokument, das in seiner eigenen Sprache geformt wird ([`bodyText.shapingLanguage: 'document'`](/de/docs/configuration-text#fließtext), der Standard), ein Zeichen aus der zuletzt deklarierten Datei gezeichnet, deren Bereich es enthält und die eine Glyphe dafür hat, so wie ein Browser zwischen Regeln `@font-face` wählt, und ein Buchstabe bleibt mit seinen kombinierenden Zeichen in einer Datei. Ein Zeichen, das kein Bereich enthält, wird aus der ersten Datei mit einer Glyphe gezeichnet. Einfache Dateien und jede Datei in einem Dokument mit `'host'` werden wie bisher in der angegebenen Reihenfolge gelesen, sodass ein Provider, der seine Dateien beschreibt, die zuletzt deklarierte weiterhin zuerst aufführt. Ein so beschriebener Schnitt wird erneut nach jedem Zeichen gefragt, nach dem er vorher nicht gefragt wurde, da eine später deklarierte Datei es enthalten kann. Der Provider der Sandbox beschreibt seine Dateien.

Zeichen, für die keine Datei des Schnitts eine Glyphe hat, werden als Glyphe `.notdef` der Schrift gezeichnet (in den meisten Schriften ein leerer Kasten), und `renderToPdf` meldet sie einmal pro Schnitt, nachdem die Seiten gezeichnet sind:

```ts
// { kind: 'missingGlyph', family: 'Noto Serif TC', weight: 400, style: 'normal',
//   characters: ['，', '！', '？'], message: '…' }
```

Die Sandbox listet diese und die beiden folgenden Warnungen nach jedem erzeugten PDF in ihrem Bedienfeld Prüfungen auf. Ändern sich das Buch, seine Einstellungen oder seine Ressourcen, werden sie als aus einem früheren PDF stammend markiert, bis das nächste sie ersetzt; das Öffnen eines anderen Buches löscht sie.

- **Fett braucht eine statische Datei pro Stärke.** Fontsource liefert jede Stärke von Noto Serif SC und TC als eigene statische Dateien aus, sodass Fett in der Sandbox funktioniert. Die Dateien von Google Fonts (`NotoSerifSC[wght].ttf`, 25 MB) sind variable Schriften: pdf-lib bettet ihre Standardinstanz ein, sodass ein Schnitt 700 in 400 ausgegeben wird, und `renderToPdf` meldet das als `variableFontDefaultInstance`. Schneiden Sie für ein Paket mit fontTools eine statische Instanz pro Stärke (`fonttools varLib.instancer NotoSerifSC[wght].ttf wght=700`) und reduzieren Sie sie mit `pyftsubset` auf die Zeichen des Buches.
- **Verwenden Sie TrueType-Fassungen.** Source Han Serif und die Dateien `.otf` von Noto Serif CJK haben CFF-Konturen, die postext-pdf ganz einbettet, 8 bis 25 MB pro Stärke; ein CFF-Schnitt über 2 MB wird als `cffEmbeddedWhole` gemeldet. Die TrueType-Fassungen (Google Fonts, Fontsource) werden auf die verwendeten Glyphen reduziert. Für Japanisch liegen Noto Serif JP und Noto Sans JP (Google Fonts oder die nummerierten Teile von Fontsource), Shippori Mincho, Zen Old Mincho und BIZ UDMincho als TrueType vor; Source Han Serif JP und die Dateien `.otf` mit `JP` von Noto Serif CJK sind CFF.
- **Japanische Formen eines pan-CJK-Schnitts.** Ein Codepunkt der Han-Zeichen, der Interpunktion oder der Anführungszeichen kann in Japan anders gezeichnet werden als in China, und ein pan-CJK-Schnitt (Source Han, Noto CJK) enthält beide Formen. Das PDF formt ein japanisches Dokument (`locale: 'ja'`) und einen japanischen Einschub (`:ltr[…]{lang=ja}`) in jedem Dokument mit dem OpenType-Sprachsystem `JAN `, sodass das Feature `locl` des Schnitts die japanischen Formen ausgibt, die Canvas und HTML über `lang` ausgeben. Ein Einschub in einer anderen Sprache innerhalb eines japanischen Buches wird mit den Formen dieser Sprache geformt (für Chinesisch mit `'host'` mit den Standardformen der Schrift) und als `Span` mit ihrem `/Lang` getaggt. Mit [`bodyText.shapingLanguage: 'document'`](/de/docs/configuration-text#fließtext), dem Standard seit postext 1.30, wird jedes Dokument und jeder Einschub in seiner eigenen Sprache geformt (`ZHS` für vereinfachtes Chinesisch), so wie das Layout es gemessen hat; mit `'host'` werden chinesische und andere Dokumente wie bisher mit den Standardformen der Schrift geformt. Ein für Japanisch gemachter Schnitt wie Noto Serif JP hat japanische Standardformen; er setzt die “ ” japanischen Textes dennoch in ihren Formen für `JAN `.

Ein Zeichen, das einer Familie fehlt, wird nicht aus einer anderen genommen: Noto Serif TC borgt nicht bei Noto Serif SC. Klären Sie die Abdeckung, wenn Sie die Schriftdateien erstellen; das Beispielbuch 红楼梦 kopiert die Glyphen, die seinen TC-Teilmengen fehlen, aus dem SC-Schnitt.

### Serverseitiger Font-Provider (Node, lokale Dateien)

In Node können Sie den WOFF2-Schritt ganz überspringen und TTF/OTF-Dateien von der Festplatte lesen:

```ts
import { readFile } from 'node:fs/promises';
import { join } from 'node:path';
import type { PdfFontProvider } from 'postext-pdf';

const FONT_DIR = '/path/to/fonts';

function filename(family: string, weight: number, style: 'normal' | 'italic'): string {
  const slug = family.replace(/\s+/g, '');
  const styleSuffix = style === 'italic' ? 'Italic' : '';
  const weightName =
    weight >= 700 ? 'Bold'
    : weight >= 600 ? 'SemiBold'
    : weight >= 500 ? 'Medium'
    : weight >= 300 ? 'Light'
    : 'Regular';
  return `${slug}-${weightName}${styleSuffix}.ttf`;
}

export const localFontProvider: PdfFontProvider = async (family, weight, style) => {
  const buf = await readFile(join(FONT_DIR, filename(family, weight, style)));
  return new Uint8Array(buf);
};
```

### Ressourcenbytes und Druckoriginale

`resourceBytes(fileId)` gibt die rohen Bytes eines Bildes zurück, und das Backend erkennt ihr Format:

- PNG, JPEG, GIF und WebP werden als Bilder eingebettet;
- SVG-Markup wird als Vektorpfade gezeichnet, sein `text` als echter Text in den eingebetteten Schriften des Dokuments gesetzt, oder im Browser mit 600 dpi gerastert, wenn es Funktionen außerhalb der Vektorteilmenge verwendet. Ein `<style>`, das nur Regeln `@font-face` enthält (von einer Autorin oder einem Autor eingebettete Schnitte), wird übersprungen und lässt die Abbildung vektoriell (seit postext-pdf 1.25); jedes andere Stylesheet macht sie zu einem Rasterbild, das mit den Schnitten erzeugt wird, die ihr Text nennt, eingebettet aus `fontProvider` (sofern nicht `diagramStyle.inlineFonts` oder das `svg.inlineFonts` der Ressource `false` ist);
- TIFF- und Photoshop-Dokumente (PSD, PSB) werden aus ihren eigenen Pixeln gedruckt: Graustufen, RGB oder CMYK, 8 oder 16 Bit, mit dem ICC-Profil und der Auflösung, die sie mitbringen. Ein CMYK-Dokument behält seine Druckfarben unverändert; Graustufen und RGB folgen `print.imageColor`. Ein Photoshop-Dokument wird aus dem zusammengesetzten Bild gelesen, das es mit „Kompatibilität maximieren“ speichert; JPEG-komprimiertes TIFF wird nicht gelesen;
- bei einem PDF wird die erste Seite unverändert als Form-XObject eingebettet.

Jedes Bild wird einmal in der Datei gespeichert, wie oft es auch gezeichnet wird. Ein als Vektorpfade gezeichnetes SVG wird zu einem Form-XObject, das jede Seite zeichnet, sodass ein Rahmen oder ein Logo in der Seitengestaltung eines dreißigseitigen Dokuments einmal geschrieben wird, nicht dreißigmal; jede weitere Seite fügt einige hundert Bytes hinzu. Bis postext-pdf 1.4 trug jede Seite ihre eigene Kopie der Pfade.

Eine SVG-Abbildung kann in `svg.pdfFileId` ein **Druckoriginal** angeben: ein einseitiges PDF derselben Abbildung, typischerweise das Original, aus dem das SVG exportiert wurde. `renderToPdf` fragt `resourceBytes` zuerst nach der ID des Originals. Es bettet diese Seite anstelle des SVG ein, mit ihren Schriften, Verläufen und Farbräumen unversehrt, überall dort, wo das SVG gezeichnet wird: als Abbildung, als Bild einer Tabellenzelle (`TableCell.image`), als Gestaltungsbild oder als Kastensymbol (auch sein `marker`). Der VDT enthält die ID des Originals bei jeder dieser Verwendungen (`svg.pdfFileId` an der Ressource der Abbildung, `pdfFileId` an einem Zellbild und an einem Block für ein Gestaltungsbild), sodass in einem Buch jedes Kapitel das Original erhält. Die Backends für Canvas und HTML zeichnen weiterhin das SVG. Stattdessen werden in drei Fällen die eigenen Bytes des SVG verwendet: Das Original fehlt, es ist kein PDF, oder die Einfarbigkeit ist eingeschaltet (`diagramStyle.singleInk` färbt nur SVG-Markup um).

```ts
const resources: Resource[] = [{
  id: 'map', typeId: 'figure', kind: 'svg', createdAt: 0, updatedAt: 0,
  svg: { fileId: 'map.svg', width: 800, height: 600, pdfFileId: 'map.pdf' },
}];
const files = new Map([['map.svg', svgBytes], ['map.pdf', masterPdfBytes]]);
const pdf = await renderToPdf(buildDocument({ markdown, resources }, config), {
  fontProvider,
  resourceBytes: (fileId) => files.get(fileId),
});
```

Ein Host kann die Bytes des Originals auch für die eigene ID des SVG zurückgeben, wie es `bundleResourceBytes` tut; beide Wege funktionieren.

Ein Browser kann weder ein TIFF noch ein Photoshop-Dokument anzeigen, deshalb behält eine daraus erzeugte Bitmap-Ressource zwei Dateien: `bitmap.fileId` ist eine PNG-Vorschau, die Canvas, HTML und EPUB zeigen, und `bitmap.printFileId` (mit `printFormat: 'tiff' | 'psd'`) ist das Original. Ein Host gibt für `bitmap.fileId` die Bytes des Originals zurück, wie es `bundleResourceBytes` und die Sandbox tun, und das PDF wird daraus gedruckt. Er gibt auch die Vorschau mit, als `previewBytes` (`bundlePreviewBytes` für ein Paket): Ein Original, das sich nicht dekodieren lässt, wird aus seiner Vorschau gedruckt, mit einer Warnung `pictureOriginalUnreadable`; ohne Vorschau bleibt ein Platzhalter. `decodePrintRaster(bytes)` und `rasterToRgba(raster)` in `postext` lesen das Original und erzeugen die Vorschau; die Sandbox erzeugt sie beim Import der Datei, und ein Paket speichert das Original als `resources/<name>.tif` oder `.psd` neben der Vorschau.

Eine Adobe-Illustrator-Datei, die mit „PDF-kompatible Datei erstellen“ gespeichert wurde, ist ein PDF und kann wie jedes andere ein Druckoriginal sein (`.ai`). Ihre Farbfelder sind ihre eigenen Platten: Der Preflight listet die auf, die die Druckfarbentabelle umbenennt, die, die keine Farbe des Buchs definiert, und, in einem Auftrag auf eigenen Platten (`print.plates`), die, die der Auftrag nicht druckt, denn eine platzierte Datei wird so gedruckt, wie sie ist.

### Vertikaler Text im PDF

Eine vertikale Seite (`layout.writingMode: 'vertical-rl'`) wird über einen um eine Vierteldrehung gedrehten Rahmen gezeichnet, so wie das Canvas sie zeichnet, und ihr Text wird die Spalte hinab gesetzt:

- **Aufrechte Zeichen** werden über eine zweite Type0-Schrift derselben eingebetteten Datei dargestellt: dieselbe CIDFont, dieselben Breiten und dieselbe ToUnicode-Tabelle, mit `Encoding /Identity-V` (vertikaler Modus). Eine Folge von Zeichen ist ein Textobjekt, dessen Glyphen von selbst je ein Geviert die Spalte hinab vorrücken (`DW2 [880 −1000]`), sodass Leseprogramme eine Spalte als eine Zeile auswählen und extrahieren. Die Glyphen werden mit den OpenType-Features `vert` und `fwid` geformt, die Klammern, Anführungszeichen, den Pausenzeichen des Festlands, Auslassungspunkten und Strichen ihre vertikalen Formen geben; ein Zeichen, das so, wie es ist, aufrecht steht, behält seine horizontale Glyphe. Nichts von der Schrift wird doppelt eingebettet.
- **Lateinische Wörter und lange Zahlen** laufen mit der horizontalen Schrift seitwärts; **eine Zahl in einer Zelle** steht aufrecht und wird, wenn sie breiter ist, quer auf das Geviert gestaucht; ein Zeichen, für das die Schrift keine vertikale Form hat, wird gedreht oder verschoben, wie im Canvas.
- **Die Laufweite** zwischen Zeichen wird als Zahlen in `TJ` geschrieben, die im vertikalen Modus den Stift die Spalte hinab bewegen.
- **Jede vertikale Zeile** ist mit einem `/ActualText` ihres Textes markiert, sodass Kopieren und Textextraktion sie wie geschrieben lesen. `pdftotext` und pdf.js lesen die Spalten von oben nach unten und von rechts nach links; pdf.js beginnt bei einer in einer Zelle gesetzten Zahl eine neue Zeile.
- **Links, Lesezeichen und Sprungziele** werden auf das Blatt abgebildet: Ein Link über einer vertikalen Zeile ist ein hohes, schmales Rechteck, und ein Lesezeichen öffnet die Seite oben an der Spalte seiner Überschrift.
- **Ein getaggtes PDF** deklariert die Schreibrichtung an seinem Element `Document` (das Layout-Attribut `WritingMode /TbRl`, das jedes Element erbt); die Validierung nach PDF/UA-1 (veraPDF) besteht ein vertikales Kapitel.
- **Betrachter:** Acrobat, Vorschau, Chrome (PDFium), pdf.js und Poppler rendern die vertikalen Schriften. Ein rechts gebundenes Buch (`page.binding`) bittet die Betrachter außerdem, seine Doppelseiten von rechts nach links anzuordnen (`/Direction /R2L`, `/PageLayout /TwoPageRight`); Acrobat und Foxit folgen dem, Chrome nicht.

Ein 43-seitiges Kapitel in Noto Serif TC (die Zeichen des Buches, TrueType) hat etwa 820 KB, wovon die beiden Schrift-Teilmengen den größten Teil ausmachen.

### Formularfelder

Ein Chip mit dem Attribut `field` ist ein ausfüllbares Formularfeld (AcroForm). Der Chip wird gesetzt und malt seinen Kasten wie jeder Chip: Sein Stil bestimmt das Aussehen und die Mindestbreite (`minWidth`), seine Wörter sind der Vorgabewert des Feldes. Das PDF legt ein interaktives Feld über den Kasten; ein zweimal verwendeter Name ergibt ein Feld mit zwei Widgets.

```md
Menge :chip[ ]{style="field" field="pos.a.qty" kind="number"}
Preis :chip[120]{style="field" field="pos.a.price" format="currency"}
Summe :chip[ ]{style="field" field="pos.a.total" format="currency" calc="product(pos.a.qty, pos.a.price)"}
Leistung :chip[ ]{style="box" field="pkg.a" kind="checkbox" on="1"}
Gesamtbetrag :chip[ ]{style="field" field="order.total" format="currency" calc="sum(pos.a.total, product(pkg.a, 161.75))"}
Größe :chip[M]{style="field" field="size" kind="choice" options="S|M|L"}
```

- `kind`: `text` (Standard), `number`, `checkbox`, `choice` (mit `options`, getrennt durch `|`). Ein Chip mit `format` oder `calc` und ohne `kind` ist ein Zahlenfeld.
- `on` (ein Kontrollkästchen): der Name des Ein-Zustands des Kästchens, also der Wert, den seine Skripte lesen, wenn es angekreuzt ist. Mit `on="1"` zählt ein angekreuztes Kästchen in einer Berechnung als 1, sodass `product(pkg.a, 161.75)` einen Festpreis addiert, sobald das Kästchen angekreuzt ist. Standard ist `Yes`, das eine Berechnung als 0 zählt.
- `format`: `currency`, `decimal` (zwei Nachkommastellen), `integer`. Geschrieben als `AFNumber_Format` und `AFNumber_Keystroke` von Acrobat, mit den Trennzeichen der Dokumentsprache (`1.234,56` im Deutschen), sofern `RenderToPdfOptions.forms.separatorStyle` nichts anderes festlegt; die Währung ist `forms.currency` (Standard `€`) und steht vor der Zahl, außer `forms.currencyBefore` ist `false`. Ein Vorgabewert wird formatiert gezeichnet.
- `calc`: `sum(…)`, `product(…)`, `min(…)`, `max(…)` oder `avg(…)`. Argumente sind andere Felder über ihren Namen, Zahlen (mit Punkt als Dezimalzeichen, `161.75`) und verschachtelte Berechnungen: `sum(pos.a.total, pos.b.total, product(pkg.a, 161.75))`. Eine Berechnung nur über Felder wird als `AFSimple_Calculate` geschrieben. Eine mit Zahlen oder verschachtelten Berechnungen wird zu einem eigenen kurzen Calculate-Skript, das jedes Feld auf dieselbe Weise liest (`AFMakeNumber` seines Werts; was keine Zahl ist, zählt 0) und das Ergebnis auf sechs Nachkommastellen rundet. Ein berechnetes Feld ist schreibgeschützt, und die Berechnungsreihenfolge berücksichtigt jedes Feld, das es liest, auch die in verschachtelten Berechnungen. Mit einer `formField`-Warnung gemeldet werden: eine Berechnung, die ein unbekanntes Feld liest (es zählt 0), ein Zyklus, ein Name, der für zwei Arten verwendet wird, und ein Kontrollkästchen in einer Berechnung, dessen `on`-Wert keine Zahl ist (es zählt immer 0).
- `readonly`, `required`, `multiline`, `tooltip` tun, was ihr Name sagt.

Ein Feld zeigt seinen Wert, und was jemand eintippt, im Schnitt seines Chips (`forms.font: 'chip'`, Standard) oder in einem Schnitt aus den Schriften des Dokuments, den `forms.font` nennt (`{ family, weight?, style? }`, beim `fontProvider` angefragt wie jeder andere). Dieser Schnitt wird **vollständig** eingebettet, nicht als Teilmenge, denn einer Teilmenge fehlen die Glyphen für später eingetippte Zeichen; er wird nur einmal eingebettet, gleich wie viele Felder ihn verwenden, in den Standardressourcen des Formulars (`/DR`) und im Standarderscheinungsbild jedes Feldes (`/DA`) genannt, und die Vorgabewerte werden mit ihm gezeichnet. Ein vollständiger Schnitt fügt dem PDF seine ganze Datei hinzu (ein lateinischer Textschnitt hat typischerweise 50–300 KB, ein CJK-Schnitt mehrere MB), zusätzlich zur Teilmenge, die der Seitentext verwendet. Der Provider darf TrueType, OpenType oder WOFF2 liefern (WOFF2 wird vor dem Einbetten entpackt). Die Felder fallen mit einer `formField`-Warnung auf Helvetica zurück, wenn sich der Schnitt nicht vollständig einbetten lässt: Seine Lizenz verbietet das Einbetten (`fsType` in OS/2 eingeschränkt oder nur Bitmap), der Provider liefert ihn in mehreren Dateien (ein aufgeteilter Schnitt), oder sein Format ist WOFF oder eine Collection. `forms.font: 'helvetica'` verwendet Helvetica, ohne etwas einzubetten. Manche Viewer (etwa Vorschau unter macOS) zeichnen den Text während der Eingabe in einer eigenen Schrift; der Wert bleibt derselbe.

Acrobat, Foxit, pdf.js (Firefox) und die meisten Viewer führen diese Skripte aus. Ein Druckstandard (PDF/X) erlaubt keine interaktiven Felder: Dort werden die Werte als Text gemalt, der Wert eines Zahlenfelds so, wie das Formular ihn zeigt (formatiert, innerhalb des `paddingX` des Stils ans Ende des Kastens gesetzt, in der Farbe des Chips).

Das Canvas malt ein Zahlenfeld genauso, sodass die Vorschau dem PDF entspricht: Übergeben Sie `renderPageToCanvas` (oder `renderPage`, `renderToCanvas`) dieselbe Option `forms` wie `renderToPdf`; in beiden Fällen richten sich die Trennzeichen standardmäßig nach dem `locale` des Dokuments (sonst nach seiner Silbentrennungssprache). Eine einzige Regel schreibt die Zahlen überall, und postext exportiert sie für andere Ausgabeformate: `formNumberStyle(forms, lang)` löst die Optionen auf, `formatFieldNumber(value, format, style)` formatiert einen Wert (undefined für Text, der keine Zahl ist), und `numberFieldText(field, words, style)` liefert, was ein gemaltes Zahlenfeld zeigt. Die Display-Liste trägt das Feld am Textlauf des Chips (`inline.field`, mit `sizePx` und `padPx` aus dem Layout).

Ein Buch kann diese Optionen in seiner Konfiguration halten: `pdfGeneration.forms` nimmt dieselben Felder (`currency`, `currencyBefore`, `separatorStyle`, `font`). `renderToPdf` und das Canvas nehmen jedes zuerst aus ihrer eigenen Option `forms`, dann aus `pdfGeneration.forms` des ersten Dokuments, dann aus den Standardwerten. Am Satz ändert das nichts, nur daran, wie die Felder geschrieben und gemalt werden. In der Sandbox ist es die Gruppe **Formularfelder** des Bereichs PDF.

```ts
pdfGeneration: {
  forms: { currency: 'USD', currencyBefore: true, separatorStyle: 0, font: { family: 'Lora', weight: 400 } },
}
```

**Über esm.sh im Browser** importieren Sie `https://esm.sh/postext-pdf?bundle`. Der Standard-Build von pdf-lib auf esm.sh legt die Annotationsklassen in ein eigenes Modul, und pdf-lib weist dann das Widget jedes Felds zurück: Das PDF behält die Kästchen, verliert aber Formate, Berechnungen und Merkmale, mit einer `formField`-Warnung je Feld. `?bundle` baut pdf-lib als ein Modul und lässt `postext` draußen, geteilt mit der Seite. Ein Bundler (Vite, webpack, Next.js) und Node sind nicht betroffen.

Der IDML-Export schreibt dieselben Felder als InDesign-Formularfelder (siehe [Programmatische Nutzung › InDesign-Pakete](/de/docs/configuration-programmatic-usage#indesign-pakete-postext-idml)).

### Links im PDF

Die Wörter eines Markdown-Links (siehe [Dokumentformat › Links](/de/docs/document-format-inline#links)) werden zu URI-Link-Annotationen, eine pro Folge verlinkter Wörter in einer Zeile. Jede deckt den Zeilenkasten ab und hat keinen Rahmen. In einem barrierefreien Rendering ist jede Folge ein Element `Link`, dessen `/Contents` sein Text ist. Verlinkt werden nur absolute Ziele mit `http:`, `https:`, `mailto:`, `tel:` und `ftp:`, weil eine relative URL innerhalb eines PDFs keine Basis hat. Zeichen außerhalb des druckbaren ASCII werden prozentkodiert. Verweise mit `:ref` und Zeilen des Inhaltsverzeichnisses behalten ihre Links innerhalb des Dokuments.

### Vollständiges Browser-Beispiel: setzen, rendern, herunterladen

Alles zusammengesetzt – den VDT setzen, als PDF rendern und im Browser einen Download auslösen:

```tsx
import { buildDocument, createMeasurementCache } from 'postext';
import { renderToPdf } from 'postext-pdf';
import { createPdfFontProvider } from './pdfFontProvider';

const fontProvider = createPdfFontProvider();

export async function downloadPdf(markdown: string, config: PostextConfig) {
  const cache = createMeasurementCache();
  const vdt = buildDocument({ markdown }, config, cache);

  const bytes = await renderToPdf(vdt, { fontProvider });

  const blob = new Blob([bytes.slice().buffer], { type: 'application/pdf' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'document.pdf';
  document.body.appendChild(a);
  a.click();
  a.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
}
```

**Wichtig:** Rufen Sie `ensureConfigFontsLoaded(config)` (oder etwas Gleichwertiges) *vor* `buildDocument` auf, wenn Ihre Konfiguration Webschriften verwendet. Das Layout wird mit den Schriftmetriken gemessen, die der Browser gerade für diese Familie hat – ist die echte Schrift noch nicht eingetroffen, wird der VDT mit einer Ersatzschrift gemessen, und das PDF stimmt nicht mit der Ausgabe von Canvas oder HTML überein. Die Sandbox tut das vor jedem Rendering ausdrücklich (siehe `packages/postext-sandbox/src/viewport/pdf/PdfViewport.tsx`).

### Das PDF in einem Worker rendern

`postext-pdf/worker` verlagert `renderToPdf` aus dem Haupt-Thread. Der Worker schreibt den Text, die Vektorabbildungen, den Strukturbaum und die Datei selbst. Zwei Aufgaben brauchen die Seite, deshalb bittet der Worker den Haupt-Thread darum: das Abrufen von Schriften und das Rastern eines SVG über ein `<img>`. Bei einem Buch von Hunderten Seiten dauert das Rendern Sekunden, die sonst die Seite einfrieren würden; bei wenigen Seiten ist der direkte Aufruf von `renderToPdf` einfacher.

```ts
import { createPdfWorker } from 'postext-pdf/worker';

const pdfWorker = createPdfWorker();
const bytes = await pdfWorker.render(docs, {
  fontProvider,                                     // runs on this thread
  resourceBytes: new Map([['map.svg', svgBytes]]),  // a Map; its buffers move to the worker
  onProgress: ({ phase, pages, totalPages }) => showProgress(phase, pages, totalPages),
  onWarning: (w) => console.info(w.message),
});
pdfWorker.dispose();
```

- `render(docs, options)` nimmt ein Dokument oder das Array der Kapiteldokumente eines Buches. Es nimmt die Optionen von `renderToPdf`, mit zwei Unterschieden. `resourceBytes` (und `previewBytes`) ist eine `Map<string, Uint8Array>`, deren Puffer übertragen werden; übergeben Sie also Kopien von Bytes, die Sie behalten. `rasterizeSvg` läuft, wenn angegeben, im Haupt-Thread; standardmäßig erledigen das eigene `Image` und das Canvas der Seite diese Aufgabe.
- Ein Handle rendert jeweils ein Dokument. `dispose()` beendet den Worker und weist jedes noch ausstehende Rendering mit einem `AbortError` (`DOMException`) zurück; behandeln Sie ihn als Abbruch. Liefert Ihr Provider nach `dispose()` noch eine Schrift oder ein Bild, wird die Antwort verworfen.
- `inspect(bytes)` liest ein fertiges PDF im Worker zurück (`inspectPrintPdf`) und liefert seinen Bericht, oder `undefined`, wenn sich die Bytes nicht als PDF lesen lassen. Die Bytes werden kopiert, Ihre bleiben also nutzbar. Ohne Aufruf wird nichts gelesen.
- `createPdfWorker({ worker })` nimmt einen `Worker`, den Sie selbst erzeugen, für Build-Werkzeuge, die die URLs von Workern kontrollieren. Dieser Worker muss `postext-pdf/worker/entry` ausführen.

**Von einem CDN.** Standardmäßig wird das Worker-Skript von der eigenen URL des Pakets geladen (`new URL('./pdf.worker.js', import.meta.url)`). Eine Seite eines anderen Ursprungs darf es unter Umständen nicht starten: Aus `esm.sh` importiert, wirft `createPdfWorker()` den Fehler `Failed to construct 'Worker': Script at 'https://esm.sh/postext-pdf@…/pdf.worker.js' cannot be accessed from origin …`. Starten Sie stattdessen einen Modul-Worker desselben Ursprungs, der den Einstieg importiert (wenn Sie eine Version festlegen, legen Sie in beiden URLs dieselbe fest):

```js
import { createPdfWorker } from 'https://esm.sh/postext-pdf/worker';

const entry = URL.createObjectURL(new Blob(
  ["import 'https://esm.sh/postext-pdf/worker/entry';"],
  { type: 'text/javascript' },
));
const pdfWorker = createPdfWorker({ worker: new Worker(entry, { type: 'module' }) });
```

Der Layout-Worker aus `postext/worker` braucht diese Hülle nicht: `createLayoutWorker()` startet ohne Optionen seinen eigenen Einstieg von esm.sh und von jedem anderen Server über seine Option `url` (siehe [Den Worker von einem CDN laden](/de/docs/configuration-programmatic-usage#den-worker-von-einem-cdn-laden)).

### Druckfertige PDFs

Für produktive Druckabläufe stimmen Sie vor dem Rendern diese Konfigurationsoptionen ab:

- **`page.cutLines.enabled: true`** – fügt um das Endformat einen Anschnittbereich und Schnittmarken hinzu und gibt jeder Seite eine TrimBox und eine BleedBox. Siehe [Schnittmarken](/de/docs/configuration-page-layout#schnittmarken).
- **`print: { standard: 'pdfx4', outputProfile: 'fogra51' }`** (oder `'pdfx1a'`) – eine PDF/X-Datei mit dem Output Intent, der Kennung und den Boxen, die eine Druckerei prüft; jede Farbe und jedes RGB-Bild über das ICC-Profil separiert, 100 % K überdruckend und große schwarze Flächen in Tiefschwarz. Siehe [Druckvorstufe (Konfiguration)](/de/docs/configuration-fonts-colors-viewers#druckvorstufe-konfiguration).
- **`colorSpace: 'cmyk'`** (oder `pdfGeneration: { forceColorSpace: true, colorSpace: 'cmyk' }`) – dieselbe Separation ohne die PDF/X-Kennung (Schnittmarken stehen immer in Passerfarbe). PDF-Druckoriginale werden so eingebettet, wie sie sind.
- **`page.dpi: 300`** – die px pro Zoll des Layouts: Eine Bitmap ohne eigene Auflösung wird in ihrer natürlichen Größe mit dieser Auflösung gedruckt. Der [Preflight](/de/docs/configuration-pdf-output#preflight) meldet Bilder unter 300 ppi in ihrer gedruckten Größe.
- **`ColorValue.cmyk`** – eine in CMYK angelegte Farbe wird mit ihren genauen Werten gedruckt.
- **`{ pageNegative: true }`** in `RenderToPdfOptions` – kehrt den Bereich des Endformats mit dem Mischmodus Differenz um (Schnittmarken bleiben unverändert). Nützlich für Preflight-Prüfungen bei dunkler Typografie auf hellem Grund.
- **`print.dieLine`** – die Stanzlinie eines Buchs mit Stanzungen, auf einer eigenen Platte gezeichnet, die die Druckmaschine nie einfärbt (standardmäßig `Die`, außer bei PDF/X-1a in einer optionalen Inhaltsgruppe). Siehe [Die Stanzlinie im PDF](/de/docs/special-inks-die-cuts#die-stanzlinie-im-pdf).

### Sonderfarben

Eine Sonderfarbe (ein Pantone-Ton, eine Hausfarbe, ein Lack) druckt auf einer eigenen Platte. Eine Farbe mit `model: 'spot'` trägt ihre Druckfarbe in `ColorValue.spot`: `name` ist der Name der Platte, wie die Druckerei ihn kennt, `cmyk` das Aussehen der Druckfarbe bei 100 % (der Ersatzwert, den das PDF jedem gibt, der die Druckfarbe nicht hat), `tint` die Stärke in Prozent (Standard 100), `overprint` lässt die Druckfarbe das Darunterliegende überdrucken, statt es auszusparen, wie ein Lack, und `finish` sagt, was für eine Spezialfarbe sie ist: metallisch, Heißfolie, fluoreszierend, Deckweiß oder Lack. `hex` ist ihre Bildschirmdarstellung. [Spezialfarben und Stanzungen](/de/docs/special-inks-die-cuts#veredelungen) erklärt, wie jede Veredelung gedruckt und angezeigt wird.

Ein CMYK- oder PDF/X-PDF schreibt jede Druckfarbe als Farbraum `Separation` mit ihrem Namen und malt jede Farbe dieser Druckfarbe in ihrem Tonwert: Farben mit demselben `name` teilen sich eine Platte. Das deckt die üblichen Aufträge ab: zweifarbig (Schwarz und eine Sonderfarbe), Vierfarbdruck mit einigen Elementen in einer Sonderfarbe und ein Lack, der auf ausgewählte Flächen überdruckt wird. Verwendet `diagramStyle.singleInk` eine Sonderfarbe, drucken SVG-Diagramme in Tonwerten dieser Platte. Ein RGB-PDF und der Bildschirm malen den `hex`-Wert der Farbe.

**Sonderfarben in einem SVG.** Siehe [Wie der Einfarbmodus arbeitet](/de/docs/configuration-resources#wie-der-einfarbmodus-arbeitet).

```ts
colorPalette: [
  { id: 'brand', name: 'Brand', value: { hex: '#1f3f99', model: 'spot', spot: { name: 'PANTONE 286 C', cmyk: { c: 100, m: 66, y: 0, k: 2 } } } },
  { id: 'brand-40', name: 'Brand 40 %', value: { hex: '#a5b6dd', model: 'spot', spot: { name: 'PANTONE 286 C', cmyk: { c: 100, m: 66, y: 0, k: 2 }, tint: 40 } } },
  { id: 'varnish', name: 'Varnish', value: { hex: '#f4f4ee', model: 'spot', spot: { name: 'Varnish', cmyk: { c: 0, m: 0, y: 10, k: 0 }, finish: { kind: 'varnish', sheen: 'gloss' } } } },
],
diagramStyle: { singleInk: true, inkColor: { hex: '#1f3f99', model: 'spot', paletteId: 'brand' } },
```

Der Preflight zählt eine Sonderfarbe als eine Druckfarbe, nimmt sie von der Flächendeckungsgrenze aus und listet die Sonderfarben des Auftrags auf (`spotInks`), auch die Druckfarben, die SVG-Bilder nennen. Er warnt, wenn eine Druckfarbe zweimal mit verschiedenen Werten definiert ist (`spotInkConflict`; das PDF verwendet die erste), wenn ein SVG eine Druckfarbe nennt, die weder eine Palettenfarbe noch ein Eintrag der Druckfarbentabelle mit `cmyk` definiert (`spotInkUndefined`; sie druckt auf einer eigenen Platte, mit dem CMYK der SVG-Farbe als Ersatzwert, eine Platte pro Name), wenn das PDF einen Plattennamen anders schreiben muss (`spotInkName`, siehe unten), und wenn sich zwei Plattennamen nur in Groß- und Kleinschreibung oder Leerzeichen unterscheiden (`spotInkSimilar`: `PANTONE 185 C` und `Pantone  185 C` wären zwei Platten). Welche Druckfarben ein SVG nennt, erfährt `preflightDocument` über `svgInks(fileId)`, eine Funktion, die die Namen zurückgibt, die `svgSpotInks(markup)` in der Datei findet; das Bedienfeld **Prüfungen** der Sandbox und `postext check` übergeben sie.

**Plattennamen.** Der Name wird so geschrieben, wie er eingegeben wird: Akzente, Symbole und `#` gelangen in UTF-8 ins PDF (`Rojo Médica` wird zu `/Rojo#20M#C3#A9dica`), und so lesen ihn Acrobat, ein RIP und der Preflight der Druckerei. Einen Namen, den eine Platte nicht tragen kann, schreibt das PDF unter einem anderen: `All`, `None`, `Cyan`, `Magenta`, `Yellow` und `Black` bekommen in jeder Schreibweise das Wort ink angehängt (`All ink`); Steuerzeichen werden entfernt, und ein Name über 127 Byte in UTF-8 wird an einer Zeichengrenze gekürzt und endet mit einem kurzen Hash, sodass zwei lange Namen mit gleichem Anfang zwei Platten bleiben. `spotInkName` im Preflight nennt den Grund (`problem`: `reserved`, `process`, `control` oder `tooLong`) und den Namen, den das PDF schreibt (`written`), und das Rendering meldet jede Umbenennung über `onWarning` (`spotInkRenamed`). Um den Namen selbst zu wählen, geben Sie der Druckfarbe in der Druckfarbentabelle einen `pdfName`.

**Eine Druckfarbe pro Farbe.** Ein Druck-Rendering erkennt eine Farbe an ihrem Bildschirm-Hex-Wert; zwei Farben, die ihre Druckwerte festlegen – zwei Druckfarben oder eine Druckfarbe und eine in CMYK angelegte Farbe –, dürfen sich daher keinen teilen. Tun sie es doch, rückt die spätere auf den nächsten freien Hex-Wert, einen Schritt entfernt und auf dem Bildschirm unsichtbar, und jede druckt auf ihrer eigenen Platte. Eine reine Bildschirmfarbe (`model: 'hex'`) mit dem Hex-Wert einer Sonderfarbe druckt als diese Sonderfarbe; verknüpfen Sie sie mit dem Paletteneintrag, um das ausdrücklich zu machen. Die verschobene Farbe ändert sich auch auf dem Bildschirm, um einen Schritt (1/255) in einem Kanal, zuerst im blauen, in jeder Ausgabe (Canvas, HTML, EPUB und RGB-PDF). Das liegt weit unter dem, was das Auge unterscheidet, und ist der Preis dafür, dass ein Druck-Rendering die Druckfarben aus dem gemalten Hex-Wert liest. Die gespeicherte Konfiguration ändert sich nicht.

#### Die Druckfarbentabelle

`print.inks` legt fest, wie die Druckfarben des Auftrags in die Druckerei gelangen, gleich wie die Farben, die SVGs und die importierten Dateien sie nennen. Eine Druckfarbe, die nicht in der Tabelle steht, druckt so, wie ihre Farben sie definieren.

```ts
interface PrintInk {
  name: string;                    // Die Druckfarbe, wie spot.name oder ein SVG sie nennt.
  aliases?: string[];              // Andere Namen derselben Druckfarbe: Sie drucken auf dieser Platte.
  pdfName?: string;                // Der Name der Platte im PDF. Standard: name.
  output?: 'spot' | 'process';     // 'process' druckt die Druckfarbe in CMYK, aus ihrem Ersatzwert.
  cmyk?: CmykPercent;              // Der Ersatzwert bei 100 %, vor dem der Farben.
  overprint?: boolean;             // Vor dem der Farben.
  finish?: InkFinish;              // Metallisch, Heißfolie, fluoreszierend, Weiß oder Lack, vor dem der Farben.
}
```

Namen und Aliasse werden ohne Rücksicht auf Groß- und Kleinschreibung und mehrfache Leerzeichen verglichen. Umbenennen ist eine Zeile, gleich wie viele Farben die Druckfarbe verwenden; ein Alias führt die Namen, die ein Farbfeld des Gestalters, ein SVG (`data-spot`, `icc-named-color`) oder eine ältere Palette derselben Druckfarbe gaben, auf einer Platte zusammen; `output: 'process'` druckt eine Druckfarbe in CMYK, wenn die Druckmaschine kein Druckwerk für sie hat, alle Tonwerte eingeschlossen; und `finish` macht eine Druckfarbe zur Spezialfarbe, woher ihr Name auch kommt, auch aus einem SVG oder einer importierten Datei, die `Gold` nennt. Die Reihenfolge der Einträge ist die Druckreihenfolge zweier Lacke, die aufeinandertreffen: Auf dem Bildschirm und in Folio liegt ein späterer Eintrag über einem früheren (siehe [Veredelungen](/de/docs/special-inks-die-cuts#veredelungen)).

In der Sandbox liegt die Tabelle unter **Gestaltung › Export › Druckvorbereitung › Farbtabelle**: eine Karte pro Druckfarbe mit **Name der Druckfarbe**, **Aliasnamen**, **Plattenname im PDF**, **Druckt als**, **Ersatz-CMYK**, **Überdrucken**, **Veredelung** und **Glanz**. **Druckfarben, die die Farben verwenden** listet die Druckfarben der Buchfarben auf, die in der Tabelle fehlen, jede mit einer Schaltfläche, die sie hinzufügt.

```ts
print: {
  standard: 'pdfx4',
  inks: [
    { name: 'Azul corporativo', pdfName: 'PANTONE 286 C', aliases: ['Pantone 286C', 'Azul'] },
    { name: 'Varnish', output: 'process' },
  ],
},
```

#### Zweifarbendruck

`print.plates` nennt die Platten, auf denen der Auftrag druckt, und nichts anderes wird gedruckt: ein Buch in Schwarz und einer Sonderfarbe, in zwei Sonderfarben oder nur in Schwarz. Die Platten des Vierfarbdrucks heißen `Cyan`, `Magenta`, `Yellow` und `Black`; eine Sonderfarbenplatte wird so benannt, wie das PDF sie nennt, oder mit einem Namen oder Alias der Druckfarbentabelle.

```ts
interface PrintPlatesConfig {
  inks?: string[];                                // Die Platten. Leer: alle Platten, wie üblich.
  images?: string[];                              // Die Platten, auf denen Bilder drucken: eine oder zwei.
  curves?: Record<string, Array<[number, number]>>; // Die Kurve einer Bildplatte: [Tonwert, Druckfarbe] in Prozent.
}
```

- Eine Farbe einer Druckfarbe, die der Auftrag druckt, oder eine CMYK-Farbe, deren Kanäle er druckt, wird unverändert gesetzt.
- Jede andere Farbe wird projiziert: Sie druckt als die Mischung aus einer oder zwei Platten, deren Aussehen über das Ausgabeprofil ihr am nächsten kommt. Eine Mischung aus zwei Druckfarben ist im PDF ein Farbraum `DeviceN`, und ein Grau bleibt allein auf `Black`. Tiefschwarz entfällt, außer der Auftrag druckt alle vier Prozessfarben.
- Bilder drucken als Monoton auf einer Platte oder als Duplex auf zwei: Der Tonwert jedes Pixels (seine Helligkeit) läuft durch die Kurve jeder Platte. `images` ist standardmäßig `Black` oder, wenn der Auftrag kein Schwarz druckt, die erste Platte. Die Kurve eines Monotons ist eine Gerade; ein Duplex legt seine erste Platte auf die Tiefen und seine zweite auf die Mitteltöne. `curves` ersetzt jede der beiden.

```ts
print: {
  standard: 'pdfx4',
  plates: {
    inks: ['Black', 'PANTONE 286 C'],
    images: ['Black', 'PANTONE 286 C'],
    curves: { 'PANTONE 286 C': [[0, 0], [50, 35], [100, 70]] },
  },
},
```

Der Preflight listet die Platten des Auftrags und jede Farbe auf, die die Projektion verschiebt. Eine Sonderfarbe oder CMYK-Farbe, die der Auftrag nicht druckt, ist ein Hinweis, wenn ihre Mischung innerhalb von ΔE 6 liegt, und eine Warnung darüber hinaus oder solange das Ausgabeprofil nicht geladen ist (`offPlateInk`, `offPlateCmyk`); eine Bildschirmfarbe, die mehr als ΔE 6 entfernt landet, ist ebenfalls eine Warnung (`offPlateColor`). Eine Sonderfarbenplatte, die keine Farbe und kein Eintrag der Druckfarbentabelle definiert, ist eine Warnung: Sie druckt und erscheint im Proof als Schwarz. In einem solchen Auftrag bleibt die Druckvorlage einer Abbildung außen vor und ihr SVG wird auf die Platten gesetzt; eine platzierte PDF-Seite oder ein Bild, das sich nicht dekodieren lässt, behält seine eigenen Druckfarben, und das Rendering warnt (`artworkOffPlates`). Im Sandbox werden die Platten unter Druckvorbereitung → Druckplatten gewählt. Seine Vorschauen und die Druckvorschau zeigen die Farben so, wie das Buch sie festlegt, nicht wie die Platten sie drucken: Prüfen Sie das PDF, in dem Für den Druck prüfen die verwendeten Druckfarben auflistet.

### Farben der Bilder

Ein Bild wird aus den Farben separiert, in denen es angelegt wurde. `print.imageColor` legt fest, wie seine Pixel gelesen werden:

```ts
interface PrintImageColorConfig {
  embeddedProfile?: 'use' | 'ignore';                  // A picture's own ICC profile. Default 'ignore'.
  assignedRgbProfile?: { name: string; fileId: string }; // Read every RGB picture through this .icc instead.
  grayDotGain?: 'profile' | 'none' | number;           // Greyscale pictures on black. Default 'none'.
  cmykProfile?: 'convert' | 'keep';                    // A CMYK picture of another press. Default 'keep'.
}
```

Die Standardwerte lassen Bilder so, wie frühere Versionen sie gedruckt haben: Jedes RGB-Bild wird als sRGB gelesen (`'ignore'`), Graustufenbilder werden wie jedes andere separiert (`'none'`) und ein CMYK-Bild behält seine Werte (`'keep'`). Jedes Verhalten der Liste schaltet sein Feld ein.

- **Sein eigenes Profil.** Ein PNG (`iCCP`) oder JPEG (`ICC_PROFILE`), das ein Profil einbettet, wird über dieses Profil gelesen, sodass ein Foto in Adobe RGB oder Display P3 so separiert wird, wie es aussieht, und nicht, als wäre es sRGB. Ein Bild ohne Profil oder mit sRGB-Profil wird wie bisher als sRGB gelesen. `'ignore'` liest jedes Bild als sRGB.
- **Ein zugewiesenes Profil.** `assignedRgbProfile` nennt eine gespeicherte `.icc`, über die jedes RGB-Bild gelesen wird, gleich welches Profil es einbettet: etwa für eine Reihe von Fotos, die ihr Profil verloren haben. Ihre Bytes kommen aus `resourceBytes`; fehlen sie, werden die eigenen Profile der Bilder verwendet, mit der Warnung `imageProfileUnavailable`.
- **Für das RIP beibehalten.** In PDF/X-4 mit `convertImages: false` wird ein Bild mit einem anderen Profil als sRGB in seinen eigenen Farben geschrieben, mit diesem Profil als `ICCBased` gekennzeichnet, und das RIP der Druckerei rechnet es um.
- **Graustufen.** Ein Graustufenbild (ein graues PNG oder JPEG oder eines mit Grauprofil) druckt allein mit Schwarz, nie als vierfarbiges Grau. Seine Tonwerte, über sein eigenes Profil gelesen (sonst so, wie der Bildschirm sie zeigt), werden an die Druckmaschine angepasst: `'profile'` über das Schwarz des Ausgabeprofils, dessen Tonwertzunahme die Druckbedingung bereits enthält; eine Zahl ist die Tonwertzunahme der Maschine im 50-%-Tonwert, in Prozent (typisch 10–30), die stattdessen ausgeglichen wird; `'none'` schreibt die Werte wie bisher unverändert.

```ts
print: {
  standard: 'pdfx4',
  imageColor: { grayDotGain: 20 },
},
```

- **Ein CMYK-Bild einer anderen Druckmaschine.** Ein CMYK-Bild, dessen eigenes Profil eine andere Druckbedingung ist (ein für SWOP oder für Zeitungspapier separiertes Foto in einem Buch für FOGRA), wird für die Druckbedingung der Ausgabe neu separiert (`cmykProfile: 'convert'`), und reines Schwarz bleibt reines Schwarz: ein TIFF- oder Photoshop-Bild aus seinen Pixeln; ein CMYK-JPEG, dessen Pixel nicht dekodiert werden, wird in PDF/X-4 mit seinem eigenen Profil als `ICCBased` gekennzeichnet, damit das RIP es umrechnet, und in PDF/X-1a, das eine solche Kennzeichnung nicht zulässt, unverändert durchgereicht; dort warnt der Preflight davor (`cmykImageForeign`), wenn der Host ihm das Profil des Bildes übergibt (`imageProfile`). In PDF/X-4 mit `convertImages: false` wird ein TIFF- oder Photoshop-Bild ebenso gekennzeichnet. `'keep'` druckt die Werte jedes CMYK-Bildes unverändert.

**Einstellungen für ein einzelnes Bild.** Das `printColor` einer Ressource nimmt dieselben Felder wie das `print.imageColor` des Buches an, nur für dieses Bild: ein Foto, dessen Profil ignoriert werden soll, eines, das über ein zugewiesenes Profil gelesen wird, ein Graustufenbild mit einer anderen Tonwertzunahme. In der Sandbox legt die Karte eines Bildes fest, ob es über sein eigenes Profil gelesen wird („Farbe im Druck“), wie seine Grautöne auf die Druckmaschine abgestimmt werden („Graustufen im Druck“) und welches Profil ihm zugewiesen ist („Zugewiesenes Profil“, eine `.icc`-Datei); ein Paket trägt die zugewiesenen Profile, das des Buches und die der Bilder, in seinem Ordner `profiles/`. Die Einstellungen des Buchs stehen unter Druckvorbereitung → Bilder.

```ts
{ id: 'archive-photo', kind: 'bitmap', bitmap: { fileId: 'photo.jpg', format: 'jpeg', width: 2400, height: 1600 },
  printColor: { embeddedProfile: 'ignore' } }
```


### In CMYK angelegte Farben

Eine in CMYK geschriebene Farbe behält ihre exakten Werte: `ColorValue.cmyk` (Prozent) wird in einer Druckausgabe unverändert gesetzt, und `hex` ist ihre Bildschirmdarstellung. Ein in CMYK angelegter Paletteneintrag gilt für jede mit ihm verknüpfte Farbe.

```ts
colorPalette: [
  { id: 'brand', name: 'Brand', value: { hex: '#00a0e3', model: 'cmyk', cmyk: { c: 100, m: 0, y: 0, k: 0 } } },
],
```

### Überdruckende Farben

Jede Farbe kann in einer Druckausgabe überdrucken: `overprint: true` an einem `ColorValue` lässt alles, was in ihr gemalt wird (Text, Linien, Kästen, Flächen), das Darunterliegende überdrucken, statt es auszusparen. Eine Prozessfarbe wird so geschrieben, wie sie separiert, unter einem überdruckenden Grafikzustand; eine Sonderfarbe überdruckt auf der Platte ihrer Druckfarbe, auch dort, wo dieselbe Druckfarbe in einer anderen Farbe ausspart. Ein überdruckendes Schwarz mit 100 % K behält die Schwarzbehandlung: Große Flächen bekommen weiterhin Tiefschwarz (`black.richBlack`). Ein RGB-PDF und der Bildschirm ignorieren es. Setzen Sie es am Paletteneintrag, damit jede mit ihm verknüpfte Farbe überdruckt, seine Tonwerte eingeschlossen; eine verknüpfte Farbe übernimmt die Einstellung des Eintrags und hat keine eigene. Die Palette eines Teils oder Abschnitts behält sie bei: Auch Text in der Farbe des Teils überdruckt.

```ts
colorPalette: [
  { id: 'title', name: 'Title', value: { hex: '#c00020', model: 'cmyk', cmyk: { c: 0, m: 100, y: 80, k: 10 }, overprint: true } },
],
```

Eine Druckausgabe erkennt eine Farbe an dem Hex-Wert, den das Layout malt; eine überdruckende Farbe teilt ihren Hex-Wert daher nie mit einer aussparenden. Fallen beide zusammen, rückt die überdruckende um einen Schritt (1/255 in einem Kanal) ab, wie es Sonderfarben tun; die Teilfarbe eines überdruckenden Eintrags rückt auf dieselbe Weise von jeder aussparenden Farbe des Buches ab. Eine überdruckende Farbe, die keine Druckfarbe aufträgt (Papierweiß, eine Druckfarbe mit 0 %), verschwindet im Druck: Der Preflight meldet sie als kritisch (`overprintWhite`). Eine Ausgabe mit mehr unterschiedlichen Farben, als sie Codes hat (rund 25 Millionen), spart den Rest aus und warnt (`overprintsExhausted`). In der Sandbox setzt der Schalter „Im Druck überdrucken“ des Farbwählers diesen Wert.

`preflightDocument(doc, options)` führt die Prüfungen an einem gesetzten Dokument aus und gibt eine Liste von Befunden zurück, jeder mit einer `kind`, einer `severity` (`'critical'`, `'warning'` oder `'info'`), dem buchweiten `pageIndex`, dem betroffenen `rect` (Seitenpixel) und, wenn das Element einen hat, seinem Quellbereich. Die Arten sind `lowImageResolution`, `declaredPixelsMismatch`, `rgbImage`, `thinRule`, `smallProcessText`, `inkLimit`, `safeZone` und `nearTrim`. Ohne `transform` zählt eine neutrale Farbe als eine Druckfarbe und jede andere als drei, und der Farbauftrag wird nicht geprüft; mit einem sind Zählung und Farbauftrag exakt. Die Auflösung eines Bildes wird aus den Pixeln berechnet, die seine Ressource angibt, oder aus denen der Datei selbst, wenn `imageSize(fileId)` sie liefert (`bitmapInfo` auf den Bytes oder das dekodierte Bild): Eine Angabe, die mehr als ein Pixel von der Datei abweicht, wird einmal als `declaredPixelsMismatch` gemeldet, als Warnung, wenn sie mehr Pixel behauptet, als die Datei hat. `placedImageResolutions(doc, { resources, imageSize })` listet jede platzierte Bitmap mit ihrer effektiven ppi-Zahl auf, ob der Preflight an ist oder nicht. Die Beschriftungen einer Abbildung zählen für `smallProcessText`, `inkLimit` und `safeZone` als Text.

```ts
import { bitmapInfo, outputTransform, parseIccProfile, preflightDocument, resolvePrintConfig } from 'postext';
import { inspectPrintMaster } from 'postext-pdf';

const print = resolvePrintConfig(config.print);
const transform = outputTransform(parseIccProfile(fogra51Bytes), { intent: print.renderingIntent });
const issues = preflightDocument(doc, {
  print,
  transform,
  resources,                                    // pixel sizes of the bitmaps
  imageSize: (fileId) => bitmapInfo(bytesOf(fileId)),  // the files' real pixels
  imageColor: (fileId) => colourOf(fileId),     // 'rgb' | 'cmyk' | 'gray', from the file
});
if (issues.some((i) => i.severity === 'critical')) process.exit(1);

const master = await inspectPrintMaster(masterBytes);
// => { nonEmbeddedFonts: ['Helvetica'], rgb: true, transparency: false }
```

### Referenzimplementierung

Die Komponente `PdfViewport` der Sandbox (`packages/postext-sandbox/src/viewport/pdf/PdfViewport.tsx`) verbindet die Teile oben zu einer Live-Vorschau mit Schaltflächen zum Neuerzeugen, Herunterladen und Drucken und ist ein guter Ausgangspunkt für jede PDF-Integration im Browser. Sie setzt den VDT über den gemeinsamen Layout-Worker (siehe [Layout in einem Web Worker ausführen](/de/docs/configuration-programmatic-usage#layout-in-einem-web-worker-ausführen)), sodass ein Klick auf *Neu berechnen* die Oberfläche nicht einfriert, während die Pipeline läuft – der Haupt-Thread übernimmt nur `renderToPdf` (das schnell ist, sobald der VDT existiert).
