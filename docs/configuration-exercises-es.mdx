# Configuración: ejercicios


## Estilos de ejercicio

La propiedad `exerciseStyles` declara los estilos con nombre que un ejercicio elige con `:::exercise{style="…"}`. Un estilo es la forma de una familia de ejercicios; las preguntas y las respuestas siguen en el Markdown (consulta [Ejercicios](/es/docs/exercises)). Por defecto se incluye un estilo, `exercise`, así que el contenedor funciona sin configuración; declarar `exerciseStyles` lo sustituye, y el primer estilo declarado es el que toma un ejercicio sin `style`. Todos los campos son opcionales, y los valores por defecto siguen el idioma del documento allí donde las escuelas no coinciden: las letras de las opciones, las letras de verdadero o falso, la disposición de la división y las palabras que se imprimen.

```ts
const config: PostextConfig = {
  exerciseStyles: [
    {
      id: 'activity',
      box: 'activity-frame',
      number: { shape: 'disc', background: { hex: '#2a5ea8', model: 'hex' } },
      instruction: { fontFamily: 'Source Sans 3' },
      options: { marker: 'circle' },
      blank: { look: 'dots', width: 'answer' },
      area: { kind: 'grid', lines: 4 },
      level: { glyph: '★', empty: '☆' },
      icons: { pair: { glyph: '👥' } },
    },
    { id: 'quiz', extends: 'activity', options: { layout: 'row', columns: 4 } },
  ],
};
```

### Número

`number` fija el número del ejercicio. Un número suelto va en negrita, en el color principal y seguido de punto; uno con forma es una cifra blanca dentro de un círculo, un cuadrado o un cuadrado redondeado del color principal, sin nada detrás.

La pantalla puede tener sus propios ajustes de ejercicios: `htmlViewer.overrides` admite también `exercises` y `exerciseStyles`, que se combinan con los del libro antes de que el visor HTML maquete. Así el papel puede llevar las soluciones al final del capítulo mientras la pantalla las oculta, o la pantalla puede prescindir de los espacios para escribir, que al lector no le sirven.

```ts
const config: PostextConfig = {
  htmlViewer: {
    overrides: {
      exercises: { solutions: { placement: 'none' } },
      exerciseStyles: [{ id: 'exercise', area: { kind: 'none' }, blank: { minWidth: { value: 6, unit: 'em' } } }],
    },
  },
};
```

### Evaluación

Por defecto, un ejercicio es de práctica: el lector comprueba tantas veces como quiera, vuelve a empezar y mira la solución. Cuatro ajustes lo convierten en un examen, para el libro en `exercises.digital` y para un estilo en su `digital`, que manda sobre los ejercicios de ese estilo:

```ts
const config: PostextConfig = {
  exercises: { digital: { passingScore: 60 } },
  exerciseStyles: [
    { id: 'exercise' },
    { id: 'test', extends: 'exercise', digital: { maxChecks: 1, maxResets: 1, showSolution: 'noChecksLeft' } },
  ],
};
```

- **`maxChecks`** cuenta las veces que se pulsa Comprobar en un intento. El botón dice cuántas quedan («Comprobar (quedan 2)»); cuando se acaban pone «Sin más comprobaciones», las respuestas se bloquean y la puntuación se queda en la barra.
- **`reset`** y **`maxResets`**: Volver a empezar borra las respuestas y abre un intento nuevo, con sus comprobaciones otra vez disponibles. `maxResets: 1` permite empezar de nuevo una vez, dos intentos en total, y el botón dice cuántas veces quedan; `reset: false` quita el botón.
- **`showSolution`**: `'always'`, siempre; `'afterCheck'`, cuando el intento ya se ha comprobado; `'noChecksLeft'`, cuando se han gastado sus comprobaciones o todas sus respuestas están bien; `'never'`, nunca. Mientras las comprobaciones están limitadas, ver la solución cierra el intento.
- **`passingScore`** es la nota según la cual un paquete SCORM informa de aprobado o suspenso (véase [Paquetes SCORM](/es/docs/configuration-html-folio-epub#paquetes-scorm-postext-scorm)).

Las palabras de los botones siguen el idioma del documento. Con `check: 'instant'` no hay botón Comprobar, así que `maxChecks` no se aplica; los demás ajustes sí. Las comprobaciones y los reinicios gastados se guardan con las respuestas: en un LMS, un paquete SCORM los guarda en el propio LMS, así que valen en cualquier dispositivo; en una página HTML o en un libro EPUB viven en el navegador del lector, y quien borra los datos del navegador empieza de cero.
