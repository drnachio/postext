## What you'll build

*House Specimen Nº 3*, from the imaginary Pellow Lane Press, is a four-page type specimen for three faces. On the cover, an ultramarine field holds a white *Ag* in Noto Serif Display italic at 240 pt and two mono lines that name the three faces; the title sits below the field. Page 2 runs Ysabeau Office down a waterfall from 7 to 14 pt, then sets Spanish, Polish and Czech pangrams whose ż, ř and ů need a second font file. Page 3 is the audit: an IBM Plex Mono table, filled in by the pen, of the ten faces the booklet declares, the six its pages are set in and the files the browser fetched for each. Page 4 sets page 1's first paragraph twice, from an early build and from the last. The early build ran before the browser had a single font file, so its lines end in other places and some run past the measure.

## Method

### 1 · Declare every file without fetching it

<Excerpt region="declare" />

A `FontFace` is one file, as an `@font-face` rule is, so a face with a latin and a latin-ext file is declared with two `FontFace` objects that share a family, weight and style and differ in `unicodeRange`, copied from the family's CSS. Adding them to `document.fonts` downloads nothing: the browser fetches a file when a `load()` call or a line of text needs its characters. Postext loads the faces a page declares through `document.fonts`; a face nothing declares is asked of the `resolve` option, which is how the other recipes get their Fontsource files from the kit. `customFonts` in a config only describes the files of a `.postext` bundle, so a page built from Markdown declares its own or hands over a `resolve`.

### 2 · Load the faces, then build

The code is [the short answer](#the-short-answer) above. `buildDocumentWithFonts` begins with `prepareFonts`, which reads the config and the text for every face they ask for, in each weight and slant, and loads them with the document's own characters as the sample, so the latin-ext files arrive with the Polish and Czech pangrams ([Loading fonts before layout](/en/docs/configuration#loading-fonts-before-layout)). It then builds, reads the faces the pages are set in, loads any that the config did not name and builds again. `onFonts` receives the report of that last look: the faces found `loaded`, the ones `missing`, and the ones the browser would have `synthesized` from another weight or slant. The pen builds three times because the booklet prints its own evidence: once too early, once with the faces, and a last time with the table and the picture filled in.

### 3 · Build the audit from the report

<Excerpt region="audit" />

The table starts from the faces `FONTS` declares and adds what the report says of each: set in the pages, faked by the browser, or set in a fallback. The last column lists the files whose `FontFace` reached `loaded`. Sixteen of the twenty were fetched: Postext loads all four faces of the text family, since `**` and `*` can ask for them in any paragraph, and the two mono italics, which no setting names, were never downloaded. The note reads three more things from the finished document: `contentWarnings`, where a face measured in a fallback is listed as `fontFallback`; `converged`, true when the layout's passes settled; and `warnings`. Check all three before you show or export a page.

### 4 · Keep an early build as evidence

<Excerpt region="art-proof" />

The pen calls `buildDocument` once before it declares a single face, so that build measures every word in the browser's fallback. Once the real faces are in, the pen paints it again and compares it line by line with the last build; the count of lines in the caption comes from that comparison, and the count of faces from the early build's own `fontFallback` warnings. A plain line measured in a narrower fallback runs past the measure until the column's clip, 2 pt past its edge, cuts off its last letters, so the pen paints page 1 with a widened column to show the whole overrun. The canvas and `postext-pdf` draw each run of a justified or mixed-style line where the layout measured it, so a real face wider than the fallback prints over the next word, and the words of a PDF built before its fonts arrived overlap. Nothing of the early build passes to the next one: `prepareFonts` finds the new faces in `document.fonts` and drops the widths measured in their families, so no call to `clearMeasurementCache()` is needed.

### 5 · A waterfall on the text's rhythm

<Excerpt region="type" />

Ysabeau Office sets the text at 11 on 15.5 pt, with a blank line between paragraphs instead of an indent. The text is ragged, so every word space keeps its natural width. Bold, italic and references are set in ink; left alone, they would take the main colour. Every waterfall size and pangram is a paragraph style two leads (31 pt) deep, so the page keeps the text's 15.5 pt rhythm. The size labels are mono chips, and the one-digit sizes get half a letter of padding on each side, so every sample starts on the same edge.

### 6 · Three faces on one cover

<Excerpt region="opener" />

The cover is the H1 level's design: the letters of the heading's `glyphs` attribute in the display face at 240 pt, and under them two mono lines that name that face and the text and label faces, as on a type foundry's specimen sheet. `span: 'page'` sets the heading across the page, and the field hangs from the top-left corner of the bleed, so it runs off the top edge. `minHeight` counts from the top margin and reserves the room down to `Y.end`, 42 mm below the field; without it the text starts a line higher, tight under the lead.

## Variations

### Hand over the files with `resolve`

`kitFonts(FONTS)`, in <RecipeLink slug="first-page-from-markdown">from a Markdown string to a designed page</RecipeLink>, declares nothing: Postext asks its `resolve` for the files of each face and adds them to `document.fonts` itself.

### Forget a face

Leave out the bold of IBM Plex Mono, which sets the kicker, the table header and the caption labels: the browser thickens the regular, the table marks the face `faked`, and the note counts one `fontFallback` warning, which names IBM Plex Mono 700 as `synthesized`.

```diff
-  'IBM Plex Mono': ['400', '400i', '700', '700i'], // labels, chips, the table, captions
+  'IBM Plex Mono': ['400', '400i', '700i'], // labels, chips, the table, captions
```

### Embed the same faces in a PDF

`renderToPdf` embeds the bytes its `fontProvider` returns for each face, and the provider in <RecipeLink slug="pdf-with-embedded-fonts">a real PDF with the same fonts embedded</RecipeLink> serves Fontsource's latin files, which stop at Latin-1: for this booklet's ż, ł, ř and ů, have it return each face's whole font file from your own folder.

## Pitfalls

- If you load a face yourself, `document.fonts.load(font)` with no sample text loads only the file that covers a space, the latin one, and ż and ř fall back to a system face. `prepareFonts` passes the document's own characters.
- `renderPageToCanvas` and `postext-pdf` clip each column 2 pt past its edge, so a line measured with a narrower fallback loses its last letters. The build that measured it names the face in `doc.contentWarnings` as `fontFallback`: read that list before you show or export a page.
