## What you'll build

Three pages from chapter 4 of *The Shell, Gently*, an invented pocket guide to the command line, on a 178 × 229 mm page. The text is justified Charis SIL in a 100 mm column, with a margin column on the outer side for notes. Each listing is a near-black box of JetBrains Mono that runs into that column, under a tab with the name of the file or the session. Keywords and typed commands print in amber, strings in green and comments in grey. Keys such as Ctrl and Tab are small outlined keycaps inside the justified lines, and a two-column cheat sheet of Ctrl shortcuts fills the foot of page 50. The Markdown keeps ordinary fenced code blocks, and the engine sets them as they are.

## Method

### 1 · Give the fences a box

The code for this step is [the short answer](#the-short-answer) above. Each ```` ``` ```` fence in the Markdown is a [code block](/en/docs/document-format#code-blocks): Postext sets its lines as typed, one line of code to a line of type, with the indents, the blank lines of the script and the two-column output of `du` kept. `codeStyle` designs every listing at once ([code listings](/en/docs/configuration-styles#code-listings)): the face and its leading, the near-black fill, the padding and the room above and below. Whatever follows the language on the fence line (`Terminal`, `backup.sh`) is the listing's title, and because `codeStyle.label` is set it prints on a [label tab](/en/docs/configuration-styles#callout-styles) on the box's top edge rather than in a title row. `codeStyle.inline` sets the inline code of the running text, `ls` or `grep -c`, in the same face at 0.88 em ([inline code](/en/docs/configuration-styles#inline-code)). The paragraph after a listing goes in `:::paragraphs{style="resume"}`, so it starts flush, as it would after a heading.

### 2 · Keep the text narrow and let the code cross the margin

<Excerpt region="page" />

At 10 pt, Charis SIL sets about 62 characters in the 100 mm column. The side column of this [column-and-a-half layout](/en/docs/configuration-page-layout#layout-types) takes only floats and notes, so the text never runs into it. `span: 'page'` in `codeStyle` stretches every listing across both columns, 143 mm. Inside its padding a box holds 73 characters of JetBrains Mono at 8.6 pt; the longest line on these pages, the comment that opens `backup.sh`, has 71.

### 3 · Colour the code by token

<Excerpt region="paint" />

The language on the fence (`console`, `bash`) picks the built-in tokenizer, and `codeStyle.tokens` gives each kind of token its colour, weight and slant ([syntax colouring](/en/docs/configuration-styles#syntax-colouring)). In `backup.sh`, keywords such as `for` and `done` and builtins such as `set` and `echo` print in amber bold, strings in green italic and comments in grey; programs like `mkdir` and `rsync` stay plain. The default style sets comments in italics, so `italic: false` keeps them upright. In a `console` fence a line that opens with a prompt is a `prompt` token and every other line is `output`, so the commands you type print in amber bold and the shell's answer stays in the listing's light grey. The kinds the recipe does not want coloured, numbers, variables and options among them, take that grey too.

### 4 · Set keys as chips

<Excerpt region="keycaps" />

Keys are `key` chips with a light fill and a 0.6 pt outline. Their size is given in points, so a key measures 7.8 pt in the 10 pt text, in the 8.6 pt margin note and in the 8.4 pt cheat sheet; `em(0.78)` would shrink the cheat sheet's keys to 6.6 pt. A chip never breaks across lines and never stretches ([inline chips](/en/docs/document-format#inline-chips)), so a line with keys puts all its slack in its word spaces. `spacing` makes the line breaker try other breaks before a space grows past 140 % of its normal width. At the default, 200 %, six lines of these pages stretch further than that; with the setting, the widest reaches 132 %.

### 5 · Number the steps on the grid

<Excerpt region="steps" />

The numbers are Sora 800 in the accent, and the separator is a mono `›` in grey. The separator has its own face and colour, so it is drawn as a separate run ([ordered lists](/en/docs/configuration-text#ordered-lists)). The list margins are zero, so the steps continue on the 14.5 pt grid of the text around them. The default 1.5 em would open 5.3 mm above the steps and push the cheat sheet to page 51.

### 6 · Float the cheat sheet to the foot of the page

<Excerpt region="sheet" />

The cheat sheet is a callout style with the listings' fill, Sora for the actions, and `placement: 'bottom'`, which floats it to the foot of page 50 ([floated boxes](/en/docs/configuration-styles#the-callout-container)). Left in the flow, a box across the page needs room for itself and two lines of text under it. Here the box would move to page 51, leaving 58 mm empty under the steps, and the chapter would run to four pages. In the Markdown, `:::columns{count=2 breaks="8"}` opens the right column at the eighth block, its heading. Balancing alone cuts by height, and when one action runs to a second line it leaves *Commands and history* at the foot of the left column. Every entry opens with the same two chips, `Ctrl` and a letter, both in the mono face, so each action begins at the same distance from the left edge of its column.

## Variations

### Hang the tab on the right

The tab moves to the box's top-right corner, which on a recto stands over the margin column.

```diff
-    position: 'top-left' },
+    position: 'top-right' },
```

### Number the lines

Every listing gets line numbers in grey in a gutter inside its box. The gutter takes about four characters of the 73, so the comment that opens `backup.sh` no longer fits: it turns over after `backup`, and `disk.` goes on below behind a `»`. The Cookbook's check reports it as a `codeOverflow` warning; shorten the comment to keep the script on its 13 lines. A single listing takes numbers with `{lineNumbers}` on its fence line.

```diff
+  lineNumbers: true, lineNumberColor: col('slate'),
   tokens: tokens(), // the colours, below
```

### Give comments the colour of strings

The comments take the green of the strings, in italics.

```diff
-    comment: { color: col('slate'), italic: false }, // upright: the default comment is italic
+    comment: { color: col('phosphor'), italic: true }, // the strings' green italic
```

## Pitfalls

- Keep every code line within 73 characters. A longer one turns over at its last space or punctuation that fits and goes on below behind a `»`, and the engine reports a `codeOverflow` warning; `overflow: 'shrink'` sets the whole listing smaller instead, and `'clip'` cuts the line at the box's edge.
- A tab in a listing advances to the next multiple of four columns (`codeStyle.tabSize`). A script indented with tabs that your editor shows eight columns wide comes out narrower here.
- With `codeStyle.inline` set, inline code never breaks across lines, as a chip does. A long path in running text, such as `~/Pictures/2025/IMG_0977.MOV`, moves whole to the next line and can leave a loose one behind it.
