## できあがり

『The Shell, Gently』という架空のコマンドライン小型入門書から、第4章の3ページを178 × 229 mmの判型で組みます。本文はCharis SILの両端そろえで、100 mmの段に組みます。小口側には傍注用の余白段を設けます。コードリストはどれもJetBrains Monoを組んだ黒に近い囲みで、この余白段まで張り出し、ファイル名かセッション名を記したタブを上に付けます。キーワードと入力コマンドは琥珀色、文字列は緑、コメントはグレーで印刷されます。CtrlやTabなどのキーは両端そろえの行の中に輪郭線付きの小さなキーキャップとして入り、50ページの下端はCtrlショートカットの2段組みチートシートが占めます。Markdownには普通のフェンス付きコードブロックを残し、エンジンがそれをそのまま組みます。

## 作り方

### 1 · フェンスを囲みに組む

この手順のコードは上の[手短な答え](#手短な答え)にあります。Markdownの```` ``` ````フェンスはどれも[コードブロック](/ja/docs/document-format#コードブロック)です。Postextはその行を書いたとおりに、コードの1行を組版の1行として組み、インデントも、スクリプトの空行も、`du`の2段の出力も保ちます。`codeStyle`はすべてのコードリストの体裁をまとめて決めます（[コードリスト](/ja/docs/configuration-styles#コードリスト)）。書体とその行送り、黒に近い塗り、パディング、上下のアキです。フェンス行で言語名の後に書いたもの（`Terminal`、`backup.sh`）はコードリストのタイトルです。`codeStyle.label`を設定しているので、タイトルはタイトル行ではなく囲みの上辺の[ラベルタブ](/ja/docs/configuration-styles#囲みスタイル)に印刷されます。`codeStyle.inline`は、本文中のインラインコード（`ls`や`grep -c`）を同じ書体の0.88 emで組みます（[インラインコード](/ja/docs/configuration-styles#インラインコード)）。リストの後の段落は`:::paragraphs{style="resume"}`に入れるので、見出しの後と同じく字下げなしで始まります。

### 2 · 本文は狭く、コードは余白まで

<Excerpt region="page" />

10 ptのCharis SILは、100 mmの段に約62字入ります。この[1段半組み](/ja/docs/configuration-page-layout#レイアウトの種類)のサイド段はフロートと傍注だけを受け持つので、本文がそこへ流れ込むことはありません。`codeStyle`の`span: 'page'`は、すべてのリストを両方の段にまたがる143 mmに広げます。パディングの内側には8.6 ptのJetBrains Monoが73字入ります。これらのページで最も長い行、`backup.sh`の冒頭のコメントは71字です。

### 3 · 字句ごとにコードに色を付ける

<Excerpt region="paint" />

フェンスの言語（`console`、`bash`）が組み込みの字句解析器を選び、`codeStyle.tokens`が字句の種類ごとに色、太さ、傾きを与えます（[構文の色分け](/ja/docs/configuration-styles#構文の色分け)）。`backup.sh`では、`for`や`done`などのキーワードと`set`や`echo`などの組み込みコマンドが琥珀色の太字、文字列が緑のイタリック、コメントがグレーで印刷されます。`mkdir`や`rsync`のようなプログラムは装飾しません。既定のスタイルはコメントをイタリックにするので、`italic: false`で正体に戻します。`console`フェンスでは、プロンプトで始まる行が`prompt`の字句、それ以外の行が`output`の字句になります。そのため入力するコマンドは琥珀色の太字で印刷され、シェルの応答はリストの明るいグレーのままです。このレシピで色を付けない種類（数値、変数、オプションなど）も、同じグレーにします。

### 4 · キーをチップにする

<Excerpt region="keycaps" />

キーは`key`チップで、淡い塗りと0.6 ptの輪郭線を持ちます。大きさをポイントで指定しているので、キーは10 ptの本文でも、8.6 ptの傍注でも、8.4 ptのチートシートでも7.8 ptになります。`em(0.78)`で指定すると、チートシートのキーは6.6 ptに縮みます。チップは行をまたいで分割されず、伸縮もしません（[インラインのチップ](/ja/docs/document-format#インラインのチップ)）。そのためキーを含む行では、余りがすべて語間に回ります。`spacing`を指定すると、改行処理はスペースが通常幅の140 %を超えて広がる前に別の改行位置を試します。既定の200 %では、これらのページの6行がそれ以上に広がります。この設定を入れると、最も広い行でも132 %に収まります。

### 5 · 手順の番号をグリッドに乗せる

<Excerpt region="steps" />

番号はアクセント色のSora 800、区切りはグレーの等幅の`›`です。区切りは独自の書体と色を持つので、別のランとして描かれます（[番号付きリスト](/ja/docs/configuration-text#番号付きリスト)）。リストの余白はゼロなので、手順は周囲の本文と同じ14.5 ptのグリッドに乗り続けます。既定の1.5 emでは手順の上に5.3 mmの空きができ、チートシートが51ページへ押し出されます。

### 6 · チートシートをページの下端にフロートさせる

<Excerpt region="sheet" />

チートシートはリストと同じ塗りの囲みスタイルで、動作の説明にはSoraを使います。`placement: 'bottom'`で、50ページの下端にフロートします（[フロートする囲み](/ja/docs/configuration-styles#calloutコンテナー)）。流れの中に置いたままだと、ページ幅の囲みは自身の高さに加えて、その下に本文2行分の余地を必要とします。ここでは囲みが51ページに移り、手順の下に58 mmの空白が残り、章は4ページに延びてしまいます。Markdownでは、`:::columns{count=2 breaks="8"}`が8番目のブロック、つまり見出しから右の段を始めます。段末そろえだけでは高さで切るので、ある動作の説明が2行目に回ると、見出し「Commands and history」が左の段の下端に取り残されます。どの項目も同じ2つのチップ、`Ctrl`と英字で始まり、どちらも等幅書体なので、各動作の説明は段の左端から同じ距離で始まります。

## アレンジ

### タブを右に掛ける

タブは囲みの右上の角に移ります。奇数ページでは、そこが余白段の上に当たります。

```diff
-    position: 'top-left' },
+    position: 'top-right' },
```

### 行に番号を付ける

どのリストにも、囲みの内側に設けた欄にグレーの行番号が付きます。この欄は73字のうち約4字分を取るので、`backup.sh`の冒頭のコメントは収まらなくなります。`backup`の後で折り返し、`disk.`が次の行の`»`の後に続きます。Cookbookのチェックはこれを`codeOverflow`警告として報告します。スクリプトを13行のままにするには、コメントを短くします。1つのリストだけに番号を付けるには、そのフェンス行に`{lineNumbers}`と書きます。

```diff
+  lineNumbers: true, lineNumberColor: col('slate'),
   tokens: tokens(), // the colours, below
```

### コメントを文字列と同じ色にする

コメントが文字列と同じ緑のイタリックになります。

```diff
-    comment: { color: col('slate'), italic: false }, // upright: the default comment is italic
+    comment: { color: col('phosphor'), italic: true }, // the strings' green italic
```

## よくあるつまずき

- コードの各行は73字以内に収めます。長い行は収まる最後のスペースか約物の後で折り返し、続きを次の行の`»`の後に組みます。このときエンジンは`codeOverflow`警告を出します。`overflow: 'shrink'`にするとリスト全体を小さく組み、`'clip'`にすると行を囲みの端で切ります。
- リストの中のタブは、次の4桁の倍数の位置まで進みます（`codeStyle.tabSize`）。エディターで8桁幅に表示されるタブでインデントしたスクリプトは、ここでは幅が狭くなります。
- `codeStyle.inline`を設定すると、インラインコードはチップと同じく行をまたいで分割されません。`~/Pictures/2025/IMG_0977.MOV`のような本文中の長いパスは丸ごと次の行に移り、その前の行の語間が広がることがあります。
