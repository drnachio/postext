## 成品一览

一本七页的使用说明书，产品是虚构的电水壶Verra W1，德文，A5开本。安全页把两个危险等级排成提示框：一条信号色的色带沿左侧竖下，承载警告三角；同色的细边框把框封住，WARNUNG用红色，VORSICHT用琥珀色。HINWEIS这一级针对的是器具损坏，它不用色带和三角，改为圆角的蓝绿色底色。提示框上方的段落把三个信号词都排成实心标签。第3页有一张零件图，编号引线在图例上方；第4页的按键名是描边标签，旁边是大号步骤编号。故障排除表跨第6、7两页。题注写作Abbildung和Tabelle，拆开的表格在两页上都标有Fortsetzung。

## 做法

### 1 · 承载三角的色带

代码见上文的[简短回答](#简短回答)。`stripe`沿左边缘画出色带。标注框带侧边竖条时，图标放在竖条正中，而不另占一栏（[标注框样式](/zh/docs/configuration-styles#标注框样式)）；`align: 'top'`让图标顶边与标题顶边平齐。同色的`border`把色带封成边框；没有它，框内文字就会立在光秃秃的页面上，旁边只是一根彩色竖条。`PAD_Y`是算出来的，让标题、标题后的间距和上下内边距合起来正好是12.8 pt网格的两行。正文沿用网格行距，所以每个框的高度都是整行数（WARNUNG 10行，VORSICHT 8行），`marginTop: pt(LEAD)`则让第2页的两个框之间恰好空一行。VORSICHT的色带和边框保留琥珀色，标题和项目符号改用墨色：琥珀色在白底上的对比度是2.0:1，而小字需要4.5:1。HINWEIS从同一个基础样式出发（`...notice(…)`），关掉色带和边框，于是它的信息图标自占一栏，`borderRadius`把一块普通底色做成圆角。

### 2 · 图和表的德文名称

<Excerpt region="types" />

`locale: 'de'`让说明书使用德文断词，也让内置类型用德文名称：不做别的设置，题注会写成Abbildung 2.1和Tabelle 5.1，拆分表格前一部分下方的说明会写Wird fortgesetzt。表格样式把这条说明和题注的后缀写成完整的说法；传入`defaultResourceTypes('de')`则是为了改两处。第一处是`counted`：`{n}`配合`resetOn: 'never'`在整本说明书中连续计数（Abbildung 1，Tabelle 1到3），而不是每节重新开始。只有表格类型设了`captionStyle.position: 'above'`，所以表格的题注在表头上方，零件图的题注仍在图下。

### 3 · 用标签排按键、信号词和零件编号

<Excerpt region="chips" />

`taste`用等宽字体为按键名描边、不填色，就像按钮上印的标签那样。信号词标签用各自提示框的颜色填充，琥珀色标签里的字用墨色，与VORSICHT标题一致。`nr`给零件编号设的圆角半径大于其高度的一半，所以它们成了圆片，与零件图上的编号圆圈一样。标签尺寸以周围文字的em为单位：按键在正文中是8.6 pt，在表格单元格中是7.5 pt（[行内标签样式](/zh/docs/configuration-styles#行内标签样式)）。

### 4 · 站在基线上的步骤编号

<Excerpt region="steps" />

步骤是一个有序列表，编号用15 pt的Red Hat Display 800，蓝绿色，不带分隔符。列表编号在其第一行中垂直居中，而不是站在基线上，所以一个15 pt的数字排在9.3 pt的文字旁时，会比该行低约1 pt。`numberVerticalOffset: pt(-1)`是在截图上量出的值，把数字的底边提到基线上。`itemSpacing`让步骤之间相隔5 pt，给大号数字留出空间。嵌套在步骤下的项目从6.5 mm处开始，与步骤正文对齐；它们是蓝绿色短横线，第三级用灰色短横线（[有序列表](/zh/docs/configuration-text#有序列表)）。

### 5 · 反白方标里的节号

<Excerpt region="section" />

每一节都是栏内的一级标题，由一个版面设计槽位绘制。方标在蓝绿色方块上用白色印出`{number}`（由`numberingTemplate: '{1}'`填入），标题从其右侧3 mm处开始。节号和标题的字号、行高相同，所以同样的上内边距让它们落在同一条基线上。方标是22 pt见方，比12.8 pt网格的两行少3.6 pt，所以标题不会超出两条网格线。封面也是一级标题，只是用了一个不编号的标题样式，因此Sicherheitshinweise是第1节。

### 6 · 可拆分、带合并单元格的故障排除表

<Excerpt region="tables" />

每个表格都是单独内容文件里的TSV。在故障排除数据中，第一个单元格为空的行属于上方的故障，`mergeCells`把这些首格合并成一个高单元格，并把被覆盖的单元格标为隐藏。`parseTSV`不设表头行，所以用`headerRowCount: 1`声明，这一行就是第7页上重复的那一行。这个表格比一页还高，所以要拆分，在下一页接续。`position: 'top'`把它设为第6页顶部的浮动体；从postext 1.25起，设为`'here'`时它也会同样拆分，但表后的文字在第7页上会从更低的位置开始，最后几行会被挤到第8页。拆分落在行与行之间，从不穿过合并单元格，因此每个故障都与它的原因在同一页（[比页面还高的表格](/zh/docs/configuration-resources#比页面还高的表)）。它在第5页被引用，排在第6页顶部，这是引用之后第一个能容纳顶部浮动体的页面。`fold`把一个列表的两半并排排出，图例和技术数据都用它；图例用`align: 'center'`让编号标签居中。

## 变化

### 按节给图和表编号

在模板中加入节号，并在每节重置，零件图就变成Abbildung 2.1，故障排除表变成Tabelle 5.1。

```diff
-const counted = { numberingTemplate: '{n}', resetOn: 'never', counterFormat: 'decimal' }; // 1, 2…
+const counted = { numberingTemplate: '{h1}.{n}', resetOn: 'h1', counterFormat: 'decimal' };
```

## 常见问题

- 各栏齐底会把收尾一页的框推到该页最后一条网格线上，于是页面上剩下的空间都出现在框的上方（[各栏齐底](/zh/docs/configuration-text#各栏齐底)）。第2页的文字是调整过的，正好填满一栏。删掉一个VORSICHT项目，框仍然结束在页脚处，但两个框之间的空隙会从4.5 mm增大到13.6 mm；如果设`headings: { balancing: { enabled: false } }`，框会保持在WARNUNG下方一行处，页面则在离底部两行的地方结束。
