## What you'll build

You set chapter I of H. G. Wells's *The Time Machine* as a 110 × 147 mm pocket edition, with the Markdown beside it. The title page has a photograph of a brass dial with four small dials, generated with diffusion models, on an oxblood field drawn in code, over the title in Cinzel. The chapter's text starts on the ninth line, under a roman numeral and a brass rule, and runs in Baskervville at 9.5 on 13 pt under small-capital running heads. Every keystroke sets the whole chapter again in a Web Worker, and the canvas on the right turns to the page that holds the caret. Under the editor, a hand that the main thread turns every frame stops while that thread is busy, and the status line gives the build's time, the longest frame and how many builds a newer keystroke cancelled. A menu at the top right moves the build to the main thread for comparison.

## Method

### 1 · Start the worker with one call

This step's code is [the short answer](#the-short-answer) above. `createLayoutWorker()` takes no options. When the module comes from esm.sh, the worker file is on esm.sh's origin, where the `Worker` constructor refuses it, so the engine starts its worker entry through a same-origin blob, at the version the page imported. In a bundled app the same call starts the worker file next to the module. The handle's `build()` takes the same content and config as `buildDocument()` and resolves to the same kind of document ([Running layout in a Web Worker](/en/docs/configuration-programmatic-usage#running-layout-in-a-web-worker)).

<Note>The postext package measures text with a canvas, so it lays out in a browser or a worker. For a batch job, the postext command line (postext-cli) lays a book out and writes its PDF with no browser; a page opened in headless Chrome with Puppeteer is the other way. For a `.postext` project on disk, the postext-port skill's `render.mjs` runs the engine in Node and measures with fontkit, from the project's own fonts, in place of a canvas ([Scripts](/en/docs/skill#scripts)).</Note>

### 2 · Load every face twice

<Excerpt region="fonts" />

The worker has a `FontFaceSet` of its own and cannot see the faces the page has loaded, so the short answer fetches the same Fontsource files and passes their bytes to `registerFonts()`, with each weight as a string (`'400'`). Leave that call out and the worker measures in a fallback font: it sets this chapter in 175 lines instead of 190, the first line ends on “him)” instead of “of”, and the page's console names each missing family once. A font file that fails to download is harder to see. If the worker receives a 404 page in place of the roman Baskervville, `registerFonts()` still resolves and the chapter comes out in 186 lines, with a warning only in the worker's console. The short answer therefore checks each response's status before it sends any bytes, and throws with the face and the HTTP status. The page loads the same faces with `loadFonts()` as well, because the canvas paints with the page's fonts.

### 3 · Build on every keystroke, paint on the main thread

<Excerpt region="editor" />

`typeset()` aborts the build in flight before it asks for the next. The aborted build's promise rejects at once with an `AbortError`, which `typeset()` turns into `null`. In the worker, a build still waiting in the queue is dropped straight away, and a running one stops at the end of its current placement pass, because the build checks for a cancel only between passes. `refresh()` numbers its builds and paints only the newest, so a worker build that arrives late cannot paint over a main-thread one. The document comes back to the main thread, where `renderPageToCanvas()` paints it with the images registered there. The worker needs only each picture's size, which the resource entry carries (1100 × 840). Every block keeps its offset in the Markdown (`sourceStart`), and `follow()` shows the last page with a block that starts at or before the caret.

<Note>Timed on the machine that made the capture, in twelve loads of the page besides the one on the card. The status line times each build from the request to the first frame after the pages arrive. The worker's first build takes 66 to 141 ms and later ones 10 to 36 ms, because the worker keeps one measurement cache for its lifetime; meanwhile the longest frame stays at 8 to 18 ms. On the main thread the first build stops the dial for 54 to 74 ms. Later builds there, with a cache of their own, take 5 to 17 ms and stretch the longest frame to 25 ms at most, about one and a half frames at 60 Hz. A build longer than a frame (16.7 ms at 60 Hz), such as this chapter's first or a build of a book with many chapters, freezes the editor on the main thread and not in the worker.</Note>

### 4 · A title page that is a heading style

<Excerpt region="title" />

The line `# The Time Machine {style="title"}` sets page 1 in the `title` heading style, whose empty `header` and `footer` leave the page without running heads or folio. `numbered: false` keeps the title out of the chapter count, so Introduction is still chapter I. The plate is anchored to the top-left corner of the bleed, and the author's name is set below the foot of the column. A design kept in its column is cut at the column's foot, so the style sets `span: 'page'`; without it the author's name is not painted.

### 5 · Running heads by page role

<Excerpt region="heads" />

`pages: 'body'` keeps the running heads off the title page and the opener, and `parity` sets the book's title on versos and the chapter's on rectos, with folios at the outer edge. The opener gets a drop folio instead, from a footer element with `pages: 'opener'`. Folios and heads are all 8 pt and hang 8.2 mm below the top edge, so the folio's figures stand on the heads' baseline.

### 6 · The chapter opener

<Excerpt region="opener" />

The design's `{number}` prints the chapter number in the form `numberingTemplate: '{1:I}'` gives it, a roman I. `minHeight` reserves at least eight lines, so the text starts on the ninth while the title takes one or two lines, and further down when a longer title needs more room. `breakBefore` with `parity: 'any'` lets the chapter open on page 2, facing its second page; the default would send it to page 3, a recto.
